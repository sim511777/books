## 2.1 Qt 설치 방법 개관

본격적으로 예제를 작성하기 전에, Qt 라이브러리와 빌드 도구를 개발 환경에 갖추어야 합니다. Qt를 설치하는 방법은 여러 가지가 있으며, 운영체제와 취향에 따라 선택할 수 있습니다.

### Qt Online Installer

The Qt Company가 공식으로 제공하는 설치 프로그램입니다. Qt 계정(무료 가입 가능)으로 로그인한 뒤, 원하는 Qt 버전(예: Qt 6.7)과 컴파일러 조합(예: Windows의 MSVC 2019/2022, MinGW, macOS의 Clang, Linux의 GCC), 그리고 필요한 애드온 모듈을 선택하여 설치합니다. 이 방법은 Qt Creator IDE와 문서, 예제 코드를 함께 설치해 준다는 장점이 있어 처음 Qt를 접하는 경우 가장 무난한 선택입니다.

### 패키지 매니저를 이용한 설치

C++ 라이브러리 패키지 매니저를 이미 사용하고 있다면 그 경로로 Qt를 설치할 수도 있습니다. 대표적으로 다음과 같은 도구들이 있습니다(자세한 사용법은 각 도구의 공식 문서를 참고하시기 바랍니다).

- **vcpkg**: 마이크로소프트에서 관리하는 C/C++ 패키지 매니저로, Qt를 포함한 다양한 라이브러리를 소스 빌드 형태로 설치할 수 있습니다.
- **Linux 배포판 패키지 매니저**: 예를 들어 Ubuntu/Debian 계열의 `apt`, Fedora의 `dnf`, Arch Linux의 `pacman` 등을 통해 배포판이 미리 빌드해 둔 Qt 패키지를 설치할 수 있습니다.
- **Homebrew**: macOS에서 널리 쓰이는 패키지 매니저로, Qt를 설치할 수 있습니다.

어떤 방법을 택하든 이 책의 예제 코드 자체는 동일하게 동작합니다. 다만 설치 경로나 CMake가 Qt를 찾는 방식(`CMAKE_PREFIX_PATH` 설정 등)이 조금씩 다를 수 있다는 점만 유의하면 됩니다.

### 컴파일러와 CMake

Qt 6는 C++17 이상을 지원하는 컴파일러가 필요합니다. Windows에서는 MSVC(Visual Studio) 또는 MinGW, macOS에서는 Xcode의 Clang, Linux에서는 GCC 또는 Clang을 사용할 수 있습니다. 또한 이 책의 예제는 빌드 시스템으로 **CMake**(3.16 이상 권장)를 사용합니다. CMake는 Qt Online Installer에 포함되어 있지 않을 수 있으므로, 별도로 설치되어 있는지 확인해야 합니다.

```
$ cmake --version
cmake version 3.27.0
```

## 2.2 CMake로 Qt 프로젝트 구성하기

Qt 6부터는 CMake가 공식적으로 권장되는 빌드 시스템입니다(과거의 `qmake`도 여전히 지원되지만, 이 책에서는 다루지 않습니다). Qt 6는 CMake와의 통합을 돕기 위해 `qt_add_executable`, `qt_add_qml_module` 같은 전용 CMake 함수를 제공합니다.

가장 기본적인 `CMakeLists.txt` 구조는 다음과 같습니다.

```cmake
cmake_minimum_required(VERSION 3.16)
project(FirstWindow LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# Qt의 MOC, UIC, RCC를 CMake 빌드 과정에 자동으로 연결한다.
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTOUIC ON)
set(CMAKE_AUTORCC ON)

# 시스템에 설치된 Qt6의 Widgets 모듈을 찾는다.
find_package(Qt6 REQUIRED COMPONENTS Widgets)

# Qt 6 전용 헬퍼로 실행 파일 타깃을 생성한다.
qt_add_executable(FirstWindow
    main.cpp
)

# 실행 파일에 Qt Widgets 모듈을 링크한다.
target_link_libraries(FirstWindow PRIVATE Qt6::Widgets)
```

각 줄이 하는 역할을 짚어보겠습니다.

- `cmake_minimum_required` / `project`: 표준적인 CMake 프로젝트 선언입니다.
- `CMAKE_CXX_STANDARD 17`: Qt 6는 최소 C++17을 요구하므로 명시적으로 설정합니다.
- `CMAKE_AUTOMOC ON`: **MOC(Meta-Object Compiler)** 를 자동으로 실행하도록 CMake에 지시합니다. `Q_OBJECT` 매크로가 포함된 클래스가 있으면 CMake가 빌드 시점에 자동으로 MOC를 호출해 부가 소스 파일을 생성합니다. MOC의 개념은 2.5절에서, 시그널/슬롯과 함께 하는 실제 활용은 3장에서 자세히 다룹니다.
- `CMAKE_AUTOUIC ON`: Qt Designer로 만든 `.ui` 파일을 자동으로 C++ 헤더로 변환합니다. 이 책에서 `.ui` 파일을 사용할 때 필요합니다.
- `CMAKE_AUTORCC ON`: `.qrc` 리소스 파일(아이콘, 이미지 등을 실행 파일에 내장할 때 사용)을 자동으로 처리합니다.
- `find_package(Qt6 REQUIRED COMPONENTS Widgets)`: 시스템에서 Qt6 패키지를 찾고, 그중 Widgets 모듈을 요구합니다. Qt를 표준 경로가 아닌 곳에 설치했다면 `CMAKE_PREFIX_PATH`에 Qt 설치 경로(예: `C:/Qt/6.7.0/msvc2019_64`)를 지정해 주어야 CMake가 이를 찾을 수 있습니다.
- `qt_add_executable`: Qt 6에서 새로 도입된 헬퍼 함수로, 내부적으로 `add_executable`을 호출하면서 플랫폼별로 필요한 추가 설정(예: macOS 앱 번들, Windows GUI 서브시스템 설정 등)을 자동으로 처리해 줍니다.
- `target_link_libraries`: 실행 파일이 `Qt6::Widgets` 타깃에 링크되도록 지정합니다. CMake의 Qt6 패키지는 각 모듈을 `Qt6::모듈이름` 형태의 임포트 타깃으로 제공하며, 이 타깃에는 필요한 include 경로와 라이브러리 경로가 이미 포함되어 있습니다.

`CMAKE_PREFIX_PATH`를 명령줄에서 지정하는 예는 다음과 같습니다.

```
$ cmake -B build -S . -DCMAKE_PREFIX_PATH="C:/Qt/6.7.0/msvc2019_64"
$ cmake --build build
```

## 2.3 첫 번째 QWidget 애플리케이션

이제 실제로 창 하나를 띄우는 가장 단순한 Qt 애플리케이션을 작성해 보겠습니다. Qt의 모든 QWidgets 애플리케이션은 `QApplication` 객체를 하나 생성하는 것으로 시작합니다.

```cpp
// main.cpp
#include <QApplication>
#include <QWidget>

int main(int argc, char *argv[])
{
    // 1. 애플리케이션 객체 생성: 이벤트 루프, 스타일, 명령줄 인자 등을 관리한다.
    QApplication app(argc, argv);

    // 2. 최상위 창으로 사용할 위젯 생성
    QWidget window;
    window.setWindowTitle("나의 첫 Qt 창");
    window.resize(400, 300);

    // 3. 창을 화면에 표시
    window.show();

    // 4. 이벤트 루프 진입: 사용자 입력, 타이머, 페인트 이벤트 등을 처리한다.
    return app.exec();
}
```

이 짧은 코드에 Qt 애플리케이션의 핵심 구조가 모두 담겨 있습니다.

- **`QApplication app(argc, argv);`**: QWidgets 기반 GUI 애플리케이션에서는 반드시 `QApplication` 객체를 하나(그리고 오직 하나만) 생성해야 합니다. 이 객체는 명령줄 인자 처리, 애플리케이션 전역 설정, 그리고 무엇보다도 **이벤트 루프**를 관리합니다. `QApplication`은 반드시 `main` 함수 안에서 다른 위젯보다 먼저 생성되어야 합니다.
- **`QWidget window;`**: `QWidget`은 모든 UI 구성요소의 기반 클래스입니다. 부모 없이(즉, 다른 위젯의 자식으로 지정하지 않고) 생성된 `QWidget`은 독립된 최상위 창(top-level window)으로 취급됩니다.
- **`window.show();`**: 위젯을 화면에 표시하도록 요청합니다. `show()`를 호출하지 않으면 위젯은 메모리상에는 존재하지만 화면에 그려지지 않습니다.
- **`app.exec();`**: Qt의 이벤트 루프를 시작합니다. 이 호출은 사용자가 창을 닫거나 `QApplication::quit()`이 호출될 때까지 반환되지 않습니다. GUI 프로그램이 마우스 클릭, 키보드 입력, 창 크기 변경 등에 반응할 수 있는 것은 바로 이 이벤트 루프 덕분입니다. `main` 함수는 관례적으로 `app.exec()`의 반환값을 그대로 프로세스 종료 코드로 사용합니다.

### 이 프로젝트를 위한 CMakeLists.txt

```cmake
cmake_minimum_required(VERSION 3.16)
project(FirstWindow LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTOUIC ON)
set(CMAKE_AUTORCC ON)

find_package(Qt6 REQUIRED COMPONENTS Widgets)

qt_add_executable(FirstWindow
    main.cpp
)

target_link_libraries(FirstWindow PRIVATE Qt6::Widgets)
```

### 빌드 및 실행

```
$ cmake -B build -S .
$ cmake --build build
$ ./build/FirstWindow      # Linux/macOS
> .\build\Debug\FirstWindow.exe   # Windows (Visual Studio 생성기 사용 시)
```

정상적으로 빌드되면 제목이 "나의 첫 Qt 창"이고 크기가 400x300인 빈 창이 화면에 나타납니다. 아직 버튼이나 텍스트 같은 내용물은 없지만, 이것이 모든 Qt Widgets 애플리케이션의 출발점입니다.

### 위젯을 자식으로 추가해 보기

`QWidget`은 그 자체로는 텍스트를 표시할 수 없으므로, 자식 위젯을 하나 추가해서 실제로 뭔가 보이는 화면을 만들어 보겠습니다. `QLabel`은 텍스트나 이미지를 표시하는 가장 단순한 위젯입니다.

```cpp
// main.cpp
#include <QApplication>
#include <QWidget>
#include <QLabel>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QWidget window;
    window.setWindowTitle("나의 첫 Qt 창");
    window.resize(400, 300);

    // window를 부모로 지정하면 window의 자식 위젯이 된다.
    QLabel *label = new QLabel("Hello, Qt!", &window);
    label->move(150, 130);

    window.show();

    return app.exec();
}
```

여기서 `new QLabel("Hello, Qt!", &window)`처럼 `QLabel`을 생성할 때 두 번째 인자로 `&window`를 넘긴 점에 주목하시기 바랍니다. Qt는 부모-자식 객체 트리를 통해 메모리를 관리하는 독특한 메커니즘을 가지고 있습니다. 부모 위젯이 소멸될 때 자식 위젯도 함께 자동으로 소멸되므로, 위 코드에서 `label`을 명시적으로 `delete`할 필요가 없습니다. 이 객체 트리와 메모리 관리 방식은 이후 장에서 더 자세히 다룹니다.

## 2.4 Qt Creator 소개

Qt Creator는 The Qt Company가 제공하는 통합 개발 환경(IDE)으로, Qt 애플리케이션 개발에 특화된 여러 기능을 제공합니다.

- **Qt Designer 통합**: `.ui` 파일을 마우스로 드래그 앤 드롭하여 UI 레이아웃을 시각적으로 편집할 수 있습니다.
- **CMake/qmake 프로젝트 통합**: `CMakeLists.txt`를 열면 자동으로 프로젝트 구조를 인식하고 빌드/실행 버튼을 제공합니다.
- **디버거 통합**: GDB, LLDB, CDB 등의 디버거를 GUI로 편리하게 다룰 수 있습니다.
- **코드 자동완성**: Qt 클래스와 API에 특화된 자동완성을 제공합니다.

Qt Creator를 사용하면 특히 UI를 시각적으로 편집하거나 디버깅할 때 생산성이 크게 향상됩니다. 하지만 **Qt Creator는 필수가 아닙니다.** 이 책의 모든 예제는 Visual Studio Code, CLion, Vim 등 여느 텍스트 에디터와 CMake, 명령줄 컴파일러 조합만으로도 동일하게 따라 할 수 있도록 작성되었습니다. 어떤 도구를 사용하든 결국 우리가 다루는 대상은 표준 C++ 코드와 CMake 빌드 스크립트이기 때문입니다. 이 책에서는 특정 IDE에 종속되지 않도록 CMake 명령줄 빌드를 기준으로 설명을 이어갑니다.

## 2.5 MOC(Meta-Object Compiler)란 무엇인가

앞서 `CMakeLists.txt`에서 `set(CMAKE_AUTOMOC ON)`을 설정했습니다. 이번 절에서는 이것이 정확히 무엇을 하는지 개념적으로 살펴보겠습니다. 자세한 활용법은 시그널과 슬롯을 배우는 3장에서 이어집니다.

### 표준 C++만으로는 부족한 것

Qt의 시그널/슬롯 메커니즘, 동적 프로퍼티 시스템, `qobject_cast`를 이용한 안전한 다운캐스팅 등은 표준 C++의 문법만으로는 구현할 수 없는 기능입니다. 표준 C++는 컴파일 시점에 클래스의 이름, 함수 목록, 상속 관계 같은 메타 정보(reflection, 리플렉션)를 런타임에 조회할 방법을 제공하지 않기 때문입니다.

Qt는 이 문제를 해결하기 위해 **MOC(Meta-Object Compiler)** 라는 자체 코드 생성 도구를 사용합니다. MOC는 다음과 같은 방식으로 동작합니다.

1. 개발자가 클래스 선언에 `Q_OBJECT` 매크로를 추가하고, `signals:`나 `slots` 관련 문법(정확히는 `Q_SIGNALS`/`Q_SLOTS`의 매크로 별칭)을 사용해 클래스를 작성합니다.
2. 빌드 과정에서 MOC가 이 헤더 파일을 분석하여, 시그널/슬롯 연결과 메타 객체 정보를 다루는 추가 C++ 소스 코드(`moc_클래스이름.cpp` 형태)를 자동으로 생성합니다.
3. 이렇게 생성된 코드가 원래 코드와 함께 컴파일되어, 런타임에 `QObject::connect()`가 시그널과 슬롯을 이어주는 등의 기능이 동작할 수 있게 됩니다.

즉, MOC는 컴파일 전에 한 번 더 소스 코드를 훑으며 Qt 전용 부가 코드를 만들어내는 "전처리 컴파일러"라고 이해하면 됩니다.

### Q_OBJECT 매크로

`Q_OBJECT`는 `QObject`를 상속하는 클래스의 `private` 영역(혹은 클래스 최상단)에 넣는 매크로로, MOC에게 "이 클래스는 메타 객체 시스템을 사용하니 처리해 달라"고 알려주는 표식입니다. 시그널이나 슬롯을 선언하려는 클래스, 또는 `QObject::connect()`의 대상이 되는 클래스는 반드시 이 매크로를 포함해야 합니다.

```cpp
#include <QObject>

class Counter : public QObject
{
    Q_OBJECT   // MOC가 이 클래스를 처리하도록 표시

public:
    explicit Counter(QObject *parent = nullptr);

    int value() const { return m_value; }

signals:
    void valueChanged(int newValue);

public slots:
    void increment();

private:
    int m_value = 0;
};
```

지금 단계에서는 `signals:`와 `slots` 부분의 구체적인 의미를 전부 이해할 필요는 없습니다. 여기서 기억해야 할 핵심은 다음 두 가지입니다.

- `QObject`를 상속하면서 시그널/슬롯을 사용하려는 클래스에는 반드시 `Q_OBJECT` 매크로가 필요하다.
- `Q_OBJECT`가 포함된 클래스는 MOC가 처리해야 하므로, CMake 프로젝트에서는 `CMAKE_AUTOMOC ON` 설정이 필요하다(또는 `qt_add_executable`을 사용하면 대부분 자동으로 처리됩니다).

`Q_OBJECT` 매크로를 깜빡 잊고 시그널/슬롯 문법을 사용하면, 흔히 링크 단계에서 "undefined reference to `vtable for 클래스이름`"과 같은 다소 낯선 오류 메시지를 만나게 됩니다. 이는 MOC가 생성해야 할 코드가 생성되지 않아 발생하는 전형적인 실수이므로, 처음 Qt를 배울 때 자주 마주치는 오류 중 하나로 기억해 두면 디버깅에 도움이 됩니다.

시그널과 슬롯을 실제로 정의하고 연결하는 방법, 그리고 MOC가 생성하는 코드의 역할은 3장에서 예제와 함께 자세히 다루겠습니다.

## 요약

- Qt는 Qt Online Installer, vcpkg, 각종 리눅스/macOS 패키지 매니저 등을 통해 설치할 수 있으며, 이 책의 예제는 어떤 설치 방법을 사용해도 동일하게 동작합니다.
- Qt 6는 CMake를 공식 빌드 시스템으로 권장하며, `find_package(Qt6 REQUIRED COMPONENTS Widgets)`, `qt_add_executable`, `target_link_libraries`, `CMAKE_AUTOMOC` 등을 조합해 프로젝트를 구성합니다.
- 모든 QWidgets 애플리케이션은 `QApplication` 객체 생성, 최상위 `QWidget` 생성 및 `show()` 호출, `app.exec()`를 통한 이벤트 루프 진입이라는 공통 구조를 가집니다.
- Qt Creator는 UI 편집과 디버깅을 편리하게 해 주는 통합 개발 환경이지만 필수는 아니며, 이 책은 CMake 명령줄 빌드를 기준으로 설명합니다.
- MOC(Meta-Object Compiler)는 표준 C++가 지원하지 않는 시그널/슬롯 등의 기능을 구현하기 위해 `Q_OBJECT` 매크로가 있는 클래스를 분석하여 부가 코드를 생성하는 Qt 전용 도구입니다. 자세한 내용은 3장에서 이어집니다.

## 연습문제

1. `CMAKE_AUTOMOC`, `CMAKE_AUTOUIC`, `CMAKE_AUTORCC` 세 가지 CMake 옵션이 각각 무엇을 자동화하는지 설명하시오.
2. `QApplication` 객체는 왜 프로그램 전체에서 하나만 생성해야 하는지, `app.exec()` 호출이 하는 역할과 연관지어 설명하시오.
3. 2.3절의 두 번째 예제에서 `QLabel`을 생성할 때 부모로 `&window`를 전달했다. 이렇게 부모를 지정하는 것이 메모리 관리 측면에서 어떤 이점을 주는지 서술하시오.
4. `Q_OBJECT` 매크로를 빠뜨리고 컴파일했을 때 흔히 발생하는 오류 증상을 설명하고, 그 근본 원인을 MOC의 동작 방식과 연결지어 설명하시오.
5. Qt Creator 없이도 이 책의 예제를 따라 할 수 있는 이유를 CMake 빌드 구조의 관점에서 설명하시오.
