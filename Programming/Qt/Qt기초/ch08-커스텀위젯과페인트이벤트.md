`QPushButton`, `QLabel`, `QTableView`처럼 Qt가 미리 만들어 둔 위젯을 조합하는 것만으로 대부분의 화면은 충분히 구성할 수 있다. 하지만 온도 게이지, 파형 그래프, 커스텀 슬라이더, 진행 상태를 원형으로 보여주는 인디케이터처럼 "기존 위젯을 아무리 조합해도 만들 수 없는 화면"을 마주치는 순간이 있다. 이럴 때는 `QWidget`을 직접 상속해서, 화면에 무엇을 어떻게 그릴지를 코드로 직접 지시하는 **커스텀 위젯**을 만들어야 한다.

이번 장에서는 `QWidget`을 상속한 나만의 위젯을 만드는 기본 골격을 살펴보고, 실제로 그림을 그리는 도구인 `QPainter`의 사용법을 `drawLine()`, `drawRect()`, `drawEllipse()`, `drawText()`를 중심으로 익힌다. 이어서 화면을 다시 그려야 할 때 왜 `paintEvent()`를 직접 호출하지 않고 `update()`를 호출해야 하는지, 그리고 매끄러운 그래픽을 위한 안티앨리어싱 설정을 배운다. 마지막으로 이 모든 내용을 종합해서 막대 그래프 위젯과 원형 게이지 위젯을 직접 만들어보고, 커스텀 위젯이 레이아웃 안에서 적절한 크기를 갖도록 `sizeHint()`를 오버라이드하는 방법으로 장을 마무리한다.

## 8.1 QWidget 상속으로 나만의 위젯 만들기

Qt의 모든 위젯은 `QWidget`을 직접 또는 간접적으로 상속한다. `QPushButton`도, `QLabel`도, `QMainWindow`도 결국 `QWidget`의 자식이다. 따라서 커스텀 위젯을 만드는 가장 기본적인 방법은 `QWidget`을 상속받은 뒤, 화면에 그림을 그리는 가상 함수인 `paintEvent()`를 오버라이드하는 것이다.

```cpp
// ShapesWidget.h
#include <QWidget>

class ShapesWidget : public QWidget
{
    Q_OBJECT
public:
    explicit ShapesWidget(QWidget *parent = nullptr);

protected:
    void paintEvent(QPaintEvent *event) override;
};
```

일반 버튼이나 레이블과 달리, 커스텀 위젯은 생성자에서 특별히 할 일이 없는 경우가 많다. 실제 화면을 결정하는 코드는 대부분 `paintEvent()` 안에 들어간다.

```cpp
// ShapesWidget.cpp
#include "ShapesWidget.h"

ShapesWidget::ShapesWidget(QWidget *parent)
    : QWidget(parent)
{
    setMinimumSize(300, 180); // 너무 작게 찌그러지지 않도록 최소 크기를 지정해둔다
}
```

`paintEvent()`는 `protected` 가상 함수로 선언한다. 이 함수는 사용자 코드가 직접 호출하는 것이 아니라, Qt가 "지금 이 위젯을 다시 그려야 한다"고 판단했을 때 프레임워크 내부에서 호출해주는 함수이기 때문이다. 이 부분은 8.3절에서 자세히 다룬다.

## 8.2 paintEvent()와 QPainter로 그리기

`paintEvent()` 안에서 실제로 그림을 그리는 도구가 `QPainter`다. `QPainter`는 특정 "그리기 대상"(paint device) 위에 선, 도형, 텍스트, 이미지를 그리는 범용 2D 그래픽 API로, 그리기 대상이 위젯이든 `QImage`든 프린터든 동일한 방식으로 동작한다. 위젯에 그림을 그릴 때는 `paintEvent()` 안에서 자기 자신(`this`)을 그리기 대상으로 넘겨 `QPainter` 객체를 만든다.

```cpp
void ShapesWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);
    QPainter painter(this);

    // 이 안에서 그리기 함수를 호출한다
}
```

`QPainter painter(this);`처럼 생성자에서 곧바로 그리기 대상을 지정하면 내부적으로 `begin()`이 호출되고, `painter`가 스코프를 벗어나 소멸할 때 `end()`가 자동으로 호출된다. `paintEvent()` 함수가 끝나는 시점에 `painter`도 함께 소멸하므로, 그리기 작업은 반드시 `paintEvent()` 안에서 시작하고 끝내야 한다.

### 펜과 브러시: QPen, QBrush

도형을 그리기 전에 먼저 알아야 할 두 가지가 **펜(QPen)** 과 **브러시(QBrush)** 다.

- **QPen**은 선과 도형의 **테두리**를 그리는 방식을 결정한다. 색상, 두께, 선 스타일(실선/점선 등), 선 끝 모양을 지정할 수 있다.
- **QBrush**는 도형 **내부를 채우는** 방식을 결정한다. 단색으로 채울 수도 있고, 채우지 않을 수도 있다(`Qt::NoBrush`).

```cpp
QPen pen(Qt::darkBlue);      // 색상만 지정한 기본 펜(두께 1, 실선)
pen.setWidth(3);
pen.setStyle(Qt::SolidLine); // Qt::DashLine, Qt::DotLine 등도 가능
pen.setCapStyle(Qt::RoundCap); // 선 끝을 둥글게

QBrush brush(Qt::yellow);    // 노란색으로 채우는 브러시
```

펜과 브러시는 `painter.setPen()`, `painter.setBrush()`로 `QPainter`에 적용한 뒤, 그 이후에 호출하는 모든 그리기 함수에 계속 적용된다. 즉 한 번 설정해두면 다음에 다시 설정하기 전까지 계속 유지된다.

### drawLine: 직선 그리기

```cpp
QPen linePen(Qt::darkBlue, 3, Qt::SolidLine, Qt::RoundCap);
painter.setPen(linePen);
painter.drawLine(20, 20, 180, 20); // (x1, y1)에서 (x2, y2)까지
```

`drawLine()`은 좌표 네 개(정수) 또는 `QPoint`/`QPointF` 두 개를 받는 여러 오버로드를 제공한다.

### drawRect: 사각형 그리기

```cpp
QPen rectPen(Qt::black, 2);
QBrush rectBrush(Qt::yellow);
painter.setPen(rectPen);
painter.setBrush(rectBrush);
painter.drawRect(20, 50, 100, 60); // (x, y, width, height)
```

`drawRect()`는 `QRect`나 `QRectF`를 인자로 받는 오버로드도 있다. 브러시를 설정해두었으므로 사각형 내부가 노란색으로 채워지고, 테두리는 펜으로 지정한 검은색 2픽셀 선으로 그려진다.

### drawEllipse: 타원(원) 그리기

```cpp
painter.setBrush(QBrush(Qt::green));
painter.drawEllipse(QPoint(200, 80), 40, 30); // 중심 좌표, 가로 반지름, 세로 반지름
```

`drawEllipse()`에 사각형(`QRect`)을 넘기면 그 사각형에 내접하는 타원을 그린다. 가로/세로 반지름이 같은 값을 넘기면 정원이 된다.

### drawText: 텍스트 그리기

```cpp
painter.setPen(Qt::black);
painter.setBrush(Qt::NoBrush);
painter.drawText(QRect(20, 130, 260, 30), Qt::AlignLeft | Qt::AlignVCenter,
                  QStringLiteral("QPainter로 그린 도형들"));
```

`drawText()`는 좌표 하나에 문자열을 찍는 단순한 오버로드도 있고, 위 예제처럼 `QRect` 영역과 정렬 플래그(`Qt::AlignLeft`, `Qt::AlignCenter` 등)를 받아 그 영역 안에서 정렬해 그리는 오버로드도 있다. 텍스트는 현재 설정된 펜의 색상으로 그려지므로, 도형을 그리다가 브러시 색을 바꿔둔 채로 `drawText()`를 호출하면 의도치 않게 브러시 색이 글자 배경에 영향을 주지는 않지만(텍스트는 배경을 채우지 않는다), 펜 색은 그대로 글자색에 반영된다는 점을 기억해두자.

네 가지 함수를 모두 모으면 다음과 같은 `paintEvent()`가 완성된다.

```cpp
void ShapesWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);
    QPainter painter(this);

    // 선
    QPen linePen(Qt::darkBlue, 3, Qt::SolidLine, Qt::RoundCap);
    painter.setPen(linePen);
    painter.drawLine(20, 20, 180, 20);

    // 사각형
    painter.setPen(QPen(Qt::black, 2));
    painter.setBrush(QBrush(Qt::yellow));
    painter.drawRect(20, 50, 100, 60);

    // 타원
    painter.setBrush(QBrush(Qt::green));
    painter.drawEllipse(QPoint(200, 80), 40, 30);

    // 텍스트
    painter.setPen(Qt::black);
    painter.setBrush(Qt::NoBrush);
    painter.drawText(QRect(20, 130, 260, 30), Qt::AlignLeft | Qt::AlignVCenter,
                      QStringLiteral("QPainter로 그린 도형들"));
}
```

## 8.3 다시 그리기 요청: update()

커스텀 위젯이 보여주는 내용이 시간에 따라 바뀐다고 해보자. 예를 들어 온도 값이 바뀌었으니 게이지 바늘을 새로 그려야 하는 상황이다. 이때 절대로 `paintEvent()`를 직접 호출해서는 안 된다.

```cpp
// 잘못된 예
void GaugeWidget::setValue(int value)
{
    m_value = value;
    QPaintEvent fakeEvent(rect());
    paintEvent(&fakeEvent); // 하지 말아야 할 방식
}
```

`paintEvent()`는 Qt가 화면을 실제로 그려야 하는 시점에, 플랫폼의 그리기 시스템(백버퍼, 클리핑 영역 등)이 준비된 상태에서 호출해주는 함수다. 이런 준비 과정 없이 함수를 그냥 호출하면 `QPainter`가 올바른 그리기 대상을 찾지 못해 오류를 내거나, 화면에 실제로는 반영되지 않는 상태가 될 수 있다.

올바른 방법은 `update()`를 호출해서 "이 위젯을 다시 그려야 한다"는 사실만 Qt에게 알려주는 것이다.

```cpp
void GaugeWidget::setValue(int value)
{
    m_value = qBound(0, value, 100);
    update(); // paintEvent()를 나중에 다시 호출해달라고 예약한다
}
```

`update()`를 호출하면 Qt는 즉시 화면을 다시 그리지 않는다. 대신 "이 위젯은 다시 그려야 함"이라고 표시만 해두고, 현재 실행 중인 이벤트 루프가 다음 차례가 되었을 때 실제로 `paintEvent()`를 호출한다. 이 방식에는 중요한 이점이 있다. 짧은 시간 안에 `update()`가 여러 번 호출되더라도, Qt는 이를 하나의 `paintEvent()` 호출로 합쳐서 처리한다. 예를 들어 반복문 안에서 값을 여러 번 바꾸면서 매번 `update()`를 호출해도, 실제 화면 다시 그리기는 반복문이 끝난 뒤 한 번만 일어난다. 덕분에 불필요한 반복 렌더링으로 인한 성능 낭비와 화면 깜빡임을 피할 수 있다.

Qt는 `update()`와 비슷하지만 즉시 동기적으로 다시 그리는 `repaint()`도 제공한다. `repaint()`는 호출하는 즉시 `paintEvent()`를 실행하고 나서야 반환되므로, 여러 번 연달아 호출하면 그만큼 여러 번 화면이 다시 그려져 성능에 불리하고 화면이 깜빡일 수 있다. 실무에서는 특별한 이유가 없는 한 `update()`를 사용하고, 애니메이션이 아닌 정말로 그 자리에서 즉시 화면 갱신을 보장해야 하는 드문 경우에만 `repaint()`를 고려한다.

## 8.4 매끄러운 그래픽을 위한 안티앨리어싱

기본 설정 상태의 `QPainter`는 대각선이나 곡선을 그릴 때 픽셀 경계가 계단처럼 울퉁불퉁하게 보이는 경우가 있다. 이는 렌더링 성능을 우선시한 기본값 때문인데, `setRenderHint()`로 안티앨리어싱(anti-aliasing)을 켜면 경계 부분에 중간 색상을 섞어 넣어 훨씬 매끄럽게 보이도록 만들 수 있다.

```cpp
QPainter painter(this);
painter.setRenderHint(QPainter::Antialiasing, true);
```

`QPainter::Antialiasing`은 도형의 테두리(선, 곡선, 원)를 부드럽게 그리는 힌트다. 이 외에도 `QPainter::TextAntialiasing`(텍스트 안티앨리어싱, 기본적으로 켜져 있음)과 `QPainter::SmoothPixmapTransform`(이미지를 확대/축소할 때 부드럽게 보간)이 있으며, 필요에 따라 `|`로 여러 힌트를 조합해 켤 수 있다.

```cpp
painter.setRenderHints(QPainter::Antialiasing | QPainter::SmoothPixmapTransform);
```

안티앨리어싱은 특히 `drawEllipse()`로 그린 원이나 기울어진 `drawLine()`에서 효과가 두드러진다. 다만 픽셀마다 색을 섞어 계산해야 하므로 켜지 않았을 때보다 그리기 비용이 늘어난다. 대부분의 데스크톱 애플리케이션에서는 체감할 수 있는 성능 차이가 거의 없으므로, 시각적 품질이 중요한 커스텀 위젯이라면 기본적으로 켜두는 것을 권장한다. 반대로 수만 개의 도형을 매 프레임 다시 그려야 하는 것처럼 성능이 민감한 상황이라면 꺼두고 측정해보는 편이 안전하다.

## 8.5 실전 예제: 막대 그래프 위젯

지금까지 배운 내용을 종합해서, 정수 값의 목록을 세로 막대 그래프로 보여주는 `BarChartWidget`을 만들어보자.

```cpp
// BarChartWidget.h
#include <QWidget>
#include <QVector>

class BarChartWidget : public QWidget
{
    Q_OBJECT
public:
    explicit BarChartWidget(QWidget *parent = nullptr);

    void setValues(const QVector<int> &values);

protected:
    void paintEvent(QPaintEvent *event) override;

private:
    QVector<int> m_values;
};
```

```cpp
// BarChartWidget.cpp
#include "BarChartWidget.h"
#include <QPainter>
#include <algorithm>

BarChartWidget::BarChartWidget(QWidget *parent)
    : QWidget(parent)
{
    setMinimumSize(240, 160);
}

void BarChartWidget::setValues(const QVector<int> &values)
{
    m_values = values;
    update(); // 데이터가 바뀌었으니 다시 그려달라고 요청한다
}

void BarChartWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);

    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);
    painter.fillRect(rect(), Qt::white);

    if (m_values.isEmpty())
        return;

    const int maxValue = *std::max_element(m_values.begin(), m_values.end());
    if (maxValue <= 0)
        return;

    const int margin = 20;
    const int labelHeight = 16;
    const int chartHeight = height() - margin * 2 - labelHeight;
    const int chartWidth = width() - margin * 2;
    const int barCount = m_values.size();
    const int gap = 8;
    const int barWidth = (chartWidth - gap * (barCount - 1)) / barCount;

    painter.setPen(QPen(Qt::black, 1));
    painter.setBrush(QBrush(QColor(70, 130, 200)));

    for (int i = 0; i < barCount; ++i) {
        const int value = m_values.at(i);
        const int barHeight = static_cast<int>(chartHeight * (double(value) / maxValue));
        const int x = margin + i * (barWidth + gap);
        const int y = margin + (chartHeight - barHeight);

        painter.drawRect(QRect(x, y, barWidth, barHeight));
        painter.drawText(QRect(x, margin + chartHeight + 2, barWidth, labelHeight),
                          Qt::AlignHCenter, QString::number(value));
    }
}
```

이 위젯을 사용하는 쪽 코드는 아래처럼 값 목록만 넘겨주면 된다.

```cpp
BarChartWidget *chart = new BarChartWidget(this);
chart->setValues({42, 88, 15, 63, 97});
```

`paintEvent()`는 매번 처음부터 전체 그래프를 새로 계산해서 그린다. 데이터 개수가 적당한 수준(수백 개 이하)이라면 이런 방식으로도 충분히 빠르게 동작하며, 별도로 이전에 그린 내용을 캐시해둘 필요가 없다. `setValues()`가 `update()`만 호출하고 실제로 다시 그리는 시점은 Qt의 이벤트 루프에 맡긴다는 점도 8.3절의 내용을 그대로 따르고 있다.

## 8.6 실전 예제: 반원형 게이지 위젯

이번에는 0~100 사이의 값을 반원형 게이지로 보여주는 `GaugeWidget`을 만들어본다. 자동차 계기판이나 대시보드에서 흔히 보는 형태다.

```cpp
// GaugeWidget.h
#include <QWidget>
#include <QColor>

class GaugeWidget : public QWidget
{
    Q_OBJECT
public:
    explicit GaugeWidget(QWidget *parent = nullptr);

    int value() const { return m_value; }
    void setValue(int value);

protected:
    void paintEvent(QPaintEvent *event) override;

private:
    QColor colorForValue(int value) const;

    int m_value = 0;
};
```

```cpp
// GaugeWidget.cpp
#include "GaugeWidget.h"
#include <QPainter>

GaugeWidget::GaugeWidget(QWidget *parent)
    : QWidget(parent)
{
    setMinimumSize(160, 160);
}

void GaugeWidget::setValue(int value)
{
    const int clamped = qBound(0, value, 100);
    if (clamped == m_value)
        return;

    m_value = clamped;
    update();
}

QColor GaugeWidget::colorForValue(int value) const
{
    if (value < 50)
        return QColor(60, 170, 90);   // 녹색: 여유 구간
    if (value < 80)
        return QColor(230, 160, 40);  // 주황색: 주의 구간
    return QColor(200, 60, 60);       // 빨간색: 경고 구간
}

void GaugeWidget::paintEvent(QPaintEvent *event)
{
    Q_UNUSED(event);

    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    const int margin = 12;
    QRectF arcRect = rect().adjusted(margin, margin, -margin, -margin);
    const qreal side = qMin(arcRect.width(), arcRect.height());
    arcRect.setWidth(side);
    arcRect.setHeight(side);

    const int startAngle = 180 * 16; // 9시 방향에서 시작 (각도 단위는 1/16도)
    const int fullSpan = -180 * 16;  // 시계 방향으로 180도 회전해서 3시 방향까지

    // 배경 아크: 전체 눈금
    QPen backgroundPen(QColor(220, 220, 220));
    backgroundPen.setWidth(14);
    backgroundPen.setCapStyle(Qt::FlatCap);
    painter.setPen(backgroundPen);
    painter.drawArc(arcRect, startAngle, fullSpan);

    // 값 아크: 현재 값만큼만 그린다
    const int valueSpan = static_cast<int>(fullSpan * (m_value / 100.0));
    QPen valuePen(colorForValue(m_value));
    valuePen.setWidth(14);
    valuePen.setCapStyle(Qt::FlatCap);
    painter.setPen(valuePen);
    painter.drawArc(arcRect, startAngle, valueSpan);

    // 가운데에 퍼센트 텍스트
    painter.setPen(Qt::black);
    QFont font = painter.font();
    font.setPointSize(16);
    font.setBold(true);
    painter.setFont(font);
    painter.drawText(rect(), Qt::AlignCenter, QStringLiteral("%1%").arg(m_value));
}
```

`drawArc()`는 사각형(`arcRect`)에 내접하는 타원의 일부 구간만 그리는 함수로, 각도는 3시 방향을 0도로 삼아 반시계 방향을 양수로 계산한다. 즉 `startAngle`을 180도(9시 방향)로 잡고 `spanAngle`을 -180도로 주면, 9시 방향에서 시작해 시계 방향으로 반 바퀴를 돌아 3시 방향까지, 다시 말해 위쪽 반원을 그리게 된다. 배경 아크를 연한 회색으로 전체 180도 그려서 "눈금판"을 만든 뒤, 그 위에 현재 값에 비례하는 각도만큼만 색이 있는 아크를 겹쳐 그려서 게이지 효과를 낸다. `colorForValue()`는 값의 구간에 따라 다른 색을 반환해서, 값이 높아질수록 경고성 색으로 바뀌는 효과를 더했다.

이 위젯을 실제로 사용할 때는 값이 바뀔 때마다 `setValue()`를 호출하기만 하면 된다.

```cpp
GaugeWidget *gauge = new GaugeWidget(this);
gauge->setValue(72); // 내부에서 update()가 호출되어 화면이 갱신된다
```

## 8.7 레이아웃에게 적정 크기 알려주기: sizeHint()

지금까지 만든 `GaugeWidget`이나 `BarChartWidget`을 `resize()`로 직접 크기를 지정해서 쓴다면 별문제가 없다. 하지만 레이아웃(`QVBoxLayout`, `QGridLayout` 등)에 위젯을 추가하면 상황이 다르다. 레이아웃은 각 위젯이 얼마나 큰 공간을 차지해야 자연스러운지 알기 위해 위젯의 `sizeHint()` 함수를 호출해서 물어본다. `QWidget`의 기본 `sizeHint()` 구현은 특별한 정보를 담고 있지 않은 유효하지 않은 크기(`QSize(-1, -1)`)를 반환하므로, 오버라이드하지 않은 커스텀 위젯을 레이아웃에 넣으면 필요 이상으로 작게 표시되거나, 다른 위젯들 사이에서 크기가 어색하게 정해질 수 있다.

`sizeHint()`를 오버라이드해서 위젯이 스스로 "이 정도 크기가 이상적이다"라고 알려주면, 레이아웃은 특별한 제약이 없는 한 이 값을 참고해서 위젯의 초기 크기를 정한다.

```cpp
// GaugeWidget.h에 추가
public:
    QSize sizeHint() const override;
```

```cpp
QSize GaugeWidget::sizeHint() const
{
    return QSize(180, 180); // 정사각형에 가까운 형태가 게이지에 가장 자연스럽다
}
```

`BarChartWidget`에도 같은 방식으로 적용할 수 있다.

```cpp
QSize BarChartWidget::sizeHint() const
{
    return QSize(320, 200);
}
```

`sizeHint()`가 반환하는 값은 어디까지나 "권장 크기"이며, 실제로 위젯이 그 크기로 고정되는 것은 아니다. 레이아웃은 `sizeHint()` 외에도 `minimumSizeHint()`(최소 허용 크기)와 `QSizePolicy`(공간이 남거나 부족할 때 어떻게 늘어나거나 줄어들지)를 함께 고려해서 최종 크기를 결정한다. 생성자에서 호출했던 `setMinimumSize()`가 최소 크기의 하한선을 강제로 지정하는 것이라면, `sizeHint()`는 "강제하지는 않지만 이 정도면 적당하다"는 힌트를 주는 것이라는 차이를 기억해두자.

## 요약

- 기존 위젯의 조합만으로 표현할 수 없는 화면은 `QWidget`을 상속하고 `paintEvent()`를 오버라이드해서 직접 그린다.
- `paintEvent()` 안에서 `QPainter painter(this);`로 그리기 도구를 만들고, `drawLine()`, `drawRect()`, `drawEllipse()`, `drawText()`로 도형과 텍스트를 그린다. 테두리는 `QPen`이, 내부 채우기는 `QBrush`가 결정한다.
- 화면을 다시 그려야 할 때는 `paintEvent()`를 직접 호출하지 말고 `update()`를 호출한다. `update()`는 다시 그리기를 예약만 하고, 짧은 시간에 여러 번 호출되어도 실제 `paintEvent()` 호출은 한 번으로 합쳐진다. 즉시 동기적으로 다시 그려야 하는 드문 경우에는 `repaint()`를 사용한다.
- `painter.setRenderHint(QPainter::Antialiasing, true)`를 설정하면 곡선과 대각선의 경계가 매끄럽게 그려지지만, 계산 비용이 늘어난다는 트레이드오프가 있다.
- 막대 그래프 위젯과 반원형 게이지 위젯 예제를 통해 데이터 값을 좌표와 각도로 환산해서 도형으로 표현하는 방법을 익혔다.
- `sizeHint()`를 오버라이드하면 커스텀 위젯이 레이아웃 안에서 자연스러운 기본 크기를 갖도록 만들 수 있다. `sizeHint()`는 강제가 아닌 권장값이며, 최소 크기는 `setMinimumSize()`나 `minimumSizeHint()`로 별도로 관리된다.

## 연습문제

1. `paintEvent()`를 직접 호출하는 방식과 `update()`를 호출하는 방식의 차이를, 호출 시점과 여러 번 호출했을 때의 동작 차이를 근거로 설명하시오.
2. `QPen`과 `QBrush`의 역할 차이를 설명하고, 테두리는 검은색 2픽셀 실선이면서 내부는 채우지 않는(투명한) 사각형을 그리는 코드를 작성하시오.
3. `painter.setRenderHint(QPainter::Antialiasing, true)`를 켰을 때와 끄지 않았을 때, `drawEllipse()`로 그린 원의 테두리가 어떻게 다르게 보이는지 설명하고, 안티앨리어싱을 켜는 것이 항상 유리하지는 않은 상황을 하나 제시하시오.
4. 본문의 `GaugeWidget`에서 `sizeHint()`를 오버라이드하지 않았다고 가정할 때, 이 위젯을 `QVBoxLayout`에 추가하면 어떤 문제가 생길 수 있는지 `QWidget::sizeHint()`의 기본 동작을 근거로 설명하시오.
5. `BarChartWidget::setValues()`에 음수 값이 포함된 `QVector<int>`가 들어왔을 때 현재 `paintEvent()` 구현이 어떻게 동작하는지 분석하고, 음수 값을 그래프에서 안전하게 처리하도록 코드를 수정하시오.
