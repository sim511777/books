3장까지는 창 하나, 위젯 하나, 버튼 하나 정도의 아주 작은 예제로 시그널과 슬롯의 개념을 익혔습니다. 하지만 실제 애플리케이션의 화면은 텍스트 입력창, 체크박스, 콤보박스처럼 여러 종류의 위젯이 한 화면에 여러 개 모여 있고, 창 크기가 바뀌어도 그 배치가 자연스럽게 따라 움직여야 합니다. 이 장에서는 QWidgets가 기본으로 제공하는 대표적인 입력 위젯들을 살펴보고, 이 위젯들을 화면에 자동으로 배치해 주는 레이아웃 시스템을 익힙니다. 그리고 그 바탕에 깔려 있는 Qt의 부모-자식 객체 트리와 메모리 관리 방식도 함께 정리합니다.

## 4.1 QWidget의 부모-자식 관계와 메모리 관리

Qt는 표준 C++의 스마트 포인터(`std::unique_ptr`, `std::shared_ptr`)와는 다른, Qt 고유의 메모리 관리 방식을 가지고 있습니다. 바로 `QObject`의 **부모-자식 객체 트리(object tree)** 입니다. `QWidget`은 `QObject`를 상속하므로 이 메커니즘을 그대로 물려받습니다.

### 객체 트리의 동작 원리

`QObject`(그리고 `QWidget`)를 생성할 때는 생성자의 마지막 인자로 부모 객체를 지정할 수 있습니다.

```cpp
QWidget *window = new QWidget();               // 부모 없음: 최상위 창
QPushButton *button = new QPushButton(window);  // window를 부모로 지정
```

부모를 지정하면 다음 두 가지 일이 함께 일어납니다.

1. **소유권(ownership)**: `window`가 파괴될 때 `button`도 함께 자동으로 `delete`됩니다. 자식을 명시적으로 `delete`할 필요가 없습니다.
2. **화면상의 포함 관계**: `QWidget`의 경우, 부모가 지정된 자식 위젯은 부모 위젯의 좌표계 안에 그려지는 자식 창(child widget)이 됩니다. 부모 없이 생성된 `QWidget`은 운영체제 관점에서 독립된 최상위 창(top-level window)으로 취급됩니다.

`QObject`의 소멸자는 자신의 자식 목록(`children()`)을 순회하며 각 자식을 `delete`합니다. 이 과정이 트리 구조를 따라 재귀적으로 일어나므로, 최상위 창 하나만 `delete`하면 그 창에 속한 수십, 수백 개의 자식 위젯이 모두 연쇄적으로 정리됩니다. 아래 예제에서 `label`과 `button`을 개발자가 직접 `delete`하는 코드는 어디에도 없다는 점에 주목하기 바랍니다.

```cpp
#include <QApplication>
#include <QWidget>
#include <QLabel>
#include <QPushButton>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    QWidget *window = new QWidget();
    window->setWindowTitle("객체 트리 예제");

    QLabel *label = new QLabel("안녕하세요", window);
    QPushButton *button = new QPushButton("닫기", window);
    label->move(20, 20);
    button->move(20, 60);

    QObject::connect(button, &QPushButton::clicked, window, &QWidget::close);

    window->resize(200, 120);
    window->show();

    int result = app.exec();
    delete window;   // label, button은 여기서 함께 자동 소멸된다.
    return result;
}
```

### 부모를 지정할 때와 지정하지 않을 때

부모를 지정하지 않고 생성한 `QObject`(또는 `QWidget`)는 스스로 수명을 관리해야 합니다. 스택에 값으로 선언하면 스코프를 벗어날 때 자동으로 소멸되고, `new`로 힙에 만들었다면 개발자가 어딘가에서 반드시 `delete`해 주어야 메모리 누수가 생기지 않습니다. 반대로 부모가 있는 자식 위젯을 스택에 값으로 선언해 놓고 부모도 나중에 `delete`되도록 두면, 스코프가 끝나면서 자식이 한 번 소멸되고 부모 소멸자가 다시 그 자식을 `delete`하려 시도하면서 이미 해제된 메모리를 또 건드리는 문제가 생길 수 있습니다. 그래서 다음과 같은 원칙을 기억해 두면 됩니다.

- 부모가 있는(다른 위젯 안에 들어가는) 위젯은 항상 `new`로 힙에 생성하고, 부모에게 소멸을 맡깁니다.
- 부모가 없는(즉 최상위 창이 되는) 위젯은 `main` 함수의 스택에 값으로 두거나, `new`로 만들고 프로그램이 종료되는 시점에 직접 정리합니다.

### setParent()와 findChild()

생성 시점이 아니라 나중에 부모를 바꾸고 싶다면 `setParent()`를 사용합니다.

```cpp
label->setParent(newContainer);
```

부모가 가지고 있는 자식 목록은 `QObject::children()`으로 조회할 수 있고, 특정 타입과 이름을 가진 자손을 찾을 때는 `findChild<T*>()`, `findChildren<T*>()`를 사용합니다.

```cpp
QPushButton *closeButton = window->findChild<QPushButton *>("closeButton");
```

이 함수가 이름으로 자식을 찾을 수 있는 이유는 `QObject`가 `setObjectName()`으로 지정한 문자열 이름을 가질 수 있기 때문입니다. Qt Designer가 만든 `.ui` 파일에서 위젯을 이름으로 참조할 때도 내부적으로 이 메커니즘이 쓰입니다.

### deleteLater()

시그널을 처리하는 슬롯 안에서 그 시그널을 보낸 객체 자신을 `delete`하는 것은 위험합니다. 아직 그 객체의 다른 코드가 실행 중일 수 있기 때문입니다. 이런 상황을 위해 Qt는 `deleteLater()`라는 지연 삭제 함수를 제공합니다.

```cpp
connect(button, &QPushButton::clicked, dialog, &QObject::deleteLater);
```

`deleteLater()`를 호출하면 객체가 즉시 삭제되지 않고, 이벤트 루프가 현재 처리 중인 이벤트를 모두 끝내고 제어권을 돌려받는 시점에 안전하게 삭제됩니다. 지금 단계에서는 "즉시 지우면 위험할 수 있는 상황에서는 `delete` 대신 `deleteLater()`를 쓴다" 정도로만 기억해 두어도 충분합니다.

## 4.2 기본 위젯 둘러보기

QtWidgets 모듈은 수십 가지의 위젯 클래스를 제공하지만, 그중에서도 거의 모든 애플리케이션에서 쓰이는 기본 위젯 여덟 가지를 살펴보겠습니다. 모든 예제는 `#include <QtWidgets>`처럼 한꺼번에 포함하는 대신, 실제 사용하는 클래스별로 헤더를 개별 포함하는 것을 권장합니다. 컴파일 시간이 짧아지고, 어떤 클래스를 어느 모듈에서 가져왔는지 코드만 보고 알 수 있기 때문입니다.

### QPushButton

눌러서 동작을 실행시키는 표준 버튼입니다.

```cpp
#include <QPushButton>

auto *button = new QPushButton("저장");
button->setEnabled(true);      // 활성/비활성 여부
button->setDefault(true);      // Enter 키로 눌리는 기본 버튼으로 지정(다이얼로그에서 주로 사용)
button->setCheckable(true);    // 토글 버튼처럼 눌린 상태를 유지하게 함

connect(button, &QPushButton::clicked, this, &MainWindow::onSave);
```

`clicked()` 시그널은 실제로는 `clicked(bool checked = false)`라는 시그니처를 가지고 있습니다. `setCheckable(true)`로 설정하지 않은 일반 버튼이라면 `checked` 값은 항상 `false`로 무시해도 되지만, 이 시그니처를 신경 쓰지 않고 `int` 하나를 받는 슬롯에 실수로 연결하면 클릭 시마다 `bool`이 `int`로 암묵 변환되어 예상치 못한 값이 전달될 수 있습니다. 함수 포인터 문법으로 연결하면 이런 타입 불일치는 대부분 컴파일 오류로 걸러지므로, 이 역시 문자열 기반 옛 문법보다 함수 포인터 문법을 선호할 이유 중 하나입니다.

### QLabel

텍스트나 이미지를 표시하기만 하는, 사용자 입력을 받지 않는 위젯입니다.

```cpp
#include <QLabel>

auto *label = new QLabel("이름:");
label->setAlignment(Qt::AlignRight | Qt::AlignVCenter);
label->setWordWrap(true);            // 긴 텍스트를 위젯 너비에 맞춰 자동 줄바꿈
label->setPixmap(QPixmap(":/icons/logo.png"));  // 이미지 표시(텍스트 대신)
```

`QLabel`은 자체적으로 시그널을 거의 발생시키지 않는 수동적인 위젯입니다. 다만 `setText()`로 표시 내용을 바꾸는 용도로 다른 위젯의 시그널을 받는 슬롯 자리에 자주 등장합니다(3장의 `Counter` 예제를 떠올려 보시기 바랍니다).

### QLineEdit

한 줄짜리 텍스트를 입력받는 위젯입니다.

```cpp
#include <QLineEdit>

auto *edit = new QLineEdit();
edit->setPlaceholderText("이메일을 입력하세요");
edit->setMaxLength(64);
edit->setEchoMode(QLineEdit::Password);   // 비밀번호 입력창처럼 문자를 가려서 표시

connect(edit, &QLineEdit::textChanged, this, &MainWindow::onEmailChanged);
connect(edit, &QLineEdit::returnPressed, this, &MainWindow::onEmailSubmitted);

QString text = edit->text();
```

`textChanged(const QString &text)`는 사용자가 입력하는 매 글자마다, 또는 코드에서 `setText()`를 호출해도 발생합니다. 반면 `textEdited(const QString &text)`는 사용자의 직접 타이핑에 의해서만 발생하고, `setText()`를 호출해서 값이 바뀌었을 때는 발생하지 않습니다. 두 시그널의 차이를 몰라서 "코드로 값을 설정했을 뿐인데 왜 텍스트가 또 바뀐 것처럼 슬롯이 호출되지?" 하는 무한 루프에 빠지는 경우가 종종 있으므로 구분해 기억해 두는 것이 좋습니다.

### QCheckBox

체크/비체크 두 상태(또는 세 상태)를 가지는 위젯입니다.

```cpp
#include <QCheckBox>

auto *agree = new QCheckBox("이용약관에 동의합니다");
agree->setChecked(false);

connect(agree, &QCheckBox::toggled, this, &MainWindow::onAgreeToggled);

bool checked = agree->isChecked();
```

`toggled(bool checked)`는 `QCheckBox`가 상속하는 `QAbstractButton`이 제공하는 시그널로, 체크 상태가 사용자 조작이든 코드에 의해서든 바뀔 때마다 발생합니다. `QCheckBox`는 `setTristate(true)`로 체크/비체크 외에 "부분 선택(partially checked)" 상태까지 표현할 수 있으며, 이 세 가지 상태 전체를 다루려면 `stateChanged(int)` 시그널과 `Qt::CheckState` 값(`Qt::Unchecked`, `Qt::PartiallyChecked`, `Qt::Checked`)을 사용합니다. 단순한 켜기/끄기 용도라면 `toggled(bool)`만으로 충분합니다.

### QRadioButton

여러 선택지 중 하나만 고르는 위젯입니다. 같은 부모 위젯 안에 여러 `QRadioButton`을 두면, Qt가 같은 부모를 공유하는 라디오 버튼들을 자동으로 하나의 그룹으로 취급하여 그중 하나만 선택되도록 상호 배타적으로 동작시킵니다.

```cpp
#include <QRadioButton>

auto *sizeSmall = new QRadioButton("소");
auto *sizeMedium = new QRadioButton("중");
auto *sizeLarge = new QRadioButton("대");
sizeMedium->setChecked(true);   // 기본 선택값

connect(sizeLarge, &QRadioButton::toggled, this, [this](bool checked) {
    if (checked)
        onSizeSelected("대");
});
```

라디오 버튼들을 시각적으로는 같은 부모 아래 두지 않으면서도 논리적으로는 하나의 그룹으로 묶고 싶을 때는 `QButtonGroup`을 사용합니다. `QButtonGroup`은 위젯이 아니라 여러 버튼을 논리적으로 묶어 주는 관리용 객체이며, `addButton()`으로 버튼을 등록하고 `buttonClicked()` 계열 시그널로 어떤 버튼이 선택되었는지 한 곳에서 받을 수 있습니다. 이 책에서는 6장 이후 다이얼로그를 다루면서 `QButtonGroup`을 실제로 활용하는 예제를 다시 살펴봅니다.

### QComboBox

여러 항목 중 하나를 드롭다운 목록에서 고르는 위젯입니다.

```cpp
#include <QComboBox>

auto *combo = new QComboBox();
combo->addItem("일반 회원");
combo->addItem("기업 회원");
combo->addItems({"학생 회원", "관리자"});

combo->setCurrentIndex(0);

connect(combo, &QComboBox::currentIndexChanged, this, &MainWindow::onMembershipChanged);
connect(combo, &QComboBox::currentTextChanged, this, [](const QString &text) {
    qDebug() << "선택됨:" << text;
});

QString selected = combo->currentText();
```

`QComboBox`는 기본적으로 목록에서 고르기만 하는 위젯이지만, `setEditable(true)`를 호출하면 사용자가 직접 텍스트를 입력할 수 있는 자동완성형 입력창처럼 동작시킬 수도 있습니다.

### QSlider

정해진 범위 안에서 값을 손으로 끌어 조절하는 위젯입니다.

```cpp
#include <QSlider>

auto *volume = new QSlider(Qt::Horizontal);
volume->setRange(0, 100);
volume->setValue(50);
volume->setSingleStep(1);
volume->setTickPosition(QSlider::TicksBelow);
volume->setTickInterval(10);

connect(volume, &QSlider::valueChanged, this, &MainWindow::onVolumeChanged);
```

생성자 인자로 `Qt::Horizontal` 또는 `Qt::Vertical`을 넘겨 가로/세로 방향을 정합니다. `valueChanged(int value)`는 값이 바뀔 때마다(드래그 도중에도 계속) 발생하며, 드래그가 끝나는 순간만 알고 싶다면 `sliderReleased()` 시그널을 함께 활용합니다.

### QSpinBox

정해진 범위의 정수를 화살표 버튼이나 직접 입력으로 조절하는 위젯입니다.

```cpp
#include <QSpinBox>

auto *age = new QSpinBox();
age->setRange(0, 120);
age->setValue(20);
age->setSingleStep(1);
age->setSuffix(" 세");
age->setPrefix("나이: ");

connect(age, &QSpinBox::valueChanged, this, &MainWindow::onAgeChanged);
```

소수를 다루어야 한다면 `QSpinBox` 대신 `QDoubleSpinBox`를 사용합니다. 사용법은 거의 동일하며 `setDecimals()`로 소수점 이하 자릿수를 지정할 수 있다는 점만 다릅니다.

## 4.3 레이아웃 매니저: QVBoxLayout과 QHBoxLayout

지금까지의 예제에서는 `move()`로 위젯의 위치를 픽셀 단위로 직접 지정했습니다. 이 방식은 위젯이 두세 개뿐인 예제에서는 통하지만, 창 크기가 바뀌거나 위젯 개수가 늘어나면 금방 한계에 부딪힙니다. 실무에서는 대신 **레이아웃 매니저(layout manager)** 를 사용해 위젯의 배치를 Qt에게 맡깁니다.

`QVBoxLayout`은 위젯을 위에서 아래로, `QHBoxLayout`은 왼쪽에서 오른쪽으로 순서대로 쌓아 배치합니다. 둘 다 공통 조상인 `QBoxLayout`의 인터페이스를 그대로 물려받습니다.

```cpp
#include <QWidget>
#include <QVBoxLayout>
#include <QPushButton>
#include <QLabel>

QWidget *window = new QWidget();
auto *layout = new QVBoxLayout(window);   // window에 이 레이아웃을 즉시 설정

auto *title = new QLabel("설정");
auto *okButton = new QPushButton("확인");
auto *cancelButton = new QPushButton("취소");

layout->addWidget(title);
layout->addStretch();          // 남는 공간을 여기서 모두 흡수
layout->addWidget(okButton);
layout->addWidget(cancelButton);

layout->setContentsMargins(12, 12, 12, 12);  // 레이아웃 바깥 여백
layout->setSpacing(8);                       // 위젯 사이 간격

window->resize(240, 200);
window->show();
```

여기서 눈여겨볼 부분이 두 가지 있습니다.

- `new QVBoxLayout(window)`처럼 레이아웃을 생성할 때 위젯을 인자로 넘기면, 그 레이아웃이 곧바로 `window`의 레이아웃으로 설정됩니다(`window->setLayout(layout)`을 따로 호출한 것과 같은 효과입니다).
- `layout->addWidget(title)`처럼 위젯을 레이아웃에 추가할 때, `title`을 생성할 때 부모를 지정하지 않았다는 점입니다. `addWidget()`이 호출되는 순간 Qt는 그 위젯을 이 레이아웃이 속한 위젯(`window`)의 자식으로 자동으로 재지정(reparent)해 줍니다. 그래서 레이아웃과 함께 위젯을 쓸 때는 생성자에 부모를 넘기지 않고, 레이아웃에 추가하는 것만으로 부모-자식 관계와 소유권까지 한 번에 해결하는 방식이 일반적입니다.

가로/세로 레이아웃은 서로 중첩해서 복잡한 배치를 만들 수 있습니다. `addLayout()`으로 레이아웃 안에 다른 레이아웃을 넣습니다.

```cpp
auto *outer = new QVBoxLayout(window);
auto *buttonRow = new QHBoxLayout();

buttonRow->addStretch();
buttonRow->addWidget(okButton);
buttonRow->addWidget(cancelButton);

outer->addWidget(title);
outer->addStretch();
outer->addLayout(buttonRow);   // 세로 레이아웃 안에 가로 레이아웃을 끼워 넣는다.
```

이 코드는 제목은 위쪽에 두고, 확인/취소 버튼 두 개는 오른쪽 정렬된 채로 아래쪽 한 줄에 나란히 배치합니다. 대부분의 실전 화면은 이렇게 `QVBoxLayout`과 `QHBoxLayout`을 여러 겹 중첩해서 구성됩니다.

## 4.4 QGridLayout과 QFormLayout

위젯을 표 형태(행과 열)로 배치하고 싶다면 `QGridLayout`이 적합합니다.

```cpp
#include <QGridLayout>
#include <QLineEdit>
#include <QLabel>

auto *grid = new QGridLayout(window);

grid->addWidget(new QLabel("이름:"), 0, 0);
grid->addWidget(new QLineEdit(),     0, 1);
grid->addWidget(new QLabel("이메일:"), 1, 0);
grid->addWidget(new QLineEdit(),     1, 1);

// 4번째 인자, 5번째 인자로 여러 행/열에 걸친 위젯도 배치할 수 있다.
auto *note = new QLabel("가입 즉시 이용 가능합니다.");
grid->addWidget(note, 2, 0, 1, 2);   // 2행 0열부터 1행 2열 크기로 병합

grid->setColumnStretch(1, 1);   // 1번 열(입력창 열)이 남는 공간을 더 많이 차지하도록
```

`addWidget(widget, row, column, rowSpan, columnSpan)`처럼 행/열 병합 범위까지 지정할 수 있어, 표 형태이면서도 일부 셀이 여러 칸을 차지하는 배치를 자유롭게 만들 수 있습니다.

"레이블 + 입력 위젯"이 반복되는 전형적인 입력 폼이라면, `QGridLayout`을 직접 쓰는 대신 그 목적에 특화된 `QFormLayout`을 쓰는 편이 코드가 훨씬 간결해집니다.

```cpp
#include <QFormLayout>
#include <QLineEdit>
#include <QComboBox>

auto *form = new QFormLayout(window);

auto *nameEdit = new QLineEdit();
auto *emailEdit = new QLineEdit();
auto *typeCombo = new QComboBox();
typeCombo->addItems({"일반 회원", "기업 회원"});

form->addRow("이름", nameEdit);
form->addRow("이메일", emailEdit);
form->addRow("회원 유형", typeCombo);
```

`addRow(label, field)`는 내부적으로 문자열을 `QLabel`로 감싸고, 그 레이블과 필드 위젯을 한 행에 나란히 배치해 줍니다. 레이블에 이미 만들어 둔 `QLabel *` 포인터나, 필드 자리에 `QLayout *`을 넘기는 오버로드도 있어서 좀 더 복잡한 행도 구성할 수 있습니다. `QFormLayout`은 레이블 정렬 방식(`setLabelAlignment()`)이나, 창이 좁아졌을 때 레이블과 필드를 한 줄에 유지할지 아래위로 접을지를 결정하는 필드 확장 정책(`setFieldGrowthPolicy()`)도 조정할 수 있어, 순수하게 손으로 `QGridLayout`을 배치하는 것보다 폼 작성에 특화되어 있습니다.

## 4.5 setLayout()과 위젯 크기 정책: QSizePolicy

### setLayout()

앞선 예제들에서는 `new QVBoxLayout(window)`처럼 레이아웃 생성자에 위젯을 바로 넘겼지만, 다음처럼 나누어 쓸 수도 있습니다.

```cpp
QWidget *window = new QWidget();
auto *layout = new QVBoxLayout();   // 아직 어떤 위젯에도 속하지 않은 레이아웃
layout->addWidget(new QLabel("안내"));

window->setLayout(layout);   // 이 시점에 window의 레이아웃으로 설정된다.
```

한 위젯에는 레이아웃을 하나만 설정할 수 있습니다. 이미 레이아웃이 설정된 위젯에 `setLayout()`을 다시 호출하면 경고가 출력되며 무시됩니다. 여러 위젯을 한 화면에 담고 싶다면, 앞서 본 것처럼 레이아웃 안에 다른 레이아웃을 중첩하거나, 위젯을 여러 개의 컨테이너 `QWidget`으로 나누고 각 컨테이너에 별도의 레이아웃을 설정하는 방식을 씁니다.

### QSizePolicy

레이아웃이 위젯들에게 얼마만큼의 공간을 나누어 줄지 결정할 때 참고하는 것이 각 위젯의 **크기 정책(size policy)** 입니다. `QSizePolicy`는 가로/세로 방향 각각에 대해 "여유 공간이 생기면 이 위젯이 늘어나도 되는지", "공간이 부족하면 줄어들어도 되는지"를 나타내는 값입니다.

```cpp
#include <QSizePolicy>

lineEdit->setSizePolicy(QSizePolicy::Expanding, QSizePolicy::Fixed);
```

위 코드는 "가로로는 남는 공간을 적극적으로 차지해도 되지만, 세로 높이는 고정된 크기를 유지한다"는 뜻입니다. `QSizePolicy::Policy` 열거형에는 다음과 같은 값들이 있습니다.

- `QSizePolicy::Fixed`: `sizeHint()`가 반환하는 크기를 그대로 유지하며 늘어나거나 줄어들지 않습니다.
- `QSizePolicy::Minimum`: `sizeHint()` 크기보다 작아지지는 않지만, 남는 공간이 있으면 늘어날 수 있습니다.
- `QSizePolicy::Maximum`: `sizeHint()` 크기보다 커지지는 않지만, 공간이 부족하면 줄어들 수 있습니다.
- `QSizePolicy::Preferred`(기본값): `sizeHint()`를 선호하지만 필요하면 커지거나 작아질 수 있습니다.
- `QSizePolicy::Expanding`: `Preferred`와 비슷하지만, 남는 공간을 다른 위젯보다 우선적으로 더 많이 차지하려고 합니다.
- `QSizePolicy::MinimumExpanding`: 최소 크기는 지키면서 `Expanding`처럼 적극적으로 늘어납니다.
- `QSizePolicy::Ignored`: `sizeHint()`를 사실상 무시하고, 오직 레이아웃이 배분하는 공간에만 맞춥니다.

대부분의 기본 위젯은 이미 합리적인 기본 정책을 가지고 있습니다. 예를 들어 `QLineEdit`은 가로로는 `Expanding`에 가깝게, 세로로는 `Fixed`에 가깝게 동작하도록 설계되어 있어서, 별도로 크기 정책을 조정하지 않아도 창을 가로로 넓히면 입력창이 자연스럽게 함께 늘어납니다. `QPushButton`은 반대로 가로/세로 모두 자기 텍스트 크기에 맞춘 `Fixed`에 가까운 정책을 가지고 있어 창을 늘려도 버튼 크기 자체는 잘 변하지 않습니다. 직접 `setSizePolicy()`를 호출해야 하는 경우는, 예를 들어 리스트나 텍스트 편집 영역처럼 "창이 커질 때 이 위젯이 남는 공간을 몽땅 차지했으면 좋겠다"는 의도를 명시적으로 표현하고 싶을 때입니다.

`QSizePolicy`는 늘어나는 비율을 조절하는 스트레치 팩터(`setHorizontalStretch()`, `setVerticalStretch()`)도 가지고 있어, 두 위젯이 모두 `Expanding`일 때 누가 더 많은 비율로 공간을 가져갈지도 세밀하게 조정할 수 있습니다. 위젯의 `sizeHint()`(레이아웃이 참고하는 "선호 크기")와 `minimumSizeHint()`(더 이상 줄어들 수 없는 최소 크기)도 크기 정책과 함께 레이아웃 계산에 사용되는 값입니다.

## 4.6 예제: 간단한 회원가입 폼 만들기

지금까지 배운 위젯과 레이아웃, 시그널/슬롯을 모두 사용해 이름, 이메일, 회원 유형, 약관 동의로 구성된 간단한 폼을 만들어 보겠습니다.

```cpp
// signupform.h
#pragma once
#include <QWidget>

class QLineEdit;
class QComboBox;
class QCheckBox;
class QPushButton;
class QLabel;

class SignupForm : public QWidget
{
    Q_OBJECT

public:
    explicit SignupForm(QWidget *parent = nullptr);

private slots:
    void onSubmit();
    void updateSubmitEnabled();

private:
    QLineEdit *m_nameEdit;
    QLineEdit *m_emailEdit;
    QComboBox *m_typeCombo;
    QCheckBox *m_agreeCheck;
    QPushButton *m_submitButton;
    QLabel *m_statusLabel;
};
```

```cpp
// signupform.cpp
#include "signupform.h"

#include <QLineEdit>
#include <QComboBox>
#include <QCheckBox>
#include <QPushButton>
#include <QLabel>
#include <QVBoxLayout>
#include <QFormLayout>

SignupForm::SignupForm(QWidget *parent)
    : QWidget(parent)
    , m_nameEdit(new QLineEdit())
    , m_emailEdit(new QLineEdit())
    , m_typeCombo(new QComboBox())
    , m_agreeCheck(new QCheckBox("이용약관에 동의합니다"))
    , m_submitButton(new QPushButton("가입하기"))
    , m_statusLabel(new QLabel())
{
    setWindowTitle("회원가입");

    m_nameEdit->setPlaceholderText("홍길동");
    m_emailEdit->setPlaceholderText("example@mail.com");
    m_typeCombo->addItems({"일반 회원", "기업 회원"});
    m_submitButton->setEnabled(false);   // 약관에 동의해야 활성화

    // 위쪽: 이름/이메일/유형 입력 폼
    auto *form = new QFormLayout();
    form->addRow("이름", m_nameEdit);
    form->addRow("이메일", m_emailEdit);
    form->addRow("회원 유형", m_typeCombo);

    // 전체를 세로로 쌓는 바깥 레이아웃
    auto *outer = new QVBoxLayout(this);
    outer->addLayout(form);
    outer->addWidget(m_agreeCheck);
    outer->addWidget(m_submitButton);
    outer->addWidget(m_statusLabel);
    outer->addStretch();

    m_statusLabel->setSizePolicy(QSizePolicy::Preferred, QSizePolicy::Fixed);

    connect(m_agreeCheck, &QCheckBox::toggled, this, &SignupForm::updateSubmitEnabled);
    connect(m_submitButton, &QPushButton::clicked, this, &SignupForm::onSubmit);
}

void SignupForm::updateSubmitEnabled()
{
    m_submitButton->setEnabled(m_agreeCheck->isChecked());
}

void SignupForm::onSubmit()
{
    if (m_nameEdit->text().isEmpty() || m_emailEdit->text().isEmpty()) {
        m_statusLabel->setText("이름과 이메일을 모두 입력해 주세요.");
        return;
    }

    m_statusLabel->setText(QString("%1 님(%2, %3)의 가입 신청이 접수되었습니다.")
                                .arg(m_nameEdit->text(), m_emailEdit->text(), m_typeCombo->currentText()));
}
```

```cpp
// main.cpp
#include <QApplication>
#include "signupform.h"

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    SignupForm form;
    form.resize(320, 220);
    form.show();

    return app.exec();
}
```

이 예제는 이 장에서 다룬 내용을 거의 모두 담고 있습니다.

- `QLineEdit`, `QComboBox`, `QCheckBox`, `QPushButton`, `QLabel` 다섯 가지 기본 위젯을 함께 사용했습니다.
- 위젯들을 생성할 때 부모를 넘기지 않고, `QFormLayout`과 `QVBoxLayout`에 추가하는 것만으로 부모-자식 관계와 소유권을 해결했습니다.
- `QFormLayout`으로 "레이블 + 입력창" 구조를, `QVBoxLayout`으로 그 폼과 체크박스, 버튼, 안내 레이블을 세로로 쌓는 구조를 만들고, `addLayout()`으로 두 레이아웃을 중첩했습니다.
- `QCheckBox::toggled`와 `QPushButton::clicked` 두 시그널을 각각 다른 슬롯에 연결해, 체크박스 상태에 따라 버튼의 활성화 여부가 실시간으로 바뀌도록 만들었습니다(느슨한 결합 덕분에 `SignupForm`은 각 위젯이 언제 값이 바뀌는지 폴링할 필요 없이 시그널이 알려주는 순간에만 반응합니다).

## 요약

- `QWidget`은 `QObject`의 부모-자식 객체 트리를 그대로 물려받습니다. 부모가 지정된 자식 위젯은 부모가 소멸할 때 함께 자동으로 삭제되므로, 레이아웃에 들어가는 자식 위젯은 대개 개발자가 직접 `delete`할 필요가 없습니다.
- 기본 위젯으로 `QPushButton`(버튼), `QLabel`(표시 전용 텍스트/이미지), `QLineEdit`(한 줄 텍스트 입력), `QCheckBox`(다중 선택), `QRadioButton`(단일 선택), `QComboBox`(드롭다운 선택), `QSlider`(범위 내 값 조절), `QSpinBox`(정수 스핀 입력)를 살펴보았으며, 각각 대표적인 시그널(`clicked`, `textChanged`, `toggled`, `currentIndexChanged`, `valueChanged` 등)을 가지고 있습니다.
- `QVBoxLayout`/`QHBoxLayout`은 위젯을 세로/가로로 순서대로 배치하고, `QGridLayout`은 표 형태로, `QFormLayout`은 "레이블 + 입력 위젯" 반복 구조에 특화되어 있습니다. 레이아웃은 서로 중첩(`addLayout()`)할 수 있습니다.
- 위젯을 레이아웃에 `addWidget()`으로 추가하면 그 레이아웃이 속한 위젯의 자식으로 자동 재지정되므로, 위젯 생성 시점에 부모를 직접 넘기지 않아도 됩니다.
- `setLayout()`은 위젯 하나에 레이아웃을 설정하는 함수이며, 한 위젯에는 레이아웃을 하나만 설정할 수 있습니다. `QSizePolicy`는 창 크기가 바뀔 때 각 위젯이 가로/세로로 얼마나 늘어나거나 줄어들 수 있는지를 나타내는 정책으로, `sizeHint()`와 함께 레이아웃 계산에 사용됩니다.

## 연습문제

1. 부모가 있는 위젯을 `new`로 힙에 생성하지 않고 스택에 값으로 선언한 뒤, 그 부모가 먼저 소멸되는 경우 어떤 문제가 발생할 수 있는지 객체 트리의 동작 원리로 설명해 보세요.
2. `QLineEdit`의 `textChanged` 시그널과 `textEdited` 시그널의 차이를 설명하고, 이 차이를 모른 채 `setText()`를 호출하는 슬롯을 `textChanged`에 연결하면 어떤 문제가 생길 수 있는지 서술해 보세요.
3. 이름, 나이(`QSpinBox`), 성별(`QRadioButton` 두 개), 뉴스레터 수신 여부(`QCheckBox`)를 입력받는 폼을 `QFormLayout`을 사용해 구성하는 코드를 작성해 보세요.
4. `QSizePolicy::Expanding`과 `QSizePolicy::Fixed`의 차이를 설명하고, 창 크기를 조절했을 때 각각 어떻게 동작할지 예를 들어 설명해 보세요.
5. 4.6절의 `SignupForm` 예제에서 `m_agreeCheck`의 `toggled` 시그널을 `updateSubmitEnabled` 슬롯에 연결하지 않았다면 어떤 문제가 생기는지, 그리고 이것이 시그널-슬롯의 느슨한 결합과 어떻게 연결되는지 설명해 보세요.
