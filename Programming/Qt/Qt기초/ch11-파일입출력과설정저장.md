지금까지는 위젯을 배치하고 시그널과 슬롯으로 화면을 동작시키는 데 집중했다. 하지만 실제로 쓸모 있는 데스크톱 프로그램이 되려면 사용자가 입력한 데이터를 저장했다가 다음에 실행했을 때 다시 불러오거나, 프로그램을 종료했다가 다시 켰을 때 창 크기와 위치가 그대로 유지되는 것과 같은 "지속성(persistence)"이 필요하다.

이 장에서는 Qt가 제공하는 파일 입출력 도구들을 살펴본다. `QFile`과 `QTextStream`으로 텍스트 파일을, `QDataStream`으로 바이너리 파일을 다루는 방법을 익히고, `QDir`과 `QFileInfo`로 파일 시스템의 경로와 정보를 다루는 법을 배운다. 그리고 마지막으로 애플리케이션의 설정 값을 플랫폼에 맞는 방식으로 자동 저장해 주는 `QSettings`를 이용해, 창 크기와 위치를 저장하고 복원하는 실전 예제를 만들어 본다.

## 11.1 QIODevice와 QFile 기초

Qt에서 파일, 소켓, 메모리 버퍼 등 "데이터를 읽고 쓸 수 있는 모든 것"은 `QIODevice`라는 추상 클래스를 상속한다. `QFile`은 그중에서도 로컬 파일 시스템의 파일을 다루는 클래스다. `QIODevice`를 상속하는 덕분에 파일을 열고 닫는 인터페이스는 소켓이나 버퍼를 다룰 때와 동일하다.

파일을 사용하는 기본 흐름은 다음과 같다.

```cpp
#include <QFile>
#include <QDebug>

void writeSimpleFile()
{
    QFile file("greeting.txt");

    if (!file.open(QIODevice::WriteOnly | QIODevice::Text)) {
        qWarning() << "파일을 열 수 없습니다:" << file.errorString();
        return;
    }

    file.write("Hello, Qt!\n");
    file.close();
}
```

`open()`에 전달하는 플래그는 `QIODevice::OpenModeFlag` 열거형의 값이며, `|` 연산자로 조합한다.

- `QIODevice::ReadOnly` / `QIODevice::WriteOnly` / `QIODevice::ReadWrite`: 읽기, 쓰기, 읽기/쓰기 모드.
- `QIODevice::Append`: 파일 끝에 이어서 쓴다.
- `QIODevice::Truncate`: 기존 내용을 지우고 새로 쓴다.
- `QIODevice::Text`: 텍스트 모드로 연다. 플랫폼별 줄바꿈 문자 변환(`\n` ↔ `\r\n`)이 자동으로 이루어진다.

`open()`은 성공하면 `true`, 실패하면 `false`를 반환하므로 반드시 반환값을 확인해야 한다. 실패 원인은 `errorString()`으로 확인할 수 있다. 또한 파일이 존재하는지는 인스턴스를 만들지 않고도 정적 함수 `QFile::exists("경로")`로 바로 확인할 수 있다.

## 11.2 QTextStream으로 텍스트 파일 읽고 쓰기

`QFile::write()`는 `QByteArray`를 그대로 기록하는 저수준 함수다. `QString`이나 숫자 같은 값을 사람이 읽기 좋은 텍스트로 저장하려면 `QTextStream`을 함께 사용하는 것이 훨씬 편리하다. `QTextStream`은 `QIODevice`를 감싸서 `<<`, `>>` 연산자와 `readLine()` 같은 편의 함수를 제공한다.

```cpp
#include <QFile>
#include <QTextStream>
#include <QDebug>

bool writeLog(const QString &path, const QStringList &lines)
{
    QFile file(path);
    if (!file.open(QIODevice::WriteOnly | QIODevice::Text)) {
        qWarning() << "파일을 열 수 없습니다:" << file.errorString();
        return false;
    }

    QTextStream out(&file);
#if QT_VERSION < QT_VERSION_CHECK(6, 0, 0)
    out.setCodec("UTF-8");
#endif

    for (const QString &line : lines)
        out << line << Qt::endl;

    file.close();
    return true;
}
```

`QTextStream`의 인코딩 처리는 Qt5와 Qt6에서 차이가 있다. Qt5에서는 `setCodec("UTF-8")`을 호출해 명시적으로 UTF-8 인코딩을 지정해야 비 ASCII 문자가 깨지지 않는다. Qt6에서는 `QTextStream`이 기본적으로 UTF-8을 사용하도록 바뀌었고, `setCodec()` 자체가 제거되었다(대신 `QStringConverter`를 이용한 `setEncoding()`이 있다). 위 코드처럼 `QT_VERSION_CHECK` 매크로로 분기하면 두 버전 모두에서 정상적으로 동작하는 코드를 작성할 수 있다.

파일을 한 줄씩 읽어 들일 때는 `atEnd()`와 `readLine()`을 조합한다.

```cpp
#include <QFile>
#include <QTextStream>

QStringList readLog(const QString &path)
{
    QStringList result;

    QFile file(path);
    if (!file.open(QIODevice::ReadOnly | QIODevice::Text))
        return result;

    QTextStream in(&file);
#if QT_VERSION < QT_VERSION_CHECK(6, 0, 0)
    in.setCodec("UTF-8");
#endif

    while (!in.atEnd())
        result << in.readLine();

    file.close();
    return result;
}
```

파일 전체를 한 번에 문자열로 읽고 싶다면 `in.readAll()`을 사용하면 된다. 큰 파일을 통째로 메모리에 올려야 하므로, 로그 파일처럼 줄 단위 처리가 자연스러운 경우에는 `readLine()`을 반복하는 쪽이 더 적합하다.

## 11.3 QDataStream으로 바이너리 파일 다루기

텍스트 파일은 사람이 읽기 편하지만, 숫자나 구조체를 그대로 저장하기에는 비효율적이다. `QDataStream`은 Qt의 기본 타입(`int`, `double`, `QString`, `QList` 등)을 플랫폼에 독립적인 이진 형식으로 직렬화해 준다.

사용자 정의 타입을 직렬화하려면 `<<`, `>>` 연산자를 오버로딩하면 된다.

```cpp
#include <QDataStream>
#include <QString>

struct Student
{
    QString name;
    int score = 0;
};

QDataStream &operator<<(QDataStream &out, const Student &s)
{
    out << s.name << s.score;
    return out;
}

QDataStream &operator>>(QDataStream &in, Student &s)
{
    in >> s.name >> s.score;
    return in;
}
```

이렇게 연산자를 정의해 두면 `Student`를 담은 `QList<Student>` 전체를 한 번에 스트림에 흘려보낼 수 있다. `QList`(및 `QVector`, `QMap` 등)는 원소 타입이 `QDataStream` 연산자를 지원하기만 하면 컨테이너 자체에 대한 스트림 연산자를 템플릿으로 이미 제공하기 때문이다.

```cpp
#include <QFile>
#include <QDataStream>
#include <QList>

bool saveStudents(const QString &path, const QList<Student> &students)
{
    QFile file(path);
    if (!file.open(QIODevice::WriteOnly))
        return false;

    QDataStream out(&file);
    out.setVersion(QDataStream::Qt_5_15);
    out << students;

    file.close();
    return true;
}

QList<Student> loadStudents(const QString &path)
{
    QList<Student> students;

    QFile file(path);
    if (!file.open(QIODevice::ReadOnly))
        return students;

    QDataStream in(&file);
    in.setVersion(QDataStream::Qt_5_15);
    in >> students;

    file.close();
    return students;
}
```

`setVersion()`은 스트림에 사용할 직렬화 형식의 버전을 고정한다. Qt 버전이 올라가면서 일부 타입의 이진 형식이 바뀔 수 있으므로, 버전을 명시적으로 지정해 두면 나중에 Qt를 업그레이드하더라도 예전에 저장한 파일을 문제없이 읽을 수 있다. 읽기와 쓰기에 같은 버전을 지정하는 것이 중요하다.

## 11.4 QDir과 QFileInfo로 경로와 파일 정보 다루기

`QDir`은 디렉터리를 다루는 클래스이고, `QFileInfo`는 하나의 파일(또는 디렉터리) 경로에 대한 상세 정보를 조회하는 클래스다. 두 클래스는 함께 쓰이는 경우가 많다.

```cpp
#include <QDir>
#include <QFileInfo>
#include <QDebug>

void listTextFiles(const QString &dirPath)
{
    QDir dir(dirPath);

    if (!dir.exists()) {
        dir.mkpath(".");   // 디렉터리가 없으면 생성(중간 경로까지 함께 생성)
        return;
    }

    const QStringList filters = { "*.txt" };
    const QStringList files = dir.entryList(filters, QDir::Files, QDir::Time);

    for (const QString &fileName : files) {
        QFileInfo info(dir.absoluteFilePath(fileName));
        qDebug() << info.fileName()
                 << info.size() << "bytes"
                 << info.lastModified().toString(Qt::ISODate);
    }
}
```

`QDir`에서 자주 쓰는 함수는 다음과 같다.

- `QDir::exists()`: 디렉터리 존재 여부.
- `QDir::mkpath(path)`: 중간 경로가 없어도 한 번에 생성한다(`mkdir()`은 바로 위 한 단계만 생성).
- `QDir::entryList(nameFilters, filters, sort)`: 이름 패턴, 종류(파일/디렉터리), 정렬 기준에 따라 항목을 나열한다. `QDir::NoDotAndDotDot` 필터를 추가하면 `.`, `..` 항목을 제외할 수 있다.
- `QDir::current()`, `QDir::home()`, `QDir::temp()`: 각각 현재 작업 디렉터리, 홈 디렉터리, 임시 디렉터리를 가리키는 `QDir` 객체를 반환하는 정적 함수다.
- `QDir::separator()`: 플랫폼에 맞는 경로 구분자(`/` 또는 `\`)를 반환한다. 다만 Qt API 내부에서는 어느 플랫폼이든 `/`를 그대로 사용해도 무방하다.

`QFileInfo`는 경로 문자열을 분해하거나 파일 속성을 조회할 때 사용한다.

- `fileName()`: 확장자를 포함한 파일 이름만.
- `baseName()` / `completeBaseName()`: 확장자를 제외한 이름.
- `suffix()` / `completeSuffix()`: 확장자.
- `absoluteFilePath()`, `absolutePath()`: 절대 경로.
- `exists()`, `isFile()`, `isDir()`: 존재 여부와 종류.
- `size()`: 바이트 단위 크기.
- `lastModified()`: 마지막 수정 시각을 `QDateTime`으로 반환.

## 11.5 QStandardPaths로 앱 데이터 위치 구하기

파일을 프로그램이 설치된 폴더나 현재 작업 디렉터리에 그냥 저장하면 안 되는 경우가 많다. Windows에서는 `Program Files` 아래에 쓰기 권한이 없을 수 있고, macOS/Linux도 애플리케이션마다 정해진 데이터 저장 위치 관례가 있다. `QStandardPaths`는 이런 플랫폼별 표준 경로를 코드 한 줄로 얻게 해 준다.

```cpp
#include <QStandardPaths>
#include <QDir>

QString appLogFilePath()
{
    const QString dirPath =
        QStandardPaths::writableLocation(QStandardPaths::AppDataLocation);

    QDir().mkpath(dirPath);   // 처음 실행 시 폴더가 없을 수 있으므로 생성

    return dirPath + "/app.log";
}
```

자주 사용하는 위치 값은 다음과 같다.

- `QStandardPaths::AppDataLocation`: 애플리케이션 전용 데이터 저장 위치(설정, 캐시가 아닌 사용자 데이터).
- `QStandardPaths::AppConfigLocation`: 설정 파일 저장에 적합한 위치.
- `QStandardPaths::DocumentsLocation`: 사용자의 "문서" 폴더.
- `QStandardPaths::DesktopLocation`: 바탕화면.
- `QStandardPaths::TempLocation`: 임시 파일 저장 위치.

`writableLocation()`이 반환하는 디렉터리는 애플리케이션이 처음 실행될 때는 실제로 존재하지 않을 수 있으므로, 파일을 쓰기 전에 `QDir::mkpath()`로 미리 생성해 두는 것이 안전하다.

## 11.6 QSettings로 애플리케이션 설정 저장하기

지금까지 다룬 `QFile`, `QTextStream`, `QDataStream`은 파일 형식을 직접 설계해야 한다. 반면 사용자 설정처럼 "이름-값" 쌍으로 표현되는 단순한 데이터는 `QSettings`를 사용하면 저장 형식을 전혀 신경 쓰지 않고 처리할 수 있다.

`QSettings`는 플랫폼에 따라 저장 위치와 형식을 자동으로 선택한다.

- Windows: 레지스트리(`HKEY_CURRENT_USER` 아래).
- macOS: `.plist` 파일.
- Linux/Unix: INI 형식의 설정 파일(`~/.config` 아래).

이 동작을 이용하려면 먼저 조직 이름과 애플리케이션 이름을 등록해야 한다. 보통 `main()` 함수 맨 앞에서 설정한다.

```cpp
// main.cpp
#include <QApplication>
#include <QCoreApplication>
#include "mainwindow.h"

int main(int argc, char *argv[])
{
    QCoreApplication::setOrganizationName("JoyStudio");
    QCoreApplication::setApplicationName("NoteApp");

    QApplication app(argc, argv);

    MainWindow window;
    window.show();

    return app.exec();
}
```

이렇게 해 두면 이후 코드 어디서든 인자 없이 `QSettings settings;`라고만 써도 항상 같은 저장소를 가리킨다.

```cpp
#include <QSettings>

void saveFontSetting()
{
    QSettings settings;
    settings.setValue("editor/fontSize", 12);
}

int loadFontSetting()
{
    QSettings settings;
    return settings.value("editor/fontSize", /*기본값=*/10).toInt();
}
```

`value()`의 두 번째 인자는 해당 키가 아직 저장되어 있지 않을 때 반환할 기본값이다. `QSettings`는 내부적으로 값을 `QVariant`로 저장하므로, 꺼내 쓸 때는 `toInt()`, `toString()`, `toBool()`, `toByteArray()` 같은 변환 함수를 사용한다.

키 이름에 `/`를 포함시키면 자동으로 계층 구조가 만들어지지만, 관련된 값들을 묶을 때는 `beginGroup()`/`endGroup()`을 사용하는 편이 더 명확하다.

```cpp
QSettings settings;

settings.beginGroup("editor");
settings.setValue("fontSize", 12);
settings.setValue("fontFamily", "Consolas");
settings.endGroup();

settings.beginGroup("editor");
const int fontSize = settings.value("fontSize", 10).toInt();
const QString fontFamily = settings.value("fontFamily", "Courier New").toString();
settings.endGroup();
```

목록처럼 여러 개의 항목을 저장해야 할 때는 `beginWriteArray()`/`beginReadArray()`를 사용한다.

```cpp
QSettings settings;
const QStringList recentFiles = { "a.txt", "b.txt", "c.txt" };

settings.beginWriteArray("recentFiles");
for (int i = 0; i < recentFiles.size(); ++i) {
    settings.setArrayIndex(i);
    settings.setValue("path", recentFiles.at(i));
}
settings.endArray();
```

```cpp
QSettings settings;
QStringList loaded;

const int count = settings.beginReadArray("recentFiles");
for (int i = 0; i < count; ++i) {
    settings.setArrayIndex(i);
    loaded << settings.value("path").toString();
}
settings.endArray();
```

특정 값이 저장되어 있는지 확인하려면 `contains()`, 삭제하려면 `remove()`, 전체를 비우려면 `clear()`를 사용한다.

레지스트리나 `.plist` 대신 항상 INI 파일을 명시적으로 사용하고 싶다면, 생성자에 경로와 형식을 직접 지정하면 된다.

```cpp
QSettings iniSettings("config.ini", QSettings::IniFormat);
```

이 방식은 배포용 프로그램을 실행 파일과 같은 폴더에 두고 "휴대용(portable)" 형태로 배포할 때 유용하다.

## 11.7 실전 예제: 창 크기와 위치 저장/복원

지금까지 배운 `QSettings`를 활용해, 프로그램을 종료할 때 창의 크기와 위치를 저장하고 다음 실행 시 그대로 복원하는 기능을 만들어 보자. `QWidget`은 창의 기하 정보를 하나의 `QByteArray`로 직렬화해 주는 `saveGeometry()`/`restoreGeometry()`를 제공하고, `QMainWindow`는 툴바나 도킹 위젯의 배치까지 함께 저장하는 `saveState()`/`restoreState()`를 추가로 제공한다.

```cpp
// mainwindow.h
#pragma once

#include <QMainWindow>

class MainWindow : public QMainWindow
{
    Q_OBJECT

public:
    explicit MainWindow(QWidget *parent = nullptr);

protected:
    void closeEvent(QCloseEvent *event) override;

private:
    void loadSettings();
    void saveSettings();
};
```

```cpp
// mainwindow.cpp
#include "mainwindow.h"

#include <QCloseEvent>
#include <QSettings>
#include <QTextEdit>

MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent)
{
    setCentralWidget(new QTextEdit(this));
    setWindowTitle("설정 저장 예제");

    loadSettings();
}

void MainWindow::loadSettings()
{
    resize(800, 600);   // 최초 실행 시 사용할 기본 크기

    QSettings settings;
    settings.beginGroup("MainWindow");

    const QByteArray geometry = settings.value("geometry").toByteArray();
    if (!geometry.isEmpty())
        restoreGeometry(geometry);

    const QByteArray state = settings.value("windowState").toByteArray();
    if (!state.isEmpty())
        restoreState(state);

    settings.endGroup();
}

void MainWindow::saveSettings()
{
    QSettings settings;
    settings.beginGroup("MainWindow");

    settings.setValue("geometry", saveGeometry());
    settings.setValue("windowState", saveState());

    settings.endGroup();
}

void MainWindow::closeEvent(QCloseEvent *event)
{
    saveSettings();
    QMainWindow::closeEvent(event);
}
```

동작 원리를 정리하면 다음과 같다.

1. 프로그램을 처음 실행하면 `QSettings`에 저장된 값이 없으므로 `value("geometry")`는 빈 `QByteArray`를 반환한다. 이때는 `restoreGeometry()`를 호출하지 않고 앞서 지정한 `resize(800, 600)` 기본 크기를 그대로 사용한다.
2. 사용자가 창 크기를 바꾸거나 이동시킨 뒤 프로그램을 종료하면 `closeEvent()`가 호출되고, `saveGeometry()`/`saveState()`로 얻은 이진 데이터가 `QSettings`에 저장된다.
3. 다음에 프로그램을 다시 실행하면 저장된 `QByteArray`가 존재하므로 `restoreGeometry()`/`restoreState()`가 이전 상태를 그대로 복원한다.

`saveGeometry()`가 반환하는 데이터는 화면 해상도, 모니터 배치 등 실행 환경 정보까지 함께 인코딩되어 있어서, 단순히 `x`, `y`, `width`, `height` 네 개의 정수를 각각 저장하는 것보다 훨씬 안정적으로 창 상태를 복원해 준다. 이 때문에 Qt 공식 문서에서도 창 위치/크기 저장에는 직접 좌표를 다루기보다 `saveGeometry()`/`restoreGeometry()` 조합을 권장한다.

## 요약

- `QFile`은 `QIODevice`를 상속하는 파일 클래스이며, `open()`에 전달하는 플래그(`ReadOnly`, `WriteOnly`, `Text` 등)로 열기 모드를 지정한다.
- `QTextStream`은 텍스트 파일을 사람이 읽기 좋은 형태로 읽고 쓸 때 사용하며, Qt5에서는 `setCodec("UTF-8")`이 필요하지만 Qt6은 기본적으로 UTF-8을 사용한다.
- `QDataStream`은 Qt의 기본 타입과 사용자 정의 타입(`<<`, `>>` 연산자 오버로딩)을 플랫폼 독립적인 이진 형식으로 직렬화한다. `setVersion()`으로 형식 버전을 고정해 두면 호환성을 유지할 수 있다.
- `QDir`은 디렉터리 탐색과 생성을, `QFileInfo`는 개별 파일/경로에 대한 상세 정보 조회를 담당한다.
- `QStandardPaths::writableLocation()`으로 플랫폼별 표준 데이터/설정 저장 위치를 얻을 수 있다.
- `QSettings`는 조직 이름과 애플리케이션 이름을 기준으로 플랫폼에 맞는 저장소(레지스트리, INI, plist 등)에 키-값 데이터를 자동으로 저장한다. `beginGroup()`/`endGroup()`으로 값들을 묶고, `beginWriteArray()`/`beginReadArray()`로 목록을 저장할 수 있다.
- `QWidget::saveGeometry()`/`restoreGeometry()`와 `QMainWindow::saveState()`/`restoreState()`를 `QSettings`와 함께 사용하면 창의 크기, 위치, 레이아웃을 안정적으로 저장하고 복원할 수 있다.

## 연습문제

1. `QFile`을 열 때 `QIODevice::WriteOnly`만 지정했을 때와 `QIODevice::WriteOnly | QIODevice::Append`를 지정했을 때 동작이 어떻게 달라지는지 설명해 보라.
2. 11.3절의 `Student` 구조체에 `QString studentId` 필드를 추가하고, `operator<<`/`operator>>`를 수정하여 바이너리 파일로 저장/불러오기가 정상적으로 동작하도록 만들어 보라.
3. `QSettings`를 이용해 "최근 열어 본 파일 목록"(최대 5개)을 저장하고, 새 파일을 열 때마다 목록의 맨 앞에 추가하면서 5개를 넘으면 가장 오래된 항목을 제거하는 함수를 작성해 보라.
4. 11.7절의 예제에서 `saveSettings()`를 `closeEvent()`가 아니라 사용자가 창 크기를 바꿀 때마다(`resizeEvent()`) 호출하도록 바꾼다면 어떤 장단점이 있을지 생각해 보라.
5. `QStandardPaths::AppDataLocation`과 `QStandardPaths::AppConfigLocation`은 어떤 용도로 구분해서 사용하는 것이 적절한지 조사하고, 각각에 어떤 종류의 파일을 저장하면 좋을지 예를 들어 설명해 보라.
