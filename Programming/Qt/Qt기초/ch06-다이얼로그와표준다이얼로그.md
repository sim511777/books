메인 창 하나만으로 모든 상호작용을 처리하는 애플리케이션은 드뭅니다. 사용자에게 파일 경로를 물어보거나, 삭제를 진행하기 전에 확인을 받거나, 설정값을 입력받는 등 잠깐 나타났다가 사라지는 보조 창이 필요한 순간이 많습니다. Qt에서는 이런 보조 창을 `QDialog`와 그 하위 클래스들로 만듭니다.

이번 장에서는 다이얼로그를 여는 두 가지 방식인 모달과 비모달의 차이를 이해하고, `QDialog`를 상속해서 나만의 다이얼로그를 만드는 방법을 배웁니다. 이어서 Qt가 기본으로 제공하는 표준 다이얼로그들(`QMessageBox`, `QFileDialog`, `QColorDialog`, `QFontDialog`, `QInputDialog`)을 살펴보고, 마지막으로 파일 열기 다이얼로그로 텍스트 파일을 읽어 화면에 표시하는 예제를 만들어 봅니다.

## 6.1 모달 다이얼로그 vs 비모달 다이얼로그

다이얼로그는 화면에 뜨는 방식에 따라 모달(modal)과 비모달(modeless, non-modal) 두 가지로 나뉩니다.

**모달 다이얼로그**는 다이얼로그가 열려 있는 동안 사용자가 같은 애플리케이션의 다른 창을 조작할 수 없도록 막습니다. "이 파일을 삭제하시겠습니까?" 같은 확인 창이 대표적입니다. 사용자가 응답하기 전에는 뒤에 있는 창을 클릭해도 반응하지 않습니다. 모달 다이얼로그는 `exec()`를 호출해서 엽니다.

```cpp
QDialog dialog(this);
// ... 다이얼로그 구성 ...
int result = dialog.exec();   // 다이얼로그가 닫힐 때까지 여기서 실행이 멈춘다
if (result == QDialog::Accepted) {
    // 사용자가 확인/OK를 눌렀을 때
}
```

`exec()`는 다이얼로그가 닫힐 때까지 **블로킹**됩니다. 즉 `exec()` 호출 이후의 코드는 사용자가 다이얼로그를 닫아야 실행됩니다. 내부적으로는 별도의 이벤트 루프를 돌리기 때문에 UI는 계속 반응하지만, 호출한 함수 입장에서는 그 자리에서 멈춰 있는 것처럼 보입니다. 이 성질 덕분에 "사용자에게 물어보고, 그 결과에 따라 바로 다음 동작을 결정"하는 코드를 순차적으로 작성할 수 있습니다.

**비모달 다이얼로그**는 열려 있어도 같은 애플리케이션의 다른 창을 자유롭게 조작할 수 있습니다. 찾기/바꾸기 창처럼 계속 띄워 둔 채로 본문 창과 번갈아 작업하는 경우에 적합합니다. 비모달로 열려면 `exec()` 대신 `show()`를 호출합니다.

```cpp
auto *findDialog = new FindDialog(this);
findDialog->setAttribute(Qt::WA_DeleteOnClose);  // 닫힐 때 객체 자동 삭제
findDialog->show();   // 즉시 반환된다. 뒤 코드가 곧바로 실행됨
```

`show()`는 호출 즉시 반환되므로, 다이얼로그의 결과를 그 자리에서 기다릴 수 없습니다. 대신 다이얼로그가 닫힐 때 발생하는 `finished(int)`, `accepted()`, `rejected()` 시그널에 슬롯을 연결해서 결과를 나중에 처리합니다.

한 가지 더 알아둘 함수로 `open()`이 있습니다. `open()`은 다이얼로그를 **모달로** 표시하지만 `exec()`처럼 실행을 멈추지 않고 즉시 반환됩니다. 대신 다이얼로그가 닫히면 `finished(int)` 시그널이 발생합니다. GUI 이벤트 루프를 직접 막고 싶지 않으면서도 다른 창과의 상호작용은 막고 싶을 때 사용합니다.

```cpp
auto *dialog = new MyDialog(this);
connect(dialog, &QDialog::finished, this, [dialog](int result) {
    if (result == QDialog::Accepted) {
        qDebug() << "사용자가 확인을 눌렀습니다";
    }
    dialog->deleteLater();
});
dialog->open();
```

세 가지 방식을 표로 정리하면 다음과 같습니다.

| 함수 | 모달 여부 | 반환 시점 | 결과 확인 방법 |
|---|---|---|---|
| `exec()` | 모달 | 다이얼로그가 닫힐 때까지 블로킹 | 반환값(`QDialog::Accepted`/`Rejected`) |
| `open()` | 모달 | 즉시 반환 | `finished(int)` 시그널 |
| `show()` | 비모달 | 즉시 반환 | `finished(int)`/`accepted()`/`rejected()` 시그널 |

간단한 확인 창처럼 결과에 따라 바로 분기하는 코드는 `exec()`가 직관적이고, 메인 이벤트 루프를 막지 않으면서 모달 동작이 필요하거나 다이얼로그를 재사용해야 하는 경우에는 `open()`이나 `show()`와 시그널 조합을 사용합니다.

## 6.2 QDialog 상속으로 커스텀 다이얼로그 만들기

간단한 정보 입력 창이 필요할 때는 `QDialog`를 상속한 클래스를 직접 만듭니다. 다이얼로그 안에는 원하는 위젯을 자유롭게 배치할 수 있고, 마지막에는 보통 확인/취소 버튼을 두어 사용자의 결정을 받습니다. 이 확인/취소 버튼 조합은 `QDialogButtonBox`로 만드는 것이 표준적인 방법입니다.

`QDialogButtonBox`는 여러 개의 버튼을 한꺼번에 관리하는 위젯으로, 플랫폼 관례에 맞게 버튼 순서를 자동으로 배치해 줍니다(예: Windows에서는 보통 "확인"이 왼쪽, macOS에서는 오른쪽에 오는 식의 차이를 신경 쓰지 않아도 됩니다).

```cpp
#include <QDialog>
#include <QDialogButtonBox>
#include <QLineEdit>
#include <QLabel>
#include <QVBoxLayout>
#include <QFormLayout>

class LoginDialog : public QDialog
{
    Q_OBJECT

public:
    explicit LoginDialog(QWidget *parent = nullptr)
        : QDialog(parent)
    {
        setWindowTitle(tr("로그인"));

        m_usernameEdit = new QLineEdit(this);
        m_passwordEdit = new QLineEdit(this);
        m_passwordEdit->setEchoMode(QLineEdit::Password);

        auto *formLayout = new QFormLayout;
        formLayout->addRow(tr("아이디:"), m_usernameEdit);
        formLayout->addRow(tr("비밀번호:"), m_passwordEdit);

        auto *buttonBox = new QDialogButtonBox(
            QDialogButtonBox::Ok | QDialogButtonBox::Cancel, this);
        connect(buttonBox, &QDialogButtonBox::accepted, this, &QDialog::accept);
        connect(buttonBox, &QDialogButtonBox::rejected, this, &QDialog::reject);

        auto *mainLayout = new QVBoxLayout(this);
        mainLayout->addLayout(formLayout);
        mainLayout->addWidget(buttonBox);
    }

    QString username() const { return m_usernameEdit->text(); }
    QString password() const { return m_passwordEdit->text(); }

private:
    QLineEdit *m_usernameEdit;
    QLineEdit *m_passwordEdit;
};
```

이 다이얼로그를 호출하는 쪽에서는 `exec()`의 반환값으로 사용자가 확인을 눌렀는지 확인한 뒤, 접근자 함수로 입력값을 꺼내 씁니다.

```cpp
LoginDialog dialog(this);
if (dialog.exec() == QDialog::Accepted) {
    QString user = dialog.username();
    QString pass = dialog.password();
    // 로그인 처리
}
```

`QDialogButtonBox`에는 `Ok`, `Cancel`, `Yes`, `No`, `Save`, `Discard`, `Apply`, `Reset`, `RestoreDefaults`, `Close`, `Help` 등 다양한 표준 버튼 플래그가 있으며, `|` 연산자로 여러 개를 조합할 수 있습니다. `accepted()` 시그널은 `Ok`, `Save`, `Yes` 등 "긍정적인" 버튼을 눌렀을 때, `rejected()` 시그널은 `Cancel`, `No`, `Close` 등 "취소성" 버튼을 눌렀을 때 발생합니다. 표준 버튼에 속하지 않는 개별 버튼의 클릭을 구분해야 한다면 `clicked(QAbstractButton *)` 시그널을 사용합니다.

입력값 검증이 필요한 다이얼로그라면, `accept()`를 곧바로 연결하는 대신 직접 슬롯을 만들어 검증 후 통과할 때만 `accept()`를 호출하는 방식도 자주 씁니다.

```cpp
connect(buttonBox, &QDialogButtonBox::accepted, this, &LoginDialog::validateAndAccept);

// ...

void LoginDialog::validateAndAccept()
{
    if (m_usernameEdit->text().isEmpty()) {
        QMessageBox::warning(this, tr("입력 오류"), tr("아이디를 입력하세요."));
        return;   // accept()를 호출하지 않으므로 다이얼로그가 닫히지 않는다
    }
    accept();
}
```

## 6.3 표준 다이얼로그

자주 필요한 몇 가지 다이얼로그는 Qt가 이미 완성된 형태로 제공합니다. 대부분 정적(static) 함수 호출 한 번으로 다이얼로그를 띄우고 결과를 받아올 수 있어 매우 간편합니다.

### 6.3.1 QMessageBox

`QMessageBox`는 정보, 경고, 오류, 확인 메시지를 보여주는 데 사용합니다. 가장 간단한 형태는 정적 편의 함수입니다.

```cpp
#include <QMessageBox>

// 단순 정보 표시 (확인 버튼만)
QMessageBox::information(this, tr("알림"), tr("저장이 완료되었습니다."));

// 경고
QMessageBox::warning(this, tr("경고"), tr("입력값이 올바르지 않습니다."));

// 오류
QMessageBox::critical(this, tr("오류"), tr("파일을 열 수 없습니다."));

// 예/아니오 질문
QMessageBox::StandardButton reply = QMessageBox::question(
    this, tr("확인"), tr("변경 사항을 저장하지 않고 종료하시겠습니까?"),
    QMessageBox::Yes | QMessageBox::No);

if (reply == QMessageBox::Yes) {
    close();
}
```

`information()`, `warning()`, `critical()`, `question()` 모두 표시할 버튼 조합을 세 번째 이후 인자로 지정할 수 있고, 기본값은 `question()`을 제외하면 `Ok` 버튼 하나입니다. `question()`의 기본 버튼 조합은 `Yes | No`입니다.

버튼 구성이 세 개 이상으로 복잡하거나, 자세한 설명(`informativeText`)을 추가로 보여주고 싶다면 `QMessageBox` 객체를 직접 만들어 세밀하게 구성할 수 있습니다.

```cpp
QMessageBox box(this);
box.setIcon(QMessageBox::Warning);
box.setWindowTitle(tr("저장하지 않은 변경 사항"));
box.setText(tr("문서가 변경되었습니다."));
box.setInformativeText(tr("저장하지 않고 닫으면 변경 내용을 잃게 됩니다."));
box.setStandardButtons(QMessageBox::Save | QMessageBox::Discard | QMessageBox::Cancel);
box.setDefaultButton(QMessageBox::Save);

int result = box.exec();
switch (result) {
case QMessageBox::Save:
    // 저장 후 종료
    break;
case QMessageBox::Discard:
    // 저장하지 않고 종료
    break;
default:
    // 취소: 아무 것도 하지 않음
    break;
}
```

### 6.3.2 QFileDialog

`QFileDialog`는 파일을 열거나 저장할 경로, 또는 폴더를 선택받는 데 사용합니다. 이 역시 정적 함수로 간단히 호출할 수 있습니다.

```cpp
#include <QFileDialog>

// 파일 열기: 하나의 파일 경로를 문자열로 반환. 취소하면 빈 문자열.
QString fileName = QFileDialog::getOpenFileName(
    this,
    tr("파일 열기"),
    QString(),                                 // 시작 디렉터리 (빈 문자열이면 기본값)
    tr("텍스트 파일 (*.txt);;모든 파일 (*)"));  // 필터

// 여러 파일을 한 번에 선택
QStringList fileNames = QFileDialog::getOpenFileNames(
    this, tr("파일 열기"), QString(), tr("이미지 파일 (*.png *.jpg)"));

// 파일 저장: 저장할 경로를 문자열로 반환
QString savePath = QFileDialog::getSaveFileName(
    this, tr("다른 이름으로 저장"), QString(), tr("텍스트 파일 (*.txt)"));

// 폴더 선택
QString dirPath = QFileDialog::getExistingDirectory(
    this, tr("폴더 선택"), QString());
```

필터 문자열은 `"설명 (*.확장자 *.확장자2);;다음 필터"` 형식으로 세미콜론 두 개(`;;`)로 여러 필터를 구분합니다. 사용자가 취소를 누르면 `getOpenFileName()`/`getSaveFileName()`/`getExistingDirectory()`는 모두 빈 문자열을 반환하고, `getOpenFileNames()`는 빈 리스트를 반환합니다. 따라서 반환값을 사용하기 전에는 항상 `isEmpty()`로 취소 여부를 확인해야 합니다.

### 6.3.3 QColorDialog

`QColorDialog::getColor()`는 색상 선택기를 열고 사용자가 고른 색을 `QColor`로 반환합니다.

```cpp
#include <QColorDialog>

QColor initial = Qt::blue;
QColor chosen = QColorDialog::getColor(initial, this, tr("색상 선택"));

if (chosen.isValid()) {
    // 사용자가 색을 골랐을 때만 isValid()가 true
    label->setStyleSheet(QStringLiteral("background-color: %1;").arg(chosen.name()));
}
```

취소를 누르면 `getColor()`는 유효하지 않은 `QColor`를 반환하므로, `isValid()`로 취소 여부를 판단합니다.

### 6.3.4 QFontDialog

`QFontDialog::getFont()`는 글꼴 선택기를 열고, 사용자가 확인을 눌렀는지를 `bool *ok` 매개변수로 알려줍니다.

```cpp
#include <QFontDialog>

bool ok = false;
QFont font = QFontDialog::getFont(&ok, this);
if (ok) {
    editor->setFont(font);
}
```

초기 글꼴을 지정한 채로 열고 싶다면 초기값을 함께 넘기는 오버로드를 사용합니다.

```cpp
bool ok = false;
QFont initialFont = editor->font();
QFont font = QFontDialog::getFont(&ok, initialFont, this, tr("글꼴 선택"));
if (ok) {
    editor->setFont(font);
}
```

### 6.3.5 QInputDialog

`QInputDialog`는 문자열, 정수, 실수, 또는 목록 중 하나처럼 값 하나를 간단히 입력받아야 할 때 커스텀 다이얼로그를 따로 만들지 않아도 되게 해줍니다.

```cpp
#include <QInputDialog>

// 한 줄 문자열 입력
bool ok = false;
QString name = QInputDialog::getText(
    this, tr("이름 입력"), tr("이름:"), QLineEdit::Normal, QString(), &ok);
if (ok && !name.isEmpty()) {
    // 입력값 사용
}

// 정수 입력 (초기값 25, 범위 0~120, 증가 단위 1)
int age = QInputDialog::getInt(
    this, tr("나이 입력"), tr("나이:"), 25, 0, 120, 1, &ok);

// 실수 입력 (초기값 0.0, 범위 0~1000, 소수점 둘째 자리까지)
double price = QInputDialog::getDouble(
    this, tr("가격 입력"), tr("가격:"), 0.0, 0.0, 1000.0, 2, &ok);

// 목록 중 하나 선택
QStringList items = {tr("한국어"), tr("English"), tr("日本語")};
QString selected = QInputDialog::getItem(
    this, tr("언어 선택"), tr("언어:"), items, 0, false, &ok);
```

`QInputDialog`의 각 정적 함수는 마지막에 `bool *ok` 인자를 받아, 사용자가 확인을 눌렀는지 취소를 눌렀는지 알려줍니다. `ok`가 `false`이면 반환값은 신뢰할 수 없으므로 반드시 확인 후 사용해야 합니다.

## 6.4 다이얼로그 결과 처리

`QDialog`는 내부적으로 정수 결과 코드를 가지고 있으며, 다음 두 값이 미리 정의되어 있습니다.

| 값 | 의미 |
|---|---|
| `QDialog::Accepted` | 사용자가 확인/저장 등 긍정적인 방법으로 다이얼로그를 닫음 |
| `QDialog::Rejected` | 사용자가 취소, 닫기 버튼, ESC 키 등으로 다이얼로그를 닫음 |

`accept()`를 호출하면 결과 코드가 `Accepted`로 설정되고 다이얼로그가 닫히면서 `accepted()`와 `finished(int)` 시그널이 발생합니다. `reject()`를 호출하면 결과 코드가 `Rejected`로 설정되고 `rejected()`와 `finished(int)` 시그널이 발생합니다. `QDialogButtonBox`의 `accepted()`/`rejected()` 시그널을 `QDialog::accept`/`QDialog::reject` 슬롯에 연결해 둔다면(6.2절 예제처럼), 버튼 클릭이 자동으로 이 흐름을 따라갑니다.

ESC 키를 누르거나 다이얼로그의 닫기(X) 버튼을 클릭하면 별도로 연결하지 않아도 `reject()`가 자동으로 호출됩니다. 즉 "취소" 버튼을 명시적으로 두지 않았더라도 사용자는 항상 ESC나 창 닫기로 다이얼로그를 취소할 수 있습니다.

`Accepted`/`Rejected` 두 가지로 부족하다면, `done(int result)`를 직접 호출해서 임의의 정수 결과 코드를 설정할 수도 있습니다. 예를 들어 3지선다 다이얼로그라면 `done(2)`처럼 사용자 정의 값을 쓰고, 호출부에서 `exec()`의 반환값을 그 정수와 비교합니다.

모달로 연 경우와 비모달/`open()`으로 연 경우의 결과 확인 방식을 정리하면 다음과 같습니다.

```cpp
// 모달: exec()의 반환값으로 바로 판단
QDialog dialog(this);
if (dialog.exec() == QDialog::Accepted) {
    // ...
}

// 비모달 또는 open(): finished 시그널로 판단
auto *dialog2 = new MyDialog(this);
connect(dialog2, &QDialog::finished, this, [](int result) {
    if (result == QDialog::Accepted) {
        // ...
    }
});
dialog2->show();   // 또는 dialog2->open();
```

## 6.5 예제: 파일 열기 다이얼로그로 텍스트 파일 읽어 표시하기

이번 장에서 배운 `QFileDialog`와 `QMessageBox`를 조합해서, 버튼을 누르면 파일 열기 다이얼로그가 뜨고 선택한 텍스트 파일의 내용을 `QLabel`에 표시하는 작은 프로그램을 만들어 봅니다. 파일을 실제로 읽어 들이는 부분은 `QFile`과 `QTextStream`을 사용합니다.

```cpp
#include <QApplication>
#include <QWidget>
#include <QVBoxLayout>
#include <QPushButton>
#include <QLabel>
#include <QScrollArea>
#include <QFileDialog>
#include <QMessageBox>
#include <QFile>
#include <QTextStream>

class FileViewerWidget : public QWidget
{
    Q_OBJECT

public:
    explicit FileViewerWidget(QWidget *parent = nullptr)
        : QWidget(parent)
    {
        setWindowTitle(tr("텍스트 파일 뷰어"));
        resize(500, 400);

        auto *openButton = new QPushButton(tr("파일 열기..."), this);
        connect(openButton, &QPushButton::clicked, this, &FileViewerWidget::openFile);

        m_contentLabel = new QLabel(tr("파일을 열어주세요."), this);
        m_contentLabel->setAlignment(Qt::AlignTop | Qt::AlignLeft);
        m_contentLabel->setWordWrap(true);

        // 내용이 길어질 수 있으므로 스크롤 영역에 담는다
        auto *scrollArea = new QScrollArea(this);
        scrollArea->setWidget(m_contentLabel);
        scrollArea->setWidgetResizable(true);

        auto *layout = new QVBoxLayout(this);
        layout->addWidget(openButton);
        layout->addWidget(scrollArea);
    }

private slots:
    void openFile()
    {
        QString fileName = QFileDialog::getOpenFileName(
            this,
            tr("텍스트 파일 열기"),
            QString(),
            tr("텍스트 파일 (*.txt);;모든 파일 (*)"));

        if (fileName.isEmpty()) {
            // 사용자가 취소한 경우: 아무 것도 하지 않는다
            return;
        }

        QFile file(fileName);
        if (!file.open(QIODevice::ReadOnly | QIODevice::Text)) {
            QMessageBox::warning(
                this,
                tr("파일 열기 실패"),
                tr("파일을 열 수 없습니다.\n%1").arg(file.errorString()));
            return;
        }

        QTextStream in(&file);
        const QString content = in.readAll();
        file.close();

        m_contentLabel->setText(content);
    }

private:
    QLabel *m_contentLabel;
};

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    FileViewerWidget viewer;
    viewer.show();

    return app.exec();
}

#include "main.moc"
```

이 예제에서 눈여겨볼 점은 두 가지입니다. 첫째, `QFileDialog::getOpenFileName()`이 반환한 문자열이 비어 있는지 먼저 확인해서 사용자의 취소를 자연스럽게 처리했습니다. 둘째, 파일 열기가 실패할 수 있는 상황(권한 없음, 파일이 삭제됨 등)을 `QFile::open()`의 반환값으로 확인하고, 실패 시 `QMessageBox::warning()`으로 사용자에게 원인을 안내했습니다. 다이얼로그를 다루는 코드는 항상 "사용자가 취소했을 가능성"과 "작업이 실패할 가능성" 두 가지를 함께 고려해야 안정적인 프로그램이 됩니다.

## 요약

- 모달 다이얼로그는 `exec()`로 열며, 닫힐 때까지 호출 지점의 실행이 멈추고 다른 창 조작도 막습니다. 비모달 다이얼로그는 `show()`로 열며 즉시 반환되고 다른 창과 동시에 조작할 수 있습니다. `open()`은 모달이지만 `exec()`처럼 블로킹되지 않고 `finished(int)` 시그널로 결과를 알려줍니다.
- `QDialog`를 상속해서 원하는 위젯을 배치한 커스텀 다이얼로그를 만들 수 있습니다. 확인/취소 버튼 조합은 `QDialogButtonBox`로 구성하며, `accepted()`/`rejected()` 시그널을 각각 `QDialog::accept`/`QDialog::reject` 슬롯에 연결하는 것이 표준적인 패턴입니다.
- Qt는 자주 쓰이는 표준 다이얼로그를 정적 함수로 제공합니다. `QMessageBox::information/warning/critical/question()`, `QFileDialog::getOpenFileName/getSaveFileName/getExistingDirectory()`, `QColorDialog::getColor()`, `QFontDialog::getFont()`, `QInputDialog::getText/getInt/getDouble/getItem()`이 대표적입니다.
- 다이얼로그의 결과는 `QDialog::Accepted`/`QDialog::Rejected` 두 상수로 판단하는 것이 기본이며, 표준 다이얼로그들은 각자 반환값(문자열, 색상, 글꼴 등)의 유효성이나 별도의 `bool *ok`/`isEmpty()`/`isValid()`로 취소 여부를 알려줍니다.
- 파일 다이얼로그와 파일 입출력을 조합할 때는 사용자의 취소와 입출력 실패 두 가지 경우를 모두 처리해야 안정적인 코드가 됩니다.

## 연습문제

1. `exec()`, `open()`, `show()`의 차이를 "블로킹 여부"와 "모달 여부" 두 기준으로 표를 그려 정리해 보세요.
2. 6.2절의 `LoginDialog`에 "비밀번호는 4자 이상"이라는 검증 규칙을 추가하고, 조건을 만족하지 않으면 `QMessageBox::warning()`을 띄운 뒤 다이얼로그를 닫지 않도록 `validateAndAccept()` 슬롯을 작성해 보세요.
3. `QMessageBox::question()`을 사용해서 "저장하지 않은 변경 사항이 있습니다. 저장하시겠습니까?"라고 묻고, `Save`/`Discard`/`Cancel` 세 가지 버튼에 따라 각각 다른 동작을 수행하는 코드를 작성해 보세요.
4. 이번 장의 텍스트 파일 뷰어 예제에 "다른 이름으로 저장" 버튼을 추가해서, `QFileDialog::getSaveFileName()`으로 경로를 받은 뒤 현재 `QLabel`에 표시된 내용을 파일로 저장하도록 확장해 보세요.
5. `QColorDialog::getColor()`와 `QFontDialog::getFont()`를 함께 사용해서, 사용자가 고른 색상과 글꼴을 적용한 미리보기 텍스트를 보여주는 작은 다이얼로그를 만들어 보세요. 사용자가 둘 중 하나라도 취소했을 때 어떻게 처리할지도 함께 설계해 보세요.
