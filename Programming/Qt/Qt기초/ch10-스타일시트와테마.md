9장에서는 위젯이 사용자 입력에 어떻게 반응하는지, 즉 위젯의 **동작**을 다뤘습니다. 이번 장에서는 시선을 돌려 위젯의 **겉모습**을 다룹니다. Qt는 위젯의 색상, 테두리, 여백 같은 시각적 요소를 CSS와 비슷한 문법으로 기술할 수 있는 **Qt 스타일시트(Qt Style Sheets, 이하 QSS)** 를 제공합니다. 버튼 하나의 배경색을 바꾸는 간단한 작업부터, 애플리케이션 전체에 다크 테마를 적용하는 작업까지 QSS 하나로 해결할 수 있습니다.

이번 장에서는 QSS의 문법과 선택자 종류를 익히고, 위젯 단위·애플리케이션 단위로 스타일시트를 적용하는 방법을 배웁니다. 이어서 다크/라이트 테마를 토글하는 실습 예제를 작성하고, QSS보다 더 저수준의 색상 커스터마이징 도구인 `QPalette`를 살펴본 뒤, 8장에서 만든 것과 같은 커스텀 페인트 위젯이 QSS의 영향을 받지 않을 수 있다는 중요한 함정까지 짚어봅니다.

## 10.1 Qt 스타일시트(QSS)란

QSS는 웹의 CSS(Cascading Style Sheets)에서 문법적 영감을 받아 만들어진, Qt 위젯 전용 스타일링 언어입니다. `선택자 { 속성: 값; }` 형태로 규칙을 작성한다는 점에서 CSS와 매우 비슷해 보이지만, 다루는 대상이 HTML 문서가 아니라 C++로 만들어진 위젯 트리라는 점에서 세부적인 동작 방식은 다릅니다.

```qss
QPushButton {
    background-color: #3c3f41;
    color: white;
    border: 1px solid #555555;
    border-radius: 4px;
    padding: 6px 12px;
}
```

### QSS와 CSS의 공통점과 차이점

| 구분 | CSS | QSS |
|---|---|---|
| 적용 대상 | HTML 문서의 DOM 엘리먼트 | `QWidget`과 그 서브클래스 인스턴스 |
| 선택자 문법 | 태그명, 클래스(`.foo`), ID(`#foo`) | Qt 클래스명, `#objectName`, `.ClassName`(정확한 타입만) |
| 상속 매칭 | 태그명은 정확히 일치해야 함 | 타입 선택자는 기본적으로 해당 클래스와 그 **서브클래스까지** 매칭 |
| 레이아웃 속성 | `display`, `position`, `flex` 등 풍부한 레이아웃 제어 | 레이아웃은 QSS의 몫이 아님. 위치·크기는 여전히 `QLayout`(4장)이 담당 |
| 지원 범위 | 브라우저가 그리는 모든 요소 | `QStyle`을 거쳐 그려지는 표준 위젯 위주. 직접 `QPainter`로 그리는 위젯은 별도 처리가 필요(10.7절) |
| 단위 | `px`, `em`, `%`, `rem` 등 다양 | 대부분 정수 픽셀 값(단위 없이 숫자만 표기) |

가장 중요한 차이는 **QSS는 위젯의 위치나 크기 배치(레이아웃)에 관여하지 않는다**는 점입니다. 버튼을 어디에 놓을지는 여전히 `QVBoxLayout`, `QGridLayout` 같은 레이아웃 매니저의 역할이며, QSS는 오직 이미 배치된 위젯이 어떤 색과 테두리로 그려질지만 결정합니다.

## 10.2 스타일시트 적용하기: setStyleSheet()

QSS 문자열을 적용하는 함수는 `setStyleSheet(const QString &styleSheet)`입니다. 이 함수는 두 군데에 존재합니다.

### 위젯 단위 적용

`QWidget::setStyleSheet()`를 호출하면 해당 위젯과 그 자식 위젯들에게 스타일이 적용됩니다.

```cpp
#include <QPushButton>

auto *button = new QPushButton(tr("저장"), this);
button->setStyleSheet(
    "background-color: #4a90d9;"
    "color: white;"
    "border-radius: 6px;"
    "padding: 8px 16px;"
);
```

빈 문자열을 다시 넣으면(`button->setStyleSheet("")`) 해당 위젯에 직접 지정했던 스타일시트가 제거되고, 상위(부모 위젯이나 애플리케이션)에서 내려오는 스타일시트만 남습니다.

### 애플리케이션 전체 적용

`QApplication`에도 동일한 이름의 `styleSheet` 프로퍼티가 있습니다. `qApp->setStyleSheet(...)`(또는 `QApplication::instance()->setStyleSheet(...)`)로 지정하면 애플리케이션 안의 **모든** 위젯에 스타일이 적용됩니다. 10.5절에서 만들 다크/라이트 테마 전환 기능은 이 방식을 사용합니다.

```cpp
#include <QApplication>

int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    app.setStyleSheet(
        "QWidget { background-color: #f5f5f5; }"
        "QPushButton { padding: 6px 14px; border-radius: 4px; }"
    );

    // ... 창 생성 및 표시
    return app.exec();
}
```

위젯 단위 스타일시트와 애플리케이션 단위 스타일시트는 서로 배타적이지 않고 **계단식으로(cascading) 함께 적용**됩니다. 애플리케이션 전체에 배경색을 지정해 두었더라도, 특정 버튼에만 `setStyleSheet()`로 다른 배경색을 지정하면 그 버튼에는 더 가까운(더 구체적인) 규칙이 우선 적용됩니다. 이는 CSS의 캐스케이딩 개념과 유사합니다.

## 10.3 선택자의 종류

### 타입 선택자와 상속 매칭

가장 기본적인 선택자는 위젯의 클래스명을 그대로 쓰는 **타입 선택자**입니다.

```qss
QPushButton {
    border: 1px solid gray;
}
```

CSS의 태그 선택자와 달리, QSS의 타입 선택자는 **해당 클래스뿐 아니라 그 클래스를 상속한 모든 서브클래스에도 매칭**됩니다. 예를 들어 `QPushButton`을 상속해서 만든 커스텀 버튼 클래스가 있다면, 위 규칙은 그 커스텀 버튼에도 그대로 적용됩니다. 이는 "새로 만든 위젯이 기존 스타일을 자연스럽게 물려받는다"는 점에서 대체로 편리한 기본 동작입니다.

### 클래스 선택자: 정확한 타입만 선택

반대로 상속 관계를 무시하고 **정확히 그 클래스의 인스턴스에만** 규칙을 적용하고 싶다면, 클래스명 앞에 마침표(`.`)를 붙인 **클래스 선택자**를 사용합니다.

```qss
.QPushButton {
    background-color: lightgray; /* QPushButton 자신에만 적용, 서브클래스는 제외 */
}
```

`QPushButton`을 상속한 `RoundIconButton` 같은 커스텀 클래스가 있다면, `.QPushButton` 규칙은 이 서브클래스에는 적용되지 않습니다. 반면 접두사 없는 `QPushButton { ... }` 규칙은 `RoundIconButton`에도 계속 적용됩니다. 커스텀 위젯에는 다른 스타일을 주고 싶을 때 이 차이를 활용할 수 있습니다.

### #objectName 선택자 (ID 선택자)

CSS의 ID 선택자처럼, `objectName` 프로퍼티 값을 기준으로 특정 위젯 하나만 정확히 지정할 수 있습니다. `objectName`은 `QObject::setObjectName()`으로 지정합니다.

```cpp
auto *dangerButton = new QPushButton(tr("모두 삭제"), this);
dangerButton->setObjectName("dangerButton");
```

```qss
#dangerButton {
    background-color: #d9534f;
    color: white;
    font-weight: bold;
}
```

같은 `QPushButton`이 여러 개 있어도 `#dangerButton`은 오직 `objectName`이 "dangerButton"인 위젯에만 매칭됩니다. 여러 화면에 흩어져 있는 특정 버튼 하나만 눈에 띄게 강조하고 싶을 때 유용합니다.

### 의사 상태(pseudo-state): :hover, :pressed, :checked

위젯의 **현재 상태**에 따라 다른 스타일을 적용하고 싶을 때는 의사 상태 선택자를 씁니다. CSS의 `:hover` 같은 의사 클래스와 이름과 쓰임새가 비슷합니다.

```qss
QPushButton {
    background-color: #e0e0e0;
    border: 1px solid #b0b0b0;
    border-radius: 4px;
    padding: 6px 12px;
}

QPushButton:hover {
    background-color: #d0d0d0;   /* 마우스가 위에 올라갔을 때 */
}

QPushButton:pressed {
    background-color: #b8b8b8;   /* 눌려 있는 동안 */
}

QPushButton:checked {
    background-color: #a0c8ff;   /* setCheckable(true)인 버튼이 선택된 상태일 때 */
    border: 1px solid #4a90d9;
}

QPushButton:disabled {
    color: #a0a0a0;              /* setEnabled(false)인 상태일 때 */
}
```

`:checked`는 `setCheckable(true)`로 지정한 `QPushButton`이나 `QCheckBox`, `QRadioButton`처럼 "눌린 채로 유지되는" 위젯의 선택 상태를 나타냅니다. 여러 의사 상태를 조합할 수도 있습니다. 예를 들어 `QPushButton:checked:hover`는 "선택된 상태이면서 동시에 마우스가 올라가 있는" 경우에만 매칭됩니다.

### 자손 선택자와 자식 선택자

특정 컨테이너 안에 있는 위젯만 골라서 스타일을 주고 싶을 때는 CSS와 마찬가지로 공백과 `>`를 사용합니다.

```qss
/* QGroupBox 안에 있는 모든 QPushButton (직계 자식이 아니어도 됨) */
QGroupBox QPushButton {
    padding: 4px 10px;
}

/* QToolBar의 직계 자식인 QPushButton만 */
QToolBar > QPushButton {
    border: none;
}
```

## 10.4 자주 쓰는 속성과 선택자 우선순위

QSS가 지원하는 속성은 CSS만큼 방대하지는 않지만, 데스크톱 UI를 꾸미는 데 필요한 핵심 속성은 대부분 갖추고 있습니다.

| 속성 | 설명 |
|---|---|
| `background-color` | 배경색 (`#rrggbb`, `rgb(r,g,b)`, 색상 이름 등) |
| `color` | 전경색(주로 텍스트) |
| `border`, `border-width`, `border-style`, `border-color` | 테두리 관련 속성 |
| `border-radius` | 모서리를 둥글게 처리 |
| `padding` | 위젯 내용과 테두리 사이 여백 |
| `margin` | 위젯 바깥쪽 여백 |
| `font-family`, `font-size`, `font-weight` | 글꼴 관련 속성 |
| `selection-background-color`, `selection-color` | 텍스트 선택 영역의 배경색/글자색 (`QLineEdit`, `QTextEdit` 등) |
| `alternate-background-color` | 목록/표에서 짝수·홀수 행을 구분하는 배경색 (`QAbstractItemView::setAlternatingRowColors(true)`와 함께 사용) |
| `gridline-color` | `QTableView`의 격자선 색상 |

여러 규칙이 같은 위젯의 같은 속성에 동시에 매칭될 경우, QSS는 CSS와 유사하게 **더 구체적인 선택자**(예: `#objectName`이 타입 선택자보다 우선)와 **나중에 선언된 규칙**을 우선시합니다. 의도한 대로 스타일이 적용되지 않는다면, 먼저 더 구체적인 다른 규칙이 같은 속성을 덮어쓰고 있지 않은지 확인해 보는 것이 좋습니다.

## 10.5 다크/라이트 테마 전환 예제

지금까지 배운 내용을 종합해서, 버튼 하나로 라이트 테마와 다크 테마를 전환하는 예제를 만들어 보겠습니다. 핵심 아이디어는 두 개의 QSS 문자열을 미리 준비해 두고, `qApp->setStyleSheet()`로 통째로 바꿔치기하는 것입니다.

```cpp
// ThemeStyles.h
#pragma once

#include <QString>

namespace ThemeStyles {

inline const QString kLight = R"(
    QWidget {
        background-color: #f5f5f5;
        color: #202020;
    }
    QPushButton {
        background-color: #e0e0e0;
        border: 1px solid #b0b0b0;
        border-radius: 4px;
        padding: 6px 12px;
    }
    QPushButton:hover {
        background-color: #d0d0d0;
    }
    QPushButton:pressed {
        background-color: #b8b8b8;
    }
    QPushButton:checked {
        background-color: #a0c8ff;
        border: 1px solid #4a90d9;
    }
    QLineEdit {
        background-color: white;
        border: 1px solid #b0b0b0;
        border-radius: 3px;
        padding: 4px;
    }
)";

inline const QString kDark = R"(
    QWidget {
        background-color: #2b2b2b;
        color: #e0e0e0;
    }
    QPushButton {
        background-color: #3c3f41;
        color: #e0e0e0;
        border: 1px solid #555555;
        border-radius: 4px;
        padding: 6px 12px;
    }
    QPushButton:hover {
        background-color: #4c4f51;
    }
    QPushButton:pressed {
        background-color: #2a2a2a;
    }
    QPushButton:checked {
        background-color: #3a6ea5;
        border: 1px solid #5a9fd4;
    }
    QLineEdit {
        background-color: #3c3f41;
        color: #e0e0e0;
        border: 1px solid #555555;
        border-radius: 3px;
        padding: 4px;
    }
)";

} // namespace ThemeStyles
```

`R"( ... )"` 형태는 C++11의 원시 문자열 리터럴(raw string literal)로, 문자열 안에 큰따옴표나 줄바꿈을 이스케이프 없이 그대로 담을 수 있어 여러 줄짜리 QSS를 작성할 때 편리합니다.

이제 이 스타일을 토글하는 `MainWindow`를 작성합니다.

```cpp
// MainWindow.h
#pragma once

#include <QMainWindow>

class MainWindow : public QMainWindow
{
    Q_OBJECT

public:
    explicit MainWindow(QWidget *parent = nullptr);

private slots:
    void applyTheme(bool dark);
};
```

```cpp
// MainWindow.cpp
#include "MainWindow.h"
#include "ThemeStyles.h"

#include <QApplication>
#include <QAction>
#include <QMenuBar>
#include <QPushButton>
#include <QLineEdit>
#include <QVBoxLayout>
#include <QWidget>

MainWindow::MainWindow(QWidget *parent)
    : QMainWindow(parent)
{
    auto *central = new QWidget(this);
    auto *layout = new QVBoxLayout(central);

    auto *nameEdit = new QLineEdit(central);
    nameEdit->setPlaceholderText(tr("이름을 입력하세요"));

    auto *okButton = new QPushButton(tr("확인"), central);

    layout->addWidget(nameEdit);
    layout->addWidget(okButton);
    setCentralWidget(central);

    // 다크 테마 토글용 체크 가능한 액션
    auto *themeAction = new QAction(tr("다크 테마"), this);
    themeAction->setCheckable(true);
    connect(themeAction, &QAction::toggled, this, &MainWindow::applyTheme);
    menuBar()->addAction(themeAction);

    applyTheme(false); // 시작할 때는 라이트 테마
}

void MainWindow::applyTheme(bool dark)
{
    qApp->setStyleSheet(dark ? ThemeStyles::kDark : ThemeStyles::kLight);
}
```

메뉴바의 "다크 테마" 액션을 체크하면 `applyTheme(true)`가 호출되어 애플리케이션 전체가 다크 테마 스타일시트로 바뀌고, 체크를 해제하면 라이트 테마로 돌아갑니다. `qApp->setStyleSheet()`는 매번 이전 스타일시트를 완전히 대체하므로, 두 테마를 동시에 섞어 쓸 걱정 없이 깔끔하게 전환됩니다.

> 참고: 이 예제처럼 두 문자열을 통째로 바꾸는 방식은 이해하기 쉽고 구현이 간단하지만, 테마가 많아지거나 색상 값을 여러 곳에서 재사용해야 한다면 QSS 문자열을 색상 팔레트 변수 없이 직접 나열하는 대신, 코드에서 `QString::arg()`나 템플릿 치환으로 색상 값을 주입하는 방식을 고려할 수 있습니다.

## 10.6 QPalette를 이용한 저수준 색상 커스터마이징

QSS가 등장하기 이전부터 Qt는 `QPalette`라는 클래스로 위젯의 색상을 관리해 왔습니다. QSS를 전혀 쓰지 않는 애플리케이션도 여전히 내부적으로는 `QPalette`에 정의된 색상들을 사용해 그려집니다.

### 색상 역할(ColorRole)과 색상 그룹(ColorGroup)

`QPalette`는 개별 색상값 대신 **역할(role)** 단위로 색을 관리합니다. 대표적인 역할은 다음과 같습니다.

| ColorRole | 의미 |
|---|---|
| `QPalette::Window` | 위젯의 일반적인 배경색 |
| `QPalette::WindowText` | 배경 위에 놓이는 일반 텍스트 색 |
| `QPalette::Base` | `QLineEdit`, `QTextEdit`, 뷰(view)류 위젯의 입력 영역 배경색 |
| `QPalette::Text` | `Base` 위에 놓이는 텍스트 색 |
| `QPalette::Button` | 버튼류 위젯의 배경색 |
| `QPalette::ButtonText` | 버튼 위의 텍스트 색 |
| `QPalette::Highlight` | 선택된 항목의 배경색 |
| `QPalette::HighlightedText` | 선택된 항목의 텍스트 색 |

또한 같은 역할이라도 위젯이 처한 **상태**에 따라 다른 색이 적용될 수 있는데, 이를 `QPalette::ColorGroup`으로 구분합니다.

- `QPalette::Active`: 현재 활성(포커스를 가진) 창의 위젯
- `QPalette::Inactive`: 비활성 창의 위젯
- `QPalette::Disabled`: `setEnabled(false)`로 비활성화된 위젯

```cpp
QPalette pal = widget->palette();
pal.setColor(QPalette::Window, QColor("#2b2b2b"));
pal.setColor(QPalette::WindowText, Qt::white);
pal.setColor(QPalette::Button, QColor("#3c3f41"));
pal.setColor(QPalette::ButtonText, Qt::white);
pal.setColor(QPalette::Highlight, QColor("#3a6ea5"));
pal.setColor(QPalette::HighlightedText, Qt::white);

// 비활성화된 상태에서는 글자색을 흐리게
pal.setColor(QPalette::Disabled, QPalette::WindowText, QColor("#808080"));

widget->setPalette(pal);
widget->setAutoFillBackground(true); // Window 색상을 실제로 배경에 칠하도록 지시
```

`setAutoFillBackground(true)`를 함께 호출해야 하는 이유는, 일반 `QWidget`은 기본적으로 자신의 배경을 자동으로 채우지 않기 때문입니다. 이 속성을 켜면 위젯이 그려지기 전에 `QPalette::Window` 색으로 배경이 먼저 칠해집니다.

### QSS와 QPalette의 관계와 차이

QSS와 `QPalette`는 목적이 겹치지만 동작 방식이 다릅니다.

- **적용 범위**: `QPalette`는 색상만 지정할 수 있습니다. 테두리 모양, 모서리 둥글기, 여백처럼 QSS가 제공하는 세밀한 박스 모델 속성은 `QPalette`로 표현할 수 없습니다.
- **렌더링 경로**: `QPalette`로 지정한 색은 플랫폼 스타일(`QStyle`, 예를 들어 Windows 스타일이나 Fusion 스타일)이 위젯을 그릴 때 참고하는 값입니다. 즉 버튼의 입체감이나 눌림 효과 같은 플랫폼 고유의 표현은 그대로 유지한 채 색상만 바뀝니다. 반면 QSS는 위젯의 그리기 방식 자체를 QSS 규칙에 맞춰 새로 정의하므로, 스타일시트가 적용된 위젯은 플랫폼 고유의 외형을 잃고 QSS가 지시한 모양대로 그려집니다.
- **우선순위**: 어떤 위젯에 QSS 규칙이 하나라도 매칭되면, Qt는 내부적으로 그 위젯의 렌더링을 `QStyleSheetStyle`이라는 특수한 스타일로 감쌉니다. 이 경우 QSS가 `QPalette` 값보다 우선 적용됩니다. 즉 같은 위젯에 두 가지를 모두 설정했다면 QSS 쪽이 최종 결과를 결정합니다.

정리하면, 플랫폼 고유의 느낌(윈도우는 윈도우답게, macOS는 macOS답게)을 최대한 유지하면서 색상 몇 가지만 손보고 싶다면 `QPalette`가, 플랫폼에 상관없이 일관된 디자인을 강하게 적용하고 싶다면 QSS가 더 적합한 도구입니다. 실무에서는 대부분 QSS를 주로 사용하고, `QPalette`는 QSS로 다루기 번거로운 극히 일부 시스템 색상(예: 선택 영역 색)을 보조적으로 조정할 때 함께 쓰는 경우가 많습니다.

## 10.7 커스텀 페인트 위젯과 QSS의 한계

QSS는 `QStyle`을 거쳐 그려지는 표준 위젯(`QPushButton`, `QLineEdit`, `QLabel` 등)에는 잘 작동합니다. 하지만 8장에서 다룬 것처럼 `paintEvent()`를 직접 오버라이드해서 `QPainter`로 내용을 그리는 커스텀 위젯은 사정이 다릅니다. 일반 `QWidget`을 상속한 위젯은 기본적으로 자신의 배경과 테두리를 QSS 규칙에 따라 자동으로 그려주지 않기 때문입니다.

예를 들어 9장에서 만든 `DrawingWidget`(마우스로 그림을 그리는 위젯)에 다음과 같이 스타일시트를 적용해도 겉모습은 바뀌지 않습니다.

```cpp
auto *canvas = new DrawingWidget(this);
canvas->setStyleSheet("background-color: #1e1e1e; border: 2px solid #444444;");
// DrawingWidget::paintEvent()가 배경/테두리를 그리지 않는 한 아무 효과가 없다
```

`DrawingWidget::paintEvent()`는 오직 점을 찍는 코드만 담고 있을 뿐, `background-color`나 `border` 값을 참고해서 배경을 칠하는 코드는 어디에도 없기 때문입니다. QSS 엔진은 이런 위젯에 규칙을 강제로 그려 넣지 않습니다.

이 문제를 해결하는 방법은 크게 두 가지입니다.

**1. `Qt::WA_StyledBackground` 속성 사용하기.** 가장 간단한 방법으로, 위젯 생성 시 이 속성을 켜면 Qt가 `paintEvent()`가 실행되기 전에 QSS로 지정된 배경과 테두리를 자동으로 먼저 그려 줍니다.

```cpp
DrawingWidget::DrawingWidget(QWidget *parent)
    : QWidget(parent)
{
    setMinimumSize(400, 300);
    setAttribute(Qt::WA_StyledBackground, true); // QSS 배경/테두리를 자동으로 반영
}
```

**2. `paintEvent()` 안에서 직접 스타일을 그리기.** 배경을 그리는 시점이나 방식을 더 세밀하게 제어해야 한다면, `QStyleOption`과 현재 위젯의 `style()`을 이용해 QSS(또는 팔레트) 기반 배경을 직접 그린 뒤 그 위에 커스텀 내용을 이어서 그릴 수 있습니다.

```cpp
void DrawingWidget::paintEvent(QPaintEvent *event)
{
    QPainter painter(this);

    // 1) 현재 스타일(QSS 포함)에 따라 위젯의 배경/테두리를 먼저 그린다.
    QStyleOption opt;
    opt.initFrom(this);
    style()->drawPrimitive(QStyle::PE_Widget, &opt, &painter, this);

    // 2) 그 위에 커스텀 콘텐츠를 이어서 그린다.
    painter.setRenderHint(QPainter::Antialiasing);
    painter.setBrush(Qt::black);
    painter.setPen(Qt::NoPen);
    for (const QPoint &p : m_points) {
        painter.drawEllipse(p, 3, 3);
    }

    Q_UNUSED(event);
}
```

두 방법 모두 "QSS가 그린 배경 위에 내가 그린 그림을 올린다"는 결과는 같습니다. 커스텀 위젯을 새로 만들 때마다 이 점을 매번 기억하기는 쉽지 않으므로, 커스텀 위젯이 화면에서 배경색이 적용되지 않는 문제를 겪는다면 가장 먼저 `Qt::WA_StyledBackground` 설정 여부를 의심해 보는 것이 좋습니다.

## 요약

- QSS(Qt Style Sheets)는 CSS와 비슷한 문법으로 위젯의 색상, 테두리, 여백 등을 지정하는 스타일링 언어입니다. 다만 레이아웃(배치)에는 관여하지 않으며, 타입 선택자가 기본적으로 서브클래스까지 매칭된다는 점에서 CSS와 차이가 있습니다.
- `QWidget::setStyleSheet()`는 특정 위젯(과 그 자식)에, `QApplication::setStyleSheet()`(`qApp->setStyleSheet()`)는 애플리케이션 전체에 스타일을 적용합니다. 두 스타일시트는 계단식으로 함께 적용됩니다.
- 선택자에는 타입 선택자(`QPushButton`, 서브클래스 포함), 클래스 선택자(`.QPushButton`, 정확한 타입만), ID 선택자(`#objectName`), 의사 상태(`:hover`, `:pressed`, `:checked` 등)가 있으며, 자손/자식 선택자로 특정 컨테이너 안의 위젯만 골라낼 수도 있습니다.
- 두 개의 QSS 문자열을 미리 준비해 두고 `qApp->setStyleSheet()`로 통째로 교체하면 라이트/다크 테마를 간단하게 전환할 수 있습니다.
- `QPalette`는 색상 역할(`ColorRole`)과 색상 그룹(`ColorGroup`) 단위로 색을 관리하는 저수준 API로, 플랫폼 고유의 외형을 유지하면서 색상만 바꾸고 싶을 때 사용합니다. 다만 같은 위젯에 QSS 규칙이 매칭되면 QSS가 `QPalette`보다 우선 적용됩니다.
- `paintEvent()`를 직접 구현하는 커스텀 위젯은 기본적으로 QSS 배경/테두리를 자동으로 반영하지 않습니다. `Qt::WA_StyledBackground` 속성을 켜거나, `paintEvent()` 안에서 `style()->drawPrimitive(QStyle::PE_Widget, ...)`을 호출해 직접 배경을 그려야 합니다.

   ```qss
   .QPushButton { background-color: lightgray; }
   ```

3. `:hover`, `:pressed`, `:checked` 의사 상태의 차이를 각각 어떤 사용자 동작에 대응하는지 기준으로 설명하고, 세 상태를 모두 활용하는 토글 버튼 스타일시트를 작성해 보세요.
4. `QPalette`로 색상을 바꾸는 방법과 QSS로 색상을 바꾸는 방법의 차이를 렌더링 경로와 우선순위 관점에서 서술하고, 각각 어떤 상황에 더 적합한지 예를 들어 설명하시오.
