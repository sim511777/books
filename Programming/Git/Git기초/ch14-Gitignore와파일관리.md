프로젝트를 진행하다 보면 저장소 안에 정작 버전 관리할 필요가 없는 파일들이 자꾸 섞여 들어옵니다. 컴파일러가 만들어내는 빌드 산출물, 에디터가 자동으로 생성하는 설정 파일, 로그 파일, 운영체제가 폴더마다 슬쩍 남겨두는 숨김 파일 같은 것들입니다. 이런 파일들을 그때그때 무시하지 않고 `git add .`를 습관적으로 실행하다 보면, 어느새 저장소에는 협업에 아무 의미가 없는 파일들이 잔뜩 쌓이고, 심지어 팀원마다 다른 운영체제나 에디터를 쓰는 경우 이런 파일들이 충돌의 원인이 되기도 합니다.

이번 장에서는 Git이 특정 파일을 아예 추적 대상에서 제외하도록 지시하는 `.gitignore` 파일의 문법을 살펴보고, 이미 실수로 커밋해버린 파일을 뒤늦게 무시 목록에 추가하는 방법을 다룹니다. 이어서 파일별로 동작 방식을 지정하는 `.gitattributes`, 대용량 파일을 다루는 Git LFS의 개념, 그리고 여러 프로젝트에 공통으로 적용할 수 있는 전역 `.gitignore` 설정까지 알아보겠습니다.

## 14.1 .gitignore가 필요한 이유

저장소 최상위(또는 원하는 하위 디렉터리)에 `.gitignore`라는 이름의 파일을 만들고, 그 안에 무시하고 싶은 파일이나 디렉터리의 패턴을 한 줄에 하나씩 적어두면, Git은 `git status`나 `git add`에서 그 패턴에 맞는 파일들을 추적되지 않은 파일 목록에서 아예 제외합니다.

```bash
# 저장소 루트에 .gitignore 파일 생성
touch .gitignore
```

`.gitignore`에 아무것도 적지 않은 상태에서 `git status`를 실행하면 빌드 산출물이나 로그 파일까지 모두 "Untracked files" 목록에 나타나 눈에 거슬립니다. 무시 패턴을 등록해두면 이런 파일들은 애초에 목록에 나타나지 않으므로, `git status`의 출력이 실제로 신경 써야 할 변경 사항만 깔끔하게 보여주게 됩니다.

## 14.2 .gitignore 문법

`.gitignore`의 문법은 단순하지만, 몇 가지 규칙을 정확히 알아두어야 의도한 대로 동작합니다.

### 정확한 파일명

파일 이름을 그대로 한 줄에 적으면 저장소의 모든 위치에서 그 이름과 일치하는 파일이 무시됩니다.

```
config.local.json
```

### 와일드카드

`*`는 슬래시를 제외한 임의의 문자열과 일치합니다. 확장자 단위로 무시할 때 자주 사용합니다.

```
*.log
*.tmp
```

`?`는 한 글자와 일치합니다.

```
report-?.csv
```

### 디렉터리 무시

이름 끝에 슬래시(`/`)를 붙이면 그 이름을 가진 디렉터리 전체(와 그 안의 모든 내용물)를 무시합니다.

```
build/
node_modules/
dist/
```

슬래시 없이 `build`라고만 적으면 같은 이름의 파일도 함께 무시 대상이 되므로, 디렉터리임을 명확히 하고 싶다면 끝에 슬래시를 붙이는 습관을 들이는 것이 좋습니다.

### 특정 위치로 한정하기

패턴 앞에 슬래시를 붙이면 저장소 루트를 기준으로 한 경로로 한정됩니다.

```
/config.json
```

이렇게 적으면 루트에 있는 `config.json`만 무시되고, 하위 디렉터리에 있는 `src/config.json` 같은 파일은 무시되지 않습니다. 슬래시 없이 `config.json`이라고만 적으면 저장소 어느 위치에 있든 같은 이름의 파일이 모두 무시됩니다.

중간에 슬래시가 포함된 패턴(예: `logs/debug.log`)도 마찬가지로 그 경로 자체를 기준으로 해석됩니다.

### 깊이에 상관없이 일치시키기(`**`)

`**`는 0개 이상의 디렉터리 단계와 일치하는 패턴입니다. 예를 들어 디렉터리 이름과 상관없이 모든 `temp` 폴더를 무시하고 싶다면 다음과 같이 씁니다.

```
**/temp/
```

특정 디렉터리 아래의 모든 내용을 깊이에 상관없이 무시하고 싶을 때도 사용합니다.

```
logs/**/*.log
```

### 부정 패턴(예외 지정)

`!`로 시작하는 패턴은 앞서 무시하기로 한 규칙 중 일부를 다시 추적 대상으로 되돌립니다.

```
*.log
!important.log
```

위 설정은 `*.log`로 모든 로그 파일을 무시하되, `important.log`만은 예외로 두어 계속 추적하겠다는 뜻입니다. 단, 여기에는 중요한 주의사항이 있습니다. 어떤 디렉터리 자체가 이미 무시된 상태라면, 그 디렉터리 안의 파일에 대해서는 `!` 예외 패턴이 적용되지 않습니다. 예를 들어 `build/`로 디렉터리 전체를 무시해둔 상태에서 `!build/keep.txt`를 추가해도, Git은 애초에 `build/` 디렉터리 내부를 들여다보지 않으므로 이 예외 규칙이 동작하지 않습니다. 특정 파일만 예외로 남기고 싶다면 디렉터리 전체가 아니라 그 안의 파일 패턴 단위로 무시 규칙을 세밀하게 작성해야 합니다.

### 주석과 빈 줄

`#`으로 시작하는 줄은 주석으로 처리되어 무시됩니다. 빈 줄은 가독성을 위한 구분선으로만 쓰이고 아무 패턴에도 영향을 주지 않습니다.

```
# 빌드 산출물
build/
dist/

# 에디터 설정 파일
.vscode/
.idea/

# OS가 생성하는 파일
.DS_Store
Thumbs.db
```

## 14.3 이미 커밋된 파일을 나중에 무시하고 싶을 때

`.gitignore`는 어디까지나 "아직 추적되지 않은 파일"에만 효과가 있습니다. 만약 어떤 파일이 이미 커밋되어 Git이 추적 중이라면, 그 파일 이름을 나중에 `.gitignore`에 추가하더라도 Git은 계속 그 파일의 변경 사항을 추적합니다. `.gitignore`는 새로 추가하는 파일을 걸러내는 필터일 뿐, 이미 저장소 이력에 들어와 있는 파일을 자동으로 빼내주지는 않습니다.

이런 경우에는 `git rm --cached` 명령으로 파일을 Git의 추적 대상에서만 제외해야 합니다. `--cached` 옵션은 스테이징 영역(그리고 이후 커밋)에서만 파일을 제거하고, 작업 디렉터리에 있는 실제 파일은 그대로 남겨둡니다.

```bash
# 실수로 커밋해버린 설정 파일을 추적에서만 제외
git rm --cached config.local.json

# .gitignore에 패턴 추가
echo "config.local.json" >> .gitignore

git add .gitignore
git commit -m "config.local.json을 추적에서 제외"
```

디렉터리 전체를 추적에서 제외하고 싶다면 `-r` 옵션을 함께 사용합니다.

```bash
git rm -r --cached logs/

echo "logs/" >> .gitignore

git add .gitignore
git commit -m "logs 디렉터리를 추적에서 제외"
```

`--cached`를 빼고 그냥 `git rm`을 실행하면 작업 디렉터리의 실제 파일까지 삭제되어버리므로, 파일은 로컬에 남겨둔 채 추적만 해제하고 싶을 때는 반드시 `--cached` 옵션을 함께 써야 합니다.

## 14.4 .gitattributes로 파일별 동작 지정하기

`.gitignore`가 "이 파일을 추적할지 말지"를 결정하는 파일이라면, `.gitattributes`는 "추적하는 파일을 Git이 어떻게 다룰지"를 세밀하게 지정하는 파일입니다. `.gitignore`와 마찬가지로 저장소 루트에 두며, 패턴과 속성을 한 줄에 하나씩 적습니다.

### 줄바꿈(line ending) 정규화

Windows는 줄바꿈으로 `CRLF`를, macOS와 Linux는 `LF`를 기본으로 사용합니다. 서로 다른 운영체제를 쓰는 팀원들이 같은 저장소에서 작업하면, 파일을 열기만 해도 줄바꿈 문자가 바뀌어 실제 내용은 그대로인데도 diff에 파일 전체가 변경된 것처럼 나타나는 문제가 자주 발생합니다. `.gitattributes`에 다음 한 줄을 추가하면 Git이 텍스트 파일의 줄바꿈을 저장소에는 항상 `LF`로 보관하고, 각자의 작업 디렉터리에는 운영체제에 맞는 방식으로 자동 변환해줍니다.

```
* text=auto
```

특정 확장자에 대해서만 줄바꿈 방식을 강제로 지정할 수도 있습니다.

```
*.sh text eol=lf
*.bat text eol=crlf
```

### 특정 파일을 diff에서 binary로 취급하기

이미지나 폰트처럼 텍스트가 아닌 파일인데도 Git이 이를 텍스트로 착각해 의미 없는 diff를 출력하는 경우가 있습니다. 이럴 때는 해당 패턴에 `binary` 속성을 지정해서 diff나 병합 시도를 하지 않도록 명시할 수 있습니다.

```
*.png binary
*.psd binary
```

`binary`는 사실 `-diff -merge -text`를 한꺼번에 지정하는 축약 표현으로, 해당 파일에 대해 텍스트 기반의 diff와 병합을 시도하지 않고 줄바꿈 변환도 하지 않도록 만듭니다.

`.gitattributes`는 이 밖에도 특정 경로에 대한 병합 전략 지정, 언어 통계에서 특정 파일을 제외하는 설정 등 다양한 용도로 쓰이지만, 이 책에서는 가장 기본적이고 실무에서 자주 마주치는 두 가지 용도만 소개합니다.

## 14.5 대용량 파일 문제와 Git LFS

Git은 원래 소스 코드처럼 크기가 작고 텍스트 기반인 파일을 다루는 데 최적화된 도구입니다. 커밋할 때마다 파일의 스냅샷을 저장하는 방식이기 때문에, 수십 MB에서 수 GB에 달하는 동영상, 대용량 이미지, 디자인 파일, 데이터셋 같은 것들을 그대로 커밋하면 저장소 전체 크기가 순식간에 불어나고, `clone`이나 `fetch` 같은 기본적인 작업조차 매우 느려집니다.

이 문제를 해결하기 위해 등장한 것이 **Git LFS(Large File Storage)** 입니다. Git LFS는 저장소에는 대용량 파일의 내용을 직접 저장하는 대신 그 파일을 가리키는 작은 포인터만 기록하고, 실제 파일 내용은 별도의 저장소에 보관하는 Git 확장 도구입니다. 이렇게 하면 Git 저장소 자체는 가벼운 상태를 유지하면서도, 필요한 시점에만 대용량 파일의 실제 내용을 내려받아 사용할 수 있습니다.

Git LFS는 Git 기본 설치에 포함되어 있지 않은 별도의 확장 프로그램이며, 사용하려면 `git-lfs`를 추가로 설치하고 저장소에서 초기화하는 과정이 필요합니다. 이 책은 Git 자체의 사용법을 다루는 범위로 한정하므로, Git LFS의 설치와 세부 설정 방법까지는 다루지 않습니다. 다만 "Git 저장소에 대용량 바이너리 파일을 그대로 쌓아두면 안 된다"는 점과, 그런 상황을 위한 별도의 도구가 존재한다는 사실은 꼭 기억해두시기 바랍니다.

## 14.6 여러 프로젝트에 공통으로 적용되는 전역 .gitignore

`.vscode/`, `.idea/`, `.DS_Store`, `*.swp`처럼 특정 프로젝트의 성격과 무관하게 개인의 개발 환경 때문에 항상 생겨나는 파일들이 있습니다. 이런 패턴을 프로젝트마다 매번 `.gitignore`에 반복해서 적어 넣는 대신, 컴퓨터 전체에 적용되는 전역 무시 목록을 한 번만 설정해둘 수 있습니다.

먼저 전역 무시 패턴을 담을 파일을 아무 위치에나 만듭니다.

```bash
touch ~/.gitignore_global
```

이 파일에 개인적으로 항상 무시하고 싶은 패턴을 적습니다.

```
.DS_Store
Thumbs.db
.vscode/
.idea/
*.swp
```

그리고 이 파일을 전역 설정으로 등록합니다.

```bash
git config --global core.excludesfile ~/.gitignore_global
```

이렇게 설정해두면, 이 컴퓨터에서 다루는 모든 저장소에서 프로젝트별 `.gitignore` 유무와 상관없이 전역 무시 목록이 함께 적용됩니다. 다만 이 설정은 어디까지나 사용자 개인의 환경에만 적용될 뿐 저장소에 함께 커밋되어 팀원들과 공유되는 파일이 아니므로, 팀 전체가 공통으로 지켜야 할 무시 규칙(예: 그 프로젝트의 빌드 산출물 디렉터리)은 반드시 프로젝트의 `.gitignore`에 넣어 저장소와 함께 커밋해야 합니다. 전역 `.gitignore`는 어디까지나 "이 파일들은 어떤 프로젝트를 하든 나에게는 항상 무의미하다"고 할 수 있는, 개인 개발 환경에 국한된 패턴을 위한 보조 수단으로 사용하는 것이 적절합니다.

## 요약

- `.gitignore`는 저장소에서 추적하지 않을 파일이나 디렉터리 패턴을 지정하는 파일입니다. 정확한 파일명, `*`/`?` 와일드카드, 끝에 슬래시를 붙인 디렉터리 패턴, `!`로 시작하는 부정(예외) 패턴을 조합해 사용합니다.
- 이미 커밋되어 추적 중인 파일은 `.gitignore`에 나중에 추가해도 무시되지 않습니다. `git rm --cached`(디렉터리는 `-r --cached`)로 추적만 해제한 뒤 `.gitignore`에 패턴을 등록해야 합니다.
- `.gitattributes`는 추적 중인 파일을 Git이 어떻게 다룰지 지정하는 파일입니다. `* text=auto`로 줄바꿈을 자동 정규화하거나, `*.png binary`처럼 특정 파일을 diff/병합 대상에서 제외할 수 있습니다.
- 대용량 바이너리 파일을 Git 저장소에 그대로 쌓아두면 저장소가 비대해지고 성능이 떨어집니다. Git LFS는 이런 대용량 파일의 실제 내용을 별도 저장소에 보관하고 포인터만 커밋하는 확장 도구입니다.
- `git config --global core.excludesfile <경로>`로 전역 `.gitignore`를 설정하면, 개인 개발 환경 때문에 반복적으로 생기는 파일들을 모든 프로젝트에서 한 번의 설정으로 무시할 수 있습니다.

## 연습문제

1. 저장소 루트의 `secrets.env` 파일과, 위치에 상관없이 모든 `*.tmp` 파일, 그리고 `build`라는 이름의 디렉터리 전체를 무시하는 `.gitignore` 내용을 작성해보세요.
2. `*.log`를 모두 무시하되 `release-notes.log`만은 예외로 계속 추적하고 싶습니다. `.gitignore`에 어떤 두 줄을 추가해야 하나요?
3. 팀원이 실수로 `node_modules/` 디렉터리 전체를 커밋해버렸습니다. 이 디렉터리를 작업 디렉터리에서는 그대로 두되 Git 추적에서만 제외하고, 이후 다시 커밋되지 않도록 하는 과정을 순서대로 명령어로 작성해보세요.
4. `.gitattributes`에 `* text=auto`를 설정하는 것이 여러 운영체제에서 협업할 때 어떤 문제를 예방해주는지 설명해보세요.
5. Git LFS가 왜 필요한지, 그리고 일반적인 Git 저장소 관리 방식과 근본적으로 무엇이 다른지 자신의 말로 설명해보세요.
