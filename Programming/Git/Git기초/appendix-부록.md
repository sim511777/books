## 설치 가이드 요약

Git은 운영체제별로 설치 방법이 조금씩 다릅니다. 상세한 설치 화면은 버전에 따라 자주 바뀌므로, 이 부록에서는 각 운영체제에서 널리 쓰이는 설치 경로의 이름만 정리합니다.

- **Windows** - 공식 배포판인 **Git for Windows** 설치 프로그램을 내려받아 실행하는 방법이 가장 널리 쓰입니다. 설치 과정에서 기본 텍스트 편집기, 줄바꿈 문자 처리 방식(CRLF/LF) 등을 선택하는 화면이 나오는데, 특별한 이유가 없다면 설치 프로그램이 제시하는 기본값을 그대로 선택해도 무방합니다. 설치가 끝나면 `Git Bash`라는 터미널 프로그램이 함께 설치되어, 이 책의 셸 명령어 예제를 그대로 실행해 볼 수 있습니다.
- **macOS** - Xcode Command Line Tools에 포함된 Git을 사용하거나, 패키지 관리자인 **Homebrew**로 `brew install git` 명령을 실행해 설치할 수 있습니다. 터미널에서 `git`을 처음 실행하면 Command Line Tools 설치를 안내하는 창이 뜨는 경우도 있습니다.
- **Linux** - 대부분의 배포판은 패키지 관리자를 통해 Git을 설치합니다. Debian/Ubuntu 계열은 APT, Fedora 계열은 DNF, Arch 계열은 pacman처럼 배포판마다 사용하는 패키지 관리자로 `git` 패키지를 설치하면 됩니다.

설치가 끝나면 다음 명령으로 버전을 확인해 정상 설치 여부를 점검합니다.

```bash
git --version
```

설치 직후에는 커밋에 기록될 사용자 이름과 이메일을 전역 설정으로 등록해 두는 것이 좋습니다.

```bash
git config --global user.name "홍길동"
git config --global user.email "hong@example.com"
```

## 이 책에 등장한 주요 명령어 요약표

책 전체에서 다룬 명령어를 기능별로 정리하면 다음과 같습니다. "관련 내용" 열은 해당 명령어를 집중적으로 다룬 장을 가리킵니다.

### 저장소 기초: 기록하고 확인하기 (1장~3장, 7장)

| 명령어 | 설명 |
|---|---|
| `git init` | 현재 디렉터리를 Git 저장소로 초기화 |
| `git add <파일>` | 작업 디렉터리의 변경 사항을 스테이징 영역에 추가 |
| `git commit -m "<메시지>"` | 스테이징된 내용을 커밋으로 기록 |
| `git status` | 작업 디렉터리와 스테이징 영역의 상태 확인 |
| `git diff` | 작업 디렉터리와 스테이징 영역(또는 커밋) 간의 변경 내용 비교 |
| `git log` | 커밋 이력 조회 |

### 브랜치와 병합 (4장, 5장, 9장)

| 명령어 | 설명 |
|---|---|
| `git branch` | 브랜치 목록 확인 또는 새 브랜치 생성 |
| `git switch <브랜치>` | 다른 브랜치로 전환 |
| `git switch -c <브랜치>` | 새 브랜치를 만들면서 동시에 전환 |
| `git merge <브랜치>` | 지정한 브랜치를 현재 브랜치에 병합 |
| `git rebase <브랜치>` | 현재 브랜치의 커밋들을 지정한 브랜치 끝으로 재배치 |
| `git rebase --continue` | 충돌 해결 후 rebase를 이어서 진행 |
| `git rebase --abort` | 진행 중인 rebase를 취소하고 원래 상태로 복귀 |

### 원격 저장소 (6장, 11장)

| 명령어 | 설명 |
|---|---|
| `git clone <URL>` | 원격 저장소를 로컬로 복제 |
| `git remote add <이름> <URL>` | 원격 저장소를 로컬 저장소에 등록 |
| `git fetch <원격>` | 원격 저장소의 변경 사항을 가져오되 로컬 브랜치에는 반영하지 않음 |
| `git pull <원격> <브랜치>` | 원격 저장소의 변경 사항을 가져와 현재 브랜치에 병합(fetch + merge) |
| `git push <원격> <브랜치>` | 로컬 커밋을 원격 저장소로 전송 |
| `git push -u <원격> <브랜치>` | 푸시와 동시에 업스트림 브랜치 설정 |
| `git push --force-with-lease` | 원격 브랜치가 예상한 상태일 때만 강제 푸시 허용 |

### 되돌리기와 임시 저장 (8장, 10장)

| 명령어 | 설명 |
|---|---|
| `git restore <파일>` | 작업 디렉터리의 파일을 마지막 커밋(또는 지정한 시점) 상태로 되돌림 |
| `git reset <커밋>` | 현재 브랜치가 가리키는 커밋 위치를 이동(히스토리 재구성) |
| `git revert <커밋>` | 지정한 커밋의 변경 내용을 되돌리는 새 커밋을 생성 |
| `git stash` | 작업 중인 변경 사항을 임시로 저장하고 작업 디렉터리를 깨끗하게 정리 |
| `git stash pop` | 저장해 둔 변경 사항을 다시 꺼내 적용 |

### 태그와 릴리스 (13장, 18장)

| 명령어 | 설명 |
|---|---|
| `git tag` | 태그 목록 확인 |
| `git tag -a <태그명> -m "<메시지>"` | 주석이 달린(annotated) 태그 생성 |
| `git push <원격> <태그명>` | 특정 태그를 원격 저장소로 전송 |
| `git push <원격> --tags` | 로컬의 모든 태그를 원격 저장소로 전송 |

### 그 밖의 유용한 명령어 (14장~17장)

| 명령어 | 설명 | 관련 장 |
|---|---|---|
| `git submodule add <URL> <경로>` | 다른 저장소를 현재 저장소의 하위 디렉터리로 포함 | 15장 |
| `git submodule update --init --recursive` | 서브모듈을 초기화하고 내용을 내려받음 | 15장 |
| `git cat-file -p <해시>` | 커밋/트리/블롭 등 Git 객체의 내용을 그대로 출력(내부 구조 확인용) | 16장 |
| `git config core.hooksPath <경로>` | Git Hooks를 찾는 디렉터리를 저장소 안의 다른 경로로 지정 | 17장 |

## 자주 쓰는 명령어 치트시트

빠르게 참고할 수 있도록 자주 쓰는 명령어만 한 페이지로 압축했습니다.

```
[시작하기]
git init                          현재 디렉터리를 저장소로 초기화
git clone <URL>                   원격 저장소 복제
git config --global user.name ""  전역 사용자 이름 설정
git config --global user.email "" 전역 이메일 설정

[기록하기]
git status                        상태 확인
git add <파일>                    스테이징
git add .                         변경된 모든 파일 스테이징
git commit -m "메시지"            커밋
git log --oneline                 커밋 이력 한 줄씩 보기
git diff                          변경 내용 확인

[브랜치]
git branch                        브랜치 목록
git switch -c <이름>              브랜치 생성 후 전환
git switch <이름>                 브랜치 전환
git merge <브랜치>                병합
git rebase <브랜치>               리베이스
git branch -d <이름>              병합된 브랜치 삭제

[원격 저장소]
git remote -v                     등록된 원격 저장소 확인
git fetch                         원격 변경 사항 가져오기(반영 안 함)
git pull                          원격 변경 사항 가져와 병합
git push                          원격으로 커밋 전송
git push origin --delete <브랜치>  원격 브랜치 삭제

[되돌리기]
git restore <파일>                작업 디렉터리 변경 취소
git restore --staged <파일>       스테이징 취소
git reset --soft <커밋>           커밋만 취소, 변경 내용은 스테이징 상태로 유지
git revert <커밋>                 되돌리는 새 커밋 생성
git stash / git stash pop         작업 임시 저장 / 복원

[태그]
git tag -a v1.0.0 -m "메시지"     주석 태그 생성
git push origin v1.0.0            태그 푸시
```

## 참고 자료

이 책을 마친 후 더 깊이 있는 내용이나 최신 정보가 필요할 때는 다음과 같은 자료를 참고할 수 있습니다.

- **Git 공식 문서** - Git 프로젝트가 직접 관리하는 공식 레퍼런스로, 각 명령어의 모든 옵션과 상세한 동작 방식을 확인할 때 가장 신뢰할 수 있는 출처입니다. `git help <명령어>` 또는 `man git-<명령어>` 명령으로 터미널에서 바로 열어 볼 수도 있습니다.
- **Pro Git** - Git 프로젝트에서 공식적으로 제공하는 무료 온라인 서적으로, Git의 내부 동작 원리부터 다양한 협업 워크플로우까지 폭넓게 다룹니다. 이 책에서 다루지 않은 고급 주제(Git 내부 객체 모델, 커스텀 병합 전략 등)를 더 깊이 공부하고 싶을 때 참고하기 좋습니다.
- **GitHub / GitLab 공식 도움말** - 11장과 18장에서 다룬 Pull Request, 브랜치 보호 규칙, GitHub Actions처럼 플랫폼 고유 기능은 각 플랫폼의 공식 도움말 문서에서 최신 정보를 확인하는 것이 가장 정확합니다.

## 다음 학습 단계 제안

이 책을 마친 후에는 다음과 같은 순서로 학습을 이어가는 것을 제안합니다.

1. **작은 개인 프로젝트를 Git으로 처음부터 관리해보기**. 18장에서 다룬 흐름(브랜치, 커밋, PR, 병합, 태그)을 혼자서라도 처음부터 끝까지 반복해 보면 손에 익는 속도가 훨씬 빨라집니다.
2. **실제 오픈소스 프로젝트에 작은 기여를 해보기**. 오탈자 수정처럼 작은 변경이라도 실제 프로젝트에서 fork, 브랜치 생성, PR, 리뷰 대응 과정을 경험해 보면 이 책에서 배운 워크플로우가 실전에서 어떻게 쓰이는지 체감할 수 있습니다.
3. **Git 내부 객체 모델을 더 깊이 파보기**. `git cat-file`로 커밋, 트리, 블롭 객체를 직접 들여다보면서 커밋이 실제로 어떻게 저장되는지 이해하면, `reset`이나 `rebase`처럼 히스토리를 다루는 명령들이 왜 그렇게 동작하는지 더 명확해집니다.
4. **GitHub Actions 같은 CI/CD 도구 익히기**. 17장에서 다룬 로컬 훅과 18장에서 언급한 서버 자동화를 연결해서, 코드가 푸시될 때마다 자동으로 테스트와 배포가 이루어지는 파이프라인을 직접 구성해 보세요.
5. **팀 단위의 브랜치 전략을 비교하고 선택해보기**. 12장에서 다룬 브랜치 전략 외에도 프로젝트마다 다양한 변형이 존재합니다. 팀의 배포 주기와 규모에 맞는 전략을 스스로 고민해 보는 것도 좋은 다음 단계입니다.

Git은 명령어 개수 자체는 많지 않지만, 각 명령어가 내부적으로 어떤 일을 하는지 이해할수록 활용의 폭이 크게 넓어지는 도구입니다. 이 책에서 다진 기본기를 바탕으로, 앞으로 마주칠 다양한 협업 상황에서도 당황하지 않고 필요한 명령어를 스스로 찾아 조합할 수 있기를 바랍니다.
