# 9장. 구조체(struct)

[◀ 이전: 8장. 포인터와 배열](ch08-포인터와배열.md) | [📖 목차](00-목차.md) | [다음: 10장. 옵셔널 타입 ▶](ch10-옵셔널타입.md)


지금까지 우리는 정수, 실수, 배열, 포인터 같은 개별적인 값들을 다뤘습니다. 하지만 실제 프로그램에서는 여러 개의 값을 하나의 의미 있는 단위로 묶어서 다뤄야 하는 경우가 훨씬 많습니다. 예를 들어 화면 위의 한 점을 표현하려면 x 좌표와 y 좌표가 항상 함께 다녀야 하고, 사람 한 명을 표현하려면 이름과 나이가 함께 다녀야 합니다.

이번 장에서는 Zig에서 이런 묶음을 만드는 방법인 `struct`(구조체)를 배웁니다. 구조체에 필드를 선언하는 방법, 구조체 리터럴로 값을 만드는 방법, 그리고 구조체 안에 함수를 정의해서 마치 메서드처럼 사용하는 방법을 차례로 살펴봅니다. 마지막에는 8장에서 배운 포인터 지식을 활용해서, 구조체의 값을 실제로 바꾸는 메서드를 작성하는 방법까지 다룹니다.

## 구조체란 무엇인가

구조체는 서로 관련된 여러 값을 하나의 타입으로 묶은 것입니다. 다음은 2차원 좌표를 표현하는 가장 단순한 구조체입니다.

```zig
const Point = struct {
    x: i32,
    y: i32,
};
```

`struct { ... }`는 새로운 타입을 만드는 식(expression)입니다. 이 식을 `const Point`에 대입했기 때문에, 이제부터 `Point`라는 이름으로 이 타입을 가리킬 수 있습니다. 중괄호 안에 나열된 `x: i32`와 `y: i32`를 필드(field)라고 부릅니다. 각 필드는 이름과 타입을 가지며, 세미콜론이 아니라 쉼표로 구분한다는 점에 주의하세요.

Zig의 타입 이름은 관례상 PascalCase(단어의 첫 글자를 대문자로)로 씁니다. 반면 변수나 함수 이름은 snake_case(단어를 밑줄로 연결)로 씁니다. `Point`, `x`, `y`처럼 이 책의 모든 코드는 이 관례를 따릅니다.

## 구조체 리터럴로 값 만들기

타입을 선언했다면 이제 그 타입의 실제 값을 만들어야 합니다. Zig에서는 구조체 리터럴(struct literal) 문법으로 값을 만듭니다.

```zig
const p = Point{ .x = 1, .y = 2 };
```

`Point{ ... }` 뒤에 오는 각 필드는 점(`.`)을 붙인 이름과 값의 쌍으로 채웁니다. 필드를 쓰는 순서는 선언 순서와 달라도 되지만, 구조체에 선언된 필드는 기본값이 없는 한 반드시 전부 채워야 합니다. 하나라도 빠뜨리면 컴파일 오류가 발생합니다.

```zig
const p2 = Point{ .y = 5, .x = 3 }; // 순서를 바꿔도 문제없다
```

타입을 이미 알 수 있는 상황이라면 타입 이름을 생략하고 `.{ ... }`만 써도 됩니다. Zig 컴파일러가 주변 문맥(함수의 반환 타입, 변수의 타입 등)으로부터 어떤 구조체인지 추론할 수 있기 때문입니다.

```zig
fn make_origin() Point {
    return .{ .x = 0, .y = 0 }; // 반환 타입이 Point이므로 생략 가능
}
```

필드에 접근할 때는 점 표기법을 사용합니다.

```zig
const p = Point{ .x = 1, .y = 2 };
std.debug.print("x = {d}, y = {d}\n", .{ p.x, p.y });
```

## 기본값이 있는 필드

구조체 필드에는 기본값을 지정할 수 있습니다. 기본값이 있는 필드는 구조체 리터럴에서 생략해도 됩니다.

```zig
const Config = struct {
    width: i32 = 800,
    height: i32 = 600,
    title: []const u8 = "Untitled",
};
```

```zig
const c1 = Config{}; // 모든 필드가 기본값으로 채워진다
const c2 = Config{ .width = 1024 }; // width만 바꾸고 나머지는 기본값
```

`c1`은 `width = 800`, `height = 600`, `title = "Untitled"`를 가진 값이 됩니다. `c2`는 `width`만 1024로 바꾸고 `height`와 `title`은 여전히 기본값을 사용합니다. 옵션이 여러 개인 설정 구조체를 만들 때 이 기능이 특히 유용합니다. 사용하는 쪽에서는 바꾸고 싶은 값만 지정하면 되기 때문입니다.

기본값이 없는 필드는 반드시 리터럴에서 값을 채워야 한다는 점을 기억하세요. `Point`의 `x`, `y`처럼 기본값이 없는 필드를 빠뜨리면 컴파일 오류가 납니다.

## 구조체 안에 함수 정의하기

구조체는 필드뿐만 아니라 함수도 담을 수 있습니다. 구조체 안에 정의된 함수는 그 구조체와 관련된 동작을 표현하며, 다른 언어의 "메서드"와 비슷한 역할을 합니다.

```zig
const Point = struct {
    x: i32,
    y: i32,

    fn manhattan_distance(self: Point) i32 {
        return @abs(self.x) + @abs(self.y);
    }
};
```

여기서 `manhattan_distance`는 `Point` 타입 안에 정의된 함수입니다. 첫 번째 매개변수 이름을 `self`로 쓰는 것은 Zig 커뮤니티에서 널리 쓰이는 관례입니다. `self`는 "이 함수가 호출된 대상 구조체 값 자신"을 의미합니다. Zig 문법상 `self`라는 이름 자체에 특별한 의미가 있는 것은 아니지만, 이 이름을 쓰는 관례를 따르면 코드를 읽는 사람이 이 함수가 메서드처럼 쓰인다는 것을 바로 알아챌 수 있습니다.

## `Self`와 `@This()`

구조체 이름이 길거나, 구조체를 나중에 다른 이름으로 옮길 가능성이 있을 때 매개변수 타입에 구조체 이름을 매번 그대로 적으면 유지보수가 번거로워집니다. Zig는 이 문제를 위해 `@This()`라는 내장 함수를 제공합니다. `@This()`는 지금 자신이 작성되고 있는 구조체(또는 유니온, 열거형)의 타입을 그 자리에서 돌려줍니다.

```zig
const Point = struct {
    x: i32,
    y: i32,

    const Self = @This();

    fn manhattan_distance(self: Self) i32 {
        return @abs(self.x) + @abs(self.y);
    }
};
```

`const Self = @This();`를 구조체 맨 위에 한 번 선언해 두면, 이후 모든 메서드에서 구조체 이름 대신 `Self`를 쓸 수 있습니다. 이렇게 하면 구조체 이름이 `Point`에서 다른 이름으로 바뀌어도 메서드 본문을 고칠 필요가 없습니다. 이 책에서도 앞으로 메서드가 있는 구조체를 정의할 때는 이 관례를 따릅니다.

## 메서드 호출 문법

`Point` 안에 정의한 `manhattan_distance`는 다음처럼 점 표기법으로 호출합니다.

```zig
const p = Point{ .x = -3, .y = 4 };
const d = p.manhattan_distance();
std.debug.print("distance = {d}\n", .{d});
```

`p.manhattan_distance()`라는 호출은 실제로는 `Point.manhattan_distance(p)`와 완전히 같은 뜻입니다. Zig 컴파일러는 `p.manhattan_distance()` 형태의 호출을 보면, `p`의 타입이 `Point`라는 것을 확인하고, `Point` 안에서 `manhattan_distance`라는 이름의 함수를 찾은 뒤, 그 함수의 첫 번째 인자로 `p`를 자동으로 채워 넣습니다. 즉 다음 두 줄은 동일한 코드입니다.

```zig
const d1 = p.manhattan_distance();
const d2 = Point.manhattan_distance(p);
```

이 사실을 알고 나면 "메서드"라는 것이 특별한 문법이 아니라, 구조체 안에 정의된 평범한 함수를 호출하는 문법적 편의(syntactic sugar)라는 것을 이해할 수 있습니다. 다른 언어에서 클래스와 메서드가 등장하는 배경 지식 없이도, Zig의 메서드가 "함수 + 첫 번째 인자 자동 채우기"에 불과하다는 점을 명확히 알아두면 나중에 헷갈릴 일이 없습니다.

구조체 안에 정의된 함수 중에서 첫 번째 매개변수가 `self`(또는 그 구조체 자신의 타입)가 아닌 함수는 점 표기법으로 호출할 수 없습니다. 이런 함수는 구조체와 관련이 있지만 특정 인스턴스에 속하지 않는 동작, 즉 다른 언어의 "정적 메서드"에 가까운 역할을 합니다.

```zig
const Point = struct {
    x: i32,
    y: i32,

    const Self = @This();

    fn origin() Self {
        return Self{ .x = 0, .y = 0 };
    }
};
```

```zig
const p = Point.origin(); // p.origin()이 아니라 Point.origin()으로 호출
```

`origin`은 특정 `Point` 값에 속한 동작이 아니라 새로운 `Point`를 만들어주는 동작이므로, `Point.origin()`처럼 타입 이름을 통해 직접 호출합니다.

## 값을 변경하는 메서드: 포인터를 받는 self

지금까지 본 `manhattan_distance`는 `self`로부터 값을 읽기만 했습니다. 그런데 메서드 안에서 구조체의 필드 값을 실제로 바꾸고 싶다면 어떻게 해야 할까요?

8장에서 배운 것처럼, Zig의 함수는 매개변수를 값으로 전달받습니다. 즉 `self: Self`로 받은 매개변수는 원본의 복사본이므로, 그 안의 필드를 바꿔도 호출한 쪽의 원본에는 아무 영향이 없습니다.

```zig
const Point = struct {
    x: i32,
    y: i32,

    const Self = @This();

    // 이 함수는 self의 복사본만 바꾸고, 원본에는 영향을 주지 못한다
    fn move_wrong(self: Self, dx: i32, dy: i32) void {
        self.x += dx; // self는 복사본이므로 이 대입은 무의미하다
        self.y += dy;
    }
};
```

원본을 실제로 바꾸려면 8장에서 살펴본 포인터를 사용해야 합니다. `self`의 타입을 `Self`가 아니라 `*Self`로 선언하면, `self`는 원본 구조체를 가리키는 포인터가 되고, `self.x`나 `self.y`에 대한 대입은 포인터가 가리키는 실제 메모리에 반영됩니다.

```zig
const Point = struct {
    x: i32,
    y: i32,

    const Self = @This();

    fn move(self: *Self, dx: i32, dy: i32) void {
        self.x += dx;
        self.y += dy;
    }
};
```

호출하는 쪽에서는 여전히 점 표기법을 그대로 사용합니다.

```zig
var p = Point{ .x = 1, .y = 2 };
p.move(3, 4);
std.debug.print("x = {d}, y = {d}\n", .{ p.x, p.y }); // x = 4, y = 6
```

`p.move(3, 4)`는 실제로는 `Point.move(&p, 3, 4)`와 같습니다. Zig 컴파일러는 메서드가 `*Self`(포인터)를 받는다는 것을 확인하면, `p.method()` 호출에서 자동으로 `p`의 주소(`&p`)를 첫 번째 인자로 넘겨줍니다. 프로그래머가 직접 `&`를 붙이지 않아도 되므로 편리하지만, 그 편의 아래에서 실제로 포인터가 전달되고 있다는 사실은 꼭 기억해 두어야 합니다.

여기서 중요한 점은 `p`가 `var`로 선언되어야 한다는 것입니다. `const p = Point{ ... };`로 선언한 값은 그 내용을 바꿀 수 없으므로, `*Self`를 받는 메서드(즉 값을 바꾸는 메서드)를 호출하면 컴파일 오류가 발생합니다. 값을 읽기만 하는 메서드는 `const`로 선언된 값에도 자유롭게 호출할 수 있지만, 값을 바꾸는 메서드는 반드시 `var`로 선언된 값에만 호출할 수 있습니다.

정리하면, 메서드를 작성할 때 `self`의 타입을 고르는 기준은 다음과 같습니다.

- 값을 읽기만 하고 바꾸지 않는다 → `self: Self`
- 값을 바꿔야 한다 → `self: *Self`
- 특정 인스턴스와 무관하게 새 값을 만들거나 구조체와 관련된 동작을 수행한다 → `self` 없이 일반 매개변수만 사용 (`Point.origin()`처럼 호출)

## 구조체를 값으로 주고받을 때의 비용

구조체가 필드를 많이 가지고 있다면, 그 구조체를 값으로 함수에 넘기거나 반환할 때마다 모든 필드가 복사됩니다. 필드가 몇 개뿐인 `Point` 같은 구조체라면 문제가 되지 않지만, 필드가 아주 많거나 구조체 안에 배열을 통째로 담고 있는 경우에는 복사 비용이 커질 수 있습니다. 이런 경우에는 값을 읽기만 하는 메서드라도 `self: Self` 대신 `self: *const Self`(수정할 수 없는 포인터)를 받도록 작성해서 복사를 피하는 방법을 쓸 수 있습니다.

```zig
const Self = @This();

fn manhattan_distance(self: *const Self) i32 {
    return @abs(self.x) + @abs(self.y);
}
```

`*const Self`는 8장에서 배운 "가리키는 값을 바꿀 수 없는 포인터"입니다. 이 메서드는 `self`를 통해 필드를 바꿀 수 없지만, 구조체 전체를 복사하지 않고 원본을 가리키기만 하므로 큰 구조체에서는 더 효율적입니다. 다만 작은 구조체에서는 포인터를 넘기는 비용과 값을 복사하는 비용이 비슷하거나 오히려 값 복사가 더 나을 수도 있으므로, 이 선택은 구조체의 크기와 사용 패턴에 따라 판단하면 됩니다. 처음 배우는 단계에서는 값을 바꿔야 하면 `*Self`, 그렇지 않으면 `Self`를 쓰는 단순한 규칙으로 시작해도 충분합니다.

## 예제: 사각형 구조체

지금까지 배운 내용을 모아서, 너비와 높이를 가진 사각형을 표현하는 구조체를 만들어보겠습니다.

```zig
const std = @import("std");

const Rectangle = struct {
    width: f64 = 1.0,
    height: f64 = 1.0,

    const Self = @This();

    fn area(self: Self) f64 {
        return self.width * self.height;
    }

    fn scale(self: *Self, factor: f64) void {
        self.width *= factor;
        self.height *= factor;
    }
};

pub fn main() void {
    var r = Rectangle{ .width = 3.0, .height = 4.0 };
    std.debug.print("area = {d}\n", .{r.area()});

    r.scale(2.0);
    std.debug.print("after scale: width = {d}, height = {d}, area = {d}\n", .{ r.width, r.height, r.area() });

    const default_rect = Rectangle{};
    std.debug.print("default area = {d}\n", .{default_rect.area()});
}
```

`area`는 값을 읽기만 하므로 `self: Self`를 받고, `scale`은 필드를 바꾸므로 `self: *Self`를 받습니다. `default_rect`는 필드를 모두 생략하고 기본값(1.0, 1.0)으로 만들어졌습니다. 이 예제 하나에 이번 장에서 배운 필드 기본값, 읽기 전용 메서드, 값을 바꾸는 메서드가 모두 담겨 있습니다.

## 요약

- `struct { ... }`로 새로운 구조체 타입을 정의하고, 그 안에 필드를 `이름: 타입` 형태로 선언한다.
- 구조체 값은 `TypeName{ .field = value, ... }` 형태의 구조체 리터럴로 만든다. 타입을 문맥에서 추론할 수 있으면 `.{ ... }`로 줄여 쓸 수 있다.
- 필드에 기본값을 지정하면 구조체 리터럴에서 그 필드를 생략할 수 있다.
- 구조체 안에 함수를 정의하고 첫 번째 매개변수를 `self`로 두면, `값.함수()` 형태의 메서드 호출 문법을 쓸 수 있다. `p.method()`는 실제로 `Point.method(p)`와 같다.
- `@This()`는 지금 작성 중인 구조체 자신의 타입을 돌려주며, 관례적으로 `const Self = @This();`로 선언해 메서드 시그니처를 간결하게 만든다.
- 값을 읽기만 하는 메서드는 `self: Self`(또는 `*const Self`)를, 값을 바꿔야 하는 메서드는 `self: *Self`를 받는다. `*Self`를 받는 메서드는 `var`로 선언된 값에만 호출할 수 있다.
- 첫 번째 매개변수가 `self`가 아닌 구조체 내부 함수는 `Type.function()` 형태로, 인스턴스와 무관하게 호출한다.

## 연습문제

1. `Circle`이라는 구조체를 정의하세요. 필드는 `radius: f64`이며 기본값은 1.0입니다. `area(self: Self) f64` 메서드를 추가해 원의 넓이(`std.math.pi * radius * radius`)를 반환하도록 작성하세요.
2. 위에서 만든 `Circle`에 `grow(self: *Self, amount: f64) void` 메서드를 추가해서 `radius`를 `amount`만큼 늘리도록 구현하세요. `var`로 선언한 값에 이 메서드를 호출해서 반지름이 실제로 늘어나는지 확인하세요.
3. `p.manhattan_distance()`가 `Point.manhattan_distance(p)`와 같다는 것을 이용해서, 직접 `Point.manhattan_distance(p)` 형태로도 호출해보고 두 결과가 같은지 확인하는 코드를 작성하세요.
4. `self: Self`를 받는 메서드와 `self: *Self`를 받는 메서드를 각각 하나씩 가진 구조체를 만들고, `const`로 선언한 값에 두 메서드를 각각 호출해보세요. 어떤 호출에서 컴파일 오류가 나는지, 그 이유는 무엇인지 설명해보세요.
5. `Self` 대신 `@This()`를 쓰지 않고 구조체 이름을 직접 매개변수 타입에 적어서 같은 구조체를 다시 작성해보세요. 두 방식의 결과가 동일하게 동작하는지 확인하고, 이름을 나중에 바꾸는 상황을 가정했을 때 `Self`를 쓰는 방식이 어떤 점에서 더 편리한지 설명해보세요.
