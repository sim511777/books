# 7장. 함수

[◀ 이전: 6장. 반복문](ch06-반복문.md) | [📖 목차](00-목차.md) | [다음: 8장. 포인터와 배열 ▶](ch08-포인터와배열.md)


지금까지 작성한 코드는 대부분 `main` 함수 하나에 모든 로직을 담고 있었습니다. 프로그램이 조금만 복잡해져도 이런 방식은 금방 한계에 부딪힙니다. 반복되는 코드를 하나의 이름으로 묶고, 입력과 출력을 명확히 정의하는 것이 함수의 역할입니다. 이 장에서는 Zig에서 함수를 어떻게 정의하고 호출하는지, 인자가 어떤 방식으로 전달되는지, 그리고 여러 값을 반환하는 관용적인 방법까지 살펴봅니다.

## 함수 정의의 기본 형태

Zig에서 함수는 `fn` 키워드로 시작합니다. 함수 이름 뒤에 괄호로 매개변수 목록을 적고, 그 다음에 반환 타입을 명시합니다.

```zig
fn add(a: i32, b: i32) i32 {
    return a + b;
}
```

매개변수는 `이름: 타입` 형태로 적으며, 여러 개일 경우 쉼표로 구분합니다. 반환 타입은 매개변수 목록을 감싼 괄호 바로 뒤에 옵니다. C나 자바처럼 타입을 앞에 적는 방식과 반대라는 점에 유의하세요.

함수를 모듈 최상위에 두면 기본적으로 해당 파일 안에서만 보이는 비공개(private) 함수가 됩니다. 다른 파일에서도 가져다 쓰려면 `pub` 키워드를 붙입니다.

```zig
pub fn add(a: i32, b: i32) i32 {
    return a + b;
}
```

`pub`은 3장에서 변수를 다룰 때 잠깐 언급했던 것과 같은 맥락으로, 17장 빌드 시스템과 패키지에서 여러 파일로 나뉜 프로젝트를 구성할 때 다시 자세히 다룹니다.

## 반환값이 없는 함수: void

값을 반환하지 않는 함수는 반환 타입 자리에 `void`를 명시해야 합니다. C나 일부 언어처럼 반환 타입을 생략할 수는 없습니다.

```zig
fn print_greeting(name: []const u8) void {
    std.debug.print("안녕하세요, {s}님\n", .{name});
}
```

`void` 함수 안에서 `return`을 쓸 수는 있지만, 이때는 값 없이 `return;`만 적어 함수를 조기에 종료하는 용도로만 사용합니다.

```zig
fn print_if_positive(n: i32) void {
    if (n <= 0) {
        return;
    }
    std.debug.print("양수입니다: {d}\n", .{n});
}
```

## 함수 호출하기

함수는 이름 뒤에 괄호를 붙이고 인자를 나열해서 호출합니다. 다음은 지금까지 배운 내용을 활용한 완전한 예제입니다.

```zig
const std = @import("std");

fn add(a: i32, b: i32) i32 {
    return a + b;
}

pub fn main() void {
    const result = add(3, 4);
    std.debug.print("3 + 4 = {d}\n", .{result});
}
```

Zig에는 기본값을 가진 매개변수나 가변 개수 인자(varargs), 매개변수 이름을 지정해서 호출하는 방식(named argument)이 없습니다. 함수 시그니처에 정의된 순서대로 정확한 개수의 인자를 전달해야 합니다. 이런 단순함은 Zig가 지향하는 "코드를 읽으면 무슨 일이 일어나는지 명확히 알 수 있어야 한다"는 철학과 맞닿아 있습니다.

## 인자는 값으로 전달된다

Zig에서 함수에 인자를 넘기면 그 값이 복사되어 전달됩니다. 함수 내부에서 매개변수에 새로운 값을 대입하려고 하면 컴파일 오류가 발생합니다. 매개변수는 함수 안에서 암묵적으로 상수(`const`)처럼 취급되기 때문입니다.

```zig
fn double_it(n: i32) i32 {
    // n = n * 2;  // 오류: 매개변수는 재대입할 수 없다
    return n * 2;
}
```

실제로 위 주석을 풀고 컴파일해 보면 아래와 비슷한 오류를 만나게 됩니다.

```
error: cannot assign to constant
```

이 규칙은 3장에서 살펴본 `const`와 `var`의 구분과 정확히 같은 원리입니다. 매개변수는 함수에 들어오는 순간 마치 `const n: i32 = ...;`로 선언된 것과 같이 동작합니다. 값을 바꿔가며 계산해야 한다면, 함수 내부에서 새로운 지역 변수를 `var`로 따로 선언해서 그 변수를 조작해야 합니다.

```zig
fn sum_up_to(n: i32) i32 {
    var total: i32 = 0;
    var i: i32 = 1;
    while (i <= n) : (i += 1) {
        total += i;
    }
    return total;
}
```

여기서 `n` 자체는 여전히 바꿀 수 없지만, `total`과 `i`는 함수 안에서 새로 선언한 `var`이므로 자유롭게 값을 바꿀 수 있습니다.

### 값 전달과 포인터의 관계

"값으로 전달된다"는 규칙은 매개변수 자체를 재대입할 수 없다는 뜻이지, 구조체처럼 큰 자료구조를 넘길 때 항상 전체를 물리적으로 복사해서 느려진다는 뜻은 아닙니다. Zig 컴파일러는 상황에 따라 값을 레지스터나 스택에 복사하거나, 내부적으로 포인터를 사용해 전달하는 방식을 선택할 수 있습니다. 다만 프로그래머 입장에서 관찰할 수 있는 동작, 즉 "함수 안에서 매개변수를 바꿔도 호출한 쪽의 원본은 영향받지 않는다"는 규칙은 항상 지켜집니다.

만약 함수가 호출한 쪽의 변수를 실제로 바꾸도록 만들고 싶다면, 값 대신 그 값의 주소, 즉 포인터를 전달해야 합니다.

```zig
fn increment(n: *i32) void {
    n.* += 1;
}

pub fn main() void {
    var x: i32 = 10;
    increment(&x);
    std.debug.print("x = {d}\n", .{x}); // x = 11
}
```

`&x`로 `x`의 주소를 넘기고, 함수 내부에서는 `n.*`로 그 주소가 가리키는 값에 접근해서 수정합니다. 포인터의 문법과 동작 원리는 8장에서 본격적으로 다룹니다.

## 여러 값을 반환하기

C 계열 언어에서는 함수가 한 번에 하나의 값만 반환할 수 있어서, 여러 값을 돌려주려면 출력용 포인터 매개변수를 추가하거나 전역 상태를 활용하는 경우가 많았습니다. Zig에서는 구조체(9장에서 자세히 다룹니다)나 튜플을 사용해 여러 값을 하나로 묶어 반환하는 방식을 관용적으로 사용합니다.

### 구조체를 이용한 다중 반환

```zig
const DivisionResult = struct {
    quotient: i32,
    remainder: i32,
};

fn divide(a: i32, b: i32) DivisionResult {
    return DivisionResult{
        .quotient = @divTrunc(a, b),
        .remainder = @rem(a, b),
    };
}

pub fn main() void {
    const r = divide(17, 5);
    std.debug.print("17 / 5 = {d} 나머지 {d}\n", .{ r.quotient, r.remainder });
}
```

이름을 가진 구조체 필드로 반환하면 각 값이 무엇을 의미하는지 호출하는 쪽에서 바로 알 수 있다는 장점이 있습니다. `r.quotient`, `r.remainder`처럼 필드 이름으로 접근하므로, 반환값의 순서를 착각해서 실수하는 일도 줄어듭니다. 구조체 리터럴 문법과 필드 접근은 9장에서 더 자세히 설명합니다.

### 익명 구조체(튜플 스타일)를 이용한 간단한 반환

매번 별도의 구조체 타입을 이름 붙여 선언하기 번거로울 정도로 간단한 경우에는, 이름 없는 익명 구조체 리터럴을 즉석에서 만들어 반환할 수도 있습니다.

```zig
fn min_max(a: i32, b: i32) struct { min: i32, max: i32 } {
    if (a < b) {
        return .{ .min = a, .max = b };
    }
    return .{ .min = b, .max = a };
}

pub fn main() void {
    const result = min_max(7, 2);
    std.debug.print("min = {d}, max = {d}\n", .{ result.min, result.max });
}
```

반환 타입 자리에 `struct { ... }`를 직접 적어 그 자리에서 타입을 정의했습니다. 함수 본문에서는 `.{ .min = a, .max = b }`처럼 타입 이름을 생략한 리터럴로 값을 만들 수 있는데, 컴파일러가 반환 타입으로부터 어떤 구조체를 만들어야 하는지 추론하기 때문입니다. 이런 축약형 리터럴은 9장에서 다시 설명합니다.

이렇게 이름 없이 필드만 나열해 만든 구조체는 흔히 "튜플"이라고 부르는 개념과 비슷한 역할을 합니다. Zig에는 다른 언어처럼 `(i32, i32)` 같은 전용 튜플 타입 문법은 없지만, 필드 이름이 `0`, `1`, `2`처럼 숫자로 매겨진 익명 구조체를 튜플처럼 사용할 수 있습니다.

```zig
fn swap(a: i32, b: i32) struct { i32, i32 } {
    return .{ b, a };
}

pub fn main() void {
    const pair = swap(1, 2);
    std.debug.print("{d}, {d}\n", .{ pair[0], pair[1] });
}
```

필드 이름을 적지 않고 타입만 나열하면 필드 이름이 자동으로 `0`, `1`, ...로 매겨지고, `.{ b, a }`처럼 값만 순서대로 나열해서 만들 수 있습니다. 접근할 때는 `pair[0]`, `pair[1]`처럼 배열과 비슷한 인덱스 문법을 씁니다. 값의 의미가 명확한 경우가 아니라면, 대부분의 경우 필드 이름을 붙인 구조체를 반환하는 쪽이 코드를 읽는 사람에게 더 친절합니다.

## 컴파일타임 매개변수 살짝 맛보기

지금까지 본 함수는 모두 매개변수의 타입이 고정되어 있었습니다. 그런데 두 정수 중 더 큰 값을 구하는 함수를 만들려고 하면, `i32`용, `i64`용, `f64`용을 각각 따로 만들어야 하는 걸까요? Zig는 타입 자체를 함수의 인자로 받는 것을 허용해서 이 문제를 해결합니다.

```zig
fn max(comptime T: type, a: T, b: T) T {
    if (a > b) {
        return a;
    }
    return b;
}

pub fn main() void {
    const m1 = max(i32, 3, 7);
    const m2 = max(f64, 3.5, 2.1);
    std.debug.print("m1 = {d}, m2 = {d}\n", .{ m1, m2 });
}
```

여기서 `comptime T: type`은 "이 매개변수 `T`는 컴파일이 진행되는 시점에 확정되어야 하는 타입 값이다"라는 뜻입니다. `type`은 Zig에서 타입 자체를 나타내는 특수한 타입으로, 이것을 매개변수로 받을 수 있다는 점이 Zig의 독특한 특징 중 하나입니다. `max(i32, 3, 7)`을 호출하면 컴파일러는 그 자리에서 `T`가 `i32`인 버전의 `max` 함수를 실제로 만들어내고, `max(f64, 3.5, 2.1)`을 호출하면 `T`가 `f64`인 버전을 별도로 만들어냅니다. 즉 함수 하나를 작성했지만, 호출하는 방식에 따라 여러 타입에 대응하는 코드가 컴파일 시점에 자동으로 생성됩니다.

이런 방식은 다른 언어의 제네릭(generic)이나 템플릿(template)과 비슷한 효과를 내지만, Zig는 별도의 문법을 새로 만들지 않고 "타입도 하나의 값이며, 컴파일타임에 값으로 다룰 수 있다"는 일관된 원칙 위에서 이를 구현합니다. `comptime` 매개변수와 그 배경이 되는 컴파일타임 실행 모델은 14장에서 훨씬 깊이 다룰 예정이니, 지금은 "타입을 인자로 넘길 수 있고, 그러면 함수가 그 타입에 맞춰 여러 벌 생성된다"는 감각만 잡아두면 충분합니다.

## 함수도 값이다: 함수 포인터 살짝 보기

Zig에서 함수는 일종의 값으로 취급되며, 함수의 주소를 가리키는 함수 포인터를 변수에 저장하거나 다른 함수의 인자로 넘길 수 있습니다.

```zig
fn square(n: i32) i32 {
    return n * n;
}

fn cube(n: i32) i32 {
    return n * n * n;
}

fn apply(f: *const fn (i32) i32, n: i32) i32 {
    return f(n);
}

pub fn main() void {
    std.debug.print("{d}\n", .{apply(square, 5)}); // 25
    std.debug.print("{d}\n", .{apply(cube, 5)}); // 125
}
```

`*const fn (i32) i32`라는 타입은 "`i32`를 받아 `i32`를 반환하는 함수를 가리키는, 변경 불가능한 포인터"를 뜻합니다. `apply` 함수는 이런 함수 포인터 `f`와 정수 `n`을 받아 `f(n)`으로 호출해줍니다. 이렇게 함수를 다른 함수에 인자로 넘기면, 정렬 기준을 비교하는 함수를 갈아끼우거나 콜백을 등록하는 등 다양한 패턴을 구현할 수 있습니다. 함수 포인터의 세부적인 활용은 8장에서 포인터 문법을 익힌 뒤 자연스럽게 이해할 수 있으므로, 여기서는 "함수도 주소를 가지며 그 주소를 변수처럼 주고받을 수 있다"는 사실만 기억해 둡시다.

## 요약

- 함수는 `fn 이름(매개변수: 타입, ...) 반환타입 { ... }` 형태로 정의하며, 반환값이 없으면 반환 타입 자리에 `void`를 명시해야 합니다.
- 모듈 최상위 함수는 기본적으로 파일 내부에서만 보이며, `pub`을 붙여야 다른 파일에서 사용할 수 있습니다.
- 함수 인자는 값으로 복사되어 전달되며, 매개변수는 함수 안에서 암묵적으로 상수처럼 취급되어 재대입할 수 없습니다. 호출한 쪽의 변수를 바꾸려면 포인터(`*T`)를 넘겨야 합니다.
- 여러 값을 반환하려면 이름을 가진 구조체나, 이름 없는 익명 구조체(튜플 스타일)를 사용하는 것이 관용적인 방법입니다.
- `comptime T: type`처럼 타입을 매개변수로 받으면, 호출 시 전달된 타입에 맞춰 컴파일 시점에 함수가 여러 벌 생성됩니다. 이 개념은 14장에서 더 깊이 다룹니다.
- 함수는 값처럼 취급되어 함수 포인터(`*const fn (...) 반환타입`)로 변수에 저장하거나 다른 함수에 넘길 수 있습니다.

4. `comptime T: type`을 이용해 두 값 중 더 작은 값을 반환하는 함수 `min(comptime T: type, a: T, b: T) T`를 작성하고, `i32`와 `f64` 두 타입으로 각각 호출해서 결과를 출력해 보세요.
5. `i32`를 받아 `i32`를 반환하는 함수 포인터를 매개변수로 받아, 배열의 모든 원소에 그 함수를 적용한 새 배열을 반환하는 함수 `map_array`를 작성해 보세요.
