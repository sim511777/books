# 8장. 포인터와 배열

[◀ 이전: 7장. 함수](ch07-함수.md) | [📖 목차](00-목차.md) | [다음: 9장. 구조체(struct) ▶](ch09-구조체.md)


7장에서 함수의 인자가 값으로 복사되어 전달된다는 것을 배웠고, 호출한 쪽의 값을 실제로 바꾸려면 그 값의 주소를 넘겨야 한다는 것도 살짝 다뤘습니다. 이 장에서는 그 "주소"라는 개념, 즉 포인터를 Zig의 문법으로 정확히 이해하고, 포인터와 밀접하게 연관된 자료구조인 배열을 함께 살펴봅니다. 포인터는 Zig에서 메모리를 직접 다루는 가장 기본적인 도구이며, 이후 13장의 슬라이스, 15장의 메모리 할당자를 이해하는 데도 반드시 필요한 토대가 됩니다.

## 배열: 크기가 타입의 일부다

배열은 같은 타입의 값을 정해진 개수만큼 나란히 늘어놓은 자료구조입니다. Zig에서 배열의 타입은 `[N]T` 형태로 쓰며, 여기서 `N`은 원소의 개수, `T`는 원소의 타입입니다.

```zig
const numbers: [5]i32 = .{ 10, 20, 30, 40, 50 };
```

여기서 중요한 점은 `5`라는 크기가 단순한 값이 아니라 타입 자체의 일부라는 것입니다. `[5]i32`와 `[3]i32`는 원소 타입이 같더라도 서로 다른 타입입니다. 그래서 다음 코드는 컴파일되지 않습니다.

```zig
var a: [5]i32 = .{ 1, 2, 3, 4, 5 };
const b: [3]i32 = .{ 1, 2, 3 };
a = b; // 오류: [3]i32는 [5]i32에 대입할 수 없다
```

배열의 크기는 컴파일 시점에 고정되어 있으므로, `numbers.len`으로 언제든 원소 개수를 알 수 있고 이 값은 런타임 계산 없이 컴파일타임에 이미 결정되어 있습니다.

```zig
const std = @import("std");

pub fn main() void {
    const numbers: [5]i32 = .{ 10, 20, 30, 40, 50 };
    std.debug.print("길이: {d}\n", .{numbers.len}); // 길이: 5
    std.debug.print("세번째 값: {d}\n", .{numbers[2]}); // 세번째 값: 30
}
```

인덱스는 `배열[인덱스]` 형태로 접근하며, 0부터 시작합니다. `안전 모드`(디버그 빌드 등)에서는 인덱스가 배열 범위를 벗어나면 즉시 패닉이 발생해서 잘못된 메모리 접근을 막아줍니다.

배열의 크기를 직접 숫자로 적지 않고, 초기값의 개수로부터 추론하게 할 수도 있습니다. 대괄호 안에 크기 대신 `_`를 적으면 됩니다.

```zig
const primes: [_]i32 = .{ 2, 3, 5, 7, 11 }; // [5]i32로 추론됨
```

## 포인터의 기본: & 로 주소 얻기, .* 로 역참조하기

포인터는 "어떤 값이 메모리의 어디에 있는지"를 가리키는 값입니다. Zig에서 어떤 변수의 주소를 얻으려면 `&` 연산자를 사용합니다.

```zig
var x: i32 = 42;
const p: *i32 = &x;
```

`p`의 타입 `*i32`는 "`i32` 값 하나를 가리키는 포인터"라는 뜻입니다. `&x`는 `x`가 저장된 메모리의 주소를 반환하고, 그 결과를 `p`에 저장했습니다. 이제 `p`를 통해 `x`가 가리키는 실제 값에 접근하려면 `.*`를 붙여 역참조합니다.

```zig
const std = @import("std");

pub fn main() void {
    var x: i32 = 42;
    const p: *i32 = &x;

    std.debug.print("x = {d}\n", .{x}); // x = 42
    std.debug.print("p.* = {d}\n", .{p.*}); // p.* = 42

    p.* = 100;
    std.debug.print("x = {d}\n", .{x}); // x = 100
}
```

`p.* = 100`은 "`p`가 가리키는 곳에 100을 써라"는 뜻이며, 그 결과 `x`의 값이 실제로 바뀝니다. `p`는 `x`와는 별개의 변수이지만, `x`가 있는 자리를 가리키고 있으므로 `p`를 통한 수정이 `x`에도 그대로 반영됩니다.

여기서 한 가지 규칙을 기억해야 합니다. `x`가 `const`로 선언되어 있다면 `&x`로 얻은 포인터를 통해 값을 바꿀 수 없습니다.

```zig
const y: i32 = 42;
const q: *const i32 = &y;
// q.* = 100; // 오류: const가 가리키는 값은 수정할 수 없다
```

`const` 변수의 주소를 얻으면 자동으로 `*const i32`, 즉 "읽기만 가능한 포인터" 타입이 됩니다. 반대로 `var`로 선언된 변수의 주소를 얻으면 `*i32`처럼 수정 가능한 포인터가 됩니다. 이렇게 포인터 타입 자체에 "이 포인터를 통해 값을 바꿀 수 있는가"라는 정보가 포함되어 있다는 점이 Zig 포인터의 중요한 특징입니다.

### 함수와 포인터

7장에서 살짝 봤던 예제를 다시 떠올려 봅시다.

```zig
fn increment(n: *i32) void {
    n.* += 1;
}

pub fn main() void {
    var x: i32 = 10;
    increment(&x);
    std.debug.print("x = {d}\n", .{x}); // x = 11
}
```

`increment` 함수는 `*i32` 타입의 매개변수 `n`을 받습니다. 함수를 호출할 때 `&x`로 `x`의 주소를 넘겼기 때문에, 함수 내부에서 `n.* += 1`로 그 주소가 가리키는 값을 바꾸면 호출한 쪽의 `x`도 함께 바뀝니다. 매개변수 `n` 자체는 여전히 재대입할 수 없는 상수 취급을 받지만(`n = &other_var;`는 불가능), `n`이 가리키는 대상의 값을 바꾸는 것은 문제가 없습니다. "매개변수를 재대입할 수 없다"는 규칙과 "포인터가 가리키는 값을 바꿀 수 있다"는 것은 서로 다른 이야기라는 점을 구분해서 기억해 두세요.

## 배열과 포인터의 관계

배열 변수의 주소를 얻으면 어떤 타입이 될까요? 배열 하나를 통째로 가리키는 포인터가 됩니다.

```zig
var arr: [5]i32 = .{ 10, 20, 30, 40, 50 };
const p: *[5]i32 = &arr;
```

`p`의 타입은 `*[5]i32`, 즉 "`[5]i32` 배열 전체를 가리키는 포인터"입니다. 이런 포인터를 통해서도 인덱스로 원소에 접근할 수 있습니다.

```zig
const std = @import("std");

pub fn main() void {
    var arr: [5]i32 = .{ 10, 20, 30, 40, 50 };
    const p: *[5]i32 = &arr;

    p[0] = 999;
    std.debug.print("{d}\n", .{arr[0]}); // 999
    std.debug.print("배열 전체를 가리키는 포인터의 길이: {d}\n", .{p.len}); // 5
}
```

`p[0]`처럼 배열을 가리키는 포인터에 대해서도 인덱스 문법을 그대로 쓸 수 있고, `p.len`으로 그 배열의 길이도 알 수 있습니다. 이는 Zig가 배열을 가리키는 포인터를 배열 자체처럼 자연스럽게 다룰 수 있도록 편의를 제공하기 때문입니다.

## 단일 항목 포인터 vs 다중 항목 포인터

여기까지 본 `*i32`나 `*[5]i32`는 모두 정확히 "하나의 값"(정수 하나, 혹은 배열 하나)을 가리키는 **단일 항목 포인터**(single-item pointer)입니다. 그런데 메모리 상에 같은 타입의 값이 여러 개 연달아 늘어서 있고, 그 시작 위치만 가리키면서 인덱스로 하나씩 접근하고 싶은 경우가 있습니다. 이럴 때 쓰는 것이 **다중 항목 포인터**(many-item pointer), `[*]T`입니다.

```zig
var arr: [5]i32 = .{ 10, 20, 30, 40, 50 };
const many: [*]i32 = &arr[0];

std.debug.print("{d}\n", .{many[0]}); // 10
std.debug.print("{d}\n", .{many[3]}); // 40
```

`[*]i32`는 "`i32` 값이 연이어 있는 메모리의 어느 지점을 가리키며, 그 지점부터 인덱스로 몇 번째 원소든 접근할 수 있다"는 의미를 가진 타입입니다. `*i32`(단일 항목 포인터)와 `[*]i32`(다중 항목 포인터)는 겉보기엔 비슷해 보이지만 중요한 차이가 있습니다.

- `*i32`는 정확히 하나의 `i32`를 가리킨다고 약속하는 타입이라서, 여기에 인덱스 문법(`p[3]`)을 쓸 수 없습니다.
- `[*]i32`는 그 지점부터 배열처럼 연속된 값들이 있다고 가정하고 인덱스 접근을 허용하지만, 정작 그 값이 몇 개나 있는지(길이)는 타입 정보에 들어있지 않습니다. 몇 개까지 안전하게 접근할 수 있는지는 프로그래머가 별도로 알고 있어야 합니다.

이 두 가지를 구분해서 쓰는 이유는, 포인터의 타입만 보고도 "이게 하나짜리 값인지, 여러 개가 연속된 시작점인지"를 컴파일러와 사람 모두가 명확히 알 수 있게 하기 위함입니다. C에서는 `int*` 하나로 이 두 가지 용법을 뒤섞어 쓰다 보니 버그가 자주 발생했는데, Zig는 애초에 타입을 나누어 이런 혼동을 줄였습니다.

## Zig 포인터는 절대 null이 될 수 없다

C 계열 언어의 포인터는 "가리키는 대상이 없음"을 나타내기 위해 흔히 `NULL`(또는 `nullptr`)이라는 특별한 값을 사용합니다. 그리고 이 널 포인터를 실수로 역참조해서 프로그램이 죽는 일이 아주 흔하게 벌어집니다. Zig는 이 문제를 근본적으로 다르게 접근합니다.

**Zig에서 `*T` 타입의 포인터는 절대로 null일 수 없습니다.** `*i32` 타입의 변수가 있다면, 그 변수는 반드시 어딘가 실제로 존재하는 `i32` 값을 가리키고 있다는 것이 타입 시스템 차원에서 보장됩니다. 다음 코드는 컴파일되지 않습니다.

```zig
var p: *i32 = null; // 오류: *i32는 null이 될 수 없다
```

그렇다면 "가리키는 대상이 있을 수도, 없을 수도 있는" 포인터가 필요할 때는 어떻게 해야 할까요? 이때는 포인터 자체를 **옵셔널**(optional)로 감싸서 `?*T`라는 타입을 사용합니다.

```zig
var maybe_p: ?*i32 = null; // 정상: 옵셔널 포인터는 null이 가능하다

var x: i32 = 5;
maybe_p = &x; // 이제 x를 가리키게 됨
```

`?*i32`는 "`*i32` 포인터일 수도 있고, 아무것도 가리키지 않는 `null`일 수도 있다"는 뜻입니다. 이렇게 null이 될 수 있는 경우를 타입 이름에 `?`를 붙여 명시적으로 드러내면, 함수 시그니처나 구조체 필드만 보고도 "이 포인터는 항상 유효하다" 또는 "이 포인터는 없을 수도 있으니 확인이 필요하다"를 즉시 구분할 수 있습니다. 옵셔널 타입을 실제로 안전하게 풀어서 사용하는 방법(`if (maybe_p) |p| { ... }` 같은 패턴)은 10장에서 본격적으로 다룹니다. 지금은 "포인터가 없을 수도 있다는 가능성은 반드시 `?`를 붙여 타입에 드러내야 하고, 그렇지 않은 평범한 `*T`는 항상 유효한 대상을 가리킨다"는 원칙만 기억해 두면 충분합니다.

## 배열과 슬라이스, 짧게 맛보기

지금까지 다룬 배열 `[5]i32`는 크기가 타입에 고정되어 있어서, 함수에 "길이가 얼마인지 모르는 정수 목록"을 넘기고 싶을 때는 다소 불편합니다. `[5]i32`를 받는 함수는 `[3]i32`나 `[10]i32`를 받을 수 없기 때문입니다.

이런 경우를 위해 Zig는 **슬라이스**(slice)라는 타입을 제공합니다. 슬라이스의 타입은 `[]T`처럼 쓰며, 내부적으로는 "어딘가를 가리키는 포인터"와 "그 지점부터 몇 개의 원소가 유효한지 나타내는 길이"를 한 쌍으로 묶어 가지고 있습니다. 앞서 살펴본 다중 항목 포인터 `[*]T`가 바로 이 포인터 부분의 실제 타입이며, 슬라이스는 이 포인터에 길이(`len`) 정보를 더해 "몇 개까지 안전하게 접근 가능한지"까지 함께 가지고 다니는 조금 더 안전한 형태라고 볼 수 있습니다.

```zig
const std = @import("std");

fn sum_all(values: []const i32) i32 {
    var total: i32 = 0;
    for (values) |v| {
        total += v;
    }
    return total;
}

pub fn main() void {
    const arr: [5]i32 = .{ 10, 20, 30, 40, 50 };
    const slice: []const i32 = &arr; // 배열 전체를 가리키는 슬라이스
    const partial: []const i32 = arr[1..4]; // 일부 구간만 가리키는 슬라이스

    std.debug.print("전체 합: {d}\n", .{sum_all(slice)}); // 150
    std.debug.print("부분 합: {d}\n", .{sum_all(partial)}); // 90
}
```

`sum_all` 함수는 `[]const i32`, 즉 "`i32`로 이루어진 읽기 전용 슬라이스"를 받으므로, 길이가 5든 3든 100이든 어떤 배열의 슬라이스라도 그대로 넘길 수 있습니다. `arr[1..4]`처럼 범위 문법을 쓰면 배열의 일부 구간만 가리키는 슬라이스를 만들 수도 있습니다.

배열, 단일 항목 포인터, 다중 항목 포인터, 슬라이스가 서로 어떻게 연관되어 있는지를 아래 그림으로 정리했습니다.

슬라이스는 Zig 코드 전반에서 문자열, 동적 크기의 목록, 함수 인자 등 아주 다양한 곳에 쓰이는 핵심적인 개념입니다. 여기서는 "슬라이스는 포인터와 길이를 함께 들고 다니는 값이며, 그래서 배열과 달리 크기가 타입에 고정되지 않는다"는 정도만 감을 잡아두고, 슬라이스를 만들고 순회하고 잘라내는 자세한 방법은 13장에서 이어서 다룹니다.

## 요약

- 배열 `[N]T`는 크기 `N`이 타입 자체에 포함되어 있어, 크기가 다른 배열은 서로 다른 타입으로 취급됩니다.
- `&`로 변수의 주소(포인터)를 얻고, `.*`로 포인터가 가리키는 값에 접근(역참조)합니다. `const` 변수의 주소는 `*const T`가 되어 값을 바꿀 수 없습니다.
- `*T`는 정확히 하나의 값을 가리키는 단일 항목 포인터이며 인덱스 문법을 쓸 수 없습니다. `[*]T`는 연속된 값들의 시작 지점을 가리키는 다중 항목 포인터로, 인덱스 접근은 가능하지만 길이 정보를 스스로 가지고 있지 않습니다.
- Zig의 평범한 포인터 `*T`는 절대 null이 될 수 없습니다. null일 가능성이 있는 포인터는 반드시 옵셔널 `?*T`로 명시해야 하며, 이를 안전하게 다루는 방법은 10장에서 다룹니다.
- 슬라이스 `[]T`는 포인터와 길이를 함께 묶어, 크기가 타입에 고정되지 않은 형태로 배열의 전체 또는 일부 구간을 가리킬 수 있게 해줍니다. 자세한 내용은 13장에서 다룹니다.

## 연습문제

1. `[4]i32` 배열을 선언하고, 그 배열 전체를 가리키는 단일 항목 포인터 `*[4]i32`를 만들어 포인터를 통해 세번째 원소의 값을 바꿔 보세요.
2. 정수 `n`을 가리키는 포인터를 매개변수로 받아, 그 값을 두 배로 만드는 함수 `double_in_place(p: *i32) void`를 작성하고 호출해서 결과를 확인하세요.
3. `*i32`와 `[*]i32`의 차이를 설명하고, 각각 어떤 상황에서 사용하는 것이 적절한지 예를 들어 서술해 보세요.
4. `?*i32` 타입의 변수를 선언해서 처음에는 `null`로 초기화하고, 이후 어떤 정수 변수의 주소를 대입해 보세요. 왜 이 변수는 `*i32`가 아니라 `?*i32`로 선언해야만 했는지 설명해 보세요.
5. `[6]i32` 배열을 만들고, 그중 가운데 네 원소만 가리키는 슬라이스를 `arr[1..5]` 형태로 만들어, 그 합을 구하는 함수에 전달해 보세요.
