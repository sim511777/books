# 4장. 연산자와 표현식

---

3장에서 변수와 자료형을 다뤘으니, 이제 그 값을 가지고 실제로 계산을 하고 판단을 내리는 방법을 알아볼 차례입니다. 산술, 비교, 논리 연산자는 다른 언어와 크게 다르지 않지만, Rust에는 `if`와 블록(`{}`)이 값을 반환하는 표현식이라는 독특한 특징이 있습니다. 이 특징은 앞으로 5장의 제어문, 6장의 반복문, 7장의 함수를 이해하는 데 중요한 밑거름이 되므로 이번 장에서 확실히 짚어 두겠습니다.

## 4.1 산술 연산자

Rust의 기본 산술 연산자는 `+`, `-`, `*`, `/`, `%`(나머지)입니다.

```rust
fn main() {
    let a = 10;
    let b = 3;

    println!("더하기: {}", a + b);
    println!("빼기: {}", a - b);
    println!("곱하기: {}", a * b);
    println!("나누기: {}", a / b); // 정수 나누기 -> 3
    println!("나머지: {}", a % b); // 1
}
```

정수 사이의 나눗셈은 소수점 이하를 버립니다. `10 / 3`은 `3.333...`이 아니라 `3`이 됩니다. 소수 결과가 필요하다면 피연산자 중 하나를 부동소수점 타입으로 만들어야 합니다.

```rust
fn main() {
    let a = 10.0;
    let b = 3.0;
    println!("{}", a / b); // 3.3333333333333335
}
```

정수 연산에서 특히 조심해야 할 부분은 오버플로우입니다. `i32`가 표현할 수 있는 최댓값을 넘어가는 연산을 하면 어떻게 될까요?

```rust
fn main() {
    let max: u8 = 255;
    let overflowed = max + 1; // 디버그 빌드에서는 panic
    println!("{overflowed}");
}
```

디버그 모드로 컴파일하면 이 코드는 실행 시 panic을 일으킵니다. Rust는 오버플로우를 조용히 넘기지 않고 문제를 드러내는 쪽을 택했습니다. 만약 오버플로우를 감싸고 도는(wrap) 동작이 필요하다면 `wrapping_add` 같은 명시적인 메서드를 사용해야 합니다. 이런 실행 시점 문제는 15장 에러 처리에서 더 자세히 다룹니다.

## 4.2 비교 연산자

비교 연산자는 두 값을 견주어 `bool` 값을 반환합니다.

```rust
fn main() {
    let x = 7;
    let y = 10;

    println!("{}", x == y); // false
    println!("{}", x != y); // true
    println!("{}", x < y);  // true
    println!("{}", x <= y); // true
    println!("{}", x > y);  // false
    println!("{}", x >= y); // false
}
```

주의할 점은, 비교하는 두 값이 반드시 같은 타입이어야 한다는 것입니다. 예를 들어 `i32`와 `f64`를 직접 비교하면 컴파일 오류가 발생합니다.

```rust
fn main() {
    let a: i32 = 5;
    let b: f64 = 5.0;
    // println!("{}", a == b); // 오류: 타입이 다름
    println!("{}", a as f64 == b); // as로 형변환 후 비교
}
```

이렇게 타입을 엄격히 따지는 것은 3장에서 살펴본 `as` 형변환과 맞물려 있습니다. 값이 "같아 보인다"는 이유로 암묵적으로 변환해주지 않기 때문에, 어떤 타입 사이의 연산이 일어나는지 코드만 보고도 명확히 알 수 있습니다.

## 4.3 논리 연산자

`bool` 값을 조합할 때는 `&&`(and), `||`(or), `!`(not)를 사용합니다.

```rust
fn main() {
    let is_adult = true;
    let has_ticket = false;

    println!("{}", is_adult && has_ticket); // false
    println!("{}", is_adult || has_ticket); // true
    println!("{}", !is_adult);              // false
}
```

`&&`와 `||`는 단축 평가(short-circuit evaluation)를 합니다. `&&`의 왼쪽이 `false`면 오른쪽은 평가하지 않고 바로 `false`를 반환하며, `||`의 왼쪽이 `true`면 오른쪽을 평가하지 않고 바로 `true`를 반환합니다.

```rust
fn expensive_check() -> bool {
    println!("비용이 큰 검사를 실행함");
    true
}

fn main() {
    let short_circuited = false && expensive_check();
    println!("결과: {short_circuited}");
    // "비용이 큰 검사를 실행함"은 출력되지 않음
}
```

이 동작은 조건이 앞에서 걸러지면 뒤쪽의 무거운 연산이나 위험한 호출(예: 존재하지 않을 수도 있는 값에 접근하는 코드)을 건너뛸 수 있게 해줍니다.

## 4.4 표현식으로서의 `if`

여기서부터가 이 장의 핵심입니다. 다른 많은 언어에서 `if`는 그저 분기를 실행하는 문장(statement)일 뿐이지만, Rust에서는 `if`가 값을 만들어내는 표현식(expression)입니다.

```rust
fn main() {
    let temperature = 28;

    let description = if temperature > 30 {
        "더움"
    } else if temperature > 20 {
        "적당함"
    } else {
        "추움"
    };

    println!("오늘 날씨: {description}");
}
```

`if temperature > 30 { "더움" } else if ... else { "추움" }` 전체가 하나의 값으로 취급되어 `description`에 대입됩니다. 이렇게 쓰면 다른 언어에서 삼항 연산자(`?:`)로 처리하던 일을 `if`만으로 자연스럽게 표현할 수 있습니다.

표현식으로 쓰이는 `if`에는 한 가지 규칙이 있습니다. 모든 분기가 **같은 타입**의 값을 반환해야 합니다.

```rust
fn main() {
    let condition = true;
    let value = if condition {
        5 // i32
    } else {
        "다섯" // 오류! &str과 i32는 다른 타입
    };
    println!("{value}");
}
```

이 코드는 컴파일되지 않습니다. `if`의 각 분기가 만들어낸 값이 결국 하나의 변수에 담기므로, 컴파일러는 그 변수가 정확히 어떤 타입인지 알아야 하기 때문입니다. 이 규칙은 12장에서 배울 `match` 표현식에도 그대로 적용됩니다.

물론 `if`를 값 없이 그냥 분기 실행용으로 쓸 수도 있습니다. 이 경우는 5장 제어문에서 더 자세히 다룹니다.

```rust
fn main() {
    let score = 85;
    if score >= 60 {
        println!("합격");
    } else {
        println!("불합격");
    }
}
```

## 4.5 블록도 표현식이다

`if`가 표현식이 될 수 있는 이유를 한 걸음 더 들어가 보면, 사실은 중괄호로 둘러싸인 **블록(`{}`) 자체가 표현식**이기 때문입니다. 블록은 마지막 줄에 세미콜론(`;`) 없는 표현식이 있으면 그 값을 블록 전체의 값으로 반환합니다.

```rust
fn main() {
    let x = {
        let a = 3;
        let b = 4;
        a * a + b * b // 세미콜론 없음 -> 이 값이 블록의 결과
    };
    println!("x = {x}"); // 25
}
```

이 블록 안에서 `let a = 3;`과 `let b = 4;`는 문장(statement)이라서 값을 만들지 않지만, 마지막 줄 `a * a + b * b`는 세미콜론이 없는 표현식이라서 블록 전체의 값이 됩니다. 만약 마지막 줄에 세미콜론을 붙이면 어떻게 될까요?

```rust
fn main() {
    let x = {
        let a = 3;
        let b = 4;
        a * a + b * b; // 세미콜론이 붙음 -> 문장이 됨
    };
    println!("x = {x:?}");
}
```

세미콜론이 붙으면 그 줄은 값을 만들지 않는 문장이 되고, 블록은 대신 아무 의미 있는 값도 없다는 뜻의 유닛 타입 `()`를 반환합니다. 이 코드는 `x`의 타입이 `()`가 되어 `{x:?}` 출력이 `()`로 나오게 됩니다. "세미콜론을 붙이면 문장, 안 붙이면 표현식"이라는 규칙은 Rust 코드 전체에서 반복적으로 나타나므로 꼭 기억해 둘 필요가 있습니다.

이 원리는 `if`뿐 아니라 함수 본문에도 그대로 적용됩니다. 함수의 마지막 줄에 세미콜론 없는 표현식을 두면 그것이 함수의 반환값이 되는데, 이 내용은 7장에서 함수를 다룰 때 자세히 설명합니다. 지금은 함수 본문도 결국 하나의 큰 블록이라는 점만 기억해 두면 됩니다.

```rust
fn square(n: i32) -> i32 {
    n * n // 세미콜론 없음 -> 반환값
}

fn main() {
    println!("{}", square(6)); // 36
}
```

## 4.6 연산자 우선순위

여러 연산자를 한 줄에 섞어 쓰면, 어떤 연산이 먼저 계산되는지가 중요해집니다.

```rust
fn main() {
    let result = 2 + 3 * 4; // 곱하기가 먼저 -> 2 + 12 = 14
    println!("{result}");

    let result2 = (2 + 3) * 4; // 괄호로 순서를 명시 -> 20
    println!("{result2}");
}
```

Rust의 연산자 우선순위는 대체로 수학과 대부분의 프로그래밍 언어에서 익숙한 규칙을 따릅니다. 곱하기·나누기·나머지가 더하기·빼기보다 먼저 계산되고, 비교 연산자는 산술 연산자보다 나중에, 논리 연산자는 비교 연산자보다 나중에 계산됩니다. 전체 연산자와 우선순위 목록은 이 책의 부록에 표로 정리해 두었으니 헷갈릴 때마다 참고하기 바랍니다. 다만 우선순위를 외우기보다는, 조금이라도 헷갈릴 여지가 있다면 괄호 `()`를 적극적으로 사용해 의도를 명확히 드러내는 습관을 들이는 편이 실무에서 훨씬 안전합니다.

## 요약

이 장에서는 Rust의 연산자와 표현식을 살펴봤습니다. 산술 연산자(`+`, `-`, `*`, `/`, `%`)는 익숙한 규칙을 따르지만 정수 오버플로우에는 주의해야 하고, 비교 연산자는 같은 타입 사이에서만 사용할 수 있습니다. 논리 연산자 `&&`와 `||`는 단축 평가로 동작합니다. Rust 고유의 특징으로, `if`는 값을 반환하는 표현식으로 쓸 수 있으며 모든 분기가 같은 타입을 반환해야 합니다. 그 근본 원리는 블록(`{}`)이 마지막 세미콜론 없는 표현식의 값을 반환한다는 규칙에 있고, 이 규칙은 함수의 반환값 처리에도 그대로 이어집니다. 연산자 우선순위가 헷갈릴 때는 부록의 표를 참고하거나 괄호를 사용하면 됩니다. 다음 장에서는 이렇게 배운 표현식을 바탕으로 `if`, `match` 등을 이용한 본격적인 제어 흐름을 다룹니다.

## 연습문제

1. `7 / 2`와 `7.0 / 2.0`의 결과가 왜 다른지 설명하고, 직접 코드로 확인해 보세요.
2. `false || expensive_check()` 형태의 코드를 작성해, `||`의 단축 평가 때문에 `expensive_check` 함수가 호출되지 않는 경우와 호출되는 경우를 각각 만들어 보세요.
3. 정수 하나를 입력받아(또는 변수로 고정해) 짝수인지 홀수인지를 나타내는 문자열을 `if` 표현식으로 만들어 변수에 저장하고 출력하는 프로그램을 작성하세요.
4. 블록 표현식 안에서 두 변수를 선언하고, 마지막 줄에 세미콜론을 붙였을 때와 붙이지 않았을 때 결과 타입이 어떻게 달라지는지 `{:?}` 포맷으로 출력해 비교해 보세요.
5. `1 + 2 * 3 - 4 / 2`의 결과를 연산자 우선순위 규칙에 따라 손으로 먼저 계산해 보고, 코드로 실행해 결과가 맞는지 확인해 보세요.
