프로그램이 항상 위에서 아래로 한 줄씩만 실행된다면 할 수 있는 일은 매우 제한적일 것이다. 실제 프로그램은 조건에 따라 다른 코드를 실행하거나, 특정 값과 일치하는 경우를 골라 처리해야 한다. 이번 장에서는 Rust에서 조건에 따라 흐름을 분기하는 방법인 `if`/`else`와 `match`, `if let`을 다룬다. 반복적으로 코드를 실행하는 `loop`, `while`, `for`는 다음 장에서 별도로 살펴본다.

## if, else if, else

Rust의 `if` 문법은 다른 언어와 크게 다르지 않다.

```rust
fn main() {
    let temperature = 28;

    if temperature > 30 {
        println!("매우 더움");
    } else if temperature > 20 {
        println!("적당히 더움");
    } else {
        println!("쾌적하거나 추움");
    }
}
```

주의할 점 하나는 조건식을 괄호로 감쌀 필요가 없다는 것이다. C나 Java에서는 `if (temperature > 30)`처럼 쓰지만, Rust에서는 `if temperature > 30`으로 충분하다. 괄호를 써도 문법 오류는 아니지만, 관용적인 Rust 코드는 괄호를 생략한다.

또 하나 중요한 규칙은 조건식이 반드시 `bool` 타입이어야 한다는 점이다. 정수를 조건으로 사용하는 C 스타일의 코드는 Rust에서 컴파일되지 않는다.

```rust
let number = 0;
if number {          // 오류: bool이 아니라 i32입니다
    println!("실행되지 않음");
}
```

정수를 조건으로 쓰고 싶다면 명시적으로 비교식을 작성해야 한다(`number != 0`처럼). 이런 엄격함은 4장에서 다룬 Rust의 강한 타입 검사 철학과 맞닿아 있다. 실수로 대입 연산자를 잘못 쓰거나 의도치 않은 값을 조건으로 넣는 실수를 컴파일 단계에서 걸러낸다.

### if는 표현식이다

4장에서 Rust의 많은 구문이 값을 만들어내는 표현식이라고 이야기했다. `if`도 예외가 아니다. `if`/`else` 블록 전체가 하나의 값으로 평가될 수 있으며, 이 값을 변수에 바로 대입할 수 있다.

```rust
fn main() {
    let temperature = 28;

    let feeling = if temperature > 30 {
        "매우 더움"
    } else if temperature > 20 {
        "적당히 더움"
    } else {
        "쾌적하거나 추움"
    };

    println!("체감: {feeling}");
}
```

여기서 각 블록의 마지막 줄에 세미콜론이 없다는 점에 주목하자. 세미콜론을 붙이면 그 줄은 문장이 되어 값을 반환하지 않고, 블록 전체의 타입이 `()`(유닛 타입)가 되어 버린다. `let feeling = if ... { "A"; } else { "B"; };`처럼 작성하면 컴파일 오류가 발생하는데, 각 분기 블록이 만들어내는 타입이 서로 일치해야 한다는 규칙 때문이다. Rust는 `if`의 각 분기가 항상 같은 타입의 값을 내야 한다고 요구한다. 한쪽은 문자열을, 다른 쪽은 정수를 반환하는 코드는 컴파일되지 않는다.

이 표현식 스타일은 삼항 연산자가 없는 Rust에서 조건부 값 선택을 깔끔하게 표현하는 방법이다. 다음 두 코드는 동등하지만 표현식 스타일이 더 간결하다.

```rust
// 명령문 스타일
let discount;
if is_member {
    discount = 10;
} else {
    discount = 0;
}

// 표현식 스타일
let discount = if is_member { 10 } else { 0 };
```

## match로 값 비교하기: 맛보기

여러 개의 `else if`를 늘어놓는 대신, 하나의 값을 여러 패턴과 비교하고 싶을 때는 `match`가 더 어울린다. 지금은 정수나 문자 같은 단순한 값을 비교하는 용도로만 살짝 맛보고, 열거형과 함께 쓰는 진짜 강력한 활용법은 12장에서 자세히 다룬다.

```rust
fn main() {
    let day = 3;

    match day {
        1 => println!("월요일"),
        2 => println!("화요일"),
        3 => println!("수요일"),
        4 | 5 => println!("목요일 또는 금요일"),
        6..=7 => println!("주말"),
        _ => println!("잘못된 값"),
    }
}
```

몇 가지 눈여겨볼 부분이 있다. `4 | 5`처럼 `|`로 여러 패턴을 하나의 분기에 묶을 수 있고, `6..=7`처럼 범위 패턴도 사용할 수 있다. 마지막의 `_`는 "그 외 모든 경우"를 처리하는 와일드카드 패턴이다. `match`는 반드시 모든 가능한 경우를 다뤄야 하므로(이를 "총망라성"이라 부른다), `_` 분기를 빼먹으면 정수처럼 값의 범위가 넓은 타입에서는 컴파일 오류가 난다.

`match`도 `if`와 마찬가지로 표현식이므로 값을 반환할 수 있다.

```rust
let day = 3;
let name = match day {
    1 => "월요일",
    2 => "화요일",
    3 => "수요일",
    4 => "목요일",
    5 => "금요일",
    _ => "주말",
};
println!("{name}");
```

`if`/`else if` 체인과 `match`는 언제 나눠 써야 할까? 대략적인 기준은 이렇다. 비교 조건이 부등식(`>`, `<` 등)이거나 서로 다른 변수를 섞어서 검사해야 한다면 `if`/`else if`가 더 자연스럽다. 반면 하나의 값이 정해진 몇 가지 경우 중 무엇에 해당하는지 분류하는 상황이라면 `match`가 더 명확하고, 컴파일러가 누락된 경우를 잡아준다는 안전성 이점도 있다.

## if let 간단 소개

Rust에는 `Option<T>`이나 `Result<T, E>`처럼 "값이 있을 수도, 없을 수도 있는" 상황을 표현하는 타입이 자주 등장한다(이 타입들은 15장 에러 처리에서 본격적으로 다룬다). 이런 타입에서 원하는 경우 하나만 뽑아내고 싶을 때 `match`를 쓰면 다음처럼 코드가 다소 길어진다.

```rust
let maybe_number: Option<i32> = Some(7);

match maybe_number {
    Some(value) => println!("값이 있습니다: {value}"),
    None => {}
}
```

`None` 분기에서 아무 일도 하지 않는다면, 이 상황을 위해 만들어진 `if let` 문법을 쓰는 것이 더 간결하다.

```rust
let maybe_number: Option<i32> = Some(7);

if let Some(value) = maybe_number {
    println!("값이 있습니다: {value}");
}
```

`if let Some(value) = maybe_number`는 "`maybe_number`가 `Some` 패턴과 일치하면, 그 안의 값을 `value`라는 이름으로 꺼내서 블록을 실행하라"는 뜻이다. 일치하지 않으면(즉 `None`이면) 그냥 블록을 건너뛴다. `else`를 붙여서 일치하지 않는 경우도 처리할 수 있다.

```rust
if let Some(value) = maybe_number {
    println!("값이 있습니다: {value}");
} else {
    println!("값이 없습니다");
}
```

`if let`은 `match`의 총망라성 검사를 요구하지 않는 대신, 관심 있는 패턴 하나만 간결하게 다루고 나머지는 무시하고 싶을 때 유용하다. `Option`과 `Result`, 그리고 이들을 다루는 더 다양한 패턴은 12장과 15장에서 이어서 살펴볼 것이다.

## 요약

- `if`/`else if`/`else`의 조건식은 괄호가 필요 없지만 반드시 `bool` 타입이어야 한다.
- `if`는 값을 반환하는 표현식이며, 각 분기 블록이 만들어내는 타입은 모두 같아야 한다.
- `match`는 하나의 값을 여러 패턴과 비교할 때 쓰며, `|`로 패턴을 묶거나 `..=`로 범위를 표현할 수 있고 총망라성이 요구된다.
- `if let`은 `Option`이나 `Result`처럼 특정 패턴 하나만 관심 있을 때 `match`보다 간결하게 쓸 수 있는 문법이다.
- 열거형과 결합한 `match`의 진짜 활용법은 12장에서 자세히 다룬다.

## 연습문제

1. 정수 변수 `score`를 받아 90 이상이면 "A", 80 이상이면 "B", 70 이상이면 "C", 그 외에는 "F"를 반환하는 `if`/`else if` 표현식을 작성하라.
2. 위 문제를 `match`와 범위 패턴(`90..=100` 등)을 사용해 다시 작성하라.
3. `let x: i32 = 5;`에 대해 `if x { ... }`처럼 정수를 조건으로 직접 사용하면 어떤 컴파일 오류가 나는지 확인하고, 왜 Rust가 이런 제약을 두는지 설명하라.
4. `Option<i32>` 값을 받아 짝수면 그 값을 두 배로 출력하고, 홀수거나 값이 없으면 아무것도 하지 않는 코드를 `if let`으로 작성하라.
5. 요일을 나타내는 정수 1~7을 받아 "평일" 또는 "주말"을 출력하는 `match` 문을 작성하고, `_` 패턴을 빼면 어떤 오류가 발생하는지 실험해 보라.
