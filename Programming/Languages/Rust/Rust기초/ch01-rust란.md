# 1장. Rust란 무엇인가

## 들어가며

프로그래밍 언어를 배우다 보면 늘 마주치는 딜레마가 있다. 빠르고 자원을 세밀하게 다룰 수 있는 언어(C, C++)는 실수하기 쉽고, 실수해도 안전하게 막아주는 언어(Java, Python, Go)는 대개 가비지 컬렉터(garbage collector) 때문에 실행 속도와 메모리 사용량에서 손해를 본다. Rust는 이 딜레마를 "컴파일 시점에 규칙을 강제한다"는 아이디어로 풀어낸 언어다. 프로그램이 실행되기도 전에, 컴파일러가 메모리를 잘못 다루는 코드를 잡아낸다. 그 결과 가비지 컬렉터 없이도 메모리 안전성을 보장하면서, C/C++에 맞먹는 실행 성능을 낼 수 있다.

이 장에서는 Rust가 왜 이런 설계를 택했는지, 어디에 쓰이는지, 다른 언어와 무엇이 다른지 살펴보고 개발 환경을 준비한다.

## 소유권 시스템: Rust의 핵심 아이디어

Rust를 다른 언어와 구분 짓는 가장 중요한 특징은 소유권(ownership) 시스템이다. 대부분의 언어는 메모리 관리를 다음 두 가지 방식 중 하나로 처리한다.

- **수동 관리(C, C++)**: 프로그래머가 직접 메모리를 할당하고 해제한다. 자유롭지만, 해제를 잊거나(메모리 누수) 두 번 해제하거나(dangling pointer) 이미 해제된 메모리를 참조하는 실수가 발생하기 쉽다.
- **가비지 컬렉터(Java, Python, Go, JavaScript)**: 런타임이 더 이상 쓰이지 않는 메모리를 자동으로 찾아 해제한다. 안전하지만, 가비지 컬렉터가 실행되는 시점을 프로그래머가 정확히 통제할 수 없고, 그로 인한 지연(latency)이 발생할 수 있다.

Rust는 세 번째 길을 택했다. 모든 값은 정확히 하나의 소유자(owner)를 가지며, 소유자가 유효 범위(scope)를 벗어나는 순간 컴파일러가 삽입한 코드가 그 값을 즉시 해제한다. 이 규칙은 런타임에 검사하는 것이 아니라 컴파일 시점에 규칙 위반 여부를 판정하기 때문에, 실행 중에는 가비지 컬렉터를 위한 별도의 비용이 들지 않는다. 이 소유권의 자세한 규칙은 8장에서, 값을 소유권 이전 없이 빌려 쓰는 빌림(borrowing)과 참조(reference)는 9장에서 다룬다. 지금은 "Rust는 메모리 관리를 컴파일러가 정적으로 검증한다"는 큰 그림만 기억하면 충분하다.

## 성능과 타입 시스템

소유권 시스템 덕분에 Rust로 작성한 프로그램은 런타임 오버헤드가 거의 없다. 함수 호출, 반복문, 구조체 접근 같은 기본 연산은 C/C++로 작성했을 때와 실행 속도 차이가 거의 나지 않는다. 컴파일러(rustc)는 LLVM이라는 백엔드를 사용해 코드를 최적화된 기계어로 변환하는데, 이는 Clang이나 GCC 같은 C/C++ 컴파일러와 같은 인프라를 공유한다.

또한 Rust는 강한 정적 타입(strong static typing) 언어다. 모든 변수의 타입은 컴파일 시점에 결정되며, 타입이 맞지 않는 연산은 컴파일이 거부된다. 변수와 자료형은 3장에서 자세히 다루지만, 여기서 강조할 점은 이렇다. Rust의 타입 검사는 단순히 "정수에 문자열을 더할 수 없다" 수준을 넘어, 널 포인터 참조나 데이터 경쟁(data race) 같은 버그까지 상당 부분 컴파일 시점에 잡아낸다. 이런 특징 때문에 Rust 프로그래머들 사이에서는 "컴파일이 되면 대체로 동작한다"는 말이 통용된다.

## 어디에 쓰이는가

Rust는 성능과 안전성이 동시에 필요한 영역에서 특히 강점을 보인다.

- **시스템 프로그래밍**: 운영체제 커널, 디바이스 드라이버, 브라우저 엔진(Firefox의 일부 컴포넌트가 Rust로 작성되었다) 등 메모리를 직접 다루면서도 안전성이 중요한 영역.
- **웹어셈블리(WebAssembly)**: Rust 코드를 컴파일해 브라우저에서 네이티브에 가까운 속도로 실행할 수 있다. 이미지 처리, 게임 엔진, 계산 집약적인 웹 애플리케이션에 활용된다.
- **CLI 도구**: 빠르게 실행되고 배포가 쉬운 단일 실행 파일을 만들 수 있어, 커맨드라인 유틸리티 제작에 널리 쓰인다. 실제로 이 책의 2장에서 만드는 첫 프로그램도 이런 실행 파일 형태다.
- **임베디드 시스템**: 운영체제 없이 마이크로컨트롤러 위에서 직접 동작하는 프로그램도 작성할 수 있다(`no_std` 환경). 메모리가 극히 제한된 장치에서 안전성을 확보하려는 목적에 잘 맞는다.
- **네트워크/백엔드 서비스**: 높은 처리량과 낮은 지연이 필요한 서버 프로그램에도 널리 채택되고 있다.

## 다른 언어와의 비교

### C++와 비교

C++는 수동 메모리 관리와 스마트 포인터(smart pointer) 같은 도구를 함께 제공하지만, 규칙을 지키는 것은 결국 프로그래머의 책임이다. 컴파일러는 댕글링 포인터(dangling pointer)나 이중 해제(double free) 같은 실수를 대부분 잡아내지 못한다. Rust는 같은 문제를 소유권 규칙으로 컴파일 시점에 원천 차단한다. 대신 그 규칙을 배우고 지키는 데 초기 학습 비용이 든다. C++ 개발자가 Rust를 처음 접하면 "왜 이렇게 간단한 코드도 컴파일이 안 되지"라는 답답함을 느끼는 경우가 많은데, 이는 컴파일러가 런타임에 발생할 수 있었던 버그를 미리 지적하고 있는 것이다.

### Go와 비교

Go는 가비지 컬렉터와 간결한 문법으로 빠른 개발 속도를 지향하는 언어다. 배우기 쉽고 동시성 프로그래밍(고루틴)이 직관적이라는 장점이 있다. 반면 Rust는 가비지 컬렉터가 없어 지연 시간이 예측 가능하고, 세밀한 메모리 제어가 필요한 상황에서 유리하다. 다만 Go보다 배워야 할 개념(소유권, 빌림, 라이프타임 등)이 많아 학습 곡선이 더 가파르다. 결과물의 성능과 제어권을 우선한다면 Rust, 개발 속도와 단순함을 우선한다면 Go가 더 적합한 경우가 많다. 어느 쪽이 "더 나은" 언어라기보다는, 문제의 성격에 맞는 도구를 고르는 문제다.

## cargo와 개발 환경 준비

Rust를 설치하면 언어 자체(rustc 컴파일러)뿐 아니라 cargo라는 빌드 도구 겸 패키지 관리자가 함께 설치된다. cargo는 프로젝트 생성, 의존성(라이브러리) 관리, 빌드, 실행, 테스트를 하나의 명령으로 처리해 준다. 이 책의 예제도 대부분 cargo를 통해 실행한다. cargo의 세부 기능은 2장과 부록에서 더 다룬다.

Rust 설치는 rustup이라는 도구를 통해 진행하는 것이 표준적인 방법이다. rustup은 Rust 버전 관리자로, 여러 버전의 Rust를 설치하고 전환할 수 있게 해준다.

- **Windows**: [rust-lang.org](https://www.rust-lang.org)에서 `rustup-init.exe`를 내려받아 실행하면 안내에 따라 설치가 진행된다. Visual Studio의 C++ 빌드 도구가 함께 필요하다는 안내가 나올 수 있는데, 이는 Windows에서 링커(linker)가 필요하기 때문이다.
- **macOS/Linux**: 터미널에서 다음 명령을 실행한다.

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

설치가 끝나면 터미널을 새로 열고 다음 명령으로 버전을 확인한다.

```bash
rustc --version
cargo --version
```

두 명령 모두 버전 번호가 출력되면 설치가 정상적으로 완료된 것이다. 편집기는 어떤 것을 써도 무방하지만, VS Code에 rust-analyzer 확장을 설치하면 자동완성과 오류 표시를 실시간으로 받아볼 수 있어 학습에 도움이 된다.

## 이 책의 학습 방향

이 책은 문법을 나열하는 대신, 실제로 코드를 작성하고 컴파일러가 내는 오류를 읽으며 배우는 방식을 지향한다. Rust 컴파일러는 다른 언어의 컴파일러보다 오류 메시지가 훨씬 친절한 편이라, 오류를 두려워하지 않고 읽는 습관을 들이는 것이 중요하다. 이 특징은 2장에서 직접 확인해 본다.

전체 구성은 크게 세 부분으로 나뉜다. 3장부터 7장까지는 변수, 연산자, 제어문, 반복문, 함수 등 다른 언어에도 있는 기본 문법을 Rust 방식으로 배운다. 8장부터 12장까지는 소유권, 빌림, 슬라이스, 구조체, 열거형과 패턴 매칭(pattern matching) 등 Rust를 Rust답게 만드는 핵심 개념을 다룬다. 13장부터 17장까지는 트레이트(trait), 제네릭(generic), 에러 처리, 컬렉션, 라이프타임(lifetime) 등 실전 프로그램을 작성하는 데 필요한 도구를 익힌다. 마지막 18장에서는 좋은 Rust 코드를 작성하는 습관을 정리한다.

## 요약

- Rust는 가비지 컬렉터 없이 소유권 시스템으로 메모리 안전성을 컴파일 시점에 보장하는 언어다.
- 실행 성능은 C/C++에 준하며, 강한 정적 타입 시스템이 다양한 버그를 컴파일 시점에 잡아낸다.
- 시스템 프로그래밍, 웹어셈블리, CLI 도구, 임베디드, 백엔드 서비스 등 성능과 안전성이 함께 필요한 분야에 널리 쓰인다.
- C++는 메모리 관리 책임이 프로그래머에게 있고, Go는 가비지 컬렉터를 사용한다는 점에서 Rust와 차별화된다.
- rustup으로 Rust와 cargo를 설치하고, `rustc --version`, `cargo --version`으로 설치를 확인한다.

## 연습문제

1. 가비지 컬렉터를 사용하는 언어와 Rust의 메모리 관리 방식이 근본적으로 다른 점은 무엇인가? 각각의 장단점을 한 문장씩으로 설명해 보라.
2. rustup을 이용해 자신의 컴퓨터에 Rust를 설치하고, `rustc --version`과 `cargo --version`의 출력 결과를 확인해 보라.
3. 본문에서 소개한 Rust의 활용 분야(시스템 프로그래밍, 웹어셈블리, CLI 도구, 임베디드, 백엔드) 중 자신의 관심 분야와 가장 관련 있는 것을 하나 고르고, 그 이유를 간단히 적어 보라.
4. C++와 Rust의 메모리 관리 방식의 차이를 "컴파일 시점 검사"라는 키워드를 사용해 설명해 보라.
5. Rust 컴파일러가 다른 언어보다 오류 메시지가 친절하다는 특징이 학습자에게 어떤 도움이 될지 생각해 보라.
