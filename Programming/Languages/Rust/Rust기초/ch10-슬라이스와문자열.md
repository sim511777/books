# 10장. 슬라이스와 문자열

9장에서 참조(`&`)는 값의 소유권을 가져오지 않고 그 값을 잠시 빌려서 사용하는 방법이라고 배웠습니다. 이번 장에서 다룰 **슬라이스(slice)**는 참조의 한 종류로, 컬렉션 전체가 아니라 그 **일부**를 소유권 없이 참조하는 방법입니다. 슬라이스를 이해하면 배열이나 벡터의 일부분을 복사하지 않고 효율적으로 다룰 수 있고, Rust에서 문자열을 다루는 표준적인 방식인 `String`과 `&str`의 관계도 훨씨 자연스럽게 이해할 수 있습니다.

## 왜 슬라이스가 필요한가

문자열에서 첫 번째 단어만 찾아내는 함수를 만든다고 해봅시다. 참조에 대한 지식만으로는 "몇 번째 바이트부터 몇 번째 바이트까지"라는 정보를 표현할 방법이 마땅치 않습니다. 인덱스를 따로 반환하는 방법을 생각해볼 수 있지만, 그러면 원본 문자열이 바뀌었을 때 그 인덱스가 여전히 유효한지 보장할 수 없습니다. Rust는 이 문제를 슬라이스로 해결합니다. 슬라이스는 "원본 데이터의 어느 지점부터 어느 지점까지를 가리키는 참조"입니다. 참조이기 때문에 소유권을 가져오지 않고, 범위를 함께 담고 있기 때문에 부분 구간이라는 정보도 표현할 수 있습니다.

## 배열과 벡터의 슬라이스

배열이나 벡터의 일부 구간을 가리키는 슬라이스는 `&[T]` 타입으로 표현하며, 범위 문법(`..`)으로 만듭니다.

```rust
fn main() {
    let numbers = [10, 20, 30, 40, 50];

    let middle = &numbers[1..4]; // 인덱스 1, 2, 3 (4는 포함하지 않음)
    println!("{:?}", middle);   // [20, 30, 40]

    let from_start = &numbers[..2]; // 처음부터 인덱스 2 전까지
    println!("{:?}", from_start);   // [10, 20]

    let to_end = &numbers[3..]; // 인덱스 3부터 끝까지
    println!("{:?}", to_end);   // [40, 50]

    let whole = &numbers[..]; // 전체를 슬라이스로
    println!("{:?}", whole);  // [10, 20, 30, 40, 50]
}
```

슬라이스는 원본 데이터를 복사하지 않고 "시작 위치"와 "길이"라는 두 정보만 들고 있는 얇은 참조입니다. 그래서 큰 배열의 일부만 다룰 때도 데이터 복사 비용이 들지 않습니다. `Vec<T>` 역시 동일한 문법으로 슬라이싱할 수 있고, 함수 매개변수를 `&[T]`로 받으면 배열과 벡터를 구분 없이 하나의 함수로 처리할 수 있습니다.

```rust
fn sum(slice: &[i32]) -> i32 {
    let mut total = 0;
    for n in slice {
        total += n;
    }
    total
}

fn main() {
    let numbers = vec![1, 2, 3, 4, 5];

    println!("{}", sum(&numbers[..3])); // 처음 세 개만 전달: 1+2+3 = 6
    println!("{}", sum(&numbers));      // 벡터 전체도 슬라이스로 자동 전달: 15
}
```

`sum` 함수는 `Vec<i32>`도, 배열도, 그 일부 구간도 모두 받을 수 있습니다. 슬라이스를 매개변수 타입으로 사용하면 함수가 훨씨 유연해집니다.

## String과 &str: 문자열의 두 얼굴

Rust에는 문자열을 다루는 타입이 크게 두 가지 있습니다.

- `String`: 힙에 할당되며, 데이터를 **소유**하는 문자열입니다. 크기를 늘리거나 줄일 수 있습니다.
- `&str`: 문자열의 일부 또는 전체를 가리키는 **슬라이스**입니다. 데이터를 소유하지 않고 빌려올 뿐입니다.

사실 `&str`은 `&[u8]`과 비슷한 개념으로, "문자열 데이터의 어느 구간을 가리키는 참조"입니다. 그래서 `&str`을 흔히 **문자열 슬라이스(string slice)**라고 부릅니다.

```rust
fn main() {
    let owned: String = String::from("hello world"); // 힙에 소유된 문자열
    let borrowed: &str = &owned[0..5];                // "hello" - owned의 일부를 빌린 슬라이스
    let literal: &str = "hello world";                // 문자열 리터럴 자체가 &str

    println!("{} / {} / {}", owned, borrowed, literal);
}
```

코드에 등장하는 문자열 리터럴, 예를 들어 `"hello world"`는 프로그램의 실행 파일 안에 고정된 데이터로 저장되며, 그 자체가 이미 `&str` 타입입니다. 그래서 `let literal: &str = "hello world";`처럼 소유권을 만들 필요 없이 바로 사용할 수 있습니다.

이 관계는 8장에서 배운 소유권, 9장에서 배운 참조와 정확히 맞아떨어집니다. `String`은 힙 데이터를 소유하는 값이고, `&str`은 그 값을 (혹은 그 값의 일부를) 빌려오는 참조입니다.

## 함수 매개변수는 &str이 더 유연하다

함수를 작성할 때는 대부분 `String` 대신 `&str`을 매개변수로 받는 것이 좋습니다.

```rust
fn greet(name: &str) {
    println!("안녕하세요, {}님!", name);
}

fn main() {
    let name1 = String::from("철수");
    let name2 = "영희";

    greet(&name1); // &String이 자동으로 &str로 변환된다 (역참조 강제)
    greet(name2);  // 이미 &str이므로 그대로 전달
}
```

`greet` 함수가 `name: String`을 받도록 작성했다면 `greet(name2)`처럼 리터럴을 직접 넘길 수 없었을 것입니다. 반면 `&str`로 받으면 `String`에 대한 참조와 문자열 리터럴을 모두 받을 수 있어서 함수 하나로 두 경우를 다 처리할 수 있습니다.

## 문자열은 UTF-8 바이트의 시퀀스다

Rust의 `String`과 `&str`은 항상 유효한 **UTF-8** 바이트 시퀀스입니다. UTF-8에서는 문자마다 차지하는 바이트 수가 다릅니다. 영어 알파벳은 보통 1바이트지만, 한글 한 글자는 3바이트를 차지합니다.

```rust
fn main() {
    let greeting = String::from("안녕하세요");
    println!("바이트 길이: {}", greeting.len());          // 15 (5글자 * 3바이트)
    println!("문자 개수: {}", greeting.chars().count());  // 5
}
```

`len()`은 바이트 수를 반환하기 때문에 "글자 수"와 다릅니다. 이 차이 때문에 Rust는 문자열에 대해 정수 인덱스로 직접 접근하는 `greeting[0]` 같은 문법을 **허용하지 않습니다**. 만약 임의의 바이트 위치로 잘라내려고 하면 어떤 일이 생기는지 봅시다.

```rust
fn main() {
    let greeting = String::from("안녕하세요");

    let ok = &greeting[0..3]; // "안" - 한글 한 글자는 3바이트라서 경계가 딱 맞음
    println!("{}", ok);

    // let oops = &greeting[0..1]; // 이 줄의 주석을 해제하면 아래와 같은 오류로 panic 발생
    // thread 'main' panicked at 'byte index 1 is not a char boundary'
}
```

`greeting[0..1]`은 "안"이라는 한글 문자를 이루는 3바이트 중 첫 1바이트만 잘라내려는 시도입니다. 이 위치는 문자의 중간이므로 유효한 UTF-8 데이터가 아니고, Rust는 이런 잘못된 슬라이싱을 실행 시점에 panic으로 막습니다. 만약 정수 인덱스로 바로 문자를 얻어올 수 있었다면, 프로그래머가 실수로 문자 중간을 잘라서 깨진 데이터를 만들기 쉬웠을 것입니다. Rust는 애초에 `String`에 정수 인덱스 접근 문법 자체를 제공하지 않음으로써 이런 실수를 원천적으로 막습니다.

## 문자 단위로 안전하게 순회하기

바이트 경계를 신경 쓰지 않고 문자 단위로 문자열을 다루고 싶다면 `chars()` 메서드를 사용합니다.

```rust
fn main() {
    let greeting = String::from("안녕하세요");

    for (i, c) in greeting.chars().enumerate() {
        println!("{}번째 문자: {}", i, c);
    }
}
```

바이트 단위 정보가 필요하다면 `bytes()`를, 안전하게 범위를 검사하며 접근하고 싶다면 `get()` 메서드를 사용해 `Option<&str>`을 얻을 수도 있습니다. 이런 메서드들은 panic 대신 `None`을 반환하므로 잘못된 경계에 접근했을 때 프로그램이 즉시 죽는 대신 우아하게 처리할 기회를 줍니다. `Option`을 활용해 오류를 다루는 방법은 15장 에러 처리에서 더 깊이 다룹니다.

첫 단어를 찾는 함수를 슬라이스로 완성해봅시다. 공백(스페이스, `b' '`)은 UTF-8에서 항상 1바이트이고 다른 문자의 바이트 일부와 절대 겹치지 않기 때문에, 바이트 단위로 검사해도 한글이 섞인 문장에서도 안전하게 동작합니다.

```rust
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[..i];
        }
    }

    &s[..] // 공백이 없으면 문자열 전체가 하나의 단어
}

fn main() {
    let sentence = String::from("러스트는 재미있다");
    let word = first_word(&sentence);
    println!("첫 단어: {}", word); // "러스트는"
}
```

`first_word`는 `&String`을 받아 `&str`을 반환합니다. 반환된 슬라이스는 `sentence`가 살아있는 동안만 유효하며, 이는 9장에서 배운 참조의 생명 주기 규칙을 그대로 따릅니다. 이렇게 반환된 참조가 원본보다 오래 살 수 없도록 컴파일러가 검사하는 구체적인 규칙은 17장 라이프타임 기초에서 이어서 설명합니다.

## 요약

- 슬라이스는 컬렉션의 일부를 소유권 없이 참조하는 방법으로, 9장에서 배운 참조의 한 종류입니다.
- 배열과 벡터는 `&arr[start..end]` 문법으로 슬라이싱하며, 결과 타입은 `&[T]`입니다.
- `String`은 힙에 데이터를 소유하는 문자열이고, `&str`은 문자열의 전체 또는 일부를 가리키는 슬라이스입니다.
- 문자열 리터럴은 그 자체로 `&str`이며 프로그램에 고정된 데이터를 가리킵니다.
- 함수 매개변수는 `String`보다 `&str`로 받는 것이 더 유연합니다. `&String`이 자동으로 `&str`로 변환되기 때문입니다.
- Rust의 문자열은 항상 유효한 UTF-8 바이트 시퀀스이며, 문자마다 차지하는 바이트 수가 다르기 때문에 정수 인덱스로 직접 접근할 수 없습니다.
- 문자 경계를 벗어난 위치로 슬라이싱하면 panic이 발생하며, `chars()`, `bytes()`, `get()` 등을 사용하면 이런 문제를 안전하게 피할 수 있습니다.

## 연습문제

1. 정수 벡터를 받아서 앞의 절반과 뒤의 절반을 각각 슬라이스로 반환하는 방식으로 두 부분의 합을 출력하는 프로그램을 작성하세요.
2. `first_word` 함수를 참고하여, 문자열에서 마지막 단어를 반환하는 `last_word` 함수를 작성하세요.
3. 한글이 포함된 문자열에서 `len()`이 반환하는 바이트 수와 `chars().count()`가 반환하는 문자 수가 왜 다른지 예제 코드로 확인하고 설명해보세요.
4. `&greeting[0..1]`처럼 문자 경계가 아닌 위치로 슬라이싱해서 실제로 panic이 발생하는 것을 확인한 뒤, `get()` 메서드를 사용해 panic 없이 `None`을 받아보는 코드로 고쳐보세요.
5. 매개변수를 `String`으로 받는 함수와 `&str`로 받는 함수를 각각 작성하고, 문자열 리터럴을 직접 넘겼을 때 어느 쪽이 컴파일되고 어느 쪽이 실패하는지 확인해보세요.
