# 7장. 함수

---

지금까지 작성한 코드는 대부분 `main` 함수 안에 모든 로직을 담아왔습니다. 하지만 프로그램이 조금이라도 복잡해지면 같은 작업을 여러 번 반복하거나, 하나의 흐름을 논리적인 단위로 나누어야 할 필요가 생깁니다. 이럴 때 사용하는 것이 바로 **함수(function)**입니다. 이번 장에서는 Rust에서 함수를 정의하고 호출하는 방법, 매개변수와 반환값을 다루는 방법, 그리고 Rust 특유의 "표현식이 곧 반환값"이라는 개념을 살펴봅니다.

## 함수 정의하기

Rust에서 함수는 `fn` 키워드로 정의합니다. 이미 여러 번 보았듯이 `main` 함수도 사실 하나의 함수일 뿐입니다.

```rust
fn main() {
    greet();
}

fn greet() {
    println!("안녕하세요, Rust!");
}
```

함수 이름은 관례상 **snake_case**(소문자와 밑줄)로 작성합니다. `greet_user`, `calculate_sum`처럼 단어를 밑줄로 구분하는 방식입니다. 함수는 `main`보다 먼저 정의되든 나중에 정의되든 상관없이 호출할 수 있습니다. Rust는 컴파일 시점에 파일 전체를 먼저 살펴보기 때문에, C언어처럼 함수를 사용하기 전에 선언(prototype)을 미리 해줄 필요가 없습니다.

## 매개변수(Parameters)

함수는 호출할 때 값을 전달받을 수 있습니다. 이 값을 **매개변수**라고 부르며, 함수 정의에서 각 매개변수는 반드시 타입을 명시해야 합니다. 3장에서 다룬 변수 선언과 달리, 함수 매개변수의 타입은 추론되지 않고 항상 명시적으로 적어주어야 합니다.

```rust
fn main() {
    print_temperature(28.5);
    add_and_print(3, 4);
}

fn print_temperature(celsius: f64) {
    println!("현재 온도는 {celsius}도입니다.");
}

fn add_and_print(a: i32, b: i32) {
    let sum = a + b;
    println!("{a} + {b} = {sum}");
}
```

매개변수가 여러 개일 때는 쉼표로 구분합니다. 각 매개변수는 독립된 타입을 가질 수 있으므로, `a: i32, b: i32`처럼 같은 타입을 반복해서 적어야 합니다(`a, b: i32`처럼 축약할 수 없습니다).

## 반환값과 `->`

함수가 값을 돌려주려면 화살표(`->`) 뒤에 반환 타입을 명시합니다.

```rust
fn square(n: i32) -> i32 {
    n * n
}

fn main() {
    let result = square(5);
    println!("5의 제곱은 {result}입니다.");
}
```

여기서 눈여겨볼 부분은 `square` 함수 본문의 마지막 줄입니다. `return n * n;`처럼 명시적으로 `return`을 쓰지 않고, 그냥 `n * n`이라고만 적었습니다. 세미콜론도 없습니다. 이것이 Rust 함수의 매우 중요한 특징입니다.

## 문(Statement)과 표현식(Expression)의 구분

Rust는 코드를 구성하는 요소를 **문(statement)**과 **표현식(expression)**으로 명확히 구분합니다. 4장에서 연산자와 표현식을 다루면서 이미 이 개념을 살짝 언급했는데, 여기서 다시 정리해 보겠습니다.

- **문(statement)**: 어떤 동작을 수행하지만, 값을 만들어내지 않는 코드 조각입니다. `let x = 5;`나 함수 정의 `fn foo() {}` 자체가 문입니다. 문은 항상 세미콜론(`;`)으로 끝납니다.
- **표현식(expression)**: 평가되어 하나의 값을 만들어내는 코드 조각입니다. `5 + 6`, `n * n`, `if condition { 1 } else { 2 }` 등이 표현식입니다.

여기서 핵심 규칙은 이렇습니다.

> **함수 본문(또는 블록 `{ }`)의 마지막 줄이 세미콜론 없는 표현식이면, 그 값이 곧 블록 전체의 값이 된다.**

다음 코드로 이 규칙을 조금 더 자세히 살펴봅시다.

```rust
fn describe_number(n: i32) -> &'static str {
    if n % 2 == 0 {
        "짝수"
    } else {
        "홀수"
    }
}

fn main() {
    println!("7은 {}입니다.", describe_number(7));
}
```

`if ... else ...` 블록 자체도 표현식입니다. 각 분기의 마지막 줄에 세미콜론이 없으므로 `"짝수"` 또는 `"홀수"`라는 값이 만들어지고, 이 값이 그대로 `describe_number` 함수의 반환값이 됩니다. `if`가 표현식으로 쓰일 때는 5장에서 다룬 `if`/`else` 제어문과 형태는 같지만, 값을 만들어낸다는 점에서 조금 다르게 이해할 필요가 있습니다.

세미콜론을 잘못 붙이면 어떤 일이 벌어질까요?

```rust
fn square_broken(n: i32) -> i32 {
    n * n; // 세미콜론을 붙이면 이 줄은 표현식이 아니라 '문'이 된다
}
```

이 코드는 컴파일되지 않습니다. `n * n;`은 세미콜론이 붙어 문이 되었으므로 아무 값도 만들어내지 않습니다. 그러면 함수 본문의 마지막 표현식이 존재하지 않게 되어, Rust는 암묵적으로 유닛 타입 `()`(빈 튜플, "아무 값도 없음"을 뜻하는 타입)를 반환하려 합니다. 하지만 함수 시그니처는 `-> i32`를 약속했으므로, 컴파일러는 다음과 같은 오류를 냅니다.

```text
error[E0308]: mismatched types
 --> src/main.rs:2:5
  |
1 | fn square_broken(n: i32) -> i32 {
  |                              --- expected `i32` because of return type
2 |     n * n;
  |          ^ help: consider removing this semicolon
```

이 오류 메시지는 Rust 컴파일러의 특징을 잘 보여줍니다. 단순히 "틀렸다"고만 말하지 않고, "세미콜론을 지워보라"는 구체적인 힌트까지 제공합니다. 이런 친절한 오류 메시지는 Rust를 배우는 과정에서 큰 도움이 됩니다.

## `return` 키워드는 언제 쓰는가

물론 `return` 키워드를 명시적으로 쓸 수도 있습니다. 특히 함수 중간에서 조건에 따라 일찍 빠져나가야 할 때 유용합니다.

```rust
fn classify_score(score: i32) -> &'static str {
    if score < 0 || score > 100 {
        return "유효하지 않은 점수";
    }

    if score >= 90 {
        "A"
    } else if score >= 80 {
        "B"
    } else {
        "C"
    }
}
```

함수의 맨 마지막에서 값을 돌려줄 때는 `return`을 생략하고 표현식만 남기는 것이 Rust 스타일에서는 더 자연스럽게 여겨집니다. 반면 함수 중간에서 조기 종료할 때는 `return`을 사용하는 것이 코드의 의도를 더 명확하게 드러냅니다.

## 값을 반환하지 않는 함수

반환 타입을 적지 않은 함수는 `()`(유닛 타입)을 반환하는 것으로 간주됩니다. 앞서 `greet`, `print_temperature` 같은 함수들이 그 예입니다. `println!` 매크로를 호출해 화면에 출력하는 것처럼, 값 자체보다 부수 효과(side effect)가 목적인 함수는 대개 반환값이 없습니다.

```rust
fn print_separator() {
    println!("--------------------");
}
```

## 함수를 여러 개 조합하기

함수의 진짜 힘은 서로 조합될 때 드러납니다. 다음은 두 정수 중 더 큰 값을 찾고, 그 값이 짝수인지 판별하는 두 함수를 조합한 예제입니다.

```rust
fn max(a: i32, b: i32) -> i32 {
    if a > b {
        a
    } else {
        b
    }
}

fn is_even(n: i32) -> bool {
    n % 2 == 0
}

fn main() {
    let larger = max(17, 42);
    if is_even(larger) {
        println!("{larger}는 짝수입니다.");
    } else {
        println!("{larger}는 홀수입니다.");
    }
}
```

이렇게 작은 함수 단위로 로직을 나누면 코드를 읽기도 쉽고, 각 함수를 독립적으로 테스트하기도 쉬워집니다.

## 함수에 값을 넘길 때 생기는 일

한 가지 짚어두어야 할 부분이 있습니다. 지금까지 예제에서 함수에 넘긴 값은 모두 `i32`, `f64`, `bool`처럼 크기가 고정된 단순한 타입이었습니다. 이런 타입은 함수에 넘겨도 원래 변수에 아무 영향이 없습니다.

```rust
fn main() {
    let x = 5;
    take_number(x);
    println!("x는 여전히 {x}입니다."); // 문제없이 동작한다
}

fn take_number(n: i32) {
    println!("전달받은 값: {n}");
}
```

하지만 `String`처럼 힙(heap)에 데이터를 저장하는 타입을 함수에 넘기면 이야기가 달라집니다. 다음 코드를 살펴봅시다.

```rust
fn main() {
    let s = String::from("안녕하세요");
    take_string(s);
    // println!("{s}"); // 이 줄의 주석을 해제하면 컴파일 오류가 발생한다!
}

fn take_string(text: String) {
    println!("전달받은 문자열: {text}");
}
```

이 코드에서 `take_string(s)`를 호출한 순간, 변수 `s`가 가지고 있던 문자열의 **소유권**이 함수 안의 `text`로 넘어가 버립니다. 함수 호출이 끝나고 `main`으로 돌아와도 `s`는 더 이상 유효한 값을 가리키지 않으므로, 그 아래에서 `s`를 사용하려고 하면 컴파일 오류가 발생합니다.

이것이 바로 Rust를 다른 언어와 구분 짓는 가장 핵심적인 개념인 **소유권(ownership)**입니다. 왜 이런 규칙이 존재하는지, 그리고 이 규칙이 어떻게 Rust가 가비지 컬렉터 없이도 메모리 안전성을 보장하게 해주는지는 바로 다음 8장에서 자세히 다룹니다.

## 요약

- 함수는 `fn` 키워드로 정의하며, 이름은 snake_case로 작성한다.
- 매개변수는 반드시 타입을 명시해야 하며, 반환 타입은 `->` 뒤에 적는다.
- Rust는 코드를 문(statement)과 표현식(expression)으로 구분한다. 문은 값을 만들지 않고 세미콜론으로 끝나며, 표현식은 값을 만들어낸다.
- 함수(또는 블록)의 마지막 줄이 세미콜론 없는 표현식이면, 그 값이 곧 함수의 반환값이 된다.
- 함수 중간에서 일찍 값을 돌려줄 때는 `return` 키워드를 사용할 수 있다.
- 반환 타입을 적지 않은 함수는 유닛 타입 `()`을 반환한다.
- `String`처럼 힙 데이터를 가진 값을 함수에 넘기면 소유권이 함수로 이동하며, 원래 변수는 더 이상 사용할 수 없다. 이 원리는 8장에서 자세히 다룬다.

   fn double(n: i32) -> i32 {
