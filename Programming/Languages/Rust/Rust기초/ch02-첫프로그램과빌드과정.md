## 들어가며

1장에서 rustup으로 Rust와 cargo를 설치했다면, 이제 실제로 코드를 작성하고 실행해 볼 차례다. 이 장에서는 cargo로 프로젝트를 만드는 방법, 전통적인 "Hello, world!" 프로그램의 각 구성 요소, `cargo run`과 `cargo build`의 차이, 소스 코드가 실행 파일이 되기까지의 과정, 그리고 Rust 컴파일러가 내는 오류 메시지를 읽는 법을 다룬다.

## cargo new로 프로젝트 만들기

Rust 프로젝트는 파일 하나만 만들어서 시작할 수도 있지만, cargo를 사용하면 프로젝트 구조와 의존성 관리를 처음부터 표준화된 방식으로 갖출 수 있다. 원하는 디렉터리에서 다음 명령을 실행해 보자.

```bash
cargo new hello_rust
```

이 명령을 실행하면 `hello_rust`라는 디렉터리가 생성되고, 그 안에 다음과 같은 구조가 만들어진다.

```
hello_rust/
├── Cargo.toml
└── src/
    └── main.rs
```

- `Cargo.toml`: 프로젝트의 이름, 버전, 사용할 외부 라이브러리(의존성) 목록 등을 적어 두는 설정 파일이다.
- `src/main.rs`: 실제 프로그램 코드를 작성하는 소스 파일이다. `src` 디렉터리 아래에 소스 코드를 두는 것이 cargo의 규칙이다.

`cargo new`는 이 두 파일 외에도 버전 관리를 위한 `.gitignore`와 git 저장소를 함께 초기화한다. 이미 만들어 둔 디렉터리에서 새로 초기화만 하고 싶다면 `cargo init`을 사용하면 된다.

## Hello, world! 한 줄씩 읽기

`cargo new`가 생성한 `src/main.rs`를 열어 보면 다음 코드가 이미 들어 있다.

```rust
fn main() {
    println!("Hello, world!");
}
```

짧은 코드지만 Rust 문법의 기본 골격이 모두 담겨 있다. 한 줄씩 뜯어보자.

- `fn main()`: `fn`은 함수(function)를 정의하는 키워드다. `main`은 특별한 이름으로, Rust 프로그램이 실행될 때 가장 먼저 호출되는 진입점(entry point) 함수다. 다른 이름의 함수는 아무리 많이 정의해도 `main` 함수가 직접 또는 간접적으로 호출하지 않으면 실행되지 않는다. 함수를 정의하는 문법은 7장에서 자세히 다룬다.
- `()`: 함수가 받는 매개변수(parameter) 목록이다. 지금은 빈 괄호이므로 매개변수가 없다는 뜻이다.
- `{ ... }`: 중괄호로 감싼 부분이 함수의 본문(body)이다. 함수가 실행할 코드를 여기에 적는다.
- `println!("Hello, world!")`: 화면(정확히는 표준 출력)에 문자열을 출력하는 코드다. 이름 끝에 붙은 `!`는 이것이 함수가 아니라 매크로(macro)라는 표시다. 매크로는 컴파일 시점에 코드를 더 복잡한 코드로 확장해 주는 기능인데, 지금 단계에서는 "느낌표가 붙은 것은 매크로이고, 화면 출력에는 `println!`을 쓴다"고만 알아두면 충분하다.
- 줄 끝의 `;`: 세미콜론은 하나의 문장(statement)이 끝났음을 나타낸다. Rust의 거의 모든 문장은 세미콜론으로 끝난다.

## cargo run과 cargo build의 차이

프로젝트 디렉터리(`hello_rust` 안)에서 다음 명령을 실행해 보자.

```bash
cargo run
```

처음 실행하면 컴파일 과정이 출력되고, 이어서 프로그램이 실행되어 `Hello, world!`가 화면에 출력된다.

```
   Compiling hello_rust v0.1.0 (/path/to/hello_rust)
    Finished dev [unoptimized + debuginfo] target(s) in 0.42s
     Running `target/debug/hello_rust`
Hello, world!
```

`cargo run`은 두 가지 일을 순서대로 한다. 먼저 소스 코드를 컴파일해서 실행 파일을 만들고, 그다음 그 실행 파일을 곧바로 실행한다. 반면 `cargo build`는 컴파일까지만 수행하고 실행은 하지 않는다.

```bash
cargo build
```

이 명령을 실행하면 `target/debug/` 디렉터리 안에 실행 파일이 생성되지만, 화면에는 별다른 출력이 없다. 생성된 실행 파일은 직접 실행할 수 있다(Windows에서는 `target\debug\hello_rust.exe`, macOS/Linux에서는 `target/debug/hello_rust`).

정리하면 다음과 같은 관계다.

| 명령 | 컴파일 | 실행 |
|---|---|---|
| `cargo build` | O | X |
| `cargo run` | O | O |

이미 컴파일된 적이 있고 소스 코드에 변화가 없다면, `cargo run`이나 `cargo build`를 다시 실행해도 컴파일 과정을 건너뛰고 곧바로 기존 실행 파일을 사용한다. cargo가 소스 파일의 수정 시각을 추적해 다시 컴파일이 필요한지를 스스로 판단하기 때문이다.

배포용으로 최적화된 실행 파일이 필요할 때는 `--release` 옵션을 붙인다.

```bash
cargo build --release
```

이 경우 결과물은 `target/release/` 디렉터리에 생성되며, 컴파일 시간은 더 걸리지만 실행 속도는 더 빠르다. 개발 중에는 컴파일 속도가 빠른 기본(debug) 모드를, 실제 배포 시에는 `--release` 모드를 사용하는 것이 일반적이다.

## 소스 코드에서 실행까지: 빌드 파이프라인

지금까지 다룬 과정을 그림으로 정리하면 다음과 같다.

```text
                    Rust 소스 코드에서 실행까지

  +------------+  rustc   +----------------+        +----------------+        +----------------+
  |  main.rs   | -------> |     rustc      | -----> |    실행 파일     | -----> |      실행       |
  | (소스 코드)  |          |   (컴파일러)     |        | (예: main.exe)  |        | (프로그램 동작)   |
  +------------+          | 문법.타입.소유권  |        |  기계어 바이너리  |        | 터미널에 결과 출력 |
                          |      검사        |        |                |        |                |
                          +----------------+        +----------------+        +----------------+

  [<-------------------- cargo build : 소스를 컴파일해서 실행 파일만 생성 ------------------->]

  [<-------------------------- cargo run : 컴파일 후 곧바로 실행 파일까지 실행 -------------------------->]

  * Cargo.toml에 정의된 설정과 의존성 정보를 바탕으로 cargo가 rustc를 호출한다.
```

핵심은 세 단계다.

1. **소스 코드(`main.rs`)**: 사람이 읽고 쓰는 Rust 문법으로 작성된 텍스트 파일.
2. **컴파일(rustc)**: Rust 컴파일러가 문법 오류, 타입 오류, (8~9장에서 배울) 소유권과 빌림 규칙 위반 여부를 검사한 뒤, 문제가 없으면 CPU가 직접 실행할 수 있는 기계어로 이루어진 실행 파일을 생성한다.
3. **실행**: 생성된 실행 파일을 운영체제가 직접 실행한다. 이 단계에서는 더 이상 Rust 컴파일러가 필요하지 않다. 배포할 때도 소스 코드 대신 이 실행 파일 하나만 전달하면 된다.

cargo는 이 과정에서 rustc를 직접 호출하는 역할을 대신해 준다. 프로젝트가 커지고 외부 라이브러리(크레이트, crate)를 여러 개 사용하게 되면, 각 라이브러리를 어떤 순서로 컴파일해야 하는지, 어떤 버전을 써야 하는지 같은 문제가 생기는데, cargo는 `Cargo.toml`에 적힌 정보를 바탕으로 이를 자동으로 관리한다. cargo와 크레이트 생태계에 대한 자세한 내용은 부록에서 다룬다.

## Cargo.toml의 역할

`Cargo.toml`을 열어 보면 다음과 같은 내용이 들어 있다.

```toml
[package]
name = "hello_rust"
version = "0.1.0"
edition = "2021"

[dependencies]
```

- `[package]` 영역은 프로젝트 자체에 대한 정보다. `name`은 프로젝트 이름, `version`은 프로젝트 버전, `edition`은 사용할 Rust 문법 규칙의 세대를 가리킨다.
- `[dependencies]` 영역은 이 프로젝트가 사용할 외부 크레이트를 나열하는 곳이다. 지금은 비어 있지만, 예를 들어 난수 생성 라이브러리인 `rand`를 쓰고 싶다면 이 아래에 `rand = "0.8"`처럼 한 줄을 추가하면 된다. 그러면 다음 빌드 시 cargo가 해당 라이브러리를 자동으로 내려받아 컴파일에 포함시킨다.

즉 `Cargo.toml`은 "이 프로젝트가 무엇이고, 무엇을 필요로 하는가"를 선언하는 설계 문서 역할을 한다.

## 흔한 컴파일 오류와 대처법

Rust 컴파일러의 가장 큰 장점 중 하나는 오류 메시지가 매우 구체적이라는 점이다. 세미콜론을 하나 빠뜨려 보자.

```rust
fn main() {
    println!("Hello, world!")
}
```

컴파일하면 다음과 비슷한 메시지가 출력된다.

```
error: expected `;`, found `}`
 --> src/main.rs:2:33
  |
2 |     println!("Hello, world!")
  |                                 ^ 여기에 세미콜론이 필요합니다
```

메시지는 단순히 "오류가 있다"고만 말하지 않는다. 오류가 발생한 정확한 파일과 줄·열 번호, 문제가 된 코드, 그리고 무엇이 기대되었는지까지 함께 알려준다. 이런 상세함은 많은 컴파일러가 흉내 내려고 하는 Rust만의 특징으로 꼽힌다.

변수 이름을 잘못 입력하는 경우도 자주 발생한다.

```rust
fn main() {
    let messege = "Hello, world!";
    println!("{}", message);
}
```

이 경우 컴파일러는 오류만 알려주는 것이 아니라, 오타로 추정되는 후보까지 제안해 준다.

```
error[E0425]: cannot find value `message` in this scope
 --> src/main.rs:3:20
  |
3 |     println!("{}", message);
  |                    ^^^^^^^ 이 이름을 찾을 수 없습니다
  |
help: 혹시 이 이름을 쓰려던 것이 아닌가요: `messege`
```

Rust 컴파일러 오류를 대처하는 원칙은 다음과 같다.

1. **오류 메시지를 처음부터 끝까지 읽는다.** 첫 줄만 보고 넘어가면 `help:`에 담긴 구체적인 해결책을 놓치기 쉽다.
2. **오류 코드(`E0425` 같은 번호)를 검색한다.** `rustc --explain E0425` 명령을 실행하면 해당 오류에 대한 더 자세한 설명을 터미널에서 바로 볼 수 있다.
3. **가장 위에 있는 오류부터 고친다.** 하나의 실수가 뒤따르는 여러 오류를 유발하는 경우가 많으므로, 첫 오류를 해결하면 나머지가 함께 사라지기도 한다.
4. **경고(warning)도 무시하지 않는다.** 경고는 컴파일을 막지는 않지만, 사용하지 않는 변수나 불필요한 코드처럼 잠재적인 문제를 알려준다.

이러한 오류 메시지를 읽고 고치는 경험은 앞으로 3장부터 다룰 변수와 자료형, 그리고 8장 이후의 소유권 규칙을 배울 때도 반복해서 마주치게 된다. 오류를 두려워하지 않고 차근차근 읽는 습관을 지금부터 들여 두면 이후 학습이 훨씬 수월해진다.

## 요약

- `cargo new 프로젝트이름`으로 `Cargo.toml`과 `src/main.rs`를 갖춘 표준 프로젝트 구조를 생성한다.
- `fn main() { ... }`은 프로그램의 진입점이며, `println!`은 화면에 문자열을 출력하는 매크로다.
- `cargo build`는 컴파일만, `cargo run`은 컴파일과 실행을 함께 수행한다. 배포용 최적화 빌드는 `cargo build --release`로 만든다.
- 소스 코드는 rustc에 의해 문법·타입·소유권 검사를 거쳐 기계어 실행 파일로 변환되고, 이후에는 컴파일러 없이 독립적으로 실행된다.
- `Cargo.toml`은 프로젝트 정보와 의존성 목록을 선언하는 설정 파일이다.
- Rust 컴파일러의 오류 메시지는 위치, 원인, 해결 제안을 함께 제공하므로 끝까지 읽는 습관이 중요하다.

## 연습문제

1. `cargo new my_app` 명령으로 프로젝트를 만들고, 생성된 파일과 디렉터리 구조를 직접 확인해 보라.
2. `println!("Hello, world!")` 뒤의 세미콜론을 지운 뒤 `cargo build`를 실행해서 어떤 오류 메시지가 나오는지 관찰하고, 다시 세미콜론을 추가해 오류가 사라지는지 확인해 보라.
3. `cargo build`와 `cargo run`을 각각 실행했을 때 터미널에 출력되는 내용이 어떻게 다른지 비교해 보라.
4. `Cargo.toml`의 `[package]` 영역에서 `name`을 다른 값으로 바꾼 뒤 `cargo run`을 실행하면 어떤 일이 일어나는지 확인해 보라.
5. `println!` 매크로를 사용해 자신의 이름을 출력하는 프로그램을 작성하고, 정상적으로 컴파일과 실행이 되는지 확인해 보라.
