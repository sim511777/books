## 들어가며

3장에서 배운 배열(`[T; N]`)은 크기가 타입에 고정되어 있어서, 컴파일 시점에 원소의 개수를 알아야 한다. 하지만 실제 프로그램에서는 사용자 입력 개수, 파일에서 읽어온 줄 수, 실행 중에 계속 늘어나는 목록처럼 크기를 미리 알 수 없는 데이터를 다뤄야 하는 경우가 훨씬 많다. 이번 장에서는 이런 상황을 위한 표준 라이브러리의 두 가지 핵심 컬렉션, `Vec<T>`와 `HashMap<K, V>`를 살펴본다. 그리고 8~9장에서 배운 소유권과 빌림 규칙이 컬렉션을 순회할 때도 그대로 적용된다는 점을 확인한다.

## Vec<T>: 크기가 변하는 배열

`Vec<T>`(벡터)는 같은 타입의 값을 여러 개 담을 수 있는, 크기가 동적으로 늘어나고 줄어드는 컬렉션이다. 배열과 달리 `Vec`는 데이터를 힙(heap)에 저장하므로, 실행 중에 원소를 추가하거나 제거해도 문제가 없다.

```rust
fn main() {
    let mut numbers: Vec<i32> = Vec::new();
    numbers.push(10);
    numbers.push(20);
    numbers.push(30);

    println!("{:?}", numbers); // [10, 20, 30]
}
```

값을 미리 알고 있다면 `vec!` 매크로로 배열과 비슷하게 초기화할 수도 있다.

```rust
let numbers = vec![10, 20, 30];
```

배열과 벡터의 핵심 차이를 정리하면 다음과 같다.

| | 배열 `[T; N]` | 벡터 `Vec<T>` |
|---|---|---|
| 크기 | 컴파일 시점에 고정 | 실행 중 변경 가능 |
| 저장 위치 | 대개 스택 | 힙 |
| 크기 변경 연산 | 없음 | `push`, `pop`, `insert`, `remove` 등 |
| 타입에 크기 포함 여부 | 포함(`[i32; 3]`은 `[i32; 5]`와 다른 타입) | 미포함(`Vec<i32>` 하나로 통일) |

### 주요 메서드: push, pop, get

`push`는 벡터 끝에 원소를 추가하고, `pop`은 끝에서 원소를 하나 꺼내서 제거한다. `pop`은 벡터가 비어 있을 수 있으므로 15장에서 배운 `Option<T>`를 반환한다.

```rust
fn main() {
    let mut stack = vec![1, 2, 3];

    stack.push(4);
    println!("{:?}", stack); // [1, 2, 3, 4]

    while let Some(top) = stack.pop() {
        println!("꺼낸 값: {top}");
    }
    // 4, 3, 2, 1 순서로 출력되고 stack은 비어 있게 된다
}
```

`while let`은 5장에서 다룬 `if let`을 반복문 형태로 확장한 문법으로, `pop()`이 `Some`을 반환하는 동안 계속 반복하다가 `None`을 만나면 자연스럽게 멈춘다.

특정 위치의 원소에 접근할 때는 인덱스 연산자(`numbers[i]`)와 `get` 메서드 두 가지 방법이 있다. 둘의 차이가 중요하다.

```rust
fn main() {
    let numbers = vec![10, 20, 30];

    let third = numbers[2]; // 30. 인덱스가 범위를 벗어나면 즉시 패닉
    println!("{third}");

    match numbers.get(5) {
        Some(value) => println!("값: {value}"),
        None => println!("인덱스 5는 존재하지 않습니다"),
    }
}
```

`numbers[5]`처럼 존재하지 않는 인덱스에 대괄호 연산자를 쓰면 그 즉시 패닉이 발생해 프로그램이 죽는다. 반면 `numbers.get(5)`는 `Option<&T>`를 반환하므로, 인덱스가 범위 밖이어도 `None`을 받아 안전하게 처리할 수 있다. 15장에서 살펴본 "실패 가능성을 타입으로 드러낸다"는 원칙이 여기서도 그대로 적용되는 것이다. 사용자 입력 등 신뢰할 수 없는 값으로 인덱싱할 때는 `get`을 쓰는 편이 안전하다.

그 밖에도 자주 쓰이는 메서드로 `len()`(길이), `is_empty()`, `insert(index, value)`(특정 위치에 삽입), `remove(index)`(특정 위치 제거), `contains(&value)`(포함 여부) 등이 있다.

## HashMap<K, V>: 키로 값 찾기

`Vec<T>`가 순서가 있는 목록이라면, `HashMap<K, V>`는 키(key)와 값(value)을 짝지어 저장하고 키로 값을 빠르게 찾는 컬렉션이다. `Vec`처럼 표준 라이브러리 최상위에서 바로 쓸 수 없고, `use` 문으로 가져와야 한다.

```rust
use std::collections::HashMap;

fn main() {
    let mut scores: HashMap<String, i32> = HashMap::new();

    scores.insert(String::from("철수"), 90);
    scores.insert(String::from("영희"), 85);

    println!("{:?}", scores);
}
```

### 주요 메서드: insert, get, entry

`insert`는 키-값 쌍을 추가하거나, 이미 있는 키라면 값을 덮어쓴다. `get`은 `Vec`의 `get`처럼 `Option<&V>`를 반환한다.

```rust
use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();
    scores.insert("철수", 90);

    match scores.get("철수") {
        Some(score) => println!("철수의 점수: {score}"),
        None => println!("철수의 점수가 없습니다"),
    }

    match scores.get("민수") {
        Some(score) => println!("민수의 점수: {score}"),
        None => println!("민수의 점수가 없습니다"),
    }
}
```

키가 존재하는지 몰라서 "있으면 갱신하고, 없으면 새로 만든다"는 로직을 짜야 할 때가 많다. 이를 직접 `match`로 작성하면 코드가 다소 번거롭다.

```rust
use std::collections::HashMap;

fn main() {
    let mut word_count: HashMap<&str, i32> = HashMap::new();
    let text = "rust is great and rust is fast";

    for word in text.split_whitespace() {
        match word_count.get(word) {
            Some(count) => {
                let new_count = count + 1;
                word_count.insert(word, new_count);
            }
            None => {
                word_count.insert(word, 1);
            }
        }
    }

    println!("{:?}", word_count);
}
```

이런 "있으면 수정, 없으면 삽입" 패턴을 위해 `entry` 메서드와 `or_insert`를 함께 쓰면 훨씬 간결해진다.

```rust
use std::collections::HashMap;

fn main() {
    let mut word_count: HashMap<&str, i32> = HashMap::new();
    let text = "rust is great and rust is fast";

    for word in text.split_whitespace() {
        let count = word_count.entry(word).or_insert(0);
        *count += 1;
    }

    println!("{:?}", word_count);
}
```

`word_count.entry(word)`는 해당 키의 항목(entry)에 대한 참조를 반환하고, `or_insert(0)`은 그 키가 없으면 값 0을 넣은 뒤 그 값에 대한 가변 참조(`&mut i32`)를 돌려준다. 키가 이미 있으면 기존 값에 대한 가변 참조를 그대로 돌려준다. `*count += 1`에서 `*`는 9장에서 다룬 참조 역참조(dereference)로, 참조가 가리키는 실제 값을 1 증가시킨다. 이 관용구는 단어 빈도 계산처럼 "그룹별로 값을 누적한다"는 상황에서 매우 자주 쓰인다.

## 컬렉션을 순회할 때도 소유권과 빌림 규칙은 그대로 적용된다

8장과 9장에서 배운 소유권과 빌림 규칙은 컬렉션을 순회할 때도 예외 없이 적용된다. `Vec<T>`나 `HashMap<K, V>`를 반복문에 넣는 방식에는 세 가지가 있고, 각각 소유권 관점에서 의미가 다르다.

### iter(): 불변 참조로 순회

`iter()`는 각 원소에 대한 불변 참조(`&T`)를 만들어낸다. 원본 컬렉션은 그대로 살아있고, 순회가 끝난 뒤에도 계속 사용할 수 있다.

```rust
fn main() {
    let numbers = vec![1, 2, 3];

    for n in numbers.iter() {
        println!("{n}"); // n의 타입은 &i32
    }

    // numbers는 여전히 유효하다
    println!("합계 확인용: {:?}", numbers);
}
```

사실 `for n in &numbers`처럼 써도 컴파일러가 자동으로 `iter()`를 호출한 것과 같은 효과를 낸다. 둘은 관용적으로 거의 동일하게 쓰인다.

### iter_mut(): 가변 참조로 순회

원소의 값을 직접 수정하고 싶다면 `iter_mut()`으로 가변 참조(`&mut T`)를 얻는다. 9장에서 배운 규칙, 즉 가변 참조가 살아있는 동안에는 다른 참조를 함께 만들 수 없다는 제약이 여기서도 유지된다.

```rust
fn main() {
    let mut numbers = vec![1, 2, 3];

    for n in numbers.iter_mut() {
        *n *= 2; // 역참조 후 값 변경
    }

    println!("{:?}", numbers); // [2, 4, 6]
}
```

### into_iter(): 소유권을 넘기며 순회

`into_iter()`는 컬렉션의 소유권 자체를 가져가면서 각 원소를 값(`T`)으로 하나씩 내놓는다. 순회가 끝나면 원본 컬렉션은 이동(move)되어 더 이상 사용할 수 없다. `for` 문에 컬렉션을 참조 없이 직접 넣으면 컴파일러가 자동으로 `into_iter()`를 호출한다.

```rust
fn main() {
    let numbers = vec![String::from("a"), String::from("b")];

    for s in numbers {
        println!("{s}"); // s의 타입은 String. 소유권을 그대로 넘겨받는다
    }

    // 여기서 numbers를 다시 사용하면 컴파일 오류: 이동되었기 때문
    // println!("{:?}", numbers);
}
```

이 세 가지 방식은 8장에서 배운 "이동은 한 번만 일어난다"는 규칙, 9장에서 배운 "가변 참조는 동시에 하나만 존재할 수 있다"는 규칙을 컬렉션 순회라는 맥락에 그대로 적용한 것일 뿐이다. 정리하면 다음과 같다.

| 방식 | 얻는 것 | 원본 컬렉션 |
|---|---|---|
| `iter()` / `for x in &v` | `&T` (불변 참조) | 순회 후에도 사용 가능 |
| `iter_mut()` / `for x in &mut v` | `&mut T` (가변 참조) | 순회 후에도 사용 가능(값은 변경될 수 있음) |
| `into_iter()` / `for x in v` | `T` (값, 소유권 이전) | 순회 후 더 이상 사용 불가 |

`HashMap`도 마찬가지로 `iter()`는 `(&K, &V)`, `iter_mut()`은 `(&K, &mut V)`, `into_iter()`는 `(K, V)`를 내놓는다.

```rust
use std::collections::HashMap;

fn main() {
    let mut scores = HashMap::new();
    scores.insert("철수", 90);
    scores.insert("영희", 85);

    for (name, score) in scores.iter() {
        println!("{name}: {score}");
    }
}
```

어떤 방식을 골라야 할지 헷갈릴 때는 이렇게 생각하면 된다. 값을 읽기만 한다면 `iter()`, 값을 직접 바꿔야 한다면 `iter_mut()`, 컬렉션 자체를 소비하면서(예: 다른 자료구조로 변환하거나 함수에 값을 그대로 넘길 때) 각 원소의 소유권이 필요하다면 `into_iter()`를 쓴다. 이 판단 기준은 결국 8~9장에서 배운 "이 값을 소유해야 하는가, 잠깐 들여다보기만 하면 되는가, 잠깐 바꾸기만 하면 되는가"라는 질문과 완전히 같다.

## 요약

- `Vec<T>`는 크기가 실행 중에 변할 수 있는 동적 배열이며, 3장의 고정 크기 배열과 달리 힙에 데이터를 저장한다.
- `push`/`pop`으로 끝에 원소를 추가·제거하고, 인덱스 연산자는 범위를 벗어나면 패닉하지만 `get`은 `Option<&T>`를 반환해 안전하다.
- `HashMap<K, V>`는 키로 값을 찾는 컬렉션이며, `insert`/`get`으로 기본 조작을 하고 `entry(...).or_insert(...)`로 "있으면 수정, 없으면 삽입" 패턴을 간결하게 표현한다.
- 컬렉션 순회 방식은 `iter()`(불변 참조), `iter_mut()`(가변 참조), `into_iter()`(소유권 이전) 세 가지가 있으며, 이는 8~9장의 소유권·빌림 규칙을 그대로 따른다.
- 어떤 순회 방식을 쓸지는 "읽기만 할 것인가, 수정할 것인가, 소유권까지 가져갈 것인가"라는 질문으로 결정하면 된다.

## 연습문제

1. 정수를 담은 `Vec<i32>`를 받아 짝수만 걸러낸 새로운 `Vec<i32>`를 반환하는 함수를 작성하라. (힌트: `iter()`로 순회하며 조건에 맞는 값만 새 벡터에 `push`한다.)
2. 문자열 벡터를 순회하며 각 문자열의 길이를 그 자리에서 두 배로 늘려 담을 수는 없지만, 각 문자열에 접미사를 추가하는 것은 `iter_mut()`으로 가능하다. `Vec<String>`의 각 원소 뒤에 "!"를 붙이는 코드를 `iter_mut()`과 `push_str`을 이용해 작성하라.
3. 문장(문자열)을 입력받아 각 단어가 몇 번 등장했는지 `HashMap<&str, i32>`로 계산하는 함수를 `entry`와 `or_insert`를 사용해 작성하라.
4. 같은 `Vec<i32>`에 대해 `for x in numbers`, `for x in &numbers`, `for x in numbers.iter_mut()`를 각각 시도해 보고, 반복문이 끝난 뒤 `numbers`를 다시 사용할 수 있는지 여부를 비교해 정리하라.
5. `HashMap<String, Vec<i32>>` 형태로 학생 이름별 점수 목록을 저장하고, 특정 학생이 이미 존재하면 점수를 추가하고 없으면 새 목록을 만들어 추가하는 코드를 `entry`와 `or_insert_with(Vec::new)`를 사용해 작성하라.
