## 들어가며

11장에서 구조체(struct)를 배우면서 `impl` 블록으로 구조체에 메서드를 붙이는 방법을 익혔다. 그런데 실무 코드를 작성하다 보면 서로 다른 구조체 여러 개가 "같은 종류의 동작"을 공유해야 하는 상황이 자주 생긴다. 예를 들어 도형을 표현하는 `Rectangle`과 `Circle` 구조체가 있다고 해보자. 둘 다 넓이(area)를 구할 수 있어야 하고, 둘 다 화면에 정보를 출력할 수 있어야 한다. 이럴 때 각 구조체마다 `rectangle_area`, `circle_area` 같은 별도 함수를 만들면, 나중에 삼각형(`Triangle`) 구조체가 추가될 때마다 비슷한 함수를 계속 늘려야 하고, "넓이를 구할 수 있는 도형이면 아무거나 받아서 처리하는 함수"를 작성할 방법이 없다.

Rust는 이 문제를 트레이트(trait)로 해결한다. 트레이트는 "이 동작을 구현하려면 어떤 메서드가 있어야 하는가"를 정의하는 명세서다. 다른 언어의 인터페이스(interface, Java나 C#)나 프로토콜(protocol, Swift)과 비슷한 역할을 한다고 생각하면 이해가 빠르다. 트레이트를 구현한 타입은 "이 트레이트가 약속한 동작을 수행할 수 있다"는 것을 컴파일러에게 보장하게 되고, 그 결과 우리는 구체적인 타입이 무엇인지 몰라도 "이 트레이트를 구현한 타입이라면 무엇이든" 다루는 코드를 작성할 수 있다.

## 트레이트 정의하기

트레이트는 `trait` 키워드로 정의한다. 내부에는 메서드의 시그니처(signature)만 적는다. 구체적인 구현은 각 타입이 알아서 채운다.

```rust
// Shape 트레이트: 넓이와 둘레를 구할 수 있어야 한다는 약속
trait Shape {
    fn area(&self) -> f64;
    fn perimeter(&self) -> f64;
}
```

이 시점에서 `Shape`는 아직 아무 동작도 하지 않는다. "넓이를 구하는 `area` 메서드와 둘레를 구하는 `perimeter` 메서드가 있어야 한다"는 규칙만 선언했을 뿐이다. 실제 동작은 이 트레이트를 구현하는 타입에서 채워 넣는다.

## 구조체에 트레이트 구현하기

11장에서 만들어 본 `Rectangle`, `Circle` 구조체를 다시 가져와, 각각에 `Shape` 트레이트를 구현해 보자. 문법은 `impl Shape for Rectangle { ... }` 형태로, 일반 `impl` 블록과 비슷하지만 어떤 트레이트를 구현하는지를 `for` 뒤에 명시한다.

```rust
struct Rectangle {
    width: f64,
    height: f64,
}

struct Circle {
    radius: f64,
}

impl Shape for Rectangle {
    fn area(&self) -> f64 {
        self.width * self.height
    }

    fn perimeter(&self) -> f64 {
        2.0 * (self.width + self.height)
    }
}

impl Shape for Circle {
    fn area(&self) -> f64 {
        std::f64::consts::PI * self.radius * self.radius
    }

    fn perimeter(&self) -> f64 {
        2.0 * std::f64::consts::PI * self.radius
    }
}
```

`Shape`가 선언한 메서드는 반드시 모두 구현해야 한다. 하나라도 빠뜨리면 컴파일 오류가 발생한다. 이 점이 중요하다. 트레이트는 단순한 규칙이 아니라 컴파일러가 강제하는 계약이다.

```rust
fn main() {
    let rect = Rectangle { width: 3.0, height: 4.0 };
    let circle = Circle { radius: 2.0 };

    println!("사각형 넓이: {}", rect.area());
    println!("원 둘레: {}", circle.perimeter());
}
```

## 기본 구현(default method)

트레이트 메서드는 시그니처만 선언할 수도 있지만, 본문을 함께 적어 기본 동작을 제공할 수도 있다. 이를 기본 구현(default method)이라 부른다. 타입이 이 메서드를 따로 구현하지 않으면 기본 구현이 그대로 쓰이고, 필요하면 얼마든지 재정의(override)할 수 있다.

`Shape` 트레이트에 도형 정보를 문자열로 요약해 주는 `describe` 메서드를 기본 구현으로 추가해 보자. 이 메서드는 이미 정의된 `area`, `perimeter`를 그대로 활용할 수 있다. 트레이트 안에서는 다른 메서드도 `self.메서드명()` 형태로 호출할 수 있기 때문이다.

```rust
trait Shape {
    fn area(&self) -> f64;
    fn perimeter(&self) -> f64;

    // 기본 구현: area와 perimeter를 조합해 요약 문자열을 만든다
    fn describe(&self) -> String {
        format!(
            "넓이 {:.2}, 둘레 {:.2}인 도형입니다",
            self.area(),
            self.perimeter()
        )
    }
}
```

`Rectangle`과 `Circle`은 `describe`를 따로 구현하지 않아도 이 기본 구현을 그대로 물려받는다.

```rust
fn main() {
    let rect = Rectangle { width: 3.0, height: 4.0 };
    println!("{}", rect.describe());
    // 출력: 넓이 12.00, 둘레 14.00인 도형입니다
}
```

만약 `Circle`만 좀 더 특별한 문구를 출력하고 싶다면, `impl Shape for Circle` 블록 안에 `describe` 메서드를 직접 작성하면 된다. 그러면 기본 구현 대신 그 구현이 사용된다.

```rust
impl Shape for Circle {
    fn area(&self) -> f64 {
        std::f64::consts::PI * self.radius * self.radius
    }

    fn perimeter(&self) -> f64 {
        2.0 * std::f64::consts::PI * self.radius
    }

    // 기본 구현을 재정의한다
    fn describe(&self) -> String {
        format!("반지름 {}인 원입니다", self.radius)
    }
}
```

기본 구현은 여러 타입이 대부분 같은 동작을 공유하되 일부만 예외적으로 다르게 동작해야 할 때 코드 중복을 크게 줄여 준다.

## 트레이트를 매개변수로 받는 함수

트레이트의 진짜 힘은 "구체적인 타입은 몰라도, 이 트레이트를 구현했다는 사실만으로 함수를 작성할 수 있다"는 데서 나온다. 앞서 이야기한 "넓이를 구할 수 있는 도형이면 아무거나 받아서 처리하는 함수"를 이제 만들 수 있다.

```rust
// Shape를 구현한 타입이라면 무엇이든 받을 수 있다
fn print_shape_info(shape: &impl Shape) {
    println!("{}", shape.describe());
}

fn main() {
    let rect = Rectangle { width: 3.0, height: 4.0 };
    let circle = Circle { radius: 2.0 };

    print_shape_info(&rect);
    print_shape_info(&circle);
}
```

매개변수 타입을 `&impl Shape`로 적으면 "`Shape`를 구현한 어떤 타입의 참조든 받는다"는 뜻이 된다. `Rectangle`이든 `Circle`이든, 앞으로 추가될 `Triangle`이든, `Shape`만 구현하면 이 함수에 그대로 넘길 수 있다. `print_shape_info` 함수는 내부적으로 `shape.area()`나 `shape.describe()`처럼 `Shape`가 약속한 메서드만 사용하므로, 구체적인 타입이 무엇인지 알 필요가 없다.

사실 `impl Trait` 문법은 다음처럼 제네릭(generic) 타입 매개변수를 사용한 코드의 축약형이다.

```rust
fn print_shape_info<T: Shape>(shape: &T) {
    println!("{}", shape.describe());
}
```

`<T: Shape>`는 "타입 매개변수 `T`는 `Shape`를 구현한 타입이어야 한다"는 제약, 즉 트레이트 바운드(trait bound)를 건 것이다. 두 표기법은 대부분의 경우 똑같이 동작하지만, 제네릭 문법 쪽이 더 유연한 경우가 있다. 이 차이와 제네릭의 본격적인 문법은 다음 14장에서 자세히 다룬다. 지금은 "트레이트는 함수가 받을 수 있는 타입의 범위를 제한하는 도구"라는 점만 기억해 두자.

## 여러 트레이트를 요구하기

함수가 하나 이상의 트레이트를 동시에 요구할 수도 있다. `+` 기호로 트레이트를 연결하면 된다.

```rust
use std::fmt::Debug;

// Shape이면서 동시에 Debug도 구현한 타입만 받는다
fn print_debug_info(shape: &(impl Shape + Debug)) {
    println!("{:?} -> {}", shape, shape.describe());
}
```

이렇게 요구 사항을 여러 개 걸면, 그 함수 안에서는 나열한 모든 트레이트의 메서드를 자유롭게 사용할 수 있다.

## 표준 라이브러리의 트레이트

지금까지는 직접 정의한 `Shape` 트레이트를 다뤘지만, Rust 표준 라이브러리도 트레이트로 가득하다. 예를 들어 `{}`로 값을 출력할 때 쓰는 `Display`, `{:?}`로 디버그 출력을 할 때 쓰는 `Debug`, 값을 복제할 때 쓰는 `Clone`, 값을 비교할 때 쓰는 `PartialEq` 등은 모두 표준 라이브러리가 제공하는 트레이트다. 이들 중 상당수는 `#[derive(Debug)]`처럼 구조체 위에 속성(attribute)을 붙이는 것만으로 컴파일러가 구현을 자동으로 생성해 준다. 이 파생(derive) 매크로들은 이후 컬렉션(16장)과 좋은 코드 작성 습관(18장)을 다루면서 실전 예제와 함께 다시 살펴본다.

## 요약

- 트레이트는 여러 타입이 공통으로 구현해야 하는 메서드의 집합을 정의하는 명세서로, 다른 언어의 인터페이스와 비슷한 역할을 한다.
- `trait` 키워드로 트레이트를 정의하고, `impl 트레이트명 for 타입명` 블록에서 각 타입이 그 메서드를 구현한다.
- 트레이트 메서드에 본문을 적으면 기본 구현이 되며, 타입은 이를 그대로 쓰거나 원하는 만큼 재정의할 수 있다.
- `&impl Trait` 매개변수는 "이 트레이트를 구현한 어떤 타입이든 받는다"는 뜻이며, 내부적으로는 제네릭과 트레이트 바운드의 축약형이다.
- `+`로 여러 트레이트를 동시에 요구할 수 있고, `Display`, `Debug`, `Clone` 같은 표준 트레이트는 종종 `derive`로 자동 구현된다.

## 연습문제

1. `Shape` 트레이트에 새로운 도형 `Triangle`(세 변의 길이 `a`, `b`, `c`를 저장)을 추가하고 `area`(헤론의 공식 사용), `perimeter`를 구현해 보라.
2. `Shape` 트레이트에 `is_bigger_than(&self, other: &impl Shape) -> bool` 기본 구현을 추가해, 두 도형의 넓이를 비교하는 메서드를 만들어 보라.
3. `print_shape_info` 함수를 `impl Trait` 문법과 제네릭(`<T: Shape>`) 문법 두 가지로 각각 작성하고, 두 코드가 동일하게 동작하는지 확인해 보라.
4. 표준 라이브러리의 `Debug` 트레이트를 `#[derive(Debug)]`로 `Rectangle`에 자동 구현하고, `{:?}` 포맷으로 출력해 보라.
5. 본문의 `Shape` 예제에서 `describe` 기본 구현을 제거하지 않고, `Rectangle`만 별도로 `describe`를 재정의하면 어떤 출력이 나오는지 예상해 보고 직접 실행해 확인해 보라.
