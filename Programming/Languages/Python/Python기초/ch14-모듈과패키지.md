지금까지 작성한 예제들은 대부분 파일 하나 안에서 시작해서 끝났습니다. 그러나 실제 프로그램은 기능이 늘어날수록 코드의 양도 함께 늘어나고, 파일 하나에 모든 내용을 담으면 원하는 부분을 찾기도 어렵고 여러 사람이 함께 작업하기도 힘들어집니다. Python은 코드를 여러 파일로 나누어 관리하고, 필요한 부분만 가져다 쓸 수 있는 **모듈**과 **패키지**라는 단위를 제공합니다. 이번 장에서는 `import` 문법, 모듈이 정확히 무엇을 의미하는지, 자기 자신이 직접 실행되었는지 확인하는 관용구, 그리고 여러 모듈을 폴더 단위로 묶는 패키지 구조를 다룹니다. 표준 라이브러리에 어떤 모듈들이 있고 각각 무엇에 쓰이는지는 17장 표준 라이브러리와 패키지 관리에서 이어서 다룹니다.

## 모듈이란 무엇인가

Python에서는 확장자가 `.py`인 파일 하나가 그대로 하나의 **모듈**(module)이 됩니다. 특별한 준비 과정이 필요한 것이 아니라, 파이썬 코드를 담은 파일을 작성하는 순간 그 파일은 이미 다른 파일에서 가져다 쓸 수 있는 모듈이 됩니다.

예를 들어 다음과 같이 `calculator.py`라는 파일을 하나 작성했다고 해보겠습니다.

```python
# calculator.py
def add(a, b):
    """a와 b를 더한 값을 반환한다"""
    return a + b


def subtract(a, b):
    """a에서 b를 뺀 값을 반환한다"""
    return a - b


PI = 3.14159
```

이 파일 자체가 `calculator`라는 이름의 모듈입니다. 같은 폴더에 있는 다른 파일에서는 다음과 같이 이 모듈을 가져와 사용할 수 있습니다.

```python
# main.py
import calculator

print(calculator.add(3, 5))       # 8
print(calculator.subtract(10, 4))  # 6
print(calculator.PI)               # 3.14159
```

`import calculator`는 "`calculator.py` 파일을 찾아서 그 안의 내용을 실행하고, 그 결과를 `calculator`라는 이름으로 사용할 수 있게 하라"는 뜻입니다. 모듈 안에 정의된 함수나 변수는 `모듈이름.이름` 형태로 접근합니다. 지금까지 우리가 리스트나 문자열의 메서드를 `변수.메서드()` 형태로 호출해온 것과 비슷한 점(속성 접근)을 눈여겨보면, 모듈도 결국 그 안의 함수와 변수를 속성으로 갖는 하나의 객체라는 사실을 짐작할 수 있습니다.

이런 방식으로 코드를 나누면 얻는 장점이 명확합니다. `calculator.py`는 "계산과 관련된 코드"만 담당하고, `main.py`는 그것을 가져다 쓰는 코드에 집중할 수 있습니다. 여러 파일, 나아가 여러 사람이 각자 맡은 모듈을 독립적으로 작성하고, 필요할 때 서로 가져다 쓰는 방식으로 협업할 수 있습니다.

## `import` 문법 살펴보기

### 기본 `import`

가장 기본적인 형태는 앞서 본 것처럼 `import 모듈이름`입니다. Python이 기본으로 제공하는 표준 라이브러리 모듈도 똑같은 방식으로 가져올 수 있습니다.

```python
>>> import math
>>> math.sqrt(16)
4.0
>>> math.pi
3.141592653589793
```

`math`는 Python 인터프리터를 설치하면 기본으로 함께 제공되는 표준 라이브러리 모듈입니다. `calculator.py`처럼 우리가 직접 만든 모듈이든, `math`처럼 Python이 제공하는 모듈이든 가져와서 사용하는 방식은 동일합니다.

한 줄에 여러 모듈을 콤마로 구분해서 한꺼번에 가져올 수도 있습니다.

```python
import math, random
```

다만 이 형태는 PEP 8 스타일 가이드에서 권장하지 않습니다. 모듈이 여러 개 필요하다면 아래처럼 한 줄에 하나씩 적는 것이 훨씬 읽기 좋습니다.

```python
import math
import random
```

### `from ... import ...`로 필요한 것만 가져오기

모듈 전체가 아니라 그 안의 특정 함수나 변수만 필요할 때는 `from 모듈이름 import 이름` 형태를 사용합니다.

```python
>>> from math import sqrt, pi
>>> sqrt(25)
5.0
>>> pi
3.141592653589793
```

이렇게 가져오면 `math.sqrt(25)`처럼 모듈 이름을 앞에 붙이지 않고 `sqrt(25)`처럼 바로 이름만으로 사용할 수 있습니다. 코드가 조금 더 짧아지지만, 그만큼 이 이름이 어느 모듈에서 왔는지가 코드만 봐서는 즉시 드러나지 않는다는 단점도 있습니다. 모듈 안의 모든 이름을 한꺼번에 가져오는 `from 모듈이름 import *` 형태도 문법적으로는 가능하지만, 어떤 이름들이 새로 들어오는지 알기 어렵고 기존에 사용하던 이름과 충돌할 위험이 있어 실무에서는 거의 사용하지 않습니다.

### `as`로 별명 붙이기

모듈이나 가져온 이름에 별명(alias)을 붙이고 싶을 때는 `as`를 사용합니다. 모듈 이름이 너무 길거나, 관례적으로 정해진 짧은 별명이 있는 경우에 유용합니다.

```python
>>> import math as m
>>> m.sqrt(9)
3.0

>>> from calculator import add as plus
>>> plus(2, 3)
5
```

데이터 분석이나 과학 계산 분야에서 자주 쓰이는 `numpy`, `pandas` 같은 외부 패키지는 관례적으로 `import numpy as np`, `import pandas as pd`처럼 짧은 별명을 붙여서 사용합니다. 이런 관례는 17장에서 외부 패키지를 설치하고 사용하는 방법을 다룰 때 다시 살펴봅니다.

### 모듈은 한 번만 로드된다

같은 모듈을 여러 번 `import`해도, Python은 그 모듈의 코드를 처음 한 번만 실행합니다. 두 번째 `import`부터는 이미 메모리에 로드해 둔 결과를 재사용합니다.

```python
# greeting.py
print("greeting 모듈이 로드되었습니다")

MESSAGE = "안녕하세요"
```

```python
>>> import greeting
greeting 모듈이 로드되었습니다
>>> import greeting  # 두 번째부터는 아무것도 출력되지 않는다
>>> greeting.MESSAGE
'안녕하세요'
```

이 덕분에 여러 파일에서 같은 모듈을 가져다 써도 그 모듈의 초기화 코드가 반복 실행되며 낭비되는 일이 없습니다.

## 모듈을 직접 실행할 때와 가져올 때 구분하기: `if __name__ == "__main__":`

Python 파일은 두 가지 방식으로 쓰일 수 있습니다. 터미널에서 `python calculator.py`처럼 직접 실행되거나, 다른 파일에서 `import calculator`로 가져와 사용되거나입니다. 그런데 모듈을 테스트해보려고 파일 맨 아래에 실행 코드를 적어두면, 그 모듈을 다른 곳에서 `import`할 때도 그 코드가 함께 실행되어 버리는 문제가 생깁니다.

```python
# calculator.py
def add(a, b):
    return a + b


print(add(1, 2))  # 테스트해보려고 적어둔 코드
```

```python
>>> import calculator  # calculator.py를 그냥 가져오기만 했는데도...
3               # 테스트 코드가 실행되어 버린다
```

이 문제를 해결하는 Python의 관용구가 바로 `if __name__ == "__main__":`입니다. `__name__`은 모든 모듈이 자동으로 갖게 되는 특수한 변수로, 그 모듈이 어떻게 실행되었는지에 따라 값이 달라집니다.

- 파일이 `python calculator.py`처럼 **직접 실행**되면, 그 파일의 `__name__`은 `"__main__"`이 됩니다.
- 파일이 다른 곳에서 `import calculator`로 **가져와졌을 때**는, `__name__`이 그 모듈의 이름인 `"calculator"`가 됩니다.

```python
# calculator.py
def add(a, b):
    return a + b


def subtract(a, b):
    return a - b


if __name__ == "__main__":
    # 이 블록은 calculator.py를 직접 실행했을 때만 동작한다
    print(add(1, 2))       # 3
    print(subtract(5, 3))  # 2
```

이제 `calculator.py`를 터미널에서 직접 실행하면 `__name__`이 `"__main__"`이므로 조건문 안의 테스트 코드가 실행됩니다. 반면 다른 파일에서 `import calculator`로 가져오면 `__name__`은 `"calculator"`이므로 조건이 거짓이 되어 그 블록은 조용히 건너뜁니다.

```
$ python calculator.py
3
2
```

```python
>>> import calculator  # 아무것도 출력되지 않는다
>>> calculator.add(10, 20)
30
```

이 관용구는 Python 코드에서 매우 자주 등장합니다. "이 파일이 프로그램의 시작점(entry point)으로 직접 실행될 때만 아래 코드를 실행하고, 다른 모듈로서 가져와졌을 때는 함수와 클래스 정의만 제공하라"는 뜻으로 이해하면 됩니다. 스크립트를 작성할 때 처음부터 이 관용구로 감싸는 습관을 들이면, 나중에 그 파일이 재사용 가능한 모듈로도 함께 쓰이길 원할 때 코드를 다시 손댈 필요가 없습니다.

## 모듈 탐색 경로

`import calculator`를 실행했을 때 Python은 `calculator.py`라는 파일을 어디서 찾는 것일까요? Python은 정해진 순서에 따라 몇 군데의 위치를 차례로 검색하며, 이 검색 대상 목록은 `sys.path`라는 리스트에 저장되어 있습니다.

```python
>>> import sys
>>> sys.path
['', '/usr/lib/python3.12', ...]
```

`sys.path`의 첫 번째 항목은 대개 현재 실행 중인 스크립트가 위치한 폴더입니다. 그래서 같은 폴더에 있는 `calculator.py`를 별다른 설정 없이 바로 `import`할 수 있었던 것입니다. 그 뒤로는 Python이 설치된 표준 라이브러리 폴더, 그리고 `pip`으로 설치한 외부 패키지가 저장되는 폴더 등이 이어집니다. `sys` 모듈 자체와 이를 활용하는 방법은 17장에서 조금 더 자세히 다룹니다. 지금은 "가져오려는 모듈 파일이 이 목록에 있는 폴더들 중 하나에 있어야 `import`가 성공한다"는 정도만 기억해두면 충분합니다.

## 패키지: 여러 모듈을 폴더로 묶기

모듈이 하나의 `.py` 파일이었다면, **패키지**(package)는 여러 모듈을 하나의 폴더 아래 체계적으로 묶어놓은 것입니다. 프로젝트 규모가 커지면 모듈 파일 수도 함께 늘어나는데, 이를 관련된 것끼리 폴더로 묶어 정리하면 구조를 파악하기 훨씬 쉬워집니다.

다음과 같은 폴더 구조를 예로 들어보겠습니다.

```
shop/
    __init__.py
    products.py
    cart.py
```

`shop`이라는 폴더 안에 `__init__.py`, `products.py`, `cart.py` 세 개의 파일이 있습니다. 이 폴더가 `__init__.py`를 포함하고 있으면, Python은 이 폴더를 `shop`이라는 이름의 패키지로 인식합니다.

```python
# shop/products.py
def list_products():
    return ["사과", "바나나", "포도"]
```

```python
# shop/cart.py
def add_to_cart(product):
    return f"{product}를 장바구니에 담았습니다."
```

이제 패키지 안의 모듈은 마침표(`.`)로 경로를 이어가며 가져올 수 있습니다.

```python
>>> from shop import products
>>> products.list_products()
['사과', '바나나', '포도']

>>> from shop.cart import add_to_cart
>>> add_to_cart("사과")
'사과를 장바구니에 담았습니다.'

>>> import shop.products
>>> shop.products.list_products()
['사과', '바나나', '포도']
```

`from shop import products`는 `shop` 패키지 안의 `products` 모듈을 가져오는 것이고, `from shop.cart import add_to_cart`는 `shop` 패키지 안 `cart` 모듈 안의 `add_to_cart` 함수를 바로 가져오는 것입니다. 패키지 구조가 깊어지면(`shop.payment.card`처럼) 마침표를 계속 이어 붙여 경로를 표현합니다.

### `__init__.py`의 역할

`__init__.py`는 이름 그대로 그 패키지가 처음 `import`될 때 실행되는 초기화 코드를 담는 파일입니다. 이 파일은 내용이 완전히 비어 있어도 상관없습니다. 비어 있더라도 "이 폴더는 평범한 폴더가 아니라 패키지다"라는 표시 역할은 여전히 수행합니다.

`__init__.py`에 코드를 작성하면, 패키지를 사용하는 쪽에서 더 짧고 편리한 방식으로 하위 모듈의 기능에 접근하게 만들 수 있습니다.

```python
# shop/__init__.py
from shop.products import list_products
from shop.cart import add_to_cart
```

이렇게 작성해두면, 사용하는 쪽에서는 하위 모듈 이름을 몰라도 패키지 이름만으로 바로 접근할 수 있습니다.

```python
>>> import shop
>>> shop.list_products()
['사과', '바나나', '포도']
>>> shop.add_to_cart("바나나")
'바나나를 장바구니에 담았습니다.'
```

`list_products`가 사실은 `shop.products` 모듈에 정의되어 있다는 세부 사항을, `shop` 패키지를 사용하는 입장에서는 몰라도 되게 만든 것입니다. 이는 패키지 내부 구조를 나중에 리팩터링하더라도, `__init__.py`에서 다시 연결만 해주면 패키지를 사용하는 외부 코드는 전혀 수정할 필요가 없다는 장점으로 이어집니다.

참고로 Python 3.3 이후 버전에서는 `__init__.py` 파일이 없는 폴더도 일정한 조건 아래 패키지처럼 취급되는 "네임스페이스 패키지"라는 기능이 추가되었습니다. 하지만 이는 비교적 고급 주제이고, 대부분의 경우 관례대로 `__init__.py`를 명시적으로 만들어 두는 편이 의도를 명확히 드러내고 문제를 예방하는 데 도움이 됩니다.

### 패키지 안에서의 상대 임포트

패키지 내부의 한 모듈이 같은 패키지 안의 다른 모듈을 가져와야 할 때는, 패키지 최상위 이름부터 전부 적는 **절대 임포트**(absolute import) 대신 현재 위치를 기준으로 상대적인 경로를 표현하는 **상대 임포트**(relative import)를 사용할 수도 있습니다.

```python
# shop/cart.py
from . import products  # 같은 패키지(shop) 안의 products 모듈
from .products import list_products  # 위와 같은 대상을, 함수까지 바로 가져오는 방식
```

마침표 하나(`.`)는 "현재 모듈이 속한 패키지"를, 마침표 두 개(`..`)는 "한 단계 위의 부모 패키지"를 의미합니다. 상대 임포트는 패키지 전체의 이름이 바뀌거나 다른 프로젝트로 옮겨지더라도 패키지 내부 모듈 간의 관계를 그대로 유지할 수 있다는 장점이 있습니다. 다만 여러 단계로 중첩되면 어떤 모듈을 가리키는지 한눈에 파악하기 어려워질 수 있으므로, 패키지 구조가 단순하다면 `from shop import products`처럼 전체 경로를 다 적는 절대 임포트를 사용하는 것도 충분히 좋은 선택입니다.

## 정리: 모듈에서 패키지까지

지금까지 다룬 개념을 계층 구조로 정리하면 다음과 같습니다.

```
shop/                     ← 패키지 (폴더 + __init__.py)
    __init__.py
    products.py           ← 모듈 (파일 하나)
        list_products()   ← 모듈 안의 함수
    cart.py                ← 모듈 (파일 하나)
        add_to_cart()      ← 모듈 안의 함수
```

파일 하나가 모듈이고, 모듈 여러 개를 담은 폴더가 패키지이며, 패키지 여러 개가 모이면 더 큰 프로젝트가 됩니다. `import`는 이 계층 구조 어디서든 원하는 단위(패키지 전체, 패키지 안의 모듈, 모듈 안의 함수나 변수)를 필요한 만큼만 가져다 쓸 수 있게 해주는 문법입니다.

Python 자체에도 이런 구조로 정리된 수많은 표준 라이브러리 모듈과 패키지가 함께 설치되어 제공됩니다. 실무에서 자주 쓰이는 표준 라이브러리 모듈에는 무엇이 있고 각각 어떤 상황에 사용하는지, 그리고 표준 라이브러리에 없는 기능을 `pip`으로 설치해서 사용하는 방법은 17장 표준 라이브러리와 패키지 관리에서 이어서 다룹니다.

## 요약

- Python에서는 `.py` 파일 하나가 곧 하나의 **모듈**이다. `import 모듈이름`으로 가져와 `모듈이름.이름` 형태로 그 안의 함수·변수에 접근한다.
- `from 모듈이름 import 이름`은 모듈 안의 특정 이름만 골라 가져오고, `as`는 모듈이나 이름에 별명을 붙인다. 같은 모듈은 여러 번 `import`해도 코드가 한 번만 실행된다.
- `if __name__ == "__main__":`은 그 파일이 직접 실행되었는지(`__name__`이 `"__main__"`) 아니면 다른 곳에서 가져와졌는지(`__name__`이 모듈 이름)를 구분하는 관용구다. 스크립트로도, 재사용 가능한 모듈로도 쓰일 파일에 이 관용구를 적용하면 편리하다.
- `import`가 모듈을 찾는 위치들은 `sys.path`에 정의되어 있으며, 현재 스크립트가 있는 폴더가 그 목록의 맨 앞에 포함된다.
- **패키지**는 `__init__.py`를 포함한 폴더로, 여러 모듈을 체계적으로 묶어 관리할 수 있게 해준다. `__init__.py`에 코드를 작성해 하위 모듈의 기능을 패키지 최상위로 끌어올려 노출시킬 수 있고, 패키지 내부에서는 `.`, `..`을 이용한 상대 임포트도 사용할 수 있다.

5. `from module import *` 형태로 모듈의 모든 이름을 한꺼번에 가져오는 방식이 실무에서 권장되지 않는 이유를, 이름 충돌과 코드 가독성 관점에서 자신의 말로 설명해보세요.
