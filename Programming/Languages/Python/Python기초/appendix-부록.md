## 문자열 메서드 치트시트

문자열은 불변(immutable)이므로, 아래 메서드들은 모두 원본을 바꾸지 않고 새로운 문자열을 반환합니다. 자세한 내용은 5장 문자열 다루기를 참고하세요.

| 메서드 | 하는 일 | 예시 |
|---|---|---|
| `s.strip()` | 양쪽 끝 공백(또는 지정 문자) 제거 | `"  hi  ".strip()` → `"hi"` |
| `s.split(sep)` | 구분자를 기준으로 나눠 리스트로 반환 | `"a,b,c".split(",")` → `['a', 'b', 'c']` |
| `sep.join(iterable)` | 이터러블의 문자열들을 sep으로 이어 붙임 | `"-".join(["a", "b"])` → `"a-b"` |
| `s.replace(old, new)` | old를 new로 모두 교체 | `"foo bar".replace("o", "0")` → `"f00 bar"` |
| `s.upper()` / `s.lower()` | 대문자 / 소문자로 변환 | `"Abc".upper()` → `"ABC"` |
| `s.find(sub)` | sub의 첫 위치(없으면 `-1`) | `"hello".find("l")` → `2` |
| `s.startswith(sub)` / `s.endswith(sub)` | 접두사 / 접미사 확인 | `"hello".startswith("he")` → `True` |
| `s.format(...)` / f-string | 값을 문자열에 끼워 넣기 | `f"{name}님"` |
| `s.isdigit()` | 모든 문자가 숫자인지 확인 | `"123".isdigit()` → `True` |
| `s.count(sub)` | sub가 등장한 횟수 | `"banana".count("a")` → `3` |

## 리스트 메서드 치트시트

리스트는 가변(mutable) 객체이므로, 아래 메서드 대부분은 원본 리스트 자체를 바꾸며 별도의 반환값이 없습니다(`None`을 반환). 자세한 내용은 6장 리스트와 튜플을 참고하세요.

| 메서드 | 하는 일 | 반환값 | 예시 |
|---|---|---|---|
| `lst.append(x)` | 끝에 원소 하나 추가 | `None` | `lst.append(4)` |
| `lst.extend(iterable)` | 끝에 여러 원소 추가 | `None` | `lst.extend([4, 5])` |
| `lst.insert(i, x)` | i번째 위치에 원소 삽입 | `None` | `lst.insert(0, "new")` |
| `lst.remove(x)` | 처음 나오는 x를 삭제(없으면 오류) | `None` | `lst.remove("a")` |
| `lst.pop(i=-1)` | i번째 원소를 꺼내며 삭제 | 꺼낸 값 | `lst.pop()` |
| `lst.sort(key=None, reverse=False)` | 원본을 정렬 | `None` | `lst.sort(reverse=True)` |
| `lst.reverse()` | 원본 순서를 뒤집음 | `None` | `lst.reverse()` |
| `lst.index(x)` | x의 첫 위치(없으면 오류) | 인덱스 | `lst.index("b")` |
| `lst.count(x)` | x가 등장한 횟수 | 개수 | `lst.count(1)` |
| `lst.copy()` | 얕은 복사본 생성 | 새 리스트 | `new_lst = lst.copy()` |
| `lst.clear()` | 모든 원소 삭제 | `None` | `lst.clear()` |

## 딕셔너리 메서드 치트시트

자세한 내용은 7장 딕셔너리와 셋을 참고하세요.

| 메서드 | 하는 일 | 예시 |
|---|---|---|
| `d.keys()` | 모든 키를 담은 뷰 반환 | `for k in d.keys():` |
| `d.values()` | 모든 값을 담은 뷰 반환 | `for v in d.values():` |
| `d.items()` | (키, 값) 쌍을 담은 뷰 반환 | `for k, v in d.items():` |
| `d.get(key, default=None)` | 키가 없어도 오류 없이 조회 | `d.get("age", 0)` |
| `d.setdefault(key, default)` | 키가 없으면 default로 설정 후 반환 | `d.setdefault("hits", 0)` |
| `d.update(other)` | 다른 딕셔너리의 내용을 병합 | `d.update({"b": 2})` |
| `d.pop(key, default)` | 키를 꺼내며 삭제(없으면 default) | `d.pop("age", None)` |
| `d.popitem()` | 마지막에 삽입된 (키, 값) 쌍을 꺼내며 삭제 | `d.popitem()` |

## 데이터 타입 비교표

3장부터 7장까지 다룬 기본 자료형들의 성질을 한눈에 비교할 수 있도록 정리했습니다. "가변"은 생성된 이후 내용을 직접 바꿀 수 있는지, "순서"는 원소를 넣은 순서가 유지되고 인덱스로 접근할 수 있는지, "중복"은 같은 값을 여러 번 담을 수 있는지를 뜻합니다.

| 자료형 | 가변/불변 | 순서 유무 | 중복 허용 | 인덱싱/슬라이싱 | 대표 리터럴 |
|---|---|---|---|---|---|
| `int`, `float` | 불변 | 해당 없음 | 해당 없음 | 해당 없음 | `42`, `3.14` |
| `bool` | 불변 | 해당 없음 | 해당 없음 | 해당 없음 | `True`, `False` |
| `str` | 불변 | 순서 있음 | 허용 | 가능 | `"안녕"` |
| `list` | 가변 | 순서 있음 | 허용 | 가능 | `[1, 2, 3]` |
| `tuple` | 불변 | 순서 있음 | 허용 | 가능 | `(1, 2, 3)` |
| `dict` | 가변(값만 변경 가능) | 삽입 순서 유지 | 키는 중복 불가, 값은 중복 가능 | 키로 접근 (슬라이싱 불가) | `{"a": 1}` |
| `set` | 가변 | 순서 없음 | 중복 불가 | 불가능 | `{1, 2, 3}` |
| `frozenset` | 불변 | 순서 없음 | 중복 불가 | 불가능 | `frozenset({1, 2})` |

이 표에서 특히 기억해둘 만한 점 몇 가지가 있습니다.

- `list`와 `tuple`은 순서와 중복 허용 여부가 동일하지만, 가변성만 다릅니다. 값을 나중에 바꿀 필요가 없다면 `tuple`을 사용하는 편이 의도를 더 명확히 드러내고, 실수로 값이 바뀌는 것도 막아줍니다.
- `dict`의 키는 반드시 불변 객체여야 합니다(`str`, `int`, `tuple` 등은 가능하지만 `list`는 키로 쓸 수 없습니다). 이는 `set`의 원소에도 똑같이 적용됩니다.
- `set`과 `frozenset`은 순서가 없기 때문에 인덱스로 특정 원소에 접근할 수 없으며, 주로 원소의 존재 여부 확인이나 집합 연산(합집합, 교집합 등)에 사용합니다.
- 가변 객체(`list`, `dict`, `set`)를 함수의 기본값 인자로 사용하면 안 되는 이유, 그리고 가변 객체를 다른 변수에 대입했을 때 두 이름이 같은 객체를 가리키게 되는 현상은 3장 변수와 자료형, 9장 함수에서 다룬 내용을 참고하세요.

## 더 공부하려면: 참고할 자료 유형

이 책 한 권으로 Python 문법의 큰 줄기는 익혔지만, 실제로 프로그램을 만들다 보면 이 책에서 다루지 않은 기능이나 특정 라이브러리의 세부 사용법이 필요한 순간이 반드시 찾아옵니다. 그럴 때 어디에서, 어떤 종류의 자료를 찾아보면 좋을지 안내합니다.

### 공식 문서

가장 신뢰할 수 있는 출처는 Python 공식 문서입니다. 언어 자체의 문법 레퍼런스와 표준 라이브러리의 모든 모듈에 대한 설명이 담겨 있으며, 대부분의 설명에는 실행 가능한 예제가 함께 제공됩니다. 특정 함수나 메서드의 정확한 매개변수 이름, 기본값, 반환값이 궁금할 때는 검색 엔진에 "python 모듈이름 official docs"처럼 검색해서 공식 문서를 먼저 찾아보는 습관을 들이는 것이 좋습니다. 17장 표준 라이브러리와 패키지 관리에서 소개한 모듈들도 모두 공식 문서에 훨씬 상세한 설명이 나와 있습니다.

### PEP(Python Enhancement Proposal)

PEP는 Python 언어 자체의 변경 제안서입니다. 8장에서 언급했던 코드 스타일 규칙(PEP 8)처럼, 특정 문법이나 관례가 "왜 그렇게 정해졌는지" 배경을 이해하고 싶을 때 참고하면 좋습니다. 언어의 새로운 문법이 도입될 때도 먼저 PEP 형태로 제안되고 논의되므로, Python이 앞으로 어떤 방향으로 발전하는지 살펴보는 데도 유용합니다.

### 패키지 저장소와 그 문서

14장 모듈과 패키지, 17장 표준 라이브러리와 패키지 관리에서 다룬 것처럼, 표준 라이브러리에 없는 기능은 외부 패키지를 설치해서 사용합니다. Python 패키지들이 공개적으로 등록되는 저장소에서 패키지를 검색하면, 대부분 사용법과 예제가 함께 정리된 페이지를 찾을 수 있습니다. 새로운 패키지를 사용하기 전에는 이런 페이지에서 설치 방법과 기본 사용 예제를 먼저 확인하는 것이 좋습니다.

### 오류 메시지와 커뮤니티 질의응답

프로그램을 작성하다 마주치는 오류 메시지는 그 자체로 훌륭한 검색어입니다. 오류 메시지의 핵심 문구를 그대로 검색하면, 같은 문제를 겪었던 다른 개발자들의 질문과 답변을 찾을 수 있는 경우가 많습니다. 다만 검색 결과의 코드를 그대로 복사해서 붙여넣기보다는, 왜 그 오류가 발생했는지 11장 예외 처리에서 배운 내용을 바탕으로 원인을 이해하고 나서 적용하는 습관이 실력 향상에 훨씬 도움이 됩니다.

### 직접 실험하기

마지막으로, 어떤 문서보다 확실한 답을 주는 것은 직접 코드를 실행해보는 것입니다. 인터프리터를 열어 `help(객체)`나 `dir(객체)`를 입력해보면 해당 객체가 어떤 메서드와 속성을 가지고 있는지, 각 메서드에 대한 간단한 설명은 무엇인지 그 자리에서 바로 확인할 수 있습니다. 궁금한 코드가 있다면 일단 짧게 작성해서 실행해보고 결과를 눈으로 확인하는 습관이, 이 책을 다 읽은 이후에도 Python 실력을 꾸준히 늘려가는 가장 확실한 방법입니다.

```python
>>> help(str.split)
>>> dir(list)
```
