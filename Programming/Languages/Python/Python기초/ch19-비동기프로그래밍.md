## 들어가며

지금까지 작성한 코드는 모두 한 줄씩 순서대로 실행되고, 함수를 호출하면 그 함수가 끝날 때까지 다음 줄로
넘어가지 않는 방식이었습니다. 이런 방식을 동기(synchronous) 실행이라고 부릅니다. 대부분의 프로그램에는
이것으로 충분하지만, 네트워크 요청이나 파일 읽기처럼 "결과를 기다리는 시간"이 긴 작업을 여러 개 처리해야
할 때는 이야기가 달라집니다. 하나가 끝나기를 기다렸다가 다음 것을 시작하면, 전체 시간은 각 작업 시간의
합이 되어버립니다.

Python은 이런 상황을 위해 `asyncio`라는 표준 라이브러리와 `async`/`await` 문법을 제공합니다. 이 장에서는
비동기 코드가 왜 필요한지, 그리고 기본적인 사용법이 무엇인지 살펴봅니다.

## 동기 코드의 한계

세 개의 서로 다른 서버에 데이터를 요청하는 상황을 가정해 보겠습니다. 실제 네트워크 호출 대신
`time.sleep()`으로 대기 시간을 흉내 내겠습니다.

```python
import time


def fetch_data(name: str, delay: float) -> str:
    print(f"{name} 요청 시작")
    time.sleep(delay)  # 네트워크 응답을 기다리는 상황을 흉내 냄
    print(f"{name} 요청 완료")
    return f"{name}의 결과"


def main() -> None:
    start = time.perf_counter()
    fetch_data("서버 A", 1)
    fetch_data("서버 B", 1)
    fetch_data("서버 C", 1)
    elapsed = time.perf_counter() - start
    print(f"총 소요 시간: {elapsed:.1f}초")


main()
```

```text
서버 A 요청 시작
서버 A 요청 완료
서버 B 요청 시작
서버 B 요청 완료
서버 C 요청 시작
서버 C 요청 완료
총 소요 시간: 3.0초
```

세 요청은 서로 아무런 관련이 없는데도, 앞의 요청이 끝나야만 다음 요청이 시작됩니다. CPU는 `time.sleep()`이
끝나기를 그냥 기다리기만 할 뿐 아무 일도 하지 않는데, 이 시간을 낭비하고 있는 셈입니다.

## 코루틴과 async/await

`async def`로 정의한 함수를 코루틴(coroutine)이라고 부릅니다. 코루틴은 일반 함수와 비슷해 보이지만,
호출한다고 바로 실행되지 않는다는 결정적인 차이가 있습니다.

```python
>>> async def say_hello():
...     print("안녕하세요")
...
>>> say_hello()
<coroutine object say_hello at 0x000001F3C2B1A040>
```

`say_hello()`를 호출했지만 "안녕하세요"가 출력되지 않고, 코루틴 객체만 돌아왔습니다. 이는 9장에서 다룬
제너레이터 함수가 `yield`를 만나기 전까지는 실행되지 않는 것과 비슷한 원리로, 코루틴도 누군가 실제로
실행을 요청해야 비로소 동작합니다. 가장 간단한 실행 방법은 `asyncio.run()`입니다.

```python
import asyncio


async def say_hello():
    print("안녕하세요")


asyncio.run(say_hello())
```

코루틴 안에서 다른 코루틴이 끝나기를 기다릴 때는 `await`를 사용합니다.

```python
import asyncio


async def fetch_data(name: str, delay: float) -> str:
    print(f"{name} 요청 시작")
    await asyncio.sleep(delay)  # time.sleep과 달리 실행을 다른 코루틴에게 양보한다
    print(f"{name} 요청 완료")
    return f"{name}의 결과"


async def main() -> None:
    result = await fetch_data("서버 A", 1)
    print(result)


asyncio.run(main())
```

`time.sleep()`은 그 시간 동안 프로그램 전체를 완전히 멈추지만, `asyncio.sleep()`은 "이 코루틴은 잠시
쉴 테니 그동안 다른 코루틴을 실행해도 좋다"고 양보하는 지점이라는 점이 핵심입니다.

## 이벤트 루프

`asyncio.run()`을 호출하면 내부적으로 이벤트 루프(event loop)가 시작됩니다. 이벤트 루프는 여러 코루틴을
등록해 두고, 어떤 코루틴이 `await`로 실행을 양보하면 곧바로 다른 준비된 코루틴에게 차례를 넘겨주는
방식으로 동작합니다. 스레드를 여러 개 만드는 것이 아니라, 단일 스레드 안에서 "대기 시간이 생기면 다른
할 일을 먼저 처리한다"는 방식으로 동시성을 흉내 내는 것입니다.

## 여러 코루틴 동시에 실행하기: asyncio.gather

앞서 본 세 개의 요청을 이번에는 순서대로 기다리지 않고 동시에 시작해 보겠습니다.

```python
import asyncio
import time


async def fetch_data(name: str, delay: float) -> str:
    print(f"{name} 요청 시작")
    await asyncio.sleep(delay)
    print(f"{name} 요청 완료")
    return f"{name}의 결과"


async def main() -> None:
    start = time.perf_counter()
    results = await asyncio.gather(
        fetch_data("서버 A", 1),
        fetch_data("서버 B", 1),
        fetch_data("서버 C", 1),
    )
    elapsed = time.perf_counter() - start
    print(results)
    print(f"총 소요 시간: {elapsed:.1f}초")


asyncio.run(main())
```

```text
서버 A 요청 시작
서버 B 요청 시작
서버 C 요청 시작
서버 A 요청 완료
서버 B 요청 완료
서버 C 요청 완료
['서버 A의 결과', '서버 B의 결과', '서버 C의 결과']
총 소요 시간: 1.0초
```

세 요청이 거의 동시에 시작되고, 전체 시간은 각 시간의 합(3초)이 아니라 가장 오래 걸리는 하나(1초)에
가까워졌습니다. `asyncio.gather()`는 여러 코루틴을 한꺼번에 실행시키고, 모두 끝날 때까지 기다렸다가
결과를 리스트로 모아줍니다.

아래 다이어그램은 방금 본 동기 실행과 비동기 실행의 시간 흐름 차이를 보여줍니다.

```text
  동기 실행 (순차 처리)

  0초                                                          3초
  |----------------|----------------|----------------|
  |  서버 A (1초)   |  서버 B (1초)   |  서버 C (1초)   |         총 3.0초
  |----------------|----------------|----------------|

  비동기 실행 (asyncio.gather)

  0초              1초
  |----------------|
  |  서버 A (1초)   |
  |----------------|
  |  서버 B (1초)   |                                           총 1.0초
  |----------------|
  |  서버 C (1초)   |
  |----------------|
```

## 예외 처리는 그대로 동작한다

코루틴 안에서도 11장에서 배운 `try`/`except`를 그대로 사용할 수 있습니다. `await`가 걸린 지점에서
예외가 발생하면, 마치 일반 함수를 호출한 것처럼 그 지점에서 예외가 올라옵니다.

```python
import asyncio


async def risky_fetch() -> str:
    await asyncio.sleep(0.5)
    raise ValueError("서버 응답 없음")


async def main() -> None:
    try:
        await risky_fetch()
    except ValueError as e:
        print(f"오류 발생: {e}")


asyncio.run(main())
```

## 언제 비동기를 써야 하는가

비동기 프로그래밍이 모든 상황에서 빠른 것은 아닙니다. 핵심은 작업의 성격을 구분하는 것입니다.

- **I/O 바운드(I/O-bound) 작업**: 네트워크 요청, 파일 읽기/쓰기, 데이터베이스 조회처럼 CPU보다는
  "응답을 기다리는 시간"이 대부분을 차지하는 작업입니다. 이런 작업은 `asyncio`로 여러 개를 동시에
  진행시키면 전체 대기 시간을 크게 줄일 수 있습니다.
- **CPU 바운드(CPU-bound) 작업**: 대량의 숫자 계산처럼 CPU를 계속 사용하는 작업입니다. Python은 GIL
  (Global Interpreter Lock)이라는 장치 때문에 한 프로세스 안에서 여러 스레드가 동시에 순수 Python
  코드를 실행할 수 없습니다. `asyncio` 역시 결국 하나의 스레드에서 동작하므로 CPU 바운드 작업에는
  도움이 되지 않으며, 이런 경우에는 `multiprocessing`처럼 여러 프로세스를 사용하는 방식이 더 적합합니다.

즉, "기다리는 시간이 많은가, 계산하는 시간이 많은가"를 먼저 따져보고 `asyncio` 도입 여부를 결정하는 것이
좋습니다.

## 요약

- 동기 코드는 작업을 순서대로 처리하므로, 대기 시간이 긴 작업이 여러 개면 전체 시간이 그만큼 늘어난다.
- `async def`로 정의한 함수는 코루틴이며, 호출만 해서는 실행되지 않고 `await`나 `asyncio.run()` 등으로
  실행을 요청해야 한다.
- `await`는 "지금은 기다려야 하니 다른 코루틴에게 실행을 양보하겠다"는 지점을 표시한다.
- 이벤트 루프는 단일 스레드 안에서 여러 코루틴을 번갈아 실행시켜 동시성을 구현한다.
- `asyncio.gather()`로 여러 코루틴을 동시에 시작하고 모든 결과를 모아 받을 수 있다.
- 코루틴 안에서도 일반 함수와 동일하게 `try`/`except`로 예외를 처리할 수 있다.
- `asyncio`는 I/O 바운드 작업에 적합하며, CPU 바운드 작업에는 멀티프로세싱이 더 알맞다.

## 연습문제

1. `asyncio.sleep()`을 이용해 2초, 1초, 3초가 걸리는 세 개의 코루틴을 만들고, `asyncio.gather()`로
   동시에 실행했을 때 총 소요 시간이 얼마인지 실제로 측정해 확인해 보세요.
2. 위 문제의 코루틴들을 `asyncio.gather()` 없이 순서대로 `await`했을 때와 시간을 비교하는 코드를
   작성해 보세요.
3. 코루틴 안에서 조건에 따라 예외를 발생시키고, 이를 호출한 쪽에서 `try`/`except`로 처리하는 예제를
   작성해 보세요.
4. `asyncio.run()`을 호출하지 않고 코루틴 함수만 호출하면 어떤 값이 반환되는지 인터프리터에서 직접
   확인하고, 왜 그런 결과가 나오는지 설명해 보세요.
5. I/O 바운드 작업과 CPU 바운드 작업의 예를 각각 두 가지씩 들고, 어떤 처리 방식(비동기, 멀티스레딩,
   멀티프로세싱)이 적합할지 설명해 보세요.
