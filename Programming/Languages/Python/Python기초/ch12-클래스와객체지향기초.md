지금까지 우리는 숫자, 문자열, 리스트, 딕셔너리 같은 Python이 기본으로 제공하는 자료형과, 9장에서 배운 함수를 이용해 프로그램을 만들어 왔습니다. 함수는 "동작"을 하나로 묶어주지만, 그 동작이 다뤄야 할 "데이터"는 대개 함수 밖에서 별도의 변수나 딕셔너리로 관리해야 했습니다. 예를 들어 강아지 여러 마리의 정보를 다룬다면, 이름과 품종을 담은 딕셔너리를 리스트에 넣고, 강아지가 짖는 동작은 별도의 함수로 만들어 그 딕셔너리를 인자로 넘기는 식으로 작성하게 됩니다.

```python
dogs = [
    {"name": "초코", "breed": "진돗개"},
    {"name": "흰둥이", "breed": "말티즈"},
]


def bark(dog):
    return f"{dog['name']}가 짖습니다: 멍멍!"


print(bark(dogs[0]))  # 초코가 짖습니다: 멍멍!
```

이 방식도 틀리지는 않지만, 데이터(`dog` 딕셔너리)와 그 데이터를 다루는 동작(`bark` 함수)이 서로 떨어져 있어서, 강아지 종류가 늘어나고 동작이 많아질수록 어떤 함수가 어떤 데이터를 위한 것인지 관리하기 번거로워집니다. **클래스**(class)는 데이터와 그 데이터를 다루는 동작을 하나의 단위로 묶어주는 Python의 도구입니다. 이번 장에서는 클래스를 정의하는 기본 문법, 인스턴스를 만드는 과정, 인스턴스 변수와 클래스 변수의 차이, 메서드, 그리고 기존 클래스의 기능을 물려받는 상속의 기초까지 다룹니다. 매직 메서드나 프로퍼티, 다중 상속처럼 조금 더 깊은 주제는 13장 객체지향 심화에서 이어서 다룹니다.

## 클래스와 인스턴스

클래스를 이해하는 가장 쉬운 비유는 "설계도"입니다. 붕어빵 틀을 하나 만들어 두면, 그 틀로 붕어빵을 몇 개든 찍어낼 수 있습니다. 각 붕어빵은 같은 틀에서 나왔으므로 모양(구조)은 똑같지만, 안에 들어가는 팥의 양이나 굽기 정도는 저마다 다를 수 있습니다.

클래스가 바로 이 "틀"에 해당합니다. 클래스는 어떤 종류의 데이터를 가지고 어떤 동작을 할 수 있는지에 대한 설계도일 뿐, 그 자체로는 실제 데이터를 담고 있지 않습니다. 이 설계도로부터 실제로 만들어진 것을 **인스턴스**(instance) 또는 **객체**(object)라고 부릅니다. 하나의 클래스로부터 여러 개의 인스턴스를 만들 수 있으며, 각 인스턴스는 클래스가 정의한 구조는 공유하지만 실제 데이터 값은 서로 다를 수 있습니다.

다음 그림은 `Dog`라는 클래스(설계도)와, 그로부터 만들어진 두 개의 인스턴스(`my_dog`, `your_dog`)의 관계를 보여줍니다.

```text
                  클래스(설계도)와 인스턴스(객체)의 관계

  +---------------------------+                +----------------------------------------+
  |       클래스 Dog           |                |    인스턴스 (객체) : my_dog              |
  |     (설계도, blueprint)     |                |----------------------------------------|
  |----------------------------|   Dog(...)     | name = "초코"                           |
  | 속성 (정의만 있음)           | 인스턴스 생성   | breed = "진돗개"                        |
  | - name                     | -------------> | my_dog.bark() -> "초코가 짖습니다: 멍멍!" |
  | - breed                    |       |        +----------------------------------------+
  |----------------------------|       |
  | 메서드                      |       |        +----------------------------------------+
  | - __init__(self, name,    |       |        |   인스턴스 (객체) : your_dog             |
  |   breed)                   |       |        |----------------------------------------|
  | - bark(self)               |       +------> | name = "흰둥이"                         |
  |----------------------------|                | breed = "말티즈"                        |
  | 실제 값은 없고,              |                | your_dog.bark() -> "흰둥이가 짖습니다:   |
  | 구조와 동작만 정의            |                |   멍멍!"                                |
  +---------------------------+                +----------------------------------------+

  핵심 개념
  - 클래스는 하나뿐이지만, 그 클래스로부터 만들어지는 인스턴스는 여러 개가 될 수 있습니다.
  - 각 인스턴스는 같은 구조(속성, 메서드)를 공유하지만, 실제 데이터(name, breed 값)는 서로 다릅니다.
  - my_dog와 your_dog는 모두 Dog 클래스의 인스턴스이므로, type(my_dog) == Dog 는 True 입니다.
  - 클래스는 붕어빵 틀, 인스턴스는 그 틀로 찍어낸 붕어빵 하나하나에 비유할 수 있습니다.
```

그림에서 볼 수 있듯이 `Dog` 클래스는 `name`, `breed`라는 속성과 `bark`라는 메서드가 "어떤 형태여야 하는지"만 정의하고 있을 뿐, 실제 이름이나 품종 값은 갖고 있지 않습니다. 반면 `my_dog`와 `your_dog`는 `Dog` 클래스가 정의한 구조를 그대로 따르면서도, 각자 `"초코"`/`"진돗개"`, `"흰둥이"`/`"말티즈"`라는 서로 다른 실제 값을 가지고 있습니다.

## `class` 키워드로 클래스 정의하기

클래스는 `class` 키워드로 정의합니다. 가장 단순한 형태는 다음과 같습니다.

```python
class Dog:
    pass


my_dog = Dog()
print(type(my_dog))  # <class '__main__.Dog'>
```

`class Dog:` 뒤에 들여쓰기된 블록이 클래스의 본문이 됩니다. 지금은 아무 내용도 없으므로 `pass`로 빈 블록임을 표시했습니다. `Dog()`처럼 클래스 이름 뒤에 괄호를 붙여 호출하면 그 클래스의 인스턴스가 하나 만들어집니다. 함수 이름을 짓는 규칙(snake_case)과 달리, 클래스 이름은 관례적으로 각 단어의 첫 글자를 대문자로 쓰는 **PascalCase**를 사용합니다.

이 상태의 `Dog`는 이름만 있을 뿐 어떤 데이터도, 어떤 동작도 갖고 있지 않습니다. 실제로 쓸모 있는 클래스를 만들려면 인스턴스가 생성될 때 필요한 데이터를 채워 넣는 절차와, 그 데이터를 활용하는 동작(메서드)을 정의해야 합니다.

## `__init__` 생성자와 `self`

인스턴스가 만들어지는 순간에 자동으로 실행되어 초기 데이터를 설정해주는 특수한 메서드가 `__init__`입니다. 이런 역할을 하는 메서드를 **생성자**(constructor)라고 부릅니다. `Dog(...)`처럼 클래스를 호출하면, Python은 새 인스턴스를 하나 만들고 그 인스턴스의 `__init__` 메서드를 자동으로 호출합니다.

```python
class Dog:
    """개 한 마리를 표현하는 클래스"""

    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

    def bark(self):
        return f"{self.name}가 짖습니다: 멍멍!"
```

```python
>>> my_dog = Dog("초코", "진돗개")
>>> your_dog = Dog("흰둥이", "말티즈")
>>> my_dog.name
'초코'
>>> your_dog.breed
'말티즈'
>>> my_dog.bark()
'초코가 짖습니다: 멍멍!'
>>> your_dog.bark()
'흰둥이가 짖습니다: 멍멍!'
```

`__init__`과 `bark` 모두 첫 번째 매개변수로 `self`를 받고 있습니다. `self`는 "이 메서드가 호출되고 있는 바로 그 인스턴스 자신"을 가리킵니다. `my_dog.bark()`처럼 인스턴스를 통해 메서드를 호출하면, Python은 내부적으로 `my_dog`를 `self` 자리에 자동으로 채워 넣어 `Dog.bark(my_dog)`를 실행하는 것과 동일하게 동작합니다. 실제로 클래스 이름을 통해 직접 호출하면서 인스턴스를 명시적으로 넘겨도 똑같은 결과를 얻을 수 있습니다.

```python
>>> Dog.bark(my_dog)
'초코가 짖습니다: 멍멍!'
```

`self.name = name`이라는 코드는 "지금 만들어지고 있는 이 인스턴스에, `name`이라는 이름의 속성으로 매개변수 `name`의 값을 저장하라"는 뜻입니다. `self.name`처럼 `self.`을 앞에 붙여 저장한 값이라야 `my_dog.name`처럼 인스턴스를 통해 나중에 꺼내 쓸 수 있습니다. 만약 `self.`을 붙이지 않고 그냥 `name = name`이라고만 썼다면, 이는 `__init__` 함수 안에서만 잠깐 쓰이고 사라지는 지역 변수(9장 참고)가 되어, 함수가 끝나는 즉시 사라져 버립니다.

`self`라는 이름 자체는 문법적으로 정해진 키워드가 아니라 관례입니다. 다른 이름을 사용해도 문법 오류는 나지 않지만, 거의 모든 Python 코드가 `self`라는 이름을 사용하므로 이 관례를 따르는 것이 좋습니다. 중요한 것은 이름이 아니라 위치입니다. 클래스 안에서 정의하는 일반 메서드는 항상 첫 번째 매개변수로 자기 자신의 인스턴스를 받는다는 규칙입니다.

## 인스턴스 변수와 클래스 변수

`self.name`, `self.breed`처럼 각 인스턴스마다 따로 저장되는 값을 **인스턴스 변수**(instance variable)라고 합니다. `my_dog`의 `name`을 바꾸어도 `your_dog`의 `name`에는 아무 영향이 없습니다. 이와 달리 모든 인스턴스가 공통으로 공유하는 값을 클래스 본문에 직접 정의할 수도 있는데, 이를 **클래스 변수**(class variable)라고 합니다.

```python
class Dog:
    species = "개"  # 클래스 변수: 모든 인스턴스가 공유하는 값
    population = 0  # 지금까지 생성된 Dog 인스턴스 수를 세는 클래스 변수

    def __init__(self, name, breed):
        self.name = name  # 인스턴스 변수
        self.breed = breed  # 인스턴스 변수
        Dog.population += 1  # 클래스 변수는 클래스 이름을 통해 갱신한다

    def bark(self):
        return f"{self.name}가 짖습니다: 멍멍!"
```

```python
>>> a = Dog("초코", "진돗개")
>>> b = Dog("흰둥이", "말티즈")
>>> a.species
'개'
>>> b.species
'개'
>>> a.name
'초코'
>>> b.name
'흰둥이'
>>> Dog.population
2
```

`species`는 `Dog` 클래스 본문에 바로 적혀 있으므로, `Dog`로부터 만들어지는 모든 인스턴스가 이 값을 공유합니다. `a.species`와 `b.species`는 서로 다른 인스턴스에서 조회했지만 같은 값 `'개'`를 돌려주는데, 이는 두 인스턴스가 각자 `species`라는 인스턴스 변수를 따로 가지고 있어서가 아니라, 인스턴스에서 `species`를 찾지 못하면 Python이 클래스 쪽에 정의된 `species`를 대신 찾아주기 때문입니다.

`population`은 `Dog` 인스턴스가 몇 개 만들어졌는지 추적하는 용도로 사용했습니다. `__init__` 안에서 `Dog.population += 1`처럼 **클래스 이름을 통해** 값을 갱신한 점에 주목하세요. 만약 실수로 `self.population += 1`이라고 썼다면, 이는 클래스 변수를 변경하는 것이 아니라 그 인스턴스에만 해당하는 새로운 인스턴스 변수 `population`을 만들어버립니다. 이는 9장에서 함수 안에서 전역 변수에 값을 대입하면 새로운 지역 변수가 만들어지던 것과 비슷한 함정이니 주의해야 합니다.

```python
>>> a = Dog("초코", "진돗개")
>>> a.population = 100  # 이는 클래스 변수를 바꾸는 것이 아니라, a에만 있는 새 인스턴스 변수를 만드는 것
>>> a.population
100
>>> Dog.population  # 클래스 변수는 그대로다
1
>>> b = Dog("흰둥이", "말티즈")
>>> b.population  # b는 a와 무관하게 여전히 클래스 변수를 그대로 본다
2
```

일반적인 규칙은 이렇습니다. 인스턴스마다 값이 달라야 한다면 `__init__`에서 `self.속성 = 값`으로 인스턴스 변수를 만들고, 모든 인스턴스가 같은 값을 공유해야 한다면 클래스 본문에 직접 클래스 변수를 정의합니다.

## 메서드 정의와 호출

클래스 본문 안에 정의된 함수를 **메서드**(method)라고 부릅니다. 지금까지 본 `bark`처럼, 첫 번째 매개변수로 `self`를 받아 그 인스턴스의 데이터를 읽거나 바꾸는 메서드를 **인스턴스 메서드**라고 합니다. 실무에서 작성하는 메서드의 대부분은 인스턴스 메서드입니다.

인스턴스 변수를 여러 개 다루는 조금 더 실용적인 예로, 계좌 하나를 표현하는 `BankAccount` 클래스를 만들어보겠습니다.

```python
class BankAccount:
    """은행 계좌 하나를 표현하는 클래스"""

    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        """계좌에 amount만큼 입금한다"""
        self.balance += amount

    def withdraw(self, amount):
        """계좌에서 amount만큼 출금한다"""
        if amount > self.balance:
            raise ValueError("잔액이 부족합니다.")
        self.balance -= amount
```

```python
>>> account = BankAccount("김철수", 10000)
>>> account.deposit(5000)
>>> account.balance
15000
>>> account.withdraw(3000)
>>> account.balance
12000
>>> account.withdraw(999999)
Traceback (most recent call last):
  ...
ValueError: 잔액이 부족합니다.
```

`__init__`은 `owner`(필수)와 `balance`(기본값 0, 9장에서 배운 기본값 인자와 같은 문법)를 받아 인스턴스 변수로 저장합니다. `deposit`과 `withdraw`는 각각 `self.balance`를 읽고 수정하는 평범한 메서드입니다. `withdraw`에서 잔액이 부족한 상황을 `ValueError` 예외로 알리는 방식은 11장 예외 처리에서 배운 내용을 그대로 활용한 것입니다. 이렇게 클래스 하나에 데이터(`owner`, `balance`)와 그 데이터를 다루는 동작(`deposit`, `withdraw`)을 함께 묶어두면, 이 계좌와 관련된 코드를 어디서 찾아야 할지 헷갈릴 일이 없습니다.

한 가지 짚고 넘어갈 점은, 지금 `account.balance`는 외부에서 얼마든지 직접 읽고 바꿀 수 있는 완전히 공개된 속성이라는 것입니다. `account.balance = -999999`처럼 대입해버리면 `deposit`, `withdraw`의 검증 로직을 그대로 우회할 수 있습니다. Python에는 다른 언어의 `private` 같은 진짜 접근 차단 키워드가 없습니다. 대신 `_balance`처럼 이름 앞에 밑줄 하나를 붙여 "이 속성은 클래스 내부용이니 되도록 직접 건드리지 말아 달라"는 관례적인 신호를 주는 정도가 전부입니다. 이 문제를 Python다운 방식으로 제대로 통제하는 방법(`@property`)은 13장 객체지향 심화에서 자세히 다룹니다.

## 상속: 기존 클래스 확장하기

여러 클래스를 만들다 보면 서로 겹치는 부분이 생기기 마련입니다. 예를 들어 개, 고양이, 새 모두 "이름을 가지고 있고, 먹이를 먹는다"는 공통점이 있지만 "소리를 내는 방식"은 저마다 다릅니다. 이럴 때 공통 기능을 담은 클래스를 하나 만들고, 각 동물별 클래스가 그 공통 기능을 물려받도록 하면 코드 중복을 줄일 수 있습니다. 이렇게 기존 클래스의 속성과 메서드를 물려받아 새로운 클래스를 만드는 것을 **상속**(inheritance)이라고 합니다. 물려주는 쪽을 **부모 클래스**(parent class, 또는 기반 클래스/베이스 클래스), 물려받는 쪽을 **자식 클래스**(child class, 또는 파생 클래스)라고 부릅니다.

```python
class Animal:
    """모든 동물이 공통으로 갖는 기능을 담은 클래스"""

    def __init__(self, name):
        self.name = name

    def eat(self):
        return f"{self.name}가 먹이를 먹습니다."

    def make_sound(self):
        return f"{self.name}가 소리를 냅니다."


class Dog(Animal):
    """Animal을 상속받는 개 클래스"""

    def __init__(self, name, breed):
        super().__init__(name)  # 부모 클래스(Animal)의 __init__을 그대로 활용
        self.breed = breed

    def make_sound(self):  # 부모의 메서드를 자신에게 맞게 재정의(오버라이딩)
        return f"{self.name}가 짖습니다: 멍멍!"
```

```python
>>> my_dog = Dog("초코", "진돗개")
>>> my_dog.eat()  # Animal로부터 물려받은 메서드
'초코가 먹이를 먹습니다.'
>>> my_dog.make_sound()  # Dog가 새로 정의한 메서드
'초코가 짖습니다: 멍멍!'
```

`class Dog(Animal):`처럼 클래스 이름 뒤 괄호 안에 부모 클래스를 적으면 상속 관계가 만들어집니다. `Dog`는 `eat` 메서드를 따로 정의하지 않았지만, `Animal`을 상속받았기 때문에 `my_dog.eat()`을 문제없이 호출할 수 있습니다.

`Dog.__init__` 안에서 사용한 `super()`는 "부모 클래스"를 가리키는 함수입니다. `super().__init__(name)`은 "부모 클래스인 `Animal`의 `__init__`을 호출해서, `name`을 저장하는 작업을 그대로 맡긴다"는 뜻입니다. 만약 이 줄이 없었다면 `self.name`을 설정하는 코드를 `Dog`의 `__init__` 안에 다시 작성해야 했을 것입니다. `super()`를 사용하면 부모 클래스가 이미 잘 만들어둔 초기화 로직을 그대로 재사용하면서, 자식 클래스에서 필요한 부분(`self.breed = breed`)만 추가로 작성할 수 있습니다.

`make_sound`는 `Animal`에도 있고 `Dog`에도 있습니다. 이렇게 자식 클래스가 부모 클래스와 같은 이름의 메서드를 다시 정의해서 동작을 바꾸는 것을 **메서드 오버라이딩**(overriding)이라고 합니다. `my_dog.make_sound()`를 호출하면 Python은 먼저 `Dog` 클래스에 `make_sound`가 있는지 찾아보고, 있으면 그것을 사용합니다. `Animal`의 `make_sound`는 `Dog`에 같은 이름의 메서드가 없을 때만 대신 사용됩니다. 여러 부모로부터 동시에 상속받는 다중 상속 상황에서 이 "검색 순서"가 어떻게 정해지는지는 13장에서 MRO(메서드 결정 순서)라는 이름으로 자세히 다룹니다.

### `isinstance`와 `issubclass`로 관계 확인하기

어떤 인스턴스가 특정 클래스(또는 그 클래스를 상속받은 자식 클래스)의 인스턴스인지는 `isinstance()` 함수로 확인할 수 있습니다.

```python
>>> isinstance(my_dog, Dog)
True
>>> isinstance(my_dog, Animal)
True
>>> isinstance(my_dog, str)
False
>>> issubclass(Dog, Animal)
True
>>> issubclass(Animal, Dog)
False
```

`my_dog`는 `Dog`의 인스턴스이면서 동시에 `Animal`의 인스턴스이기도 합니다. 상속 관계에서는 "자식 클래스의 인스턴스는 부모 클래스의 인스턴스이기도 하다"는 것이 항상 성립하기 때문입니다. `issubclass(자식, 부모)`는 인스턴스가 아니라 클래스 자체끼리의 상속 관계를 확인할 때 사용합니다.

## 클래스 메서드와 정적 메서드 살짝 맛보기

지금까지 본 메서드는 모두 `self`를 받아 인스턴스의 데이터를 다루는 인스턴스 메서드였습니다. Python은 이 외에도 두 가지 특별한 메서드를 `@classmethod`, `@staticmethod`라는 표시(데코레이터)를 붙여 만들 수 있게 해줍니다. 데코레이터가 정확히 어떤 원리로 동작하는지는 16장 데코레이터와 컨텍스트 매니저에서 다루므로, 여기서는 "이런 것이 있다" 정도로만 짚고 넘어가겠습니다.

`@classmethod`는 `self` 대신 클래스 자신을 받는 메서드로, 주로 인스턴스를 만드는 또 다른 방법(대체 생성자)을 제공할 때 사용합니다.

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    @classmethod
    def open_with_bonus(cls, owner):
        """신규 계좌 개설 시 5,000원의 가입 축하금을 넣어준다"""
        return cls(owner, balance=5000)
```

```python
>>> account = BankAccount.open_with_bonus("김철수")
>>> account.balance
5000
```

`@staticmethod`는 `self`도 `cls`도 받지 않는, 사실상 클래스 안에 넣어둔 평범한 함수입니다. 그 클래스와 개념적으로 관련은 있지만 인스턴스나 클래스 자체의 데이터가 굳이 필요 없는 보조 기능을 담을 때 사용합니다.

```python
class BankAccount:
    # ... 생략 ...

    @staticmethod
    def is_valid_amount(amount):
        """입출금 금액으로 유효한지(0보다 큰지) 검사한다"""
        return amount > 0
```

```python
>>> BankAccount.is_valid_amount(1000)
True
>>> BankAccount.is_valid_amount(-500)
False
```

두 가지 모두 실무에서 자주 쓰이는 도구이지만, 처음 클래스를 설계할 때부터 반드시 사용해야 하는 것은 아닙니다. 대부분의 경우 인스턴스 메서드만으로 충분하며, "인스턴스를 만드는 새로운 방법이 필요하다" 또는 "이 클래스와 관련은 있지만 인스턴스 데이터는 필요 없는 함수다"라는 필요가 생겼을 때 선택적으로 도입하면 됩니다.

## 요약

- **클래스**는 데이터와 그 데이터를 다루는 동작을 하나로 묶는 설계도이고, **인스턴스**(객체)는 그 설계도로부터 실제로 만들어진 결과물이다. 하나의 클래스로부터 여러 인스턴스를 만들 수 있다.
- `class` 키워드로 클래스를 정의하며, 클래스 이름은 관례적으로 PascalCase를 사용한다. `__init__`은 인스턴스가 생성될 때 자동으로 호출되는 생성자로, 여기서 인스턴스 변수를 초기화한다.
- `self`는 메서드가 호출된 대상 인스턴스 자신을 가리키며, 인스턴스 메서드의 첫 번째 매개변수로 항상 등장한다. `instance.method()` 호출은 내부적으로 `Class.method(instance)`와 같다.
- **인스턴스 변수**(`self.속성`)는 각 인스턴스마다 따로 저장되고, **클래스 변수**(클래스 본문에 직접 정의)는 모든 인스턴스가 공유한다. 클래스 변수를 갱신할 때는 클래스 이름을 통해 접근해야 실수로 새 인스턴스 변수를 만드는 것을 피할 수 있다.
- **상속**을 사용하면 `class 자식클래스(부모클래스):` 형태로 기존 클래스의 속성과 메서드를 물려받을 수 있다. `super()`로 부모 클래스의 메서드(특히 `__init__`)를 재사용할 수 있고, 자식 클래스에서 같은 이름의 메서드를 다시 정의하면 부모의 동작을 오버라이딩할 수 있다.
- Python에는 진짜 `private` 키워드가 없으며, `_속성`처럼 밑줄을 붙이는 것은 관례일 뿐이다. 속성에 대한 접근을 실제로 통제하는 방법은 13장의 `@property`에서 다룬다.
