프로그램은 항상 예상한 대로만 흘러가지 않습니다. 사용자가 숫자를 넣어야 할 자리에 문자를 입력하거나, 존재하지 않는 파일을 열려고 하거나, 리스트의 범위를 벗어난 인덱스에 접근하는 일은 실무에서 흔히 벌어집니다. 이런 상황에서 프로그램이 아무 대비 없이 멈춰버리면 사용자 경험도 나빠지고, 디버깅도 어려워집니다.

Python은 이런 오류 상황을 **예외(exception)**라는 객체로 표현하고, 이를 감지하고 처리할 수 있는 문법을 제공합니다. 이 장에서는 예외가 무엇인지, 어떻게 잡아내고 대응하는지, 그리고 직접 예외를 만들어 사용하는 방법까지 살펴봅니다.

## 예외란 무엇인가

먼저 예외가 발생하는 상황을 직접 만들어 보겠습니다.

```python
>>> 10 / 0
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ZeroDivisionError: division by zero
```

`10 / 0`을 실행하면 Python은 `ZeroDivisionError`라는 예외를 발생시키고, 프로그램(또는 인터프리터 세션)은 이 지점에서 실행을 멈춥니다. 이렇게 실행 중에 감지된 오류를 알리기 위해 발생하는 것이 예외입니다.

몇 가지 예외 상황을 더 살펴보겠습니다.

```python
>>> int("abc")
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: invalid literal for int() with base 10: 'abc'

>>> numbers = [1, 2, 3]
>>> numbers[10]
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
IndexError: list index out of range

>>> data = {"name": "홍길동"}
>>> data["age"]
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
KeyError: 'age'
```

각 상황마다 서로 다른 이름의 예외가 발생한다는 점에 주목하세요. `ValueError`, `IndexError`, `KeyError`처럼 예외에는 상황을 설명하는 구체적인 이름이 붙어 있습니다. 이 이름들은 모두 클래스입니다. 예외가 클래스라는 사실은 12장 "클래스와 객체지향 기초"를 배우고 나면 더 명확하게 이해할 수 있는데, 실제로 Python의 모든 예외는 `BaseException`을 최상위로 하는 클래스 계층 구조를 이루고 있습니다. 대부분의 예외는 그중에서도 `Exception` 클래스를 상속받아 만들어집니다.

이 계층 구조 중 자주 마주치는 일부를 정리하면 다음과 같습니다.

```
BaseException
 └── Exception
      ├── ArithmeticError
      │    └── ZeroDivisionError
      ├── LookupError
      │    ├── IndexError
      │    └── KeyError
      ├── ValueError
      ├── TypeError
      ├── AttributeError
      ├── FileNotFoundError (OSError의 하위)
      └── ...
```

## try/except: 예외를 잡아내기

예외가 발생해도 프로그램이 멈추지 않도록 하려면 `try`와 `except`를 사용합니다.

```python
>>> try:
...     result = 10 / 0
... except ZeroDivisionError:
...     print("0으로 나눌 수 없습니다.")
...
0으로 나눌 수 없습니다.
```

동작 방식은 다음과 같습니다.

1. `try` 블록 안의 코드를 실행합니다.
2. 예외가 발생하지 않으면 `except` 블록은 건너뛰고 계속 진행합니다.
3. 예외가 발생하면 즉시 `try` 블록의 나머지 코드를 건너뛰고, 발생한 예외의 타입과 일치하는 `except` 블록을 찾아 실행합니다.
4. 일치하는 `except` 블록이 없으면 예외는 처리되지 않은 채로 상위로 전파됩니다.

간단한 함수로 확인해 보겠습니다.

```python
def safe_divide(a, b):
    """a를 b로 나눈 결과를 반환한다. 0으로 나누면 None을 반환한다."""
    try:
        return a / b
    except ZeroDivisionError:
        print(f"{a} / {b} 는 계산할 수 없습니다.")
        return None
```

```python
>>> safe_divide(10, 2)
5.0
>>> safe_divide(10, 0)
10 / 0 는 계산할 수 없습니다.
```

### 여러 예외 타입 처리하기

하나의 `try` 블록에서 여러 종류의 예외가 발생할 수 있다면, `except`를 여러 번 작성하면 됩니다.

```python
def parse_and_divide(a_text, b_text):
    """문자열 두 개를 정수로 바꾼 뒤 나눈 값을 반환한다."""
    try:
        a = int(a_text)
        b = int(b_text)
        return a / b
    except ValueError:
        print("숫자로 변환할 수 없는 입력입니다.")
    except ZeroDivisionError:
        print("0으로는 나눌 수 없습니다.")
```

```python
>>> parse_and_divide("10", "2")
5.0
>>> parse_and_divide("열", "2")
숫자로 변환할 수 없는 입력입니다.
>>> parse_and_divide("10", "0")
0으로는 나눌 수 없습니다.
```

여러 예외를 같은 방식으로 처리해도 된다면, 튜플로 묶어서 하나의 `except`에 지정할 수 있습니다.

```python
def parse_and_divide_v2(a_text, b_text):
    try:
        a = int(a_text)
        b = int(b_text)
        return a / b
    except (ValueError, ZeroDivisionError) as e:
        print(f"계산할 수 없습니다: {e}")
```

```python
>>> parse_and_divide_v2("열", "2")
계산할 수 없습니다: invalid literal for int() with base 10: '열'
>>> parse_and_divide_v2("10", "0")
계산할 수 없습니다: division by zero
```

### 예외 객체에서 정보 꺼내기: as e

`except ExceptionType as e`처럼 작성하면 발생한 예외 객체를 `e`라는 이름의 변수로 받을 수 있습니다. 이 객체는 예외에 대한 부가 정보를 담고 있습니다.

```python
>>> try:
...     numbers = [1, 2, 3]
...     print(numbers[10])
... except IndexError as e:
...     print("예외 타입:", type(e))
...     print("예외 메시지:", e)
...     print("args 속성:", e.args)
...
예외 타입: <class 'IndexError'>
예외 메시지: list index out of range
예외 메시지: ('list index out of range',)
```

`e`를 `print()`로 출력하면 사람이 읽기 좋은 오류 메시지가 나오고, `e.args`를 확인하면 예외 생성 시 전달된 원본 인자들을 튜플로 볼 수 있습니다. 로그를 남기거나 사용자에게 구체적인 안내 메시지를 보여줄 때 유용합니다.

```python
def read_config_value(config, key):
    try:
        return config[key]
    except KeyError as e:
        print(f"설정 키 {e}를 찾을 수 없습니다. 기본값을 사용합니다.")
        return None
```

```python
>>> settings = {"language": "ko"}
>>> read_config_value(settings, "timeout")
설정 키 'timeout'를 찾을 수 없습니다. 기본값을 사용합니다.
```

### 모든 예외를 잡아내는 except (주의해서 사용)

`except:`만 단독으로 쓰거나 `except Exception:`으로 쓰면 대부분의 예외를 포괄적으로 잡아낼 수 있습니다. 하지만 이렇게 하면 예상하지 못한 버그(예: 오타로 인한 `NameError`)까지 조용히 삼켜버려서 디버깅이 매우 어려워집니다.

```python
# 좋지 않은 예: 모든 예외를 뭉뚱그려 숨긴다
try:
    process_data()
except Exception:
    pass  # 무슨 문제가 생겼는지 전혀 알 수 없다
```

가능하면 예상되는 구체적인 예외 타입을 명시하는 것이 좋습니다. 정말 포괄적으로 처리해야 하는 경우(예: 프로그램 최상위에서 로그를 남기고 종료하는 경우)라도, 최소한 예외 정보를 기록해야 합니다.

```python
import logging

try:
    process_data()
except Exception as e:
    logging.error("예상치 못한 오류 발생: %s", e)
    raise  # 로그를 남긴 뒤 다시 예외를 전파한다
```

## else와 finally

`try` 문에는 `except` 외에도 `else`와 `finally` 절을 추가할 수 있습니다.

- `else`: `try` 블록이 예외 없이 성공적으로 끝났을 때만 실행됩니다.
- `finally`: 예외 발생 여부와 관계없이 항상 실행됩니다.

```python
def load_score(text):
    try:
        score = int(text)
    except ValueError:
        print("점수는 숫자여야 합니다.")
    else:
        print(f"점수 {score}를 정상적으로 읽었습니다.")
        return score
    finally:
        print("점수 읽기 시도를 마쳤습니다.")
```

```python
>>> load_score("95")
점수 95를 정상적으로 읽었습니다.
점수 읽기 시도를 마쳤습니다.
95
>>> load_score("구십오")
점수는 숫자여야 합니다.
점수 읽기 시도를 마쳤습니다.
```

`else`를 사용하면 "예외를 처리하는 코드"와 "성공했을 때만 실행할 코드"를 명확히 구분할 수 있습니다. 굳이 `else` 없이 `try` 블록 안에 이어서 써도 동작은 비슷하지만, `else`를 쓰면 `try` 블록 안에는 예외가 발생할 가능성이 있는 코드만 남기고, 성공 이후의 로직은 분리할 수 있어 가독성이 좋아집니다.

`finally`는 파일이나 네트워크 연결처럼 반드시 정리(clean-up)해야 하는 자원이 있을 때 특히 유용합니다.

```python
def read_first_line(filename):
    file = open(filename, encoding="utf-8")
    try:
        return file.readline()
    finally:
        file.close()  # 예외가 발생하든 안 하든 파일은 반드시 닫는다
```

다만 파일이나 네트워크 자원을 다룰 때는 `finally`를 직접 쓰는 대신 `with` 문(컨텍스트 매니저)을 사용하는 것이 더 Python다운 방식입니다. 이 내용은 15장 "파일 입출력"과 16장 "데코레이터와 컨텍스트 매니저"에서 자세히 다룹니다.

지금까지의 흐름을 정리하면 다음과 같습니다.

```python
try:
    # 예외가 발생할 수 있는 코드
    risky_operation()
except SomeError as e:
    # SomeError가 발생했을 때 처리
    handle_error(e)
else:
    # 예외가 전혀 발생하지 않았을 때만 실행
    handle_success()
finally:
    # 예외 발생 여부와 관계없이 항상 실행
    cleanup()
```

## raise: 예외를 직접 발생시키기

지금까지는 Python이 자동으로 발생시키는 예외를 처리하는 방법을 봤습니다. 이번에는 반대로, 우리가 직접 예외를 발생시키는 방법을 살펴보겠습니다. 함수를 만들다 보면 "이 상황은 호출한 쪽에서 잘못 사용한 것"이라고 명확히 알려야 할 때가 있습니다. 이럴 때 `raise` 문을 사용합니다.

```python
def set_age(age):
    """나이를 설정한다. 음수는 허용하지 않는다."""
    if age < 0:
        raise ValueError("나이는 음수가 될 수 없습니다.")
    print(f"나이가 {age}살로 설정되었습니다.")
```

```python
>>> set_age(25)
나이가 25살로 설정되었습니다.
>>> set_age(-5)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 4, in set_age
ValueError: 나이는 음수가 될 수 없습니다.
```

`raise`로 발생시킨 예외도 `try/except`로 잡을 수 있습니다.

```python
>>> try:
...     set_age(-5)
... except ValueError as e:
...     print("입력값 오류:", e)
...
입력값 오류: 나이는 음수가 될 수 없습니다.
```

### 예외 다시 던지기

`except` 블록 안에서 `raise`만 단독으로 쓰면, 방금 잡은 예외를 그대로 다시 발생시킬 수 있습니다. 로그만 남기고 상위 코드에는 문제를 계속 알리고 싶을 때 사용합니다.

```python
def load_settings(path):
    try:
        with open(path, encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        print(f"설정 파일 {path}이 없습니다. 관리자에게 문의하세요.")
        raise  # 예외를 처리했지만, 호출한 쪽에도 실패 사실을 알린다
```

### 예외 원인 연결하기: raise ... from ...

한 예외를 처리하다가 새로운 예외를 발생시켜야 할 때는 `from`을 사용해 두 예외의 인과 관계를 명시할 수 있습니다.

```python
def get_user_age(user_data):
    try:
        return int(user_data["age"])
    except KeyError as original_error:
        raise ValueError("age 필드가 없습니다.") from original_error
```

```python
>>> get_user_age({"name": "홍길동"})
Traceback (most recent call last):
  ...
KeyError: 'age'

The above exception was the direct cause of the following exception:

Traceback (most recent call last):
  ...
ValueError: age 필드가 없습니다.
```

이렇게 하면 최종적으로 보이는 오류뿐 아니라, 그 오류의 근본 원인이 된 예외까지 함께 확인할 수 있어 디버깅에 도움이 됩니다.

## 커스텀 예외 클래스 만들기

Python이 기본으로 제공하는 예외만으로는 우리 프로그램의 상황을 정확히 표현하기 어려울 때가 있습니다. 예를 들어 "재고가 부족하다"는 상황은 `ValueError`로 표현할 수도 있지만, 프로그램의 의도를 더 명확히 드러내려면 우리만의 예외 클래스를 만드는 것이 좋습니다. 방법은 간단합니다. `Exception`을 상속받는 클래스를 정의하면 됩니다.

```python
class OutOfStockError(Exception):
    """재고가 부족할 때 발생시키는 예외."""
    pass
```

```python
>>> def order(item, requested, stock):
...     if requested > stock:
...         raise OutOfStockError(f"{item} 재고가 부족합니다. (재고: {stock}, 요청: {requested})")
...     print(f"{item} {requested}개를 주문했습니다.")
...
>>> order("공책", 3, 10)
공책 3개를 주문했습니다.
>>> order("공책", 20, 10)
Traceback (most recent call last):
  ...
OutOfStockError: 공책 재고가 부족합니다. (재고: 10, 요청: 20)
```

커스텀 예외도 일반 클래스이므로, `__init__`을 직접 정의해서 필요한 정보를 속성으로 저장할 수 있습니다. 클래스 정의에 대한 자세한 내용은 12장에서 다루지만, 지금 수준에서도 다음과 같은 패턴은 충분히 이해할 수 있습니다.

```python
class OutOfStockError(Exception):
    """재고가 부족할 때 발생시키는 예외."""

    def __init__(self, item, requested, stock):
        message = f"{item} 재고가 부족합니다. (재고: {stock}, 요청: {requested})"
        super().__init__(message)
        self.item = item
        self.requested = requested
        self.stock = stock
```

```python
>>> try:
...     raise OutOfStockError("공책", 20, 10)
... except OutOfStockError as e:
...     print(e)
...     print("부족한 수량:", e.requested - e.stock)
...
공책 재고가 부족합니다. (재고: 10, 요청: 20)
부족한 수량: 10
```

`super().__init__(message)`를 호출하면 부모 클래스인 `Exception`의 초기화 로직이 실행되어, `print(e)`를 했을 때 우리가 만든 메시지가 정상적으로 출력됩니다. `super()`에 대한 자세한 설명은 12장 "클래스와 객체지향 기초"의 상속 부분에서 다룹니다.

### 예외 계층 만들기

관련된 예외가 여러 개라면, 공통 부모 예외를 하나 만들어 계층을 구성하는 것이 좋습니다. 이렇게 하면 세부 예외를 개별적으로 처리할 수도 있고, 부모 예외로 한 번에 묶어서 처리할 수도 있습니다.

```python
class ShopError(Exception):
    """쇼핑몰 도메인에서 발생하는 모든 예외의 기반 클래스."""
    pass


class OutOfStockError(ShopError):
    """재고가 부족할 때 발생시키는 예외."""
    pass


class InvalidCouponError(ShopError):
    """쿠폰이 유효하지 않을 때 발생시키는 예외."""
    pass
```

```python
>>> def use_coupon(code, valid_codes):
...     if code not in valid_codes:
...         raise InvalidCouponError(f"{code}는 유효하지 않은 쿠폰입니다.")
...
>>> try:
...     use_coupon("WINTER2020", {"SUMMER2026"})
... except ShopError as e:
...     print("쇼핑몰 오류 발생:", e)
...
쇼핑몰 오류 발생: WINTER2020는 유효하지 않은 쿠폰입니다.
```

`InvalidCouponError`가 발생했지만 `except ShopError`로도 잡히는 이유는, `InvalidCouponError`가 `ShopError`를 상속받았기 때문입니다. `except`는 지정한 클래스 자신뿐 아니라 그 하위 클래스(자식 클래스)의 인스턴스도 함께 잡아냅니다.

## EAFP와 LBYL: 파이썬다운 예외 처리 철학

같은 문제를 해결하는 데도 두 가지 접근 방식이 있습니다.

- **LBYL (Look Before You Leap, 도약하기 전에 살펴보기)**: 어떤 동작을 실행하기 전에 조건을 미리 검사해서 문제가 없는지 확인하는 방식.
- **EAFP (Easier to Ask Forgiveness than Permission, 허락보다는 용서를 구하는 것이 쉽다)**: 일단 실행해보고, 문제가 생기면 예외로 처리하는 방식.

딕셔너리에서 키를 조회하는 예로 두 방식을 비교해 보겠습니다.

```python
# LBYL 방식: 먼저 키가 있는지 확인한다
def get_price_lbyl(prices, item):
    if item in prices:
        return prices[item]
    else:
        print(f"{item}의 가격 정보가 없습니다.")
        return None


# EAFP 방식: 일단 시도하고, 실패하면 예외로 처리한다
def get_price_eafp(prices, item):
    try:
        return prices[item]
    except KeyError:
        print(f"{item}의 가격 정보가 없습니다.")
        return None
```

```python
>>> prices = {"사과": 1500, "바나나": 2000}
>>> get_price_lbyl(prices, "사과")
1500
>>> get_price_eafp(prices, "사과")
1500
```

두 함수는 결과만 보면 동일하게 동작합니다. 하지만 Python 커뮤니티에서는 일반적으로 EAFP 방식을 더 파이썬다운(pythonic) 스타일로 여깁니다. 그 이유는 다음과 같습니다.

1. **경쟁 조건(race condition)을 피할 수 있습니다.** 예를 들어 파일이 존재하는지 확인(`os.path.exists`)한 뒤 여는 사이에, 다른 프로세스가 그 파일을 삭제할 수도 있습니다. LBYL 방식은 "확인"과 "실행" 사이에 시간차가 있어 이런 문제에 취약합니다. EAFP는 애초에 실행을 먼저 시도하므로 이런 틈이 생기지 않습니다.
2. **정상 경로(happy path)의 코드가 더 간결해집니다.** 조건 검사 코드가 실제 로직보다 길어지는 경우를 방지할 수 있습니다.
3. **중복 작업을 줄일 수 있습니다.** LBYL 방식은 조건을 검사할 때 한 번, 실제로 값을 사용할 때 또 한 번, 사실상 같은 작업을 두 번 하는 경우가 많습니다.

물론 EAFP가 항상 정답은 아닙니다. 예외 처리 자체에는 비용이 있고, 예외가 아주 빈번하게 발생하는 상황이라면 조건 검사가 더 효율적일 수 있습니다. 또한 되돌릴 수 없는 작업(예: 이미 실행된 결제)을 시도하기 전에는 미리 검증하는 LBYL 방식이 더 안전합니다. 두 방식의 장단점을 이해하고 상황에 맞게 선택하는 것이 중요합니다.

```python
>>> numbers = [1, 2, 3]
>>> index = 5
>>>
>>> # LBYL: 길이를 먼저 확인
>>> if index < len(numbers):
...     print(numbers[index])
... else:
...     print("범위를 벗어났습니다.")
...
범위를 벗어났습니다.
>>>
>>> # EAFP: 먼저 시도하고 예외로 처리
>>> try:
...     print(numbers[index])
... except IndexError:
...     print("범위를 벗어났습니다.")
...
범위를 벗어났습니다.
```

간단한 인덱스 검사 정도는 둘 다 무난하지만, 딕셔너리 조회나 속성 접근, 타입 변환처럼 "미리 확인하는 조건문 자체가 복잡해지는" 상황일수록 EAFP 스타일의 장점이 두드러집니다. 9장 "함수"에서 다룬 것처럼 함수는 하나의 책임에 집중할 때 이해하기 쉬운데, 예외 처리 역시 "정상적인 계산 로직"과 "예외적인 상황에 대한 대응"을 분리해서 작성하면 코드를 읽기가 훨씬 수월해집니다.

## 요약

- 예외는 프로그램 실행 중 발생하는 오류 상황을 나타내는 객체이며, `ZeroDivisionError`, `ValueError`, `KeyError`처럼 상황에 맞는 이름을 갖고 `Exception`을 정점으로 하는 클래스 계층을 이룹니다.
- `try` 블록에서 예외가 발생할 수 있는 코드를 실행하고, `except`로 원하는 예외 타입을 잡아 처리합니다. `except ExceptionType as e` 형태로 예외 객체의 정보를 확인할 수 있습니다.
- `else`는 예외가 없을 때만, `finally`는 예외 발생 여부와 관계없이 항상 실행됩니다. 자원 정리에는 `finally`나 `with` 문을 사용합니다.
- `raise`로 예외를 직접 발생시킬 수 있고, `except` 블록 안에서 `raise`만 쓰면 예외를 다시 던질 수 있으며, `raise ... from ...`으로 예외의 인과관계를 표시할 수 있습니다.
- `Exception`을 상속받아 우리만의 커스텀 예외 클래스를 만들 수 있고, 공통 부모 예외를 두어 예외 계층을 구성하면 세부적으로도, 포괄적으로도 처리할 수 있습니다.
- LBYL은 실행 전에 조건을 검사하는 방식이고, EAFP는 먼저 시도한 뒤 예외로 대응하는 방식입니다. Python은 일반적으로 EAFP 스타일을 선호하지만, 상황에 따라 적절한 방식을 선택해야 합니다.

5. 다음 코드를 실행했을 때 출력되는 내용을 예상해 보고, 실제로 실행해서 확인하세요. `else`와 `finally`가 각각 언제 실행되는지 설명해 보세요.

```python
def check(n):
    try:
        if n < 0:
            raise ValueError("음수는 허용되지 않습니다.")

check(-3)
```
