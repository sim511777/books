## 남의 클래스에 내 함수를 추가하고 싶을 때

9장에서 클래스를 만들고 그 안에 함수(메서드)를 정의하는 방법을 배웠다. 그런데 클래스는 항상 내가 만든 것만 다루게 되지는 않는다. `String`이나 `List` 같은 Kotlin 표준 라이브러리 클래스, 혹은 Java로 작성된 외부 라이브러리의 클래스를 사용하다 보면 "이 클래스에 이런 기능이 하나만 더 있으면 딱 좋겠다"는 순간이 자주 생긴다.

전통적인 객체지향 언어에서는 이럴 때 선택지가 별로 없었다. 클래스의 소스 코드를 직접 고칠 수 없으니(표준 라이브러리는 당연히 그렇다), 보통은 별도의 유틸리티 함수를 만들어 `StringUtils.isPalindrome(someString)`처럼 호출해야 했다. 동작은 하지만, `someString.isPalindrome()`처럼 자연스럽게 이어 쓰지 못해 아쉬움이 남는다.

Kotlin은 이 문제를 **확장 함수(extension function)**로 해결한다. 기존 클래스의 소스 코드를 전혀 건드리지 않고도, 마치 그 클래스에 원래 있던 메서드처럼 새로운 함수를 "추가"할 수 있다.

## 확장 함수의 문법

확장 함수를 선언하는 문법은 일반 함수 선언과 거의 같다. 다만 함수 이름 앞에 "어떤 타입을 확장하는지"를 명시한다.

```kotlin
fun String.isPalindrome(): Boolean {
    val cleaned = this.lowercase()
    return cleaned == cleaned.reversed()
}

fun main() {
    println("level".isPalindrome())      // true
    println("Kotlin".isPalindrome())     // false
    println("A man a".isPalindrome())    // false (공백까지 포함해서 비교)
}
```

`fun String.isPalindrome()`에서 `String`을 **수신 타입(receiver type)**이라고 부른다. 함수 본문 안에서 `this`는 확장 함수가 호출된 대상, 즉 수신 객체(receiver object)를 가리킨다. 위 예제에서 `"level".isPalindrome()`을 호출하면 `this`는 `"level"`이 된다.

일반 함수와 마찬가지로 매개변수를 받을 수도 있다.

```kotlin
fun String.repeatWithSeparator(times: Int, separator: String): String {
    return (1..times).joinToString(separator) { this }
}

fun main() {
    println("ㅎㅎ".repeatWithSeparator(3, " ")) // ㅎㅎ ㅎㅎ ㅎㅎ
}
```

## 표준 라이브러리 클래스에도, Java 클래스에도

확장 함수의 대상은 Kotlin이 제공하는 클래스뿐만 아니라, Java로 작성된 클래스에도 똑같이 적용된다. Kotlin 코드는 Java 클래스를 그냥 하나의 타입으로 다루기 때문에, `java.util.Date`나 `java.io.File`처럼 우리가 소스 코드를 손댈 수 없는 클래스에도 자유롭게 확장 함수를 붙일 수 있다. 이 내용은 17장에서 Java 상호운용을 다룰 때 다시 살펴보겠지만, 지금 알아둘 점은 "누가 만든 클래스인지는 중요하지 않다"는 것이다. 확장 함수는 클래스 자체를 수정하는 게 아니라, 그 클래스의 인스턴스를 받아 쓰는 함수를 조금 특별한 문법으로 호출 가능하게 만들 뿐이다.

12장에서 다룬 컬렉션 타입에도 물론 확장 함수를 만들 수 있다.

```kotlin
fun List<Int>.average2(): Double {
    if (this.isEmpty()) return 0.0
    return this.sum().toDouble() / this.size
}

fun main() {
    val scores = listOf(85, 92, 78, 95)
    println(scores.average2()) // 87.5
}
```

실제로 `map`, `filter`, `average` 같은, 13장에서 이미 사용했던 컬렉션 함수들 역시 대부분 Kotlin 표준 라이브러리 안에서 확장 함수로 정의되어 있다. 즉, `List` 클래스 자체는 아주 단순하게 유지하고, 그 위에 편의 기능들을 확장 함수로 쌓아 올린 것이다. 이것이 확장 함수가 Kotlin 표준 라이브러리 설계 전반에 깔려 있는 핵심 아이디어다.

## 진짜 정체: 정적 메서드로 컴파일된다

확장 함수는 마치 클래스 내부에 메서드를 추가한 것처럼 보이지만, 실제로는 전혀 그렇지 않다. Kotlin 컴파일러는 확장 함수를 **평범한 정적 메서드(static method)**로 변환하고, 수신 객체는 그 정적 메서드의 첫 번째 매개변수로 슬쩍 전달한다.

앞서 본 `isPalindrome` 예제는 대략 다음과 같은 Java 코드로 컴파일된다고 생각하면 된다(개념을 보여주기 위한 근사치다).

```java
// 컴파일된 결과의 개념적 이미지 (실제 바이트코드와는 세부사항이 다르다)
public static boolean isPalindrome(String receiver) {
    String cleaned = receiver.toLowerCase();
    return cleaned.equals(new StringBuilder(cleaned).reverse().toString());
}
```

`"level".isPalindrome()`이라는 호출은 겉보기엔 메서드 호출이지만, 실제로는 `isPalindrome("level")`이라는 정적 함수 호출로 바뀐다. `this`가 진짜 객체의 필드나 메서드에 접근하는 것도, 사실은 매개변수로 전달받은 객체에 접근하는 것뿐이다.

이 사실이 왜 중요한지는 다음 예제로 확인할 수 있다.

```kotlin
open class Animal
class Dog : Animal()

fun Animal.speak() = println("동물이 소리를 냅니다")
fun Dog.speak() = println("멍멍!")

fun main() {
    val animal: Animal = Dog()
    animal.speak() // "동물이 소리를 냅니다" 가 출력된다!
}
```

`animal` 변수의 실제 객체는 `Dog`이지만, 변수의 **선언된 타입**은 `Animal`이다. 만약 `speak`가 클래스 내부에 정의된 진짜 메서드였다면, 11장에서 다룬 다형성(polymorphism) 원리에 따라 실제 객체 타입인 `Dog`의 `speak`가 호출되어야 한다. 하지만 확장 함수는 정적 메서드로 컴파일되기 때문에, **호출 시점에 컴파일러가 알고 있는 변수의 선언된 타입**을 기준으로 어느 함수를 호출할지 결정한다. 이를 정적 디스패치(static dispatch)라고 부르는데, 클래스의 진짜 메서드가 사용하는 동적 디스패치(dynamic dispatch)와 대비된다.

정리하면, 확장 함수는 다형성이 적용되지 않는다는 명확한 한계를 가진다. 이는 버그가 아니라 확장 함수의 본질적인 설계다. 확장 함수는 클래스 계층 구조에 진짜로 끼어드는 것이 아니라, 특정 타입에 대해 호출 가능한 "편의 함수"를 문법적으로 예쁘게 포장한 것이기 때문이다.

## 언제 확장 함수를 써야 할까

확장 함수는 다음과 같은 상황에서 특히 유용하다.

- **기존 클래스에 유틸리티 기능을 자연스럽게 추가하고 싶을 때.** `string.isPalindrome()`처럼 이어 쓰는 문법이 `StringUtils.isPalindrome(string)`보다 읽기 좋다.
- **내가 소유하지 않은 클래스(표준 라이브러리, 외부 라이브러리, Java 클래스)에 기능을 붙이고 싶을 때.** 소스 코드를 고칠 수 없어도 확장 함수는 항상 가능하다.
- **다형성이 필요 없는, 순수하게 데이터를 다루는 보조 함수를 만들 때.** 확장 함수가 상속 관계까지 고려해야 하는 로직이라면, 클래스 내부의 진짜 메서드나 11장에서 다룰 인터페이스를 사용하는 것이 더 적절하다.

반대로, 객체의 내부 상태에 깊이 관여하거나 하위 클래스마다 다르게 동작해야 하는 로직이라면 확장 함수보다는 클래스 안에 진짜 메서드로 정의하는 편이 안전하다. 확장 함수는 "편리한 겉포장"이지 "객체의 진짜 행동을 재정의하는 도구"가 아니라는 점을 기억해두면, 언제 확장 함수를 쓰고 언제 피해야 하는지 자연스럽게 판단할 수 있다.

## 요약

- 확장 함수는 기존 클래스의 소스 코드를 수정하지 않고도 새로운 함수를 추가하는 문법으로, `fun 타입.함수이름()` 형태로 선언한다.
- 함수 본문에서 `this`는 확장 함수가 호출된 대상인 수신 객체를 가리킨다.
- 확장 함수는 Kotlin 표준 라이브러리 클래스뿐 아니라 Java로 작성된 클래스에도 동일하게 적용할 수 있다.
- 컴파일러는 확장 함수를 정적 메서드로 변환하고, 수신 객체를 첫 번째 매개변수로 넘긴다.
- 이 때문에 확장 함수는 다형성이 적용되지 않는다. 어떤 함수가 호출될지는 변수의 실제 객체 타입이 아니라 선언된(컴파일 시점에 알려진) 타입을 기준으로 정적으로 결정된다.
- 소유하지 않은 클래스에 편의 기능을 추가하거나, 다형성이 필요 없는 유틸리티성 함수를 만들 때 확장 함수가 특히 유용하다.

## 연습문제

1. `Int` 타입에 대해 `isEven()`이라는 확장 함수를 작성하여, 짝수인지 여부를 반환하도록 만들어라.
2. `String`에 대해 `wordCount()`라는 확장 함수를 작성하여, 공백으로 구분된 단어의 개수를 반환하도록 만들어라.
3. 이 장에서 본 `Animal`/`Dog` 예제를 직접 실행해보고, 만약 `speak`가 확장 함수가 아니라 클래스 내부의 `open` 메서드로 정의되어 있었다면 결과가 어떻게 달라질지 설명해보라.
4. `List<Int>`에 대해 `secondOrNull()`이라는 확장 함수를 작성하여, 리스트의 두 번째 요소를 반환하거나 요소가 부족하면 `null`을 반환하도록 만들어라(8장에서 다룬 null 안전성을 활용해보라).
5. 확장 함수와 클래스 내부에 직접 정의한 메서드 중 하나를 선택해야 하는 상황을 하나 생각해보고, 어떤 기준으로 선택할지 이유를 들어 설명해보라.
