# 11장. 인터페이스와 추상 클래스

---

10장에서는 클래스를 상속해서 부모의 속성과 동작을 물려받는 방법을 배웠습니다. 그런데 상속만으로는 부족한 상황이 있습니다. 예를 들어 "날 수 있다"와 "헤엄칠 수 있다"라는 두 가지 능력을 동시에 가진 객체를 만들고 싶다면 어떻게 해야 할까요? Kotlin의 클래스는 오직 하나의 부모 클래스만 상속할 수 있기 때문에, 이런 경우에는 인터페이스(interface)가 해답이 됩니다. 이번 장에서는 인터페이스의 정의와 구현, 인터페이스의 기본 구현 제공, 다중 인터페이스 구현, 그리고 추상 클래스와 인터페이스의 차이를 살펴봅니다.

## 인터페이스란 무엇인가

인터페이스는 클래스가 반드시 갖춰야 할 기능의 "명세" 또는 "약속"입니다. 인터페이스 자체는 객체를 직접 만들 수 없고, 이를 구현(implement)하는 클래스가 그 약속을 실제 코드로 채워 넣습니다.

```kotlin
// 인터페이스 정의: 함수의 시그니처만 선언
interface Flyable {
    fun fly()
}

// 인터페이스를 구현하는 클래스
class Bird : Flyable {
    override fun fly() {
        println("새가 날개를 펄럭이며 날아갑니다.")
    }
}

fun main() {
    val bird = Bird()
    bird.fly()
}
```

클래스가 상속을 표현할 때 쓰던 콜론(`:`)을 인터페이스 구현에도 그대로 사용합니다. 다만 인터페이스의 함수를 구현할 때는 `override` 키워드를 반드시 붙여야 합니다. 인터페이스에 선언된 함수는 기본적으로 본문이 없는 "추상 함수"이므로, 구현 클래스는 이를 반드시 재정의해야 합니다.

인터페이스에는 함수뿐 아니라 프로퍼티도 선언할 수 있습니다. 단, 인터페이스의 프로퍼티는 상태(값)를 직접 저장할 수 없고, 구현 클래스가 값을 채워 넣어야 합니다.

```kotlin
interface Vehicle {
    val maxSpeed: Int // 구현 클래스가 값을 제공해야 함
    fun drive()
}

class Car : Vehicle {
    override val maxSpeed: Int = 200

    override fun drive() {
        println("최고 속도 ${maxSpeed}km/h로 주행합니다.")
    }
}
```

## 인터페이스의 기본 구현

Kotlin 인터페이스의 특별한 점 하나는, 함수 본문을 미리 작성해서 "기본 구현"을 제공할 수 있다는 것입니다. 이는 Java의 default method와 유사한 개념입니다. 구현 클래스가 굳이 재정의하지 않아도 인터페이스에 적힌 동작이 그대로 사용됩니다.

```kotlin
interface Greetable {
    val name: String

    // 기본 구현이 있는 함수: override 없이 그대로 사용 가능
    fun greet() {
        println("안녕하세요, ${name}님!")
    }
}

class Guest(override val name: String) : Greetable

class VipGuest(override val name: String) : Greetable {
    // 필요하다면 기본 구현을 덮어쓸 수 있음
    override fun greet() {
        println("귀하신 몸, ${name}님. 특별히 환영합니다!")
    }
}

fun main() {
    Guest("영수").greet()      // 안녕하세요, 영수님!
    VipGuest("지민").greet()   // 귀하신 몸, 지민님. 특별히 환영합니다!
}
```

`Guest`는 `greet` 함수를 재정의하지 않고도 인터페이스의 기본 동작을 그대로 사용했고, `VipGuest`는 필요에 따라 자신만의 동작으로 덮어썼습니다. 이렇게 기본 구현을 제공하면 공통 로직을 인터페이스 한 곳에 모아두고, 예외적인 클래스만 별도로 재정의하는 식으로 코드 중복을 줄일 수 있습니다.

## 다중 인터페이스 구현

클래스는 부모 클래스를 하나만 가질 수 있지만, 인터페이스는 원하는 만큼 여러 개를 동시에 구현할 수 있습니다. 앞서 언급한 "날 수도 있고 헤엄칠 수도 있는" 객체가 바로 이런 경우입니다.

```kotlin
interface Flyable {
    fun fly() = println("하늘을 날아갑니다.")
}

interface Swimmable {
    fun swim() = println("물속을 헤엄칩니다.")
}

// 콤마로 구분해서 여러 인터페이스를 동시에 구현
class Duck : Flyable, Swimmable {
    fun describe() {
        println("오리는 날 수도 있고 헤엄칠 수도 있습니다.")
    }
}

fun main() {
    val duck = Duck()
    duck.fly()
    duck.swim()
    duck.describe()
}
```

만약 두 인터페이스가 같은 이름의 함수를 각각 기본 구현으로 제공한다면 어떻게 될까요? 이럴 때 Kotlin 컴파일러는 어느 쪽 구현을 선택해야 할지 알 수 없으므로 컴파일 오류를 발생시키고, 구현 클래스가 직접 함수를 재정의하도록 강제합니다. 이때는 `super<인터페이스명>.함수명()` 문법으로 특정 인터페이스의 구현을 명시적으로 호출할 수 있습니다.

```kotlin
interface A {
    fun show() = println("A의 구현")
}

interface B {
    fun show() = println("B의 구현")
}

// A와 B 둘 다 show()의 기본 구현을 가지고 있으므로 반드시 재정의해야 함
class C : A, B {
    override fun show() {
        super<A>.show() // A의 구현을 명시적으로 호출
        super<B>.show() // B의 구현도 호출
    }
}
```

## 추상 클래스와 인터페이스의 차이

10장에서 상속을 배울 때 `open` 클래스를 다뤘는데, 여기에 더해 Kotlin은 `abstract` 키워드로 "추상 클래스"를 만들 수 있습니다. 추상 클래스는 인터페이스와 비슷하게 구현이 없는 함수(추상 함수)를 선언할 수 있지만, 몇 가지 중요한 차이가 있습니다.

```kotlin
abstract class Animal(val name: String) {
    abstract fun makeSound() // 추상 함수: 본문 없음, 자식이 반드시 구현

    fun introduce() { // 일반 함수: 상태(name)를 활용한 공통 로직
        println("저는 ${name}입니다.")
    }
}

class Dog(name: String) : Animal(name) {
    override fun makeSound() = println("멍멍!")
}

fun main() {
    val dog = Dog("바둑이")
    dog.introduce()
    dog.makeSound()
}
```

추상 클래스는 생성자를 가질 수 있고 `name`처럼 상태를 저장하는 프로퍼티를 가질 수 있다는 점에서 인터페이스와 다릅니다. 반면 인터페이스는 상태를 직접 저장하지 못하고, 값을 저장하지 않는 함수와 프로퍼티 선언 위주로 구성됩니다.

두 개념을 표로 비교하면 다음과 같습니다.

| 비교 항목 | 인터페이스 (interface) | 추상 클래스 (abstract class) |
|---|---|---|
| 다중 구현/상속 | 여러 개 동시 구현 가능 | 하나만 상속 가능 |
| 생성자 | 가질 수 없음 | 가질 수 있음 |
| 상태 저장 (프로퍼티에 값 보관) | 불가능 (기본값 없는 선언만) | 가능 |
| 함수 기본 구현 | 가능 (default method와 유사) | 가능 |
| 사용 목적 | "할 수 있는 일"의 계약, 역할 정의 | 공통 상태 + 일부 구현을 가진 뼈대 |
| 접근 제어자 | 기본적으로 public만 허용되던 제약이 완화되어 있으나 관례상 public 위주 | private, protected 등 다양하게 사용 |

실무에서 선택 기준을 간단히 정리하면 이렇습니다. 서로 관련 없는 클래스들에 공통된 "행동"만 강제하고 싶다면 인터페이스를, 공통된 "상태와 초기화 로직"까지 물려주고 싶다면 추상 클래스를 선택합니다. 실제로는 추상 클래스를 상속하면서 동시에 여러 인터페이스를 구현하는 조합도 자주 사용됩니다.

```kotlin
interface Chargeable {
    fun charge() = println("충전 중입니다.")
}

abstract class Device(val brand: String) {
    abstract fun powerOn()
}

// 추상 클래스는 하나만, 인터페이스는 여러 개 함께 사용 가능
class Smartphone(brand: String) : Device(brand), Chargeable {
    override fun powerOn() = println("${brand} 스마트폰이 켜졌습니다.")
}

fun main() {
    val phone = Smartphone("Kotlon")
    phone.powerOn()
    phone.charge()
}
```

## 요약

이번 장에서는 인터페이스와 추상 클래스를 다뤘습니다. 인터페이스는 `interface` 키워드로 정의하며, 함수와 프로퍼티의 명세를 선언하고 `override`로 구현합니다. 함수 본문을 미리 채운 기본 구현을 제공하면 구현 클래스가 재정의를 생략할 수 있으며, 이는 Java의 default method와 유사한 개념입니다. 클래스는 부모 클래스를 하나만 상속할 수 있지만 인터페이스는 콤마로 나열해 여러 개를 동시에 구현할 수 있고, 같은 이름의 기본 구현이 충돌하면 `super<인터페이스명>.함수명()`으로 명시적으로 해결해야 합니다. 추상 클래스는 `abstract` 키워드로 정의하며, 생성자와 상태를 가질 수 있다는 점에서 인터페이스와 구별됩니다. 10장의 상속과 이번 장의 인터페이스/추상 클래스를 조합하면 훨씬 유연한 클래스 설계가 가능해집니다.

1. `Playable`이라는 인터페이스를 정의하고, `play()`라는 함수에 "재생을 시작합니다."를 출력하는 기본 구현을 작성하세요. 이를 구현하는 `MusicPlayer` 클래스를 만들고 기본 구현을 그대로 사용해보세요.
2. `Resizable`과 `Movable` 두 인터페이스를 각각 정의하고, 이 둘을 동시에 구현하는 `Window` 클래스를 작성하세요.
3. `Shape`라는 추상 클래스를 만들고 `area()`라는 추상 함수를 선언하세요. 이를 상속하는 `Circle`과 `Rectangle` 클래스를 작성하고 각각 넓이를 계산하도록 구현하세요.
4. 인터페이스 `A`와 `B`가 똑같은 이름의 함수 `hello()`에 대해 서로 다른 기본 구현을 제공할 때, 이를 동시에 구현하는 클래스에서 발생하는 컴파일 오류를 재현해보고, `super<A>.hello()` 문법으로 해결해보세요.
5. 인터페이스와 추상 클래스 중 어느 것을 선택할지 애매한 상황을 하나 떠올려보고, 그 이유를 상태 저장 여부와 다중 구현 가능성 관점에서 설명해보세요.
