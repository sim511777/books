# 10장. 데이터 클래스와 상속

---

9장에서는 `class`로 클래스를 정의하고 생성자와 프로퍼티, 접근 제한자로 캡슐화하는 방법을 배웠습니다. 그런데 데이터를 담는 용도로만 쓰이는 클래스는 매번 `equals`, `hashCode`, `toString`을 직접 작성하는 일이 번거롭습니다. 이번 장에서는 이런 클래스를 위한 `data class`와, 클래스 사이에 "부모-자식" 관계를 만드는 상속을 다룹니다.

## 일반 클래스의 불편함

9장에서 만든 `Person` 클래스로 두 객체를 비교해보겠습니다.

```kotlin
class Person(val name: String, val age: Int)

fun main() {
    val p1 = Person("김철수", 25)
    val p2 = Person("김철수", 25)

    println(p1 == p2)   // false!
    println(p1)          // Person@1b6d3586 같은 의미 없는 문자열
}
```

이름과 나이가 완전히 같은데도 `p1 == p2`는 `false`입니다. Kotlin에서 `==`는 기본적으로 `equals()`를 호출하는데, 일반 클래스의 `equals()`는 "같은 값을 가졌는가"가 아니라 "메모리상 같은 객체인가"를 비교하기 때문입니다. `toString()` 역시 클래스 이름과 메모리 주소 같은 값만 출력해서 디버깅에 별 도움이 안 됩니다. 이 문제를 해결하려면 `equals()`, `hashCode()`, `toString()`을 직접 오버라이드해야 하는데, 프로퍼티가 늘어날 때마다 이 코드를 손으로 유지보수하는 것은 실수를 부르기 쉽습니다.

## data class: 값을 담는 클래스를 위한 문법

클래스 앞에 `data` 키워드만 붙이면 Kotlin 컴파일러가 주 생성자에 선언된 프로퍼티를 기준으로 `equals()`, `hashCode()`, `toString()`, `copy()`를 자동으로 만들어줍니다.

```kotlin
data class Person(val name: String, val age: Int)

fun main() {
    val p1 = Person("김철수", 25)
    val p2 = Person("김철수", 25)

    println(p1 == p2)   // true, 값이 같으면 같다고 판단
    println(p1)          // Person(name=김철수, age=25)
}
```

같은 값을 가진 두 객체가 `==`로 같다고 판단되고, `println`으로 출력하면 어떤 값을 담고 있는지 한눈에 알 수 있는 문자열이 나옵니다. 이것만으로도 `data class`는 로그 출력, 테스트 코드에서의 값 비교, 12장에서 다룰 컬렉션에 담아 검색하는 작업까지 훨씬 편해집니다.

### copy(): 일부만 바꾼 새 객체 만들기

`data class`가 제공하는 `copy()`는 기존 객체의 값을 그대로 가져오면서 원하는 프로퍼티만 바꾼 새 객체를 만들어줍니다. `val`로 선언한 프로퍼티가 많아 불변(immutable) 객체를 선호하는 Kotlin 스타일에서 특히 유용합니다.

```kotlin
data class Person(val name: String, val age: Int)

fun main() {
    val p1 = Person("김철수", 25)
    val p2 = p1.copy(age = 26)   // name은 그대로, age만 26으로

    println(p1)   // Person(name=김철수, age=25) -- 원본은 그대로
    println(p2)   // Person(name=김철수, age=26)
}
```

원본 `p1`은 그대로 남아 있고, `age`만 바뀐 새로운 객체 `p2`가 만들어졌습니다. 이렇게 "기존 객체를 바꾸는 대신 바뀐 값을 가진 새 객체를 만든다"는 패턴은 8장에서 다룬 안전한 코드 작성 습관과도 잘 어울립니다.

### componentN(): 구조 분해

`data class`는 `component1()`, `component2()`처럼 순서대로 값을 꺼내는 함수도 자동으로 만들어주기 때문에, 다음처럼 **구조 분해 선언**을 쓸 수 있습니다.

```kotlin
val (name, age) = Person("이영희", 30)
println("$name / $age")   // 이영희 / 30
```

### 일반 class와 data class 비교

| 항목 | class | data class |
|---|---|---|
| `equals()` / `hashCode()` | 기본은 참조 비교 | 프로퍼티 값 기준으로 자동 생성 |
| `toString()` | 클래스명@해시코드 | `클래스명(프로퍼티=값, ...)` 형태로 자동 생성 |
| `copy()` | 없음 | 자동 생성 |
| 용도 | 동작과 상태를 함께 가진 객체(9장의 `BankAccount`처럼 규칙을 강제해야 하는 경우) | 값 자체를 표현하는 객체(좌표, DTO, 함수의 결과값 묶음 등) |

주 생성자에 프로퍼티가 하나도 없는 클래스에는 `data`를 붙일 수 없고, `abstract`, `open`, `sealed`(15장에서 다룹니다), `inner` 클래스와도 함께 쓸 수 없다는 제약이 있습니다. 즉 `data class`는 상속 계층의 부모 역할보다는, 값을 표현하는 단말 클래스에 적합하도록 설계되어 있습니다.

## 상속: Kotlin은 기본적으로 클래스를 상속할 수 없다

많은 객체지향 언어에서는 클래스를 자유롭게 상속할 수 있지만, Kotlin은 정반대의 기본값을 택했습니다. **모든 클래스는 기본적으로 `final`이라서 상속할 수 없습니다.** 다른 클래스가 상속할 수 있게 하려면 반드시 `open` 키워드를 붙여야 합니다.

```kotlin
// open이 없으면 상속 불가 (컴파일 오류)
open class Animal(val name: String) {
    open fun makeSound() {
        println("$name 이 소리를 냅니다.")
    }
}

class Dog(name: String) : Animal(name) {
    override fun makeSound() {
        println("$name: 멍멍!")
    }
}
```

`class Dog(name: String) : Animal(name)`에서 콜론(`:`) 뒤에 부모 클래스 이름과 생성자 호출을 함께 적어줍니다. `Dog`는 자기 생성자에서 받은 `name`을 그대로 부모인 `Animal`의 생성자로 넘기고 있습니다.

이렇게 기본값을 `final`로 정한 이유는 "설계 의도 없이 상속되는 클래스"를 막기 위해서입니다. 클래스를 상속에 대비해서 설계하지 않았는데 누군가 임의로 상속해서 내부 동작을 깨뜨리는 사고를 줄이려는 목적입니다. 클래스를 만들 때 "이 클래스는 확장을 허용할 것인가?"를 항상 명시적으로 결정하게 되는 것이죠. 이 원칙은 11장에서 다루는 인터페이스나 추상 클래스와도 연결되는데, 인터페이스의 메서드는 기본적으로 열려 있어 구현체가 자유롭게 오버라이드하도록 설계되어 있습니다.

## 메서드 오버라이딩: open과 override

프로퍼티와 마찬가지로 함수도 기본적으로 오버라이드할 수 없습니다. 부모 클래스에서 `open fun`으로 열어준 함수만 자식 클래스에서 `override fun`으로 재정의할 수 있습니다.

```kotlin
open class Animal(val name: String) {
    open fun makeSound() {
        println("$name 이(가) 소리를 냅니다.")
    }

    // open이 없으므로 자식 클래스에서 재정의 불가
    fun sleep() {
        println("$name 이(가) 잠을 잡니다.")
    }
}

class Cat(name: String) : Animal(name) {
    override fun makeSound() {
        println("$name: 야옹~")
    }
}
```

`override`를 붙이면서 자식 클래스가 부모의 동작에 새 내용을 덧붙이고 싶다면 `super`로 부모의 구현을 호출할 수 있습니다.

```kotlin
class LoudDog(name: String) : Animal(name) {
    override fun makeSound() {
        super.makeSound()      // 부모의 makeSound() 먼저 실행
        println("...그리고 아주 큰 소리로: 멍멍멍!!!")
    }
}
```

프로퍼티 역시 `open val`/`open var`로 선언하면 자식 클래스에서 `override`로 재정의할 수 있습니다.

## 다형성: 부모 타입으로 자식들을 다루기

여러 종류의 동물을 하나의 목록에 담고, 각 동물의 실제 타입에 맞는 `makeSound()`가 호출되게 만들어봅니다. 이렇게 부모 타입의 변수나 매개변수로 다양한 자식 타입의 객체를 다루는 것을 **다형성(polymorphism)**이라고 합니다.

```kotlin
open class Animal(val name: String) {
    open fun makeSound() = println("$name 이(가) 소리를 냅니다.")
}

class Dog(name: String) : Animal(name) {
    override fun makeSound() = println("$name: 멍멍!")
}

class Cat(name: String) : Animal(name) {
    override fun makeSound() = println("$name: 야옹~")
}

fun main() {
    // 12장에서 자세히 다루는 List에 서로 다른 하위 타입을 담을 수 있다
    val animals: List<Animal> = listOf(Dog("바둑이"), Cat("나비"), Animal("이름없는동물"))

    for (animal in animals) {
        animal.makeSound()   // 실제 타입에 맞는 makeSound()가 호출된다
    }
}
```

`animals` 리스트의 타입은 `List<Animal>`이지만, 실제로 각 원소는 `Dog`, `Cat`, `Animal`이라는 서로 다른 구체 타입입니다. `animal.makeSound()`를 호출하면 Kotlin은 컴파일 시점의 타입(`Animal`)이 아니라 실행 시점의 실제 타입을 기준으로 오버라이드된 함수를 찾아 실행합니다. 이 덕분에 `if`나 `when`으로 타입을 일일이 분기하지 않고도 각 동물에 맞는 동작을 자연스럽게 실행할 수 있습니다. 타입별로 분기해야 하는 경우가 정말 필요하다면 15장에서 배울 `sealed class`와 `when`의 조합이 더 안전한 대안이 됩니다.

## data class와 상속을 함께 쓸 때 주의할 점

`data class`는 다른 `data class`를 상속할 수 없으며, 자기 자신이 `open`으로 상속을 허용하는 부모가 되는 것도 권장되지 않습니다. `equals`/`hashCode`가 주 생성자의 프로퍼티만 기준으로 생성되기 때문에, 상속 관계에서 자식이 추가한 프로퍼티까지 고려한 비교가 되지 않아 예상치 못한 버그로 이어지기 쉽습니다. 값을 표현하는 목적이라면 `data class` 여러 개를 만들거나, 11장에서 다루는 인터페이스로 공통점을 묶는 방식이 더 안전합니다. 반면 `Animal`처럼 동작과 상태를 함께 가지며 계층을 이루는 설계라면 `open class` + 상속이 적합하고, 동작 없이 값만 표현하면서 계층이 필요 없는 경우라면 `data class`가 적합합니다.

## 요약

- `data class`는 주 생성자의 프로퍼티를 기준으로 `equals()`, `hashCode()`, `toString()`, `copy()`, `componentN()`을 자동으로 생성해줘서 값 비교와 디버깅이 쉬워집니다.
- `copy()`는 기존 객체를 바꾸는 대신 일부 값만 바뀐 새 불변 객체를 만듭니다.
- Kotlin의 클래스는 기본적으로 `final`이라 상속할 수 없으며, 상속을 허용하려면 `open`을 명시해야 합니다.
- 자식 클래스는 `: 부모클래스(생성자 인자)` 문법으로 상속하고, `open fun`으로 열린 함수만 `override fun`으로 재정의할 수 있습니다.
- `super.함수()`로 부모의 구현을 호출한 뒤 추가 동작을 덧붙일 수 있습니다.
- 다형성을 이용하면 부모 타입의 컬렉션에 여러 자식 타입을 담고도, 각 객체의 실제 타입에 맞는 동작이 실행됩니다.
- `data class`는 상속 계층의 부모로 쓰기보다 값 표현에 집중하는 편이 안전합니다.

다음 11장에서는 클래스 하나만으로는 표현하기 어려운 "여러 클래스가 공통으로 가져야 할 규약"을 인터페이스와 추상 클래스로 표현하는 방법을 배웁니다.

## 연습문제

1. `id`, `title`, `price`를 가진 `Product`를 `data class`로 정의하고, `price`만 10% 할인한 새 객체를 `copy()`로 만들어 출력해 보세요.
2. 두 개의 `Product` 객체를 만들어 `==`로 비교하고, `toString()` 결과를 각각 출력해서 일반 class와 어떻게 다른지 확인해 보세요.
3. `open class Shape(val name: String)`에 `open fun area(): Double`을 두고, `Circle(radius: Double)`과 `Rectangle(width: Double, height: Double)`이 이를 상속해 각자의 넓이 계산을 `override`하도록 만들어 보세요.
