2장에서는 Kotlin 프로그램을 작성하고 빌드해서 실행하는 과정을 살펴봤습니다. 이제부터는 실제로 코드를 채워나가는 데 필요한 기본 재료들을 하나씩 배워보겠습니다. 이번 장의 주제는 변수와 자료형입니다. 값을 어떻게 담고, 그 값이 어떤 종류인지를 어떻게 표현하는지 알아야 이후의 모든 내용을 이해할 수 있습니다.

## val과 var: 읽기 전용과 가변

Kotlin에서 변수를 선언하는 방법은 두 가지입니다. `val`과 `var`입니다.

```kotlin
val name = "김코틀린"   // 읽기 전용, 재할당 불가
var age = 20            // 가변, 재할당 가능

age = 21   // OK
// name = "이코틀린"   // 컴파일 오류: val은 재할당할 수 없다
```

`val`은 value의 줄임말로, 한 번 값을 할당하면 다시 다른 값을 대입할 수 없습니다. `var`은 variable의 줄임말로, 언제든 새로운 값을 대입할 수 있습니다. 자바를 알고 있다면 `val`은 `final` 변수와 비슷하다고 생각하면 이해가 빠릅니다.

여기서 중요한 점은 `val`이라고 해서 그 값 자체가 변하지 않는다는 뜻은 아니라는 것입니다. `val`은 오직 "이 변수가 가리키는 참조를 다시 바꿀 수 없다"는 뜻입니다. 예를 들어 `val` 리스트에 원소를 추가하는 것은 가능합니다(리스트 자체가 가변 컬렉션이라면). 이 차이는 12장 컬렉션 기초에서 다시 자세히 다룹니다. 지금은 "재할당 가능 여부"만 기억하면 충분합니다.

### 왜 val을 기본값으로 권장하는가

Kotlin 코드를 작성할 때는 특별한 이유가 없다면 `var`보다 `val`을 먼저 고려하는 것이 관례입니다. 이유는 다음과 같습니다.

- **예측 가능성**: `val`로 선언된 변수는 코드 어디를 봐도 값이 바뀌지 않는다는 것이 보장됩니다. 함수가 길어지거나 협업하는 동료가 많아질수록 이 보장은 큰 힘이 됩니다.
- **버그 예방**: 실수로 값을 덮어써서 발생하는 버그는 실제 개발에서 꽤 흔합니다. `val`은 컴파일 시점에 이런 실수를 원천적으로 막아줍니다.
- **동시성 안전성**: 여러 스레드가 동시에 값을 읽고 쓰는 상황에서, 재할당이 불가능한 값은 관리하기가 훨씬 쉽습니다. 16장에서 다룰 코루틴 코드에서도 `val`을 우선 사용하는 습관이 큰 도움이 됩니다.

그래서 실무에서는 보통 이렇게 접근합니다. 변수를 선언할 때 일단 `val`로 시작하고, 정말로 값을 나중에 바꿔야 하는 상황이 생기면 그때 `var`로 고칩니다. 반대로 습관적으로 `var`을 먼저 쓰고 보는 것은 좋은 습관이 아닙니다. 이 사고방식은 18장 좋은 Kotlin 코드 작성 습관에서 다시 강조됩니다.

## 기본 타입

Kotlin에는 숫자, 논리값, 문자, 문자열을 표현하는 기본 타입들이 있습니다. 대표적인 것들을 살펴봅시다.

```kotlin
val score: Int = 95           // 정수
val average: Double = 87.5    // 실수
val isPassed: Boolean = true  // 논리값
val grade: Char = 'A'         // 문자 (단일 인용부호)
val comment: String = "우수함" // 문자열 (이중 인용부호)
```

숫자 타입만 좀 더 세분화하면 다음과 같습니다.

| 타입 | 설명 |
|---|---|
| `Int` | 32비트 정수. 가장 흔히 쓰는 정수 타입 |
| `Long` | 64비트 정수. 큰 값이 필요할 때 사용, 리터럴 끝에 `L` 표기 (`10000000000L`) |
| `Double` | 64비트 실수. 소수를 표현할 때 기본으로 쓰는 타입 |
| `Float` | 32비트 실수. `f` 접미사 필요 (`3.14f`) |
| `Boolean` | `true` 또는 `false` |
| `Char` | 문자 하나, 단일 인용부호 사용 |
| `String` | 문자열, 이중 인용부호 사용 |

### 모든 것이 객체다

자바를 먼저 배운 사람이라면 `int`, `double` 같은 원시 타입(primitive type)과 `Integer`, `Double` 같은 래퍼 클래스(wrapper class)가 구분되어 있다는 점이 익숙할 것입니다. Kotlin은 이 구분을 언어 차원에서 없앴습니다. `Int`, `Double`, `Boolean`을 포함한 모든 타입은 겉보기에 객체처럼 다뤄집니다.

```kotlin
val n: Int = 10
println(n.toString())     // Int도 객체처럼 메서드를 호출할 수 있다
println(n.coerceAtLeast(5))
```

물론 실제로 컴파일된 바이트코드 수준에서는 성능을 위해 가능한 경우 자바의 원시 타입으로 최적화되어 처리됩니다. 하지만 우리가 코드를 작성하는 입장에서는 그런 내부 사정을 신경 쓸 필요가 없습니다. `Int`도 `String`도 모두 똑같이 메서드를 가진 객체로 취급하면 됩니다. 이런 일관성은 나중에 9장에서 클래스를 직접 만들 때, 그리고 14장에서 확장 함수를 배울 때 왜 Kotlin이 이렇게 설계되었는지 이해하는 데 도움이 됩니다.

## 타입 추론

지금까지 예제에서 타입을 명시적으로 적었지만, 사실 Kotlin은 초깃값만 보면 타입을 스스로 알아낼 수 있습니다. 이것을 타입 추론(type inference)이라고 합니다.

```kotlin
val score = 95        // Int로 추론
val average = 87.5    // Double로 추론
val name = "김코틀린"  // String으로 추론
val isPassed = true   // Boolean으로 추론
```

타입을 직접 명시할 수도 있고, 추론에 맡길 수도 있습니다. 실무에서는 초깃값이 있는 지역 변수라면 타입을 생략하는 것이 일반적입니다. 코드가 간결해지고, 읽는 사람도 우변의 값만 보면 타입을 쉽게 짐작할 수 있기 때문입니다. 다만 함수의 매개변수나 반환 타입처럼 초깃값이 없는 경우, 또는 코드의 의도를 명확히 드러내고 싶은 경우에는 타입을 명시하는 편이 좋습니다. 함수의 타입 표기 규칙은 7장에서 자세히 다룹니다.

## 문자열 템플릿

문자열 안에 변수 값이나 계산식을 끼워 넣고 싶을 때, Kotlin은 문자열 템플릿(string template)이라는 편리한 문법을 제공합니다.

```kotlin
val name = "김코틀린"
val age = 20

println("이름: $name, 나이: $age")               // 변수 하나만 넣을 때는 $변수명
println("내년 나이: ${age + 1}")                  // 표현식은 ${ } 로 감싼다
println("${name}님은 성인입니다: ${age >= 19}")
```

단순히 변수 하나를 넣을 때는 `$name`처럼 달러 기호만 붙이면 됩니다. 반면 `age + 1`처럼 계산이 필요한 표현식을 넣을 때는 `${ }`로 감싸야 합니다. 이 방식은 문자열을 `+` 연산자로 이어붙이는 것보다 훨씬 읽기 쉽고 실수도 적습니다.

```kotlin
// 비교: 전통적인 문자열 연결 방식
println("이름: " + name + ", 나이: " + age)

// Kotlin다운 방식
println("이름: $name, 나이: $age")
```

## 형변환

Kotlin은 타입 간 자동 변환을 매우 엄격하게 제한합니다. 예를 들어 `Int` 값을 `Double`이 필요한 곳에 그냥 넣을 수 없습니다.

```kotlin
val count: Int = 10
// val price: Double = count   // 컴파일 오류: 자동 변환되지 않는다
val price: Double = count.toDouble()   // 명시적으로 변환해야 한다
```

자바에서는 `int`가 `double`로 자동 확장(widening)되는 경우가 많지만, Kotlin은 이런 암묵적 변환이 실수를 유발할 수 있다고 보고 허용하지 않습니다. 대신 각 숫자 타입은 `toInt()`, `toDouble()`, `toLong()`, `toFloat()`, `toChar()` 등의 변환 함수를 제공합니다.

```kotlin
val d: Double = 3.9
val i: Int = d.toInt()          // 3 (소수부는 버려진다, 반올림이 아님)

val s: String = "42"
val n: Int = s.toInt()          // 문자열을 숫자로 변환
val n2: Int? = "abc".toIntOrNull()  // 변환할 수 없으면 null 반환

val num = 100
val text: String = num.toString()   // 숫자를 문자열로 변환
```

`toIntOrNull()`처럼 이름에 `OrNull`이 붙은 함수들은 변환에 실패했을 때 예외를 던지는 대신 `null`을 반환합니다. 이 `null`이라는 값과 물음표(`?`)가 붙은 타입이 무엇을 의미하는지는 8장 null 안전성에서 본격적으로 다룹니다. 지금은 "값이 없을 수도 있다"는 상황을 표현하는 방법이 따로 있다는 정도만 기억해두면 됩니다.

## 요약

- `val`은 읽기 전용, `var`은 가변 변수를 선언한다. 특별한 이유가 없다면 `val`을 기본으로 사용하는 것이 안전하고 예측 가능한 코드를 만든다.
- Kotlin의 기본 타입에는 `Int`, `Long`, `Double`, `Float`, `Boolean`, `Char`, `String` 등이 있으며, 자바와 달리 원시 타입과 객체 타입의 구분 없이 모두 객체처럼 다뤄진다.
- 초깃값이 있으면 타입을 생략해도 컴파일러가 타입을 추론해준다.
- 문자열 템플릿(`$변수`, `${표현식}`)을 사용하면 문자열 결합을 간결하게 표현할 수 있다.
- 서로 다른 타입 간에는 자동 변환이 일어나지 않으며, `toInt()`, `toDouble()` 같은 명시적 변환 함수를 사용해야 한다.
