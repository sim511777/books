프로그램은 위에서 아래로 순서대로 실행되는 코드만으로는 유용한 일을 하기 어렵습니다. 상황에 따라 다른 코드를 실행해야 할 때가 훨씬 많죠. 이번 장에서는 Kotlin에서 조건에 따라 흐름을 분기하는 두 가지 도구, `if`와 `when`을 다룹니다. 특히 Kotlin의 `if`와 `when`은 Java의 동명 구문과 겉모습은 비슷하지만, 값을 반환하는 **표현식**으로도 쓸 수 있다는 점에서 훨씬 강력합니다. 이 차이를 이해하면 이후 7장에서 함수의 반환값을 다루거나 15장에서 `sealed class`와 `when`을 결합할 때 훨씬 자연스럽게 코드를 읽고 쓸 수 있습니다.

## if의 기본 형태

가장 단순한 형태는 이미 3장과 4장의 예제에서 몇 차례 본 적이 있을 겁니다.

```kotlin
fun main() {
    val temperature = 28

    if (temperature > 30) {
        println("무척 더운 날씨입니다")
    } else if (temperature > 20) {
        println("따뜻한 날씨입니다")
    } else {
        println("쌀쌀한 날씨입니다")
    }
}
```

조건은 반드시 `Boolean` 값이어야 합니다. Java나 C 계열 언어처럼 정수 0을 `false`로, 1을 `true`로 취급하는 암묵적 변환은 Kotlin에 존재하지 않습니다. 이는 4장에서 살펴본 Kotlin의 엄격한 타입 시스템과 일관된 설계입니다.

중괄호는 문장이 하나뿐이라면 생략할 수 있지만, 실무에서는 코드 수정 시 실수를 줄이기 위해 한 줄짜리 `if`라도 중괄호를 쓰는 습관을 권장합니다.

```kotlin
if (temperature > 30) println("무척 더운 날씨입니다")
```

## 표현식으로서의 if

Kotlin의 `if`가 Java의 `if`와 결정적으로 다른 지점은, `if`가 **값을 만들어내는 표현식**으로 쓰일 수 있다는 것입니다. 각 분기의 마지막 줄이 그 분기의 값이 되고, `if` 전체는 조건에 따라 선택된 값을 갖습니다.

```kotlin
fun main() {
    val score = 76

    val grade = if (score >= 90) {
        "A"
    } else if (score >= 80) {
        "B"
    } else if (score >= 70) {
        "C"
    } else {
        "F"
    }

    println("점수 $score 는 $grade 등급입니다")
}
```

이렇게 하면 Java에서 흔히 보던 아래와 같은 패턴이 사라집니다.

```kotlin
// 이렇게 변수를 미리 선언하고 나중에 대입하는 방식은 Kotlin에서는 불필요합니다
var grade: String
if (score >= 90) {
    grade = "A"
} else {
    grade = "F"
}
```

값을 만드는 `if`를 쓰려면 반드시 `else` 분기가 있어야 합니다. `else`가 없으면 조건이 거짓일 때 어떤 값을 반환할지 컴파일러가 알 수 없기 때문입니다. 참고로 조건문이 아니라 명령문(단순히 부수 효과를 위해 실행하는 코드)으로 쓸 때는 `else` 없이 써도 됩니다.

간단한 최댓값 비교처럼 삼항 연산자가 그리울 수 있는 상황에서도, Kotlin은 별도의 `?:` 삼항 연산자를 두지 않고 `if` 표현식으로 대체합니다.

```kotlin
fun maxOf(a: Int, b: Int): Int = if (a > b) a else b
```

이런 한 줄짜리 함수는 7장에서 배울 함수의 단일 표현식 문법과 자연스럽게 이어집니다.

## when: Java의 switch를 넘어서

여러 개의 `else if`가 이어지면 코드를 읽기 어려워집니다. 이럴 때 Kotlin은 `when`이라는 고유한 구문을 제공합니다. `when`은 Java의 `switch`와 비슷한 자리에서 쓰이지만 훨씬 유연합니다. Java의 `switch`는 정수, 문자열, enum 같은 제한된 타입의 **동등 비교**만 가능했던 반면(최신 Java에서 패턴 매칭이 추가되긴 했지만), Kotlin의 `when`은 처음부터 임의의 타입에 대한 조건, 범위 검사, 타입 검사까지 하나의 구문 안에서 처리할 수 있도록 설계되었습니다.

가장 기본적인 형태부터 보겠습니다.

```kotlin
fun main() {
    val dayOfWeek = 3

    val dayName = when (dayOfWeek) {
        1 -> "월요일"
        2 -> "화요일"
        3 -> "수요일"
        4 -> "목요일"
        5 -> "금요일"
        6, 7 -> "주말"
        else -> "알 수 없는 요일"
    }

    println(dayName)
}
```

`6, 7 -> "주말"`처럼 쉼표로 여러 값을 한 번에 매칭할 수 있고, Java처럼 각 분기 끝에 `break`를 써주지 않아도 됩니다. Kotlin의 `when`은 분기가 매칭되면 자동으로 종료되며, `break`가 없어서 다음 분기로 흘러 들어가는(fall-through) Java의 실수 유발 패턴 자체가 존재하지 않습니다.

## when을 조건문으로 사용하기: 범위와 타입 검사

`when`이 진짜 강력해지는 지점은 각 분기의 조건에 등호 비교 이외의 것도 넣을 수 있다는 점입니다. 대상 값을 괄호에 넣지 않고 각 분기에 독립적인 `Boolean` 조건을 적을 수도 있습니다.

```kotlin
fun describeTemperature(temp: Int): String = when {
    temp < 0 -> "영하입니다"
    temp in 0..15 -> "쌀쌀합니다"
    temp in 16..25 -> "적당합니다"
    else -> "덥습니다"
}
```

`in` 뒤에 범위(`0..15`)를 두면 4장에서 다룬 범위 문법을 그대로 조건으로 활용할 수 있습니다. 대상값 없이 쓰는 `when`은 사실상 `if`-`else if` 연쇄를 대체하는 더 읽기 좋은 표현이라고 볼 수 있습니다.

`when`은 타입 검사도 지원합니다. `is` 키워드를 분기 조건에 쓰면 값의 실제 타입에 따라 분기할 수 있습니다.

```kotlin
fun describe(value: Any): String = when (value) {
    is Int -> "정수: $value"
    is String -> "문자열, 길이는 ${value.length}"
    is Boolean -> "불리언 값: $value"
    else -> "알 수 없는 타입"
}
```

여기서 눈여겨볼 부분은 `is String` 분기 안에서 `value.length`를 바로 쓸 수 있다는 점입니다. Kotlin 컴파일러가 타입 검사를 통해 그 분기 내부에서는 `value`가 `String`임을 이미 알고 있고, 별도의 형변환 코드 없이 스마트 캐스트를 적용해 줍니다. 이 스마트 캐스트 개념은 8장의 null 안전성, 15장의 `sealed class` 활용에서 반복해서 등장하는 핵심 아이디어입니다.

`when`을 표현식으로 쓸 때(즉 결과를 변수에 대입하거나 함수의 반환값으로 쓸 때)는 `if`와 마찬가지로 모든 경우를 다뤄야 합니다. 대상이 `Boolean`이 아니거나 `enum`이 아니라면 컴파일러가 모든 경우를 다뤘는지 완벽히 판단할 수 없으므로, 이때는 `else` 분기를 반드시 작성해야 컴파일됩니다. 반면 명령문으로만 쓸 때는 `else`를 생략해도 되지만, 놓친 경우를 조용히 무시하게 되는 버그의 원인이 될 수 있어 습관적으로 `else`를 넣는 편이 안전합니다.

이 장에서는 `when`을 조건문으로 쓰는 기본기만 다뤘습니다. `sealed class`와 함께 쓰면 `else` 없이도 컴파일러가 "모든 경우를 다 처리했다"고 보장해 주는 훨씬 강력한 패턴이 있는데, 이는 15장에서 자세히 다룹니다.

## 중첩 조건문과 가독성

조건문은 서로 안에 들어갈 수 있습니다. 하지만 중첩이 깊어지면 코드는 급격히 읽기 어려워집니다.

```kotlin
// 가독성이 떨어지는 중첩 예시
fun checkAccess(age: Int, hasTicket: Boolean, isMember: Boolean): String {
    if (age >= 18) {
        if (hasTicket) {
            if (isMember) {
                return "입장 가능, 회원 혜택 적용"
            } else {
                return "입장 가능"
            }
        } else {
            return "입장 불가: 티켓 필요"
        }
    } else {
        return "입장 불가: 연령 미달"
    }
}
```

이런 코드는 조건을 하나씩 되짚어야 흐름을 이해할 수 있습니다. 이를 개선하는 대표적인 방법은 조건이 거짓일 때 곧바로 함수를 빠져나가는 **조기 반환(early return)** 패턴입니다.

```kotlin
fun checkAccess(age: Int, hasTicket: Boolean, isMember: Boolean): String {
    if (age < 18) return "입장 불가: 연령 미달"
    if (!hasTicket) return "입장 불가: 티켓 필요"
    if (isMember) return "입장 가능, 회원 혜택 적용"
    return "입장 가능"
}
```

들여쓰기 깊이가 줄어들고, 각 조건이 예외적인 상황을 걸러내는 하나의 문장으로 명확하게 드러납니다. 또한 여러 개의 `Boolean` 조건을 `&&`, `||`로 조합해 하나의 `if`로 합칠 수 있다면(4장에서 배운 논리 연산자), 억지로 중첩시키기보다 조합하는 편이 낫습니다.

```kotlin
if (age >= 18 && hasTicket) {
    // ...
}
```

일반적인 기준으로는 중첩 깊이가 2~3단계를 넘어가면 조기 반환이나 함수 분리, 혹은 `when`으로의 전환을 고려해 볼 신호로 삼는 것이 좋습니다.

## 요약

- Kotlin의 `if`는 문장이자 동시에 값을 반환하는 **표현식**으로 쓸 수 있습니다. 표현식으로 쓸 때는 모든 경로에 값이 있어야 하므로 `else`가 필수입니다.
- `when`은 Java의 `switch`보다 강력한 Kotlin 고유 구문으로, 값 매칭뿐 아니라 범위(`in`), 임의의 `Boolean` 조건, 타입 검사(`is`)까지 표현할 수 있습니다.
- `when`의 `is` 분기 안에서는 스마트 캐스트가 적용되어 별도의 형변환 없이 해당 타입의 멤버를 바로 사용할 수 있습니다.
- `when`을 값으로 쓸 때는 모든 경우를 다뤄야 하며, 컴파일러가 완전성을 보장하지 못하는 경우 `else`가 반드시 필요합니다.
- 중첩 조건문이 깊어지면 조기 반환 패턴이나 논리 연산자 조합으로 평탄화하는 것이 가독성에 도움이 됩니다.

## 연습문제

1. 정수 하나를 입력받아 양수, 음수, 0인지 판별해 문자열로 반환하는 함수를 `if` 표현식으로 작성해 보세요.
2. 월(1~12)을 나타내는 정수를 받아 해당 계절("봄", "여름", "가을", "겨울")을 반환하는 함수를 `when`과 범위(`in`)를 이용해 작성해 보세요.
3. `Any` 타입의 값을 받아 그 값이 `Int`, `Double`, `String` 중 무엇인지에 따라 다른 메시지를 출력하는 함수를 `when (value) { is ... -> }` 형태로 작성해 보세요.
4. 3단계 이상 중첩된 `if`-`else` 코드를 하나 임의로 작성한 뒤, 조기 반환 패턴을 이용해 중첩 없는 코드로 다시 작성해 보세요.
5. 나이, 회원 여부, 할인 쿠폰 소지 여부 세 가지 `Boolean`/`Int` 조건을 받아 최종 할인율을 계산하는 함수를 작성하되, 중첩 `if` 대신 `when { }` 형태의 조건문으로 구현해 보세요.
