## 들어가며

1장에서 Kotlin이 어떤 언어인지 큰 그림을 살펴봤다면, 이 장에서는 실제로 첫 Kotlin 프로그램을 작성하고 실행해 봅니다. 코드를 한 줄씩 뜯어보면서 각 부분이 무슨 뜻인지 확인하고, 우리가 작성한 소스 코드가 어떤 과정을 거쳐 실제로 화면에 출력을 만들어내는지도 함께 이해해 보겠습니다. 마지막으로는 처음 Kotlin을 접할 때 자주 마주치는 오류들과 그 대처법도 정리합니다.

## Hello World 작성하기

가장 먼저 만들어 볼 프로그램은 화면에 문구를 출력하는 간단한 프로그램입니다. IntelliJ IDEA에서 새 Kotlin 프로젝트를 만든 뒤, `src` 폴더 아래에 `Main.kt` 파일을 만들고 다음 코드를 입력합니다.

```kotlin
fun main() {
    println("Hello, Kotlin!")
}
```

이 코드를 실행하면 콘솔에 다음과 같이 출력됩니다.

```
Hello, Kotlin!
```

단 세 줄뿐인 이 코드에도 Kotlin 문법의 여러 요소가 담겨 있습니다. 하나씩 뜯어보겠습니다.

### `fun main()` — 프로그램의 시작점

`fun`은 function(함수)을 뜻하는 키워드로, 함수를 선언할 때 사용합니다. `main`은 함수의 이름인데, 이 이름은 임의로 정한 것이 아니라 Kotlin이 정한 약속입니다. JVM이 프로그램을 실행할 때 가장 먼저 찾아서 호출하는 함수가 바로 `main`이기 때문입니다. 즉 `main` 함수는 "프로그램이 시작되는 지점(entry point)"입니다.

괄호 `()`는 이 함수가 받는 매개변수 목록을 나타내는데, 지금은 비어 있으므로 매개변수가 없는 함수입니다. 참고로 Kotlin의 `main` 함수는 명령줄 인자를 받아야 할 때 `fun main(args: Array<String>)`처럼 매개변수를 추가할 수도 있지만, 인자를 사용하지 않는다면 생략해도 됩니다. 함수에 대한 자세한 내용은 7장에서 다룹니다.

### 중괄호 `{ }` — 함수의 본문

여는 중괄호 `{`와 닫는 중괄호 `}` 사이의 영역이 함수의 본문(body)입니다. 이 함수가 호출되었을 때 실제로 실행되는 코드가 이 안에 들어갑니다. Kotlin은 중괄호로 코드 블록의 범위를 표시하는데, 이는 Java, C, JavaScript 등 많은 언어와 공통된 방식입니다.

### `println(...)` — 표준 출력 함수

`println`은 Kotlin 표준 라이브러리가 기본으로 제공하는 함수로, 괄호 안의 값을 콘솔에 출력하고 줄바꿈까지 해 줍니다. 이름은 "print line"의 줄임말입니다. 만약 줄바꿈 없이 출력하고 싶다면 `print`를 사용하면 됩니다. 문자열은 큰따옴표(`" "`)로 감싸서 표현하며, 이는 3장에서 다룰 `String` 타입의 값입니다.

## 세미콜론은 선택 사항

Java 코드를 작성해 본 경험이 있다면 문장 끝에 세미콜론(`;`)을 붙이는 데 익숙할 것입니다. Kotlin에서는 세미콜론이 문장의 끝을 표시하는 데 필수가 아닙니다. 컴파일러가 줄바꿈을 기준으로 문장이 끝났는지를 대부분 스스로 판단하기 때문입니다. 즉 다음 두 코드는 완전히 동일하게 동작합니다.

```kotlin
fun main() {
    println("Hello, Kotlin!")
}
```

```kotlin
fun main() {
    println("Hello, Kotlin!");
}
```

다만 한 줄에 여러 문장을 이어 쓰고 싶다면 세미콜론으로 구분해야 합니다.

```kotlin
fun main() {
    val a = 1; val b = 2
    println(a + b)
}
```

이런 스타일은 가독성을 떨어뜨리므로 실무에서는 거의 쓰지 않으며, 한 줄에 한 문장씩 작성하고 세미콜론은 생략하는 것이 Kotlin의 일반적인 코드 스타일입니다. 이러한 스타일 관례는 18장에서 더 폭넓게 다룹니다.

## 소스 코드가 실행되기까지: 컴파일과 바이트코드

`println("Hello, Kotlin!")`이라는 코드를 작성한 것만으로는 컴퓨터가 곧바로 이해하지 못합니다. 우리가 작성한 텍스트 파일이 실제로 실행되기까지는 몇 단계를 거칩니다.

1. **소스 코드 작성**: 우리가 `.kt` 확장자를 가진 파일에 Kotlin 문법으로 코드를 작성합니다.
2. **컴파일**: Kotlin 컴파일러(`kotlinc`)가 이 소스 코드를 읽어 문법 오류나 타입 오류가 없는지 검사하고, 문제가 없으면 바이트코드(bytecode)라는 중간 형식으로 변환합니다. 이 바이트코드는 `.class` 파일에 저장되며, 사람이 읽는 코드가 아니라 JVM이 이해할 수 있는 저수준 명령어 집합입니다.
3. **실행**: JVM(Java Virtual Machine)이 이 바이트코드를 읽어 실제 컴퓨터가 처리할 수 있는 동작으로 해석하고 실행합니다.

여기서 중요한 점은, Kotlin 컴파일러가 만들어내는 바이트코드가 Java 컴파일러(`javac`)가 만들어내는 바이트코드와 형식이 같다는 것입니다. 그래서 JVM은 이 바이트코드가 원래 Kotlin 코드였는지 Java 코드였는지 구분하지 않고 동일하게 실행할 수 있습니다. 이것이 1장에서 언급한 "Java와의 100% 상호운용성"이 가능한 근본적인 이유입니다. 전체 흐름을 그림으로 정리하면 다음과 같습니다.

```text
+----------------+   컴파일   +--------------------+   생성   +------------------+  실행  +------------------+
|   소스 코드    | --------> |  Kotlin 컴파일러   | ------> |    바이트코드    | -----> |       JVM        |
|   Main.kt      | (kotlinc) |     kotlinc         |         |  MainKt.class    |        | Java Virtual     |
|                |           |  문법 검사          |         |  JVM이 이해하는  |        | Machine          |
| fun main() {   |           |  타입 추론 · 최적화|         |  중간 표현 형식  |        |------------------|
|   println(...) |           |                     |         |                  |        |   프로그램 실행   |
+----------------+           +--------------------+         +------------------+        +------------------+

Kotlin 소스 코드는 컴파일러를 거쳐 Java와 동일한 형식의 바이트코드로 변환되고,
이 바이트코드를 JVM이 해석하여 실제 프로그램을 실행합니다.
(Java 소스 코드도 javac 컴파일러를 통해 같은 형식의 바이트코드로 변환되어, 동일한 JVM에서 함께 실행될 수 있습니다.)
```

IntelliJ IDEA에서는 이 과정을 우리가 직접 명령어로 다루지 않아도 됩니다. `main` 함수 옆의 실행 버튼(초록색 삼각형)을 누르면 IDE가 내부적으로 컴파일과 실행을 모두 처리해 콘솔에 결과를 보여줍니다.

## 흔히 마주치는 오류와 대처법

처음 Kotlin을 작성할 때 자주 마주치는 오류 몇 가지와 그 원인을 정리해 봅니다.

**1. `main` 함수를 찾을 수 없다는 오류**

```
Error: Main method not found in class MainKt
```

`main` 함수의 이름을 잘못 적었거나(`Main`처럼 대문자로 시작하는 경우), 함수가 클래스 안에 있는데 `companion object` 같은 별도 설정 없이 작성한 경우 발생할 수 있습니다. 함수 이름이 정확히 `main`인지, 그리고 파일의 최상위 레벨(클래스 밖)에 작성되어 있는지 확인합니다.

**2. 괄호나 중괄호 짝이 맞지 않는 오류**

```
Error: expecting '}'
```

여는 괄호나 중괄호를 열어놓고 닫지 않은 경우입니다. IntelliJ IDEA는 짝이 맞는 괄호를 자동으로 색으로 강조해 주므로, 오류가 나면 커서를 괄호 옆에 두고 짝이 되는 괄호가 올바른 위치에 있는지 확인하는 습관을 들이면 좋습니다.

**3. 문자열의 인용부호를 닫지 않은 오류**

```kotlin
println("Hello, Kotlin!)  // 닫는 큰따옴표 누락
```

문자열을 감싸는 큰따옴표 중 하나를 빠뜨리면 컴파일러가 문자열이 어디서 끝나는지 알 수 없어 오류를 냅니다. 문자열은 항상 여는 인용부호와 닫는 인용부호가 짝을 이루어야 합니다.

**4. 함수 이름이나 변수 이름의 대소문자 오류**

Kotlin은 대소문자를 구분하는 언어이므로 `println`과 `Println`은 완전히 다른 이름으로 취급됩니다. 오류 메시지에 "Unresolved reference"가 뜬다면 이름의 오타나 대소문자를 가장 먼저 확인해 보는 것이 좋습니다.

이런 오류들은 특별한 게 아니라 모든 언어를 처음 배울 때 누구나 겪는 과정입니다. 오류 메시지를 읽고 원인을 추적해 보는 경험 자체가 실력을 쌓는 좋은 방법이 됩니다.

## 요약

- 첫 Kotlin 프로그램은 `fun main() { println("...") }` 세 줄로 작성할 수 있으며, `main`은 프로그램의 시작점, `println`은 표준 출력 함수입니다.
- Kotlin에서는 세미콜론이 선택 사항이며, 한 줄에 한 문장씩 작성하고 세미콜론을 생략하는 것이 일반적인 스타일입니다.
- Kotlin 소스 코드는 컴파일러(`kotlinc`)를 거쳐 Java와 동일한 형식의 바이트코드로 변환되고, 이 바이트코드는 JVM이 실행합니다.
- Kotlin과 Java의 바이트코드 형식이 같다는 사실이 두 언어 간 100% 상호운용성의 근본적인 이유입니다.
- 초보자가 자주 마주치는 오류는 대부분 함수 이름, 괄호 짝, 인용부호, 대소문자와 관련된 단순한 실수이며, 오류 메시지를 차근차근 읽는 습관이 중요합니다.
