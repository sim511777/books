## 이 장에서 다루는 내용

프로그램이 다루는 데이터는 결국 어딘가에 저장되어야 하고, 다시 읽혀야 합니다. 설정 파일을 읽거나, 로그를 남기거나, 데이터를 CSV로 내보내는 작업은 실무 코드에서 빠지지 않습니다. 15장 Java 상호운용에서 배웠듯 Clojure는 JVM 위에서 동작하므로, 자바의 파일 입출력 클래스(`java.io.File`, `Reader`, `Writer` 등)를 그대로 쓸 수도 있습니다. 하지만 그렇게 하면 코드가 장황해지기 때문에, Clojure는 흔한 파일 작업을 짧게 표현할 수 있는 함수들을 `clojure.core`와 `clojure.java.io`에 준비해 두었습니다.

이번 장에서는 `slurp`와 `spit`으로 파일을 통째로 읽고 쓰는 방법, `with-open`으로 자원을 안전하게 정리하는 방법, `clojure.java.io`의 `reader`/`writer`로 좀 더 세밀하게 입출력 스트림을 다루는 방법, 그리고 `line-seq`로 파일을 줄 단위 시퀀스로 처리하는 방법을 순서대로 살펴봅니다.

## slurp: 파일 전체를 문자열로 읽기

`slurp`는 파일(또는 URL, 각종 입력 소스)의 내용 전체를 한 번에 읽어 문자열로 돌려주는 함수입니다. "빨아들인다"는 이름 그대로, 작은 파일을 간단히 읽을 때 가장 먼저 떠올리는 함수입니다.

먼저 예제로 쓸 파일을 하나 만들어 보겠습니다. (파일 쓰기는 잠시 뒤에 나올 `spit`을 미리 써서 준비합니다.)

```clojure
(spit "greeting.txt" "안녕하세요, Clojure!\n반가워요.")
```

이제 `slurp`로 파일 내용을 읽어옵니다.

```clojure
(slurp "greeting.txt")
;; => "안녕하세요, Clojure!\n반가워요."

(println (slurp "greeting.txt"))
;; 안녕하세요, Clojure!
;; 반가워요.
;; => nil
```

`slurp`가 반환하는 값은 평범한 문자열이므로, 3장 기본 문법과 데이터 타입에서 배운 문자열 함수나 정규식 함수를 그대로 적용할 수 있습니다.

```clojure
(count (slurp "greeting.txt"))
;; => 21

(clojure.string/split (slurp "greeting.txt") #"\n")
;; => ["안녕하세요, Clojure!" "반가워요."]
```

인코딩을 명시하고 싶다면 `:encoding` 옵션을 줄 수 있습니다.

```clojure
(slurp "greeting.txt" :encoding "UTF-8")
```

`slurp`는 파일 경로 문자열뿐 아니라 URL 문자열도 받을 수 있어서, 웹에 있는 텍스트 자원을 그 자리에서 읽어올 때도 종종 사용됩니다.

```clojure
;; 네트워크 상황에 따라 결과가 달라질 수 있는 예시입니다.
(slurp "https://example.com")
```

## spit: 문자열을 파일에 쓰기

`spit`은 `slurp`의 반대 방향, 즉 문자열을 파일에 써 넣는 함수입니다. "뱉어낸다"는 이름처럼 값을 그대로 파일로 흘려보냅니다.

```clojure
(spit "notes.txt" "첫 번째 메모입니다.")
;; => nil
```

기본적으로 `spit`은 파일이 이미 있으면 내용을 덮어씁니다. 기존 내용 뒤에 이어서 쓰고 싶다면 `:append true` 옵션을 사용합니다.

```clojure
(spit "notes.txt" "\n두 번째 메모입니다." :append true)

(println (slurp "notes.txt"))
;; 첫 번째 메모입니다.
;; 두 번째 메모입니다.
;; => nil
```

`spit`은 문자열이 아닌 값도 받을 수 있지만, 내부적으로 `str`을 호출해 문자열로 바꾼 뒤에 씁니다. 그래서 맵이나 벡터를 그대로 넘기면 사람이 읽기엔 애매한 형태로 저장될 수 있습니다.

```clojure
(spit "data.txt" {:name "클로저" :year 2007})

(slurp "data.txt")
;; => "{:name \"클로저\", :year 2007}"
```

흥미롭게도 이 출력은 Clojure의 데이터 리터럴 문법과 동일한 형태이기 때문에, 나중에 `clojure.edn/read-string`으로 다시 읽어 들이면 원래의 맵으로 복원할 수 있습니다. 이런 식으로 EDN(Extensible Data Notation) 형식을 활용해 데이터를 저장하고 복원하는 방식은 실전에서 설정 파일이나 간단한 데이터 저장에 자주 쓰입니다.

```clojure
(require '[clojure.edn :as edn])

(edn/read-string (slurp "data.txt"))
;; => {:name "클로저", :year 2007}
```

`slurp`와 `spit`은 편리하지만 파일 전체를 메모리에 올린다는 한계가 있습니다. 수백 메가바이트짜리 로그 파일을 통째로 읽으면 메모리 부담이 커지므로, 그런 경우에는 이어서 소개할 스트림 기반 접근을 사용하는 것이 좋습니다.

## 자원 정리와 with-open

자바에서 파일을 다루려면 `FileReader`나 `FileWriter` 같은 스트림 객체를 열고, 작업이 끝나면 반드시 닫아줘야 합니다. 스트림을 닫지 않고 방치하면 운영체제가 관리하는 파일 핸들이 계속 점유된 채로 남아, 결국 "파일을 너무 많이 열었다"는 오류로 이어질 수 있습니다. 자바에서는 이 문제를 `try`-with-resources 구문으로 해결하는데, Clojure에는 그와 같은 역할을 하는 `with-open` 매크로가 있습니다.

```clojure
(with-open [reader (clojure.java.io/reader "greeting.txt")]
  (println (slurp reader)))
;; 안녕하세요, Clojure!
;; 반가워요.
;; => nil
```

`with-open`은 바인딩 형태(`[symbol 자원-생성-표현식 ...]`)로 하나 이상의 자원을 열고, 본문을 실행한 뒤 본문이 정상적으로 끝나든 예외가 발생하든 상관없이 각 자원의 `.close` 메서드를 자동으로 호출해줍니다. 14장 예외 처리와 에러 다루기에서 다룬 `try`/`finally`와 비슷한 안전망을 훨씬 짧은 코드로 얻는 셈입니다. 사실 `with-open`을 매크로 전개해보면 내부적으로 정확히 `try`/`finally`와 `.close` 호출로 이루어져 있습니다. 12장 매크로 기초에서 다룬 것처럼, 매크로는 반복되는 패턴을 감춰서 코드를 짧고 안전하게 만들어주는 도구입니다.

여러 자원을 동시에 열 수도 있습니다.

```clojure
(with-open [reader (clojure.java.io/reader "greeting.txt")
            writer (clojure.java.io/writer "greeting-copy.txt")]
  (doseq [line (line-seq reader)]
    (.write writer line)
    (.newLine writer)))
```

이 예제에서는 파일을 읽는 `reader`와 쓰는 `writer`를 동시에 열어서, 한쪽에서 읽은 줄을 다른 쪽에 그대로 옮겨 적었습니다. `with-open` 블록이 끝나면 두 자원 모두 자동으로 닫힙니다.

## clojure.java.io의 reader와 writer

`clojure.java.io` 네임스페이스는 자바의 입출력 클래스를 좀 더 편하게 다루기 위한 함수 모음입니다. 이 장에서 가장 자주 쓰는 두 함수는 `reader`와 `writer`입니다.

```clojure
(require '[clojure.java.io :as io])
```

`io/reader`는 파일 경로, `File` 객체, URL, 심지어 이미 열려 있는 스트림 등 다양한 입력을 받아 하나의 통일된 `Reader`(문자 단위 입력 스트림)로 바꿔줍니다. `io/writer` 역시 마찬가지 방식으로 `Writer`를 만들어 줍니다. `slurp`와 `spit`도 사실 내부적으로 `io/reader`와 `io/writer`를 사용해 구현되어 있습니다.

```clojure
(with-open [w (io/writer "log.txt")]
  (.write w "서버가 시작되었습니다.\n")
  (.write w "설정 파일을 불러왔습니다.\n"))

(with-open [r (io/reader "log.txt")]
  (println (slurp r)))
;; 서버가 시작되었습니다.
;; 설정 파일을 불러왔습니다.
;; => nil
```

`io/writer`도 `:append true` 옵션을 지원해서, `spit`과 마찬가지로 기존 파일 뒤에 이어 쓸 수 있습니다.

```clojure
(with-open [w (io/writer "log.txt" :append true)]
  (.write w "요청을 처리했습니다.\n"))
```

`io/file` 함수는 경로 문자열을 `java.io.File` 객체로 바꿔주는데, 파일의 존재 여부 확인, 삭제, 디렉터리 목록 조회 같은 작업을 할 때 유용합니다.

```clojure
(def f (io/file "greeting.txt"))

(.exists f)
;; => true

(.length f)
;; => 21

(.getName f)
;; => "greeting.txt"

(io/delete-file "greeting-copy.txt")
;; => true
```

이렇게 `File` 객체가 등장하면 15장에서 배운 인스턴스 메서드 호출 문법(`.exists`, `.length`, `.getName`)이 그대로 적용된다는 점을 알 수 있습니다. `clojure.java.io`는 자바 입출력 API를 완전히 대체하는 것이 아니라, 자주 쓰는 부분을 짧게 감싸 놓은 얇은 층에 가깝습니다.

## line-seq: 파일을 줄 단위 시퀀스로 다루기

파일을 한 번에 통째로 읽기보다, 줄 단위로 하나씩 처리하고 싶을 때가 많습니다. 예를 들어 수백만 줄짜리 로그 파일에서 특정 조건에 맞는 줄만 찾아내는 상황을 생각해 보면, 파일 전체를 메모리에 올리는 대신 한 줄씩 읽으면서 처리하는 편이 훨씬 안전합니다.

`line-seq`는 열려 있는 `Reader`를 받아서, 각 줄을 원소로 하는 지연 시퀀스(lazy sequence)를 만들어 줍니다. 8장 시퀀스 추상화와 고차 함수에서 다룬 지연 평가(lazy evaluation) 개념이 여기서도 그대로 적용됩니다. 즉, `line-seq`가 반환한 시퀀스는 실제로 필요한 시점에만 파일에서 한 줄씩 읽어옵니다.

먼저 여러 줄로 이루어진 예제 파일을 만들어 보겠습니다.

```clojure
(spit "fruits.txt"
      (clojure.string/join "\n"
                            ["사과,500"
                             "바나나,300"
                             "포도,1200"
                             "딸기,800"]))
```

이제 `with-open`과 `line-seq`를 조합해 파일을 줄 단위로 읽습니다.

```clojure
(with-open [r (io/reader "fruits.txt")]
  (doseq [line (line-seq r)]
    (println "읽은 줄:" line)))
;; 읽은 줄: 사과,500
;; 읽은 줄: 바나나,300
;; 읽은 줄: 포도,1200
;; 읽은 줄: 딸기,800
;; => nil
```

`line-seq`가 만든 시퀀스에도 여느 시퀀스와 마찬가지로 `map`, `filter`, `reduce` 같은 고차 함수를 적용할 수 있습니다. 각 줄을 쉼표로 나누어 이름과 가격을 뽑아내는 예제를 만들어 보겠습니다.

```clojure
(defn parse-fruit-line [line]
  (let [[name price] (clojure.string/split line #",")]
    {:name name
     :price (Integer/parseInt price)}))

(with-open [r (io/reader "fruits.txt")]
  (->> (line-seq r)
       (map parse-fruit-line)
       (doall)))
;; => ({:name "사과", :price 500}
;;     {:name "바나나", :price 300}
;;     {:name "포도", :price 1200}
;;     {:name "딸기", :price 800})
```

여기서 `doall`을 꼭 짚고 넘어가야 합니다. `map`이 반환하는 결과는 지연 시퀀스이기 때문에, `with-open` 블록을 벗어난 뒤에 실제로 값을 꺼내 쓰려고 하면 이미 파일 스트림이 닫힌 뒤라 오류가 발생합니다. `doall`은 지연된 계산을 그 자리에서 모두 강제로 수행시켜, `with-open` 블록 안에서 파일이 열려 있는 동안 모든 줄 읽기를 끝마치도록 보장합니다. `with-open`과 지연 시퀀스를 함께 쓸 때 자주 나오는 실수이니 기억해 두면 좋습니다.

`doall` 없이 지연 시퀀스만 반환하면 어떤 문제가 생기는지 직접 살펴보겠습니다.

```clojure
(def lazy-result
  (with-open [r (io/reader "fruits.txt")]
    (map parse-fruit-line (line-seq r))))

(first lazy-result)
;; Execution error (IOException) ...
;; Stream closed
```

`with-open` 블록이 끝나는 순간 `reader`는 닫혔는데, `map`의 결과는 아직 실제로 계산되지 않은 상태였습니다. 그래서 나중에 `first`로 값을 꺼내려는 시점에는 이미 닫힌 스트림에서 데이터를 읽으려다 예외가 발생합니다. 지연 평가는 강력한 도구이지만, 자원의 생명주기와 얽히면 이렇게 주의가 필요합니다.

### 조건에 맞는 줄만 골라내기

`line-seq`와 `filter`를 조합하면 대용량 파일에서도 메모리 효율적으로 원하는 줄만 골라낼 수 있습니다.

```clojure
(with-open [r (io/reader "fruits.txt")]
  (->> (line-seq r)
       (map parse-fruit-line)
       (filter #(> (:price %) 500))
       (doall)))
;; => ({:name "포도", :price 1200} {:name "딸기", :price 800})
```

`filter`가 조건에 맞지 않는 줄을 건너뛰더라도, `line-seq` 자체는 여전히 파일을 한 줄씩만 메모리에 올리며 진행하기 때문에 파일 크기가 아무리 커도 프로그램이 한꺼번에 많은 메모리를 잡아먹지 않습니다.

## 처리 결과를 다시 파일로 저장하기

읽어 들인 데이터를 가공한 뒤 다시 파일에 쓰는 흐름도 자주 마주칩니다. `line-seq`로 읽고 `io/writer`로 쓰는 두 과정을 하나의 함수로 묶어 보겠습니다.

```clojure
(defn filter-fruits-over [input-path output-path min-price]
  (with-open [r (io/reader input-path)
              w (io/writer output-path)]
    (doseq [line (line-seq r)]
      (let [fruit (parse-fruit-line line)]
        (when (> (:price fruit) min-price)
          (.write w (str (:name fruit) "," (:price fruit)))
          (.newLine w))))))

(filter-fruits-over "fruits.txt" "expensive-fruits.txt" 500)

(println (slurp "expensive-fruits.txt"))
;; 포도,1200
;; 딸기,800
;; => nil
```

이 예제에서는 `doseq`(6장 제어 흐름에서 다룬 반복문)를 사용했습니다. `doseq`는 `map`/`filter`와 달리 지연 시퀀스를 만들지 않고 즉시 부작용(side effect)을 수행하기 때문에, 파일에 쓰는 것처럼 순서대로 확실히 실행되어야 하는 작업에 잘 어울립니다. 파일 입출력처럼 부작용이 핵심인 작업에서는 지연 시퀀스보다 즉시 실행되는 `doseq`가 더 적합한 경우가 많습니다.

## 예외 상황 다루기

파일이 존재하지 않거나 권한이 없는 경로에 접근하면 자바 예외가 그대로 올라옵니다. 14장 예외 처리와 에러 다루기와 15장 Java 상호운용에서 배운 대로 `try`/`catch`로 감싸서 처리할 수 있습니다.

```clojure
(defn safe-slurp [path]
  (try
    (slurp path)
    (catch java.io.FileNotFoundException e
      (println "파일을 찾을 수 없습니다:" path)
      nil)))

(safe-slurp "존재하지않는파일.txt")
;; 파일을 찾을 수 없습니다: 존재하지않는파일.txt
;; => nil

(safe-slurp "fruits.txt")
;; => "사과,500\n바나나,300\n포도,1200\n딸기,800"
```

## slurp/spit과 with-open, 언제 무엇을 쓸까

지금까지 배운 방법들을 정리하면 다음과 같은 기준으로 선택할 수 있습니다.

- 파일 크기가 작고, 내용을 한 번에 통째로 다뤄도 무방하다 → `slurp`/`spit`으로 간단하게 처리합니다.
- 파일이 크거나, 줄 단위로 순차 처리해야 한다 → `with-open` + `io/reader`/`io/writer` + `line-seq` 조합을 사용합니다.
- 자원을 여러 개 동시에 열어야 하거나, 자원이 반드시 닫히도록 보장해야 한다 → `with-open`을 사용합니다.
- 파일 존재 여부, 삭제, 메타데이터 확인이 필요하다 → `clojure.java.io/file`로 `File` 객체를 얻어 15장에서 배운 방식으로 메서드를 호출합니다.

## 요약

- `slurp`는 파일(또는 URL) 전체를 문자열로 읽고, `spit`은 문자열을 파일에 씁니다. 둘 다 작은 파일을 다룰 때 가장 간단한 선택지입니다.
- `spit`은 기본적으로 파일을 덮어쓰며, `:append true` 옵션으로 이어 쓸 수 있습니다.
- `with-open`은 하나 이상의 자원을 열고, 블록이 끝나면 예외 발생 여부와 상관없이 자동으로 자원을 닫아주는 매크로입니다. 자바의 자원 관리 관용구를 Clojure식으로 감싼 것입니다.
- `clojure.java.io`의 `reader`/`writer`는 다양한 입력·출력 대상을 통일된 스트림으로 변환해주며, `slurp`/`spit`도 내부적으로 이 함수들을 사용합니다.
- `line-seq`는 열린 `Reader`로부터 줄 단위 지연 시퀀스를 만들어, 대용량 파일도 메모리 부담 없이 처리할 수 있게 해줍니다.
- 지연 시퀀스를 `with-open` 블록 안에서 만들었다면, 블록을 벗어나기 전에 `doall` 등으로 강제 평가해야 스트림이 닫힌 뒤 오류가 나는 것을 막을 수 있습니다.
- 순서대로 확실히 실행되어야 하는 파일 쓰기 작업에는 지연 평가되는 `map`/`filter`보다 즉시 실행되는 `doseq`가 더 적합합니다.

## 연습문제

1. 임의의 여러 줄짜리 텍스트 파일을 `spit`으로 만든 뒤, `slurp`로 읽어 전체 줄 수와 전체 글자 수를 출력하는 함수 `file-stats`를 작성하세요.
2. `line-seq`를 사용해 텍스트 파일을 읽고, 각 줄의 앞뒤 공백을 제거한 뒤 빈 줄은 걸러내고 나머지만 새로운 파일에 저장하는 함수 `remove-blank-lines`를 작성하세요. (`with-open`으로 입력과 출력을 동시에 열어보세요.)
3. `spit`으로 맵 데이터를 EDN 형식으로 저장한 뒤, `clojure.edn/read-string`으로 다시 읽어 원래 맵과 같은지 `=`로 비교하는 코드를 작성하세요.
4. 이름과 점수가 쉼표로 구분된 CSV 형태의 파일(`이름,점수`)을 읽어, 점수의 평균을 계산하는 함수 `average-score`를 `line-seq`와 `reduce`를 이용해 작성하세요.
5. 지연 시퀀스를 `with-open` 블록 밖으로 그대로 반환했을 때 어떤 문제가 생기는지 이 장의 예제를 참고해 직접 재현해보고, `doall`을 추가했을 때와 결과가 어떻게 달라지는지 비교해 보세요.
