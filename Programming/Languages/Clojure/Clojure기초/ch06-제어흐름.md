5장에서 함수의 본문이 여러 표현식으로 이루어질 수 있고, 마지막 표현식의 값이 곧 반환값이 된다는 것을 배웠습니다. 이번 장에서는 그 표현식들이 조건에 따라 어떤 값을 만들어낼지를 결정하는 도구들, 즉 제어 흐름을 다룹니다.

여기서 미리 강조해두고 싶은 것이 하나 있습니다. Clojure의 조건문들은 명령형 언어의 `if`문처럼 "실행 경로를 바꾸는 문장"이 아니라, 그 자체로 **값을 만들어내는 표현식**입니다. 이 관점의 차이가 이번 장 전체를 관통하는 핵심 아이디어입니다.

## if: 가장 기본적인 조건 표현식

`if`의 형태는 다음과 같습니다.

```clojure
(if 조건 참일때-표현식 거짓일때-표현식)
```

`조건`을 평가한 값이 `nil`이나 `false`가 아니면(Clojure에서는 이 둘만 "거짓"으로 취급되고, `0`이나 `""`, 빈 컬렉션조차 모두 "참"으로 취급됩니다) 참일때-표현식이 평가되어 반환되고, 그렇지 않으면 거짓일때-표현식이 평가되어 반환됩니다.

```clojure
(if (> 5 3)
  "5는 3보다 큽니다"
  "5는 3보다 크지 않습니다")
;; => "5는 3보다 큽니다"

(if (empty? [])
  "비어있음"
  "비어있지 않음")
;; => "비어있음"
```

`if`는 표현식이므로 그 결과를 바로 `def`에 담거나 다른 함수의 인자로 넘길 수 있습니다.

```clojure
(def status (if (> (rand-int 10) 5) :high :low))
status
;; => :low  (실행할 때마다 :high 또는 :low 중 하나)

(println "결과:" (if true "성공" "실패"))
;; 결과: 성공
;; => nil
```

거짓일때-표현식은 생략할 수 있습니다. 이 경우 조건이 거짓이면 `if` 전체가 `nil`을 반환합니다.

```clojure
(if (neg? 5)
  "음수입니다")
;; => nil
```

주의할 점은, `if`는 참/거짓 각각에 대해 **딱 하나의 표현식**만 받을 수 있다는 것입니다. 여러 표현식을 묶고 싶다면 잠시 뒤에 볼 `do`를 사용해야 합니다.

```clojure
;; 아래처럼 여러 표현식을 그냥 나열하면 에러가 난다 (if는 인자를 3개까지만 받는다)
;; (if true (println "a") (println "b") (println "c"))

;; do로 묶어야 한다
(if true
  (do (println "확인 중")
      "성공")
  "실패")
;; 확인 중
;; => "성공"
```

## when과 when-let: 거짓 분기가 필요 없을 때

"조건이 참일 때만 무언가를 하고, 거짓이면 그냥 `nil`을 반환해도 상관없다"는 경우가 실무에서는 훨씬 흔합니다. 이럴 때 `if`에 `do`를 얹어 쓰는 대신 `when`을 쓰면 더 깔끔합니다.

```clojure
(when 조건
  표현식1
  표현식2
  ...)
```

`when`은 조건이 참이면 본문의 표현식들을 순서대로 평가하고 마지막 값을 반환하며, 조건이 거짓이면 본문을 아예 평가하지 않고 `nil`을 반환합니다. 즉 `when`은 "거짓 분기가 없는 `if` + `do`"라고 이해하면 됩니다.

```clojure
(defn describe-age
  [age]
  (when (>= age 18)
    (println (str age "세는 성인입니다."))
    :adult))

(describe-age 20)
;; 20세는 성인입니다.
;; => :adult

(describe-age 10)
;; => nil
```

### when-let

`let`(잠시 뒤에 설명합니다)으로 값을 바인딩하면서 동시에 그 값이 참인지 검사하고 싶을 때는 `when-let`을 씁니다. 특히 "어떤 값을 조회했는데 그 값이 있으면(즉 `nil`이 아니면) 그 값을 가지고 무언가를 하라"는 패턴에서 자주 사용됩니다.

```clojure
(when-let [바인딩 표현식]
  본문...)
```

`표현식`을 평가한 결과가 참(`nil`도 `false`도 아님)이면 그 값을 `바인딩`에 연결한 채 본문을 평가하고, 거짓이면 본문을 평가하지 않고 `nil`을 반환합니다.

```clojure
(defn find-user
  [id]
  (get {1 "지우" 2 "서준"} id))

(defn greet-user
  [id]
  (when-let [name (find-user id)]
    (str "안녕하세요, " name "님!")))

(greet-user 1)
;; => "안녕하세요, 지우님!"

(greet-user 99)
;; => nil
```

`when-let` 없이 이 로직을 짜려면 다음처럼 값을 두 번 계산하거나 임시 변수를 따로 다뤄야 해서 번거롭습니다.

```clojure
;; when-let이 없었다면 이렇게 써야 했을 코드
(defn greet-user-verbose
  [id]
  (let [name (find-user id)]
    (if name
      (str "안녕하세요, " name "님!")
      nil)))
```

`when-let`은 이런 "조회하고, 있으면 쓴다"는 패턴을 한 번에 표현해줍니다.

## if-let

`if-let`은 `when-let`과 비슷하지만, 조건이 거짓일 때 실행할 표현식을 따로 지정할 수 있습니다.

```clojure
(if-let [바인딩 표현식]
  참일때-표현식
  거짓일때-표현식)
```

```clojure
(defn greet-user
  [id]
  (if-let [name (find-user id)]
    (str "안녕하세요, " name "님!")
    "등록되지 않은 사용자입니다."))

(greet-user 2)
;; => "안녕하세요, 서준님!"

(greet-user 42)
;; => "등록되지 않은 사용자입니다."
```

정리하면, `if`와 `when`이 "조건 → 분기"의 짝이듯, `if-let`과 `when-let`은 "바인딩 + 조건 검사 → 분기"의 짝입니다. 아래 표로 네 가지를 비교해봅시다.

| 형태 | 값을 바인딩하는가 | 거짓 분기 지정 가능 | 거짓일 때 기본 반환값 |
|---|---|---|---|
| `if` | 아니오 | 예 | (직접 지정해야 함) |
| `when` | 아니오 | 아니오 | `nil` |
| `if-let` | 예 | 예 | (직접 지정해야 함) |
| `when-let` | 예 | 아니오 | `nil` |

## cond: 여러 조건을 순차적으로 검사하기

조건이 두 개뿐이라면 `if`로 충분하지만, 조건이 셋 이상으로 늘어나면 `if`를 중첩해야 해서 코드가 금방 지저분해집니다.

```clojure
;; if를 중첩한 경우 - 조건이 늘어날수록 읽기 힘들어진다
(defn grade
  [score]
  (if (>= score 90)
    "A"
    (if (>= score 80)
      "B"
      (if (>= score 70)
        "C"
        "F"))))
```

이런 상황을 위해 `cond`가 있습니다. `cond`는 "조건, 결과" 쌍을 나열하고, 위에서부터 순서대로 조건을 검사해 처음으로 참이 되는 조건의 결과를 반환합니다.

```clojure
(cond
  조건1 결과1
  조건2 결과2
  조건3 결과3
  :else 기본결과)
```

`grade` 함수를 `cond`로 다시 써보면 다음과 같습니다.

```clojure
(defn grade
  [score]
  (cond
    (>= score 90) "A"
    (>= score 80) "B"
    (>= score 70) "C"
    :else "F"))

(grade 95)
;; => "A"

(grade 72)
;; => "C"

(grade 40)
;; => "F"
```

마지막 줄의 `:else`는 특별한 키워드가 아니라 그냥 "항상 참으로 평가되는 값"을 관례적으로 쓴 것입니다. 키워드는 자기 자신을 평가한 결과가 자기 자신이고, `nil`도 `false`도 아니므로 참으로 취급됩니다. `:else` 대신 `:default`나 그냥 `true`를 써도 동작은 같지만, `:else`가 관례로 널리 쓰입니다. 이 마지막 조건을 생략하면, 어떤 조건도 참이 되지 않을 때 `cond`는 `nil`을 반환합니다.

```clojure
(cond
  (> 1 2) "일이 이보다 크다"
  (> 1 3) "일이 삼보다 크다")
;; => nil
```

## case: 값 자체를 비교할 때

`cond`의 각 조건이 "같은 값을 여러 후보와 비교하는" 패턴으로만 이루어져 있다면, `case`를 쓰는 것이 더 간결하고 빠릅니다. `case`는 하나의 표현식 값을 미리 정해둔 상수 값들과 비교해서, 일치하는 첫 번째 절의 결과를 반환합니다.

```clojure
(case 검사할-값
  상수1 결과1
  상수2 결과2
  기본결과)
```

```clojure
(defn day-type
  [day-keyword]
  (case day-keyword
    :saturday "주말"
    :sunday "주말"
    (:monday :tuesday :wednesday :thursday :friday) "평일"
    "알 수 없는 요일"))

(day-type :saturday)
;; => "주말"

(day-type :wednesday)
;; => "평일"

(day-type :holiday)
;; => "알 수 없는 요일"
```

위 예에서 `(:monday :tuesday :wednesday :thursday :friday)`처럼 여러 상수를 리스트로 묶으면 "이 중 하나와 일치하면"이라는 뜻이 됩니다. 마지막 줄의 `"알 수 없는 요일"`처럼 짝이 없는 표현식 하나만 남으면 그것이 기본값(default)이 됩니다.

`case`와 `cond`의 근본적인 차이는 다음과 같습니다.

- `cond`는 각 절마다 **임의의 조건식**(비교, 함수 호출 등 무엇이든)을 평가합니다.
- `case`는 검사 대상 값 하나를 **상수들과 동등 비교**(내부적으로 해시 기반 조회를 사용해 매우 빠릅니다)만 할 수 있습니다. 상수 자리에는 변수나 함수 호출을 쓸 수 없습니다.

따라서 "이 값이 이 상수들 중 무엇과 같은가?"라는 질문에는 `case`가, "이 조건들 중 무엇이 참인가?"라는 좀 더 일반적인 질문에는 `cond`가 어울립니다.

```clojure
;; case의 상수 자리에는 변수를 쓸 수 없다 - 아래는 기대한 대로 동작하지 않는다
(def target 10)
(case 10
  target "일치함"   ;; target은 심볼 그대로 취급되어 값 10과 비교되지 않는다
  "불일치")
;; => "불일치"  (target이라는 심볼 리터럴과 비교했기 때문)
```

이런 이유로, 비교 대상이 변수의 값이어야 한다면 `case` 대신 `cond`와 `=`를 사용해야 합니다.

## do: 여러 표현식을 하나로 묶기

`do`는 여러 표현식을 순서대로 평가하고 마지막 값만 반환하는 특수형입니다. 앞서 `if`의 각 분기에는 표현식을 하나만 쓸 수 있다고 했는데, `do`로 감싸면 그 하나의 표현식 자리에 여러 동작을 몰아넣을 수 있습니다.

```clojure
(do
  (println "1단계 진행")
  (println "2단계 진행")
  (+ 1 2))
;; 1단계 진행
;; 2단계 진행
;; => 3
```

`do`는 주로 부작용(화면 출력, 파일 쓰기, 상태 변경 등)을 순서대로 일으켜야 하는데 그 자리가 표현식 하나만 허용하는 문맥(예: `if`의 분기)일 때 사용됩니다. 이미 여러 표현식을 자연스럽게 허용하는 곳, 예를 들어 `defn`의 본문이나 `when`, `let`의 본문에는 `do`가 암묵적으로 적용되어 있으므로 따로 감쌀 필요가 없습니다.

```clojure
;; defn 본문은 이미 여러 표현식을 허용하므로 do가 필요 없다
(defn log-and-add
  [a b]
  (println "더하기 연산 시작")
  (+ a b))

(log-and-add 2 3)
;; 더하기 연산 시작
;; => 5
```

## let: 지역 바인딩 만들기

`let`은 특정 범위 안에서만 유효한 이름(지역 바인딩)을 만듭니다. 형태는 다음과 같습니다.

```clojure
(let [이름1 값1
      이름2 값2
      ...]
  본문...)
```

대괄호 안에 이름과 값을 짝지어 나열하고, 본문에서 그 이름들을 사용합니다. `let`도 표현식이므로 본문의 마지막 값을 반환합니다.

```clojure
(let [x 10
      y 20]
  (+ x y))
;; => 30
```

`let`이 유용한 이유는 크게 두 가지입니다.

**첫째, 같은 계산을 여러 번 반복하지 않도록 값을 한 번만 계산해서 이름을 붙여둘 수 있습니다.**

```clojure
;; let 없이 - (rand-int 100)을 두 번 호출해서 서로 다른 값이 나올 위험이 있다
(defn risky-double
  []
  (+ (rand-int 100) (rand-int 100)))  ;; 두 값이 다를 수 있음

;; let으로 한 번만 계산 - 같은 값을 재사용
(defn safe-double
  []
  (let [n (rand-int 100)]
    (+ n n)))

(safe-double)
;; => 84  (실행마다 다른 값이지만, 항상 짝수)
```

**둘째, 복잡한 표현식에 의미 있는 이름을 붙여서 코드를 읽기 쉽게 만들어줍니다.**

```clojure
(defn body-mass-index
  [weight-kg height-m]
  (let [height-squared (* height-m height-m)
        bmi (/ weight-kg height-squared)]
    (cond
      (< bmi 18.5) "저체중"
      (< bmi 25) "정상"
      (< bmi 30) "과체중"
      :else "비만")))

(body-mass-index 70 1.75)
;; => "정상"
```

`let` 안에서는 앞서 바인딩한 이름을 뒤에서 바로 사용할 수 있습니다. 위 예의 `bmi`가 `height-squared`를 참조하는 것처럼요. 또한 `let`의 바인딩 벡터에서는 같은 이름을 다시 사용해서 값을 가리는(shadowing) 것도 가능합니다.

```clojure
(let [x 5
      x (* x 2)
      x (+ x 1)]
  x)
;; => 11
```

이렇게 같은 이름을 계속 갱신하는 것처럼 보이는 코드도, 사실은 매번 새로운 지역 바인딩을 만드는 것이지 기존 값을 변경하는 것이 아닙니다. Clojure의 값들은 기본적으로 불변(immutable)이라는 원칙은 9장 불변성과 영속적 자료구조에서 훨씬 깊이 다룹니다. 여기서는 "`let`으로 만든 이름은 한 번 값이 정해지면 그 범위 안에서 바뀌지 않는다"는 정도만 기억해두면 충분합니다.

`let`의 바인딩 벡터에서는 구조 분해(destructuring)라는 강력한 기능도 사용할 수 있는데, 이는 11장 구조 분해에서 본격적으로 다룹니다.

```clojure
;; 구조 분해를 살짝 맛보기 - 벡터를 분해해서 각 원소에 이름 붙이기
(let [[first-item second-item] [100 200 300]]
  (+ first-item second-item))
;; => 300
```

## Clojure에는 전통적인 for문이나 while문이 없다

C, Java, Python 같은 언어에서 반복은 대개 `for`, `while` 같은 **문(statement)**으로 이루어집니다. 이런 문들은 값을 반환하지 않고, 변수를 계속 변경(mutation)하면서 루프를 돕니다.

Clojure에는 이런 형태의 반복문이 없습니다. Clojure에서 `for`라는 이름의 매크로가 존재하긴 하지만, 이것은 명령형 언어의 `for` 루프와는 전혀 다른 것으로, 시퀀스를 생성하는 표현식입니다. 이 부분은 흔한 오해를 낳는 지점이므로 짚고 넘어갑니다.

```clojure
;; Clojure의 for는 반복 실행문이 아니라 시퀀스를 만드는 표현식이다
(for [n [1 2 3 4 5]]
  (* n n))
;; => (1 4 9 16 25)
```

보다시피 `for`는 어떤 동작을 "실행"하는 것이 아니라 새로운 값(여기서는 지연 시퀀스)을 만들어냅니다. 값을 누적하며 변수를 계속 덮어쓰는 명령형 반복 대신, Clojure는 다음과 같은 방식으로 "반복적인 일"을 표현합니다.

- 컬렉션의 각 원소에 함수를 적용해 새 컬렉션을 만드는 `map`, `filter` 같은 함수
- 컬렉션을 하나의 값으로 접어나가는 `reduce`
- 재귀 호출, 그리고 Clojure가 지원하는 꼬리 호출 최적화 기법인 `recur`
- 지금 살펴본 `for` 매크로(리스트 컴프리헨션에 가까운 개념)

즉 Clojure에서는 "루프를 돌며 변수를 바꾼다"는 발상 대신 "입력 컬렉션을 출력 컬렉션으로 변환한다" 또는 "값을 하나씩 접어 최종 결과를 만든다"는 발상으로 반복을 표현합니다. 이런 사고방식의 전환이 처음에는 낯설게 느껴질 수 있지만, 일단 익숙해지면 부작용이 적고 검증하기 쉬운 코드를 자연스럽게 작성하게 됩니다.

재귀와 `recur`를 이용한 반복, `loop`, 그리고 `for`와 `map`, `reduce`를 이용한 반복적 데이터 처리는 다음 장인 7장 재귀와 반복에서 본격적으로 다룹니다. 지금 단계에서는 "Clojure의 모든 것은 값을 만들어내는 표현식이고, 반복조차도 예외가 아니다"라는 큰 그림만 기억해두면 충분합니다.

## 표현식 중심 사고방식 다시 보기

이번 장에서 다룬 `if`, `when`, `cond`, `case`, `let`, 그리고 `do`까지, 이들의 공통점은 전부 **값을 반환하는 표현식**이라는 것입니다. 이 사실은 다음과 같은 자연스러운 결과를 낳습니다.

```clojure
;; 조건 표현식의 결과를 바로 다른 함수에 넘길 수 있다
(println (if (> 10 5) "크다" "작다"))
;; 크다
;; => nil

;; let으로 만든 값을 조건에 활용하고, 그 결과를 다시 컬렉션에 담을 수 있다
(let [scores [88 92 75 60]]
  (map (fn [s] (cond
                 (>= s 90) :A
                 (>= s 80) :B
                 (>= s 70) :C
                 :else :F))
       scores))
;; => (:B :A :C :F)
```

이렇게 조건과 바인딩이 값을 만들어내는 도구로 통일되어 있다는 점은, 나중에 8장에서 고차 함수를 배우고 12장에서 매크로를 배울 때도 계속 힘을 발휘합니다. "이것도 결국 값을 돌려주는 표현식이다"라는 관점을 가지고 있으면 Clojure 코드를 훨씬 편하게 읽고 쓸 수 있습니다.

## 요약

- `if`는 조건에 따라 두 표현식 중 하나를 평가해 값을 반환하는 기본 조건 표현식이다. 각 분기에는 표현식을 하나만 쓸 수 있다.
- `when`은 거짓 분기가 필요 없을 때 쓰는 `if`이며, 조건이 거짓이면 `nil`을 반환한다. `when-let`은 바인딩과 조건 검사를 동시에 한다.
- `if-let`은 값을 바인딩하면서 참/거짓 분기를 모두 지정할 수 있다.
- `cond`는 여러 임의 조건을 위에서부터 순서대로 검사해 처음 참이 되는 절의 결과를 반환한다. 관례적으로 마지막에 `:else`를 두어 기본값을 지정한다.
- `case`는 하나의 값을 미리 정한 상수들과 비교하는 데 특화되어 있으며, `cond`보다 빠르지만 상수 비교만 가능하다.
- `do`는 여러 표현식을 순서대로 평가해 마지막 값만 반환한다. 표현식 하나만 허용되는 자리에서 여러 부작용을 묶을 때 사용한다.
- `let`은 지역 바인딩을 만든다. 값을 한 번만 계산해 재사용하거나, 복잡한 표현식에 이름을 붙여 가독성을 높이는 데 쓰인다.
- Clojure에는 전통적인 `for`/`while` 반복문이 없다. Clojure의 `for`는 시퀀스를 만드는 표현식이며, 실제 반복 처리는 `map`, `filter`, `reduce`, 재귀와 `recur` 등을 통해 이루어진다. 자세한 내용은 7장에서 다룬다.
