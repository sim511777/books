## 이 장에서 다루는 내용

Clojure는 독립적인 실행 엔진을 가진 언어가 아니라 JVM(Java Virtual Machine) 위에서 동작하는 언어입니다. 소스 코드는 컴파일 과정을 거쳐 JVM 바이트코드로 변환되고, 그 결과물은 자바 클래스와 똑같은 방식으로 실행됩니다. 이 사실 하나만으로도 Clojure는 자바 표준 라이브러리 전체와, 세상에 존재하는 수많은 자바 라이브러리를 아무런 번역 계층 없이 곧바로 사용할 수 있습니다.

이번 장에서는 Clojure 코드에서 자바 클래스와 객체를 다루는 문법을 정리합니다. 메서드 호출, 필드 접근, 정적 멤버 접근, 객체 생성, 그리고 여러 메서드를 연속으로 호출할 때 쓰는 `doto`까지 살펴본 뒤, 외부 자바 라이브러리를 프로젝트에 끌어와 쓰는 흐름도 간단히 소개합니다.

## 왜 자바 상호운용이 중요한가

새로운 언어를 배울 때 가장 아쉬운 순간은 "이 기능을 하려면 라이브러리가 있어야 하는데, 아직 이 생태계엔 그런 라이브러리가 없다"는 걸 깨닫는 순간입니다. Clojure는 이 문제에서 비교적 자유롭습니다. 날짜 계산이 필요하면 `java.time` 패키지를, 정규식이 필요하면 `java.util.regex`를, 암호화가 필요하면 `javax.crypto`를 그대로 가져다 쓸 수 있기 때문입니다. Clojure 자체 문법에 없는 기능도 자바 쪽에서 빌려오면 대부분 해결됩니다.

물론 이 상호운용 문법은 Clojure의 나머지 문법과는 결이 조금 다릅니다. Clojure 함수 호출은 언제나 `(함수 인자1 인자2)` 형태로 일관되지만, 자바 쪽 객체를 다루려면 "이 값은 메서드를 가진 객체다"라는 사실을 문법적으로 표시해줘야 합니다. 이 장에서 소개하는 점(`.`)이 붙은 특수 형태들이 그 표시 역할을 합니다.

## 인스턴스 메서드 호출

자바 객체의 메서드를 호출할 때는 메서드 이름 앞에 점(`.`)을 붙이고, 그 뒤에 객체와 인자를 나열합니다.

```clojure
(.method 객체 인자1 인자2 ...)
```

문자열도 사실은 `java.lang.String`의 인스턴스이므로, 문자열 메서드를 곧바로 호출해볼 수 있습니다.

```clojure
(.toUpperCase "hello, clojure")
;; => "HELLO, CLOJURE"

(.length "hello")
;; => 5

(.substring "clojure lisp" 0 7)
;; => "clojure"

(.indexOf "banana" "an")
;; => 1
```

숫자나 다른 객체에 대해서도 동일합니다.

```clojure
(def sb (StringBuilder. "안녕"))

(.append sb "하세요")
;; => #object[java.lang.StringBuilder ... "안녕하세요"]

(.toString sb)
;; => "안녕하세요"
```

여기서 눈여겨볼 점은 `(.method obj args)`가 사실 `(. obj method args)`라는 더 기본적인 특수 형태의 축약형이라는 것입니다. 두 표현은 완전히 동일하게 동작합니다.

```clojure
(. "hello" toUpperCase)
;; => "HELLO"

(. "hello" (toUpperCase))
;; => "HELLO"
```

실전에서는 거의 항상 `(.method obj args)` 형태를 사용합니다. `.` 특수 형태를 직접 쓰는 경우는 드물지만, 매크로 전개 결과를 이해할 때 도움이 됩니다.

### 필드 접근

메서드가 아니라 필드(속성)에 접근할 때는 점 뒤에 하이픈(`-`)을 붙입니다.

```clojure
(import 'java.awt.Point)

(def p (Point. 3 5))

(.-x p)
;; => 3

(.-y p)
;; => 5
```

메서드는 `.method`, 필드는 `.-field`라는 규칙만 기억하면 헷갈릴 일이 없습니다.

## 정적 메서드와 정적 필드

클래스 자체에 속한 정적(static) 멤버에 접근할 때는 슬래시(`/`)를 사용합니다. 5장 함수 정의와 호출에서 네임스페이스에 속한 함수를 `namespace/함수이름`으로 부르는 것과 형태가 비슷하다고 생각하면 기억하기 쉽습니다.

```clojure
(Math/pow 2 10)
;; => 1024.0

(Math/sqrt 2)
;; => 1.4142135623730951

(Math/max 3 7)
;; => 7

(Integer/parseInt "42")
;; => 42

(Long/parseLong "1000000")
;; => 1000000
```

정적 필드(주로 상수)도 같은 방식으로 읽습니다.

```clojure
Math/PI
;; => 3.141592653589793

Integer/MAX_VALUE
;; => 2147483647

Long/MIN_VALUE
;; => -9223372036854775808
```

정적 메서드는 `ClassName/method`, 인스턴스 메서드는 `.method`. 이 구분이 자바 상호운용 문법의 핵심 축입니다.

## 객체 생성: new와 점(.) 표기

자바 객체를 새로 만들 때는 `new` 특수 형태를 사용합니다.

```clojure
(new java.util.Date)
;; => #inst "2026-08-07T02:14:00.000-00:00"

(new StringBuilder "시작")
;; => #object[java.lang.StringBuilder ... "시작"]
```

하지만 실무에서는 클래스 이름 뒤에 점을 붙이는 축약형을 훨씬 더 자주 씁니다.

```clojure
(java.util.Date.)
;; => #inst "2026-08-07T02:14:00.000-00:00"

(StringBuilder. "시작")
;; => #object[java.lang.StringBuilder ... "시작"]

(java.util.ArrayList. [1 2 3])
;; => [1 2 3]
```

`(ClassName. args)`는 `(new ClassName args)`와 완전히 동일합니다. 클래스 이름 끝의 점은 "이건 생성자 호출이다"라는 신호라고 이해하면 됩니다.

### import로 클래스 이름 줄이기

매번 `java.util.Date`처럼 전체 경로를 적는 대신, `import`로 클래스를 가져오면 짧은 이름만으로 사용할 수 있습니다. 10장 네임스페이스와 코드 구성에서 다룬 `require`가 Clojure 네임스페이스를 위한 것이라면, `import`는 자바 클래스를 위한 대응물이라고 볼 수 있습니다.

```clojure
(import 'java.util.Date)
(import '(java.util ArrayList HashMap))

(Date.)
;; => #inst "2026-08-07T02:14:00.000-00:00"

(ArrayList. [1 2 3])
;; => [1 2 3]
```

`ns` 선언 안에서는 `:import` 키를 사용하는 것이 관용적입니다.

```clojure
(ns my-app.core
  (:import (java.util Date ArrayList)
           (java.time LocalDate LocalDateTime)))
```

참고로 `java.lang` 패키지(`String`, `Math`, `Integer` 등)는 모든 네임스페이스에서 자동으로 임포트되어 있어 별도 선언 없이 바로 쓸 수 있습니다. 앞서 예제에서 `Math/pow`나 `Integer/parseInt`를 import 없이 쓸 수 있었던 이유가 여기에 있습니다.

## 메서드 체이닝과 스레딩 매크로

자바 코드에서는 `sb.append("a").append("b").toString()`처럼 메서드를 연속으로 호출하는 체이닝이 흔합니다. Clojure에서 이런 흐름을 그대로 표현하려면 8장 시퀀스 추상화와 고차 함수에서 살펴본 `->` 스레딩 매크로가 아주 잘 맞습니다.

```clojure
(-> (StringBuilder.)
    (.append "안녕")
    (.append ", ")
    (.append "세계")
    (.toString))
;; => "안녕, 세계"
```

`->`는 첫 번째 결과를 다음 호출의 첫 번째 인자 자리에 밀어 넣어주므로, `(.append obj "안녕")` 형태로 정확히 확장됩니다. 자바의 메서드 체이닝을 Clojure식으로 옮길 때 가장 자연스러운 표현 방법입니다.

## doto: 반환값이 필요 없는 연속 호출

객체를 생성하고 나서 그 객체에 설정 메서드를 여러 번 호출해야 하는 경우가 많습니다. 예를 들어 `StringBuilder`에 여러 조각을 이어 붙이면서 매번 반환값(자기 자신)을 신경 쓸 필요 없이, "이 객체에 대고 이런 부작용을 순서대로 일으켜라"라고 표현하고 싶을 때 `doto`가 정확히 맞아떨어집니다.

```clojure
(def sb (doto (StringBuilder.)
          (.append "하나")
          (.append " ")
          (.append "둘")
          (.append " ")
          (.append "셋")))

(.toString sb)
;; => "하나 둘 셋"
```

`doto`는 각 폼의 첫 번째 인자 자리에 대상 객체를 끼워 넣어 순서대로 실행하고, 마지막에는 각 호출의 결과가 아니라 **처음에 주어진 객체 자체**를 반환합니다. `->`와 비슷해 보이지만 의도가 다릅니다.

- `->`: 각 단계의 반환값을 다음 단계로 흘려보낸다 (값 변환 파이프라인)
- `doto`: 매번 같은 객체에 부작용을 일으키고, 마지막에 그 객체를 그대로 돌려준다 (설정/초기화 목적)

`java.util.ArrayList`처럼 자기 자신을 반환하지 않는 메서드(`add`는 `boolean`을 반환합니다)를 다룰 때 `doto`의 진가가 드러납니다.

```clojure
(def numbers (doto (java.util.ArrayList.)
               (.add 10)
               (.add 20)
               (.add 30)))

numbers
;; => [10 20 30]

(.add numbers 40)
;; => true  (add의 반환값은 boolean이지만, doto 밖에서는 이 값이 그대로 보인다)

numbers
;; => [10 20 30 40]
```

`(.add numbers 10)`을 `->`로 연결했다면 두 번째 단계부터는 `true`(boolean)를 객체로 착각해 메서드를 호출하려다 오류가 났을 것입니다. `doto`는 이런 상황에서 실수를 방지해 줍니다.

## 자바 예외와의 관계

자바 메서드는 실패 시 예외(exception)를 던지는 방식으로 오류를 알립니다. Clojure에서 자바 메서드를 호출하다 보면 `NumberFormatException`, `ArithmeticException`, `IndexOutOfBoundsException`처럼 익숙한 자바 예외 클래스를 그대로 마주치게 됩니다.

```clojure
(Integer/parseInt "abc")
;; Execution error (NumberFormatException) ...
;; For input string: "abc"
```

14장 예외 처리와 에러 다루기에서 다룬 `try`/`catch`는 자바 예외를 그대로 잡아낼 수 있습니다.

```clojure
(defn safe-parse-int [s]
  (try
    (Integer/parseInt s)
    (catch NumberFormatException e
      (println "숫자로 변환할 수 없습니다:" (.getMessage e))
      nil)))

(safe-parse-int "123")
;; => 123

(safe-parse-int "abc")
;; 숫자로 변환할 수 없습니다: For input string: "abc"
;; => nil
```

`catch` 절에 클래스 이름을 그대로 적을 수 있다는 점, 그리고 잡은 예외 객체에서 `.getMessage`처럼 인스턴스 메서드를 호출할 수 있다는 점 모두 이번 장에서 배운 문법 그대로입니다.

## 타입 힌트는 언제 필요한가

Clojure는 기본적으로 리플렉션(실행 시점에 타입을 조사하는 방식)을 통해 어떤 메서드를 호출할지 알아냅니다. 대부분의 경우 이것으로 충분하지만, 성능이 중요한 반복 구간에서는 타입 힌트(type hint)를 붙여 리플렉션을 피하고 컴파일 시점에 메서드를 결정하게 만들 수 있습니다.

```clojure
(defn string-length [^String s]
  (.length s))
```

`^String`처럼 심볼 앞에 캐럿(`^`)과 타입 이름을 붙이는 것이 타입 힌트입니다. 입문 단계에서는 굳이 신경 쓰지 않아도 괜찮은 최적화 기법이므로, "이런 것이 존재한다" 정도로만 기억해두고 넘어가도 충분합니다.

## 외부 자바 라이브러리를 프로젝트에 추가하기

지금까지는 JDK에 기본 포함된 클래스만 사용했지만, 실제 프로젝트에서는 외부에서 배포되는 자바 라이브러리(예: JSON 파싱 라이브러리, HTTP 클라이언트 등)를 가져다 쓰는 일이 흔합니다. 2장 개발 환경 준비와 첫 실행에서 소개한 `deps.edn` 방식을 사용한다면, 좌표를 `:deps` 맵에 추가하는 것만으로 라이브러리를 내려받아 클래스패스에 올릴 수 있습니다.

```clojure
;; deps.edn 예시
{:deps {org.clojure/clojure {:mvn/version "1.11.1"}
        com.fasterxml.jackson.core/jackson-databind {:mvn/version "2.15.2"}}}
```

라이브러리가 클래스패스에 올라가면, 그 안의 클래스는 지금까지 배운 것과 똑같은 방식으로 사용합니다.

```clojure
(ns my-app.core
  (:import (com.fasterxml.jackson.databind ObjectMapper)))

(def mapper (ObjectMapper.))

(.writeValueAsString mapper {"name" "clojure"})
```

물론 실전에서는 이런 원시 자바 클래스를 직접 다루기보다, 해당 라이브러리를 감싼 Clojure 전용 래퍼 라이브러리(예: JSON 처리를 위한 `cheshire`, `jsonista` 등)를 사용하는 경우가 더 많습니다. 하지만 그런 래퍼 라이브러리들도 내부적으로는 지금까지 배운 자바 상호운용 문법으로 구현되어 있습니다. 이 장의 문법을 이해하고 나면, 필요할 때 언제든 자바 생태계 전체를 Clojure의 확장 표준 라이브러리처럼 활용할 수 있습니다.

## 정리 예제: 날짜 다루기

배운 내용을 종합해서 `java.time` 패키지로 오늘 날짜에 며칠을 더한 날짜를 계산하는 함수를 만들어 보겠습니다.

```clojure
(ns my-app.dates
  (:import (java.time LocalDate)))

(defn days-from-today [n]
  (-> (LocalDate/now)
      (.plusDays n)))

(days-from-today 10)
;; => #object[java.time.LocalDate 0x... "2026-08-17"]

(str (days-from-today 10))
;; => "2026-08-17"

(defn weekday-name [^LocalDate date]
  (-> date
      (.getDayOfWeek)
      (.toString)))

(weekday-name (LocalDate/now))
;; => "FRIDAY"
```

`LocalDate/now`는 정적 메서드 호출, `.plusDays`와 `.getDayOfWeek`는 인스턴스 메서드 호출, `->`는 이 둘을 자연스러운 순서로 연결하는 스레딩 매크로입니다. 이 장에서 배운 문법 요소들이 한 예제 안에 모두 녹아 있습니다.

## 요약

- Clojure는 JVM 위에서 동작하며, 자바 클래스와 라이브러리를 별도의 변환 계층 없이 곧바로 사용할 수 있습니다.
- 인스턴스 메서드 호출은 `(.method 객체 인자...)`, 필드 접근은 `(.-field 객체)` 형태를 씁니다. 두 형태 모두 `(. 객체 ...)`라는 기본 특수 형태의 축약입니다.
- 정적 메서드와 정적 필드는 `ClassName/member` 형태로 접근합니다.
- 객체 생성은 `(new ClassName args)` 또는 축약형인 `(ClassName. args)`로 합니다.
- 메서드 체이닝은 8장에서 배운 `->` 스레딩 매크로로 자연스럽게 표현할 수 있습니다.
- `doto`는 같은 객체에 여러 메서드를 순서대로 호출하면서 각 메서드의 반환값이 아니라 원래 객체를 결과로 돌려주는, 설정/초기화에 특화된 매크로입니다.
- 자바 메서드가 던지는 예외는 14장에서 다룬 `try`/`catch`로 그대로 잡을 수 있습니다.
- `deps.edn`에 좌표를 추가하면 외부 자바 라이브러리도 동일한 상호운용 문법으로 사용할 수 있습니다.

## 연습문제

1. `java.time.LocalDateTime`을 사용해 현재 시각을 구하고, `.getHour`와 `.getMinute` 메서드로 시와 분을 각각 추출하는 함수 `current-hour-minute`를 작성하세요. (반환값은 `[시 분]` 형태의 벡터로 만들어 보세요.)
2. `StringBuilder`를 사용해 문자열 컬렉션을 받아 쉼표와 공백(`, `)으로 이어 붙인 하나의 문자열로 만드는 함수 `join-with-builder`를 `doto`를 활용해 작성하세요. (힌트: 마지막 항목 뒤에는 구분자를 붙이지 않아야 합니다.)
3. `Integer/parseInt`를 사용해 문자열 시퀀스를 정수 시퀀스로 변환하되, 변환할 수 없는 문자열을 만나면 `NumberFormatException`을 잡아서 그 자리에 `0`을 넣는 함수 `parse-ints-safely`를 작성하세요.
4. `java.util.Random` 클래스를 `import`해서, `.nextInt` 메서드로 0 이상 100 미만의 난수를 5개 생성해 벡터로 반환하는 함수를 작성하세요.
5. `(.method obj args)`와 `(. obj method args)`가 동일하게 동작함을 REPL에서 직접 확인하고, 어떤 경우에 축약형 대신 기본 형태를 쓰는 것이 더 명확할지 자신의 생각을 정리해 보세요.
