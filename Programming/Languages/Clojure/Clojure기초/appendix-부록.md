## A. 자주 쓰는 함수·특수형 치트시트

여기서 정리하는 함수와 특수형은 대부분 4장(컬렉션), 5장(함수), 6장(제어 흐름), 7장(재귀와 반복), 8장(시퀀스 추상화와 고차 함수)에서 다룬 내용입니다. 각 챕터의 설명과 예제를 함께 참고하세요.

### A-1. 컬렉션 만들기·기본 조작

| 이름 | 설명 | 예시 |
|---|---|---|
| `list` | 리스트 생성 | `(list 1 2 3)` → `(1 2 3)` |
| `vector` | 벡터 생성 | `(vector 1 2 3)` → `[1 2 3]` |
| `hash-map` | 맵 생성 | `(hash-map :a 1 :b 2)` → `{:a 1 :b 2}` |
| `hash-set` | 셋 생성 | `(hash-set 1 2 2 3)` → `#{1 2 3}` |
| `conj` | 컬렉션에 요소 추가 (컬렉션 종류에 따라 추가 위치가 다름) | `(conj [1 2] 3)` → `[1 2 3]`, `(conj '(1 2) 3)` → `(3 1 2)` |
| `cons` | 시퀀스 맨 앞에 요소 하나를 붙임 | `(cons 0 '(1 2))` → `(0 1 2)` |
| `into` | 한 컬렉션의 요소들을 다른 컬렉션에 채워 넣음 | `(into [] '(1 2 3))` → `[1 2 3]` |
| `concat` | 여러 시퀀스를 이어붙임 | `(concat [1 2] [3 4])` → `(1 2 3 4)` |
| `count` | 요소 개수 | `(count [1 2 3])` → `3` |
| `empty?` | 비어 있는지 검사 | `(empty? [])` → `true` |
| `first` | 첫 요소 | `(first [1 2 3])` → `1` |
| `rest` | 첫 요소를 뺀 나머지 (시퀀스, 항상 반환) | `(rest [1 2 3])` → `(2 3)` |
| `next` | 첫 요소를 뺀 나머지, 남는 게 없으면 `nil` | `(next [1])` → `nil` |
| `last` | 마지막 요소 | `(last [1 2 3])` → `3` |
| `nth` | n번째 요소 (0부터 시작) | `(nth [1 2 3] 1)` → `2` |
| `get` | 키/인덱스로 값 조회, 없으면 기본값 | `(get {:a 1} :b 0)` → `0` |
| `assoc` | 키에 값을 연결(불변, 새 컬렉션 반환) | `(assoc {:a 1} :b 2)` → `{:a 1 :b 2}` |
| `dissoc` | 맵에서 키 제거 | `(dissoc {:a 1 :b 2} :a)` → `{:b 2}` |
| `update` | 키에 대응하는 값을 함수로 갱신 | `(update {:a 1} :a inc)` → `{:a 2}` |
| `merge` | 여러 맵을 합침 (뒤의 값이 우선) | `(merge {:a 1} {:a 2 :b 3})` → `{:a 2 :b 3}` |
| `keys` / `vals` | 맵의 키들/값들 | `(keys {:a 1 :b 2})` → `(:a :b)` |
| `contains?` | 키(또는 인덱스, 셋의 원소)가 있는지 검사 | `(contains? {:a 1} :a)` → `true` |
| `reverse` | 순서 뒤집기 | `(reverse [1 2 3])` → `(3 2 1)` |
| `sort` / `sort-by` | 정렬 / 기준 함수로 정렬 | `(sort-by :age 사람들)` |
| `distinct` | 중복 제거 | `(distinct [1 1 2])` → `(1 2)` |
| `flatten` | 중첩된 시퀀스를 평평하게 폄 | `(flatten [[1 2] [3]])` → `(1 2 3)` |

### A-2. 시퀀스 변환·고차 함수 (8장)

| 이름 | 설명 | 예시 |
|---|---|---|
| `map` | 각 요소에 함수를 적용한 새 시퀀스 | `(map inc [1 2 3])` → `(2 3 4)` |
| `filter` | 조건을 만족하는 요소만 남김 | `(filter even? [1 2 3 4])` → `(2 4)` |
| `remove` | 조건을 만족하는 요소를 뺌 (`filter`의 반대) | `(remove even? [1 2 3 4])` → `(1 3)` |
| `reduce` | 요소들을 누적해서 하나의 값으로 | `(reduce + 0 [1 2 3])` → `6` |
| `mapcat` | `map` 후 결과들을 이어붙임 | `(mapcat range [1 2])` → `(0 0 1)` |
| `take` / `drop` | 앞에서 n개 취함 / 버림 | `(take 2 [1 2 3])` → `(1 2)` |
| `take-while` / `drop-while` | 조건이 참인 동안 취함/버림 | `(take-while pos? [1 2 -1 3])` → `(1 2)` |
| `partition` | 고정 크기로 나눔 | `(partition 2 [1 2 3 4])` → `((1 2) (3 4))` |
| `partition-by` | 함수 결과가 바뀔 때마다 나눔 | `(partition-by even? [1 3 2 4 5])` → `((1 3) (2 4) (5))` |
| `group-by` | 함수 결과를 키로 그룹핑한 맵을 만듦 | `(group-by even? [1 2 3 4])` → `{false [1 3], true [2 4]}` |
| `frequencies` | 요소별 등장 횟수를 맵으로 | `(frequencies [1 1 2])` → `{1 2, 2 1}` |
| `some` | 조건을 만족하는 첫 결과(truthy 값)를 반환 | `(some even? [1 3 4])` → `true` |
| `every?` / `not-any?` | 모두/아무도 조건을 만족하지 않는지 | `(every? pos? [1 2 3])` → `true` |
| `apply` | 함수에 시퀀스를 인자 목록으로 펼쳐서 적용 | `(apply + [1 2 3])` → `6` |
| `iterate` | 함수를 반복 적용한 무한 지연 시퀀스 | `(take 3 (iterate inc 1))` → `(1 2 3)` |
| `repeat` / `repeatedly` | 값(또는 함수 호출 결과)을 반복 | `(take 3 (repeat 0))` → `(0 0 0)` |
| `range` | 연속된 정수 시퀀스 | `(range 3)` → `(0 1 2)` |
| `keep` | 함수 결과 중 `nil`이 아닌 것만 남김 | `(keep #(when (even? %) %) [1 2 3 4])` → `(2 4)` |
| `sort-by` | 기준 함수의 결과로 정렬 | `(sort-by count ["ab" "a" "abc"])` → `("a" "ab" "abc")` |

### A-3. 제어 흐름 특수형·매크로 (6장, 7장)

| 이름 | 설명 | 예시 |
|---|---|---|
| `if` | 조건에 따라 두 갈래 중 하나 평가 | `(if (pos? x) "양수" "음수 또는 0")` |
| `if-let` | 바인딩 결과가 truthy일 때만 참 분기 실행 | `(if-let [v (get m :k)] v :없음)` |
| `when` | 조건이 참일 때만 여러 표현식 실행 (거짓이면 `nil`) | `(when (pos? x) (println x) x)` |
| `when-let` | `if-let`의 `when` 버전 | `(when-let [v (seq xs)] (first v))` |
| `cond` | 여러 조건을 순서대로 검사 | `(cond (neg? x) "음수" (zero? x) "영" :else "양수")` |
| `case` | 값 자체를 비교해 분기 (컴파일 시점 상수만 가능) | `(case day 1 "월" 2 "화" "기타")` |
| `let` | 지역 바인딩 생성 | `(let [x 1 y 2] (+ x y))` |
| `do` | 여러 표현식을 순서대로 평가, 마지막 값 반환 | `(do (println "a") 1)` |
| `loop` / `recur` | 꼬리 재귀 반복 (7장) | `(loop [i 0] (if (< i 3) (recur (inc i)) i))` |
| `doseq` | 부작용을 위한 반복 (반환값은 `nil`) | `(doseq [x [1 2 3]] (println x))` |
| `dotimes` | n번 반복 | `(dotimes [i 3] (println i))` |
| `->` | 스레딩 매크로: 값을 각 식의 첫 번째 인자로 넘김 | `(-> 5 inc (* 2))` → `12` |
| `->>` | 스레딩 매크로: 값을 각 식의 마지막 인자로 넘김 | `(->> [1 2 3] (map inc) (reduce +))` |
| `some->` | 중간에 `nil`이 나오면 즉시 멈추는 `->` | `(some-> m :a :b)` |
| `and` / `or` | 논리곱/논리합, 단락 평가 | `(and true 1)` → `1` |

### A-4. 함수 정의·바인딩 (5장, 11장)

| 이름 | 설명 | 예시 |
|---|---|---|
| `defn` | 이름 있는 함수 정의 | `(defn 더하기 [a b] (+ a b))` |
| `fn` | 익명 함수 정의 | `(fn [x] (* x x))` |
| `#(...)` | 익명 함수 축약 문법 | `#(* % 2)` |
| `def` | 최상위 값(var) 정의 | `(def pi 3.14)` |
| 구조 분해 (벡터) | 위치 기반으로 값 분해 | `(let [[a b] [1 2]] ...)` |
| 구조 분해 (맵) | 키 기반으로 값 분해 | `(let [{:keys [name age]} 사람] ...)` |
| `&` (나머지 인자) | 가변 인자를 시퀀스로 받음 | `(defn f [a & rest] ...)` |

### A-5. 동시성·상태 (13장)

| 이름 | 설명 | 예시 |
|---|---|---|
| `atom` | 동기적이고 독립적인 가변 참조 생성 | `(def counter (atom 0))` |
| `swap!` | 아톰의 값을 함수로 갱신 | `(swap! counter inc)` |
| `reset!` | 아톰의 값을 특정 값으로 교체 | `(reset! counter 0)` |
| `deref` / `@` | 참조의 현재 값을 읽음 | `@counter` |
| `ref` | 트랜잭션 기반 가변 참조 생성 | `(def balance (ref 1000))` |
| `dosync` | 여러 레퍼런스를 원자적으로 갱신하는 트랜잭션 블록 | `(dosync (alter balance - 100))` |
| `agent` | 비동기적으로 갱신되는 참조 생성 | `(def log (agent []))` |
| `send` / `send-off` | 에이전트에 작업을 비동기로 전달 | `(send log conj "이벤트")` |

## B. 데이터 리터럴 문법표

3장과 4장에서 다룬 Clojure의 기본 데이터 표기법을 한데 모았습니다.

| 종류 | 리터럴 표기 | 예시 | 비고 |
|---|---|---|---|
| 정수 | 숫자 그대로 | `42`, `-7` | 내부적으로 `long` |
| 큰 정수 | 숫자 뒤에 `N` | `100000000000000000000N` | `BigInteger` |
| 부동소수점 | 소수점 포함 | `3.14`, `-0.5` | `double` |
| 정확한 소수 | 숫자 뒤에 `M` | `3.14M` | `BigDecimal`, 반올림 오차 없음 |
| 분수 | 분자`/`분모 | `1/3`, `22/7` | 자동으로 약분됨 |
| 문자열 | 큰따옴표 | `"안녕하세요"` | 여러 줄도 그대로 포함 가능 |
| 문자 | `\` + 문자 | `\a`, `\한`, `\newline`, `\space` | 특수 문자는 이름으로 표기 |
| 불리언 | `true` / `false` | `true` | |
| nil | `nil` | `nil` | 없음을 나타냄, 거짓으로 취급됨 |
| 키워드 | `:` + 이름 | `:name`, `:상태` | 자기 자신을 평가한 값, 주로 맵의 키로 사용 |
| 네임스페이스 키워드 | `::` 또는 `:ns/이름` | `::로컬`, `:user/id` | 네임스페이스가 붙은 키워드 |
| 심볼 | 이름 그대로 (따옴표 없이 평가하면 값을 참조) | `x`, `더하기`, `'x` (인용) | `'`를 붙이면 평가하지 않고 심볼 자체를 값으로 다룸 |
| 리스트 | `(...)` | `(1 2 3)`, `'(a b c)` | 코드 형태이기도 해서, 데이터로 쓸 때는 보통 `'`로 인용 |
| 벡터 | `[...]` | `[1 2 3]` | 인덱스 접근이 빠른 순서 있는 컬렉션 |
| 맵 | `{...}` (키-값 쌍) | `{:a 1 :b 2}` | 순서 없는 키-값 컬렉션 |
| 셋 | `#{...}` | `#{1 2 3}` | 중복 없는 컬렉션 |
| 정규식 | `#"..."` | `#"[0-9]+"` | `java.util.regex.Pattern` |
| 익명 함수 축약 | `#(...)` | `#(+ % 1)`, `#(+ %1 %2)` | `%`는 첫 인자, `%1 %2 ...`는 순서대로, `%&`는 나머지 |
| 주석 | `;` 또는 `;;` | `;; 이것은 주석입니다` | 이 책에서는 관례상 `;;` 사용 |
| 폼 무시 | `#_` | `#_(디버그용 식) (실제 식)` | 바로 뒤 폼 하나를 통째로 무시 |
| 인용 | `'` | `'(1 2 3)` | 평가하지 않고 코드를 데이터로 다룸 (12장 매크로에서 자주 사용) |
| 문법적 인용 | `` ` `` | `` `(a ~b) `` | 매크로 안에서 사용, `~`로 평가 결과를 끼워 넣음 |
| 문법적 인용 펼치기 | `~@` | `` `(1 ~@xs 2) `` | 시퀀스를 펼쳐서 끼워 넣음 |
| 메타데이터 | `^` | `^:private`, `^{:doc "설명"}` | 심볼이나 컬렉션에 부가 정보를 붙임 |

## C. 참고할 만한 자료 유형 안내

이 책 한 권으로 Clojure의 모든 것을 다룰 수는 없습니다. 이 책을 마친 뒤 더 깊이 파고들고 싶을 때, 어떤 종류의 자료를 어떻게 찾아보면 좋을지 안내합니다. 특정 책이나 상품명을 나열하는 대신, 자료의 성격별로 소개합니다.

### 공식 문서

언어 자체의 핵심 함수와 특수형에 대한 가장 정확한 설명은 언제나 공식 문서에서 찾을 수 있습니다. 각 함수의 정확한 인자 형태(시그니처), 반환값의 동작, 버전별 변경 사항은 공식 문서가 가장 신뢰할 수 있는 출처입니다. REPL에서도 `(doc 함수이름)`을 호출하면 해당 함수의 공식 문서 내용을 바로 확인할 수 있고, `(source 함수이름)`을 호출하면 실제 구현 코드를 볼 수 있습니다. 이 두 가지를 습관적으로 활용하는 것만으로도 별도의 검색 없이 많은 궁금증을 해결할 수 있습니다.

```clojure
(doc map)
(source map)
(find-doc "reduce") ;; "reduce"라는 단어가 포함된 문서를 가진 모든 var 검색
```

### 라이브러리 저장소와 그 문서

Clojure 생태계의 라이브러리들은 대부분 공개 저장소를 통해 배포되며, 각 라이브러리는 보통 자신의 소스 코드 저장소에 사용법과 예제를 함께 제공합니다. 새로운 라이브러리를 도입하기 전에는 해당 라이브러리의 저장소에 있는 README와 예제 코드를 먼저 읽어보는 습관을 들이면 좋습니다. 라이브러리가 활발히 관리되고 있는지, 최근에도 업데이트가 있었는지를 함께 확인하는 것도 중요합니다.

### 커뮤니티 채널

Clojure 커뮤니티는 채팅 기반 커뮤니티, 질의응답 게시판, 지역·주제별 모임 등 다양한 형태로 존재합니다. 막히는 부분이 생겼을 때 비슷한 질문을 이미 누군가 해결해둔 경우가 많으므로, 질문을 올리기 전에 먼저 검색해보는 것이 좋습니다. 질문을 올릴 때는 최소한으로 재현 가능한 코드와 함께, 무엇을 시도했고 무엇이 예상과 달랐는지를 구체적으로 적으면 훨씬 좋은 답변을 받을 수 있습니다.

### REPL 자체를 자료로 활용하기

이 책 전체에서 강조했듯, Clojure를 배우는 가장 좋은 방법 중 하나는 REPL을 계속 열어두고 궁금한 것이 생길 때마다 바로 실험해보는 것입니다. 어떤 함수가 정확히 무슨 값을 반환하는지, 특정 표현식이 어떤 순서로 평가되는지는 문서를 읽는 것보다 직접 평가해보는 것이 더 빠르고 정확할 때가 많습니다. 18장에서 이야기한 REPL 기반 개발 습관은 새로운 개념을 학습할 때도 그대로 적용됩니다.

### 소스 코드 읽기

언어의 핵심 함수든 서드파티 라이브러리든, Clojure로 작성된 코드는 비교적 짧고 읽기 쉬운 경우가 많습니다. 어떤 함수가 정확히 어떻게 동작하는지 문서만으로 이해가 되지 않는다면, `source`로 실제 구현을 열어보거나 라이브러리의 소스 코드 저장소를 직접 열어 읽어보는 것을 주저하지 마세요. 잘 작성된 오픈소스 프로젝트를 읽는 것은 이 책에서 배운 관용구들이 실전에서 어떻게 쓰이는지 배우는 가장 좋은 방법 중 하나입니다.
