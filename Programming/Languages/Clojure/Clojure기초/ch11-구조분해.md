## 들어가며

4장에서 벡터, 맵과 같은 컬렉션을 다루는 법을 배웠고, 5장에서는 함수를 정의하고 호출하는 법을 배웠습니다. 이 두 가지를 실제로 함께 쓰다 보면 아주 흔한 패턴이 반복됩니다. 벡터를 받아서 `(nth v 0)`, `(nth v 1)`로 요소를 하나씩 꺼내거나, 맵을 받아서 `(get m :name)`, `(get m :age)`로 값을 하나씩 뽑아내는 코드입니다.

Clojure는 이런 "꺼내서 이름 붙이기" 작업을 언어 차원에서 지원합니다. 이것이 바로 **구조 분해(destructuring)**입니다. 구조 분해는 컬렉션의 모양(구조)을 그대로 코드에 나타내면, Clojure가 알아서 그 구조에 맞는 값을 꺼내 지역 이름에 바인딩(binding)해 주는 문법입니다.

이 장에서는 `let`과 함수 매개변수 목록에서 구조 분해를 사용하는 방법을 배우고, 벡터/시퀀스 구조 분해와 맵 구조 분해를 각각 살펴본 다음, 중첩된 자료구조를 분해하는 예제와 구조 분해 전/후 코드를 비교하며 왜 이 기능이 실전에서 유용한지 확인합니다.

## 구조 분해란 무엇인가

구조 분해는 한마디로 "패턴에 맞춰 값을 꺼내는 문법"입니다. 예를 들어 좌표를 나타내는 벡터 `[3 4]`가 있을 때, 우리는 보통 이렇게 씁니다.

```clojure
(def point [3 4])

(let [x (first point)
      y (second point)]
  (println "x:" x "y:" y))
;; => x: 3 y: 4
```

구조 분해를 쓰면 `point`의 모양을 그대로 흉내 낸 바인딩 형태 `[x y]`를 왼쪽에 두는 것만으로 같은 일이 끝납니다.

```clojure
(let [[x y] point]
  (println "x:" x "y:" y))
;; => x: 3 y: 4
```

`[x y]`라는 벡터 모양이 "point는 벡터이고, 첫 번째 요소를 x, 두 번째 요소를 y라고 부르겠다"는 선언 그 자체가 됩니다. 이것이 구조 분해의 핵심 아이디어입니다. **바인딩할 변수 이름들을, 원본 데이터와 똑같은 모양으로 나열하면 Clojure가 나머지를 알아서 처리한다**는 것입니다.

## let에서의 구조 분해

`let`은 구조 분해가 가장 자주 쓰이는 자리입니다. `let`의 바인딩 형태(binding form) 자리에는 단순한 심볼뿐 아니라 벡터나 맵 패턴도 올 수 있습니다.

### 벡터 구조 분해 (위치 기반)

벡터나 리스트처럼 순서가 있는 시퀀스는 **위치 기반**으로 분해합니다. 즉 패턴에서 몇 번째 자리에 있느냐에 따라 값이 결정됩니다.

```clojure
(let [[a b c] [10 20 30]]
  (println a b c))
;; => 10 20 30
```

분해할 값보다 패턴의 이름이 적으면 나머지는 그냥 무시됩니다.

```clojure
(let [[a b] [10 20 30 40]]
  (println a b))
;; => 10 20
```

반대로 패턴의 이름이 더 많으면 남는 이름에는 `nil`이 바인딩됩니다.

```clojure
(let [[a b c d] [1 2]]
  (println a b c d))
;; => 1 2 nil nil
```

### 밑줄로 필요 없는 값 건너뛰기

가운데 값은 필요 없고 처음과 세 번째 값만 필요하다면, 관례적으로 `_`(밑줄)을 자리 표시자로 사용합니다. `_`도 사실은 그냥 평범한 심볼이지만, "이 값은 쓰지 않겠다"는 의도를 드러내는 관용구입니다.

```clojure
(let [[first-name _ last-name] ["김" "중간" "철수"]]
  (println first-name last-name))
;; => 김 철수
```

### 나머지 요소 모으기: &

앞에서 몇 개만 이름을 붙이고, 그 뒤에 남는 요소를 전부 하나의 시퀀스로 받고 싶을 때는 `&`를 사용합니다. 이것은 함수의 가변 인자(variadic) 문법과 똑같은 모양입니다.

```clojure
(let [[first-item & rest-items] [1 2 3 4 5]]
  (println "첫 요소:" first-item)
  (println "나머지:" rest-items))
;; => 첫 요소: 1
;; => 나머지: (2 3 4 5)
```

`rest-items`는 벡터가 아니라 시퀀스라는 점에 유의하세요. `&` 뒤에 모인 값은 항상 시퀀스로 취급됩니다.

### 원본 전체도 함께 받기: :as

분해하면서 동시에 원본 컬렉션 전체도 이름 붙여 갖고 있고 싶다면 `:as` 키워드를 패턴의 끝에 붙입니다.

```clojure
(let [[x y :as whole] [7 8 9]]
  (println "x:" x "y:" y "전체:" whole))
;; => x: 7 y: 8 전체: [7 8 9]
```

`:as`는 특정 값을 로그로 남기거나, 분해한 값과 원본을 함께 다른 함수에 넘겨야 할 때 유용합니다.

### 시퀀스뿐 아니라 모든 시퀀스 가능한 것에 동작

벡터 구조 분해 문법은 벡터에만 국한되지 않습니다. 리스트, `range`가 만든 결과, 문자열(문자의 시퀀스로 취급)처럼 시퀀스로 변환 가능한 것이라면 모두 같은 문법으로 분해할 수 있습니다.

```clojure
(let [[a b c] '(100 200 300)]
  (println a b c))
;; => 100 200 300

(let [[c1 c2] "clojure"]
  (println c1 c2))
;; => \c \l
```

## 맵 구조 분해

맵은 순서가 없는 키-값 구조이므로 벡터처럼 위치로 분해할 수 없습니다. 대신 **키를 지정해서** 값을 꺼냅니다.

### :keys를 이용한 기본형

가장 널리 쓰이는 형태는 `:keys`입니다. 맵의 키가 키워드일 때, 그 키워드 이름과 똑같은 이름의 지역 변수로 값을 꺼내옵니다.

```clojure
(def user {:name "이영희" :age 29 :city "서울"})

(let [{:keys [name age city]} user]
  (println name "-" age "세, " city "거주"))
;; => 이영희 - 29 세, 서울 거주
```

`{:keys [name age city]}`는 "`user` 맵에서 `:name`, `:age`, `:city` 키의 값을 꺼내서 각각 `name`, `age`, `city`라는 이름으로 부르겠다"는 뜻입니다. 이름과 키워드 이름이 정확히 일치해야 자동으로 매칭된다는 점을 기억하세요.

맵에 없는 키를 요청하면 `nil`이 바인딩됩니다.

```clojure
(let [{:keys [name job]} user]
  (println name job))
;; => 이영희 nil
```

### :strs와 :syms

맵의 키가 키워드가 아니라 문자열이거나 심볼일 수도 있습니다. 이럴 때는 `:strs`, `:syms`를 사용합니다.

```clojure
(def config-by-string {"host" "localhost" "port" 8080})

(let [{:strs [host port]} config-by-string]
  (println host port))
;; => localhost 8080

(def config-by-symbol {'host "localhost" 'port 8080})

(let [{:syms [host port]} config-by-symbol]
  (println host port))
;; => localhost 8080
```

실무에서는 대부분 키워드 키를 쓰기 때문에 `:keys`를 압도적으로 많이 사용하지만, JSON을 파싱한 결과처럼 문자열 키 맵을 다뤄야 할 때는 `:strs`가 유용합니다.

### 기본값 지정: :or

맵에 키가 없을 때 `nil` 대신 다른 기본값을 쓰고 싶다면 `:or`를 함께 사용합니다.

```clojure
(let [{:keys [name job]
       :or {job "무직"}} user]
  (println name job))
;; => 이영희 무직
```

`:or` 뒤에는 "이름 -> 기본값" 형태의 맵을 적습니다. 여기서 이름은 `:keys`에서 사용한 것과 똑같은 지역 변수 이름이어야 합니다.

### 원본 맵 전체 받기: :as

벡터와 마찬가지로 맵을 분해하면서 원본 맵 자체도 갖고 싶다면 `:as`를 사용합니다.

```clojure
(let [{:keys [name age] :as whole-user} user]
  (println name age)
  (println "원본 맵:" whole-user))
;; => 이영희 29
;; => 원본 맵: {:name 이영희, :age 29, :city 서울}
```

`:as`로 받은 `whole-user`는 원본 맵을 그대로 가리키므로, 나중에 `assoc`으로 값을 갱신하거나 다른 함수에 그대로 넘길 때 편리합니다.

### 키워드 이름을 그대로 바인딩 이름으로: 축약 문법

키워드 키를 분해할 때, 변수 이름을 키워드와 동일하게 쓰는 것이 워낙 흔한 패턴이라 Clojure는 `:keys`보다 더 짧은 축약 문법도 제공합니다. 바로 맵 패턴 자체에 `:키워드`를 직접 나열하는 방식입니다.

```clojure
(let [{:keys [name age]} user]
  [name age])
;; 위와 동일한 결과를 내는 또 다른 표기: 네임스페이스가 붙은 키워드에서 자주 쓰임
(def user2 #:person{:name "박민수" :age 40})

(let [{:person/keys [name age]} user2]
  (println name age))
;; => 박민수 40
```

네임스페이스 있는 키워드(`:person/name`처럼)를 다룰 때는 `:person/keys`처럼 네임스페이스를 붙인 `:keys` 변형을 사용하면, 매번 네임스페이스를 반복해서 적지 않아도 됩니다. 이 부분은 10장 네임스페이스와 코드 구성에서 다룬 네임스페이스 키워드 개념과 이어집니다.

## 함수 매개변수에서의 구조 분해

구조 분해는 `let`뿐 아니라 함수의 매개변수 목록에서도 그대로 사용할 수 있습니다. 함수가 벡터나 맵을 인자로 받는 경우, 함수 몸체 첫 줄에서 다시 분해하는 대신 매개변수 자리에서 곧바로 분해해버리면 코드가 한결 깔끔해집니다.

### 벡터를 받는 함수

```clojure
(defn distance-from-origin [[x y]]
  (Math/sqrt (+ (* x x) (* y y))))

(distance-from-origin [3 4])
;; => 5.0
```

`[[x y]]`에서 바깥쪽 `[]`는 "매개변수가 하나"라는 뜻이고, 안쪽 `[x y]`는 "그 하나의 매개변수를 벡터로 보고 분해하겠다"는 뜻입니다. 처음 보면 대괄호가 겹쳐서 헷갈릴 수 있으니, 매개변수 목록 전체를 감싸는 바깥 `[]`와 분해 패턴인 안쪽 `[]`를 구분해서 읽는 연습이 필요합니다.

### 맵을 받는 함수: 옵션 인자 패턴

Clojure에서 함수에 여러 옵션을 전달할 때 맵 하나로 묶어서 넘기고, 함수 정의부에서 `:keys`로 분해하는 방식이 매우 흔한 관용구입니다.

```clojure
(defn make-greeting [{:keys [name greeting]
                       :or {greeting "안녕하세요"}}]
  (str greeting ", " name "님!"))

(make-greeting {:name "지훈"})
;; => "안녕하세요, 지훈님!"

(make-greeting {:name "지훈" :greeting "반갑습니다"})
;; => "반갑습니다, 지훈님!"
```

이 패턴은 인자 개수(애리티)를 늘리지 않고도 함수에 새로운 옵션을 추가할 수 있게 해줍니다. 만약 나중에 `:emoji?` 같은 옵션을 추가하고 싶다면, 함수 호출부를 바꿀 필요 없이 `:keys` 목록에 `emoji?`만 추가하면 됩니다.

### & 를 이용한 가변 인자와 맵 구조 분해의 결합

함수가 `키 값 키 값 ...` 형태로 나열된 가변 인자를 받되, 내부적으로는 맵처럼 다루고 싶을 때는 `&`와 맵 구조 분해를 함께 씁니다.

```clojure
(defn connect [host & {:keys [port timeout]
                        :or {port 80 timeout 3000}}]
  (println (str host ":" port) "에 연결, 타임아웃" timeout "ms"))

(connect "example.com")
;; => example.com:80 에 연결, 타임아웃 3000 ms

(connect "example.com" :port 443 :timeout 5000)
;; => example.com:443 에 연결, 타임아웃 5000 ms
```

`& {:keys [...]}`는 "이 뒤로 오는 인자들을 모아서 맵으로 만든 다음 곧바로 분해한다"는 의미입니다. 내부적으로 `&`는 나머지 인자를 시퀀스로 모으고, 그 시퀀스가 `(:port 443 :timeout 5000)`처럼 짝수 개의 키-값 쌍이면 맵 구조 분해 패턴이 이를 맵으로 해석해 처리합니다.

## 중첩된 자료구조 구조 분해

구조 분해의 진짜 힘은 중첩된 자료구조를 다룰 때 드러납니다. 패턴을 데이터의 모양과 똑같이 중첩시키기만 하면, 아무리 깊은 곳에 있는 값도 한 번에 꺼낼 수 있습니다.

### 벡터 안의 벡터

```clojure
(def line [[0 0] [3 4]])

(let [[[x1 y1] [x2 y2]] line]
  (println "시작점:" x1 y1)
  (println "끝점:" x2 y2))
;; => 시작점: 0 0
;; => 끝점: 3 4
```

`line`은 "점 두 개로 이루어진 벡터"이고, 각 점은 다시 "[x y]로 이루어진 벡터"입니다. 패턴 `[[x1 y1] [x2 y2]]`는 이 구조를 그대로 흉내 낸 모양입니다.

### 맵 안의 맵

```clojure
(def order
  {:id 1001
   :customer {:name "최수진" :email "sujin@example.com"}
   :items [{:product "키보드" :price 55000}
           {:product "마우스" :price 25000}]})

(let [{:keys [id]
       {customer-name :name customer-email :email} :customer} order]
  (println "주문번호:" id)
  (println "고객:" customer-name customer-email))
;; => 주문번호: 1001
;; => 고객: 최수진 sujin@example.com
```

여기서 `{customer-name :name customer-email :email} :customer` 부분을 눈여겨보세요. 맵 구조 분해에는 `:keys` 축약형 외에 **"변수 심볼 키워드" 쌍을 나란히 나열하는 완전한 형태**도 있습니다. `:keys [name email]`처럼 변수 이름과 키워드 이름이 같을 때만 축약형을 쓸 수 있고, 이름을 다르게 붙이고 싶다면(`name` 대신 `customer-name`처럼) 이 완전한 형태를 사용해야 합니다. 이 형태를 중첩 맵 값 앞에 붙이면, 중첩된 `:customer` 맵을 다시 그 자리에서 분해할 수 있습니다.

### 벡터 안의 맵 시퀀스와 & 조합

`order`의 `:items`처럼 맵으로 이루어진 벡터에서, 첫 번째 항목만 자세히 들여다보고 나머지는 그대로 두고 싶은 경우도 흔합니다.

```clojure
(let [{:keys [items]} order
      [{first-product :product first-price :price} & rest-items] items]
  (println "첫 상품:" first-product first-price "원")
  (println "나머지 상품 수:" (count rest-items)))
;; => 첫 상품: 키보드 55000 원
;; => 나머지 상품 수: 1
```

이렇게 벡터 구조 분해, 맵 구조 분해, `&`, `:as`를 자유롭게 조합할 수 있다는 점이 Clojure 구조 분해 문법의 강점입니다. 데이터가 아무리 복잡하게 중첩되어 있어도, 그 모양을 패턴으로 그대로 옮겨 적으면 됩니다.

### 완전한 형태로 전체 예제 다시 보기

```clojure
(defn describe-order [{:keys [id]
                        {:keys [name email]} :customer
                        items :items}]
  (str "주문 #" id " - 고객: " name " (" email "), "
       "상품 " (count items) "개"))

(describe-order order)
;; => "주문 #1001 - 고객: 최수진 (sujin@example.com), 상품 2개"
```

함수 매개변수 자리에서도 `let`과 똑같은 방식으로 중첩 패턴을 쓸 수 있음을 보여주는 예제입니다.

## 구조 분해 전/후 비교: 왜 코드가 간결해지는가

이제 구조 분해를 쓰지 않았을 때와 썼을 때를 나란히 비교해 보면서, 이 문법이 실제로 코드에 어떤 이득을 주는지 확인해 보겠습니다.

### 예제 1: 좌표 계산

**구조 분해 이전**

```clojure
(defn midpoint-old [p1 p2]
  (let [x1 (first p1)
        y1 (second p1)
        x2 (first p2)
        y2 (second p2)]
    [(/ (+ x1 x2) 2.0) (/ (+ y1 y2) 2.0)]))

(midpoint-old [0 0] [4 6])
;; => [2.0 3.0]
```

**구조 분해 이후**

```clojure
(defn midpoint [[x1 y1] [x2 y2]]
  [(/ (+ x1 x2) 2.0) (/ (+ y1 y2) 2.0)])

(midpoint [0 0] [4 6])
;; => [2.0 3.0]
```

`first`, `second`를 호출하며 임시 이름을 만드는 4줄짜리 `let` 블록이, 매개변수 목록 자체의 패턴으로 완전히 사라졌습니다. 함수의 의도("점 두 개를 받아 중점을 구한다")도 시그니처만 보고 더 잘 드러납니다.

### 예제 2: 사용자 정보 요약

**구조 분해 이전**

```clojure
(defn summarize-user-old [user]
  (let [name (get user :name)
        age (get user :age "미상")
        email (get user :email)]
    (str name " (" age ") - " (or email "이메일 없음"))))

(summarize-user-old {:name "한지민" :age 33 :email "jimin@example.com"})
;; => "한지민 (33) - jimin@example.com"
```

**구조 분해 이후**

```clojure
(defn summarize-user [{:keys [name email]
                        :or {age "미상"}
                        :as user}]
  (str name " (" (:age user "미상") ") - " (or email "이메일 없음")))
```

이 예에서는 사실 `:or`가 `:age`처럼 맵에 값이 있을 때는 적용되지 않고 키가 아예 없을 때만 적용된다는 미묘한 차이가 있어, 완전히 동일하게 옮기려면 오히려 원래 코드의 `(get user :age "미상")` 방식이 더 명확할 수도 있습니다. 이는 실전에서 매우 중요한 교훈입니다.

> **주의:** `:or`의 기본값은 키가 맵에 **존재하지 않을 때만** 적용됩니다. 값이 `nil`로 명시적으로 들어있는 경우에도 `:or` 기본값이 적용되지만, `false`처럼 nil이 아닌 값이 들어있으면 그 값이 그대로 사용됩니다. 반면 `(get m :k "기본값")`은 `nil`이든 키가 없든 상관없이 값이 "참(truthy)"이 아니면 무조건 기본값을 반환하지 않고, 정확히는 키가 없을 때만 기본값을 씁니다. 미세한 차이가 있으므로 값이 `nil`일 수 있는 상황에서는 실제 동작을 REPL에서 확인하는 습관을 들이세요.

간결함만 보고 무작정 구조 분해를 남용하기보다, 의미가 정확히 같은지 확인하는 것이 중요합니다. 아래는 의미를 정확히 유지하면서 구조 분해로 정리한 버전입니다.

```clojure
(defn summarize-user [{:keys [name email] :as user}]
  (str name " (" (:age user "미상") ") - " (or email "이메일 없음")))

(summarize-user {:name "한지민" :age 33 :email "jimin@example.com"})
;; => "한지민 (33) - jimin@example.com"

(summarize-user {:name "박서준"})
;; => "박서준 (미상) - 이메일 없음"
```

`:age`처럼 맵 조회 시 기본값이 필요한 경우에는 `:keys`의 `:or` 대신, 필요한 자리에서 직접 `(:age user "미상")`처럼 키워드를 함수처럼 호출하는 3장에서 배운 문법을 사용하는 편이 더 명확할 때도 많습니다.

### 예제 3: 시퀀스에서 처음 두 값만 다루기

**구조 분해 이전**

```clojure
(defn describe-top-scores-old [scores]
  (let [sorted (sort > scores)
        top (first sorted)
        second-place (second sorted)]
    (str "1위: " top ", 2위: " second-place)))

(describe-top-scores-old [88 95 72 95 60])
;; => "1위: 95, 2위: 95"
```

**구조 분해 이후**

```clojure
(defn describe-top-scores [scores]
  (let [[top second-place] (sort > scores)]
    (str "1위: " top ", 2위: " second-place)))

(describe-top-scores [88 95 72 95 60])
;; => "1위: 95, 2위: 95"
```

`first`, `second`라는 두 번의 함수 호출이 하나의 패턴으로 합쳐지면서, "정렬한 결과에서 앞의 두 값을 쓴다"는 의도가 한눈에 들어옵니다.

## 구조 분해와 시퀀스 추상화

8장에서 배운 `map`, `reduce` 같은 고차 함수와 구조 분해를 결합하면 시너지가 커집니다. 특히 맵의 항목들(키-값 쌍)을 순회할 때 구조 분해가 빛을 발합니다. 맵을 시퀀스로 변환하면 `[키 값]` 형태의 벡터들이 나오기 때문입니다.

```clojure
(def prices {:apple 1500 :banana 800 :grape 3200})

(map (fn [[fruit price]] (str fruit ": " price "원"))
     prices)
;; => ("apple: 1500원" "banana: 800원" "grape: 3200원")
```

`(fn [[fruit price]] ...)`는 맵의 각 항목이 `[키 값]` 벡터로 들어온다는 사실을 알고, 그 자리에서 곧바로 분해해버립니다. `reduce`에서도 마찬가지입니다.

```clojure
(reduce (fn [total [_ price]] (+ total price))
        0
        prices)
;; => 5500
```

여기서는 키는 필요 없으므로 `_`로 무시하고 값만 취해 누적합니다. 이런 패턴은 실무 Clojure 코드에서 정말 자주 등장하므로 꼭 익숙해져 두는 것이 좋습니다.

## 정리: 구조 분해 패턴 한눈에 보기

| 패턴 | 의미 |
|---|---|
| `[a b c]` | 벡터/시퀀스에서 위치 순서대로 분해 |
| `[a b & rest]` | 앞의 몇 개는 이름 붙이고, 나머지는 시퀀스로 |
| `[a b :as whole]` | 분해하면서 원본 전체도 함께 받기 |
| `{:keys [a b]}` | 맵에서 `:a`, `:b` 키의 값을 꺼내기 |
| `{:strs [a b]}` | 맵에서 `"a"`, `"b"` 문자열 키의 값을 꺼내기 |
| `{:syms [a b]}` | 맵에서 `'a`, `'b` 심볼 키의 값을 꺼내기 |
| `{:keys [a] :or {a 0}}` | 키가 없을 때 기본값 지정 |
| `{:keys [a] :as whole}` | 분해하면서 원본 맵도 함께 받기 |
| `{x :some-key}` | 키워드와 다른 이름으로 바인딩 |

## 요약

- 구조 분해는 컬렉션의 모양을 패턴으로 표현해서, 값을 자동으로 지역 이름에 바인딩하는 문법입니다.
- `let` 바인딩과 함수 매개변수 목록 양쪽에서 동일한 문법으로 구조 분해를 사용할 수 있습니다.
- 벡터/시퀀스는 위치 기반으로 분해하며, `&`로 나머지를 모으고 `:as`로 원본 전체를 함께 받을 수 있습니다.
- 맵은 키 기반으로 분해하며, `:keys`/`:strs`/`:syms`로 키 종류에 맞게 값을 꺼내고, `:or`로 기본값을, `:as`로 원본 맵을 함께 받을 수 있습니다.
- 패턴을 중첩시키면 아무리 깊게 중첩된 자료구조라도 한 번에 분해할 수 있습니다.
- 구조 분해는 `first`/`second`/`get` 호출을 반복하던 코드를 간결하게 줄여주지만, `:or` 기본값의 동작(키 부재 시에만 적용)처럼 미묘한 차이가 있으니 의미가 정확히 같은지 항상 확인해야 합니다.
- `map`, `reduce` 같은 고차 함수의 콜백에서 `[k v]` 형태로 맵 항목을 분해하는 패턴은 실전에서 매우 자주 쓰입니다.
