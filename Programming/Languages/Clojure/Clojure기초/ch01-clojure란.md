프로그래밍 언어를 새로 배운다는 것은 단순히 새로운 문법을 외우는 일이 아닙니다. 그 언어가 세상을 어떻게 바라보는지, 문제를 어떤 방식으로 쪼개고 다시 조립하는지를 배우는 일입니다. Clojure는 그런 의미에서 상당히 독특한 관점을 가진 언어입니다. 괄호로 가득한 낯선 문법 뒤에는 "프로그램은 데이터를 변형하는 과정이다"라는 아주 오래되고도 강력한 아이디어가 자리 잡고 있습니다. 이번 장에서는 Clojure가 어떤 언어인지, 어디에 쓰이고 왜 배울 만한지, 그리고 이 책을 어떤 방식으로 따라가면 좋을지 살펴봅니다.

## Clojure는 어떤 언어인가

Clojure는 리치 히키(Rich Hickey)가 2007년에 공개한 프로그래밍 언어로, 세 가지 굵직한 특징으로 요약할 수 있습니다. 첫째는 Lisp 계열 언어라는 점, 둘째는 JVM(Java Virtual Machine) 위에서 동작하는 함수형 언어라는 점, 셋째는 불변 자료구조와 REPL 중심 개발을 핵심 가치로 삼는다는 점입니다. 하나씩 풀어보겠습니다.

### Lisp 계열 언어

Lisp은 1958년에 등장한, 컴퓨터 과학 역사에서 두 번째로 오래된 고급 프로그래밍 언어 계열입니다. Lisp 계열 언어의 가장 큰 특징은 코드 자체가 데이터 구조로 표현된다는 점입니다. 이를 흔히 "코드가 곧 데이터다(code as data)" 또는 동형성(homoiconicity)이라고 부릅니다. 예를 들어 다음과 같은 Clojure 코드를 봅시다.

```clojure
(+ 1 2 3)
;; => 6
```

이 코드는 괄호로 둘러싸인 리스트처럼 보입니다. 실제로도 그렇습니다. `(+ 1 2 3)`은 "더하기 함수에 1, 2, 3을 넘겨서 실행하라"는 의미이면서 동시에 `+`, `1`, `2`, `3`이라는 네 개의 원소를 가진 리스트라는 데이터이기도 합니다. 코드와 데이터의 형태가 같다는 사실은 나중에 12장 매크로 기초에서 다시 만나게 될 텐데, 이는 Clojure로 새로운 문법을 스스로 만들어낼 수 있는 기반이 됩니다. 지금 단계에서는 "Clojure 코드는 함수 이름을 맨 앞에 두고 괄호로 감싼다"는 표기법, 즉 전위 표기법(prefix notation)에만 익숙해지면 충분합니다.

### JVM 기반 함수형 언어

Clojure는 자바 가상 머신 위에서 실행됩니다. 소스 코드를 작성하면 바이트코드로 컴파일되어 JVM에서 실행되고, 자바로 만들어진 방대한 라이브러리 생태계를 그대로 가져다 쓸 수 있습니다. 문자열 처리, 날짜 계산, 네트워크 통신, 데이터베이스 접속 같은 것들을 자바 라이브러리에서 빌려 쓰는 일이 흔합니다. 이 부분은 15장 Java 상호운용에서 자세히 다룹니다.

동시에 Clojure는 함수형 프로그래밍 언어입니다. 함수형 프로그래밍이란 프로그램을 "상태를 변경하는 명령어의 나열"이 아니라 "입력을 받아 출력을 내놓는 함수의 조합"으로 바라보는 접근입니다. 예를 들어 리스트에서 짝수만 골라 두 배로 만드는 작업을 Clojure에서는 이렇게 표현합니다.

```clojure
(defn double-evens [numbers]
  (->> numbers
       (filter even?)
       (map #(* 2 %))))

(double-evens [1 2 3 4 5 6])
;; => (4 8 12)
```

반복문으로 인덱스를 하나씩 옮겨가며 조건을 확인하는 대신, "짝수를 걸러내라", "두 배로 만들어라"라는 두 개의 작은 함수를 파이프라인처럼 이어 붙였습니다. 이런 식으로 작은 함수를 조합해 큰 문제를 해결하는 방식은 8장 시퀀스 추상화와 고차 함수에서 본격적으로 다룹니다.

### 불변 자료구조와 REPL 중심 개발

Clojure에서 만들어지는 대부분의 값은 불변(immutable)입니다. 한 번 만든 벡터나 맵은 절대로 그 내용이 바뀌지 않습니다. "값을 바꾸는" 것처럼 보이는 연산은 사실 원본은 그대로 둔 채 변경된 내용을 담은 새로운 값을 만들어내는 것입니다.

```clojure
(def original [1 2 3])
(def changed (conj original 4))

original
;; => [1 2 3]

changed
;; => [1 2 3 4]
```

`conj`로 4를 추가했지만 `original`은 여전히 `[1 2 3]`입니다. 이렇게 원본을 훼손하지 않고 새 값을 만들어내면서도 메모리와 성능을 낭비하지 않는 자료구조를 영속적 자료구조(persistent data structure)라고 부릅니다. 이 개념은 여러 스레드가 동시에 같은 데이터를 읽어도 안전하다는 뜻이기도 해서, Clojure가 동시성 프로그래밍에서 강점을 갖는 근본적인 이유가 됩니다. 자세한 내용은 9장 불변성과 영속적 자료구조, 13장 상태와 동시성 모델에서 다룹니다.

또 하나의 핵심 가치는 REPL(Read-Eval-Print Loop) 중심 개발입니다. REPL은 코드를 한 줄씩 즉시 실행해보고 결과를 바로 확인할 수 있는 대화형 환경입니다. Clojure 개발자는 프로그램을 처음부터 끝까지 작성한 뒤 실행 결과를 기다리는 대신, REPL에 함수 하나를 정의하고 바로 호출해보고, 결과가 마음에 들지 않으면 고쳐서 다시 호출해보는 식으로 살아있는 프로그램과 대화하듯 개발합니다. REPL이 왜 중요한지, 어떻게 사용하는지는 2장 개발 환경 준비와 첫 실행에서 직접 체험해봅니다.

## Clojure는 어디에 쓰이는가

Clojure는 학술적인 실험 언어가 아니라 실무에서 널리 쓰이는 언어입니다. 대표적인 활용 분야는 다음과 같습니다.

- **웹 백엔드**: Ring, Compojure, Pedestal 같은 라이브러리를 이용해 HTTP 서버와 API를 구축합니다. 불변 자료구조 덕분에 여러 요청을 동시에 처리해도 예상치 못한 부작용이 적습니다.
- **데이터 처리와 분석**: 맵과 벡터로 표현된 데이터를 함수 파이프라인으로 변환하는 데 뛰어나서, ETL(추출-변환-적재) 파이프라인이나 배치 처리 시스템에 자주 쓰입니다.
- **동시성이 중요한 시스템**: 아톰(atom), 레퍼런스(ref), 에이전트(agent) 같은 도구로 여러 스레드가 안전하게 상태를 공유하는 시스템을 비교적 단순하게 작성할 수 있습니다. 금융 거래 시스템이나 실시간 데이터 스트리밍 시스템에서 이런 특성이 빛을 발합니다.
- **인프라 및 도구 개발**: 빌드 도구, 정적 분석기, 사내 자동화 도구처럼 "정확성과 표현력"이 중요한 코드베이스에서도 선호됩니다.

또한 ClojureScript라는 자매 언어를 통해 같은 언어로 브라우저에서 동작하는 프런트엔드 코드를 작성할 수도 있습니다. 이 책에서는 JVM 위에서 동작하는 Clojure 자체에 집중하지만, 익힌 개념 대부분은 ClojureScript에도 그대로 적용됩니다.

## 다른 언어와 비교했을 때 Clojure의 위치

프로그래밍 경험이 있는 독자라면 Java나 Python 같은 언어와 Clojure가 어떻게 다른지 궁금할 것입니다.

Java와 비교하면, 둘 다 JVM 위에서 동작하고 상호운용이 가능하지만 사고방식은 상당히 다릅니다. Java는 클래스와 객체를 중심으로 상태를 캡슐화하는 객체지향 언어입니다. 객체 내부에 필드를 두고 메서드로 그 필드를 변경하는 것이 자연스러운 패턴입니다. 반면 Clojure는 "데이터는 데이터일 뿐이고, 함수는 그 데이터를 변형한다"는 관점을 취합니다. 클래스 계층을 설계하는 대신, 맵이나 벡터 같은 몇 가지 범용 자료구조와 그 위에서 동작하는 풍부한 함수 집합을 사용합니다. 이 덕분에 서로 다른 도메인의 데이터라도 같은 함수(예: `map`, `filter`, `reduce`)로 다룰 수 있다는 장점이 있습니다.

Python과 비교하면, 둘 다 동적 타입 언어이고 REPL을 지원하며 간결한 코드를 지향한다는 공통점이 있습니다. 그러나 Python의 리스트나 딕셔너리는 기본적으로 가변(mutable)인 반면 Clojure의 컬렉션은 기본적으로 불변입니다. 또한 Python은 들여쓰기와 다양한 연산자 우선순위 규칙을 가진 문법을 사용하지만, Clojure는 거의 모든 것이 괄호로 둘러싸인 함수 호출 형태를 취하는 균일한 문법을 가집니다. 처음에는 괄호가 많아 낯설게 느껴지지만, 익숙해지면 "이 코드가 무엇을 의미하는지" 애매한 경우가 오히려 줄어듭니다.

Clojure가 내세우는 핵심 철학은 단순함(simplicity)입니다. 여기서 단순함은 "배우기 쉽다"는 뜻이 아니라 "여러 개념이 서로 얽혀 있지 않다(단일 관심사를 가진다)"는 뜻에 가깝습니다. 리치 히키는 유명한 강연 "Simple Made Easy"에서 단순함(simple)과 쉬움(easy)을 구분했습니다. 클래스 상속처럼 익숙해서 쉽게 느껴지는 도구라도 여러 개념을 뒤섞어 복잡하게 만들 수 있다는 것이 그의 주장입니다. Clojure가 상속 대신 합성(composition)을, 가변 상태 대신 불변 값을 선호하는 이유도 여기에 있습니다. 앞서 본 코드와 데이터의 동일성 역시 이런 단순함 철학의 연장선입니다. 특수한 문법을 새로 만드는 대신, 이미 있는 데이터 구조(리스트)로 코드 자체를 표현함으로써 언어의 개념 수를 최소화한 것입니다.

## 이 책의 학습 방향

이 책은 프로그래밍 경험은 있지만 함수형 언어나 Lisp 계열 언어는 처음 접하는 독자를 대상으로 합니다. 따라서 "이 문법은 무엇을 의미하는가"보다 "왜 이런 방식으로 문제를 풀면 유리한가"에 초점을 맞춰 설명을 이어가려 합니다.

전체 구성은 크게 네 부분으로 나눌 수 있습니다.

1. **기초 다지기(1~4장)**: 개발 환경을 준비하고, 기본 문법과 데이터 타입, 컬렉션을 익힙니다.
2. **함수형 사고 익히기(5~9장)**: 함수 정의, 제어 흐름, 재귀, 고차 함수, 불변성처럼 Clojure다운 사고방식의 핵심을 다룹니다.
3. **언어의 힘 활용하기(10~14장)**: 네임스페이스, 구조 분해, 매크로, 동시성, 예외 처리 등 실무 코드에서 자주 마주치는 주제를 다룹니다.
4. **실전 응용(15~18장)**: Java 상호운용, 파일 입출력, 테스트 작성, 좋은 코드 작성 습관을 통해 실제 프로젝트에 적용할 준비를 합니다.

각 장에는 REPL에서 직접 실행해볼 수 있는 예제 코드가 풍부하게 들어 있습니다. 가능하다면 눈으로만 읽지 말고 2장에서 준비할 REPL을 옆에 띄워두고 코드를 직접 입력하면서 결과를 확인하기를 권합니다. Clojure는 "REPL과 대화하며 배우는 언어"이기 때문에, 손으로 직접 입력해보는 것이 가장 빠른 학습 방법입니다.

## 요약

- Clojure는 리치 히키가 만든 Lisp 계열의 함수형 프로그래밍 언어이며, JVM 위에서 동작합니다.
- Lisp 계열 언어답게 코드와 데이터의 형태가 같은 동형성을 가지며, 이는 매크로 같은 강력한 기능의 기반이 됩니다.
- Clojure의 컬렉션은 기본적으로 불변이며, 원본을 훼손하지 않고 새 값을 만들어내는 영속적 자료구조를 사용합니다.
- REPL을 이용한 대화형 개발이 Clojure 개발 문화의 핵심이며, 코드를 작성하고 즉시 평가해보며 발전시켜 나갑니다.
- Clojure는 웹 백엔드, 데이터 처리, 동시성이 중요한 시스템 등 다양한 실무 분야에서 사용됩니다.
- Java와는 JVM 기반이라는 공통점이 있지만 객체지향 대신 데이터와 함수 중심의 접근을 취하며, Python과는 동적 타입이라는 공통점이 있지만 불변성과 균일한 문법에서 차이를 보입니다.
- Clojure의 핵심 철학은 단순함이며, 이는 여러 개념을 뒤섞지 않고 각 도구가 하나의 관심사만 다루도록 하는 것을 의미합니다.

## 연습문제

1. 다음 표현식이 리스트로서 가지는 원소가 몇 개이고 각각 무엇인지 말로 설명해보세요: `(* (+ 1 2) 3)`. 그리고 이 표현식을 계산하면 어떤 값이 나올지 예상해보세요.
2. 자신이 알고 있는 언어(Java, Python, JavaScript 등) 중 하나를 골라, 그 언어에서 "리스트나 배열에 원소를 추가하는 연산"이 원본을 변경하는지, 아니면 새로운 값을 만들어내는지 조사해서 정리해보세요. Clojure의 방식과 어떻게 다른지 비교해보세요.
3. 이 장에서 소개한 `double-evens` 함수를 참고하여, 정수 리스트에서 3의 배수만 골라 그 값을 제곱하는 과정을 말로 설명해보세요(코드로 작성하지 않아도 됩니다. "먼저 무엇을 걸러내고, 그다음 무엇을 적용한다"는 순서를 서술하면 됩니다).
4. "단순함(simple)과 쉬움(easy)은 다르다"는 이 장의 설명을 참고하여, 자신이 경험한 개발 도구나 언어 기능 중 "쉽지만 단순하지는 않았던" 사례를 하나 떠올려 짧게 적어보세요.
5. Clojure가 실무에서 활용되는 분야 네 가지(웹 백엔드, 데이터 처리, 동시성 시스템, 인프라 도구) 중 자신의 관심 분야와 가장 가까운 것을 고르고, 그 분야에서 불변 자료구조가 어떤 도움을 줄 수 있을지 자신의 생각을 적어보세요.
