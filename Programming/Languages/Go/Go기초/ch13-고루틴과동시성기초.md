지금까지 작성한 프로그램은 모두 위에서 아래로, 한 줄씩 순서대로 실행되었습니다. 함수를 호출하면 그 함수가 끝날 때까지 기다렸다가 다음 줄로 넘어가는 식이었죠. 하지만 현실의 프로그램은 종종 "여러 일을 동시에 처리해야" 합니다. 웹 서버는 수천 명의 사용자 요청을 동시에 처리해야 하고, 파일을 여러 개 내려받는 프로그램은 하나가 끝나기를 기다렸다가 다음 것을 시작하기보다는 여러 개를 한꺼번에 진행하는 편이 훨씬 빠릅니다.

Go는 이런 요구를 언어 차원에서 지원하도록 설계된 언어입니다. 1장 "Go란 무엇인가"에서 이미 언급했듯, 동시성은 Go의 핵심 설계 목표 중 하나입니다. 이번 장에서는 Go 동시성 프로그래밍의 가장 기본 단위인 고루틴(goroutine)을 소개합니다. 고루틴끼리 데이터를 주고받는 방법은 14장 "채널"에서 이어서 다룹니다.

## 동시성과 병렬성

고루틴을 이해하기 전에 먼저 짚고 넘어가야 할 개념이 있습니다. 바로 동시성(concurrency)과 병렬성(parallelism)의 차이입니다. 두 단어는 비슷해 보이지만 가리키는 대상이 다릅니다.

- **동시성**은 여러 작업을 "동시에 진행되도록 다루는 것"을 뜻합니다. 여러 작업이 서로 겹쳐서 진행되며, 하나가 잠깐 멈춘 사이 다른 작업이 진행될 수 있도록 구조를 짜는 것이 핵심입니다. 반드시 물리적으로 같은 순간에 실행될 필요는 없습니다.
- **병렬성**은 여러 작업을 "실제로 같은 순간에" 실행하는 것을 뜻합니다. 이를 위해서는 CPU 코어가 여러 개 있어야 합니다.

비유를 들어보겠습니다. 바리스타 한 명이 커피 세 잔을 준비한다고 합시다. 원두를 가는 동안 다른 손님의 우유를 데우고, 우유가 데워지는 동안 첫 번째 손님의 컵을 준비하는 식으로 작업을 번갈아 가며 진행하면, 바리스타는 한 명뿐이지만 세 주문이 "동시에 진행되고 있는" 것처럼 보입니다. 이것이 동시성입니다. 반면 바리스타가 세 명이라서 각자 자기 주문을 정말로 같은 순간에 만들고 있다면, 이것이 병렬성입니다.

CPU 코어가 하나뿐인 컴퓨터에서도 운영체제는 여러 프로그램을 아주 짧은 시간 단위로 번갈아 실행시켜서 "동시에 실행되는 것처럼" 보이게 만들 수 있습니다. 이것도 동시성입니다. 반면 코어가 여러 개 있어야만 병렬성이 성립합니다. 정리하면 동시성은 프로그램을 어떻게 "구조화"할 것인가의 문제이고, 병렬성은 그 구조화된 작업을 하드웨어가 실제로 어떻게 "실행"하느냐의 문제입니다.

Go의 고루틴은 동시성을 위한 도구입니다. 여러 개의 고루틴을 실행해두면, Go 런타임의 스케줄러가 상황에 따라 이들을 하나의 CPU 코어에서 번갈아 실행시키거나(동시성만 있는 경우), 여러 코어에 나누어 진짜로 동시에 실행시킵니다(병렬성까지 있는 경우). 프로그래머는 "이 작업을 독립적으로 실행해도 된다"는 것만 표현하면 되고, 실제로 몇 개의 코어에 어떻게 배치할지는 런타임이 알아서 결정합니다.

## go 키워드로 고루틴 실행하기

Go에서 새로운 고루틴을 실행하는 방법은 아주 간단합니다. 함수를 호출하는 코드 앞에 `go` 키워드만 붙이면 됩니다.

```go
package main

import (
	"fmt"
	"time"
)

func sayHello() {
	fmt.Println("안녕하세요!")
}

func main() {
	go sayHello()                      // 새로운 고루틴에서 실행
	time.Sleep(100 * time.Millisecond) // 고루틴이 실행될 시간을 벌어준다
	fmt.Println("main 함수 종료")
}
```

`go sayHello()`는 `sayHello` 함수를 새로운 고루틴에서 실행하라는 뜻이며, 이 문장은 함수가 끝날 때까지 기다리지 않고 즉시 다음 줄로 넘어갑니다. 이것이 일반 함수 호출과 고루틴 실행의 가장 큰 차이입니다. 일반 호출은 함수가 끝나야 다음 줄로 넘어가지만, `go`를 붙인 호출은 "이 작업은 백그라운드에서 진행시켜라"라고 지시만 하고 곧바로 다음 줄로 진행합니다.

사실 `main` 함수 자체도 하나의 고루틴 위에서 실행됩니다. 이를 **메인 고루틴**이라고 부릅니다. `go sayHello()`를 호출하면 메인 고루틴과 별개로 동작하는 새로운 고루틴이 하나 더 생기는 셈이고, 이 순간부터 프로그램에는 두 개의 고루틴이 동시에 존재하게 됩니다.

## 고루틴은 왜 가벼운가

다른 언어에서 "동시에 여러 작업을 실행한다"고 하면 보통 운영체제 스레드(OS thread)를 떠올립니다. 그런데 Go는 왜 굳이 고루틴이라는 별도의 개념을 만들었을까요? 답은 비용에 있습니다.

운영체제 스레드는 하나를 만들 때마다 보통 수 메가바이트 크기의 스택 공간을 미리 확보하고, 스레드 사이를 전환할 때마다 커널이 개입해야 합니다. 그래서 스레드를 수천 개만 만들어도 메모리와 성능에 부담이 됩니다.

반면 고루틴은 Go 런타임이 자체적으로 관리하는 훨씬 가벼운 실행 단위입니다. 고루틴 하나는 처음에 몇 킬로바이트 정도의 아주 작은 스택만 가지고 시작하며, 필요에 따라 이 스택이 자동으로 늘어나거나 줄어듭니다. 게다가 고루틴을 스케줄링하는 작업은 커널이 아니라 Go 런타임이 사용자 영역에서 직접 처리하기 때문에 전환 비용도 훨씬 저렴합니다. Go 런타임은 이렇게 만들어진 수많은 고루틴을 적은 수의 운영체제 스레드 위에 올려서 실행하는데, 이런 방식을 M개의 고루틴을 N개의 스레드에 배치한다는 의미에서 M:N 스케줄링이라고 부릅니다.

이 덕분에 Go 프로그램에서는 고루틴을 수만 개, 많게는 수십만 개까지도 부담 없이 만들 수 있습니다. 정확한 스케줄링 원리까지 깊이 알 필요는 없지만, "고루틴은 스레드보다 훨씬 저렴하기 때문에 마음 놓고 많이 만들어도 된다"는 감각만 기억해두면 충분합니다.

## 흔한 실수: main 함수가 먼저 끝나버리는 문제

고루틴을 처음 사용할 때 거의 모든 사람이 한 번쯤 겪는 실수가 있습니다. 다음 코드를 봅시다.

```go
package main

import "fmt"

func main() {
	go fmt.Println("이 메시지는 화면에 안 보일 수도 있다")
	fmt.Println("main 함수 종료")
}
```

이 프로그램을 실행하면 "이 메시지는 화면에 안 보일 수도 있다"라는 문장이 출력될 수도 있고, 안 될 수도 있습니다. 왜 이런 일이 벌어질까요?

Go 프로그램은 메인 고루틴이 종료되는 순간 프로그램 전체가 즉시 끝나버립니다. 다른 고루틴이 아직 작업을 끝내지 못했더라도 기다려주지 않습니다. 위 코드에서 `go fmt.Println(...)`은 새로운 고루틴을 만들라는 지시만 내리고 그 즉시 다음 줄로 넘어갑니다. 운이 좋으면 새 고루틴이 `fmt.Println`을 실행할 시간을 확보하지만, 운이 나쁘면 `main` 함수가 먼저 끝나버려서 새 고루틴은 시작도 못 해보고 프로그램과 함께 사라집니다.

앞의 `sayHello` 예제에서 `time.Sleep`을 넣었던 것도 이 문제를 임시로 피하기 위해서였습니다. 하지만 `time.Sleep`으로 시간을 버는 방식은 진짜 해결책이 아닙니다. 고루틴이 정확히 몇 밀리초 만에 끝날지 알 수 없는데 무작정 기다리는 시간을 정해두는 것은 신뢰할 수 없는 방법이기 때문입니다. 너무 짧게 기다리면 여전히 문제가 재발하고, 너무 길게 기다리면 불필요하게 프로그램이 느려집니다.

올바른 해결책은 "고루틴이 끝날 때까지 실제로 기다리는" 동기화 도구를 사용하는 것입니다. 표준 라이브러리 `sync` 패키지의 `WaitGroup`이 그 대표적인 도구입니다.

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var wg sync.WaitGroup

	wg.Add(1) // 기다려야 할 고루틴 개수를 1 늘린다
	go func() {
		defer wg.Done() // 고루틴이 끝나면 카운트를 1 줄인다
		fmt.Println("이 메시지는 이제 확실히 보인다")
	}()

	wg.Wait() // 카운트가 0이 될 때까지 기다린다
	fmt.Println("main 함수 종료")
}
```

`wg.Add(1)`은 "기다려야 할 작업이 하나 늘었다"고 알리고, 고루틴 안에서 호출하는 `wg.Done()`은 "이 작업은 끝났다"고 알립니다. `wg.Wait()`은 아직 끝나지 않은 작업이 하나라도 남아있는 한 그 자리에서 멈춰 기다립니다. 이렇게 하면 `time.Sleep`처럼 시간을 어림짐작할 필요 없이, 고루틴이 정확히 끝나는 순간까지 안전하게 기다릴 수 있습니다.

## 여러 고루틴 동시 실행 예제

이번에는 여러 개의 고루틴을 한꺼번에 실행하는 예제를 살펴보겠습니다.

```go
package main

import (
	"fmt"
	"sync"
)

func worker(id int, wg *sync.WaitGroup) {
	defer wg.Done()
	fmt.Printf("작업자 %d 시작\n", id)
	fmt.Printf("작업자 %d 종료\n", id)
}

func main() {
	var wg sync.WaitGroup

	for i := 1; i <= 5; i++ {
		wg.Add(1)
		go worker(i, &wg)
	}

	wg.Wait() // 다섯 작업자가 모두 끝날 때까지 대기
	fmt.Println("모든 작업자가 종료되었다")
}
```

이 프로그램을 여러 번 실행해보면 "작업자 1 시작", "작업자 2 시작", "작업자 3 종료" 같은 문장들이 매번 다른 순서로 뒤섞여 출력되는 것을 볼 수 있습니다. 이것이 바로 동시성 프로그램의 본질적인 특징입니다. Go 스케줄러는 어떤 고루틴을 먼저 실행할지, 얼마나 실행하다가 다른 고루틴으로 넘어갈지를 프로그래머 대신 알아서 결정하며, 그 순서를 프로그래머가 예측하거나 강제할 수 없습니다. 만약 "반드시 작업자 1이 먼저 끝나야 한다"처럼 순서를 보장해야 하는 상황이라면, 고루틴을 무작정 여러 개 띄우는 것만으로는 부족하고 14장에서 배울 채널 같은 별도의 동기화 수단이 필요합니다.

한 가지 더 주의할 점이 있습니다. 위 코드에서는 `worker(i, &wg)`처럼 반복문 변수 `i`를 함수의 인자로 직접 넘겼습니다. 예전 Go 버전(1.22 이전)에서는 `for` 반복문의 변수 `i`가 매 반복마다 새로 만들어지지 않고 반복문 전체에서 하나의 변수를 계속 재사용했습니다. 그래서 고루틴 클로저 안에서 `i`를 직접 참조하면, 고루틴이 실제로 실행되는 시점에는 반복문이 이미 다 돌아서 `i`가 마지막 값으로 바뀌어 있는 경우가 흔했습니다. Go 1.22부터는 반복문 변수가 매 반복마다 새로 생성되도록 언어 명세가 바뀌어 이 문제가 사라졌지만, 여전히 값을 함수 인자로 명시적으로 넘겨서 각 고루틴이 자기만의 복사본을 갖도록 작성하는 습관을 들이면 Go 버전에 상관없이 안전한 코드를 쓸 수 있습니다.

아래 그림은 `main` 고루틴이 세 개의 작업자 고루틴을 실행시키고, 이 고루틴들의 실행 구간이 시간축 위에서 서로 겹치는 모습을 보여줍니다.

```text
여러 고루틴의 동시 실행

main 고루틴  |<================================================>|
             |  wg.Wait()로 세 고루틴이 끝날 때까지 대기            |
             |   go worker(1,..)
             |     v
고루틴 1      |     |<-------------->|
             |     |  worker(1) 실행 중
             |        go worker(2,..)
             |          v
고루틴 2      |          |<-------------->|
             |          |  worker(2) 실행 중
             |             go worker(3,..)
             |               v
고루틴 3      |               |<-------------->|
             |               |  worker(3) 실행 중
             |
             +------------------------------------------------> 시간

  고루틴 1, 2, 3의 실행 구간이 겹쳐 있는 것이 동시성입니다. 실제로 물리적으로
  동시에(병렬로) 실행되는지는 CPU 코어 수와 Go 스케줄러의 판단에 따라 달라집니다.
```

그림에서 볼 수 있듯 고루틴 1, 2, 3은 서로 다른 시점에 시작해서 실행 구간이 겹쳐 있습니다. 이 그림이 보여주는 것은 어디까지나 동시성, 즉 "여러 작업이 겹쳐서 진행되는 구조"입니다. 이 겹치는 구간이 실제로 물리적으로 동시에(병렬로) 실행되는지, 아니면 하나의 CPU 코어 안에서 아주 짧은 간격으로 번갈아 실행되는지는 실행 환경의 CPU 코어 수와 Go 스케줄러의 판단에 달려 있으며, 프로그래머 입장에서는 크게 신경 쓰지 않아도 되는 부분입니다.

## 고루틴끼리 값을 주고받으려면

지금까지 살펴본 예제에서 고루틴들은 각자 독립적으로 자기 할 일만 했을 뿐, 서로 데이터를 주고받지는 않았습니다. `sync.WaitGroup`도 "끝났는지 여부"만 알려줄 뿐 실제 값을 전달하는 도구는 아닙니다. 하지만 실전에서는 한 고루틴이 계산한 결과를 다른 고루틴에게 안전하게 전달해야 하는 경우가 훨씬 많습니다.

여러 고루틴이 같은 변수를 직접 공유하고 동시에 값을 읽고 쓰게 만들면 데이터 경쟁(data race)이라는 골치 아픈 버그가 생기기 쉽습니다. Go는 이 문제를 다루기 위해 채널(channel)이라는 전용 도구를 언어에 내장하고 있습니다. 다음 14장 "채널"에서는 고루틴들이 채널을 통해 안전하게 값을 주고받는 방법과, 이를 이용해 여러 작업자 고루틴에게 일을 나누어 처리시키는 워커 풀(worker pool) 패턴까지 살펴보겠습니다.

## 요약

- 동시성은 여러 작업을 겹쳐서 진행되도록 구조화하는 것이고, 병렬성은 여러 작업을 실제로 같은 순간에 실행하는 것입니다. 동시성이 있다고 항상 병렬성이 있는 것은 아닙니다.
- `go 함수호출()` 형태로 문장을 작성하면 그 함수 호출을 새로운 고루틴에서 실행할 수 있으며, `go` 문은 함수가 끝나기를 기다리지 않고 즉시 다음 줄로 넘어갑니다.
- 고루틴은 작은 크기로 시작해 필요에 따라 늘어나는 스택과, Go 런타임이 직접 관리하는 저렴한 스케줄링 덕분에 운영체제 스레드보다 훨씬 가볍습니다.
- 메인 고루틴(`main` 함수)이 종료되면 다른 고루틴이 끝나지 않았어도 프로그램 전체가 즉시 종료됩니다. `time.Sleep`으로 임시방편을 쓰기보다는 `sync.WaitGroup`처럼 실제로 완료를 기다리는 동기화 도구를 사용해야 합니다.
- 여러 고루틴을 동시에 실행하면 그 실행 순서는 예측할 수 없으며, 실행할 때마다 출력 순서가 달라질 수 있습니다.
- 고루틴끼리 값을 안전하게 주고받는 방법은 14장 "채널"에서 다룹니다.

## 연습문제

1. `go` 키워드 없이 함수를 세 번 호출하는 코드와, `go` 키워드를 붙여서 세 번 호출하는 코드를 각각 작성하고 두 프로그램의 실행 결과와 종료 시점이 어떻게 다른지 비교해 보세요.
2. `time.Sleep`만으로 메인 고루틴 종료 문제를 해결한 코드를, `sync.WaitGroup`을 사용하는 코드로 바꿔보고 두 방식의 차이를 설명해 보세요.
3. `for` 반복문으로 고루틴 10개를 실행해서 각 고루틴이 자신의 번호를 출력하도록 작성해 보세요. `sync.WaitGroup`으로 모든 고루틴이 끝나기를 기다린 뒤, 프로그램을 여러 번 실행해서 출력 순서가 매번 달라지는지 관찰해 보세요.
4. 동시성과 병렬성의 차이를 여러분만의 비유를 들어 한 문단으로 설명해 보세요.
5. 고루틴이 운영체제 스레드보다 가벼운 이유를 스택 크기와 스케줄링 주체(커널 대 Go 런타임) 두 가지 관점에서 각각 한두 문장으로 정리해 보세요.
