# 19장. 테스트 작성

## 들어가며

지금까지는 작성한 함수가 제대로 동작하는지 `main` 함수 안에서 값을 직접 출력해 눈으로 확인해
왔습니다. 이 방식은 코드가 작아질 때는 괜찮지만, 프로젝트가 커지고 함수를 수정할 일이 잦아지면
매번 눈으로 확인하는 것만으로는 한계가 있습니다. Go는 별도의 외부 프레임워크 없이 표준 라이브러리
`testing` 패키지만으로 테스트를 작성하고 실행할 수 있는 도구를 기본 제공합니다. 이 장에서는 그
기본 사용법을 살펴봅니다.

## 첫 번째 테스트 작성하기

Go의 테스트는 몇 가지 관례를 따릅니다.

- 테스트 파일 이름은 `_test.go`로 끝나야 합니다.
- 테스트 함수 이름은 `Test`로 시작해야 하며, 매개변수로 `*testing.T`를 하나 받습니다.
- `go test` 명령으로 실행합니다.

`add.go`에 아래와 같은 함수가 있다고 해 봅시다.

```go
package mathutil

func Add(a, b int) int {
	return a + b
}
```

같은 패키지 안에 `add_test.go`라는 이름으로 테스트 파일을 만듭니다.

```go
package mathutil

import "testing"

func TestAdd(t *testing.T) {
	got := Add(2, 3)
	want := 5

	if got != want {
		t.Errorf("Add(2, 3) = %d, 기대값 %d", got, want)
	}
}
```

터미널에서 `go test`를 실행하면 다음과 같은 결과를 볼 수 있습니다.

```text
$ go test
PASS
ok      example.com/mathutil    0.002s
```

만약 `Add` 함수에 버그가 있어 `a - b`를 반환하도록 잘못 작성했다면, `go test`는 다음과 같이 실패
이유를 알려줍니다.

```text
$ go test
--- FAIL: TestAdd (0.00s)
    add_test.go:8: Add(2, 3) = -1, 기대값 5
FAIL
```

## t.Error, t.Errorf, t.Fatal의 차이

- `t.Error`/`t.Errorf`: 실패를 기록하지만 테스트 함수의 나머지 코드는 계속 실행됩니다. 한 테스트
  함수 안에서 여러 검증을 하고 싶을 때 유용합니다.
- `t.Fatal`/`t.Fatalf`: 실패를 기록하고 즉시 해당 테스트 함수를 중단합니다. 이후 코드가 실패를
  전제로 하면 오류를 일으킬 수 있는 상황(예: 파일 열기에 실패했는데 그 파일을 계속 읽으려는 경우)에
  사용합니다.

## 테이블 기반 테스트

같은 함수를 여러 입력값으로 검증해야 할 때, Go 커뮤니티에서는 테스트 케이스를 슬라이스(7장 참고)로
나열하고 반복문으로 돌리는 "테이블 기반 테스트(table-driven test)"를 관용적으로 사용합니다.

```go
package mathutil

import "testing"

func TestAddTable(t *testing.T) {
	cases := []struct {
		name string
		a, b int
		want int
	}{
		{"양수 더하기", 2, 3, 5},
		{"음수 포함", -1, 5, 4},
		{"0 더하기", 0, 0, 0},
	}

	for _, c := range cases {
		got := Add(c.a, c.b)
		if got != c.want {
			t.Errorf("%s: Add(%d, %d) = %d, 기대값 %d", c.name, c.a, c.b, got, c.want)
		}
	}
}
```

8장에서 다룬 익명 구조체 슬라이스를 이용해 테스트 케이스를 한곳에 모아두면, 케이스를 추가하고
싶을 때 슬라이스에 항목 하나만 추가하면 되므로 유지보수가 훨씬 편해집니다.

## 서브테스트로 구분하기

`t.Run`을 사용하면 테이블의 각 케이스를 이름이 붙은 서브테스트로 나눠서 실행할 수 있습니다. 이렇게
하면 어떤 케이스가 실패했는지 더 명확하게 알 수 있고, `go test -run` 옵션으로 특정 케이스만 골라
실행할 수도 있습니다.

```go
func TestAddTable(t *testing.T) {
	cases := []struct {
		name string
		a, b int
		want int
	}{
		{"양수 더하기", 2, 3, 5},
		{"음수 포함", -1, 5, 4},
	}

	for _, c := range cases {
		c := c // Go 1.22 미만 버전을 사용한다면 반복 변수를 지역 변수로 복사해 두는 것이 안전합니다
		t.Run(c.name, func(t *testing.T) {
			got := Add(c.a, c.b)
			if got != c.want {
				t.Errorf("Add(%d, %d) = %d, 기대값 %d", c.a, c.b, got, c.want)
			}
		})
	}
}
```

```text
$ go test -v
=== RUN   TestAddTable
=== RUN   TestAddTable/양수_더하기
=== RUN   TestAddTable/음수_포함
--- PASS: TestAddTable (0.00s)
    --- PASS: TestAddTable/양수_더하기 (0.00s)
    --- PASS: TestAddTable/음수_포함 (0.00s)
PASS
```

## 에러를 반환하는 함수 테스트하기

11장에서 다룬 것처럼 Go 함수는 흔히 `(결과, error)`를 반환합니다. 이런 함수를 테스트할 때는 에러가
나야 하는 경우와 나지 말아야 하는 경우를 모두 확인하는 것이 좋습니다.

```go
func TestDivide(t *testing.T) {
	_, err := Divide(10, 0)
	if err == nil {
		t.Error("0으로 나누었는데 에러가 반환되지 않았습니다")
	}

	got, err := Divide(10, 2)
	if err != nil {
		t.Fatalf("예상치 못한 에러: %v", err)
	}
	if got != 5 {
		t.Errorf("Divide(10, 2) = %d, 기대값 5", got)
	}
}
```

## 벤치마크 살짝 맛보기

`testing` 패키지는 성능 측정용 벤치마크도 지원합니다. 이름이 `Benchmark`로 시작하고 `*testing.B`를
받는 함수를 작성하면 됩니다.

```go
func BenchmarkAdd(b *testing.B) {
	for i := 0; i < b.N; i++ {
		Add(2, 3)
	}
}
```

```text
$ go test -bench=.
BenchmarkAdd-8   	1000000000	    0.25 ns/op
```

`b.N`은 테스트 프레임워크가 신뢰할 만한 측정치를 얻을 때까지 자동으로 조절해 주는 반복 횟수이므로,
직접 반복 횟수를 정할 필요는 없습니다. 입문 단계에서는 이런 기능이 있다는 정도만 기억해 두어도
충분합니다.

## 테스트 커버리지 확인하기

`go test -cover`를 실행하면 테스트가 코드의 몇 퍼센트를 실행해 보았는지 알려줍니다.

```text
$ go test -cover
PASS
coverage: 85.7% of statements
ok      example.com/mathutil    0.003s
```

커버리지가 높다고 해서 버그가 없다는 뜻은 아니지만, 전혀 테스트되지 않은 코드가 어디인지 찾는
용도로는 유용합니다.

## 요약

- 테스트 파일은 `_test.go`로 끝나야 하고, 테스트 함수는 `Test`로 시작하며 `*testing.T`를 인자로
  받는다.
- `go test`로 테스트를 실행하며, `-v`로 상세 출력을, `-run`으로 특정 테스트만 골라 실행할 수 있다.
- `t.Error`/`t.Errorf`는 실패를 기록하고 계속 진행하고, `t.Fatal`/`t.Fatalf`는 즉시 중단한다.
- 여러 입력값을 검증할 때는 테스트 케이스를 슬라이스로 모아두는 테이블 기반 테스트가 관용적이다.
- `t.Run`으로 각 테스트 케이스를 이름 붙은 서브테스트로 분리할 수 있다.
- `(결과, error)`를 반환하는 함수는 에러가 나야 하는 경우와 나지 말아야 하는 경우를 모두 테스트한다.
- `Benchmark` 함수와 `go test -bench`로 성능을 측정할 수 있고, `go test -cover`로 테스트 커버리지를
  확인할 수 있다.

## 연습문제

1. 7장에서 만든 슬라이스 관련 함수 하나를 골라, 정상 입력과 빈 슬라이스 입력을 각각 검증하는
   테스트를 작성해 보세요.
2. 세 가지 이상의 입력값을 검증하는 테이블 기반 테스트를 작성하고, `t.Run`으로 서브테스트를
   나누어 보세요.
3. 에러를 반환하는 함수를 하나 만들고, 에러가 발생하는 경우와 발생하지 않는 경우를 모두 확인하는
   테스트를 작성해 보세요.
4. `go test -v`와 `go test -run` 옵션을 각각 사용해 보고 출력 결과가 어떻게 달라지는지 비교해
   보세요.
5. `go test -cover`를 실행해 자신이 작성한 코드의 테스트 커버리지를 확인하고, 테스트되지 않은
   부분이 있다면 어떤 입력값을 추가해야 할지 생각해 보세요.
