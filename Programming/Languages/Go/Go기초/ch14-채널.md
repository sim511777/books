13장에서는 `go` 키워드로 여러 고루틴을 동시에 실행하는 방법을 배웠습니다. 하지만 그 예제들에서 고루틴들은 서로 데이터를 주고받지 않았습니다. `sync.WaitGroup`은 "작업이 끝났는지"만 알려줄 뿐, 계산 결과 같은 실제 값을 전달하지는 못합니다.

현실의 동시성 프로그램에서는 한 고루틴이 만든 결과를 다른 고루틴이 이어받아 처리해야 하는 경우가 훨씬 많습니다. 예를 들어 한 고루틴이 파일을 읽어오는 동안 다른 고루틴은 그 내용을 파싱하고, 또 다른 고루틴은 파싱된 결과를 데이터베이스에 저장하는 식입니다. 이런 상황에서 여러 고루틴이 같은 변수를 아무런 규칙 없이 동시에 읽고 쓰게 만들면, 두 고루틴이 정확히 같은 순간에 값을 건드리면서 결과가 뒤죽박죽되는 데이터 경쟁(data race) 문제가 발생하기 쉽습니다.

Go는 이 문제를 다루는 독자적인 방식을 언어 차원에서 제공합니다. 바로 채널(channel)입니다.

## 채널이란?

Go 설계자들은 "여러 고루틴이 하나의 변수를 함께 두고 잠금(lock)으로 접근을 통제하며 값을 주고받는 방식" 대신, "데이터 자체를 통로에 실어서 한쪽 고루틴에서 다른 쪽 고루틴으로 직접 전달하는 방식"을 기본 관용구로 삼자는 철학을 채널이라는 도구로 구현했습니다. 데이터를 가운데 놓고 여러 고루틴이 눈치를 보며 접근하는 대신, 데이터를 아예 다음 고루틴에게 넘겨버리고 나면 이전 고루틴은 더 이상 그 값을 신경 쓸 필요가 없어집니다. 이렇게 하면 값을 주고받는 시점과 순서가 채널이라는 통로 하나로 명확하게 정리되기 때문에, 잠금을 세밀하게 관리하는 것보다 실수할 여지가 훨씬 줄어듭니다.

채널은 특정 타입의 값만 오갈 수 있는, 여러 고루틴이 동시에 사용해도 안전한 통로입니다. 마치 한쪽 끝으로 물건을 넣으면 다른 쪽 끝에서 순서대로 꺼낼 수 있는 파이프를 떠올리면 됩니다. 채널은 내장 함수 `make`로 만들며, 어떤 타입의 값을 주고받을지 함께 지정합니다.

```go
ch := make(chan int)      // int 값을 주고받는 채널
names := make(chan string) // string 값을 주고받는 채널
```

## 송신과 수신: <- 연산자

채널에 값을 보내거나 받을 때는 `<-` 연산자를 사용합니다. 화살표가 채널을 향하면 송신, 채널에서 나오면 수신입니다.

```go
ch <- 42       // 채널에 42를 보낸다 (송신)
value := <-ch  // 채널에서 값을 하나 받는다 (수신)
```

간단한 예제로 살펴보겠습니다.

```go
package main

import "fmt"

func main() {
	ch := make(chan string)

	go func() {
		ch <- "고루틴에서 보낸 메시지" // 채널에 값을 보낸다
	}()

	msg := <-ch // 값이 도착할 때까지 여기서 기다린다
	fmt.Println(msg)
}
```

이 코드에는 13장에서 겪었던 "메인 함수가 먼저 끝나버리는 문제"를 해결할 실마리가 담겨 있습니다. `make(chan string)`으로 만든 채널은 기본적으로 버퍼가 없는 채널이며, 이런 채널에서 수신(`<-ch`)은 실제로 값이 도착할 때까지 그 자리에서 자동으로 멈춰 기다립니다. 즉 `time.Sleep`으로 임시방편을 쓰지 않아도, 채널 자체가 "값이 준비될 때까지 기다린다"는 동기화 역할을 대신해줍니다.

## 버퍼 없는 채널과 버퍼 있는 채널

채널은 버퍼(내부에 값을 잠시 담아둘 공간)가 있는지 없는지에 따라 동작이 달라집니다.

**버퍼 없는 채널**(`make(chan T)`)은 송신자와 수신자가 동시에 준비되어야만 값이 오갑니다. 송신하는 쪽은 누군가 받아갈 때까지 멈춰서 기다리고, 수신하는 쪽도 누군가 보낼 때까지 멈춰서 기다립니다. 마치 두 사람이 물건을 직접 손에서 손으로 건네는 것과 같아서, 이런 동작을 랑데부(rendezvous)라고 부르기도 합니다.

**버퍼 있는 채널**(`make(chan T, n)`)은 최대 `n`개의 값을 임시로 담아둘 수 있는 공간을 가집니다. 버퍼에 여유가 있으면 송신자는 수신자가 없어도 값을 넣고 바로 다음 작업으로 넘어갈 수 있고, 버퍼가 가득 찼을 때만 그 자리에서 멈춰 기다립니다. 반대로 수신자는 버퍼가 비어있을 때만 멈춰 기다립니다.

```go
buffered := make(chan int, 3) // 버퍼 크기 3
buffered <- 1                 // 버퍼에 여유가 있어 즉시 끝난다
buffered <- 2
buffered <- 3
// buffered <- 4 // 버퍼가 가득 차서 누군가 받아갈 때까지 여기서 멈춘다

fmt.Println(<-buffered) // 1
fmt.Println(<-buffered) // 2
```

두 방식은 용도가 다릅니다. 버퍼 없는 채널은 "이 시점에 상대방이 확실히 값을 받았다"는 것을 보장해야 할 때, 즉 엄격한 동기화가 필요할 때 적합합니다. 버퍼 있는 채널은 송신자와 수신자의 속도 차이를 어느 정도 흡수하고 싶을 때, 예를 들어 처리할 작업 목록을 미리 큐에 쌓아두고 싶을 때 유용합니다.

## close와 range로 여러 값 받기

한 고루틴이 여러 개의 값을 연속으로 보내고, 다 보냈으면 "더 이상 보낼 값이 없다"고 알려야 하는 경우가 많습니다. 이때 사용하는 것이 내장 함수 `close`입니다.

```go
package main

import "fmt"

func main() {
	ch := make(chan int)

	go func() {
		for i := 1; i <= 5; i++ {
			ch <- i
		}
		close(ch) // 더 이상 보낼 값이 없음을 알린다
	}()

	for v := range ch { // 채널이 닫힐 때까지 값을 하나씩 받는다
		fmt.Println(v)
	}
	fmt.Println("모든 값을 받았다")
}
```

`for v := range ch`는 채널에서 값을 하나씩 계속 받다가, 채널이 닫히고 남은 값도 모두 받고 나면 자동으로 반복문을 끝냅니다. 배열이나 슬라이스에 쓰던 `range`가 채널에도 똑같이 자연스럽게 적용되는 셈입니다(슬라이스에 대한 `range`는 7장 "배열과 슬라이스"에서 다뤘습니다).

닫힌 채널에서 수신할 때는 몇 가지 규칙을 기억해야 합니다.

- 이미 닫힌 채널에서 값을 받으면, 남아있던 값을 먼저 다 받고 난 뒤에는 그 타입의 제로 값을 즉시 반환합니다(더 이상 기다리지 않습니다).
- 값과 함께 "이 값이 실제로 보내진 값인지, 아니면 채널이 닫혀서 나온 제로 값인지"를 구분하고 싶다면 두 번째 반환값을 받는 관용구를 사용합니다.

```go
v, ok := <-ch
if !ok {
	fmt.Println("채널이 닫혔고 더 이상 값이 없다")
} else {
	fmt.Println("받은 값:", v)
}
```

- 채널은 값을 **보내는 쪽**에서 닫는 것이 원칙입니다. 받는 쪽에서 채널을 닫으면 안 됩니다. 이미 닫힌 채널을 또 닫거나, 닫힌 채널에 값을 보내려고 하면 프로그램이 패닉(panic)을 일으키며 종료됩니다.

## select문으로 여러 채널 다루기

여러 개의 채널을 동시에 지켜보다가, 그중 준비된 채널을 처리하고 싶을 때는 `select`문을 사용합니다. 문법은 `switch`문과 비슷하지만, 각 `case`가 채널 송수신 연산이라는 점이 다릅니다.

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ch1 := make(chan string)
	ch2 := make(chan string)

	go func() {
		time.Sleep(50 * time.Millisecond)
		ch1 <- "채널1에서 온 메시지"
	}()
	go func() {
		time.Sleep(20 * time.Millisecond)
		ch2 <- "채널2에서 온 메시지"
	}()

	for i := 0; i < 2; i++ {
		select {
		case msg1 := <-ch1:
			fmt.Println(msg1)
		case msg2 := <-ch2:
			fmt.Println(msg2)
		}
	}
}
```

`select`는 여러 `case` 중에서 지금 당장 처리할 수 있는(값을 주고받을 준비가 된) 것을 골라 실행합니다. 만약 여러 `case`가 동시에 준비되어 있다면 그중 하나를 무작위로 골라 실행하고, 준비된 `case`가 하나도 없다면 하나라도 준비될 때까지 그 자리에서 기다립니다. 위 예제에서는 `ch2`가 먼저(20밀리초 뒤) 값을 보내므로 "채널2에서 온 메시지"가 먼저 출력되고, 그 다음 "채널1에서 온 메시지"가 출력됩니다.

`select`에 `default` 절을 추가하면, 준비된 채널이 하나도 없을 때 기다리지 않고 즉시 `default`를 실행합니다. 이렇게 하면 채널을 블로킹 없이 확인만 하고 지나갈 수 있습니다.

```go
select {
case v := <-ch:
	fmt.Println("값 수신:", v)
default:
	fmt.Println("받을 값이 아직 없다, 기다리지 않고 넘어간다")
}
```

또한 `time.After`와 함께 사용하면 "일정 시간 안에 응답이 없으면 포기한다"는 타임아웃 패턴을 간단히 구현할 수 있습니다.

```go
select {
case v := <-ch:
	fmt.Println("값 수신:", v)
case <-time.After(1 * time.Second):
	fmt.Println("1초 동안 응답이 없어 타임아웃 처리한다")
}
```

아래 그림은 고루틴 하나가 채널에 값을 보내고, 다른 고루틴이 그 값을 받아가는 기본적인 흐름을 보여줍니다.

```text
채널을 통한 고루틴 간 통신

  +--------------+                +-------------------------+                +--------------+
  |   고루틴 1    |     송신        |     채널 ch (chan int)    |      수신       |   고루틴 2    |
  | (송신하는 쪽)  | -------------> |  +----+  +----+  +----+  | -------------> | (수신하는 쪽)  |
  |  ch <- 42    |                |  |    |  |    |  |    |  |                |  v := <-ch   |
  +--------------+                |  +----+  +----+  +----+  |                +--------------+
                                   | 먼저 들어온 값이 먼저 나간다 (FIFO) |
                                   +-------------------------+

핵심 요약
버퍼 없는 채널에서는 송신자와 수신자가 동시에 준비되어야 값이 전달됩니다(랑데부).
버퍼 있는 채널에서는 버퍼에 빈 슬롯이 있는 한, 수신자가 없어도 송신이 먼저 끝날 수 있습니다.
```

## 13장과 결합: 간단한 워커 풀

이제 13장에서 배운 `go` 키워드와 이번 장에서 배운 채널을 결합해서, 여러 작업자 고루틴에게 일을 나누어 처리시키는 워커 풀(worker pool) 패턴을 만들어보겠습니다. 워커 풀은 "처리할 작업을 채널에 넣어두고, 미리 실행해둔 여러 작업자 고루틴이 그 채널에서 작업을 꺼내가며 처리한 뒤 결과를 또 다른 채널에 담아 돌려주는" 구조입니다.

```go
package main

import "fmt"

// jobs는 받기 전용(<-chan), results는 보내기 전용(chan<-) 채널로 선언해
// 이 함수가 각 채널을 어떤 방향으로만 사용하는지 시그니처만 보고도 알 수 있게 한다.
func worker(id int, jobs <-chan int, results chan<- int) {
	for j := range jobs { // jobs가 닫히면 반복문이 자동으로 끝난다
		fmt.Printf("작업자 %d가 작업 %d를 처리 중\n", id, j)
		results <- j * j // 제곱값을 결과로 보낸다
	}
}

func main() {
	const numJobs = 5
	const numWorkers = 3

	jobs := make(chan int, numJobs)
	results := make(chan int, numJobs)

	// 작업자 고루틴 3개를 미리 실행해둔다 (13장에서 배운 go 키워드)
	for w := 1; w <= numWorkers; w++ {
		go worker(w, jobs, results)
	}

	// 작업 5개를 채널에 넣는다
	for j := 1; j <= numJobs; j++ {
		jobs <- j
	}
	close(jobs) // 더 이상 작업이 없음을 알린다

	// 결과 5개를 모두 받는다
	sum := 0
	for a := 1; a <= numJobs; a++ {
		sum += <-results
	}
	fmt.Println("제곱의 합:", sum) // 1+4+9+16+25 = 55
}
```

이 예제에서 `jobs <-chan int`처럼 채널 타입 앞에 방향을 명시하면, 그 함수가 채널을 받기 전용 또는 보내기 전용으로만 사용하겠다고 컴파일러에게 약속하는 것입니다. `worker` 함수는 `jobs`에서 값을 꺼내기만 하고 `results`에는 값을 넣기만 하므로, 이렇게 방향을 제한해두면 실수로 반대 방향의 연산을 사용하는 것을 컴파일 시점에 막을 수 있습니다.

전체 흐름을 정리하면 다음과 같습니다.

1. `jobs`와 `results`라는 두 개의 버퍼 있는 채널을 만든다.
2. 작업자 고루틴 3개를 미리 실행해둔다. 이 고루틴들은 각자 `for range`로 `jobs` 채널을 지켜보다가 값이 들어오면 처리한다.
3. `main` 고루틴은 작업 5개를 `jobs` 채널에 넣고 `close(jobs)`로 마감을 알린다.
4. 작업자 고루틴들은 자신이 처리한 결과를 `results` 채널에 보낸다.
5. `main` 고루틴은 `results`에서 값을 5번 받아 합계를 구한다.

작업 5개를 작업자 3개가 나누어 처리하므로, 어떤 작업자가 어떤 작업을 맡을지는 실행할 때마다 달라질 수 있습니다. 하지만 채널이 각 값의 전달을 안전하게 보장해주기 때문에, 어떤 순서로 처리되든 결과의 합계는 항상 55로 정확하게 나옵니다. 이것이 채널이 주는 가장 큰 이점입니다. 여러 고루틴이 관여하는 복잡한 흐름 속에서도, 값을 주고받는 지점을 채널 하나로 명확하게 정리해서 데이터 경쟁 없이 안전하게 동시성을 활용할 수 있게 해줍니다.

## 요약

- 채널은 고루틴끼리 값을 안전하게 주고받는 통로이며, `make(chan T)`로 만들고 `<-` 연산자로 송신(`ch <- v`)과 수신(`v := <-ch`)을 수행합니다.
- 버퍼 없는 채널은 송신자와 수신자가 동시에 준비되어야 값이 오가고(랑데부), 버퍼 있는 채널(`make(chan T, n)`)은 버퍼에 여유가 있는 동안 송신자가 기다리지 않고 값을 넣을 수 있습니다.
- `close(ch)`로 채널을 닫아 "더 이상 값이 없다"는 것을 알릴 수 있고, `for v := range ch`는 채널이 닫힐 때까지 값을 받다가 자동으로 종료됩니다. 채널은 항상 보내는 쪽에서 닫아야 합니다.
- `select`문은 여러 채널 중 준비된 것을 골라 처리하며, `default` 절로 블로킹 없는 확인을, `time.After`와 함께 타임아웃 처리를 구현할 수 있습니다.
- 13장의 고루틴과 채널을 결합하면 여러 작업자에게 일을 나누어 처리시키는 워커 풀 패턴을 만들 수 있으며, `<-chan T`/`chan<- T`로 채널의 사용 방향을 제한해 안전성을 높일 수 있습니다.
