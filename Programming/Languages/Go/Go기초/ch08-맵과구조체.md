7장(배열과 슬라이스)에서는 같은 타입의 값을 순서대로 늘어놓는 방법을 살펴봤습니다. 하지만 현실의 데이터는 "순서"보다 "이름"으로 찾아야 할 때가 많습니다. 사용자의 아이디로 사용자 정보를 찾거나, 단어로 그 뜻을 찾는 것처럼요. 또 어떤 데이터는 서로 다른 타입의 값 여러 개를 하나의 묶음으로 다뤄야 합니다. 한 사람의 이름(문자열), 나이(정수), 이메일(문자열)을 묶어서 "사용자"라는 하나의 개념으로 다루고 싶을 때가 그렇습니다.

이번 장에서는 키로 값을 찾는 자료구조인 맵(map)과, 서로 다른 타입의 필드를 하나로 묶는 구조체(struct)를 다룹니다. 이 두 타입은 이후 9장(포인터)부터 시작해 Go 코드 전반에서 계속 등장할 만큼 기초적이고 중요한 도구입니다.

## 맵: 키와 값의 쌍을 저장하는 자료구조

맵은 키(key)와 값(value)의 쌍을 저장하는 자료구조입니다. 다른 언어의 딕셔너리(dictionary)나 해시맵(hash map)과 같은 역할을 합니다. 맵의 타입은 `map[키타입]값타입`으로 표기합니다.

### 맵 선언과 생성

맵을 만드는 방법은 크게 두 가지입니다. 내장 함수 `make`를 사용하거나, 맵 리터럴로 값을 채우면서 만드는 방법입니다.

```go
package main

import "fmt"

func main() {
	// make로 빈 맵 생성
	ages := make(map[string]int)
	ages["철수"] = 20
	ages["영희"] = 22

	fmt.Println(ages) // map[영희:22 철수:20]

	// 맵 리터럴로 값을 채우면서 생성
	capitals := map[string]string{
		"한국": "서울",
		"일본": "도쿄",
		"프랑스": "파리",
	}
	fmt.Println(capitals["한국"]) // 서울
}
```

맵의 키는 `==` 연산자로 비교 가능한 타입(comparable type)이어야 합니다. 문자열, 숫자, bool은 물론이고 배열이나 구조체도 그 필드가 모두 비교 가능하다면 키로 쓸 수 있습니다. 반대로 슬라이스, 맵, 함수 타입은 `==` 비교를 지원하지 않으므로 맵의 키로 사용할 수 없습니다.

### 값 읽기와 쓰기

맵에 값을 넣고 꺼내는 문법은 배열이나 슬라이스와 비슷하게 대괄호를 사용합니다.

```go
scores := map[string]int{"국어": 90, "수학": 85}

scores["영어"] = 78     // 새 키 추가
scores["국어"] = 95     // 기존 키의 값 수정

fmt.Println(scores["수학"]) // 85
fmt.Println(len(scores))  // 3, 저장된 키-값 쌍의 개수
```

### 존재하지 않는 키를 조회하면?

맵에 없는 키를 조회하면 오류가 나는 대신, 값 타입의 제로 값이 반환됩니다. 이 동작이 편리할 때도 있지만, "값이 0이라서 없는 것"인지 "정말로 값이 0으로 저장되어 있는 것"인지 구분할 수 없다는 함정이 있습니다.

```go
scores := map[string]int{"국어": 90}

fmt.Println(scores["영어"]) // 0, "영어" 키가 없어도 에러 없이 제로 값이 나온다
```

### 콤마 ok 패턴

키가 실제로 존재하는지 확실히 구분하고 싶을 때는 맵 조회에서 두 번째 반환값을 함께 받는 콤마 ok 패턴을 사용합니다. 이 패턴은 6장(함수)에서 살펴본 다중 반환값 문법을 맵 조회에 응용한 형태입니다.

```go
scores := map[string]int{"국어": 90}

value, ok := scores["영어"]
fmt.Println(value, ok) // 0 false, "영어"는 없다

value, ok = scores["국어"]
fmt.Println(value, ok) // 90 true, "국어"는 있다
```

`ok`는 키가 존재하면 `true`, 존재하지 않으면 `false`가 되는 `bool` 값입니다. 5장(제어문)에서 배운 `if` 초기화 문과 결합하면 다음처럼 자연스럽게 쓸 수 있습니다.

```go
if value, ok := scores["영어"]; ok {
	fmt.Println("영어 점수:", value)
} else {
	fmt.Println("영어 점수가 없습니다.")
}
```

### 키 삭제하기

맵에서 키-값 쌍을 제거할 때는 내장 함수 `delete`를 사용합니다.

```go
scores := map[string]int{"국어": 90, "수학": 85}
delete(scores, "국어")
fmt.Println(scores) // map[수학:85]

delete(scores, "존재하지않는키") // 없는 키를 지워도 에러가 나지 않는다
```

### 맵은 참조 타입이다

7장에서 배열은 값 타입이라 대입하면 복사된다고 배웠습니다. 맵은 이와 반대입니다. 맵을 다른 변수에 대입하거나 함수에 전달해도 내부 데이터는 복사되지 않고 공유됩니다. 슬라이스와 마찬가지로, 맵 변수가 실제로 들고 있는 것은 내부 해시 테이블을 가리키는 참조뿐이기 때문입니다.

```go
package main

import "fmt"

func addEntry(m map[string]int) {
	m["추가됨"] = 100 // 원본 맵에도 영향을 준다
}

func main() {
	original := map[string]int{"기존": 1}
	copySameMap := original // 맵 자체가 아니라 참조가 복사된다

	copySameMap["기존"] = 999
	fmt.Println(original) // map[기존:999] — 원본도 바뀐다

	addEntry(original)
	fmt.Println(original) // map[기존:999 추가됨:100]
}
```

### nil 맵을 다룰 때 주의할 점

맵의 제로 값은 `nil`입니다. `nil` 맵에서 값을 읽는 것은 안전하지만(제로 값을 반환), `nil` 맵에 값을 쓰려고 하면 런타임 패닉(panic)이 발생합니다. 패닉이 무엇이고 어떻게 다루는지는 12장(defer, panic, recover)에서 자세히 다루지만, 지금은 "선언만 하고 초기화하지 않은 맵에는 값을 쓸 수 없다"는 규칙만 기억해 두면 충분합니다.

```go
var m map[string]int // nil 맵

fmt.Println(m["아무키"]) // 0, 읽기는 안전하다
fmt.Println(m == nil)   // true

// m["키"] = 1 // 패닉 발생: assignment to entry in nil map
```

맵을 사용하기 전에는 반드시 `make`나 맵 리터럴로 초기화하는 습관을 들여야 합니다.

### 맵 순회와 순서

`for range`로 맵의 모든 키-값 쌍을 순회할 수 있습니다.

```go
capitals := map[string]string{"한국": "서울", "일본": "도쿄", "중국": "베이징"}

for country, capital := range capitals {
	fmt.Println(country, "-", capital)
}
```

여기서 반드시 기억해야 할 점이 있습니다. **맵을 순회하는 순서는 보장되지 않습니다.** Go 런타임은 오히려 의도적으로 순회 순서를 실행할 때마다 무작위로 섞습니다. 이는 프로그래머가 실수로 특정 순서에 의존하는 코드를 작성하지 못하도록 막기 위한 설계입니다.

만약 키를 정렬된 순서로 순회하고 싶다면, 키들을 슬라이스로 뽑아낸 뒤 정렬해서 그 순서대로 접근해야 합니다. 정렬에 사용하는 `sort` 패키지는 17장(표준 라이브러리 둘러보기)에서 더 자세히 다룹니다.

```go
import "sort"

keys := make([]string, 0, len(capitals))
for country := range capitals {
	keys = append(keys, country)
}
sort.Strings(keys)

for _, country := range keys {
	fmt.Println(country, "-", capitals[country])
}
```

## 구조체: 서로 다른 타입을 하나로 묶기

구조체는 서로 다른 타입의 필드(field) 여러 개를 하나의 타입으로 묶은 것입니다. `type` 키워드와 `struct` 키워드를 함께 사용해 정의합니다.

```go
package main

import "fmt"

// Person은 이름과 나이를 가진 구조체다
type Person struct {
	Name string
	Age  int
}

func main() {
	var p Person
	p.Name = "철수"
	p.Age = 20

	fmt.Println(p)        // {철수 20}
	fmt.Println(p.Name)   // 철수
	fmt.Println(p.Age)    // 20
}
```

구조체의 필드도 다른 식별자와 마찬가지로, 이름이 대문자로 시작하면 다른 패키지에서도 접근할 수 있는 exported 필드가 되고, 소문자로 시작하면 같은 패키지 안에서만 접근할 수 있는 비공개 필드가 됩니다. 이 규칙은 1장에서 언급한 Go의 가시성 규칙과 동일합니다.

### 구조체 리터럴

구조체 값을 선언과 동시에 채우려면 구조체 리터럴을 사용합니다. 필드 이름을 명시하는 방식과, 순서대로 값만 나열하는 방식 두 가지가 있습니다.

```go
// 필드 이름을 명시 — 순서에 상관없고, 일부 필드만 채워도 된다
p1 := Person{Name: "영희", Age: 22}
p2 := Person{Name: "민수"} // Age는 명시하지 않으면 제로 값 0

// 필드 이름 없이 순서대로 — 필드 순서와 개수를 정확히 지켜야 한다
p3 := Person{"지훈", 25}

fmt.Println(p1, p2, p3) // {영희 22} {민수 0} {지훈 25}
```

필드 이름을 명시하는 방식이 더 장황해 보이지만, 구조체에 필드가 추가되거나 순서가 바뀌어도 코드가 깨지지 않는다는 장점이 있어 실무에서 훨씬 널리 쓰입니다. 순서만으로 값을 채우는 방식은 필드가 두세 개뿐인 간단한 구조체가 아니라면 권장되지 않습니다.

### 구조체는 값 타입이다

배열과 마찬가지로 구조체도 값 타입입니다. 구조체를 다른 변수에 대입하거나 함수에 전달하면 모든 필드가 통째로 복사됩니다.

```go
p1 := Person{Name: "철수", Age: 20}
p2 := p1 // 완전히 독립된 복사본
p2.Name = "영희"

fmt.Println(p1) // {철수 20} — 그대로다
fmt.Println(p2) // {영희 20}
```

구조체가 필드를 많이 가지고 있거나 함수 호출이 잦다면 복사 비용이 부담될 수 있습니다. 이런 경우 구조체의 포인터를 주고받는 방법을 사용하는데, 이는 9장(포인터)에서 자세히 다룹니다.

### 구조체 비교

구조체는 모든 필드가 비교 가능한 타입으로만 이루어져 있다면 `==`, `!=` 연산자로 비교할 수 있습니다. 모든 필드의 값이 같아야 두 구조체가 같다고 판단됩니다.

```go
p1 := Person{Name: "철수", Age: 20}
p2 := Person{Name: "철수", Age: 20}
p3 := Person{Name: "철수", Age: 21}

fmt.Println(p1 == p2) // true, 모든 필드가 같다
fmt.Println(p1 == p3) // false, Age가 다르다
```

## 구조체에 메서드 정의하기

함수를 특정 타입에 묶어서 "이 타입의 값이 할 수 있는 동작"으로 정의할 수 있습니다. 이런 함수를 메서드(method)라고 부릅니다. 메서드는 일반 함수와 문법이 거의 같지만, 함수 이름 앞에 리시버(receiver)라고 부르는 매개변수를 하나 추가로 붙입니다.

```go
package main

import "fmt"

type Rectangle struct {
	Width  float64
	Height float64
}

// Area는 Rectangle의 넓이를 계산하는 메서드다. r이 리시버다.
func (r Rectangle) Area() float64 {
	return r.Width * r.Height
}

func main() {
	rect := Rectangle{Width: 3, Height: 4}
	fmt.Println(rect.Area()) // 12
}
```

`func (r Rectangle) Area() float64`에서 `(r Rectangle)` 부분이 리시버입니다. 이 메서드는 `Rectangle` 타입의 값 `rect`에 대해 `rect.Area()`처럼 마침표로 호출할 수 있습니다. 메서드 본문 안에서 리시버 이름(`r`)은 그 메서드를 호출한 구조체 값 자체를 가리킵니다.

### 값 리시버는 복사본에서 동작한다

지금까지 정의한 `Area` 메서드는 값 리시버(value receiver)를 사용합니다. 매개변수와 마찬가지로, 값 리시버도 메서드를 호출할 때마다 원본의 복사본을 받습니다. 그래서 값 리시버 메서드 안에서 리시버의 필드를 변경해도 원본에는 영향을 주지 않습니다.

```go
type Counter struct {
	Count int
}

// Increment는 값 리시버라서 c는 복사본이다
func (c Counter) Increment() {
	c.Count++ // 복사본만 바뀐다
}

func main() {
	counter := Counter{Count: 0}
	counter.Increment()
	fmt.Println(counter.Count) // 0 — 바뀌지 않았다!
}
```

원본 구조체의 상태를 실제로 바꾸는 메서드가 필요하다면 포인터 리시버(pointer receiver)를 사용해야 합니다. 포인터 리시버는 리시버 타입을 `*Counter`처럼 포인터로 선언해서, 복사본이 아니라 원본을 직접 가리키도록 만드는 방식입니다. 포인터의 개념과 포인터 리시버의 구체적인 문법은 다음 9장(포인터)에서 자세히 다룹니다. 지금은 "값 리시버는 읽기 전용에 가깝고, 상태를 바꾸려면 포인터 리시버가 필요하다"는 원칙만 기억해 두면 됩니다.

## 구조체 임베딩: Go에는 상속이 없다

자바나 C++ 같은 언어를 사용해 봤다면 "공통 필드와 메서드를 부모 클래스에 두고, 자식 클래스가 상속받아 재사용한다"는 상속(inheritance) 개념에 익숙할 것입니다. **Go에는 클래스도, 상속도 없습니다.** 대신 Go는 구조체 임베딩(embedding)이라는 합성(composition) 방식으로 코드 재사용을 지원합니다.

임베딩은 구조체 필드를 선언할 때 필드 이름을 생략하고 타입만 적는 것입니다.

```go
package main

import "fmt"

type Animal struct {
	Name string
	Age  int
}

func (a Animal) Describe() string {
	return fmt.Sprintf("%s(%d살)", a.Name, a.Age)
}

// Dog는 Animal을 임베딩한다
type Dog struct {
	Animal        // 필드 이름 없이 타입만 — 이것이 임베딩이다
	Breed  string
}

func main() {
	d := Dog{
		Animal: Animal{Name: "바둑이", Age: 3},
		Breed:  "진돗개",
	}

	// Animal의 필드가 Dog로 승격되어 바로 접근할 수 있다
	fmt.Println(d.Name) // 바둑이 (d.Animal.Name과 동일)
	fmt.Println(d.Age)  // 3

	// Animal의 메서드도 Dog에서 바로 호출할 수 있다
	fmt.Println(d.Describe()) // 바둑이(3살)
}
```

### 필드와 메서드의 승격

`Dog` 구조체는 `Name`이나 `Age`라는 필드를 직접 선언하지 않았습니다. 하지만 `Animal`을 임베딩했기 때문에 `Animal`의 필드들이 `Dog`로 승격(promotion)되어, 마치 `Dog`가 원래부터 그 필드를 가지고 있던 것처럼 `d.Name`으로 바로 접근할 수 있습니다. 같은 원리로 `Animal`에 정의된 `Describe` 메서드도 `d.Describe()`처럼 바로 호출할 수 있습니다.

물론 `d.Animal.Name`처럼 임베딩된 필드의 이름을 명시해서 접근하는 것도 항상 가능합니다. 승격은 편의를 위한 문법일 뿐, `Animal`이라는 필드가 실제로 `Dog` 안에 존재한다는 사실은 달라지지 않습니다.

### 상속이 아니라 합성인 이유

임베딩이 상속과 근본적으로 다른 점은, `Dog`가 `Animal`의 "하위 타입"이 되는 것이 아니라는 데 있습니다. 임베딩은 그저 `Dog` 구조체 안에 `Animal` 타입의 필드 하나가 이름 없이 들어 있는 것뿐입니다. 그래서 `Dog` 값을 `Animal` 타입이 필요한 자리에 그대로 넘길 수 없습니다(`Dog`를 `Animal`로 취급하는 다형성은 없습니다). 대신 `d.Animal`을 명시적으로 꺼내서 넘겨야 합니다.

이런 방식을 "is-a(~은 ~이다) 관계 대신 has-a(~을 가지고 있다) 관계로 코드를 재사용한다"고 표현합니다. `Dog`는 `Animal`이 아니라, `Animal`을 가지고 있을 뿐입니다. Go 설계자들은 상속 계층이 깊어질수록 코드의 결합도가 높아지고 유지보수가 어려워진다는 문제의식에서, 의도적으로 상속 대신 합성을 기본 도구로 채택했습니다. 이 철학은 10장(인터페이스)에서 인터페이스를 배우면 더 뚜렷하게 이해할 수 있습니다. Go에서는 "무엇을 상속받았는가"보다 "무엇을 할 수 있는가"로 타입을 다루는 경우가 훨씬 많습니다.

### 이름이 겹칠 때

임베딩한 구조체와 바깥 구조체에 같은 이름의 필드나 메서드가 있으면, 바깥 구조체에 정의된 것이 우선합니다. 그리고 이런 경우 승격이 일어나지 않으므로, 임베딩된 쪽의 필드나 메서드에 접근하려면 이름을 명시해야 합니다.

```go
type Dog struct {
	Animal
	Breed string
}

// Dog에도 Describe를 새로 정의하면 이 메서드가 우선한다
func (d Dog) Describe() string {
	return fmt.Sprintf("%s(품종: %s)", d.Name, d.Breed)
}

func main() {
	d := Dog{Animal: Animal{Name: "바둑이", Age: 3}, Breed: "진돗개"}

	fmt.Println(d.Describe())        // 바둑이(품종: 진돗개) — Dog의 메서드
	fmt.Println(d.Animal.Describe()) // 바둑이(3살) — Animal의 메서드를 명시적으로 호출
}
```

## 요약

- 맵은 `map[키타입]값타입`으로 선언하며, `make`나 맵 리터럴로 생성합니다. 존재하지 않는 키를 조회하면 값 타입의 제로 값이 반환되므로, 키의 존재 여부를 확인하려면 `value, ok := m[key]` 형태의 콤마 ok 패턴을 사용합니다.
- 맵은 참조 타입이라 대입하거나 함수에 전달해도 내부 데이터가 공유됩니다. `nil` 맵은 읽기는 안전하지만 쓰기는 패닉을 일으키므로 반드시 초기화 후 사용해야 합니다.
- 맵을 `range`로 순회하는 순서는 보장되지 않으며, 정렬된 순서가 필요하면 키를 슬라이스로 뽑아 직접 정렬해야 합니다.
- 구조체는 `type Name struct { ... }`로 정의하며, 서로 다른 타입의 필드를 하나로 묶습니다. 구조체는 값 타입이라 대입하거나 함수에 전달하면 복사됩니다.
- 메서드는 `func (리시버 타입) 이름(...)` 형태로 정의합니다. 값 리시버는 복사본에서 동작하므로 원본을 수정하지 못하며, 원본을 수정하는 메서드는 9장에서 다룰 포인터 리시버가 필요합니다.
- Go에는 클래스 상속이 없습니다. 대신 구조체 임베딩으로 필드와 메서드를 승격시켜 재사용하는 합성(composition) 방식을 사용하며, 이는 "is-a"가 아니라 "has-a" 관계입니다.
