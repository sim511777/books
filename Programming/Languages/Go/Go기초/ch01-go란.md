## 들어가며

이 책을 펼친 여러분 중에는 프로그래밍을 처음 시작하는 분도 있을 것이고, 이미 Python이나 Java, C 같은 언어를 다뤄본 뒤 Go를 새로 배우려는 분도 있을 것입니다. 어느 쪽이든 상관없습니다. 1장에서는 Go가 어떤 언어인지, 왜 만들어졌는지, 어디에 쓰이는지, 그리고 이 언어를 배우면 무엇을 할 수 있게 되는지를 먼저 살펴봅니다. 코드를 한 줄도 작성하지 않는 장이지만, 앞으로 17개 챕터를 관통하는 Go의 설계 철학을 이해하고 나면 이후의 문법과 관용구들이 왜 그런 모습을 하고 있는지 훨씬 자연스럽게 받아들일 수 있습니다.

## Go는 어떤 언어인가

Go(공식 명칭은 "Go"이며, 검색 편의를 위해 흔히 "Golang"이라고도 부릅니다)는 2007년 구글 내부에서 로버트 그리즈머, 롭 파이크, 켄 톰프슨 세 사람이 설계를 시작해 2009년 오픈소스로 공개한 프로그래밍 언어입니다. 이들은 모두 유닉스와 C 언어의 역사에 깊이 관여했던 인물들로, Go 역시 그 계보 위에서 "지금 시대의 대규모 소프트웨어를 짜기에 더 적합한 도구"를 목표로 설계되었습니다.

Go를 한 문장으로 요약하면 다음과 같습니다.

> Go는 정적 타입을 가진 컴파일 언어로, 문법이 단순하고 컴파일 속도가 빠르며, 동시성(concurrency)을 언어 차원에서 지원한다.

이 문장에 담긴 각 특징을 하나씩 풀어보겠습니다.

### 정적 타입 언어

Go에서는 모든 변수가 컴파일 시점에 타입이 결정됩니다. 즉, 변수에 정수를 넣을지 문자열을 넣을지가 프로그램을 실행하기 전에 이미 확정되어 있어야 합니다. 이는 Python이나 JavaScript처럼 실행 중에 타입이 바뀔 수 있는 동적 타입 언어와 대비되는 특징입니다.

정적 타입의 가장 큰 장점은 오류를 조기에 발견할 수 있다는 점입니다. 문자열과 숫자를 실수로 더하려 하거나, 함수에 잘못된 개수의 인자를 넘기는 실수를 컴파일러가 실행 전에 잡아줍니다. 대규모 프로젝트에서는 이런 조기 검증이 유지보수 비용을 크게 줄여줍니다.

```go
// Go는 변수의 타입을 컴파일 시점에 확정한다
var age int = 30
// age = "서른" // 컴파일 오류: string을 int 변수에 대입할 수 없다
```

### 컴파일 언어

Go로 작성한 소스 코드는 실행 전에 반드시 기계어로 컴파일되는 과정을 거칩니다. 이는 별도의 인터프리터 없이 운영체제가 직접 실행할 수 있는 바이너리 파일을 만든다는 뜻입니다. 컴파일된 바이너리는 별도의 런타임 설치 없이 배포할 수 있고, 대체로 인터프리터 언어보다 실행 속도가 빠릅니다. 컴파일과 실행의 구체적인 과정은 2장에서 직접 실습하며 확인합니다.

### 단순한 문법

Go는 언어 자체의 키워드 수가 매우 적습니다(약 25개 정도). 클래스 대신 구조체(struct)와 인터페이스(interface)를 사용하고, 상속 대신 조합(composition)을 권장하며, 예외(exception) 처리 메커니즘 대신 값으로 표현되는 에러를 사용합니다. 이런 선택들은 "기능을 최대한 많이 넣는 것"이 아니라 "적은 개념으로 많은 것을 표현하는 것"을 지향하는 설계 철학에서 나온 것입니다. 실제로 Go 언어 명세(specification)는 다른 주류 언어에 비해 훨씬 짧아서, 숙련된 개발자라면 하루 이틀 만에 전체 문법을 훑어볼 수 있을 정도입니다.

### 빠른 컴파일

Go는 처음 설계될 때부터 컴파일 속도를 핵심 목표로 삼았습니다. 구글처럼 수백만 줄 규모의 코드베이스를 다루는 조직에서는, C++ 프로젝트 하나를 컴파일하는 데 수십 분이 걸리는 문제가 실제로 개발 생산성을 갉아먹는 요인이었습니다. Go는 의존성 구조를 단순하게 강제하고(순환 임포트 금지 등), 타입 추론과 파싱 방식을 최적화해서 대규모 프로젝트도 수 초에서 수십 초 안에 컴파일이 끝나도록 설계되었습니다.

### 동시성을 언어 차원에서 지원

Go의 가장 유명한 특징은 고루틴(goroutine)과 채널(channel)이라는 동시성 도구를 언어 문법 자체에 내장하고 있다는 점입니다. 다른 많은 언어에서 동시성 프로그래밍은 별도의 라이브러리나 복잡한 스레드 관리 API를 통해 다뤄지지만, Go는 `go` 키워드 하나로 새로운 고루틴을 실행할 수 있고, 채널을 통해 고루틴 사이에 안전하게 값을 주고받을 수 있습니다.

```go
// go 키워드만 붙이면 새로운 고루틴에서 함수가 실행된다
go doSomething()
```

고루틴과 채널에 대해서는 13장 고루틴과 동시성 기초, 14장 채널에서 본격적으로 다룹니다. 지금은 "Go는 동시성 프로그래밍을 쉽게 만들기 위해 설계된 언어"라는 인상만 가지고 있으면 충분합니다.

## Go는 어디에 쓰이는가

Go는 특정 산업 하나에 국한되지 않고 폭넓게 쓰이지만, 특히 다음 세 분야에서 두드러집니다.

### 서버와 백엔드 개발

Go는 HTTP 서버를 표준 라이브러리만으로도 손쉽게 만들 수 있고, 동시성 처리가 뛰어나 다수의 요청을 동시에 처리해야 하는 API 서버, 마이크로서비스에 적합합니다. Uber, Twitch, Dropbox 같은 회사들이 트래픽이 많은 백엔드 시스템의 일부를 Go로 구축한 사례가 잘 알려져 있습니다.

### 클라우드 인프라 도구

지금 클라우드 생태계를 지탱하는 핵심 도구들 중 상당수가 Go로 작성되어 있습니다. 컨테이너 기술의 표준이 된 Docker, 컨테이너 오케스트레이션의 사실상 표준인 Kubernetes, 인프라를 코드로 관리하는 Terraform 등이 모두 Go로 만들어졌습니다. 이런 인프라 도구들이 Go를 선택한 이유는 배포가 간단하고(단일 실행 파일), 여러 운영체제에 크로스 컴파일하기 쉬우며, 다수의 네트워크 연결이나 프로세스를 동시에 다뤄야 하는 요구사항과 Go의 동시성 모델이 잘 맞아떨어지기 때문입니다.

### 커맨드라인 도구(CLI)

Go로 빌드한 프로그램은 별도의 런타임 설치 없이 배포되는 단일 실행 파일이기 때문에, 사용자가 "다운로드해서 바로 실행"할 수 있는 CLI 도구를 만들기에 이상적입니다. GitHub의 공식 CLI인 `gh`, HashiCorp의 여러 도구들이 Go로 만들어진 대표적인 예입니다.

이 밖에도 네트워크 프로그래밍, 데이터 파이프라인, DevOps 자동화 스크립트 등 다양한 영역에서 Go가 쓰이고 있습니다.

## 다른 언어와 비교한 Go의 위치

Go를 처음 접하는 사람들은 자연스럽게 자신이 알고 있는 언어와 비교하게 됩니다. 몇 가지 대표적인 비교를 통해 Go의 위치를 가늠해봅시다.

### C와 비교

Go는 문법적으로 C의 영향을 짙게 받았습니다. 중괄호로 블록을 표시하고, 세미콜론(내부적으로는 자동 삽입되지만), 포인터 개념 등이 C와 닮아 있습니다. 하지만 Go는 C보다 훨씬 높은 수준의 안전장치를 제공합니다. 예를 들어 Go는 자동 메모리 관리(가비지 컬렉션)를 제공하므로 C처럼 `malloc`과 `free`를 직접 짝지어 호출할 필요가 없고, 배열 경계를 벗어난 접근은 실행 시점에 즉시 감지되어 프로그램이 안전하게 중단됩니다. 포인터는 있지만 포인터 연산(주소에 숫자를 더하는 등)은 허용하지 않아 C보다 훨씬 제한적이고 안전합니다. 포인터는 9장 포인터에서 자세히 다룹니다.

### Java와 비교

Java와 Go는 둘 다 정적 타입 언어이고 가비지 컬렉션을 사용한다는 공통점이 있습니다. 하지만 Go에는 전통적인 의미의 클래스나 상속이 없습니다. 대신 구조체에 메서드를 붙이고, 인터페이스는 명시적으로 "implements"를 선언하지 않아도 필요한 메서드를 갖추기만 하면 자동으로 그 인터페이스를 만족하는 구조적 타이핑(structural typing) 방식을 씁니다. 이 방식은 10장 인터페이스에서 자세히 다룹니다. 또한 Java 애플리케이션은 JVM이라는 별도의 런타임 위에서 실행되지만, Go는 컴파일 시점에 필요한 것을 모두 바이너리에 담아 독립적으로 실행되는 파일을 만듭니다.

### Python과 비교

Python은 동적 타입 언어이며 인터프리터로 실행되기 때문에, 짧은 스크립트를 빠르게 작성하고 실험하기에 매우 편리합니다. 반면 Go는 정적 타입에 컴파일 언어라서 초반에 타입을 선언하는 수고가 조금 더 들지만, 프로그램 규모가 커질수록 컴파일러가 잡아주는 오류의 가치가 커지고 실행 속도도 Python보다 훨씬 빠릅니다. 두 언어는 경쟁 관계라기보다 "빠른 프로토타이핑이 중요한가, 아니면 성능과 안정성이 중요한가"에 따라 다르게 선택되는 도구에 가깝습니다.

## Go의 설계 철학: 단순함과 명시성

Go의 설계자들은 여러 인터뷰와 발표에서 반복적으로 두 가지 가치를 강조해왔습니다. 바로 단순함(simplicity)과 명시성(explicitness)입니다.

**단순함**은 언어에 기능을 최소한으로 유지한다는 뜻입니다. Go에는 다른 언어에 흔히 있는 제네릭 이전 시절의 오버로딩, 예외 처리를 위한 `try/catch`, 삼항 연산자, 암묵적 타입 변환 같은 기능이 없거나 제한적입니다. 처음에는 "왜 이런 편리한 기능이 없을까"라고 느낄 수 있지만, 기능이 적을수록 코드를 읽는 사람이 예측해야 할 경우의 수가 줄어들고, 여러 사람이 협업할 때 코드 스타일의 편차가 줄어드는 효과가 있습니다.

**명시성**은 프로그램이 하는 일을 코드에 최대한 드러낸다는 뜻입니다. 대표적인 예가 에러 처리입니다. Go는 예외를 던지고 잡는 방식 대신, 함수가 실패할 수 있으면 에러 값을 반환값으로 명시적으로 돌려주는 관용구를 씁니다.

```go
result, err := doSomething()
if err != nil {
	// 에러가 발생했을 때의 처리를 명시적으로 작성한다
	return err
}
```

이 패턴은 처음 보면 반복적이라고 느껴질 수 있지만, 어떤 함수가 실패할 수 있는지, 실패했을 때 어떻게 처리하는지가 코드 흐름에 그대로 드러난다는 장점이 있습니다. 에러 처리는 11장 에러 처리에서 본격적으로 다룹니다.

이 두 철학은 이 책 전체에서 반복해서 등장할 것입니다. 어떤 문법이 "왜 이렇게 생겼을까" 싶을 때는 대개 단순함과 명시성이라는 기준으로 설명할 수 있습니다.

## 개발 환경 준비하기

이제 Go를 실제로 설치해봅시다.

### Go 설치

공식 웹사이트(go.dev)에서 운영체제에 맞는 설치 파일을 내려받아 설치하는 것이 가장 확실한 방법입니다. Windows, macOS, Linux 모두 공식 인스톨러 또는 패키지 관리자(예: macOS의 Homebrew, Linux의 apt)를 통해 설치할 수 있습니다. 설치가 끝나면 터미널에서 다음 명령으로 정상적으로 설치되었는지 확인합니다.

```
go version
```

이 명령을 실행하면 `go version go1.22.0 windows/amd64`처럼 설치된 Go의 버전과 운영체제/아키텍처 정보가 출력됩니다. 이 출력이 보이지 않고 "명령을 찾을 수 없습니다" 같은 오류가 뜬다면, 설치 경로가 시스템의 PATH 환경 변수에 등록되지 않은 것이므로 설치 과정을 다시 확인해야 합니다.

### go.mod란 무엇인가

Go 프로젝트는 대부분 모듈(module) 단위로 관리됩니다. 모듈은 관련된 여러 패키지를 하나로 묶은 배포 단위이며, 각 모듈의 루트 디렉터리에는 `go.mod`라는 파일이 있습니다. 이 파일은 다음과 같은 정보를 담고 있습니다.

- 모듈의 이름(다른 프로젝트에서 이 모듈을 가져다 쓸 때 사용하는 경로)
- 이 모듈이 사용하는 Go 언어 버전
- 이 모듈이 의존하는 외부 패키지 목록과 그 버전

새 프로젝트를 시작할 때는 다음 명령으로 `go.mod` 파일을 생성합니다.

```
go mod init example/hello
```

이 명령을 실행하면 현재 디렉터리에 다음과 같은 내용의 `go.mod` 파일이 만들어집니다.

```
module example/hello

go 1.22
```

`go.mod`는 Python의 `requirements.txt`나 `pyproject.toml`, Node.js의 `package.json`과 비슷한 역할을 한다고 생각하면 이해하기 쉽습니다. 모듈과 패키지에 대한 자세한 내용, 그리고 외부 패키지를 내려받아 쓰는 방법은 16장 패키지와 모듈에서 다룹니다. 지금은 "Go 프로젝트를 시작하려면 `go mod init`으로 `go.mod` 파일부터 만든다"는 정도만 기억해두면 됩니다.

### 에디터 선택

Go 코드를 작성하는 데는 특별한 IDE가 필요하지 않지만, Visual Studio Code에 공식 Go 확장을 설치하면 자동 완성, 정의로 이동, 자동 포맷팅, 오류 표시 같은 기능을 편하게 쓸 수 있습니다. GoLand 같은 전용 IDE도 널리 쓰입니다. 이 책의 예제는 어떤 에디터를 쓰든 동일하게 동작하므로, 평소 익숙한 도구를 사용해도 무방합니다.

## 이 책의 학습 방향

이 책은 크게 네 부분으로 나눌 수 있습니다.

1. **기초 문법** (1장~6장): Go의 기본 문법, 변수와 자료형, 연산자, 제어문, 함수를 다룹니다. 다른 언어 경험이 있다면 빠르게 훑고 지나갈 수 있는 부분입니다.
2. **자료구조와 타입 시스템** (7장~10장): 배열과 슬라이스, 맵과 구조체, 포인터, 인터페이스처럼 Go 프로그램의 데이터를 구성하는 핵심 도구들을 다룹니다.
3. **에러 처리와 프로그램 흐름 제어** (11장~12장): Go 특유의 에러 처리 관용구와 디퍼(지연 실행), 패닉, 복구를 다룹니다.
4. **동시성과 실전 활용** (13장~18장): Go의 대표 강점인 동시성 프로그래밍(고루틴, 채널, 동기화 도구)과 패키지 관리, 표준 라이브러리 활용, 좋은 코드 작성 습관까지 다룹니다.

각 장은 이전 장에서 배운 내용을 전제로 이어지도록 구성되어 있으므로, 순서대로 읽는 것을 권장합니다. 다만 이미 다른 언어에 익숙한 독자라면 3~6장은 빠르게 훑어보고 7장부터 속도를 늦춰 읽어도 좋습니다. 모든 코드 예제는 실제로 직접 타이핑해서 실행해보길 권합니다. 특히 Go는 컴파일러가 매우 엄격해서 사용하지 않는 변수나 임포트가 있으면 컴파일 자체가 되지 않는데, 이런 특징은 글로만 읽기보다 직접 오류를 마주치고 고쳐보는 과정에서 훨씬 잘 체득됩니다. 이 부분은 2장에서 바로 실습합니다.

## 요약

- Go는 2009년 구글에서 공개한 정적 타입, 컴파일 언어로, 단순한 문법과 빠른 컴파일, 언어 차원의 동시성 지원을 특징으로 한다.
- Go는 서버/백엔드, 클라우드 인프라 도구(Docker, Kubernetes, Terraform 등), 커맨드라인 도구 개발에서 특히 널리 쓰인다.
- C와 비교하면 더 안전하고(가비지 컬렉션, 제한된 포인터 연산), Java와 비교하면 클래스 상속 대신 구조체와 구조적 타이핑을 사용하며, Python과 비교하면 정적 타입과 컴파일을 통해 더 이른 시점에 오류를 발견할 수 있다.
- Go의 설계 철학은 단순함(적은 기능, 예측 가능한 코드)과 명시성(에러를 값으로 명시적으로 다루는 등)으로 요약된다.
- `go version`으로 설치를 확인하고, `go mod init`으로 `go.mod` 파일을 만들어 프로젝트를 시작한다.
- `go.mod`는 모듈의 이름, Go 버전, 의존 패키지 정보를 담는 파일로, 자세한 내용은 16장에서 다룬다.

## 연습문제

1. Go의 설계자 세 명의 이름을 찾아보고, 이들이 Go 이전에 어떤 프로젝트나 언어에 참여했는지 한 가지씩 조사해 정리해보세요.
2. 자신의 컴퓨터에 Go를 설치한 뒤 `go version` 명령을 실행하여 설치된 버전을 확인해보세요. 설치된 버전과 운영체제/아키텍처 정보를 적어보세요.
3. 원하는 디렉터리에서 `go mod init` 명령으로 `go.mod` 파일을 생성해보고, 파일 내용을 열어 어떤 정보가 담겨 있는지 확인해보세요.
4. 본문에서 소개한 정적 타입과 동적 타입의 차이를 자신의 언어로 다시 설명해보고, 여러분이 알고 있는 언어 중 정적 타입 언어와 동적 타입 언어를 하나씩 예로 들어보세요.
5. Docker, Kubernetes, Terraform 중 하나를 골라 공식 문서나 소개 자료를 찾아보고, 이 도구가 왜 Go로 작성되었는지에 대한 설명이 있다면 어떤 이유를 들고 있는지 정리해보세요.
