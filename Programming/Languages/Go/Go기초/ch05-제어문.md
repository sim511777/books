# 5장. 제어문

---

프로그램은 위에서 아래로 순서대로 실행되는 코드만으로는 부족합니다. 조건에 따라 다른 일을 하거나, 같은 작업을 여러 번 반복해야 할 때가 훨씬 많습니다. 이런 흐름을 제어하는 문법을 통틀어 제어문(control statement)이라고 부릅니다.

Go의 제어문은 C, Java, JavaScript 같은 언어를 써본 사람에게는 낯익으면서도 군더더기가 빠져 있다는 인상을 줍니다. 조건식에 괄호를 강제로 두르지 않고, 반복문은 `for` 하나로 통일되어 있으며, `switch`는 다른 언어보다 훨씬 유연합니다. 이번 장에서는 `if`, `switch`, `for`, 그리고 `break`/`continue`와 레이블(label)까지 Go가 프로그램의 흐름을 제어하는 방식을 하나씩 살펴봅니다.

## if문

### 기본 형태

Go의 `if`문은 조건식을 감싸는 괄호가 없다는 점이 가장 먼저 눈에 띕니다. 대신 중괄호 `{}`는 절대 생략할 수 없습니다.

```go
package main

import "fmt"

func main() {
	age := 20

	if age >= 18 {
		fmt.Println("성인입니다.")
	} else {
		fmt.Println("미성년자입니다.")
	}
}
```

C나 Java에서는 `if (age >= 18)`처럼 괄호를 쓰지만, Go에서는 `if age >= 18`이라고만 씁니다. 조건식에 괄호를 붙이면 오히려 컴파일 에러는 아니지만 gofmt가 제거해 버립니다. 반면 중괄호는 조건문이 한 줄짜리라도 생략할 수 없습니다. 이는 "중괄호를 생략했다가 나중에 문장을 하나 더 추가하면서 버그가 생기는" 흔한 실수를 원천적으로 막기 위한 설계입니다.

### else if 연결

여러 조건을 순서대로 검사하려면 `else if`를 연결합니다.

```go
func gradeOf(score int) string {
	if score >= 90 {
		return "A"
	} else if score >= 80 {
		return "B"
	} else if score >= 70 {
		return "C"
	} else {
		return "F"
	}
}
```

다만 이런 식으로 조건이 여러 개 이어질 때는 뒤에서 살펴볼 조건 없는 `switch`문을 쓰는 편이 더 Go다운 표현일 때가 많습니다.

### 초기화 문을 포함한 if

Go의 `if`문이 가진 독특한 특징 중 하나는 조건식 앞에 짧은 초기화 문(init statement)을 함께 쓸 수 있다는 점입니다. 세미콜론(`;`)으로 초기화 문과 조건식을 구분합니다.

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	input := "42"

	if n, err := strconv.Atoi(input); err != nil {
		fmt.Println("숫자로 변환할 수 없습니다:", err)
	} else {
		fmt.Println("변환된 값:", n)
	}
}
```

이 형태의 핵심은 초기화 문에서 선언한 변수(`n`, `err`)의 유효 범위(scope)가 `if`와 그에 딸린 `else` 블록 안으로 한정된다는 점입니다. `if` 블록을 벗어나면 `n`과 `err`는 더 이상 존재하지 않습니다. 이렇게 하면 함수 하나에서 여러 번 임시 결과를 검사할 때마다 매번 새 변수명을 고민할 필요 없이 `n`, `err` 같은 이름을 계속 재사용할 수 있고, 실수로 함수 바깥 범위까지 변수가 새어 나가는 일도 없습니다.

이 패턴은 11장(에러 처리)에서 다룰 `if err != nil` 관용구와 함께 Go 코드 전반에서 가장 자주 보게 될 형태이니 지금 익혀 두는 것이 좋습니다.

```go
if err := doSomething(); err != nil {
	fmt.Println("오류 발생:", err)
	return
}
```

### 조건식은 반드시 bool

Go에서는 `if 0`이나 `if pointer`처럼 정수나 포인터를 조건식 자리에 바로 쓸 수 없습니다. 조건식의 결과는 반드시 `bool` 타입이어야 합니다.

```go
var count int = 0

// if count { ... } // 컴파일 에러: count는 int이지 bool이 아님
if count != 0 {
	fmt.Println("count가 0이 아닙니다.")
}
```

C 계열 언어에서 넘어온 사람이라면 처음에는 번거롭게 느껴질 수 있지만, "0이 아니면 참"과 같은 암묵적 규칙이 사라지면서 조건식의 의도가 코드에 더 명확하게 드러나는 효과가 있습니다. 3장에서 다룬 자료형과 4장의 비교 연산자를 떠올리면 자연스럽게 이해될 것입니다.

## switch문

### 기본 형태와 자동 break

Go의 `switch`문은 다른 언어와 비교했을 때 두 가지가 크게 다릅니다. 첫째, 각 `case`는 기본적으로 끝나면 자동으로 `switch` 블록을 빠져나갑니다. C나 Java처럼 다음 `case`로 흘러 들어가는(fall-through) 일이 기본값이 아닙니다.

```go
package main

import "fmt"

func main() {
	weekday := 3

	switch weekday {
	case 1:
		fmt.Println("월요일")
	case 2:
		fmt.Println("화요일")
	case 3:
		fmt.Println("수요일")
	case 4:
		fmt.Println("목요일")
	case 5:
		fmt.Println("금요일")
	default:
		fmt.Println("주말")
	}
}
```

C에서라면 각 `case` 끝에 `break;`를 빼먹지 않도록 항상 신경 써야 했지만, Go에서는 그럴 필요가 없습니다. `case 3:`에 해당하면 "수요일"을 출력하고 바로 `switch`문을 빠져나갑니다.

### 하나의 case에 여러 값

쉼표로 구분하면 하나의 `case`에 여러 값을 나열할 수 있습니다.

```go
switch weekday {
case 1, 2, 3, 4, 5:
	fmt.Println("평일")
case 6, 7:
	fmt.Println("주말")
}
```

### fallthrough가 필요한 이유

자동으로 다음 case로 넘어가지 않는다는 것은, 반대로 "의도적으로 다음 case까지 실행하고 싶을 때"는 별도의 키워드가 필요하다는 뜻입니다. 그래서 Go는 `fallthrough` 키워드를 제공합니다.

```go
package main

import "fmt"

func describe(n int) {
	switch {
	case n >= 90:
		fmt.Println("우수 등급 이상입니다.")
		fallthrough
	case n >= 70:
		fmt.Println("합격입니다.")
	default:
		fmt.Println("불합격입니다.")
	}
}

func main() {
	describe(95)
	// 출력:
	// 우수 등급 이상입니다.
	// 합격입니다.
}
```

`fallthrough`는 조건을 다시 검사하지 않고 무조건 바로 다음 case의 본문을 실행시킨다는 점에 유의해야 합니다. 즉 `n >= 70`이 참인지 검사하는 게 아니라, 그냥 다음 블록으로 넘어갑니다. 이 때문에 `fallthrough`는 실수로 넣으면 의도치 않은 코드가 실행될 위험이 있어서, 정말 필요한 경우가 아니면 잘 쓰이지 않습니다. 대부분의 Go 코드에서는 `case`에 값을 여러 개 나열하는 방식(위의 "하나의 case에 여러 값" 참고)이나 조건 없는 switch로 대부분의 요구를 해결합니다.

### 조건 없는 switch: if-else 체인 대체하기

`switch` 뒤에 판별할 값을 아예 생략하면, 각 `case`는 `bool` 값을 내는 임의의 조건식이 됩니다. 이는 `switch true`와 동일하게 동작하며, 여러 개의 `if-else if-else`를 연결하는 것보다 훨씬 읽기 좋은 코드를 만들어 줍니다.

```go
package main

import "fmt"

func gradeOf(score int) string {
	switch {
	case score >= 90:
		return "A"
	case score >= 80:
		return "B"
	case score >= 70:
		return "C"
	default:
		return "F"
	}
}

func main() {
	fmt.Println(gradeOf(85)) // B
}
```

앞서 `if`문에서 본 `gradeOf` 함수와 비교해 보면, 조건이 세 개, 네 개로 늘어날수록 `switch` 쪽이 들여쓰기가 깊어지지 않고 각 조건이 나란히 정렬되어 훨씬 눈에 잘 들어옵니다. Go 표준 라이브러리 소스 코드에서도 이런 형태의 조건 없는 `switch`를 자주 볼 수 있습니다. "조건 분기가 세 개 이상 이어진다면 switch를 먼저 고려한다"는 것을 하나의 습관으로 삼아도 좋습니다.

### switch에도 초기화 문을 쓸 수 있다

`if`문과 마찬가지로 `switch`도 조건식 앞에 초기화 문을 둘 수 있습니다.

```go
switch n := len(input); {
case n == 0:
	fmt.Println("빈 입력입니다.")
case n < 10:
	fmt.Println("짧은 입력입니다.")
default:
	fmt.Println("긴 입력입니다.")
}
```

## for문 — Go의 유일한 반복문

C, Java, Python 등 많은 언어는 `for`, `while`, `do-while`처럼 여러 종류의 반복문을 따로 제공합니다. Go는 이들을 모두 `for` 키워드 하나로 통합했습니다. 겉모습에 따라 세 가지 형태로 나뉠 뿐, 문법적으로는 전부 같은 `for`문입니다.

### 전통적인 형태: 초기화; 조건; 후처리

C 스타일에 익숙한 사람에게 가장 친숙한 형태입니다. 다만 Go에서는 이 경우에도 괄호를 두르지 않습니다.

```go
package main

import "fmt"

func main() {
	for i := 0; i < 5; i++ {
		fmt.Println(i)
	}
}
```

세 부분(초기화 문, 조건식, 후처리 문)은 세미콜론으로 구분됩니다. 초기화 문에서 선언한 `i`는 `for`문 블록 안에서만 유효합니다.

### 조건만 있는 형태: while을 대신하다

초기화 문과 후처리 문을 생략하면 다른 언어의 `while`문과 똑같이 동작합니다.

```go
package main

import "fmt"

func main() {
	n := 1
	for n < 100 {
		n *= 2
	}
	fmt.Println(n) // 128
}
```

Go에는 `while` 키워드가 아예 없습니다. "조건만 있는 for문"이 곧 while문 역할을 합니다. 이 사실을 처음 접하면 어색하게 느껴질 수 있지만, 반복문의 형태가 하나로 통일되어 있다는 점은 오히려 Go 문법을 단순하게 유지해 주는 요소입니다.

### 무한 루프: 조건 자체를 생략

조건식마저 생략하면 무한히 반복하는 루프가 됩니다.

```go
package main

import "fmt"

func main() {
	count := 0
	for {
		count++
		if count == 3 {
			break
		}
		fmt.Println("반복 중:", count)
	}
}
```

무한 루프는 서버 프로그램이 요청을 계속 받아들이는 경우, 혹은 13장(고루틴과 동시성 기초)과 14장(채널)에서 다룰 것처럼 채널에서 값을 계속 받아 처리하는 경우에 자주 쓰입니다. 무한 루프 안에서는 보통 `if` 조건과 함께 `break`를 사용해 특정 조건이 되면 루프를 빠져나오도록 작성합니다.

### range를 이용한 순회

7장(배열과 슬라이스)과 8장(맵과 구조체)에서 자세히 다루겠지만, `for`문은 `range` 키워드와 함께 슬라이스, 배열, 맵, 문자열 등을 순회하는 데도 쓰입니다. 여기서는 감을 잡을 수 있도록 간단한 예시만 살펴봅니다.

```go
fruits := []string{"사과", "바나나", "포도"}

for i, fruit := range fruits {
	fmt.Println(i, fruit)
}
```

`range`도 결국 `for`문의 한 형태일 뿐, 별도의 반복문 키워드가 아니라는 점을 기억해 두면 좋습니다.

## break, continue, 그리고 레이블

### break와 continue

`break`는 반복문을 즉시 빠져나가고, `continue`는 현재 반복을 건너뛰고 다음 반복으로 넘어갑니다. 두 키워드는 C, Java 등 다른 언어와 동일하게 동작합니다.

```go
package main

import "fmt"

func main() {
	for i := 1; i <= 10; i++ {
		if i%2 != 0 {
			continue // 홀수는 건너뛴다
		}
		if i > 6 {
			break // 6을 넘으면 반복 종료
		}
		fmt.Println(i)
	}
	// 출력: 2 4 6
}
```

### 레이블을 이용한 중첩 루프 탈출

`break`와 `continue`는 기본적으로 자신을 감싸고 있는 가장 안쪽 반복문에만 영향을 줍니다. 그런데 반복문이 두 겹, 세 겹으로 중첩된 상황에서 바깥쪽 루프까지 한 번에 빠져나가고 싶을 때가 있습니다. 이럴 때 쓰는 것이 레이블(label)입니다.

레이블은 반복문 바로 앞에 `이름:` 형태로 붙이고, `break 이름` 또는 `continue 이름`처럼 사용합니다.

```go
package main

import "fmt"

func main() {
outer:
	for i := 1; i <= 3; i++ {
		for j := 1; j <= 3; j++ {
			if i*j >= 6 {
				fmt.Println("탈출 지점:", i, j)
				break outer
			}
			fmt.Println(i, j)
		}
	}
	fmt.Println("바깥 루프까지 종료됨")
}
```

레이블이 없다면 `break`는 안쪽 `for j` 루프만 빠져나가고 바깥쪽 `for i` 루프는 계속 실행됩니다. `break outer`라고 명시하면 `outer`라는 이름이 붙은 바깥쪽 루프까지 한 번에 종료됩니다. `continue outer`를 쓰면 바깥쪽 루프의 다음 반복으로 바로 넘어갈 수도 있습니다.

레이블은 유용하지만 남용하면 코드 흐름을 따라가기 어려워질 수 있습니다. 대부분의 경우 조건을 반환값이 있는 함수로 분리하고 `return`으로 빠져나오는 편이 더 읽기 좋은 코드가 됩니다. 이 내용은 6장(함수)에서 함수를 이용해 로직을 정리하는 방법과 함께 다시 생각해 볼 수 있습니다. 레이블은 정말 중첩 루프 탈출이 가장 단순한 해법일 때만 제한적으로 사용하는 것이 좋습니다.

## 요약

- Go의 `if`문은 조건식에 괄호를 쓰지 않지만 중괄호는 항상 필요합니다. 조건식은 반드시 `bool` 값이어야 합니다.
- `if`와 `switch` 모두 조건 앞에 세미콜론으로 구분된 초기화 문을 쓸 수 있고, 그렇게 선언한 변수는 해당 블록 안에서만 유효합니다. `if n, err := f(); err != nil { ... }` 형태는 11장에서 다룰 에러 처리의 기본 관용구입니다.
- `switch`의 각 `case`는 자동으로 종료되며(자동 break), 다음 `case`로 넘어가려면 명시적으로 `fallthrough`를 써야 합니다.
- 판별할 값을 생략한 조건 없는 `switch`는 여러 개의 `if-else if` 체인을 대체하는 관용적인 표현입니다.
- Go에는 `while`, `do-while`이 따로 없고 `for` 하나가 전통적인 형태, 조건만 있는 형태, 무한 루프 형태를 모두 담당합니다.
- `break`와 `continue`는 기본적으로 가장 안쪽 반복문에만 적용되며, 레이블을 사용하면 중첩된 바깥쪽 루프까지 제어할 수 있습니다.

## 연습문제
