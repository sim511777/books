## 자주 쓰는 내장 함수 치트시트

내장 함수(built-in function)는 `import` 없이 바로 사용할 수 있는, Go 언어 자체에 내장된 함수입니다.

| 함수 | 대상 | 역할 |
|---|---|---|
| `len(x)` | 배열, 슬라이스, 맵, 문자열, 채널 | 길이(요소 개수, 바이트 길이 등)를 반환 |
| `cap(x)` | 배열, 슬라이스, 채널 | 용량(재할당 없이 늘릴 수 있는 최대 크기)을 반환 |
| `make(T, ...)` | 슬라이스, 맵, 채널 | 초기화된 값을 만들어 반환 (제로 값이 아니라 바로 쓸 수 있는 상태로) |
| `new(T)` | 모든 타입 | `T` 타입의 제로 값을 담을 메모리를 할당하고 그 포인터(`*T`)를 반환 |
| `append(s, vs...)` | 슬라이스 | 슬라이스 끝에 값을 추가한 새 슬라이스를 반환 |
| `copy(dst, src)` | 슬라이스 | `src`의 값을 `dst`로 복사하고 복사된 개수를 반환 |
| `delete(m, k)` | 맵 | 맵에서 키 `k`에 해당하는 항목을 제거 |
| `close(ch)` | 채널 | 채널을 닫아 더 이상 값을 보낼 수 없게 함 |
| `panic(v)` | 모든 값 | 정상적인 실행 흐름을 중단시키고 즉시 패닉을 일으킴 |
| `recover()` | - | `defer`된 함수 안에서 진행 중인 패닉을 회수해 복구 |
| `min(a, b, ...)`, `max(a, b, ...)` | 비교 가능한 타입 | 여러 값 중 최솟값/최댓값 반환 (Go 1.21 이상) |
| `print`, `println` | - | 저수준 디버깅용 출력. 일반 코드에서는 `fmt` 패키지를 사용하는 것이 관례 |

```go
s := make([]int, 0, 4) // 길이 0, 용량 4인 슬라이스
s = append(s, 1, 2, 3)

m := make(map[string]int)
m["a"] = 1
delete(m, "a")

p := new(int) // *int, 가리키는 값은 0
*p = 42

fmt.Println(len(s), cap(s), *p)
```

`make`와 `new`는 헷갈리기 쉬운데, `make`는 슬라이스·맵·채널처럼 "내부에 준비 과정이 필요한" 세 가지 타입 전용이고, `new`는 어떤 타입이든 제로 값을 담을 메모리를 할당해 포인터만 돌려준다는 차이를 기억해두면 좋습니다. 실무에서는 `new`보다 `&T{}` 형태의 구조체 리터럴을 쓰는 경우가 더 흔합니다.

## 표준 라이브러리 함수 치트시트 (17장 총정리)

17장에서 소개한 패키지별 대표 함수를 한 표로 모았습니다.

### fmt

| 함수 | 역할 |
|---|---|
| `fmt.Println(a...)` | 값을 출력하고 줄바꿈 |
| `fmt.Printf(format, a...)` | 서식 지정자를 사용해 출력 |
| `fmt.Sprintf(format, a...)` | 서식 지정자를 사용해 문자열 생성(출력하지 않음) |
| `fmt.Errorf(format, a...)` | 서식 지정자를 사용해 error 값 생성 (`%w`로 에러 감싸기 가능) |

### strings

| 함수 | 역할 |
|---|---|
| `strings.Contains(s, sub)` | 부분 문자열 포함 여부 |
| `strings.Split(s, sep)` | 구분자로 분리 |
| `strings.Join(slice, sep)` | 구분자로 이어붙이기 |
| `strings.TrimSpace(s)` | 앞뒤 공백 제거 |
| `strings.ToUpper(s)` / `ToLower(s)` | 대소문자 변환 |
| `strings.ReplaceAll(s, old, new)` | 전체 치환 |
| `strings.Builder` | 효율적인 문자열 조립 |

### strconv

| 함수 | 역할 |
|---|---|
| `strconv.Atoi(s)` | 문자열 → int |
| `strconv.Itoa(i)` | int → 문자열 |
| `strconv.ParseFloat(s, 64)` | 문자열 → float64 |
| `strconv.ParseBool(s)` | 문자열 → bool |

### os

| 함수/변수 | 역할 |
|---|---|
| `os.Args` | 명령줄 인자 |
| `os.Getenv(key)` / `os.LookupEnv(key)` | 환경 변수 읽기 |
| `os.Exit(code)` | 즉시 종료 |
| `os.ReadFile(name)` / `os.WriteFile(name, data, perm)` | 파일 읽기/쓰기 (자세한 내용은 16장 참고) |

### time

| 함수 | 역할 |
|---|---|
| `time.Now()` | 현재 시각 |
| `time.Since(t)` | 경과 시간 |
| `time.Sleep(d)` | 지정한 시간만큼 대기 |
| `t.Format(layout)` / `time.Parse(layout, s)` | 시각 ↔ 문자열 변환 |

### encoding/json

| 함수 | 역할 |
|---|---|
| `json.Marshal(v)` | Go 값 → JSON 바이트 |
| `json.Unmarshal(data, &v)` | JSON 바이트 → Go 값 |
| `json.MarshalIndent(v, prefix, indent)` | 들여쓰기가 적용된 JSON 생성 |

### net/http

| 함수 | 역할 |
|---|---|
| `http.HandleFunc(pattern, handler)` | 경로별 처리 함수 등록 |
| `http.ListenAndServe(addr, handler)` | 서버 시작 |
| `http.Get(url)` | GET 요청 보내기 |

## 타입 크기표 (3장 총정리)

| 자료형 | 크기 | 비고 |
|---|---|---|
| `bool` | 1바이트 | `true` 또는 `false` |
| `int8` | 1바이트(8비트) | -128 ~ 127 |
| `int16` | 2바이트(16비트) | -32768 ~ 32767 |
| `int32` | 4바이트(32비트) | 약 -21억 ~ 21억. `rune`의 별칭 |
| `int64` | 8바이트(64비트) | 약 -922경 ~ 922경 |
| `uint8` | 1바이트(8비트) | 0 ~ 255. `byte`의 별칭 |
| `uint16` | 2바이트(16비트) | 0 ~ 65535 |
| `uint32` | 4바이트(32비트) | 0 ~ 약 42억 |
| `uint64` | 8바이트(64비트) | 0 ~ 약 1844경 |
| `int`, `uint` | 4바이트 또는 8바이트 | 실행 플랫폼에 따라 `int32`/`int64`와 동일한 크기. 특별한 이유가 없다면 정수는 `int`를 사용 |
| `float32` | 4바이트 | 단정밀도 부동소수점 |
| `float64` | 8바이트 | 배정밀도 부동소수점. 특별한 이유가 없다면 실수는 `float64`를 사용 |
| `string` | 가변 길이 | 내부적으로 UTF-8로 인코딩된 바이트의 나열 |
| 포인터(`*T`) | 4바이트 또는 8바이트 | 실행 플랫폼의 워드 크기에 따름(64비트 환경에서는 8바이트) |

이 표는 "이 타입은 대략 이 정도 크기구나"를 감 잡기 위한 참고용입니다. 정확한 메모리 배치나 구조체의 전체 크기(필드 정렬로 인한 패딩 포함)가 궁금하다면 `unsafe.Sizeof`로 직접 확인해볼 수 있습니다.

```go
package main

import (
	"fmt"
	"unsafe"
)

func main() {
	var i int32
	var f float64
	fmt.Println(unsafe.Sizeof(i)) // 4
	fmt.Println(unsafe.Sizeof(f)) // 8
}
```

## 참고 자료 유형 안내

이 책 이후에도 Go를 계속 공부하고 싶다면 다음과 같은 유형의 자료를 활용하는 것을 추천합니다. 특정 책이나 강의를 콕 집어 추천하기보다는, 어떤 종류의 자료가 어떤 상황에 도움이 되는지를 안내합니다.

- **공식 문서**: Go 프로젝트가 직접 관리하는 언어 명세와 표준 라이브러리 문서는 가장 정확하고 최신 정보를 담고 있습니다. 함수 하나의 정확한 동작이 궁금할 때는 언제나 공식 문서를 1순위로 확인하는 습관을 들이는 것이 좋습니다.
- **표준 라이브러리 소스 코드**: Go 표준 라이브러리 자체가 관용적인 Go 코드의 훌륭한 예시입니다. 자주 쓰는 함수의 내부 구현을 직접 읽어보는 것만으로도 좋은 스타일을 익힐 수 있습니다.
- **언어·도구 변경 이력**: Go는 매 버전마다 변경 사항을 공식적으로 공지합니다. 새 버전이 나올 때마다 무엇이 달라졌는지 훑어보면 언어의 발전 방향을 자연스럽게 따라갈 수 있습니다.
- **오픈소스 프로젝트 코드 읽기**: 실제로 널리 쓰이는 오픈소스 프로젝트의 코드를 읽어보면, 이 책에서 배운 개념들이 실전에서 어떻게 조합되는지 확인할 수 있습니다. 특히 에러 처리와 동시성 패턴은 실제 코드에서 배우는 것이 효과적입니다.
- **커뮤니티 컨퍼런스 발표 영상**: Go 관련 컨퍼런스에서는 언어 설계자와 실무자들이 설계 배경이나 실전 노하우를 자주 공유합니다. 문서에는 잘 나오지 않는 "왜 이렇게 설계했는가"에 대한 맥락을 얻기 좋습니다.
- **직접 만들어보며 배우기**: 결국 가장 효과적인 학습 자료는 스스로 작성하고 고쳐 나가는 코드 그 자체입니다. 18장에서 제안한 방향(웹 서버, CLI 도구, 동시성 프로그램 등)을 참고해 작은 프로젝트를 완성해보는 경험을 꼭 가져보시기 바랍니다.
