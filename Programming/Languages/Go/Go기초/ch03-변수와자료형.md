프로그램은 결국 데이터를 다루는 일이다. 데이터를 담아두는 그릇이 변수이고, 그 그릇에 어떤 종류의 데이터를 담을 수 있는지를 정하는 것이 자료형이다. 2장에서 이미 `var`와 `:=`를 살짝 사용해 보았지만, 이번 장에서는 Go의 변수 선언 방법과 기본 자료형을 체계적으로 정리한다. Go는 자료형을 다루는 데 있어 상당히 엄격한 언어다. 이 엄격함이 처음에는 불편하게 느껴질 수 있지만, 결국은 실수를 컴파일 시점에 잡아주는 안전장치라는 것을 알게 될 것이다.

## 변수 선언: var 키워드

Go에서 변수를 선언하는 가장 기본적인 방법은 `var` 키워드를 사용하는 것이다.

```go
package main

import "fmt"

func main() {
	var age int
	var name string
	var height float64

	age = 17
	name = "지훈"
	height = 172.5

	fmt.Println(name, age, height)
}
```

`var 변수이름 자료형` 형태로 선언하고, 이후에 `=`로 값을 대입한다. 선언과 동시에 초기값을 지정할 수도 있다.

```go
var age int = 17
var name string = "지훈"
```

이때 자료형은 오른쪽 값으로부터 추론이 가능하기 때문에 생략할 수도 있다.

```go
var age = 17       // int로 추론됨
var name = "지훈"   // string으로 추론됨
```

### 여러 변수를 한 번에 선언하기

관련된 변수가 여러 개라면 괄호를 사용해 묶어서 선언하면 코드가 훨씬 깔끔해진다.

```go
var (
	name   string = "지훈"
	age    int    = 17
	height float64
)
```

또는 같은 자료형의 변수 여러 개를 한 줄에 선언할 수도 있다.

```go
var x, y, z int
var a, b = 1, "hello"
```

`var x, y, z int`처럼 자료형을 하나만 적으면 나열된 변수 모두가 그 자료형을 갖는다. `var a, b = 1, "hello"`처럼 초기값을 각각 다르게 주면 자료형도 각 값에 맞춰 추론된다.

## 짧은 변수 선언: :=

Go에는 함수 내부에서만 사용할 수 있는 축약 문법이 있다. 바로 `:=` 연산자다.

```go
func main() {
	age := 17
	name := "지훈"
	height := 172.5

	fmt.Println(name, age, height)
}
```

`:=`는 `var`와 자료형 추론을 합쳐놓은 것이라고 생각하면 된다. `var age int = 17`을 `age := 17`로 줄여 쓸 수 있는 것이다. 다중 대입도 가능하다.

```go
x, y := 1, 2
name, ok := "지훈", true
```

### var와 :=, 언제 무엇을 쓸까

두 방법 모두 변수를 만들지만 쓰이는 상황이 다르다.

- **`:=`는 함수 내부에서만 사용할 수 있다.** 패키지 최상위 레벨(함수 바깥)에서는 반드시 `var`를 사용해야 한다.
- **제로 값으로 시작하고 싶을 때는 `var`가 자연스럽다.** 예를 들어 `var total int`라고 선언하면 `total`은 자동으로 0이 되고, 이후 반복문 안에서 값을 누적할 수 있다. `total := 0`도 결과는 같지만, 의도를 드러내는 방식이 다르다.
- **자료형을 명시적으로 지정하고 싶을 때는 `var`를 쓴다.** 예를 들어 `var price float64 = 100`처럼 정수 리터럴을 실수형 변수에 대입하고 싶을 때, `:=`만으로는 이런 표현이 번거롭다.
- **간단한 지역 변수는 `:=`가 훨씬 간결하다.** 실무에서는 함수 안에서 대부분 `:=`를 사용하고, 최상위 레벨 선언이나 자료형을 강조하고 싶을 때만 `var`를 쓰는 경우가 많다.

한 가지 주의할 점은 `:=`는 왼쪽에 있는 변수 중 최소 하나는 새로 선언되는 변수여야 한다는 것이다.

```go
x := 1
x, y := 2, 3   // x는 재대입, y는 새로 선언 — 가능
x, y := 4, 5   // 새로 선언되는 변수가 하나도 없음 — 컴파일 에러
```

또한 이미 선언된 변수를 `var`로 같은 스코프에서 다시 선언하면 컴파일 에러가 나지만, `:=`를 사용할 때 위와 같이 변수 중 하나라도 새로운 이름이면 허용된다는 점이 다르다.

## 기본 자료형

Go의 기본 자료형은 크게 정수형, 실수형, 문자열, 불리언으로 나뉜다.

### 정수형

Go의 정수형은 부호가 있는 것과 없는 것으로 나뉘고, 각각 크기(비트 수)가 다른 여러 종류가 있다.

| 자료형 | 크기 | 표현 범위 |
|---|---|---|
| `int8` | 8비트 | -128 ~ 127 |
| `int16` | 16비트 | -32768 ~ 32767 |
| `int32` | 32비트 | 약 -21억 ~ 21억 |
| `int64` | 64비트 | 약 -922경 ~ 922경 |
| `uint8` | 8비트 | 0 ~ 255 |
| `uint16` | 16비트 | 0 ~ 65535 |
| `uint32` | 32비트 | 0 ~ 약 42억 |
| `uint64` | 64비트 | 0 ~ 약 1844경 |

이 외에도 `int`와 `uint`가 있는데, 이 둘은 크기가 고정되어 있지 않다. 실행되는 플랫폼(32비트 시스템인지 64비트 시스템인지)에 따라 `int32`와 같은 크기가 되거나 `int64`와 같은 크기가 된다. 요즘 대부분의 환경은 64비트이므로 사실상 `int64`와 같다고 생각해도 무방하다. 특별한 이유가 없다면 정수를 다룰 때는 그냥 `int`를 사용하는 것이 Go의 일반적인 관례다. 특정 크기가 반드시 필요한 경우(예: 네트워크 프로토콜의 바이트 구조를 그대로 표현해야 하는 경우)에만 `int32`, `uint16`처럼 크기를 명시한 자료형을 사용한다.

```go
var smallNumber int8 = 100
var bigNumber int64 = 9000000000
var count int = 42
```

정수형의 범위를 넘어서는 값을 대입하려고 하면 컴파일 시점에 에러가 발생한다.

```go
var tooSmall int8 = 200 // 컴파일 에러: 200이 int8 범위를 벗어남
```

### byte와 rune

Go에는 정수형이지만 특별한 이름을 가진 두 가지 별칭(alias)이 있다.

- `byte`는 `uint8`의 별칭이다. 8비트 부호 없는 정수이며, 문자 하나(정확히는 바이트 하나)를 표현할 때 주로 쓰인다.
- `rune`은 `int32`의 별칭이다. 유니코드 코드 포인트 하나를 표현할 때 사용한다.

Go의 문자열은 내부적으로 UTF-8로 인코딩된 바이트의 나열이다. 영어 알파벳처럼 1바이트로 표현되는 문자도 있지만, 한글처럼 3바이트가 필요한 문자도 있다. 그래서 문자열에서 "문자 하나"를 다룰 때는 `byte`가 아니라 `rune`을 사용해야 하는 경우가 많다.

```go
s := "Go언어"
fmt.Println(len(s)) // 바이트 길이: 8 (G,o는 각 1바이트, 언,어는 각 3바이트)

for i, r := range s {
	fmt.Printf("인덱스 %d: %c\n", i, r)
}
```

이 내용은 7장(배열과 슬라이스)에서 문자열과 슬라이스를 함께 다룰 때 조금 더 자세히 살펴본다. 지금은 "문자 하나를 다룰 때는 rune, 원시 바이트를 다룰 때는 byte"라는 정도만 기억해두자.

### 실수형

실수를 표현하는 자료형은 `float32`와 `float64` 두 가지가 있다.

```go
var pi32 float32 = 3.1415927
var pi64 float64 = 3.14159265358979
```

`float32`는 정밀도가 낮고 `float64`는 정밀도가 높다. 특별한 이유(예: 메모리를 극도로 아껴야 하는 상황)가 없다면 실수는 `float64`를 사용하는 것이 일반적이다. `:=`로 실수 리터럴을 선언하면 자동으로 `float64`로 추론된다.

```go
price := 19.99 // float64로 추론
```

부동소수점 연산은 근본적으로 오차를 가질 수 있다는 점도 기억해두자. 예를 들어 `0.1 + 0.2`는 정확히 `0.3`이 되지 않을 수 있다. 이는 Go만의 특성이 아니라 IEEE 754 부동소수점 표준을 따르는 대부분의 언어에서 공통적으로 나타나는 현상이다.

### 문자열

문자열은 `string` 자료형으로 표현한다. Go의 문자열은 한번 만들어지면 내용을 바꿀 수 없는 불변(immutable) 값이다.

```go
greeting := "안녕하세요"
name := "Go"
message := greeting + ", " + name + "!"
fmt.Println(message)
```

문자열은 큰따옴표(`"`)로 감싸거나, 여러 줄에 걸친 원시 문자열을 표현할 때는 백틱(`` ` ``)을 사용한다.

```go
oneLine := "첫 줄\n둘째 줄" // \n이 줄바꿈 문자로 해석됨
raw := `첫 줄
둘째 줄` // 백틱 안에서는 이스케이프 문자가 그대로 텍스트로 취급됨
```

### 불리언

논리값은 `bool` 자료형으로 표현하며, 값은 `true` 또는 `false` 둘 중 하나다.

```go
var isActive bool = true
isDone := false
```

C 계열 언어와 달리 Go는 정수를 불리언처럼 취급하지 않는다. `if 1 { ... }`와 같은 코드는 Go에서 컴파일되지 않는다. 조건식은 반드시 `bool` 자료형의 값이어야 한다. 이 내용은 5장(제어문)에서 조건문을 다룰 때 다시 확인하게 된다.

## 제로 값: 초기화하지 않아도 기본값이 있다

Go의 중요한 특징 중 하나는, 변수를 선언하고 초기값을 주지 않아도 자료형에 따라 정해진 **제로 값(zero value)**으로 자동 초기화된다는 것이다. C나 C++에서는 초기화하지 않은 지역 변수가 어떤 쓰레기 값을 가질지 알 수 없지만, Go에서는 그런 일이 없다.

| 자료형 | 제로 값 |
|---|---|
| 정수형 (`int`, `int8` 등) | `0` |
| 실수형 (`float32`, `float64`) | `0.0` |
| `bool` | `false` |
| `string` | `""` (빈 문자열) |
| 포인터, 슬라이스, 맵, 채널, 함수, 인터페이스 | `nil` |

```go
package main

import "fmt"

func main() {
	var count int
	var price float64
	var active bool
	var name string

	fmt.Println(count, price, active, name)
	// 출력: 0 0 false
}
```

이 설계 덕분에 "이 변수가 아직 값이 설정되지 않았을 때는 무엇을 의미하는가"라는 질문에 항상 명확한 답을 미리 정해둘 수 있다. 예를 들어 구조체(8장에서 다룬다)를 만들 때 필드 일부만 값을 채워도, 나머지 필드는 자동으로 제로 값을 갖게 되어 프로그램이 예측 가능하게 동작한다. 포인터의 제로 값인 `nil`에 대해서는 9장(포인터)에서 자세히 다룬다.

## 상수: const와 iota

변경되지 않는 값을 다룰 때는 변수 대신 상수를 사용한다. 상수는 `const` 키워드로 선언하며, 컴파일 시점에 값이 결정되어야 한다.

```go
const Pi = 3.14159
const MaxRetries = 3
const AppName = "MyApp"
```

여러 상수를 묶어서 선언할 수도 있다.

```go
const (
	StatusOK       = 200
	StatusNotFound = 404
	StatusError    = 500
)
```

상수는 이름 그대로 선언 이후 값을 바꿀 수 없다. 재대입을 시도하면 컴파일 에러가 발생한다.

```go
const MaxUsers = 100
MaxUsers = 200 // 컴파일 에러: 상수는 재대입할 수 없음
```

### iota로 연속된 상수 만들기

관련된 상수들을 순서대로 나열해야 할 때, Go는 `iota`라는 특별한 식별자를 제공한다. `iota`는 `const` 블록 안에서 0부터 시작해 한 줄씩 내려갈 때마다 1씩 증가하는 값이다.

```go
type Weekday int

const (
	Sunday Weekday = iota // 0
	Monday                // 1
	Tuesday                // 2
	Wednesday              // 3
	Thursday               // 4
	Friday                  // 5
	Saturday                // 6
)
```

`const` 블록에서 첫 줄에 표현식을 적어두면, 이후 줄에서 표현식을 생략해도 같은 표현식이 반복 적용되면서 `iota` 값만 증가한다. 이 성질을 이용하면 2의 거듭제곱 같은 값도 간결하게 표현할 수 있다.

```go
const (
	_  = iota             // 0은 사용하지 않고 버림
	KB = 1 << (10 * iota) // 1 << 10 = 1024
	MB                     // 1 << 20
	GB                     // 1 << 30
)
```

첫 줄에서 `_`(밑줄, 빈 식별자)를 사용해 0번째 값을 버리는 것도 자주 쓰이는 관용구다. `iota`는 열거형(enum)과 비슷한 개념을 표현할 때 특히 유용하다. Go에는 다른 언어처럼 별도의 `enum` 키워드가 없기 때문에, `const`와 `iota`, 그리고 이름이 붙은 자료형(`type Weekday int`처럼)을 조합해 열거형을 흉내 낸다. 이런 이름이 붙은 자료형은 10장(인터페이스)과 관련된 논의에서도 다시 등장한다.

## 형변환: 명시적 변환만 허용하는 Go의 엄격함

C, C++, 자바스크립트 같은 언어에 익숙하다면 서로 다른 자료형의 값을 섞어 계산하는 데 익숙할 것이다. 하지만 Go는 이 부분에서 매우 엄격하다. **자료형이 다르면 암묵적으로 변환되지 않는다.** 심지어 `int`와 `int64`처럼 둘 다 정수를 표현하는 자료형이라도 서로 다른 자료형으로 취급되어 직접 연산할 수 없다.

```go
var a int = 10
var b int64 = 20

// fmt.Println(a + b) // 컴파일 에러: int와 int64는 다른 자료형
```

이런 경우에는 명시적으로 형변환을 해주어야 한다. Go의 형변환 문법은 `자료형(값)` 형태다.

```go
var a int = 10
var b int64 = 20

result := int64(a) + b // a를 int64로 변환한 뒤 더함
fmt.Println(result)    // 30
```

정수와 실수 사이의 변환도 마찬가지로 명시적으로 해야 한다.

```go
var count int = 7
var total int = 20

ratio := float64(count) / float64(total) // 둘 다 float64로 변환 후 나눗셈
fmt.Println(ratio) // 0.35
```

만약 `float64(count) / float64(total)`이 아니라 `count / total`을 그대로 계산하면, 정수 나눗셈이 되어 결과가 `0`이 되어 버린다는 점도 주의해야 한다(정수 나눗셈에 대해서는 4장에서 다시 설명한다).

문자열과 숫자 사이의 변환은 조금 다르게 동작한다. `string(65)`처럼 정수를 `string()`으로 감싸면, 그 숫자가 문자열의 형태로 바뀌는 것이 아니라 해당 숫자를 유니코드 코드 포인트로 해석해 그에 대응하는 문자로 변환한다.

```go
fmt.Println(string(rune(65))) // "A" (유니코드 65번은 'A')
```

정수를 실제로 숫자 형태의 문자열로 바꾸고 싶다면(예를 들어 `65`를 `"65"`로), 표준 라이브러리의 `strconv` 패키지를 사용해야 한다.

```go
import "strconv"

n := 65
s := strconv.Itoa(n) // "65"

m, err := strconv.Atoi("123") // 123, nil
if err != nil {
	fmt.Println("변환 실패:", err)
}
```

`strconv.Atoi`처럼 실패할 가능성이 있는 변환은 값과 함께 에러를 반환한다. 이런 패턴은 Go 전반에 걸쳐 반복해서 나타나는데, 11장(에러 처리)에서 본격적으로 다룬다. `strconv` 패키지를 포함한 유용한 표준 라이브러리들은 17장(표준 라이브러리 둘러보기)에서 더 폭넓게 소개한다.

이처럼 Go가 암묵적 변환을 허용하지 않는 이유는 실수를 방지하기 위해서다. 서로 다른 자료형을 무심코 섞어 쓰다가 의도치 않은 정밀도 손실이나 오버플로우가 발생하는 것을 컴파일 시점에 막아준다. 처음에는 매번 형변환을 명시해야 해서 번거롭게 느껴질 수 있지만, 이는 Go가 "명확함"을 얼마나 중요하게 여기는지 보여주는 대표적인 예다.

## 요약

- 변수는 `var 이름 자료형` 또는 `var 이름 = 값` 형태로 선언한다. 함수 내부에서는 `이름 := 값` 형태의 짧은 선언을 사용할 수 있다.
- `:=`는 함수 내부에서만 쓸 수 있고, 왼쪽 변수 중 최소 하나는 새로 선언되는 변수여야 한다.
- 정수형에는 크기가 다른 여러 종류(`int8`~`int64`, `uint8`~`uint64`)와 플랫폼에 따라 크기가 정해지는 `int`, `uint`가 있다. 특별한 이유가 없다면 `int`를 사용한다.
- `byte`는 `uint8`의 별칭, `rune`은 `int32`의 별칭이며, 각각 바이트 하나와 유니코드 문자 하나를 다룰 때 쓰인다.
- 실수형은 `float32`, `float64`가 있고 보통은 `float64`를 사용한다.
- 문자열(`string`)은 불변 값이며, 불리언(`bool`)은 `true`/`false` 두 값만 가진다.
- Go의 변수는 초기화하지 않아도 자료형에 따른 제로 값(정수 0, 실수 0.0, 불리언 false, 문자열 "", 나머지는 nil)을 자동으로 가진다.
- 상수는 `const`로 선언하며 재대입할 수 없다. `iota`를 이용하면 연속된 값을 가진 상수 그룹을 간결하게 만들 수 있다.
- Go는 서로 다른 자료형 사이의 암묵적 변환을 허용하지 않는다. `자료형(값)` 형태의 명시적 형변환이 항상 필요하다.

## 연습문제

1. `var`를 사용해 `int`, `string`, `bool` 자료형의 변수를 각각 선언하고 초기값을 대입하는 프로그램을 작성하라. 그다음 같은 변수들을 `:=`를 사용해서 다시 작성해 보고 두 방식의 차이를 설명하라.
2. 다음 코드는 왜 컴파일되지 않는지 설명하고, 컴파일되도록 수정하라.
   ```go
   var a int32 = 100
   var b int64 = 200
   fmt.Println(a + b)
   ```
3. 초기값 없이 `var count int`, `var price float64`, `var label string`을 선언하고 각 변수의 값을 출력하는 프로그램을 작성하라. 제로 값이 왜 유용한지 한두 문장으로 설명하라.
4. `iota`를 사용해 요일(`Sunday`부터 `Saturday`까지)을 나타내는 상수 그룹을 정의하고, 그중 하나를 출력하는 프로그램을 작성하라.
5. 사용자로부터 두 정수를 입력받아(또는 코드에 직접 값을 넣어) 그 평균을 실수로 계산해 출력하는 프로그램을 작성하라. 정수 나눗셈으로 인한 오류를 피하기 위해 어떤 형변환이 필요한지 설명하라.
