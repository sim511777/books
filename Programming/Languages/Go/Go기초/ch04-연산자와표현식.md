# 4장. 연산자와 표현식

[◀ 이전: 3장. 변수와 자료형](ch03-변수와자료형.md) | [📖 목차](00-목차.md) | [다음: 5장. 제어문 ▶](ch05-제어문.md)

---

3장에서는 변수에 값을 담는 방법과 Go의 기본 자료형을 살펴보았습니다. 하지만 변수에 값을 넣기만 해서는 아무 일도 일어나지 않습니다. 값을 더하고, 비교하고, 조합해야 비로소 프로그램이 무언가를 계산하기 시작합니다. 이런 계산을 수행하는 기호가 연산자(operator)이고, 연산자와 값을 조합해서 하나의 결과값으로 평가되는 코드 조각이 표현식(expression)입니다.

이번 장에서는 산술, 비교, 논리 연산자를 차례로 살펴보고, 다른 언어에 익숙한 사람이라면 특히 낯설게 느낄 Go의 증감 연산자, 그리고 짧은 변수 선언과 다중 대입을 다룹니다.

## 산술 연산자

Go의 산술 연산자는 대부분의 언어와 크게 다르지 않습니다.

| 연산자 | 의미 | 예시 |
|---|---|---|
| `+` | 덧셈 | `3 + 2` → `5` |
| `-` | 뺄셈 | `3 - 2` → `1` |
| `*` | 곱셈 | `3 * 2` → `6` |
| `/` | 나눗셈 | `3 / 2` → `1` |
| `%` | 나머지 | `3 % 2` → `1` |

```go
package main

import "fmt"

func main() {
	a := 7
	b := 2

	fmt.Println(a + b) // 9
	fmt.Println(a - b) // 5
	fmt.Println(a * b) // 14
	fmt.Println(a / b) // 3
	fmt.Println(a % b) // 1
}
```

### 정수 나눗셈은 정수를 낳는다

산술 연산자 중 가장 자주 실수가 나오는 부분은 나눗셈입니다. Go에서는 피연산자(operand)가 모두 정수형이면 `/` 연산의 결과도 정수형이 되며, 소수점 이하는 그대로 버려집니다.

```go
result := 7 / 2
fmt.Println(result) // 3 (3.5가 아니라 3)
```

이는 3장(변수와 자료형)에서 언급했던 내용이기도 합니다. 소수점까지 포함한 결과를 얻고 싶다면 나눗셈을 하기 전에 피연산자 중 최소 하나를 실수형으로 명시적으로 형변환해야 합니다.

```go
a := 7
b := 2

wrong := a / b                          // 3, 정수 나눗셈
correct := float64(a) / float64(b)      // 3.5, 실수 나눗셈
fmt.Println(wrong, correct)
```

Go는 자료형이 다른 값끼리는 연산 자체를 허용하지 않으므로, `float64(a) / b`처럼 한쪽만 변환하고 다른 쪽을 그대로 두면 컴파일 오류가 발생합니다. 두 피연산자를 모두 실수형으로 맞춰주어야 합니다.

### 나머지 연산자 %

`%`는 나눗셈의 나머지를 구합니다. 정수형에만 사용할 수 있으며, 실수형에는 적용할 수 없습니다. 짝수/홀수 판별이나 "몇 번째마다 한 번씩" 같은 로직을 짤 때 자주 쓰입니다.

```go
for i := 1; i <= 5; i++ {
	if i%2 == 0 {
		fmt.Println(i, "짝수")
	} else {
		fmt.Println(i, "홀수")
	}
}
```

이 예제에 쓰인 `for`문과 `if`문은 5장(제어문)에서 자세히 다루므로, 지금은 `%` 연산자의 쓰임새만 눈에 익혀두어도 충분합니다.

## 비교 연산자

비교 연산자는 두 값을 비교해서 항상 `bool` 자료형의 값(`true` 또는 `false`)을 결과로 내놓습니다.

| 연산자 | 의미 |
|---|---|
| `==` | 같다 |
| `!=` | 다르다 |
| `<` | 작다 |
| `>` | 크다 |
| `<=` | 작거나 같다 |
| `>=` | 크거나 같다 |

```go
a := 10
b := 20

fmt.Println(a == b) // false
fmt.Println(a != b) // true
fmt.Println(a < b)  // true
fmt.Println(a >= b) // false
```

비교 연산자를 쓸 때 주의할 점은, Go에서는 서로 다른 자료형끼리 비교하는 것이 허용되지 않는다는 것입니다. 3장에서 살펴본 형변환 규칙이 비교 연산자에도 그대로 적용됩니다.

```go
var x int = 10
var y int64 = 10

// fmt.Println(x == y) // 컴파일 에러: int와 int64는 다른 자료형
fmt.Println(x == int(y)) // true, 명시적으로 변환한 뒤 비교
```

또한 C 계열 언어와 달리 Go는 정수를 `bool`처럼 취급하지 않으므로, 비교 연산자의 결과는 오직 조건문의 조건식이나 `bool` 변수에만 사용할 수 있습니다. 이 내용은 5장(제어문)에서 `if`문을 다룰 때 다시 확인합니다.

## 논리 연산자

논리 연산자는 `bool` 값끼리 조합해서 새로운 `bool` 값을 만듭니다.

| 연산자 | 의미 |
|---|---|
| `&&` | 그리고(AND) — 둘 다 참일 때만 참 |
| `\|\|` | 또는(OR) — 하나라도 참이면 참 |
| `!` | 부정(NOT) — 참/거짓을 뒤집음 |

```go
age := 20
hasTicket := true

canEnter := age >= 18 && hasTicket
fmt.Println(canEnter) // true

isChild := age < 13
isAdult := age >= 18
fmt.Println(isChild || isAdult) // true

fmt.Println(!hasTicket) // false
```

### 단락 평가(short-circuit evaluation)

`&&`와 `||`는 왼쪽 피연산자만으로 전체 결과가 확정되면 오른쪽 피연산자를 아예 평가하지 않습니다. 이를 단락 평가라고 부릅니다.

- `A && B`에서 `A`가 이미 `false`라면, 전체 결과는 어차피 `false`이므로 `B`는 평가되지 않습니다.
- `A || B`에서 `A`가 이미 `true`라면, 전체 결과는 어차피 `true`이므로 `B`는 평가되지 않습니다.

```go
func isPositive(n int) bool {
	fmt.Println("isPositive 호출됨")
	return n > 0
}

func main() {
	n := 0

	if n != 0 && isPositive(n) {
		fmt.Println("양수입니다.")
	}
	// n이 0이므로 n != 0이 false이고, isPositive(n)은 아예 호출되지 않는다
}
```

단락 평가는 단순히 성능을 아끼는 효과만 있는 것이 아니라, 실수로 잘못된 접근을 막아주는 안전장치로도 자주 활용됩니다. 예를 들어 포인터(9장에서 다룹니다)가 `nil`인지 먼저 확인하고, 그 값이 `nil`이 아닐 때만 안전하게 필드에 접근하는 다음과 같은 패턴이 대표적입니다.

```go
// p가 nil이면 && 뒤쪽은 평가되지 않으므로 안전하다
if p != nil && p.Age >= 18 {
	fmt.Println("성인입니다.")
}
```

## 증감 연산자: ++와 --는 표현식이 아니라 문이다

C, Java, JavaScript 등 여러 언어를 다뤄본 사람이라면 `++`와 `--`를 다음과 같이 값을 반환하는 표현식처럼 사용하는 데 익숙할 것입니다.

```c
// C에서는 가능한 코드
int a = 5;
int b = a++;       // b에 5가 대입되고, a는 6이 됨
printf("%d\n", ++a); // 전위 증가의 결과값(7)을 그대로 출력
```

Go에서는 이런 사용이 전혀 불가능합니다. Go의 `++`와 `--`는 값을 만들어내는 표현식이 아니라, 그 자체로 하나의 완결된 문(statement)입니다. 이 차이는 사소해 보이지만 실제로 코드를 작성하다 보면 자주 부딪히게 되는 Go의 특이한 규칙이므로 정확히 짚고 넘어갈 필요가 있습니다.

```go
a := 5
a++ // a는 이제 6이다. 이 자체가 하나의 문이며 값을 반환하지 않는다
a-- // a는 다시 5가 된다
```

Go에서 `++`와 `--`가 문이라는 것은 다음과 같은 제약으로 나타납니다.

**1. 전위(prefix) 형태가 없다.** `++a`처럼 변수 앞에 붙이는 문법 자체가 Go에는 존재하지 않습니다. 오직 `a++`처럼 뒤에 붙이는 형태만 허용됩니다.

```go
a := 5
// ++a // 컴파일 에러: Go에는 전위 증감 연산자가 없다
a++     // 이것만 가능
```

**2. 다른 표현식 안에 끼워 넣을 수 없다.** `b := a++`처럼 증감 연산의 결과를 다른 변수에 대입하거나, `fmt.Println(a++)`처럼 함수의 인자로 바로 넘기는 것이 불가능합니다.

```go
a := 5
// b := a++          // 컴파일 에러: a++는 값이 아니라 문이다
// fmt.Println(a++)  // 컴파일 에러: 같은 이유

a++
b := a // 반드시 이렇게 문을 따로 실행한 뒤 값을 읽어야 한다
fmt.Println(a, b)
```

**3. `for`문의 조건식 자리에는 못 쓰지만, 증감식 자리에는 쓸 수 있다.** 이 부분이 특히 헷갈리기 쉬운데, `for`문의 세 번째 자리(증감식)는 애초에 표현식이 아니라 문을 기대하는 자리이므로 `i++`를 그대로 사용할 수 있습니다.

```go
for i := 0; i < 5; i++ { // 증감식 자리에는 문제없이 쓸 수 있다
	fmt.Println(i)
}
```

`for`문의 각 부분에 대해서는 5장(제어문)에서 본격적으로 다룹니다.

Go 설계자들이 `++`와 `--`를 표현식이 아닌 문으로 만든 이유는 1장에서 살펴본 "명시성"이라는 철학과 맞닿아 있습니다. `a++ + ++a`처럼 한 줄에서 증감 연산을 여러 번 뒤섞어 쓰면, 평가 순서에 따라 결과가 달라져 코드를 읽는 사람이 실행 순서를 정확히 추적하기 어려워집니다. Go는 이런 모호함의 여지를 아예 문법 차원에서 차단하고, "값을 하나 증가시키는 동작"과 "그 값을 다른 곳에 사용하는 동작"을 항상 별개의 문으로 분리하도록 강제합니다.

## 대입 연산자와 복합 대입

기본적인 대입은 `=`로 하지만, "현재 값에 무언가를 연산한 뒤 다시 대입하는" 패턴이 매우 흔하기 때문에 Go는 산술/비트 연산자와 대입을 합친 복합 대입 연산자도 제공합니다.

| 연산자 | 같은 의미의 풀어쓴 표현 |
|---|---|
| `a += b` | `a = a + b` |
| `a -= b` | `a = a - b` |
| `a *= b` | `a = a * b` |
| `a /= b` | `a = a / b` |
| `a %= b` | `a = a % b` |

```go
total := 0
total += 10 // total = total + 10, 즉 10
total += 5  // 15
total -= 3  // 12
fmt.Println(total) // 12
```

증감 연산자와 마찬가지로, `total += 10` 역시 표현식이 아니라 문이므로 `x := (total += 10)`처럼 다른 곳에 값을 끼워 넣는 용도로는 쓸 수 없습니다.

## 짧은 변수 선언과 다중 대입

3장에서 `:=`를 이용한 짧은 변수 선언을 이미 소개했습니다. 여기서는 표현식과 관련해서 조금 더 짚어볼 부분을 살펴보겠습니다.

### 여러 값을 한 번에 대입하기

Go는 등호(`=`) 하나로 여러 변수에 값을 동시에 대입하는 다중 대입을 지원합니다.

```go
x, y := 1, 2
fmt.Println(x, y) // 1 2

x, y = y, x // 오른쪽이 먼저 모두 평가된 뒤 왼쪽에 대입되므로 값이 서로 바뀐다
fmt.Println(x, y) // 2 1
```

`x, y = y, x`처럼 임시 변수 없이 두 변수의 값을 맞바꿀 수 있는 것은, Go가 대입문의 오른쪽에 있는 모든 표현식을 먼저 전부 평가한 다음에야 왼쪽 변수들에 순서대로 대입하기 때문입니다. 이 성질 덕분에 다른 언어라면 `temp := x; x = y; y = temp`처럼 임시 변수를 하나 만들어야 하는 상황을, Go에서는 한 줄로 간결하게 처리할 수 있습니다.

### 함수의 다중 반환값과 함께 쓰이는 다중 대입

다중 대입은 함수가 값을 여러 개 반환할 때 특히 자주 쓰입니다. Go 함수는 하나의 값만 반환하는 다른 언어와 달리 여러 값을 동시에 반환할 수 있는데, 이때 호출하는 쪽에서도 다중 대입으로 결괏값들을 각각 받습니다.

```go
import "strconv"

n, err := strconv.Atoi("42")
fmt.Println(n, err) // 42 <nil>
```

이 패턴은 11장(에러 처리)에서 본격적으로 다룰 `if err != nil` 관용구의 기반이 되며, 함수를 직접 정의하는 방법은 6장(함수)에서 자세히 다룹니다. 지금은 "표현식 하나가 아니라 값 여러 개를 한꺼번에 왼쪽 변수들에 대입할 수 있다"는 정도만 기억해두면 충분합니다.

## 연산자 우선순위

여러 연산자가 한 표현식에 섞여 있을 때 어떤 연산이 먼저 계산되는지는 연산자 우선순위(operator precedence)로 정해집니다. Go도 대부분의 언어와 마찬가지로 곱셈과 나눗셈이 덧셈과 뺄셈보다 먼저 계산되고, 비교 연산자는 산술 연산자보다 나중에, 논리 연산자는 비교 연산자보다도 나중에 계산되는 일반적인 순서를 따릅니다.

```go
result := 2 + 3*4   // 곱셈이 먼저 계산되어 2 + 12 = 14
check := 1+2 == 3 && 4 > 2 // 산술 -> 비교 -> 논리 순서로 계산되어 true
```

우선순위를 전부 외우려 하기보다는, 의도를 명확히 드러내고 싶을 때 괄호 `()`를 적극적으로 사용하는 편이 훨씬 안전하고 읽기 좋은 코드를 만듭니다.

```go
result := 2 + (3 * 4) // 위와 결과는 같지만 의도가 더 분명하게 드러난다
```

Go 연산자의 전체 우선순위 표(가장 높은 단계부터 낮은 단계까지 이항 연산자를 묶어놓은 표)는 이 책의 부록에 정리해 두었으니, 복잡한 표현식을 만나 헷갈릴 때마다 참고하기 바랍니다.

## 요약

- Go의 산술 연산자(`+`, `-`, `*`, `/`, `%`)는 대체로 다른 언어와 비슷하지만, 정수끼리 `/` 연산을 하면 결과도 정수가 되어 소수점 이하가 버려진다는 점을 주의해야 합니다.
- 비교 연산자(`==`, `!=`, `<`, `>`, `<=`, `>=`)는 항상 `bool` 값을 만들며, 서로 다른 자료형끼리는 비교할 수 없습니다.
- 논리 연산자(`&&`, `\|\|`, `!`)는 `bool` 값을 조합하며, `&&`와 `\|\|`는 왼쪽만으로 결과가 확정되면 오른쪽을 평가하지 않는 단락 평가를 수행합니다.
- Go의 `++`, `--`는 값을 만들어내는 표현식이 아니라 그 자체로 완결된 문입니다. 전위 형태가 없고, 다른 표현식 안에 끼워 넣을 수 없습니다.
- `+=`, `-=` 같은 복합 대입 연산자로 "연산 후 재대입"을 간결하게 표현할 수 있습니다.
- Go는 `x, y = y, x`처럼 다중 대입을 지원하며, 오른쪽 표현식을 모두 먼저 평가한 뒤 왼쪽에 대입합니다. 이 방식은 함수의 다중 반환값을 받을 때도 사용됩니다.
- 연산자 우선순위가 헷갈릴 때는 외우기보다 괄호로 의도를 명확히 드러내는 편이 안전합니다. 전체 우선순위 표는 부록에 있습니다.
