## 들어가며

새로운 프로그래밍 언어를 배우기 전에 "이 언어는 왜 존재하고, 어디에 쓰이며, 다른 언어와 무엇이 다른가"를 먼저 이해하면 학습 방향을 잡기가 훨씬 수월해집니다. C 언어는 1972년 벨 연구소의 데니스 리치(Dennis Ritchie)가 개발한 이래, 반세기가 넘는 시간 동안 컴퓨터 과학과 소프트웨어 산업의 근간을 이루어 온 언어입니다. 여러분이 지금 사용하고 있는 운영체제, 스마트폰의 펌웨어, 심지어 다른 프로그래밍 언어의 실행 엔진 상당수가 C 언어로 작성되어 있습니다. 이번 장에서는 C 언어의 정체성과 특징, 활용 분야, 그리고 이 책을 읽어 나가기 위해 준비해야 할 개발 환경에 대해 살펴봅니다.

## C 언어의 정체성

### 절차지향 언어

C는 절차지향(procedural) 프로그래밍 언어입니다. 프로그램을 "데이터를 어떻게 처리할 것인가"에 대한 일련의 절차, 즉 함수(function)들의 모음으로 구성합니다. 객체지향 언어처럼 클래스나 객체라는 개념이 언어 차원에 존재하지 않으며, 프로그램의 실행 흐름은 `main` 함수에서 시작해 다른 함수를 호출하고 되돌아오는 방식으로 진행됩니다. 이런 단순한 실행 모델 덕분에 프로그램이 "지금 무슨 일을 하고 있는지"를 코드만 보고도 비교적 직관적으로 추적할 수 있습니다.

이러한 절차지향적 접근은 8장 함수에서 본격적으로 다루게 됩니다. 함수를 어떻게 정의하고 호출하며, 값을 주고받는지가 C 프로그램을 구성하는 핵심 뼈대가 됩니다.

### 저수준 접근이 가능한 고수준 언어

C는 흔히 "저수준 접근이 가능한 고수준 언어"라고 설명됩니다. 이 말은 다소 모순적으로 들릴 수 있지만, C의 성격을 가장 잘 요약하는 표현입니다.

- **고수준 언어**로서 C는 사람이 읽고 쓰기 편한 문법(조건문, 반복문, 함수, 배열 등)을 제공합니다. 기계어나 어셈블리어처럼 CPU 레지스터를 직접 다루지 않아도 됩니다.
- **저수준 접근**이 가능하다는 것은, C가 메모리 주소를 직접 다루는 포인터(pointer)라는 도구를 제공하고, 운영체제나 하드웨어에 가까운 작업(메모리 할당, 비트 연산, 파일 시스템 접근 등)을 별도의 특별한 권한 없이 수행할 수 있다는 뜻입니다.

예를 들어 Python이나 Java 같은 언어는 메모리 관리를 언어 런타임(가비지 컬렉터)이 자동으로 처리해 주지만, C는 프로그래머가 메모리를 직접 요청하고 반납하는 책임을 집니다. 이는 초보자에게는 번거로운 일처럼 보일 수 있지만, 메모리가 어떻게 동작하는지 근본적으로 이해하게 해 주는 훈련 과정이기도 합니다. 이 내용은 14장 동적 메모리 할당에서 자세히 다룹니다.

### 이식성

C 언어로 작성된 코드는 특정 컴파일러를 통해 각 운영체제와 하드웨어에 맞는 기계어로 변환됩니다. 같은 C 소스 코드가 표준을 잘 지켜 작성되었다면, 윈도우에서도, 리눅스에서도, 심지어 마이크로컨트롤러에서도 (약간의 수정만으로, 혹은 전혀 수정 없이) 컴파일되어 동작할 수 있습니다. 이런 이식성(portability) 덕분에 C는 다양한 플랫폼을 지원해야 하는 시스템 소프트웨어의 표준 언어로 자리 잡았습니다.

### 성능

C는 컴파일된 언어로, 소스 코드가 실행 전에 기계어로 완전히 변환됩니다. 인터프리터 언어(Python 등)처럼 실행 시점에 한 줄씩 해석하는 과정이 없고, 언어 차원의 오버헤드(가비지 컬렉션, 동적 타입 검사 등)가 거의 없기 때문에 실행 속도가 매우 빠릅니다. 이런 성능적 이점 때문에 실시간성이 중요하거나 자원이 제한된 환경에서는 지금도 C가 선호됩니다.

## C 언어는 어디에 쓰이는가

C 언어의 활용 분야를 살펴보면 왜 이 언어를 배워야 하는지가 더 명확해집니다.

- **운영체제**: 리눅스 커널, 윈도우 커널의 상당 부분, macOS의 기반이 되는 XNU 커널 등이 C로 작성되어 있습니다. 운영체제는 하드웨어를 직접 제어해야 하므로 C의 저수준 접근 능력이 필수적입니다.
- **임베디드 시스템**: 세탁기, 자동차 ECU, 드론, IoT 센서처럼 자원이 극도로 제한된 소형 컴퓨터(마이크로컨트롤러)에서 동작하는 소프트웨어 대부분이 C로 작성됩니다.
- **시스템 프로그래밍**: 데이터베이스 엔진(SQLite, 초기 MySQL 등), 네트워크 스택, 파일 시스템, 디바이스 드라이버 등 시스템의 근간이 되는 소프트웨어들이 C로 개발되었습니다.
- **다른 언어의 구현체**: Python, Ruby, PHP 등 여러 인터프리터 언어의 공식 구현체가 C로 작성되어 있습니다. 즉, 여러분이 Python 코드를 실행할 때, 그 내부에서는 C로 작성된 인터프리터가 동작하고 있는 것입니다.
- **게임 엔진과 그래픽스**: 성능이 중요한 게임 엔진의 핵심부, 그래픽 드라이버 등도 C 또는 C의 확장 언어인 C++로 작성됩니다.

C를 배운다는 것은 단순히 하나의 프로그래밍 언어를 익히는 것을 넘어, 컴퓨터가 메모리와 명령을 어떻게 다루는지에 대한 근본 원리를 이해하는 과정이라고 할 수 있습니다.

## 다른 언어와 비교했을 때 C의 위치

Python이나 Java 같은 언어를 먼저 접한 독자라면 C가 낯설게 느껴질 수 있습니다. 몇 가지 핵심적인 차이를 비교해 보겠습니다.

| 특성 | C | Python | Java |
|---|---|---|---|
| 실행 방식 | 컴파일 (기계어로 변환) | 인터프리터 (한 줄씩 해석) | 컴파일 후 가상머신에서 실행 |
| 메모리 관리 | 프로그래머가 직접 관리 | 가비지 컬렉터가 자동 관리 | 가비지 컬렉터가 자동 관리 |
| 타입 시스템 | 정적 타입, 컴파일 시점에 자료형 고정 | 동적 타입 | 정적 타입 |
| 실행 속도 | 매우 빠름 | 상대적으로 느림 | 빠르지만 C보다는 오버헤드 존재 |
| 저수준 접근 | 포인터로 메모리 직접 제어 가능 | 불가능(언어 차원에서 차단) | 제한적 |
| 대표 용도 | OS, 임베디드, 시스템 프로그래밍 | 데이터 분석, 스크립팅, 자동화 | 엔터프라이즈 애플리케이션, 안드로이드 |

Python에 익숙한 독자는 C를 배우면서 "왜 이렇게 사소한 것까지 신경 써야 하나"라는 답답함을 느낄 수 있습니다. 예를 들어 Python에서는 리스트에 아무 값이나 담을 수 있지만, C의 배열(array)은 하나의 자료형만 담을 수 있고 크기도 미리 정해야 합니다. 이런 제약은 3장 변수와 자료형, 9장 배열에서 자세히 설명하겠지만, 결국 이 제약들이 프로그램의 동작 방식을 예측 가능하게 만들고 실행 속도를 높이는 원천이 된다는 점을 기억해 두시기 바랍니다.

반대로 다른 언어 경험이 전혀 없는 입문자라면, C를 통해 "변수는 결국 메모리의 한 칸이다", "함수 호출은 실행 흐름의 이동이다"와 같은 프로그래밍의 본질적인 개념을 몸으로 익히게 될 것입니다. 이는 이후에 어떤 언어를 배우더라도 든든한 기초가 되어 줍니다.

## 개발 환경 준비하기

C 프로그램을 작성하고 실행하려면 두 가지가 필요합니다. 코드를 작성할 **편집기(또는 IDE)**와, 작성한 코드를 실행 파일로 변환해 줄 **컴파일러**입니다.

### 컴파일러

컴파일러는 사람이 작성한 C 소스 코드를 컴퓨터가 실행할 수 있는 기계어로 변환하는 프로그램입니다. 대표적인 C 컴파일러는 다음과 같습니다.

- **GCC (GNU Compiler Collection)**: 리눅스 환경에서 사실상 표준으로 쓰이는 오픈소스 컴파일러입니다. 윈도우에서는 MinGW나 WSL(Windows Subsystem for Linux)을 통해 설치할 수 있습니다.
- **Clang**: LLVM 프로젝트 기반의 컴파일러로, macOS의 기본 컴파일러(Xcode Command Line Tools를 통해 제공)이며 오류 메시지가 읽기 쉽다는 평가를 받습니다.
- **MSVC (Microsoft Visual C++)**: 윈도우 환경에서 Visual Studio에 포함되어 제공되는 마이크로소프트의 컴파일러입니다.

이 책에서는 여러 운영체제에서 널리 쓰이는 GCC를 기준으로 명령어 예시를 설명하지만, Clang이나 MSVC를 사용해도 대부분의 예제는 동일하게 동작합니다. 컴파일러가 실제로 소스 코드를 어떻게 실행 파일로 바꾸는지는 2장 첫 프로그램과 빌드 과정에서 단계별로 자세히 다룹니다.

### 편집기와 IDE

코드를 작성할 도구로는 크게 두 가지 선택지가 있습니다.

1. **텍스트 편집기 + 명령줄 컴파일**: Visual Studio Code, Sublime Text, Vim, Notepad++ 같은 가벼운 편집기로 코드를 작성하고, 터미널(명령 프롬프트)에서 컴파일러를 직접 호출하는 방식입니다. 빌드 과정이 눈에 보이기 때문에 C가 실제로 어떻게 동작하는지 배우기에 좋습니다. 이 책의 예제들은 기본적으로 이 방식을 전제로 설명합니다.
2. **통합 개발 환경(IDE)**: Visual Studio, CLion, Code::Blocks, Dev-C++ 등은 편집기, 컴파일러, 디버거가 하나로 묶여 있어 버튼 클릭만으로 컴파일과 실행이 가능합니다. 초보자가 진입 장벽 없이 시작하기에 편리하지만, 빌드 과정이 가려져 있어 내부 동작을 이해하기에는 다소 불리할 수 있습니다.

어느 쪽을 선택하든 상관없습니다. 다만 이 책을 처음 학습하는 단계에서는 명령줄에서 직접 컴파일 명령을 입력해 보는 것을 권장합니다. 오류 메시지를 직접 읽고 해석하는 경험이 실력 향상에 큰 도움이 되기 때문입니다.

### 어떤 환경을 선택하든 확인해야 할 것

운영체제와 무관하게, 다음 사항만 확인되면 이 책의 모든 예제를 따라 할 수 있습니다.

- 터미널(또는 명령 프롬프트, PowerShell)에서 `gcc --version` 혹은 `clang --version` 명령을 입력했을 때 버전 정보가 출력되는가
- 텍스트 파일을 작성하고 `.c` 확장자로 저장할 수 있는 편집기가 있는가

두 조건이 충족된다면 준비는 끝났습니다. 구체적인 설치 방법은 운영체제마다 다르고 시간이 지나면서 바뀔 수 있으므로, 이 책에서는 특정 설치 명령을 강요하지 않습니다. 대신 각자의 운영체제에 맞는 최신 설치 가이드를 참고해 컴파일러를 준비하신 후, 2장부터 함께 실습해 나가시기 바랍니다.

## 이 책의 학습 방향

이 책은 다음과 같은 원칙으로 구성되어 있습니다.

- **직접 실행하며 배우기**: 모든 개념은 실행 가능한 예제 코드와 함께 설명됩니다. 눈으로만 읽지 말고 반드시 직접 타이핑하고 컴파일해서 실행 결과를 확인하시기 바랍니다. 오타 때문에 발생하는 컴파일 오류조차도 훌륭한 학습 자료가 됩니다.
- **아래에서 위로 쌓아 올리기**: 3장부터 8장까지는 변수, 연산자, 입출력, 제어문, 함수 같은 프로그래밍의 기본 뼈대를 다룹니다. 9장부터는 배열과 문자열, 11~12장에서는 C 언어의 핵심이자 난관으로 꼽히는 포인터를 단계적으로 다룹니다. 이후 구조체, 동적 메모리 할당, 파일 입출력, 전처리기로 이어지며 실전 프로그램을 작성하는 데 필요한 도구를 갖추게 됩니다.
- **개념과 실용성의 균형**: C가 왜 그렇게 설계되었는지에 대한 배경 설명과, 실제로 어떻게 코드를 작성해야 하는지에 대한 실용적인 조언을 함께 제공합니다. 마지막 18장 좋은 C 코드 작성 습관에서는 문법을 넘어 실무에서 통용되는 코딩 관례까지 다룹니다.
- **막히면 다시 돌아가기**: 포인터나 동적 메모리 할당처럼 처음에는 이해하기 어려운 개념이 나올 수 있습니다. 이는 자연스러운 과정입니다. 앞 장의 예제를 다시 실행해 보거나 잠시 다음 장으로 넘어갔다가 돌아오는 것도 좋은 학습 전략입니다.

이제 준비가 되었다면, 2장 첫 프로그램과 빌드 과정에서 실제로 첫 C 프로그램을 작성하고 실행해 보겠습니다.

## 요약

- C는 1972년 개발된 절차지향 프로그래밍 언어로, "저수준 접근이 가능한 고수준 언어"로 요약된다.
- 메모리를 프로그래머가 직접 관리한다는 특징이 있으며, 이는 번거로움이자 동시에 컴퓨터 동작 원리를 깊이 이해하게 해 주는 요소이다.
- 이식성이 뛰어나고 실행 속도가 빨라 운영체제, 임베디드 시스템, 시스템 프로그래밍, 다른 언어의 구현체 등 폭넓은 분야에서 사용된다.
- Python, Java 등과 비교했을 때 C는 정적 타입, 수동 메모리 관리, 컴파일 실행 방식이라는 점에서 차별화된다.
- C 프로그램을 작성하려면 편집기(또는 IDE)와 컴파일러(GCC, Clang, MSVC 등)가 필요하다.
- 이 책은 실행 중심, 단계적 축적, 개념과 실용성의 균형을 원칙으로 삼아 구성되었다.

## 연습문제

1. C 언어가 "저수준 접근이 가능한 고수준 언어"라고 불리는 이유를 자신의 언어로 두세 문장으로 설명해 보세요.
2. 여러분이 평소 관심 있는 소프트웨어나 기기(스마트폰 앱, 웹 서비스, 가전제품, 자동차 등) 중에서 C 언어가 실제로 사용되고 있을 가능성이 높은 사례를 세 가지 찾아보고, 왜 그렇게 생각하는지 이유를 적어보세요.
3. 자신의 컴퓨터에 설치할 C 컴파일러를 하나 선택하고(GCC, Clang, MSVC 중), 터미널에서 버전 확인 명령(`gcc --version`, `clang --version`, `cl` 등)을 실행해 정상적으로 출력되는지 확인해 보세요. 설치되어 있지 않다면 설치 과정을 기록해 보세요.
4. C와 Python(또는 자신이 알고 있는 다른 언어) 중 메모리 관리 방식의 차이를 표로 정리해 보고, 각 방식의 장단점을 하나씩 적어보세요.
5. "C 언어는 왜 지금도 운영체제나 임베디드 시스템에서 널리 사용될까?"라는 질문에 대해, 이번 장에서 배운 C의 특징(이식성, 성능, 저수준 접근) 중 최소 두 가지를 근거로 삼아 답변을 작성해 보세요.
