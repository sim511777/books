## 부록 A. 연산자 우선순위와 결합법칙

4장 연산자와 표현식에서 다룬 연산자들을 포함해, C 언어의 모든 연산자를 우선순위가 높은 것부터 낮은 순서로 정리했습니다. 같은 줄(같은 우선순위)에 있는 연산자들은 결합법칙(associativity)에 따라 계산 순서가 정해집니다. 우선순위가 헷갈리는 표현식을 작성할 때는 이 표에 의존하기보다 괄호 `()`를 명시적으로 사용해 의도를 분명히 드러내는 것이 실수를 줄이는 가장 좋은 방법이라는 점을 항상 기억하시기 바랍니다.

| 우선순위 | 연산자 | 설명 | 결합법칙 |
|---|---|---|---|
| 1 (가장 높음) | `()` | 함수 호출 |  왼쪽에서 오른쪽 |
| | `[]` | 배열 인덱싱 | 왼쪽에서 오른쪽 |
| | `.` | 구조체/공용체 멤버 접근 | 왼쪽에서 오른쪽 |
| | `->` | 포인터를 통한 멤버 접근 | 왼쪽에서 오른쪽 |
| | `++`, `--` | 후위 증가/감소 | 왼쪽에서 오른쪽 |
| 2 | `++`, `--` | 전위 증가/감소 | 오른쪽에서 왼쪽 |
| | `+`, `-` | 단항 양/음부호 | 오른쪽에서 왼쪽 |
| | `!` | 논리 부정 | 오른쪽에서 왼쪽 |
| | `~` | 비트 반전 | 오른쪽에서 왼쪽 |
| | `(type)` | 형 변환(cast) | 오른쪽에서 왼쪽 |
| | `*` | 역참조(포인터가 가리키는 값) | 오른쪽에서 왼쪽 |
| | `&` | 주소 연산자 | 오른쪽에서 왼쪽 |
| | `sizeof` | 자료형/변수의 크기 | 오른쪽에서 왼쪽 |
| 3 | `*`, `/`, `%` | 곱셈, 나눗셈, 나머지 | 왼쪽에서 오른쪽 |
| 4 | `+`, `-` | 덧셈, 뺄셈(이항) | 왼쪽에서 오른쪽 |
| 5 | `<<`, `>>` | 비트 시프트(왼쪽/오른쪽) | 왼쪽에서 오른쪽 |
| 6 | `<`, `<=`, `>`, `>=` | 크기 비교 | 왼쪽에서 오른쪽 |
| 7 | `==`, `!=` | 동등/부등 비교 | 왼쪽에서 오른쪽 |
| 8 | `&` | 비트 AND | 왼쪽에서 오른쪽 |
| 9 | `^` | 비트 XOR | 왼쪽에서 오른쪽 |
| 10 | `\|` | 비트 OR | 왼쪽에서 오른쪽 |
| 11 | `&&` | 논리 AND | 왼쪽에서 오른쪽 |
| 12 | `\|\|` | 논리 OR | 왼쪽에서 오른쪽 |
| 13 | `?:` | 삼항 조건 연산자 | 오른쪽에서 왼쪽 |
| 14 | `=`, `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `^=`, `\|=`, `<<=`, `>>=` | 대입 연산자 | 오른쪽에서 왼쪽 |
| 15 (가장 낮음) | `,` | 콤마 연산자 | 왼쪽에서 오른쪽 |

### 표를 읽는 방법

- 숫자가 작을수록(표의 위쪽일수록) 우선순위가 높습니다. 즉, 하나의 표현식 안에 여러 연산자가 섞여 있으면 우선순위가 높은 연산자부터 먼저 계산됩니다.
- 결합법칙은 우선순위가 같은 연산자가 연달아 나올 때 어느 쪽부터 묶어서 계산할지를 정합니다. 예를 들어 대입 연산자(`=`)는 오른쪽에서 왼쪽으로 결합하기 때문에 `a = b = 5;`는 `a = (b = 5);`로 해석되어 `b`와 `a`가 모두 5가 됩니다.
- 단항 연산자(`*`, `&`, `-`, `!` 등)는 이항 연산자와 기호가 같은 경우가 많아 헷갈리기 쉽습니다. 예를 들어 `*`는 곱셈(이항, 우선순위 3)으로 쓰일 수도 있고 포인터 역참조(단항, 우선순위 2)로 쓰일 수도 있으므로, 문맥(피연산자가 하나인지 둘인지)으로 구분해야 합니다.
- 대표적인 헷갈리는 예시: `int result = a + b > 10 ? 1 : 0;`은 `+`가 `>`보다 우선순위가 높고, `>`가 `?:`보다 우선순위가 높으므로 `((a + b) > 10) ? 1 : 0`으로 해석됩니다.

## 부록 B. ASCII 코드표

3장 변수와 자료형에서 `char`형이 결국 정수 코드로 문자를 표현한다고 설명했습니다. ASCII(American Standard Code for Information Interchange)는 0부터 127까지의 정수에 문자를 대응시킨 표준 코드 체계입니다. 자주 쓰이는 범위를 중심으로 정리했습니다.

### 제어 문자 (0~31, 127): 화면에 보이지 않는 특수 목적 문자

| 10진수 | 문자 | 의미 |
|---|---|---|
| 0 | `NUL` | 널 문자 (문자열의 끝을 표시, `'\0'`) |
| 7 | `BEL` | 경고음 (`'\a'`) |
| 8 | `BS` | 백스페이스 (`'\b'`) |
| 9 | `TAB` | 수평 탭 (`'\t'`) |
| 10 | `LF` | 줄바꿈(개행), 유닉스/리눅스 계열 (`'\n'`) |
| 13 | `CR` | 캐리지 리턴, 윈도우 줄바꿈의 일부 (`'\r'`) |
| 27 | `ESC` | 이스케이프 |
| 127 | `DEL` | 삭제 |

### 출력 가능 문자 (32~126): 화면에 보이는 문자

| 10진수 범위 | 내용 | 예시 |
|---|---|---|
| 32 | 공백(space) | `' '` |
| 33~47 | 특수 기호 | `!`, `"`, `#`, `$`, `%`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `-`, `.`, `/` |
| 48~57 | 숫자 | `0`(48) ~ `9`(57) |
| 58~64 | 특수 기호 | `:`, `;`, `<`, `=`, `>`, `?`, `@` |
| 65~90 | 대문자 알파벳 | `A`(65) ~ `Z`(90) |
| 91~96 | 특수 기호 | `[`, `\`, `]`, `^`, `_`, `` ` `` |
| 97~122 | 소문자 알파벳 | `a`(97) ~ `z`(122) |
| 123~126 | 특수 기호 | `{`, `\|`, `}`, `~` |

### 알아두면 유용한 규칙

- **숫자 문자와 실제 숫자값의 관계**: 문자 `'0'`의 ASCII 코드는 48입니다. 그래서 숫자로 이루어진 문자(`'0'`~`'9'`)에서 48을 빼면 해당 숫자값을 얻을 수 있습니다. 예를 들어 `'7' - '0'`은 정수 7이 됩니다. 이 원리는 문자열을 숫자로 직접 변환하는 코드를 짤 때 자주 활용됩니다.
- **대문자와 소문자의 관계**: 대문자 `'A'`(65)와 소문자 `'a'`(97)는 정확히 32만큼 차이가 납니다. 대문자에 32를 더하면 소문자가 되고, 소문자에서 32를 빼면 대문자가 됩니다. 물론 실전 코드에서는 이 값을 직접 계산하기보다 17장 표준 라이브러리 둘러보기에서 소개한 `ctype.h`의 `toupper`, `tolower` 함수를 사용하는 것이 안전하고 명확합니다.
- **128 이상의 문자**: ASCII는 0~127까지만 정의합니다. 한글이나 이모지처럼 ASCII 범위를 벗어나는 문자는 UTF-8 같은 별도의 인코딩 방식을 통해 여러 바이트를 조합해 표현합니다. 이 책의 예제에서 한글 문자열을 다룰 때는 이런 멀티바이트 인코딩이 적용되고 있다는 점을 참고로 알아 두면 좋습니다.

## 부록 C. 자료형별 크기와 범위

3장 변수와 자료형에서 설명했듯, C 표준은 각 자료형의 "최소 보장 크기"만 규정할 뿐, 정확한 바이트 크기는 컴파일러와 플랫폼(32비트/64비트, 운영체제, CPU 아키텍처)에 따라 달라질 수 있습니다. 아래 표는 오늘날 가장 흔한 환경인 64비트 시스템에서 GCC나 Clang을 사용할 때 일반적으로 볼 수 있는 값입니다. 정확한 값은 실제 사용하는 환경에서 `sizeof` 연산자로 직접 확인하거나, `limits.h`/`float.h`에 정의된 매크로 상수(`INT_MAX`, `INT_MIN`, `DBL_MAX` 등)를 출력해 확인하는 것이 가장 정확합니다.

### 정수 자료형

| 자료형 | 일반적인 크기 | 표현 범위(부호 있음 기준) |
|---|---|---|
| `char` | 1바이트 | 컴파일러에 따라 `-128`~`127` 또는 `0`~`255` |
| `signed char` | 1바이트 | `-128` ~ `127` |
| `unsigned char` | 1바이트 | `0` ~ `255` |
| `short` (`short int`) | 2바이트 | `-32,768` ~ `32,767` |
| `unsigned short` | 2바이트 | `0` ~ `65,535` |
| `int` | 4바이트 | `-2,147,483,648` ~ `2,147,483,647` |
| `unsigned int` | 4바이트 | `0` ~ `4,294,967,295` |
| `long` | 4바이트(윈도우) 또는 8바이트(리눅스/macOS) | 플랫폼에 따라 다름 |
| `unsigned long` | 4바이트 또는 8바이트 | 플랫폼에 따라 다름 |
| `long long` | 8바이트 | `-9,223,372,036,854,775,808` ~ `9,223,372,036,854,775,807` |
| `unsigned long long` | 8바이트 | `0` ~ `18,446,744,073,709,551,615` |

`long`형의 크기가 운영체제에 따라 달라진다는 점은 특히 주의가 필요합니다. 정확히 몇 바이트인지가 중요한 코드를 작성해야 한다면, `long` 대신 `stdint.h` 헤더가 제공하는 `int32_t`, `int64_t`처럼 크기가 명시적으로 고정된 자료형을 사용하는 것이 이식성 측면에서 더 안전합니다.

### 실수 자료형

| 자료형 | 일반적인 크기 | 유효 자릿수(대략) |
|---|---|---|
| `float` | 4바이트 | 약 6~7자리 |
| `double` | 8바이트 | 약 15~16자리 |
| `long double` | 8바이트, 10바이트, 16바이트 등(플랫폼에 따라 다름) | `double`보다 크거나 같음 |

### 기타

| 자료형 | 일반적인 크기 | 비고 |
|---|---|---|
| `_Bool` (`bool`, C99 이상 `stdbool.h` 사용 시) | 1바이트 | 0(거짓) 또는 1(참) |
| 포인터(`int *`, `char *` 등) | 4바이트(32비트 시스템) 또는 8바이트(64비트 시스템) | 가리키는 자료형과 무관하게 포인터 자체의 크기는 동일 |

### 자신의 환경에서 직접 확인하기

아래 코드를 컴파일해 실행하면 현재 사용 중인 컴파일러와 운영체제에서 각 자료형이 실제로 몇 바이트인지 확인할 수 있습니다.

```c
#include <stdio.h>

int main(void)
{
    printf("char: %zu바이트\n", sizeof(char));
    printf("short: %zu바이트\n", sizeof(short));
    printf("int: %zu바이트\n", sizeof(int));
    printf("long: %zu바이트\n", sizeof(long));
    printf("long long: %zu바이트\n", sizeof(long long));
    printf("float: %zu바이트\n", sizeof(float));
    printf("double: %zu바이트\n", sizeof(double));
    printf("포인터(int *): %zu바이트\n", sizeof(int *));

    return 0;
}
```

`sizeof`가 반환하는 값의 자료형은 `size_t`이며, 이를 출력할 때는 `%zu` 서식 지정자를 사용하는 것이 정확합니다.

## 부록 D. 더 공부하고 싶다면 참고할 자료 유형

이 책은 C 언어에 입문하는 데 필요한 기본기를 다루는 데 초점을 맞췄습니다. 더 깊이 있는 내용이나 최신 정보가 필요할 때는 다음과 같은 유형의 자료를 참고하는 것을 권장합니다. 특정 책이나 웹사이트를 하나만 고집하기보다, 아래 유형들을 상황에 맞게 넘나들며 활용하는 것이 좋습니다.

- **C 언어 표준 문서**: C 언어의 문법과 표준 라이브러리의 동작은 국제 표준화 기구가 제정한 공식 표준 문서에 정의되어 있습니다. 표준 문서는 다소 딱딱하고 읽기 어렵지만, 어떤 동작이 "표준으로 보장되는지" 혹은 "정의되지 않은 동작(undefined behavior)인지"를 확인해야 할 때 가장 신뢰할 수 있는 최종 근거가 됩니다.
- **컴파일러 공식 매뉴얼과 문서**: GCC, Clang, MSVC 등 각 컴파일러는 자체적으로 지원하는 확장 기능, 경고 옵션, 최적화 옵션에 대한 공식 문서를 제공합니다. `-Wall`이 정확히 어떤 경고들을 포함하는지, 특정 플랫폼에서 자료형의 크기가 어떻게 되는지는 사용 중인 컴파일러의 문서에서 확인하는 것이 가장 정확합니다.
- **표준 라이브러리 함수 레퍼런스**: 특정 함수의 정확한 매개변수, 반환값, 실패 조건이 궁금할 때는 함수별로 정리된 온라인 레퍼런스 문서나 운영체제에 내장된 매뉴얼 페이지(유닉스/리눅스 계열의 `man` 명령 등)를 참고하면 좋습니다. 17장 표준 라이브러리 둘러보기에서 소개한 함수 외에도 훨씬 많은 함수가 존재하므로, 필요할 때마다 이런 레퍼런스를 찾아보는 습관을 들이는 것이 중요합니다.
- **정적 분석 도구와 메모리 검사 도구 문서**: 프로그램을 실행하지 않고 코드만 분석해 잠재적 버그를 찾아 주는 정적 분석 도구나, 프로그램 실행 중 메모리 오용(경계 초과 접근, 메모리 누수 등)을 탐지해 주는 동적 분석 도구들이 있습니다. 이런 도구를 익혀 두면 18장 좋은 C 코드 작성 습관에서 다룬 흔한 실수들을 훨씬 이른 단계에서 자동으로 잡아낼 수 있습니다.
- **오픈소스 프로젝트의 코드와 기여 가이드**: 실제로 널리 쓰이는 오픈소스 C 프로젝트의 소스 코드, 코딩 스타일 가이드, 기여(contributing) 문서를 읽어 보면 실전에서 통용되는 관례를 자연스럽게 익힐 수 있습니다.
- **온라인 커뮤니티와 질의응답 사이트**: 특정 오류 메시지나 예상치 못한 동작으로 막혔을 때, 프로그래밍 관련 질의응답 커뮤니티에서 비슷한 사례를 검색해 보는 것도 효율적인 학습 방법입니다. 다만 커뮤니티의 답변은 항상 표준 문서나 공식 문서로 한 번 더 검증하는 습관을 들이는 것이 좋습니다.

자료의 형태가 무엇이든, 코드를 직접 작성하고 실행해 보면서 확인하는 과정을 대체할 수는 없습니다. 이 책에서 다룬 18개 장의 예제들을 다시 열어 스스로 변형해 보고, 오류를 일부러 만들어 컴파일러와 실행 결과가 어떻게 반응하는지 관찰하는 것이야말로 가장 확실한 복습 방법이라는 점을 마지막으로 강조하고 싶습니다.
