## 들어가며

1장에서 C 언어의 특징과 개발 환경 준비 방법을 살펴보았습니다. 이번 장에서는 실제로 첫 C 프로그램을 작성하고, 그것을 컴퓨터가 실행할 수 있는 프로그램으로 변환하는 전체 과정을 경험해 봅니다. 프로그래밍 언어를 처음 배울 때 관습적으로 작성하는 "Hello, World" 프로그램을 통해 C 프로그램의 기본 골격을 익히고, 소스 코드 한 줄이 어떻게 화면에 문자열을 출력하는 실행 파일로 바뀌는지 그 뒷단의 과정까지 이해하는 것이 이번 장의 목표입니다.

## Hello, World 작성하기

먼저 텍스트 편집기를 열고 `hello.c`라는 이름으로 파일을 하나 만들어 보겠습니다. 다음 내용을 그대로 입력해 보세요.

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

이 짧은 프로그램은 화면에 `Hello, World!`라는 문자열을 출력하고 종료합니다. 별것 아닌 것처럼 보이지만, 이 다섯 줄 안에는 C 프로그램을 이해하는 데 필요한 핵심 요소가 모두 들어 있습니다. 한 줄씩 뜯어보겠습니다.

### `#include <stdio.h>`

이 줄은 전처리기(preprocessor) 지시문입니다. `#`으로 시작하는 줄은 컴파일이 본격적으로 시작되기 전에 전처리기가 먼저 처리합니다. `#include <stdio.h>`는 "표준 입출력(Standard Input/Output)과 관련된 함수 선언이 담긴 `stdio.h`라는 헤더 파일(header file)의 내용을 이 위치에 그대로 가져다 붙여라"는 의미입니다.

우리가 곧 사용할 `printf` 함수는 C 언어 문법 자체에 내장된 키워드가 아니라, 표준 라이브러리가 제공하는 함수입니다. 이 함수를 사용하려면 컴파일러에게 "이런 이름과 형태의 함수가 존재한다"는 사실을 미리 알려주어야 하는데, 그 선언이 `stdio.h` 안에 들어 있습니다. `#include`와 헤더 파일의 자세한 동작 원리는 16장 전처리기와 매크로에서 더 깊이 다룹니다.

### `int main(void)`

모든 C 프로그램은 `main`이라는 이름의 함수에서 실행을 시작합니다. 운영체제가 프로그램을 실행시키면, 가장 먼저 호출되는 것이 바로 이 `main` 함수입니다.

- `int`는 이 함수가 실행을 마친 뒤 정수형 값을 반환한다는 뜻입니다. 이 반환값은 프로그램이 정상적으로 끝났는지, 오류가 있었는지를 운영체제나 다른 프로그램에게 알려주는 용도로 쓰입니다.
- `main`은 함수의 이름입니다. 반드시 이 이름이어야 실행 시작점으로 인식됩니다.
- 괄호 안의 `void`는 이 함수가 매개변수를 받지 않는다는 것을 명시적으로 나타냅니다. (명령줄 인자를 받는 `int main(int argc, char *argv[])` 형태는 이후 장에서 다룹니다.)
- 함수의 몸통은 중괄호 `{ }`로 감쌉니다. 이 책의 스타일 규칙대로, 여는 중괄호는 줄 끝이 아니라 다음 줄에 배치했지만, 실무에서는 같은 줄에 배치하는 스타일도 널리 쓰입니다. 어느 쪽이든 팀이나 프로젝트 내에서 일관성을 유지하는 것이 중요합니다.

함수를 정의하고 호출하는 자세한 문법은 8장 함수에서 본격적으로 학습합니다. 지금은 "`main` 함수는 프로그램의 출발점이다"라는 사실만 기억하면 충분합니다.

### `printf("Hello, World!\n");`

`printf`는 표준 라이브러리가 제공하는 함수로, 괄호 안에 전달한 문자열을 화면(정확히는 표준 출력)에 그대로 출력합니다. `"Hello, World!\n"`처럼 큰따옴표로 둘러싸인 텍스트를 **문자열 리터럴**이라고 부릅니다.

문자열 끝에 붙은 `\n`은 하나의 문자처럼 보이지만 실제로는 **줄바꿈**을 의미하는 특수한 문자입니다. 이런 표기를 이스케이프 시퀀스(escape sequence)라고 하며, 화면에 직접 표시할 수 없는 문자(줄바꿈, 탭 등)를 문자열 안에 넣을 때 사용합니다. `\n`을 빼먹으면 다음에 출력되는 내용이 같은 줄에 이어 붙어 나오게 되므로, 습관적으로 줄 끝에 붙여 주는 것이 좋습니다.

문장의 끝에 붙은 세미콜론(`;`)도 눈여겨봐야 합니다. C에서는 하나의 문장(statement)이 끝났음을 세미콜론으로 표시합니다. 이를 빠뜨리면 컴파일 오류가 발생합니다.

### `return 0;`

`main` 함수가 `int`를 반환한다고 선언했으므로, 함수 몸통 안에서 실제로 정수값을 반환해야 합니다. 관례적으로 `0`은 "프로그램이 정상적으로 종료되었음"을 의미합니다. 0이 아닌 값(주로 1 등의 양수)을 반환하면 어떤 오류나 비정상적인 상황이 있었다는 신호로 해석됩니다. 이 값은 셸 스크립트나 다른 프로그램이 우리 프로그램의 실행 결과를 판단할 때 사용됩니다.

## 소스 코드에서 실행 파일까지: 빌드 파이프라인

`hello.c` 파일을 저장했다고 해서 바로 실행할 수 있는 것은 아닙니다. 컴퓨터의 CPU는 C 언어 문법을 이해하지 못합니다. CPU가 이해할 수 있는 것은 오직 기계어(machine code)뿐입니다. 따라서 사람이 읽을 수 있는 C 소스 코드를, CPU가 실행할 수 있는 기계어로 변환하는 과정이 필요합니다. 이 전체 과정을 **빌드(build)**라고 부르며, 다음과 같은 다섯 단계로 이루어집니다.

```text
                       C 프로그램 빌드 파이프라인
              소스 코드에서 실행 파일이 만들어지기까지

+----------+     +-----------+     +----------+     +----------+     +--------+     +--------+
| 소스 코드 | --> | 전처리기   | --> | 컴파일러  | --> | 어셈블러  | --> | 링커    | --> | 실행   |
| hello.c  |     |#include,  |     |C->어셈블리|     |어셈블리->|     |라이브러리|     | 파일   |
|          |     |#define 처리|     |hello.s   |     |기계어     |     |와 결합  |     | a.out  |
|          |     |확장된 소스 |     |          |     |hello.o   |     |여러 목적|     |        |
|          |     |           |     |          |     |(목적파일)|     |파일 연결|     |        |
+----------+     +-----------+     +----------+     +----------+     +--------+     +--------+
  (원본)            gcc -E           gcc -S           gcc -c        ld(내부적으로 사용)

  |------------------------------------------------------------------------------|
     gcc hello.c -o hello  실행 시 이 다섯 단계가 자동으로 순서대로 수행됨
```

### 1단계: 전처리 (Preprocessing)

전처리기는 소스 코드에서 `#`으로 시작하는 지시문들을 처리합니다. `#include <stdio.h>`가 있던 자리에는 `stdio.h` 파일의 실제 내용이 그대로 삽입되고, `#define`으로 정의된 매크로가 있다면 해당 위치에 치환됩니다. 이 단계의 결과물은 여전히 C 언어 문법을 따르는 텍스트이지만, 모든 지시문이 처리되어 확장된 형태의 소스 코드입니다.

### 2단계: 컴파일 (Compilation)

컴파일러는 전처리가 끝난 C 코드를 문법적으로 분석하고, 각 어셈블리어 명령어로 변환합니다. 이 단계에서 문법 오류(세미콜론 누락, 괄호 짝이 맞지 않음, 선언되지 않은 변수 사용 등)가 있다면 컴파일 오류(compile error)가 발생하고 빌드가 중단됩니다. 정상적으로 처리되면 어셈블리어로 작성된 코드가 생성됩니다.

### 3단계: 어셈블 (Assembly)

어셈블러는 어셈블리어 코드를 실제 CPU가 이해하는 기계어(2진수 명령어)로 변환합니다. 이 결과물을 목적 파일(object file, 확장자는 보통 `.o` 또는 `.obj`)이라고 부릅니다. 목적 파일에는 기계어 코드가 들어 있지만, 아직 완전한 실행 파일은 아닙니다.

### 4단계: 링크 (Linking)

우리가 작성한 `hello.c`는 `printf`라는 함수를 호출하지만, `printf`의 실제 구현 코드는 우리 파일 안에 없습니다. `printf`의 실제 동작은 C 표준 라이브러리라는 별도의 파일에 미리 컴파일되어 존재합니다. 링커(linker)는 우리가 만든 목적 파일과 표준 라이브러리(또는 우리가 작성한 다른 목적 파일들)를 하나로 결합해서, 프로그램 실행에 필요한 모든 코드가 포함된 완전한 실행 파일을 만들어냅니다. 여러 개의 소스 파일로 나뉜 큰 프로젝트일수록 이 링크 단계의 역할이 중요해집니다.

### 5단계: 실행

이렇게 만들어진 실행 파일(윈도우에서는 `.exe`, 리눅스나 macOS에서는 확장자가 없는 바이너리)을 운영체제가 메모리에 적재하고 실행하면, 비로소 `main` 함수부터 코드가 순서대로 실행되며 우리가 원하는 동작(여기서는 화면에 문자열 출력)이 일어납니다.

다행히도 이 다섯 단계를 사람이 일일이 손으로 수행할 필요는 없습니다. `gcc`나 `clang` 같은 컴파일러 도구는 이 모든 과정을 한 번의 명령어로 자동 처리해 줍니다. 다만 각 단계가 무엇을 하는지 이해해 두면, 나중에 "링크 오류"와 "컴파일 오류"를 구분하는 등 문제 해결 능력이 크게 향상됩니다.

## gcc로 컴파일하고 실행하기

터미널(윈도우의 명령 프롬프트, PowerShell, 또는 리눅스/macOS의 셸)을 열고, `hello.c` 파일이 있는 폴더로 이동한 다음 아래 명령을 입력해 보겠습니다.

```bash
gcc hello.c -o hello
```

각 부분의 의미는 다음과 같습니다.

- `gcc`: GNU 컴파일러를 실행하는 명령입니다.
- `hello.c`: 컴파일할 소스 파일입니다.
- `-o hello`: 출력(output) 파일의 이름을 `hello`(윈도우에서는 자동으로 `hello.exe`)로 지정하는 옵션입니다. 이 옵션을 생략하면 기본적으로 `a.out`(윈도우에서는 `a.exe`)이라는 이름으로 실행 파일이 생성됩니다.

오류 없이 컴파일이 끝나면, 같은 폴더에 `hello`(또는 `hello.exe`) 실행 파일이 생성됩니다. 이제 이 파일을 실행해 보겠습니다.

```bash
./hello
```

윈도우 명령 프롬프트에서는 다음과 같이 실행합니다.

```bash
hello.exe
```

정상적으로 실행되었다면 터미널에 다음과 같이 출력됩니다.

```
Hello, World!
```

축하합니다. 여러분은 방금 첫 C 프로그램을 작성하고, 빌드하고, 실행하는 전체 과정을 완료했습니다.

### 빌드 과정을 단계별로 눈으로 확인하기

gcc는 앞서 설명한 각 단계의 중간 결과물을 별도로 만들어 볼 수 있는 옵션도 제공합니다. 빌드 파이프라인을 몸으로 이해하고 싶다면 다음 명령들을 순서대로 실행해 보시기 바랍니다.

```bash
# 1. 전처리 결과만 확인 (확장된 소스 코드)
gcc -E hello.c -o hello.i

# 2. 컴파일 결과만 확인 (어셈블리어 코드)
gcc -S hello.c -o hello.s

# 3. 어셈블 결과만 확인 (목적 파일, 아직 링크 전)
gcc -c hello.c -o hello.o

# 4. 최종 링크까지 수행 (완전한 실행 파일)
gcc hello.o -o hello
```

`hello.i` 파일을 열어 보면 `stdio.h`의 내용이 통째로 삽입되어 원본 파일보다 훨씬 길어진 것을 확인할 수 있습니다. `hello.s` 파일을 열어 보면 우리가 작성한 적 없는 어셈블리어 명령어들이 나타납니다. 이 실습을 통해 "컴파일"이라는 한 단어 뒤에 실제로는 여러 단계가 숨어 있다는 사실을 직접 확인할 수 있습니다.

## 흔한 컴파일 오류와 경고, 그리고 대처법

프로그래밍을 배우는 과정에서 오류 메시지는 피할 수 없는 동반자입니다. 오류를 두려워하기보다, 오류 메시지를 정확히 읽는 습관을 들이는 것이 실력 향상의 지름길입니다. 자주 마주치는 몇 가지 상황을 살펴보겠습니다.

### 1. 세미콜론 누락

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n")
    return 0;
}
```

`printf` 문장 끝에 세미콜론이 빠졌습니다. 컴파일하면 다음과 비슷한 오류가 발생합니다.

```
error: expected ';' before 'return'
```

C 컴파일러는 세미콜론이 나올 때까지를 하나의 문장으로 인식하므로, 세미콜론이 없으면 다음 줄과 이어서 해석하려다 오류를 냅니다. 오류 메시지에 표시된 줄 번호는 세미콜론이 빠진 실제 줄이 아니라 그 다음 줄로 나오는 경우가 많다는 점에 유의하세요.

### 2. 헤더 파일을 포함하지 않음

```c
int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

`#include <stdio.h>`를 빠뜨리면 컴파일러가 `printf`라는 이름을 알지 못해 다음과 같은 경고 또는 오류가 발생합니다.

```
warning: implicit declaration of function 'printf'
```

일부 컴파일러나 표준 설정에 따라서는 이것이 경고로 그치고 실행 파일이 만들어지기도 하지만, 최신 C 표준을 엄격하게 적용하면 오류로 처리되기도 합니다. 어떤 함수를 사용하든 그 함수가 선언된 헤더 파일을 반드시 포함시키는 습관을 들이시기 바랍니다.

### 3. 중괄호 짝이 맞지 않음

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
```

닫는 중괄호 `}`가 빠졌습니다. 이 경우 다음과 같은 오류가 발생합니다.

```
error: expected declaration or statement at end of input
```

이런 오류는 실제 문제가 발생한 지점이 아니라 파일의 맨 끝에서 보고되는 경우가 많습니다. 중괄호가 맞지 않는다는 오류를 만나면, 파일 전체를 위에서부터 훑으며 여는 중괄호와 닫는 중괄호의 개수를 세어 보는 것이 효과적입니다. 대부분의 편집기는 괄호 짝을 자동으로 강조해서 보여주는 기능을 제공하므로 적극 활용하시기 바랍니다.

### 4. 오타로 인한 정의되지 않은 식별자

```c
#include <stdio.h>

int main(void)
{
    printff("Hello, World!\n");
    return 0;
}
```

`printf`를 `printff`로 잘못 입력했습니다.

```
error: implicit declaration of function 'printff'
```

함수 이름이나 변수 이름의 오타는 프로그래밍에서 가장 흔한 실수 중 하나입니다. 오류 메시지에 등장하는 이름을 자신이 작성한 코드와 한 글자씩 비교해 보는 습관을 들이면 빠르게 찾아낼 수 있습니다.

### 오류와 경고의 차이

컴파일러가 내는 메시지는 크게 **오류(error)**와 **경고(warning)**로 나뉩니다. 오류가 하나라도 있으면 실행 파일이 만들어지지 않습니다. 경고는 실행 파일이 만들어지긴 하지만 "이 코드에 문제가 있을 수 있다"는 컴파일러의 알림입니다. 초보자일수록 경고를 무시하기 쉬운데, 실제로는 많은 버그가 경고 메시지 단계에서 미리 감지될 수 있습니다. 다음과 같이 경고를 더 엄격하게 보여주는 옵션을 사용하는 것을 권장합니다.

```bash
gcc -Wall -Wextra hello.c -o hello
```

`-Wall`과 `-Wextra`는 더 많은 종류의 잠재적 문제를 경고로 표시해 달라는 옵션입니다. 이 책의 예제를 실습할 때도 가급적 이 옵션을 함께 사용해 보시기 바랍니다. 처음에는 낯선 경고 메시지가 많이 나올 수 있지만, 각 경고가 무엇을 지적하는지 하나씩 읽어 나가는 과정 자체가 좋은 학습이 됩니다.

## 요약

- C 프로그램은 `#include` 지시문으로 필요한 헤더 파일을 포함시키고, `main` 함수에서 실행이 시작되며, `printf` 같은 표준 라이브러리 함수로 화면에 값을 출력한다.
- 소스 코드는 전처리, 컴파일, 어셈블, 링크의 네 단계를 거쳐 실행 파일로 만들어지며, `gcc hello.c -o hello`와 같은 명령 한 줄이 이 과정을 모두 자동으로 수행한다.
- `gcc -E`, `-S`, `-c` 옵션을 사용하면 빌드 파이프라인의 각 중간 결과물을 직접 눈으로 확인할 수 있다.
- 세미콜론 누락, 헤더 파일 누락, 중괄호 짝 불일치, 오타는 초보자가 자주 마주치는 대표적인 컴파일 오류 원인이다.
- 오류(error)는 빌드를 중단시키지만 경고(warning)는 빌드를 막지 않는다. 그러나 경고 역시 잠재적 버그의 신호이므로 `-Wall -Wextra` 옵션과 함께 꼼꼼히 확인하는 습관이 중요하다.

## 연습문제

1. `hello.c`를 수정해서 자신의 이름을 포함한 인사말(예: `안녕하세요, 홍길동입니다!`)을 출력하도록 만들고, `printf`를 두 번 사용해 두 줄에 걸쳐 출력해 보세요.
2. `printf` 문장 끝의 세미콜론을 의도적으로 지운 뒤 컴파일해서 어떤 오류 메시지가 나오는지 확인하고, 오류 메시지에 표시된 줄 번호와 실제 문제가 있는 줄이 일치하는지 비교해 보세요.
3. `gcc -E`, `gcc -S`, `gcc -c` 옵션을 각각 사용해 `hello.c`의 전처리 결과, 어셈블리어 결과, 목적 파일을 만들어 보고, 전처리 결과 파일(`hello.i`)의 줄 수가 원본 파일보다 얼마나 늘어났는지 확인해 보세요.
4. `main` 함수의 반환값을 `0`이 아닌 `1`로 바꾼 뒤 프로그램을 실행하고, 운영체제에서 직전 프로그램의 종료 코드를 확인하는 방법(예: 리눅스/macOS의 `echo $?`, 윈도우 PowerShell의 `$LASTEXITCODE`)을 찾아 실제로 값이 어떻게 바뀌는지 확인해 보세요.
5. `#include <stdio.h>`를 지운 채로 컴파일했을 때 나타나는 경고 또는 오류 메시지를 확인하고, `-Wall -Wextra` 옵션을 추가로 사용했을 때 메시지가 어떻게 달라지는지 비교해 보세요.
