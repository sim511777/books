지금까지 작성한 예제들은 대부분 `main` 함수 하나에 모든 코드를 몰아넣은 형태였습니다. 프로그램이 몇 줄 되지 않을 때는 이렇게 해도 큰 문제가 없지만, 프로그램이 커지기 시작하면 이야기가 달라집니다. 똑같은 계산을 여러 곳에서 반복해야 하거나, 코드가 수백 줄로 늘어나면서 특정 기능이 어디에 있는지 찾기 어려워지는 문제가 생깁니다.

함수(function)는 이런 문제를 해결하는 가장 기본적인 도구입니다. 특정 작업을 수행하는 코드 뭉치에 이름을 붙여두고, 필요할 때마다 그 이름을 불러서 재사용하는 것입니다. 사실 우리는 이미 `printf`나 `scanf` 같은 함수를 계속 사용해 왔습니다. 이번 장에서는 이런 함수를 직접 만드는 방법과, 함수를 이해하는 데 꼭 필요한 개념들인 매개변수, 반환값, 스코프, 재귀, 값에 의한 전달을 차례로 살펴봅니다.

## 함수의 정의와 호출

함수를 만드는 것을 함수 정의(definition)라고 하고, 만들어진 함수를 실행하는 것을 함수 호출(call)이라고 합니다. 함수 정의의 기본 형태는 다음과 같습니다.

```c
반환형 함수이름(매개변수 목록) {
    // 함수가 수행할 코드
    return 반환값;
}
```

간단한 예제로, 두 정수를 더해서 결과를 돌려주는 함수를 만들어 보겠습니다.

```c
#include <stdio.h>

// 두 정수를 더한 값을 반환하는 함수
int add(int a, int b) {
    int result = a + b;
    return result;
}

int main(void) {
    int x = add(3, 4);       // 함수 호출: add에 3과 4를 넘겨줌
    printf("3 + 4 = %d\n", x);

    printf("10 + 20 = %d\n", add(10, 20));  // 호출 결과를 바로 printf에 사용

    return 0;
}
```

`add`라는 이름의 함수는 `int` 타입의 매개변수(parameter) `a`와 `b`를 받아서, 둘을 더한 `int` 값을 반환합니다. `main` 함수 안에서 `add(3, 4)`처럼 함수 이름과 괄호 안에 값을 넣어 호출하면, 그 순간 프로그램의 실행 흐름이 `add` 함수 내부로 넘어갑니다. `add` 함수는 `a`에 3을, `b`에 4를 받아 계산을 마친 뒤 `return`문으로 결과를 돌려주고, 실행 흐름은 다시 `add`를 호출했던 자리로 돌아옵니다.

함수를 호출할 때 넘겨주는 값(위 예제의 3, 4, 10, 20)을 인자(argument)라고 부르고, 함수 정의에서 그 값을 받는 변수(`a`, `b`)를 매개변수라고 부릅니다. 두 용어를 명확히 구분해서 쓰지 않는 경우도 흔하지만, "호출하는 쪽에서 넘기는 것이 인자, 함수 쪽에서 받는 것이 매개변수"라고 기억해 두면 혼란이 줄어듭니다.

### 반환값이 없는 함수: void

모든 함수가 값을 돌려줄 필요는 없습니다. 화면에 무언가를 출력하기만 하고 끝나는 함수처럼, 반환할 값이 없는 경우에는 반환형 자리에 `void`를 씁니다.

```c
#include <stdio.h>

// 반환값이 없는 함수
void print_star_line(int count) {
    for (int i = 0; i < count; i++) {
        printf("*");
    }
    printf("\n");
}

int main(void) {
    print_star_line(5);
    print_star_line(10);
    return 0;
}
```

`void` 함수 안에서도 `return;`처럼 값 없이 `return`을 사용해서 함수를 즉시 끝낼 수 있습니다. 다만 반환할 값은 없으므로 `return` 뒤에 아무것도 쓰지 않습니다.

### 매개변수가 없는 함수

매개변수가 필요 없는 함수는 괄호 안에 `void`를 명시하거나 비워 둡니다. C 언어에서는 `void`를 명시하는 쪽이 더 안전한 습관으로 권장됩니다.

```c
void print_greeting(void) {
    printf("안녕하세요!\n");
}
```

## 함수 선언(프로토타입)과 정의의 차이

C 컴파일러는 코드를 위에서 아래로 순서대로 읽어가며 처리합니다. 그래서 어떤 함수를 호출하는 코드가, 그 함수가 정의된 코드보다 앞에 나오면 컴파일러는 "이런 함수가 있는지 모른다"며 오류를 내거나 경고를 냅니다.

```c
#include <stdio.h>

int main(void) {
    int result = square(5);   // 이 시점에는 아직 square를 모른다
    printf("%d\n", result);
    return 0;
}

int square(int n) {           // square의 정의는 main보다 뒤에 있음
    return n * n;
}
```

이 문제를 해결하는 방법이 함수 선언(declaration), 흔히 프로토타입(prototype)이라고 부르는 것입니다. 함수 선언은 함수의 반환형, 이름, 매개변수의 타입만을 미리 컴파일러에게 알려주는 문장으로, 함수 몸체(중괄호 블록) 없이 세미콜론으로 끝납니다.

```c
#include <stdio.h>

int square(int n);   // 함수 선언(프로토타입): "이런 함수가 나중에 정의될 것이다"

int main(void) {
    int result = square(5);   // 이제 컴파일러는 square를 알고 있으므로 문제없다
    printf("%d\n", result);
    return 0;
}

int square(int n) {   // 함수 정의: 실제 동작을 작성
    return n * n;
}
```

정리하면 다음과 같은 차이가 있습니다.

- **함수 선언(프로토타입)**: 함수의 존재와 형태(반환형, 이름, 매개변수 타입)만 알려주는 문장. 세미콜론으로 끝난다.
- **함수 정의**: 함수가 실제로 어떤 일을 하는지 중괄호 블록 안에 구현하는 것.

프로그램이 작을 때는 함수를 사용하기 전에 정의해버리면 선언이 따로 필요 없지만, 여러 함수가 서로를 호출하거나 프로그램 규모가 커지면 선언을 파일 맨 위에 모아두는 방식이 훨씬 관리하기 편합니다. 이런 함수 선언들을 별도의 `.h` 파일, 즉 헤더 파일(header file)에 모아두고 `#include`로 불러와 사용하는 방식이 실무에서는 일반적입니다. 예를 들어 `math.h` 헤더 파일에는 `sqrt`, `pow` 같은 수학 함수들의 선언이 모여 있습니다. 헤더 파일을 직접 만들어서 여러 소스 파일에 나누어 프로그램을 작성하는 방법은 16장 전처리기와 매크로에서 조금 더 다룹니다.

## 지역변수와 전역변수, 스코프

변수는 선언된 위치에 따라 접근 가능한 범위가 달라지는데, 이를 스코프(scope, 범위)라고 합니다. C 언어에서 변수는 크게 지역변수(local variable)와 전역변수(global variable)로 나뉩니다.

### 지역변수

함수 내부(또는 중괄호 블록 내부)에서 선언된 변수를 지역변수라고 합니다. 지역변수는 그 블록 안에서만 존재하며, 블록 실행이 끝나면 사라집니다.

```c
#include <stdio.h>

void my_function(void) {
    int local_var = 100;   // my_function 안에서만 존재하는 지역변수
    printf("local_var = %d\n", local_var);
}

int main(void) {
    my_function();
    // printf("%d\n", local_var);   // 오류! local_var는 여기서 보이지 않는다
    return 0;
}
```

같은 이름의 지역변수를 서로 다른 함수에서 각각 선언해도 전혀 문제가 되지 않습니다. 두 변수는 완전히 독립된 별개의 저장 공간이기 때문입니다.

```c
#include <stdio.h>

void func_a(void) {
    int value = 1;   // func_a만의 value
    printf("func_a의 value: %d\n", value);
}

void func_b(void) {
    int value = 999;   // func_b만의 value, func_a의 value와 아무 관련 없음
    printf("func_b의 value: %d\n", value);
}

int main(void) {
    func_a();
    func_b();
    return 0;
}
```

### 전역변수

함수 바깥, 즉 파일의 최상단 영역에서 선언된 변수를 전역변수라고 합니다. 전역변수는 선언된 지점부터 파일이 끝날 때까지, 프로그램 내 모든 함수에서 접근할 수 있습니다.

```c
#include <stdio.h>

int total_count = 0;   // 전역변수: 모든 함수에서 접근 가능

void increase(void) {
    total_count++;   // 전역변수를 직접 수정
}

int main(void) {
    increase();
    increase();
    increase();
    printf("total_count = %d\n", total_count);   // 3이 출력됨
    return 0;
}
```

전역변수는 여러 함수가 상태를 공유해야 할 때 편리하지만, 남용하면 문제가 생깁니다. 어떤 함수가 전역변수를 언제 어떻게 바꾸는지 추적하기가 점점 어려워지고, 여러 함수가 같은 전역변수를 서로 다른 의도로 수정하면서 예상치 못한 버그가 발생하기 쉽습니다. 일반적으로는 꼭 필요한 경우가 아니라면 지역변수와 매개변수, 반환값을 통해 데이터를 주고받는 방식을 우선적으로 고려하는 것이 좋은 습관입니다.

### 같은 이름의 지역변수와 전역변수

지역변수와 전역변수의 이름이 같으면, 그 지역변수가 선언된 범위 안에서는 지역변수가 우선합니다.

```c
#include <stdio.h>

int value = 10;   // 전역변수

void show(void) {
    int value = 20;   // 지역변수가 전역변수를 가림(shadowing)
    printf("show 안의 value: %d\n", value);   // 20 출력
}

int main(void) {
    show();
    printf("main의 value: %d\n", value);   // 10 출력 (전역변수)
    return 0;
}
```

이처럼 지역변수가 전역변수를 가리는 현상을 셰도잉(shadowing)이라고 부릅니다. 코드를 읽는 사람이 헷갈리기 쉬우므로, 되도록 지역변수와 전역변수의 이름은 겹치지 않게 짓는 것이 바람직합니다.

## 재귀 함수

함수가 자기 자신을 다시 호출하는 것을 재귀(recursion)라고 합니다. 처음 접하면 다소 낯설게 느껴질 수 있지만, 문제를 "더 작은 같은 형태의 문제"로 쪼갤 수 있을 때 매우 강력하고 우아한 해결 방법이 됩니다.

재귀 함수를 만들 때는 반드시 두 가지 요소가 필요합니다.

1. **기저 조건(base case)**: 더 이상 재귀 호출을 하지 않고 바로 답을 내는 경우. 이것이 없으면 함수가 영원히 자기 자신을 호출하다가 프로그램이 비정상 종료됩니다.
2. **재귀 단계(recursive case)**: 문제를 더 작은 문제로 줄여서 자기 자신을 다시 호출하는 부분.

가장 대표적인 예로 팩토리얼을 계산하는 함수를 살펴보겠습니다. n의 팩토리얼(n!)은 1부터 n까지의 모든 정수를 곱한 값으로, 수학적으로는 다음과 같이 정의됩니다.

- 0! = 1 (기저 조건)
- n! = n × (n-1)! (n이 1 이상일 때, 재귀 단계)

이 정의를 그대로 C 코드로 옮기면 다음과 같습니다.

```c
#include <stdio.h>

int factorial(int n) {
    if (n == 0) {
        return 1;              // 기저 조건: 0! = 1
    }
    return n * factorial(n - 1);   // 재귀 단계: n! = n * (n-1)!
}

int main(void) {
    for (int i = 0; i <= 5; i++) {
        printf("%d! = %d\n", i, factorial(i));
    }
    return 0;
}
```

`factorial(3)`을 호출하면 내부적으로 다음과 같은 순서로 계산이 진행됩니다.

```
factorial(3)
= 3 * factorial(2)
= 3 * (2 * factorial(1))
= 3 * (2 * (1 * factorial(0)))
= 3 * (2 * (1 * 1))
= 6
```

`factorial(0)`에 도달하기 전까지는 계속 자기 자신을 호출하며 계산을 미뤄두다가, 기저 조건인 `factorial(0)`이 1을 반환하는 순간부터 미뤄두었던 곱셈이 하나씩 실제로 계산되면서 결과가 위로 전달됩니다.

이 과정에서 각각의 `factorial` 호출은 컴퓨터 메모리 안에 자신만의 독립적인 공간, 즉 스택 프레임(stack frame)을 가지고 자신의 매개변수 `n`과 지역변수를 따로 기억합니다. 재귀 호출이 깊어질수록 이 스택 프레임이 계속 쌓여나가고, 기저 조건에 도달해 함수들이 하나씩 값을 반환하며 끝날 때마다 스택 프레임도 순서대로 정리(제거)됩니다. 아래 그림은 `factorial(3)`이 호출되고 반환되는 과정에서 스택 프레임이 어떻게 쌓이고 줄어드는지를 보여줍니다.

```text
        factorial(3) 호출 시 함수 호출 스택의 변화

 [1] 호출 단계 (스택이 쌓임)         [2] 반환 단계 (스택이 줄어듦)

 +---------------------------+       +--------------------------------+
 | factorial(0) 프레임        |       | factorial(0)                   |
 | n = 0 (기저 조건, return 1)|       | return 1 (완료, 프레임 제거)     |
 +---------------------------+       +--------------------------------+
              ^                                    |
              |  (호출할 때마다                      v
 +---------------------------+       +--------------------------------+
 | factorial(1) 프레임        |       | factorial(1)                   |
 | n = 1                      |       | return 1 * factorial(0) = 1    |
 +---------------------------+       +--------------------------------+
              ^  새 프레임이                        |
              |  위로 쌓입니다                        v
 +---------------------------+       +--------------------------------+
 | factorial(2) 프레임        |       | factorial(2)                   |
 | n = 2                      |       | return 2 * factorial(1) = 2    |
 +---------------------------+       +--------------------------------+
              ^  (스택 push)                        |
              |                                    v
 +---------------------------+       +--------------------------------+
 | factorial(3) 프레임        |       | factorial(3)                   |
 | n = 3                      |       | return 3 * factorial(2) = 6    |
 +---------------------------+       +--------------------------------+
                                     (값을 반환하며 프레임이 아래에서부터
                                      제거됩니다 - 스택 pop)

 각 함수 호출은 자신만의 지역변수(n 등)를 담은 독립된 스택 프레임을 가집니다.
 재귀 호출이 깊어질수록 프레임이 계속 쌓여나가며, 기저 조건(n == 0)에
 도달하면 더 이상 호출하지 않고 값을 반환하면서 프레임이 순서대로 제거됩니다.
```

재귀는 특히 피보나치 수열, 트리 구조 탐색, 하노이의 탑처럼 "같은 구조가 반복해서 작은 규모로 나타나는" 문제에서 코드를 매우 간결하게 만들어 줍니다. 예를 들어 피보나치 수열의 n번째 항을 구하는 함수도 팩토리얼과 비슷한 형태로 작성할 수 있습니다.

```c
#include <stdio.h>

// 피보나치 수열: 0, 1, 1, 2, 3, 5, 8, 13, ...
int fibonacci(int n) {
    if (n == 0) {
        return 0;   // 기저 조건 1
    }
    if (n == 1) {
        return 1;   // 기저 조건 2
    }
    return fibonacci(n - 1) + fibonacci(n - 2);   // 재귀 단계
}

int main(void) {
    for (int i = 0; i < 10; i++) {
        printf("%d ", fibonacci(i));
    }
    printf("\n");
    return 0;
}
```

다만 재귀는 스택 프레임을 계속 쌓아가는 방식이기 때문에, 재귀 호출이 지나치게 깊어지면 메모리를 과도하게 사용하다가 스택 오버플로우(stack overflow)가 발생할 수 있습니다. 또한 위의 `fibonacci` 함수처럼 같은 계산을 중복해서 여러 번 반복하는 경우 반복문을 사용한 방식보다 훨씬 느려질 수도 있습니다. 재귀는 코드를 우아하고 이해하기 쉽게 만들어주는 강력한 도구이지만, 항상 반복문보다 우월한 것은 아니며 문제의 성격에 따라 적절히 선택해야 하는 도구라는 점을 기억해 두면 좋습니다.

## 값에 의한 전달(call by value)

C 언어에서 함수를 호출할 때 인자를 넘기는 방식은 기본적으로 값에 의한 전달(call by value)입니다. 이는 함수를 호출할 때 인자의 **값을 복사**해서 매개변수에 넘겨준다는 뜻입니다. 즉, 함수 안에서 매개변수를 변경해도 호출한 쪽의 원래 변수에는 아무런 영향을 주지 않습니다.

```c
#include <stdio.h>

void try_to_double(int number) {
    number = number * 2;   // 이건 복사된 값만 바꾸는 것
    printf("함수 내부: number = %d\n", number);
}

int main(void) {
    int x = 5;
    try_to_double(x);
    printf("함수 호출 후: x = %d\n", x);   // 여전히 5
    return 0;
}
```

실행 결과는 다음과 같습니다.

```
함수 내부: number = 10
함수 호출 후: x = 5
```

`try_to_double` 함수 안의 `number`는 `main`의 `x`가 아니라, `x`의 값 5를 그대로 복사해서 만든 완전히 별개의 변수입니다. 그래서 함수 안에서 `number`를 아무리 바꿔도, 원본인 `x`는 전혀 영향을 받지 않습니다. 이는 마치 서류의 원본이 아니라 복사본을 건네주는 것과 비슷합니다. 복사본에 낙서를 해도 원본은 깨끗하게 남아 있는 것과 같은 이치입니다.

그렇다면 함수가 호출한 쪽의 원래 변수 값을 실제로 바꾸고 싶다면 어떻게 해야 할까요? 이럴 때 필요한 것이 포인터(pointer)입니다. 변수의 값 자체가 아니라 그 변수가 저장된 "주소"를 함수에 넘겨주면, 함수 내부에서 그 주소를 통해 원본 변수에 직접 접근하여 값을 바꿀 수 있습니다. 이런 방식을 흔히 참조에 의한 전달(call by reference)이라고 부르며, 포인터를 이용한 함수 호출은 12장 포인터 응용에서 자세히 다룹니다. 지금 단계에서는 "C 언어의 함수 호출은 기본적으로 값을 복사해서 전달한다"는 원칙만 확실히 기억해 두면 충분합니다.

## 요약

- 함수는 특정 작업을 수행하는 코드에 이름을 붙여 재사용할 수 있게 만든 것으로, `반환형 함수이름(매개변수 목록) { ... }` 형태로 정의한다.
- 반환값이 없는 함수는 반환형에 `void`를 쓰고, 매개변수가 없는 함수는 괄호 안에 `void`를 명시하는 것이 안전하다.
- 함수 선언(프로토타입)은 함수의 형태만 미리 알려주는 문장이고, 함수 정의는 실제 동작을 구현하는 것이다. 여러 함수를 사용하는 프로그램에서는 선언을 앞쪽에 모아두거나 헤더 파일로 분리해 관리한다.
- 지역변수는 선언된 블록 안에서만 존재하고, 전역변수는 파일 전체에서 접근 가능하다. 전역변수는 편리하지만 남용하면 코드 추적이 어려워지므로 신중하게 사용해야 한다.
- 재귀 함수는 자기 자신을 호출하는 함수로, 반드시 기저 조건과 재귀 단계를 갖추어야 하며, 호출될 때마다 독립된 스택 프레임이 쌓였다가 반환되면서 정리된다.
- C 언어의 함수 호출은 기본적으로 값에 의한 전달(call by value)이며, 매개변수를 바꿔도 호출한 쪽의 원본 변수에는 영향을 주지 않는다. 원본을 바꾸려면 포인터가 필요하며, 이는 12장 포인터 응용에서 다룬다.

## 연습문제

1. 두 정수 중 더 큰 값을 반환하는 함수 `int max_of_two(int a, int b)`를 작성하고, `main` 함수에서 세 개의 정수를 입력받아 그중 가장 큰 값을 출력하는 프로그램을 완성하시오. (`max_of_two`를 두 번 호출하는 방식을 사용해 봅니다.)
2. 정수 n을 받아 1부터 n까지의 합을 반환하는 함수를 반복문 버전과 재귀 버전 두 가지로 각각 작성하고, 두 결과가 같은지 비교하시오.
3. 정수 배열이 아니라 정수 하나를 매개변수로 받아 10을 더한 뒤 반환하지 않고 그냥 끝내는 함수 `void add_ten(int number)`를 작성하고, `main`에서 이 함수를 호출한 후 원래 변수의 값이 바뀌지 않았음을 `printf`로 확인하시오. 왜 값이 바뀌지 않는지 설명하시오.
4. 전역변수 하나를 두고, 이를 증가시키는 함수와 감소시키는 함수를 각각 만들어 여러 번 호출한 뒤 최종 값을 출력하는 프로그램을 작성하시오.
5. 재귀를 이용하여 정수 n의 각 자릿수 합을 구하는 함수 `int digit_sum(int n)`을 작성하시오. (예: `digit_sum(12345)`는 15를 반환해야 한다.) 이 함수의 기저 조건과 재귀 단계가 무엇인지 주석으로 설명하시오.
