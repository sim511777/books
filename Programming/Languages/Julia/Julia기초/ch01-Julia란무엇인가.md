## 들어가며

새로운 프로그래밍 언어를 배우기 전에 가장 먼저 던져야 할 질문은 "이 언어는 왜 만들어졌는가"입니다. 언어를 설계한 사람들이 어떤 문제를 풀고 싶었는지 알면, 그 언어의 문법이나 관용구가 왜 지금과 같은 모습을 하고 있는지 훨씬 쉽게 이해할 수 있습니다. Julia도 마찬가지입니다. Julia는 취미 삼아 만들어진 언어가 아니라, 특정한 불편함을 없애기 위해 명확한 목표를 가지고 설계된 언어입니다. 이번 장에서는 Julia가 어떤 배경에서 태어났고, 어떤 특징을 가지고 있으며, 다른 언어들과 비교했을 때 어느 위치에 서 있는지를 살펴보겠습니다. 아직 코드를 한 줄도 쓰지 않지만, 이 장의 내용은 앞으로 이 책 전체를 읽어 나가는 데 중요한 지도 역할을 해줄 것입니다.

## Julia의 탄생: 두 언어 문제를 넘어서

과학 계산이나 데이터 분석을 해본 사람이라면 다음과 같은 상황이 낯설지 않을 것입니다. 아이디어를 빠르게 검증하고 싶을 때는 Python이나 MATLAB, R처럼 배우기 쉽고 즉시 결과를 확인할 수 있는 언어를 사용합니다. 그런데 프로토타입이 실제로 쓸만하다는 것이 확인되고 나면, 속도가 문제가 됩니다. 대량의 데이터를 처리하거나 반복 계산이 많은 코드는 이런 언어들만으로는 충분히 빠르지 않은 경우가 많습니다. 그러면 개발자는 핵심 로직을 C나 Fortran, C++ 같은 언어로 다시 작성해야 합니다.

이 과정을 흔히 "두 언어 문제(two-language problem)"라고 부릅니다. 하나의 프로젝트를 만들기 위해 서로 다른 두 언어를 오가며 같은 로직을 두 번 작성해야 하는 상황을 가리키는 말입니다. 문제는 단순히 코드를 두 번 쓰는 수고로움에 그치지 않습니다. 프로토타입 언어와 성능 언어 사이의 문법과 사고방식이 크게 다르기 때문에, 두 버전의 코드가 정확히 같은 동작을 하는지 검증하는 데에도 많은 시간이 듭니다. 새로운 기능을 추가할 때마다 두 곳을 동시에 고쳐야 하고, 두 언어를 모두 잘 다루는 사람이 필요하다는 점도 진입 장벽이 됩니다. 대학 연구실이나 기업의 연구개발 부서에서는 이런 이중 작업이 오랫동안 당연한 것처럼 받아들여져 왔습니다.

Julia는 바로 이 문제를 정면으로 해결하기 위해 2009년경 매사추세츠 공과대학(MIT)에서 시작된 프로젝트입니다. Jeff Bezanson, Stefan Karpinski, Viral Shah, Alan Edelman 네 사람이 중심이 되어 개발을 진행했고, 2012년에 정식으로 공개되었습니다. 이들의 목표는 명확했습니다. "Python처럼 쉽게 쓸 수 있으면서도, C에 가까운 속도로 실행되는 언어를 만들자." 즉 프로토타입을 작성하는 언어와 실제 배포되는 고성능 코드를 작성하는 언어를 하나로 합치는 것이 Julia의 존재 이유였습니다.

이 목표는 단순한 마케팅 문구가 아니라 Julia의 언어 설계 전반에 깊이 스며들어 있습니다. 타입을 명시하지 않아도 되는 유연한 문법을 제공하면서도, 내부적으로는 컴파일러가 타입 정보를 적극적으로 활용해 기계어에 가까운 코드를 만들어냅니다. 이러한 설계 철학이 실제로 어떻게 구현되어 있는지는 다음 절에서 조금 더 구체적으로 살펴보겠습니다.

## 동적 타입과 JIT 컴파일: 빠르면서도 유연한 언어

Julia로 코드를 작성할 때 겉으로 드러나는 모습은 Python과 크게 다르지 않습니다. 변수를 선언할 때 타입을 미리 적어줄 필요가 없고, 함수를 정의할 때도 인자의 타입을 굳이 명시하지 않아도 됩니다. 다음 코드를 보겠습니다.

```julia
function square(x)
    return x * x
end

println(square(3))      # 정수를 넣으면 정수 결과
println(square(3.5))    # 실수를 넣으면 실수 결과
```

이처럼 `square` 함수는 정수든 실수든 가리지 않고 받아들입니다. 이것이 동적 타입(dynamic typing) 언어의 특징입니다. 변수나 함수 인자의 타입이 코드를 작성하는 시점이 아니라 프로그램이 실제로 실행되는 시점에 결정됩니다. 이런 유연함 덕분에 코드를 짧고 간결하게 쓸 수 있고, 아이디어를 빠르게 실험해 볼 수 있습니다.

문제는 일반적으로 이런 유연함에는 대가가 따른다는 점입니다. 전통적인 동적 타입 언어의 인터프리터는 코드를 실행할 때마다 "지금 이 변수의 타입이 무엇인지"를 매번 확인해야 하므로, 컴파일된 C 코드에 비해 실행 속도가 크게 떨어지는 경우가 많습니다. Julia는 이 문제를 JIT(Just-In-Time) 컴파일이라는 방식으로 풀어냅니다.

Julia는 함수가 처음 호출되는 순간, 그 호출에 사용된 인자들의 실제 타입을 파악합니다. 예를 들어 `square(3)`이 호출되면 Julia는 "인자가 `Int64` 타입일 때의 `square` 함수"를 위한 전용 기계어 코드를 그 자리에서 생성합니다. 이 과정에서 Julia는 LLVM이라는 검증된 컴파일러 인프라를 사용합니다. LLVM은 Clang(C/C++ 컴파일러)을 비롯한 여러 고성능 컴파일러의 백엔드로 널리 쓰이는 도구로, 다양한 하드웨어에 최적화된 기계어를 생성하는 데 특화되어 있습니다. 이렇게 한 번 컴파일된 코드는 이후 같은 타입 조합으로 함수가 다시 호출될 때 재사용되므로, 두 번째 호출부터는 인터프리터 방식과 비교할 수 없을 정도로 빠르게 실행됩니다.

만약 이후에 `square(3.5)`처럼 실수 인자로 같은 함수를 호출하면, Julia는 "인자가 `Float64` 타입일 때의 `square` 함수"를 위한 또 다른 전용 코드를 새로 생성합니다. 즉 하나의 함수 정의로부터 실제로 사용되는 타입 조합마다 최적화된 여러 개의 기계어 버전이 만들어지는 것입니다. 이 과정을 특수화(specialization)라고 부르며, Julia가 동적 타입 언어이면서도 정적 타입 언어에 준하는 속도를 낼 수 있는 핵심 비결입니다.

정리하면 Julia는 소스 코드를 작성하는 개발자에게는 동적 타입 언어처럼 유연한 경험을 제공하면서, 내부적으로는 실행 직전에 타입을 확정하고 그에 맞는 최적화된 기계어를 만들어냄으로써 정적 타입 언어에 버금가는 성능을 이끌어냅니다. "쉽게 쓰지만 느리다"와 "빠르지만 쓰기 어렵다"라는 양자택일 구도를 깨는 것, 이것이 Julia가 두 언어 문제를 해결하는 구체적인 방법입니다.

## 과학 계산과 데이터 과학의 언어

Julia는 처음 설계될 때부터 수치 계산과 과학 계산을 염두에 두고 만들어졌습니다. 이 점은 언어 곳곳에서 확인할 수 있습니다.

먼저 문법 수준에서부터 수학 표기와 가깝게 코드를 쓸 수 있도록 배려되어 있습니다. 예를 들어 Julia는 유니코드 문자를 변수명이나 연산자로 사용할 수 있어서, 수식을 코드로 옮길 때 논문에 쓰인 그리스 문자나 수학 기호를 거의 그대로 사용할 수 있습니다. 이 책의 예제는 일관성을 위해 기본적으로 ASCII 문자로 이름을 짓지만, Julia 자체는 이런 표현력을 언어 차원에서 지원한다는 점은 알아둘 필요가 있습니다.

또한 Julia는 배열과 행렬 연산을 언어의 1급 시민으로 다룹니다. 배열끼리 더하거나 배열에 함수를 원소별로 적용하는 브로드캐스팅 연산이 아주 자연스럽게 문법에 녹아들어 있는데, 이 내용은 8장에서 자세히 다룹니다. MATLAB이나 NumPy를 사용해 본 경험이 있다면 비슷한 느낌을 받겠지만, Julia는 이런 연산조차도 앞서 설명한 JIT 컴파일과 특수화를 통해 별도의 라이브러리 호출 없이도 빠르게 실행합니다. 즉 "배열 연산이라서 빠르다"가 아니라 "Julia로 작성한 코드 자체가 빠르기 때문에 배열 연산도 빠르다"는 점이 다른 언어의 과학 계산 생태계와 구별되는 지점입니다.

이런 특징들 덕분에 Julia는 물리학, 생물정보학, 계량경제학, 기계공학 시뮬레이션, 금융 공학, 기계 학습 등 대규모 수치 계산이 필요한 다양한 분야에서 점점 더 널리 쓰이고 있습니다. 특히 미분방정식을 풀어야 하는 시뮬레이션 분야나, 최적화 문제를 반복적으로 계산해야 하는 데이터 과학 분야에서 "Python으로 프로토타입을 만들고 C++로 다시 작성한다"는 전통적인 워크플로 대신 "Julia 하나로 처음부터 끝까지 작성한다"는 방식을 채택하는 사례가 늘어나고 있습니다.

## 다중 디스패치: Julia의 핵심 설계 철학 맛보기

Julia를 다른 언어와 구별짓는 가장 독특한 설계 철학을 하나만 꼽으라면, 그것은 다중 디스패치(multiple dispatch)입니다. 이 개념은 10장에서 본격적으로 다루지만, Julia라는 언어의 정체성을 이해하려면 지금 단계에서 맛보기 정도는 짚고 넘어갈 필요가 있습니다.

많은 객체지향 언어에서는 하나의 메서드가 어떤 함수로 실행될지가 첫 번째 인자, 흔히 `self`나 `this`로 불리는 객체의 타입 하나에 의해서만 결정됩니다. 이를 단일 디스패치(single dispatch)라고 부릅니다. 반면 Julia는 함수에 전달되는 모든 인자의 타입 조합을 보고 실제로 실행할 코드를 결정합니다. 다음의 간단한 예를 보겠습니다.

```julia
combine(x::Int, y::Int) = x + y
combine(x::String, y::String) = x * y   # 문자열은 * 로 이어붙임
combine(x::Int, y::String) = "$x" * y

println(combine(1, 2))          # 3
println(combine("가", "나"))     # 가나
println(combine(1, "번"))        # 1번
```

여기서 `combine`이라는 이름은 하나지만, 실제로는 인자의 타입 조합에 따라 서로 다른 세 개의 메서드 중 하나가 선택되어 실행됩니다. 정수 두 개가 들어오면 덧셈을, 문자열 두 개가 들어오면 이어붙이기를, 정수와 문자열이 섞여 들어오면 또 다른 방식을 적용하도록 정의할 수 있는 것입니다. 이처럼 첫 번째 인자뿐 아니라 모든 인자의 타입을 함께 고려해서 어떤 코드를 실행할지 결정하는 방식이 바로 다중 디스패치입니다.

다중 디스패치는 단순히 함수를 여러 버전으로 오버로딩하는 문법적 편의 기능이 아닙니다. Julia의 표준 라이브러리와 패키지 생태계 전체가 이 원리를 바탕으로 구성되어 있어서, 서로 다른 패키지가 정의한 타입들도 별다른 접착 코드 없이 자연스럽게 함께 동작하는 경우가 많습니다. 예를 들어 한 패키지가 새로운 수 타입을 정의하고, 다른 패키지가 행렬 연산 함수를 정의했다면, 그 수 타입을 담은 행렬을 그 함수에 넣었을 때도 대체로 잘 동작합니다. 두 패키지의 개발자가 서로의 존재를 몰랐어도 말입니다. 이 놀라운 상호운용성이 어떻게 가능한지는 10장에서 타입 시스템과 함께 자세히 다루겠습니다.

## 다른 언어들과 비교한 Julia의 위치

지금까지 설명한 내용을 바탕으로, Julia가 흔히 비교되는 세 언어와 어떤 관계에 있는지 간단히 정리해 보겠습니다.

**Python과 비교하면**, 둘 다 배우기 쉬운 문법과 대화형 개발 환경을 제공한다는 공통점이 있습니다. 실제로 Julia의 REPL이나 스크립트 작성 흐름은 Python 사용자에게 낯설지 않을 것입니다. 다만 Python은 인터프리터 방식으로 동작하며 순수 Python 코드만으로는 반복이 많은 수치 계산에서 속도가 느린 경우가 많아, NumPy나 Pandas처럼 내부가 C로 구현된 라이브러리에 크게 의존합니다. 반면 Julia는 별도의 저수준 라이브러리 없이도 순수 Julia 코드 자체가 빠르게 컴파일되어 실행되므로, "라이브러리가 제공하는 기능 안에서만 빠르다"는 제약에서 상대적으로 자유롭습니다.

**MATLAB과 비교하면**, 두 언어 모두 행렬과 배열 연산을 언어의 핵심에 두고 설계되었다는 점에서 닮아 있습니다. 과학 계산 및 공학 시뮬레이션 커뮤니티에서 MATLAB을 사용하던 사용자라면 Julia의 배열 문법이 친숙하게 느껴질 것입니다. 차이점이라면 MATLAB은 상용 소프트웨어로 라이선스 비용이 발생하는 반면, Julia는 오픈소스로 무료로 사용할 수 있습니다. 또한 Julia는 범용 프로그래밍 언어로 설계되어 있어 수치 계산 이외의 영역, 예를 들어 웹 서버나 일반적인 소프트웨어 개발에도 폭넓게 활용될 수 있습니다.

**C(또는 C++, Fortran)와 비교하면**, 이들은 오랫동안 고성능 계산의 표준으로 자리잡아 온 언어들입니다. 정적 타입과 수동 메모리 관리를 통해 매우 빠른 실행 속도를 보장하지만, 그만큼 코드를 작성하고 디버깅하는 데 드는 시간과 노력이 큽니다. Julia는 이 언어들만큼 최적화된 상황에서는 근접한 성능을 낼 수 있으면서도, 변수의 타입을 매번 선언하거나 메모리를 직접 관리할 필요가 없어 개발 생산성이 훨씬 높습니다. 즉 Julia는 "C만큼 빠르게, Python만큼 쉽게"라는 목표를 세운 언어이며, 이 책 전체를 통해 그 목표가 실제로 어떻게 언어 설계에 구현되어 있는지를 하나씩 확인해 나가게 될 것입니다.

물론 Julia가 모든 상황에서 다른 언어들을 완전히 대체하는 것은 아닙니다. 각 언어는 오랜 시간에 걸쳐 구축된 고유의 생태계와 커뮤니티를 가지고 있고, 프로젝트의 특성에 따라 적합한 도구는 달라질 수 있습니다. 다만 "쉽게 쓸 수 있는 언어"와 "빠르게 실행되는 언어" 사이의 간극을 좁히려는 시도라는 점에서, Julia는 분명히 주목할 만한 독자적인 위치를 차지하고 있습니다.

## 요약

- Julia는 2012년 MIT에서 공개된 언어로, 프로토타입 작성 언어와 고성능 언어를 따로 써야 했던 "두 언어 문제"를 해결하기 위해 설계되었습니다.
- Julia는 동적 타입 언어처럼 유연한 문법을 제공하면서도, LLVM 기반의 JIT 컴파일과 타입 특수화를 통해 정적 타입 언어에 준하는 실행 속도를 냅니다.
- 함수가 호출될 때 인자의 실제 타입을 바탕으로 전용 기계어 코드를 생성하고 재사용하는 것이 Julia가 빠른 핵심 원리입니다.
- 언어 설계 초기부터 배열 연산과 수치 계산을 염두에 두었기 때문에 과학 계산, 데이터 과학, 시뮬레이션 분야에서 널리 활용됩니다.
- 다중 디스패치는 함수의 모든 인자 타입 조합을 보고 실행할 코드를 결정하는 Julia의 핵심 설계 철학이며, 서로 다른 패키지 간의 자연스러운 상호운용성을 가능하게 합니다. 자세한 내용은 10장에서 다룹니다.
- Julia는 Python의 쉬운 문법, MATLAB의 배열 중심 사고, C의 실행 속도라는 장점들을 하나의 언어 안에 모으려는 시도로 이해할 수 있습니다.

## 연습문제

1. "두 언어 문제"란 무엇인지, 그리고 이 문제가 실제 프로젝트에서 어떤 불편함을 만들어내는지 자신의 말로 설명해 보세요.
2. 동적 타입 언어와 정적 타입 언어의 차이를 설명하고, Julia가 두 방식의 장점을 어떻게 함께 취하고 있는지 서술해 보세요.
3. JIT 컴파일에서 "특수화(specialization)"라는 개념이 무엇을 의미하는지, 그리고 이것이 왜 실행 속도 향상으로 이어지는지 설명해 보세요.
4. 이번 장에서 본 `combine` 함수 예제를 참고하여, 인자의 타입에 따라 서로 다르게 동작해야 할 것 같은 자신만의 함수 아이디어를 하나 떠올리고, 어떤 타입 조합에 대해 어떤 동작을 정의하고 싶은지 말로 설명해 보세요. (실제 코드 작성은 7장과 10장에서 다시 다룹니다.)
5. Julia를 Python, MATLAB, C 중 하나와 비교했을 때, 자신이 관심 있는 분야(예: 데이터 분석, 시뮬레이션, 웹 개발 등)에서 Julia를 선택하면 어떤 장단점이 있을지 생각해 보세요.
