# 11장. 구조체와 사용자 정의 타입

[◀ 이전: 10장. 다중 디스패치](ch10-다중디스패치.md) | [📖 목차](00-목차.md) | [다음: 12장. 컬렉션(튜플, 딕셔너리, 세트) ▶](ch12-컬렉션.md)


9장에서는 Julia가 `Int64`, `Float64`, `String`처럼 다양한 내장 타입과 그 타입들 사이의 추상 타입 계층을 어떻게 구성하는지 살펴보았습니다. 10장에서는 그 타입 정보를 활용해 하나의 함수 이름 아래 인자 타입에 따라 서로 다른 동작을 연결하는 다중 디스패치를 배웠습니다. 하지만 지금까지 다룬 타입은 모두 Julia가 이미 정의해 둔 것들이었습니다. 이번 장에서는 한 걸음 더 나아가, 우리가 직접 새로운 타입을 만들고 그 타입에 대해 다중 디스패치를 적용하는 방법을 배웁니다. 좌표 위의 점(`Point`)이나 도형(`Circle`, `Rectangle`) 같은 예제를 통해 `struct`로 데이터를 묶고, 그 데이터에 대한 동작을 함수로 정의하는 Julia 특유의 스타일을 익혀보겠습니다.

## 사용자 정의 타입이 필요한 이유

점 하나의 좌표를 표현한다고 생각해 봅시다. x와 y 두 값을 따로따로 변수에 담을 수도 있습니다.

```julia
x1, y1 = 3.0, 4.0
x2, y2 = 0.0, 0.0

# 두 점 사이의 거리 계산
distance = sqrt((x1 - x2)^2 + (y1 - y2)^2)
println(distance)  # 5.0
```

점이 하나 둘일 때는 이런 방식도 괜찮지만, 점이 여러 개로 늘어나거나 점을 함수의 인자로 주고받아야 한다면 금방 한계가 드러납니다. `x1`, `y1`이 한 점을 이룬다는 사실은 오직 변수 이름의 규칙("1"이 붙어 있다는 것)에만 의존하고 있고, 실수로 `x1`과 `y2`를 짝지어 계산해도 Julia는 이를 막아주지 않습니다. 12장에서 배울 튜플로 `(3.0, 4.0)`처럼 묶을 수도 있지만, 튜플은 각 원소가 무엇을 의미하는지 이름으로 알려주지 않습니다.

이럴 때 필요한 것이 사용자 정의 타입입니다. `struct` 키워드로 "점은 x와 y로 이루어진다"는 사실 자체를 타입으로 선언하면, 이후로는 `Point`라는 이름 하나로 좌표를 안전하게 묶어서 다룰 수 있습니다.

## 불변 구조체: struct

`struct` 키워드는 여러 개의 값을 필드(field)로 묶은 새로운 타입을 정의합니다. 필드는 이름과 타입을 `이름::타입` 형태로 적습니다.

```julia
struct Point
    x::Float64
    y::Float64
end
```

이렇게 정의하면 Julia는 필드 값을 순서대로 받는 생성자를 자동으로 만들어 줍니다. 이를 기본 생성자(default constructor) 또는 외부 생성자(outer constructor)라고 부릅니다.

```julia
p = Point(3.0, 4.0)

println(p.x)          # 3.0
println(p.y)          # 4.0
println(typeof(p))    # Point
println(p isa Point)  # true

fieldnames(Point)     # (:x, :y)
```

필드 값은 점(`.`) 표기법으로 읽습니다. 정수 `3`을 넘겨도 Julia가 `Float64`로 자동 변환해 주므로 `Point(3, 4)`처럼 호출해도 문제없이 동작합니다.

`struct`로 정의한 타입은 기본적으로 불변(immutable)입니다. 한 번 만든 인스턴스의 필드 값은 이후에 바꿀 수 없습니다.

```julia
p = Point(3.0, 4.0)
p.x = 10.0
# ERROR: setfield!: immutable struct of type Point cannot be changed
```

값을 바꾸고 싶다면 새 인스턴스를 만들어야 합니다.

```julia
p2 = Point(10.0, p.y)
```

이런 불변성은 제약처럼 보이지만 장점이 많습니다. `Point` 인스턴스를 함수에 넘기거나 여러 곳에서 공유해도 누군가 몰래 값을 바꿔버릴 걱정이 없고, Julia 컴파일러 입장에서도 "이 값은 절대 바뀌지 않는다"는 사실을 알고 있으면 더 공격적으로 최적화할 수 있습니다.

## 가변 구조체: mutable struct

반대로 시간이 지나며 상태가 바뀌어야 하는 대상도 있습니다. 은행 계좌를 생각해 보면, 잔액은 입금과 출금에 따라 계속 변해야 합니다. 이런 경우에는 `mutable struct`를 사용합니다.

```julia
mutable struct BankAccount
    owner::String
    balance::Float64
end
```

```julia
acc = BankAccount("김하나", 10_000.0)

acc.balance += 5_000.0   # 입금
println(acc.balance)     # 15000.0

acc.balance -= 3_000.0   # 출금
println(acc.balance)     # 12000.0
```

`mutable struct`로 정의한 타입은 필드에 새 값을 대입할 수 있다는 점만 빼면 `struct`와 사용법이 동일합니다. 다만 가변 구조체의 인스턴스는 여러 변수가 같은 객체를 참조할 수 있다는 점을 주의해야 합니다.

```julia
acc2 = acc                # acc2는 acc와 같은 객체를 가리킨다
acc2.balance += 1_000.0
println(acc.balance)      # 13000.0 - acc도 함께 바뀐다
```

이는 8장에서 배열을 다룰 때 보았던 참조 동작과 같은 원리입니다. 값이 그 자체로 의미를 가지며 절대 바뀌지 않아야 한다면 `struct`를, 시간에 따라 상태가 바뀌는 대상을 표현한다면 `mutable struct`를 선택하는 것이 좋은 기준입니다.

## 필드 타입 명시와 타입 안정성

`Point`와 `BankAccount`의 필드는 모두 `::Float64`, `::String`처럼 구체적인 타입을 명시했습니다. 필드 타입을 생략하면 어떻게 될까요?

```julia
struct LoosePoint
    x
    y
end
```

타입을 적지 않은 필드는 `x::Any`, `y::Any`와 같습니다. 즉 `LoosePoint`의 필드에는 정수, 문자열, 배열 등 무엇이든 들어갈 수 있습니다.

```julia
LoosePoint(3.0, 4.0)    # 가능
LoosePoint("x", [1, 2]) # 이것도 가능 - 의도한 사용이 아닐 수 있다
```

유연해 보이지만 대가가 따릅니다. 필드 타입이 `Any`이면 Julia 컴파일러는 그 필드에 실제로 어떤 타입의 값이 들어올지 미리 알 수 없기 때문에, 필드에 접근할 때마다 실제 타입을 확인하고 값을 박싱(boxing)된 형태로 다뤄야 합니다. 반면 `Point`처럼 필드 타입을 구체 타입(concrete type)으로 명시해두면 컴파일러가 메모리 레이아웃과 연산을 미리 특수화(specialize)할 수 있어 실행 속도가 훨씬 빨라집니다.

```julia
struct Point
    x::Float64  # 구체 타입 - 빠르다
    y::Float64
end

struct LoosePoint
    x  # Any와 동일 - 느리다
    y
end
```

이렇게 타입이 코드 실행 경로를 예측 가능하게 만들어 주는 성질을 타입 안정성(type stability)이라고 부르며, 16장 "성능 최적화 기초"에서 본격적으로 다룹니다. 지금 단계에서는 "구조체를 정의할 때는 되도록 필드마다 구체적인 타입을 명시한다"는 습관만 기억해 두면 충분합니다.

## 내부 생성자로 유효성 검사하기

지금까지 본 기본 생성자는 값을 받아 그대로 필드에 채워 넣을 뿐, 값이 올바른지는 전혀 검사하지 않습니다. 예를 들어 반지름이 음수인 원도 만들어질 수 있다는 뜻입니다. 이런 문제를 막으려면 내부 생성자(inner constructor)를 직접 정의합니다.

먼저 여러 도형을 아우르는 추상 타입을 하나 선언해 두겠습니다. 9장에서 다룬 추상 타입은 구체 타입들을 하나의 이름 아래 묶어주는 역할을 했는데, 이번에는 우리가 직접 만든 구체 타입들을 묶는 데 사용합니다.

```julia
abstract type Shape end
```

이제 `Shape`의 하위 타입으로 `Circle`을 정의하면서, 내부 생성자로 반지름이 양수인지 검사해 보겠습니다.

```julia
struct Circle <: Shape
    radius::Float64

    function Circle(radius)
        radius > 0 || error("반지름은 양수여야 합니다: $radius")
        new(radius)
    end
end
```

`struct` 본문 안에 타입 이름과 똑같은 이름의 함수를 정의하면 그것이 내부 생성자가 됩니다. 내부 생성자 안에서만 쓸 수 있는 `new` 함수는 검사를 통과한 값으로 실제 인스턴스를 만들어 냅니다. 한 가지 중요한 규칙은, 내부 생성자를 하나라도 정의하면 Julia가 자동으로 만들어 주던 기본 생성자는 더 이상 제공되지 않는다는 점입니다. 즉 `Circle`의 인스턴스는 오직 이 검사를 통과해야만 만들어질 수 있습니다.

```julia
c1 = Circle(2.0)
println(c1.radius)   # 2.0

c2 = Circle(-1.0)
# ERROR: 반지름은 양수여야 합니다: -1.0
```

같은 방식으로 너비와 높이가 모두 양수여야 하는 `Rectangle`도 정의할 수 있습니다.

```julia
struct Rectangle <: Shape
    width::Float64
    height::Float64

    function Rectangle(width, height)
        (width > 0 && height > 0) || error("너비와 높이는 양수여야 합니다")
        new(width, height)
    end
end
```

내부 생성자가 있어도 편의를 위한 추가 생성자를 바깥에 따로 정의할 수 있습니다. 예를 들어 너비와 높이가 같은 정사각형을 간단히 만들고 싶다면 다음처럼 외부 생성자를 추가합니다.

```julia
Rectangle(side) = Rectangle(side, side)
```

이 외부 생성자는 결국 내부에서 검증을 마친 `Rectangle(side, side)`를 호출하므로, 검증 로직을 중복해서 작성할 필요가 없습니다.

## 다중 디스패치와 사용자 정의 타입

이제 `Circle`과 `Rectangle`이라는 서로 다른 두 타입이 `Shape`라는 공통 추상 타입 아래 놓여 있습니다. 10장에서 배운 다중 디스패치는 여기서 진가를 발휘합니다. 각 도형에 대해 넓이를 구하는 방법은 다르지만, 함수 이름은 `area` 하나로 통일할 수 있습니다.

```julia
area(c::Circle) = π * c.radius^2
area(r::Rectangle) = r.width * r.height

perimeter(c::Circle) = 2π * c.radius
perimeter(r::Rectangle) = 2 * (r.width + r.height)
```

```julia
c = Circle(2.0)
r = Rectangle(3.0, 4.0)

println(area(c))       # 12.566370614359172
println(area(r))       # 12.0
println(perimeter(c))  # 12.566370614359172
println(perimeter(r))  # 14.0
```

`area(c)`를 호출하면 Julia는 인자 `c`의 타입이 `Circle`이라는 것을 보고 `area(c::Circle)` 메서드를 선택합니다. 새로운 도형 타입, 예를 들어 `Triangle`을 추가하고 싶다면 기존 `Circle`이나 `Rectangle` 코드를 전혀 건드리지 않고 `area(t::Triangle)` 메서드 하나만 새로 추가하면 됩니다.

`Shape`라는 공통 타입이 있으므로 여러 도형을 한 배열에 담아 다룰 수도 있습니다.

```julia
shapes = Shape[Circle(2.0), Rectangle(3.0, 4.0), Circle(1.0)]

for s in shapes
    println("$(typeof(s)) 넓이: $(area(s))")
end
```

8장에서 배운 브로드캐스팅으로도 같은 결과를 얻을 수 있습니다.

```julia
areas = area.(shapes)   # 각 도형에 area를 개별 적용
println(areas)          # [12.566370614359172, 12.0, 3.141592653589793]
```

`area`와 `perimeter`처럼 구체 타입마다 다른 메서드를 정의하는 대신, `Shape`를 받는 함수 하나로 공통 동작을 표현할 수도 있습니다.

```julia
function describe(s::Shape)
    println("넓이: $(area(s)), 둘레: $(perimeter(s))")
end

describe(c)  # 넓이: 12.566370614359172, 둘레: 12.566370614359172
describe(r)  # 넓이: 12.0, 둘레: 14.0
```

`describe`는 인자 타입을 `Shape`로 선언했기 때문에 `Circle`이든 `Rectangle`이든, 심지어 나중에 추가할 `Triangle`이든 상관없이 동작합니다. 함수 내부에서 호출하는 `area(s)`와 `perimeter(s)`는 그 시점에 `s`의 실제 타입을 보고 다시 한번 다중 디스패치로 알맞은 메서드를 찾아갑니다. 이렇게 "추상 타입을 받는 일반적인 함수"와 "구체 타입마다 다르게 동작하는 세부 메서드"를 조합하는 것이 Julia에서 다형성을 다루는 전형적인 방식입니다.

## Base 함수를 확장해 출력 형식 꾸미기

지금까지 `println`으로 `Circle`이나 `Rectangle` 값을 출력하면 `Circle(2.0)`처럼 필드가 그대로 나열되는 기본 표현이 사용되었습니다. Julia는 값을 화면에 표시하는 방법도 `show`라는 함수 하나로 통일해 두었기 때문에, 우리 타입에 대한 `show` 메서드를 추가하면 출력 형식을 바꿀 수 있습니다.

```julia
function Base.show(io::IO, c::Circle)
    print(io, "반지름 $(c.radius)인 원")
end

c = Circle(2.0)
println(c)        # 반지름 2.0인 원
```

`Base.show`처럼 이미 존재하는 함수에 우리 타입을 위한 메서드를 추가하는 것 역시 다중 디스패치입니다. Julia의 표준 라이브러리에 있는 `println`, `print`, REPL의 자동 출력(2장 참고)은 모두 내부적으로 `show`를 호출하도록 만들어져 있으므로, `show` 메서드 하나만 추가해도 값을 출력하는 모든 경로에 일관되게 반영됩니다.

## struct와 mutable struct 중 무엇을 선택할까

정리하면 다음과 같은 기준으로 선택하면 됩니다.

- **struct(불변)**: 좌표, 색상, 날짜처럼 "값 그 자체"를 표현하고, 한 번 만들어지면 바뀔 이유가 없는 데이터. 안전하고, 컴파일러 최적화에도 유리합니다.
- **mutable struct(가변)**: 계좌 잔액, 게임 캐릭터의 체력처럼 시간에 따라 상태가 바뀌어야 하는 데이터. 다만 여러 변수가 같은 인스턴스를 참조할 수 있다는 점을 염두에 두어야 합니다.

특별한 이유가 없다면 `struct`를 기본으로 사용하고, 정말로 필드를 나중에 바꿔야 하는 경우에만 `mutable struct`로 전환하는 것이 좋은 습관입니다.

## 요약

이번 장에서는 `struct`와 `mutable struct`로 우리만의 타입을 정의하는 방법을 배웠습니다. `struct`는 한 번 만들면 필드를 바꿀 수 없는 불변 타입을, `mutable struct`는 필드를 자유롭게 수정할 수 있는 가변 타입을 만듭니다. 필드는 `이름::타입` 형태로 구체 타입을 명시하는 것이 좋으며, 이는 코드를 읽기 쉽게 할 뿐 아니라 16장에서 다룰 성능에도 직접적인 영향을 줍니다. 타입 이름과 같은 이름의 함수를 구조체 본문 안에 정의하면 내부 생성자가 되며, `new` 함수와 조건 검사를 조합해 유효하지 않은 값으로 인스턴스가 만들어지는 것을 막을 수 있습니다. 마지막으로 `Circle`, `Rectangle`을 공통 추상 타입 `Shape`로 묶고 `area`, `perimeter` 같은 함수에 여러 메서드를 정의함으로써, 10장에서 배운 다중 디스패치가 사용자 정의 타입에도 그대로 적용된다는 것을 확인했습니다. 다음 장에서는 여러 값을 묶는 또 다른 방법인 튜플, 네임드 튜플, 딕셔너리, 세트 같은 컬렉션을 살펴봅니다.

## 연습문제

1. `x::Float64`, `y::Float64`, `z::Float64` 필드를 가진 불변 구조체 `Point3D`를 정의하고, 원점 `(0.0, 0.0, 0.0)`으로부터의 거리를 구하는 함수 `distance_from_origin(p::Point3D)`를 작성하세요.
2. `mutable struct`로 `Counter`를 정의하세요(필드: `count::Int`). 카운트를 1 증가시키는 함수 `increment!(c::Counter)`와 현재 값을 반환하는 함수 `value(c::Counter)`를 작성해 보세요. (함수 이름 끝의 `!`가 무엇을 의미하는지는 7장을 참고하세요.)
3. 삼각형을 표현하는 구조체 `Triangle`(변의 길이 `a`, `b`, `c`)을 정의하고, 내부 생성자에서 삼각형 부등식(어느 한 변도 나머지 두 변의 합보다 크거나 같으면 안 됨)을 검사하도록 만드세요. 헤론의 공식을 이용해 `area(t::Triangle)` 메서드도 작성하세요.
4. 이번 장의 `Shape` 계층에 `Triangle <: Shape`를 추가하고 `area`, `perimeter` 메서드를 구현한 뒤, `Circle`, `Rectangle`, `Triangle`을 모두 담은 배열을 만들어 넓이가 가장 큰 도형을 찾는 코드를 작성하세요.
5. 필드 타입을 명시한 구조체와 명시하지 않은 구조체를 각각 정의하고 인스턴스를 만든 뒤, `typeof(instance.x)`로 필드에 실제로 들어 있는 값의 타입을, `fieldtype(구조체이름, :x)`로 필드에 선언된 타입을 각각 확인해 두 결과가 어떻게 다른지 비교해 보세요.
