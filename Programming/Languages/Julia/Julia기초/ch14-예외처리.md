# 14장. 예외 처리

[◀ 이전: 13장. 모듈과 패키지 관리](ch13-모듈과패키지관리.md) | [📖 목차](00-목차.md) | [다음: 15장. 매크로 기초 ▶](ch15-매크로기초.md)


프로그램을 작성하다 보면 예상치 못한 상황을 마주치기 마련입니다. 존재하지 않는 파일을 열려고 하거나, 배열의 범위를 벗어난 인덱스에 접근하거나, 0으로 나누는 연산을 시도할 수도 있습니다. Julia는 이런 상황을 **예외(exception)**라는 형태로 표현하고, 프로그램이 무작정 멈추는 대신 상황에 맞게 대처할 수 있도록 `try`/`catch`/`finally` 구문을 제공합니다. 이번 장에서는 예외를 잡아 처리하는 방법, 직접 예외를 발생시키는 방법, 그리고 나만의 예외 타입을 정의하는 방법까지 살펴봅니다.

## 14.1 예외란 무엇인가

지금까지 작성한 코드에서도 이미 여러 차례 예외를 만난 적이 있습니다. 예를 들어 3장에서 타입이 맞지 않는 값을 대입했을 때 발생했던 `InexactError`도 예외의 한 종류입니다.

```julia
julia> arr = [1, 2, 3]
julia> arr[10]
ERROR: BoundsError: attempt to access 3-element Vector{Int64} at index [10]
```

이처럼 프로그램 실행 중 정상적인 흐름을 이어갈 수 없는 상황이 발생하면 Julia는 예외를 **던지고(throw)**, 별도의 처리가 없다면 프로그램(혹은 REPL의 현재 입력)은 오류 메시지를 출력하며 중단됩니다. 하지만 항상 프로그램을 중단시키는 것이 최선은 아닙니다. 파일이 없으면 기본값을 사용하거나, 사용자에게 다시 입력을 요청하는 등 예외를 잡아서 적절히 대응하고 싶은 경우가 많습니다. 이럴 때 사용하는 것이 `try`/`catch`입니다.

## 14.2 try/catch/finally 구조

`try` 블록 안의 코드를 실행하다가 예외가 발생하면, 프로그램은 즉시 `catch` 블록으로 넘어가 예외를 처리합니다.

```julia
julia> try
           x = 10
           y = 0
           println(x / y)
       catch
           println("오류가 발생했습니다")
       end
Inf
```

방금 예제에서는 오류 메시지가 출력되지 않고 `Inf`가 출력되었습니다. Julia에서 부동소수점 나눗셈 `10 / 0`은 예외를 던지지 않고 무한대를 뜻하는 `Inf`를 반환하기 때문입니다. 정수 나눗셈에서 실제로 예외가 발생하는 경우를 살펴보겠습니다.

```julia
julia> try
           x = div(10, 0)
           println(x)
       catch
           println("0으로 나눌 수 없습니다")
       end
0으로 나눌 수 없습니다
```

`div()`는 정수 나눗셈을 수행하는 함수인데, 두 번째 인자로 0이 들어오면 `DivideError`를 던집니다. `try` 블록에서 이 예외가 발생하자 곧바로 `catch` 블록이 실행된 것을 볼 수 있습니다.

### finally: 항상 실행되는 블록

`finally` 블록을 추가하면, 예외가 발생했는지 여부와 관계없이 항상 실행되는 코드를 지정할 수 있습니다. 파일을 닫거나 자원을 정리하는 등 반드시 수행해야 하는 마무리 작업에 사용합니다.

```julia
julia> try
           println("작업을 시작합니다")
           error("문제가 발생했습니다")
       catch e
           println("예외를 처리합니다: ", e)
       finally
           println("정리 작업을 수행합니다")
       end
작업을 시작합니다
예외를 처리합니다: ErrorException("문제가 발생했습니다")
정리 작업을 수행합니다
```

`error()` 함수는 문자열 메시지를 담은 `ErrorException`을 즉시 던지는 간단한 방법입니다. 위 예제에서 `finally` 블록은 `catch`에서 예외를 처리한 뒤에도 정상적으로 실행되었습니다. 만약 `catch` 블록이 아예 없어서 예외가 처리되지 않고 그대로 전파되는 경우에도, `finally` 블록은 프로그램이 중단되기 직전에 실행됩니다.

`try`/`catch`/`finally`는 세 부분을 모두 갖출 수도 있고, 상황에 따라 `catch` 없이 `finally`만 쓰거나 `finally` 없이 `catch`만 쓸 수도 있습니다.

## 14.3 throw로 예외 발생시키기

`throw()` 함수를 사용하면 원하는 시점에 직접 예외를 발생시킬 수 있습니다. 함수의 인자가 유효하지 않을 때 이를 알리는 용도로 자주 사용됩니다.

```julia
julia> function withdraw(balance, amount)
           if amount > balance
               throw(ArgumentError("인출 금액이 잔액을 초과합니다"))
           end
           return balance - amount
       end
withdraw (generic function with 1 method)

julia> withdraw(1000, 500)
500

julia> withdraw(1000, 2000)
ERROR: ArgumentError: 인출 금액이 잔액을 초과합니다
```

`error()`는 항상 `ErrorException`을 던지는 반면, `throw()`는 어떤 종류의 예외든 던질 수 있다는 점에서 더 유연합니다. 상황에 맞는 구체적인 예외 타입을 골라 던지면, 이 예외를 잡아 쓰는 쪽에서도 어떤 문제가 생겼는지 더 명확하게 파악할 수 있습니다.

## 14.4 내장 예외 타입들

Julia는 흔히 발생하는 오류 상황에 대응하는 다양한 내장 예외 타입을 미리 정의해 두었습니다. 자주 쓰이는 몇 가지를 살펴보겠습니다.

### ArgumentError

함수에 전달된 인자의 값이 유효하지 않을 때 사용합니다.

```julia
julia> function set_age(age)
           if age < 0
               throw(ArgumentError("나이는 음수가 될 수 없습니다"))
           end
           return age
       end
set_age (generic function with 1 method)

julia> set_age(-5)
ERROR: ArgumentError: 나이는 음수가 될 수 없습니다
```

### BoundsError

배열이나 문자열 등에서 유효한 범위를 벗어난 인덱스에 접근하려 할 때 자동으로 발생합니다.

```julia
julia> scores = [90, 85, 77]
julia> scores[5]
ERROR: BoundsError: attempt to access 3-element Vector{Int64} at index [5]
```

### DomainError

수학적으로 정의되지 않은 입력값이 함수에 전달되었을 때 발생합니다. 예를 들어 음수의 제곱근은 실수 범위에서 정의되지 않습니다.

```julia
julia> sqrt(-4)
ERROR: DomainError with -4.0:
sqrt was called with a negative real argument but will only return a complex result if called with a complex argument.
```

### 그 밖의 자주 만나는 예외 타입

| 타입 | 발생 상황 |
|---|---|
| `MethodError` | 주어진 타입 조합에 맞는 메서드가 없을 때 (10장 다중 디스패치 참고) |
| `KeyError` | 딕셔너리에 존재하지 않는 키로 접근할 때 (12장 참고) |
| `InexactError` | 값을 다른 타입으로 정확히 변환할 수 없을 때 (3장에서 살펴본 예) |
| `DivideError` | 정수 나눗셈에서 0으로 나누려 할 때 |
| `TypeError` | 예상한 타입과 다른 타입의 값이 사용되었을 때 |

각 예외 타입의 이름 자체가 어떤 문제가 발생했는지 알려주므로, 직접 예외를 던질 때도 무작정 `error()`를 쓰기보다는 상황에 가장 잘 맞는 내장 타입을 고르는 습관을 들이면 좋습니다.

## 14.5 catch로 예외 객체 다루기

`catch` 뒤에 변수 이름을 적으면 발생한 예외 객체를 그 변수에 담아 내용을 살펴볼 수 있습니다.

```julia
julia> try
           throw(ArgumentError("유효하지 않은 값입니다"))
       catch e
           println("예외 타입: ", typeof(e))
           println("메시지: ", e.msg)
       end
예외 타입: ArgumentError
메시지: 유효하지 않은 값입니다
```

예외 객체도 하나의 값이므로 `typeof()`로 타입을 확인할 수 있고, `e.msg`처럼 필드에 접근해 세부 정보를 꺼낼 수도 있습니다. 예외 타입마다 가지고 있는 필드가 다르므로, 어떤 필드가 있는지는 `fieldnames()`로 확인할 수 있습니다.

```julia
julia> fieldnames(ArgumentError)
(:msg,)

julia> fieldnames(BoundsError)
(:a, :i)
```

예외의 종류에 따라 다르게 대응하고 싶다면, `catch`로 잡은 예외의 타입을 `isa`로 검사해 분기할 수 있습니다.

```julia
julia> function safe_divide(a, b)
           try
               return div(a, b)
           catch e
               if e isa DivideError
                   println("0으로 나눌 수 없어 0을 반환합니다")
                   return 0
               else
                   rethrow(e)
               end
           end
       end
safe_divide (generic function with 1 method)

julia> safe_divide(10, 2)
5

julia> safe_divide(10, 0)
0으로 나눌 수 없어 0을 반환합니다
0
```

`rethrow()`는 잡은 예외를 처리하지 않고 다시 던지는 함수입니다. 예상하지 못한 종류의 예외까지 조용히 삼켜버리면 진짜 문제를 알아채기 어려워지므로, 위 예제처럼 처리할 수 있는 예외만 골라 대응하고 나머지는 `rethrow()`로 그대로 전파하는 방식이 안전합니다.

## 14.6 커스텀 예외 타입 정의하기

내장 예외 타입만으로는 애플리케이션 고유의 오류 상황을 충분히 표현하지 못할 때가 있습니다. 이럴 때는 `Exception`을 상속받는 새로운 구조체를 정의해 나만의 예외 타입을 만들 수 있습니다. 구조체를 정의하는 방법 자체는 11장에서 자세히 다루었으니, 여기서는 예외 타입에 특화된 부분을 살펴보겠습니다.

```julia
struct InsufficientBalanceError <: Exception
    balance::Float64
    amount::Float64
end
```

`<: Exception`은 `InsufficientBalanceError`가 `Exception` 타입을 상속(정확히는 서브타입화)한다는 뜻입니다. 이렇게 정의한 타입은 다른 예외와 마찬가지로 `throw()`로 던지고 `catch`로 잡을 수 있습니다.

```julia
julia> function withdraw(balance, amount)
           if amount > balance
               throw(InsufficientBalanceError(balance, amount))
           end
           return balance - amount
       end
withdraw (generic function with 1 method)

julia> withdraw(1000.0, 1500.0)
ERROR: InsufficientBalanceError(1000.0, 1500.0)
```

기본적으로는 필드 값을 그대로 나열한 형태로 출력되어 그다지 읽기 좋지 않습니다. 이 메시지를 사람이 읽기 좋은 형태로 바꾸려면 `Base.showerror()` 메서드를 오버라이드하면 됩니다.

### Base.showerror 오버라이드

```julia
function Base.showerror(io::IO, e::InsufficientBalanceError)
    print(io, "InsufficientBalanceError: 잔액 $(e.balance)원으로는 $(e.amount)원을 인출할 수 없습니다")
end
```

`Base.showerror`는 예외가 출력될 때 어떤 메시지를 보여줄지를 정의하는 함수입니다. `io`는 메시지를 써 넣을 출력 스트림이고, `e`는 출력할 예외 객체입니다. 이 메서드를 정의한 뒤 같은 예외를 다시 던져 보면 훨씬 읽기 좋은 메시지가 나옵니다.

```julia
julia> withdraw(1000.0, 1500.0)
ERROR: InsufficientBalanceError: 잔액 1000.0원으로는 1500.0원을 인출할 수 없습니다
```

`catch`로 잡았을 때도 이 메시지를 그대로 활용할 수 있습니다. 예외 객체를 문자열로 만들고 싶다면 `sprint(showerror, e)`를 사용합니다.

```julia
julia> try
           withdraw(1000.0, 1500.0)
       catch e
           println("거래 실패: ", sprint(showerror, e))
       end
거래 실패: InsufficientBalanceError: 잔액 1000.0원으로는 1500.0원을 인출할 수 없습니다
```

이처럼 커스텀 예외 타입은 단순히 오류가 발생했다는 사실뿐 아니라, 오류와 관련된 구체적인 데이터(위 예제의 `balance`, `amount`)까지 함께 담아 전달할 수 있다는 장점이 있습니다. 이 데이터는 `catch e` 이후 `e.balance`, `e.amount`처럼 필드로 바로 꺼내 쓸 수 있어서, 오류 로그를 남기거나 사용자에게 구체적인 안내를 보여줄 때 유용합니다.

## 14.7 @assert로 조건 검사하기

`@assert`는 주어진 조건이 참인지 확인하고, 거짓이면 `AssertionError`를 던지는 매크로입니다.

```julia
julia> function set_score(score)
           @assert score >= 0 "점수는 음수가 될 수 없습니다"
           @assert score <= 100 "점수는 100을 초과할 수 없습니다"
           return score
       end
set_score (generic function with 1 method)

julia> set_score(85)
85

julia> set_score(-10)
ERROR: AssertionError: 점수는 음수가 될 수 없습니다
```

`@assert 조건 "메시지"` 형태로 쓰면, 조건이 거짓일 때 지정한 메시지와 함께 오류가 발생합니다. 메시지를 생략하면 조건식 자체가 오류 메시지로 표시됩니다.

```julia
julia> @assert 1 + 1 == 3
ERROR: AssertionError: 1 + 1 == 3
```

`@assert`는 이름 앞에 `@`가 붙어 있는데, 이는 Julia의 **매크로(macro)**라는 특별한 기능입니다. 매크로는 일반 함수와 달리 코드 자체를 입력받아 변형하는 기능으로, 조건식이 거짓일 때 그 조건식을 그대로 오류 메시지에 담아 보여줄 수 있는 것도 매크로이기 때문에 가능한 일입니다. 매크로를 직접 만들고 활용하는 방법은 다음 15장에서 자세히 다룹니다.

`@assert`는 `throw(ArgumentError(...))`처럼 명시적으로 예외를 던지는 것과 비슷해 보이지만, 용도가 조금 다릅니다. `@assert`는 주로 "이 조건은 프로그램이 올바르게 동작한다면 당연히 참이어야 한다"는 개발자의 가정을 코드에 남겨 두고 검증하는 용도로 사용합니다. 반면 사용자 입력값 검증처럼 실행 중에 실제로 발생할 수 있는 오류 상황을 처리할 때는 `ArgumentError` 등을 명시적으로 `throw`하는 방식이 더 적합합니다. 또한 `@assert`는 성능이 중요한 코드에서 비활성화될 수 있으므로, 반드시 실행되어야 하는 검증 로직에는 사용하지 않는 것이 안전합니다.

## 요약

- `try`/`catch`/`finally` 구문으로 예외가 발생할 수 있는 코드를 감싸고, 발생 시 처리할 로직과 항상 실행할 정리 로직을 나눠서 작성할 수 있습니다.
- `throw()`로 원하는 시점에 예외를 직접 발생시킬 수 있으며, `error()`는 `ErrorException`을 던지는 간단한 방법입니다.
- Julia는 `ArgumentError`, `BoundsError`, `DomainError`, `KeyError`, `MethodError` 등 다양한 상황에 대응하는 내장 예외 타입을 제공합니다. 상황에 맞는 구체적인 타입을 골라 사용하면 오류의 원인을 더 명확히 전달할 수 있습니다.
- `catch e`로 잡은 예외 객체는 `typeof(e)`로 타입을, `e.필드이름`으로 세부 정보를 확인할 수 있습니다. 처리할 수 없는 예외는 `rethrow()`로 다시 던지는 것이 안전합니다.
- `struct MyError <: Exception ... end` 형태로 나만의 예외 타입을 정의할 수 있고, `Base.showerror()`를 오버라이드하면 예외가 출력될 때 보여줄 메시지를 원하는 대로 꾸밀 수 있습니다.
- `@assert 조건 "메시지"` 매크로는 조건이 거짓일 때 `AssertionError`를 던지며, 프로그램이 정상 동작한다면 당연히 참이어야 할 가정을 검증하는 용도로 사용합니다. 매크로에 대해서는 15장에서 자세히 다룹니다.

## 연습문제

1. 두 수를 입력받아 나눗셈을 수행하는 함수를 작성하되, `try`/`catch`를 사용해 두 번째 인자가 0일 때 `DivideError`를 잡아 "0으로 나눌 수 없습니다"라는 메시지를 출력하도록 만들어 보세요.
2. 나이를 인자로 받는 함수에서 나이가 0보다 작거나 150보다 크면 `ArgumentError`를 `throw`하도록 작성해 보세요. 그리고 이 함수를 `try`/`catch`로 감싸 예외가 발생했을 때 `e.msg`를 출력해 보세요.
3. `NegativeDepositError <: Exception`이라는 커스텀 예외 타입을 정의하고, 입금액이 음수일 때 이 예외를 던지는 `deposit(balance, amount)` 함수를 작성해 보세요. `Base.showerror`를 오버라이드해서 "입금액은 음수가 될 수 없습니다: -100.0원이 입력되었습니다"와 같은 형식의 메시지가 출력되도록 만들어 보세요.
4. `@assert`와 `throw(ArgumentError(...))`는 둘 다 조건을 검사해 오류를 발생시킨다는 점에서 비슷합니다. 두 방법을 각각 언제 사용하는 것이 더 적합한지 자신의 말로 설명해 보세요.
5. `finally` 블록이 왜 필요한지, `catch` 블록만으로는 처리할 수 없는 상황을 예로 들어 설명해 보세요. (힌트: 예외가 발생하지 않아도 반드시 실행되어야 하는 작업을 떠올려 보세요.)
