# 12장. 컬렉션(튜플, 딕셔너리, 세트)

[◀ 이전: 11장. 구조체와 사용자 정의 타입](ch11-구조체와사용자정의타입.md) | [📖 목차](00-목차.md) | [다음: 13장. 모듈과 패키지 관리 ▶](ch13-모듈과패키지관리.md)


11장에서는 필드에 이름을 붙여 데이터를 묶는 구조체를 배웠습니다. 이번 장에서는 그보다 가볍게, 상황에 맞는 방식으로 여러 값을 묶는 방법들을 살펴봅니다. 이미 8장에서 배열(Array)로 같은 종류의 값을 순서대로 모으는 법을 배웠는데, 배열은 원소를 자유롭게 추가·삭제할 수 있고 정수 인덱스로 접근하는 컬렉션이었습니다. 이번 장에서는 그와 성격이 다른 네 가지 컬렉션인 튜플(Tuple), 네임드 튜플(NamedTuple), 딕셔너리(Dict), 세트(Set)를 배우고, 각각을 언제 사용하는 것이 적절한지 비교해 봅니다.

## 튜플(Tuple): 불변이고 순서가 있는 묶음

튜플은 소괄호로 여러 값을 묶은 것입니다. 배열과 달리 서로 다른 타입의 값을 함께 담을 수 있고, 한 번 만들면 원소를 바꾸거나 추가·삭제할 수 없습니다.

```julia
t = (1, "hello", 3.14)

println(t[1])       # 1
println(t[2])       # hello
println(length(t))  # 3
println(typeof(t))  # Tuple{Int64, String, Float64}
```

인덱스는 배열과 마찬가지로 1부터 시작합니다. 튜플은 불변이므로 값을 바꾸려 하면 오류가 발생합니다.

```julia
t[1] = 10
# ERROR: MethodError: no method matching setindex!(::Tuple{Int64, String, Float64}, ::Int64, ::Int64)
```

튜플의 가장 흔한 용도는 함수에서 여러 값을 한꺼번에 반환하는 것입니다.

```julia
function min_max(numbers)
    return minimum(numbers), maximum(numbers)  # 튜플로 묶여 반환된다
end

lo, hi = min_max([3, 1, 4, 1, 5, 9])  # 구조 분해로 각각 받기
println(lo)  # 1
println(hi)  # 9
```

`min_max`가 반환하는 `minimum(numbers), maximum(numbers)`는 자동으로 `(1, 9)`라는 튜플이 되고, 이를 `lo, hi = ...`처럼 받으면 각 변수에 원소가 순서대로 대입됩니다. 7장에서 함수가 값을 하나만 반환한다고 배웠다면, 사실은 그 "하나의 값"이 튜플일 수도 있었던 것입니다.

원소 개수가 고정되어 있고 각 자리의 의미가 코드 상에서 분명할 때(첫 번째는 최솟값, 두 번째는 최댓값처럼), 튜플은 굳이 이름 있는 타입을 만들지 않고도 여러 값을 안전하게 묶는 가장 가벼운 방법입니다.

## 네임드 튜플(NamedTuple): 이름이 붙은 튜플

튜플은 가볍지만, 자리마다 무엇을 뜻하는지 이름으로 알려주지 않기 때문에 필드가 늘어나면 헷갈리기 쉽습니다. 네임드 튜플은 각 원소에 이름을 붙인 튜플입니다.

```julia
point = (x=3.0, y=4.0)

println(point.x)        # 3.0
println(point.y)        # 4.0
println(point[1])       # 3.0 - 인덱스로도 접근 가능
println(typeof(point))  # NamedTuple{(:x, :y), Tuple{Float64, Float64}}
```

`point.x`처럼 점 표기법으로 필드를 읽을 수 있어서 11장에서 만든 `Point` 구조체와 사용법이 매우 비슷해 보입니다. 실제로 필드 몇 개를 임시로 묶어서 다루고 싶을 때, 굳이 `struct`를 선언하지 않고 네임드 튜플로 대신하는 경우가 많습니다.

```julia
function summarize(scores)
    return (average=sum(scores) / length(scores), best=maximum(scores))
end

result = summarize([80, 90, 75, 100])
println(result.average)  # 86.25
println(result.best)     # 100
```

다만 네임드 튜플은 구조체와 다르게 유효성 검사나 전용 메서드를 붙일 수 없고, 튜플과 마찬가지로 불변입니다. "이 데이터가 프로그램 전반에서 반복적으로 등장하고, 검증 로직이나 전용 동작이 필요하다"면 11장의 구조체로 정식 타입을 만드는 편이 낫고, "함수 하나가 여러 값을 임시로 묶어 반환하는 정도"라면 네임드 튜플로 충분합니다.

## 딕셔너리(Dict): 키와 값의 짝

딕셔너리는 키(key)와 값(value)을 짝지어 저장하는 컬렉션입니다. 배열이 정수 인덱스로 값을 찾는다면, 딕셔너리는 임의의 값을 키로 사용해 값을 찾습니다.

```julia
ages = Dict("영수" => 25, "지민" => 30, "하나" => 28)

println(ages["영수"])     # 25
ages["소연"] = 22          # 새 항목 추가
ages["영수"] = 26          # 기존 값 변경

println(length(ages))     # 4
```

`=>`는 키와 값을 짝짓는 연산자입니다. 존재하지 않는 키로 조회하면 오류가 발생하므로, 키가 있는지 먼저 확인하거나 기본값을 지정하는 방법을 함께 알아두어야 합니다.

```julia
haskey(ages, "영수")   # true
haskey(ages, "철수")   # false

get(ages, "철수", 0)   # 키가 없으면 0을 반환한다 (딕셔너리 자체는 바뀌지 않는다)
get!(ages, "철수", 0)  # 키가 없으면 0을 넣고 반환한다 (딕셔너리에 실제로 추가된다)

println(ages["철수"])  # 0
```

`ages["철수"]`처럼 대괄호로 직접 조회했는데 키가 없으면 `ERROR: KeyError: key "철수" not found`가 발생합니다. `get`은 이런 상황에서도 안전하게 기본값을 돌려주고, `get!`은 한 걸음 더 나아가 기본값을 딕셔너리에 실제로 저장까지 해 줍니다.

딕셔너리를 순회할 때는 `for`문으로 키와 값을 함께, 또는 따로 꺼낼 수 있습니다.

```julia
for (name, age) in ages
    println("$name 은 $age 살입니다")
end

for name in keys(ages)
    println(name)
end

for age in values(ages)
    println(age)
end
```

딕셔너리는 원소 사이에 정해진 순서를 보장하지 않으므로, 특정 순서로 처리해야 한다면 `sort`나 별도의 정렬 로직을 함께 사용해야 합니다. 항목을 지울 때는 `delete!`를 사용합니다.

```julia
delete!(ages, "철수")
haskey(ages, "철수")  # false
```

딕셔너리는 "이름으로 나이 찾기", "단어별 등장 횟수 세기"처럼 값을 키로 빠르게 찾아야 하는 상황에 적합합니다.

```julia
# 단어별 등장 횟수 세기
words = ["사과", "바나나", "사과", "체리", "바나나", "사과"]
counts = Dict{String, Int}()

for word in words
    counts[word] = get(counts, word, 0) + 1
end

println(counts)  # 예: Dict("사과" => 3, "바나나" => 2, "체리" => 1)
```

## 세트(Set): 중복 없는 모음

세트는 순서와 중복을 모두 신경 쓰지 않고, "어떤 값이 포함되어 있는가"만 관리하는 컬렉션입니다. 같은 값을 여러 번 넣어도 한 번만 저장됩니다.

```julia
s = Set([1, 2, 2, 3, 3, 3])
println(s)          # 예: Set([2, 3, 1]) - 원소가 출력되는 순서는 보장되지 않는다
println(length(s))  # 3

push!(s, 4)
push!(s, 1)          # 이미 있으므로 무시된다
println(3 in s)      # true
println(10 in s)     # false
```

세트는 집합 연산을 그대로 함수로 제공합니다. 아래 예제들 역시 결과에 담긴 원소의 출력 순서는 보장되지 않지만, 어떤 원소가 포함되는지는 항상 동일합니다.

```julia
a = Set([1, 2, 3, 4])
b = Set([3, 4, 5, 6])

union(a, b)       # {1, 2, 3, 4, 5, 6} - 합집합
intersect(a, b)   # {3, 4}             - 교집합
setdiff(a, b)     # {1, 2}             - 차집합 (a에는 있지만 b에는 없는 것)
symdiff(a, b)     # {1, 2, 5, 6}       - 대칭차집합 (어느 한쪽에만 있는 것)
```

예를 들어 두 수업의 수강생 명단이 각각 세트로 있다면, 두 수업을 모두 듣는 학생은 `intersect`로, 어느 한 수업이라도 듣는 학생은 `union`으로 바로 구할 수 있습니다.

```julia
class_a = Set(["영수", "지민", "하나"])
class_b = Set(["지민", "소연", "철수"])

println(intersect(class_a, class_b))  # {"지민"} - 두 수업 모두 수강
println(union(class_a, class_b))      # 두 수업 중 하나라도 수강하는 전체 명단
```

값이 이미 들어 있는지를 반복적으로 확인해야 하거나("이 사용자를 이미 처리했는가?"), 중복을 원천적으로 없애고 싶을 때 세트가 배열보다 훨씬 적합합니다. 배열에서 `in`으로 포함 여부를 확인하면 원소를 하나씩 훑어야 하지만, 세트는 이런 확인을 훨씬 빠르게 처리하도록 설계되어 있습니다.

## 어떤 컬렉션을 언제 쓸까

지금까지 등장한 컬렉션들을 정리하면 다음과 같습니다.

| 컬렉션 | 순서 | 중복 | 가변성 | 접근 방법 | 적합한 상황 |
|---|---|---|---|---|---|
| 배열(Array, 8장) | 있음 | 허용 | 가변 | 정수 인덱스 | 같은 종류의 값을 순서대로 모아 처리 |
| 튜플(Tuple) | 있음 | 허용 | 불변 | 정수 인덱스 | 함수의 다중 반환값, 자리가 고정된 값 묶음 |
| 네임드 튜플(NamedTuple) | 있음 | 허용 | 불변 | 이름 또는 인덱스 | 이름이 필요한 임시 데이터 묶음 |
| 딕셔너리(Dict) | 보장 안 됨 | 값은 허용(키는 불가) | 가변 | 임의의 키 | 키로 값을 빠르게 찾아야 할 때 |
| 세트(Set) | 보장 안 됨 | 불허 | 가변 | 포함 여부(`in`) | 중복 제거, 집합 연산, 포함 여부 확인 |
| 구조체(11장) | - | - | 선택 가능 | 이름(필드) | 검증 로직·전용 동작이 필요한 정식 타입 |

정리하면, 값들의 "자리"가 의미를 가지고 개수가 고정되어 있다면 튜플이나 네임드 튜플을, 이름(키)으로 값을 찾아야 한다면 딕셔너리를, 포함 여부와 집합 연산이 중요하다면 세트를, 같은 종류의 값을 순서대로 다루려면 배열을(8장 참고), 그리고 데이터에 검증 로직이나 전용 함수가 필요한 정식 타입이 되어야 한다면 11장에서 배운 구조체를 선택하면 됩니다. 이 다섯 가지 도구를 상황에 맞게 조합하는 것만으로도 대부분의 데이터를 자연스럽게 표현할 수 있습니다.

## 요약

이번 장에서는 배열 외에 Julia가 제공하는 네 가지 컬렉션을 배웠습니다. 튜플은 서로 다른 타입의 값을 순서대로, 하지만 불변으로 묶으며 함수의 다중 반환값을 표현하는 데 특히 자주 쓰입니다. 네임드 튜플은 튜플에 이름을 더해 `point.x`처럼 필드 이름으로 접근할 수 있게 하며, 정식 구조체를 만들 정도는 아닌 가벼운 데이터 묶음에 적합합니다. 딕셔너리는 키와 값을 짝지어 저장하며 `haskey`, `get`, `get!`로 안전하게 조회하고 `for (k, v) in dict`로 순회할 수 있었습니다. 세트는 중복 없는 값의 모음으로, `union`, `intersect`, `setdiff`, `symdiff` 같은 집합 연산과 빠른 포함 여부 확인이 강점입니다. 다음 13장에서는 이런 데이터와 함수들을 하나의 이름 공간으로 묶고 외부 패키지를 가져와 쓰는 모듈과 패키지 관리를 다룹니다.
