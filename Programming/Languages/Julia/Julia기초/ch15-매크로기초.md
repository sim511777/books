# 15장. 매크로 기초

[◀ 이전: 14장. 예외 처리](ch14-예외처리.md) | [📖 목차](00-목차.md) | [다음: 16장. 성능 최적화 기초 ▶](ch16-성능최적화기초.md)


14장에서는 프로그램 실행 중에 발생하는 예외를 `try`-`catch`로 처리하는 방법을 다뤘습니다. 지금까지 다룬 내용은 모두 "코드가 실행되는 동안 무슨 일이 벌어지는가"에 관한 것이었습니다. 이번 장에서는 관점을 한 단계 더 끌어올려서, "코드가 실행되기 전에 코드 자체를 어떻게 다룰 수 있는가"를 살펴봅니다. 이것이 바로 **매크로(macro)**의 세계입니다.

매크로는 처음 접하면 다소 낯설게 느껴질 수 있는 개념입니다. 이 장에서는 매크로가 정확히 무엇인지, 왜 필요한지, 그리고 아주 간단한 매크로를 직접 만들어보면서 감을 잡는 데 집중합니다. 매크로를 활용한 본격적인 메타프로그래밍은 이 책의 범위를 넘어서지만, 이후 다른 사람이 작성한 Julia 코드나 패키지를 읽을 때 매크로를 마주치는 일은 매우 흔하므로 기본 개념을 알아두는 것이 중요합니다.

## 15.1 매크로란 무엇인가

지금까지 우리가 다룬 **함수**는 값을 받아서 값을 반환하는 도구였습니다. 예를 들어 `sqrt(4.0)`을 호출하면 함수는 `4.0`이라는 값을 받아 `2.0`이라는 값을 계산해서 돌려줍니다. 함수는 프로그램이 **실행되는 중**에 동작합니다.

반면 **매크로(macro)**는 값이 아니라 **코드 자체**, 정확히는 아직 실행되지 않은 코드의 구조(이를 **표현식**, expression이라고 부릅니다)를 입력으로 받아서 **또 다른 코드**를 만들어 반환합니다. 그리고 이 과정은 프로그램이 실행되기 전, 즉 **컴파일되기 전 단계**에서 일어납니다. Julia는 소스 코드를 파싱한 뒤 매크로가 있는 자리를 찾아 매크로가 생성한 새 코드로 그 자리를 바꿔치기하고, 그 다음에야 비로소 컴파일과 실행이 진행됩니다. 이 바꿔치기 과정을 **매크로 확장(macro expansion)**이라고 부릅니다.

| | 함수(function) | 매크로(macro) |
|---|---|---|
| 입력 | 값(value) | 코드(표현식, expression) |
| 출력 | 값(value) | 코드(표현식, expression) |
| 동작 시점 | 프로그램 실행 중 | 프로그램 실행 전(컴파일 전) |
| 호출 방법 | `함수이름(인자)` | `@매크로이름 인자` |

매크로는 이름 앞에 `@` 기호를 붙여서 호출합니다. 지금까지 알게 모르게 이미 매크로를 몇 번 사용해 보았을 수도 있습니다.

```julia
julia> @show 1 + 2
1 + 2 = 3
3
```

`@show`는 `1 + 2`라는 코드를 값으로 계산하기 전에 코드 형태 그대로 받아서, "이 코드가 무엇이었는지"와 "그 결과가 무엇인지"를 함께 출력하도록 코드를 변형합니다. 만약 `@show`가 매크로가 아니라 함수였다면, `1 + 2`는 함수에 전달되기도 전에 이미 `3`으로 계산되어 버리기 때문에 `1 + 2 = 3`이라는 원래 코드 모양을 출력에 담을 방법이 없습니다. 매크로만이 실행되기 전의 코드 모양 자체에 접근할 수 있기 때문에 가능한 일입니다.

매크로가 실제로 어떤 코드로 바뀌는지는 `@macroexpand`로 확인할 수 있습니다.

```julia
julia> @macroexpand @show 1 + 2
:(begin
      Base.println("1 + 2 = ", Base.repr(begin
                  var"#1#value" = 1 + 2
              end))
      var"#1#value"
  end)
```

정확한 출력 형태는 Julia 버전마다 조금씩 다를 수 있지만, 핵심은 `@show 1 + 2`라는 한 줄이 실제로는 "계산하고, 원래 코드 문자열과 함께 출력하고, 값을 반환하는" 훨씬 복잡한 코드로 확장된다는 점입니다. 우리는 이 복잡한 코드를 직접 쓸 필요 없이 `@show` 한 줄로 표현할 수 있는 셈입니다. 이처럼 매크로의 핵심 역할은 **반복적이거나 번거로운 코드 패턴을 짧고 읽기 좋은 문법으로 감싸주는 것**입니다.

## 15.2 자주 쓰이는 내장 매크로

Julia는 개발 과정에서 자주 쓰이는 유용한 매크로를 기본으로 제공합니다. 이미 이 책의 여러 곳에서 사용해 보았거나 곧 사용하게 될 매크로들을 정리해 보겠습니다.

### @time: 실행 시간 측정

`@time`은 뒤따라오는 코드를 실행하고, 실행에 걸린 시간과 메모리 할당량을 함께 출력합니다.

```julia
julia> @time sum(1:1_000_000)
  0.000003 seconds
500000500000
```

값 자체(`500000500000`)는 평소와 똑같이 반환되고, 그 위에 실행 시간과 메모리 관련 정보가 덤으로 출력됩니다. `@time`은 코드의 실행 흐름을 바꾸지 않으면서 성능 정보만 곁들여 보여주는 좋은 예입니다. `@time`을 활용해 성능을 점검하는 습관은 16장에서 더 자세히 다룹니다.

### @show: 변수명과 값을 함께 출력

`@show`는 디버깅할 때 특히 유용합니다. `println`은 값만 출력하지만, `@show`는 "어떤 코드의 결과인지"까지 함께 보여줍니다.

```julia
julia> x = 10
10

julia> y = 20

julia> @show x + y
x + y = 30
30
```

여러 줄의 값을 한 번에 확인하고 싶을 때 `println("x = ", x)`를 매번 쓰는 대신 `@show x`라고만 쓰면 되므로 디버깅 코드를 작성하는 시간이 크게 줄어듭니다.

### @assert: 조건 검사

`@assert`는 조건이 참인지 검사하고, 거짓이면 오류를 발생시킵니다. 14장에서 다룬 예외 처리와 함께 쓰면 프로그램이 잘못된 상태로 계속 진행되는 것을 막을 수 있습니다.

```julia
julia> function divide(a, b)
           @assert b != 0 "0으로 나눌 수 없습니다"
           return a / b
       end
divide (generic function with 1 method)

julia> divide(10, 2)
5.0

julia> divide(10, 0)
ERROR: AssertionError: 0으로 나눌 수 없습니다
```

`@assert 조건 "메시지"` 형태로 쓰면, 조건이 거짓일 때 지정한 메시지와 함께 `AssertionError`가 발생합니다. 함수의 입력값이 특정 조건을 만족해야 할 때, 혹은 계산 중간에 절대 일어나서는 안 되는 상황을 점검할 때 유용합니다.

### @inbounds: 경계 검사 생략

Julia는 기본적으로 배열에 인덱스로 접근할 때마다 그 인덱스가 배열 범위 안에 있는지 검사합니다. 이 검사는 안전성을 보장해주지만 약간의 성능 비용이 따릅니다. `@inbounds`는 이 검사를 건너뛰도록 컴파일러에게 지시하는 매크로입니다.

```julia
function sum_fast(arr)
    total = 0
    @inbounds for i in eachindex(arr)
        total += arr[i]
    end
    return total
end
```

`@inbounds`는 성능이 매우 중요한 반복문에서 미세한 속도 향상을 위해 사용되지만, 인덱스가 실제로 범위를 벗어나는 경우 프로그램이 충돌하거나 예측 불가능한 값을 반환할 수 있으므로 인덱스 범위가 확실히 보장된 상황에서만 신중하게 사용해야 합니다. 성능 최적화에 대한 전반적인 내용은 16장에서 다룹니다.

## 15.3 나만의 매크로 만들어보기

매크로가 어떻게 동작하는지 감을 잡는 가장 좋은 방법은 아주 단순한 매크로를 직접 만들어보는 것입니다. 매크로는 `macro` 키워드로 정의하며, 함수와 비슷한 모양을 하고 있습니다.

```julia
macro 매크로이름(인자)
    # 코드(표현식)를 반환하는 본문
end
```

`@time`과 비슷하지만, 실행 시간과 함께 어떤 코드를 실행했는지도 로그로 남기는 `@log_time` 매크로를 만들어보겠습니다.

```julia
macro log_time(expr)
    return quote
        local start_time = time()
        local result = $(esc(expr))
        local elapsed = time() - start_time
        println("[로그] ", $(string(expr)), " 실행 시간: ", elapsed, "초")
        result
    end
end
```

몇 가지 낯선 요소를 하나씩 짚어보겠습니다.

- `expr`은 매크로가 받는 인자입니다. 함수와 달리 이 자리에는 값이 아니라 **계산되지 않은 코드**가 그대로 전달됩니다. 예를 들어 `@log_time sum(1:10)`이라고 호출하면 `expr`에는 `10`이라는 값이 아니라 `sum(1:10)`이라는 코드 구조 자체가 담깁니다.
- `quote ... end`는 코드를 값처럼 다룰 수 있게 감싸는 블록입니다. 이 블록 안에 작성한 코드가 매크로 호출 자리에 그대로 삽입될 새로운 코드가 됩니다.
- `$(esc(expr))`는 원래 전달받은 코드(`expr`)를 결과 코드 안에 끼워 넣는 부분입니다. `esc()`는 "이 코드는 매크로가 손대지 않고 호출한 곳의 문맥 그대로 실행되어야 한다"는 것을 표시하는 함수입니다. `esc()`를 붙이지 않으면 매크로 내부에서 사용한 임시 변수 이름(`start_time`, `result` 등)과 호출한 쪽의 변수 이름이 우연히 겹쳐서 예상치 못한 오류가 날 수 있습니다. 이런 이름 충돌을 막아주는 성질을 **매크로 위생(macro hygiene)**이라고 부르는데, 지금 단계에서는 "원래 코드를 그대로 실행하고 싶을 때는 `esc()`로 감싼다" 정도로만 기억해도 충분합니다.
- `$(string(expr))`은 코드 자체를 문자열로 바꿔서 로그 메시지에 어떤 코드를 실행했는지 남기는 부분입니다.

이제 이 매크로를 사용해 보겠습니다.

```julia
julia> @log_time sum(1:1_000_000)
[로그] sum(1:1000000) 실행 시간: 0.0021초
500000500000
```

`@macroexpand`로 실제 확장된 코드를 확인하면 이해에 도움이 됩니다.

```julia
julia> @macroexpand @log_time sum(1:10)
:(begin
      local start_time = Main.time()
      local result = sum(1:10)
      local elapsed = Main.time() - start_time
      Main.println("[로그] ", "sum(1:10)", " 실행 시간: ", elapsed, "초")
      result
  end)
```

`@log_time sum(1:10)`이라는 한 줄이, 시간을 재고 로그를 남기고 결과를 반환하는 다섯 줄짜리 코드로 확장된 것을 볼 수 있습니다. 이것이 매크로의 본질입니다. 매크로는 짧은 문법 뒤에 반복적인 코드 패턴을 숨겨서, 사용하는 쪽에서는 핵심 로직(`sum(1:10)`)만 눈에 보이도록 해줍니다.

## 15.4 매크로 남용은 피하기

매크로는 강력한 도구지만 그만큼 조심해서 사용해야 합니다. 매크로가 코드를 어떻게 변형하는지는 `@macroexpand`를 실행해보기 전까지는 눈에 바로 보이지 않기 때문에, 매크로를 많이 사용한 코드는 실제로 어떤 코드가 실행되는지 파악하기가 어려워집니다. 함수 호출은 "이 함수가 이런 값을 반환하겠구나"라고 비교적 쉽게 예상할 수 있지만, 매크로 호출은 코드 구조 자체를 바꿔버릴 수 있어서 추적하기가 더 까다롭습니다.

일반적인 원칙은 다음과 같습니다.

- **함수로 해결할 수 있는 문제는 함수로 해결합니다.** 매크로는 값을 받아 값을 반환하는 방식으로는 해결할 수 없는, 즉 코드 구조 자체를 다뤄야 하는 문제에만 사용합니다. `@show`처럼 원래 코드의 모양(변수명, 표현식)을 그대로 출력에 담아야 하는 경우가 대표적입니다.
- **매크로는 성능을 위한 도구가 아닙니다.** "매크로를 쓰면 더 빠르다"는 오해가 있지만, 이는 사실이 아닙니다(`@inbounds`처럼 예외적인 경우도 있지만, 이는 경계 검사를 생략하는 특별한 목적 때문입니다). Julia에서 함수는 이미 충분히 빠르며, 성능 최적화는 16장에서 다룰 타입 안정성 등 다른 방법으로 달성합니다.
- **매크로는 최소한으로, 단순하게 유지합니다.** 여러 매크로를 겹겹이 쌓거나 매크로 안에서 복잡한 로직을 처리하려 하면 코드를 읽는 사람(미래의 나 자신을 포함해서)이 코드의 동작을 이해하기 매우 어려워집니다.

이 책에서 매크로를 직접 정의하는 일은 이번 장이 마지막입니다. 앞으로 다른 사람이 만든 패키지를 사용하다가 `@`로 시작하는 낯선 이름을 만나면, "이것은 코드를 다른 코드로 바꿔주는 도구구나"라고 생각하고 필요하다면 `@macroexpand`로 실제 동작을 확인해 보면 됩니다.

## 요약

- 매크로는 값이 아니라 코드(표현식)를 입력으로 받아 코드를 반환하는 메타프로그래밍 도구로, 프로그램이 실행되기 전인 매크로 확장 단계에서 동작합니다. 함수는 값을 받아 값을 반환하고 실행 중에 동작한다는 점에서 매크로와 다릅니다.
- `@매크로이름` 형태로 호출하며, `@macroexpand`를 사용하면 매크로가 실제로 어떤 코드로 확장되는지 확인할 수 있습니다.
- 자주 쓰이는 내장 매크로로는 실행 시간을 측정하는 `@time`, 코드와 값을 함께 출력하는 `@show`, 조건을 검사하는 `@assert`, 배열 경계 검사를 생략하는 `@inbounds`가 있습니다.
- `macro 이름(인자) ... end`로 매크로를 직접 정의할 수 있습니다. `quote ... end`로 새 코드를 구성하고, `$(esc(expr))`로 원래 코드를 안전하게 끼워 넣습니다.
- 매크로는 강력하지만 코드의 동작을 추적하기 어렵게 만들 수 있으므로, 함수로 해결되는 문제라면 함수를 사용하고 매크로는 꼭 필요한 경우에만 단순하게 사용합니다.
