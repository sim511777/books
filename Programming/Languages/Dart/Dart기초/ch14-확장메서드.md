## 남의 클래스에 메서드를 추가하고 싶을 때

9장에서 클래스를 만들 때, 새로운 기능이 필요하면 그 클래스에 메서드를 직접 추가하면 됩니다. 그런데 `String`이나 `int`처럼 Dart 표준 라이브러리가 이미 제공하는 클래스에는 어떻게 기능을 추가할 수 있을까요? 예를 들어 문자열이 팰린드롬(앞뒤로 읽어도 같은 단어)인지 확인하는 기능이 자주 필요하다고 해봅시다.

```dart
bool isPalindrome(String text) {
  var clean = text.replaceAll(' ', '').toLowerCase();
  return clean == clean.split('').reversed.join();
}

void main() {
  print(isPalindrome('level')); // true
  print(isPalindrome('토마토')); // true
}
```

이 함수는 잘 동작하지만, 사용할 때마다 `isPalindrome(myText)`처럼 문자열을 함수의 인자로 넘겨야 합니다. `myText.isPalindrome()`처럼 마치 문자열 자체의 메서드인 것처럼 쓸 수 있다면 훨씬 읽기 좋을 것입니다. 하지만 `String` 클래스는 표준 라이브러리 코드이므로 직접 열어서 메서드를 추가할 수 없고, 11장에서 배운 상속으로 `class MyString extends String`을 만들 수도 없습니다(`String`은 상속을 허용하지 않는 봉인된 클래스입니다). 게다가 문자열 리터럴 `'level'`은 애초에 `MyString`의 인스턴스가 아니라 그냥 `String`이기 때문에, 상속으로는 이 문제를 풀 수 없습니다.

이런 상황을 해결하기 위해 Dart는 **확장 메서드(extension methods)**라는 기능을 제공합니다. 기존 클래스의 소스 코드를 전혀 건드리지 않고, 마치 그 클래스에 새 메서드가 있는 것처럼 붙여 넣는 기능입니다.

## 확장 메서드 문법

`extension` 키워드로 확장을 선언하고, `on` 뒤에 확장하고자 하는 타입을 지정합니다.

```dart
extension StringUtils on String {
  bool isPalindrome() {
    var clean = replaceAll(' ', '').toLowerCase();
    return clean == clean.split('').reversed.join();
  }
}

void main() {
  print('level'.isPalindrome()); // true
  print('토마토'.isPalindrome()); // true
  print('hello'.isPalindrome()); // false
}
```

`StringUtils`는 확장의 이름이고, `on String`은 이 확장이 `String` 타입에 메서드를 추가한다는 뜻입니다. 확장 본문 안에서는 `this`가 확장 대상이 되는 값을 가리키므로, 위 예제의 `replaceAll`처럼 별도의 매개변수 없이 곧바로 `String`의 기존 멤버를 호출할 수 있습니다.

이렇게 선언하고 나면 `String` 타입의 어떤 값에서든 `.isPalindrome()`을 호출할 수 있습니다. 실제로 `String` 클래스가 수정된 것은 아니지만, 컴파일러가 `'level'.isPalindrome()`을 만나면 `StringUtils` 확장 안의 메서드를 찾아 연결해주는 것입니다.

메서드뿐 아니라 게터, 세터, 연산자도 확장에 추가할 수 있습니다.

```dart
extension NumberFormatting on int {
  String get withComma {
    // 세 자리마다 쉼표를 넣어 반환한다
    var text = toString();
    var buffer = StringBuffer();
    for (var i = 0; i < text.length; i++) {
      if (i > 0 && (text.length - i) % 3 == 0) buffer.write(',');
      buffer.write(text[i]);
    }
    return buffer.toString();
  }
}

void main() {
  print(1234567.withComma); // 1,234,567
}
```

## 언제 확장 메서드가 유용한가

확장 메서드는 대체로 두 가지 상황에서 힘을 발휘합니다.

첫째, 표준 라이브러리 클래스나 다른 패키지가 제공하는 클래스처럼 직접 수정할 수 없는 코드에 기능을 덧붙이고 싶을 때입니다. 위의 `String`, `int` 예제가 여기에 해당합니다.

둘째, 이미 있는 유틸리티 함수를 메서드 문법으로 바꿔 가독성을 높이고 싶을 때입니다. 다음 두 코드를 비교해봅시다.

```dart
// 함수 스타일: 안에서 바깥으로 읽어야 한다
print(formatDate(addDays(parseDate('2026-08-08'), 7)));

// 확장 메서드 스타일: 왼쪽에서 오른쪽으로 순서대로 읽힌다
print('2026-08-08'.toDate().addDays(7).format());
```

함수를 겹쳐 호출하면 실제 실행 순서와 코드를 읽는 방향이 반대가 되어 이해하기 번거롭습니다. 확장 메서드로 같은 로직을 표현하면 값이 왼쪽에서 오른쪽으로 차례차례 가공되는 흐름이 코드에 그대로 드러납니다. 13장에서 본 `list.where(...).map(...)`처럼 메서드를 연결(chaining)하는 스타일과 잘 어울리는 이유도 여기에 있습니다.

## 이름 없는 확장과 확장 충돌

확장 이름은 생략할 수도 있습니다.

```dart
extension on String {
  String shout() => '${toUpperCase()}!';
}
```

이름이 없는 확장도 자동으로 적용되는 데는 문제가 없습니다. 다만 이름이 없으면 다른 파일에서 이 확장만 선택적으로 가져오거나, 충돌을 해결할 때 명시적으로 지정할 방법이 없습니다. 그래서 여러 파일에 나눠 쓰는 라이브러리라면 이름을 붙여두는 것이 안전합니다.

두 개의 확장이 같은 타입에 같은 이름의 메서드를 추가하면 충돌이 생길 수 있습니다.

```dart
extension LoudString on String {
  String shout() => '${toUpperCase()}!!';
}

extension QuietString on String {
  String shout() => toLowerCase();
}

void main() {
  // print('hi'.shout()); // 오류! 어느 확장의 shout인지 알 수 없다
  print(LoudString('hi').shout()); // 확장 이름으로 직접 지정하면 해결된다
}
```

이럴 때는 확장 이름을 생성자처럼 사용해 `LoudString('hi').shout()`처럼 명시적으로 어떤 확장을 쓸지 지정하면 충돌을 해결할 수 있습니다. 또한 확장이 추가한 멤버는 원래 클래스의 멤버와 이름이 같으면 항상 원래 클래스의 멤버가 우선합니다. 확장은 어디까지나 "없던 것을 덧붙이는" 도구이지, 기존 동작을 덮어쓰는 도구가 아니라는 점을 기억해두면 좋습니다.

한 가지 더 유의할 점은 확장 메서드가 값의 **정적 타입**을 기준으로 연결된다는 것입니다. 즉 실행 시점의 실제 타입이 아니라, 코드에 적힌 변수의 선언 타입을 보고 어떤 확장을 적용할지 결정합니다. 예를 들어 `Object` 타입으로 선언된 변수에 문자열을 담아두면, 실제 값은 문자열이라도 `Object`에는 `StringUtils` 확장이 적용되지 않아 `isPalindrome()`을 호출할 수 없습니다. 이는 클래스의 메서드가 실제 타입을 기준으로 동적으로 연결되는 것과 다른 확장 메서드만의 특징입니다.

## 제네릭과 결합한 확장 메서드

12장에서 배운 제네릭은 확장 메서드에도 그대로 적용할 수 있습니다. 특정 타입 하나가 아니라 `List<T>`처럼 제네릭 타입 전체를 확장하고 싶을 때 유용합니다. 13장의 컬렉션 처리 메서드와 12장의 제한된 타입 매개변수를 결합해, 숫자로 이루어진 리스트에 합계와 평균을 구하는 확장을 만들어보겠습니다.

```dart
extension NumericListStats<T extends num> on List<T> {
  num get total => fold(0, (sum, element) => sum + element);

  double get average {
    if (isEmpty) return 0;
    return total / length;
  }
}

void main() {
  var scores = [90, 85, 100];
  print(scores.total); // 275
  print(scores.average); // 91.66666666666667

  var prices = [1500.0, 2300.5, 999.5];
  print(prices.total); // 4800.0
  print(prices.average); // 1600.0
}
```

`extension NumericListStats<T extends num> on List<T>`는 "`T`가 `num`의 하위 타입일 때만, `List<T>`에 이 확장을 적용한다"는 뜻입니다. 이 제약이 있어야 `fold` 안에서 `sum + element` 같은 숫자 연산을 안전하게 쓸 수 있습니다. 만약 제약을 걷어내고 `<T>`로만 선언했다면, `T`가 `String`이나 `Person`일 수도 있으므로 `+` 연산이 항상 성립한다는 보장이 없어 컴파일 오류가 납니다.

이 확장을 선언해두면 `List<int>`든 `List<double>`이든 상관없이 `.total`, `.average`를 곧바로 쓸 수 있습니다. 제네릭 클래스를 직접 설계하지 않고도, 이미 존재하는 표준 컬렉션 타입에 필요한 기능만 살짝 얹어 쓰는 셈입니다. 이처럼 제네릭과 확장 메서드를 함께 쓰면, 특정 타입 하나에 얽매이지 않으면서도 타입 안전성을 잃지 않는 유틸리티를 만들 수 있습니다.

## 요약

- 확장 메서드(`extension ... on ...`)는 기존 클래스의 소스 코드를 수정하지 않고도 새로운 메서드, 게터, 세터, 연산자를 추가하는 기능입니다.
- `String`, `int`처럼 상속으로 손댈 수 없는 표준 라이브러리 클래스에 기능을 덧붙이거나, 기존 유틸리티 함수를 메서드 문법으로 바꿔 가독성을 높이는 데 특히 유용합니다.
- 확장 이름은 생략할 수 있지만, 이름이 같은 멤버를 가진 확장이 여러 개 있으면 충돌이 생기므로 이름을 붙여 `확장이름(값).메서드()`처럼 명시적으로 구분해야 합니다. 원래 클래스의 멤버는 항상 확장의 멤버보다 우선합니다.
- 확장 메서드는 값의 정적 타입을 기준으로 연결되므로, `Object`처럼 넓은 타입으로 선언된 변수에는 원하는 확장이 적용되지 않을 수 있습니다.
- 12장의 제네릭과 결합하면 `extension NumericListStats<T extends num> on List<T>`처럼 특정 조건을 만족하는 제네릭 타입 전체에 기능을 추가할 수 있습니다.

3. 이름이 같은 메서드를 가진 두 확장을 직접 만들어 충돌 상황을 재현하고, 확장 이름을 명시해 충돌을 해결하는 코드를 작성해보세요.
