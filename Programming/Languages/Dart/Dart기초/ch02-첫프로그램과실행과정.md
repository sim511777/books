## 들어가며

1장에서 Dart가 어떤 언어인지, 무엇에 강점이 있는지 살펴보았다. 이제 직접 코드를 작성하고 실행해볼 차례다. 프로그래밍 언어를 배울 때 가장 먼저 작성하는 프로그램은 관습적으로 화면에 "Hello, World!"라는 문장을 출력하는 것이다. 겨우 몇 줄짜리 프로그램이지만, 이 안에는 Dart 프로그램의 기본 골격이 모두 들어있다. 이번 장에서는 이 짧은 코드를 한 줄씩 뜯어보고, `dart run` 명령으로 실행하는 방법, 그리고 Dart가 코드를 실제로 실행하는 두 가지 방식인 JIT와 AOT를 살펴본다. 마지막으로 처음 코드를 작성할 때 누구나 한 번쯤 겪는 흔한 오류들과 대처법도 정리한다.

## Hello World 작성하기

텍스트 편집기에서 `hello.dart`라는 파일을 만들고 다음 내용을 작성해보자.

```dart
void main() {
  print('Hello, World!');
}
```

짧지만 이 세 줄에는 Dart 프로그램을 구성하는 핵심 요소가 모두 담겨 있다. 하나씩 뜯어보자.

### void main() — 프로그램의 시작점

```dart
void main() {
  // ...
}
```

Dart로 작성한 실행 가능한 프로그램은 반드시 `main`이라는 이름의 함수를 최상위(top-level)에 가지고 있어야 한다. Dart 실행 환경은 프로그램을 실행할 때 다른 함수가 아니라 항상 `main` 함수부터 코드를 읽어 내려가기 시작한다. 즉 `main`은 "이 프로그램이 시작되는 자리"라는 약속이다.

`main` 앞에 붙은 `void`는 이 함수가 어떤 값도 반환하지 않는다는 뜻이다. 함수와 반환값에 대한 자세한 문법은 7장에서 다루지만, 지금은 "`void`가 붙은 함수는 결과값을 돌려주지 않고 그저 어떤 동작을 수행할 뿐이다"라는 정도만 기억해두면 충분하다.

함수 이름 뒤의 괄호 `()`는 이 함수가 받는 매개변수 목록을 나타낸다. `main` 함수는 매개변수 없이도 정의할 수 있고, 명령줄 인수를 받고 싶을 때는 `void main(List<String> arguments)` 형태로 받을 수도 있다. 명령줄 인수를 받아 처리하는 방법은 17장 패키지와 생태계에서 실제 프로그램을 만들 때 다시 등장한다.

중괄호 `{ }`는 함수의 본문(body), 즉 이 함수가 실행할 코드의 범위를 감싼다. 여는 중괄호부터 닫는 중괄호까지가 `main` 함수가 실행할 내용이다.

### print('Hello, World!'); — 화면에 출력하기

`print()`는 Dart가 기본으로 제공하는 함수로, 괄호 안에 넘긴 값을 콘솔(터미널) 화면에 출력하고 줄을 바꾼다. 여기서는 문자열 `'Hello, World!'`를 넘겼으므로, 그 글자 그대로가 화면에 나타난다.

문자열은 작은따옴표나 큰따옴표로 감싸서 표현하는데, 문자열과 자료형에 대한 자세한 내용은 3장에서 다룬다. 지금은 `print()` 괄호 안에 원하는 문자열을 넣으면 그 내용이 화면에 출력된다는 사실만 알면 된다.

문장의 끝에는 세미콜론(`;`)을 붙인다. Dart에서 세미콜론은 "이 문장은 여기서 끝난다"는 표시이며, 함수 정의처럼 중괄호로 블록을 이루는 경우를 제외하면 거의 모든 문장 끝에 세미콜론이 필요하다. 세미콜론을 빼먹는 실수는 이 장 뒷부분에서 다시 다룬다.

## dart run으로 실행하기

코드를 작성했다면 이제 실행해볼 차례다. 1장에서 설치한 Dart SDK에는 `dart`라는 커맨드라인 도구가 포함되어 있다. 터미널(명령 프롬프트, PowerShell, 또는 macOS/Linux의 터미널)을 열고, `hello.dart` 파일이 있는 폴더로 이동한 뒤 다음 명령을 입력한다.

```
dart run hello.dart
```

정상적으로 실행되면 다음과 같은 결과가 화면에 나타난다.

```
Hello, World!
```

`dart run`은 소스 코드를 사람이 별도로 컴파일할 필요 없이 곧바로 실행해주는 명령이다. 내부적으로는 Dart 가상 머신(Dart VM)이 코드를 읽어서 실행하는데, 이 과정에서 무슨 일이 벌어지는지는 다음 절에서 자세히 살펴본다.

파일 이름을 생략하고 `dart run`만 입력해도 되는 경우가 있다. 프로젝트가 `bin/` 폴더 구조를 갖춘 정식 Dart 패키지라면, `dart run`은 기본적으로 `bin/` 안의 진입점 파일을 찾아 실행한다. 지금 단계에서는 파일 이름을 직접 지정하는 방식으로 충분하며, 패키지 구조는 17장에서 다룬다.

## Dart 코드가 실행되는 두 가지 방식: JIT와 AOT

1장에서 Dart가 "클라이언트 최적화 언어"로서 JIT와 AOT라는 두 가지 실행 방식을 함께 지원한다고 언급했다. 방금 실행한 `dart run` 명령이 바로 그중 하나인 JIT 방식이다. 두 방식이 실제로 어떻게 다른지 그림으로 확인해보자.

```text
                     Dart 소스 코드
                     (예: hello.dart)
                            |
              +-------------+-------------+
              |                           |
              v                           v
   dart run (개발 모드 - JIT)     dart compile exe (배포 모드 - AOT)
              |                           |
              v                           v
      +----------------+          +--------------------+
      | Dart VM 시작    |          | AOT 컴파일러 실행     |
      | (가상 머신 위에서 |          | (컴파일 시점에 처리)   |
      |  실행)          |          +--------------------+
      +----------------+                   |
              |                            v
              v                   +--------------------+
      +----------------+          | 소스 전체를 미리      |
      | JIT 컴파일러가   |          | 네이티브 기계어로     |
      | 필요한 부분을    |          | 전부 변환            |
      | 그때그때        |          +--------------------+
      | 기계어로 변환    |                   |
      +----------------+                   v
              |                   +--------------------+
              v                   | 독립 실행형 파일 생성  |
      +----------------+          | (예: hello.exe)      |
      | 코드 수정 시     |          +--------------------+
      | 핫 리로드로      |                   |
      | 즉시 반영        |                   v
      +----------------+          +--------------------+
              |                   | 빠른 시작 - 배포에 적합|
              v                   | (런타임 없이 OS가     |
      +----------------+          |  직접 실행)          |
      | 빠른 반복 개발에  |          +--------------------+
      | 적합            |
      | (느린 시작,      |
      |  큰 런타임)      |
      +----------------+

  개발 중에는 JIT로 빠르게 반복하고, 배포할 때는 AOT로 네이티브 성능을 확보한다.
  같은 소스 코드(.dart) 한 벌이 상황에 따라 서로 다른 두 경로로 실행된다.
```

### JIT: 개발 중 빠른 반복을 위한 방식

`dart run hello.dart`를 실행하면, Dart VM이라는 가상 머신이 먼저 시작된다. 그리고 JIT(Just-In-Time) 컴파일러가 코드가 실제로 실행되는 순간에, 필요한 부분만 그때그때 기계어로 번역해서 실행한다. "필요할 때 즉시(Just-In-Time) 컴파일한다"는 이름 그대로다.

이 방식의 가장 큰 장점은 개발 속도다. 코드를 조금 고치고 다시 실행하기까지 걸리는 시간이 짧고, Flutter 앱을 개발할 때는 실행 중인 앱에 코드 변경 사항을 즉시 반영하는 핫 리로드(hot reload) 기능까지 가능해진다. 대신 Dart VM이라는 런타임을 함께 띄워야 하므로 시작 시간이 상대적으로 느리고, 배포할 결과물의 크기도 커지는 편이다. 그래서 JIT 방식은 개발하는 동안 코드를 빠르게 확인하고 수정하는 용도에 적합하다.

### AOT: 배포를 위한 네이티브 컴파일

배포할 프로그램을 만들 때는 상황이 다르다. 사용자는 코드를 수정할 일이 없고, 오히려 프로그램이 얼마나 빨리 시작되고 얼마나 빠르게 동작하는지가 중요하다. 이때는 AOT(Ahead-Of-Time) 컴파일을 사용한다. "미리(Ahead-Of-Time)"라는 이름처럼, 프로그램을 실행하기 전에 소스 코드 전체를 그 자리에서 컴퓨터가 직접 실행할 수 있는 네이티브 기계어로 미리 다 변환해두는 방식이다.

Dart SDK로 AOT 컴파일을 해보려면 다음 명령을 사용한다.

```
dart compile exe hello.dart
```

이 명령을 실행하면 `hello.exe`(Windows 기준, macOS나 Linux에서는 확장자 없는 실행 파일)라는 독립 실행형 파일이 생성된다. 이 파일은 Dart VM이나 Dart SDK가 설치되어 있지 않은 컴퓨터에서도 곧바로 실행할 수 있다. 이미 네이티브 기계어로 변환이 끝난 상태이기 때문에, 운영체제가 별도의 통역 과정 없이 파일을 직접 실행할 수 있는 것이다.

```
./hello.exe
Hello, World!
```

정리하면, `dart run`은 JIT 방식으로 개발 중 빠른 반복을 지원하고, `dart compile exe`는 AOT 방식으로 배포에 적합한 독립 실행 파일을 만들어준다. 같은 소스 코드 한 벌이 상황에 따라 서로 다른 경로를 거쳐 실행된다는 점이 핵심이다. 이 책의 예제는 대부분 학습 목적이므로 `dart run`으로 충분하지만, 실제로 프로그램을 배포할 시점이 오면 `dart compile exe`를 떠올리면 된다.

## 흔한 오류와 대처법

처음 Dart 코드를 작성하다 보면 몇 가지 오류를 반복해서 만나게 된다. 미리 알아두면 당황하지 않고 빠르게 해결할 수 있다.

**세미콜론을 빠뜨린 경우**

```dart
void main() {
  print('Hello, World!')  // 세미콜론이 없다
}
```

이렇게 작성하면 `Expected ';' after this.` 같은 오류가 나타난다. Dart는 문장의 끝을 세미콜론으로 구분하므로, 문장 하나를 다 쓴 뒤에는 세미콜론을 붙이는 습관을 들여야 한다.

**중괄호나 소괄호의 짝이 맞지 않는 경우**

```dart
void main() {
  print('Hello, World!');
// 닫는 중괄호가 없다
```

이 경우 `Expected a class member.` 같은, 원인을 바로 짐작하기 어려운 오류 메시지가 나오기도 한다. 코드 편집기에 Dart 확장을 설치해두면 짝이 맞지 않는 괄호를 색깔이나 밑줄로 미리 알려주므로, 이런 실수를 줄이는 데 큰 도움이 된다.

**함수 이름이나 대소문자를 잘못 쓴 경우**

```dart
void main() {
  Print('Hello, World!'); // print가 아니라 Print로 잘못 씀
}
```

Dart는 대소문자를 구분하는 언어이므로 `Print`와 `print`는 완전히 다른 이름으로 취급된다. 이 경우 `Print`라는 이름을 찾을 수 없다는 오류가 발생한다. 오류 메시지에 등장하는 이름을 코드에서 그대로 찾아보면 원인을 빠르게 좁힐 수 있다.

**문자열의 따옴표를 닫지 않은 경우**

```dart
void main() {
  print('Hello, World!); // 닫는 작은따옴표가 없다
}
```

문자열이 어디서 끝나는지 컴파일러가 판단할 수 없게 되어 오류가 발생한다. 문자열을 열었으면 같은 종류의 따옴표로 반드시 닫아야 한다는 점을 기억하자.

**파일 이름이나 경로를 잘못 지정한 경우**

```
dart run hell.dart
```

파일 이름을 오타로 잘못 입력하면 `Error: No such file or directory` 같은 오류가 나타난다. 이 경우는 Dart 문법 문제가 아니라 터미널에서 파일을 찾지 못한 것이므로, 현재 폴더에 어떤 파일이 있는지 다시 확인하는 것이 먼저다.

오류 메시지를 두려워할 필요는 없다. Dart의 오류 메시지는 대부분 어떤 파일의 몇 번째 줄에서 무엇이 문제인지 구체적으로 알려준다. 오류가 나면 메시지를 차분히 읽고, 그 줄 근처를 살펴보는 습관을 들이는 것이 디버깅의 시작이다.

## 요약

- Dart 프로그램은 반드시 최상위 `main()` 함수를 가지며, 프로그램은 이 함수부터 실행된다.
- `void`는 반환값이 없다는 표시이고, `print()`는 값을 콘솔에 출력하는 기본 함수이며, 문장 끝에는 세미콜론이 필요하다.
- `dart run 파일명.dart`로 소스 코드를 즉시 실행할 수 있으며, 이는 Dart VM과 JIT 컴파일을 사용하는 방식이다.
- `dart compile exe 파일명.dart`는 AOT 컴파일로 독립 실행형 네이티브 파일을 만들며, 배포에 적합하다.
- JIT는 개발 중 빠른 반복에, AOT는 실행 속도와 배포 편의성에 강점이 있다.
- 세미콜론 누락, 괄호 짝 불일치, 대소문자 오류, 따옴표 미닫힘, 파일 경로 오타는 초보자가 자주 마주치는 오류이며, 오류 메시지를 읽는 습관이 해결의 첫걸음이다.

## 연습문제

1. `hello.dart` 파일을 직접 작성하고 `dart run`으로 실행해서 "Hello, World!"가 출력되는지 확인해보라.
2. `print()`를 두 번 사용해서 자신의 이름과 좋아하는 프로그래밍 언어를 각각 한 줄씩 출력하는 프로그램을 작성해보라.
3. 일부러 세미콜론을 빼고 실행해 어떤 오류 메시지가 나오는지 확인한 뒤, 오류를 고쳐보라.
4. `dart compile exe`로 자신이 작성한 프로그램을 컴파일하고, 생성된 실행 파일을 직접 실행해보라.
5. JIT와 AOT 방식의 차이를 각각 한 문장으로 정리하고, 어떤 상황에 어떤 방식이 더 적합한지 설명해보라.
