# 11장. 인터페이스와 추상 클래스

10장에서는 `extends`로 부모 클래스의 기능을 물려받는 상속과, 여러 기능을 섞어 쓰는 믹스인을 배웠다. 이번 장에서는 상속과는 목적이 조금 다른 도구인 인터페이스와 추상 클래스를 다룬다. 상속이 "기존 코드를 재사용하는 것"에 초점을 맞춘다면, 인터페이스와 추상 클래스는 "이 타입은 반드시 이런 기능을 제공해야 한다"는 약속, 즉 규격을 정의하는 데 초점을 맞춘다.

## 모든 클래스는 인터페이스다

Java나 C#을 접해본 독자라면 `interface`라는 별도의 키워드를 기대할 수 있다. 그런데 Dart에는 그런 키워드가 없다. 대신 Dart의 모든 클래스는 그 자체로 암묵적인 인터페이스 역할을 겸한다. 클래스를 하나 선언하면, 그 클래스가 가진 메서드와 프로퍼티의 목록이 곧 하나의 "규격"이 되고, 다른 클래스가 `implements` 키워드로 그 규격을 구현할 수 있다.

다음 예제를 보자.

```dart
// 평범한 클래스 선언
class Printer {
  void printDocument(String content) {
    print('출력 중: $content');
  }
}

// Printer를 인터페이스로 사용
class NetworkPrinter implements Printer {
  @override
  void printDocument(String content) {
    print('네트워크로 전송: $content');
  }
}

void main() {
  NetworkPrinter printer = NetworkPrinter();
  printer.printDocument('보고서.pdf');
}
```

`Printer`는 특별히 인터페이스로 선언된 것이 아니라 그냥 평범한 클래스다. 하지만 `NetworkPrinter`가 `implements Printer`라고 선언하는 순간, `Printer` 클래스가 가진 모든 멤버(여기서는 `printDocument`)를 반드시 다시 구현해야 하는 계약이 생긴다. `implements`를 쓰면 부모의 구현 코드는 전혀 물려받지 못하고, 오직 "이런 메서드가 있어야 한다"는 시그니처만 물려받는다.

만약 `NetworkPrinter`에서 `printDocument`를 구현하지 않고 빈 채로 두면, 정적 분석기가 즉시 오류를 표시한다. 이것이 인터페이스의 핵심 역할이다. 구현은 강제하지만 구현 방법은 전혀 관여하지 않는다.

## 여러 인터페이스를 동시에 구현하기

상속은 `extends`로 오직 하나의 클래스만 지정할 수 있지만, `implements`는 쉼표로 여러 개를 나열할 수 있다. 하나의 클래스가 여러 역할을 동시에 수행해야 할 때 유용하다.

```dart
class Flyable {
  void fly() => print('날아갑니다');
}

class Swimmable {
  void swim() => print('헤엄칩니다');
}

// 두 인터페이스를 동시에 구현
class Duck implements Flyable, Swimmable {
  @override
  void fly() => print('오리가 날아갑니다');

  @override
  void swim() => print('오리가 헤엄칩니다');
}

void main() {
  final duck = Duck();
  duck.fly();
  duck.swim();
}
```

`Duck`은 `Flyable`이면서 동시에 `Swimmable`이다. 클래스 계층상 부모는 하나뿐이어야 하지만, "할 수 있는 일"의 목록은 여러 개를 조합할 수 있다는 것이 인터페이스의 장점이다.

## 추상 클래스로 구현을 강제하기

앞서 살펴본 `Printer`처럼 평범한 클래스를 인터페이스로 쓰는 방식은 한 가지 아쉬운 점이 있다. `Printer` 자체를 그대로 인스턴스로 만들어 쓸 수도 있다는 점이다. 하지만 "이 클래스는 그 자체로는 의미가 없고, 반드시 자식 클래스가 구체적인 내용을 채워야 한다"는 의도를 표현하려면 `abstract class`를 사용한다.

```dart
// 추상 클래스: 인스턴스를 직접 만들 수 없다
abstract class Shape {
  double get area; // 구현 없는 추상 게터

  void describe() {
    // 일반 메서드는 구현을 가질 수 있다
    print('이 도형의 면적은 ${area.toStringAsFixed(2)}입니다');
  }
}

class Circle extends Shape {
  final double radius;
  Circle(this.radius);

  @override
  double get area => 3.14159 * radius * radius;
}

void main() {
  final circle = Circle(3);
  circle.describe(); // 이 도형의 면적은 28.27입니다

  // Shape shape = Shape(); // 오류! 추상 클래스는 인스턴스화할 수 없다
}
```

추상 클래스의 특징을 정리하면 다음과 같다.

- `abstract` 키워드로 선언하며, 이 클래스로는 `Shape()`처럼 직접 객체를 만들 수 없다.
- 본문이 없는 메서드나 게터(추상 멤버)를 선언해 자식 클래스가 반드시 구현하도록 강제할 수 있다.
- 동시에 이미 구현이 끝난 일반 메서드도 함께 둘 수 있다. 위 예제의 `describe()`처럼 공통 로직은 추상 클래스에서 미리 작성해두고, 각 자식이 달라져야 하는 부분(`area`)만 추상으로 남겨두는 식이다.

이 점이 순수 인터페이스 역할을 하는 평범한 클래스와의 가장 큰 차이다. 평범한 클래스를 인터페이스처럼 쓰면 모든 멤버를 자식이 처음부터 다시 구현해야 하지만, 추상 클래스는 공통 로직을 미리 제공하면서 일부만 자식에게 위임할 수 있다.

## implements vs extends: 무엇이 다른가

같은 `Shape`을 `extends`로 상속할 수도 있고, `implements`로 구현할 수도 있다. 겉보기엔 비슷해 보여도 결과는 완전히 다르다.

```dart
abstract class Animal {
  String get name;
  void makeSound() => print('$name이 소리를 냅니다');
}

// extends: name의 구현이 없으므로 여전히 makeSound 로직은 물려받는다
class Dog extends Animal {
  @override
  String get name => '강아지';
  // makeSound()를 새로 작성하지 않아도 부모의 구현을 그대로 쓸 수 있다
}

// implements: 부모의 구현은 전혀 물려받지 못한다
class Cat implements Animal {
  @override
  String get name => '고양이';

  @override
  void makeSound() => print('$name이 야옹 하고 웁니다'); // 직접 다시 작성해야 함
}
```

`Dog`는 `extends`를 썼기 때문에 `Animal`의 `makeSound()` 구현을 그대로 물려받는다. 반면 `Cat`은 `implements`를 썼기 때문에 `Animal`이 가진 시그니처만 물려받고, `makeSound()`도 처음부터 다시 작성해야 한다. 심지어 `Animal`에 필드가 있었다면 `implements`를 사용하는 쪽은 그 필드도 게터/세터 형태로 다시 정의해야 한다.

두 방식의 차이를 표로 정리하면 다음과 같다.

| 구분 | `extends` (상속) | `implements` (구현) |
|---|---|---|
| 물려받는 대상 개수 | 오직 하나 (`with`로 믹스인 추가 가능) | 쉼표로 여러 개 가능 |
| 부모의 구현 코드 | 그대로 물려받아 재사용 가능 | 전혀 물려받지 못함, 전부 재작성 |
| 부모가 추상 클래스일 때 | 구현되지 않은 멤버만 채우면 됨 | 모든 멤버를 새로 구현해야 함 |
| `super` 호출 | 가능 | 불가능 |
| 주된 목적 | 코드 재사용, "is-a" 관계 확장 | 규격 준수 보장, 다중 타입 표현 |
| private 멤버(`_`로 시작) 접근 | 같은 라이브러리 내에서 접근 가능 | 마찬가지로 규격에는 포함되지만 재정의 필요 |

정리하면, 부모의 코드를 재사용하고 싶다면 `extends`, 부모의 구현은 필요 없고 오직 "이런 기능을 갖췄다"는 것만 보장하고 싶다면 `implements`를 선택한다. 10장에서 배운 믹스인(`with`)은 이 둘의 중간쯤에 있다. 믹스인은 구현 코드를 재사용하면서도 단일 상속의 제약 없이 여러 개를 조합할 수 있다는 점에서, 상속과 인터페이스 구현의 장점을 절충한 도구라고 볼 수 있다.

## 언제 무엇을 쓸까

실전에서는 대략 다음과 같은 기준으로 선택하면 도움이 된다.

- 여러 클래스가 공통으로 가져야 할 동작의 "틀"만 정의하고, 구체적인 내용은 각자 다르게 채우고 싶다면 추상 클래스가 적합하다. 위의 `Shape` 예제처럼 공통 메서드(`describe`)와 강제할 멤버(`area`)를 함께 두고 싶을 때 특히 유용하다.
- 서로 관련 없는 클래스들이 "이런 기능도 할 수 있다"는 것만 보장하면 될 때는 평범한 클래스를 `implements`로 구현하거나, 순수하게 추상 멤버만 있는 추상 클래스를 만들어 구현한다. 앞의 `Flyable`, `Swimmable`처럼 하나의 클래스가 여러 규격을 동시에 만족해야 하는 경우가 대표적이다.
- 부모의 코드를 그대로 재사용하면서 일부 동작만 바꾸고 싶다면 10장에서 배운 `extends` 상속이 정답이다.

Dart 커뮤니티에서는 관례적으로 "순수 인터페이스" 역할만 하도록 의도한 클래스에는 모든 멤버를 추상으로 남겨두는 것이 일반적이다. 즉 실제로 인터페이스 전용으로 설계할 때는 대부분 `abstract class`로 선언하고 구현부가 있는 일반 메서드를 섞지 않는다. 반면 공통 로직을 함께 제공하려는 의도라면 앞서 본 `Shape`처럼 일반 메서드와 추상 멤버를 섞어서 사용한다.

## 요약

- Dart에는 `interface` 키워드가 없다. 모든 클래스는 선언되는 순간 암묵적으로 인터페이스 역할을 겸한다.
- `implements`로 다른 클래스의 규격을 구현할 수 있으며, 이때는 부모의 구현 코드를 전혀 물려받지 못하고 모든 멤버를 새로 작성해야 한다.
- `implements`는 쉼표로 여러 개를 나열해 다중 구현이 가능하다는 점이 `extends`와 다르다.
- `abstract class`는 직접 인스턴스화할 수 없는 클래스로, 구현 없는 추상 멤버를 선언해 자식 클래스에 구현을 강제할 수 있다. 동시에 완성된 일반 메서드를 함께 두어 공통 로직을 재사용할 수도 있다.
- `extends`는 코드 재사용과 "is-a" 관계 확장에 쓰이고, `implements`는 규격 준수 보장과 다중 타입 표현에 쓰인다. 10장의 믹스인(`with`)은 이 둘의 절충안이다.

## 연습문제

1. `interface` 키워드 없이 Dart가 인터페이스를 표현하는 방식을 한 문단으로 설명해보자.
2. `Comparable`이라는 이름의 추상 클래스를 만들고, `compareTo(Object other)`라는 추상 메서드를 선언하라. 이를 구현하는 `Money` 클래스를 작성해 두 `Money` 객체의 금액을 비교해보자.
3. `Chargeable`(충전 가능)과 `Portable`(휴대 가능)이라는 두 개의 평범한 클래스를 만들고, 이를 동시에 `implements`하는 `SmartWatch` 클래스를 작성해보자.
4. 다음 코드에서 컴파일 오류가 나는 줄을 찾고 이유를 설명하라.
   ```dart
   abstract class Vehicle {
     void move();
   }

   void main() {
     Vehicle v = Vehicle();
   }
   ```
5. 동일한 부모 클래스 `Animal`을 두고, 하나는 `extends`로 상속받는 `Dog` 클래스를, 다른 하나는 `implements`로 구현하는 `Robot` 클래스를 작성해 두 방식의 코드량 차이를 직접 비교해보자.
