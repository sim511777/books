## 타입마다 똑같은 코드를 반복해야 한다면

값을 하나 담아두는 상자 클래스를 만든다고 생각해봅시다. 정수를 담는 상자와 문자열을 담는 상자가 각각 필요하다면 다음과 같이 작성할 수 있습니다.

```dart
class IntBox {
  int value;
  IntBox(this.value);

  void printValue() => print('담긴 값: $value');
}

class StringBox {
  String value;
  StringBox(this.value);

  void printValue() => print('담긴 값: $value');
}
```

두 클래스는 필드와 메서드의 구조가 완전히 같고, 오직 타입만 다릅니다. 만약 `double`을 담는 상자, `Person`을 담는 상자가 추가로 필요해진다면 똑같은 코드를 계속 복제해야 합니다. 이런 복제는 유지보수를 어렵게 만듭니다. `printValue()`의 동작을 바꾸고 싶다면 존재하는 모든 상자 클래스를 일일이 고쳐야 하기 때문입니다.

한 가지 해법은 `value`의 타입을 `Object?`로 선언해 아무 값이나 받는 것입니다. 하지만 이렇게 하면 상자에서 값을 꺼낼 때마다 원래 타입으로 다시 캐스팅해야 하고, 실수로 다른 타입의 값을 넣어도 컴파일 시점에는 걸러지지 않습니다. 즉 타입 안전성을 잃어버립니다. 이럴 때 필요한 도구가 바로 **제네릭(generics)**입니다.

## 제네릭 클래스: class Box\<T\>

제네릭은 클래스나 함수를 작성할 때 구체적인 타입을 바로 정하지 않고, 사용하는 시점에 타입을 끼워 넣을 수 있게 하는 기능입니다. 타입 자체를 매개변수처럼 다루는 것입니다. 앞의 `IntBox`, `StringBox`를 하나의 제네릭 클래스로 합쳐보겠습니다.

```dart
class Box<T> {
  T value;
  Box(this.value);

  void printValue() => print('담긴 값: $value');
}

void main() {
  var intBox = Box<int>(10);
  var stringBox = Box<String>('안녕');

  intBox.printValue(); // 담긴 값: 10
  stringBox.printValue(); // 담긴 값: 안녕

  print(intBox.value.runtimeType); // int
  print(stringBox.value.runtimeType); // String
}
```

`class Box<T>`에서 `<T>`는 이 클래스가 하나의 타입 매개변수를 받는다는 뜻입니다. `T`는 관례적으로 쓰는 이름일 뿐이고, 실제로는 아무 식별자나 사용할 수 있습니다. `Box<int>`처럼 사용하는 순간 `T`가 `int`로 치환되어, 마치 `IntBox`를 쓰는 것과 똑같이 동작합니다. `Box<String>`을 쓰면 같은 클래스가 이번엔 `String`을 다루는 상자로 바뀝니다.

중요한 점은 타입 안전성이 그대로 유지된다는 것입니다.

```dart
var box = Box<int>(5);
box.value = '문자열'; // 오류! String은 int에 대입할 수 없다
```

`Object?`로 선언했을 때와 달리, 정적 분석기가 `Box<int>`에는 `int`만 들어갈 수 있다는 것을 알고 있으므로 컴파일 시점에 오류를 잡아줍니다. 9장에서 배운 클래스의 장점에 "타입별 재사용"이라는 능력이 더해진 셈입니다.

타입 매개변수는 두 개 이상 둘 수도 있습니다. 예를 들어 두 값을 짝지어 담는 클래스는 다음처럼 작성합니다.

```dart
class Pair<A, B> {
  A first;
  B second;
  Pair(this.first, this.second);

  @override
  String toString() => '($first, $second)';
}

void main() {
  var pair = Pair<String, int>('나이', 25);
  print(pair); // (나이, 25)
}
```

## 제네릭 함수와 메서드

타입 매개변수는 클래스뿐 아니라 함수와 메서드에도 붙일 수 있습니다. 리스트의 첫 번째 요소를 반환하는 함수를 생각해봅시다.

```dart
T first<T>(List<T> items) {
  return items[0];
}

void main() {
  print(first<int>([1, 2, 3])); // 1
  print(first<String>(['가', '나', '다'])); // 가

  // 타입 인자는 대부분 생략해도 대입되는 값으로부터 추론된다
  print(first([10, 20, 30])); // 10
}
```

함수 이름 뒤에 `<T>`를 붙이면 이 함수 전체에서 `T`라는 타입을 자유롭게 쓸 수 있습니다. 호출할 때 `first<int>(...)`처럼 타입을 직접 지정할 수도 있지만, 대부분의 경우 Dart는 전달된 인자로부터 타입을 스스로 추론하므로 생략해도 무방합니다. 7장에서 배운 함수 문법에 타입 매개변수라는 축이 하나 더 추가된 것뿐입니다.

메서드도 마찬가지입니다. 클래스 자체는 제네릭이 아니어도 특정 메서드만 제네릭으로 선언할 수 있습니다.

```dart
class Converter {
  List<T> wrapEach<T>(List<T> items) {
    return items;
  }
}
```

## 표준 라이브러리는 이미 제네릭으로 가득하다

13장에서 다룬 `List`, `Set`, `Map`을 다시 떠올려봅시다. 이 세 타입은 사실 지금까지 배운 것과 똑같은 방식으로 만들어진 제네릭 클래스입니다.

```dart
List<int> scores = [90, 85, 100];
Map<String, int> ages = {'철수': 20, '영희': 22};
```

`List<int>`는 `Box<int>`와 원리가 같습니다. `List`라는 하나의 클래스가 타입 매개변수 `T`를 받아 `List<int>`, `List<String>`, `List<Person>` 등 무수히 많은 구체적인 타입으로 재사용되는 것입니다. `Map<K, V>`는 앞서 만든 `Pair<A, B>`처럼 두 개의 타입 매개변수를 받는 제네릭 클래스입니다. 이제는 왜 `ages['없는사람']`의 타입이 `int?`가 되는지, 왜 `scores.add('문자열')`이 오류가 되는지를 "제네릭 클래스가 타입 매개변수를 `V`, `T`로 고정해서 검사하기 때문"이라고 정확히 설명할 수 있습니다.

직접 만든 클래스 안에서 표준 컬렉션을 활용해 제네릭을 조합할 수도 있습니다.

```dart
class Stack<T> {
  final List<T> _items = [];

  void push(T item) => _items.add(item);
  T pop() => _items.removeLast();
  bool get isEmpty => _items.isEmpty;
}

void main() {
  var stack = Stack<String>();
  stack.push('첫번째');
  stack.push('두번째');
  print(stack.pop()); // 두번째
}
```

`Stack<T>`는 내부적으로 `List<T>`를 사용합니다. 바깥에서 `Stack<String>`을 만들면 내부의 `List<T>`도 자동으로 `List<String>`이 되어, 타입이 한 겹의 제네릭 클래스에서 다른 겹의 제네릭 클래스로 그대로 전달됩니다.

## 제한된 타입 매개변수

`Box<T>`는 `T`에 어떤 타입이든 넣을 수 있습니다. 하지만 상자 안의 값끼리 더하기 연산을 하고 싶다면 어떨까요?

```dart
class NumberBox<T> {
  T value;
  NumberBox(this.value);

  T add(T other) => value + other; // 오류! T는 + 연산자가 있다는 보장이 없다
}
```

`T`는 `String`이 될 수도 있고 `Person`이 될 수도 있으므로, Dart는 `T` 값에 `+` 연산자가 있다는 것을 알 수 없어 컴파일 오류를 냅니다. 이럴 때는 `extends` 키워드로 타입 매개변수가 특정 타입(또는 그 하위 타입)이어야 한다는 제약을 걸 수 있습니다. 이를 **제한된 타입 매개변수(bounded type parameter)**라고 부릅니다.

```dart
class NumberBox<T extends num> {
  T value;
  NumberBox(this.value);

  num add(T other) => value + other; // num은 int, double의 공통 상위 타입
}

void main() {
  var box = NumberBox<int>(10);
  print(box.add(5)); // 15

  // var wrong = NumberBox<String>('a'); // 오류! String은 num의 하위 타입이 아니다
}
```

`<T extends num>`는 "`T` 자리에는 `num`이거나 `num`의 하위 타입(즉 `int` 또는 `double`)만 올 수 있다"는 뜻입니다. 여기서 `extends`는 11장에서 배운 클래스 상속의 `extends`와 같은 단어를 쓰지만 의미는 조금 다릅니다. 상속에서는 부모 클래스를 하나 지정하는 것이었지만, 타입 매개변수의 `extends`는 "이 타입이거나 그 이하로 구체적인 타입"이라는 경계선을 긋는 역할을 합니다. 이 제약이 있으면 `value + other`처럼 `num`이 제공하는 연산을 `T` 값에 대해 안전하게 사용할 수 있습니다. 반대로 `NumberBox<String>`처럼 경계를 벗어난 타입을 넣으려 하면 정적 분석기가 즉시 막아줍니다.

## 요약

- 타입마다 거의 동일한 클래스나 함수를 반복해서 작성해야 하는 문제는 **제네릭**으로 해결할 수 있습니다. `class Box<T>`처럼 타입을 매개변수로 받아 하나의 코드로 여러 타입을 안전하게 다룹니다.
- 타입 매개변수는 클래스(`Box<T>`, `Pair<A, B>`)뿐 아니라 함수와 메서드(`T first<T>(List<T> items)`)에도 붙일 수 있으며, 대부분 호출 시점에 타입이 자동으로 추론됩니다.
- 13장에서 다룬 `List<T>`, `Map<K, V>`, `Set<T>`는 표준 라이브러리가 제공하는 대표적인 제네릭 클래스입니다. 직접 만든 클래스 내부에서도 이들을 그대로 활용해 제네릭을 조합할 수 있습니다.
- `<T extends num>`처럼 타입 매개변수에 제약을 걸면, 그 제약이 보장하는 연산이나 멤버를 타입 매개변수 값에 대해 안전하게 사용할 수 있습니다.

## 연습문제

1. `IntBox`와 `StringBox`처럼 타입만 다르고 구조가 같은 클래스 두 개를 직접 작성해본 뒤, 이를 하나의 `Box<T>` 제네릭 클래스로 합쳐보세요.
2. 리스트를 받아 가장 마지막 요소를 반환하는 제네릭 함수 `T last<T>(List<T> items)`를 작성하고, `int`와 `String` 리스트로 각각 호출해보세요.
3. `Pair<A, B>` 클래스에 두 값을 서로 바꾸는(swap) 메서드 `Pair<B, A> swapped()`를 추가해보세요.
4. `Stack<T>` 클래스에 맨 위 요소를 제거하지 않고 확인만 하는 `T peek()` 메서드를 추가해보세요.
5. `<T extends num>` 제약을 가진 제네릭 클래스 `Calculator<T extends num>`를 만들고, 두 값을 더하는 `add`와 곱하는 `multiply` 메서드를 작성해보세요. 그리고 `Calculator<String>`을 만들려고 할 때 어떤 오류가 발생하는지 확인해보세요.
