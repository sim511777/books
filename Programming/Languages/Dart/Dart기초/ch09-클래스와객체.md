## 클래스란 무엇인가

지금까지는 변수, 함수, 제어문처럼 프로그램의 작은 조각들을 다뤘습니다. 하지만 실제 프로그램은 "은행 계좌", "학생", "주문서"처럼 여러 데이터와 그 데이터를 다루는 동작이 하나로 묶인 대상을 다룹니다. Dart에서 이런 대상을 표현하는 도구가 바로 **클래스(class)**입니다.

클래스는 어떤 대상이 어떤 데이터(필드)를 가지고 어떤 동작(메서드)을 할 수 있는지 정의하는 **설계도**입니다. 설계도 자체는 실체가 아닙니다. 설계도를 바탕으로 실제로 만들어진 것을 **객체(object)** 또는 **인스턴스(instance)**라고 부릅니다. 같은 클래스에서 여러 개의 인스턴스를 만들 수 있고, 각 인스턴스는 같은 구조를 공유하면서도 서로 다른 값을 가질 수 있습니다.

```dart
class Person {
  String name;
  int age;

  Person(this.name, this.age);

  void introduce() {
    print('안녕하세요, 저는 $name이고 $age살입니다.');
  }
}

void main() {
  var p1 = Person('지수', 25);
  var p2 = Person('민호', 30);

  p1.introduce(); // 안녕하세요, 저는 지수이고 25살입니다.
  p2.introduce(); // 안녕하세요, 저는 민호이고 30살입니다.
}
```

`Person`이라는 하나의 클래스에서 `p1`, `p2`라는 두 개의 서로 다른 객체가 만들어졌습니다. 이 관계를 그림으로 보면 다음과 같습니다.

![클래스와 인스턴스의 관계](images/ch09-class-instance.svg)

클래스는 하나뿐이지만, 그 클래스로부터 만들어지는 객체는 얼마든지 있을 수 있고 각자 독립된 필드 값을 가집니다. 7장에서 함수가 "재사용 가능한 동작의 묶음"이었다면, 클래스는 "데이터와 그 데이터에 관련된 동작을 함께 묶은 것"이라고 이해하면 됩니다.

## 필드와 생성자

클래스 안에 선언된 변수를 **필드(field)**라고 합니다. 필드는 객체마다 독립적으로 값을 가지는 저장 공간입니다. 객체를 만들 때 필드 값을 초기화하는 특별한 함수가 **생성자(constructor)**입니다. 생성자 이름은 클래스 이름과 같아야 합니다.

```dart
class BankAccount {
  String owner;
  double balance;

  // 기본 생성자
  BankAccount(this.owner, this.balance);
}
```

`this.owner`, `this.balance`처럼 생성자 매개변수 앞에 `this.`를 붙이면 "이 매개변수 값을 같은 이름의 필드에 그대로 대입한다"는 뜻이 됩니다. Dart는 이런 패턴이 매우 흔하기 때문에 별도의 문법으로 지원합니다. 아래처럼 대입문을 직접 쓰는 것과 결과는 같습니다.

```dart
class BankAccount {
  String owner;
  double balance;

  BankAccount(String owner, double balance)
      : owner = owner,
        balance = balance;
}
```

하지만 매개변수 이름과 필드 이름이 같을 때는 `this.owner` 형태가 훨씬 간결하므로 실무에서는 거의 이 방식을 씁니다.

## this 키워드

`this`는 "현재 이 메서드를 호출하고 있는 객체 자기 자신"을 가리키는 참조입니다. 필드 이름과 매개변수 이름이 겹칠 때 구분하는 용도로 가장 많이 쓰이지만, 메서드 안에서 명시적으로 자신을 가리켜야 할 때도 사용합니다.

```dart
class Counter {
  int value = 0;

  Counter increase(int amount) {
    this.value = this.value + amount;
    return this; // 자기 자신을 반환하면 메서드를 연속으로 호출할 수 있다
  }
}

void main() {
  var c = Counter();
  c.increase(3).increase(5).increase(2);
  print(c.value); // 10
}
```

필드와 매개변수 이름이 겹치지 않는 상황에서는 `this.`를 생략해도 되지만, 코드의 의도를 명확히 하고 싶을 때는 붙여도 무방합니다.

## 명명된 생성자

하나의 클래스가 서로 다른 방식으로 객체를 초기화해야 할 때가 있습니다. 예를 들어 은행 계좌를 "초기 입금액과 함께 개설"할 수도 있고 "잔액 0원인 빈 계좌로 개설"할 수도 있습니다. Dart는 클래스당 이름 없는 생성자를 하나만 허용하지만, 이름이 붙은 생성자는 여러 개 만들 수 있습니다. 이를 **명명된 생성자(named constructor)**라고 하며 `ClassName.name` 형태로 선언합니다.

```dart
class BankAccount {
  String owner;
  double balance;

  BankAccount(this.owner, this.balance);

  // 명명된 생성자: 빈 계좌를 만든다
  BankAccount.empty(this.owner) : balance = 0.0;

  // 명명된 생성자: 다른 계좌를 복제한다
  BankAccount.from(BankAccount other)
      : owner = other.owner,
        balance = other.balance;
}

void main() {
  var a1 = BankAccount('지수', 10000);
  var a2 = BankAccount.empty('민호');
  var a3 = BankAccount.from(a1);

  print(a2.balance); // 0.0
  print(a3.owner);   // 지수
}
```

`BankAccount.empty`처럼 생성자 이름 뒤에 콜론(`:`)을 붙이고 필드를 초기화하는 부분을 **초기화 리스트(initializer list)**라고 합니다. 초기화 리스트는 생성자 본문이 실행되기 전에, 필드 값을 계산하거나 다른 필드를 참조해 값을 정하는 데 사용됩니다. 특히 `final` 필드처럼 한 번만 값을 대입할 수 있는 필드를 초기화할 때 유용합니다.

```dart
class Rectangle {
  final double width;
  final double height;
  final double area;

  Rectangle(this.width, this.height) : area = width * height;
}
```

생성자 본문(`{ }` 안)이 실행되기 전에 `area`가 계산되므로, 본문에서는 이미 계산이 끝난 `area`를 바로 사용할 수 있습니다.

## 게터와 세터

필드에 직접 접근하는 대신, 값을 읽거나 쓸 때 추가 로직을 넣고 싶을 때가 있습니다. Dart는 이를 위해 **게터(getter)**와 **세터(setter)**를 제공합니다. 게터는 `get` 키워드로, 세터는 `set` 키워드로 선언하며, 사용하는 쪽에서는 마치 필드처럼 괄호 없이 접근합니다.

```dart
class BankAccount {
  String owner;
  double _balance; // 밑줄(_)로 시작하면 같은 파일 밖에서는 접근할 수 없다

  BankAccount(this.owner, this._balance);

  double get balance => _balance;

  set balance(double newBalance) {
    if (newBalance < 0) {
      throw ArgumentError('잔액은 음수가 될 수 없습니다.');
    }
    _balance = newBalance;
  }
}

void main() {
  var account = BankAccount('지수', 5000);
  print(account.balance); // 5000.0 - 괄호 없이 필드처럼 접근

  account.balance = 8000; // 세터 호출
  print(account.balance); // 8000.0

  account.balance = -100; // ArgumentError 발생
}
```

이름 앞에 밑줄(`_`)을 붙인 `_balance`는 Dart의 **라이브러리 프라이버시(privacy)** 규칙에 따라 같은 파일(라이브러리) 밖에서는 접근할 수 없습니다. 다른 언어의 `private` 키워드와 비슷한 역할을 하지만, Dart는 클래스 단위가 아니라 파일 단위로 이 규칙을 적용한다는 점이 특징입니다. 이렇게 필드를 감추고 게터/세터로만 접근하게 만들면, 나중에 유효성 검사나 계산 로직을 추가해도 이를 사용하는 코드는 전혀 바꿀 필요가 없습니다.

## 종합 예제: BankAccount 설계하기

지금까지 배운 내용을 모아 조금 더 완성도 있는 `BankAccount` 클래스를 만들어 봅시다.

```dart
class BankAccount {
  final String owner;
  double _balance;

  BankAccount(this.owner, this._balance);

  BankAccount.empty(String owner) : this(owner, 0.0);

  double get balance => _balance;

  void deposit(double amount) {
    if (amount <= 0) {
      throw ArgumentError('입금액은 0보다 커야 합니다.');
    }
    _balance += amount;
  }

  void withdraw(double amount) {
    if (amount > _balance) {
      throw StateError('잔액이 부족합니다.');
    }
    _balance -= amount;
  }

  @override
  String toString() => '$owner의 계좌 (잔액: $_balance원)';
}

void main() {
  var account = BankAccount.empty('지수');
  account.deposit(50000);
  account.withdraw(20000);
  print(account); // 지수의 계좌 (잔액: 30000.0원)
}
```

여기서 `BankAccount.empty` 생성자는 `this(owner, 0.0)` 형태로 같은 클래스의 다른 생성자를 재사용하고 있습니다. 이렇게 생성자에서 다른 생성자를 호출하는 것을 **생성자 리다이렉트(constructor redirect)**라고 하며, 중복되는 초기화 로직을 줄이는 데 유용합니다. `toString` 메서드에 붙은 `@override`는 원래 모든 클래스가 기본으로 가지고 있는 동작을 재정의했다는 표시인데, 이 내용은 10장 상속과 믹스인에서 자세히 다룹니다.

## 요약

- 클래스는 데이터(필드)와 동작(메서드)을 묶은 설계도이며, 객체(인스턴스)는 그 설계도로 실제로 만들어진 결과물입니다. 같은 클래스에서 여러 객체를 만들 수 있고, 각 객체는 독립된 필드 값을 가집니다.
- 생성자는 객체를 초기화하는 특별한 함수로, `this.필드명` 문법을 사용하면 매개변수 값을 필드에 간결하게 대입할 수 있습니다.
- 명명된 생성자(`ClassName.name`)를 사용하면 하나의 클래스에 여러 가지 초기화 방식을 제공할 수 있습니다.
- 초기화 리스트(`:` 뒤에 오는 부분)는 생성자 본문 실행 전에 필드 값을 계산하며, `final` 필드를 초기화할 때 특히 중요합니다.
- 게터(`get`)와 세터(`set`)를 사용하면 필드처럼 보이는 문법으로 값을 읽고 쓰면서도, 내부적으로 유효성 검사나 계산 로직을 추가할 수 있습니다.
- 이름 앞에 밑줄(`_`)을 붙이면 파일(라이브러리) 단위로 접근이 제한됩니다.

다음 장에서는 클래스 사이의 관계, 즉 상속(`extends`)과 믹스인(`mixin`)을 통해 여러 클래스가 코드를 공유하는 방법을 살펴봅니다.
