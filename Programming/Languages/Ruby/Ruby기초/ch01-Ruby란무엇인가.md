# 1장. Ruby란 무엇인가

## Ruby의 탄생

Ruby는 1995년 일본의 프로그래머 마츠모토 유키히로(松本行弘, 애칭 "마츠(Matz)")가 처음 세상에 공개한 프로그래밍 언어입니다. 마츠모토는 평소 Perl, Python, Smalltalk, Lisp 같은 여러 언어의 특징을 눈여겨보다가, "내가 정말 쓰고 싶은 언어가 없다"는 생각에 직접 언어를 설계하기 시작했다고 알려져 있습니다. 그는 스크립트 언어의 간결함과 Smalltalk 같은 언어의 철저한 객체지향성을 하나로 묶어보려 했고, 그 결과물이 바로 Ruby입니다.

이름의 유래에 대해서는 여러 이야기가 전해지는데, 그중 널리 알려진 것은 동료 개발자와 이름을 의논하던 중 탄생석 이야기가 나왔고, 당시 사용 중이던 언어 이름(Perl, 진주)에 빗대어 그보다 한 단계 더 값진 보석인 "루비(Ruby)"로 정했다는 설명입니다. 실제 유래가 정확히 어느 쪽인지는 마츠모토 본인의 회고에서도 여러 버전으로 소개된 적이 있어, 하나의 정설로 굳어져 있지는 않습니다.

초창기 Ruby는 일본 내에서 주로 알려진 언어였지만, 2004년 데이비드 하이네마이어 핸슨(David Heinemeier Hansson)이 Ruby로 만든 웹 프레임워크 **Ruby on Rails**를 공개하면서 상황이 크게 바뀌었습니다. Rails는 "설정보다 관습(Convention over Configuration)"이라는 원칙과 빠른 개발 속도로 큰 반향을 일으켰고, 이를 계기로 Ruby는 전 세계 개발자들의 관심을 받는 언어로 성장했습니다.

## 설계 철학: 프로그래머의 행복

Ruby를 이야기할 때 빠지지 않는 문장이 있습니다. 마츠모토가 여러 인터뷰에서 밝힌 "Ruby는 프로그래머를 행복하게 만들기 위해 설계되었다"는 말입니다. 대부분의 언어가 "기계가 빠르게 처리할 수 있는가"를 최우선으로 고려해 설계되는 것과 달리, Ruby는 "사람이 코드를 작성하고 읽을 때 얼마나 자연스럽고 즐거운가"를 핵심 가치로 삼습니다.

이 철학은 실제 문법 곳곳에 녹아 있습니다. 예를 들어 조건문 하나를 표현하는 방법이 여러 가지 존재합니다.

```ruby
age = 20

# 표준적인 조건문
if age >= 18
  puts "성인입니다"
end

# 뒤에 붙는 조건문(후위 if)으로 더 짧게
puts "성인입니다" if age >= 18

# unless로 부정 조건을 자연스럽게 표현
puts "미성년자입니다" unless age >= 18
```

셋 다 같은 의미를 표현하지만, 상황에 따라 더 읽기 좋은 방식을 자유롭게 골라 쓸 수 있습니다. 이런 유연함은 "언어가 프로그래머에게 하나의 정답만을 강요하지 않는다"는 Ruby의 태도를 잘 보여줍니다.

Ruby 커뮤니티에서는 이런 설계 방향을 **최소 놀람의 원칙(Principle of Least Surprise)**이라는 말로 표현하기도 합니다. 코드를 처음 보는 사람도 "아마 이렇게 동작하겠지"라고 예상한 대로 실제로 동작해야 한다는 뜻입니다. 물론 무엇이 "놀랍지 않은 동작"인지는 사람마다 다르게 느낄 수 있어 절대적인 기준은 아니지만, Ruby의 문법과 표준 라이브러리를 설계하는 데 중요한 지침 역할을 해왔습니다.

## 동적 타입 언어

Ruby는 **동적 타입(dynamic typing)** 언어입니다. 변수를 선언할 때 정수형인지 문자열인지 미리 지정할 필요가 없고, 하나의 변수에 서로 다른 타입의 값을 자유롭게 담을 수도 있습니다.

```ruby
value = 10          # 지금은 정수
puts value.class    # Integer

value = "열 개"      # 이제는 문자열
puts value.class    # String

value = [1, 2, 3]   # 이제는 배열
puts value.class    # Array
```

C나 Java처럼 `int`, `String` 같은 타입을 변수 선언 시점에 명시하는 언어를 **정적 타입(static typing)** 언어라고 부릅니다. 정적 타입 언어는 컴파일 시점에 타입 오류를 미리 잡아낼 수 있다는 장점이 있는 반면, Ruby 같은 동적 타입 언어는 타입을 신경 쓰지 않고 빠르게 코드를 작성할 수 있다는 장점이 있습니다. 대신 타입과 관련된 실수는 프로그램을 실제로 실행해봐야 드러나는 경우가 많으므로, 이 특성을 이해하고 테스트를 충분히 작성하는 습관이 중요합니다. 변수와 자료형에 대해서는 3장에서 더 자세히 다룹니다.

## 순수 객체지향: 모든 것이 객체

Ruby의 가장 큰 특징 중 하나는 **철저한 객체지향성**입니다. Ruby에서는 정수, 문자열, 배열은 물론이고 `nil`(값이 없음을 나타내는 특별한 값)이나 `true`, `false`, 심지어 클래스 그 자체까지도 모두 객체입니다. 예외 없이, 정말로 "모든 것이 객체"입니다.

```ruby
puts 1.class          # Integer
puts nil.class        # NilClass
puts true.class       # TrueClass
puts "hello".class    # String
puts Integer.class    # Class

# 정수도 객체이므로 메서드를 호출할 수 있습니다
puts 5.even?          # false
puts (-3).abs         # 3

# 심지어 사칙연산도 메서드 호출입니다
puts 1 + 2            # 3
puts 1.+(2)           # 3 (위와 완전히 동일한 표현)
```

마지막 예시가 특히 인상적인데, Ruby에서 `1 + 2`라는 익숙한 수식은 사실 정수 객체 `1`이 `+`라는 이름의 메서드를 호출하면서 `2`를 인자로 넘기는 것과 같습니다. Java나 C 같은 언어에서는 `int`, `boolean` 같은 **원시 타입(primitive type)**이 따로 존재해서 객체처럼 다룰 수 없지만, Ruby에는 그런 예외가 없습니다. 이 덕분에 Ruby에서는 숫자든 문자열이든 `nil`이든 항상 동일한 방식(메서드 호출)으로 다룰 수 있어 언어 전체의 일관성이 높습니다.

이처럼 클래스와 객체를 중심으로 프로그램을 구성하는 방식은 9장 클래스와 객체, 10장 상속과 모듈에서 본격적으로 다룹니다.

## Ruby의 여러 구현체

"Ruby"라는 이름은 언어 자체(문법과 동작 방식에 대한 명세)를 가리키기도 하고, 그 언어를 실제로 실행하는 프로그램(구현체)을 가리키기도 합니다. 대표적인 구현체는 다음과 같습니다.

- **MRI(Matz's Ruby Interpreter)**: 흔히 **CRuby**라고도 불리며, 마츠모토를 중심으로 개발된 공식 기준 구현체입니다. C 언어로 작성되어 있고, 대부분의 사람들이 "Ruby를 설치한다"고 할 때 설치하는 것이 바로 이 MRI입니다. 이 책에서 다루는 모든 예제도 MRI를 기준으로 합니다.
- **JRuby**: Java 가상 머신(JVM) 위에서 동작하는 Ruby 구현체입니다. Java로 작성된 라이브러리를 Ruby 코드에서 그대로 가져다 쓸 수 있어, Java 기반 인프라를 이미 사용하고 있는 조직에서 유용합니다.
- **TruffleRuby**: GraalVM이라는 고성능 가상 머신 위에서 동작하는 구현체로, 특정 상황에서 MRI보다 빠른 실행 속도를 목표로 개발되고 있습니다.

이 밖에도 몇 가지 구현체가 존재하지만, 입문 단계에서는 "Ruby를 실행하는 프로그램이 하나만 있는 것은 아니다" 정도로 기억해두면 충분합니다. 이 책의 2장에서 설치하는 것도 가장 널리 쓰이는 MRI입니다.

## Ruby가 활약하는 분야

Ruby는 다양한 영역에서 쓰이고 있지만, 특히 다음 분야에서 두드러진 존재감을 보입니다.

**웹 개발**은 Ruby가 가장 유명세를 얻은 분야입니다. 앞서 언급한 **Ruby on Rails**는 지금도 수많은 스타트업과 서비스의 백엔드를 지탱하고 있으며, "아이디어를 빠르게 실제 서비스로 만들어보고 싶을 때" 즐겨 선택되는 프레임워크입니다.

**스크립팅과 자동화**도 Ruby가 강점을 보이는 영역입니다. 파일을 정리하거나, 반복적인 작업을 자동화하거나, 텍스트 데이터를 가공하는 짧은 스크립트를 작성할 때 Ruby의 간결한 문법이 큰 도움이 됩니다.

**DevOps 도구** 분야에서도 Ruby의 흔적을 쉽게 찾을 수 있습니다. 서버 구성 관리 도구인 Chef나 Puppet, 가상 개발 환경을 다루는 Vagrant 등 인프라 자동화 도구들이 Ruby로 작성되었거나 Ruby 문법을 설정 언어로 채택하고 있습니다.

## 다른 언어와 비교해보는 Ruby만의 색깔

같은 목적을 가진 코드를 여러 언어로 작성해 비교해보면 Ruby의 개성이 더 뚜렷하게 드러납니다.

### 블록 문법

Ruby에는 **블록(block)**이라는 독특한 문법이 있습니다. 메서드에 코드 덩어리 자체를 인자처럼 넘기는 방식인데, 반복 작업을 표현할 때 특히 자연스럽습니다.

```ruby
# Ruby: 배열의 각 요소를 순회하며 출력
[1, 2, 3].each do |number|
  puts number * 2
end
```

Python이라면 보통 `for` 문을 사용해 다음과 같이 표현합니다.

```python
# Python: for 문을 사용한 동일한 로직
for number in [1, 2, 3]:
    print(number * 2)
```

두 코드 모두 "각 숫자를 두 배로 만들어 출력한다"는 같은 일을 하지만, Ruby는 `each`라는 배열의 메서드에 "이 블록을 실행해줘"라고 코드 덩어리를 통째로 넘기는 방식으로 표현합니다. 이 블록 문법은 11장 블록, 프로크, 람다와 12장 이터레이터와 Enumerable에서 훨씬 깊이 있게 다룹니다.

### 유연한 문법

Ruby는 괄호나 세미콜론 같은 문법적 장치를 상당 부분 생략할 수 있도록 허용합니다.

```ruby
# 괄호를 생략해도 동작합니다
def greet name
  puts "안녕하세요, #{name}님"
end

greet "지수"

# 물론 괄호를 붙여도 됩니다
def greet(name)
  puts "안녕하세요, #{name}님"
end

greet("지수")
```

Java였다면 메서드 정의와 호출 모두 괄호가 필수이고, 세미콜론으로 문장의 끝을 명시해야 합니다.

```java
// Java: 괄호와 세미콜론이 필수
void greet(String name) {
    System.out.println("안녕하세요, " + name + "님");
}

greet("지수");
```

이러한 문법적 여유는 코드를 짧게 쓰고 싶은 사람과, 명시적으로 쓰고 싶은 사람 모두를 만족시키려는 Ruby의 태도를 보여줍니다.

### 메타프로그래밍

Ruby는 프로그램이 실행되는 도중에 클래스나 메서드 자체를 동적으로 정의하거나 수정할 수 있는 **메타프로그래밍(metaprogramming)** 기능을 폭넓게 제공합니다.

```ruby
class Person
  # 실행 시점에 메서드를 동적으로 정의합니다
  define_method(:greet) do
    puts "안녕하세요!"
  end
end

Person.new.greet   # 안녕하세요!
```

이 코드는 `greet`라는 메서드를 미리 손으로 적어두지 않고, `define_method`라는 또 다른 메서드를 이용해 프로그램 실행 중에 만들어냅니다. Java나 C 같은 언어에서는 이런 일이 훨씬 제한적이거나 별도의 복잡한 장치(리플렉션 등)를 필요로 하지만, Ruby에서는 언어의 기본 기능만으로 자연스럽게 가능합니다. 메타프로그래밍은 잘못 쓰면 코드를 이해하기 어렵게 만들 수도 있는 강력한 도구이므로, 16장 메타프로그래밍 기초에서 기본 개념과 주의할 점을 함께 다룹니다.

## 요약

- Ruby는 1995년 마츠모토 유키히로가 공개한 언어로, 2004년 Ruby on Rails의 등장을 계기로 세계적으로 널리 퍼졌습니다.
- Ruby의 핵심 설계 철학은 "프로그래머의 행복"이며, 하나의 로직을 여러 방식으로 자연스럽게 표현할 수 있도록 유연한 문법을 제공합니다.
- Ruby는 동적 타입 언어로, 변수에 타입을 미리 선언하지 않고 실행 중에 타입이 결정됩니다.
- Ruby는 정수, `nil`, `true`/`false`, 클래스까지 예외 없이 모든 것을 객체로 다루는 순수 객체지향 언어입니다.
- 대표적인 구현체로 공식 구현체인 MRI(CRuby), JVM 기반의 JRuby, GraalVM 기반의 TruffleRuby가 있습니다.
- Ruby는 웹 개발(Ruby on Rails), 스크립팅/자동화, DevOps 도구 분야에서 특히 널리 쓰입니다.
- 블록 문법, 유연한 문법, 강력한 메타프로그래밍 기능은 다른 언어와 구분되는 Ruby만의 개성입니다.

## 연습문제

1. Ruby의 설계 철학인 "프로그래머의 행복"이 실제 문법에서 어떻게 드러나는지, 본문에 나온 조건문 예시 외에 자신이 이해한 방식으로 한 문장으로 설명해보세요.
2. 동적 타입 언어와 정적 타입 언어의 차이를 각각 하나의 장점과 함께 설명해보세요.
3. 다음 중 Ruby에서 객체가 아닌 것을 고르세요: `1`, `nil`, `true`, `"Ruby"`, 없음(모두 객체입니다). 그리고 왜 그렇게 생각하는지 이유를 적어보세요.
4. irb나 파일 실행 없이, `10.class`, `nil.class`, `"hello".class`를 실행하면 각각 어떤 결과가 나올지 예상해서 적어보세요. (2장에서 직접 실행해 확인해봅니다.)
5. MRI, JRuby, TruffleRuby 중 자신이 Java 기반 시스템과 Ruby 코드를 함께 써야 하는 상황이라면 어떤 구현체를 고려해볼 만한지, 그 이유와 함께 적어보세요.
