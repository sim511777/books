지금까지 17개 장에 걸쳐 Ruby의 문법과 다양한 기능을 배웠습니다. 하지만 "동작하는 코드"와 "좋은 코드"는 다릅니다. 좋은 코드란 동작하는 것은 물론이고, 다른 사람(그리고 몇 달 뒤의 자신)이 읽었을 때 의도를 쉽게 파악할 수 있고, 문제가 생겼을 때 안심하고 수정할 수 있는 코드입니다. 이 마지막 장에서는 Ruby다운 코드 스타일, 코드 품질을 관리하는 도구, 테스트의 중요성을 살펴본 뒤, 책 전체를 되돌아보고 앞으로의 학습 방향을 제안합니다.

## Ruby다운(idiomatic) 코드 스타일

같은 동작을 하는 코드라도 "Ruby답게" 쓰는 방법과 그렇지 않은 방법이 있습니다. Ruby 커뮤니티에서는 이렇게 그 언어의 관용구와 철학을 잘 살린 코드를 **idiomatic한 코드**라고 부릅니다.

### 불필요한 괄호 생략하기

1장에서 살펴봤듯 Ruby는 메서드 호출 시 괄호를 생략할 수 있습니다. 인자가 없거나 문맥이 명확한 경우, 특히 `puts`처럼 자주 쓰는 메서드는 괄호 없이 쓰는 편이 더 자연스럽게 읽힙니다.

```ruby
# 괄호가 있어도 문법적으로는 문제없지만
puts("안녕하세요")

# Ruby 커뮤니티에서는 이렇게 쓰는 쪽을 더 선호합니다
puts "안녕하세요"
```

다만 괄호를 생략하면 오히려 헷갈리는 경우도 있습니다. 예를 들어 메서드를 여러 개 중첩해서 호출하거나, 인자가 여러 개라 어디까지가 인자인지 애매해질 수 있는 상황에서는 괄호를 명시하는 쪽이 더 안전합니다.

```ruby
# 괄호가 없으면 어디까지가 인자인지 헷갈릴 수 있습니다
def calculate_total(price, tax_rate)
  price + price * tax_rate
end

# 이런 경우는 괄호를 붙이는 편이 명확합니다
result = calculate_total(1000, 0.1)
```

정리하면, "괄호를 아예 쓰지 않는 것"이 목표가 아니라 "코드를 읽는 사람이 헷갈리지 않는 선에서 불필요한 장식을 덜어내는 것"이 Ruby다운 스타일의 핵심입니다.

### unless와 until을 적절히 사용하기

`unless`는 `if !조건`을, `until`은 `while !조건`을 대신할 수 있는 Ruby 고유의 표현입니다. 부정 조건을 자연스러운 문장처럼 표현하고 싶을 때 유용합니다.

```ruby
stock = 0

# if !condition보다
puts "품절입니다" if !(stock > 0)

# unless가 더 읽기 좋습니다
puts "품절입니다" unless stock > 0
```

```ruby
attempts = 0

# while이 아니라 조건이 참이 될 때까지 반복하고 싶다는 의도를 그대로 담아
until attempts >= 3
  attempts += 1
  puts "#{attempts}번째 시도"
end
```

다만 `unless`에 `&&`나 `||`가 여러 개 섞인 복잡한 조건을 넣거나, `unless ... else`처럼 `else`를 붙이는 것은 피하는 것이 좋습니다. 부정 조건에 또 다른 부정이나 복잡한 논리가 겹치면 코드를 읽는 사람이 머릿속으로 이중 부정을 풀어야 해서 오히려 가독성이 떨어지기 때문입니다. 그런 경우라면 차라리 `if`를 사용해 긍정문으로 표현하는 편이 낫습니다.

```ruby
# 좋지 않은 예: unless에 else, 복잡한 조건이 섞임
unless user.active? && user.verified?
  puts "이용할 수 없습니다"
else
  puts "환영합니다"
end

# 이렇게 if로 바꾸면 더 명확합니다
if user.active? && user.verified?
  puts "환영합니다"
else
  puts "이용할 수 없습니다"
end
```

### 가드절(guard clause) 패턴

**가드절**은 메서드 초입에서 예외적인 상황을 먼저 걸러내고 조기에 반환함으로써, 정상적인 로직을 들여쓰기 깊숙한 곳에 파묻지 않는 패턴입니다. 5장에서 배운 후위 조건문과 잘 어울리는 스타일입니다.

가드절을 쓰지 않으면 다음처럼 조건문이 중첩되기 쉽습니다.

```ruby
def withdraw(account, amount)
  if account.active?
    if amount > 0
      if account.balance >= amount
        account.balance -= amount
        puts "#{amount}원을 출금했습니다"
      else
        puts "잔액이 부족합니다"
      end
    else
      puts "출금 금액은 0보다 커야 합니다"
    end
  else
    puts "비활성화된 계좌입니다"
  end
end
```

같은 로직을 가드절로 다시 쓰면 다음과 같습니다.

```ruby
def withdraw(account, amount)
  return puts "비활성화된 계좌입니다" unless account.active?
  return puts "출금 금액은 0보다 커야 합니다" unless amount > 0
  return puts "잔액이 부족합니다" if account.balance < amount

  account.balance -= amount
  puts "#{amount}원을 출금했습니다"
end
```

가드절 버전은 들여쓰기가 한 단계로 유지되고, "예외 상황을 먼저 쳐낸 뒤 정상 흐름을 다룬다"는 순서가 코드 위에서 아래로 자연스럽게 읽힙니다. 조건이 중첩될수록 이 차이는 더욱 두드러집니다.

## 정적 분석 도구: RuboCop

사람마다 코드를 쓰는 습관이 조금씩 다릅니다. 어떤 사람은 문자열에 큰따옴표를 쓰고, 어떤 사람은 작은따옴표를 씁니다. 어떤 사람은 들여쓰기에 공백 2칸을, 어떤 사람은 4칸을 씁니다. 여러 사람이 함께 작업하는 프로젝트에서 이런 차이가 뒤섞이면 코드 전체의 일관성이 떨어지고 읽기 피곤해집니다.

**RuboCop**은 17장에서 이름만 소개했던 gem으로, Ruby 커뮤니티에서 정립된 스타일 가이드를 기준으로 코드를 자동으로 점검해주는 정적 분석(static analysis) 도구입니다. "정적"이라는 말은 코드를 실제로 실행하지 않고 코드 자체(텍스트)만 분석한다는 뜻입니다.

```bash
gem install rubocop
rubocop app.rb
```

RuboCop을 실행하면 줄 길이 초과, 사용하지 않는 변수, 불필요한 괄호, 따옴표 스타일 불일치 등을 찾아 위치와 함께 알려줍니다. 상당수의 지적 사항은 다음 명령으로 자동으로 고칠 수도 있습니다.

```bash
rubocop -a app.rb
```

RuboCop이 지적하는 규칙 하나하나를 처음부터 완벽히 외울 필요는 없습니다. 중요한 것은 "코드 스타일도 팀이 합의하고 도구로 강제할 수 있는 대상"이라는 사실을 아는 것입니다. 프로젝트 루트에 `.rubocop.yml` 파일을 두면 팀의 상황에 맞게 규칙을 켜고 끄거나 세부 값을 조정할 수 있습니다.

## 테스트의 중요성과 RSpec 맛보기

지금까지 작성한 코드가 올바르게 동작하는지는 어떻게 확인해왔을까요? 대부분 `puts`로 값을 출력해서 눈으로 직접 확인하는 방식이었을 것입니다. 이 방법은 예제 코드 몇 줄을 확인하기에는 충분하지만, 코드가 수백, 수천 줄로 늘어나고 여러 사람이 함께 수정하는 프로젝트에서는 한계가 뚜렷합니다. 어떤 기능을 고쳤을 때 그 수정이 다른 기능을 망가뜨리지 않았는지, 매번 사람이 눈으로 일일이 확인하는 것은 비현실적이기 때문입니다.

**테스트 코드**는 "이 코드가 이런 입력에 대해 이런 결과를 내야 한다"는 기대를 코드 자체로 작성해두고, 필요할 때마다 자동으로 실행해 검증하는 방법입니다. 한 번 작성해두면 코드를 수정할 때마다 반복해서 실행하며 "예전에 잘 되던 기능이 여전히 잘 되는지"를 순식간에 확인할 수 있습니다.

Ruby 진영에서 널리 쓰이는 테스트 프레임워크가 17장에서 이름을 언급했던 **RSpec**입니다. RSpec은 테스트 코드를 사람이 읽는 문장에 가깝게 작성할 수 있도록 `describe`, `it`, `expect` 같은 표현을 제공합니다. 다음은 간단한 계산기 클래스와 그에 대한 RSpec 테스트의 형태를 보여주는 예시입니다.

```ruby
# lib/calculator.rb
class Calculator
  def add(a, b)
    a + b
  end
end
```

```ruby
# spec/calculator_spec.rb
require "calculator"

describe Calculator do
  describe "#add" do
    it "두 숫자를 더한 값을 반환한다" do
      calculator = Calculator.new
      expect(calculator.add(2, 3)).to eq(5)
    end

    it "음수를 더해도 올바르게 계산한다" do
      calculator = Calculator.new
      expect(calculator.add(-1, -1)).to eq(-2)
    end
  end
end
```

`describe`는 "무엇에 대한 테스트인지"를 나타내는 묶음이고, `it`은 그 안에서 확인하고 싶은 하나의 구체적인 상황을 문장으로 설명합니다. `expect(실제값).to eq(기대값)`은 "실제값이 기대값과 같아야 한다"는 검증을 표현합니다. 이 테스트 파일을 `rspec` 명령으로 실행하면, 각 `it` 블록이 통과했는지 실패했는지를 알려줍니다.

```bash
rspec spec/calculator_spec.rb
```

이 책에서는 RSpec의 문법과 사용법을 자세히 다루지 않지만, `describe`/`it`/`expect`라는 형태와 "코드로 기대 동작을 명세하고 자동으로 검증한다"는 테스트의 기본 개념만은 꼭 기억해두길 바랍니다. 이후 실무 수준의 Ruby(특히 Rails) 프로젝트를 다루게 되면 테스트 코드 작성은 선택이 아니라 필수에 가까운 습관이 됩니다.

- **10장. 상속과 모듈(Mixin)**: 클래스 간 상속 관계를 만드는 방법과, 모듈을 통해 여러 클래스에 기능을 나눠 섞는 방법을 배웠습니다.
- **11장. 블록, 프로크, 람다**: 코드 덩어리 자체를 값처럼 다루는 Ruby 특유의 블록, 그리고 이를 객체로 저장하는 프로크와 람다를 배웠습니다.
- **12장. 이터레이터와 Enumerable**: `each`, `map`, `select` 같은 이터레이터 메서드와 이를 뒷받침하는 Enumerable 모듈을 살펴봤습니다.
- **13장. 심볼과 문자열 심화**: 심볼과 문자열의 차이, 그리고 문자열을 다루는 다양한 메서드를 깊이 있게 다뤘습니다.
- **14장. 예외 처리**: `begin`/`rescue`/`ensure`를 이용해 프로그램 실행 중 발생하는 오류 상황에 안전하게 대응하는 방법을 배웠습니다.
- **15장. 개방 클래스와 몽키패칭**: 이미 정의된 클래스에 나중에 기능을 추가하는 Ruby의 유연함과, 그에 따르는 위험을 함께 살펴봤습니다.
- **16장. 메타프로그래밍 기초**: 프로그램이 스스로 코드를 정의하거나 조작하는 메타프로그래밍의 기본 개념을 맛보았습니다.
- **17장. gem과 Bundler**: 재사용 가능한 코드 묶음인 gem과, 프로젝트의 의존성을 관리하는 Bundler의 사용법을 배웠습니다.
- **18장. 좋은 Ruby 코드 작성 습관**: Ruby다운 코드 스타일, RuboCop, 테스트의 중요성을 살펴보며 "동작하는 코드"에서 "좋은 코드"로 나아가는 방법을 고민했습니다.

## 앞으로의 학습 방향

이 책은 Ruby라는 언어의 문법과 기본 개념을 다루는 입문서입니다. 여기서 배운 내용을 바탕으로 더 나아갈 수 있는 몇 가지 방향을 소개하며 책을 마무리하려 합니다.

**Ruby on Rails**는 이 책 전반에서 여러 차례 언급된, Ruby로 작성된 웹 애플리케이션 프레임워크입니다. 데이터베이스 연동, 라우팅, 화면 렌더링 등 웹 서비스 개발에 필요한 요소들을 갖추고 있어, Ruby로 실제 서비스를 만들어보고 싶다면 자연스러운 다음 단계입니다.

**동시성(concurrency)**은 여러 작업을 동시에 처리하는 기법을 다루는 주제입니다. Ruby에는 가벼운 실행 흐름을 만드는 **Fiber**와, Ruby 3부터 도입되어 진정한 병렬 실행을 가능하게 하는 **Ractor** 같은 기능이 있습니다. 대량의 요청을 처리하거나 시간이 걸리는 작업을 효율적으로 다뤄야 하는 상황에서 중요해지는 주제입니다.

**성능 최적화**도 더 공부해볼 만한 방향입니다. 코드가 왜 느린지 측정하는 프로파일링 기법, 메모리 사용을 줄이는 방법, MRI 대신 JRuby나 TruffleRuby 같은 다른 구현체를 선택했을 때의 장단점 등이 여기에 포함됩니다.

이 밖에도 데이터베이스 다루는 법, API 설계, 배포와 운영처럼 실제 서비스를 만들고 운영하는 데 필요한 지식들이 이어져 있습니다. 언어 하나를 배우는 것은 끝이 아니라 시작에 가깝습니다. 이 책에서 다진 Ruby의 기초가, 앞으로 나아갈 여러 방향에서 든든한 발판이 되기를 바랍니다.

## 요약

- Ruby다운 코드는 불필요한 괄호를 덜어내고, `unless`/`until`로 부정 조건을 자연스럽게 표현하며, 가드절로 조건 중첩을 줄이는 방식으로 작성됩니다.
- 가드절 패턴은 메서드 초입에서 예외 상황을 먼저 `return`으로 걸러내, 정상 로직의 들여쓰기를 얕게 유지합니다.
- RuboCop 같은 정적 분석 도구는 코드를 실행하지 않고도 스타일 일관성을 점검하고, 상당 부분 자동으로 교정해줍니다.
- 테스트 코드는 기대하는 동작을 코드로 명세해두고 반복 실행함으로써, 수정 시 기존 기능이 깨지지 않았는지 빠르게 확인할 수 있게 해줍니다.
- RSpec은 `describe`/`it`/`expect` 형태로 테스트를 사람이 읽는 문장처럼 작성할 수 있게 해주는 대표적인 Ruby 테스트 프레임워크입니다.
- 18개 장에서 배운 개념들은 서로 독립적이지 않고 유기적으로 연결되어 있으며, 앞으로는 Rails, 동시성(Fiber/Ractor), 성능 최적화 등의 방향으로 학습을 확장해갈 수 있습니다.

```ruby
  end
end
```
