# 9장. 클래스와 객체

[◀ 이전: 8장. 배열과 해시](ch08-배열과해시.md) | [📖 목차](00-목차.md) | [다음: 10장. 상속과 모듈(Mixin) ▶](ch10-상속과모듈.md)


## 이 장에서 배울 내용

7장에서는 메서드로 코드를 묶는 방법을, 8장에서는 배열과 해시로 데이터를 묶는 방법을 배웠습니다. 하지만 실제 프로그램에서는 데이터와 그 데이터를 다루는 동작을 함께 묶어야 할 때가 훨씬 많습니다. 예를 들어 "은행 계좌"라는 개념은 잔액이라는 데이터와 입금·출금이라는 동작이 뗄 수 없이 붙어 있습니다. 이렇게 데이터와 동작을 하나의 단위로 묶는 방법이 바로 **클래스**입니다.

Ruby는 순수한 객체 지향 언어입니다. 정수, 문자열, 배열, 심지어 `nil`까지도 모두 객체입니다. 이 장에서는 나만의 클래스를 정의하고, 그 클래스로부터 객체(인스턴스)를 만들어 사용하는 방법을 처음부터 차근차근 살펴봅니다.

## 클래스와 객체란 무엇인가

**클래스(class)**는 객체를 만들기 위한 설계도입니다. **객체(object)** 또는 **인스턴스(instance)**는 그 설계도로 실제로 찍어낸 결과물입니다.

붕어빵 틀을 클래스라고 하면, 그 틀로 구워낸 붕어빵 하나하나가 인스턴스입니다. 틀은 하나뿐이지만 붕어빵은 여러 개 만들 수 있고, 각 붕어빵은 팥이 든 것도 있고 슈크림이 든 것도 있는 것처럼 같은 클래스로 만든 객체라도 저마다 다른 데이터(상태)를 가질 수 있습니다.

```ruby
class Dog
end

my_dog = Dog.new
your_dog = Dog.new

my_dog.class      #=> Dog
my_dog.is_a?(Dog) #=> true
my_dog == your_dog #=> false (서로 다른 객체)
```

`class`부터 `end`까지가 클래스 정의이고, `Dog.new`는 `Dog` 클래스의 인스턴스를 새로 만드는 메서드 호출입니다. `my_dog`와 `your_dog`는 같은 클래스로 만들었지만 서로 다른 객체입니다.

## initialize와 인스턴스 변수

빈 클래스는 쓸모가 없습니다. 객체가 태어날 때부터 자기만의 데이터를 갖게 하려면 `initialize` 메서드를 정의합니다. `initialize`는 `new`를 호출할 때 Ruby가 자동으로 실행해 주는 특별한 메서드로, 생성자(constructor)라고 부릅니다.

```ruby
class Dog
  def initialize(name, breed)
    @name = name
    @breed = breed
  end
end

buddy = Dog.new("버디", "진돗개")
```

`@name`, `@breed`처럼 `@`으로 시작하는 변수를 **인스턴스 변수**라고 합니다. 인스턴스 변수는 그 객체가 살아 있는 동안 유지되며, 같은 객체 안의 모든 메서드에서 공유됩니다. 반면 다른 객체의 인스턴스 변수와는 완전히 독립되어 있습니다.

```ruby
buddy = Dog.new("버디", "진돗개")
choco = Dog.new("초코", "말티즈")
```

`buddy`의 `@name`은 `"버디"`이고 `choco`의 `@name`은 `"초코"`입니다. 두 객체는 같은 클래스에서 나왔지만 각자의 인스턴스 변수 값은 독립적입니다.

주의할 점은, 인스턴스 변수는 클래스 바깥에서 직접 접근할 수 없다는 것입니다.

```ruby
buddy.@name #=> 문법 오류(SyntaxError)
```

인스턴스 변수의 값을 클래스 바깥에서 읽거나 쓰려면 그 값을 반환하거나 설정해 주는 메서드가 따로 필요합니다. 이것이 바로 다음 절의 주제입니다.

## 인스턴스 메서드

`initialize`처럼 `def` 안에 정의하는 메서드는 모두 **인스턴스 메서드**입니다. 인스턴스 메서드는 객체를 통해 호출하며, 그 메서드 안에서는 `@`로 시작하는 인스턴스 변수에 자유롭게 접근할 수 있습니다.

```ruby
class Dog
  def initialize(name, breed)
    @name = name
    @breed = breed
  end

  def introduce
    "안녕하세요, 저는 #{@breed}인 #{@name}입니다."
  end

  def bark
    "#{@name}: 멍멍!"
  end
end

buddy = Dog.new("버디", "진돗개")
puts buddy.introduce #=> 안녕하세요, 저는 진돗개인 버디입니다.
puts buddy.bark       #=> 버디: 멍멍!
```

`introduce`와 `bark`는 모두 인스턴스 메서드이며, `buddy`라는 구체적인 객체에 속한 데이터(`@name`, `@breed`)를 사용합니다. 같은 메서드를 호출해도 어떤 객체를 통해 호출했느냐에 따라 결과가 달라집니다.

## attr_accessor, attr_reader, attr_writer

인스턴스 변수를 클래스 바깥에서 읽거나 쓰려면 다음과 같이 메서드를 직접 정의할 수 있습니다.

```ruby
class Dog
  def initialize(name)
    @name = name
  end

  def name
    @name
  end

  def name=(new_name)
    @name = new_name
  end
end

buddy = Dog.new("버디")
puts buddy.name  #=> 버디
buddy.name = "버디2세"
puts buddy.name  #=> 버디2세
```

`name` 메서드는 값을 읽는 **getter**, `name=` 메서드는 값을 쓰는 **setter**입니다. 이런 패턴은 매우 자주 쓰이기 때문에 Ruby는 이를 한 줄로 줄여 주는 클래스 메서드를 제공합니다.

```ruby
class Dog
  attr_accessor :name   # getter와 setter를 모두 생성
  attr_reader :breed    # getter만 생성 (읽기 전용)
  attr_writer :owner     # setter만 생성 (쓰기 전용)

  def initialize(name, breed)
    @name = name
    @breed = breed
  end
end

buddy = Dog.new("버디", "진돗개")
buddy.name = "버디2세"   # attr_accessor 덕분에 가능
puts buddy.name          #=> 버디2세
puts buddy.breed         #=> 진돗개
buddy.breed = "푸들"     #=> NoMethodError: undefined method `breed='
```

- `attr_accessor`: 읽기와 쓰기가 모두 필요할 때
- `attr_reader`: 값을 밖으로 노출하되 바깥에서 함부로 바꾸지는 못하게 하고 싶을 때
- `attr_writer`: 값을 설정만 하고 읽을 필요는 없을 때 (실무에서는 드물게 사용)

`attr_accessor :name`은 앞서 직접 작성한 `name`, `name=` 메서드 두 개를 자동으로 만들어 주는 것과 같습니다. 여러 속성을 한 번에 선언할 수도 있습니다.

```ruby
attr_accessor :name, :breed, :age
```

## 실전 예제: BankAccount 클래스

지금까지 배운 내용을 종합해서 은행 계좌를 표현하는 클래스를 만들어 보겠습니다.

```ruby
class BankAccount
  attr_reader :owner, :balance

  def initialize(owner, balance = 0)
    @owner = owner
    @balance = balance
    @history = []
  end

  def deposit(amount)
    raise ArgumentError, "입금액은 0보다 커야 합니다" if amount <= 0

    @balance += amount
    @history << "입금: +#{amount}원"
    @balance
  end

  def withdraw(amount)
    raise ArgumentError, "출금액은 0보다 커야 합니다" if amount <= 0
    raise "잔액이 부족합니다" if amount > @balance

    @balance -= amount
    @history << "출금: -#{amount}원"
    @balance
  end

  def print_history
    @history.each { |line| puts line }
  end
end

account = BankAccount.new("김민준", 10_000)
account.deposit(5_000)
account.withdraw(3_000)

puts account.balance #=> 12000
account.print_history
#=> 입금: +5000원
#=> 출금: -3000원
```

`balance`는 `attr_reader`로만 선언했기 때문에 외부에서 `account.balance = 1_000_000`처럼 직접 값을 바꿀 수 없습니다. 잔액을 바꾸는 유일한 방법은 `deposit`과 `withdraw` 메서드를 통하는 것뿐이며, 이 메서드들은 금액이 올바른지 검사하는 로직을 함께 가지고 있습니다. 이렇게 데이터를 마음대로 건드리지 못하게 막고 정해진 방법으로만 접근하게 하는 것을 **캡슐화(encapsulation)**라고 하며, 객체 지향 프로그래밍의 핵심 개념 중 하나입니다.

## 클래스 메서드와 클래스 변수

지금까지 본 메서드는 모두 객체(인스턴스)에 속한 **인스턴스 메서드**였습니다. 반면 클래스 자체에 속한 메서드도 정의할 수 있는데, 이를 **클래스 메서드**라고 하며 메서드 이름 앞에 `self.`를 붙여 정의합니다.

```ruby
class BankAccount
  attr_reader :owner, :balance

  @@total_accounts = 0

  def initialize(owner, balance = 0)
    @owner = owner
    @balance = balance
    @@total_accounts += 1
  end

  def self.total_accounts
    @@total_accounts
  end
end

BankAccount.new("김민준")
BankAccount.new("이서연")
BankAccount.new("박지훈")

puts BankAccount.total_accounts #=> 3
```

`@@total_accounts`처럼 `@@`으로 시작하는 변수는 **클래스 변수**로, 그 클래스로부터 만들어진 모든 인스턴스가 값을 공유합니다. 인스턴스가 새로 만들어질 때마다 `@@total_accounts`를 1씩 늘렸으므로, `BankAccount.total_accounts`를 호출하면 지금까지 생성된 계좌 수를 알 수 있습니다.

`total_accounts`는 `self.total_accounts`로 정의했기 때문에 특정 계좌 하나(`account.total_accounts`)가 아니라 `BankAccount` 클래스 자체(`BankAccount.total_accounts`)를 통해 호출합니다. 계좌 개수는 어느 한 계좌에 속한 정보가 아니라 `BankAccount`라는 개념 전체에 속한 정보이므로 클래스 메서드로 표현하는 것이 자연스럽습니다.

클래스 메서드는 특정 인스턴스의 상태와 무관하게 동작하는 기능, 예를 들어 객체를 만드는 대체 방법(팩토리 메서드)을 정의할 때도 자주 쓰입니다.

```ruby
class BankAccount
  def self.open_with_bonus(owner)
    new(owner, 1_000) # 신규 개설 축하금 1,000원
  end
end

account = BankAccount.open_with_bonus("최유진")
puts account.balance #=> 1000
```

## 접근 제어: public, private, protected

클래스 안의 메서드는 기본적으로 `public`이어서 클래스 바깥 어디서든 호출할 수 있습니다. 하지만 어떤 메서드는 클래스 내부의 구현 세부 사항일 뿐, 외부에 노출할 필요가 없는 경우가 있습니다. 이럴 때 `private`을 사용합니다.

```ruby
class BankAccount
  def initialize(owner, balance = 0)
    @owner = owner
    @balance = balance
  end

  def withdraw(amount)
    if sufficient_funds?(amount)
      @balance -= amount
    else
      puts "잔액이 부족합니다"
    end
  end

  private

  def sufficient_funds?(amount)
    amount <= @balance
  end
end

account = BankAccount.new("김민준", 5_000)
account.withdraw(3_000)          # OK: withdraw는 public
account.sufficient_funds?(1_000) #=> NoMethodError: private method
```

`private` 아래에 정의된 메서드는 그 클래스의 인스턴스 메서드 안에서만(수신자를 명시하지 않고) 호출할 수 있고, 클래스 바깥에서 `객체.메서드` 형태로는 호출할 수 없습니다. `sufficient_funds?`는 잔액을 확인하는 내부 로직일 뿐이므로 외부에 공개할 필요가 없고, 오히려 감춰야 외부 코드가 계좌 클래스의 내부 구현에 의존하지 않게 됩니다.

`protected`는 `private`과 비슷하지만 조금 더 완화된 규칙을 가집니다. `protected` 메서드는 같은 클래스(또는 그 하위 클래스)의 **다른 인스턴스**에서는 호출할 수 있습니다. 두 계좌의 잔액을 비교하는 예를 봅시다.

```ruby
class BankAccount
  def initialize(balance)
    @balance = balance
  end

  def richer_than?(other_account)
    balance > other_account.balance
  end

  protected

  def balance
    @balance
  end
end

a = BankAccount.new(10_000)
b = BankAccount.new(5_000)

a.richer_than?(b) #=> true
a.balance          #=> NoMethodError: protected method
```

`richer_than?` 안에서 `other_account.balance`를 호출할 수 있는 이유는 `balance`가 `protected`이기 때문입니다. 만약 `balance`가 `private`이었다면 `other_account.balance`처럼 수신자를 명시한 호출은 허용되지 않아 오류가 났을 것입니다. 정리하면 다음과 같습니다.

| 접근 제어자 | 클래스 내부에서 호출 | 같은 클래스의 다른 인스턴스에서 호출 | 클래스 외부에서 호출 |
|---|---|---|---|
| `public` | 가능 | 가능 | 가능 |
| `protected` | 가능 | 가능 | 불가능 |
| `private` | 가능(수신자 생략) | 불가능 | 불가능 |

실무에서는 `protected`보다 `private`을 훨씬 자주 사용합니다. `protected`는 지금과 같이 같은 클래스의 인스턴스끼리 서로의 비공개 데이터를 비교해야 할 때처럼 제한적인 상황에서만 사용합니다.

## to_s와 inspect 오버라이드

`puts`로 객체를 출력하거나 `p`로 객체를 살펴볼 때, Ruby는 기본적으로 별로 유용하지 않은 표현을 보여줍니다.

```ruby
class BankAccount
  def initialize(owner, balance)
    @owner = owner
    @balance = balance
  end
end

account = BankAccount.new("김민준", 10_000)
puts account #=> #<BankAccount:0x00007f9b8c0a1234>
p account    #=> #<BankAccount:0x00007f9b8c0a1234 @owner="김민준", @balance=10000>
```

`puts`는 객체의 `to_s` 메서드를, `p`(그리고 `inspect`)는 `inspect` 메서드를 호출합니다. 기본 구현은 객체의 클래스 이름과 메모리 주소 정도만 보여줄 뿐이라 디버깅이나 로그 출력에 유용하지 않습니다. 이 두 메서드를 직접 정의하면 원하는 형태로 바꿀 수 있습니다.

```ruby
class BankAccount
  def initialize(owner, balance)
    @owner = owner
    @balance = balance
  end

  def to_s
    "#{@owner}님의 계좌 (잔액: #{@balance}원)"
  end

  def inspect
    "#<BankAccount owner=#{@owner.inspect} balance=#{@balance}>"
  end
end

account = BankAccount.new("김민준", 10_000)
puts account   #=> 김민준님의 계좌 (잔액: 10000원)
p account      #=> #<BankAccount owner="김민준" balance=10000>
puts "계좌 정보: #{account}" #=> 계좌 정보: 김민준님의 계좌 (잔액: 10000원)
```

`to_s`는 문자열 보간(`"#{account}"`)이나 `puts`처럼 사람이 읽기 좋은 형태로 객체를 표현할 때 쓰이고, `inspect`는 `p`나 배열·해시 안에 객체가 들어 있을 때처럼 개발자가 디버깅 목적으로 객체의 상태를 정확히 들여다볼 때 쓰입니다. 관례상 `inspect`는 클래스 이름과 주요 데이터를 `#<ClassName ...>` 형태로 보여주도록 작성하는 경우가 많습니다.

## 요약

- 클래스는 객체를 만드는 설계도이고, 객체(인스턴스)는 그 설계도로 만들어진 실체입니다.
- `initialize`는 `new` 호출 시 자동으로 실행되는 생성자이며, 여기서 `@`로 시작하는 인스턴스 변수를 초기화합니다.
- 인스턴스 변수는 객체마다 독립적으로 유지되며, 클래스 바깥에서 직접 접근할 수 없습니다.
- `attr_accessor`, `attr_reader`, `attr_writer`는 인스턴스 변수를 읽고 쓰는 getter/setter 메서드를 자동으로 만들어 줍니다.
- `self.`을 붙여 정의하는 클래스 메서드는 특정 인스턴스가 아니라 클래스 자체에 속한 기능을 표현하며, `@@`으로 시작하는 클래스 변수는 모든 인스턴스가 값을 공유합니다.
- `public`, `private`, `protected`로 메서드의 접근 범위를 제어함으로써 캡슐화를 실현할 수 있습니다.
- `to_s`와 `inspect`를 오버라이드하면 객체를 사람이 읽기 좋은 형태 또는 디버깅에 유용한 형태로 출력할 수 있습니다.

## 연습문제

1. `Rectangle` 클래스를 만드세요. `initialize`는 `width`와 `height`를 받고, `area` 메서드는 넓이를, `perimeter` 메서드는 둘레를 반환합니다. `width`와 `height`는 `attr_reader`로 외부에 읽기만 허용하세요.

2. 위에서 만든 `BankAccount` 클래스에 `transfer(other_account, amount)` 메서드를 추가하세요. 이 메서드는 자신의 계좌에서 `amount`만큼 출금하여 `other_account`에 입금합니다. 잔액이 부족하면 예외를 발생시키세요.

3. `Product` 클래스를 만들어 `name`, `price` 인스턴스 변수를 가지게 하고, `to_s`를 오버라이드하여 `"상품명 - 1,000원"`과 같은 형태로 출력되게 하세요. (힌트: 숫자에 쉼표를 넣으려면 문자열을 직접 가공하거나 `"%d" % price`와 같은 형식 문자열을 활용해 보세요.)

4. `Counter` 클래스를 만들어 `increment` 메서드를 호출할 때마다 내부 카운트가 1씩 증가하게 하고, 지금까지 생성된 모든 `Counter` 인스턴스의 개수를 반환하는 클래스 메서드 `Counter.instance_count`를 클래스 변수를 이용해 구현하세요.

5. `private` 메서드와 `protected` 메서드의 차이를 자신의 언어로 설명하고, 각각이 어떤 상황에 적합한지 예를 하나씩 들어 보세요.
