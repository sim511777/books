# 13장. 심볼과 문자열 심화

[◀ 이전: 12장. 이터레이터와 Enumerable](ch12-이터레이터와Enumerable.md) | [📖 목차](00-목차.md) | [다음: 14장. 예외 처리 ▶](ch14-예외처리.md)


3장에서 심볼과 문자열을 Ruby의 기본 자료형으로 간단히 소개했습니다. 이 장에서는 한 걸음 더 들어가서 심볼이 문자열과 근본적으로 어떻게 다른지, 그리고 왜 Ruby 코드 곳곳에서 심볼이 그렇게 자주 등장하는지를 살펴봅니다. 이어서 문자열을 다루는 실전 메서드들과 정규표현식의 기초, 그리고 객체를 변경 불가능하게 만드는 `freeze`까지 다룹니다.

## 심볼이란 무엇인가

심볼은 `:이름` 형태로 쓰는 리터럴로, 이름 그 자체를 가리키는 가벼운 객체입니다. 겉모습은 문자열과 비슷해 보이지만 용도와 동작 방식이 다릅니다.

```ruby
status = :active
puts status.class   # Symbol
puts status          # active
```

심볼은 "이름표"에 가깝습니다. 프로그램 안에서 어떤 값을 식별하거나 분류할 때, 그 값 자체의 내용(문자 하나하나)이 아니라 "이것이 무엇을 의미하는 이름인가"가 중요할 때 심볼을 씁니다.

### 문자열과의 차이: 불변성과 동일성

문자열과 심볼의 가장 근본적인 차이는 두 가지입니다.

1. 문자열은 내용을 바꿀 수 있는(mutable) 객체이고, 심볼은 한 번 만들어지면 내용을 바꿀 수 없습니다.
2. 같은 내용의 문자열 리터럴은 등장할 때마다 새로운 객체가 만들어지지만, 같은 이름의 심볼은 프로그램 전체에서 단 하나의 객체만 존재합니다.

`object_id`는 객체마다 부여되는 고유한 식별 번호입니다. 두 변수의 `object_id`가 같다면 두 변수는 완전히 같은 객체를 가리키고 있다는 뜻입니다. 다음 예제로 확인해 보겠습니다.

```ruby
sym1 = :hello
sym2 = :hello
puts sym1.object_id == sym2.object_id   # true - 같은 객체

str1 = "hello"
str2 = "hello"
puts str1.object_id == str2.object_id   # false - 서로 다른 객체
```

`sym1`과 `sym2`는 리터럴로 두 번 썼지만 실제로는 Ruby 내부에 등록된 동일한 심볼 객체 하나를 참조합니다. 반면 `str1`과 `str2`는 내용은 같아도 메모리상에는 별개의 문자열 객체 두 개가 생성됩니다.

이 차이는 실제로 눈에 보이는 동작 차이로도 이어집니다. 문자열은 값을 바꿀 수 있습니다.

```ruby
greeting = "hello"
greeting << " world"
puts greeting   # hello world
```

반면 심볼에는 내용을 바꾸는 메서드 자체가 존재하지 않습니다. `:hello`라는 심볼은 태어날 때부터 죽을 때까지 `:hello`일 뿐입니다. 이런 성질을 **불변성(immutability)**이라고 부릅니다.

## 심볼을 해시 키로 쓰는 관례와 이유

8장에서 해시를 다루면서 `{name: "김루비", age: 20}`처럼 심볼을 키로 쓰는 모습을 이미 보았을 것입니다. 이는 단순한 취향이 아니라 Ruby 커뮤니티에서 굳어진 관례이며, 여기에는 분명한 이유가 있습니다.

### 이유 1: 성능

문자열을 해시 키로 쓰면 키를 비교할 때마다 문자열의 내용을 한 글자씩 비교해야 합니다. 반면 심볼은 프로그램 안에 오직 하나의 객체만 존재하므로, 두 심볼이 같은지 비교할 때는 `object_id`만 비교하면 됩니다. 이는 문자 하나하나를 비교하는 것보다 훨씬 빠릅니다.

또한 같은 이름의 문자열 키를 여러 번 사용하면 그때마다 새로운 문자열 객체가 메모리에 만들어지지만, 심볼은 한 번 등록되면 재사용되므로 메모리도 절약됩니다.

```ruby
user = { name: "김루비", age: 20, role: :admin }

# 아래와 동일한 표기입니다
user = { :name => "김루비", :age => 20, :role => :admin }
```

### 이유 2: 가독성과 의도 표현

심볼은 "이 값은 변하지 않는 이름/분류표다"라는 의도를 코드에 명시적으로 드러냅니다. 예를 들어 사용자의 권한을 나타낼 때 문자열 `"admin"`을 쓸 수도 있지만, 오타가 나도 런타임까지 발견하기 어렵고 `"Admin"`, `"admin "`처럼 미묘하게 다른 문자열이 섞여 들어갈 위험이 있습니다. 심볼 `:admin`은 그 자체로 고정된 어휘 집합의 하나임을 드러내며, 실수로 다른 값이 섞여도 비교 실패를 통해 빠르게 드러납니다.

```ruby
def change_role(user, role)
  case role
  when :admin
    user[:role] = :admin
  when :member
    user[:role] = :member
  else
    raise ArgumentError, "알 수 없는 역할: #{role}"
  end
end
```

7장에서 다룬 메서드의 키워드 인자 역시 내부적으로 심볼을 이름으로 사용합니다.

```ruby
def introduce(name:, age:)
  puts "#{name}은(는) #{age}살입니다."
end

introduce(name: "김루비", age: 20)
```

이처럼 "고정된 이름이 필요한 자리"에는 심볼, "내용 자체가 데이터인 자리"에는 문자열을 쓰는 것이 Ruby의 기본적인 구분법입니다.

## 문자열 메서드 심화

이제 실무에서 자주 쓰이는 문자열 메서드들을 살펴보겠습니다.

### gsub로 치환하기

`gsub`는 문자열 안에서 패턴에 맞는 부분을 모두 찾아 다른 문자열로 바꿉니다. 이름의 `g`는 "global"을 의미하며, 첫 번째로 매치되는 부분만 바꾸고 싶다면 `sub`를 사용합니다.

```ruby
text = "2026-08-09"
puts text.gsub("-", "/")   # 2026/08/09

# sub는 처음 하나만 바꾼다
puts text.sub("-", "/")    # 2026/08-09
```

`gsub`는 블록을 받을 수도 있습니다. 매치된 부분을 블록에 넘겨서 원하는 규칙으로 변환할 수 있습니다.

```ruby
price = "사과 100원, 바나나 250원"
doubled = price.gsub(/\d+/) { |num| (num.to_i * 2).to_s }
puts doubled   # 사과 200원, 바나나 500원
```

해시를 넘겨 여러 패턴을 한 번에 치환하는 것도 가능합니다.

```ruby
mapping = { "고양이" => "cat", "강아지" => "dog" }
puts "고양이와 강아지".gsub(/고양이|강아지/, mapping)
# cat와 dog
```

### split으로 문자열 쪼개기

`split`은 문자열을 구분자를 기준으로 나누어 배열로 반환합니다.

```ruby
csv_line = "김루비,20,서울"
fields = csv_line.split(",")
puts fields.inspect   # ["김루비", "20", "서울"]
```

구분자로 정규표현식을 쓸 수도 있고, 두 번째 인자로 나눌 개수의 상한을 지정할 수도 있습니다.

```ruby
sentence = "Ruby   is   fun"
puts sentence.split.inspect          # ["Ruby", "is", "fun"] (공백 연속도 처리)
puts sentence.split(" ", 2).inspect  # ["Ruby", "  is   fun"]
```

인자 없이 `split`을 호출하면 연속된 공백을 하나로 취급해 단어 단위로 나눠 준다는 점을 기억해 두면 편리합니다.

### strip과 형제 메서드들

공백이나 줄바꿈을 제거하는 메서드는 여러 종류가 있으며, 각각 제거하는 위치와 대상이 다릅니다.

```ruby
raw = "  hello world  \n"

puts raw.strip.inspect    # "hello world"   (양쪽 공백/개행 제거)
puts raw.lstrip.inspect   # "hello world  \n" (왼쪽만)
puts raw.rstrip.inspect   # "  hello world"   (오른쪽만)

line = "hello\n"
puts line.chomp.inspect   # "hello" (끝의 개행만 제거)

word = "hello"
puts word.chop.inspect    # "hell" (끝 문자를 무조건 하나 제거)
```

`chomp`는 줄 끝의 개행 문자(`\n`, `\r\n`)만 골라서 제거하므로 파일이나 표준 입력에서 한 줄씩 읽은 뒤 개행을 떼어낼 때 유용합니다. `chop`은 어떤 문자든 마지막 한 글자를 무조건 잘라내므로 용도가 다릅니다.

### % 연산자와 sprintf, format

문자열 서식을 지정할 때는 C 언어의 `printf`와 비슷한 표기법을 사용합니다. `%` 연산자는 왼쪽의 서식 문자열에 오른쪽 배열(또는 단일 값)의 값을 채워 넣습니다.

```ruby
name = "김루비"
age = 20
puts "이름: %s, 나이: %d살" % [name, age]
# 이름: 김루비, 나이: 20살
```

자주 쓰는 서식 지정자는 다음과 같습니다.

| 지정자 | 의미 |
|---|---|
| `%s` | 문자열 |
| `%d` | 정수 |
| `%f` | 실수 |
| `%05d` | 정수를 5자리로, 빈 자리는 0으로 채움 |
| `%.2f` | 소수점 둘째 자리까지 표시 |

```ruby
puts "%05d" % 42        # 00042
puts "%.2f" % 3.14159   # 3.14
```

`sprintf`와 `format`은 같은 기능을 하는 메서드로, `%` 연산자보다 인자를 더 명시적으로 나열할 수 있어 가독성이 좋습니다. 둘은 완전히 동일하게 동작하는 별칭 관계입니다.

```ruby
message = sprintf("이름: %s, 나이: %d살", name, age)
message2 = format("이름: %s, 나이: %d살", name, age)
puts message == message2   # true
```

## 정규표현식 기초

정규표현식(regular expression)은 문자열 안에서 특정 패턴을 찾기 위한 표기법입니다. Ruby는 `/패턴/` 형태의 리터럴로 정규표현식 객체(`Regexp`)를 만듭니다.

```ruby
pattern = /\d+/       # 숫자 하나 이상
puts pattern.class     # Regexp
```

### =~ 연산자와 match

`=~` 연산자는 문자열이 패턴과 매치되는 위치(인덱스)를 반환하며, 매치되지 않으면 `nil`을 반환합니다.

```ruby
text = "제 나이는 20살입니다"
if text =~ /\d+/
  puts "숫자를 발견했습니다. 시작 위치: #{$~.begin(0)}"
  puts "매치된 내용: #{$~[0]}"
end
```

매치가 성공하면 특수 변수 `$~`에 `MatchData` 객체가 저장됩니다. 다만 특수 변수는 코드의 흐름과 분리되어 있어 가독성이 떨어질 수 있으므로, 실무에서는 `match` 메서드를 더 많이 사용합니다.

```ruby
result = text.match(/\d+/)
if result
  puts result[0]   # 20 (매치된 전체 문자열)
end
```

매치 여부만 확인하고 싶다면 `match?`가 더 적합합니다. `MatchData` 객체를 만들지 않고 참/거짓만 반환하므로 더 빠르고, 특수 변수도 건드리지 않습니다.

```ruby
puts text.match?(/\d+/)   # true
```

괄호로 그룹을 지정하면 부분 매치도 꺼낼 수 있습니다.

```ruby
log = "2026-08-09"
if (m = log.match(/(\d{4})-(\d{2})-(\d{2})/))
  puts "년: #{m[1]}, 월: #{m[2]}, 일: #{m[3]}"
end
```

### scan으로 모든 매치 찾기

`match`는 첫 번째 매치만 찾지만, `scan`은 패턴에 맞는 모든 부분을 배열로 반환합니다.

```ruby
receipt = "사과 100원, 바나나 250원, 포도 500원"
prices = receipt.scan(/\d+/)
puts prices.inspect   # ["100", "250", "500"]
```

그룹을 포함한 패턴을 `scan`에 넘기면 각 매치가 그룹별 배열로 묶여서 반환됩니다.

```ruby
pairs = receipt.scan(/([가-힣]+) (\d+)원/)
puts pairs.inspect
# [["사과", "100"], ["바나나", "250"], ["포도", "500"]]
```

정규표현식은 그 자체로 방대한 주제입니다. 이 장에서는 문자열 처리와 곧바로 연결되는 최소한의 기초만 다루었으니, 더 복잡한 패턴이 필요할 때는 필요한 문법을 그때그때 찾아 익혀 나가는 것으로 충분합니다.

## freeze로 불변 객체 만들기

지금까지 살펴본 것처럼 문자열은 기본적으로 변경 가능한 객체입니다. 하지만 때로는 "이 값은 절대 바뀌지 않아야 한다"는 것을 코드로 강제하고 싶을 때가 있습니다. 이럴 때 사용하는 것이 `freeze`입니다.

```ruby
name = "김루비".freeze
puts name.frozen?   # true

name << " 님"   # FrozenError: can't modify frozen String
```

`freeze`는 심볼처럼 아예 변경 메서드가 없는 것과는 다르게, 원래는 변경 가능한 객체를 "이후로는 변경을 금지"하도록 잠그는 방식입니다. 한 번 얼리면 다시 해제할 수 없습니다.

`freeze`된 객체를 바탕으로 새 값을 만들고 싶다면 `dup`이나 `clone`을 사용합니다. 둘의 차이는 얼린 상태를 유지하느냐입니다.

```ruby
frozen_name = "김루비".freeze

copy1 = frozen_name.dup
puts copy1.frozen?   # false - dup은 얼린 상태를 복사하지 않는다

copy2 = frozen_name.clone
puts copy2.frozen?   # true - clone은 얼린 상태까지 그대로 복사한다
```

`freeze`는 상수와 함께 쓰일 때 특히 자주 등장합니다. Ruby의 상수는 재대입만 경고할 뿐 내부 값 변경까지 막지는 않으므로, 진짜로 변경 불가능한 상수를 만들려면 `freeze`를 함께 써 주는 것이 안전합니다.

```ruby
SUPPORTED_ROLES = [:admin, :member, :guest].freeze

SUPPORTED_ROLES << :guest2   # FrozenError 발생
```

배열을 얼려도 배열 자체에 새 원소를 추가하는 것만 막을 뿐, 배열 안에 든 각 원소까지 자동으로 얼려주지는 않는다는 점은 주의할 부분입니다. 배열 안의 문자열까지 완전히 불변으로 만들고 싶다면 원소 하나하나에도 `freeze`를 호출해야 합니다.

파일 맨 위에 `# frozen_string_literal: true`라는 매직 코멘트를 추가하면, 그 파일 안의 모든 문자열 리터럴이 기본적으로 얼린 상태로 생성됩니다. 문자열을 실수로 변경하는 버그를 예방하고 싶은 프로젝트에서 널리 쓰이는 관례이니 기억해 두면 좋습니다.

## 요약

- 심볼(`:이름`)은 이름을 나타내는 불변 객체로, 같은 이름의 심볼은 프로그램 전체에서 항상 동일한 객체(`object_id`가 동일)를 가리킵니다. 반면 문자열 리터럴은 매번 새로운 객체를 만듭니다.
- 심볼은 비교가 빠르고 메모리를 절약할 수 있어 해시 키나 고정된 분류값으로 널리 쓰이는 관례가 있습니다.
- `gsub`/`sub`는 패턴 치환, `split`은 문자열 분리, `strip`/`chomp`/`chop`은 각각 다른 방식으로 문자열 끝을 정리합니다.
- `%` 연산자와 `sprintf`/`format`은 서식 문자열에 값을 채워 넣는 동일한 기능을 제공합니다.
- 정규표현식은 `/패턴/` 리터럴로 만들며, `match`/`match?`로 매치를 확인하고 `scan`으로 모든 매치를 한 번에 찾을 수 있습니다.
- `freeze`는 객체를 더 이상 변경할 수 없도록 잠그며, `dup`은 얼린 상태를 유지하지 않고 `clone`은 유지합니다.
