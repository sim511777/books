# 7장. 메서드

[◀ 이전: 6장. 반복문](ch06-반복문.md) | [📖 목차](00-목차.md) | [다음: 8장. 배열과 해시 ▶](ch08-배열과해시.md)


지금까지는 코드를 위에서 아래로 한 줄씩 실행하는 프로그램을 다뤘습니다. 하지만 프로그램이 조금만 커져도 똑같은 작업을 여러 번 반복하게 되고, 그때마다 같은 코드를 복사해서 붙여넣는 것은 비효율적일 뿐만 아니라 버그의 온상이 됩니다. 이번 장에서는 코드 조각에 이름을 붙이고 필요할 때마다 불러 쓸 수 있게 해주는 **메서드(method)**를 배웁니다.

메서드는 Ruby 프로그램을 구성하는 가장 기본적인 단위입니다. 앞으로 배울 클래스와 객체, 모듈, 블록 같은 개념들도 결국 메서드를 중심으로 돌아가므로, 이번 장의 내용을 충분히 이해하고 넘어가는 것이 중요합니다.

## 메서드 정의와 호출

메서드는 `def` 키워드로 시작해서 `end`로 끝납니다.

```ruby
def greet
  puts "안녕하세요!"
end

greet  # => 안녕하세요!
```

`greet`라는 이름의 메서드를 정의했고, `greet`라고 한 줄만 적으면 그 메서드가 실행됩니다. 메서드 이름은 변수와 마찬가지로 소문자와 밑줄을 사용하는 `snake_case` 관례를 따릅니다.

인자를 받는 메서드는 이름 뒤 괄호 안에 매개변수(parameter)를 나열합니다.

```ruby
def greet(name)
  puts "안녕하세요, #{name}님!"
end

greet("지민")  # => 안녕하세요, 지민님!
```

여기서 `name`은 매개변수(parameter), 호출할 때 넘긴 `"지민"`은 인자(argument)입니다. 이 둘을 구분해서 부르는 습관을 들이면 이후 문서나 에러 메시지를 이해하기 쉬워집니다.

## 암묵적 반환값

Ruby의 메서드는 `return`을 명시하지 않아도 **마지막으로 평가된 표현식의 값을 자동으로 반환**합니다. 이는 Ruby의 매우 중요한 특징 중 하나입니다.

```ruby
def add(a, b)
  a + b
end

result = add(3, 4)
puts result  # => 7
```

`add` 메서드의 본문에서 마지막 줄인 `a + b`가 평가된 값이 그대로 반환값이 됩니다. `return a + b`라고 써도 동일하게 동작하지만, Ruby 커뮤니티에서는 굳이 마지막 표현식에까지 `return`을 붙이지 않는 것이 관례입니다. 대신 메서드 중간에서 조건에 따라 일찍 빠져나가야 할 때는 `return`을 사용합니다.

```ruby
def positive_or_zero(n)
  return 0 if n < 0

  n
end

puts positive_or_zero(-5)  # => 0
puts positive_or_zero(5)   # => 5
```

메서드 안에서 조건문이 마지막 표현식일 경우, 그 조건문이 평가된 값이 곧 반환값이 됩니다.

```ruby
def sign(n)
  if n > 0
    "양수"
  elsif n < 0
    "음수"
  else
    "영"
  end
end

puts sign(-3)  # => 음수
```

`if`문 전체가 메서드의 마지막 표현식이므로, 실행된 분기의 값이 그대로 메서드의 반환값이 됩니다. 이런 식으로 값을 반환하는 표현식을 적절히 조합하면 `return`을 거의 쓰지 않고도 깔끔한 메서드를 작성할 수 있습니다.

## 기본값이 있는 인자

매개변수에 기본값을 지정해 두면, 호출할 때 해당 인자를 생략할 수 있습니다.

```ruby
def greet(name, greeting = "안녕하세요")
  puts "#{greeting}, #{name}님!"
end

greet("수아")            # => 안녕하세요, 수아님!
greet("수아", "반갑습니다")  # => 반갑습니다, 수아님!
```

기본값이 있는 매개변수는 없는 매개변수보다 뒤에 두는 것이 일반적입니다. 그래야 Ruby가 어떤 인자가 어떤 매개변수에 대응하는지 헷갈리지 않고 판단할 수 있습니다.

기본값 표현식은 메서드가 호출되는 시점에 평가되므로, 다른 매개변수의 값을 참조하는 것도 가능합니다.

```ruby
def describe(width, height, area = width * height)
  puts "가로 #{width}, 세로 #{height}, 넓이 #{area}"
end

describe(3, 4)      # => 가로 3, 세로 4, 넓이 12
describe(3, 4, 100) # => 가로 3, 세로 4, 넓이 100
```

## 가변 인자

인자의 개수를 미리 알 수 없는 경우가 있습니다. 예를 들어 숫자 여러 개를 받아 합계를 구하는 메서드를 만든다고 합시다. 이때는 매개변수 앞에 `*`을 붙여서 **가변 인자(splat argument)**로 선언합니다.

```ruby
def sum(*numbers)
  total = 0
  numbers.each { |n| total += n }
  total
end

puts sum(1, 2, 3)        # => 6
puts sum(1, 2, 3, 4, 5)  # => 15
puts sum                 # => 0
```

`*numbers`로 선언하면, 호출 시 넘긴 인자들이 모두 `numbers`라는 배열로 묶입니다. 인자를 하나도 넘기지 않으면 `numbers`는 빈 배열이 됩니다. 배열에 대해서는 8장에서 자세히 다루지만, 지금은 "여러 개의 값을 순서대로 담는 상자" 정도로 이해하면 충분합니다.

가변 인자는 다른 일반 매개변수와 함께 사용할 수도 있습니다. 이때 가변 인자는 보통 마지막 위치가 아니어도 되지만, 혼동을 피하려면 다음과 같이 앞쪽에 고정 인자를, 뒤쪽 혹은 중간에 가변 인자를 두는 방식을 권장합니다.

```ruby
def introduce(name, *hobbies)
  puts "#{name}님의 취미: #{hobbies.join(', ')}"
end

introduce("민준", "독서", "등산", "요리")
# => 민준님의 취미: 독서, 등산, 요리
```

## 키워드 인자

인자가 여러 개일 때 순서를 일일이 기억하는 것은 실수를 유발하기 쉽습니다. Ruby는 인자에 이름을 붙여서 전달하는 **키워드 인자(keyword argument)**를 지원합니다.

```ruby
def create_user(name:, age:, city: "서울")
  puts "이름: #{name}, 나이: #{age}, 도시: #{city}"
end

create_user(name: "하은", age: 27)
# => 이름: 하은, 나이: 27, 도시: 서울

create_user(age: 33, name: "도윤", city: "부산")
# => 이름: 도윤, 나이: 33, 도시: 부산
```

`name:`, `age:`처럼 콜론이 붙은 매개변수는 호출할 때 반드시 이름과 함께 값을 넘겨야 하는 **필수 키워드 인자**입니다. `city: "서울"`처럼 기본값이 지정된 키워드 인자는 생략할 수 있습니다. 키워드 인자를 사용하면 호출 코드만 보고도 각 값이 무엇을 의미하는지 바로 알 수 있고, 인자의 순서를 바꿔서 넘겨도 문제가 없다는 장점이 있습니다.

가변 인자에 대응하는 개념으로, 정해지지 않은 개수의 키워드 인자를 한꺼번에 받고 싶다면 `**`을 붙입니다.

```ruby
def print_profile(**options)
  options.each do |key, value|
    puts "#{key}: #{value}"
  end
end

print_profile(name: "서준", job: "학생", hobby: "게임")
# => name: 서준
# => job: 학생
# => hobby: 게임
```

`**options`로 선언하면 호출 시 넘긴 키워드 인자들이 해시(hash)라는 자료 구조로 묶입니다. 해시 역시 8장에서 본격적으로 다룹니다.

일반 인자, 가변 인자, 키워드 인자는 한 메서드 안에서 함께 사용할 수 있습니다.

```ruby
def register(name, *tags, active: true, **extra)
  puts "이름: #{name}"
  puts "태그: #{tags.join(', ')}"
  puts "활성 여부: #{active}"
  puts "추가 정보: #{extra}"
end

register("루비", "언어", "동적", active: false, level: "초급")
# => 이름: 루비
# => 태그: 언어, 동적
# => 활성 여부: false
# => 추가 정보: {:level=>"초급"}
```

## 메서드 이름 관례: `?`와 `!`

Ruby는 메서드 이름 끝에 `?`나 `!`를 붙일 수 있게 허용합니다. 이는 문법적으로 특별한 의미를 갖는 것은 아니지만, 커뮤니티 전체가 지키는 강력한 관례입니다.

### `?`로 끝나는 메서드

이름이 `?`로 끝나는 메서드는 **참(true) 또는 거짓(false)을 반환한다**는 신호입니다. 그래야 코드를 읽는 사람이 반환값의 성격을 이름만 보고 예측할 수 있습니다.

```ruby
def even?(n)
  n % 2 == 0
end

puts even?(4)  # => true
puts even?(7)  # => false
```

Ruby 표준 라이브러리에도 `empty?`, `include?`, `nil?`처럼 `?`로 끝나는 메서드가 많습니다. 직접 메서드를 만들 때도 불리언 값을 반환한다면 이 관례를 따르는 것이 좋습니다.

```ruby
def adult?(age)
  age >= 19
end

if adult?(20)
  puts "성인입니다"
end
```

### `!`로 끝나는 메서드

이름이 `!`로 끝나는 메서드는 관례상 **호출 대상을 직접 변경(파괴적 변경, destructive change)한다**는 경고의 의미를 가집니다. 대표적인 예가 문자열의 `upcase`와 `upcase!`입니다.

```ruby
name = "ruby"

upper = name.upcase
puts upper  # => RUBY
puts name   # => ruby (원본은 그대로)

name.upcase!
puts name   # => RUBY (원본 자체가 바뀜)
```

`upcase`는 대문자로 바꾼 **새로운 문자열을 반환**할 뿐, 원본 `name`은 건드리지 않습니다. 반면 `upcase!`는 `name`이 가리키는 문자열 자체를 대문자로 바꿔버립니다. 이 차이는 매우 중요합니다. 원본이 예상치 못하게 바뀌면 프로그램의 다른 부분에서 버그가 발생할 수 있기 때문입니다.

주의할 점은, `!`가 붙었다고 해서 항상 "위험한" 메서드라는 뜻은 아니며, 정확히는 "같은 이름의 `!` 없는 메서드에 비해 더 파괴적이거나 예외를 던질 가능성이 있는 메서드"라는 상대적인 의미로 사용됩니다. 예를 들어 배열의 `sort`와 `sort!`도 같은 관계입니다.

```ruby
numbers = [3, 1, 2]

sorted = numbers.sort
puts sorted.inspect   # => [1, 2, 3]
puts numbers.inspect  # => [3, 1, 2] (원본 유지)

numbers.sort!
puts numbers.inspect  # => [1, 2, 3] (원본이 정렬됨)
```

직접 메서드를 설계할 때도 이 관례를 지켜서, 원본을 바꾸는 메서드에는 `!`를 붙이고 짝이 되는 비파괴적 버전을 함께 제공하면 좋습니다.

```ruby
def shout(text)
  text.upcase + "!"
end

def shout!(text)
  text.upcase!
  text
end
```

## 괄호 생략

Ruby에서는 메서드를 호출할 때 인자를 감싸는 괄호를 생략할 수 있습니다.

```ruby
puts "안녕하세요"

# 아래와 동일
puts("안녕하세요")
```

메서드를 정의할 때도 괄호를 생략할 수 있습니다.

```ruby
def greet name
  puts "안녕하세요, #{name}님!"
end
```

두 방식 모두 문법적으로는 올바르지만, 실무에서는 다음과 같은 기준을 따르는 경우가 많습니다.

- 인자가 없는 메서드 호출: 괄호 생략 (`puts`, `greet`)
- 인자가 있는 메서드 정의: 괄호 사용 (`def greet(name)`)
- 인자가 있는 메서드 호출: 상황에 따라 다르지만, 다른 메서드 호출과 중첩되거나 인자가 여러 개일 때는 괄호를 쓰는 것이 가독성에 좋음

```ruby
# 괄호가 없으면 어디까지가 인자인지 헷갈릴 수 있다
puts greet "지민", "안녕"

# 괄호를 쓰면 명확하다
puts(greet("지민", "안녕"))
```

이 책의 예제에서도 상황에 따라 괄호를 쓰거나 생략하는 것을 모두 보게 될 텐데, 일관성만 지킨다면 어느 쪽이든 큰 문제가 되지 않습니다. 다만 팀 프로젝트에서는 하나의 스타일로 통일하는 것이 좋습니다.

## 접근 제어 살짝 엿보기

메서드는 기본적으로 `public`이어서 어디서든 호출할 수 있습니다. 그런데 클래스를 설계하다 보면, 클래스 내부에서만 쓰이고 외부에는 노출하고 싶지 않은 메서드가 생깁니다. Ruby는 이를 위해 `private`과 `protected`라는 접근 제어 키워드를 제공합니다.

```ruby
class Wallet
  def initialize(balance)
    @balance = balance
  end

  def display_balance
    "잔액: #{formatted_balance}원"
  end

  private

  def formatted_balance
    @balance.to_s.reverse.scan(/\d{1,3}/).join(",").reverse
  end
end

wallet = Wallet.new(1234567)
puts wallet.display_balance  # => 잔액: 1,234,567원
# wallet.formatted_balance   # => NoMethodError 발생 (외부에서 호출 불가)
```

`private` 선언 아래에 정의된 메서드는 클래스 외부에서 직접 호출할 수 없습니다. `formatted_balance`는 `display_balance` 내부에서만 쓰이는 보조 메서드이므로, 외부에는 감춰두는 것이 자연스럽습니다. 이렇게 내부 구현을 숨기고 필요한 기능만 외부에 노출하는 것을 **캡슐화(encapsulation)**라고 부릅니다.

`class`와 `def`가 아직 낯설게 느껴질 수 있지만, 지금은 "메서드에도 공개 범위를 정할 수 있다" 정도만 기억해 두면 충분합니다. `public`, `private`, `protected`의 정확한 차이와 활용법은 9장 클래스와 객체에서 본격적으로 다룹니다.

## 요약

- 메서드는 `def`~`end`로 정의하며, `return`이 없어도 마지막으로 평가된 표현식의 값이 자동으로 반환된다.
- 매개변수에는 기본값을 지정할 수 있으며(`age = 20`), 호출 시 해당 인자를 생략하면 기본값이 사용된다.
- `*args`로 선언한 가변 인자는 개수가 정해지지 않은 인자들을 배열로 받는다.
- `key:` 형태의 키워드 인자는 이름을 명시해서 값을 전달하며, 순서에 구애받지 않고 의도를 명확히 드러낼 수 있다. `**kwargs`는 정해지지 않은 키워드 인자들을 해시로 받는다.
- 이름이 `?`로 끝나는 메서드는 참/거짓을 반환한다는 관례이고, `!`로 끝나는 메서드는 호출 대상을 직접 변경할 가능성이 있다는 관례다.
- 메서드 호출 시 괄호는 생략할 수 있지만, 가독성을 위해 상황에 맞게 사용 여부를 판단해야 한다.
- `private`을 사용하면 클래스 내부에서만 쓰이는 메서드를 외부에 노출하지 않을 수 있다. 자세한 내용은 9장에서 다룬다.

4. `title:`, `author:`, `year: 2020`을 키워드 인자로 받아 `"제목 (연도) - 저자"` 형태의 문자열을 반환하는 `book_info` 메서드를 작성하세요.
5. 양의 정수를 받아 그 수가 3의 배수이면 `true`, 아니면 `false`를 반환하는 `multiple_of_three?(n)` 메서드를 작성하고, 이 메서드의 이름에 `?`가 붙은 이유를 한 문장으로 설명하세요.
