# 3장. 변수와 자료형

[◀ 이전: 2장. 첫 프로그램과 실행 환경](ch02-첫프로그램과실행환경.md) | [📖 목차](00-목차.md) | [다음: 4장. 연산자와 표현식 ▶](ch04-연산자와표현식.md)


프로그램은 결국 데이터를 어딘가에 담아 두고, 그 데이터를 이리저리 옮기고 계산하는 일의 연속입니다. 이번 장에서는 Ruby가 데이터를 담는 그릇, 즉 변수를 어떻게 다루는지 살펴보고, Ruby가 기본으로 제공하는 자료형들을 하나씩 훑어보겠습니다.

## 변수를 선언하는 방식

C나 Java 같은 언어를 먼저 배운 사람이라면 변수를 쓰기 전에 `int count;`처럼 타입을 미리 선언해야 한다는 규칙에 익숙할 것입니다. Ruby에는 그런 규칙이 없습니다. 변수에 값을 대입하는 순간이 곧 그 변수가 태어나는 순간입니다.

```ruby
count = 3
name = "홍길동"
price = 12500.5
```

위 코드에서 `count`, `name`, `price`는 모두 별도의 선언 없이 바로 등장했습니다. Ruby 인터프리터는 `=` 왼쪽에 처음 보는 이름이 나오면 "아, 이런 이름의 변수를 새로 만들어야겠구나" 하고 판단합니다. 타입을 적지 않았다고 해서 값에 타입이 없는 것은 아닙니다. `count`에 들어 있는 3은 엄연히 정수(Integer)이고, `name`에 들어 있는 문자열은 String입니다. 다만 그 타입 정보를 변수가 아니라 값 자체가 들고 다닌다는 점이 다릅니다.

이런 방식을 **동적 타입(dynamic typing)**이라고 부릅니다. 변수는 그저 값을 가리키는 이름표에 가깝고, 같은 이름표를 다른 종류의 값에 다시 붙이는 것도 자유롭습니다.

```ruby
box = 100        # 지금은 정수를 가리킴
box = "선물 상자"  # 이제는 문자열을 가리킴
box = [1, 2, 3]  # 이제는 배열을 가리킴
```

세 줄 모두 문법 오류 없이 실행됩니다. `box`라는 이름표를 이 값에서 저 값으로 옮겨 붙였을 뿐입니다. 이렇게 자유로운 대신, 어떤 변수에 지금 어떤 종류의 값이 들어 있는지는 프로그래머가 스스로 신경 써야 합니다. 타입을 명시하는 언어라면 컴파일러가 실수를 미리 잡아 주지만, Ruby는 프로그램을 실제로 실행해 보기 전까지는 타입 실수를 알아채지 못하는 경우가 많습니다. 이 차이는 자유로움과 안전성 사이의 트레이드오프라고 이해하면 됩니다.

## 변수의 다섯 가지 종류

Ruby에는 이름의 첫 글자만 보고도 구분할 수 있는 다섯 종류의 변수(정확히는 네 종류의 변수와 한 종류의 상수)가 있습니다. 이 규칙은 Ruby 문법에 고정되어 있어서, 이름만 보면 그 변수가 어디까지 통용되는지 바로 알 수 있습니다.

| 종류 | 이름 규칙 | 예시 |
|---|---|---|
| 지역 변수 | 소문자나 밑줄로 시작 | `age`, `user_name` |
| 인스턴스 변수 | `@`로 시작 | `@age`, `@user_name` |
| 클래스 변수 | `@@`로 시작 | `@@count`, `@@total` |
| 전역 변수 | `$`로 시작 | `$config`, `$debug` |
| 상수 | 대문자로 시작 | `MAX_SIZE`, `Color` |

### 지역 변수

가장 흔하게 쓰는 변수입니다. 소문자나 밑줄(`_`)로 시작하며, 정의된 범위(메서드 안, 블록 안 등) 안에서만 존재합니다. 범위를 벗어나면 그 변수는 더 이상 존재하지 않는 것처럼 취급됩니다.

```ruby
def greet
  message = "안녕하세요"
  puts message
end

greet
# puts message  # 여기서는 오류: message는 greet 메서드 밖에서는 존재하지 않음
```

`message`는 `greet` 메서드 내부에서 만들어졌기 때문에 메서드 밖에서는 접근할 수 없습니다. 이렇게 변수가 유효한 범위를 **스코프(scope)**라고 부르는데, 지역 변수의 스코프는 원칙적으로 메서드 하나, 또는 블록 하나로 제한됩니다. 메서드와 스코프의 관계는 7장에서 좀 더 자세히 다룹니다.

### 인스턴스 변수

`@`로 시작하는 변수는 인스턴스 변수입니다. 하나의 객체에 속한 데이터를 저장할 때 사용하며, 그 객체가 살아 있는 동안에는 어떤 메서드에서 접근하든 같은 값을 공유합니다.

```ruby
class Wallet
  def initialize(balance)
    @balance = balance
  end

  def show_balance
    puts "현재 잔액: #{@balance}원"
  end
end

wallet = Wallet.new(50_000)
wallet.show_balance  # 현재 잔액: 50000원
```

`@balance`는 `initialize` 메서드에서 값을 받아 저장했지만, `show_balance` 메서드에서도 아무 문제 없이 접근할 수 있습니다. 인스턴스 변수가 지역 변수와 다른 점이 바로 이것입니다. 클래스와 객체, 인스턴스 변수의 역할은 9장에서 본격적으로 다룹니다.

한 가지 특징을 미리 짚어 두면, 인스턴스 변수는 초기화하지 않고 읽어도 오류를 내지 않고 `nil`을 돌려줍니다. 지역 변수라면 정의되지 않은 이름을 읽으려는 순간 오류가 나는 것과 대조적입니다. 이 관대함은 편리하기도 하지만, 오타를 낸 변수 이름이 조용히 `nil`을 반환하며 버그를 숨길 수도 있으니 주의가 필요합니다.

### 클래스 변수

`@@`로 시작하는 변수는 클래스 변수입니다. 인스턴스 변수가 객체마다 따로 존재하는 것과 달리, 클래스 변수는 그 클래스로 만들어진 모든 객체가 하나의 값을 공유합니다.

```ruby
class Counter
  @@total = 0

  def initialize
    @@total += 1
  end

  def self.total
    @@total
  end
end

Counter.new
Counter.new
Counter.new
puts Counter.total  # 3
```

`Counter` 객체를 새로 만들 때마다 `@@total`이 1씩 늘어나는데, 이 값은 모든 `Counter` 인스턴스가 공유하는 단 하나의 값입니다. 클래스 변수는 상속 관계에서 예상 밖의 방식으로 동작할 때가 있어서 실무에서는 신중하게 사용하는 편입니다. 이 주제는 10장에서 상속을 다루며 다시 짚어 보겠습니다.

### 전역 변수

`$`로 시작하는 변수는 전역 변수입니다. 프로그램 어디에서든, 클래스 안이든 메서드 안이든 상관없이 접근할 수 있습니다.

```ruby
$app_name = "가계부"

def show_title
  puts "#{$app_name}에 오신 것을 환영합니다"
end

show_title  # 가계부에 오신 것을 환영합니다
```

접근 범위에 아무런 제약이 없다 보니 매우 편리해 보이지만, 프로그램 규모가 커지면 전역 변수는 오히려 골칫거리가 되기 쉽습니다. 어느 코드에서 그 값을 바꿨는지 추적하기 어려워지기 때문입니다. 그래서 실무 Ruby 코드에서는 전역 변수를 거의 쓰지 않고, 꼭 필요한 경우에만 제한적으로 사용합니다.

### 상수

대문자로 시작하는 이름은 상수로 취급됩니다. 관례상 상수는 `MAX_SIZE`처럼 전부 대문자와 밑줄로 쓰거나, `Color`처럼 클래스나 모듈 이름을 나타낼 때는 첫 글자만 대문자인 파스칼 표기법을 씁니다.

```ruby
MAX_USERS = 100
SITE_NAME = "루비 기초"

puts MAX_USERS   # 100
```

이름에서 짐작할 수 있듯 상수는 한 번 정한 값을 바꾸지 않는다는 약속으로 사용합니다. 그런데 흥미롭게도 Ruby는 상수 값을 다시 대입해도 프로그램을 멈추지 않습니다.

```ruby
MAX_USERS = 100
MAX_USERS = 200  # warning: already initialized constant MAX_USERS
```

경고 메시지만 출력할 뿐, 실행 자체는 계속됩니다. 즉 "상수를 바꾸지 말라"는 규칙은 Ruby 언어가 강제하는 규칙이 아니라, 프로그래머들 사이의 약속에 가깝습니다. 이런 점 때문에 Ruby를 가리켜 "규칙을 강제하기보다 신뢰를 바탕으로 설계된 언어"라고 표현하기도 합니다.

## 기본 자료형 둘러보기

이제 변수라는 그릇에 담기는 값, 즉 자료형을 살펴보겠습니다.

### Integer(정수)

정수는 소수점이 없는 숫자입니다. Ruby의 정수는 자릿수 제한이 사실상 없어서, 아주 큰 수를 계산해도 오버플로를 걱정할 필요가 없습니다.

```ruby
age = 27
big_number = 10 ** 30

puts age.class         # Integer
puts big_number        # 1000000000000000000000000000000
```

숫자가 길어질 때는 밑줄(`_`)을 자릿수 구분 기호로 넣을 수 있습니다. 이 밑줄은 사람이 읽기 편하라고 넣는 표시일 뿐, 값 계산에는 아무 영향을 주지 않습니다.

```ruby
population = 51_780_000
puts population  # 51780000
```

### Float(실수)

소수점이 있는 숫자는 Float입니다.

```ruby
pi = 3.14159
temperature = -4.5

puts pi.class  # Float
```

Float는 컴퓨터 내부에서 이진수로 근사 처리되기 때문에, 사람이 보기에 딱 떨어지는 계산도 미세한 오차가 생길 수 있습니다.

```ruby
puts 0.1 + 0.2  # 0.30000000000000004
```

이 현상은 Ruby만의 특징이 아니라 부동소수점을 사용하는 대부분의 언어에서 공통으로 나타나는 현상입니다. 돈 계산처럼 오차가 치명적인 상황에서는 Float 대신 정수(예: 원 단위 대신 전부 계산한 뒤 나누기)를 활용하거나 별도의 정밀 계산 라이브러리를 쓰는 것이 안전합니다.

### String(문자열)

문자열은 텍스트 데이터를 담습니다. 작은따옴표와 큰따옴표 둘 다로 만들 수 있지만, 둘 사이에는 분명한 차이가 있습니다.

```ruby
single = 'Ruby기초'
double = "Ruby기초"
```

가장 큰 차이는 **문자열 보간(string interpolation)**입니다. 큰따옴표 문자열 안에서는 `#{}` 안에 Ruby 표현식을 넣으면 그 결과가 문자열 속에 그대로 끼워집니다.

```ruby
name = "지민"
level = 3

puts "#{name}님의 현재 레벨은 #{level}입니다"
# 지민님의 현재 레벨은 3입니다
```

같은 코드를 작은따옴표로 쓰면 `#{}`는 그저 글자 그대로 출력됩니다.

```ruby
puts '#{name}님의 현재 레벨은 #{level}입니다'
# #{name}님의 현재 레벨은 #{level}입니다
```

이스케이프 시퀀스(escape sequence)의 해석 여부도 다릅니다. 큰따옴표 문자열에서는 `\n`(줄바꿈), `\t`(탭) 같은 표현이 실제 제어 문자로 해석되지만, 작은따옴표 문자열에서는 `\\`와 `\'` 두 가지를 제외하면 백슬래시가 그냥 문자 그대로 남습니다.

```ruby
puts "첫째 줄\n둘째 줄"
# 첫째 줄
# 둘째 줄

puts '첫째 줄\n둘째 줄'
# 첫째 줄\n둘째 줄
```

정리하면, 보간이나 이스케이프가 필요 없는 순수한 텍스트에는 작은따옴표를, 변수를 끼워 넣거나 줄바꿈 등을 표현해야 할 때는 큰따옴표를 쓰는 것이 일반적인 관례입니다.

### Symbol(심볼)

Symbol은 Ruby에 처음 입문할 때 낯설게 느껴지는 자료형입니다. 콜론(`:`)을 앞에 붙여서 만들며, 겉모습은 문자열과 비슷하지만 성격은 사뭇 다릅니다.

```ruby
status = :active
puts status.class  # Symbol
```

문자열은 같은 내용이라도 새로 만들 때마다 별개의 객체가 생성되지만, 심볼은 내용이 같으면 항상 같은 객체를 가리킵니다.

```ruby
puts "active".object_id == "active".object_id  # false
puts :active.object_id == :active.object_id    # true
```

이런 성격 덕분에 심볼은 해시의 키나, 메서드 이름을 나타내는 용도처럼 "값 자체가 아니라 이름표 역할"을 하는 곳에 즐겨 쓰입니다. 심볼에 대해서는 13장에서 문자열과 비교하며 더 깊이 다루겠습니다.

### true, false, nil

Ruby는 참과 거짓을 나타내는 `true`, `false`라는 값을 가지고 있고, "값이 없음"을 나타내는 `nil`이라는 값도 가지고 있습니다.

```ruby
is_valid = true
is_empty = false
result = nil
```

여기서 꼭 기억해 둘 사실이 하나 있습니다. Ruby에서는 `true`, `false`, `nil`을 포함해 **세상에 존재하는 모든 것이 객체**입니다. 이는 Ruby 설계 철학의 핵심이기도 합니다. 다른 언어에서는 `null`이나 `None`이 "아무 객체도 아님"을 뜻하는 특수한 표식으로 취급되지만, Ruby의 `nil`은 어엿한 `NilClass`의 유일한 인스턴스입니다.

```ruby
puts nil.class      # NilClass
puts nil.to_s       # "" (빈 문자열)
puts nil.to_a       # []
puts nil.inspect    # "nil"
```

`nil`이 객체이기 때문에 `nil.to_s`나 `nil.class`처럼 메서드를 호출할 수 있습니다. 만약 `nil`이 그냥 "아무것도 없음을 뜻하는 특수 기호"였다면 이런 메서드 호출 자체가 불가능했을 것입니다. 이 점은 나중에 안전 내비게이션 연산자(`&.`)를 배울 때 다시 등장하니 기억해 두면 좋습니다. 자세한 내용은 4장에서 다룹니다.

조건문에서 `false`로 취급되는 값은 Ruby에서 오직 `false`와 `nil` 두 가지뿐입니다. 숫자 0이나 빈 문자열 `""`, 빈 배열 `[]`도 조건문에서는 모두 참으로 취급된다는 점이 다른 언어를 먼저 배운 사람에게는 의외로 다가올 수 있습니다.

```ruby
if 0
  puts "0은 참으로 취급됩니다"
end
# 0은 참으로 취급됩니다
```

## 타입을 확인하는 방법

동적 타입 언어에서는 "지금 이 변수에 어떤 종류의 값이 들어 있는가"를 코드 안에서 직접 물어봐야 할 때가 종종 있습니다. Ruby는 이를 위한 몇 가지 방법을 제공합니다.

### class 메서드

가장 직접적인 방법은 `class` 메서드로 정확한 클래스를 물어보는 것입니다.

```ruby
puts 42.class        # Integer
puts 3.14.class       # Float
puts "hi".class       # String
puts :sym.class       # Symbol
puts true.class       # TrueClass
puts false.class      # FalseClass
puts nil.class        # NilClass
```

흥미롭게도 `true`와 `false`는 서로 다른 클래스에 속합니다. `true`는 `TrueClass`의 유일한 인스턴스이고, `false`는 `FalseClass`의 유일한 인스턴스입니다. Ruby에는 `Boolean`이라는 이름의 클래스가 따로 존재하지 않습니다.

### is_a?와 kind_of?

`class`가 정확히 일치하는 클래스 이름을 돌려준다면, `is_a?`는 "이 객체가 이런 종류인가?"를 물어봐서 참/거짓으로 답을 얻는 방법입니다. 상속 관계에 있는 상위 클래스나 포함된 모듈까지 함께 고려한다는 점이 `class`와의 차이입니다.

```ruby
puts 42.is_a?(Integer)   # true
puts 42.is_a?(Numeric)   # true (Integer는 Numeric의 하위 클래스)
puts 42.is_a?(String)    # false
```

`kind_of?`는 `is_a?`와 완전히 동일하게 동작하는 별칭(alias)입니다. 두 이름 중 어느 쪽을 써도 상관없으며, 팀이나 프로젝트의 관례에 맞춰 하나를 골라 쓰면 됩니다. 클래스 사이의 상속 관계는 10장에서 자세히 설명합니다.

### respond_to?

때로는 객체의 클래스가 무엇인지보다, "이 객체가 이 메서드를 호출할 수 있는가"가 더 중요할 때가 있습니다. `respond_to?`는 바로 그 질문에 답해 줍니다.

```ruby
puts "hello".respond_to?(:upcase)   # true
puts 42.respond_to?(:upcase)        # false
puts 42.respond_to?(:+)             # true
```

이런 식으로 "어떤 클래스인지"가 아니라 "어떤 행동을 할 수 있는지"에 주목해서 객체를 다루는 방식을 Ruby 커뮤니티에서는 **덕 타이핑(duck typing)**이라고 부릅니다. "오리처럼 걷고 오리처럼 소리를 내면 오리로 취급한다"는 발상에서 나온 이름으로, Ruby 코드 곳곳에서 이런 사고방식이 자연스럽게 녹아 있습니다. 이 개념은 12장과 이후 장에서 인터페이스를 다루며 다시 등장합니다.

## 요약

- Ruby 변수는 타입을 미리 선언하지 않는 동적 타입 방식이며, 값을 대입하는 순간 변수가 만들어집니다.
- 변수는 이름의 첫 글자로 종류가 구분됩니다. 소문자/밑줄은 지역 변수, `@`는 인스턴스 변수, `@@`는 클래스 변수, `$`는 전역 변수, 대문자는 상수입니다.
- 기본 자료형에는 Integer, Float, String, Symbol, true/false, nil이 있으며, 이 중 nil도 NilClass의 인스턴스인 어엿한 객체입니다.
- 문자열은 작은따옴표와 큰따옴표로 만들 수 있고, 큰따옴표에서만 `#{}` 문자열 보간과 이스케이프 시퀀스가 해석됩니다.
- Ruby에서 조건문이 거짓으로 취급하는 값은 `false`와 `nil` 뿐이며, 0이나 빈 문자열도 참으로 취급됩니다.
- 타입을 확인할 때는 정확한 클래스를 알려주는 `class`, 상속 관계까지 고려하는 `is_a?`, 메서드 호출 가능 여부를 알려주는 `respond_to?`를 상황에 맞게 사용합니다.
