# 14장. 예외 처리

[◀ 이전: 13장. 심볼과 문자열 심화](ch13-심볼과문자열심화.md) | [📖 목차](00-목차.md) | [다음: 15장. 개방 클래스와 몽키패칭 ▶](ch15-개방클래스와몽키패칭.md)


프로그램은 언제나 예상대로만 흘러가지 않습니다. 사용자가 잘못된 입력을 넣거나, 파일이 존재하지 않거나, 네트워크가 끊기거나, 0으로 나누는 계산을 시도하는 등 다양한 상황에서 오류가 발생할 수 있습니다. Ruby는 이런 상황을 **예외(exception)**라는 객체로 표현하고, 예외가 발생했을 때 프로그램이 갑자기 멈추지 않고 적절히 대응할 수 있는 문법을 제공합니다. 이 장에서는 예외를 잡고, 발생시키고, 나만의 예외를 정의하는 방법을 배웁니다.

## 예외란 무엇인가

예외 없이 오류 상황이 벌어지면 프로그램은 그 자리에서 강제로 종료됩니다.

```ruby
def divide(a, b)
  a / b
end

puts divide(10, 0)
# ZeroDivisionError (divided by 0)
```

이 오류 메시지에 등장한 `ZeroDivisionError`가 바로 예외 객체의 클래스입니다. Ruby의 모든 예외는 `Exception` 클래스를 최상위로 하는 계층 구조를 이루며, 우리가 다루는 대부분의 예외는 그 하위의 `StandardError`를 상속합니다.

## begin/rescue/ensure/else 구조

예외가 발생해도 프로그램이 멈추지 않게 하려면 `begin`/`rescue` 블록으로 위험한 코드를 감쌉니다.

```ruby
begin
  result = 10 / 0
  puts result
rescue
  puts "0으로 나눌 수 없습니다."
end

puts "프로그램은 계속 실행됩니다."
```

`begin` 블록 안에서 예외가 발생하면 그 즉시 실행이 중단되고 `rescue` 블록으로 넘어갑니다. `rescue` 블록이 끝나면 프로그램은 정상적으로 다음 줄부터 이어서 실행됩니다.

전체 구조는 다음과 같이 네 부분으로 이루어집니다.

```ruby
begin
  # 예외가 발생할 수 있는 코드
rescue => e
  # 예외가 발생했을 때 실행
else
  # 예외가 발생하지 않았을 때만 실행
ensure
  # 예외 발생 여부와 상관없이 항상 실행
end
```

각 절의 역할을 예제로 확인해 보겠습니다.

```ruby
def read_number(text)
  begin
    number = Integer(text)
  rescue ArgumentError => e
    puts "숫자로 변환할 수 없습니다: #{e.message}"
  else
    puts "변환 성공: #{number}"
  ensure
    puts "read_number 호출 종료"
  end
end

read_number("42")
# 변환 성공: 42
# read_number 호출 종료

read_number("abc")
# 숫자로 변환할 수 없습니다: invalid value for Integer(): "abc"
# read_number 호출 종료
```

`else` 절은 `begin` 블록이 예외 없이 끝났을 때만 실행되고, `ensure` 절은 예외 발생 여부와 무관하게 항상 실행됩니다. `ensure`는 파일이나 네트워크 연결을 닫는 등 "무슨 일이 있어도 반드시 정리해야 하는 작업"을 넣기에 알맞은 자리입니다.

## 특정 예외 클래스 지정해서 rescue하기

`rescue`만 단독으로 쓰면 `StandardError`와 그 하위 클래스의 예외만 잡힙니다. 대부분의 경우 이것으로 충분하지만, 어떤 예외를 잡을지 명시적으로 지정하는 것이 훨씬 안전하고 의도가 분명합니다. 의도치 않은 예외까지 조용히 삼켜버리면 진짜 버그를 찾기 어려워지기 때문입니다.

```ruby
begin
  file = File.read("존재하지_않는_파일.txt")
rescue Errno::ENOENT => e
  puts "파일을 찾을 수 없습니다: #{e.message}"
end
```

여러 종류의 예외를 서로 다른 방식으로 처리하고 싶다면 `rescue` 절을 여러 개 나열합니다. 이때 더 구체적인(하위) 예외 클래스를 먼저 적고, 더 포괄적인(상위) 예외 클래스를 나중에 적어야 합니다. Ruby는 위에서부터 순서대로 매치를 검사하기 때문에, 포괄적인 예외를 먼저 두면 그 아래의 구체적인 `rescue` 절은 실행될 기회를 잃습니다.

```ruby
def safe_divide(a, b)
  a / b
rescue ZeroDivisionError => e
  puts "0으로 나눌 수 없습니다."
rescue TypeError => e
  puts "숫자가 아닌 값이 섞여 있습니다."
rescue StandardError => e
  puts "예상치 못한 오류: #{e.message}"
end

safe_divide(10, 0)     # 0으로 나눌 수 없습니다.
safe_divide(10, "2")   # 숫자가 아닌 값이 섞여 있습니다.
```

하나의 `rescue` 절에서 여러 예외 클래스를 한꺼번에 잡고 싶다면 쉼표로 나열할 수 있습니다.

```ruby
begin
  # ...
rescue ZeroDivisionError, TypeError => e
  puts "계산 중 오류가 발생했습니다: #{e.message}"
end
```

## raise로 예외 발생시키기

`raise`를 사용하면 원하는 시점에 직접 예외를 발생시킬 수 있습니다. 여러 형태로 호출할 수 있습니다.

```ruby
raise "무언가 잘못되었습니다"              # RuntimeError로 발생
raise ArgumentError                        # 메시지 없이 클래스만 지정
raise ArgumentError, "나이는 음수일 수 없습니다"  # 클래스와 메시지 함께 지정
```

메서드 인자를 검증하는 경우를 예로 들어 보겠습니다.

```ruby
def set_age(age)
  raise ArgumentError, "나이는 0 이상이어야 합니다" if age < 0
  @age = age
end

set_age(-5)
# ArgumentError: 나이는 0 이상이어야 합니다
```

### 커스텀 예외 클래스 정의하기

내장된 예외 클래스만으로 표현하기 어려운 상황, 즉 우리 프로그램의 도메인에 특화된 오류를 나타내고 싶을 때는 `StandardError`를 상속한 나만의 예외 클래스를 정의합니다. 9장과 10장에서 배운 클래스 정의, 상속 문법이 여기에 그대로 사용됩니다.

```ruby
class InsufficientFundsError < StandardError
  def initialize(msg = "잔액이 부족합니다")
    super
  end
end

class BankAccount
  def initialize(balance)
    @balance = balance
  end

  def withdraw(amount)
    raise InsufficientFundsError if amount > @balance

    @balance -= amount
  end
end

account = BankAccount.new(1000)

begin
  account.withdraw(5000)
rescue InsufficientFundsError => e
  puts e.message   # 잔액이 부족합니다
end
```

예외 클래스에 추가 정보를 담고 싶다면 속성을 정의하고 `initialize`에서 값을 채워 넣을 수 있습니다.

```ruby
class InsufficientFundsError < StandardError
  attr_reader :shortage

  def initialize(shortage)
    @shortage = shortage
    super("잔액이 #{shortage}원 부족합니다")
  end
end

class BankAccount
  def initialize(balance)
    @balance = balance
  end

  def withdraw(amount)
    if amount > @balance
      raise InsufficientFundsError.new(amount - @balance)
    end

    @balance -= amount
  end
end

account = BankAccount.new(1000)

begin
  account.withdraw(5000)
rescue InsufficientFundsError => e
  puts e.message     # 잔액이 4000원 부족합니다
  puts e.shortage     # 4000
end
```

이렇게 커스텀 예외를 정의하면 `rescue` 절에서 오류의 종류를 구체적으로 구분할 수 있을 뿐 아니라, 예외 객체 자체가 오류에 대한 부가 정보(위 예제의 `shortage`처럼)를 실어 나르는 역할까지 할 수 있습니다.

## retry로 재시도하는 패턴

`retry`는 `rescue` 절 안에서 사용하며, 다시 `begin` 블록의 처음으로 돌아가 코드를 재실행합니다. 네트워크 요청처럼 일시적인 오류가 발생할 수 있는 작업을 몇 차례 다시 시도하고 싶을 때 유용합니다.

```ruby
def fetch_data
  attempts = 0

  begin
    attempts += 1
    puts "#{attempts}번째 시도"
    raise "일시적인 네트워크 오류" if attempts < 3

    puts "데이터 가져오기 성공"
  rescue => e
    if attempts < 3
      puts "실패: #{e.message}. 재시도합니다."
      retry
    else
      puts "여러 번 시도했지만 실패했습니다."
    end
  end
end

fetch_data
```

`retry`를 사용할 때는 반드시 재시도 횟수를 제한하는 조건을 두어야 합니다. 조건 없이 `retry`만 호출하면 예외가 계속 발생하는 상황에서 프로그램이 끝없이 같은 코드를 반복 실행하는 무한 루프에 빠질 수 있습니다.

## 메서드 전체를 감싸는 암묵적 begin

지금까지의 예제 중 일부에서 이미 사용했지만, 메서드를 정의할 때는 `begin`을 따로 쓰지 않고도 `def`와 `end` 사이에 바로 `rescue`를 둘 수 있습니다. 메서드 본문 전체가 암묵적으로 `begin` 블록의 역할을 하기 때문입니다.

```ruby
def divide(a, b)
  a / b
rescue ZeroDivisionError => e
  puts "0으로 나눌 수 없습니다: #{e.message}"
  nil
ensure
  puts "나눗셈 시도가 끝났습니다."
end

divide(10, 0)
```

이 방식은 메서드 본문 전체를 예외 처리 대상으로 삼을 때 `begin`/`end`로 한 번 더 들여쓰기를 하지 않아도 되므로 코드가 한결 간결해집니다. 메서드의 일부분만 예외 처리하고 싶다면 이전처럼 그 부분만 `begin`/`rescue`로 별도로 감싸면 됩니다.

## 예외를 남용하지 않아야 하는 이유

예외는 강력한 도구지만, 프로그램의 정상적인 흐름을 제어하는 용도로 남용해서는 안 됩니다. 예외를 발생시키고 잡는 과정은 일반적인 조건문보다 비용이 크고, 무엇보다 "이 코드는 오류가 날 수도 있다"는 신호를 예외로 표현하면 코드를 읽는 사람이 정상 경로와 오류 경로를 구분하기 어려워집니다.

Ruby에는 예외를 던지는 대신 `?`로 끝나는 메서드나 `nil`을 반환하는 메서드로 상황을 먼저 확인하는 관례가 폭넓게 자리 잡고 있습니다. 다음 두 코드를 비교해 보겠습니다.

```ruby
# 예외에 의존하는 방식 - 정상적으로 있을 수 있는 상황까지 예외로 처리
begin
  content = File.read("config.txt")
rescue Errno::ENOENT
  content = nil
end

# ?로 먼저 확인하는 방식 - 더 명확하고 비용도 적다
if File.exist?("config.txt")
  content = File.read("config.txt")
else
  content = nil
end
```

해시나 배열에서 값을 꺼낼 때도 마찬가지입니다.

```ruby
user = { name: "김루비" }

# 예외를 유발할 수 있는 fetch 대신
age = user.fetch(:age, nil)   # 기본값을 지정해 예외 없이 처리

# 있는지 먼저 확인
puts user[:age] if user.key?(:age)
```

물론 모든 상황에서 `?` 메서드로 대체할 수 있는 것은 아닙니다. "파일이 존재하는지 확인한 직후 다른 프로세스가 파일을 지워버리는" 것처럼 확인과 실행 사이에 상태가 바뀔 수 있는 경우, 혹은 애초에 발생 자체가 드물고 프로그램의 정상 흐름으로 볼 수 없는 진짜 오류 상황(데이터베이스 연결 실패, 설정 파일의 형식이 완전히 잘못된 경우 등)에는 예외가 훨씬 적합합니다.

정리하면 다음과 같은 기준으로 선택하면 됩니다.

- 일어날 수 있다고 충분히 예상되는 상황이고, 미리 확인할 방법이 있다면 → `?` 메서드나 조건문으로 먼저 확인합니다.
- 미리 확인하기 어렵거나, 정말로 예외적이고 드문 오류 상황이라면 → 예외를 사용합니다.

이 균형 감각은 15장 이후에 다룰 코드 스타일 전반과도 연결되며, 18장에서 좋은 Ruby 코드를 작성하는 습관을 이야기할 때 다시 짚어보게 됩니다.

## 요약

- `begin`/`rescue`/`else`/`ensure`로 예외 발생 시의 처리, 정상 종료 시의 처리, 항상 실행할 정리 작업을 구분해서 작성할 수 있습니다.
- `rescue`에 예외 클래스를 명시하면 원하는 종류의 예외만 정확히 잡을 수 있고, 여러 `rescue` 절을 둘 때는 구체적인 예외를 먼저, 포괄적인 예외를 나중에 적어야 합니다.
- `raise`로 예외를 직접 발생시킬 수 있으며, `StandardError`를 상속해 도메인에 특화된 커스텀 예외 클래스를 정의할 수 있습니다.
- `retry`는 `rescue` 절에서 `begin` 블록을 재실행하며, 반드시 재시도 횟수 제한을 두어야 무한 루프를 피할 수 있습니다.
- 메서드 정의에서는 `begin` 없이 `def`와 `end` 사이에 바로 `rescue`/`ensure`를 둘 수 있습니다.
- 예외는 정상적인 흐름 제어 수단이 아닙니다. 미리 확인할 수 있는 상황이라면 `?` 메서드나 조건문을 우선하고, 정말 예외적인 오류에만 예외를 사용하는 것이 Ruby의 관례입니다.

## 연습문제

1. 사용자로부터 입력받은 문자열을 정수로 변환하는 메서드를 작성하고, 변환에 실패하면 `ArgumentError`를 잡아 `0`을 반환하도록 `begin`/`rescue`로 처리해 보세요.
2. `ZeroDivisionError`와 `TypeError`를 각각 다른 메시지로 처리하는 나눗셈 메서드를 작성하고, 두 예외 상황을 모두 재현하는 코드로 확인해 보세요.
3. `StandardError`를 상속한 `InvalidAgeError` 클래스를 정의하고, 나이를 저장하는 메서드에서 음수가 들어오면 이 예외를 `raise`하도록 만들어 보세요.
4. 최대 3번까지 재시도하고, 그래도 실패하면 포기 메시지를 출력하는 `retry` 예제를 직접 작성해 보세요. 재시도 횟수를 세는 변수를 어디에 선언해야 하는지 주의 깊게 생각해 보세요.
5. 배열에서 특정 인덱스의 값을 안전하게 가져오는 코드를, (a) `begin`/`rescue`로 `IndexError`를 잡는 방식과 (b) 인덱스 범위를 먼저 확인하는 방식 두 가지로 작성하고, 어느 쪽이 더 적절한지 이유와 함께 비교해 보세요.
