# 3장. 기본 문법과 데이터 타입

2장에서 REPL을 켜고 `(+ 1 2)` 같은 식을 몇 번 입력해 보았습니다. 이번 장에서는 그 괄호 뭉치가 정확히 무엇을 의미하는지, 그리고 Lisp가 다루는 값의 종류에는 어떤 것들이 있는지 차근차근 살펴봅니다. Lisp 문법은 다른 언어에 비해 규칙이 극단적으로 적은데, 그 적은 규칙을 제대로 이해하고 나면 오히려 문법을 "외울" 필요가 거의 없어집니다.

## S-표현식: 괄호가 전부다

Lisp의 모든 코드는 **S-표현식**(symbolic expression, 줄여서 S-expr)이라는 단 하나의 형태로 작성됩니다. S-표현식은 다음 두 가지 중 하나입니다.

1. **원자(atom)**: `42`, `3.14`, `"hello"`, `my-variable` 처럼 더 이상 쪼갤 수 없는 낱값
2. **리스트(list)**: 괄호로 둘러싸인 S-표현식들의 나열, 예를 들면 `(+ 1 2)`나 `(list 1 2 3)`

리스트 형태의 S-표현식을 평가(evaluate)할 때 Lisp는 다음 규칙을 따릅니다.

```lisp
(연산자 인자1 인자2 ...)
```

즉 괄호를 열고 **가장 먼저 오는 것이 함수(또는 매크로/특수 연산자)의 이름**이고, 그 뒤에 오는 것들이 인자입니다. 이를 **전위 표기법**(prefix notation)이라고 부릅니다. 우리에게 익숙한 수식 `1 + 2`는 Lisp에서 이렇게 씁니다.

```lisp
* (+ 1 2)
=> 3
```

`+`가 연산자 자리에, `1`과 `2`가 인자 자리에 놓였을 뿐입니다. 중위 표기법(`1 + 2`)에 익숙한 눈에는 낯설지만, 규칙은 오히려 더 단순합니다. 연산자 우선순위 표를 외울 필요가 없고, 괄호 위치만 보면 계산 순서가 명확히 드러납니다.

```lisp
* (+ 1 (* 2 3) 4)
=> 11

* (* (+ 1 2) (+ 3 4))
=> 21
```

첫 번째 식은 `1 + (2 * 3) + 4`를, 두 번째 식은 `(1 + 2) * (3 + 4)`를 계산한 것입니다. 안쪽 괄호부터 평가되어 바깥쪽으로 값이 전달되는 구조라서, 괄호가 많아 보여도 계산 순서를 헷갈릴 일은 없습니다.

`+`나 `*`는 인자를 몇 개든 받을 수 있다는 점도 눈여겨볼 만합니다.

```lisp
* (+ 1 2 3 4 5)
=> 15

* (+)
=> 0

* (*)
=> 1
```

## 코드가 곧 데이터: 리스트로 표현되는 프로그램

Lisp라는 이름 자체가 "LISt Processing"에서 왔습니다. 그런데 흥미로운 사실은, 앞서 본 `(+ 1 2)`라는 **코드** 자체가 `+`, `1`, `2`라는 세 원소를 담은 **리스트**와 똑같은 모양이라는 점입니다. Lisp는 실제로 이 둘을 구분하지 않습니다. 프로그램 코드는 곧 리스트라는 데이터 구조이고, 리스트는 평가하면 코드가 됩니다. 이런 성질을 **동형성**(homoiconicity)이라고 부릅니다.

이 개념을 직접 확인해 봅시다. `quote`(줄여서 `'`)를 사용하면 리스트를 평가하지 않고 데이터 그대로 다룰 수 있습니다.

```lisp
* '(+ 1 2)
=> (+ 1 2)

* (quote (+ 1 2))
=> (+ 1 2)
```

`'`을 붙이지 않으면 Lisp는 `(+ 1 2)`를 "`+`라는 함수를 `1`, `2`에 적용하라"는 **명령**으로 읽고 실행하여 `3`을 돌려줍니다. 반면 `'`을 붙이면 "이건 그냥 세 원소짜리 리스트 데이터야"라고 알려주는 셈이라, 평가하지 않고 리스트 `(+ 1 2)` 자체를 반환합니다.

```lisp
* (first '(+ 1 2))
=> +

* (rest '(+ 1 2))
=> (1 2)
```

즉 코드 `(+ 1 2)`를 리스트로 취급하면 그 첫 원소는 심볼 `+`이고, 나머지는 `(1 2)`라는 리스트입니다. 코드와 데이터가 같은 얼굴을 하고 있다는 이 성질은 11장 매크로에서 다시 만나게 됩니다. 매크로는 결국 "코드를 데이터처럼 조작해서 새로운 코드를 만들어내는 함수"이기 때문입니다. 지금은 "리스트 앞에 `'`을 붙이면 평가되지 않고 데이터 그대로 남는다"는 사실만 기억해 두면 충분합니다.

## 원자값: 숫자, 문자열, 문자, 심볼

리스트가 아닌 낱값들을 원자(atom)라고 부릅니다. Lisp가 기본으로 다루는 원자 타입들을 하나씩 살펴보겠습니다.

### 숫자

Common Lisp는 정수와 실수를 엄격히 구분하며, 정수 연산은 오차 없이 정확하게 계산됩니다.

```lisp
* (+ 1 2)
=> 3

* (/ 1 3)
=> 1/3

* (/ 1.0 3)
=> 0.33333334

* (* 1/3 3)
=> 1
```

`(/ 1 3)`이 소수로 뭉개지지 않고 정확한 분수 `1/3`로 표현되는 점이 특징입니다. 정수와 유리수는 임의 정밀도로 계산되므로, 아무리 큰 정수를 곱해도 오버플로가 발생하지 않습니다.

```lisp
* (* 99999999999999999999 2)
=> 199999999999999999998
```

실수를 섞어서 계산하면 결과도 실수(부동소수점)로 바뀝니다.

```lisp
* (+ 1 2.5)
=> 3.5
```

### 문자열과 문자

문자열은 큰따옴표로 감쌉니다.

```lisp
* "hello, lisp"
=> "hello, lisp"

* (length "hello")
=> 5
```

문자 하나는 `#\`을 앞에 붙여 표기합니다. 문자열과 문자는 서로 다른 타입임에 유의하세요.

```lisp
* #\a
=> #\a

* (char "hello" 0)
=> #\h
```

문자열과 문자에 관한 더 다양한 함수는 14장에서 자세히 다룹니다.

### 심볼

심볼(symbol)은 이름 그 자체를 나타내는 값입니다. 변수 이름, 함수 이름이 모두 심볼로 표현됩니다.

```lisp
* 'my-symbol
=> MY-SYMBOL

* (symbolp 'my-symbol)
=> T
```

REPL이 소문자로 입력한 심볼을 대문자로 돌려주는 것을 눈치챘을 것입니다. Common Lisp는 기본적으로 심볼 이름을 대문자로 정규화해서 저장하기 때문인데, 코드를 작성할 때는 소문자를 그대로 사용해도 무방하며 관례상 소문자 kebab-case(`my-variable`, `calculate-total`처럼 단어를 하이픈으로 연결하는 방식)를 씁니다.

### `nil`과 `t`: 거짓과 참, 그리고 빈 리스트

Common Lisp에는 별도의 불리언 타입이 없습니다. 대신 `nil`이 "거짓"과 "빈 리스트"를 동시에 나타내고, `nil`이 아닌 모든 값이 "참"으로 취급됩니다. 관례적으로 참을 명시할 때는 심볼 `t`를 사용합니다.

```lisp
* (null nil)
=> T

* (null '())
=> T

* (eq nil '())
=> T

* (if 3 "참이다" "거짓이다")
=> "참이다"

* (if nil "참이다" "거짓이다")
=> "거짓이다"
```

`nil`과 `'()`(빈 리스트)이 같은 값이라는 점이 Lisp 초심자에게는 다소 신기하게 느껴질 수 있습니다. "리스트가 비어 있다"는 것과 "조건이 거짓이다"라는 것을 같은 값으로 표현하도록 설계된 것입니다. 조건문과 불리언 값의 자세한 활용은 5장에서 다룹니다.

## 값 바인딩하기: `setf`, `defparameter`, `defvar`

지금까지는 값을 그 자리에서 바로 썼지만, 실제 프로그램에서는 값에 이름을 붙여 두고 재사용해야 합니다. Common Lisp에는 이를 위한 몇 가지 도구가 있습니다.

### `defparameter`: 전역 변수 선언 (재정의 허용)

```lisp
* (defparameter *max-users* 100)
=> *MAX-USERS*

* *max-users*
=> 100
```

전역 변수 이름을 별표(`*`)로 감싸는 것은 필수 문법이 아니라 관례입니다. 이렇게 표시해 두면 "이 이름은 전역 변수구나"라고 코드를 읽는 사람이 한눈에 알아볼 수 있습니다. `defparameter`로 선언한 변수는 같은 이름으로 다시 `defparameter`를 실행하면 값이 갱신됩니다.

```lisp
* (defparameter *max-users* 200)
=> *MAX-USERS*

* *max-users*
=> 200
```

### `defvar`: 전역 변수 선언 (이미 있으면 유지)

`defvar`는 `defparameter`와 비슷하지만, 변수가 **이미 정의되어 있으면 값을 바꾸지 않습니다**. 주로 프로그램이 처음 로드될 때 기본값을 한 번만 설정하고 싶을 때 사용합니다.

```lisp
* (defvar *retry-count* 3)
=> *RETRY-COUNT*

* (defvar *retry-count* 999)  ; 이미 정의되어 있으므로 무시됨
=> *RETRY-COUNT*

* *retry-count*
=> 3
```

REPL에서 실험할 때는 `defparameter`가, 코드를 여러 번 다시 불러와도(reload) 설정값이 초기화되지 않게 하고 싶을 때는 `defvar`가 적합합니다.

### `setf`: 이미 있는 자리에 값 대입하기

`setf`는 변수든, 리스트의 한 칸이든, 구조체의 필드든, "값이 저장될 수 있는 자리"에 새 값을 대입하는 범용 도구입니다. 지금은 변수에 값을 대입하는 가장 단순한 형태만 살펴봅니다.

```lisp
* (defparameter *counter* 0)
=> *COUNTER*

* (setf *counter* (+ *counter* 1))
=> 1

* *counter*
=> 1
```

`defparameter`/`defvar`가 "변수를 새로 만드는" 것이라면, `setf`는 "이미 존재하는 자리의 값을 바꾸는" 역할을 합니다. `setf`가 리스트나 구조체의 내부까지 자유롭게 수정할 수 있는 범용 대입 연산자라는 점은 7장과 12장에서 더 실감 나게 확인하게 됩니다.

## 심볼 vs 키워드: `:keyword`

콜론(`:`)으로 시작하는 심볼을 **키워드**라고 부릅니다. 키워드는 일반 심볼과 겉모습은 비슷하지만 중요한 차이가 있습니다.

```lisp
* :name
=> :NAME

* (keywordp :name)
=> T

* (keywordp 'name)
=> NIL
```

가장 큰 차이는 **키워드는 항상 자기 자신으로 평가된다**는 점입니다. 일반 심볼은 변수로 사용되면 그 변수에 바인딩된 값을 나타내지만, 키워드는 quote를 하지 않아도 평가하면 그대로 자기 자신이 나옵니다.

```lisp
* (defparameter x 10)
=> X

* x
=> 10

* :x
=> :X
```

`x`라는 심볼은 값 `10`에 바인딩되어 있어서 평가하면 `10`이 나오지만, `:x`라는 키워드는 애초에 "이름표" 그 자체가 목적이라 평가해도 항상 `:X`입니다. 이런 성질 때문에 키워드는 주로 다음과 같은 용도로 쓰입니다.

- 함수의 옵션 이름 표시: `(make-array 5 :initial-element 0)`의 `:initial-element`
- 열거형처럼 구분되는 상태 값 표현: `:active`, `:pending`, `:done`

```lisp
* (defparameter *status* :pending)
=> *STATUS*

* (eq *status* :pending)
=> T
```

문자열 `"pending"` 대신 키워드 `:pending`을 쓰면 오타에 덜 취약하고(정의되지 않은 키워드는 존재하지 않으므로 REPL이나 편집기 도움을 받기 쉽습니다), 비교도 `eq`라는 빠른 연산으로 처리할 수 있어 Lisp 코드 전반에서 즐겨 사용됩니다. 함수에 `&key` 인자로 옵션을 전달할 때 키워드가 어떻게 쓰이는지는 4장에서 다시 살펴봅니다.

## 요약

- Lisp 코드는 모두 S-표현식으로 이루어지며, 리스트 형태의 S-표현식은 `(연산자 인자...)`라는 전위 표기법으로 평가됩니다.
- 코드 자체가 리스트 데이터와 같은 모양을 하고 있으며(동형성), `'`(quote)을 붙이면 평가를 막고 데이터 그대로 다룰 수 있습니다.
- 원자값에는 정수·유리수·실수 같은 숫자, 문자열, 문자(`#\a`), 심볼이 있습니다.
- `nil`은 거짓이자 빈 리스트를 동시에 나타내며, `nil`이 아닌 모든 값은 참으로 취급되고 관례상 `t`로 참을 표시합니다.
- `defparameter`와 `defvar`는 전역 변수를 선언하며, 전자는 항상 갱신하고 후자는 처음 한 번만 값을 설정합니다. `setf`는 이미 존재하는 자리에 새 값을 대입하는 범용 연산자입니다.
- `:keyword` 형태의 키워드는 항상 자기 자신으로 평가되는 특수한 심볼로, 옵션이나 상태 값 표현에 널리 쓰입니다.

## 연습문제

1. `(+ 1 (* 2 (- 5 3)) 4)`를 손으로 먼저 계산해 보고, REPL에 입력하여 결과가 맞는지 확인해 보세요.
2. `'(1 2 3)`과 `(list 1 2 3)`을 각각 REPL에 입력해 보고, 두 결과가 같은지, quote가 하는 역할이 무엇인지 설명해 보세요.
3. `(first '(a b c))`와 `(rest '(a b c))`의 결과를 예상해 보고 실행하여 확인하세요. 코드가 리스트로 취급될 때 `+`, `-` 같은 연산자가 첫 원소 자리에 온다는 사실과 연결 지어 설명해 보세요.
4. `defparameter`로 `*my-name*`이라는 변수에 자신의 이름(문자열)을 저장한 뒤, `setf`를 사용해 다른 이름으로 바꿔 보세요.
5. `(eq :active 'active)`의 결과를 예상해 보고 실행한 다음, 왜 그런 결과가 나오는지 심볼과 키워드의 차이로 설명해 보세요.
