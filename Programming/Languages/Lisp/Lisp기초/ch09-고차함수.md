## 함수도 값이다

4장에서는 `defun`으로 함수를 정의하는 법을 배웠습니다. 그런데 Lisp에서 함수는 그저 "호출할 수 있는 코드 덩어리"가 아니라, 숫자나 문자열처럼 변수에 담고 다른 함수에 전달할 수 있는 하나의 **값**입니다. 이런 성질을 가진 함수를 인자로 받거나 결과로 돌려주는 함수를 **고차 함수(higher-order function)**라고 부릅니다.

Common Lisp을 처음 접하면 이 부분에서 살짝 헷갈릴 수 있습니다. 왜냐하면 Common Lisp은 함수 이름공간과 변수 이름공간이 분리된 "Lisp-2" 언어이기 때문입니다. 즉, 같은 심볼 `foo`라도 함수로 쓰일 때와 변수로 쓰일 때가 서로 다른 의미를 가질 수 있습니다.

```lisp
(defun square (x)
  "x의 제곱을 반환한다."
  (* x x))

* (square 5)
25
```

여기서 `square`라는 심볼은 함수 이름공간에 정의되어 있습니다. 이 함수 자체를 값으로 꺼내려면 `#'` (샵쿼트, sharp-quote)를 사용합니다.

```lisp
* #'square
#<FUNCTION SQUARE>
```

`#'square`는 `(function square)`의 축약 표기입니다. `'square`(단순 quote)와 헷갈리기 쉬운데, `'square`는 그냥 심볼 `square`를 반환할 뿐이고, `#'square`는 그 심볼이 가리키는 **함수 객체**를 반환합니다.

```lisp
* 'square
SQUARE

* (symbolp 'square)
T

* (functionp #'square)
T
```

## funcall과 apply로 함수 값 호출하기

함수를 값으로 손에 쥐었다면, 이제 그것을 호출할 방법이 필요합니다. Common Lisp은 두 가지 도구를 제공합니다: `funcall`과 `apply`입니다.

`funcall`은 함수와 인자들을 하나씩 나열해서 호출합니다.

```lisp
* (funcall #'square 7)
49

* (funcall #'+ 1 2 3)
6
```

`apply`는 마지막 인자로 리스트를 받아서, 그 리스트의 원소들을 인자로 풀어서 호출합니다. 인자 개수를 미리 알 수 없을 때 유용합니다.

```lisp
* (apply #'+ '(1 2 3 4))
10

* (apply #'+ 1 2 '(3 4))
10
```

두 번째 예시처럼 `apply`는 마지막 인자만 리스트로 풀고, 그 앞의 인자들은 그대로 붙입니다. `funcall`은 인자 개수가 고정되어 있을 때, `apply`는 리스트 형태로 인자를 모아둔 경우에 쓴다고 기억하면 됩니다.

함수를 변수에 담아 두었다가 나중에 호출하는 것도 자연스럽습니다.

```lisp
* (let ((op #'square))
    (funcall op 9))
81
```

여기서 `let`은 6장에서 배운 지역 바인딩입니다. `op`라는 지역 변수에 함수 객체를 담아 두고, 필요할 때 `funcall`로 꺼내 쓰는 것이지요.

## lambda: 이름 없는 함수

매번 `defun`으로 이름을 붙여 함수를 정의하는 것은 번거로울 때가 있습니다. 딱 한 번, 그 자리에서만 쓸 함수라면 이름을 붙일 필요조차 없습니다. 이럴 때 쓰는 것이 **람다(lambda)**, 즉 익명 함수입니다.

```lisp
* (lambda (x) (* x x))
#<FUNCTION (LAMBDA (X)) {1004ABCDEF}>
```

`lambda` 표현식 자체는 함수 객체를 만들어낼 뿐, 아직 호출된 것은 아닙니다. `funcall`이나 `apply`로 호출해야 합니다.

```lisp
* (funcall (lambda (x) (* x x)) 6)
36
```

`(lambda (x) ...)`는 `#'(lambda (x) ...)`와 마찬가지로 함수 객체를 만들어내므로, `#'`를 굳이 붙이지 않아도 됩니다. Common Lisp이 특별히 `lambda` 형태를 함수로 인식해주기 때문입니다. 다만 명확성을 위해 `#'(lambda ...)`라고 쓰는 코드도 종종 볼 수 있습니다. 이 책에서는 간결함을 위해 `#'` 없이 쓰겠습니다.

## mapcar: 리스트의 모든 원소에 함수 적용하기

7장에서 리스트를 다루는 다양한 함수들을 배웠습니다. 그중에서도 `mapcar`는 고차 함수의 대표주자입니다. 리스트의 각 원소에 함수를 적용해서 새 리스트를 만들어냅니다.

```lisp
* (mapcar #'square '(1 2 3 4 5))
(1 4 9 16 25)
```

`defun`으로 만든 이름 있는 함수뿐 아니라, `lambda`로 즉석에서 만든 익명 함수도 그대로 넘길 수 있습니다.

```lisp
* (mapcar (lambda (x) (+ x 10)) '(1 2 3))
(11 12 13)
```

`mapcar`는 리스트를 여러 개 동시에 받을 수도 있습니다. 이 경우 각 리스트에서 같은 위치의 원소들을 함께 함수에 넘깁니다.

```lisp
* (mapcar #'+ '(1 2 3) '(10 20 30))
(11 22 33)

* (mapcar #'list '(a b c) '(1 2 3))
((A 1) (B 2) (C 3))
```

리스트 길이가 다르면 짧은 쪽에 맞춰서 멈춥니다.

```lisp
* (mapcar #'+ '(1 2 3) '(10 20))
(11 22)
```

`mapcar`와 비슷하지만 결과를 리스트로 모으지 않는 `mapc`도 있습니다. 부수 효과(화면 출력 등)를 위해 순회만 하고 싶을 때 사용합니다.

```lisp
* (mapc (lambda (x) (format t "~a " x)) '(1 2 3))
1 2 3
NIL
```

`format t`는 14장에서 자세히 다루겠지만, 여기서는 "화면에 출력한다" 정도로 이해하면 충분합니다. `mapc`는 원래 리스트(첫 번째 인자)를 그대로 반환값으로 돌려줍니다.

## reduce: 리스트를 하나의 값으로 접기

`mapcar`가 리스트를 같은 길이의 새 리스트로 변환한다면, `reduce`는 리스트 전체를 순회하면서 누적된 하나의 값으로 "접어(fold)" 냅니다.

```lisp
* (reduce #'+ '(1 2 3 4 5))
15

* (reduce #'* '(1 2 3 4 5))
120
```

동작 방식을 풀어써보면 이렇습니다. `(reduce #'+ '(1 2 3 4))`는 다음과 같이 왼쪽부터 순서대로 계산됩니다.

```
(+ (+ (+ 1 2) 3) 4)
=> (+ (+ 3 3) 4)
=> (+ 6 4)
=> 10
```

`reduce`는 `:initial-value` 키워드 인자로 시작값을 지정할 수 있습니다. 빈 리스트를 다룰 때 특히 중요합니다.

```lisp
* (reduce #'+ '() :initial-value 0)
0

* (reduce #'+ '(1 2 3) :initial-value 100)
106
```

리스트에서 최댓값을 찾거나 문자열을 이어 붙이는 등, "여러 값을 하나로 합치는" 작업에는 대부분 `reduce`가 자연스럽게 들어맞습니다.

```lisp
* (reduce #'max '(3 7 2 9 4))
9

* (reduce (lambda (acc x) (if (> x acc) x acc))
           '(3 7 2 9 4)
           :initial-value 0)
9
```

8장에서 재귀로 리스트 합계나 최댓값을 직접 구현해봤다면, `reduce`가 사실상 그 재귀 패턴을 일반화한 함수라는 것을 눈치챘을 것입니다. "누적값과 다음 원소를 받아서 새 누적값을 만드는" 함수만 넘기면, 반복 구조 자체는 `reduce`가 대신 처리해줍니다.

## 함수를 반환하는 함수

고차 함수는 함수를 인자로 받는 것뿐 아니라, 함수를 **결과로 반환**하는 것도 포함합니다. 예를 들어 "n을 더하는 함수"를 만들어주는 함수를 생각해봅시다.

```lisp
(defun make-adder (n)
  "n을 더하는 함수를 반환한다."
  (lambda (x) (+ x n)))

* (defparameter *add5* (make-adder 5))
*ADD5*

* (funcall *add5* 10)
15

* (funcall (make-adder 100) 1)
101
```

`make-adder`가 반환한 `lambda`가 자신을 만들어낸 `make-adder`의 지역 변수 `n`을 계속 "기억"하고 있다는 점이 흥미롭습니다. 이 현상은 **클로저(closure)**라고 부르며, 6장에서 배운 지역 바인딩과 깊은 관련이 있습니다. 클로저의 원리와 활용법은 10장에서 본격적으로 다루겠습니다.

## 정리하며 보는 관계도

지금까지 나온 함수들을 정리하면 다음과 같습니다.

| 함수 | 역할 |
|---|---|
| `funcall` | 함수와 인자를 나열해서 호출 |
| `apply` | 함수와 인자 리스트를 풀어서 호출 |
| `lambda` | 이름 없는 함수 생성 |
| `mapcar` | 리스트의 각 원소에 함수 적용, 새 리스트 반환 |
| `mapc` | `mapcar`와 비슷하지만 결과 리스트를 만들지 않음 |
| `reduce` | 리스트를 순회하며 하나의 값으로 누적 |

4장에서 `defun`으로 이름 있는 함수를 정의하는 법을 배웠다면, 이번 장에서는 그 함수를 값으로 다루고, 다른 함수에 실어 보내는 법을 배운 셈입니다. 이런 관점은 Lisp뿐 아니라 함수형 프로그래밍 전반의 핵심 아이디어이기도 합니다.

## 요약

- Common Lisp은 함수 이름공간과 변수 이름공간이 분리되어 있으며, `#'`(샵쿼트)로 함수 객체를 값으로 꺼낼 수 있습니다.
- `funcall`은 인자를 나열해서, `apply`는 인자 리스트를 풀어서 함수를 호출합니다.
- `lambda`는 이름 없는 함수를 그 자리에서 만들어냅니다.
- `mapcar`는 리스트의 각 원소에 함수를 적용해 새 리스트를 만들고, `mapc`는 결과 리스트 없이 순회만 합니다.
- `reduce`는 리스트를 순회하며 하나의 값으로 누적하며, `:initial-value`로 시작값을 지정할 수 있습니다.
- 함수는 다른 함수의 결과로 반환될 수도 있으며, 이때 등장하는 것이 10장에서 다룰 클로저입니다.
