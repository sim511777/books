# 6장. let과 지역 바인딩

4장에서 함수를 정의하면서 매개변수라는 형태로 이름에 값을 묶는 방법을 배웠습니다. 그런데 함수 본문 안에서 계산 중간 결과에 임시로 이름을 붙이고 싶을 때는 어떻게 해야 할까요? 매번 새 함수를 정의할 수는 없는 노릇입니다. 이번 장에서 배울 `let`과 `let*`가 바로 이런 상황을 위한 도구입니다.

## 왜 지역 변수가 필요한가

다음 함수를 봅시다. 직각삼각형의 빗변 길이를 구하는 함수입니다.

```lisp
* (defun 빗변 (a b)
    (sqrt (+ (* a a) (* b a))))
빗변
```

어딘가 이상하지 않나요? `(* a a)`와 `(* b a)`처럼 같은 식을 여러 번 반복해서 쓰다 보면 오타가 나기 쉽고(방금도 `(* b a)`가 아니라 `(* b b)`여야 했습니다), 코드를 읽는 사람도 각 부분식이 무엇을 의미하는지 한눈에 파악하기 어렵습니다. 만약 "a의 제곱", "b의 제곱"이라는 이름을 붙일 수 있다면 코드가 훨씬 명확해질 것입니다. 바로 이럴 때 `let`을 사용합니다.

## let: 여러 변수를 한꺼번에 바인딩하기

`let`의 기본 형태는 다음과 같습니다.

```lisp
(let ((변수1 초기값1)
      (변수2 초기값2)
      ...)
  본문1
  본문2
  ...)
```

`let`은 나열된 변수들을 각각의 초기값으로 바인딩한 다음, 본문을 실행합니다. 본문의 마지막 식의 값이 전체 `let` 식의 값이 됩니다. 앞의 `빗변` 함수를 고쳐 써 봅시다.

```lisp
* (defun 빗변 (a b)
    (let ((a제곱 (* a a))
          (b제곱 (* b b)))
      (sqrt (+ a제곱 b제곱))))
빗변

* (빗변 3 4)
5.0
```

`a제곱`과 `b제곱`이라는 이름 덕분에 마지막 줄 `(sqrt (+ a제곱 b제곱))`을 읽으면 "제곱의 합의 제곱근"이라는 의미가 바로 드러납니다. 계산 결과에 이름을 붙이는 것만으로 코드의 의도가 훨씬 잘 전달됩니다.

`let`으로 바인딩한 변수는 초기값을 생략할 수도 있으며, 이 경우 `nil`로 초기화됩니다.

```lisp
* (let ((결과))
    결과)
NIL
```

또한 여러 변수를 바인딩할 때, 변수 하나만 있고 초기값이 없다면 괄호를 생략하고 변수 이름만 적어도 됩니다.

```lisp
* (let (x (y 10))
    (list x y))
(NIL 10)
```

## let의 중요한 규칙: 초기값은 "동시에" 평가된다

`let`에서 가장 헷갈리기 쉬운 부분이자 반드시 짚고 넘어가야 할 규칙이 있습니다. `let`의 각 초기값 식은 **바깥쪽 환경을 기준으로 평가**되며, 서로를 참조할 수 없습니다. 즉 먼저 나온 바인딩이 아직 본문 안에서는 유효하지만, 다른 초기값을 계산하는 시점에는 아직 존재하지 않는 것처럼 취급됩니다.

다음 예를 보면 이 규칙이 왜 문제가 되는지 알 수 있습니다.

```lisp
* (let ((x 10))
    (let ((x 1)
          (y (+ x 1)))
      (list x y)))
```

바깥쪽 `x`는 10입니다. 안쪽 `let`에서 `x`를 1로 새로 바인딩하려 하고, 동시에 `y`를 `(+ x 1)`로 바인딩하려 합니다. 이때 `y`를 계산하는 `x`는 안쪽에서 새로 바인딩되는 1이 아니라 **바깥쪽의 10**을 가리킵니다.

```lisp
* (list x y)
(1 11)
```

즉 `y`는 `(+ 10 1)`, 곧 11이 됩니다. 같은 `let` 블록 안에서 나중에 나온 변수가 앞에서 정의한 변수를 참조하고 싶어도 `let`은 이를 허용하지 않는 것입니다. 이런 동작 방식은 마치 여러 대입을 "동시에" 수행하는 것과 비슷합니다. 두 변수의 값을 맞바꾸는 다음 코드를 보면 이 성질이 오히려 유용하다는 것도 알 수 있습니다.

```lisp
* (let ((a 1) (b 2)))
* (defparameter *a* 1)
*A*
* (defparameter *b* 2)
*B*
* (let ((*a* *b*) (*b* *a*))
    (format t "let 안: a=~A, b=~A~%" *a* *b*))
let 안: a=2, b=1
NIL
```

`*a*`와 `*b*`를 별도의 임시 변수 없이 맞바꿀 수 있는 것은 두 초기값이 모두 "이전 값"을 기준으로 동시에 평가되기 때문입니다.

## let*: 앞서 바인딩한 변수를 참조하고 싶을 때

하지만 대부분의 경우 우리가 원하는 것은 정반대입니다. 앞에서 계산한 값을 바탕으로 다음 값을 계산하고 싶은 경우가 훨씬 흔합니다. 이때 쓰는 것이 `let*`입니다. `let*`는 바인딩을 **순서대로 하나씩** 처리하며, 각 초기값 식은 그 앞에서 이미 바인딩된 변수를 참조할 수 있습니다.

```lisp
* (let* ((x 10)
         (y (+ x 1))
         (z (* y 2)))
    (list x y z))
(10 11 22)
```

`y`는 방금 바인딩된 `x`(10)를 사용해 11이 되고, `z`는 방금 바인딩된 `y`(11)를 사용해 22가 됩니다. `let`이었다면 `y`와 `z`를 계산할 때 `x`와 `y`가 아직 정의되지 않았다는 오류가 발생했을 것입니다.

원기둥의 부피를 구하는 예를 봅시다. 반지름으로부터 밑면 넓이를 구하고, 밑면 넓이로부터 부피를 구하는 단계적 계산에 `let*`가 자연스럽게 어울립니다.

```lisp
* (defun 원기둥-부피 (반지름 높이)
    (let* ((밑면넓이 (* pi 반지름 반지름))
           (부피 (* 밑면넓이 높이)))
      부피))
원기둥-부피

* (원기둥-부피 2 5)
62.83185307179586
```

## let과 let* 중 무엇을 쓸 것인가

간단한 기준이 있습니다. **바인딩하는 변수들이 서로 독립적이라면 `let`을, 뒤의 변수가 앞의 변수를 필요로 한다면 `let*`를 사용**하면 됩니다. `let`을 쓸 수 있는 상황에서 굳이 `let*`를 써도 결과는 같지만(뒤의 변수가 앞의 변수를 참조하지 않으니까요), 코드를 읽는 사람에게 "이 변수들은 서로 의존 관계가 없다"는 신호를 주고 싶다면 `let`을 쓰는 편이 의도를 더 잘 전달합니다.

```lisp
* ;; 서로 독립적인 값이므로 let이 자연스럽다
  (let ((이름 "홍길동")
        (나이 30))
    (format t "~A님은 ~A세입니다.~%" 이름 나이))
홍길동님은 30세입니다.
NIL
```

## 지역 바인딩과 스코프

`let`(또는 `let*`)로 만든 변수는 그 `let` 식의 **본문 안에서만** 유효합니다. 이렇게 특정 범위 안에서만 이름이 의미를 갖는 것을 스코프(scope)라고 부릅니다. `let` 식을 벗어나면 그 변수는 더 이상 존재하지 않습니다.

```lisp
* (let ((비밀 42))
    (* 비밀 2))
84

* 비밀

debugger invoked on a UNBOUND-VARIABLE ...
```

함수의 매개변수도 사실 같은 원리로 동작합니다. 함수를 호출할 때 인자가 매개변수에 바인딩되고, 그 바인딩은 함수 본문이 끝나면 사라집니다. `let`은 이 원리를 함수 본문 "안"에서, 원할 때 원하는 곳에 자유롭게 적용할 수 있게 해 주는 도구인 셈입니다.

`let`은 중첩해서 쓸 수도 있습니다. 안쪽 `let`에서 바깥쪽 `let`과 같은 이름의 변수를 다시 바인딩하면, 안쪽 스코프 안에서는 안쪽 변수가 바깥쪽 변수를 가립니다(shadowing).

```lisp
* (let ((x 1))
    (let ((x 2))
      (format t "안쪽 x: ~A~%" x))
    (format t "바깥쪽 x: ~A~%" x))
안쪽 x: 2
바깥쪽 x: 1
NIL
```

안쪽 `let`이 끝나는 순간 안쪽 `x`는 사라지고, 바깥쪽 `x`는 처음 값 그대로 남아 있습니다. 각 `let`이 독립된 스코프를 형성한다는 점을 잘 보여주는 예입니다.

## 함수와 let의 조합

`let`은 함수 정의 안에서 특히 자주 쓰입니다. 여러 개의 매개변수를 받아 복잡한 계산을 하는 함수라면, 중간 결과에 이름을 붙여 단계를 나누는 것이 가독성에 큰 도움이 됩니다.

```lisp
* (defun bmi-판정 (몸무게 키)
    (let* ((키미터 (/ 키 100.0))
           (bmi (/ 몸무게 (* 키미터 키미터))))
      (cond ((< bmi 18.5) (list bmi "저체중"))
            ((< bmi 25) (list bmi "정상"))
            ((< bmi 30) (list bmi "과체중"))
            (t (list bmi "비만")))))
bmi-판정

* (bmi-판정 70 175)
(22.857142857142858 "정상")
```

몸무게와 키라는 두 매개변수로부터 `키미터`와 `bmi`라는 지역 변수를 차례로 계산하고, 마지막으로 5장에서 배운 `cond`로 분기하는 구조입니다. 함수 정의, 지역 바인딩, 조건문이 자연스럽게 어우러진 모습을 볼 수 있습니다.

## 앞으로의 이야기: 클로저의 씨앗

지금까지 살펴본 `let`은 값을 계산하고 나면 그 자리에서 스코프가 끝나는, 다소 "일회성"의 지역 바인딩이었습니다. 그런데 만약 함수 안에서 `let`으로 변수를 만들고, 그 변수를 사용하는 함수를 다시 만들어서 바깥으로 반환한다면 어떻게 될까요? `let`으로 만든 변수의 생명이 그 함수가 반환된 뒤에도 계속 이어질 수 있을까요?

정답은 "그렇다"입니다. 이렇게 자신을 둘러싼 환경의 변수를 "기억하는" 함수를 클로저(closure)라고 부르며, 10장 "클로저와 렉시컬 스코프"에서 본격적으로 다룰 주제입니다. 지금 단계에서는 `let`이 단순히 "임시 변수를 만드는 문법"에 그치지 않고, Lisp의 스코프 규칙을 이해하는 출발점이라는 점만 기억해 두면 충분합니다.

## 요약

- `let`은 `(let ((변수 초기값) ...) 본문...)` 형태로 여러 변수를 한꺼번에 바인딩하며, 계산 중간 결과에 이름을 붙여 코드를 읽기 쉽게 만들어 준다.
- `let`의 모든 초기값 식은 바깥쪽 환경을 기준으로 동시에 평가되므로, 같은 `let` 안에서 나중 변수가 앞선 변수를 참조할 수 없다.
- `let*`는 바인딩을 순서대로 처리하여, 뒤의 초기값 식이 앞서 바인딩된 변수를 참조할 수 있게 해 준다.
- 서로 독립적인 값은 `let`으로, 단계적으로 의존하는 계산은 `let*`로 표현하면 의도가 잘 드러난다.
- `let`이 만든 지역 바인딩은 그 본문 안에서만 유효한 스코프를 형성하며, 중첩된 `let`은 같은 이름의 바깥쪽 변수를 가릴 수 있다.
- 이 스코프 규칙은 10장에서 배울 클로저를 이해하기 위한 토대가 된다.

## 연습문제

1. 세 변수 `a`, `b`, `c`를 각각 1, 2, 3으로 바인딩하고 그 합을 반환하는 식을 `let`으로 작성하세요.
2. 반지름을 매개변수로 받아 원의 넓이와 둘레를 각각 지역 변수로 계산한 뒤, `(넓이 둘레)` 리스트로 반환하는 함수를 `let`을 사용해 작성하세요.
3. `let*`를 사용해, 정수 `n`을 받아 `n`의 제곱을 `제곱`이라는 변수에, `제곱`에 1을 더한 값을 `결과`라는 변수에 바인딩한 뒤 `결과`를 반환하는 함수를 작성하세요. 같은 코드를 `let`으로 바꾸면 왜 동작하지 않는지 설명해 보세요.
4. 다음 코드의 실행 결과를 예측한 뒤 REPL에서 확인하세요. 왜 그런 결과가 나오는지 스코프 관점에서 설명하세요.
   ```lisp
   (let ((x 5))
     (let ((y (+ x 1)))
       (let ((x 100))
         (list x y))))
   ```
5. 두 개의 지역 변수를 사용해 두 수 `m`, `n`을 인자로 받아 더 큰 값과 더 작은 값을 각각 `큰값`, `작은값`에 바인딩한 후 `(list 큰값 작은값)`을 반환하는 함수를 작성하세요. `let`과 `let*` 중 어느 쪽이 더 적절한지 근거를 들어 설명하세요.
