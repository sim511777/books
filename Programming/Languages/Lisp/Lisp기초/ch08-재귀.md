# 8장. 재귀

지금까지 4장에서 함수를 정의하는 방법을, 7장에서 리스트가 cons 셀의 사슬로 이루어져 있다는 것을 배웠습니다. 이번 장에서는 이 두 지식을 합쳐서, 리스트를 처음부터 끝까지 순회하며 무언가를 계산하는 함수를 직접 만들어 봅니다. 그런데 여기서 자연스럽게 떠오르는 질문이 있습니다. 다른 언어에서 흔히 쓰는 `for` 루프는 왜 안 쓰는 걸까요?

## Common Lisp에는 전통적인 for 루프가 없다

C나 Java, Python에 익숙한 사람이라면 리스트를 순회할 때 반사적으로 `for (int i = 0; i < n; i++)` 같은 구문을 떠올릴 것입니다. 그런데 Common Lisp의 뿌리는 그런 명령형 반복문이 아니라 함수 정의와 함수 호출입니다. 물론 Common Lisp에도 `loop`나 `dotimes`, `dolist` 같은 강력한 반복 매크로들이 있습니다. 이 도구들은 17장에서 제대로 다룰 예정입니다.

하지만 17장까지 가기 전에, Lisp이 반복을 표현하는 가장 근본적인 방법을 먼저 이해하고 넘어가는 것이 좋습니다. 그것이 바로 **재귀(recursion)**입니다. 재귀는 단순히 "루프 대신 쓰는 트릭"이 아니라, 리스트라는 자료구조 자체의 정의와 정확히 맞아떨어지는 자연스러운 접근법입니다. 7장에서 본 것처럼 리스트는 "원소 하나 + 나머지 리스트"로 이루어진 구조이고, 나머지 리스트도 다시 "원소 하나 + 나머지 리스트"입니다. 이렇게 자기 자신과 같은 모양이 계속 반복되는 정의를 다루기에, 자기 자신을 다시 호출하는 재귀 함수보다 더 자연스러운 도구는 없습니다.

## 기저 조건과 재귀 단계

재귀 함수는 항상 두 부분으로 나뉩니다.

- **기저 조건(base case)**: 더 이상 쪼갤 수 없는 가장 단순한 입력에 대해 답을 바로 내어주는 부분입니다. 리스트의 경우 보통 "빈 리스트일 때"가 기저 조건이 됩니다.
- **재귀 단계(recursive case)**: 문제를 조금 더 작은 문제로 줄인 뒤, 그 작은 문제를 자기 자신에게 다시 맡기는 부분입니다. 리스트의 경우 "첫 원소를 처리하고, 나머지(cdr)에 대해서는 같은 함수를 다시 호출"하는 형태가 됩니다.

이 두 조각이 없으면 재귀 함수는 절대 멈추지 않습니다. 기저 조건이 없다면 함수는 영원히 자신을 호출하다가 결국 스택이 넘쳐서 에러를 냅니다.

```lisp
* (defun 무한루프 (n)
    (+ n (무한루프 (+ n 1))))   ; 절대 멈추지 않는 잘못된 예
```

위 함수는 절대로 호출하지 마세요. 기저 조건이 없어서 스택 오버플로우가 날 때까지 계속 자신을 호출합니다. 재귀를 작성할 때는 항상 "언제 멈출 것인가"를 가장 먼저 정해야 합니다.

## 첫 번째 예제: 리스트의 합 구하기

리스트에 담긴 숫자들을 모두 더하는 함수를 직접 만들어 보겠습니다. Common Lisp에는 이미 이런 일을 해주는 함수가 있지만(9장에서 `reduce`로 다시 보게 됩니다), 여기서는 재귀의 감각을 익히기 위해 손수 구현해봅니다.

리스트의 합을 구하는 문제를 재귀적으로 쪼개봅시다.

- 빈 리스트의 합은 0이다. (기저 조건)
- 비어 있지 않은 리스트의 합은, 첫 번째 원소(car)에 나머지 리스트(cdr)의 합을 더한 것이다. (재귀 단계)

이 정의를 그대로 코드로 옮기면 됩니다.

```lisp
(defun 리스트합 (lst)
  (if (null lst)
      0
      (+ (car lst) (리스트합 (cdr lst)))))
```

REPL에서 확인해봅시다.

```lisp
* (리스트합 '(1 2 3 4 5))
15
* (리스트합 nil)
0
* (리스트합 '(10))
10
```

`(리스트합 '(1 2 3))`이 실제로 어떻게 계산되는지 하나씩 풀어써 보면 재귀의 흐름이 눈에 보입니다.

```
(리스트합 '(1 2 3))
= (+ 1 (리스트합 '(2 3)))
= (+ 1 (+ 2 (리스트합 '(3))))
= (+ 1 (+ 2 (+ 3 (리스트합 nil))))
= (+ 1 (+ 2 (+ 3 0)))
= (+ 1 (+ 2 3))
= (+ 1 5)
= 6
```

함수는 리스트가 빈 상태에 도달할 때까지 계속 자기 자신을 호출하며 "덧셈을 나중에 하기로 미루어 쌓아두다가", 기저 조건에 닿는 순간부터 그 쌓인 덧셈들을 안쪽에서부터 바깥쪽으로 실제로 계산해 나갑니다.

물론 표준 라이브러리를 쓰면 이렇게 짧게 끝낼 수도 있습니다.

```lisp
* (apply #'+ '(1 2 3 4 5))
15
```

하지만 지금은 `apply`가 내부적으로 하는 일을 우리 손으로 직접 재현해보는 것이 목적입니다.

## 두 번째 예제: 리스트 길이 직접 구현하기

이번에는 7장에서 이미 써본 `length` 함수를 재귀로 직접 만들어 보겠습니다.

- 빈 리스트의 길이는 0이다. (기저 조건)
- 비어 있지 않은 리스트의 길이는, 1(첫 번째 원소 자신)에 나머지 리스트의 길이를 더한 것이다. (재귀 단계)

```lisp
(defun 내길이 (lst)
  (if (null lst)
      0
      (+ 1 (내길이 (cdr lst)))))
```

```lisp
* (내길이 '(a b c d))
4
* (내길이 nil)
0
* (내길이 (list 1 2 3 4 5 6 7))
7
```

`리스트합`과 `내길이`는 구조가 거의 똑같다는 것을 눈치챘을 것입니다. 둘 다 "빈 리스트면 특정 값을 반환하고, 아니면 car를 가지고 무언가를 한 다음 cdr에 대해 재귀 호출한 결과와 합친다"는 패턴을 따릅니다. 이 패턴은 리스트를 다루는 재귀 함수에서 계속 반복해서 나타납니다. 이 패턴을 함수로 추상화한 것이 바로 9장에서 배울 `reduce`, `mapcar` 같은 고차 함수들입니다. 즉 지금 손으로 짜본 재귀는 나중에 배울 고차 함수의 속마음을 미리 들여다본 셈입니다.

## 꼬리 재귀

위에서 작성한 `리스트합`을 다시 보면, 재귀 호출의 결과를 받아온 다음 여전히 `(+ (car lst) ...)`라는 계산을 남겨두고 있습니다. 즉 재귀 호출이 함수의 "마지막 동작"이 아닙니다. 이런 방식은 재귀 호출이 깊어질수록 "나중에 처리할 덧셈들"을 계속 스택에 쌓아두어야 합니다.

이와 달리, 재귀 호출이 함수에서 실행되는 **맨 마지막 동작**이고 그 결과를 그대로 반환하는 형태를 **꼬리 재귀(tail recursion)**라고 부릅니다. 꼬리 재귀는 이전 계산을 스택에 쌓아둘 필요가 없기 때문에, 많은 처리 환경에서 일반 반복문과 비슷한 효율로 실행될 수 있습니다.

`리스트합`을 꼬리 재귀 형태로 바꿔봅시다. 핵심 아이디어는 "지금까지 누적된 합"을 인자로 함께 들고 다니는 것입니다.

```lisp
(defun 리스트합-꼬리 (lst &optional (누적 0))
  (if (null lst)
      누적
      (리스트합-꼬리 (cdr lst) (+ 누적 (car lst)))))
```

`&optional`은 인자를 생략할 수 있게 해주는 문법으로, 4장에서 이미 다룬 내용입니다. 사용하는 쪽에서는 두 번째 인자를 신경 쓸 필요 없이 그냥 호출하면 됩니다.

```lisp
* (리스트합-꼬리 '(1 2 3 4 5))
15
```

이번에는 계산 과정을 풀어써 봅시다.

```
(리스트합-꼬리 '(1 2 3) 0)
= (리스트합-꼬리 '(2 3) 1)
= (리스트합-꼬리 '(3) 3)
= (리스트합-꼬리 nil 6)
= 6
```

앞선 버전과 비교해보면 차이가 분명합니다. 이번에는 함수를 호출할 때마다 "덧셈을 나중으로 미루는" 것이 아니라, 그 자리에서 바로 계산을 끝내고 결과를 다음 호출에 넘겨줍니다. 재귀 호출 `(리스트합-꼬리 (cdr lst) (+ 누적 (car lst)))`이 `if`의 마지막 가지에서 그대로 반환되고, 그 뒤에 덧붙는 계산이 전혀 없다는 점을 확인하세요. 이것이 꼬리 재귀의 핵심입니다.

`내길이`도 같은 방식으로 바꿀 수 있습니다.

```lisp
(defun 내길이-꼬리 (lst &optional (개수 0))
  (if (null lst)
      개수
      (내길이-꼬리 (cdr lst) (+ 개수 1))))
```

```lisp
* (내길이-꼬리 '(a b c d e))
5
```

## 요약

이번 장에서는 Common Lisp에서 리스트를 순회하는 가장 근본적인 방법인 재귀를 배웠습니다. 전통적인 for 루프가 없는 대신(17장에서 다룰 반복 매크로가 있긴 하지만), 재귀는 "원소 하나 + 나머지 리스트"라는 리스트 자체의 구조와 정확히 맞아떨어지는 자연스러운 도구입니다. 재귀 함수는 항상 더 이상 쪼갤 수 없는 기저 조건과, 문제를 작게 줄여 자기 자신에게 넘기는 재귀 단계로 이루어집니다. 우리는 `리스트합`과 `내길이`를 직접 구현하며 이 구조를 몸에 익혔고, 재귀 호출을 함수의 마지막 동작으로 만들어 누적값을 인자로 들고 다니는 꼬리 재귀 기법도 살펴보았습니다. 이 장에서 손으로 짠 패턴들은 9장의 고차 함수, 10장의 클로저를 이해하는 밑거름이 되고, 더 편리한 반복 도구를 원한다면 17장에서 그 답을 찾을 수 있습니다.
