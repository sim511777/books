# 5장. 조건문

---

프로그램이 항상 같은 일만 반복한다면 굳이 컴퓨터가 필요하지 않을 것입니다. 입력값이나 상황에 따라 다른 길을 선택하는 능력, 그것이 바로 조건문이 존재하는 이유입니다. 이번 장에서는 Common Lisp가 참과 거짓을 어떻게 판단하는지부터 시작해서, `if`, `cond`, `when`, `unless`라는 네 가지 조건 표현식을 살펴봅니다.

## 참과 거짓: nil만이 거짓이다

다른 언어에 익숙한 독자라면 이 사실을 가장 먼저 마음에 새겨야 합니다. Common Lisp에서는 **`nil`만 거짓이고, 그 밖의 모든 값은 참**으로 취급됩니다. 숫자 `0`도, 빈 문자열 `""`도 참입니다. 이는 파이썬이나 자바스크립트처럼 "falsy한 값"이 여러 개 있는 언어와 크게 다른 점입니다.

```lisp
* (if 0 "참이다" "거짓이다")
"참이다"

* (if "" "참이다" "거짓이다")
"참이다"

* (if nil "참이다" "거짓이다")
"거짓이다"
```

그렇다면 참을 명시적으로 나타내고 싶을 때는 무엇을 쓸까요? 관례적으로 `t`를 사용합니다. `t`는 특별한 예약어가 아니라 그냥 자기 자신을 값으로 갖는 심볼이지만, "참"을 표현하는 관용구로 널리 쓰입니다.

```lisp
* (if t "참이다" "거짓이다")
"참이다"
```

또 하나 기억할 점은 빈 리스트 `()`와 `nil`이 Common Lisp에서 **같은 것**이라는 사실입니다. 즉 `()`도 거짓입니다.

```lisp
* (if '() "참이다" "거짓이다")
"거짓이다"

* (eq nil '())
T
```

이 규칙 하나만 확실히 알아도 이번 장의 절반은 이해한 셈입니다.

## if: 가장 단순한 갈림길

`if`는 조건이 하나뿐인 가장 기본적인 분기 형식입니다. 문법은 다음과 같습니다.

```lisp
(if 조건식 참일-때-실행할-식 거짓일-때-실행할-식)
```

3장에서 이미 몇 차례 등장했지만, 여기서 제대로 짚고 넘어갑시다.

```lisp
* (if (> 10 5) "10이 더 크다" "5가 더 크다")
"10이 더 크다"

* (defun 짝수인가 (n)
    (if (= (mod n 2) 0)
        "짝수"
        "홀수"))
짝수인가

* (짝수인가 7)
"홀수"
* (짝수인가 12)
"짝수"
```

`if`에서 주의할 점은 세 번째 자리(거짓일 때 실행할 식)가 **선택 사항**이라는 것입니다. 생략하면 조건이 거짓일 때 `nil`을 반환합니다.

```lisp
* (if (< 5 3) "5가 작다")
NIL
```

또한 `if`의 두 번째와 세 번째 자리에는 오직 **하나의 식**만 올 수 있습니다. "조건이 참이면 이것도 하고 저것도 하고 싶다"는 상황이라면 `progn`으로 여러 식을 하나로 묶어야 합니다.

```lisp
* (defun 인사하기 (이름)
    (if (string= 이름 "관리자")
        (progn
          (format t "환영합니다, 관리자님.~%")
          (format t "권한 목록을 불러옵니다.~%"))
        (format t "환영합니다, ~A님.~%" 이름)))
인사하기

* (인사하기 "관리자")
환영합니다, 관리자님.
권한 목록을 불러옵니다.
NIL
```

여러 식을 묶어야 하는 상황이 자주 생긴다면, 사실 이는 `when`이나 `unless`를 쓰라는 신호일 수 있습니다. 곧 살펴보겠습니다.

## cond: 여러 조건을 순서대로 검사한다

조건이 두세 개를 넘어가면 `if`를 중첩해서 쓰는 코드는 금세 읽기 어려워집니다.

```lisp
* (defun 학점 (점수)
    (if (>= 점수 90)
        "A"
        (if (>= 점수 80)
            "B"
            (if (>= 점수 70)
                "C"
                "F"))))
학점
```

동작은 하지만 괄호가 계단처럼 깊어지고, 조건이 하나 더 늘어날 때마다 들여쓰기가 오른쪽으로 밀려납니다. 이럴 때 쓰는 것이 `cond`입니다. `cond`는 `(조건 결과)` 형태의 절(clause)을 여러 개 나열하고, 위에서부터 순서대로 조건을 검사해서 **처음으로 참이 되는 절**의 결과를 반환합니다.

```lisp
(cond (조건1 결과1)
      (조건2 결과2)
      (조건3 결과3)
      ...)
```

앞의 `학점` 함수를 `cond`로 다시 쓰면 다음과 같습니다.

```lisp
* (defun 학점 (점수)
    (cond ((>= 점수 90) "A")
          ((>= 점수 80) "B")
          ((>= 점수 70) "C")
          (t "F")))
학점

* (학점 95)
"A"
* (학점 72)
"C"
* (학점 40)
"F"
```

마지막 절 `(t "F")`가 눈에 띌 것입니다. `t`는 언제나 참이므로, 앞의 모든 조건에 해당하지 않는 경우를 처리하는 "그 외의 경우(default)" 절 역할을 합니다. 다른 언어의 `switch`문에서 `default`에 해당한다고 생각하면 됩니다. 만약 어떤 절도 참이 되지 않고 `t` 절도 없다면 `cond`는 `nil`을 반환합니다.

`cond`의 각 절은 결과 부분에 여러 식을 나열할 수 있다는 점도 `if`와 다릅니다. `progn`으로 감쌀 필요 없이 그냥 나열하면 순서대로 실행되고 마지막 식의 값이 절의 값이 됩니다.

```lisp
* (defun 상태-보고 (온도)
    (cond ((> 온도 38)
           (format t "위험 수준입니다.~%")
           "고온 경보")
          ((> 온도 36.5)
           "정상")
          (t
           (format t "저체온 주의가 필요합니다.~%")
           "저온 경보")))
상태-보고

* (상태-보고 39)
위험 수준입니다.
"고온 경보"
```

또 하나 알아두면 유용한 형태는 절이 조건 하나만 갖고 결과가 없는 경우입니다. 이때는 조건식 자체의 값이 반환됩니다.

```lisp
* (defun 첫-참값 (a b)
    (cond (a)
          (b)
          (t "둘 다 nil")))
첫-참값

* (첫-참값 nil 42)
42
```

## when과 unless: 단일 분기를 위한 축약형

앞서 `인사하기` 예제에서 조건이 참일 때만 여러 일을 처리하기 위해 `progn`을 썼습니다. 그런데 "거짓일 때는 아무것도 안 한다"는 패턴은 매우 흔해서, Common Lisp는 이를 위한 전용 매크로 `when`과 `unless`를 제공합니다.

`when`은 "조건이 참일 때만" 본문을 실행합니다.

```lisp
(when 조건식
  본문1
  본문2
  ...)
```

`인사하기`를 `when`으로 다시 써 봅시다.

```lisp
* (defun 인사하기 (이름)
    (when (string= 이름 "관리자")
      (format t "환영합니다, 관리자님.~%")
      (format t "권한 목록을 불러옵니다.~%")))
인사하기

* (인사하기 "관리자")
환영합니다, 관리자님.
권한 목록을 불러옵니다.
NIL

* (인사하기 "손님")
NIL
```

`progn`이 사라지고 본문을 그냥 나열할 수 있어 훨씬 깔끔합니다. `when`은 조건이 거짓이면 아무 일도 하지 않고 `nil`을 반환합니다.

`unless`는 `when`의 반대입니다. "조건이 **거짓**일 때만" 본문을 실행합니다.

```lisp
(unless 조건식
  본문1
  본문2
  ...)
```

```lisp
* (defun 재고-확인 (수량)
    (unless (> 수량 0)
      (format t "재고가 없습니다. 발주가 필요합니다.~%")))
재고-확인

* (재고-확인 0)
재고가 없습니다. 발주가 필요합니다.
NIL

* (재고-확인 5)
NIL
```

`(unless 조건 본문)`은 `(when (not 조건) 본문)`과 완전히 같은 의미입니다. 둘 중 어느 것을 쓸지는 "긍정문으로 읽었을 때 더 자연스러운 쪽"을 고르면 됩니다. "관리자라면 환영 인사를 한다"는 `when`이, "재고가 없지 않다면 아무 말도 안 한다"보다는 "재고가 없다면 경고한다"는 `unless`가 더 자연스럽게 읽힙니다.

## 어떤 것을 언제 쓸까

정리하면 다음과 같은 기준으로 고르면 됩니다.

- 참/거짓 두 갈래 모두에서 값을 만들어내야 한다 → `if` (또는 조건이 여러 개면 `cond`)
- 조건이 세 개 이상이고 각각 다른 결과를 내야 한다 → `cond`
- 조건이 참일 때만 어떤 일을 하고, 거짓이면 아무것도 안 해도 된다 → `when`
- 조건이 거짓일 때만 어떤 일을 하고, 참이면 아무것도 안 해도 된다 → `unless`

사실 `when`과 `unless`, 심지어 `cond`까지도 내부적으로는 `if`를 조합해 만들어진 매크로입니다. 매크로가 정확히 무엇이고 어떻게 이런 것을 직접 만들 수 있는지는 11장 "매크로 기초"에서 다시 다룹니다. 지금은 "같은 일을 하더라도 상황에 맞는 도구를 쓰면 코드가 더 읽기 쉬워진다"는 감각만 챙겨가면 충분합니다.

## 요약

- Common Lisp에서는 `nil`(그리고 이와 동일한 빈 리스트 `()`)만 거짓이며, 그 밖의 모든 값은 참으로 취급된다.
- `if`는 `(if 조건 참-결과 거짓-결과)` 형태로 하나의 조건을 검사하며, 각 자리에는 식이 하나씩만 올 수 있다. 여러 식을 실행하려면 `progn`으로 묶는다.
- `cond`는 `(조건 결과...)` 절을 순서대로 검사해 처음 참이 되는 절의 결과를 반환하며, `(t ...)` 절로 기본 분기를 만든다.
- `when`은 조건이 참일 때만, `unless`는 조건이 거짓일 때만 여러 식으로 이루어진 본문을 실행하는 축약형이다.
- 값이 필요 없는 단순 분기에는 `when`/`unless`가, 두 갈래 모두 값을 내야 할 때는 `if`나 `cond`가 더 자연스럽다.

## 연습문제

1. 정수 하나를 받아 양수면 `"양수"`, 음수면 `"음수"`, 0이면 `"영"`을 반환하는 함수 `부호-판별`을 `cond`로 작성하세요.
2. 위의 `부호-판별`을 `if`만 사용해 다시 작성해 보고, 두 버전 중 어느 쪽이 더 읽기 쉬운지 생각해 보세요.
3. 리스트를 인자로 받아, 리스트가 비어 있지 않으면 `(format t "요소 개수: ~A~%" (length 리스트))`를 실행하는 함수를 `when`을 사용해 작성하세요.
4. 숫자를 인자로 받아, 100보다 크지 **않으면** `"허용 범위 내"`를 출력하는 함수를 `unless`로 작성하세요.
