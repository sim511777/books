# 3장. VS Code 설치와 C/C++ 확장

[◀ 이전: 2장. GCC 설치와 커맨드라인 컴파일](ch02-GCC설치와커맨드라인컴파일.md) | [📖 목차](00-목차.md) | [다음: 4장. VS Code로 빌드하고 디버깅하기 ▶](ch04-VSCode로빌드하고디버깅하기.md)


2장에서는 GCC를 설치하고, 터미널에서 `g++` 명령 하나로 소스 코드를 실행 파일로 바꾸는 과정을 직접 손으로 해보았습니다. 이 과정 자체는 앞으로도 크게 달라지지 않습니다. 컴파일러는 여전히 GCC가 맡고, 소스 코드를 기계어로 바꾸는 일도 여전히 `g++`가 합니다. 달라지는 것은 그 명령을 누가, 어떻게 실행시켜 주느냐입니다. 이 장부터는 매번 터미널 창을 열어 긴 명령을 손으로 치는 대신, 편집기 하나에서 코드 작성·빌드·디버깅을 모두 처리할 수 있는 환경을 갖춥니다. 그 편집기가 바로 Visual Studio Code, 줄여서 VS Code입니다.

## VS Code란 무엇인가

VS Code는 마이크로소프트가 만들어 무료로 배포하는 소스 코드 편집기입니다. "IDE"라는 표현을 쓰지 않고 굳이 "편집기"라고 부르는 데는 이유가 있습니다. Visual Studio나 CLion 같은 전통적인 통합 개발 환경(IDE)은 컴파일러, 디버거, 프로젝트 관리 기능까지 하나의 거대한 프로그램 안에 묶어서 설치합니다. 반면 VS Code 자체는 텍스트를 편집하고, 화면을 구성하고, 확장을 실행하는 뼈대만 제공합니다. 컴파일러도, 디버거도, 언어별 자동완성 기능도 VS Code 안에 내장되어 있지 않습니다. 이 모든 기능은 확장(extension)이라는 형태로 나중에 붙습니다.

이런 구조 덕분에 VS Code 하나로 C++뿐 아니라 Python, JavaScript, Rust, Go 등 거의 모든 언어를 다룰 수 있습니다. 필요한 확장만 설치하면 되기 때문입니다. 이 강좌에서는 C++ 개발에 필요한 확장만 골라서 설치하고 설정할 것입니다. 즉 지금부터 만드는 환경은 "VS Code라는 범용 편집기 위에 C++ 툴체인을 연결해 놓은 상태"라고 이해하면 정확합니다.

VS Code는 Windows, macOS, Linux를 모두 지원하며, 설정 파일과 단축키 체계가 세 플랫폼에서 거의 동일합니다. 이 책은 Windows 환경을 기준으로 설명하지만, 다른 운영체제를 쓰더라도 이 장과 4장에서 다루는 내용은 그대로 적용됩니다.

## VS Code 설치하기

VS Code는 공식 웹사이트(code.visualstudio.com)에서 내려받습니다. Windows용 설치 파일은 "User Installer"와 "System Installer" 두 종류로 나뉘는데, 일반적인 개인 PC라면 별도의 관리자 권한 없이 설치할 수 있는 User Installer를 선택하는 편이 무난합니다.

설치 프로그램을 실행하면 몇 가지 옵션 화면이 나옵니다. 이 중 눈여겨볼 항목이 두 가지 있습니다.

- **PATH에 추가(Add to PATH)**: 이 옵션을 체크하면 터미널에서 `code`라는 명령으로 VS Code를 바로 실행할 수 있습니다. 예를 들어 어떤 폴더에서 `code .`를 입력하면 그 폴더가 VS Code로 열립니다. 이후 실습에서 자주 사용하게 되므로 체크해 두는 것을 권장합니다.
- **탐색기 컨텍스트 메뉴에 "Code로 열기" 추가**: 파일 탐색기에서 폴더를 마우스 우클릭했을 때 VS Code로 바로 열 수 있는 메뉴를 추가하는 옵션입니다. 편의를 위해 함께 체크해 두면 좋습니다.

설치가 끝나고 VS Code를 처음 실행하면 시작 화면(Welcome 탭)이 나타납니다. 이 화면은 언제든 닫아도 되며, 왼쪽 세로로 늘어선 아이콘 모음(액티비티 바)에서 탐색기, 검색, 소스 제어, 실행 및 디버그, 확장 아이콘을 확인할 수 있습니다. 이 장에서는 이 중 탐색기와 확장 아이콘을 주로 사용합니다.

## 확장 마켓플레이스와 C/C++ 확장 설치

VS Code 왼쪽 액티비티 바에서 네모 블록 네 개가 겹쳐진 모양의 아이콘을 클릭하면 확장 뷰가 열립니다. 단축키는 `Ctrl+Shift+X`입니다. 이 화면 위쪽 검색창에 원하는 확장 이름이나 키워드를 입력하면 마켓플레이스에 등록된 확장 목록이 나타납니다.

검색창에 `C++`를 입력해 봅시다. 여러 결과 중에서 게시자(Publisher)가 "Microsoft"로 표시되고 확장 ID가 `ms-vscode.cpptools`인 항목을 찾습니다. 이름은 단순히 "C/C++"로 표시됩니다. 이 확장이 이번 강좌 전체에서 기준으로 삼는 C/C++ 확장입니다. 해당 항목을 클릭한 뒤 나타나는 상세 화면에서 "Install" 버튼을 누르면 설치가 진행됩니다.

C/C++ 확장이 제공하는 기능은 크게 세 가지로 나눌 수 있습니다.

- **IntelliSense**: 코드를 입력하는 동안 자동완성, 함수 시그니처 표시, 정의로 이동 등을 지원합니다. 이 기능이 정확히 동작하려면 컴파일러 정보와 include 경로를 알려주어야 하는데, 그 설정 방법은 5장에서 자세히 다룹니다.
- **디버깅 지원**: GDB나 LLDB, Windows의 Visual Studio 디버거를 VS Code 화면 안에서 조작할 수 있게 해 줍니다. 중단점, 변수 감시, 콜 스택 확인 같은 기능이 여기에 포함되며, 4장에서 직접 사용해 봅니다.
- **코드 서식 및 탐색**: 괄호 짝 맞추기, 코드 서식 정리, 심볼 검색 등 편집 보조 기능을 제공합니다.

참고로 마켓플레이스에는 "C/C++ Extension Pack"이라는 항목도 있습니다. 이는 `ms-vscode.cpptools`를 포함해 CMake Tools(9장에서 다룹니다), 코드 러너 등 여러 확장을 한 번에 묶어 설치해 주는 모음입니다. 지금 단계에서는 `ms-vscode.cpptools` 하나만 설치해도 충분하며, 나머지 확장은 각 장에서 필요할 때 개별적으로 설치하면서 그 역할을 하나씩 이해하는 방식으로 진행하겠습니다.

설치가 끝나면 확장 뷰 왼쪽 목록의 "설치됨(Installed)" 항목에서 C/C++ 확장을 확인할 수 있습니다. 별도의 재시작 안내가 뜨면 안내에 따라 VS Code를 한 번 다시 시작합니다.

## 워크스페이스: 폴더를 연다는 것의 의미

VS Code는 파일 하나만 열어서 편집할 수도 있지만, C++ 프로젝트를 다룰 때는 항상 폴더 단위로 연다고 생각하는 편이 좋습니다. 상단 메뉴에서 `파일 > 폴더 열기`(File > Open Folder)를 선택하거나, 터미널에서 프로젝트 폴더로 이동한 뒤 `code .`를 입력하면 그 폴더가 VS Code의 작업 대상이 됩니다.

이렇게 열린 폴더를 VS Code에서는 워크스페이스(workspace)라고 부릅니다. 워크스페이스라는 개념이 중요한 이유는, VS Code의 많은 설정과 기능이 "지금 열려 있는 폴더" 단위로 동작하기 때문입니다. 빌드 설정, 디버그 설정, 확장이 인식하는 include 경로 등이 모두 이 폴더를 기준으로 저장되고 적용됩니다. 폴더 하나가 곧 하나의 프로젝트라고 생각하면 이해하기 쉽습니다.

간단한 실습으로 워크스페이스 개념을 확인해 봅시다.

```bash
mkdir hello-vscode
cd hello-vscode
code .
```

이 명령을 실행하면 `hello-vscode`라는 빈 폴더가 VS Code로 열립니다. 왼쪽 탐색기 패널에 아직 아무 파일도 없지만, 상단에는 폴더 이름이 워크스페이스 이름으로 표시됩니다. 이 상태에서 탐색기 패널의 "새 파일" 아이콘을 눌러 `main.cpp` 파일을 만들고 2장에서 작성했던 것과 비슷한 간단한 코드를 입력해 봅니다.

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, VS Code!" << std::endl;
    return 0;
}
```

## `.vscode` 폴더: 프로젝트별 설정이 담기는 곳

워크스페이스에 어떤 설정을 저장하면, VS Code는 그 워크스페이스 폴더 안에 `.vscode`라는 숨김 폴더를 만들고 그 안에 설정 파일을 저장합니다. 이 폴더는 지금 당장은 비어 있지만, 4장에서 빌드 태스크와 디버그 설정을 만들면 다음과 같은 파일들이 이 폴더 안에 생깁니다.

- `settings.json`: 이 워크스페이스에만 적용되는 설정
- `tasks.json`: 빌드 등 반복 작업을 정의하는 설정 (4장)
- `launch.json`: 디버거 실행 방법을 정의하는 설정 (4장)
- `c_cpp_properties.json`: IntelliSense가 참조할 컴파일러와 include 경로 정보 (5장)

`.vscode` 폴더가 갖는 가장 중요한 특징은, 이 설정들이 오직 그 폴더(워크스페이스)에서 VS Code를 열었을 때만 적용된다는 점입니다. 다른 프로젝트 폴더를 열면 그 프로젝트의 `.vscode` 폴더에 있는 설정이 적용되고, 지금 만든 `hello-vscode`의 설정과는 서로 영향을 주지 않습니다. 여러 프로젝트를 오가며 작업하더라도 각 프로젝트마다 다른 컴파일러 옵션이나 디버그 설정을 독립적으로 유지할 수 있는 것은 바로 이 구조 덕분입니다.

## workspace 설정과 user 설정의 차이

VS Code의 설정은 크게 두 층으로 나뉩니다.

- **User 설정(사용자 설정)**: 컴퓨터에 로그인한 사용자 전체에 적용되는 설정입니다. 어떤 폴더를 열든 공통으로 적용됩니다. 예를 들어 편집기 글꼴 크기, 테마 색상, 자동 저장 여부처럼 프로젝트와 무관하게 항상 같았으면 하는 설정을 여기에 둡니다.
- **Workspace 설정(작업 영역 설정)**: 지금 열려 있는 폴더에만 적용되는 설정입니다. 이 설정은 앞서 설명한 `.vscode/settings.json` 파일에 저장됩니다. 예를 들어 이 프로젝트에서만 특정 컴파일러 경로를 쓰고 싶다거나, 특정 코드 스타일 규칙을 적용하고 싶을 때 여기에 설정을 둡니다.

두 설정을 여는 방법은 다음과 같습니다. `Ctrl+Shift+P`로 명령 팔레트를 연 뒤 "Preferences: Open User Settings (JSON)"을 입력하면 사용자 설정 파일이 열리고, "Preferences: Open Workspace Settings (JSON)"을 입력하면 현재 워크스페이스의 `.vscode/settings.json`이 열립니다(파일이 없으면 자동으로 생성됩니다).

두 설정에 같은 항목이 존재하면 workspace 설정이 user 설정을 덮어씁니다. 즉 적용 우선순위는 workspace가 더 높습니다. 이런 구조는 실무에서 매우 유용합니다. 예를 들어 개인적으로는 4칸 들여쓰기를 선호해서 user 설정에 넣어 두었더라도, 팀 프로젝트에서 2칸 들여쓰기 규칙을 쓴다면 그 프로젝트의 workspace 설정에만 2칸 규칙을 넣어 두면 됩니다. 다른 프로젝트를 열 때는 여전히 개인 설정인 4칸 들여쓰기가 적용됩니다.

이 강좌에서 다루는 설정, 특히 6장 이후의 CMake 관련 설정이나 10장 이후의 vcpkg 경로 설정은 대부분 workspace 설정으로 다룹니다. 프로젝트마다 사용하는 컴파일러 버전이나 라이브러리 경로가 다를 수 있기 때문에, 이런 정보를 프로젝트 폴더 안에 함께 보관해 두면 나중에 프로젝트를 다른 컴퓨터로 옮기거나 다른 사람과 공유할 때도 설정이 그대로 따라갑니다.

## VS Code에서 GCC 확인하기

이제 VS Code가 2장에서 설치한 GCC를 제대로 인식하는지 확인해 볼 차례입니다. VS Code에는 터미널 패널이 내장되어 있어서, 별도의 프로그램을 열지 않고도 명령을 실행할 수 있습니다. 상단 메뉴에서 `터미널 > 새 터미널`(Terminal > New Terminal)을 선택하거나 단축키 ``Ctrl+` ``(백틱)를 누르면 화면 아래쪽에 터미널 패널이 열립니다.

이 터미널은 운영체제의 실제 셸(Windows라면 PowerShell이나 명령 프롬프트, macOS·Linux라면 bash나 zsh 등)을 그대로 띄운 것입니다. VS Code가 특별한 셸을 흉내 내는 것이 아니라, 실제 시스템 셸을 편집기 안에 통합해서 보여주는 것뿐입니다. 따라서 2장에서 명령 프롬프트나 PowerShell 창에서 실행했던 명령을 이 터미널 패널에서도 똑같이 실행할 수 있습니다.

터미널 패널에 다음 명령을 입력해 봅니다.

```bash
g++ --version
```

2장에서 GCC 설치와 PATH 설정을 올바르게 마쳤다면, 다음과 비슷한 형태로 GCC 버전 정보가 출력됩니다.

```bash
g++ (MinGW-W64 x86_64-ucrt-posix-seh, ...) 13.2.0
Copyright (C) 2023 Free Software Foundation, Inc.
...
```

만약 "g++을(를) 찾을 수 없습니다" 또는 "command not found"와 비슷한 오류가 나온다면, 이는 VS Code나 C/C++ 확장의 문제가 아니라 시스템 PATH에 GCC 경로가 등록되지 않았다는 뜻입니다. VS Code의 터미널은 시스템 PATH를 그대로 상속받기 때문에, 여기서 명령을 찾지 못한다면 일반 명령 프롬프트에서도 마찬가지로 찾지 못할 가능성이 높습니다. 이 경우 2장에서 다룬 PATH 등록 절차를 다시 확인하고, VS Code를 완전히 종료했다가 다시 실행해 봅니다. PATH 환경 변수는 프로그램이 처음 실행될 때 읽어 들이기 때문에, PATH를 변경한 뒤에는 이미 열려 있던 VS Code 창에 곧바로 반영되지 않는 경우가 있습니다.

`g++ --version` 명령이 정상적으로 버전 정보를 출력했다면, VS Code와 GCC를 연결할 준비가 끝난 것입니다. 지금까지는 이 터미널에 직접 `g++ main.cpp -o main.exe`와 같은 명령을 입력해서 빌드해야 했지만, 다음 장에서는 이 반복적인 명령을 VS Code에게 "빌드"라는 하나의 동작으로 등록해 두고 단축키 한 번으로 실행하는 방법을 다룹니다. 나아가 실행 파일을 디버거로 실행해 중단점에서 멈추고 변수 값을 들여다보는 방법까지 이어집니다.

## 요약

- VS Code는 마이크로소프트가 배포하는 무료 편집기로, 자체적으로는 컴파일러나 디버거를 포함하지 않고 확장을 통해 언어별 기능을 갖춘다.
- C++ 개발에는 Microsoft가 게시한 C/C++ 확장(확장 ID `ms-vscode.cpptools`)을 설치한다. 확장 뷰(`Ctrl+Shift+X`)에서 검색해 설치할 수 있다.
- VS Code에서 폴더를 여는 것을 워크스페이스를 연다고 하며, 빌드·디버그·IntelliSense 설정은 대부분 워크스페이스 단위로 관리된다.
- 워크스페이스 설정은 해당 폴더의 `.vscode` 폴더 안 파일(`settings.json`, 이후 장에서 다룰 `tasks.json`, `launch.json`, `c_cpp_properties.json`)에 저장된다.
- User 설정은 컴퓨터 전체에 적용되고, Workspace 설정은 현재 폴더에만 적용되며 동일 항목이 있으면 workspace 설정이 우선한다.
- VS Code에 내장된 터미널 패널은 시스템 셸을 그대로 통합한 것이므로, `g++ --version`을 실행해 GCC 인식 여부를 확인할 수 있다.

## 연습문제

1. 확장 마켓플레이스에서 게시자가 "Microsoft"이고 확장 ID가 `ms-vscode.cpptools`인 확장을 직접 검색해 설치해 보고, 설치된 확장 목록에서 이를 확인하시오.
2. 새 폴더를 만들어 VS Code로 열고(`code .`), 이 폴더가 워크스페이스로 인식되는지 탐색기 패널에서 확인하시오. 이후 이 폴더 안에 `.vscode` 폴더가 언제, 어떤 계기로 생기는지 다음 장 실습을 통해 관찰하시오.
3. 명령 팔레트(`Ctrl+Shift+P`)에서 "Preferences: Open User Settings (JSON)"과 "Preferences: Open Workspace Settings (JSON)"을 각각 열어 두 파일의 저장 위치가 어떻게 다른지 비교하시오.
4. User 설정에 원하는 글꼴 크기(`editor.fontSize`)를 지정한 뒤, 특정 워크스페이스의 Workspace 설정에 다른 글꼴 크기를 지정해 보고 어느 값이 실제로 적용되는지 확인하시오.
5. VS Code 터미널 패널을 열어 `g++ --version`을 실행하고, 출력된 GCC 버전이 2장에서 명령 프롬프트로 확인했던 버전과 일치하는지 비교하시오.
