## GCC란 무엇인가

GCC(GNU Compiler Collection)는 GNU 프로젝트가 만들고 유지해온 컴파일러 모음입니다. 이름에 "Collection"이 들어가는 이유는 C 언어만이 아니라 C++, 포트란, Ada 등 여러 언어를 컴파일할 수 있는 여러 개의 컴파일러 프론트엔드를 한데 묶어 배포하기 때문입니다. 그중 C 언어를 컴파일하는 프론트엔드가 `gcc` 명령이고, C++ 언어를 컴파일하는 프론트엔드가 `g++` 명령입니다.

`gcc`와 `g++`는 내부적으로 같은 컴파일러 엔진을 공유하지만, 몇 가지 중요한 차이가 있습니다. `g++`는 확장자가 `.cpp`, `.cc`, `.cxx`인 파일을 자동으로 C++ 코드로 인식해서 처리하고, 표준 C++ 라이브러리(`libstdc++`)를 자동으로 링크해줍니다. 반면 `gcc`로 `.cpp` 파일을 컴파일하려 하면 문법 분석까지는 C++로 처리하더라도 표준 C++ 라이브러리를 자동으로 링크해주지 않아서 컴파일은 되어도 링크 단계에서 오류가 나는 경우가 흔합니다. 이 책에서는 C++을 다루므로 앞으로 모든 예제에서 `g++`를 사용합니다. GCC라는 이름과 `g++`라는 명령을 혼동하지 않는 것이 중요합니다. GCC는 도구 모음 전체를 가리키는 이름이고, `g++`는 그 안에서 우리가 실제로 터미널에 입력할 명령입니다.

## Windows에 GCC 설치하기: MSYS2 경로

Windows에는 GCC가 기본으로 설치되어 있지 않습니다. Windows용 GCC를 준비하는 방법은 여러 가지가 있지만(MinGW 단독 설치, MSYS2, WSL 등), 이 책에서는 MSYS2를 통한 설치를 권장 경로로 안내합니다. MSYS2는 Windows 위에서 리눅스와 비슷한 패키지 관리 환경(pacman)을 제공하는 프로젝트로, GCC를 비롯한 여러 개발 도구를 최신 버전으로 유지보수하기 쉽게 관리해줍니다. 특히 뒤에서 배울 vcpkg나 여러 오픈소스 라이브러리들이 MSYS2 환경과 잘 맞물려 동작하기 때문에, 처음부터 MSYS2 기반으로 시작해 두면 이후 장에서 겪을 시행착오를 줄일 수 있습니다.

### MSYS2 설치

MSYS2 공식 사이트(msys2.org)에서 설치 프로그램을 내려받아 실행하면 기본 경로인 `C:\msys64`에 설치됩니다. 설치가 끝나면 시작 메뉴에 "MSYS2 UCRT64", "MSYS2 MINGW64", "MSYS2 CLANG64" 등 여러 개의 터미널 항목이 생기는데, 이는 MSYS2가 서로 다른 런타임 조합을 지원하기 때문입니다. 이 책에서는 최신 Windows용 C 런타임(UCRT)을 사용하는 "MSYS2 UCRT64" 터미널을 기준으로 진행합니다. 특별한 이유가 없다면 이 터미널만 사용하는 것으로 충분합니다.

### GCC 툴체인 설치

MSYS2 UCRT64 터미널을 열고 다음 명령으로 패키지 데이터베이스를 최신화한 뒤 GCC 툴체인을 설치합니다.

```bash
pacman -Syu
pacman -S mingw-w64-ucrt-x86_64-gcc
```

첫 번째 명령은 MSYS2 자체와 패키지 목록을 업데이트하는 명령이고, 두 번째 명령이 실제로 GCC, g++, 링커 등을 포함한 UCRT64용 GCC 툴체인을 설치합니다. `pacman -Syu`를 실행하면 터미널을 닫고 다시 열어서 한 번 더 실행하라는 안내가 나올 수 있는데, 이는 MSYS2 자체의 핵심 구성요소가 업데이트되었을 때 정상적으로 나타나는 절차이니 안내에 따라 터미널을 재실행하면 됩니다.

### PATH 환경변수 설정

패키지 설치가 끝나면 `g++.exe`는 보통 `C:\msys64\ucrt64\bin` 폴더 안에 위치합니다. 이 경로를 MSYS2 터미널 밖, 즉 일반 Windows 명령 프롬프트나 PowerShell, 그리고 뒤에서 사용할 VS Code에서도 인식할 수 있도록 시스템 PATH 환경변수에 추가해야 합니다.

Windows 검색창에서 "환경 변수 편집"을 열고, 사용자 변수 또는 시스템 변수의 `Path` 항목에 `C:\msys64\ucrt64\bin` 경로를 추가합니다. 설정을 마친 뒤에는 열려 있던 터미널을 모두 닫고 새로 열어야 변경된 PATH가 반영됩니다.

## macOS와 Linux에 GCC 설치하기

macOS에서는 두 가지 경로가 있습니다. 하나는 Xcode Command Line Tools를 설치하는 방법으로, 터미널에서 `xcode-select --install` 명령을 실행하면 Apple이 제공하는 컴파일러 도구 모음이 설치됩니다. 다만 이렇게 설치되는 `gcc`, `g++` 명령은 실제로는 Apple Clang이라는 다른 컴파일러를 가리키는 별칭인 경우가 많습니다. Clang은 GCC와는 다른 프로젝트이지만 명령줄 사용법과 대부분의 옵션이 GCC와 거의 동일하므로, 이 책에서 다루는 커맨드라인 사용법은 그대로 적용됩니다. 진짜 GCC를 macOS에 설치하고 싶다면 Homebrew 패키지 관리자를 통해 `brew install gcc` 명령으로 설치할 수 있으며, 이 경우 `g++-14`처럼 버전 번호가 붙은 명령으로 실행하게 됩니다.

Linux에서는 대부분의 배포판이 패키지 관리자를 통해 GCC를 제공합니다. Debian 계열(Ubuntu 포함)에서는 다음 명령으로 설치합니다.

```bash
sudo apt install g++
```

Fedora 계열에서는 `sudo dnf install gcc-c++`, Arch Linux 계열에서는 `sudo pacman -S gcc` 명령을 사용합니다. 이 책의 이후 예제는 플랫폼에 상관없이 `g++` 명령이 PATH에 등록되어 있다는 전제로 진행되므로, 자신의 환경에 맞는 방법으로 설치를 마친 뒤 다음 단계로 넘어가면 됩니다.

## 설치 확인하기

플랫폼에 상관없이 설치가 제대로 되었는지는 다음 명령으로 확인합니다.

```bash
g++ --version
```

정상적으로 설치되었다면 다음과 비슷한 형태의 출력이 나타납니다(버전 번호와 세부 문구는 설치 환경에 따라 달라집니다).

```
g++ (Rev2, Built by MSYS2 project) 13.2.0
Copyright (C) 2023 Free Software Foundation, Inc.
```

이 명령이 "찾을 수 없는 명령"이라는 오류를 내며 실패한다면, GCC 자체가 설치되지 않았거나 PATH 환경변수 설정이 아직 반영되지 않은 것입니다. Windows라면 터미널을 새로 열었는지, PATH에 정확한 경로(`C:\msys64\ucrt64\bin`)가 들어갔는지 다시 확인합니다.

## 첫 번째 컴파일: 커맨드라인에서 직접 컴파일하기

이제 아주 단순한 C++ 코드를 하나 작성해서 직접 컴파일해 보겠습니다. 작업할 폴더를 하나 만들고 그 안에 `main.cpp` 파일을 다음과 같이 작성합니다.

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, C++ toolchain!" << std::endl;
    return 0;
}
```

이 파일이 있는 폴더에서 터미널을 열고 다음 명령을 실행합니다.

```bash
g++ main.cpp -o main
```

이 명령을 하나씩 뜯어보면, `g++`는 우리가 사용할 컴파일러 프론트엔드이고, `main.cpp`는 컴파일할 소스 파일이며, `-o main`은 "결과로 만들어질 실행 파일의 이름을 main으로 지정하라"는 뜻입니다. `-o` 옵션을 생략하면 Linux/macOS에서는 `a.out`, Windows(MinGW 계열)에서는 `a.exe`라는 기본 이름으로 실행 파일이 만들어지므로, 결과물의 이름을 원하는 대로 정하고 싶다면 `-o` 옵션을 쓰는 습관을 들이는 것이 좋습니다.

명령이 별다른 출력 없이 끝났다면 컴파일이 성공한 것입니다. GCC를 비롯한 대부분의 컴파일러는 "문제가 없으면 조용히 있고, 문제가 있을 때만 말을 하는" 방식으로 동작합니다. 이제 만들어진 실행 파일을 실행해 봅니다. Windows에서는 다음과 같이 실행합니다.

```bash
.\main.exe
```

macOS나 Linux에서는 다음과 같이 실행합니다.

```bash
./main
```

터미널에 `Hello, C++ toolchain!`이 출력되었다면, 여러분은 방금 소스 코드 작성부터 컴파일, 실행까지 C++ 개발의 가장 기본적인 흐름을 손으로 직접 완료한 것입니다. 앞으로 VS Code나 CMake 같은 도구들이 이 과정을 자동화하고 편리하게 만들어주겠지만, 그 편리함 밑에서 실제로 벌어지는 일은 지금 실행한 이 `g++` 명령과 본질적으로 다르지 않습니다.

## 여러 소스 파일 함께 컴파일하기

실제 프로젝트는 소스 파일 하나로 끝나는 경우가 거의 없습니다. 기능별로 파일을 나누는 것이 일반적이므로, 여러 개의 `.cpp` 파일을 함께 컴파일하는 방법도 간단히 살펴보겠습니다. 앞서 만든 폴더에 `greet.h`와 `greet.cpp`를 추가로 작성해 보겠습니다.

```cpp
// greet.h
#pragma once
#include <string>

void greet(const std::string& name);
```

```cpp
// greet.cpp
#include "greet.h"
#include <iostream>

void greet(const std::string& name) {
    std::cout << "Hello, " << name << "!" << std::endl;
}
```

그리고 `main.cpp`를 다음과 같이 수정합니다.

```cpp
#include "greet.h"

int main() {
    greet("C++");
    return 0;
}
```

이제 두 개의 `.cpp` 파일을 한 번에 g++ 명령에 넘겨서 컴파일합니다.

```bash
g++ main.cpp greet.cpp -o main
```

`g++`는 나열된 소스 파일들을 각각 컴파일한 뒤, 서로 참조하는 함수(`greet`)를 연결(링크)해서 하나의 실행 파일로 묶어줍니다. 소스 파일이 2개일 때는 이렇게 명령에 나란히 나열하는 방식이 그럭저럭 견딜 만하지만, 파일이 10개, 50개로 늘어나면 매번 모든 파일을 하나하나 나열하는 것도, 파일 하나만 고쳤는데도 전체를 처음부터 다시 컴파일하는 것도 비효율적으로 변합니다. 이런 문제를 해결하기 위해 등장하는 것이 바로 빌드 시스템이며, 이 책에서는 6장부터 CMake를 이용해 이런 프로젝트 구조를 체계적으로 관리하는 방법을 다룹니다. 지금 단계에서는 "결국 여러 파일을 컴파일한다는 것은 g++에게 파일 목록을 넘기는 일"이라는 감각만 잡아두면 충분합니다.

## 요약

- GCC는 여러 언어의 컴파일러를 모아놓은 도구 모음이며, 이 책에서 사용하는 `g++`는 그중 C++ 전용 프론트엔드입니다.
- Windows에서는 MSYS2를 설치하고 `pacman -S mingw-w64-ucrt-x86_64-gcc` 명령으로 GCC 툴체인을 설치한 뒤, `ucrt64\bin` 경로를 PATH에 등록하는 방식을 권장합니다.
- macOS는 Xcode Command Line Tools(Apple Clang) 또는 Homebrew의 gcc, Linux는 배포판 패키지 관리자(`apt`, `dnf`, `pacman` 등)로 GCC를 설치합니다.
- `g++ --version`으로 설치를 확인하고, `g++ main.cpp -o main`으로 컴파일한 뒤 생성된 실행 파일을 직접 실행할 수 있습니다.
- 여러 소스 파일은 `g++ main.cpp greet.cpp -o main`처럼 나열해서 함께 컴파일할 수 있지만, 파일 수가 늘어나면 이 방식은 한계에 부딪히며, 이는 6장 이후 CMake를 배우는 이유가 됩니다.

## 연습문제

1. `gcc`와 `g++` 명령의 차이를 설명하고, 이 책에서 왜 `g++`를 사용하는지 서술해 보세요.
2. 자신의 컴퓨터에 GCC를 설치하고, `g++ --version` 명령의 실제 출력 결과를 확인해 보세요.
3. 본문의 `main.cpp` 예제를 직접 작성하고 컴파일하여 실행 결과를 확인해 보세요. 만약 `-o` 옵션을 생략하면 어떤 이름의 실행 파일이 만들어지는지 자신의 운영체제에서 직접 확인해 보세요.
4. `greet.h`, `greet.cpp`, `main.cpp` 세 파일 구성을 그대로 따라 작성한 뒤, 소스 파일 하나를 더 추가해서(예: 인사말을 대문자로 바꾸는 함수) 세 개의 `.cpp` 파일을 한 번에 컴파일해 보세요.
5. 만약 `greet.cpp`를 컴파일 명령에서 빠뜨리고 `g++ main.cpp -o main`만 실행하면 어떤 오류 메시지가 나오는지 직접 확인하고, 그 오류가 왜 발생하는지 설명해 보세요.
