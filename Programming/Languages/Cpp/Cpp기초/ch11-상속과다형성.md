10장에서는 클래스를 이용해 데이터와 그 데이터를 다루는 함수를 하나로 묶는 방법을 배웠습니다. 그런데 실제 프로그램을 작성하다 보면 "비슷하지만 조금 다른" 여러 종류의 객체를 다뤄야 하는 경우가 자주 생깁니다. 게임에 등장하는 `Warrior`, `Mage`, `Archer`는 모두 "캐릭터"라는 공통점을 갖지만 공격 방식은 서로 다릅니다. 이런 상황을 깔끔하게 표현하기 위한 도구가 바로 **상속(inheritance)**과 **다형성(polymorphism)**입니다.

## 상속의 기본 문법

상속은 이미 존재하는 클래스의 멤버 변수와 멤버 함수를 새로운 클래스가 물려받는 것을 말합니다. 원래의 클래스를 **기반 클래스(base class)** 또는 부모 클래스라 하고, 물려받는 클래스를 **파생 클래스(derived class)** 또는 자식 클래스라고 합니다.

```cpp
#include <iostream>
#include <string>

class Animal {
public:
    Animal(const std::string& name) : name_(name) {}

    void introduce() const {
        std::cout << "저는 " << name_ << "입니다." << std::endl;
    }

protected:
    std::string name_;
};

// Animal을 public으로 상속받는 Dog 클래스
class Dog : public Animal {
public:
    Dog(const std::string& name) : Animal(name) {}

    void bark() const {
        std::cout << name_ << ": 멍멍!" << std::endl;
    }
};

int main() {
    Dog my_dog("초코");
    my_dog.introduce();  // 부모 클래스의 함수를 그대로 사용
    my_dog.bark();       // 자식 클래스에서 추가한 함수
    return 0;
}
```

`class Dog : public Animal`이라는 문법으로 상속 관계를 표현합니다. `Dog`는 `Animal`이 가진 `introduce` 함수와 `name_` 변수를 그대로 물려받으면서, 자신만의 `bark` 함수를 추가로 정의했습니다.

여기서 `name_`을 `private`이 아니라 `protected`로 선언한 점에 주목하세요. `private` 멤버는 파생 클래스에서도 접근할 수 없지만, `protected` 멤버는 파생 클래스 내부에서는 접근이 허용됩니다. 반면 클래스 외부에서는 `private`과 마찬가지로 접근할 수 없습니다.

파생 클래스의 생성자는 반드시 기반 클래스의 생성자를 호출해야 합니다. 위 예제에서 `Dog(const std::string& name) : Animal(name)`처럼 초기화 목록에서 기반 클래스 생성자를 명시적으로 호출한 것이 이 때문입니다. 명시하지 않으면 기반 클래스의 기본 생성자가 자동으로 호출되는데, 만약 기반 클래스에 기본 생성자가 없다면 컴파일 오류가 발생합니다.

## 가상 함수와 오버라이딩

상속만으로는 진짜 힘을 발휘하기 어렵습니다. 앞의 예제에서 `Animal` 타입의 포인터로 `Dog` 객체를 가리킨 뒤 `introduce`를 호출하면, `Animal`에 정의된 `introduce`가 호출됩니다. 하지만 만약 `Dog`가 `introduce`를 자신만의 방식으로 재정의하고 싶다면 어떻게 해야 할까요? 이때 필요한 것이 `virtual` 키워드입니다.

```cpp
#include <iostream>
#include <string>

class Animal {
public:
    Animal(const std::string& name) : name_(name) {}

    // virtual로 선언하면 파생 클래스에서 재정의(오버라이딩)할 수 있다
    virtual void speak() const {
        std::cout << name_ << ": (아무 소리도 내지 않는다)" << std::endl;
    }

protected:
    std::string name_;
};

class Dog : public Animal {
public:
    Dog(const std::string& name) : Animal(name) {}

    // override 키워드로 기반 클래스의 함수를 재정의한다는 것을 명시
    void speak() const override {
        std::cout << name_ << ": 멍멍!" << std::endl;
    }
};

class Cat : public Animal {
public:
    Cat(const std::string& name) : Animal(name) {}

    void speak() const override {
        std::cout << name_ << ": 야옹~" << std::endl;
    }
};

int main() {
    Dog dog("초코");
    Cat cat("나비");

    // 기반 클래스 참조로 파생 클래스 객체를 다룬다
    Animal& ref1 = dog;
    Animal& ref2 = cat;

    ref1.speak();  // "초코: 멍멍!" -- Dog::speak가 호출된다
    ref2.speak();  // "나비: 야옹~" -- Cat::speak가 호출된다

    return 0;
}
```

`speak`가 `virtual`로 선언되어 있으면, `Animal&` 타입의 참조를 통해 호출하더라도 실제로 그 참조가 가리키는 객체의 실제 타입(`Dog` 또는 `Cat`)에 맞는 함수가 호출됩니다. 이를 **동적 바인딩(dynamic binding)** 또는 **런타임 폴리모피즘**이라고 부릅니다. 반대로 `virtual`이 없다면 참조나 포인터의 선언된 타입(`Animal`)을 기준으로 함수가 정해지는데, 이를 **정적 바인딩**이라고 합니다.

파생 클래스에서 `override` 키워드를 붙이는 습관을 들이는 것이 좋습니다. `override`는 "이 함수는 기반 클래스의 가상 함수를 재정의하는 것이다"라고 컴파일러에 알려주는 표시입니다. 만약 함수 이름이나 매개변수 목록을 잘못 적어서 실제로는 오버라이딩이 성립하지 않는데도 `override`를 붙였다면, 컴파일러가 오류를 내며 알려줍니다. 이런 실수는 `override` 없이는 조용히 넘어가서 찾기 힘든 버그로 이어지기 쉽습니다.

## 가상 소멸자가 필요한 이유

9장에서 RAII(Resource Acquisition Is Initialization)를 다루면서, 객체가 소멸될 때 소멸자가 자동으로 호출되어 자원을 정리한다고 배웠습니다. 그런데 상속 관계에서는 소멸자에 한 가지 함정이 숨어 있습니다.

```cpp
#include <iostream>

class Base {
public:
    ~Base() {  // virtual이 아닌 소멸자
        std::cout << "Base 소멸" << std::endl;
    }
};

class Derived : public Base {
public:
    Derived() { data_ = new int[100]; }
    ~Derived() {
        std::cout << "Derived 소멸" << std::endl;
        delete[] data_;
    }

private:
    int* data_;
};

int main() {
    Base* ptr = new Derived();
    delete ptr;  // 문제 발생!
    return 0;
}
```

이 코드를 실행하면 화면에 "Base 소멸"만 출력됩니다. `Derived`의 소멸자가 호출되지 않았기 때문에 `data_`가 가리키던 메모리는 해제되지 않고 그대로 누수됩니다. `Base` 타입의 포인터를 통해 `delete`를 호출했을 때, 소멸자가 `virtual`이 아니면 컴파일러는 포인터의 선언된 타입, 즉 `Base`의 소멸자만 호출하기 때문입니다.

해결 방법은 간단합니다. 기반 클래스의 소멸자를 `virtual`로 선언하는 것입니다.

```cpp
class Base {
public:
    virtual ~Base() {  // virtual 소멸자
        std::cout << "Base 소멸" << std::endl;
    }
};
```

이렇게 하면 `delete ptr;`을 실행할 때 실제 객체 타입인 `Derived`의 소멸자가 먼저 호출되고, 이어서 `Base`의 소멸자가 호출됩니다. 파생 클래스가 존재할 가능성이 있는 클래스, 즉 다른 클래스의 기반 클래스로 쓰일 클래스라면 소멸자를 항상 `virtual`로 선언하는 것이 안전한 습관입니다. 이는 곧 배울 추상 클래스에서도 마찬가지로 중요합니다.

## 순수 가상 함수와 추상 클래스

`Animal` 예제에서 `speak` 함수는 "아무 소리도 내지 않는다"라는 기본 구현을 가지고 있었습니다. 하지만 생각해 보면 "동물"이라는 개념 자체는 구체적인 울음소리를 가지지 않습니다. 실제로 존재하는 것은 개, 고양이처럼 구체적인 동물들뿐입니다. 이런 경우 `Animal` 자체는 객체로 만들어질 필요가 없고, 오히려 만들어지지 않도록 막는 것이 설계 의도를 더 명확히 드러냅니다.

이럴 때 사용하는 것이 **순수 가상 함수(pure virtual function)**입니다. 함수 선언 끝에 `= 0`을 붙이면 순수 가상 함수가 되며, 몸체(구현)를 제공하지 않습니다.

```cpp
#include <iostream>
#include <string>

// 순수 가상 함수를 하나 이상 가진 클래스는 추상 클래스가 된다
class Shape {
public:
    Shape(const std::string& name) : name_(name) {}
    virtual ~Shape() = default;

    // 순수 가상 함수: 파생 클래스가 반드시 구현해야 한다
    virtual double area() const = 0;

    void print_area() const {
        std::cout << name_ << "의 면적: " << area() << std::endl;
    }

protected:
    std::string name_;
};

class Circle : public Shape {
public:
    Circle(double radius) : Shape("원"), radius_(radius) {}

    double area() const override {
        return 3.14159 * radius_ * radius_;
    }

private:
    double radius_;
};

class Rectangle : public Shape {
public:
    Rectangle(double width, double height)
        : Shape("사각형"), width_(width), height_(height) {}

    double area() const override {
        return width_ * height_;
    }

private:
    double width_;
    double height_;
};

int main() {
    Circle circle(5.0);
    Rectangle rect(4.0, 6.0);

    circle.print_area();
    rect.print_area();

    return 0;
}
```

순수 가상 함수를 하나라도 가진 클래스를 **추상 클래스(abstract class)**라고 부릅니다. 추상 클래스는 직접 객체를 만들 수 없습니다. `Shape shape("모양");`처럼 작성하면 컴파일 오류가 발생합니다. 대신 `Circle`, `Rectangle`처럼 순수 가상 함수를 실제로 구현한 파생 클래스만 객체로 만들 수 있습니다. `Shape`의 소멸자를 `virtual ~Shape() = default;`로 선언한 것도 앞서 설명한 가상 소멸자의 원칙을 그대로 따른 것입니다.

## 다형성 활용하기: 여러 객체를 하나의 인터페이스로 다루기

추상 클래스와 가상 함수의 진짜 가치는 서로 다른 파생 클래스들을 기반 클래스 포인터나 참조를 통해 똑같은 방식으로 다룰 수 있다는 점에서 나옵니다. 8장에서 배열과 포인터를, 9장에서 참조를 다뤘던 내용을 떠올리며 다음 예제를 살펴보겠습니다.

```cpp
#include <iostream>
#include <vector>
#include <memory>

// Shape, Circle, Rectangle은 위 예제와 동일하다고 가정

int main() {
    // 서로 다른 파생 클래스 객체들을 하나의 컨테이너에 담는다
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(3.0));
    shapes.push_back(std::make_unique<Rectangle>(2.0, 5.0));
    shapes.push_back(std::make_unique<Circle>(1.5));

    // 각 객체가 실제로 Circle인지 Rectangle인지 신경 쓰지 않고
    // Shape의 공용 인터페이스만으로 처리한다
    for (const auto& shape : shapes) {
        shape->print_area();
    }

    return 0;
}
```

`shapes` 벡터에는 `Circle`과 `Rectangle` 객체가 섞여 들어가 있지만, 반복문에서는 `Shape` 인터페이스만 알고 있으면 됩니다. `print_area`를 호출하면 각 객체가 실제로 어떤 파생 클래스인지에 따라 올바른 `area` 구현이 자동으로 선택됩니다. 이것이 다형성의 핵심입니다: "무엇을 할지"는 공통 인터페이스로 표현하고, "어떻게 할지"는 각 파생 클래스가 알아서 책임지는 것입니다.

이런 구조는 새로운 도형을 추가할 때도 유리합니다. `Triangle` 클래스를 새로 만들어 `Shape`를 상속받고 `area`를 구현하기만 하면, 기존의 `main` 함수나 반복문 코드는 전혀 손대지 않아도 잘 동작합니다. `unique_ptr`을 사용한 이유는 15장에서 자세히 다룰 스마트 포인터가 힙에 할당한 객체의 소멸을 자동으로 관리해 주기 때문입니다. `Shape`에 가상 소멸자가 있으므로, `unique_ptr<Shape>`가 소멸될 때도 실제 객체의 파생 클래스 소멸자가 올바르게 호출됩니다.

## 요약

이번 장에서는 클래스 상속의 기본 문법과 다형성의 개념을 배웠습니다. `: public`으로 기반 클래스를 상속받으면 그 멤버들을 물려받을 수 있고, 함수를 `virtual`로 선언하면 파생 클래스에서 `override`를 통해 재정의할 수 있습니다. 이렇게 재정의된 가상 함수는 기반 클래스 포인터나 참조를 통해 호출되더라도 실제 객체의 타입에 맞는 동작을 수행하는데, 이를 동적 바인딩이라 부릅니다. 상속 관계에서 기반 클래스의 소멸자는 반드시 `virtual`로 선언해야 파생 클래스의 자원이 안전하게 정리됩니다. 순수 가상 함수(`= 0`)를 이용하면 구체적인 구현이 없는 추상 클래스를 정의할 수 있고, 이를 통해 파생 클래스들이 반드시 구현해야 하는 공용 인터페이스를 강제할 수 있습니다. 마지막으로 여러 파생 클래스 객체를 하나의 컨테이너와 인터페이스로 다루는 다형성 활용 패턴을 살펴보았습니다.
