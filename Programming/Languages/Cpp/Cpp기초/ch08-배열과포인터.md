# 8장. 배열과 포인터

7장에서는 함수를 통해 코드를 재사용하는 방법을 배웠습니다. 이번 장에서는 여러 개의 값을 하나로 묶어 다루는 **배열(array)**과, 메모리 주소를 직접 다루는 **포인터(pointer)**를 살펴봅니다. 배열과 포인터는 서로 별개의 개념이지만 C++에서는 밀접하게 연결되어 있어, 함께 이해해야 각각을 제대로 활용할 수 있습니다.

## 배열의 선언과 초기화

같은 타입의 값을 여러 개 저장하고 싶을 때 변수를 하나씩 선언하는 것은 비효율적입니다. 예를 들어 학생 다섯 명의 점수를 저장한다고 변수를 `score1`, `score2`, `score3`, `score4`, `score5`로 만드는 것은 관리하기 어렵습니다. 이럴 때 **배열**을 사용합니다.

```cpp
int scores[5];  // int 5개를 담을 수 있는 배열 선언

scores[0] = 90;
scores[1] = 85;
scores[2] = 77;
scores[3] = 92;
scores[4] = 68;
```

배열을 선언과 동시에 초기화할 수도 있습니다.

```cpp
int scores[5] = {90, 85, 77, 92, 68};

// 원소 개수를 명시하지 않으면 초기화 목록의 개수로 자동 결정된다
int values[] = {1, 2, 3};  // values는 크기 3인 배열

// 일부만 초기화하면 나머지는 0으로 채워진다
int zeros[5] = {1, 2};  // {1, 2, 0, 0, 0}
```

배열의 각 원소는 `배열이름[인덱스]` 형태로 접근합니다. C++에서 인덱스는 항상 **0부터 시작**하므로, 크기가 5인 배열은 `scores[0]`부터 `scores[4]`까지 유효합니다. `scores[5]`는 존재하지 않는 원소이며, 이 부분은 뒤에서 다시 다루겠습니다.

배열의 크기는 선언할 때 한 번 정해지면 이후에 바꿀 수 없습니다. 이 점이 나중에 살펴볼 `std::vector`와 가장 큰 차이입니다.

## 포인터란 무엇인가

컴퓨터 메모리의 모든 변수는 특정 위치, 즉 **주소(address)**에 저장됩니다. **포인터**는 다른 변수의 메모리 주소를 저장하는 변수입니다. "이 값이 저장된 위치를 가리킨다"는 의미에서 포인터라는 이름이 붙었습니다.

포인터를 다루려면 두 개의 연산자를 알아야 합니다.

- `&` (주소 연산자): 변수 앞에 붙여 그 변수의 메모리 주소를 얻습니다.
- `*` (역참조 연산자): 포인터 앞에 붙여 그 포인터가 가리키는 위치에 저장된 값을 얻습니다.

```cpp
#include <iostream>

int main() {
    int number = 42;
    int* p = &number;  // p는 number의 주소를 저장하는 포인터

    std::cout << "number의 값: " << number << std::endl;
    std::cout << "number의 주소: " << &number << std::endl;
    std::cout << "p가 저장한 주소: " << p << std::endl;
    std::cout << "p가 가리키는 값: " << *p << std::endl;  // 역참조 -> 42

    *p = 100;  // p가 가리키는 곳의 값을 바꾼다
    std::cout << "number의 새 값: " << number << std::endl;  // 100

    return 0;
}
```

`int* p`에서 `*`는 "p는 int를 가리키는 포인터"라는 타입 선언의 일부입니다. 반면 `*p = 100;`에서 `*`는 역참조 연산자로, "p가 가리키는 곳"을 뜻합니다. 같은 기호가 문맥에 따라 다르게 쓰이므로 처음에는 혼동하기 쉽지만, "선언에서는 타입의 일부, 식에서는 역참조"라고 구분하면 됩니다.

포인터를 선언했지만 아직 어떤 주소도 대입하지 않았다면, 안전하게 `nullptr`로 초기화해두는 습관을 들이는 것이 좋습니다.

```cpp
int* p = nullptr;  // 아직 아무것도 가리키지 않음을 명시
```

## 배열과 포인터의 관계

C++에서 배열 이름은 특별한 상황에서 그 배열의 첫 번째 원소를 가리키는 포인터처럼 동작합니다. 이를 배열이 포인터로 **decay(변환)**된다고 표현합니다.

```cpp
int numbers[5] = {10, 20, 30, 40, 50};
int* p = numbers;  // numbers는 &numbers[0]과 같은 의미로 쓰인다

std::cout << *p << std::endl;       // 10, numbers[0]과 동일
std::cout << *(p + 1) << std::endl; // 20, numbers[1]과 동일
std::cout << p[2] << std::endl;     // 30, 포인터에도 [] 를 쓸 수 있다
```

이 관계를 그림으로 보면 더 명확합니다. 아래 다이어그램은 `numbers` 배열의 다섯 원소가 메모리에 연속으로 배치되어 있고, 포인터 `p`가 그 시작 주소(첫 원소의 위치)를 저장하고 있는 모습을 보여줍니다.

```text
                      배열의 메모리 배치와 포인터

  int numbers[5] = {10, 20, 30, 40, 50};
  int* p = numbers;   // 배열 이름은 첫 원소의 주소로 변환된다

         0x1000    0x1004    0x1008    0x100C    0x1010
        +--------+--------+--------+--------+--------+
        |   10   |   20   |   30   |   40   |   50   |   (연속된 메모리)
        +--------+--------+--------+--------+--------+
        numbers[0] numbers[1] numbers[2] numbers[3] numbers[4]
            ^
            |
            | (가리킴)
            |
  +----------------+
  |   포인터 변수    |
  |  p = 0x1000     |
  +----------------+

  p는 numbers 배열의 첫 원소 numbers[0]의 주소를 저장하며,
  *p는 10, *(p+1)은 20, p[2]는 30을 가리킨다.
```

여기서 핵심은 두 가지입니다. 첫째, 배열의 원소들은 메모리에 **빈틈없이 연속으로** 배치됩니다. 둘째, 포인터는 그 시작 주소 하나만 알고 있을 뿐이며, 나머지 원소들은 주소에 일정한 간격(원소 하나의 크기)을 더해가며 찾아갑니다.

## 포인터 연산

포인터에 정수를 더하거나 빼면, 단순히 주소값에 1을 더하는 것이 아니라 **가리키는 타입의 크기만큼** 이동합니다. `int`가 4바이트라면 `p + 1`은 주소값 기준으로 4바이트만큼 뒤로 이동한 위치를 가리킵니다. 덕분에 프로그래머는 바이트 단위를 신경 쓰지 않고 "원소 하나 다음"이라는 개념으로 포인터를 다룰 수 있습니다.

```cpp
int numbers[5] = {10, 20, 30, 40, 50};
int* p = numbers;

for (int i = 0; i < 5; i++) {
    std::cout << *(p + i) << " ";  // p + i는 numbers[i]와 같은 원소를 가리킨다
}
std::cout << std::endl;

p++;  // p를 다음 원소로 이동
std::cout << *p << std::endl;  // 20
```

배열을 순회할 때 인덱스 대신 포인터 자체를 이동시키는 방식은 저수준 코드에서 자주 쓰이지만, 처음 배울 때는 인덱스 방식(`numbers[i]`)이 더 직관적이고 실수도 적습니다. 두 방식이 결과적으로 같은 메모리를 가리킨다는 점만 이해하면 충분합니다.

## 흔한 실수

포인터와 배열을 다룰 때 특히 조심해야 할 두 가지 실수가 있습니다.

**초기화되지 않은 포인터 사용**. 포인터를 선언만 하고 초기화하지 않으면, 그 안에는 어떤 값이 들어있을지 알 수 없습니다. 그런 포인터를 역참조하면 프로그램이 예측할 수 없는 동작을 하거나 곧바로 충돌(crash)할 수 있습니다.

```cpp
int* p;          // 초기화하지 않음: p는 쓰레기 값을 담고 있다
std::cout << *p; // 위험! 어떤 메모리를 건드릴지 알 수 없다
```

**배열 경계를 벗어난 접근**. C++은 배열 인덱스가 유효한 범위인지 실행 중에 검사해주지 않습니다. `scores[5]`처럼 존재하지 않는 원소에 접근해도 컴파일은 되지만, 실행 시 다른 변수의 메모리를 침범하거나 알 수 없는 값을 읽어오는 등 심각한 버그로 이어집니다.

```cpp
int scores[5] = {90, 85, 77, 92, 68};
std::cout << scores[5];  // 정의되지 않은 동작(undefined behavior): 컴파일은 되지만 위험하다
```

이런 실수는 컴파일러가 잡아주지 않기 때문에, 반복문에서 배열을 순회할 때는 항상 인덱스 범위를 `배열크기`보다 작게 유지하도록 조건문을 꼼꼼히 확인해야 합니다. 6장에서 다룬 반복문의 종료 조건을 다시 떠올려보면, 왜 `i < 5`처럼 부등호를 정확히 써야 하는지 이해가 될 것입니다.

## C 스타일 배열의 한계

지금까지 살펴본 배열, 흔히 **C 스타일 배열**이라고 부르는 이 방식은 다음과 같은 한계를 가지고 있습니다.

- 크기가 고정되어 있어, 선언한 뒤에는 원소 개수를 늘리거나 줄일 수 없습니다.
- 배열 자체는 자신의 크기를 기억하지 못합니다. 함수에 배열을 넘기면 포인터로 변환되어 크기 정보가 사라지므로, 크기를 별도의 매개변수로 함께 넘겨야 합니다.
- 경계를 벗어난 접근을 실행 중에 검사해주지 않아 버그의 원인이 되기 쉽습니다.
- 배열을 복사하거나 비교하는 등의 편리한 기능이 기본으로 제공되지 않습니다.

이런 문제들은 C++ 표준 라이브러리가 제공하는 `std::vector`를 사용하면 대부분 해결됩니다. `std::vector`는 크기를 자동으로 조절하고, 자신의 크기를 스스로 알고 있으며, 훨씬 안전한 인터페이스를 제공합니다. 지금 단계에서는 배열과 포인터의 동작 원리를 확실히 이해해두는 것이 중요한데, `std::vector`를 비롯한 여러 컨테이너를 편리하게 쓸 수 있게 되었을 때도 그 내부 동작은 결국 이번 장에서 배운 메모리 개념에 기반하고 있기 때문입니다. `std::vector`에 대해서는 14장에서 자세히 다룹니다.

## 요약

이 장에서는 배열과 포인터의 기본 개념을 배웠습니다. 배열은 같은 타입의 값을 메모리에 연속으로 배치해 인덱스로 접근할 수 있게 해주는 자료구조입니다. 포인터는 메모리 주소를 저장하는 변수이며, `&`로 주소를 얻고 `*`로 그 주소의 값을 역참조합니다. 배열 이름은 첫 원소를 가리키는 포인터로 변환되기 때문에, 포인터 연산과 배열 인덱싱은 사실상 같은 메모리를 다루는 두 가지 표현 방식입니다. 초기화되지 않은 포인터의 역참조와 배열 경계를 벗어난 접근은 컴파일러가 잡아주지 않는 대표적인 실수이므로 항상 주의해야 합니다. C 스타일 배열은 크기가 고정되고 크기 정보를 스스로 기억하지 못하는 한계가 있으며, 이는 14장에서 배울 `std::vector`가 보완해줍니다.

## 연습문제

1. 정수 6개를 담는 배열을 선언하고 초기화한 뒤, 반복문으로 모든 원소의 합을 구하는 프로그램을 작성하세요.
2. 정수 변수 하나를 선언하고, 그 변수를 가리키는 포인터를 만들어 포인터를 통해 변수의 값을 변경해보세요.
3. 배열 이름을 포인터에 대입한 뒤, 인덱스 접근(`arr[i]`)과 포인터 연산(`*(p + i)`)이 같은 값을 가리키는지 코드로 확인해보세요.
4. 크기가 4인 배열을 선언한 뒤 인덱스 4에 접근하는 코드를 작성해보고(경계 초과), 왜 이 코드가 컴파일은 되지만 위험한지 설명해보세요.
5. `int* p;`처럼 초기화하지 않은 포인터를 선언한 경우와 `int* p = nullptr;`처럼 초기화한 경우의 차이를 설명하고, 왜 후자가 더 안전한 습관인지 서술하세요.
