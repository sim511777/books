## 같은 코드를 타입마다 다시 쓰는 문제

7장에서 함수를 배우면서 반복되는 코드를 하나의 함수로 묶어 재사용하는 법을 익혔습니다. 그런데 함수를 만들다 보면 또 다른 종류의 반복이 나타납니다. 두 정수 중 더 큰 값을 구하는 함수를 다음과 같이 작성했다고 합시다.

```cpp
int get_max_int(int a, int b) {
    return (a > b) ? a : b;
}
```

문제는 이 함수를 `double`에도, `char`에도, 심지어 나중에 만들 `Money`라는 클래스에도 쓰고 싶다는 점입니다. 그러면 다음과 같이 이름만 바꿔서 똑같은 함수를 여러 번 만들어야 합니다.

```cpp
double get_max_double(double a, double b) {
    return (a > b) ? a : b;
}

char get_max_char(char a, char b) {
    return (a > b) ? a : b;
}
```

로직은 완전히 동일한데 타입만 다릅니다. 함수 이름도 따로 지어야 하고, 로직에 버그가 있으면 모든 복제본을 일일이 찾아 고쳐야 합니다. 이런 상황에서 C++는 **템플릿(template)** 이라는 도구를 제공합니다. 템플릿은 "타입을 나중에 정하는 코드"를 작성하는 방법입니다. 즉, 함수나 클래스를 만들 때 구체적인 타입 대신 자리표시자를 써 두고, 실제로 사용하는 순간에 컴파일러가 그 자리표시자를 진짜 타입으로 채워 넣게 만드는 것입니다.

## 함수 템플릿

함수 템플릿은 `template` 키워드와 타입 매개변수를 선언한 뒤, 그 매개변수를 마치 실제 타입처럼 사용해서 만듭니다.

```cpp
template <typename T>
T get_max(T a, T b) {
    return (a > b) ? a : b;
}
```

여기서 `T`는 특정 타입을 의미하는 것이 아니라 "호출할 때 결정될 어떤 타입"을 나타내는 이름입니다. `typename` 대신 `class` 키워드를 써도 의미는 같습니다(`template <class T>`). 관례상 이름은 `T`를 많이 쓰지만 `Value`, `Item`처럼 의미가 드러나는 이름을 붙여도 됩니다.

이제 이 함수를 다양한 타입으로 호출할 수 있습니다.

```cpp
#include <iostream>

int main() {
    std::cout << get_max(3, 7) << '\n';        // int로 호출
    std::cout << get_max(2.5, 1.1) << '\n';    // double로 호출
    std::cout << get_max('a', 'z') << '\n';    // char로 호출
}
```

`get_max(3, 7)`을 호출하면 컴파일러는 인자의 타입이 `int`임을 보고 `T`를 `int`로 채운 함수를 만들어 냅니다. `get_max(2.5, 1.1)`에서는 `T`가 `double`이 됩니다. 우리는 함수를 한 번만 작성했지만, 컴파일러는 실제로 사용된 타입마다 별도의 함수를 만들어 줍니다. 이 과정을 **템플릿 인스턴스화(template instantiation)** 라고 부릅니다.

## 템플릿 인스턴스화란

인스턴스화는 "설계도로부터 실물을 찍어낸다"는 뜻입니다. `template <typename T> T get_max(T a, T b)`는 그 자체로는 실행 가능한 코드가 아니라 코드를 만드는 설계도입니다. 컴파일러는 소스 코드에서 `get_max(3, 7)`처럼 실제로 호출되는 지점을 보고서야, 그 타입에 맞는 진짜 함수를 생성합니다. 앞의 예제에서는 `get_max<int>`, `get_max<double>`, `get_max<char>` 세 가지 버전이 컴파일 결과물에 실제로 존재하게 됩니다.

이 방식의 장점은 명확합니다. 소스 코드에는 로직이 한 번만 존재하므로 유지보수가 쉽고, 실행 시점에 타입을 판단하는 비용이 전혀 들지 않습니다(타입은 컴파일 시점에 이미 결정됩니다). 다만 사용하는 타입 종류가 많아질수록 최종 실행 파일의 크기가 늘어날 수 있다는 점은 알아 두어야 합니다.

타입을 명시적으로 지정하고 싶다면 `get_max<double>(3, 7)`처럼 꺾쇠괄호로 적을 수도 있습니다. 보통은 컴파일러가 인자로부터 타입을 추론할 수 있으므로 생략합니다.

## 클래스 템플릿

함수뿐 아니라 클래스도 템플릿으로 만들 수 있습니다. 10장에서 만든 클래스 중 하나가 특정 타입의 값 하나를 안전하게 담아 두는 상자 역할을 한다고 합시다.

```cpp
template <typename T>
class Box {
public:
    explicit Box(T value) : value_(value) {}

    T get() const { return value_; }
    void set(T value) { value_ = value; }

private:
    T value_;
};
```

`Box`는 `int`를 담을 수도, `std::string`을 담을 수도 있습니다. 사용할 때는 어떤 타입을 담을지 꺾쇠괄호로 지정합니다.

```cpp
Box<int> int_box(42);
Box<std::string> name_box("hyunwoo");

std::cout << int_box.get() << '\n';
std::cout << name_box.get() << '\n';
```

클래스 템플릿은 함수 템플릿과 달리 타입을 자동으로 추론해 주지 않는 경우가 많아서(최신 표준에서는 일부 추론이 가능하지만), 대부분 `Box<int>`처럼 타입을 명시해서 사용합니다. `Box<int>`와 `Box<std::string>`은 컴파일러 입장에서 완전히 다른 두 개의 클래스로 취급됩니다. 즉 `Box<int>`가 인스턴스화되면 `int value_`를 멤버로 갖는 클래스가, `Box<std::string>`이 인스턴스화되면 `std::string value_`를 멤버로 갖는 클래스가 각각 따로 생성됩니다.

## 타입 매개변수 여러 개 사용하기

템플릿은 타입 매개변수를 두 개 이상 받을 수도 있습니다. 예를 들어 키와 값을 한 쌍으로 묶는 클래스를 만들어 봅시다.

```cpp
template <typename K, typename V>
class Pair {
public:
    Pair(K key, V value) : key_(key), value_(value) {}

    K get_key() const { return key_; }
    V get_value() const { return value_; }

private:
    K key_;
    V value_;
};

Pair<std::string, int> score("alice", 95);
```

이렇게 두 개의 타입 매개변수를 자유롭게 조합할 수 있다는 점이 템플릿의 핵심적인 유연성입니다. 9장에서 다룬 참조나 포인터를 템플릿 매개변수와 함께 쓰는 경우도 흔합니다. 예를 들어 `T&`, `const T&`처럼 참조로 값을 받으면 큰 객체를 복사하지 않고 넘길 수 있어 성능에 도움이 됩니다.

## 다음 장을 위한 예고: STL은 전부 템플릿이다

지금까지 살펴본 `Box<T>`나 `Pair<K, V>`는 사실 여러분이 이미 알고 있는 무언가와 정확히 같은 원리로 동작합니다. 바로 14장에서 배울 `std::vector`, `std::string`, `std::map`, `std::set` 같은 **표준 템플릿 라이브러리(Standard Template Library, STL)** 컨테이너들입니다. `std::vector<int>`라는 이름을 자세히 보면 `Box<int>`와 형태가 똑같습니다. `vector`는 C++ 표준 라이브러리가 미리 만들어 둔 클래스 템플릿이고, `<int>`는 우리가 `Box<int>`를 쓸 때처럼 그 안에 담을 원소의 타입을 지정하는 부분입니다.

즉, 지금까지 8장에서 다룬 배열은 크기와 타입이 정해진 저장 공간이었지만, `std::vector<int>`는 "임의의 원소 타입을 받아 크기가 자유롭게 늘어나는 배열"을 클래스 템플릿으로 구현해 둔 것입니다. `std::map<K, V>`는 방금 만든 `Pair<K, V>`와 비슷하게 키와 값을 다루지만, 여러 쌍을 저장하고 키로 빠르게 검색할 수 있도록 훨씬 정교하게 설계되어 있습니다. 템플릿의 원리를 이해했다면, 다음 장에서 이 컨테이너들의 사용법을 배우는 일은 새로운 문법을 외우는 것이 아니라 이미 아는 개념을 실전에 적용하는 과정이 될 것입니다.

## 요약

- 같은 로직을 타입마다 복제해서 작성하는 문제를 해결하기 위해 템플릿을 사용한다.
- 함수 템플릿은 `template <typename T>`를 붙여 타입을 매개변수처럼 다루며, 호출 시 인자로부터 타입이 추론된다.
- 템플릿 인스턴스화란 컴파일러가 실제로 사용된 타입에 맞춰 코드를 생성하는 과정이다.
- 클래스 템플릿은 `Box<T>`처럼 여러 타입을 담을 수 있는 클래스를 하나의 정의로 표현하며, 타입 매개변수는 여러 개를 둘 수도 있다.
- `std::vector`, `std::string`, `std::map`, `std::set` 등 14장에서 다룰 STL 컨테이너는 모두 클래스 템플릿으로 구현되어 있다.

## 연습문제

1. `get_max` 함수 템플릿을 참고하여, 두 값 중 더 작은 값을 반환하는 `get_min` 함수 템플릿을 작성하시오.
2. `Box<T>` 클래스 템플릿에 `bool is_empty() const` 같은 멤버 함수 대신, 값이 특정 조건을 만족하는지 검사하는 `bool matches(T target) const` 멤버 함수를 추가해 보시오.
3. 타입 매개변수 세 개(`typename A, typename B, typename C`)를 받아 세 값을 저장하는 `Triple` 클래스 템플릿을 설계하고, `int`, `double`, `std::string` 조합으로 인스턴스를 만들어 보시오.
4. `template <typename T> T get_max(T a, T b)`에서 `T`에 사용자 정의 클래스(예: 10장에서 만든 클래스)를 넣으면 왜 컴파일 오류가 나는지, 그리고 이를 해결하려면 무엇이 필요한지 설명하시오. (힌트: 12장의 연산자 오버로딩과 연결된다.)
5. `Pair<K, V>` 클래스 템플릿에서 `K`와 `V`에 같은 타입을 넣는 것과 다른 타입을 넣는 것이 각각 컴파일러 입장에서 왜 서로 다른 클래스로 취급되는지 설명하시오.
