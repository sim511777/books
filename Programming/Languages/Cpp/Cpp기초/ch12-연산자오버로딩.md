# 12장. 연산자 오버로딩

---

4장에서 `+`, `-`, `==`, `<<`와 같은 연산자들이 `int`나 `double` 같은 기본 자료형에 대해 어떻게 동작하는지 살펴봤습니다. 그런데 10장에서 배운 클래스로 나만의 자료형을 만들면, 그 자료형에도 `+`나 `==` 같은 연산자를 자연스럽게 쓸 수 있을까요? C++는 이를 가능하게 해주는 **연산자 오버로딩(operator overloading)**이라는 기능을 제공합니다. 이번 장에서는 사용자 정의 타입에 연산자를 직접 정의하는 방법과, 그 과정에서 지켜야 할 원칙들을 살펴봅니다.

## 왜 연산자 오버로딩이 필요한가

2차원 벡터를 표현하는 `Vector2D` 클래스를 예로 들어 보겠습니다. 연산자 오버로딩이 없다면 두 벡터를 더하는 코드는 다음과 같이 작성해야 합니다.

```cpp
class Vector2D {
public:
    Vector2D(double x, double y) : x_(x), y_(y) {}

    double x_;
    double y_;
};

Vector2D add(const Vector2D& a, const Vector2D& b) {
    return Vector2D(a.x_ + b.x_, a.y_ + b.y_);
}

int main() {
    Vector2D v1(1.0, 2.0);
    Vector2D v2(3.0, 4.0);
    Vector2D v3 = add(v1, v2);  // v1 + v2 라고 쓸 수 없다
    return 0;
}
```

수학에서 벡터의 덧셈은 `v1 + v2`처럼 표현하는 것이 훨씬 직관적입니다. `add(v1, v2)`라는 함수 호출 문법은 틀린 것은 아니지만, 코드를 읽는 사람이 수식의 의미를 곧바로 알아차리기 어렵습니다. 연산자 오버로딩을 사용하면 `Vector2D` 타입에 대해 `+` 연산자가 어떤 의미인지 직접 정의하여, `v1 + v2`라는 자연스러운 표현을 쓸 수 있게 됩니다.

## 멤버 함수로 연산자 오버로딩하기

연산자 오버로딩은 `operator` 키워드 뒤에 연산자 기호를 붙인 특수한 이름의 함수를 정의하는 것입니다. 먼저 멤버 함수로 정의하는 방법을 살펴봅니다.

```cpp
#include <iostream>

class Vector2D {
public:
    Vector2D(double x = 0.0, double y = 0.0) : x_(x), y_(y) {}

    // 멤버 함수로 + 연산자를 오버로딩
    // *this가 왼쪽 피연산자, other가 오른쪽 피연산자에 해당한다
    Vector2D operator+(const Vector2D& other) const {
        return Vector2D(x_ + other.x_, y_ + other.y_);
    }

    // == 연산자도 멤버 함수로 오버로딩
    bool operator==(const Vector2D& other) const {
        return x_ == other.x_ && y_ == other.y_;
    }

    double x_;
    double y_;
};

int main() {
    Vector2D v1(1.0, 2.0);
    Vector2D v2(3.0, 4.0);

    Vector2D v3 = v1 + v2;  // v1.operator+(v2) 와 동일하게 동작
    std::cout << "v3 = (" << v3.x_ << ", " << v3.y_ << ")" << std::endl;

    if (v1 == Vector2D(1.0, 2.0)) {
        std::cout << "v1과 (1.0, 2.0)은 같다" << std::endl;
    }

    return 0;
}
```

`v1 + v2`라는 코드는 컴파일러에 의해 `v1.operator+(v2)`로 해석됩니다. 즉 왼쪽 피연산자(`v1`)가 멤버 함수를 호출하는 객체가 되고, 오른쪽 피연산자(`v2`)가 함수의 매개변수로 전달됩니다. `operator+`가 `const`로 선언된 것도 주목할 만합니다. 덧셈은 원본 객체를 변경하지 않고 새로운 값을 만들어내는 연산이므로, `const` 멤버 함수로 선언하는 것이 자연스럽습니다.

## 비멤버 함수(friend)로 연산자 오버로딩하기

`v1 + v2`처럼 두 피연산자가 모두 `Vector2D`라면 멤버 함수로 오버로딩해도 문제가 없습니다. 하지만 `<<` 연산자, 즉 `std::cout << v1`과 같은 출력 연산은 상황이 다릅니다. 이 식을 멤버 함수로 처리하려면 `std::ostream`(즉 `std::cout`의 타입) 쪽에 `operator<<`를 추가해야 하는데, 우리는 표준 라이브러리의 `ostream` 클래스를 수정할 수 없습니다.

이런 경우에는 **비멤버 함수**로 연산자를 오버로딩합니다. 만약 그 함수가 클래스의 `private` 멤버에 접근해야 한다면 `friend` 선언을 이용합니다.

```cpp
#include <iostream>

class Vector2D {
public:
    Vector2D(double x = 0.0, double y = 0.0) : x_(x), y_(y) {}

    Vector2D operator+(const Vector2D& other) const {
        return Vector2D(x_ + other.x_, y_ + other.y_);
    }

    // friend 선언: 이 비멤버 함수가 private 멤버에 접근할 수 있도록 허용
    friend std::ostream& operator<<(std::ostream& os, const Vector2D& v);

private:
    double x_;
    double y_;
};

// 비멤버 함수로 << 연산자를 오버로딩
// 첫 번째 매개변수가 왼쪽 피연산자(os), 두 번째가 오른쪽 피연산자(v)
std::ostream& operator<<(std::ostream& os, const Vector2D& v) {
    os << "(" << v.x_ << ", " << v.y_ << ")";
    return os;  // 연쇄 출력을 위해 os를 반환한다
}

int main() {
    Vector2D v1(1.0, 2.0);
    Vector2D v2(3.0, 4.0);
    Vector2D v3 = v1 + v2;

    // std::cout << v1 << " + " << v2 << " = " << v3 처럼 연쇄해서 쓸 수 있다
    std::cout << v1 << " + " << v2 << " = " << v3 << std::endl;

    return 0;
}
```

`operator<<`가 `std::ostream&`을 반환하는 이유는 `std::cout << v1 << " + " << v2`처럼 연산자를 연쇄적으로 사용할 수 있게 하기 위해서입니다. `os << "..."`이 반환한 `os` 자체를 다시 반환함으로써, 그 결과에 또 다른 `<<`를 적용할 수 있습니다.

여기서 `x_`, `y_`를 `private`으로 바꾸었기 때문에 `operator<<` 함수가 이 값들에 접근하려면 `friend` 선언이 필요합니다. `friend`로 선언된 함수는 클래스의 멤버가 아니지만, 그 클래스의 `private`과 `protected` 멤버에 접근할 수 있는 특별한 권한을 갖습니다.

## 멤버 함수와 비멤버 함수, 언제 무엇을 선택할까

두 방식 중 어느 쪽을 선택할지 판단하는 기준은 대체로 다음과 같습니다.

- **왼쪽 피연산자가 항상 그 클래스 타입이어야 하는 연산자**(`+=`, `[]`, `()`, `->` 등)는 보통 멤버 함수로 정의합니다.
- **왼쪽 피연산자가 다른 타입일 수 있거나, 연산의 대칭성을 유지해야 하는 경우**는 비멤버 함수가 유리합니다.

예를 들어 `Vector2D`에 스칼라를 곱하는 연산을 생각해 봅시다.

```cpp
class Vector2D {
public:
    Vector2D(double x = 0.0, double y = 0.0) : x_(x), y_(y) {}

    // v * 2.0 형태만 지원 (왼쪽이 Vector2D인 경우)
    Vector2D operator*(double scalar) const {
        return Vector2D(x_ * scalar, y_ * scalar);
    }

    double x_;
    double y_;
};

// 2.0 * v 형태를 지원하려면 비멤버 함수가 필요하다
Vector2D operator*(double scalar, const Vector2D& v) {
    return v * scalar;  // 이미 정의된 멤버 함수를 재사용
}
```

멤버 함수로만 `operator*`를 정의하면 `v * 2.0`은 가능하지만 `2.0 * v`는 불가능합니다. 왜냐하면 `2.0 * v`를 멤버 함수 호출로 해석하려면 `double`이 멤버 함수를 가진 타입이어야 하는데, `double`은 기본 자료형이라 그럴 수 없기 때문입니다. 이런 비대칭성을 없애려면 `2.0 * v` 형태는 비멤버 함수로 별도 정의해야 합니다. 이때 새로 만든 비멤버 함수 안에서 이미 정의된 멤버 함수를 재사용하면 코드 중복을 줄일 수 있습니다.

## 연산자 오버로딩을 남용하지 말아야 하는 이유

연산자 오버로딩은 강력한 도구지만, 잘못 사용하면 오히려 코드를 이해하기 어렵게 만듭니다. 다음과 같은 원칙을 기억하는 것이 좋습니다.

**첫째, 연산자의 원래 의미와 동떨어진 동작을 정의하지 않습니다.** 예를 들어 `Vector2D`의 `+` 연산자가 두 벡터를 더하는 것이 아니라 화면에 무언가를 그리는 부수 효과를 일으킨다면, 이 코드는 읽는 사람의 직관을 배반합니다. `+`를 보면 "더한다"는 결과를 기대하는 것이 자연스러운데, 그 기대와 다르게 동작하면 버그를 찾기가 매우 어려워집니다.

**둘째, 모든 연산자를 다 오버로딩할 필요는 없습니다.** `Vector2D`에 `/` 연산자(스칼라로 나누기)는 자연스럽지만, `%`(나머지) 연산자는 벡터에 대해 딱히 자연스러운 의미가 없습니다. 억지로 의미를 부여해서 오버로딩하기보다는, 필요한 연산만 정의하고 나머지는 그냥 함수로 표현하는 것이 낫습니다.

**셋째, 값을 바꾸지 않는 연산자는 `const`로, 원본을 반환해야 하는 연산자는 참조를 반환하도록 일관성을 지킵니다.** 예를 들어 `==`나 `+`처럼 새로운 값을 만들어내는 연산자는 원본 객체를 변경하지 않아야 하므로 `const` 멤버 함수로 선언하고, `<<`나 `+=`처럼 스트림이나 자기 자신을 반환해 연쇄 호출을 지원해야 하는 연산자는 참조를 반환합니다.

```cpp
class Vector2D {
public:
    Vector2D(double x = 0.0, double y = 0.0) : x_(x), y_(y) {}

    // += 는 자기 자신을 변경하고, 그 참조를 반환한다
    Vector2D& operator+=(const Vector2D& other) {
        x_ += other.x_;
        y_ += other.y_;
        return *this;  // 연쇄 호출(v1 += v2 += v3)을 위해 자신의 참조를 반환
    }

    double x_;
    double y_;
};
```

**넷째, 비교 연산자(`==`, `!=`, `<` 등)를 오버로딩할 때는 서로 논리적으로 일관되게 만듭니다.** `a == b`가 참이면서 `a != b`도 참인 것처럼 모순된 결과가 나오지 않도록 주의해야 합니다. 보통은 `operator==`를 먼저 정의하고, `operator!=`는 `return !(a == b);`처럼 이를 이용해 구현하면 일관성을 유지하기 쉽습니다.

정리하면, 연산자 오버로딩은 "이 타입에 이 연산자를 쓰면 누구나 당연히 이런 의미일 것이다"라고 예상할 수 있는 경우에만 사용하는 것이 좋습니다. 코드의 가독성을 높이기 위한 도구가 오히려 가독성을 해치는 함정이 되지 않도록 늘 신중하게 판단해야 합니다.

## 요약

이번 장에서는 사용자 정의 타입에 `+`, `==`, `<<`와 같은 연산자의 동작을 직접 정의하는 연산자 오버로딩을 배웠습니다. `operator+`처럼 `operator` 키워드와 연산자 기호를 조합한 이름의 함수를 정의하면 되며, 멤버 함수로 정의할 때는 왼쪽 피연산자가 암묵적으로 `*this`가 됩니다. `<<` 연산자처럼 왼쪽 피연산자가 클래스 타입이 아니거나 대칭적인 연산이 필요한 경우에는 비멤버 함수(필요하면 `friend`)로 오버로딩하는 것이 적절합니다. `Vector2D` 예제를 통해 `+`와 `<<`를 각각 멤버 함수와 비멤버 함수로 오버로딩하는 방법을 살펴보았고, 연쇄 호출을 위해 참조를 반환하는 패턴도 확인했습니다. 마지막으로 연산자의 직관적인 의미를 벗어나지 않는 것, 불필요한 연산자까지 억지로 오버로딩하지 않는 것, `const`와 반환 타입의 일관성을 지키는 것이 좋은 연산자 오버로딩 설계의 핵심 원칙임을 정리했습니다.

## 연습문제

1. `Vector2D` 클래스에 `operator-`(두 벡터의 차)와 `operator!=`를 추가해 보세요. `operator!=`는 이미 정의한 `operator==`를 재사용해서 구현해 보세요.

2. `Fraction`(분수)이라는 클래스를 만들어 분자와 분모를 멤버로 가지도록 하고, `operator+`, `operator*`, 그리고 `operator<<`를 오버로딩해 두 분수를 더하고 곱한 결과를 화면에 출력해 보세요.

3. `Vector2D operator*(double scalar, const Vector2D& v)`처럼 비멤버 함수로 정의해야만 하는 이유를 멤버 함수만으로 시도했을 때 발생하는 컴파일 오류를 직접 확인하며 설명해 보세요.

4. `operator++`(전위 증가와 후위 증가)를 오버로딩하려면 두 가지를 어떻게 구분해서 선언해야 하는지 조사해 보고, 정수를 감싸는 간단한 `Counter` 클래스에 이를 구현해 보세요.

5. 연산자 오버로딩을 남용한 예시 코드를 하나 스스로 작성해 보세요(예: `+` 연산자가 실제로는 뺄셈을 수행하는 코드). 그 코드를 읽는 다른 사람이 어떤 혼란을 겪을 수 있는지 설명하고, 어떻게 고쳐야 할지 제안해 보세요.
