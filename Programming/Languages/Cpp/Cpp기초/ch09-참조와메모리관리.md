# 9장. 참조와 메모리 관리(RAII)

---

8장에서는 포인터를 이용해 메모리 주소를 직접 다루는 방법을 배웠습니다. 이번 장에서는 포인터와 비슷하지만 훨씬 안전하게 사용할 수 있는 **참조(reference)**를 소개하고, `new`와 `delete`로 힙 메모리를 직접 관리할 때 생기는 문제, 그리고 그 문제를 해결하는 철학인 **RAII**를 다룹니다. RAII는 15장에서 배울 스마트 포인터의 이론적 기반이 되므로, 이 장의 내용을 잘 이해해 두면 이후 학습이 훨씬 쉬워집니다.

## 9.1 참조란 무엇인가

참조는 이미 존재하는 변수에 붙이는 또 다른 이름이라고 생각하면 됩니다. `&` 기호를 사용해 선언하지만, 8장에서 배운 포인터의 `&`(주소 연산자)와는 문법적 위치가 다릅니다.

```cpp
int original_value = 10;
int& ref_to_value = original_value;  // original_value의 또 다른 이름

ref_to_value = 20;  // original_value도 20으로 바뀐다
std::cout << original_value << '\n';  // 20 출력
```

`ref_to_value`는 `original_value`와 완전히 같은 메모리 공간을 가리키는 별명입니다. 둘 중 하나를 바꾸면 다른 하나도 함께 바뀝니다. 내부적으로 컴파일러는 참조를 포인터와 비슷한 방식으로 구현하지만, 프로그래머가 사용하는 문법은 일반 변수처럼 자연스럽습니다.

## 9.2 참조와 포인터의 차이

8장에서 배운 포인터와 참조는 자주 혼동되지만, 다음과 같은 중요한 차이가 있습니다.

| 특징 | 포인터 | 참조 |
|---|---|---|
| null 가능 여부 | 가능 (`nullptr`) | 불가능 |
| 초기화 없이 선언 | 가능 | 불가능 (반드시 초기화) |
| 재대입(다른 대상 가리키기) | 가능 | 불가능 |
| 역참조 문법 | `*ptr` 필요 | 불필요 (그냥 사용) |
| 주소 연산 | `ptr + 1` 등 가능 | 불가능 |

```cpp
int a = 1;
int b = 2;

int* ptr = &a;
ptr = &b;  // 포인터는 가리키는 대상을 바꿀 수 있다

int& ref = a;
// ref = b;  // 이 코드는 재대입이 아니라 a에 b의 값을 "복사"하는 것!
```

주의할 점은 `ref = b;`가 참조를 `b`로 바꾸는 것이 아니라, `ref`가 가리키던 `a`에 `b`의 값을 대입한다는 것입니다. 참조는 한 번 어떤 변수에 묶이면 프로그램이 끝날 때까지 그 변수를 떠날 수 없습니다. 이 제약 덕분에 참조는 포인터보다 실수할 여지가 적고, "이 참조는 항상 유효한 대상을 가리킨다"는 것을 코드만 보고 신뢰할 수 있습니다.

## 9.3 함수에 참조 전달하기

참조의 가장 흔한 용도는 함수 매개변수입니다. 7장에서 함수를 배울 때 매개변수는 기본적으로 값이 복사되어 전달된다고 했습니다. 참조를 매개변수로 사용하면 복사 없이 원본 변수를 직접 조작할 수 있습니다.

```cpp
// 값으로 전달: 원본은 바뀌지 않는다
void try_increase(int value) {
    value += 1;
}

// 참조로 전달: 원본이 바뀐다
void increase(int& value) {
    value += 1;
}

int main() {
    int number = 5;
    try_increase(number);
    std::cout << number << '\n';  // 5 (변화 없음)

    increase(number);
    std::cout << number << '\n';  // 6 (원본이 바뀜)
}
```

두 개 이상의 값을 함수에서 동시에 돌려주고 싶을 때도 참조가 유용합니다.

```cpp
// 나눗셈의 몫과 나머지를 동시에 구해서 돌려준다
void divide(int dividend, int divisor, int& quotient, int& remainder) {
    quotient = dividend / divisor;
    remainder = dividend % divisor;
}

int main() {
    int q = 0;
    int r = 0;
    divide(17, 5, q, r);
    std::cout << "몫: " << q << ", 나머지: " << r << '\n';  // 몫: 3, 나머지: 2
}
```

큰 객체를 함수에 넘길 때 복사 비용을 줄이려면 `const` 참조를 사용합니다. `const int&`처럼 선언하면 원본을 바꾸지 않겠다고 약속하면서도 복사를 피할 수 있습니다. 이 패턴은 10장에서 클래스 객체를 함수에 전달할 때 특히 중요해집니다.

```cpp
void print_report(const std::string& title) {
    std::cout << title << '\n';
    // title = "변경";  // 컴파일 오류: const 참조는 수정할 수 없다
}
```

## 9.4 동적 메모리 할당: new와 delete

지금까지 사용한 변수들은 대부분 함수가 실행되는 동안만 존재하는 **스택(stack)** 메모리에 자동으로 생성되고 사라졌습니다. 하지만 프로그램이 실행되는 도중에 크기가 결정되거나, 함수가 끝나도 계속 살아있어야 하는 데이터가 필요할 때는 **힙(heap)** 메모리를 사용합니다. C++에서는 `new`로 힙에 메모리를 할당하고 `delete`로 해제합니다.

```cpp
int* dynamic_number = new int(42);   // 힙에 int 하나를 할당하고 42로 초기화
std::cout << *dynamic_number << '\n';
delete dynamic_number;               // 사용이 끝나면 반드시 해제

int* dynamic_array = new int[5];     // 힙에 int 5개짜리 배열 할당
for (int i = 0; i < 5; ++i) {
    dynamic_array[i] = i * i;
}
delete[] dynamic_array;              // 배열은 delete[]로 해제해야 한다
```

`new`로 할당한 메모리는 스코프(중괄호 블록)가 끝나도 자동으로 사라지지 않습니다. 프로그래머가 직접 `delete`를 호출해야만 메모리가 운영체제에 반환됩니다. 배열을 할당할 때는 `new[]`와 `delete[]`를 짝지어 사용해야 하며, `new`와 `delete[]`, 또는 `new[]`와 `delete`를 섞어 쓰면 정의되지 않은 동작이 발생합니다.

## 9.5 메모리 누수 문제

`delete`를 잊어버리면 어떻게 될까요? 그 메모리는 프로그램이 종료될 때까지 계속 점유된 채로 남습니다. 이를 **메모리 누수(memory leak)**라고 부릅니다.

```cpp
void leaky_function() {
    int* data = new int[1000];
    // data를 사용하는 코드...

    if (/* 어떤 조건 */ true) {
        return;  // delete data를 호출하지 않고 함수를 빠져나간다!
    }

    delete[] data;  // 이 줄은 실행되지 않을 수 있다
}
```

이 함수가 반복적으로 호출되면 프로그램은 점점 더 많은 메모리를 소모하다가 결국 시스템 자원이 부족해질 수 있습니다. 더 심각한 문제는 예외가 발생하는 경우입니다. `delete`를 호출하기 전에 예외가 던져지면(예외 처리는 16장에서 자세히 다룹니다), 그 아래에 있는 `delete` 코드는 절대 실행되지 않습니다.

```cpp
void risky_function() {
    Resource* res = new Resource();
    do_something_that_might_throw();  // 여기서 예외가 발생하면?
    delete res;  // 이 줄까지 도달하지 못한다 -> 누수!
}
```

수동으로 `delete`를 호출하는 방식은 이런 실수를 근본적으로 막을 수 없습니다. 조건문, 여러 개의 `return`, 예외 상황 등 프로그램의 흐름이 복잡해질수록 `delete`를 빠뜨릴 위험은 커집니다.

## 9.6 RAII: 자원 획득은 초기화다

이 문제를 해결하는 C++의 핵심 철학이 **RAII(Resource Acquisition Is Initialization)**입니다. 발상은 단순합니다. "자원을 다 쓰고 나서 수동으로 정리하지 말고, 자원을 소유한 객체가 사라질 때 자동으로 정리되게 만들자"는 것입니다.

10장에서 배우겠지만, 클래스에는 객체가 생성될 때 호출되는 **생성자**와, 객체가 스코프를 벗어나 사라질 때 자동으로 호출되는 **소멸자**가 있습니다. RAII는 자원(동적으로 할당한 메모리, 파일 핸들, 네트워크 연결 등)을 생성자에서 획득하고, 소멸자에서 해제하는 패턴입니다.

```cpp
class IntBuffer {
public:
    // 생성자: 객체가 만들어질 때 자원을 획득한다
    explicit IntBuffer(int size) : data_(new int[size]), size_(size) {
        std::cout << "버퍼 " << size_ << "개 할당\n";
    }

    // 소멸자: 객체가 사라질 때 자원을 자동으로 해제한다
    ~IntBuffer() {
        delete[] data_;
        std::cout << "버퍼 해제\n";
    }

    int& at(int index) { return data_[index]; }

private:
    int* data_;
    int size_;
};

void use_buffer() {
    IntBuffer buffer(10);   // 생성자가 자동 호출된다
    buffer.at(0) = 100;
    // ... 이 함수가 끝나면 소멸자가 자동으로 호출되어 delete[]가 실행된다
}
```

`use_buffer` 함수가 `return`을 여러 번 하거나 예외를 던지더라도, `buffer` 객체가 스코프를 벗어나는 순간 소멸자는 **반드시** 호출됩니다. 이것이 RAII의 강력함입니다. 자원 해제를 프로그래머의 기억력에 맡기지 않고, 언어의 스코프 규칙에 맡기는 것입니다.

물론 매번 이런 클래스를 직접 만드는 것은 번거롭습니다. 그래서 표준 라이브러리는 이미 RAII 원칙을 구현한 도구들을 제공합니다. 15장에서 배울 `std::unique_ptr`와 `std::shared_ptr`가 바로 그것으로, `new`/`delete`를 직접 호출하지 않고도 RAII의 안전함을 그대로 누릴 수 있게 해줍니다.

## 9.7 스택과 힙, 다시 정리하기

지금까지 나온 스택과 힙의 차이를 그림으로 정리하면 다음과 같습니다.

```text
                      스택(Stack)과 힙(Heap) 메모리

  +----------------------------+       +----------------------------+
  |         스택 영역           |       |          힙 영역             |
  | 함수 호출과 함께 자동 생성/소멸 |       | new로 할당, delete로 해제      |
  |                            |       |                            |
  | +------------------------+ |       | +------------------------+ |
  | | main() 함수 프레임        | |       | | new int[5]로 할당된 블록  | |
  | | int number = 5;         | |       | | [0][1][2][3][4]         | |
  | | int& ref = number;      | |       | | delete[] 호출 전까지      | |
  | +------------------------+ |       | | 계속 존재                | |
  |                            |       | +------------------------+ |
  | +------------------------+ |       |                            |
  | | use_buffer() 함수 프레임  | |------>| +------------------------+ |
  | | int* dynamic_array      | |  가리킴 | | delete[]를 잊으면        | |
  | | (힙 주소를 저장)          | |       | | 메모리 누수 발생 (점선)    | |
  | +------------------------+ |       | +------------------------+ |
  |            |               |       |                            |
  |            v                |       |                            |
  |   호출될수록 아래로 쌓임        |       |                            |
  |                            |       |                            |
  |   스코프 종료 시 자동 해제       |       |   프로그래머(또는 RAII 객체)가|
  |   (별도의 delete 불필요)      |       |   직접 해제 책임을 짐          |
  +----------------------------+       +----------------------------+
```

스택은 함수 호출과 함께 자동으로 쌓이고 함수가 끝나면 자동으로 정리되는 영역입니다. 지역 변수, 매개변수, 참조가 여기에 놓입니다. 반면 힙은 `new`로 요청할 때만 할당되고, `delete`로 명시적으로 반환하기 전까지(혹은 RAII 객체의 소멸자가 대신 반환할 때까지) 계속 남아 있는 영역입니다. 스택은 크기가 작고 접근이 빠르지만 프로그램이 끝날 때까지 살아있어야 하는 큰 데이터에는 적합하지 않고, 힙은 크기 제약이 적지만 관리 책임이 프로그래머(또는 RAII 객체)에게 있습니다.

## 요약

- 참조는 기존 변수에 붙이는 별명으로, 포인터와 달리 null이 될 수 없고 초기화 후 다른 대상으로 재대입할 수 없습니다.
- 함수 매개변수를 참조로 선언하면 복사 없이 원본을 수정할 수 있고, 여러 값을 동시에 돌려줄 수 있습니다. 수정할 필요가 없다면 `const` 참조로 복사 비용만 줄일 수 있습니다.
- `new`/`delete`, `new[]`/`delete[]`는 힙 메모리를 직접 할당하고 해제합니다. 짝을 맞추지 않으면 정의되지 않은 동작이 발생합니다.
- `delete`를 빠뜨리면 메모리 누수가 발생하며, 복잡한 흐름(조건문, 예외)일수록 실수하기 쉽습니다.
- RAII는 생성자에서 자원을 획득하고 소멸자에서 자원을 해제해, 스코프가 끝나는 순간 자원 해제가 자동으로 보장되게 하는 원칙입니다.
- 15장에서 배울 스마트 포인터는 RAII를 이미 구현해 둔 표준 라이브러리 도구입니다.

## 연습문제

1. 참조와 포인터의 차이를 세 가지 이상 설명하고, 각각 어떤 상황에서 참조를 선택해야 하는지 예를 들어보세요.
2. 두 정수 변수의 값을 서로 바꾸는 함수 `void swap_values(int& a, int& b)`를 작성하세요.
3. `new`로 할당한 `double` 배열을 사용하는 함수를 작성하되, 함수 중간에서 특정 조건일 때 `return`으로 빠져나가도 메모리 누수가 발생하지 않도록 코드를 구성해보세요. (힌트: 모든 `return` 경로 앞에서 `delete[]`를 호출하거나, RAII 클래스로 감싸보세요.)
4. 소멸자에서 "자원 해제됨"이라는 메시지를 출력하는 간단한 RAII 클래스 `FileGuard`를 설계해보세요. 생성자에서는 "자원 획득됨"을 출력합니다. 이 클래스의 객체가 스코프를 벗어날 때 메시지가 어떤 순서로 출력되는지 예측해보고 실제로 확인해보세요.
5. 스택 메모리와 힙 메모리 중 어느 쪽이 다음 상황에 더 적합할지 판단하고 이유를 설명하세요: (a) 함수 안에서만 쓰이는 임시 정수 하나, (b) 사용자가 입력한 개수만큼 만들어야 하는 배열, (c) 함수가 끝난 뒤에도 다른 함수에서 계속 사용해야 하는 데이터.
