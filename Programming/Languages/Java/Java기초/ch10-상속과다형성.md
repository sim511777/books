# 10장. 상속과 다형성

---

9장에서는 `BankAccount`처럼 하나의 클래스로 필드와 메서드를 묶는 방법을 배웠습니다. 그런데 실제 프로그램에서는 "일반 계좌"와 "적금 계좌"처럼 서로 비슷하면서도 조금씩 다른 클래스들을 여러 개 만들어야 하는 경우가 많습니다. 이럴 때 매번 클래스를 처음부터 새로 작성하면 중복 코드가 늘어납니다. 자바는 이 문제를 **상속(inheritance)**으로 해결하며, 상속을 잘 활용하면 **다형성(polymorphism)**이라는 강력한 개념도 함께 얻을 수 있습니다.

## 10.1 상속: extends로 기존 클래스 확장하기

상속은 이미 존재하는 클래스의 필드와 메서드를 물려받아 새로운 클래스를 만드는 방법입니다. 물려주는 클래스를 **부모 클래스(상위 클래스, superclass)**, 물려받는 클래스를 **자식 클래스(하위 클래스, subclass)**라 부릅니다.

```java
// 부모 클래스
public class Animal {
    protected String name;

    public Animal(String name) {
        this.name = name;
    }

    public void eat() {
        System.out.println(name + "이(가) 먹이를 먹습니다.");
    }

    public void makeSound() {
        System.out.println(name + "이(가) 소리를 냅니다.");
    }
}
```

```java
// 자식 클래스: Animal을 확장
public class Dog extends Animal {
    public Dog(String name) {
        super(name);   // 부모의 생성자를 호출
    }

    public void fetch() {
        System.out.println(name + "이(가) 공을 물어옵니다.");
    }
}
```

`Dog`는 `Animal`을 `extends`했으므로 `eat()` 메서드를 새로 작성하지 않아도 그대로 사용할 수 있고, 여기에 `fetch()`라는 자신만의 메서드를 추가로 가집니다.

```java
Dog dog = new Dog("바둑이");
dog.eat();        // Animal로부터 물려받은 메서드
dog.fetch();       // Dog에만 있는 메서드
```

필드 `name`은 9장에서 `private`으로 선언했다면 자식 클래스에서 직접 접근할 수 없습니다. 그래서 자식 클래스에서도 쓸 수 있게 하려면 `protected`로 선언합니다. `protected`는 같은 패키지뿐 아니라 다른 패키지의 자식 클래스에서도 접근을 허용하는 접근 제한자였음을 9장에서 다뤘습니다.

자바는 클래스가 부모를 하나만 가질 수 있는 **단일 상속**만 지원합니다. 여러 타입의 능력을 동시에 갖고 싶을 때는 11장에서 배울 인터페이스를 함께 사용합니다.

## 10.2 super 키워드

`super`는 `this`가 자기 자신을 가리키듯, **부모 클래스**를 가리키는 키워드입니다. 두 가지 상황에서 주로 사용합니다.

**첫째, 부모의 생성자를 호출할 때.** 자식 클래스의 생성자는 첫 줄에서 `super(...)`를 호출해 부모의 초기화를 먼저 수행할 수 있습니다. 만약 `super(...)`를 명시하지 않으면 자바는 자동으로 부모의 매개변수 없는 생성자를 호출하려 시도하는데, 부모에 그런 생성자가 없으면 컴파일 오류가 발생합니다.

**둘째, 부모의 메서드를 호출할 때.** 자식 클래스에서 부모의 메서드를 재정의했더라도, 부모의 원래 동작이 필요하면 `super.메서드이름()`으로 호출할 수 있습니다.

```java
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public void makeSound() {
        super.makeSound();               // 부모의 동작을 먼저 실행
        System.out.println("멍멍!");      // 자식만의 동작을 추가
    }
}
```

## 10.3 메서드 오버라이딩과 @Override

부모 클래스에 정의된 메서드를 자식 클래스에서 **같은 이름, 같은 매개변수 목록**으로 다시 정의하는 것을 **오버라이딩(overriding)**이라 합니다. 8장에서 배운 오버로드(overload)는 매개변수 목록을 다르게 하여 이름만 같은 별개의 메서드를 여러 개 만드는 것이었고, 오버라이딩은 부모의 메서드를 자식이 새로운 내용으로 덮어쓰는 것이므로 서로 다른 개념입니다.

```java
public class Cat extends Animal {
    public Cat(String name) {
        super(name);
    }

    @Override
    public void makeSound() {
        System.out.println(name + "이(가) 야옹 하고 웁니다.");
    }
}
```

메서드 위에 붙인 `@Override`는 **애너테이션(annotation)**으로, "이 메서드는 부모의 메서드를 재정의하는 것이다"라고 컴파일러에게 알려줍니다. 이 표시가 없어도 오버라이딩 자체는 동작하지만, `@Override`를 붙이면 메서드 이름이나 매개변수를 잘못 적었을 때 컴파일러가 오류로 알려주므로 실수를 예방할 수 있습니다. 오버라이딩할 때는 부모 메서드보다 접근 범위를 더 좁게 만들 수 없다는 규칙도 기억해 두세요. 예를 들어 부모가 `public`이면 자식도 `public`이어야 합니다.

## 10.4 다형성: 부모 타입으로 자식 객체를 다루기

**다형성**은 "같은 타입의 참조 변수로 서로 다른 실제 동작을 이끌어낼 수 있다"는 성질입니다. 자바에서는 부모 클래스 타입의 변수에 자식 클래스의 객체를 담을 수 있습니다.

```java
Animal a1 = new Dog("바둑이");
Animal a2 = new Cat("나비");

a1.makeSound();   // "바둑이이(가) ... 멍멍!" — Dog의 오버라이딩 버전이 실행됨
a2.makeSound();   // "나비이(가) 야옹 하고 웁니다." — Cat의 오버라이딩 버전이 실행됨
```

`a1`과 `a2`는 둘 다 `Animal` 타입으로 선언되었지만, 실제로 `makeSound()`를 호출하면 각 객체가 실제로 어떤 클래스로 만들어졌는지에 따라 **오버라이딩된 메서드**가 실행됩니다. 이를 활용하면 배열이나 컬렉션에 부모 타입으로 여러 종류의 자식 객체를 함께 담아 반복 처리할 수 있습니다.

```java
Animal[] animals = { new Dog("바둑이"), new Cat("나비"), new Dog("초코") };

for (Animal a : animals) {
    a.eat();
    a.makeSound();
}
```

이 반복문은 `animals` 배열에 어떤 동물이 들어있는지 전혀 신경 쓰지 않고, 단지 "Animal이라면 eat과 makeSound를 할 수 있다"는 사실만 믿고 코드를 작성합니다. 나중에 `Bird` 클래스를 추가하더라도 이 반복문 코드는 전혀 수정할 필요가 없습니다. 이것이 다형성이 주는 가장 큰 이점이며, 7장에서 배운 배열과 8장의 메서드를 객체지향적으로 확장한 형태라 할 수 있습니다.

## 10.5 instanceof와 다운캐스팅

부모 타입 변수에는 부모 클래스에 정의된 멤버만 접근할 수 있습니다. 앞선 예제의 `a1`은 실제로는 `Dog` 객체를 담고 있지만, `Animal` 타입으로 선언되었기 때문에 `Dog`에만 있는 `fetch()`는 바로 호출할 수 없습니다.

```java
Animal a1 = new Dog("바둑이");
a1.fetch();   // 컴파일 오류! Animal에는 fetch가 없음
```

이럴 때는 **다운캐스팅(down-casting)**으로 실제 타입을 명시해 접근합니다.

```java
if (a1 instanceof Dog) {
    Dog dog = (Dog) a1;   // Animal 타입을 Dog 타입으로 형 변환
    dog.fetch();
}
```

`instanceof`는 참조 변수가 실제로 가리키는 객체가 특정 클래스(또는 그 자손)의 인스턴스인지 검사하는 연산자입니다. 검사 없이 다운캐스팅했다가 실제 타입이 맞지 않으면 실행 중에 `ClassCastException`이 발생하므로, 항상 `instanceof`로 먼저 확인하는 습관이 안전합니다. 이런 실행 중 오류는 12장에서 배울 예외 처리와 함께 다루면 더 견고한 코드를 작성할 수 있습니다.

자바 16 이상에서는 패턴 매칭 문법으로 검사와 형 변환을 한 줄로 줄일 수도 있습니다.

```java
if (a1 instanceof Dog dog) {
    dog.fetch();
}
```

## 10.6 다형성 활용 예제: 도형 그리기

다형성이 실제로 유용한 상황을 좀 더 살펴보겠습니다. 여러 종류의 도형이 각자 다른 방식으로 넓이를 계산하는 예제입니다.

```java
public class Shape {
    protected String name;

    public Shape(String name) {
        this.name = name;
    }

    public double getArea() {
        return 0.0;   // 기본값, 자식 클래스가 반드시 재정의
    }

    public void printInfo() {
        System.out.println(name + "의 넓이: " + getArea());
    }
}

public class Circle extends Shape {
    private double radius;

    public Circle(double radius) {
        super("원");
        this.radius = radius;
    }

    @Override
    public double getArea() {
        return Math.PI * radius * radius;
    }
}

public class Rectangle extends Shape {
    private double width;
    private double height;

    public Rectangle(double width, double height) {
        super("사각형");
        this.width = width;
        this.height = height;
    }

    @Override
    public double getArea() {
        return width * height;
    }
}
```

```java
Shape[] shapes = { new Circle(3.0), new Rectangle(4.0, 5.0) };

double total = 0;
for (Shape s : shapes) {
    s.printInfo();      // 각 도형에 맞는 getArea()가 자동으로 호출됨
    total += s.getArea();
}
System.out.println("전체 넓이 합계: " + total);
```

`printInfo()`는 `Shape` 클래스에 딱 한 번만 작성했지만, 내부에서 호출하는 `getArea()`는 실행 시점에 실제 객체(`Circle` 또는 `Rectangle`)의 오버라이딩된 버전으로 실행됩니다. 새로운 도형(`Triangle` 등)을 추가하고 싶다면 `Shape`를 상속하는 클래스 하나만 더 작성하면 되고, `printInfo()`나 반복문 코드는 그대로 재사용됩니다.

## 10.7 final 클래스와 final 메서드

`final` 키워드를 클래스나 메서드에 붙이면 상속과 오버라이딩을 제한할 수 있습니다.

```java
public final class ImmutablePoint {
    // 이 클래스는 더 이상 상속할 수 없음
}
```

```java
public class Shape {
    public final void printInfo() {
        // 자식 클래스가 이 메서드를 오버라이딩할 수 없음
    }
}
```

클래스에 `final`을 붙이면 그 클래스를 부모로 삼는 자식 클래스를 만들 수 없습니다. 대표적으로 자바 표준 라이브러리의 `String` 클래스가 `final`로 선언되어 있어, 문자열의 동작이 예기치 않게 변경될 위험이 없습니다. 메서드에 `final`을 붙이면 그 메서드만 오버라이딩을 금지할 수 있는데, 핵심 로직이 자식 클래스에서 실수로 덮어써지는 것을 막고 싶을 때 사용합니다. 다형성을 적극적으로 활용하는 설계와, `final`로 특정 동작을 고정하는 설계는 상황에 맞게 균형을 잡아야 하는 선택입니다.

## 요약

- `extends`로 상속을 선언하면 자식 클래스가 부모 클래스의 필드와 메서드를 물려받고, 자신만의 멤버를 추가로 정의할 수 있습니다.
- `super`는 부모의 생성자나 메서드를 명시적으로 호출할 때 사용하며, 자식 생성자의 첫 줄에서 `super(...)`로 부모 초기화를 수행하는 것이 일반적입니다.
- 메서드 오버라이딩은 부모의 메서드를 같은 시그니처로 재정의하는 것이며, `@Override` 애너테이션으로 실수를 방지할 수 있습니다. 매개변수를 다르게 하는 오버로드와는 구분되는 개념입니다.
- 다형성은 부모 타입의 참조 변수(또는 배열)로 서로 다른 자식 객체를 다루면서도, 실제 실행되는 메서드는 각 객체의 실제 타입에 따라 결정되는 성질입니다.
- `instanceof`로 실제 타입을 확인한 뒤 다운캐스팅해야 자식 클래스의 고유 멤버에 접근할 수 있고, 확인 없이 캐스팅하면 `ClassCastException`의 위험이 있습니다.
- `final` 클래스는 상속을 금지하고, `final` 메서드는 오버라이딩을 금지합니다.

이 장에서 배운 상속과 다형성은 객체지향 설계의 중심축입니다. 다음 11장에서는 구현이 전혀 없는 순수한 규약인 인터페이스와, 일부만 구현된 추상 클래스를 살펴보며 "여러 클래스가 같은 계약을 지키게 만드는 방법"을 더 깊이 다룹니다.
