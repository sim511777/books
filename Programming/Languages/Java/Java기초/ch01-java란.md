# 1장. Java란 무엇인가

## 들어가며

프로그래밍을 처음 배우기로 마음먹었다면 가장 먼저 마주치는 질문은 "어떤 언어로 시작할까"입니다. 이 책은 Java를 선택했습니다. Java는 1995년 처음 발표된 이후 지금까지도 은행 시스템, 쇼핑몰 서버, 안드로이드 앱, 대규모 데이터 처리 시스템 등 현업 곳곳에서 쓰이고 있는 언어입니다. 오래된 언어라고 해서 낡은 언어라는 뜻은 아닙니다. Java는 매년 새 버전이 나오면서 계속 다듬어지고 있고, 문법이 명확하고 규칙이 엄격해서 "왜 이렇게 동작하는지"를 이해하기 좋은 언어이기도 합니다. 이 장에서는 본격적으로 코드를 작성하기 전에, Java가 어떤 원리로 동작하는 언어인지, 어디에 쓰이는지, 그리고 학습 환경을 어떻게 준비하는지 살펴봅니다.

## JVM 기반 언어라는 특징

Java 코드를 이해하려면 먼저 **JVM(Java Virtual Machine, 자바 가상 머신)**이라는 개념을 알아야 합니다. 대부분의 프로그래밍 언어는 소스 코드를 컴파일해서 특정 운영체제와 CPU에서 바로 실행되는 기계어로 만듭니다. 하지만 Java는 한 단계를 더 거칩니다. Java 소스 코드(`.java` 파일)는 `javac`라는 컴파일러를 거쳐 **바이트코드(bytecode)**라는 중간 형태(`.class` 파일)로 변환되고, 이 바이트코드는 실제 기계어가 아니라 JVM이라는 가상의 컴퓨터가 이해하는 명령어입니다.

실행할 때는 각 운영체제(Windows, macOS, Linux 등)에 맞게 만들어진 JVM이 이 바이트코드를 해석하고 실제 CPU가 이해할 수 있는 명령으로 옮겨줍니다. 즉 Java 프로그램은 운영체제를 직접 상대하지 않고, 항상 JVM이라는 중간 관리자를 거쳐서 실행됩니다. 이 구조가 만들어내는 결과가 바로 다음 절에서 설명할 플랫폼 독립성입니다. 소스 코드가 바이트코드로, 바이트코드가 JVM 위에서 실행되는 전체 흐름은 2장에서 그림과 함께 자세히 다룹니다.

## "Write Once, Run Anywhere" — 플랫폼 독립성

Java를 소개할 때 가장 자주 인용되는 문구가 "Write Once, Run Anywhere(한 번 작성하면 어디서든 실행된다)"입니다. C나 C++로 작성한 프로그램은 Windows용으로 컴파일한 실행 파일을 macOS에서 그대로 실행할 수 없습니다. 운영체제와 CPU 구조에 맞춰 다시 컴파일해야 합니다. 반면 Java는 `.class` 파일 하나만 있으면, 그 파일을 실행할 JVM이 설치된 어떤 환경에서도 똑같이 동작합니다. Windows에서 컴파일한 `.class` 파일을 Linux 서버에 그대로 올려서 실행해도 문제가 없습니다.

이것이 가능한 이유는 앞서 설명한 JVM의 역할 때문입니다. 운영체제마다 다른 JVM 구현체가 존재하고, 각 JVM이 자신의 환경에 맞게 바이트코드를 해석해주기 때문에 개발자는 "어떤 운영체제에서 실행될지"를 크게 신경 쓰지 않고 코드를 작성할 수 있습니다. 물론 완벽히 모든 차이를 감춰주는 것은 아니지만(파일 경로 구분자처럼 운영체제마다 다른 부분은 여전히 존재합니다), 핵심 실행 로직에 대해서는 이식성을 상당히 보장해줍니다. 이런 특징 덕분에 Java는 서로 다른 서버 환경을 오가는 엔터프라이즈 시스템에서 특히 신뢰받는 언어가 되었습니다.

## 정적 타입 객체지향 언어

Java는 **정적 타입(static typing)** 언어입니다. 변수를 선언할 때 그 변수가 담을 데이터의 자료형을 명시해야 하고, 컴파일 시점에 타입이 맞는지 검사합니다. 예를 들어 정수를 담는 변수에 문자열을 대입하려고 하면 프로그램을 실행하기도 전에 컴파일 오류로 알려줍니다. 이는 Python처럼 실행하면서 타입을 확인하는 동적 타입 언어와 대비되는 특징으로, 초보자에게는 다소 엄격하게 느껴질 수 있지만 실수를 일찍 발견하게 해준다는 장점이 있습니다. 자료형에 대한 구체적인 내용은 3장 변수와 자료형에서 다룹니다.

또한 Java는 **객체지향(object-oriented)** 언어입니다. 프로그램을 구성하는 기본 단위가 데이터와 그 데이터를 다루는 동작을 하나로 묶은 **객체(object)**이며, 객체는 **클래스(class)**라는 틀을 바탕으로 만들어집니다. 이 책의 중반부인 9장부터는 클래스와 객체, 10장의 상속(inheritance), 11장의 인터페이스(interface) 등 객체지향의 핵심 개념을 차례로 다룹니다. 지금 단계에서는 "Java 프로그램은 여러 객체들이 서로 메시지를 주고받으며 동작하는 구조"라는 큰 그림만 기억해두면 충분합니다.

## Java는 어디에 쓰이는가

Java의 활용 분야를 이해하면 왜 이 언어를 배울 가치가 있는지 체감할 수 있습니다.

- **엔터프라이즈 백엔드 시스템**: 금융, 물류, 이커머스 등 대규모 기업 시스템의 서버 쪽 로직은 여전히 Java(그리고 Spring 같은 Java 기반 프레임워크)로 많이 작성됩니다. 안정성, 성능, 풍부한 라이브러리 생태계가 그 이유입니다.
- **안드로이드 앱 개발**: 안드로이드는 원래 Java를 표준 개발 언어로 채택했습니다. 최근에는 Kotlin이 권장 언어로 자리잡았지만, Kotlin 역시 JVM 위에서 동작하고 Java 코드와 자유롭게 섞어 쓸 수 있기 때문에 Java 문법을 알면 안드로이드 개발 진입 장벽이 크게 낮아집니다.
- **대규모 데이터 처리와 인프라**: Hadoop, Kafka, Elasticsearch 같은 빅데이터·인프라 도구들도 Java(혹은 JVM 계열 언어)로 만들어졌습니다.

이처럼 Java는 한 가지 분야에 특화된 언어가 아니라, 서버부터 모바일, 인프라까지 폭넓게 쓰이는 범용 언어입니다.

## 다른 언어와 비교하기

이미 다른 언어를 접해본 독자라면 Java가 그 언어들과 어떻게 다른지 궁금할 것입니다.

**C#과의 비교**: C#은 Microsoft가 만든 언어로, Java와 문법이 매우 비슷합니다. 둘 다 정적 타입 객체지향 언어이고, 소스 코드를 중간 코드로 컴파일한 뒤 가상 머신(Java는 JVM, C#은 .NET의 CLR)에서 실행하는 구조도 동일합니다. 사실상 하나를 배우면 다른 하나로 넘어가기가 어렵지 않을 정도로 두 언어는 닮아 있습니다. 차이는 주로 생태계에 있는데, C#은 Windows 환경과 게임 엔진 Unity에서 강세를 보이고, Java는 서버와 안드로이드 쪽에서 더 널리 쓰입니다.

**Python과의 비교**: Python은 동적 타입 언어로, 변수의 자료형을 미리 선언하지 않고 세미콜론이나 중괄호 없이도 코드를 작성할 수 있어 문법이 간결합니다. 배우기 쉽고 빠르게 결과물을 만들어보기에 좋지만, 프로그램이 커질수록 타입 오류를 실행 중에야 발견하게 되는 경우가 생깁니다. Java는 반대로 문법이 다소 장황하고 규칙이 엄격하지만, 그 엄격함이 대규모 협업 프로젝트에서 오류를 줄여주는 안전판 역할을 합니다. 두 언어는 "빠른 프로토타이핑"과 "견고한 시스템 구축"이라는 서로 다른 강점을 가진 셈입니다.

이런 비교를 통해 알 수 있는 것은, Java의 문법이 다소 낯설고 규칙이 많게 느껴지더라도 그것이 무의미한 복잡함이 아니라 안정성을 위한 설계라는 점입니다. 이 책을 따라가다 보면 그 규칙들이 왜 필요한지 하나씩 이해하게 될 것입니다.

## JDK 설치와 개발 환경 준비

Java로 개발을 시작하려면 **JDK(Java Development Kit)**를 설치해야 합니다. JDK는 앞서 설명한 컴파일러(`javac`), 실행기(`java`), 그리고 JVM을 포함한 개발 도구 모음입니다. 참고로 JVM만 포함하고 개발 도구는 빠진 것을 JRE(Java Runtime Environment)라고 부르는데, 요즘은 JDK 하나만 설치하면 실행과 개발이 모두 가능하므로 JRE를 따로 신경 쓸 필요는 거의 없습니다.

JDK는 여러 배포판이 있습니다. Oracle이 배포하는 Oracle JDK, 무료이며 널리 쓰이는 Eclipse Temurin(구 AdoptOpenJDK), Amazon Corretto 등이 대표적입니다. 이 책에서는 어떤 배포판을 쓰든 문법이나 실행 방식에 차이가 없으므로, 입문자라면 Eclipse Temurin의 최신 LTS(장기 지원) 버전을 설치하는 것을 권장합니다.

설치가 끝나면 터미널(Windows는 명령 프롬프트나 PowerShell, macOS·Linux는 터미널)에서 다음 명령으로 설치가 잘 되었는지 확인합니다.

```
java -version
javac -version
```

두 명령이 모두 버전 정보를 출력한다면 준비가 끝났습니다. 코드를 작성할 때는 메모장 같은 단순 텍스트 편집기도 쓸 수 있지만, 문법 오류를 미리 잡아주고 자동 완성을 지원하는 통합 개발 환경(IDE)을 쓰면 훨씬 편합니다. IntelliJ IDEA나 Visual Studio Code가 널리 쓰이는 선택지이며, 이 책의 예제는 어떤 편집기를 쓰더라도 동일하게 따라 할 수 있도록 작성되어 있습니다.

## 이 책의 학습 방향

이 책은 총 18개 장으로 구성되어 있으며, 크게 세 단계로 나눌 수 있습니다. 1장부터 8장까지는 변수, 연산자, 제어문, 반복문, 배열, 메서드 등 프로그래밍의 기본 문법을 다룹니다. 9장부터 13장까지는 클래스, 상속, 인터페이스, 예외 처리, 제네릭 등 Java의 객체지향적 특징을 본격적으로 배웁니다. 마지막으로 14장부터 18장까지는 컬렉션 프레임워크, 람다, 스트림, 멀티스레딩처럼 실무에서 자주 쓰이는 현대적인 Java 기능과, 좋은 코드를 작성하는 습관을 다룹니다.

바로 다음 장인 2장에서는 실제로 첫 Java 프로그램을 작성하고, 그것이 컴파일되어 실행되기까지의 전체 과정을 직접 눈으로 확인해볼 것입니다. 지금까지 이론으로만 설명한 JVM과 바이트코드의 개념이 실습을 통해 훨씬 명확해질 것입니다.

## 요약

- Java 코드는 `javac`로 컴파일되어 바이트코드(`.class`)가 되고, 이 바이트코드는 각 운영체제에 설치된 JVM 위에서 실행됩니다.
- JVM 덕분에 Java는 "Write Once, Run Anywhere"라는 플랫폼 독립성을 가집니다.
- Java는 컴파일 시점에 자료형을 검사하는 정적 타입 언어이며, 객체를 중심으로 프로그램을 구성하는 객체지향 언어입니다.
- 엔터프라이즈 백엔드, 안드로이드, 대규모 데이터 인프라 등 다양한 분야에서 널리 쓰입니다.
- 문법이 비슷한 C#, 문법이 간결한 동적 타입 언어 Python과 비교하면 Java의 특징이 더 뚜렷하게 드러납니다.
- 개발을 시작하려면 JDK를 설치하고 `java -version`, `javac -version`으로 설치를 확인합니다.

## 연습문제

1. JVM이 하는 역할을 자신의 말로 설명해 보세요. 소스 코드, 바이트코드, JVM, 기계어라는 네 단어를 모두 사용해서 설명해야 합니다.
2. "Write Once, Run Anywhere"가 가능한 이유를 JVM의 구조와 연결해서 서술해 보세요.
3. 정적 타입 언어와 동적 타입 언어의 차이를 예를 들어 설명하고, Java는 어느 쪽에 속하는지 말해 보세요.
4. Java가 활용되는 분야 세 가지를 나열하고 각각 왜 Java가 적합한지 생각해 보세요.
5. 자신의 컴퓨터에 JDK를 설치하고 `java -version`, `javac -version` 명령의 실행 결과를 확인해 보세요.
