프로그램은 늘 예상대로만 흘러가지 않는다. 사용자가 숫자를 입력해야 할 곳에 문자를 입력하거나, 파일이 존재하지 않거나, 배열의 범위를 벗어난 인덱스에 접근하는 일은 실무에서 매일 벌어진다. 이런 비정상적인 상황을 프로그램이 갑자기 멈추지 않고 적절히 감지하고 대응하도록 만드는 장치가 바로 **예외 처리(exception handling)**다. 이번 장에서는 자바의 예외 처리 문법과 예외 계층 구조, 그리고 자바만의 독특한 checked/unchecked 예외 구분을 다룬다.

## try-catch-finally 기본 구조

예외가 발생할 수 있는 코드는 `try` 블록에 넣고, 예외가 발생했을 때 처리할 코드는 `catch` 블록에 작성한다. `finally` 블록은 예외 발생 여부와 상관없이 항상 실행된다.

```java
public class DivisionDemo {
    public static void main(String[] args) {
        int[] numbers = { 10, 20, 0, 5 };
        int divisor = 0;

        try {
            int result = numbers[0] / divisor; // 0으로 나누면 예외 발생
            System.out.println("결과: " + result);
        } catch (ArithmeticException e) {
            // 예외가 발생하면 여기로 제어가 넘어온다
            System.out.println("0으로 나눌 수 없습니다: " + e.getMessage());
        } finally {
            // 예외 발생 여부와 무관하게 항상 실행된다
            System.out.println("계산 시도를 마쳤습니다");
        }

        System.out.println("프로그램은 계속 진행된다");
    }
}
```

`catch` 블록이 예외를 잡아내지 않았다면 프로그램은 그 자리에서 비정상 종료됐을 것이다. `finally`는 주로 파일을 닫거나 자원을 반납하는 등, 예외 여부와 관계없이 반드시 수행해야 하는 정리 작업에 사용한다. 하나의 `try`에 여러 `catch`를 연결해 서로 다른 예외 타입을 각각 처리할 수도 있다.

```java
try {
    int[] arr = new int[3];
    arr[5] = 10; // 배열 범위 초과
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("배열 범위를 벗어났습니다: " + e.getMessage());
} catch (Exception e) {
    // 위에서 잡지 못한 나머지 예외를 처리
    System.out.println("알 수 없는 예외 발생: " + e.getMessage());
}
```

`catch` 블록은 위에서부터 순서대로 검사되므로, 더 구체적인 예외 타입을 먼저 적고 포괄적인 `Exception`은 마지막에 두어야 한다. 순서가 반대이면 컴파일 오류가 발생한다.

## 예외 계층 구조: Throwable - Exception - Error

자바에서 던져질 수 있는 모든 문제 상황은 `Throwable` 클래스를 최상위 부모로 한다. `Throwable`은 두 개의 큰 갈래로 나뉜다.

```
Throwable
 ├── Exception       (프로그램이 처리할 수 있는 예외)
 │    ├── RuntimeException  (unchecked 예외)
 │    │    ├── NullPointerException
 │    │    ├── ArrayIndexOutOfBoundsException
 │    │    ├── ArithmeticException
 │    │    └── ClassCastException
 │    └── IOException 등 (checked 예외)
 └── Error            (시스템 수준의 심각한 문제, 보통 복구 불가)
      ├── OutOfMemoryError
      └── StackOverflowError
```

`Error`는 메모리 부족이나 JVM 내부 오류처럼 애플리케이션 코드로 복구하기 어려운 심각한 문제를 나타내며, 일반적으로 `catch`하지 않는다. 우리가 실제로 다루는 대상은 대부분 `Exception`과 그 하위 클래스들이다.

## checked 예외와 unchecked 예외

자바의 독특한 특징 중 하나는 예외를 **checked 예외**와 **unchecked 예외**로 구분하고, 컴파일러가 이 둘을 다르게 취급한다는 점이다.

- **checked 예외**: `Exception`의 하위이면서 `RuntimeException`은 아닌 예외들(예: `IOException`, `SQLException`). 이 예외가 발생할 수 있는 코드는 반드시 `try-catch`로 처리하거나 `throws`로 선언해야 한다. 그렇지 않으면 **컴파일 자체가 되지 않는다**. 컴파일러가 "이 예외에 대비했는가?"를 강제로 확인하는 것이다.
- **unchecked 예외**: `RuntimeException`과 그 하위 클래스들(예: `NullPointerException`, `ArithmeticException`). 컴파일러는 이 예외들에 대한 처리를 강제하지 않는다. 대부분 프로그래머의 논리적 실수(잘못된 인덱스, null 참조 등)로 발생하며, 코드를 올바르게 작성하면 예방할 수 있는 경우가 많다.

```java
import java.io.FileReader;
import java.io.IOException;

public class CheckedExample {
    public static void main(String[] args) {
        // FileReader 생성자는 checked 예외인 IOException을 던질 수 있다
        // try-catch로 처리하지 않으면 컴파일 오류가 발생한다
        try {
            FileReader reader = new FileReader("data.txt");
            reader.close();
        } catch (IOException e) {
            System.out.println("파일을 열 수 없습니다: " + e.getMessage());
        }
    }
}
```

반면 다음 코드는 `catch`로 감싸지 않아도 컴파일에는 문제가 없다. 다만 실행 중 조건에 따라 예외가 발생할 수 있다.

```java
public class UncheckedExample {
    public static void main(String[] args) {
        String text = null;
        System.out.println(text.length()); // NullPointerException, 컴파일은 됨
    }
}
```

이 구분은 다른 언어에서는 보기 힘든 자바만의 설계 철학이다. checked 예외는 "호출하는 쪽이 반드시 대비해야 하는 예측 가능한 실패"(파일이 없을 수도 있다, 네트워크가 끊길 수도 있다)를 표현하고, unchecked 예외는 "코드를 제대로 작성하면 피할 수 있는 프로그래밍 오류"를 표현한다는 관점으로 이해하면 구분이 자연스럽다.

## throws로 예외 선언하기

메서드 내부에서 checked 예외가 발생할 수 있는데 그 메서드 안에서 직접 처리하지 않고 호출한 쪽으로 책임을 넘기고 싶다면, 메서드 시그니처에 `throws`를 적어 선언한다.

```java
import java.io.IOException;
import java.io.FileReader;

public class FileLoader {
    // 이 메서드를 호출하는 쪽에서 IOException을 처리해야 한다
    public void loadFile(String path) throws IOException {
        FileReader reader = new FileReader(path);
        reader.close();
    }

    public static void main(String[] args) {
        FileLoader loader = new FileLoader();
        try {
            loader.loadFile("config.txt");
        } catch (IOException e) {
            System.out.println("설정 파일 로드 실패: " + e.getMessage());
        }
    }
}
```

`throws`는 예외를 처리하는 것이 아니라 "이 메서드는 이런 예외를 던질 수 있으니 호출하는 쪽에서 대비하라"고 컴파일러와 다른 개발자에게 알리는 선언이다.

## throw로 예외 직접 발생시키기

`throw` 키워드는 실제로 예외 객체를 생성해서 던지는 명령이다. 메서드 인자가 유효하지 않거나 어떤 상태가 잘못되었을 때, 미리 오류를 감지해 명확한 예외를 던지는 방식으로 방어적인 코드를 작성할 수 있다.

```java
public class BankAccount {
    private int balance;

    public BankAccount(int initialBalance) {
        this.balance = initialBalance;
    }

    public void withdraw(int amount) {
        if (amount > balance) {
            // 잔액이 부족하면 직접 예외를 던진다
            throw new IllegalArgumentException("잔액이 부족합니다. 현재 잔액: " + balance);
        }
        balance -= amount;
        System.out.println(amount + "원 출금 완료, 남은 잔액: " + balance);
    }
}
```

```java
BankAccount account = new BankAccount(1000);
account.withdraw(500);  // 정상 처리
account.withdraw(2000); // IllegalArgumentException 발생
```

## 커스텀 예외 클래스 만들기

자바가 기본으로 제공하는 예외 클래스만으로는 도메인의 의미를 정확히 표현하기 어려울 때가 있다. 이럴 때는 `Exception`이나 `RuntimeException`을 상속하여 직접 예외 클래스를 정의한다.

```java
// 잔액 부족을 명확히 표현하는 커스텀 checked 예외
public class InsufficientBalanceException extends Exception {
    public InsufficientBalanceException(String message) {
        super(message); // 부모 클래스의 생성자를 호출해 메시지를 전달
    }
}
```

```java
public class BankAccount {
    private int balance;

    public BankAccount(int initialBalance) {
        this.balance = initialBalance;
    }

    // checked 예외이므로 throws로 선언해야 한다
    public void withdraw(int amount) throws InsufficientBalanceException {
        if (amount > balance) {
            throw new InsufficientBalanceException(
                "요청 금액 " + amount + "원이 잔액 " + balance + "원보다 큽니다");
        }
        balance -= amount;
    }
}
```

```java
BankAccount account = new BankAccount(1000);
try {
    account.withdraw(2000);
} catch (InsufficientBalanceException e) {
    System.out.println("출금 실패: " + e.getMessage());
}
```

`Exception`을 상속하면 checked 예외가 되고, `RuntimeException`을 상속하면 unchecked 예외가 된다. 어떤 실패가 "호출자가 반드시 대비해야 하는 것"인지, "프로그래밍 오류에 가까운 것"인지에 따라 부모 클래스를 선택하면 된다.

## try-with-resources를 이용한 자원 관리

파일, 네트워크 연결, 데이터베이스 커넥션처럼 사용이 끝나면 반드시 닫아야 하는 자원을 다룰 때, 예전에는 `finally` 블록에서 일일이 `close()`를 호출해야 했다.

```java
// try-with-resources 없이 작성한 경우 - 번거롭고 실수하기 쉽다
FileReader reader = null;
try {
    reader = new FileReader("data.txt");
    // 파일 사용
} catch (IOException e) {
    System.out.println("오류: " + e.getMessage());
} finally {
    if (reader != null) {
        try {
            reader.close();
        } catch (IOException e) {
            System.out.println("닫기 실패: " + e.getMessage());
        }
    }
}
```

자바 7부터는 `AutoCloseable` 인터페이스를 구현한 자원을 `try(...)` 괄호 안에 선언하면, 블록이 끝날 때 자동으로 `close()`가 호출된다.

```java
// try-with-resources: 블록이 끝나면 reader.close()가 자동으로 호출된다
try (FileReader reader = new FileReader("data.txt")) {
    int data = reader.read();
    System.out.println("읽은 문자 코드: " + data);
} catch (IOException e) {
    System.out.println("파일 처리 중 오류: " + e.getMessage());
}
```

괄호 안에는 세미콜론으로 구분하여 여러 자원을 동시에 선언할 수도 있으며, 선언된 순서의 역순으로 자동으로 닫힌다. 직접 만든 클래스도 `AutoCloseable`을 구현하면 이 문법을 사용할 수 있다.

```java
public class SimpleResource implements AutoCloseable {
    private String name;

    public SimpleResource(String name) {
        this.name = name;
        System.out.println(name + " 자원을 열었습니다");
    }

    public void use() {
        System.out.println(name + " 자원을 사용 중입니다");
    }

    @Override
    public void close() {
        // 자원을 정리하는 코드
        System.out.println(name + " 자원을 닫았습니다");
    }
}
```

```java
try (SimpleResource res = new SimpleResource("데이터베이스 연결")) {
    res.use();
} // 이 지점에서 res.close()가 자동으로 호출된다
```

`finally`를 직접 작성하지 않아도 자원이 안전하게 정리되므로, 코드가 훨씬 간결해지고 자원 누수의 위험도 줄어든다.

## 요약

- `try-catch-finally`로 예외 상황을 감지하고 처리하며, `finally`는 예외 발생 여부와 무관하게 항상 실행된다.
- 모든 예외와 오류는 `Throwable`을 최상위로 하여 `Exception`과 `Error`로 나뉘고, `Exception`은 다시 checked 예외와 `RuntimeException` 계열의 unchecked 예외로 나뉜다.
- checked 예외는 컴파일러가 처리를 강제하는 예측 가능한 실패를, unchecked 예외는 코드 오류에 가까운 문제를 나타낸다.
- `throws`는 메서드가 던질 수 있는 예외를 선언하고, `throw`는 실제로 예외 객체를 생성해 던진다.
- `Exception`이나 `RuntimeException`을 상속해 도메인에 맞는 커스텀 예외 클래스를 만들 수 있다.
- `AutoCloseable`을 구현한 자원은 try-with-resources 문법으로 선언하면 블록이 끝날 때 자동으로 닫힌다.

## 연습문제

1. 사용자로부터 입력받은 문자열을 정수로 변환하는 코드를 작성하고, 변환에 실패했을 때 발생하는 `NumberFormatException`을 `try-catch`로 처리해보자.
2. `InsufficientBalanceException`처럼 도메인 의미를 담은 커스텀 예외 클래스를 하나 더 설계해보자. 예를 들어 재고가 부족할 때 던지는 `OutOfStockException`을 만들고, 이를 던지는 메서드와 잡아 처리하는 코드를 각각 작성하라.
3. checked 예외와 unchecked 예외의 차이를 컴파일러 관점에서 설명하고, 새로운 예외 클래스를 만들 때 `Exception`과 `RuntimeException` 중 무엇을 상속할지 어떻게 판단할 수 있는지 서술해보자.
4. `AutoCloseable`을 구현한 클래스를 하나 작성하고, try-with-resources 문법으로 사용했을 때와 일반 try-finally로 자원을 닫았을 때의 코드 길이와 안전성을 비교해보자.
5. 하나의 `try` 블록 안에서 여러 종류의 예외가 발생할 수 있는 상황을 만들고, `catch` 블록의 순서를 바꿔가며 어떤 경우에 컴파일 오류가 발생하는지 실험해보자.
