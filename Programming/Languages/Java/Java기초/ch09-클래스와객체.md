# 9장. 클래스와 객체

[◀ 이전: 8장. 메서드](ch08-메서드.md) | [📖 목차](00-목차.md) | [다음: 10장. 상속과 다형성 ▶](ch10-상속과다형성.md)

---

지금까지는 `int`, `double`, `boolean` 같은 기본형 변수를 다루거나, 배열과 메서드로 데이터를 처리하는 방법을 배웠습니다. 하지만 실제 프로그램은 "사람", "계좌", "자동차"처럼 여러 속성과 동작을 함께 가진 대상을 다룰 때가 훨씬 많습니다. 이런 대상을 표현하는 자바의 도구가 바로 **클래스(class)**와 **객체(object)**입니다. 이 장에서는 클래스를 정의하는 방법, 객체를 생성하고 사용하는 방법, 그리고 객체지향 프로그래밍의 첫 걸음을 다룹니다.

## 9.1 클래스는 설계도, 객체는 그 결과물

클래스는 어떤 종류의 데이터를 가질지, 그 데이터로 어떤 동작을 할 수 있을지를 정의하는 **설계도**입니다. 설계도 자체는 실체가 아닙니다. 건축 설계도로 집을 짓듯, 클래스로부터 실제 메모리에 만들어지는 결과물이 **객체(인스턴스)**입니다.

예를 들어 "은행 계좌"라는 개념을 클래스로 표현하면, 계좌 소유자 이름과 잔액이라는 **필드(field)**, 그리고 입금·출금 같은 **메서드(method)**로 구성할 수 있습니다. 이 하나의 클래스로부터 민수의 계좌, 지은의 계좌처럼 서로 다른 값을 가진 여러 객체를 얼마든지 만들 수 있습니다. 이 관계는 다음 그림으로 정리할 수 있습니다.

```text
     BankAccount 클래스 (설계도)                      인스턴스 (객체)
    +---------------------------+
    | 필드                       |        new   +--------------------------------+
    |  - owner: String          | ------------->| myAccount : BankAccount         |
    |  - balance: long          |               |  owner = "민수"                  |
    |---------------------------|               |  balance = 50000                |
    | 생성자                     |               +--------------------------------+
    |  BankAccount(owner)       |
    |---------------------------|        new   +--------------------------------+
    | 메서드                     | ------------->| yourAccount : BankAccount       |
    |  + deposit(amount)        |               |  owner = "지은"                  |
    |  + withdraw(amount)       |               |  balance = 120000               |
    |  + getBalance()           |               +--------------------------------+
    |                           |
    | (필드와 메서드의 구조만 정의) |        new   +--------------------------------+
    +---------------------------+ ------------->| savingsAccount : BankAccount    |
                                                 |  owner = "민수"                  |
                                                 |  balance = 3000000              |
                                                 +--------------------------------+

    하나의 클래스로부터 서로 독립적인 필드 값을 가진 여러 객체를 만들 수 있다
```

## 9.2 클래스 정의하기

클래스는 `class` 키워드로 정의하며, 내부에 필드와 메서드를 선언합니다.

```java
public class BankAccount {
    // 필드: 객체가 가지는 데이터
    private String owner;
    private long balance;

    // 메서드: 객체가 할 수 있는 동작
    public void deposit(long amount) {
        balance = balance + amount;
    }

    public long getBalance() {
        return balance;
    }
}
```

필드는 객체마다 독립적으로 저장되는 값이고, 메서드는 그 값을 이용해 동작을 수행하는 코드입니다. 클래스 이름은 관례상 PascalCase(`BankAccount`처럼 단어마다 첫 글자를 대문자로)로 짓고, 필드와 메서드 이름은 camelCase(`getBalance`처럼 첫 단어만 소문자로 시작)로 짓습니다.

## 9.3 객체 생성과 참조 변수

클래스로부터 객체를 만들 때는 `new` 연산자를 사용합니다.

```java
BankAccount account1 = new BankAccount();
account1.deposit(10000);
System.out.println(account1.getBalance());  // 10000
```

여기서 중요한 개념이 등장합니다. `account1`이라는 변수는 객체 자체가 아니라, 객체가 메모리 어딘가에 만들어진 위치를 가리키는 **참조(reference)**를 담고 있습니다. 3장에서 배운 `int`, `double` 같은 기본형 변수는 값 자체를 변수에 직접 저장하지만, 클래스 타입의 변수는 항상 참조를 저장합니다. 이 차이는 대입과 비교 연산에서 실제로 드러납니다.

```java
int a = 10;
int b = a;      // 값 10이 그대로 복사됨
b = 20;         // a는 여전히 10

BankAccount acc1 = new BankAccount();
BankAccount acc2 = acc1;   // 참조가 복사됨 (같은 객체를 가리킴)
acc2.deposit(5000);
System.out.println(acc1.getBalance());  // 5000, acc1도 영향을 받음
```

`acc1`과 `acc2`는 서로 다른 변수이지만 같은 객체를 가리키므로, 어느 한쪽으로 객체를 변경하면 다른 쪽에서도 그 변화가 보입니다. 기본형은 값 자체를 복사하지만 참조형은 "같은 대상을 가리키는 이름표"를 복사한다는 점을 기억해 두세요.

## 9.4 생성자: 객체를 만드는 순간을 제어하기

지금까지는 `new BankAccount()`로 객체를 만든 뒤 별도로 값을 넣어주었습니다. 하지만 계좌를 만들 때부터 소유자 이름을 지정하고 싶다면 **생성자(constructor)**를 정의합니다. 생성자는 클래스 이름과 동일한 이름을 가지며 반환 타입을 쓰지 않습니다.

```java
public class BankAccount {
    private String owner;
    private long balance;

    // 생성자: 객체 생성 시 반드시 소유자 이름을 받도록 강제
    public BankAccount(String owner) {
        this.owner = owner;
        this.balance = 0;
    }
}
```

```java
BankAccount account = new BankAccount("민수");
```

클래스에 생성자를 하나도 작성하지 않으면 자바가 매개변수 없는 **기본 생성자(default constructor)**를 자동으로 만들어 줍니다. 하지만 생성자를 하나라도 직접 작성하면 기본 생성자는 더 이상 자동으로 제공되지 않으므로, 매개변수 없는 생성 방식도 필요하다면 별도로 작성해야 합니다.

같은 클래스에 매개변수 목록이 다른 생성자를 여러 개 두는 것도 가능한데, 이를 **생성자 오버로드(overload)**라고 합니다.

```java
public class BankAccount {
    private String owner;
    private long balance;

    public BankAccount(String owner) {
        this.owner = owner;
        this.balance = 0;
    }

    public BankAccount(String owner, long initialBalance) {
        this.owner = owner;
        this.balance = initialBalance;
    }
}
```

```java
BankAccount a = new BankAccount("민수");
BankAccount b = new BankAccount("지은", 100000);
```

컴파일러는 전달된 인자의 개수와 타입을 보고 어떤 생성자를 호출할지 판단합니다. 이는 8장에서 살펴본 메서드 오버로드와 같은 원리입니다.

## 9.5 this 키워드

위 생성자 코드에서 `this.owner = owner;`라는 표현을 보았습니다. `this`는 **현재 메서드나 생성자가 호출된 객체 자기 자신**을 가리키는 참조입니다. 매개변수 이름과 필드 이름이 같을 때, `this.owner`는 필드를, 그냥 `owner`는 매개변수를 의미하므로 둘을 구분할 수 있습니다.

`this`는 한 생성자에서 같은 클래스의 다른 생성자를 호출할 때도 쓸 수 있습니다.

```java
public class BankAccount {
    private String owner;
    private long balance;

    public BankAccount(String owner) {
        this(owner, 0);   // 아래 생성자를 호출하며 초기 잔액 0을 전달
    }

    public BankAccount(String owner, long initialBalance) {
        this.owner = owner;
        this.balance = initialBalance;
    }
}
```

이렇게 하면 초기화 로직을 한 곳에 모아 중복을 줄일 수 있습니다. `this(...)` 형태의 호출은 반드시 생성자의 첫 줄에서만 사용할 수 있습니다.

## 9.6 접근 제한자: 필드와 메서드 숨기기

`BankAccount`의 `balance` 필드를 `private`으로 선언한 이유는, 외부에서 `account.balance = -999999;`처럼 잔액을 직접 조작하는 것을 막기 위해서입니다. 이렇게 필드를 감추고 메서드를 통해서만 접근하도록 하는 설계를 **캡슐화(encapsulation)**라고 하며, 자바에서는 접근 제한자로 이를 구현합니다.

| 접근 제한자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 그 외 |
|---|---|---|---|---|
| `public` | O | O | O | O |
| `protected` | O | O | O | X |
| (기본, 생략) | O | O | X | X |
| `private` | O | X | X | X |

`protected`는 10장에서 다룰 상속 관계에서 자식 클래스가 부모의 멤버에 접근할 수 있도록 열어줄 때 주로 사용합니다. 아무 제한자도 쓰지 않은 **default(package-private)** 접근은 같은 패키지 안에서만 공유하고 싶은 멤버에 사용합니다. 일반적인 원칙은 "필드는 `private`으로 감추고, 외부에 꼭 필요한 기능만 `public` 메서드로 열어준다"입니다.

```java
public class BankAccount {
    private String owner;
    private long balance;

    public BankAccount(String owner, long initialBalance) {
        this.owner = owner;
        this.balance = initialBalance;
    }

    public void deposit(long amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("입금액은 0보다 커야 합니다.");
        }
        balance += amount;
    }

    public void withdraw(long amount) {
        if (amount > balance) {
            throw new IllegalStateException("잔액이 부족합니다.");
        }
        balance -= amount;
    }

    public long getBalance() {
        return balance;
    }

    public String getOwner() {
        return owner;
    }
}
```

이렇게 작성하면 잔액을 변경하는 유일한 방법은 `deposit`과 `withdraw`뿐이므로, 항상 유효성 검사를 거치게 됩니다. `getBalance`, `getOwner`처럼 필드 값을 읽어주는 메서드를 **getter**라 부르고, 값을 바꿔주는 메서드를 **setter**라 부릅니다. 예외를 던지는 부분은 12장 예외 처리에서 더 자세히 다룹니다.

## 9.7 필드의 기본값과 메서드 재사용

필드는 초기화하지 않아도 자바가 타입별 기본값을 자동으로 채워줍니다. 숫자형은 `0`, `boolean`은 `false`, 참조형은 `null`입니다. 이는 3장에서 배운 지역 변수와 다른 점인데, 지역 변수는 초기화하지 않고 사용하면 컴파일 오류가 나지만, 필드는 기본값으로 자동 초기화됩니다. 다만 명시적으로 초기값을 지정하는 습관이 코드를 더 명확하게 만듭니다.

한 클래스 안의 메서드는 같은 객체의 다른 필드와 메서드를 자유롭게 사용할 수 있습니다. 예를 들어 `withdraw` 메서드 안에서 `getBalance()`를 호출하거나, 새로운 메서드 `transfer`를 만들어 `deposit`과 `withdraw`를 조합할 수도 있습니다. 이렇게 메서드를 조합해 재사용하는 것은 8장에서 배운 메서드 분리의 자연스러운 확장입니다.

```java
public void transfer(BankAccount target, long amount) {
    this.withdraw(amount);
    target.deposit(amount);
}
```

`transfer` 메서드는 자기 자신의 잔액을 줄이고, 매개변수로 받은 다른 `BankAccount` 객체의 잔액을 늘립니다. 이렇게 객체끼리 메서드를 호출하며 협력하는 방식이 객체지향 프로그램의 핵심입니다.

## 요약

- 클래스는 필드(데이터)와 메서드(동작)를 정의하는 설계도이고, 객체(인스턴스)는 `new`로 만들어지는 실제 결과물입니다. 하나의 클래스에서 여러 독립된 객체를 만들 수 있습니다.
- 클래스 타입 변수는 객체를 직접 담지 않고 참조를 저장합니다. 이 점이 값을 직접 저장하는 기본형과 가장 큰 차이입니다.
- 생성자는 객체 생성 시점에 초기화를 강제하며, 매개변수 목록을 달리해 오버로드할 수 있습니다. 생성자를 하나라도 정의하면 자동 기본 생성자는 제공되지 않습니다.
- `this`는 현재 객체 자신을 가리키며, 필드와 매개변수 이름 충돌을 해소하거나 다른 생성자를 호출할 때 사용합니다.
- 접근 제한자(`public`, `protected`, 기본, `private`)로 멤버의 노출 범위를 제어하며, 필드를 `private`으로 감추고 메서드로만 접근하게 하는 캡슐화가 안전한 설계의 기본입니다.

이 장에서 만든 `BankAccount`처럼 상태와 동작을 하나로 묶는 것이 클래스의 본질입니다. 다음 10장에서는 이런 클래스들 사이에 "무엇의 한 종류이다"라는 관계를 표현하는 상속을 다루며, 클래스 설계를 한 단계 더 확장합니다.
