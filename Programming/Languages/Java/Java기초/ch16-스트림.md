## 들어가며: 반복문으로 데이터 다루기

14장에서 배운 `List`, `Set`, `Map` 같은 컬렉션은 여러 데이터를 담는 그릇이다. 그런데 데이터를 담는 것과 그 데이터를 **가공**하는 것은 다른 문제다. "짝수만 골라서 제곱한 뒤 리스트로 모으고 싶다"처럼 여러 단계를 거쳐야 하는 작업을 반복문으로 작성하면 이렇게 된다.

```java
import java.util.*;

public class LoopStyle {
    public static void main(String[] args) {
        List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);
        List<Integer> result = new ArrayList<>();

        for (int n : numbers) {
            if (n % 2 == 0) {          // 1단계: 짝수만 걸러냄
                result.add(n * n);      // 2단계: 제곱해서 새 리스트에 담음
            }
        }

        System.out.println(result); // [4, 16, 36]
    }
}
```

코드 자체는 어렵지 않지만, "무엇을" 하는지보다 "어떻게" 반복하고 임시 리스트를 만드는지에 코드의 많은 부분이 쓰인다. 조건 하나를 더 추가하거나 단계를 하나 더 늘릴 때마다 반복문 내부는 점점 복잡해진다.

자바 8부터 도입된 **스트림(Stream) API**는 이런 "데이터를 걸러내고, 변환하고, 모으는" 작업을 선언적으로 표현하게 해준다. 위 코드를 스트림으로 다시 써보자.

```java
import java.util.*;
import java.util.stream.Collectors;

public class StreamStyle {
    public static void main(String[] args) {
        List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

        List<Integer> result = numbers.stream()
                .filter(n -> n % 2 == 0)   // 짝수만 남김
                .map(n -> n * n)             // 제곱으로 변환
                .collect(Collectors.toList()); // 리스트로 모음

        System.out.println(result); // [4, 16, 36]
    }
}
```

임시 변수 `result`를 미리 만들고 `add`를 호출하는 코드가 사라지고, "짝수를 걸러서(`filter`) 제곱으로 바꾼(`map`) 다음 리스트로 모은다(`collect`)"는 의도가 코드 순서 그대로 읽힌다. 이것이 스트림이 주는 가장 큰 이점이다.

## 스트림이란 무엇인가

스트림은 컬렉션 그 자체가 아니라, **컬렉션에 담긴 데이터를 처리하는 파이프라인**이다. 다음 세 가지 특징을 기억해두면 스트림을 다루기 쉬워진다.

1. 스트림은 데이터를 저장하지 않는다. 원본 컬렉션은 그대로 남아 있고, 스트림은 그 위를 흘러가는 데이터의 흐름일 뿐이다.
2. 스트림은 **한 번만** 사용할 수 있다. 최종 연산을 한 번 거치면 그 스트림은 소모되어 다시 쓸 수 없다.
3. 스트림 연산은 원본을 변경하지 않는다. `filter`나 `map`은 새로운 스트림을 만들 뿐, 원본 리스트의 원소를 수정하지 않는다.

스트림을 만드는 가장 흔한 방법은 컬렉션의 `stream()` 메서드를 호출하는 것이다.

```java
List<String> names = List.of("정우", "민준", "서연", "하늘");
var nameStream = names.stream(); // Stream<String>
```

## 중간 연산과 최종 연산

스트림 파이프라인은 크게 두 종류의 연산으로 구성된다.

- **중간 연산(intermediate operation)**: `filter`, `map`처럼 스트림을 받아 또 다른 스트림을 반환하는 연산. 여러 개를 이어 붙일 수 있다.
- **최종 연산(terminal operation)**: `collect`, `forEach`, `reduce`처럼 스트림을 소모하여 결과(리스트, 값, 또는 아무 반환값 없음)를 만들어내는 연산. 파이프라인당 한 번만 나온다.

아래 그림은 앞서 본 짝수 필터링·제곱 예제의 파이프라인을 도식화한 것이다.

```text
  스트림 파이프라인: filter -> map -> collect

  +-------------+        +-----------+        +-----------------------+        +-----------------------+        +-------------+
  | 원본 리스트   | -----> | stream()  | -----> |      중간 연산         | -----> |      중간 연산         | -----> |   최종 연산   |
  | [1,2,3,4,5,6]|        |           |        | filter(               |        | map(                  |        | collect(    |
  +-------------+        +-----------+        |   n -> n % 2 == 0)    |        |   n -> n * n)         |        |   toList()) |
                                               |  짝수만 남김           |        |  각 값을 제곱으로 변환   |        |  결과 생성    |
                                               +-----------------------+        +-----------------------+        +-------------+
                                                    -> [2, 4, 6]                     -> [4, 16, 36]                -> [4, 16, 36]

  - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - - -
  filter와 map은 중간 연산으로, collect가 호출되기 전까지는 실제로 실행되지 않는다 (지연 실행)
  collect가 호출되는 순간, 원본 리스트의 각 원소가 파이프라인을 한 번씩 통과하며 최종 결과가 만들어진다

  범례:
  [   ] 얇은 테두리 = 중간 연산 (Intermediate Operation) - 새로운 스트림을 반환
  [===] 굵은 테두리 = 최종 연산 (Terminal Operation) - 파이프라인을 실행하고 결과를 만듦
```

`filter`와 `map`은 중간 연산이라 새로운 스트림을 반환하지만, 그 자체로는 아무 계산도 일어나지 않는다. 계산은 `collect`라는 최종 연산이 호출되는 순간, 원본 리스트의 원소들이 파이프라인을 하나씩 통과하면서 비로소 일어난다. 이를 **지연 실행(lazy evaluation)**이라고 부른다. 다음 코드로 이를 직접 확인해보자.

```java
List<Integer> numbers = List.of(1, 2, 3);

var stream = numbers.stream()
        .filter(n -> {
            System.out.println("filter 검사: " + n);
            return n % 2 == 0;
        });

System.out.println("아직 아무 것도 출력되지 않았다");
long count = stream.count(); // 최종 연산: 이 시점에 filter가 실제로 실행된다
System.out.println("짝수 개수: " + count);
```

`filter`를 호출한 시점에는 "filter 검사: ..." 문구가 전혀 출력되지 않는다. `count()`라는 최종 연산이 호출된 뒤에야 파이프라인이 실제로 동작한다. 이 지연 실행 덕분에 스트림은 불필요한 계산을 미리 하지 않고, 최종 연산이 필요한 만큼만 데이터를 처리할 수 있다.

## 대표적인 스트림 메서드

### filter: 조건에 맞는 원소만 남기기

`filter`는 15장에서 배운 `Predicate<T>`를 인자로 받아, 조건을 만족하는 원소만 남긴 새 스트림을 반환하는 중간 연산이다.

```java
List<String> names = List.of("정우", "민준", "서연", "하늘");

List<String> twoLetterNames = names.stream()
        .filter(name -> name.length() == 2)
        .collect(Collectors.toList());

System.out.println(twoLetterNames); // [정우, 민준, 서연, 하늘] (모두 2글자이므로 전부 포함)
```

### map: 원소를 다른 형태로 변환하기

`map`은 15장의 `Function<T, R>`을 인자로 받아, 각 원소를 다른 값으로 변환한 새 스트림을 반환하는 중간 연산이다. 원소의 개수는 그대로지만 형태(또는 타입)가 바뀔 수 있다.

```java
List<String> names = List.of("정우", "민준", "서연");

List<Integer> nameLengths = names.stream()
        .map(String::length)   // 각 이름을 길이(정수)로 변환
        .collect(Collectors.toList());

System.out.println(nameLengths); // [2, 2, 2]
```

### collect: 스트림을 컬렉션으로 모으기

`collect`는 스트림의 원소들을 리스트, 집합, 맵 등의 컬렉션으로 모아주는 최종 연산이다. `Collectors` 클래스가 제공하는 다양한 수집 방법을 함께 사용한다.

```java
List<String> names = List.of("정우", "민준", "서연", "하늘");

Set<String> nameSet = names.stream()
        .collect(Collectors.toSet());

String joined = names.stream()
        .collect(Collectors.joining(", "));

System.out.println(joined); // 정우, 민준, 서연, 하늘
```

### reduce: 모든 원소를 하나의 값으로 합치기

`reduce`는 스트림의 모든 원소를 차례로 결합해 하나의 값으로 만드는 최종 연산이다. 초깃값과, 두 값을 어떻게 합칠지 정하는 람다(누산기)를 인자로 받는다.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

int sum = numbers.stream()
        .reduce(0, (acc, n) -> acc + n); // 0에서 시작해 차례로 더함

System.out.println(sum); // 15
```

이 코드는 `acc`(누적값)를 0에서 시작해서, 스트림의 각 원소 `n`을 만날 때마다 `acc + n`으로 갱신해 나간다. 합계, 최댓값, 문자열 연결처럼 "여러 값을 하나로 합치는" 작업은 대부분 `reduce`로 표현할 수 있다.

## 14장 컬렉션 + 15장 람다 = 스트림 파이프라인

스트림 API는 독립된 새 기능이 아니라, 이전 두 장의 개념을 결합해 만들어진 도구다. 14장에서 배운 `List`, `Map` 같은 컬렉션이 데이터를 담고, 15장에서 배운 람다와 `Predicate`, `Function` 같은 함수형 인터페이스가 그 데이터를 어떻게 처리할지 정의한다. 예를 들어 `Map`에 저장된 학생별 점수를 처리하는 다음 코드는 세 장의 내용이 모두 녹아 있다.

```java
import java.util.*;
import java.util.stream.Collectors;

public class ScoreReport {
    public static void main(String[] args) {
        // 14장: Map으로 데이터를 담는다
        Map<String, Integer> scores = new HashMap<>();
        scores.put("정우", 85);
        scores.put("민준", 92);
        scores.put("서연", 76);

        // 15장의 람다와 16장의 스트림을 결합해 처리한다
        List<String> passedStudents = scores.entrySet().stream()
                .filter(entry -> entry.getValue() >= 80)      // 15장: Predicate 역할의 람다
                .map(Map.Entry::getKey)                        // 이름만 추출
                .collect(Collectors.toList());                 // 최종 연산으로 리스트 생성

        System.out.println(passedStudents); // [정우, 민준]
    }
}
```

`scores.entrySet()`으로 얻은 `Map.Entry` 컬렉션을 스트림으로 바꾸고, 점수가 80 이상인 항목만 걸러낸 뒤 이름만 뽑아 리스트로 모았다. 반복문으로 작성했다면 조건문과 임시 리스트로 여러 줄이 필요했을 코드가, 파이프라인 형태로 한눈에 읽히는 몇 줄로 압축된다.

## 요약

- 컬렉션을 반복문으로 처리하면 "무엇을 할지"보다 반복과 임시 변수 관리에 코드가 많이 쓰인다. 스트림은 이를 선언적인 파이프라인으로 표현한다.
- 스트림은 데이터를 저장하지 않고, 한 번만 사용할 수 있으며, 원본 컬렉션을 변경하지 않는다.
- 파이프라인은 **중간 연산**(`filter`, `map` 등, 새 스트림을 반환)과 **최종 연산**(`collect`, `reduce`, `forEach` 등, 결과를 만들어냄)으로 구성된다.
- 중간 연산은 즉시 실행되지 않고 최종 연산이 호출되는 순간 실행된다. 이를 지연 실행이라 한다.
- `filter`는 조건에 맞는 원소만 남기고, `map`은 원소를 변환하며, `collect`는 스트림을 컬렉션으로 모으고, `reduce`는 모든 원소를 하나의 값으로 합친다.
- 스트림 API는 14장의 컬렉션과 15장의 람다·함수형 인터페이스를 결합해 데이터 처리 코드를 간결하게 만드는 도구다.

## 연습문제

1. 정수 리스트 `List.of(3, 8, 1, 9, 4, 6)`에서 5보다 큰 값만 걸러내어 리스트로 모아 보라.
2. 문자열 리스트를 받아 모든 문자열을 대문자로 변환한 뒤, 쉼표로 이어붙인 하나의 문자열을 만드는 스트림 파이프라인을 작성해 보라. (`Collectors.joining` 활용)
3. `reduce`를 사용해 정수 리스트에서 가장 큰 값을 구하는 코드를 작성해 보라.
4. 아래 반복문 코드를 스트림 파이프라인으로 바꿔 보라.
   ```java
   List<Integer> ages = List.of(17, 22, 15, 30, 19);
   int adultCount = 0;
   for (int age : ages) {
       if (age >= 19) {
           adultCount++;
       }
   }
   ```
5. 중간 연산과 최종 연산의 차이를 설명하고, 왜 `filter`만 호출하고 최종 연산을 호출하지 않으면 실제로 아무 일도 일어나지 않는지 이유를 서술해 보라.
