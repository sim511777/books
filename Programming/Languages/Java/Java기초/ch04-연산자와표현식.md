# 4장. 연산자와 표현식

[◀ 이전: 3장. 변수와 자료형](ch03-변수와자료형.md) | [📖 목차](00-목차.md) | [다음: 5장. 제어문 ▶](ch05-제어문.md)

---

3장에서 우리는 값을 담는 그릇인 변수와 그 값의 종류를 정하는 자료형을 배웠다. 이제 그 값들을 가지고 실제로 무언가를 계산하는 방법, 즉 **연산자(operator)**를 알아본다. 연산자와 피연산자(operand)가 결합된 것을 **표현식(expression)**이라 부르며, 표현식은 항상 하나의 값으로 계산(평가)된다. 이 장에서 배우는 내용은 5장 제어문과 6장 반복문에서 조건을 작성할 때 곧바로 사용된다.

## 4.1 산술 연산자

가장 익숙한 연산자는 사칙연산이다.

```java
int a = 17;
int b = 5;

System.out.println(a + b); // 22
System.out.println(a - b); // 12
System.out.println(a * b); // 85
System.out.println(a / b); // 3  (정수 나눗셈: 소수점 이하 버림)
System.out.println(a % b); // 2  (나머지)
```

여기서 가장 중요한 점은 **정수 나눗셈**이다. `int`끼리 나누면 결과도 `int`이므로 소수점 이하는 그대로 버려진다. 실수 결과를 얻고 싶다면 피연산자 중 하나 이상을 `double`이나 `float`로 만들어야 한다.

```java
System.out.println(17 / 5);        // 3
System.out.println(17.0 / 5);      // 3.4
System.out.println((double) 17 / 5); // 3.4, 캐스팅으로 실수 나눗셈을 유도
```

0으로 나누는 경우도 자료형에 따라 결과가 다르다. 정수를 0으로 나누면 `ArithmeticException`(12장에서 다룰 예외)이 발생하지만, 실수를 0.0으로 나누면 예외 없이 `Infinity`나 `NaN`이 나온다.

```java
System.out.println(5 / 0);     // 예외 발생: / by zero
System.out.println(5.0 / 0.0); // Infinity
```

## 4.2 관계 연산자

관계 연산자는 두 값을 비교해서 항상 `boolean` 값(`true` 또는 `false`)을 만들어낸다. 5장 제어문의 `if` 조건식은 대부분 이 연산자로 만들어진다.

```java
int x = 10, y = 20;

System.out.println(x == y); // false, 같다
System.out.println(x != y); // true,  다르다
System.out.println(x > y);  // false
System.out.println(x < y);  // true
System.out.println(x >= 10); // true
System.out.println(x <= 9);  // false
```

주의할 점은 `String` 같은 참조형에 `==`를 사용하면 값이 아니라 참조(주소)를 비교한다는 것이다. 문자열 내용을 비교할 때는 `equals` 메서드를 써야 하며, 이는 9장에서 클래스와 객체를 배운 뒤 다시 자세히 다룬다.

```java
String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);      // false, 서로 다른 객체를 참조
System.out.println(s1.equals(s2)); // true, 내용이 같음
```

## 4.3 논리 연산자

논리 연산자는 `boolean` 값들을 조합한다.

```java
boolean isAdult = true;
boolean hasTicket = false;

System.out.println(isAdult && hasTicket); // false, 둘 다 참이어야 참
System.out.println(isAdult || hasTicket); // true,  하나만 참이어도 참
System.out.println(!isAdult);             // false, 부정
```

`&&`와 `||`는 **단축 평가(short-circuit evaluation)**를 한다. 즉 `&&`는 앞쪽이 `false`면 뒤쪽을 평가하지 않고 곧바로 `false`를 결정하며, `||`는 앞쪽이 `true`면 뒤쪽을 평가하지 않는다. 이는 성능뿐 아니라 안전성에도 중요하다.

```java
String text = null;
if (text != null && text.length() > 0) {
    System.out.println("문자열이 있습니다.");
}
// text가 null이면 앞쪽 조건에서 이미 false가 확정되므로
// text.length()는 실행되지 않아 NullPointerException을 피할 수 있다.
```

단축 평가를 하지 않는 버전인 `&`와 `|`도 존재하지만(양쪽을 항상 평가), 이들은 실무에서 논리 연산보다는 다음 절의 비트 연산 맥락에서 더 자주 쓰인다.

## 4.4 비트 연산자

비트 연산자는 정수형 값을 이진수 비트 단위로 다룬다. 흔히 쓰이지는 않지만, 플래그 조합이나 저수준 최적화에서 여전히 쓰인다.

```java
int p = 0b1100; // 12
int q = 0b1010; // 10

System.out.println(p & q);  // 8  (0b1000, AND: 둘 다 1인 자리만 1)
System.out.println(p | q);  // 14 (0b1110, OR: 하나라도 1이면 1)
System.out.println(p ^ q);  // 6  (0b0110, XOR: 서로 다르면 1)
System.out.println(~p);     // -13 (NOT: 모든 비트 반전)

System.out.println(p << 2); // 48 (왼쪽으로 2비트 이동, 4를 곱한 효과)
System.out.println(p >> 2); // 3  (오른쪽으로 2비트 이동, 부호 유지)
System.out.println(-8 >>> 2); // 부호 없는 오른쪽 이동, 최상위 비트에 0이 채워짐
```

`>>`는 부호를 유지하는 산술 이동(음수는 왼쪽에 1이 채워짐)이고, `>>>`는 부호와 관계없이 왼쪽에 항상 0을 채우는 비트 이동이다. 이 둘의 차이는 음수를 다룰 때만 드러난다.

## 4.5 증감 연산자

`++`와 `--`는 변수의 값을 1만큼 늘리거나 줄인다. 변수 앞에 두느냐(전위) 뒤에 두느냐(후위)에 따라 표현식의 결과값이 달라진다.

```java
int i = 5;
System.out.println(i++); // 5 출력 후 i는 6이 됨 (후위: 먼저 값을 읽고 나중에 증가)
System.out.println(i);   // 6

int j = 5;
System.out.println(++j); // 6 출력 (전위: 먼저 증가시키고 그 값을 읽음)
System.out.println(j);   // 6
```

두 방식 모두 변수 자체의 최종 값은 같지만, **표현식 안에서 사용할 때 반환되는 값이 다르다**는 점이 핵심이다. 이 차이는 6장 반복문의 `for (int i = 0; i < n; i++)` 같은 구문에서 흔히 마주친다. 가독성을 위해 한 문장에서 같은 변수에 증감 연산자를 두 번 이상 쓰는 것은 피하는 것이 좋다.

## 4.6 삼항 연산자

삼항 연산자(`조건 ? 참일때값 : 거짓일때값`)는 `if-else`를 한 줄로 압축한 표현식이다. 5장에서 배울 `if` 문과 결과는 비슷하지만, 삼항 연산자는 문(statement)이 아니라 값으로 평가되는 표현식이라는 차이가 있다.

```java
int score = 85;
String result = (score >= 60) ? "합격" : "불합격";
System.out.println(result); // 합격

int a = 10, b = 20;
int max = (a > b) ? a : b;
System.out.println(max); // 20
```

삼항 연산자는 중첩할 수도 있지만, 두 번 이상 중첩하면 코드가 급격히 읽기 어려워지므로 이럴 때는 5장의 `if-else if` 체인을 쓰는 것이 낫다.

## 4.7 연산자 우선순위

한 표현식에 여러 연산자가 섞이면 어떤 연산을 먼저 계산할지 순서가 필요한데, 이를 **연산자 우선순위(operator precedence)**라 한다. 예를 들어 곱셈과 나눗셈은 덧셈과 뺄셈보다 먼저 계산되고, 비교 연산자는 논리 연산자보다 먼저 계산된다.

```java
int result = 2 + 3 * 4;       // 곱셈이 먼저: 2 + 12 = 14
boolean check = 1 < 2 && 3 > 2; // 관계 연산이 먼저: true && true = true
```

모든 연산자의 정확한 우선순위와 결합 방향(왼쪽에서 오른쪽인지, 오른쪽에서 왼쪽인지)을 외울 필요는 없다. 전체 표는 이 책의 부록에 정리해 두었으니 헷갈릴 때마다 참고하고, 실무에서는 우선순위를 완벽히 기억하기보다 **괄호 `()`를 적극적으로 사용해 의도를 명확히 드러내는 것**이 훨씬 안전하고 읽기 좋은 코드를 만든다.

```java
// 우선순위를 몰라도 괄호만으로 의도가 명확하다
int total = (2 + 3) * 4; // 20
```

## 4.8 instanceof 연산자 살짝 맛보기

지금까지 다룬 연산자들은 모두 기본형 값을 다뤘지만, `instanceof`는 참조형 변수가 가리키는 객체가 특정 타입(또는 그 하위 타입)인지를 검사해 `boolean`을 반환하는 연산자다.

```java
Object value = "안녕하세요";
System.out.println(value instanceof String); // true
```

지금 단계에서는 "어떤 객체가 무슨 타입인지 물어보는 연산자"라는 정도만 기억해두면 충분하다. `instanceof`가 왜 필요한지, 그리고 자바 16부터 지원하는 패턴 매칭(`if (value instanceof String s)`) 문법은 상속과 다형성을 다루는 10장, 그리고 인터페이스와 추상 클래스를 다루는 11장에서 클래스 계층 구조와 함께 훨씬 자연스럽게 이해할 수 있으므로 그때 자세히 다룬다.

## 요약

- 산술 연산자(`+ - * / %`)에서 정수 나눗셈은 소수점을 버리며, 실수 결과가 필요하면 피연산자를 `double`/`float`로 만들어야 한다.
- 관계 연산자(`== != > < >= <=`)는 `boolean` 값을 만들며, 참조형에서 `==`는 값이 아니라 참조를 비교한다.
- 논리 연산자(`&& || !`) 중 `&&`, `||`는 단축 평가를 하므로 조건 순서를 이용해 오류를 예방할 수 있다.
- 비트 연산자(`& | ^ ~ << >> >>>`)는 정수를 비트 단위로 다루며, `>>`와 `>>>`는 부호 처리 방식이 다르다.
- 증감 연산자(`++ --`)는 전위와 후위에 따라 표현식이 반환하는 값의 시점이 다르다.
- 삼항 연산자(`? :`)는 `if-else`를 값으로 표현하는 축약형이다.
- 연산자 우선순위는 부록의 표를 참고하되, 헷갈리면 괄호로 명확히 표현하는 습관을 들이자.
- `instanceof`는 객체의 타입을 검사하는 연산자로, 자세한 내용은 11장에서 다룬다.

## 연습문제

1. `int result = 7 / 2 + 7 % 2;`의 결과값을 계산 과정을 적어가며 예측하고, 실제로 실행해 확인하라.
2. `text`라는 `String` 변수가 `null`일 수도 있는 상황에서, `NullPointerException` 없이 `text`가 `null`이 아니고 길이가 0보다 큰지 검사하는 조건식을 단축 평가를 이용해 작성하라.
3. `int i = 3; int result = i++ + ++i;`를 실행했을 때 `result`와 최종 `i`의 값을 단계별로 추론하고 실제 실행 결과와 비교하라.
4. 삼항 연산자를 이용해 세 정수 중 가장 큰 값을 구하는 표현식을 작성하라. 그리고 같은 로직을 5장에서 배울 `if-else`로도 작성해 두 방식을 비교하라.
5. `5 & 3`, `5 | 3`, `5 ^ 3`의 결과를 각각 이진수로 손으로 계산한 뒤, 코드로 실행해 값을 확인하라.
