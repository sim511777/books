# 5장. 제어문

---

프로그램이 항상 위에서 아래로 한 줄씩만 실행된다면 할 수 있는 일은 매우 제한적입니다. 사용자의 입력값에 따라 다른 동작을 해야 하거나, 특정 조건을 만족할 때만 어떤 코드를 실행하고 싶을 때가 훨씬 많습니다. 이번 장에서는 실행 흐름을 조건에 따라 분기시키는 **제어문(control statement)**, 그중에서도 `if`문과 `switch`문을 다룹니다. 3장과 4장에서 익힌 변수와 연산자가 이제 실제로 "판단"을 내리는 데 쓰이는 셈입니다.

## if문의 기본 구조

`if`문은 조건식이 `true`일 때만 블록 안의 코드를 실행합니다. 조건식은 반드시 `boolean` 타입의 값이어야 합니다.

```java
public class TemperatureCheck {
    public static void main(String[] args) {
        int temperature = 32;

        if (temperature >= 30) {
            System.out.println("폭염 주의보 발령 수준입니다.");
        }

        System.out.println("현재 기온: " + temperature + "도");
    }
}
```

조건이 하나뿐이고 실행할 문장도 한 줄이라면 중괄호를 생략할 수 있지만, 이는 나중에 코드를 수정하다가 문장을 하나 더 추가하는 순간 버그의 원인이 되기 쉽습니다. 이 책에서는 항상 중괄호를 사용하는 스타일을 권장합니다.

```java
// 중괄호를 생략한 예 - 권장하지 않음
if (temperature >= 30)
    System.out.println("더워요");
    System.out.println("이 줄은 조건과 무관하게 항상 실행됩니다"); // 흔한 실수
```

## else와 else if

조건이 거짓일 때 실행할 코드는 `else`로 지정합니다. 여러 조건을 순서대로 검사해야 한다면 `else if`를 연결합니다.

```java
public class GradeEvaluator {
    public static void main(String[] args) {
        int score = 76;
        char grade;

        if (score >= 90) {
            grade = 'A';
        } else if (score >= 80) {
            grade = 'B';
        } else if (score >= 70) {
            grade = 'C';
        } else if (score >= 60) {
            grade = 'D';
        } else {
            grade = 'F';
        }

        System.out.println("점수 " + score + "점 -> 등급 " + grade);
    }
}
```

여기서 주의할 점은 `else if` 체인이 위에서부터 순서대로 평가된다는 것입니다. `score`가 95라면 첫 번째 조건에서 이미 `true`가 되어 `grade`에 `'A'`가 대입되고, 나머지 조건은 검사조차 하지 않습니다. 조건의 순서를 바꾸면 결과가 완전히 달라질 수 있으므로, 범위를 좁혀가는 조건은 항상 더 엄격한 조건부터 배치해야 합니다.

## switch문 - 기존 방식

여러 조건이 하나의 변수 값과의 "동등 비교"로만 이루어진다면 `switch`문이 `if-else` 체인보다 훨씬 읽기 좋습니다.

```java
public class DayNameOld {
    public static void main(String[] args) {
        int day = 3;
        String dayName;

        switch (day) {
            case 1:
                dayName = "월요일";
                break;
            case 2:
                dayName = "화요일";
                break;
            case 3:
                dayName = "수요일";
                break;
            case 4:
                dayName = "목요일";
                break;
            case 5:
                dayName = "금요일";
                break;
            case 6:
            case 7:
                dayName = "주말";
                break;
            default:
                dayName = "알 수 없는 요일";
        }

        System.out.println(day + "번째 요일은 " + dayName + "입니다.");
    }
}
```

`case 6`과 `case 7`을 연달아 붙여 놓은 부분을 눈여겨보세요. `case 6:` 바로 뒤에 `break`가 없으면 실행 흐름이 그대로 `case 7:`로 "떨어져 내려가는(fall-through)" 특성 때문에, 두 값에 대해 같은 코드를 공유할 수 있습니다. 반대로 각 `case` 끝에 `break`를 빠뜨리면 원치 않는 case까지 줄줄이 실행되는 흔한 실수가 발생합니다. `default`는 어떤 case에도 해당하지 않을 때 실행되며, 관례상 마지막에 두지만 문법적으로 위치가 강제되는 것은 아닙니다.

## switch 표현식 - Java 14+의 화살표 문법

Java 14부터는 `switch`를 문장이 아니라 **표현식**으로 사용할 수 있는 새로운 문법이 정식으로 도입되었습니다. 화살표(`->`)를 사용하면 `break`가 필요 없고, fall-through도 발생하지 않으며, 결과값을 바로 변수에 대입할 수 있습니다.

```java
public class DayNameModern {
    public static void main(String[] args) {
        int day = 3;

        String dayName = switch (day) {
            case 1 -> "월요일";
            case 2 -> "화요일";
            case 3 -> "수요일";
            case 4 -> "목요일";
            case 5 -> "금요일";
            case 6, 7 -> "주말";
            default -> "알 수 없는 요일";
        };

        System.out.println(day + "번째 요일은 " + dayName + "입니다.");
    }
}
```

`case 6, 7 -> "주말";`처럼 콤마로 여러 값을 한 줄에 나열할 수 있어 기존 방식보다 훨씬 간결합니다. 여러 줄의 로직이 필요하다면 중괄호와 `yield` 키워드로 값을 반환합니다.

```java
public class ShippingFee {
    public static void main(String[] args) {
        String region = "제주";

        int fee = switch (region) {
            case "서울", "경기", "인천" -> 2500;
            case "제주" -> {
                System.out.println("제주는 항공 운송비가 추가됩니다.");
                yield 6000; // 블록 안에서는 yield로 결과값을 반환한다
            }
            default -> 3500;
        };

        System.out.println("배송비: " + fee + "원");
    }
}
```

새 프로젝트라면 화살표 문법의 `switch` 표현식을 우선 고려할 만합니다. 다만 기존 코드베이스나 다른 사람이 작성한 코드를 읽을 일이 많으므로, 콜론(`:`)과 `break`를 쓰는 전통적인 `switch`문 역시 반드시 읽고 이해할 수 있어야 합니다.

## 삼항 연산자와의 관계

4장에서 다룬 삼항 연산자(`조건 ? 참일때값 : 거짓일때값`)는 사실 `if-else`를 표현식 형태로 축약한 것입니다. 단순히 두 값 중 하나를 고르는 상황이라면 삼항 연산자가 `if-else`보다 간결합니다.

```java
int score = 85;

// if-else로 작성
String result1;
if (score >= 60) {
    result1 = "합격";
} else {
    result1 = "불합격";
}

// 삼항 연산자로 작성 - 같은 의미, 더 짧다
String result2 = score >= 60 ? "합격" : "불합격";
```

하지만 조건이 세 개 이상이거나 각 분기에서 여러 동작을 해야 한다면 삼항 연산자를 억지로 중첩하는 것보다 `if-else if` 체인이나 `switch` 표현식을 쓰는 것이 가독성 면에서 낫습니다. 다음처럼 삼항 연산자를 중첩하면 코드를 읽는 사람이 한눈에 의미를 파악하기 어렵습니다.

```java
// 이렇게 중첩하지 말 것 - 가독성이 크게 떨어진다
String grade = score >= 90 ? "A" : score >= 80 ? "B" : score >= 70 ? "C" : "F";
```

## 중첩 조건문과 가독성

조건문 안에 또 다른 조건문을 넣는 것을 **중첩(nesting)**이라고 합니다. 중첩 자체는 문법적으로 아무 문제가 없지만, 깊어질수록 코드는 급격히 읽기 어려워집니다.

```java
public class LoginCheck {
    public static void main(String[] args) {
        boolean idExists = true;
        boolean passwordCorrect = false;
        boolean accountLocked = false;

        // 중첩이 깊어 조건들이 한눈에 들어오지 않는 예
        if (idExists) {
            if (!accountLocked) {
                if (passwordCorrect) {
                    System.out.println("로그인 성공");
                } else {
                    System.out.println("비밀번호가 일치하지 않습니다");
                }
            } else {
                System.out.println("계정이 잠겨 있습니다");
            }
        } else {
            System.out.println("존재하지 않는 아이디입니다");
        }
    }
}
```

이런 경우 조건을 뒤집어 "정상적이지 않은 경우를 먼저 걸러내고 일찍 반환/출력"하는 방식으로 중첩을 줄이면 훨씬 읽기 쉬워집니다. 이런 스타일을 흔히 **가드 조건(guard clause)**이라고 부르는데, 8장에서 메서드와 함께 `return`을 배우면 더 자연스럽게 활용할 수 있습니다. 지금 단계에서는 조건을 부정해서 먼저 처리하는 것만으로도 중첩 깊이를 줄일 수 있다는 감각을 익혀두는 것이 좋습니다.

```java
public class LoginCheckFlat {
    public static void main(String[] args) {
        boolean idExists = true;
        boolean passwordCorrect = false;
        boolean accountLocked = false;

        if (!idExists) {
            System.out.println("존재하지 않는 아이디입니다");
        } else if (accountLocked) {
            System.out.println("계정이 잠겨 있습니다");
        } else if (!passwordCorrect) {
            System.out.println("비밀번호가 일치하지 않습니다");
        } else {
            System.out.println("로그인 성공");
        }
    }
}
```

두 코드는 결과가 동일하지만, 두 번째 버전은 조건들이 나란히 나열되어 있어서 "이 코드가 검사하는 경우의 수가 몇 가지인지"를 한눈에 파악하기 쉽습니다. 일반적으로 중첩은 2~3단계를 넘지 않도록 하고, 그 이상 깊어질 것 같으면 조건 순서를 재배치하거나 별도의 메서드로 분리하는 것을 고려하세요.

## 요약

- `if`문은 `boolean` 조건이 참일 때만 블록을 실행하며, `else if`를 연결해 여러 조건을 순서대로 검사할 수 있습니다. 조건은 위에서부터 평가되므로 순서가 결과에 영향을 줍니다.
- 코드 블록에는 항상 중괄호를 사용하는 것이 실수를 줄이는 안전한 습관입니다.
- 기존 `switch`문은 콜론과 `case`, `break`, `default`로 구성되며, `break`를 빠뜨리면 fall-through가 발생합니다.
- Java 14부터 도입된 화살표(`->`) 기반 `switch` 표현식은 `break`가 필요 없고, 값을 바로 반환할 수 있으며, 여러 값을 콤마로 묶을 수 있어 더 간결합니다. 여러 줄의 로직이 필요하면 중괄호와 `yield`를 사용합니다.
- 삼항 연산자는 `if-else`의 축약형이지만, 중첩해서 쓰면 가독성이 떨어지므로 단순한 두 값 선택에만 사용하는 것이 좋습니다.
- 중첩 조건문은 깊어질수록 읽기 어려워지므로, 조건을 뒤집어 나열하는 방식으로 깊이를 줄이는 습관을 들이면 좋습니다.

## 연습문제

1. 정수형 변수 `age`를 선언하고, 13세 미만이면 "어린이", 13세 이상 19세 미만이면 "청소년", 19세 이상이면 "성인"을 출력하는 `if-else if` 문을 작성하세요.
2. 월(1~12)을 나타내는 정수를 입력받아 해당 계절("봄", "여름", "가을", "겨울")을 출력하는 프로그램을, 화살표 문법의 `switch` 표현식으로 작성하세요. (12, 1, 2월은 겨울, 3~5월은 봄 등으로 정의)
3. 정수 하나를 받아 양수/음수/0인지 판별하는 코드를 삼항 연산자를 중첩하지 않고, `if-else if`로 작성한 뒤 왜 중첩 삼항 연산자보다 나은지 한 문단으로 설명해보세요.
4. 세 개의 `boolean` 변수(`hasTicket`, `isVip`, `seatAvailable`)를 사용해 입장 가능 여부를 판단하는 코드를 깊게 중첩된 `if`문으로 먼저 작성한 다음, 가드 조건 스타일로 다시 작성해 두 버전을 비교해보세요.
5. 기존 콜론 방식의 `switch`문에서 `break`를 실수로 빠뜨렸을 때 어떤 문제가 발생하는지 예제 코드로 보여주고, 같은 로직을 화살표 문법으로 바꾸면 왜 그 문제가 원천적으로 사라지는지 설명해보세요.
