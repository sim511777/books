## 들어가며: 익명 클래스의 번거로움

11장에서 인터페이스는 "행동의 규격"이라고 배웠다. 인터페이스를 실제로 사용하려면 그 규격을 구현하는 클래스가 필요한데, 상황에 따라 이름 있는 클래스를 따로 만들기가 번거로울 때가 있다. 예를 들어 문자열 목록을 정렬할 때 정렬 기준을 직접 정의하고 싶다고 하자.

```java
import java.util.*;

public class SortExample {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>(List.of("Banana", "apple", "cherry"));

        // 대소문자를 구분하지 않고 정렬하기 위해 Comparator를 구현
        Collections.sort(names, new Comparator<String>() {
            @Override
            public int compare(String a, String b) {
                return a.compareToIgnoreCase(b);
            }
        });

        System.out.println(names); // [apple, Banana, cherry]
    }
}
```

`Comparator<String>`이라는 인터페이스를 구현하기 위해 이름 없는 클래스, 즉 익명 클래스(anonymous class)를 즉석에서 만들어 넘겼다. 코드가 하는 일은 "두 문자열을 대소문자 구분 없이 비교한다"는 한 줄짜리 로직인데, 이를 표현하기 위해 `new Comparator<String>() { ... }`라는 상당히 무거운 문법을 동원해야 한다. 클래스 선언, 메서드 시그니처, `@Override` 애너테이션까지 갖추고 나서야 진짜 로직인 `a.compareToIgnoreCase(b)` 한 줄이 등장한다.

이런 상황—인터페이스에 메서드가 딱 하나뿐이고, 그 메서드의 구현만 필요한 경우—는 자바 프로그램에서 매우 자주 나타난다. 자바 8부터는 이 패턴을 위해 훨씬 간결한 문법인 **람다 표현식(lambda expression)**을 제공한다.

## 함수형 인터페이스란

람다 표현식을 이해하려면 먼저 **함수형 인터페이스(functional interface)**라는 개념을 알아야 한다. 함수형 인터페이스는 **추상 메서드가 정확히 하나뿐인 인터페이스**를 말한다. 앞서 본 `Comparator<String>`도 `compare` 메서드 하나만 추상 메서드로 가지므로 함수형 인터페이스다.

```java
// 함수형 인터페이스 예시: 추상 메서드가 하나뿐이다
public interface Calculator {
    int calculate(int a, int b);
}
```

11장에서 배웠듯 인터페이스는 `default` 메서드나 `static` 메서드를 여러 개 가질 수 있지만, 그것들은 추상 메서드로 세지 않는다. 함수형 인터페이스의 조건은 오직 **구현해야 할 추상 메서드가 하나**라는 것뿐이다.

이 조건이 왜 중요할까? 추상 메서드가 하나라는 것은 "무엇을 구현해야 하는지"가 애매하지 않다는 뜻이다. 메서드 이름, 매개변수 개수와 타입, 반환 타입이 인터페이스 하나로 이미 정해져 있으니, 구현하는 쪽에서는 메서드 이름이나 시그니처를 다시 쓸 필요 없이 **본문만** 제공하면 충분하다. 바로 이 지점에서 람다 표현식이 등장한다.

컴파일러가 특정 인터페이스가 함수형 인터페이스임을 명확히 하도록 `@FunctionalInterface` 애너테이션을 붙이는 관례도 있다. 이 애너테이션을 붙이면, 실수로 추상 메서드를 두 개 이상 추가했을 때 컴파일 오류로 바로 알려준다.

```java
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);
}
```

## 람다 표현식 문법

람다 표현식은 "이름 없는 함수"를 표현하는 간결한 문법이다. 기본 형태는 다음과 같다.

```java
(매개변수 목록) -> 표현식 또는 블록
```

앞서 만든 `Calculator` 인터페이스를 람다로 구현해 보자.

```java
public class LambdaBasics {
    public static void main(String[] args) {
        // 익명 클래스 대신 람다로 Calculator를 구현
        Calculator add = (a, b) -> a + b;
        Calculator multiply = (a, b) -> a * b;

        System.out.println(add.calculate(3, 4));      // 7
        System.out.println(multiply.calculate(3, 4));  // 12
    }
}
```

`(a, b) -> a + b`라는 짧은 코드가 `Calculator` 인터페이스를 구현하는 객체를 만들어낸다. 매개변수 `a`, `b`의 타입은 컴파일러가 `Calculator.calculate(int, int)` 시그니처를 보고 자동으로 추론하므로 따로 쓰지 않아도 된다. 이를 **타입 추론(type inference)**이라 한다.

본문이 여러 문장으로 이루어질 때는 중괄호와 `return`을 사용한다.

```java
Calculator safeDivide = (a, b) -> {
    if (b == 0) {
        System.out.println("0으로 나눌 수 없습니다.");
        return 0;
    }
    return a / b;
};
```

매개변수가 하나뿐이면 괄호를 생략할 수 있고, 매개변수가 없으면 빈 괄호 `()`를 그대로 쓴다.

```java
// 매개변수 하나: 괄호 생략 가능
java.util.function.Function<Integer, Integer> square = x -> x * x;

// 매개변수 없음
Runnable greet = () -> System.out.println("안녕하세요!");
greet.run();
```

앞서 나온 정렬 예제를 람다로 다시 써보면 차이가 확연히 드러난다.

```java
List<String> names = new ArrayList<>(List.of("Banana", "apple", "cherry"));
Collections.sort(names, (a, b) -> a.compareToIgnoreCase(b));
System.out.println(names); // [apple, Banana, cherry]
```

익명 클래스로 8줄 가까이 쓰던 코드가 한 줄로 줄었다. 람다는 "새로운 종류의 객체"가 아니라, 함수형 인터페이스를 구현하는 객체를 만드는 **더 짧은 문법**일 뿐이라는 점을 기억하자. `add`, `multiply`, `safeDivide` 변수는 모두 여전히 `Calculator` 타입의 참조 변수다.

## 메서드 참조: 람다를 더 줄이기

람다 본문이 단순히 기존 메서드를 그대로 호출하는 경우, **메서드 참조(method reference)** 문법 `클래스명::메서드명`으로 더 줄일 수 있다.

```java
List<String> names = new ArrayList<>(List.of("Banana", "apple", "cherry"));

// 람다: (a, b) -> a.compareToIgnoreCase(b)
// 메서드 참조로 표현
Collections.sort(names, String::compareToIgnoreCase);
```

메서드 참조는 지금 단계에서 문법만 알아두면 충분하며, 원리를 이해했다면 람다와 자유롭게 바꿔 쓸 수 있다.

## 자바가 미리 만들어둔 함수형 인터페이스

매번 `Calculator`처럼 함수형 인터페이스를 직접 정의할 필요는 없다. 자바는 `java.util.function` 패키지에 자주 쓰이는 형태의 함수형 인터페이스를 미리 정의해두었다. 대표적인 네 가지를 살펴보자.

### Function<T, R>: 값을 받아 값을 반환

```java
import java.util.function.Function;

Function<String, Integer> stringLength = s -> s.length();
System.out.println(stringLength.apply("Java")); // 4
```

`Function<T, R>`은 타입 `T`를 받아 타입 `R`을 반환하는 `apply` 메서드 하나를 가진다. "입력을 받아 변환해서 출력한다"는 동작을 표현할 때 쓴다.

### Predicate<T>: 값을 받아 참/거짓을 반환

```java
import java.util.function.Predicate;

Predicate<Integer> isEven = n -> n % 2 == 0;
System.out.println(isEven.test(4));  // true
System.out.println(isEven.test(7));  // false
```

`Predicate<T>`는 `test` 메서드를 통해 조건을 검사하고 `boolean`을 반환한다. "이 값이 조건에 맞는가?"를 표현할 때 쓰며, 16장에서 배울 `filter` 연산이 바로 이 형태를 사용한다.

### Consumer<T>: 값을 받아 소비만 하고 반환값 없음

```java
import java.util.function.Consumer;

Consumer<String> printer = s -> System.out.println("결과: " + s);
printer.accept("완료"); // 결과: 완료
```

`Consumer<T>`는 `accept` 메서드로 값을 받아 어떤 동작(주로 출력이나 저장)을 수행하고 아무것도 반환하지 않는다.

### Supplier<T>: 아무것도 받지 않고 값을 반환

```java
import java.util.function.Supplier;

Supplier<String> greeting = () -> "안녕하세요, Java!";
System.out.println(greeting.get()); // 안녕하세요, Java!
```

`Supplier<T>`는 매개변수 없이 `get` 메서드로 값을 만들어낸다. 필요한 시점에 값을 "공급"하는 역할이라 이름이 그렇게 붙었다.

이 네 가지 인터페이스는 각각 입력·출력 개수만 다를 뿐 구조는 단순하다. 정리하면 다음과 같다.

| 인터페이스 | 메서드 | 입력 | 출력 |
|---|---|---|---|
| `Function<T, R>` | `apply` | 있음 | 있음 |
| `Predicate<T>` | `test` | 있음 | `boolean` |
| `Consumer<T>` | `accept` | 있음 | 없음 |
| `Supplier<T>` | `get` | 없음 | 있음 |

## 11장 인터페이스와의 관계

결국 람다는 완전히 새로운 개념이 아니라, 11장에서 배운 인터페이스를 구현하는 또 하나의 방법이다. 클래스로 구현하든, 익명 클래스로 구현하든, 람다로 구현하든, 결과적으로 만들어지는 것은 그 인터페이스 타입의 객체다. 다만 인터페이스에 추상 메서드가 정확히 하나일 때만 람다를 쓸 수 있다는 제약이 있을 뿐이다.

이 개념은 다음 장에서 본격적으로 쓰이게 된다. 16장에서 다룰 스트림(Stream) API는 `filter`, `map` 같은 메서드에 람다를 인자로 넘겨서 데이터 처리 파이프라인을 구성한다. 즉 15장에서 배운 람다 문법과 `Predicate`, `Function` 같은 함수형 인터페이스가 16장의 스트림을 이해하는 데 필요한 전제 지식이 된다.

## 요약

- 인터페이스를 구현하려고 매번 이름 있는 클래스나 무거운 익명 클래스를 만드는 것은 번거롭다.
- **함수형 인터페이스**는 추상 메서드가 정확히 하나뿐인 인터페이스이며, `@FunctionalInterface` 애너테이션으로 명시할 수 있다.
- **람다 표현식**은 `(매개변수) -> 본문` 형태로 함수형 인터페이스를 간결하게 구현하는 문법이다. 매개변수 타입은 컴파일러가 추론한다.
- 람다 본문이 기존 메서드 호출과 같다면 `클래스명::메서드명` 형태의 **메서드 참조**로 더 줄일 수 있다.
- `java.util.function` 패키지는 `Function<T, R>`(변환), `Predicate<T>`(판별), `Consumer<T>`(소비), `Supplier<T>`(생성)처럼 자주 쓰이는 함수형 인터페이스를 미리 제공한다.
- 람다는 11장의 인터페이스 개념을 대체하는 것이 아니라, 인터페이스를 구현하는 더 간결한 방법이며, 16장 스트림 API의 기반이 된다.

## 연습문제

1. 추상 메서드가 하나뿐인 함수형 인터페이스 `StringTransformer`를 정의하고, 문자열을 모두 대문자로 바꾸는 람다를 구현해 보라.
2. 다음 익명 클래스 코드를 람다 표현식으로 바꿔 보라.
   ```java
   Runnable task = new Runnable() {
       @Override
       public void run() {
           System.out.println("작업 실행");
       }
   };
   ```
3. `Predicate<Integer>`를 사용해 어떤 정수가 3의 배수인지 검사하는 람다를 작성하고, 1부터 10까지 정수 중 3의 배수만 출력해 보라.
4. `Function<Integer, Integer>`를 사용해 정수를 입력받아 제곱을 반환하는 람다를 작성하라.
5. 함수형 인터페이스에 추상 메서드가 두 개 이상이면 왜 람다로 구현할 수 없는지, `@FunctionalInterface` 애너테이션이 이를 어떻게 막아주는지 설명해 보라.
