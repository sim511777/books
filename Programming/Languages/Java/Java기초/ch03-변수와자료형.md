# 3장. 변수와 자료형

2장에서 우리는 `System.out.println("Hello, World!");` 한 줄을 컴파일하고 실행하는 과정을 살펴봤다. 이제부터는 프로그램이 실제로 다루는 대상, 즉 데이터를 담는 그릇인 **변수**와 그 그릇의 종류를 결정하는 **자료형**을 알아본다. 변수와 자료형은 이후 모든 장에서 계속 등장하는 가장 기본적인 재료이므로, 이 장의 내용은 눈으로만 읽지 말고 직접 코드를 작성해보며 익히길 권한다.

## 3.1 변수란 무엇인가

변수(variable)는 값을 저장하기 위해 이름을 붙인 메모리 공간이다. Java에서 변수를 사용하려면 반드시 **선언(declaration)** 을 해야 하는데, 이때 변수의 자료형과 이름을 함께 지정한다.

```java
int age;        // int형 변수 age를 선언 (아직 값은 없음)
age = 25;       // age에 값 25를 대입 (초기화)

int score = 90; // 선언과 동시에 초기화
```

Java는 **정적 타입 언어(statically typed language)** 다. 즉, 변수의 자료형이 컴파일 시점에 고정되며, 한 번 int로 선언한 변수에는 이후 문자열이나 실수를 담을 수 없다. 이는 파이썬이나 자바스크립트 같은 동적 타입 언어와 크게 다른 점이며, 컴파일러가 미리 많은 오류를 잡아주는 대신 타입을 정확히 명시해야 하는 책임이 개발자에게 있다.

변수 이름을 지을 때는 이 책의 스타일 가이드에 맞춰 camelCase(예: `totalScore`, `userName`)를 사용한다. 자바 문법상으로는 변수 이름이 문자, `_`, `$`로 시작해야 하고 숫자로 시작할 수 없으며, `class`, `int`, `if` 같은 예약어는 사용할 수 없다.

지역 변수는 반드시 사용하기 전에 초기화해야 한다. 다음 코드는 컴파일 오류가 난다.

```java
int count;
System.out.println(count); // 오류: count가 초기화되지 않았을 수 있음
```

## 3.2 기본형(primitive type) 8가지

Java의 자료형은 크게 **기본형(primitive type)**과 **참조형(reference type)**으로 나뉜다. 기본형은 언어 자체에 내장된 8가지 타입으로, 값 그 자체를 메모리에 직접 저장한다.

| 자료형 | 크기 | 표현 범위(근사) | 용도 |
|---|---|---|---|
| `byte` | 1바이트 | -128 ~ 127 | 아주 작은 정수, 파일/네트워크 바이트 데이터 |
| `short` | 2바이트 | -32,768 ~ 32,767 | 잘 쓰이지 않는 작은 정수 |
| `int` | 4바이트 | 약 -21억 ~ 21억 | 가장 널리 쓰는 정수형 |
| `long` | 8바이트 | 약 -922경 ~ 922경 | 매우 큰 정수(예: 밀리초 단위 시간) |
| `float` | 4바이트 | 약 ±3.4×10³⁸ (유효자리 약 7자리) | 정밀도가 낮아도 되는 실수 |
| `double` | 8바이트 | 약 ±1.8×10³⁰⁸ (유효자리 약 15자리) | 실수 계산의 기본 타입 |
| `char` | 2바이트 | 0 ~ 65,535 (유니코드 문자 1개) | 문자 하나 |
| `boolean` | 1비트(개념상) | `true` 또는 `false` | 참/거짓 |

```java
byte smallNumber = 100;
short year = 2026;
int population = 51000000;
long totalMillis = 9223372036854775807L; // long 리터럴은 L 접미사
float pi7 = 3.14159F;                    // float 리터럴은 F 접미사
double pi15 = 3.14159265358979;
char grade = 'A';                        // 문자는 단일 인용부호
boolean isPassed = true;
```

몇 가지 기억할 점이 있다.

- `int`는 자바에서 정수 연산의 기본 타입이다. 정수 리터럴은 별도 접미사가 없으면 자동으로 `int`로 취급된다.
- `long` 리터럴에는 반드시 `L`(또는 소문자 `l`, 하지만 숫자 `1`과 혼동되므로 대문자 권장)을 붙여야 한다.
- 실수 리터럴은 접미사가 없으면 기본적으로 `double`로 취급되므로, `float` 변수에 대입할 때는 `F` 접미사를 붙이거나 명시적 형변환이 필요하다.
- `char`는 내부적으로 2바이트 정수로 표현되는 유니코드 코드 포인트이며, 문자 연산 결과는 `int`로 승격된다는 점을 4장 연산자에서 다시 확인한다.
- `boolean`은 다른 숫자형과 서로 변환되지 않는 독립적인 타입이다. C 언어처럼 0과 1로 대체할 수 없다.

## 3.3 참조형과 기본형의 차이

기본형이 아닌 나머지 모든 타입, 즉 `String`, 배열, 그리고 우리가 9장에서 만들게 될 사용자 정의 클래스는 **참조형(reference type)**이다. 참조형 변수는 값 자체가 아니라 그 값(객체)이 저장된 메모리 위치를 가리키는 **참조(reference)**를 저장한다.

```java
int number = 10;              // 기본형: 변수 자체에 값 10이 저장됨
String name = "홍길동";        // 참조형: name은 "홍길동" 객체를 가리키는 참조를 저장
```

이 차이는 변수를 대입하거나 메서드에 전달할 때 뚜렷하게 드러난다. 기본형 변수를 다른 변수에 대입하면 값이 복사되어 두 변수는 완전히 독립적이지만, 참조형 변수를 대입하면 같은 객체를 가리키는 참조가 복사되므로 두 변수가 같은 객체를 공유하게 된다. 이 내용은 8장(메서드)과 9장(클래스와 객체)에서 매개변수 전달 방식과 함께 더 자세히 다룬다.

또한 참조형 변수는 아직 어떤 객체도 가리키지 않는 상태, 즉 `null`을 가질 수 있다. 기본형 변수에는 `null`을 대입할 수 없다.

```java
String city = null; // 아무 객체도 가리키지 않음
int count = null;   // 컴파일 오류: int는 참조형이 아니므로 null 불가
```

## 3.4 형변환: 암시적 변환과 명시적 변환

값의 자료형이 다른 변수 사이에 값을 옮기려면 형변환(type conversion)이 필요하다. Java는 두 가지 방식을 제공한다.

**암시적 변환(implicit conversion, widening)**은 더 작은 범위의 타입을 더 큰 범위의 타입으로 옮길 때 정보 손실이 없으므로 자동으로 이루어진다.

```java
int intValue = 100;
long longValue = intValue;   // int -> long, 자동 변환
double doubleValue = longValue; // long -> double, 자동 변환
```

변환이 가능한 대략적인 순서는 `byte -> short -> int -> long -> float -> double`이다(`char`는 `int`로 자동 변환된다). 다만 `long`에서 `float`나 `double`로 갈 때는 정밀도(유효자리 수)가 줄어들 수 있다는 점은 알아두자.

**명시적 변환(explicit conversion, narrowing, 흔히 캐스팅이라 부른다)**은 더 큰 범위의 타입을 더 작은 범위의 타입으로 옮길 때 필요하며, 정보가 손실될 수 있으므로 프로그래머가 의도를 명확히 표시해야 한다. 괄호 안에 원하는 타입을 적어서 수행한다.

```java
double price = 9999.99;
int roundedDown = (int) price;   // 결과: 9999, 소수점 이하가 버려짐(반올림 아님)

int big = 300;
byte small = (byte) big;         // byte 범위(-128~127)를 초과해 값이 예상치 못하게 바뀜(결과: 44)
```

캐스팅은 컴파일러가 "이 손실을 알고도 하는 것"이라고 인정해주는 도구일 뿐, 값을 안전하게 만들어주지는 않는다. `byte small = (byte) big;`의 결과가 44가 되는 이유는 300을 표현하는 비트 중 byte 크기(8비트)를 넘어가는 상위 비트가 잘려나가기 때문이다. 이런 오버플로 상황은 4장에서 연산자를 다루며 다시 언급한다.

## 3.5 리터럴

리터럴(literal)은 소스 코드에 직접 적은 값 자체를 말한다. 자바는 가독성을 위해 몇 가지 편의 표기를 지원한다.

```java
int decimal = 1000;
int hex = 0x3E8;          // 16진수 리터럴 (1000과 같은 값)
int binary = 0b1111101000; // 2진수 리터럴 (Java 7+)
int withUnderscore = 1_000_000; // 밑줄로 자리 구분(가독성용, 값에는 영향 없음)

char letter = 'A';
char unicodeChar = '가'; // 유니코드 이스케이프('가')
String greeting = "안녕하세요"; // 문자열 리터럴(String은 참조형)
```

`char`는 단일 인용부호(`'`), `String`은 이중 인용부호(`"`)를 사용한다는 점을 혼동하지 않도록 주의한다.

## 3.6 var를 이용한 지역 변수 타입 추론 (Java 10+)

Java 10부터는 지역 변수를 선언할 때 `var` 키워드로 타입을 컴파일러가 추론하게 할 수 있다.

```java
var count = 10;              // int로 추론됨
var name = "홍길동";          // String으로 추론됨
var price = 19.99;           // double로 추론됨
```

여기서 오해하기 쉬운 부분이 있는데, `var`는 동적 타입이 아니다. 컴파일 시점에 우변의 값을 보고 타입이 확정되며, 이후에는 여전히 정적 타입 언어의 규칙을 그대로 따른다.

```java
var count = 10;
count = "문자열"; // 컴파일 오류: count는 이미 int로 확정됨
```

`var`는 지역 변수에만 쓸 수 있고, 필드나 매개변수, 반환형에는 사용할 수 없다. 또한 초기값이 없거나(`var x;`) 초기값이 `null`뿐이면 타입을 추론할 근거가 없으므로 오류가 난다. 실무에서는 `ArrayList<String> names = new ArrayList<String>();`처럼 타입이 코드에 이미 명확히 드러나는 경우 `var names = new ArrayList<String>();`로 줄여 가독성을 높이는 용도로 주로 쓰이며, 타입이 한눈에 드러나지 않는 상황에서는 명시적 타입을 쓰는 것이 오히려 더 읽기 좋다.

## 요약

- 변수는 자료형과 이름을 갖는 메모리 공간이며, 지역 변수는 사용 전에 초기화해야 한다.
- Java의 기본형은 `byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean` 8가지이며 각각 고정된 크기와 표현 범위를 가진다.
- 참조형(`String`, 배열, 클래스 등)은 값이 아니라 객체를 가리키는 참조를 저장하며 `null`을 가질 수 있다.
- 작은 범위에서 큰 범위로 가는 변환은 암시적으로, 큰 범위에서 작은 범위로 가는 변환은 명시적 캐스팅으로 이루어지며 후자는 정보 손실 가능성이 있다.
- 정수, 실수, 문자, 문자열 리터럴에는 각각의 표기 규칙과 접미사(`L`, `F`)가 있다.
- `var`는 지역 변수의 타입을 컴파일러가 추론하게 하는 문법이며, 여전히 정적 타입을 따른다.

## 연습문제

1. 다음 각 값을 저장하기에 가장 적절한 기본형을 고르고 그 이유를 설명하라: (a) 사람의 나이, (b) 원-달러 환율(소수점 포함), (c) 어떤 상품의 재고 유무.
2. `int big = 130; byte small = (byte) big;`을 실행하면 `small`에 어떤 값이 저장되는지 예상하고, 그 이유를 비트 관점에서 설명하라.
3. 참조형 변수 두 개가 같은 객체를 가리키는 상황을 코드로 작성하고, 하나를 통해 값을 바꿨을 때 다른 변수로 확인한 값이 어떻게 되는지 실행해보라(9장에서 다시 다룰 개념의 예고편이다).
4. `var`를 사용했을 때 컴파일 오류가 발생하는 상황을 두 가지 이상 만들어보고, 왜 오류가 나는지 설명하라.
5. `0x1F`, `0b101`, `1_000_000` 세 리터럴이 각각 어떤 값을 나타내는지 10진수로 변환하라.
