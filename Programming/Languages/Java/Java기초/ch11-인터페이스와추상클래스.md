# 11장. 인터페이스와 추상 클래스

[◀ 이전: 10장. 상속과 다형성](ch10-상속과다형성.md) | [📖 목차](00-목차.md) | [다음: 12장. 예외 처리 ▶](ch12-예외처리.md)

10장에서는 상속을 통해 부모 클래스의 기능을 자식 클래스가 물려받고, 같은 메서드 호출이 실제 객체의 타입에 따라 다르게 동작하는 다형성을 살펴봤다. 그런데 상속만으로는 설계가 부족한 상황이 생긴다. 예를 들어 `Bird`와 `Airplane`은 둘 다 "날 수 있다"는 공통점이 있지만, 클래스 계층상 전혀 다른 뿌리를 가진다. 새는 동물이고 비행기는 기계이기 때문에 같은 부모 클래스를 둘 수 없다. 이럴 때 필요한 것이 바로 **인터페이스(interface)**다. 이번 장에서는 인터페이스의 정의와 구현, 추상 클래스와의 차이, 그리고 둘 중 어떤 것을 언제 써야 하는지를 다룬다.

## 인터페이스란 무엇인가

인터페이스는 클래스가 "무엇을 할 수 있는지"를 약속하는 명세다. 구현 코드는 하나도 없이 메서드의 이름과 시그니처만 정의하고, 실제 동작은 그 인터페이스를 구현하는 클래스가 채운다.

```java
// 날 수 있는 능력을 나타내는 인터페이스
public interface Flyable {
    void fly(); // 본문 없이 선언만 한다 (추상 메서드)
    void land();
}
```

인터페이스 안에 선언된 메서드는 기본적으로 `public abstract`가 붙은 것으로 간주되므로 따로 적지 않아도 된다. 인터페이스 자체로는 객체를 만들 수 없다. `new Flyable()`은 컴파일 오류다.

## implements로 인터페이스 구현하기

클래스는 `implements` 키워드로 인터페이스를 구현한다. 이때 인터페이스가 선언한 모든 추상 메서드를 반드시 구현해야 한다. 하나라도 빠뜨리면 컴파일 오류가 발생한다.

```java
public class Bird implements Flyable {
    private String name;

    public Bird(String name) {
        this.name = name;
    }

    @Override
    public void fly() {
        System.out.println(name + "가 날개를 펄럭이며 날아오른다");
    }

    @Override
    public void land() {
        System.out.println(name + "가 나뭇가지에 내려앉는다");
    }
}

public class Airplane implements Flyable {
    private String modelName;

    public Airplane(String modelName) {
        this.modelName = modelName;
    }

    @Override
    public void fly() {
        System.out.println(modelName + "이 이륙하여 활공한다");
    }

    @Override
    public void land() {
        System.out.println(modelName + "이 활주로에 착륙한다");
    }
}
```

`Bird`와 `Airplane`은 상속 관계로 묶일 수 없지만, `Flyable`이라는 공통 인터페이스를 통해 같은 방식으로 다룰 수 있다.

```java
public class FlyableDemo {
    public static void main(String[] args) {
        Flyable[] flyables = { new Bird("참새"), new Airplane("보잉747") };

        // 실제 타입이 무엇인지 상관없이 fly()를 호출할 수 있다
        for (Flyable f : flyables) {
            f.fly();
            f.land();
        }
    }
}
```

이렇게 인터페이스 타입으로 변수를 선언하고 실제 구현 객체를 담아 다루는 것은 10장에서 배운 다형성의 또 다른 형태다. 참조 변수의 타입은 인터페이스이지만, 실행 시점에 어떤 클래스의 `fly()`가 호출될지는 실제 객체가 결정한다.

## 다중 인터페이스 구현

자바 클래스는 오직 하나의 클래스만 상속(`extends`)할 수 있지만, 인터페이스는 **여러 개를 동시에 구현**할 수 있다. 이는 단일 상속의 한계를 보완하는 인터페이스의 핵심 장점이다.

```java
public interface Swimmable {
    void swim();
}

// 오리는 날 수도 있고 헤엄칠 수도 있다
public class Duck implements Flyable, Swimmable {
    private String name;

    public Duck(String name) {
        this.name = name;
    }

    @Override
    public void fly() {
        System.out.println(name + "가 낮게 날아간다");
    }

    @Override
    public void land() {
        System.out.println(name + "가 물 위에 내려앉는다");
    }

    @Override
    public void swim() {
        System.out.println(name + "가 물 위에서 헤엄친다");
    }
}
```

`Duck`은 `Flyable`과 `Swimmable`을 모두 구현했으므로 `Flyable` 타입으로도, `Swimmable` 타입으로도 취급될 수 있다.

## 인터페이스의 default 메서드와 static 메서드 (Java 8+)

자바 8 이전에는 인터페이스에 구현 코드를 전혀 넣을 수 없었다. 그래서 인터페이스에 메서드를 하나 추가하면 그것을 구현한 모든 클래스가 컴파일 오류를 일으키는 문제가 있었다. 이를 해결하기 위해 자바 8부터 **default 메서드**와 **static 메서드**가 도입되었다.

### default 메서드

`default` 키워드가 붙은 메서드는 본문을 가질 수 있고, 구현 클래스가 재정의하지 않으면 그 기본 동작을 그대로 사용한다.

```java
public interface Flyable {
    void fly();
    void land();

    // 기본 구현이 있는 메서드 — 구현 클래스가 원하면 재정의할 수 있다
    default void hover() {
        System.out.println("공중에 잠시 정지한다 (기본 동작)");
    }
}
```

`Bird`나 `Airplane`이 `hover()`를 따로 구현하지 않아도 인터페이스에 정의된 기본 동작이 호출된다. 만약 `Airplane`이 다른 방식으로 동작해야 한다면 `@Override`로 재정의하면 된다.

```java
public class Airplane implements Flyable {
    // ... fly(), land() 생략 ...

    @Override
    public void hover() {
        System.out.println("헬리콥터 모드로 제자리 비행한다");
    }
}
```

### static 메서드

인터페이스는 `static` 메서드도 가질 수 있다. 이 메서드는 구현 클래스의 인스턴스와 무관하게 인터페이스 이름으로 직접 호출하는 유틸리티성 메서드다.

```java
public interface Flyable {
    void fly();
    void land();

    static Flyable createDefault() {
        // 기본 구현체를 반환하는 팩토리 메서드
        return new Bird("이름없는새");
    }
}
```

```java
Flyable f = Flyable.createDefault(); // 인터페이스 이름으로 직접 호출
```

default와 static 메서드가 생기면서 인터페이스는 단순한 규칙 명세를 넘어 어느 정도의 공통 로직도 제공할 수 있게 되었다. 다만 인터페이스가 구현 코드로 가득 차면 추상 클래스와의 경계가 모호해질 수 있으므로, 여전히 인터페이스의 본질은 "할 수 있는 일의 약속"이라는 점을 기억해야 한다.

## 추상 클래스란 무엇인가

**추상 클래스(abstract class)**는 `abstract` 키워드가 붙은 클래스로, 인터페이스와 마찬가지로 직접 인스턴스를 만들 수 없다. 하지만 추상 클래스는 일반 클래스처럼 필드, 생성자, 완성된 메서드를 가질 수 있고, 그 안에 구현이 없는 추상 메서드를 섞어 넣을 수 있다.

```java
public abstract class Animal {
    protected String name; // 필드를 가질 수 있다

    public Animal(String name) { // 생성자도 가질 수 있다
        this.name = name;
    }

    // 완성된 메서드 - 공통 동작
    public void sleep() {
        System.out.println(name + "가 잠을 잔다");
    }

    // 추상 메서드 - 자식 클래스가 반드시 구현해야 한다
    public abstract void makeSound();
}
```

```java
public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public void makeSound() {
        System.out.println(name + "가 짖는다: 멍멍!");
    }
}
```

`Animal animal = new Animal("얼룩말");`처럼 추상 클래스를 직접 인스턴스화하려 하면 컴파일 오류가 난다. 오직 `Dog`처럼 추상 메서드를 모두 구현한 자식 클래스만 객체를 만들 수 있다.

## 추상 클래스와 인터페이스 비교

| 구분 | 추상 클래스 | 인터페이스 |
|---|---|---|
| 키워드 | `abstract class` | `interface` |
| 상속/구현 방식 | `extends` (단일 상속만 가능) | `implements` (다중 구현 가능) |
| 필드 | 일반 필드 가능 (`private`, `protected` 등) | 기본적으로 `public static final` 상수만 가능 |
| 생성자 | 가질 수 있음 | 가질 수 없음 |
| 일반 메서드 | 얼마든지 가질 수 있음 | `default`, `static` 메서드로 제한적 구현 가능 (Java 8+) |
| 접근 제어자 | 다양하게 지정 가능 | 메서드는 기본적으로 `public` |
| 목적 | "이것은 ~이다(is-a)" 관계, 공통 상태와 동작 공유 | "이것은 ~할 수 있다(can-do)" 관계, 행동의 규약 |
| 다중 적용 | 한 클래스는 하나의 추상 클래스만 상속 | 한 클래스가 여러 인터페이스를 동시에 구현 가능 |

## 언제 무엇을 쓸 것인가

두 도구는 비슷해 보이지만 목적이 다르다. 판단 기준은 대략 다음과 같다.

- **공통 상태(필드)와 생성자 로직을 자식들이 공유해야 한다면 추상 클래스**를 쓴다. 예를 들어 모든 `Animal`이 `name`이라는 필드와 `sleep()`이라는 공통 동작을 가진다면, 그 상태와 동작을 한 곳에 모아두는 것이 자연스럽다.
- **서로 관련 없는 클래스들에 공통 행동 규약만 부여하고 싶다면 인터페이스**를 쓴다. `Bird`와 `Airplane`처럼 상속 계층이 완전히 다른 클래스들에게 "날 수 있다"는 능력만 부여하려면 인터페이스가 적합하다.
- **다중 상속이 필요한 상황**이라면 인터페이스를 선택해야 한다. 자바는 클래스의 다중 상속을 허용하지 않으므로, `Duck`처럼 여러 능력을 동시에 가져야 하는 클래스는 인터페이스를 여러 개 구현하는 방식으로만 표현할 수 있다.
- 실무에서는 두 가지를 함께 쓰는 경우도 흔하다. 인터페이스로 "무엇을 할 수 있는가"의 큰 규약을 정의하고, 그 규약을 구현하는 추상 클래스를 중간에 두어 공통 로직을 제공한 뒤, 최종 클래스가 세부 사항만 채우는 3단 구조도 널리 쓰인다.

## 요약

- 인터페이스는 메서드의 시그니처만 정의하는 행동의 규약이며, `implements`로 구현한다.
- 클래스는 여러 인터페이스를 동시에 구현할 수 있어 단일 상속의 한계를 보완한다.
- 자바 8부터 인터페이스는 본문이 있는 `default` 메서드와 `static` 메서드를 가질 수 있게 되었다.
- 추상 클래스는 `abstract` 키워드로 선언하며, 필드·생성자·완성된 메서드와 추상 메서드를 함께 가질 수 있지만 단일 상속만 가능하다.
- 공통 상태와 구현을 공유해야 하면 추상 클래스, 서로 다른 계층의 클래스에 공통 행동만 부여하려면 인터페이스를 선택한다.

## 연습문제

1. `Chargeable`이라는 인터페이스를 만들어 `charge()` 추상 메서드를 선언하고, `Smartphone`과 `ElectricCar` 클래스가 이를 각각 구현하도록 작성해보자.
2. 위 `Chargeable` 인터페이스에 `default void checkBattery()` 메서드를 추가하고, 기본 동작을 출력하도록 구현한 뒤 한 클래스에서만 재정의해보자.
3. `Shape`라는 추상 클래스를 만들어 `area()`라는 추상 메서드와, 모든 도형이 공유할 `printInfo()`라는 완성된 메서드를 정의해보자. 이후 `Circle`, `Rectangle` 클래스로 상속받아 구현하라.
4. 어떤 상황에서 인터페이스 대신 추상 클래스를 선택해야 하는지, 그리고 그 반대의 경우는 언제인지 각각 예를 들어 설명해보자.
5. 하나의 클래스가 두 개 이상의 인터페이스를 구현할 때 두 인터페이스에 동일한 이름의 `default` 메서드가 있다면 어떤 문제가 발생할지 예상해보고, 실제로 코드를 작성하여 컴파일 오류 메시지를 확인해보자.
