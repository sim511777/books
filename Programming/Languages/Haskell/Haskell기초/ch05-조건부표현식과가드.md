# 5장. 조건부 표현식과 가드

4장에서는 패턴 매칭으로 함수의 인자를 여러 경우로 나누어 정의하는 방법을 살펴봤습니다. 하지만 "이 숫자가 0보다 크면 양수, 아니면 음수"처럼 패턴이 아니라 **조건(condition)**에 따라 분기해야 하는 경우도 많습니다. 이번 장에서는 Haskell에서 조건에 따라 값을 고르는 세 가지 도구인 `if-then-else`, 가드(guard), `case ... of`를 다룹니다. 세 가지 모두 겉보기엔 익숙하지만, Haskell에서는 하나같이 "**값을 만들어내는 표현식**"이라는 공통점을 갖고 있다는 점을 기억하며 읽어보세요.

## if-then-else는 표현식이다

C, Java, Python 같은 명령형 언어에서 `if`는 **문장(statement)**입니다. 조건에 따라 어떤 코드 블록을 실행할지 결정할 뿐, `if` 자체가 값을 갖지는 않습니다. 그래서 다음과 같은 Python 코드에서 `else`를 생략해도 문법적으로 문제가 없습니다.

```python
# Python: else가 없어도 됨
if x > 0:
    print("양수")
```

Haskell의 `if`는 완전히 다릅니다. `if-then-else`는 **표현식(expression)**이며, 반드시 하나의 값으로 평가됩니다. 이 말은 두 가지 중요한 규칙을 의미합니다.

1. `else`를 절대 생략할 수 없습니다. 조건이 거짓일 때 돌려줄 값이 없다면 표현식 전체가 값을 가질 수 없기 때문입니다.
2. `then` branch와 `else` branch는 **반드시 같은 타입**의 값을 내놓아야 합니다.

절댓값을 구하는 함수를 만들어봅시다.

```haskell
absoluteValue :: Int -> Int
absoluteValue n = if n < 0 then -n else n
```

```
ghci> absoluteValue (-7)
7
ghci> absoluteValue 7
7
```

`if n < 0 then -n else n` 전체가 하나의 `Int` 값으로 평가된다는 점이 핵심입니다. 그래서 `if`를 함수 인자 자리, `let` 바인딩, 다른 표현식 안 어디에나 자유롭게 끼워 넣을 수 있습니다.

```haskell
describeParity :: Int -> String
describeParity n =
    "이 숫자는 " ++ (if even n then "짝수" else "홀수") ++ "입니다."
```

```
ghci> describeParity 4
"이 숫자는 짝수입니다."
```

만약 `else`를 빼려고 하면 GHC는 곧바로 컴파일 오류를 냅니다. "값이 없는 경우가 있는 표현식"은 Haskell에서 존재할 수 없기 때문입니다. 이 원칙은 나중에 12장에서 `Maybe`와 `Either`로 "값이 없을 수도 있음"을 다룰 때 다시 마주치게 될 아이디어이기도 합니다 — Haskell은 "값이 없는 경우"조차 명시적인 값(`Nothing`)으로 표현하려는 언어입니다.

물론 조건이 여러 개로 갈라지면 `if`를 중첩해서 쓸 수도 있습니다.

```haskell
signOf :: Int -> String
signOf n =
    if n > 0
        then "양수"
        else if n < 0
            then "음수"
            else "영"
```

동작은 정확하지만, 이렇게 `if`를 계속 겹쳐 쓰면 들여쓰기가 깊어지고 읽기 어려워집니다. 조건이 셋 이상으로 갈라질 때는 아래에서 소개할 가드가 훨씬 깔끔한 대안입니다.

## 가드(Guard) 문법

4장에서 패턴 매칭은 인자의 **모양(shape)**을 검사했습니다. 예를 들어 리스트가 비어 있는지, 튜플의 첫 번째 원소가 특정 값인지 같은 것들입니다. 하지만 "이 수가 0보다 큰가?"처럼 모양이 아니라 **불(Boolean) 조건**을 검사해야 할 때는 패턴 매칭만으로 부족합니다. 이때 쓰는 것이 가드입니다. 가드는 함수 정의의 각 절(clause) 뒤에 `|` 기호로 붙는 조건들로, 위에서부터 차례로 검사되어 참(`True`)인 첫 번째 조건의 본문이 실행됩니다.

```haskell
signOf :: Int -> String
signOf n
    | n > 0     = "양수"
    | n < 0     = "음수"
    | otherwise = "영"
```

```
ghci> signOf 5
"양수"
ghci> signOf (-3)
"음수"
ghci> signOf 0
"영"
```

`otherwise`는 단순히 `True`로 정의된 값으로, 앞선 조건이 모두 거짓일 때 잡아주는 안전망 역할을 합니다. `otherwise`가 없고 모든 가드가 거짓이면, 그 함수 절은 매칭에 실패하고 런타임 오류가 발생합니다. 그래서 웬만하면 마지막 가드는 `otherwise`로 마무리하는 습관을 들이는 게 좋습니다.

가드는 패턴 매칭과 자연스럽게 함께 쓸 수 있습니다. 즉, 특정 패턴에 매칭된 다음에도 추가적인 조건으로 다시 나눌 수 있습니다.

```haskell
bmiCategory :: Double -> Double -> String
bmiCategory weight height
    | bmi <= 18.5 = "저체중"
    | bmi <= 23.0 = "정상"
    | bmi <= 25.0 = "과체중"
    | otherwise   = "비만"
  where
    bmi = weight / (height * height)
```

```
ghci> bmiCategory 68 1.75
"정상"
```

여기서 `where`로 정의한 `bmi`는 모든 가드에서 공유해서 사용할 수 있습니다. 같은 계산을 가드마다 반복하지 않아도 되니 코드가 훨씬 깔끔해집니다.

패턴과 가드를 함께 쓰는 예도 살펴봅시다. 리스트의 모양(패턴)과 값의 조건(가드)을 동시에 검사합니다.

```haskell
describeList :: [Int] -> String
describeList []           = "빈 리스트"
describeList [x]
    | x > 100   = "매우 큰 원소 하나"
    | otherwise = "원소 하나"
describeList (x:_)
    | x < 0     = "음수로 시작하는 리스트"
    | otherwise = "여러 원소를 가진 리스트"
```

```
ghci> describeList []
"빈 리스트"
ghci> describeList [200]
"매우 큰 원소 하나"
ghci> describeList [-5, 1, 2]
"음수로 시작하는 리스트"
```

즉 패턴은 "모양이 맞는가"를, 가드는 "값이 조건을 만족하는가"를 검사한다고 정리할 수 있습니다. 둘은 경쟁 관계가 아니라 상호 보완적인 도구입니다.

## case ... of 표현식

`if`가 두 갈래, 가드가 여러 갈래의 불 조건을 다룬다면, `case ... of`는 하나의 값을 여러 **패턴**과 비교해서 분기하는 표현식입니다. 사실 4장에서 배운, 함수 정의를 여러 절로 나누는 문법은 내부적으로 `case` 표현식으로 변환된다고 생각해도 무방합니다. `case`는 그 메커니즘을 함수 본문 어디에서나 직접 쓸 수 있게 해주는 표현식 버전입니다.

```haskell
describeDay :: Int -> String
describeDay day =
    case day of
        1 -> "월요일"
        2 -> "화요일"
        3 -> "수요일"
        4 -> "목요일"
        5 -> "금요일"
        6 -> "토요일"
        7 -> "일요일"
        _ -> "잘못된 요일 번호"
```

```
ghci> describeDay 3
"수요일"
ghci> describeDay 9
"잘못된 요일 번호"
```

C나 Java의 `switch`와 비슷해 보이지만 중요한 차이가 있습니다. `switch`는 문장이라 `break`를 빼먹으면 다음 케이스로 흘러 들어가는(fall-through) 버그가 흔합니다. Haskell의 `case`는 `if`와 마찬가지로 **표현식**이므로, 매칭된 브랜치 하나만 평가되어 값을 내놓고, 모든 브랜치는 같은 타입을 가져야 합니다. `_`는 어떤 값과도 매칭되는 와일드카드 패턴으로, `otherwise`처럼 안전망 역할을 합니다.

`case`의 각 브랜치에도 가드를 붙일 수 있어서, 패턴과 조건을 한 번에 표현할 수 있습니다.

```haskell
classify :: Int -> String
classify n =
    case n of
        0 -> "영"
        _ | n < 0     -> "음수"
          | n < 100   -> "작은 양수"
          | otherwise -> "큰 양수"
```

```
ghci> classify (-3)
"음수"
ghci> classify 42
"작은 양수"
```

`case`는 표현식이기 때문에 `let`이나 다른 함수 호출 인자 위치에도 자유롭게 넣을 수 있습니다.

```haskell
greet :: Int -> String
greet score =
    "결과: " ++ (case compare score 60 of
                    GT -> "합격"
                    EQ -> "합격"
                    LT -> "불합격")
```

```
ghci> greet 75
"결과: 합격"
```

여기서 `compare score 60`은 `Ordering` 타입의 값(`LT`, `EQ`, `GT` 중 하나)을 돌려주는데, `case`로 그 결과를 패턴 매칭한 것입니다. 이처럼 `case`는 특정 함수 정의 문법에 묶여 있지 않고, 값이 필요한 어디에서든 쓸 수 있는 범용 도구입니다.

## 요약

이번 장에서는 Haskell의 세 가지 조건 분기 도구를 살펴봤습니다.

- `if-then-else`는 문장이 아니라 **표현식**이며, `else`를 생략할 수 없고 두 branch는 같은 타입을 가져야 합니다.
- 가드(`|`)는 패턴 매칭 절 뒤에 불 조건을 위에서부터 순서대로 검사하며, `otherwise`로 안전망을 만드는 것이 관례입니다. 패턴은 "모양"을, 가드는 "조건"을 검사한다는 점에서 서로 보완적입니다.
- `case ... of`는 값 하나를 여러 패턴과 비교하는 표현식이며, 함수 정의의 여러 절 문법과 본질적으로 같은 일을 하지만 어디서나 직접 쓸 수 있습니다. `case`의 각 브랜치에 가드를 붙일 수도 있습니다.

이 세 도구 모두 "값을 만들어낸다"는 Haskell 표현식의 성질을 공유합니다. 다음 6장에서는 이 조건들과 함께 자주 등장하는 자료구조인 리스트의 기초를 다루면서, `if`와 가드, `case`를 실제 리스트 처리 함수에 적용해봅니다.

1. `if-then-else`를 사용해 세 정수 중 가장 큰 값을 돌려주는 `maxOfThree :: Int -> Int -> Int -> Int` 함수를 작성하세요.
2. 위 `maxOfThree`를 가드만 사용해서 다시 작성해보세요. 어느 쪽이 더 읽기 쉬운가요?
3. 정수를 받아 "fizz"(3의 배수), "buzz"(5의 배수), "fizzbuzz"(둘 다), 그 외에는 숫자 자체를 문자열로 돌려주는 `fizzbuzz :: Int -> String` 함수를 가드로 작성하세요.
4. `Ordering` 값(`LT`, `EQ`, `GT`)을 받아 각각 "작다", "같다", "크다"라는 문자열로 바꿔주는 함수를 `case ... of`로 작성하세요.
