# 1장. Haskell이란 무엇인가

## 들어가며

프로그래밍을 처음 배울 때 접하는 언어는 대부분 Python, Java, C++처럼 "명령형" 언어입니다. 이런 언어에서는 프로그램이 컴퓨터에게 "이렇게 하고, 그다음 저렇게 하고, 변수 값을 이렇게 바꿔라"라고 순서대로 지시하는 방식으로 동작합니다. Haskell은 이와는 근본적으로 다른 사고방식을 요구하는 **순수 함수형 프로그래밍 언어**입니다. 이 장에서는 Haskell이 어떤 언어인지, 왜 다른 언어들과 다르게 느껴지는지, 그리고 어떤 곳에서 실제로 쓰이는지를 살펴봅니다.

## 순수 함수형 언어라는 특징

Haskell에서 함수는 수학에서의 함수와 매우 비슷한 의미를 가집니다. 같은 입력을 넣으면 항상 같은 출력이 나오고, 함수를 호출하는 것만으로 프로그램의 다른 부분에 영향을 주는 일이 없습니다. 이런 성질을 **참조 투명성(referential transparency)**이라고 부릅니다. 예를 들어 다음과 같은 함수가 있다고 합시다.

```haskell
square :: Int -> Int
square x = x * x
```

`square 5`는 언제, 어디서, 몇 번을 호출하든 항상 `25`를 반환합니다. 전역 변수를 몰래 바꾸거나, 파일에 로그를 남기거나, 화면에 무언가를 출력하는 등의 부작용(side effect)이 전혀 없습니다. 이렇게 부작용이 없는 함수를 **순수 함수(pure function)**라고 합니다.

명령형 언어에서는 함수 안에서 전역 변수를 수정하거나, 객체의 내부 상태를 바꾸는 일이 흔합니다. Haskell은 이런 일을 원천적으로 막습니다. 값은 한번 만들어지면 절대 바뀌지 않는데, 이를 **불변성(immutability)**이라고 합니다. 리스트에 원소를 "추가"하는 것처럼 보이는 연산도 사실은 기존 리스트를 그대로 둔 채 새로운 리스트를 만들어내는 것입니다.

```haskell
ghci> let xs = [1, 2, 3]
ghci> let ys = 0 : xs
ghci> xs
[1,2,3]
ghci> ys
[0,1,2,3]
```

`xs`는 `ys`를 만든 뒤에도 전혀 바뀌지 않았습니다. 이런 불변성은 처음에는 불편하게 느껴질 수 있지만, 프로그램이 커질수록 "이 변수를 누가 언제 바꿨는지" 추적하는 부담을 크게 줄여줍니다.

물론 실제 프로그램은 화면에 출력을 하거나 파일을 읽는 등 부작용이 필요합니다. Haskell은 이런 부작용을 `IO`라는 특별한 타입으로 명확히 표시해서, 순수한 코드와 부작용이 있는 코드를 타입 수준에서 구분합니다. 이 내용은 15장 모나드와 IO에서 자세히 다룹니다.

## 강한 정적 타입과 타입 추론

Haskell은 **강한 정적 타입(strong static typing)** 언어입니다. 모든 값은 컴파일 시점에 타입이 결정되며, 타입이 맞지 않는 연산은 프로그램을 실행하기도 전에 컴파일 단계에서 오류로 잡힙니다. 예를 들어 문자열과 숫자를 더하려고 하면 컴파일이 되지 않습니다.

재미있는 점은 Haskell에서는 대부분의 경우 타입을 직접 적어주지 않아도 된다는 것입니다. 컴파일러가 코드를 분석해서 스스로 타입을 알아내는데, 이를 **타입 추론(type inference)**이라고 합니다.

```haskell
ghci> let double x = x + x
ghci> :type double
double :: Num a => a -> a
```

`double` 함수에 타입을 명시하지 않았지만, GHCi는 이 함수가 "숫자 타입 `a`를 받아서 같은 타입 `a`를 반환한다"는 사실을 스스로 추론해냈습니다. 타입 추론 덕분에 Haskell 코드는 짧고 간결하면서도, 정적 타입 언어의 안전성을 그대로 누릴 수 있습니다. 타입에 대한 자세한 내용은 3장과 11장에서 다룹니다.

## 지연 평가라는 실행 모델

대부분의 언어는 **즉시 평가(eager evaluation)**를 사용합니다. 표현식을 만나면 바로 계산해서 값을 만들어냅니다. Haskell은 반대로 **지연 평가(lazy evaluation)**를 기본 전략으로 사용합니다. 값이 실제로 필요해지는 순간까지 계산을 미루는 것입니다.

```haskell
ghci> let numbers = [1, 2, undefined, 4]
ghci> take 2 numbers
[1,2]
```

`numbers` 리스트의 세 번째 원소는 `undefined`로, 평가하면 오류가 발생하는 값입니다. 하지만 `take 2 numbers`는 앞의 두 원소만 필요로 하기 때문에 세 번째 원소는 평가되지 않고, 오류 없이 결과를 얻을 수 있습니다. 이런 지연 평가 덕분에 Haskell에서는 "무한히 긴 리스트"조차 자연스럽게 다룰 수 있습니다. 지연 평가의 원리와 활용법은 13장에서 깊이 다룹니다.

## Haskell은 어디에 쓰이는가

Haskell은 학계에서 프로그래밍 언어 이론과 타입 시스템 연구를 위한 도구로 오랫동안 사용되어 왔습니다. 동시에 산업 현장에서도 의외로 널리 쓰입니다.

- **금융 분야**: Standard Chartered, Barclays 같은 금융 기관은 복잡한 금융 상품을 정확하게 모델링하기 위해 Haskell을 사용합니다. 순수 함수와 강한 타입 시스템은 계산 오류를 줄이는 데 큰 도움이 됩니다.
- **컴파일러와 언어 도구**: GHC(Haskell 컴파일러) 자체가 Haskell로 작성되어 있으며, Rust 컴파일러 초기 버전이나 여러 정적 분석 도구도 Haskell로 만들어졌습니다.
- **학계와 연구**: 타입 시스템, 프로그램 검증, 동시성 모델 등 다양한 컴퓨터 과학 연구에서 Haskell은 이상적인 실험 도구로 쓰입니다.

이렇게 신뢰성이 중요한 분야에서 Haskell이 선택받는 이유는 결국 앞서 설명한 순수성과 강한 타입 시스템이 버그를 줄여주기 때문입니다.

## 명령형 언어와의 사고방식 차이

Python이나 Java에 익숙한 사람이 Haskell을 처음 배우면 가장 크게 부딫히는 부분이 "반복문이 없다"는 사실입니다. Haskell에는 `for`나 `while` 같은 반복문이 없습니다. 대신 **재귀(recursion)**와 **고차 함수(higher-order function)**를 사용해 반복적인 작업을 표현합니다.

명령형 언어로 리스트의 모든 원소를 두 배로 만드는 코드는 보통 이렇게 생겼습니다.

```python
result = []
for x in numbers:
    result.append(x * 2)
```

Haskell에서는 "무엇을 할지"를 선언하는 방식으로 같은 일을 표현합니다.

```haskell
ghci> map (*2) [1, 2, 3, 4]
[2,4,6,8]
```

`map` 함수는 "리스트의 각 원소에 이 함수를 적용해달라"는 의도를 그대로 코드로 옮긴 것입니다. 어떻게 반복할지에 대한 세부 사항은 `map`이 알아서 처리합니다. 이런 스타일을 **선언형 프로그래밍(declarative programming)**이라고 부르며, 고차 함수는 9장에서 본격적으로 다룹니다.

## GHC와 GHCi 설치하기

Haskell 코드를 실행하려면 컴파일러가 필요합니다. 가장 널리 쓰이는 구현체는 **GHC(Glasgow Haskell Compiler)**이며, 대화형으로 코드를 실험해볼 수 있는 **GHCi**도 함께 제공됩니다.

가장 간단한 설치 방법은 공식 설치 도구인 **GHCup**을 사용하는 것입니다.

```
# Windows(PowerShell), macOS, Linux 공통 안내 페이지: https://www.haskell.org/ghcup/
# GHCup을 설치하면 ghc, ghci, cabal, stack 명령을 한 번에 설치할 수 있습니다.
```

설치가 끝나면 터미널에서 버전을 확인해봅니다.

```
> ghc --version
The Glorious Glasgow Haskell Compilation System, version 9.x.x
> ghci --version
The Glorious Glasgow Haskell Compilation System, version 9.x.x
```

GHC와 GHCi를 실제로 실행하고 첫 코드를 작성하는 구체적인 과정은 2장에서 이어서 다룹니다.

## 이 책의 학습 방향

이 책은 Haskell을 처음 배우는 독자를 대상으로, 실행 가능한 예제와 GHCi 실습을 중심으로 진행됩니다. 3장부터는 기본 문법과 데이터 타입, 함수 정의, 패턴 매칭 같은 기초를 다지고, 이후 재귀와 고차 함수로 Haskell다운 사고방식을 익힙니다. 후반부에서는 커스텀 데이터 타입, 타입클래스, 펑터와 모나드처럼 Haskell의 핵심 개념을 다루며, 마지막에는 실전에서 좋은 Haskell 코드를 작성하는 습관까지 살펴봅니다.

Haskell을 배우는 과정은 처음에는 낯설고 답답하게 느껴질 수 있습니다. 반복문이 없고, 변수를 바꿀 수 없고, 타입 오류 메시지는 길고 복잡해 보입니다. 하지만 이 낯섦을 넘어서면, 코드가 "왜 동작하는지"를 훨씬 명확하게 이해하게 되고, 컴파일러가 잡아주는 안전망 덕분에 오히려 더 자유롭게 코드를 고칠 수 있게 됩니다.

## 요약

이번 장에서는 Haskell이 어떤 언어인지 큰 그림을 살펴보았습니다. Haskell은 부작용이 없는 순수 함수와 참조 투명성을 기본으로 하는 순수 함수형 언어이며, 값의 불변성을 지킵니다. 강한 정적 타입 시스템과 타입 추론을 통해 안전하면서도 간결한 코드를 작성할 수 있고, 지연 평가라는 독특한 실행 모델을 사용해 필요한 계산만 수행합니다. 금융, 컴파일러, 학계 등 신뢰성이 중요한 분야에서 실제로 활용되고 있으며, 반복문 대신 재귀와 고차 함수를 사용하는 선언형 사고방식이 명령형 언어와 가장 큰 차이점입니다. GHC와 GHCi 설치까지 마쳤다면, 2장에서 본격적으로 첫 코드를 실행해볼 준비가 된 것입니다.

## 연습문제

1. 참조 투명성이란 무엇인지 자신의 말로 설명하고, 참조 투명성을 만족하지 않는 함수의 예를 명령형 언어(Python이나 Java 등)에서 하나 떠올려 보세요.
2. 순수 함수와 부작용이 있는 함수의 차이를 예시 코드와 함께 설명해 보세요.
3. 지연 평가가 왜 무한 리스트를 다루는 데 유용한지, 즉시 평가와 비교해서 설명해 보세요.
4. 타입 추론이 있는 언어와 없는 언어(또는 동적 타입 언어)의 차이를 각각 한 가지 장단점씩 들어 설명해 보세요.
5. 자신이 알고 있는 명령형 언어의 반복문 예제 하나를 골라, Haskell이라면 어떤 함수(예: `map`, `filter`)로 대체할 수 있을지 추측해 보세요.
