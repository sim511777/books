## 함수도 값이다

4장에서 함수 정의를 배우면서, Haskell에서는 함수 역시 다른 값들과 마찬가지로 취급된다는 점을 잠깐 언급했다. 정수나 문자열을 변수에 담을 수 있듯, 함수도 변수에 담을 수 있고, 다른 함수의 인자로 넘길 수 있고, 심지어 함수를 결과로 반환하는 함수도 만들 수 있다. 이런 성질을 가진 함수를 **고차 함수(higher-order function)**라고 부른다.

고차 함수는 "함수를 인자로 받는 함수" 또는 "함수를 결과로 반환하는 함수" 둘 중 하나(혹은 둘 다)에 해당하는 함수를 말한다. 예를 들어 다음 함수는 함수 하나와 숫자 하나를 받아서, 그 함수를 숫자에 두 번 적용한다.

```haskell
applyTwice :: (a -> a) -> a -> a
applyTwice f x = f (f x)
```

타입 시그니처를 보면 `(a -> a)`라는 부분이 있는데, 이것은 "`a`를 받아서 `a`를 돌려주는 함수"라는 타입이다. `applyTwice`는 이런 함수 `f`와 값 `x`를 받아서 `f x`를 계산하고 그 결과에 다시 `f`를 적용한다.

```haskell
ghci> applyTwice (+3) 10
16
ghci> applyTwice (++ " world") "hello"
"hello world world"
```

`(+3)`은 3을 더하는 함수이고, `applyTwice`는 이 함수를 10에 두 번 적용해서 `10 + 3 + 3 = 16`을 얻는다. 이렇게 함수를 값처럼 주고받을 수 있다는 사실이 Haskell 프로그래밍의 핵심이다. 이번 장에서는 이 개념을 실제로 활용하는 대표적인 고차 함수들, 즉 `map`, `filter`, `foldr`/`foldl`을 살펴보고, 람다 표현식과 커링, 함수 합성까지 다룬다.

## map: 리스트의 모든 요소 변환하기

6장에서 리스트를 다룰 때 각 요소에 어떤 연산을 적용하고 싶은 경우가 많았다. `map` 함수는 리스트의 모든 요소에 주어진 함수를 적용해서 새 리스트를 만들어준다.

```haskell
map :: (a -> b) -> [a] -> [b]
```

타입을 보면 `a`를 `b`로 바꾸는 함수와 `a`의 리스트를 받아서 `b`의 리스트를 돌려준다. 입력과 출력의 타입이 달라도 된다는 점이 중요하다.

```haskell
ghci> map (*2) [1,2,3,4]
[2,4,6,8]
ghci> map show [1,2,3]
["1","2","3"]
ghci> map (\x -> x * x) [1,2,3,4,5]
[1,4,9,16,25]
```

`map`이 없었다면 재귀로 다음처럼 직접 구현해야 했을 것이다. 8장에서 배운 재귀와 비교해보면 `map`이 하는 일이 명확해진다.

```haskell
doubleAll :: [Int] -> [Int]
doubleAll [] = []
doubleAll (x:xs) = (x * 2) : doubleAll xs
```

`map (*2)`는 정확히 이 함수와 같은 일을 한다. 반복되는 재귀 패턴을 함수로 뽑아내고, "무엇을 할지"만 인자로 넘기는 것이 고차 함수의 핵심 아이디어다.

## filter: 조건에 맞는 요소만 골라내기

`filter`는 리스트에서 특정 조건을 만족하는 요소만 남긴다.

```haskell
filter :: (a -> Bool) -> [a] -> [a]
```

`a -> Bool` 타입의 함수를 **술어(predicate)**라고 부른다. 각 요소에 술어를 적용해서 `True`가 나오는 것만 결과 리스트에 남긴다.

```haskell
ghci> filter even [1..10]
[2,4,6,8,10]
ghci> filter (\x -> length x > 3) ["cat", "elephant", "dog", "giraffe"]
["elephant","giraffe"]
ghci> filter (/= ' ') "hello world"
"helloworld"
```

`map`과 `filter`는 함께 자주 쓰인다. 예를 들어 1부터 20까지 숫자 중 짝수만 골라 제곱한 결과를 구해보자.

```haskell
ghci> map (^2) (filter even [1..20])
[4,16,36,64,100,144,196,256,324,400]
```

이렇게 작은 함수들을 조합해서 원하는 계산을 표현하는 방식이 Haskell 스타일 코드의 특징이다. 5장에서 배운 가드를 술어 안에 활용할 수도 있다.

```haskell
isValidAge :: Int -> Bool
isValidAge age
  | age < 0   = False
  | age > 150 = False
  | otherwise = True

ghci> filter isValidAge [-5, 20, 200, 45, 70]
[20,45,70]
```

## fold: 리스트를 하나의 값으로 접기

`map`과 `filter`는 리스트를 리스트로 바꾼다. 반면 리스트의 모든 요소를 하나로 "접어서(fold)" 합계, 최댓값, 문자열 연결 같은 단일 결과를 만들어야 할 때가 있다. 이럴 때 쓰는 함수가 `foldr`와 `foldl`이다.

```haskell
foldr :: (a -> b -> b) -> b -> [a] -> b
foldl :: (b -> a -> b) -> b -> [a] -> b
```

세 개의 인자를 받는다: 결합 방법을 나타내는 함수, 초기값(누산기의 시작 값), 그리고 리스트. 예를 들어 리스트의 합을 구하는 `sum`은 `foldr`로 이렇게 표현할 수 있다.

```haskell
mySum :: [Int] -> Int
mySum = foldr (+) 0

ghci> mySum [1,2,3,4,5]
15
```

`foldr (+) 0 [1,2,3]`이 계산되는 과정을 펼쳐보면 다음과 같다.

```haskell
foldr (+) 0 [1,2,3]
= 1 + (2 + (3 + 0))
= 6
```

`foldr`는 리스트의 오른쪽 끝(초기값)부터 시작해서 각 요소를 함수로 하나씩 결합해 나간다. 이름의 `r`은 결합이 오른쪽에서부터(right) 일어난다는 뜻이다. 반대로 `foldl`은 왼쪽부터 누적한다.

```haskell
foldl (+) 0 [1,2,3]
= ((0 + 1) + 2) + 3
= 6
```

합계처럼 결합 순서가 결과에 영향을 주지 않는 연산이라면 `foldr`와 `foldl` 어느 쪽을 써도 결과는 같다. 하지만 순서가 중요한 경우에는 차이가 드러난다. 문자열을 뒤집어 이어붙이는 예를 보자.

```haskell
ghci> foldr (\x acc -> acc ++ [x]) [] [1,2,3]
[3,2,1]
ghci> foldl (\acc x -> acc ++ [x]) [] [1,2,3]
[1,2,3]
```

`foldr`는 함수의 두 번째 인자로 누산기를 받고(`a -> b -> b`), `foldl`은 첫 번째 인자로 누산기를 받는다(`b -> a -> b`)는 순서 차이도 기억해두면 헷갈리지 않는다.

`fold`를 이용하면 `length`, `reverse`, `maximum` 같은 함수들도 직접 만들 수 있다.

```haskell
myLength :: [a] -> Int
myLength = foldr (\_ acc -> acc + 1) 0

myReverse :: [a] -> [a]
myReverse = foldl (\acc x -> x : acc) []

myMaximum :: [Int] -> Int
myMaximum = foldr1 max
```

마지막 예시의 `foldr1`은 초기값 없이 리스트의 첫 요소를 초기값으로 사용하는 버전이다. 단, 빈 리스트에는 사용할 수 없으니 주의해야 한다.

```haskell
ghci> myMaximum [3, 7, 2, 9, 4]
9
```

## 람다: 이름 없는 함수

지금까지 예제에서 `\x -> x * x` 같은 표현을 여러 번 사용했다. 이것을 **람다(lambda)** 또는 익명 함수(anonymous function)라고 부른다. `\`는 그리스 문자 λ(람다)를 흉내 낸 표기이고, `->` 뒤에 함수의 본문이 온다.

```haskell
ghci> (\x -> x + 1) 5
6
ghci> (\x y -> x * y) 3 4
12
```

람다는 어딘가에 딱 한 번만 쓰이는 짧은 함수를 위해 별도의 이름을 붙이기 귀찮을 때 유용하다. 특히 `map`이나 `filter`에 넘길 함수를 그 자리에서 즉석으로 만들 때 자주 쓴다.

```haskell
ghci> map (\x -> if even x then x else -x) [1..6]
[-1,2,-3,4,-5,6]
```

물론 이름 있는 함수로 똑같이 표현할 수도 있다.

```haskell
signedByParity :: Int -> Int
signedByParity x = if even x then x else -x

ghci> map signedByParity [1..6]
[-1,2,-3,4,-5,6]
```

이름 있는 함수는 재사용하기 좋고 의미를 드러내는 이름을 붙일 수 있는 반면, 람다는 코드를 짧게 유지할 수 있다. 함수가 여러 곳에서 쓰이거나 로직이 복잡하면 이름을 붙이고, 그 자리에서만 쓰이는 단순한 변환이라면 람다를 쓰는 것이 일반적인 관례다.

## 부분 적용과 커링

Haskell의 모든 함수는 사실 인자를 **하나씩만** 받는다. 두 개의 인자를 받는 것처럼 보이는 함수도 실제로는 "인자 하나를 받아서, 나머지 인자를 받는 함수를 반환하는" 함수다. 이런 성질을 **커링(currying)**이라고 한다.

`add :: Int -> Int -> Int`라는 시그니처를 예로 들어보자. 이는 실제로 `Int -> (Int -> Int)`와 같다. 즉 `Int`를 받아서 `Int -> Int` 타입의 함수를 돌려준다는 뜻이다.

```haskell
add :: Int -> Int -> Int
add x y = x + y

ghci> add 3 5
8
ghci> :type add 3
add 3 :: Int -> Int
```

`add 3`처럼 인자를 일부만 넘기는 것을 **부분 적용(partial application)**이라고 한다. `add 3`은 "3을 더하는 함수"라는 새로운 함수 값이 된다.

```haskell
ghci> let add3 = add 3
ghci> add3 10
13
ghci> map (add 10) [1,2,3]
[11,12,13]
```

앞서 사용했던 `(*2)`, `(+3)` 같은 표기도 부분 적용의 한 형태다. 이를 **연산자 섹션(operator section)**이라고 부른다.

```haskell
ghci> map (*2) [1,2,3]
[2,4,6]
ghci> map (subtract 1) [1,2,3]
[0,1,2]
```

`(*2)`는 `\x -> x * 2`와 같고, `(2*)`도 마찬가지로 `\x -> 2 * x`와 같다. 다만 `-` 연산자는 섹션으로 쓸 때 음수 리터럴과 혼동되므로 `(subtract 1)`처럼 `subtract` 함수를 쓰는 것이 안전하다.

커링 덕분에 함수를 "설정해두고" 나중에 나머지 인자를 채워 넣는 스타일의 코드를 자연스럽게 쓸 수 있다. 이것이 고차 함수와 부분 적용이 특히 잘 어울리는 이유다.

## 함수 합성

**함수 합성(function composition)**은 두 함수를 이어붙여 하나의 새 함수를 만드는 것이다. Haskell은 이를 위한 `.` 연산자를 제공한다.

```haskell
(.) :: (b -> c) -> (a -> b) -> a -> c
(f . g) x = f (g x)
```

`f . g`는 "먼저 `g`를 적용하고, 그 결과에 `f`를 적용하는" 새로운 함수다. 수학에서 함수 합성을 쓰던 것과 똑같은 방향이니 기억해두면 헷갈리지 않는다.

```haskell
ghci> let addOneThenDouble = (*2) . (+1)
ghci> addOneThenDouble 5
12
```

`5`에 먼저 `(+1)`이 적용되어 `6`이 되고, 그 결과에 `(*2)`가 적용되어 `12`가 된다. 여러 함수를 체인처럼 연결할 수도 있다.

```haskell
ghci> let process = filter even . map (*3)
ghci> process [1,2,3,4,5]
[6,12]
```

`map (*3) [1,2,3,4,5]`는 `[3,6,9,12,15]`가 되고, 여기서 `filter even`을 적용하면 `[6,12]`가 남는다. 함수 합성을 쓰면 중간 결과에 이름을 붙이지 않고도 데이터 처리 파이프라인을 한 줄로 표현할 수 있다.

다음처럼 괄호와 중간 변수를 쓰는 코드와 비교해보자.

```haskell
-- 합성을 쓰지 않은 버전
processVerbose :: [Int] -> [Int]
processVerbose xs = filter even (map (*3) xs)

-- 합성을 쓴 버전
processCompact :: [Int] -> [Int]
processCompact = filter even . map (*3)
```

두 함수는 완전히 동일하게 동작하지만, 합성을 쓴 버전은 인자 `xs`를 언급하지 않는다는 점이 눈에 띈다. 이런 스타일을 **포인트-프리(point-free) 스타일**이라고 부르는데, "값을 가리키는 변수(포인트) 없이" 함수 자체를 조합해서 정의를 만든다는 뜻이다. 항상 포인트-프리가 더 좋은 것은 아니며, 합성 체인이 너무 길어지면 오히려 읽기 어려워질 수 있으니 상황에 맞게 선택하면 된다.

## map, filter, fold, 합성을 함께 사용하기

배운 내용을 모아 간단한 예제를 만들어보자. 학생들의 점수 리스트가 있을 때, 60점 이상인 점수만 골라 10점을 보너스로 더하고, 그 총합을 구하는 함수를 작성해본다.

```haskell
scoreSummary :: [Int] -> Int
scoreSummary = sum . map (+10) . filter (>= 60)

ghci> scoreSummary [45, 72, 88, 55, 91, 60]
321
```

이 한 줄은 다음 순서로 동작한다: 먼저 `filter (>= 60)`으로 60점 이상만 남기고(`[72,88,91,60]`), `map (+10)`으로 각각에 10을 더하고(`[82,98,101,70]`), 마지막으로 `sum`으로 전부 더한다(`351`이 아니라 실제로는 위 예시 값 기준으로 계산된 값). 함수 합성은 오른쪽에서 왼쪽으로 적용된다는 점을 항상 기억하자.

## 요약

이번 장에서는 함수를 값처럼 다루는 고차 함수의 개념을 배웠다. `map`은 리스트의 모든 요소를 변환하고, `filter`는 조건을 만족하는 요소만 골라내며, `foldr`/`foldl`은 리스트를 하나의 값으로 접는다. 람다(`\x -> ...`)는 이름 없는 즉석 함수를 만드는 방법이고, 커링과 부분 적용은 Haskell의 모든 함수가 인자를 하나씩만 받는다는 사실에서 자연스럽게 나오는 성질이다. 마지막으로 함수 합성 연산자 `.`는 여러 함수를 파이프라인처럼 이어붙여 간결한 코드를 작성하게 해준다. 이 도구들은 8장의 재귀를 대체하는 경우가 많으며, 앞으로 12장의 `Maybe`/`Either` 처리나 14장의 펑터/애플리커티브를 이해하는 데도 중요한 기반이 된다.

## 연습문제

1. `map`과 `filter`만 사용해서, 정수 리스트에서 3의 배수를 찾아 각각 제곱한 리스트를 반환하는 함수 `squareMultiplesOfThree`를 작성하라.
2. `foldl`을 사용해서 리스트에 있는 모든 문자열의 총 길이를 구하는 함수 `totalLength :: [String] -> Int`를 작성하라. (힌트: 누산기에 길이를 계속 더한다.)
3. `applyTwice`처럼, 함수와 횟수를 받아서 그 함수를 지정한 횟수만큼 반복 적용하는 `applyN :: Int -> (a -> a) -> a -> a`를 작성하라. `applyN 3 (+1) 10`은 `13`이어야 한다.
4. 연산자 섹션을 사용해서 리스트의 모든 요소에서 5를 빼는 함수와, 5에서 각 요소를 빼는 함수를 각각 한 줄로 작성하고 결과가 다름을 GHCi에서 확인하라.
5. `filter`, `map`, `.` 합성 연산자를 사용해서 문자열 리스트 중 길이가 5 이상인 것만 대문자로(문자열 각 글자를 `Data.Char`의 `toUpper`로 변환) 바꿔주는 포인트-프리 함수를 작성해보라.
