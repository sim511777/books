# 8장. 재귀

지금까지 작성한 함수들은 대부분 한 번의 계산으로 결과가 나오는 짧은 함수였습니다. 하지만 "리스트의 모든 원소를 더하라"거나 "n부터 1까지 곱하라"처럼 **같은 작업을 반복**해야 하는 문제를 만나면 어떻게 해야 할까요? 다른 언어라면 `for`나 `while` 루프를 떠올리겠지만, Haskell에는 그런 반복 구문이 없습니다. 이번 장에서는 Haskell이 반복을 표현하는 기본 방법인 **재귀(recursion)**를 다룹니다.

## Haskell에는 왜 루프가 없는가

C나 Python 같은 언어의 `for`, `while` 루프는 변수의 값을 계속 덮어쓰면서(mutation) 반복을 진행합니다. 하지만 3장에서 이야기했듯 Haskell의 값은 **불변(immutable)**입니다. 한 번 묶인 이름은 계산이 끝날 때까지 값이 바뀌지 않습니다. 그러니 "카운터 변수를 1씩 증가시키며 반복"하는 방식 자체가 Haskell의 근본 모델과 맞지 않습니다.

대신 Haskell은 "더 작은 같은 문제를 풀고, 그 결과를 이용해 지금 문제를 푼다"는 방식으로 반복을 표현합니다. 이것이 재귀입니다. 함수가 자기 자신을 정의 안에서 호출하는 것이죠.

## 팩토리얼: 재귀의 가장 기본적인 예

팩토리얼은 재귀를 설명할 때 가장 자주 쓰이는 예제입니다. 수학적으로 팩토리얼은 다음과 같이 정의됩니다.

- `0! = 1`
- `n! = n * (n-1)!` (단, n > 0)

이 정의를 그대로 Haskell 코드로 옮기면 재귀 함수가 됩니다. 4장에서 배운 패턴 매칭을 이용하면 정의를 거의 그대로 코드로 옮길 수 있습니다.

```haskell
factorial :: Int -> Int
factorial 0 = 1                      -- 기저 조건
factorial n = n * factorial (n - 1)  -- 재귀 단계
```

```haskell
ghci> factorial 0
1
ghci> factorial 5
120
ghci> factorial 10
3628800
```

이 함수에는 재귀 함수를 이루는 두 가지 필수 요소가 모두 담겨 있습니다.

- **기저 조건(base case)**: 더 이상 재귀하지 않고 곧바로 답을 내는 경우. `factorial 0 = 1`이 여기 해당합니다. 기저 조건이 없으면 함수는 영원히 자기 자신을 호출하며 멈추지 않습니다.
- **재귀 단계(recursive case)**: 문제를 더 작은 버전으로 줄여서 자기 자신을 호출하고, 그 결과를 조합해 지금 문제의 답을 만드는 부분. `n * factorial (n - 1)`이 여기 해당합니다.

`factorial 5`가 어떻게 계산되는지 펼쳐서 보면 재귀의 흐름이 뚜렷하게 보입니다.

```
factorial 5
= 5 * factorial 4
= 5 * (4 * factorial 3)
= 5 * (4 * (3 * factorial 2))
= 5 * (4 * (3 * (2 * factorial 1)))
= 5 * (4 * (3 * (2 * (1 * factorial 0))))
= 5 * (4 * (3 * (2 * (1 * 1))))
= 120
```

매 호출마다 인자가 `n`에서 `n - 1`로 **줄어들며** 언젠가 기저 조건인 `0`에 도달합니다. 이 "줄어드는 방향"이 없으면 재귀는 끝나지 않습니다.

## 리스트 합계 직접 구현하기

Haskell은 리스트의 합을 구하는 `sum` 함수를 기본으로 제공하지만, 재귀를 이해하기 위해 직접 만들어 봅시다. 6장에서 다룬 리스트는 사실 "빈 리스트" 또는 "머리(head)와 나머지 꼬리(tail)로 이루어진 리스트"라는 재귀적 구조를 갖고 있습니다. 이 구조를 그대로 패턴 매칭으로 따라가면 됩니다.

```haskell
mySum :: [Int] -> Int
mySum [] = 0                 -- 기저 조건: 빈 리스트의 합은 0
mySum (x:xs) = x + mySum xs  -- 재귀 단계: 머리 + 나머지의 합
```

```haskell
ghci> mySum []
0
ghci> mySum [1, 2, 3, 4, 5]
15
```

리스트가 `[]`(빈 리스트)에 도달하는 순간이 기저 조건이고, `(x:xs)`로 머리와 꼬리를 분리해 꼬리에 대해 다시 `mySum`을 호출하는 부분이 재귀 단계입니다. 리스트를 다루는 재귀 함수는 거의 항상 이 "빈 리스트 vs. 머리:꼬리" 패턴을 따릅니다.

## 리스트 길이 직접 구현하기

같은 패턴으로 리스트의 길이를 구하는 `length`도 직접 만들 수 있습니다. 이번에는 원소의 값 자체는 필요 없고 "원소가 하나 있다"는 사실만 셀 뿐이므로, 머리 부분은 밑줄 패턴 `_`로 무시합니다.

```haskell
myLength :: [a] -> Int
myLength [] = 0                  -- 기저 조건: 빈 리스트의 길이는 0
myLength (_:xs) = 1 + myLength xs -- 재귀 단계: 1 + 나머지의 길이
```

```haskell
ghci> myLength []
0
ghci> myLength "haskell"
7
ghci> myLength [10, 20, 30]
3
```

`mySum`과 `myLength`는 모양이 거의 똑같습니다. 둘 다 "빈 리스트는 기저 조건으로 처리하고, `x:xs`는 머리를 이용한 계산에 꼬리에 대한 재귀 결과를 결합한다"는 틀을 그대로 따릅니다. 이 틀은 9장에서 배울 `foldr` 같은 고차 함수로 일반화됩니다. 즉 지금 손으로 짜는 재귀 패턴이 바로 그 고차 함수들이 내부적으로 하는 일입니다.

## 기저 조건과 재귀 단계를 명확히 구분하기

재귀 함수를 작성할 때는 항상 다음 두 질문에 먼저 답해야 합니다.

1. **더 이상 나눌 수 없는 가장 작은 경우는 무엇인가?** (기저 조건)
2. **일반적인 경우, 문제를 어떻게 더 작은 문제로 줄이고 그 결과를 어떻게 조합할 것인가?** (재귀 단계)

기저 조건을 빠뜨리면 어떤 일이 벌어지는지 확인해 봅시다.

```haskell
-- 기저 조건이 없는 잘못된 정의
badFactorial :: Int -> Int
badFactorial n = n * badFactorial (n - 1)
```

```haskell
ghci> badFactorial 3
*** Exception: stack overflow
```

`n`이 계속 줄어들어 음수를 지나 무한히 작아지므로 절대 멈추지 않고 결국 스택이 넘칩니다. 재귀 함수를 작성한 뒤에는 항상 "이 함수가 정말 기저 조건에 도달하는가?"를 스스로 점검하는 습관이 중요합니다.

## 꼬리 재귀와 누산기 패턴

앞서 작성한 `mySum`을 다시 살펴봅시다.

```haskell
mySum (x:xs) = x + mySum xs
```

이 함수는 `mySum xs`의 결과를 받아온 **다음에** `x`를 더하는 작업이 남아 있습니다. 즉 재귀 호출이 함수의 "마지막 동작"이 아닙니다. 이런 함수는 재귀가 깊어질수록 "나중에 더할 값들"을 계속 쌓아두어야 하므로, 리스트가 매우 길면 메모리 사용이 커질 수 있습니다.

이를 개선하는 방법이 **누산기(accumulator)**를 추가하는 것입니다. 지금까지의 중간 결과를 인자로 들고 다니면서, 재귀 호출이 함수의 정말로 마지막 동작이 되도록 만드는 방식입니다. 이런 형태를 **꼬리 재귀(tail recursion)**라고 부릅니다.

```haskell
sumAcc :: [Int] -> Int
sumAcc xs = go xs 0
  where
    go [] acc     = acc            -- 기저 조건: 누적된 값을 그대로 반환
    go (x:xs) acc = go xs (acc + x) -- 재귀 단계: 누산기를 갱신하고 즉시 재귀 호출
```

```haskell
ghci> sumAcc [1, 2, 3, 4, 5]
15
```

`go` 함수를 보면 재귀 호출 `go xs (acc + x)`가 그 줄의 **가장 마지막에 실행되는 동작**입니다. 더 이상 할 일이 남아있지 않고 바로 다음 재귀 호출로 넘어가므로, "나중에 처리할 계산"이 쌓이지 않습니다. `where`로 보조 함수 `go`를 두고 누산기를 두 번째 인자로 들고 다니는 방식은 Haskell에서 매우 흔한 패턴이며, 팩토리얼도 같은 방식으로 다시 쓸 수 있습니다.

```haskell
factorialAcc :: Int -> Int
factorialAcc n = go n 1
  where
    go 0 acc = acc
    go k acc = go (k - 1) (acc * k)
```

```haskell
ghci> factorialAcc 5
120
```

다만 Haskell은 기본적으로 **지연 평가(lazy evaluation)**를 사용하므로, 꼬리 재귀가 항상 즉시 실행되어 스택을 아낀다고 단순히 보장되지는 않습니다. 지연 평가가 누산기 패턴과 어떻게 상호작용하는지, 그리고 `foldl'`처럼 엄격한 평가를 강제하는 도구는 13장 지연 평가에서 더 자세히 다룹니다. 지금은 "누산기를 함수 인자로 들고 다니며 재귀 호출을 마지막 동작으로 만드는" 형태 자체를 익히는 것으로 충분합니다.

## 요약

- Haskell에는 `for`/`while` 루프가 없습니다. 값이 불변이기 때문에 반복은 재귀로 표현합니다.
- 재귀 함수는 **기저 조건**(더 이상 나눌 수 없는 가장 작은 경우)과 **재귀 단계**(문제를 줄여 자기 자신을 호출하고 결과를 조합하는 부분)로 구성됩니다.
- 리스트를 다루는 재귀는 "빈 리스트 `[]`" vs. "머리와 꼬리 `(x:xs)`"라는 패턴 매칭 구조를 거의 항상 따릅니다.
- `factorial`, `mySum`, `myLength`를 직접 구현해 보면서 재귀의 공통 구조를 확인했습니다.
- 기저 조건이 없거나 문제가 줄어들지 않으면 재귀는 멈추지 않고 스택 오버플로를 일으킵니다.
- 누산기를 추가해 재귀 호출을 함수의 마지막 동작으로 만드는 것이 꼬리 재귀 패턴이며, 이는 이후 9장의 `fold` 계열 함수와 13장의 지연 평가로 이어지는 중요한 개념입니다.
