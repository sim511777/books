## 왜 나만의 타입이 필요한가

3장에서 `Int`, `Bool`, `String` 같은 기본 타입을 배웠고, 6~7장에서는 리스트와 튜플로 여러 값을 묶는 방법을 살펴봤다. 하지만 프로그램이 복잡해지면 기존 타입만으로는 의미를 정확히 표현하기 어려워진다. 예를 들어 "원(circle)"과 "직사각형(rectangle)"을 모두 표현하려고 튜플을 쓴다면 다음과 같이 될 것이다.

```haskell
-- 튜플로 도형을 표현하려는 시도 (권장하지 않음)
circle1 :: (String, Double)
circle1 = ("circle", 5.0)

rectangle1 :: (String, Double, Double)
rectangle1 = ("rectangle", 3.0, 4.0)
```

이 방식은 두 도형의 필드 개수가 달라서 같은 타입으로 묶을 수도 없고, 문자열 `"circle"`을 잘못 입력해도 컴파일러가 잡아주지 못한다. Haskell은 이런 문제를 `data` 키워드로 해결한다. `data`로 정의하는 타입을 **대수적 데이터 타입(algebraic data type, ADT)**이라고 부르는데, 이번 장에서는 이 타입을 만들고 다루는 방법을 배운다.

## data로 새 타입 만들기

가장 단순한 형태는 하나의 생성자(constructor)만 가진 타입이다.

```haskell
data Point = Point Double Double
```

이 선언은 두 가지를 동시에 정의한다. 첫째, `Point`라는 새로운 **타입**을 만든다. 둘째, `Point`라는 이름의 **생성자(값을 만드는 함수)**를 만든다. 타입 이름과 생성자 이름이 같아서 처음에는 헷갈릴 수 있지만, 쓰이는 위치가 다르다. 타입 시그니처에는 타입 이름이, 값을 만들 때는 생성자가 쓰인다.

```haskell
origin :: Point
origin = Point 0.0 0.0

ghci> :type Point
Point :: Double -> Double -> Point
```

생성자 `Point`는 사실 `Double -> Double -> Point` 타입을 가진 평범한 함수처럼 동작한다. 9장에서 배운 부분 적용이나 `map`에 그대로 넘길 수도 있다.

```haskell
ghci> map (Point 0.0) [1.0, 2.0, 3.0]
```

값을 출력해보고 싶다면 `Show` 타입클래스를 자동으로 구현하게 해주는 `deriving` 절을 붙이면 된다. `deriving`은 11장에서 타입클래스를 본격적으로 다룰 때 더 자세히 설명하지만, 지금은 "이 타입에 대해 표준적인 동작(출력, 비교 등)을 자동으로 만들어 달라"는 지시로 이해하면 충분하다.

```haskell
data Point = Point Double Double deriving (Show, Eq)

ghci> Point 1.0 2.0
Point 1.0 2.0
ghci> Point 1.0 2.0 == Point 1.0 2.0
True
```

`deriving (Show, Eq)`가 없었다면 `ghci`가 `Point 1.0 2.0`을 화면에 어떻게 출력해야 할지 몰라 에러를 낸다. `Show`는 값을 문자열로 바꾸는 방법을, `Eq`는 `==`로 값을 비교하는 방법을 제공한다.

## 여러 생성자를 가진 타입

`data`의 진짜 힘은 하나의 타입이 **여러 가지 형태(생성자)** 중 하나일 수 있다는 데서 나온다. `|`로 생성자를 나열하면 된다. 이 장 서두에서 언급한 도형 예제를 제대로 만들어보자.

```haskell
data Shape = Circle Double
           | Rectangle Double Double
           deriving (Show, Eq)
```

이 선언은 "`Shape`는 `Circle`이거나 `Rectangle`이다"라고 읽으면 된다. `Circle`은 반지름 하나(`Double`)를 받고, `Rectangle`은 가로와 세로 두 값을 받는다. 같은 타입 `Shape`에 속하지만 내부 구조가 다른 값들을 만들 수 있다.

```haskell
myCircle :: Shape
myCircle = Circle 5.0

myRect :: Shape
myRect = Rectangle 3.0 4.0

shapes :: [Shape]
shapes = [Circle 1.0, Rectangle 2.0 5.0, Circle 3.5]
```

`shapes` 리스트의 타입이 `[Shape]` 하나로 통일된다는 점에 주목하자. 튜플로 표현할 때는 불가능했던 일이다.

## 패턴 매칭으로 생성자별로 처리하기

4장에서 배운 패턴 매칭은 커스텀 데이터 타입을 다룰 때 가장 강력하게 활용된다. 각 생성자에 대해 별도의 처리를 정의할 수 있다.

```haskell
area :: Shape -> Double
area (Circle r) = pi * r * r
area (Rectangle w h) = w * h
```

```haskell
ghci> area (Circle 5.0)
78.53981633974483
ghci> area (Rectangle 3.0 4.0)
12.0
```

`area` 함수는 `Shape` 값을 받아서 어떤 생성자로 만들어졌는지에 따라 다른 계산식을 적용한다. `Circle r`이라는 패턴은 값이 `Circle` 생성자로 만들어졌을 때만 매칭되고, 그 안에 들어있던 `Double` 값을 `r`이라는 이름으로 꺼내준다.

만약 새로운 도형을 추가하고 그에 대한 처리를 빠뜨리면 어떻게 될까?

```haskell
data Shape = Circle Double
           | Rectangle Double Double
           | Triangle Double Double Double
           deriving (Show, Eq)

-- area 함수를 고치지 않으면 Triangle에 대한 패턴이 없다
```

이 경우 GHC는 대개 "패턴이 모든 경우를 다루지 않는다(non-exhaustive patterns)"는 경고를 컴파일 시점에 보여준다. 그리고 실제로 `area (Triangle 3 4 5)`를 실행하면 런타임 에러가 발생한다. 이런 이유로 `Shape`처럼 생성자가 여러 개인 타입을 다룰 때는 각 함수에서 모든 생성자를 빠짐없이 처리하는 습관이 중요하다. 5장에서 배운 가드와 결합해서 조건을 더 세밀하게 나눌 수도 있다.

```haskell
describeShape :: Shape -> String
describeShape (Circle r)
  | r <= 0    = "잘못된 원"
  | r < 1     = "아주 작은 원"
  | otherwise = "원, 반지름 " ++ show r
describeShape (Rectangle w h)
  | w == h    = "정사각형"
  | otherwise = "직사각형"
describeShape (Triangle a b c) = "삼각형"

ghci> describeShape (Rectangle 4.0 4.0)
"정사각형"
```

값을 담지 않는 단순한 열거형(enumeration)도 같은 방식으로 만들 수 있다.

```haskell
data TrafficLight = Red | Yellow | Green deriving (Show, Eq)

nextLight :: TrafficLight -> TrafficLight
nextLight Red = Green
nextLight Green = Yellow
nextLight Yellow = Red

ghci> nextLight Red
Green
```

`Red`, `Yellow`, `Green`은 아무 값도 담지 않는 생성자다. 이런 생성자는 인자를 받지 않으므로 마치 `Bool`의 `True`/`False`처럼 동작한다.

## 필드에 이름 붙이기: 레코드 문법

생성자의 필드가 여러 개가 되면 순서만으로 어떤 값이 무엇인지 기억하기 어려워진다. Haskell은 필드에 이름을 붙일 수 있는 **레코드 문법(record syntax)**을 제공한다.

```haskell
data Person = Person
  { personName :: String
  , personAge  :: Int
  } deriving (Show, Eq)

alice :: Person
alice = Person { personName = "Alice", personAge = 30 }
```

레코드 문법을 쓰면 필드 이름과 같은 이름의 **접근자 함수(accessor function)**가 자동으로 생긴다.

```haskell
ghci> personName alice
"Alice"
ghci> personAge alice
30
```

값의 일부만 바꾼 새 값을 만들 때도 레코드 업데이트 문법이 편리하다. Haskell 값은 4장에서 이미 이야기했듯 기본적으로 불변(immutable)이므로, "바꾸기"는 실제로는 일부 필드만 다른 새로운 값을 만드는 것이다.

```haskell
birthday :: Person -> Person
birthday p = p { personAge = personAge p + 1 }

ghci> birthday alice
Person {personName = "Alice", personAge = 31}
```

## 타입 매개변수를 가진 데이터 타입

지금까지 만든 타입은 내부에 담는 값의 타입이 고정되어 있었다(`Double`, `String` 등). 하지만 리스트가 `[Int]`도 되고 `[String]`도 될 수 있었던 것처럼, 커스텀 타입도 **타입 매개변수(type parameter)**를 가질 수 있다. 아무 타입이나 하나 담을 수 있는 간단한 상자 타입을 만들어보자.

```haskell
data Box a = Box a deriving (Show, Eq)
```

여기서 `a`는 타입 변수다. `Box`는 그 자체로는 완전한 타입이 아니라, `a`에 구체적인 타입을 채워 넣어야 완전한 타입이 된다. `Box Int`, `Box String`, `Box Bool` 모두 유효한 타입이다.

```haskell
intBox :: Box Int
intBox = Box 42

stringBox :: Box String
stringBox = Box "hello"

ghci> intBox
Box 42
ghci> stringBox
Box "hello"
```

`Box`의 내부 값을 꺼내거나 변형하는 함수도 타입 매개변수를 그대로 유지한 채 정의할 수 있다.

```haskell
unBox :: Box a -> a
unBox (Box x) = x

mapBox :: (a -> b) -> Box a -> Box b
mapBox f (Box x) = Box (f x)

ghci> unBox intBox
42
ghci> mapBox (+1) intBox
Box 43
ghci> mapBox show intBox
Box "42"
```

`mapBox`의 타입 시그니처 `(a -> b) -> Box a -> Box b`를 보면, 입력 상자의 내부 타입 `a`와 출력 상자의 내부 타입 `b`가 다를 수 있다는 것을 알 수 있다. 눈치 빠른 독자라면 이 `mapBox`가 9장의 `map`과 구조적으로 닮았다는 것을 느낄 것이다. 실제로 이런 패턴을 일반화한 개념이 14장에서 배울 **펑터(Functor)**다. `Box`는 사실 펑터의 아주 간단한 예시라고 볼 수 있다.

타입 매개변수는 여러 개 가질 수도 있다. 두 값을 담는 상자를 만들어보자.

```haskell
data Pair a b = Pair a b deriving (Show, Eq)

coord :: Pair Int Int
coord = Pair 3 5

nameAge :: Pair String Int
nameAge = Pair "Bob" 25

swapPair :: Pair a b -> Pair b a
swapPair (Pair x y) = Pair y x

ghci> swapPair nameAge
Pair 25 "Bob"
```

타입 매개변수를 가진 데이터 타입은 여러 생성자와 결합할 수도 있다. 예를 들어 "값이 있을 수도, 없을 수도 있다"는 상황을 표현하는 타입을 직접 만들어보자. (사실 이는 Haskell 표준 라이브러리의 `Maybe` 타입과 거의 동일한데, `Maybe`와 `Either`는 12장에서 에러 처리 목적으로 자세히 다룬다.)

```haskell
data Optional a = None | Some a deriving (Show, Eq)

safeDivide :: Int -> Int -> Optional Int
safeDivide _ 0 = None
safeDivide x y = Some (x `div` y)

ghci> safeDivide 10 2
Some 5
ghci> safeDivide 10 0
None
```

`Optional`도 패턴 매칭으로 다룬다는 점에서 앞서 본 `Shape`나 `TrafficLight`와 다르지 않다.

```haskell
describeResult :: Optional Int -> String
describeResult None = "결과 없음"
describeResult (Some n) = "결과: " ++ show n

ghci> describeResult (safeDivide 10 0)
"결과 없음"
```

## type으로 타입 별칭 만들기

지금까지는 `data`로 새로운 타입을 만들었다. 반면 `type` 키워드는 **새 타입을 만드는 것이 아니라, 이미 있는 타입에 다른 이름(별칭)을 붙이는 것**이다. 예를 들어 이름을 나타내는 `String`에 의미 있는 이름을 붙여보자.

```haskell
type Name = String
type Age = Int

describePerson :: Name -> Age -> String
describePerson name age = name ++ "은 " ++ show age ++ "살이다"

ghci> describePerson "철수" 20
"철수은 20살이다"
```

`Name`은 `String`과 완전히 같은 타입이다. 컴파일러 입장에서는 아무 차이가 없고, `Name` 타입의 값이 필요한 곳에 그냥 `String` 값을 넘겨도 전혀 문제가 없다. `type`은 오직 사람이 코드를 읽을 때 의미를 더 잘 전달하기 위한 것이다.

`type`은 복잡한 타입 표현을 짧게 줄이는 데도 유용하다. 좌표를 튜플로 표현한다고 하면 다음처럼 쓸 수 있다.

```haskell
type Coord = (Double, Double)

distance :: Coord -> Coord -> Double
distance (x1, y1) (x2, y2) = sqrt ((x2 - x1) ^ 2 + (y2 - y1) ^ 2)

ghci> distance (0.0, 0.0) (3.0, 4.0)
5.0
```

`type`도 매개변수를 가질 수 있다.

```haskell
type Dictionary v = [(String, v)]

phoneBook :: Dictionary Int
phoneBook = [("Alice", 12345), ("Bob", 67890)]
```

여기서 주의할 점은 `data`로 만든 타입과 `type` 별칭의 근본적인 차이다. `data Box a = Box a`로 만든 `Box Int`는 `Int`와는 별개의, 새로운 타입이라서 `Box 5`와 `5`를 같은 자리에 섞어 쓸 수 없다. 반면 `type Name = String`으로 만든 `Name`은 `String`과 완전히 같은 타입이라 아무 제약 없이 섞어 쓸 수 있다. 타입 안전성이 중요하다면 `data`(혹은 이후에 배울 `newtype`)를, 단순히 가독성을 높이고 싶다면 `type`을 선택하면 된다.

## 요약

이번 장에서는 `data` 키워드로 나만의 대수적 데이터 타입을 만드는 방법을 배웠다. 하나의 생성자만 가진 단순한 타입부터, `Shape`처럼 `|`로 여러 생성자를 나열한 타입까지 만들어보았고, 4장에서 배운 패턴 매칭을 이용해 각 생성자에 맞는 처리를 정의하는 방법을 확인했다. 레코드 문법으로 필드에 이름을 붙이고 접근자 함수를 자동으로 얻는 방법도 살펴봤다. 이어서 `Box a`, `Pair a b`, `Optional a`처럼 타입 매개변수를 가진 데이터 타입을 만들어, 하나의 정의로 여러 타입에 대해 동작하는 유연한 타입을 설계하는 방법을 배웠다. 마지막으로 `type` 키워드로 기존 타입에 의미 있는 별칭을 붙이는 방법과, 이것이 `data`로 만든 완전히 새로운 타입과 어떻게 다른지 구분했다. 이번 장에서 만든 `Optional` 타입은 다음 장인 11장에서 타입클래스를 배우고, 12장에서 표준 `Maybe`/`Either` 타입으로 자연스럽게 확장된다.

## 연습문제

1. 세 종류의 생성자 `Circle Double`, `Rectangle Double Double`, `Square Double`을 가진 `Shape` 타입을 정의하고, 각 도형의 둘레를 계산하는 `perimeter :: Shape -> Double` 함수를 패턴 매칭으로 작성하라.
2. 레코드 문법을 사용해서 `title`, `author`, `year` 필드를 가진 `Book` 타입을 정의하고, 특정 연도 이후에 출판된 책인지 확인하는 `isPublishedAfter :: Int -> Book -> Bool` 함수를 작성하라.
3. 타입 매개변수를 가진 `data Tree a = Leaf | Node a (Tree a) (Tree a)` 타입을 정의하고, 트리에 들어있는 모든 값의 개수를 세는 `countNodes :: Tree a -> Int` 함수를 재귀로 작성하라. (8장의 재귀를 복습해보자.)
4. `type Grid = [[Int]]`라는 별칭을 정의하고, 이를 사용해 격자의 모든 숫자의 합을 구하는 `sumGrid :: Grid -> Int` 함수를 작성하라.
5. `data Result a = Failure String | Success a`라는 타입을 정의하고, 이 타입을 반환하는 안전한 나눗셈 함수 `safeDivide :: Int -> Int -> Result Int`를 작성하라. 0으로 나누는 경우 `Failure "0으로 나눌 수 없다"`를 반환하도록 하라. 이 타입이 12장에서 배울 `Either`와 어떻게 비슷한지 생각해보라.
