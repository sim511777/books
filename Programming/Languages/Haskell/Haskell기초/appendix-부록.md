## 자주 쓰는 Prelude 함수 치트시트

### 리스트 만들고 훑어보기 (6장)

| 함수 | 타입(간략) | 설명 | 예시 |
|---|---|---|---|
| `length` | `[a] -> Int` | 원소 개수 | `length [1,2,3]` → `3` |
| `null` | `[a] -> Bool` | 비어 있는지 확인 | `null []` → `True` |
| `reverse` | `[a] -> [a]` | 순서 뒤집기 | `reverse [1,2,3]` → `[3,2,1]` |
| `++` | `[a] -> [a] -> [a]` | 리스트 이어붙이기 | `[1,2] ++ [3,4]` → `[1,2,3,4]` |
| `head` / `tail` | `[a] -> a` / `[a] -> [a]` | 첫 원소 / 첫 원소를 뗀 나머지 (부분 함수, 18장 참고) | `head [1,2,3]` → `1` |
| `!!` | `[a] -> Int -> a` | 인덱스로 접근 (부분 함수) | `[10,20,30] !! 1` → `20` |
| `take` / `drop` | `Int -> [a] -> [a]` | 앞에서 n개 취하기 / 버리기 | `take 2 [1,2,3,4]` → `[1,2]` |
| `elem` | `a -> [a] -> Bool` | 원소 포함 여부 | `3 \`elem\` [1,2,3]` → `True` |
| `concat` | `[[a]] -> [a]` | 리스트의 리스트를 평평하게 | `concat [[1,2],[3]]` → `[1,2,3]` |
| `sum` / `product` | `[a] -> a` | 합 / 곱 | `sum [1,2,3]` → `6` |
| `minimum` / `maximum` | `[a] -> a` | 최솟값 / 최댓값 (부분 함수) | `maximum [3,1,4]` → `4` |
| `[a..b]` | — | 범위 리스트 생성 | `[1..5]` → `[1,2,3,4,5]` |

### 함수를 값처럼 다루기 (9장)

| 함수 | 타입(간략) | 설명 | 예시 |
|---|---|---|---|
| `map` | `(a -> b) -> [a] -> [b]` | 각 원소에 함수 적용 | `map (*2) [1,2,3]` → `[2,4,6]` |
| `filter` | `(a -> Bool) -> [a] -> [a]` | 조건을 만족하는 원소만 | `filter even [1..6]` → `[2,4,6]` |
| `foldr` | `(a -> b -> b) -> b -> [a] -> b` | 오른쪽부터 접어 나가기 | `foldr (+) 0 [1,2,3]` → `6` |
| `foldl` | `(b -> a -> b) -> b -> [a] -> b` | 왼쪽부터 접어 나가기 | `foldl (-) 10 [1,2,3]` → `4` |
| `zip` | `[a] -> [b] -> [(a,b)]` | 두 리스트를 튜플로 짝짓기 | `zip [1,2] "ab"` → `[(1,'a'),(2,'b')]` |
| `zipWith` | `(a->b->c) -> [a] -> [b] -> [c]` | 짝지으며 함수 적용 | `zipWith (+) [1,2] [10,20]` → `[11,22]` |
| `.` | `(b->c) -> (a->b) -> a -> c` | 함수 합성 | `(negate . abs) (-5)` → `-5` |
| `$` | `(a->b) -> a -> b` | 괄호 대신 쓰는 낮은 우선순위 적용 | `print $ 1 + 2` |
| `curry` / `uncurry` | — | 튜플 인자 ↔ 다중 인자 전환 | `uncurry (+) (3,4)` → `7` |

### 튜플 (7장)

| 함수 | 타입(간략) | 설명 | 예시 |
|---|---|---|---|
| `fst` / `snd` | `(a,b) -> a` / `(a,b) -> b` | 2-튜플의 원소 꺼내기 | `fst (3,4)` → `3` |
| `zip3` | `[a]->[b]->[c]->[(a,b,c)]` | 세 리스트를 3-튜플로 | `zip3 [1] "a" [True]` |

### `Maybe`와 `Either` (12장)

| 함수 | 타입(간략) | 설명 | 예시 |
|---|---|---|---|
| `maybe` | `b -> (a->b) -> Maybe a -> b` | `Nothing`/`Just`를 값 하나로 축약 | `maybe 0 (+1) (Just 5)` → `6` |
| `fromMaybe` | `a -> Maybe a -> a` (`Data.Maybe`) | 기본값과 함께 꺼내기 | `fromMaybe 0 Nothing` → `0` |
| `catMaybes` | `[Maybe a] -> [a]` (`Data.Maybe`) | `Just`만 모아 꺼내기 | `catMaybes [Just 1, Nothing, Just 2]` → `[1,2]` |
| `either` | `(a->c)->(b->c)->Either a b->c` | `Left`/`Right`를 값 하나로 축약 | `either show id (Right "ok")` |

### 지연 평가와 무한 구조 (13장)

| 함수 | 타입(간략) | 설명 | 예시 |
|---|---|---|---|
| `take` | `Int -> [a] -> [a]` | 무한 리스트에서 앞부분만 꺼내기 | `take 5 [1..]` |
| `repeat` | `a -> [a]` | 같은 값을 무한히 반복 | `take 3 (repeat 7)` → `[7,7,7]` |
| `cycle` | `[a] -> [a]` | 리스트를 무한히 반복 | `take 5 (cycle [1,2])` → `[1,2,1,2,1]` |
| `iterate` | `(a->a) -> a -> [a]` | 함수를 반복 적용한 무한 리스트 | `take 4 (iterate (*2) 1)` → `[1,2,4,8]` |

### IO (15장)

| 함수 | 타입(간략) | 설명 |
|---|---|---|
| `putStr` / `putStrLn` | `String -> IO ()` | 줄바꿈 없이 / 있이 출력 |
| `print` | `Show a => a -> IO ()` | `show`한 뒤 출력 |
| `getLine` | `IO String` | 한 줄 입력 받기 |
| `readLn` | `Read a => IO a` | 입력을 받아 타입에 맞게 해석 |
| `return` / `pure` | `a -> IO a` | 순수 값을 IO 안에 감싸기 |

이 표에 없는 함수가 필요하다면, GHCi에서 `:type 함수이름`으로 시그니처를 먼저 확인하고, `:info 함수이름`으로 어떤 모듈·타입 클래스에 속하는지 살펴보는 것이 18장에서 강조한 탐색적 개발의 기본이다.

## 자주 쓰는 타입 클래스 요약표

11장, 14장, 15장, 16장에서 다룬 타입 클래스들을 한자리에 정리한다.

| 타입 클래스 | 핵심 메서드 | 의미 | 대표 인스턴스 |
|---|---|---|---|
| `Eq` | `(==)`, `(/=)` | 두 값이 같은지 비교할 수 있다 | `Int`, `Bool`, `Char`, 대부분의 커스텀 타입 |
| `Ord` | `compare`, `(<)`, `(<=)` 등 | 값 사이에 순서를 매길 수 있다 (`Eq`를 전제로 함) | `Int`, `Double`, `Char` |
| `Show` | `show` | 값을 사람이 읽을 문자열로 바꿀 수 있다 | 거의 모든 표준 타입 |
| `Read` | `read` | 문자열을 값으로 되돌릴 수 있다 (`Show`의 반대 방향) | `Int`, `Double` 등 |
| `Num` | `(+)`, `(-)`, `(*)` | 숫자처럼 사칙연산이 가능하다 | `Int`, `Integer`, `Double` |
| `Functor` | `fmap` (`<$>`) | 상자 속 값에 함수를 적용할 수 있다 | `Maybe`, `[]`, `Either e`, `IO` |
| `Applicative` | `pure`, `(<*>)` | 상자 속 함수를 상자 속 값에 적용할 수 있다 | `Maybe`, `[]`, `Either e`, `IO` |
| `Monad` | `return`, `(>>=)` | 상자 속 값을 "상자를 반환하는 함수"에 연쇄적으로 넘길 수 있다 | `Maybe`, `[]`, `Either e`, `IO` |

각 타입 클래스가 실제로 어떤 일을 하는지, 아래 예시로 다시 감을 잡아 보자.

```haskell
-- Eq, Ord, Show는 보통 deriving으로 자동 생성한다 (10장, 11장)
data Fruit = Apple | Banana | Cherry
  deriving (Eq, Ord, Show)

ghci> Apple == Banana
False
ghci> compare Apple Banana
LT
ghci> show Apple
"Apple"
```

```haskell
-- Functor: 상자 속 값 변형
ghci> fmap (+1) (Just 4)
Just 5
ghci> (+1) <$> [1, 2, 3]
[2,3,4]

-- Applicative: 상자 속 함수를 상자 속 값에 적용
ghci> Just (+3) <*> Just 4
Just 7

-- Monad: 실패할 수 있는 연쇄 계산
safeDiv :: Int -> Int -> Maybe Int
safeDiv _ 0 = Nothing
safeDiv a b = Just (a `div` b)

ghci> Just 20 >>= safeDiv 100 >>= safeDiv 1000
Nothing -- Just 20을 100으로 나눈 5, 그 뒤 1000을 5로 나눈 200... 처럼 연쇄되다 0을 만나면 즉시 Nothing
```

`Functor` → `Applicative` → `Monad`는 단계적으로 더 많은 능력을 갖춘 관계다. `Monad`인 타입은 항상 `Applicative`이기도 하고, `Applicative`인 타입은 항상 `Functor`이기도 하다. 14장과 15장에서 이 관계를 자세히 다뤘으니, 헷갈릴 때는 "상자 속 값 하나를 변형하는 것뿐이면 `Functor`, 상자 속 함수와 상자 속 값을 합치는 것이면 `Applicative`, 이전 결과에 따라 다음 계산(다음 상자)을 결정해야 하면 `Monad`"라고 구분해 보면 도움이 된다.

16장에서 배운 사용자 정의 타입 클래스도 같은 틀 안에 있다. 스스로 타입 클래스를 만들 때도, 이 표의 표준 타입 클래스들이 "메서드가 몇 개 안 되지만 다형성을 강력하게 표현한다"는 점을 참고하면 설계에 도움이 된다.

## 연산자 우선순위와 결합 방향

Haskell의 연산자는 실제로는 모두 함수이며, `infixl`/`infixr`/`infix` 선언으로 우선순위(숫자가 클수록 먼저 계산됨)와 결합 방향이 정해져 있다. GHCi에서 `:info (연산자)`를 입력하면 언제든 확인할 수 있지만, 자주 쓰는 것들을 표로 모아 둔다.

| 우선순위 | 연산자 | 결합 방향 | 설명 |
|---|---|---|---|
| 9 | `.` | 오른쪽 (`infixr`) | 함수 합성 |
| 9 | `!!` | 왼쪽 (`infixl`) | 리스트 인덱싱 |
| 8 | `^`, `^^`, `**` | 오른쪽 (`infixr`) | 거듭제곱 |
| 7 | `*`, `/`, `` `div` ``, `` `mod` `` | 왼쪽 (`infixl`) | 곱셈·나눗셈 계열 |
| 6 | `+`, `-` | 왼쪽 (`infixl`) | 덧셈·뺄셈 |
| 5 | `:` | 오른쪽 (`infixr`) | 리스트 맨 앞에 원소 추가 |
| 5 | `++` | 오른쪽 (`infixr`) | 리스트 이어붙이기 |
| 4 | `==`, `/=`, `<`, `<=`, `>`, `>=` | 없음 (`infix`) | 비교 연산자 |
| 4 | `<$>`, `<*>` | 왼쪽 (`infixl`) | 펑터·애플리커티브 적용 |
| 3 | `&&` | 오른쪽 (`infixr`) | 논리 AND |
| 2 | `\|\|` | 오른쪽 (`infixr`) | 논리 OR |
| 1 | `>>`, `>>=` | 왼쪽 (`infixl`) | 모나드 연쇄 |
| 0 | `$` | 오른쪽 (`infixr`) | 가장 낮은 우선순위의 함수 적용 |

몇 가지 실질적인 함의를 짚어 보자.

- `2 + 3 * 4`는 `*`(우선순위 7)가 `+`(우선순위 6)보다 먼저 계산되어 `2 + (3 * 4)` = `14`가 된다. 수학에서 익숙한 순서와 같다.
- `1 : 2 : 3 : []`는 `:`가 오른쪽 결합이므로 `1 : (2 : (3 : []))`로 묶여 `[1,2,3]`이 된다. 8장에서 리스트를 재귀적으로 분해할 때 `(x:xs)` 패턴이 자연스러운 이유도 `:`의 이런 결합 방향과 맞닿아 있다.
- `==`, `<` 같은 비교 연산자는 결합 방향이 **없다(`infix`)**. `1 < 2 < 3`처럼 연쇄해서 쓸 수 없다는 뜻이며, 실제로 이 코드는 컴파일 오류가 난다. 각 비교는 `Bool`을 내놓는데, `Bool`끼리는 다시 `<`로 비교할 수 없기 때문이다.
- `$`는 우선순위가 가장 낮은 오른쪽 결합 연산자다. `print $ 1 + 2 * 3`은 `print (1 + 2 * 3)`과 같다. "이 오른쪽 전체를 통째로 계산한 뒤 왼쪽 함수에 넘긴다"는 뜻으로, 괄호를 줄이기 위해 9장에서부터 자주 등장했다.
- `.`(함수 합성)은 오른쪽 결합이라서 `f . g . h`는 `f . (g . h)`로 묶이지만, 결합 방향과 무관하게 실제 적용 순서는 항상 "오른쪽에서 왼쪽"이다. 즉 `(f . g . h) x`는 `f (g (h x))`와 같다.

우선순위를 외우는 것보다 중요한 습관은, 헷갈릴 때 괄호를 명시적으로 쳐서 의도를 분명히 드러내는 것이다. Haskell 코드가 짧다고 해서 항상 괄호를 최소화해야 하는 것은 아니다.

## 더 공부하려면: 참고 자료를 찾는 법

이 책은 Haskell의 핵심 개념을 순서대로 소개하는 입문서이지만, 실제 개발에서는 언어와 라이브러리의 최신 세부 사항을 계속 찾아봐야 한다. 특정 책이나 강의를 나열하는 대신, **어떤 종류의 자료를 어떤 상황에 찾아야 하는지**를 안내한다.

- **언어 자체의 공식 명세**: Haskell 언어 표준(Haskell Report)은 문법과 의미의 최종 근거다. 일상적인 코딩에는 잘 쓰지 않지만, "이 문법이 정확히 왜 이렇게 동작하는가"처럼 근본적인 질문이 생겼을 때 찾아볼 가치가 있다.
- **컴파일러 사용자 가이드**: 사용 중인 GHC 버전의 사용자 가이드에는 컴파일러 옵션(`-Wall` 같은 경고 옵션 포함), 언어 확장(language extension) 목록이 정리되어 있다. 이 책에서 다루지 않은 고급 언어 확장이 필요해지면 가장 먼저 찾아볼 곳이다.
- **패키지 저장소와 각 라이브러리의 API 문서**: `Data.List`, `Data.Map` 같은 표준 라이브러리 모듈뿐 아니라, 커뮤니티가 배포하는 수많은 패키지의 함수 시그니처와 사용 예시를 찾을 수 있다. 어떤 함수의 정확한 타입이나 동작이 궁금할 때, GHCi의 `:type`, `:info`와 함께 가장 먼저 확인할 자료다. 함수 이름으로 타입 시그니처를 검색해 원하는 기능을 하는 함수를 찾아 주는 검색 도구도 널리 쓰인다.
- **패키지에 딸린 README와 예제 코드**: 널리 쓰이는 라이브러리는 대개 저장소에 사용법을 보여주는 예제를 함께 제공한다. API 문서만으로 감이 잘 안 잡힐 때 실제 사용 맥락을 파악하는 데 유용하다.
- **커뮤니티 질의응답과 토론 공간**: 특정 오류 메시지의 의미, 관용적인 코드 스타일, 라이브러리 선택에 대한 의견처럼 공식 문서에 없는 실전 지식은 활발한 커뮤니티 공간에서 얻을 수 있는 경우가 많다. 다만 답변의 Haskell 버전이나 라이브러리 버전이 오래되지 않았는지 확인하는 습관이 필요하다.
- **컴파일러가 보여주는 오류와 경고 메시지 자체**: GHC의 오류 메시지는 처음엔 낯설어 보여도, 실제로는 문제의 원인과 관련 타입을 상당히 구체적으로 알려 준다. 오류 메시지를 끝까지 차분히 읽는 습관이, 어떤 외부 자료보다 빠른 첫 번째 참고 자료가 되는 경우가 많다.

이 책에서 다진 기본기 위에서, 위와 같은 자료들을 스스로 찾아 읽고 판단하는 능력이야말로 장기적으로 가장 중요한 실력이다. 18장에서 이야기한 것처럼, 작은 프로젝트를 직접 완성해 보면서 필요할 때마다 이런 자료를 찾아보는 경험을 반복하는 것이 최선의 학습 경로다.
