# 11장. 타입클래스 기초

3장에서 `square x = x * x`의 타입을 물어봤을 때 `Num a => a -> a`라는 결과를 본 적이 있다. 그때는 "숫자 타입이라면 다 된다는 뜻"이라고만 넘어갔지만, 이제는 그 `Num a =>` 부분이 정확히 무엇인지 짚어볼 차례다. 이 장에서 다루는 **타입클래스(type class)**가 바로 그 답이다. 10장에서 `data` 키워드로 직접 데이터 타입을 만들어봤다면, 이번 장에서는 그렇게 만든 타입에 "동등 비교가 가능하다", "순서를 매길 수 있다", "문자열로 보여줄 수 있다" 같은 능력을 부여하는 방법을 배운다.

## 타입클래스란 무엇인가

타입클래스는 "이 타입이 어떤 동작을 지원하는지"를 나타내는 규칙 모음이다. 조금 더 구체적으로 말하면, 특정 함수들(연산)을 제공해야 그 타입클래스에 속할 수 있다는 약속이다. 예를 들어 `Eq`라는 타입클래스는 "이 타입의 값 두 개를 `==`로 비교할 수 있다"는 약속이고, `Show`는 "이 타입의 값을 문자열로 바꿀 수 있다"는 약속이다.

10장에서 만들었을 법한 다음과 같은 도형 타입을 예로 들어보자.

```haskell
data Shape = Circle Double | Rectangle Double Double
```

`Shape` 값 두 개를 `==`로 비교하려고 하면 어떤 일이 벌어질까.

```haskell
ghci> Circle 3.0 == Circle 3.0

<interactive>: No instance for (Eq Shape) arising from a use of ‘==’
```

GHC는 "`Shape`에는 `Eq` 인스턴스가 없다"고 딱 잘라 말한다. `==` 자체가 존재하지 않는 게 아니라, `Shape`라는 타입이 `Eq`라는 약속을 아직 지키고 있지 않다는 뜻이다. 이 오류 메시지가 바로 타입클래스의 정체를 가장 잘 보여준다. Haskell에서 `==`, `show`, `compare` 같은 함수는 특정 타입에 고정된 함수가 아니라, **그 타입이 해당 타입클래스에 속해 있어야만 쓸 수 있는 함수**다.

## Eq: 동등 비교

`Eq` 타입클래스는 `==`와 `/=`(같지 않다) 두 연산을 제공한다.

```haskell
ghci> 3 == 3
True
ghci> 3 == 4
False
ghci> "hello" == "hello"
True
ghci> 'a' /= 'b'
True
```

`Int`, `Char`, `String`처럼 흔히 쓰는 타입은 모두 이미 `Eq`에 속해 있어서 곧바로 `==`를 쓸 수 있다. 문제는 우리가 직접 만든 `Shape` 같은 타입이다. 이런 타입에 `Eq`를 붙이는 방법은 이 장 뒤쪽에서 바로 다룬다.

## Ord: 순서 비교

`Ord` 타입클래스는 값 사이에 크고 작음을 매길 수 있다는 약속이다. `<`, `>`, `<=`, `>=`뿐 아니라 `compare`, `max`, `min` 함수도 함께 제공한다.

```haskell
ghci> 3 < 5
True
ghci> compare 3 5
LT
ghci> compare 5 5
EQ
ghci> compare 7 5
GT
ghci> max 3 7
7
```

`compare`는 `True`/`False`를 돌려주는 대신 `LT`(작다), `EQ`(같다), `GT`(크다)라는 세 값 중 하나를 돌려준다. 이 `LT`, `EQ`, `GT`는 `Ordering`이라는 이름의, 역시 `data`로 정의된 평범한 타입일 뿐이다.

```haskell
data Ordering = LT | EQ | GT
```

10장에서 본 것과 똑같은 모양의 대수적 데이터 타입이다. 타입클래스와 커스텀 데이터 타입은 서로 무관한 개념이 아니라, 타입클래스가 제공하는 함수의 결과 역시 결국 평범한 데이터 타입이라는 점을 기억해두면 좋다. 그리고 `Ord`에 속하려면 먼저 `Eq`에도 속해 있어야 한다. 순서를 매길 수 있다면 당연히 같은지 다른지도 구별할 수 있어야 하기 때문이다. 이런 관계를 "`Ord`는 `Eq`를 상위 클래스(superclass)로 가진다"고 표현한다.

## Show: 문자열로 표현

`Show` 타입클래스는 값을 문자열로 바꿔주는 `show` 함수를 제공한다.

```haskell
ghci> show 42
"42"
ghci> show True
"True"
ghci> show [1, 2, 3]
"[1,2,3]"
```

GHCi가 계산 결과를 화면에 찍어줄 때도 사실은 내부적으로 `show`를 호출하고 있다. `print`라는 함수는 정확히 "`show`로 문자열을 만들고 그것을 화면에 출력한다"는 두 단계를 합쳐놓은 것이다.

```haskell
ghci> print 42
42
ghci> putStrLn (show 42)
42
```

`Shape`처럼 `Show`가 없는 타입을 GHCi에서 그냥 평가해보면 어떤 일이 생기는지 확인해보자.

```haskell
ghci> Circle 3.0

<interactive>: No instance for (Show Shape) arising from a use of ‘print’
```

역시 같은 패턴의 오류다. `Shape`를 화면에 찍으려면 GHCi가 `show`를 호출해야 하는데, `Shape`가 `Show`라는 약속을 지키지 않고 있으니 GHC가 컴파일 단계에서(또는 GHCi에서는 평가 시점에) 이를 막는 것이다.

## deriving으로 자동 구현 받기

`Shape` 같은 타입에 `Eq`, `Ord`, `Show`를 매번 손으로 구현해줘야 한다면 번거로울 것이다. 다행히 Haskell은 이런 흔한 타입클래스에 대해서는 컴파일러가 구현을 자동으로 만들어주는 기능을 제공한다. `data` 선언 뒤에 `deriving`을 붙이면 된다.

```haskell
data Shape = Circle Double | Rectangle Double Double
  deriving (Eq, Show)
```

이제 `Shape`는 `==`와 `show`를 모두 쓸 수 있다.

```haskell
ghci> Circle 3.0 == Circle 3.0
True
ghci> Circle 3.0 == Rectangle 2.0 4.0
False
ghci> Circle 3.0
Circle 3.0
ghci> Rectangle 2.0 4.0
Rectangle 2.0 4.0
```

`deriving`이 만들어주는 `Eq` 구현은 상식적으로 이해할 수 있는 규칙을 따른다. 같은 생성자(constructor)이고 그 안의 필드 값들도 모두 같아야 `True`다. `Show` 구현은 생성자 이름과 필드 값을 그대로 이어붙인 문자열을 만든다.

열거형처럼 단순한 타입이라면 `Ord`도 함께 파생시킬 수 있다.

```haskell
data Priority = Low | Medium | High
  deriving (Eq, Ord, Show)
```

```haskell
ghci> Low < High
True
ghci> compare Medium Medium
EQ
ghci> maximum [Low, High, Medium]
High
```

여기서 순서는 **생성자를 선언한 순서**를 그대로 따른다. `Low`, `Medium`, `High` 순서로 적었기 때문에 `Low`가 가장 작고 `High`가 가장 크다고 취급된다. 필드가 있는 타입에 `Ord`를 파생시키면 먼저 생성자 순서로 비교하고, 같은 생성자라면 필드를 왼쪽부터 순서대로 비교한다.

```haskell
data Point = Point Double Double
  deriving (Eq, Ord, Show)
```

```haskell
ghci> Point 1.0 2.0 < Point 1.0 3.0
True
ghci> Point 1.0 2.0 == Point 1.0 2.0
True
```

`deriving`은 사람이 직접 정의했다면 자연스러웠을 규칙을 그대로 자동화해준 것이지, 마법을 부리는 것이 아니다. 다만 이 규칙이 항상 의미상으로 옳지는 않을 수 있다는 점은 기억해두자. 예를 들어 좌표를 나타내는 `Point`에서 "x가 작은 게 더 작다"는 순서가 실제로 의미 있는 비교인지는 상황에 따라 다르다. 자동 파생이 원하는 의미와 다르다면, 16장에서 배울 것처럼 `Ord` 인스턴스를 직접 작성할 수도 있다.

## 타입클래스와 다른 언어의 인터페이스

Java나 TypeScript의 인터페이스를 알고 있다면 타입클래스가 낯설지 않을 것이다. 둘 다 "이 타입이 어떤 메서드(함수)를 지원해야 한다"는 규약을 정의하고, 여러 타입이 같은 규약을 각자의 방식으로 구현할 수 있게 해준다는 점에서 비슷하다.

```java
// Java의 인터페이스 예시 (Haskell 코드가 아니다)
interface Comparable<T> {
    int compareTo(T other);
}
```

하지만 결정적인 차이가 하나 있다. Java에서는 클래스를 정의할 때 `implements Comparable`이라고 미리 못박아둬야 한다. 즉 인터페이스를 구현하려면 그 클래스의 소스 코드를 직접 고칠 권한이 있어야 한다. 반면 Haskell의 타입클래스 인스턴스는 타입을 정의한 나중에도, 심지어 다른 사람이 만든 라이브러리의 타입에 대해서도 별도로 선언할 수 있다. 이를 **애드혹 다형성(ad-hoc polymorphism)**이라 부르는데, "이 타입에 대해서는 이렇게 동작한다"는 규칙을 타입과 무관하게 나중에 덧붙일 수 있다는 뜻이다. `deriving`은 그중에서도 가장 흔한 경우(구조를 그대로 비교하거나 출력하는 것)를 컴파일러가 대신 만들어주는 지름길일 뿐이다.

또 하나 기억할 점은, 타입클래스 자체는 상태나 데이터를 갖지 않는다는 것이다. 타입클래스는 순수하게 "이 타입에는 이런 함수가 존재한다"는 약속이고, 실제 구현(인스턴스)은 각 타입마다 따로 붙는다. 이 개념은 16장 "사용자 정의 타입클래스와 다형성"에서 직접 타입클래스를 선언하고 인스턴스를 작성해보며 더 깊이 파헤친다. 지금은 `Eq`, `Ord`, `Show`처럼 Prelude가 미리 준비해둔 타입클래스를 자유롭게 쓰고, 필요하면 `deriving`으로 손쉽게 구현을 얻는 것으로 충분하다.

## 요약

- 타입클래스는 "이 타입이 어떤 동작(함수)을 지원하는지"를 정의하는 규약이다. 어떤 타입이 특정 타입클래스에 속하려면 그 타입클래스가 요구하는 함수들을 구현(또는 파생)해야 한다.
- `Eq`는 `==`, `/=`를 제공해 동등 비교를 가능하게 하고, `Ord`는 `compare`, `<`, `>`, `max`, `min` 등을 제공해 순서 비교를 가능하게 한다. `Ord`는 `Eq`를 상위 클래스로 요구한다.
- `Show`는 `show` 함수로 값을 문자열로 바꿔주며, GHCi가 결과를 출력하거나 `print`가 동작할 때 내부적으로 사용된다.
- `data` 선언 뒤에 `deriving (Eq, Show, Ord)`를 붙이면 컴파일러가 상식적인 규칙(생성자와 필드를 그대로 비교하거나, 선언 순서대로 정렬하는 등)에 따라 구현을 자동으로 만들어준다.
- 타입클래스는 다른 언어의 인터페이스와 비슷하지만, 타입을 정의한 뒤에도 다른 곳에서 인스턴스를 추가할 수 있다는 점(애드혹 다형성)에서 근본적으로 다르다. 직접 타입클래스를 만들고 인스턴스를 작성하는 방법은 16장에서 다룬다.

## 연습문제

1. 다음 타입에 `deriving`을 이용해 `Eq`와 `Show`를 추가하고, GHCi에서 `Won 1000 == Won 1000`과 `print (Won 500)`을 각각 실행해 결과를 확인해 보라.

   ```haskell
   data Currency = Won Int | Dollar Double
   ```

2. `Ord`를 파생시킨 다음 열거형 타입에서 생성자를 선언한 순서를 바꾸면 `compare` 결과가 어떻게 달라지는지, 직접 순서를 바꿔보고 GHCi로 확인해 보라.

   ```haskell
   data Size = Small | Medium | Large
     deriving (Eq, Ord, Show)
   ```

3. `Eq` 인스턴스가 없는 타입에 `==`를 사용하면 어떤 오류 메시지가 나오는지 직접 GHCi에서 확인하고, 그 오류가 왜 "함수가 없다"는 오류와 다른지 설명해 보라.

4. 필드 두 개를 가진 `data Score = Score Int Int deriving (Eq, Ord, Show)` 타입에서, `Ord`가 파생될 때 두 필드 중 어느 쪽이 먼저 비교되는지 예제 값 몇 개로 실험해 알아내 보라.

5. Java나 Python 같은 언어의 인터페이스(또는 프로토콜) 개념과 Haskell 타입클래스의 공통점과 차이점을 각각 한 가지씩 자신의 말로 정리해 보라.
