# 14장. 펑터와 애플리커티브

12장에서는 `Maybe`와 `Either`로 실패할 수 있는 계산을 표현하는 방법을 배웠습니다. 그런데 `Maybe Int` 안에 들어있는 값에 함수를 적용하려면 매번 `case`로 값을 꺼내야 했습니다. 이번 장에서는 "컨테이너 안의 값을 직접 꺼내지 않고도 변형한다"는 관점에서 펑터(Functor)와 애플리커티브(Applicative)라는 두 타입클래스를 소개합니다.

## 컨테이너 안의 값을 변형하기

`Maybe Int` 값에 함수를 적용하는 상황을 다시 떠올려 봅시다. 12장에서는 이렇게 `case`로 직접 분기했습니다.

```haskell
addTen :: Maybe Int -> Maybe Int
addTen (Just n) = Just (n + 10)
addTen Nothing  = Nothing
```

이 패턴은 값이 있으면 함수를 적용하고, 없으면 그대로 `Nothing`을 돌려주는 아주 흔한 모양입니다. `Maybe`뿐 아니라 리스트, `Either` 같은 다른 타입에서도 똑같은 패턴이 반복됩니다. Haskell은 이 반복되는 패턴을 **펑터(Functor)**라는 타입클래스로 추상화했습니다.

```haskell
class Functor f where
  fmap :: (a -> b) -> f a -> f b
```

`f`는 `Maybe`나 `[]`처럼 "안에 값을 담는" 타입 생성자입니다. `fmap`은 "`a`를 `b`로 바꾸는 함수"와 "`a`를 담은 컨테이너 `f a`"를 받아서, "`b`를 담은 컨테이너 `f b`"를 돌려줍니다. 즉 컨테이너를 열어보지 않고도, 그 안에 들어있는 값에 함수를 적용해 달라고 요청하는 것입니다.

## `Maybe`와 리스트에 `fmap` 적용하기

`Maybe`의 `Functor` 인스턴스는 값이 있으면(`Just`) 함수를 적용하고, 없으면(`Nothing`) 아무 일도 하지 않습니다.

```haskell
ghci> fmap (+10) (Just 5)
Just 15
ghci> fmap (+10) Nothing
Nothing
```

`addTen` 함수를 `case` 없이 한 줄로 다시 쓸 수 있습니다.

```haskell
addTen :: Maybe Int -> Maybe Int
addTen = fmap (+10)
```

`Nothing`이 들어오면 `fmap`이 아무것도 하지 않고 그대로 `Nothing`을 돌려주므로, "실패 상태를 전파한다"는 12장의 규칙이 자연스럽게 유지됩니다.

리스트도 `Functor`의 인스턴스입니다. 사실 리스트에 대한 `fmap`은 6장에서 배운 `map`과 정확히 같은 동작을 합니다.

```haskell
ghci> fmap (*2) [1, 2, 3]
[2,4,6]
ghci> map (*2) [1, 2, 3]
[2,4,6]
```

`Either e a`도 `Functor`의 인스턴스입니다. `Left`는 보통 오류를, `Right`는 성공한 결과를 담는다고 배웠는데(12장 참고), `fmap`은 `Right`에 담긴 값에만 함수를 적용하고 `Left`는 그대로 둡니다.

```haskell
ghci> fmap (*2) (Right 21 :: Either String Int)
Right 42
ghci> fmap (*2) (Left "오류 발생" :: Either String Int)
Left "오류 발생"
```

`fmap`에는 `<$>`라는 중위 연산자 별칭이 있어서, 함수를 마치 일반적인 값에 적용하는 것처럼 자연스럽게 쓸 수 있습니다.

```haskell
ghci> (*2) <$> Just 21
Just 42
ghci> (++ "!") <$> ["Haskell", "펑터"]
["Haskell!","펑터!"]
```

## 펑터로는 부족한 상황

펑터는 "컨테이너 밖에 있는 함수 하나"를 "컨테이너 안의 값"에 적용합니다. 그런데 함수 자체가 컨테이너 안에 들어있는 경우는 어떻게 해야 할까요? 예를 들어 두 개의 `Maybe Int`를 더하고 싶다고 합시다.

```haskell
ghci> :type fmap (+) (Just 3)
fmap (+) (Just 3) :: Num a => Maybe (a -> a)
```

`fmap (+) (Just 3)`의 결과는 `Just (3 +)`, 즉 **함수가 `Maybe` 안에 들어있는 값**입니다. 이제 이 `Maybe (a -> a)`를 다른 `Maybe a` 값에 적용해서 `Maybe a`를 얻고 싶은데, `fmap`의 타입 `(a -> b) -> f a -> f b`로는 이 상황을 표현할 수 없습니다. `fmap`의 첫 번째 인자는 "평범한 함수"여야 하는데, 지금은 그 함수마저 `Maybe`에 감싸여 있기 때문입니다.

## 애플리커티브: 컨테이너 안의 함수를 적용하기

이 상황을 위해 Haskell은 **애플리커티브(Applicative)**라는 타입클래스를 제공합니다.

```haskell
class Functor f => Applicative f where
  pure  :: a -> f a
  (<*>) :: f (a -> b) -> f a -> f b
```

`pure`는 평범한 값을 컨테이너에 담아주고, `<*>`("apply"라고 읽습니다)는 컨테이너 안에 들어있는 함수를 컨테이너 안에 들어있는 값에 적용합니다. 방금 막혔던 두 `Maybe Int`를 더하는 문제를 이제 풀 수 있습니다.

```haskell
ghci> Just (+3) <*> Just 5
Just 8
ghci> Just (+3) <*> Nothing
Nothing
ghci> Nothing <*> Just 5
Nothing
```

두 개의 `Maybe Int`를 더하려면 `fmap`으로 먼저 함수를 컨테이너 안에 넣고, `<*>`로 두 번째 값에 적용하는 조합을 씁니다.

```haskell
ghci> (+) <$> Just 3 <*> Just 5
Just 8
ghci> (+) <$> Just 3 <*> Nothing
Nothing
ghci> (+) <$> Nothing <*> Just 5
Nothing
```

`(+) <$> Just 3`은 `Just (3 +)`를 만들고, 여기에 `<*> Just 5`를 이어 붙이면 `Just (3 + 5)`, 즉 `Just 8`이 됩니다. 두 값 중 하나라도 `Nothing`이면 결과 전체가 `Nothing`이 되어, 실패를 전파하는 규칙이 그대로 유지됩니다. 회원가입 폼에서 이름과 나이를 각각 검증해 `Maybe String`, `Maybe Int`로 얻은 뒤 둘 다 성공했을 때만 최종 데이터를 조합하는 경우처럼, 여러 개의 `Maybe` 값을 동시에 다뤄야 할 때 이 패턴이 특히 유용합니다.

리스트에서 `<*>`는 조금 다르게 동작합니다. 함수들의 리스트를 값들의 리스트에 적용하되, **가능한 모든 조합**을 만들어냅니다.

```haskell
ghci> [(+1), (*2)] <*> [10, 20]
[11,21,20,40]
```

`(+1)`을 `10`과 `20`에 각각 적용한 `[11, 21]`, 그리고 `(*2)`를 `10`과 `20`에 각각 적용한 `[20, 40]`을 이어붙인 결과입니다. 이렇게 리스트의 애플리커티브는 "모든 함수와 모든 값의 조합"을 표현하는 데 유용합니다.

`pure`는 값을 있는 그대로 컨테이너에 담아줍니다. 어떤 컨테이너에 담기는지는 타입 추론에 맡겨집니다.

```haskell
ghci> pure 5 :: Maybe Int
Just 5
ghci> pure 5 :: [Int]
[5]
```

## 펑터와 애플리커티브를 함께 정리하기

| 상황 | 필요한 도구 | 타입 |
|---|---|---|
| 컨테이너 밖 함수를 컨테이너 안 값에 적용 | `fmap` (`<$>`) | `(a -> b) -> f a -> f b` |
| 컨테이너 안 함수를 컨테이너 안 값에 적용 | `<*>` | `f (a -> b) -> f a -> f b` |
| 평범한 값을 컨테이너에 담기 | `pure` | `a -> f a` |

`fmap`은 함수 하나를 컨테이너 하나에 적용할 때, `<*>`는 여러 개의 컨테이너에 담긴 값들을 동시에 조합해야 할 때 씁니다. 두 도구는 서로 배타적이지 않고, `(+) <$> Just 3 <*> Just 5`처럼 자연스럽게 함께 쓰입니다.

## 15장 예고: 모나드로 이어지는 이야기

애플리커티브로도 아직 표현하기 어려운 상황이 하나 남아 있습니다. 지금까지는 각 컨테이너의 값이 서로 독립적이었지만, 만약 **첫 번째 계산의 결과에 따라 두 번째로 어떤 계산을 할지 결정**해야 한다면 어떨까요? 예를 들어 나이를 검증한 결과가 `Just 25`일 때만, 그 나이를 기준으로 다음 검증을 수행하고 싶은 경우입니다. 이런 "이전 결과에 의존하는 연쇄적인 계산"을 다루기 위한 도구가 **모나드(Monad)**입니다. 15장에서는 모나드가 펑터, 애플리커티브와 어떤 관계를 가지는지, 그리고 `IO` 타입이 왜 모나드로 설계되었는지 자세히 다룹니다.

## 요약

펑터(Functor)는 `fmap`(또는 `<$>`)을 통해 컨테이너 안의 값을 꺼내지 않고도 함수를 적용할 수 있게 해주는 타입클래스로, `Maybe`의 `Just`/`Nothing`, 리스트, `Either`의 `Right`/`Left` 모두에서 "성공한 값만 변형하고 실패 상태는 그대로 전파한다"는 일관된 동작을 보여줍니다. 하지만 함수 자체가 컨테이너 안에 들어있는 경우에는 `fmap`으로 해결할 수 없는데, 이때 필요한 것이 애플리커티브(Applicative)입니다. `pure`로 값을 컨테이너에 담고 `<*>`로 컨테이너 안의 함수를 컨테이너 안의 값에 적용하면, 여러 개의 `Maybe`나 리스트 값을 독립적으로 조합할 수 있습니다. 다만 이전 계산의 결과에 따라 다음 계산이 달라지는 상황은 애플리커티브로도 부족하며, 이 문제는 15장의 모나드에서 해결됩니다.

## 연습문제

1. `fmap (subtract 1) (Just 10)`과 `fmap (subtract 1) Nothing`의 결과를 예측해 보고, GHCi에서 확인해 보세요.
2. `Either String Int` 타입의 값 `Right 100`과 `Left "실패"`에 각각 `fmap (*3)`을 적용했을 때 결과가 왜 다른지 설명해 보세요.
3. `(*) <$> Just 6 <*> Just 7`의 최종 결과와 계산 과정을 단계별로 적어 보세요. 두 값 중 하나가 `Nothing`이라면 결과가 어떻게 바뀌는지도 함께 설명해 보세요.
4. `[(*10), (+100)] <*> [1, 2]`의 결과를 손으로 먼저 계산해보고, GHCi에서 실제 결과와 비교해 보세요.
5. `fmap`만으로는 "이름"과 "나이" 두 개의 `Maybe` 값을 조합해서 사람 정보를 만들 수 없는 이유를 설명하고, `<*>`를 사용해서 실제로 조합하는 코드를 작성해 보세요. (힌트: `data Person = Person String Int deriving Show`를 정의하고 `Person <$> Just "지수" <*> Just 27`을 시도해 보세요.)
