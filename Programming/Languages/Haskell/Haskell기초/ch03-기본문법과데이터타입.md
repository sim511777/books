# 3장. 기본 문법과 데이터 타입

---

2장에서 GHCi를 실행해 `1 + 1`을 계산해 봤다면, 이제 그 뒤에 숨어 있는 규칙을 제대로 들여다볼 차례다. Haskell은 겉보기엔 계산기처럼 단순해 보이지만, 모든 값에는 반드시 타입이 있고, 한 번 이름에 묶인 값은 절대 바뀌지 않는다는 두 가지 원칙이 언어 전체를 지배한다. 이 장에서는 그 원칙을 실제 코드로 확인한다.

## 타입 시그니처: `::`의 의미

Haskell에서 `::`는 "~라는 타입을 가진다"라고 읽는다. 수학에서 집합을 표기하는 것과 비슷하게, 어떤 값이나 표현식이 어떤 종류의 데이터인지 선언하는 기호다.

```haskell
age :: Int
age = 32
```

이 코드는 "`age`는 `Int` 타입이고, 그 값은 32다"라고 선언한다. GHCi에서 직접 타입을 물어볼 수도 있다.

```haskell
ghci> :type 32
32 :: Num a => a
ghci> :type age
age :: Int
```

`:type`(줄여서 `:t`)은 앞으로 이 책 전체에서 가장 자주 쓸 명령어다. 어떤 값이나 함수의 타입이 헷갈릴 때마다 GHCi에 물어보는 습관을 들이면, 타입 오류를 눈으로 직접 확인하며 배울 수 있다.

함수에도 타입 시그니처를 붙인다. 화살표 `->`는 "입력을 받아 출력을 낸다"는 뜻이다.

```haskell
double :: Int -> Int
double n = n * 2
```

`double`은 `Int` 하나를 받아 `Int` 하나를 돌려준다는 뜻이다. 타입 시그니처는 필수는 아니지만(컴파일러가 추론해 주므로), 함수의 의도를 코드만 보고 파악할 수 있게 해 주는 최고의 문서다. 이 책의 모든 함수 정의에는 시그니처를 붙일 것이다.

## 기본 타입 훑어보기

Haskell의 기본 타입 몇 가지를 GHCi에서 직접 확인해 보자.

```haskell
ghci> :type 42
42 :: Num a => a
ghci> :type (42 :: Int)
(42 :: Int) :: Int
ghci> :type 3.14
3.14 :: Fractional a => a
ghci> :type 'a'
'a' :: Char
ghci> :type "hello"
"hello" :: [Char]
ghci> :type True
True :: Bool
```

각 타입의 특징은 다음과 같다.

- **Int**: 고정된 크기의 정수. 대부분의 시스템에서 최소 -2^63 ~ 2^63-1 범위를 다루며, 이 범위를 넘으면 오버플로가 발생한다.
- **Integer**: 크기 제한이 없는 임의 정밀도 정수. 팩토리얼처럼 값이 아주 커질 수 있는 계산에 안전하다.
- **Double**: 배정밀도 부동소수점 실수. `3.14`, `2.0` 같은 소수를 표현한다.
- **Char**: 단일 문자. 항상 작은따옴표(`'a'`, `'가'`)로 감싼다.
- **Bool**: `True`와 `False` 두 값만 가지는 타입.
- **String**: 사실은 별도 타입이 아니라 `[Char]`, 즉 문자(Char)의 리스트다. 큰따옴표(`"hello"`)로 감싼다.

`Int`와 `Integer`의 차이는 실제로 확인해 볼 만하다.

```haskell
ghci> (maxBound :: Int)
9223372036854775807
ghci> (maxBound :: Int) + 1
-9223372036854775808
ghci> factorial :: Integer -> Integer; factorial n = product [1..n]
ghci> factorial 25
15511210043330985984000000
```

`Int`는 한계를 넘으면 조용히 음수로 넘어가 버리지만(오버플로), `Integer`는 메모리가 허락하는 한 얼마든지 커질 수 있다. 정확한 큰 수 계산이 필요하면 `Integer`를, 성능이 중요하고 범위가 보장되면 `Int`를 쓴다.

`String`이 `[Char]`의 별칭이라는 사실은 6장 리스트 기초에서 다시 만나게 된다. 문자열에 리스트 함수(`length`, `++`, `reverse` 등)를 그대로 쓸 수 있는 이유가 바로 이것이다.

```haskell
ghci> length "hello"
5
ghci> "hi" ++ "there"
"hithere"
```

## `let`과 `where`로 이름 묶기

계산 중간에 값에 이름을 붙여 두면 코드가 훨씬 읽기 쉬워진다. Haskell에는 두 가지 방법이 있다.

### GHCi와 표현식 안에서: `let`

GHCi에서는 `let`으로 임시 이름을 만들 수 있다.

```haskell
ghci> let radius = 5.0
ghci> let pi' = 3.14159
ghci> pi' * radius * radius
78.53975
```

`let`은 코드 블록 안에서도 쓴다. `in`과 함께 짝을 이뤄, "이 이름들을 이 표현식 안에서만 쓰겠다"고 선언하는 형태다.

```haskell
circleArea :: Double -> Double
circleArea radius =
  let pi' = 3.14159
      doubled = radius * radius
  in pi' * doubled
```

`let ... in ...` 블록 안에서는 여러 이름을 한 번에 정의할 수 있고, 각 줄의 들여쓰기만 맞춰 주면 된다.

### 함수 본문 뒤에 붙이는: `where`

`where`는 `let`과 비슷한 일을 하지만 위치가 다르다. 함수 정의 전체의 "뒤"에 붙어서, 그 함수 전용의 보조 이름을 정의한다.

```haskell
circleArea :: Double -> Double
circleArea radius = pi' * radius * radius
  where
    pi' = 3.14159
```

`let`과 `where`의 실질적인 차이는 이렇다. `let`은 표현식이라서 값이 필요한 어디에나 끼워 넣을 수 있고, 표현식이 먼저 나오고 정의가 뒤따른다. `where`는 함수(또는 가드, 5장 참고) 전체에 속하는 선언이라서, 여러 개의 등식이 같은 `where` 절을 공유할 수도 있다. 지금은 "식 안에서 잠깐 쓸 이름은 `let`, 함수 전체에서 반복되는 이름은 `where`"라고 기억해 두면 충분하다.

## 타입 추론: 컴파일러가 스스로 알아내는 타입

Haskell 컴파일러(GHC)는 타입 시그니처를 적지 않아도 대부분의 경우 문맥만으로 타입을 알아낼 수 있다. 이를 **타입 추론**이라 한다.

```haskell
ghci> :type (\x -> x * 2)
(\x -> x * 2) :: Num a => a -> a
```

시그니처 없이 정의한 함수도 GHCi에서 타입을 물어보면 추론 결과를 확인할 수 있다.

```haskell
square x = x * x
```

```haskell
ghci> :type square
square :: Num a => a -> a
```

여기서 `Num a => a -> a`라는 표현이 등장한다. `Num a =>` 부분은 "`a`가 무엇이든 상관없지만, 반드시 숫자(Num 타입 클래스에 속하는 타입)여야 한다"는 제약이다. 즉 `square`는 `Int`에도, `Double`에도, `Integer`에도 똑같이 쓸 수 있는 다형적인 함수라는 뜻이다. 타입 클래스라는 개념은 11장에서 본격적으로 다루니, 지금은 "`Num a =>` 같은 게 붙으면 특정 조건을 만족하는 타입이라면 다 된다는 뜻"이라고만 이해하면 된다.

타입 추론이 있다고 해서 시그니처를 안 써도 된다는 뜻은 아니다. 오히려 실무에서는 최상위 함수에는 항상 시그니처를 명시하는 것이 관례다. 시그니처는 문서 역할을 할 뿐 아니라, 정의에 실수가 있을 때 더 정확한 위치에서 오류를 잡아내는 데도 도움이 된다.

## 불변성: 값을 바꾸는 게 아니라 이름을 묶는다

지금까지 나온 코드에서 `=`을 눈여겨보자. 다른 언어의 `=`는 흔히 "대입(assignment)"이라 부르며 변수의 내용을 바꾸는 동작을 뜻한다. 하지만 Haskell의 `=`는 전혀 다르다. **한 번 이름에 값을 묶으면, 그 이름은 프로그램이 끝날 때까지 같은 값을 가리킨다.** 이것이 Haskell의 **불변성(immutability)**이다.

```haskell
ghci> let x = 10
ghci> x
10
ghci> let x = 20
```

두 번째 `let x = 20`은 기존의 `x`를 "변경"한 게 아니다. GHCi라는 대화형 환경이 새로운 스코프를 열어 `x`라는 이름을 다시 정의(shadowing, 가림)한 것뿐이다. 함수 안에서는 같은 이름을 두 번 바인딩하는 것 자체가 불가능하다.

```haskell
weird :: Int -> Int
weird n =
  let n = n + 1  -- 오류: 이렇게 자기 자신을 참조해 값을 "바꾸는" 건 안 된다
  in n
```

이런 코드는 무한 루프이거나 컴파일 오류가 난다. Haskell에서는 "변수"라는 말보다 "이름(name)" 또는 "바인딩(binding)"이라는 말이 더 정확하다. 한 번 값이 묶이면 끝이기 때문이다.

불변성은 처음엔 불편해 보일 수 있다. 반복문에서 카운터를 1씩 증가시키는 익숙한 패턴을 쓸 수 없기 때문이다. 하지만 이 제약은 큰 이점을 준다. 함수에 어떤 값을 넘겨도 그 값이 함수 내부에서 몰래 바뀔 걱정이 없고, 코드의 어느 지점에서 봐도 같은 이름은 항상 같은 값을 가리킨다는 확신을 가질 수 있다. 이 확신이 뒤에 나올 재귀(8장)와 고차 함수(9장)를 이해하는 데 중요한 토대가 된다. Haskell에서 "반복"은 변수를 바꾸는 게 아니라 재귀 호출로 표현한다는 것을, 8장에서 자세히 보게 될 것이다.

## 요약

- `::`는 값이나 함수의 타입을 선언하는 문법이며, GHCi의 `:type`(또는 `:t`) 명령으로 언제든 확인할 수 있다.
- 기본 타입에는 고정 크기 정수 `Int`, 임의 정밀도 정수 `Integer`, 실수 `Double`, 문자 `Char`, 논리값 `Bool`이 있고, `String`은 사실 `[Char]`의 별칭이다.
- `let ... in ...`은 표현식 안에서 임시 이름을 묶고, `where`는 함수 정의 전체에 딸린 보조 이름을 정의한다.
- 타입 시그니처를 생략해도 GHC는 문맥으로부터 타입을 추론하지만, 관례상 최상위 함수에는 시그니처를 명시한다.
- Haskell의 `=`는 대입이 아니라 이름과 값을 한 번만 묶는 바인딩이다. 즉 값은 절대 "바뀌지" 않으며, 이 불변성이 이후 장들에서 다룰 재귀와 함수형 스타일의 기반이 된다.

## 연습문제

1. GHCi에서 `:type`을 이용해 `'H'`, `"Haskell"`, `3 + 4.5`, `not True`의 타입을 각각 확인하고, 왜 그런 타입이 나왔는지 설명해 보라.
2. `Int`와 `Integer`의 차이를 설명하고, `factorial :: Integer -> Integer` 함수로 `factorial 30`을 계산해 결과를 확인해 보라. 만약 시그니처를 `Int -> Int`로 바꾸면 어떤 문제가 생길 수 있는지 생각해 보라.
3. 반지름과 높이를 입력받아 원기둥의 부피를 계산하는 `cylinderVolume :: Double -> Double -> Double` 함수를 `where` 절을 이용해 작성하라. (부피 = 밑면적 × 높이)
4. 같은 `cylinderVolume` 함수를 이번에는 `let ... in ...`을 이용해 다시 작성하고, 두 방식의 차이를 한두 문장으로 정리해 보라.
5. 다음 코드가 왜 컴파일되지 않는지, 혹은 왜 기대와 다르게 동작하는지 설명해 보라: `let y = 5 in let y = y + 1 in y`.
