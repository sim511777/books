## 들어가며

1장에서 Haskell이 어떤 언어인지 큰 그림을 살펴보았다면, 이번 장에서는 실제로 손을 움직여 코드를 실행해봅니다. Haskell을 실행하는 방법에는 두 가지 큰 축이 있습니다. 코드를 바로바로 실험해볼 수 있는 **GHCi**와, `.hs` 파일을 실행 가능한 프로그램으로 만들어주는 **GHC**입니다. 이 둘의 관계를 이해하는 것이 이 장의 핵심입니다.

## GHC와 GHCi의 관계

**GHC(Glasgow Haskell Compiler)**는 Haskell 소스 코드(`.hs` 파일)를 읽어서 실행 가능한 바이너리로 컴파일해주는 컴파일러입니다. C나 Java의 컴파일러와 비슷한 역할을 합니다.

**GHCi(GHC interactive)**는 GHC와 같은 컴파일 엔진을 사용하지만, 코드를 파일로 저장하지 않고 한 줄씩 입력해서 즉시 결과를 확인할 수 있는 대화형 환경입니다. Python의 대화형 셸(`python`을 입력했을 때 나오는 `>>>` 프롬프트)이나 Node.js의 REPL과 비슷한 역할을 한다고 생각하면 됩니다.

두 도구는 완전히 분리된 별개의 프로그램이 아니라, 같은 컴파일러 코어를 공유하는 하나의 도구 모음입니다. 실무에서는 다음과 같은 흐름으로 두 도구를 함께 사용합니다.

1. GHCi에서 함수나 아이디어를 빠르게 실험한다.
2. 잘 동작하는 코드를 `.hs` 파일로 옮겨 정리한다.
3. GHCi로 그 파일을 불러와 다시 테스트한다.
4. 최종적으로 GHC로 컴파일해서 배포 가능한 프로그램을 만든다.

이 순환 흐름은 이 장의 끝에서 그림으로 다시 살펴보겠습니다.

## GHCi 실행하기

터미널(PowerShell)을 열고 `ghci`를 입력합니다.

```
> ghci
GHCi, version 9.4.7: https://www.haskell.org/ghc/  :? for help
ghci>
```

`ghci>` 프롬프트가 나타나면 이제부터 Haskell 표현식을 입력하고 바로 결과를 볼 수 있습니다. 몇 가지 간단한 표현식을 평가해봅시다.

```haskell
ghci> 3 + 4
7
ghci> 10 `div` 3
3
ghci> "Hello, " ++ "Haskell!"
"Hello, Haskell!"
ghci> length [1, 2, 3, 4, 5]
5
```

각 줄을 입력하고 엔터를 누르면 GHCi가 즉시 그 표현식을 평가해서 결과를 출력합니다. 이 즉각적인 피드백 루프가 Haskell을 배우는 데 매우 중요한 도구입니다. 새로운 함수를 마주쳤을 때 문서를 읽기 전에 GHCi에서 직접 실험해보는 습관을 들이는 것을 추천합니다.

GHCi에는 표현식 평가 외에도 유용한 명령어들이 있습니다. 콜론(`:`)으로 시작하는 명령어들입니다.

```haskell
ghci> :type length
length :: Foldable t => t a -> Int
ghci> let x = 42
ghci> :type x
x :: Integer
ghci> :quit
Leaving GHCi.
```

`:type`(줄여서 `:t`)은 표현식의 타입을 보여주고, `:quit`(줄여서 `:q`)은 GHCi를 종료합니다. `let`으로는 GHCi 세션 안에서 임시로 변수나 함수를 정의할 수 있습니다.

## Hello World 작성하기

이제 파일로 코드를 작성해봅시다. 아무 텍스트 에디터로 `Hello.hs`라는 파일을 만들고 다음 내용을 입력합니다.

```haskell
-- Hello.hs
-- Haskell 프로그램의 시작점은 항상 main이라는 이름의 값이다.
main :: IO ()
main = putStrLn "Hello, Haskell!"
```

이 짧은 프로그램을 하나씩 살펴봅시다.

- `main :: IO ()`는 `main`의 타입을 명시한 것입니다. `IO ()`는 "부작용을 일으키는 동작이며, 그 결과로 특별히 의미 있는 값을 돌려주지는 않는다"는 뜻입니다. `IO`와 부작용의 자세한 원리는 15장에서 다룹니다.
- `putStrLn`은 문자열을 출력하고 줄바꿈을 추가하는 함수입니다.
- Haskell 프로그램을 실행하면 항상 `main`이라는 이름의 동작이 실행됩니다. C의 `main` 함수, Java의 `public static void main`과 같은 역할입니다.

## 파일을 GHC로 컴파일하기

`Hello.hs` 파일이 있는 폴더에서 다음 명령을 실행합니다.

```
> ghc Hello.hs
[1 of 1] Compiling Main             ( Hello.hs, Hello.o )
Linking Hello.exe ...
```

컴파일이 끝나면 실행 파일(Windows에서는 `Hello.exe`)이 생성됩니다. 이를 실행해봅니다.

```
> .\Hello.exe
Hello, Haskell!
```

`ghc`는 컴파일 과정에서 `.o`(오브젝트 파일), `.hi`(인터페이스 파일) 같은 중간 파일도 함께 만듭니다. 이런 파일들은 실행 파일을 만들기 위한 중간 산물이므로 지워도 무방합니다.

## 파일을 GHCi에 로드하기

매번 컴파일을 거치지 않고도, GHCi에 파일을 불러와서 그 안에 정의된 함수를 바로 테스트할 수 있습니다. `Hello.hs`가 있는 폴더에서 GHCi를 실행한 뒤 `:load`(줄여서 `:l`) 명령을 사용합니다.

```haskell
ghci> :load Hello.hs
[1 of 1] Compiling Main             ( Hello.hs, interpreted )
Ok, one module loaded.
ghci> main
Hello, Haskell!
```

파일을 로드한 뒤에는 그 파일 안에 정의된 모든 함수를 GHCi에서 자유롭게 호출할 수 있습니다. 파일을 수정한 뒤에는 `:reload`(줄여서 `:r`)로 다시 불러올 수 있습니다.

```haskell
ghci> :reload
[1 of 1] Compiling Main             ( Hello.hs, interpreted )
Ok, one module loaded.
```

이 방식은 파일을 조금씩 고치면서 즉시 결과를 확인하고 싶을 때 매우 유용합니다. 앞으로 이 책의 모든 예제는 이렇게 GHCi에서 직접 실행해보면서 따라오는 것을 권장합니다.

## 코드 작성부터 결과 확인까지의 순환 흐름

지금까지 살펴본 작업 흐름을 정리하면 다음과 같습니다. 에디터에서 `.hs` 파일에 코드를 작성하고, GHCi에 그 파일을 로드한 뒤, 함수나 표현식을 평가해서 결과를 확인합니다. 결과가 원하는 대로 나오지 않으면 다시 코드를 수정하고, `:reload`로 반영한 뒤 다시 평가합니다. 이 순환을 아래 그림으로 표현했습니다.

```text
GHCi 개발 순환 흐름

  +----------------------+           +----------------------+
  |    1. 코드 작성       |           |    2. GHCi에 로드      |
  | 에디터에서 .hs 파일    |  ------>  | :load Hello.hs        |
  | 편집 (예: Hello.hs)   |           | (수정 후에는 :reload)  |
  +----------------------+           +----------------------+
        ^                                       |
        |                                       v
  +----------------------+           +----------------------+
  |   4. 결과 확인        |           |      3. 평가          |
  | 출력 값과 :type 확인  |  <------  | ghci> main             |
  | 기대한 결과인지 검토   |           | 함수와 표현식 호출     |
  +----------------------+           +----------------------+
   (결과가 다르면 코드를 다시 수정)

  코드 작성 -> 로드(:load/:reload) -> 평가 -> 결과 확인 -> 다시 코드 작성으로
  이어지는 반복 흐름
```

이 순환은 Haskell뿐 아니라 대부분의 대화형 개발 환경(REPL)을 가진 언어에서 공통적으로 나타나는 패턴입니다. 다만 Haskell에서는 타입 시스템이 강력하기 때문에, "결과 확인" 단계에서 실행 결과뿐 아니라 `:type` 명령으로 타입을 확인하는 것도 매우 중요한 습관입니다.

## 요약

이번 장에서는 Haskell 개발 환경의 두 축인 GHC와 GHCi를 실제로 사용해보았습니다. GHCi는 표현식을 즉시 평가해주는 대화형 환경으로, 새로운 개념을 빠르게 실험하는 데 최적입니다. GHC는 `.hs` 파일을 실행 파일로 컴파일해주는 컴파일러입니다. `main :: IO ()`로 시작하는 Hello World 프로그램을 작성하고, 이를 `ghc`로 컴파일해 직접 실행하거나 `:load`와 `:reload`로 GHCi에서 불러와 테스트하는 방법을 배웠습니다. 코드 작성, 로드, 평가, 결과 확인으로 이어지는 순환 흐름은 앞으로 이 책 전체에서 반복적으로 사용할 기본 작업 방식입니다. 다음 장부터는 이 환경을 바탕으로 Haskell의 기본 문법과 데이터 타입을 본격적으로 다룹니다.

## 연습문제

1. GHCi를 실행하고 `:type`을 사용해 `True`, `'a'`, `[1,2,3]`, `"hello"`의 타입을 각각 확인해 보세요.
2. `main :: IO ()`에서 `IO`가 왜 필요한지, 만약 `main`이 순수 함수라면 어떤 문제가 생길지 생각해 보세요.
3. `Greet.hs`라는 파일을 만들어 이름을 인자로 받지 않고 고정된 문자열로 인사말을 출력하는 `main`을 작성하고, `ghc`로 컴파일해서 실행해 보세요.
4. 앞서 작성한 `Greet.hs`를 GHCi에서 `:load`로 불러온 뒤, 파일 내용을 조금 수정하고 `:reload`로 반영해서 바뀐 결과를 확인해 보세요.
5. GHCi의 `:quit`, `:type`, `:load`, `:reload` 명령어를 각각 한 문장으로 설명해 보세요.
