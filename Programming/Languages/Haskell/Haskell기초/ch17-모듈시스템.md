지금까지는 GHCi 안에서, 또는 파일 하나짜리 프로그램으로 코드를 작성했다. 하지만 프로그램이 커지면 함수와 타입을 논리적인 단위로 나누고, 필요한 것만 골라서 다른 파일에서 가져다 쓸 수 있어야 한다. Haskell에서 이 역할을 하는 것이 **모듈(module)**이다. 이번 장에서는 모듈을 선언하고 가져오는 문법, 자주 쓰는 표준 라이브러리 모듈, 그리고 여러 파일로 프로젝트를 구성하는 기초를 다룬다.

## 모듈이란 무엇인가

모듈은 관련된 함수, 타입, 타입 클래스를 하나의 이름 공간(namespace) 아래 묶어 놓은 단위다. 2장에서 `ghc`로 파일을 컴파일하거나 `runghc`로 실행할 때 항상 다뤘던 `.hs` 파일 하나하나가, 사실은 이미 모듈이었다.

```haskell
-- Main.hs
main :: IO ()
main = putStrLn "Hello, Haskell!"
```

이 파일에는 모듈 선언이 없지만, Haskell은 이런 경우 자동으로 `Main`이라는 이름의 모듈로 취급한다. `main`이라는 이름의 값이 그 모듈 안에 있어야만 실행 가능한 프로그램이 된다는 규칙도 여기서 비롯된다.

모듈 이름을 직접 정하고 싶다면 파일 맨 위에 `module ... where`를 적는다.

```haskell
module Main where

main :: IO ()
main = putStrLn "Hello, Haskell!"
```

`Main`이 아닌 모듈은 실행 프로그램의 진입점이 될 수 없지만, 다른 모듈에서 가져다 쓸 수 있는 라이브러리 역할을 한다. 예를 들어 도형의 넓이를 계산하는 모듈을 만들어 보자.

```haskell
-- Shapes.hs
module Shapes where

-- 원의 넓이
circleArea :: Double -> Double
circleArea r = pi * r * r

-- 직사각형의 넓이
rectangleArea :: Double -> Double -> Double
rectangleArea w h = w * h
```

**중요한 규칙**: 모듈 이름은 반드시 대문자로 시작해야 하고, 관례상 파일 이름과 모듈 이름을 똑같이 맞춘다. `Shapes` 모듈은 `Shapes.hs` 파일에 담겨야 한다. 이름이 어긋나면 GHC가 모듈을 찾지 못해 컴파일에 실패한다.

## 내보내기 목록: 무엇을 공개할까

`module Shapes where`처럼 아무 목록도 적지 않으면, 그 모듈 안에서 최상위로 정의된 모든 이름이 외부에 공개된다. 하지만 보통은 내부 구현에만 쓰이는 보조 함수를 감추고, 외부에서 쓸 이름만 골라 내보내고 싶을 때가 많다. 이때는 모듈 이름 뒤에 괄호로 **내보내기 목록(export list)**을 적는다.

```haskell
module Shapes
  ( circleArea
  , rectangleArea
  ) where

circleArea :: Double -> Double
circleArea r = pi * r * r

rectangleArea :: Double -> Double -> Double
rectangleArea w h = w * h

-- 내보내기 목록에 없으므로 이 모듈 밖에서는 보이지 않는다
validateSide :: Double -> Double
validateSide s
  | s > 0     = s
  | otherwise = error "길이는 양수여야 합니다"
```

`validateSide`는 내보내기 목록에 없으므로, 이 모듈을 가져다 쓰는 다른 파일에서는 존재 자체를 알 수 없다. 이렇게 공개 범위를 제한하면 두 가지 이점이 생긴다. 첫째, 모듈 사용자는 공개된 이름만 신경 쓰면 되므로 인터페이스가 명확해진다. 둘째, 내부 구현(`validateSide`의 세부 동작)을 나중에 자유롭게 바꿔도 외부 코드가 깨지지 않는다. 이는 18장에서 다룰 "좋은 코드"의 핵심 원칙과도 이어진다. 함수 하나하나뿐 아니라 모듈 단위에서도 "무엇을 공개하고 무엇을 감출지"를 설계하는 것이 좋은 습관이다.

10장에서 배운 커스텀 데이터 타입을 내보낼 때는 몇 가지 방식이 있다.

```haskell
module Shapes
  ( Shape(..)      -- 타입과 모든 생성자를 함께 내보낸다
  , area
  ) where

data Shape = Circle Double | Rectangle Double Double

area :: Shape -> Double
area (Circle r)      = pi * r * r
area (Rectangle w h) = w * h
```

`Shape(..)`는 `Shape` 타입과 그 생성자 `Circle`, `Rectangle`을 모두 공개한다. 생성자를 감추고 타입만 공개하려면 `Shape`만 적으면 된다. 이 경우 외부 코드는 `area` 같은 함수를 통해서만 `Shape` 값을 다룰 수 있고, 생성자를 직접 호출해 새 값을 만들 수는 없다. 이런 기법을 흔히 **추상 데이터 타입(abstract data type)**이라 부르며, 내부 표현이 바뀌어도 외부 인터페이스가 안정적으로 유지되도록 하는 대표적인 설계 방법이다.

## import로 모듈 가져오기

다른 모듈이 내보낸 이름을 쓰려면 `import`를 사용한다. `import`는 항상 모듈 선언 바로 다음, 즉 파일 맨 위쪽에 모아 적는다.

```haskell
-- Main.hs
module Main where

import Shapes

main :: IO ()
main = do
  print (circleArea 3.0)
  print (rectangleArea 4.0 5.0)
```

`import Shapes`는 `Shapes`가 내보낸 모든 이름을 지금 이 파일에서 마치 로컬 함수처럼 그대로 쓸 수 있게 해 준다.

### 선택적으로 가져오기

모듈이 내보내는 이름이 많을 때, 그중 일부만 가져오고 싶다면 괄호로 명시한다.

```haskell
import Shapes (circleArea)

main :: IO ()
main = print (circleArea 2.0)
```

이렇게 하면 `rectangleArea`는 이 파일에서 쓸 수 없다. 반대로 특정 이름만 제외하고 나머지는 다 가져오고 싶다면 `hiding`을 쓴다.

```haskell
import Shapes hiding (rectangleArea)
```

가져오는 이름을 좁히는 것은 단순히 타이핑을 줄이는 것을 넘어서, 이 파일이 실제로 무엇에 의존하는지를 코드만 보고 알 수 있게 해 준다는 실질적인 이점이 있다.

### 이름 충돌과 `qualified`, `as`

서로 다른 모듈이 같은 이름의 함수를 내보내는 경우가 흔하다. 예를 들어 6장에서 다룬 `Data.List`의 `sort`와, 직접 만든 모듈의 `sort`가 이름이 같다면 어느 쪽을 부르는지 컴파일러가 알 수 없다. 이럴 때 `qualified` 가져오기를 쓴다.

```haskell
import qualified Data.List as L

main :: IO ()
main = print (L.sort [3, 1, 2])
```

`qualified ... as L`은 "이 모듈이 내보내는 이름은 반드시 `L.` 접두사를 붙여서만 부르겠다"는 뜻이다. `L.sort`처럼 접두사를 붙이면 다른 모듈의 `sort`와 절대 헷갈리지 않는다. `as` 뒤의 별칭은 관례상 짧게 짓는다. `Data.Map`은 `M`, `Data.Text`는 `T`처럼 줄여 쓰는 것이 일반적이다.

`qualified` 없이 `as`만 쓸 수도 있다. 이 경우 원래 이름과 별칭 둘 다로 부를 수 있다.

```haskell
import Data.List as L

-- sort와 L.sort 둘 다 가능
main :: IO ()
main = print (sort [3, 1, 2])
```

실무에서는 이름이 겹치기 쉬운 컨테이너 모듈(`Data.Map`, `Data.Set` 등)은 `qualified`로, 이름이 겹칠 일이 적은 모듈(`Data.Char` 등)은 전체 가져오기로 쓰는 경향이 있다.

## 자주 쓰는 표준 라이브러리 모듈 살짝 보기

Haskell은 `Prelude`라는 모듈을 모든 파일에 자동으로 가져와 준다. `map`, `filter`, `foldr`, `length` 같은 지금까지 써 온 함수들이 모두 `Prelude`에 들어 있다. 그 외에 자주 쓰는 표준 모듈 몇 가지를 짧게 소개한다. 자세한 함수 목록은 부록의 치트시트에서 다시 정리한다.

### `Data.List`

6장과 9장에서 다룬 리스트 관련 함수 중 `Prelude`에 없는 것들이 여기 모여 있다.

```haskell
import Data.List (sort, nub, group, intercalate)

ghci> sort [3, 1, 4, 1, 5, 9, 2, 6]
[1,1,2,3,4,5,6,9]
ghci> nub [1, 1, 2, 2, 3, 1]      -- 중복 제거
[1,2,3]
ghci> group [1, 1, 2, 3, 3, 3]    -- 연속된 같은 값끼리 묶기
[[1,1],[2],[3,3,3]]
ghci> intercalate ", " ["사과", "바나나", "포도"]
"사과, 바나나, 포도"
```

### `Data.Map`

7장에서 튜플의 리스트로 "이름과 값의 짝"을 표현했다면, 실제로 키를 이용해 값을 빠르게 찾아야 할 때는 `Data.Map`이 훨씬 적합하다. 이름이 `Prelude`나 `Data.List`의 함수와 자주 겹치므로 거의 항상 `qualified`로 가져온다.

```haskell
import qualified Data.Map as Map

scores :: Map.Map String Int
scores = Map.fromList [("민지", 88), ("도윤", 45), ("하은", 92)]

ghci> Map.lookup "하은" scores
Just 92
ghci> Map.lookup "지훈" scores
Nothing
```

`Map.lookup`이 12장에서 배운 `Maybe`를 결과로 돌려준다는 점에 주목하자. 키가 없을 수도 있다는 사실이 타입에 그대로 드러난다.

### `Data.Char`

문자 하나를 검사하거나 변환하는 함수들이 모여 있다. 7장의 리스트 컴프리헨션 예제에서 이미 `isUpper`를 잠깐 썼다.

```haskell
import Data.Char (toUpper, isDigit)

ghci> map toUpper "hello"
"HELLO"
ghci> filter isDigit "abc123def456"
"123456"
```

이 밖에도 `Data.Maybe`(12장의 `Maybe` 다루기), `Data.Either`, `Control.Monad`(15장의 모나드 관련 함수) 등이 표준 라이브러리에 폭넓게 갖춰져 있다. 직접 함수를 짜기 전에 표준 라이브러리에 이미 있는지 GHCi의 `:t`나 온라인 문서로 확인해 보는 습관을 들이면 좋다.

## 여러 파일로 프로젝트 구성하기

작은 예제라면 한 파일로 충분하지만, 프로그램이 자라면 기능별로 파일을 나누는 것이 자연스럽다. 다음과 같은 세 파일짜리 프로젝트를 생각해 보자.

```haskell
-- Shapes.hs
module Shapes (Shape(..), area, perimeter) where

data Shape
  = Circle Double
  | Rectangle Double Double

area :: Shape -> Double
area (Circle r)      = pi * r * r
area (Rectangle w h) = w * h

perimeter :: Shape -> Double
perimeter (Circle r)      = 2 * pi * r
perimeter (Rectangle w h) = 2 * (w + h)
```

```haskell
-- Report.hs
module Report (describe) where

import Shapes

-- 도형을 설명하는 문자열을 만든다
describe :: Shape -> String
describe shape =
  "넓이: " ++ show (area shape) ++ ", 둘레: " ++ show (perimeter shape)
```

```haskell
-- Main.hs
module Main where

import Shapes
import Report

main :: IO ()
main = do
  let c = Circle 3.0
  putStrLn (describe c)
```

`Report` 모듈은 `Shapes`가 내보낸 `Shape`, `area`, `perimeter`만 알고 있으면 되고, 도형이 내부적으로 어떻게 표현되는지는 신경 쓰지 않는다. `Main`은 다시 `Shapes`와 `Report`를 조합해 실제 프로그램을 완성한다. 이렇게 역할을 나누면 각 모듈을 독립적으로 이해하고 테스트할 수 있다.

같은 디렉터리에 세 파일을 두었다면, GHC에게 `Main.hs`를 시작점으로 빌드하라고 알려 주면 나머지 모듈은 자동으로 찾아서 컴파일한다.

```powershell
ghc --make Main.hs
.\Main.exe
```

`--make` 옵션은 `Main.hs`가 `import`하는 모듈들을 추적해서, 필요한 파일을 전부 찾아 순서대로 컴파일해 준다. 파일이 몇 개 안 될 때는 이 방식으로 충분하다.

## 폴더 구조와 모듈 이름의 대응

프로젝트가 더 커지면 파일을 폴더로도 나누고 싶어진다. Haskell에서는 모듈 이름에 점(`.`)을 넣어 계층을 표현하고, 그 계층이 실제 폴더 구조와 정확히 일치해야 한다.

```
project/
  Main.hs
  Geometry/
    Shapes.hs
    Report.hs
```

```haskell
-- Geometry/Shapes.hs
module Geometry.Shapes where
-- ...
```

```haskell
-- Geometry/Report.hs
module Geometry.Report where

import Geometry.Shapes
-- ...
```

```haskell
-- Main.hs
import Geometry.Shapes
import Geometry.Report
```

`Geometry.Shapes`라는 모듈 이름은 `Geometry` 폴더 아래 `Shapes.hs` 파일에 있어야 한다는 뜻이다. 이 대응 관계는 GHC가 파일을 찾을 때 그대로 활용된다.

실제 규모가 있는 프로젝트에서는 `ghc --make`를 파일 하나하나 직접 호출하는 대신, `cabal`이나 `stack` 같은 빌드 도구가 이 과정을 대신 관리해 준다. 이 도구들은 어떤 모듈이 어떤 패키지에 속하는지, 어떤 표준 라이브러리 버전을 쓸지까지 설정 파일로 관리해 주지만, 그 밑바탕에는 지금 배운 "모듈 이름 = 파일 경로"라는 규칙과 `import` 문법이 그대로 깔려 있다. 지금은 작은 프로젝트를 여러 파일로 나누고 `ghc --make`로 직접 빌드해 보는 것만으로도 이 장의 목표는 충분하다.

## 요약

- 모듈은 `module 이름 where`로 선언하며, 파일 이름과 모듈 이름이 일치해야 하고 대문자로 시작해야 한다.
- 모듈 이름 뒤에 괄호로 내보내기 목록을 적어 공개할 이름을 제한할 수 있으며, 이를 통해 내부 구현을 감추는 추상화가 가능하다.
- `import 모듈`은 전체를, `import 모듈 (이름들)`은 일부를, `import 모듈 hiding (이름들)`은 일부를 제외하고 가져온다.
- 이름 충돌을 피하려면 `import qualified 모듈 as 별칭`을 쓰고, 별칭을 붙인 이름으로만 접근한다.
- `Data.List`, `Data.Map`, `Data.Char` 등 표준 라이브러리 모듈은 이미 검증된 함수를 다양하게 제공하므로, 직접 구현하기 전에 먼저 찾아보는 습관이 유용하다.
- 여러 파일로 프로젝트를 구성할 때는 모듈 간 `import` 관계를 그래프처럼 그려 보면 역할 분리가 잘 되었는지 점검할 수 있고, `ghc --make`는 이 관계를 추적해 자동으로 빌드해 준다.
- 폴더 구조를 나눌 때는 모듈 이름의 점(`.`) 계층이 실제 폴더 경로와 정확히 일치해야 한다.

## 연습문제

1. `Temperature.hs`라는 모듈을 만들어 섭씨를 화씨로, 화씨를 섭씨로 변환하는 두 함수를 정의하고 내보내기 목록으로 공개하라. 그리고 `Main.hs`에서 이 모듈을 가져와 사용하는 프로그램을 작성하라.
2. 위 `Temperature` 모듈에 두 변환 함수가 공통으로 쓰는 보조 함수를 하나 추가하되, 내보내기 목록에는 포함시키지 말고 모듈 내부에서만 쓰이게 하라.
3. `Data.List`를 `qualified`로 가져와 별칭 `L`을 붙이고, `L.sort`와 `L.nub`을 이용해 정수 리스트를 정렬한 뒤 중복을 제거하는 함수를 작성하라.
4. `import Data.Map hiding (filter)`처럼 `hiding`을 쓰는 상황이 실제로 필요한 경우를 생각해 보고, 왜 그런 충돌이 생기는지 설명하라. (`Prelude`와 `Data.Map`이 같은 이름의 함수를 갖고 있는 경우를 GHCi에서 확인해 보라.)
5. `Shape` 데이터 타입을 정의하는 모듈과, 그 타입 값을 화면에 출력하는 함수를 정의하는 모듈, 그리고 둘을 조합해 실행하는 `Main` 모듈까지 세 파일로 나누어 작은 프로그램을 만들고, `ghc --make Main.hs`로 빌드해 실행해 보라.
