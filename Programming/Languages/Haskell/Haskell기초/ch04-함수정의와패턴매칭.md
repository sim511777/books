# 4장. 함수 정의와 패턴 매칭

3장에서 `double n = n * 2`처럼 등호 하나로 함수를 정의하는 법을 봤다. 하지만 실제로 유용한 함수는 입력에 따라 다르게 동작해야 하는 경우가 많다. 이 장에서는 하나의 함수를 여러 개의 등식으로 쪼개 정의하는 **패턴 매칭**을 배운다. 이는 Haskell 코드를 다른 언어와 가장 다르게 만드는 특징 중 하나이며, 앞으로 나올 재귀(8장)와 고차 함수(9장)를 이해하는 데 핵심적인 도구다.

## 함수 정의의 기본 문법

함수 정의는 항상 "함수 이름, 매개변수, 등호, 본문" 순서로 이루어진다.

```haskell
greet :: String -> String
greet name = "안녕하세요, " ++ name ++ "님!"
```

```haskell
ghci> putStrLn (greet "지수")
안녕하세요, 지수님!
```

매개변수가 여러 개면 공백으로 나열한다. 화살표로 이어진 타입 시그니처와 매개변수 개수가 정확히 대응한다.

```haskell
addThree :: Int -> Int -> Int -> Int
addThree a b c = a + b + c
```

```haskell
ghci> addThree 1 2 3
6
```

여기까지는 3장에서 본 것과 크게 다르지 않다. 흥미로운 부분은 지금부터다.

## 여러 개의 등식으로 나눠 정의하기

같은 함수 이름을 여러 번 써서, 입력값의 "모양"에 따라 다른 본문을 실행하게 만들 수 있다. 대표적인 예가 팩토리얼이다.

```haskell
factorial :: Integer -> Integer
factorial 0 = 1
factorial n = n * factorial (n - 1)
```

이 코드는 두 개의 등식으로 이루어져 있다.

- `factorial 0 = 1`: 입력이 정확히 `0`이면 결과는 `1`이다.
- `factorial n = n * factorial (n - 1)`: 그 외의 모든 경우, `n`이라는 이름으로 입력값을 받아 재귀적으로 계산한다.

GHC는 함수를 호출할 때 위에서부터 순서대로 등식을 검사하며, 입력값이 첫 번째 패턴(`0`)과 일치하는지 본다. 일치하면 그 등식을 쓰고, 아니면 다음 등식으로 넘어간다. `n`처럼 이름만 있는 패턴은 어떤 값과도 일치하므로 "나머지 모든 경우"를 받는 역할을 한다.

```haskell
ghci> factorial 0
1
ghci> factorial 5
120
```

이렇게 값을 직접 나열해 매칭하는 것을 **리터럴 패턴**이라 부른다. 재귀 호출이 어떻게 종료되는지는 8장에서 훨씬 자세히 다룰 테니, 지금은 "패턴에 따라 등식이 나뉜다"는 형태에 집중하자.

패턴 순서는 중요하다. 만약 `factorial n = ...`을 먼저 쓰고 `factorial 0 = 1`을 나중에 쓰면, `n`이 모든 값을 다 받아버리기 때문에 `0`에 대한 등식은 영원히 실행되지 않는다.

```haskell
-- 잘못된 순서: 이 정의는 무한 재귀에 빠진다
badFactorial :: Integer -> Integer
badFactorial n = n * badFactorial (n - 1)
badFactorial 0 = 1
```

## 와일드카드 `_`

패턴에서 값을 실제로 쓰지 않을 거라면, 이름을 붙이는 대신 밑줄(`_`)을 쓸 수 있다. 이는 "여기 오는 값은 무엇이든 상관없고, 쓰지도 않겠다"는 뜻이다.

```haskell
isZero :: Int -> Bool
isZero 0 = True
isZero _ = False
```

```haskell
ghci> isZero 0
True
ghci> isZero 42
False
```

`_`를 쓰면 컴파일러가 "이 이름을 쓰지 않았다"는 경고를 내지 않으며, 코드를 읽는 사람에게도 "이 값은 이 등식에서 중요하지 않다"는 의도를 분명히 전달한다.

## 리스트 패턴: `x:xs`

Haskell 리스트는 내부적으로 "첫 원소"와 "나머지 리스트"로 이루어진 구조다(6장에서 리스트를 더 깊이 다룬다). 이 구조를 그대로 패턴으로 쓸 수 있는데, 관례적으로 첫 원소는 `x`, 나머지는 `xs`(x들, 즉 복수형)라고 이름 붙인다.

```haskell
firstOrDefault :: [Int] -> Int
firstOrDefault [] = 0
firstOrDefault (x:xs) = x
```

```haskell
ghci> firstOrDefault []
0
ghci> firstOrDefault [7, 8, 9]
7
```

`[]`는 빈 리스트에만 매칭되는 패턴이고, `(x:xs)`는 원소가 하나 이상 있는 리스트에서 첫 원소를 `x`에, 나머지 전체를 `xs`에 묶는다. `xs`가 비어 있는 리스트여도 상관없다.

```haskell
ghci> firstOrDefault [42]  -- x = 42, xs = []
42
```

리스트 패턴은 여러 겹으로 쓸 수도 있다. 예를 들어 원소가 두 개 이상인 리스트에서 앞의 두 원소를 뽑아내려면 다음처럼 쓴다.

```haskell
firstTwo :: [Int] -> String
firstTwo [] = "원소가 없습니다"
firstTwo [_] = "원소가 하나뿐입니다"
firstTwo (x:y:_) = "처음 두 원소: " ++ show x ++ ", " ++ show y
```

```haskell
ghci> putStrLn (firstTwo [1])
원소가 하나뿐입니다
ghci> putStrLn (firstTwo [1, 2, 3])
처음 두 원소: 1, 2
```

`[_]`는 "원소가 정확히 하나인 리스트"에 매칭되는 패턴이다. 밑줄과 리스트 패턴을 이렇게 섞어 쓰면 리스트의 길이에 따른 여러 경우를 매우 간결하게 표현할 수 있다. 재귀 함수를 작성할 때 `x:xs` 패턴은 "리스트의 머리와 꼬리를 나눠서, 머리를 처리하고 꼬리에 대해 재귀한다"는 전형적인 흐름의 출발점이 된다. 이 흐름은 8장에서 리스트 재귀를 다룰 때 계속 등장한다.

## 튜플 패턴

튜플은 서로 다른 타입의 값을 고정된 개수만큼 묶은 것이다(7장에서 튜플을 자세히 다룬다). 튜플도 패턴으로 그 구성 요소를 바로 분해할 수 있다.

```haskell
distanceFromOrigin :: (Double, Double) -> Double
distanceFromOrigin (x, y) = sqrt (x * x + y * y)
```

```haskell
ghci> distanceFromOrigin (3.0, 4.0)
5.0
```

`(x, y)`라는 패턴은 "이 인자는 반드시 두 원소짜리 튜플이며, 첫 번째를 `x`, 두 번째를 `y`라 부르겠다"는 뜻이다. 튜플 안에 리터럴이나 와일드카드를 섞어 쓸 수도 있다.

```haskell
describePoint :: (Int, Int) -> String
describePoint (0, 0) = "원점"
describePoint (0, _) = "y축 위의 점"
describePoint (_, 0) = "x축 위의 점"
describePoint (_, _) = "그 외의 점"
```

```haskell
ghci> putStrLn (describePoint (0, 0))
원점
ghci> putStrLn (describePoint (0, 5))
y축 위의 점
ghci> putStrLn (describePoint (3, 3))
그 외의 점
```

여기서도 순서가 중요하다. `(0, 0)`이 가장 구체적인 패턴이므로 맨 위에 와야 한다. 만약 `(0, _)`를 먼저 쓰면 `(0, 0)`도 그 패턴에 걸려버려서, 아래에 있는 `(0, 0) = "원점"` 등식은 결코 실행되지 않는다.

## let, where 안에서도 패턴 매칭이 가능하다

3장에서 배운 `let`과 `where`도 패턴을 그대로 받을 수 있다.

```haskell
swap :: (Int, Int) -> (Int, Int)
swap pair =
  let (a, b) = pair
  in (b, a)
```

이렇게 하면 함수 매개변수 자리뿐 아니라 지역 바인딩에서도 데이터를 분해해서 이름을 붙일 수 있다.

## 함수도 값이다: 잠깐 미리보기

지금까지는 함수에 숫자나 문자열, 리스트, 튜플을 넘겼다. 그런데 Haskell에서는 **함수 자체도 다른 값과 똑같은 자격을 가진 값**이다. 즉 함수를 변수에 담을 수 있고, 다른 함수의 인자로 넘길 수 있고, 함수가 함수를 결과로 반환할 수도 있다.

```haskell
ghci> let myFunc = factorial
ghci> myFunc 5
120
```

`myFunc`라는 이름에 `factorial`이라는 함수 자체를 그대로 묶었다. 이것이 가능한 이유는 Haskell에서 함수가 `Int`나 `Bool`과 동등한 "일급 값(first-class value)"이기 때문이다. 이 성질은 9장 고차 함수에서 본격적으로 활용된다. 예를 들어 리스트의 모든 원소에 함수를 적용하는 `map`, 조건에 맞는 원소만 골라내는 `filter` 같은 함수들이 바로 "함수를 인자로 받는 함수"다. 지금 당장 이해할 필요는 없지만, 오늘 배운 "함수는 등식들의 모음"이라는 감각이 그 함수들을 이해하는 데 그대로 이어진다는 점을 기억해 두자.

## 요약

- 함수는 이름, 매개변수, 등호, 본문으로 정의하며, 같은 이름으로 여러 등식을 나열해 입력값의 모양에 따라 다르게 동작하도록 만들 수 있다(패턴 매칭).
- 패턴은 위에서부터 순서대로 검사되므로, 더 구체적인 패턴(리터럴 값 등)을 먼저 쓰고 일반적인 패턴(변수, 와일드카드)을 나중에 써야 한다.
- 와일드카드 `_`는 값을 쓰지 않고 무시하겠다는 뜻이며, `x:xs`는 리스트를 머리와 꼬리로 분해하고, `(a, b)`는 튜플을 구성 요소로 분해한다.
- `let`과 `where`에서도 패턴을 이용해 데이터를 분해할 수 있다.
- Haskell에서 함수는 다른 값과 동등한 일급 값이며, 이름에 묶거나 다른 함수에 넘길 수 있다. 이 개념은 9장 고차 함수에서 본격적으로 다룬다.

## 연습문제

1. `describeNumber :: Int -> String` 함수를 패턴 매칭으로 작성해, 입력이 `0`이면 `"영"`, `1`이면 `"하나"`, 그 외에는 `"기타"`를 반환하도록 만들어라.
2. 리스트를 받아 원소가 정확히 3개일 때만 `True`를 반환하는 `hasThreeElements :: [Int] -> Bool` 함수를 리스트 패턴으로 작성하라.
3. 세 원소짜리 튜플 `(Int, Int, Int)`을 받아 그중 최댓값을 반환하는 `maxOfThree` 함수를 작성하되, 튜플 패턴으로 세 값을 분해한 뒤 `where` 절에서 비교 로직을 정리해 보라.
4. 다음 정의는 의도한 대로 동작하지 않는다. 문제가 무엇인지 설명하고 올바르게 고쳐라.
   ```haskell
   isEmpty :: [Int] -> Bool
   isEmpty xs = True
   isEmpty [] = False
   ```
5. `x:xs` 패턴을 이용해, 리스트의 첫 번째와 두 번째 원소가 같은지 확인하는 `firstTwoEqual :: [Int] -> Bool` 함수를 작성하라. 원소가 2개보다 적을 때는 `False`를 반환해야 한다.
