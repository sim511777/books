# 15장. 예외 처리

[◀ 이전: 14장. 컬렉션과 LINQ](ch14-컬렉션과LINQ.md) | [📖 목차](00-목차.md) | [다음: 16장. 델리게이트와 이벤트 ▶](ch16-델리게이트와이벤트.md)

---

프로그램은 언제나 예상한 대로만 흘러가지 않습니다. 사용자가 숫자 대신 글자를 입력하거나, 열려야 할 파일이 없거나, 네트워크가 끊기는 일은 프로그램을 짜는 사람이 아무리 조심해도 벌어질 수 있습니다. C#은 이런 "실행 중에 터지는 문제"를 예외(exception)라는 객체로 표현하고, 이를 `try`/`catch`/`finally` 구문으로 다루도록 설계되어 있습니다. 이 장에서는 예외가 무엇인지, 어떻게 잡아내고 처리하는지, 그리고 자원을 안전하게 정리하는 방법까지 살펴봅니다.

## 예외란 무엇인가

예외는 프로그램 실행 중 정상적인 흐름을 이어갈 수 없는 상황이 발생했을 때 .NET 런타임이나 코드가 던지는 신호입니다. 예를 들어 배열의 범위를 벗어난 인덱스에 접근하거나, 0으로 나누는 연산을 시도하면 런타임은 예외를 발생시킵니다. 예외를 처리하지 않으면 프로그램은 그 자리에서 강제로 종료됩니다.

```csharp
int[] numbers = { 1, 2, 3 };
Console.WriteLine(numbers[5]); // IndexOutOfRangeException 발생, 프로그램 종료
```

이런 상황을 그대로 방치하지 않고, 문제를 예측하고 적절히 대응하기 위해 예외 처리 구문을 사용합니다.

## try, catch, finally의 기본 구조

`try` 블록에는 예외가 발생할 수 있는 코드를 넣고, `catch` 블록에는 예외가 발생했을 때 실행할 코드를 넣습니다. `finally` 블록은 예외가 발생하든 안 하든 항상 실행되는 마무리 코드를 담습니다.

```csharp
try
{
    Console.Write("나눌 숫자를 입력하세요: ");
    string input = Console.ReadLine();
    int divisor = int.Parse(input);
    int result = 100 / divisor;
    Console.WriteLine($"결과: {result}");
}
catch (DivideByZeroException ex)
{
    Console.WriteLine($"0으로 나눌 수 없습니다: {ex.Message}");
}
catch (FormatException ex)
{
    Console.WriteLine($"숫자 형식이 아닙니다: {ex.Message}");
}
finally
{
    Console.WriteLine("입력 처리를 마쳤습니다.");
}
```

이 코드는 사용자가 `0`을 입력하면 `DivideByZeroException`을, 숫자가 아닌 문자열을 입력하면 `FormatException`을 잡아냅니다. 어느 경우든 `finally` 블록은 반드시 실행되므로, 파일을 닫거나 로그를 남기는 등 "무조건 해야 하는 뒷정리"를 여기에 두면 됩니다.

## 예외 계층과 여러 타입 처리하기

C#의 모든 예외 타입은 `System.Exception` 클래스를 최상위 부모로 두는 상속 계층을 이룹니다. `DivideByZeroException`이나 `FormatException`은 각각 `ArithmeticException`, `Exception` 계열의 자손 클래스입니다. 10장 상속과 다형성에서 다룬 개념이 여기서도 그대로 적용됩니다. 부모 타입으로 `catch`를 걸면 자식 타입의 예외까지 함께 잡힙니다.

```csharp
try
{
    int[] data = { 1, 2, 3 };
    Console.WriteLine(data[10] / 0);
}
catch (IndexOutOfRangeException ex)
{
    Console.WriteLine($"인덱스 오류: {ex.Message}");
}
catch (Exception ex)
{
    // 위에서 잡지 못한 모든 예외를 여기서 잡는다
    Console.WriteLine($"알 수 없는 오류: {ex.Message}");
}
```

여러 `catch` 블록을 나열할 때는 반드시 더 구체적인(자식) 타입을 위에, 더 포괄적인(부모) 타입을 아래에 놓아야 합니다. 순서가 반대라면 부모 타입 `catch`가 모든 예외를 가로채 버려서 아래에 있는 구체적인 `catch` 블록은 컴파일 오류가 나거나 결코 실행되지 않습니다. 가장 포괄적인 `Exception`은 항상 마지막에 두어 "예상하지 못한 나머지"를 처리하는 안전망 역할을 하게 합니다.

## throw로 예외 직접 발생시키기

`throw` 키워드를 쓰면 조건에 맞지 않는 상황을 직접 예외로 알릴 수 있습니다. 메서드를 만들 때 잘못된 입력값을 그냥 통과시키기보다, 문제를 발견한 즉시 예외를 던지는 것이 좋은 습관입니다.

```csharp
static double CalculateAverage(int[] scores)
{
    if (scores == null || scores.Length == 0)
    {
        throw new ArgumentException("점수 배열이 비어 있습니다.", nameof(scores));
    }

    int sum = 0;
    foreach (int score in scores)
    {
        sum += score;
    }
    return (double)sum / scores.Length;
}
```

`ArgumentException`은 .NET이 기본으로 제공하는 예외 타입 중 하나로, 메서드에 잘못된 인수가 전달되었을 때 쓰기에 적합합니다. 비슷한 목적의 내장 예외로 `ArgumentNullException`, `InvalidOperationException` 등이 있으며, 직접 예외 타입을 만들기 전에는 이런 표준 타입 중 상황에 맞는 것을 먼저 찾아보는 것이 좋습니다.

## 커스텀 예외 클래스 만들기

프로그램의 도메인에 특화된 오류 상황은 직접 예외 클래스를 만들어 표현하면 코드의 의도가 훨씬 명확해집니다. 커스텀 예외는 `Exception`을 상속하는 클래스로 정의합니다.

```csharp
// 재고 부족 상황을 나타내는 커스텀 예외
class InsufficientStockException : Exception
{
    public string ProductName { get; }
    public int RequestedQuantity { get; }

    public InsufficientStockException(string productName, int requestedQuantity)
        : base($"'{productName}' 재고가 부족합니다. 요청 수량: {requestedQuantity}")
    {
        ProductName = productName;
        RequestedQuantity = requestedQuantity;
    }
}

class Warehouse
{
    private int _stock = 5;

    public void Ship(string productName, int quantity)
    {
        if (quantity > _stock)
        {
            throw new InsufficientStockException(productName, quantity);
        }
        _stock -= quantity;
        Console.WriteLine($"{productName} {quantity}개 출고 완료. 남은 재고: {_stock}");
    }
}
```

이렇게 만든 예외는 일반적인 `Exception`처럼 `catch`로 잡아 쓸 수 있고, `ProductName`이나 `RequestedQuantity` 같은 추가 속성을 통해 문제 상황에 대한 정보를 풍부하게 전달할 수 있습니다.

```csharp
var warehouse = new Warehouse();
try
{
    warehouse.Ship("무선 키보드", 10);
}
catch (InsufficientStockException ex)
{
    Console.WriteLine($"출고 실패: {ex.Message}");
    Console.WriteLine($"요청 수량 {ex.RequestedQuantity}개를 재주문 목록에 추가합니다.");
}
```

커스텀 예외 클래스의 이름은 관례적으로 `Exception`으로 끝나게 짓습니다. 이는 코드를 읽는 사람이 타입 이름만 보고도 "이건 예외 클래스구나"를 바로 알 수 있게 해주는 작은 배려입니다.

## using으로 자원을 안전하게 해제하기

파일, 네트워크 연결, 데이터베이스 연결처럼 사용을 마치면 반드시 닫아야 하는 자원들은 `IDisposable` 인터페이스를 구현합니다. `IDisposable`은 `Dispose()`라는 메서드 하나만을 요구하는 간단한 인터페이스이며, 이 메서드를 호출하면 자원이 해제됩니다. 문제는 자원을 사용하는 도중 예외가 발생하면 `Dispose()` 호출이 누락될 수 있다는 점인데, `using` 문이 바로 이 문제를 해결합니다.

```csharp
using (StreamWriter writer = new StreamWriter("log.txt"))
{
    writer.WriteLine("작업을 시작합니다.");
    int result = 10 / int.Parse("0"); // 예외 발생
    writer.WriteLine("이 줄은 실행되지 않습니다.");
}
// 예외가 발생해도 writer.Dispose()는 반드시 호출된다
```

`using` 블록을 벗어나는 순간(정상 종료든, 예외로 인한 이탈이든) `Dispose()`가 자동으로 호출됩니다. 내부적으로는 `try`/`finally`와 동일하게 동작하며, 사실 위 코드는 다음과 같이 풀어 쓴 것과 같습니다.

```csharp
StreamWriter writer = new StreamWriter("log.txt");
try
{
    writer.WriteLine("작업을 시작합니다.");
    int result = 10 / int.Parse("0");
}
finally
{
    writer.Dispose();
}
```

C# 8 이후에는 중괄호 블록 없이 쓰는 `using` 선언도 지원합니다. 변수가 선언된 블록(보통은 메서드 전체)이 끝나는 시점에 자동으로 `Dispose()`가 호출됩니다.

```csharp
static void WriteLog(string message)
{
    using StreamWriter writer = new StreamWriter("log.txt", append: true);
    writer.WriteLine(message);
    // 메서드가 끝나는 시점에 writer.Dispose()가 자동 호출된다
}
```

들여쓰기가 한 단계 줄어들어 코드가 더 간결해지므로, 자원을 메서드 끝까지 계속 써야 하는 경우에는 `using` 선언을 선호하는 경우가 많습니다. 여러 개의 자원을 함께 다뤄야 할 때는 `using` 문을 중첩하거나, `using` 선언을 여러 줄 나열해도 무방합니다.

## 요약

- 예외는 실행 중 정상적인 흐름을 이어갈 수 없는 상황을 나타내는 객체로, `try`/`catch`/`finally`로 처리합니다.
- 모든 예외 타입은 `System.Exception`을 상위 클래스로 하는 상속 계층을 이루며, `catch` 블록은 구체적인 타입부터 포괄적인 타입 순으로 나열해야 합니다.
- `throw`로 코드 어디서든 예외를 직접 발생시킬 수 있으며, 잘못된 입력은 가능한 한 빨리 예외로 알리는 것이 좋습니다.
- `Exception`을 상속해 도메인에 맞는 커스텀 예외 클래스를 만들면 오류 상황을 더 명확하게 표현할 수 있습니다.
- `IDisposable` 자원은 `using` 문(또는 `using` 선언)으로 감싸면 예외가 발생하더라도 `Dispose()`가 자동으로 호출되어 자원 누수를 막을 수 있습니다.

## 연습문제

1. 정수 두 개를 입력받아 나눈 값을 출력하는 프로그램을 작성하고, `FormatException`과 `DivideByZeroException`을 각각 다른 `catch` 블록으로 처리해보세요.
2. `catch (Exception)` 블록을 `catch (DivideByZeroException)` 블록보다 위에 두면 어떤 컴파일 오류가 나는지 직접 코드를 작성해 확인해보세요.
3. 나이를 매개변수로 받는 메서드를 만들고, 나이가 음수이면 `ArgumentException`을 던지도록 구현해보세요.
4. `Exception`을 상속하는 `NegativeAmountException` 커스텀 예외 클래스를 만들고, 계좌에서 음수 금액을 출금하려 할 때 이 예외를 던지는 `Withdraw` 메서드를 작성해보세요.
5. `using` 선언을 사용해 텍스트 파일에 여러 줄을 기록하는 메서드를 작성하고, 중간에 예외를 발생시켜도 파일 자원이 정상적으로 정리되는지 확인해보세요.
