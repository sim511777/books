9장에서 클래스를 정의하고 객체를 만드는 방법을 배웠습니다. 그런데 실제 프로그램을 작성하다 보면 "정규직 직원"과 "계약직 직원"처럼 서로 비슷하지만 조금씩 다른 여러 클래스를 만들어야 하는 상황이 자주 생깁니다. 이런 경우 공통되는 부분을 매번 새로 작성하는 것은 비효율적입니다. 이번 장에서는 클래스 간의 공통점을 재사용하는 **상속(inheritance)**과, 여러 클래스를 하나의 공통된 형태로 다루는 **다형성(polymorphism)**을 배웁니다.

## 클래스 상속

C#에서는 `:` 기호를 이용해 다른 클래스를 상속받을 수 있습니다. 상속을 받는 클래스를 **파생 클래스(derived class)** 또는 **자식 클래스**, 상속을 주는 클래스를 **기반 클래스(base class)** 또는 **부모 클래스**라고 부릅니다.

```csharp
// 기반 클래스
public class Employee
{
    public string Name;
    public int BaseSalary;

    public Employee(string name, int baseSalary)
    {
        Name = name;
        BaseSalary = baseSalary;
    }

    public void PrintInfo()
    {
        Console.WriteLine($"{Name} - 기본급 {BaseSalary}원");
    }
}

// 파생 클래스: Employee를 상속받는다
public class Manager : Employee
{
    public int TeamSize;

    public Manager(string name, int baseSalary, int teamSize)
        : base(name, baseSalary)  // 기반 클래스의 생성자 호출
    {
        TeamSize = teamSize;
    }
}
```

`Manager` 클래스는 `Employee`를 상속받았기 때문에 `Name`, `BaseSalary` 필드와 `PrintInfo()` 메서드를 별도로 작성하지 않아도 그대로 사용할 수 있습니다.

```csharp
Manager m = new Manager("김철수", 4000000, 5);
m.PrintInfo();               // Employee의 메서드를 그대로 사용
Console.WriteLine(m.TeamSize);
```

## base 키워드

`base`는 파생 클래스에서 기반 클래스의 멤버에 접근할 때 사용하는 키워드입니다. 위 예제의 `: base(name, baseSalary)`처럼 기반 클래스의 생성자를 호출하는 데 주로 쓰이며, 기반 클래스의 메서드를 호출할 때도 사용할 수 있습니다.

```csharp
public class Manager : Employee
{
    public int TeamSize;

    public Manager(string name, int baseSalary, int teamSize)
        : base(name, baseSalary)
    {
        TeamSize = teamSize;
    }

    public void PrintFullInfo()
    {
        base.PrintInfo();  // 기반 클래스의 메서드 호출
        Console.WriteLine($"팀원 수: {TeamSize}명");
    }
}
```

파생 클래스의 생성자는 반드시 기반 클래스의 생성자가 먼저 실행된 다음에 자신의 코드를 실행합니다. `base(...)`를 명시하지 않으면 기반 클래스의 매개변수 없는 생성자가 자동으로 호출되는데, 만약 기반 클래스에 매개변수 없는 생성자가 없다면 컴파일 오류가 발생하므로 `base(...)`로 명확히 지정해야 합니다.

## virtual과 override로 메서드 재정의하기

기반 클래스의 메서드를 파생 클래스에서 다른 내용으로 바꾸고 싶을 때가 있습니다. 이를 **메서드 재정의(overriding)**라고 하며, 기반 클래스에서는 `virtual`을, 파생 클래스에서는 `override`를 붙여야 합니다.

```csharp
public class Employee
{
    public string Name;

    public virtual decimal CalculateSalary()
    {
        return 3000000;
    }
}

public class Manager : Employee
{
    public override decimal CalculateSalary()
    {
        return 5000000;  // 관리자는 급여 계산 방식이 다름
    }
}
```

이렇게 재정의된 메서드는 실제로 어떤 클래스의 객체인지에 따라 실행되는 코드가 달라집니다.

```csharp
Employee e = new Manager();
Console.WriteLine(e.CalculateSalary());  // 5000000 (Manager의 버전이 실행됨)
```

변수 `e`의 타입은 `Employee`이지만, 실제로 담겨 있는 객체는 `Manager`이기 때문에 `CalculateSalary()`를 호출하면 `Manager`가 재정의한 버전이 실행됩니다.

### new 키워드와의 차이

`override` 대신 `new`를 사용해도 파생 클래스에서 같은 이름의 메서드를 다시 정의할 수 있습니다. 하지만 동작 방식이 전혀 다릅니다. `new`로 숨긴 메서드는 변수의 **선언된 타입**을 기준으로 어떤 메서드가 실행될지 결정됩니다.

```csharp
public class Employee
{
    public void Greet()  // virtual이 아님
    {
        Console.WriteLine("저는 직원입니다.");
    }
}

public class Manager : Employee
{
    public new void Greet()
    {
        Console.WriteLine("저는 관리자입니다.");
    }
}

Employee e = new Manager();
e.Greet();  // "저는 직원입니다." — 변수의 선언 타입(Employee) 기준으로 결정됨

Manager m2 = new Manager();
m2.Greet(); // "저는 관리자입니다."
```

`virtual`/`override` 조합은 실제 객체의 타입을 기준으로 동작하는 반면, `new`는 단순히 같은 이름의 새 메서드를 만들어 기존 메서드를 가리는 것에 불과합니다. 다형성을 제대로 활용하려면 `virtual`/`override` 조합을 사용해야 합니다.

## 인터페이스

**인터페이스(interface)**는 클래스가 반드시 구현해야 할 메서드나 속성의 목록만 정의하고, 실제 구현은 담지 않는 계약입니다. 관례적으로 이름 앞에 `I`를 붙입니다.

```csharp
public interface IPayable
{
    decimal CalculatePayment();
}
```

클래스는 `:` 뒤에 인터페이스 이름을 적어서 이를 구현합니다.

```csharp
public class Freelancer : IPayable
{
    public int HoursWorked;
    public decimal HourlyRate;

    public decimal CalculatePayment()
    {
        return HoursWorked * HourlyRate;
    }
}
```

인터페이스를 구현한 클래스는 그 인터페이스가 정의한 메서드를 반드시 작성해야 하며, 그렇지 않으면 컴파일 오류가 발생합니다. C#은 클래스 상속은 하나만 가능하지만, 인터페이스는 여러 개를 동시에 구현할 수 있습니다.

```csharp
public interface INotifiable
{
    void SendNotification(string message);
}

// 클래스는 하나만 상속받지만 인터페이스는 여러 개 구현 가능
public class Freelancer : IPayable, INotifiable
{
    public decimal CalculatePayment() => 0;  // 실제 구현은 생략

    public void SendNotification(string message)
    {
        Console.WriteLine($"알림: {message}");
    }
}
```

## 추상 클래스와 인터페이스의 차이

**추상 클래스(abstract class)**는 `abstract` 키워드로 선언하며, 그 자체로는 객체를 만들 수 없고 반드시 다른 클래스가 상속받아야 하는 클래스입니다. 추상 클래스는 구현된 메서드와 구현되지 않은 **추상 메서드**를 함께 가질 수 있습니다.

```csharp
public abstract class Shape
{
    public string Name;

    public Shape(string name)
    {
        Name = name;
    }

    // 구현이 없는 추상 메서드: 반드시 파생 클래스가 구현해야 함
    public abstract double GetArea();

    // 이미 구현된 일반 메서드
    public void PrintName()
    {
        Console.WriteLine($"도형 이름: {Name}");
    }
}

public class Circle : Shape
{
    public double Radius;

    public Circle(double radius) : base("원")
    {
        Radius = radius;
    }

    public override double GetArea()
    {
        return Math.PI * Radius * Radius;
    }
}
```

`Shape shape = new Shape("도형");`처럼 추상 클래스를 직접 인스턴스화하려고 하면 컴파일 오류가 발생합니다. 반드시 `Circle`처럼 이를 상속받은 클래스를 통해서만 사용할 수 있습니다.

추상 클래스와 인터페이스는 비슷해 보이지만 다음과 같은 중요한 차이가 있습니다.

| 구분 | 추상 클래스 | 인터페이스 |
|---|---|---|
| 필드 보유 | 가능 | 불가능 |
| 일반 메서드(구현체) 보유 | 가능 | 기본적으로 계약만 정의 (C# 8.0 이후 기본 구현 가능하지만 초급 단계에서는 지양) |
| 다중 상속/구현 | 클래스는 하나만 상속 가능 | 여러 개 동시 구현 가능 |
| 생성자 | 가질 수 있음 | 가질 수 없음 |
| 사용 목적 | "이것은 ~이다"라는 강한 공통 정체성을 표현 (is-a) | "이것은 ~를 할 수 있다"라는 능력을 표현 (can-do) |

일반적으로 여러 클래스가 필드나 공통 로직을 진짜로 공유해야 한다면 추상 클래스를, 서로 관련 없는 클래스들이 특정 동작만 공통으로 갖추면 되는 경우라면 인터페이스를 선택합니다.

## 다형성 활용 예제: 공통 인터페이스로 여러 클래스를 하나의 리스트에 담기

다형성의 진짜 힘은 서로 다른 클래스의 객체들을 하나의 공통된 타입(인터페이스나 기반 클래스)으로 묶어서 처리할 수 있다는 데 있습니다. 7장에서 배운 리스트를 활용해 보겠습니다.

```csharp
public interface IShape
{
    double GetArea();
    string GetDescription();
}

public class Circle : IShape
{
    public double Radius;
    public Circle(double radius) { Radius = radius; }

    public double GetArea() => Math.PI * Radius * Radius;
    public string GetDescription() => $"반지름 {Radius}인 원";
}

public class Rectangle : IShape
{
    public double Width;
    public double Height;
    public Rectangle(double width, double height)
    {
        Width = width;
        Height = height;
    }

    public double GetArea() => Width * Height;
    public string GetDescription() => $"{Width} x {Height} 크기의 사각형";
}

public class Triangle : IShape
{
    public double Base;
    public double Height;
    public Triangle(double baseLength, double height)
    {
        Base = baseLength;
        Height = height;
    }

    public double GetArea() => Base * Height / 2;
    public string GetDescription() => $"밑변 {Base}, 높이 {Height}인 삼각형";
}
```

`Circle`, `Rectangle`, `Triangle`은 서로 상속 관계가 전혀 없는 독립적인 클래스이지만, 모두 `IShape` 인터페이스를 구현하고 있으므로 다음과 같이 하나의 리스트로 다룰 수 있습니다.

```csharp
List<IShape> shapes = new List<IShape>
{
    new Circle(5),
    new Rectangle(4, 6),
    new Triangle(3, 8)
};

double totalArea = 0;
foreach (IShape shape in shapes)
{
    Console.WriteLine($"{shape.GetDescription()} - 넓이: {shape.GetArea():F2}");
    totalArea += shape.GetArea();
}
Console.WriteLine($"전체 넓이 합: {totalArea:F2}");
```

`foreach` 안에서 `shape` 변수는 매번 실제로는 `Circle`, `Rectangle`, `Triangle` 중 하나를 가리키지만, 우리는 그것이 정확히 어떤 클래스인지 신경 쓸 필요 없이 `IShape`가 보장하는 `GetArea()`와 `GetDescription()`만 호출하면 됩니다. 새로운 도형 클래스(예: `Pentagon`)를 추가하더라도 `IShape`만 구현하면 이 `foreach` 코드는 전혀 수정할 필요가 없습니다. 이것이 다형성이 주는 확장성의 핵심입니다. 이런 도형 목록을 정렬하거나 조건에 맞게 걸러내는 작업은 14장 컬렉션과 LINQ에서 훨씬 간결하게 다시 다루게 됩니다.

## 요약

- `:` 문법으로 클래스를 상속받으며, `base`로 기반 클래스의 생성자와 멤버에 접근한다.
- `virtual`로 선언된 메서드를 파생 클래스에서 `override`로 재정의하면, 실제 객체의 타입을 기준으로 어떤 버전이 실행될지 결정된다.
- `new`로 메서드를 숨기는 것은 변수의 선언 타입을 기준으로 동작이 결정되므로 `override`와는 근본적으로 다르다.
- 인터페이스는 구현을 담지 않는 계약이며, 클래스는 여러 인터페이스를 동시에 구현할 수 있다.
- 추상 클래스는 필드와 구현된 메서드를 가질 수 있지만 직접 인스턴스화할 수 없으며, 인터페이스와는 "is-a"와 "can-do"의 관점에서 구분해 사용한다.
- 공통 인터페이스나 기반 클래스를 이용하면 서로 다른 클래스의 객체를 하나의 컬렉션으로 다루는 다형성을 구현할 수 있다.

1. `Animal` 기반 클래스에 `virtual` 메서드 `MakeSound()`를 정의하고, 이를 상속하는 `Dog`, `Cat` 클래스에서 각각 `override`로 재정의해 보세요. `List<Animal>`에 여러 동물을 담고 `foreach`로 순회하며 `MakeSound()`를 호출해 보세요.
2. `IPrintable` 인터페이스를 정의해 `Print()` 메서드를 선언하고, 서로 관련 없는 두 클래스(`Invoice`, `Receipt`)가 이를 각각 구현하도록 만들어 보세요.
3. `virtual`/`override` 조합과 `new` 키워드를 각각 사용한 두 가지 버전의 코드를 작성하고, 기반 클래스 타입 변수를 통해 호출했을 때 결과가 어떻게 달라지는지 확인해 보세요.
4. 추상 클래스 `Vehicle`에 추상 메서드 `Move()`와 일반 메서드 `Stop()`을 정의하고, 이를 상속하는 `Car`, `Bicycle` 클래스를 작성해 보세요. `Vehicle`을 직접 `new`로 생성하려고 하면 어떤 오류가 발생하는지 확인해 보세요.
5. 본문의 `IShape` 예제에 `Pentagon`(오각형) 클래스를 추가로 구현하고, 기존 `foreach` 코드를 전혀 수정하지 않고도 리스트에 포함되어 정상적으로 동작하는지 확인해 보세요.
