프로그램이 항상 위에서 아래로 한 줄씩만 실행된다면 할 수 있는 일이 매우 제한적일 것입니다. 실제로 우리가 작성하는 대부분의 프로그램은 "이 조건이면 이렇게, 저 조건이면 저렇게" 동작을 갈라야 합니다. 이렇게 조건에 따라 실행 흐름을 선택하는 문장을 제어문(control statement)이라고 하며, 이 장에서는 C#의 조건 분기 도구들을 살펴봅니다.

## if 문의 기본 구조

가장 기본적인 조건문은 `if`입니다. 괄호 안의 조건식이 `true`이면 뒤따르는 블록이 실행됩니다.

```csharp
int score = 85;

if (score >= 60)
{
    Console.WriteLine("합격입니다.");
}
```

조건식은 반드시 `bool` 형이어야 합니다. C나 C++처럼 정수를 조건으로 바로 쓸 수 없다는 점이 C#의 특징입니다. 예를 들어 `if (score)`처럼 정수를 그대로 넣으면 컴파일 오류가 발생합니다. 이는 "0이 아니면 참"이라는 암묵적 규칙에 의존하다 발생하는 실수를 컴파일 단계에서 막아주는 안전장치입니다.

조건이 거짓일 때 다른 동작을 하려면 `else`를 붙입니다.

```csharp
int temperature = 5;

if (temperature > 0)
{
    Console.WriteLine("영상입니다.");
}
else
{
    Console.WriteLine("영하입니다.");
}
```

## else if로 여러 조건 잇기

세 개 이상의 경우를 나누고 싶다면 `else if`를 연쇄적으로 사용합니다. 위에서부터 순서대로 조건을 검사하다가 처음으로 `true`가 되는 블록만 실행되고 나머지는 무시됩니다.

```csharp
int score = 72;
string grade;

if (score >= 90)
{
    grade = "A";
}
else if (score >= 80)
{
    grade = "B";
}
else if (score >= 70)
{
    grade = "C";
}
else
{
    grade = "F";
}

Console.WriteLine($"학점: {grade}");
```

여기서 순서가 중요합니다. 만약 `score >= 70`을 가장 위에 두었다면 90점을 받은 학생도 곧바로 "C" 조건에 걸려 버립니다. 조건을 좁은 범위에서 넓은 범위로, 혹은 더 우선적인 경우부터 배치하는 습관을 들이는 것이 좋습니다.

블록이 한 줄뿐이면 중괄호를 생략할 수도 있지만, 이 책에서는 항상 중괄호를 쓰는 것을 권장합니다. 나중에 코드를 수정하며 문장을 하나 더 추가했는데 중괄호가 없어서 의도치 않게 `if` 블록 밖으로 빠져나가는 실수는 실무에서 실제로 자주 발생하는 버그이기 때문입니다.

## switch 문

여러 값 중 하나와 정확히 일치하는지를 비교하는 상황이라면 `if-else if`를 길게 나열하는 대신 `switch` 문이 더 읽기 좋습니다.

```csharp
int dayNumber = 3;
string dayName;

switch (dayNumber)
{
    case 1:
        dayName = "월요일";
        break;
    case 2:
        dayName = "화요일";
        break;
    case 3:
        dayName = "수요일";
        break;
    default:
        dayName = "알 수 없음";
        break;
}

Console.WriteLine(dayName);
```

각 `case` 블록 끝에는 `break`가 필요합니다. C#은 C와 달리 한 `case`에서 다음 `case`로 흐름이 자연스럽게 넘어가는 "fall-through"를 기본적으로 허용하지 않습니다. `break`나 `return`, `goto case` 같은 명시적인 종료 없이 다음 줄로 코드가 이어지면 컴파일 오류가 발생합니다. 이는 실수로 `break`를 빠뜨려 생기는 버그를 미리 막아주는 C#의 의도적인 설계입니다. 단, 여러 값이 같은 처리를 공유해야 한다면 아래처럼 `case`를 나란히 쓸 수 있습니다.

```csharp
switch (dayNumber)
{
    case 6:
    case 7:
        Console.WriteLine("주말입니다.");
        break;
    default:
        Console.WriteLine("평일입니다.");
        break;
}
```

## switch 표현식과 패턴 매칭 살짝 맛보기

C# 8.0부터는 값을 만들어내는 목적의 `switch`를 훨씬 간결하게 쓸 수 있는 switch 표현식(switch expression)이 도입되었습니다. 위에서 본 요일 예제를 switch 표현식으로 다시 쓰면 다음과 같습니다.

```csharp
string dayName = dayNumber switch
{
    1 => "월요일",
    2 => "화요일",
    3 => "수요일",
    4 => "목요일",
    5 => "금요일",
    6 => "토요일",
    7 => "일요일",
    _ => "알 수 없음"
};
```

기존 `switch` 문과 비교하면 몇 가지 차이가 눈에 띕니다. 비교할 값을 `switch` 뒤가 아니라 앞에 쓰고, `case`와 `break` 대신 `=>`로 결과 값을 바로 연결하며, `default` 대신 밑줄 `_`을 사용합니다. 각 분기가 하나의 식(expression)이므로 전체 `switch` 표현식 자체가 하나의 값으로 평가되어 변수에 곧바로 대입할 수 있습니다.

switch 표현식은 단순한 값 비교뿐 아니라 패턴 매칭(pattern matching)과 결합하면 더욱 강력해집니다. 예를 들어 값의 범위를 조건으로 걸 수도 있습니다.

```csharp
string grade = score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 70 => "C",
    _ => "F"
};
```

패턴 매칭은 형(type)에 따라 분기하는 데에도 쓰입니다. 지금은 다음과 같은 형태가 있다는 것만 눈에 익혀두고, 클래스와 상속을 다루는 9장과 10장 이후 다시 자세히 설명하겠습니다.

```csharp
object value = 123;

string description = value switch
{
    int n => $"정수입니다: {n}",
    string s => $"문자열입니다: {s}",
    null => "값이 없습니다.",
    _ => "알 수 없는 형입니다."
};
```

패턴 매칭은 C#의 최신 기능 중에서도 자주 쓰이는 축에 속하므로, 지금 단계에서는 "값 하나와 정확히 같은지"만 비교하던 `switch`가 "이런 모양이나 조건을 만족하는지"까지 검사할 수 있게 확장되었다는 정도로 이해하면 충분합니다.

## 삼항 연산자

조건에 따라 두 값 중 하나를 고르기만 하는 아주 단순한 상황이라면, `if-else` 전체를 쓰는 대신 삼항 연산자(conditional operator) `?:`로 한 줄에 표현할 수 있습니다.

```csharp
int age = 17;
string status = age >= 18 ? "성인" : "미성년자";
```

`조건 ? 참일때값 : 거짓일때값` 형태로, `if-else`와 완전히 같은 의미이지만 값을 만들어 바로 대입하는 상황에 훨씬 간결합니다. 다만 삼항 연산자를 중첩해서 쓰면 가독성이 급격히 떨어지므로 주의해야 합니다.

```csharp
// 읽기 어려운 예 - 지양할 것
string grade = score >= 90 ? "A" : score >= 80 ? "B" : score >= 70 ? "C" : "F";
```

위 코드는 동작은 하지만 한눈에 의미를 파악하기 어렵습니다. 분기가 세 개 이상으로 늘어난다면 앞서 본 switch 표현식이나 `if-else if` 체인을 쓰는 것이 훨씬 낫습니다. 삼항 연산자는 "조건 하나, 선택 두 가지"처럼 정말 단순한 경우에만 사용하는 것을 원칙으로 삼길 권합니다.

## 중첩 조건문과 가독성

조건문 안에 또 조건문을 넣는 중첩(nesting)은 로직을 표현하는 데 필요할 때가 많지만, 너무 깊어지면 코드를 읽기가 매우 힘들어집니다.

```csharp
int age = 25;
bool hasLicense = true;
bool hasInsurance = true;

if (age >= 18)
{
    if (hasLicense)
    {
        if (hasInsurance)
        {
            Console.WriteLine("운전이 가능합니다.");
        }
        else
        {
            Console.WriteLine("보험 가입이 필요합니다.");
        }
    }
    else
    {
        Console.WriteLine("운전면허가 필요합니다.");
    }
}
else
{
    Console.WriteLine("성인만 가능합니다.");
}
```

들여쓰기가 계단처럼 깊어지는 이런 형태를 흔히 "화살표 코드(arrow code)"라고 부르는데, 조건이 하나만 추가되어도 전체 구조를 다시 파악해야 하는 부담이 생깁니다. 이럴 때는 조건을 만족하지 못하는 경우를 먼저 걸러내고 함수를 일찍 끝내는 방식, 즉 조기 반환(early return) 스타일로 바꾸면 중첩을 크게 줄일 수 있습니다.

```csharp
void CheckDriving(int age, bool hasLicense, bool hasInsurance)
{
    if (age < 18)
    {
        Console.WriteLine("성인만 가능합니다.");
        return;
    }

    if (!hasLicense)
    {
        Console.WriteLine("운전면허가 필요합니다.");
        return;
    }

    if (!hasInsurance)
    {
        Console.WriteLine("보험 가입이 필요합니다.");
        return;
    }

    Console.WriteLine("운전이 가능합니다.");
}
```

각 조건이 독립적인 문단처럼 나열되어 들여쓰기 깊이가 일정하게 유지되고, "예외적인 상황을 먼저 쳐내고 정상적인 경우를 마지막에 남긴다"는 흐름이 명확히 드러납니다. 조기 반환은 8장 함수(메서드)에서 함수를 본격적으로 다룰 때 다시 짚어보겠습니다. 지금은 조건문이 중첩될수록 가독성이 떨어진다는 사실과, 조건을 먼저 걸러내는 것만으로도 코드가 훨씬 단순해질 수 있다는 감각을 익히는 것이 목표입니다.

## 요약

- `if`, `else if`, `else`는 조건에 따라 실행 경로를 나누는 가장 기본적인 도구이며, C#에서는 조건식이 반드시 `bool` 형이어야 합니다.
- `switch` 문은 하나의 값과 여러 후보를 비교할 때 유용하며, 각 `case`는 명시적인 종료(`break` 등)가 필요합니다.
- switch 표현식은 값을 만들어내는 목적의 `switch`를 간결하게 표현하며, 범위나 형을 검사하는 패턴 매칭과 함께 사용할 수 있습니다.
- 삼항 연산자 `?:`는 단순한 두 값 중 하나를 고르는 상황에만 제한적으로 사용하는 것이 좋습니다.
- 조건문의 중첩이 깊어지면 가독성이 떨어지므로, 조기 반환 등을 활용해 구조를 평탄하게 유지하는 습관이 중요합니다.
