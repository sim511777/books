같은 작업을 열 번, 백 번, 혹은 데이터가 끝날 때까지 반복해야 하는 상황은 프로그래밍에서 매우 흔합니다. 5장에서 배운 제어문이 "어느 길로 갈지"를 결정하는 도구였다면, 이 장에서 다루는 반복문(loop)은 "같은 길을 몇 번이나 다시 갈지"를 결정하는 도구입니다. C#은 `while`, `do-while`, `for`, `foreach`라는 네 가지 반복문을 제공하며, 각각 어울리는 상황이 조금씩 다릅니다.

## while 문

`while`은 조건이 `true`인 동안 블록을 계속 실행합니다. 조건을 먼저 검사하고 나서 블록을 실행하는 구조이므로, 처음부터 조건이 거짓이면 블록은 단 한 번도 실행되지 않습니다.

```csharp
int count = 1;

while (count <= 5)
{
    Console.WriteLine($"카운트: {count}");
    count++;
}
```

`while`은 반복 횟수를 미리 알 수 없고, 어떤 조건이 만족되는 동안만 계속해야 하는 상황에 적합합니다. 예를 들어 사용자가 올바른 입력을 할 때까지 계속 물어보는 경우를 생각해 볼 수 있습니다.

```csharp
string? input;
int number;

do
{
    Console.Write("1부터 10 사이의 숫자를 입력하세요: ");
    input = Console.ReadLine();
}
while (!int.TryParse(input, out number) || number < 1 || number > 10);

Console.WriteLine($"입력하신 숫자: {number}");
```

여기서 `while` 문에 조건을 반드시 갱신하는 코드가 들어 있어야 한다는 점을 꼭 기억해야 합니다. 만약 `count++`처럼 조건에 영향을 주는 변수를 변경하는 코드를 빠뜨리면 조건이 영원히 `true`로 남아 무한 루프에 빠지게 됩니다. 무한 루프는 프로그램이 응답 없이 멈춘 것처럼 보이는 대표적인 원인이므로, `while` 문을 작성할 때는 항상 "이 조건이 언젠가 거짓이 될 수 있는가"를 스스로 점검하는 습관이 필요합니다.

## do-while 문

`do-while`은 `while`과 거의 같지만, 조건을 검사하는 시점이 다릅니다. 블록을 먼저 한 번 실행한 다음에 조건을 검사하므로, 조건이 처음부터 거짓이더라도 블록은 최소한 한 번은 실행됩니다.

```csharp
int attempts = 0;

do
{
    attempts++;
    Console.WriteLine($"{attempts}번째 시도");
}
while (attempts < 3);
```

바로 앞서 본 숫자 입력 예제가 `do-while`을 쓴 이유도 여기에 있습니다. 사용자에게 값을 입력받는 동작 자체는 조건을 검사하기 전에 반드시 한 번 실행되어야 하기 때문입니다. "일단 한 번은 실행하고, 그 결과를 보고 계속할지 결정한다"는 상황이라면 `while`보다 `do-while`이 자연스럽습니다.

## for 문

반복할 횟수를 미리 알고 있거나, 특정 값에서 시작해 일정한 규칙으로 증가·감소시키며 반복할 때는 `for` 문이 가장 명확합니다. `for` 문은 초기화, 조건, 증감식 세 부분을 한 줄에 모아 씁니다.

```csharp
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine($"i의 값: {i}");
}
```

괄호 안의 세 부분은 각각 `초기화; 조건; 증감식` 순서로, 반복이 시작되기 전 딱 한 번 초기화가 실행되고, 매 반복마다 조건을 검사한 뒤, 블록 실행이 끝나면 증감식이 수행됩니다. `count`나 `attempts` 같은 변수를 `while` 문 밖에서 선언하고 안에서 갱신했던 앞의 예제들과 비교하면, `for` 문은 반복에 필요한 변수의 선언·조건·갱신을 한곳에 모아두어 코드를 훨씬 압축적으로 표현한다는 차이가 보입니다.

`for` 문은 거꾸로 반복하거나 두 칸씩 건너뛰는 등 증감식을 자유롭게 바꿀 수 있습니다.

```csharp
// 10부터 1까지 거꾸로 출력
for (int i = 10; i >= 1; i--)
{
    Console.WriteLine(i);
}

// 0부터 20까지 짝수만 출력
for (int i = 0; i <= 20; i += 2)
{
    Console.WriteLine(i);
}
```

## foreach 문 - 컬렉션 순회에 특화된 반복문

C#에는 `for`, `while`과는 성격이 다른 `foreach`라는 반복문이 있습니다. 배열이나 리스트처럼 여러 값의 모음(컬렉션)을 다룰 때, `foreach`는 인덱스를 신경 쓰지 않고 "이 모음에 들어 있는 항목 하나하나에 대해"라는 의도를 그대로 코드로 옮길 수 있게 해 줍니다.

```csharp
string[] fruits = { "사과", "바나나", "포도" };

foreach (string fruit in fruits)
{
    Console.WriteLine(fruit);
}
```

같은 일을 `for` 문으로 하면 다음과 같습니다.

```csharp
for (int i = 0; i < fruits.Length; i++)
{
    Console.WriteLine(fruits[i]);
}
```

두 코드는 결과가 같지만 `foreach` 쪽이 훨씬 단순합니다. `for` 문에서는 `i`라는 인덱스 변수를 직접 관리해야 하고, `i < fruits.Length`처럼 범위를 벗어나지 않는지도 스스로 챙겨야 합니다. 인덱스 계산을 한 칸 잘못하면 배열 범위를 벗어나는 오류(`IndexOutOfRangeException`)로 이어지기도 합니다. `foreach`는 이런 세부 사항을 모두 대신 처리해 주므로, "몇 번째 항목인지"가 중요하지 않고 "각 항목 자체"만 필요하다면 `foreach`를 우선적으로 선택하는 것이 C#다운 방식입니다. 배열과 리스트 같은 컬렉션 자체는 7장 배열과 컬렉션 기초, 14장 컬렉션과 LINQ에서 더 깊이 다루지만, `foreach`의 편리함은 지금부터 충분히 체감할 수 있습니다.

다만 `foreach`에는 중요한 제약이 있습니다. 반복 변수(`fruit`)는 읽기 전용이라서 반복 중에 컬렉션의 내용을 직접 수정할 수 없습니다.

```csharp
List<int> numbers = new List<int> { 1, 2, 3 };

foreach (int number in numbers)
{
    // numbers.Add(number * 2); // 컬렉션을 순회하며 수정하면 예외가 발생합니다.
}
```

컬렉션의 내용을 바꿔야 한다면 인덱스를 다루는 `for` 문을 쓰거나, 별도의 새 리스트에 결과를 담는 방식을 사용해야 합니다.

## break와 continue

반복문 안에서 흐름을 세밀하게 제어하고 싶을 때는 `break`와 `continue`를 사용합니다. `break`는 반복문을 즉시 완전히 빠져나가고, `continue`는 현재 반복만 건너뛰고 다음 반복으로 넘어갑니다.

```csharp
// break: 7을 찾으면 반복을 즉시 종료
for (int i = 1; i <= 10; i++)
{
    if (i == 7)
    {
        Console.WriteLine("7을 찾았습니다. 탐색을 멈춥니다.");
        break;
    }

    Console.WriteLine($"확인 중: {i}");
}
```

```csharp
// continue: 짝수는 건너뛰고 홀수만 출력
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        continue;
    }

    Console.WriteLine(i);
}
```

`break`는 "더 이상 반복할 필요가 없는 상황"에서 불필요한 반복을 줄여 성능을 아끼는 데도 유용합니다. 예를 들어 리스트 안에서 특정 조건을 만족하는 항목을 찾는 즉시 멈추면, 나머지 항목을 모두 검사하는 낭비를 막을 수 있습니다.

## 중첩 반복문

반복문 안에 또 다른 반복문을 넣는 중첩 반복문은 2차원 데이터를 다루거나 모든 조합을 검사해야 할 때 자주 등장합니다. 대표적인 예로 구구단 출력을 들 수 있습니다.

```csharp
for (int i = 2; i <= 9; i++)
{
    for (int j = 1; j <= 9; j++)
    {
        Console.Write($"{i} x {j} = {i * j}\t");
    }

    Console.WriteLine();
}
```

바깥쪽 `for` 문이 한 바퀴 도는 동안 안쪽 `for` 문은 처음부터 끝까지 여러 번 반복됩니다. 위 코드에서는 `i`가 2부터 9까지 총 8번 바뀌고, `i`가 한 번 바뀔 때마다 `j`는 1부터 9까지 9번 반복되므로 전체적으로는 `Console.Write`가 8 × 9 = 72번 호출됩니다. 중첩이 늘어날수록 전체 반복 횟수는 곱셈으로 늘어난다는 점을 기억해 두면, 나중에 반복문의 실행 비용을 가늠하는 데 도움이 됩니다.

중첩 반복문에서 `break`를 사용할 때는 주의가 필요합니다. `break`는 자신이 속한 가장 안쪽 반복문 하나만 종료시키기 때문입니다.

```csharp
for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        if (j == 2)
        {
            break; // 안쪽 for 문만 종료되고, 바깥쪽 for 문은 계속됩니다.
        }

        Console.WriteLine($"i={i}, j={j}");
    }
}
```

바깥쪽 반복문까지 한꺼번에 종료하고 싶다면 상태를 나타내는 `bool` 변수를 두어 바깥쪽에서도 검사하게 만들거나, `goto` 문으로 레이블까지 한 번에 빠져나가는 방법을 쓸 수 있습니다. 다만 `goto`는 코드 흐름을 예측하기 어렵게 만들어 남용하면 가독성을 해치므로, 대부분의 경우에는 종료 여부를 담는 변수를 사용하는 쪽을 권장합니다.

```csharp
bool found = false;

for (int i = 1; i <= 3 && !found; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        if (i == 2 && j == 2)
        {
            found = true;
            break;
        }
    }
}
```

## 요약

- `while`은 조건이 `true`인 동안 반복하며, 조건을 먼저 검사하므로 처음부터 거짓이면 한 번도 실행되지 않습니다.
- `do-while`은 블록을 먼저 실행한 뒤 조건을 검사하므로 최소 한 번은 실행이 보장됩니다.
- `for` 문은 초기화, 조건, 증감식을 한곳에 모아 반복 횟수가 명확한 상황에 적합합니다.
- `foreach`는 컬렉션의 각 항목을 순회하는 데 특화된 C#의 반복문으로, 인덱스 관리를 대신해 주지만 반복 중 컬렉션을 직접 수정할 수는 없습니다.
- `break`는 반복문을 즉시 종료하고, `continue`는 현재 반복만 건너뜁니다. 중첩 반복문에서 `break`는 가장 안쪽 반복문만 종료시킨다는 점에 주의해야 합니다.
