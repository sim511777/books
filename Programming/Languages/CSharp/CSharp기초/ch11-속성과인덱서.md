## 들어가며

9장에서 클래스를 배우면서 필드(field)는 되도록 `private`으로 감추고, 외부에는 메서드를 통해서만 접근을 허용하는 것이 캡슐화의 기본이라고 이야기했습니다. 그런데 이 방식에는 한 가지 불편함이 있습니다. 값을 하나 읽거나 바꾸는 것뿐인데도 `GetName()`, `SetName(string value)`처럼 메서드를 두 개씩 만들어야 하고, 사용하는 쪽 코드도 `person.SetAge(20)`처럼 다소 어색해집니다.

C#의 속성(property)은 이 문제를 해결하기 위한 문법입니다. 겉으로는 필드처럼 `person.Age = 20;`, `int a = person.Age;`처럼 쓰지만, 실제로는 내부에서 코드가 실행되는 메서드입니다. 즉 속성은 "필드처럼 보이는 메서드 한 쌍"이라고 생각하면 됩니다.

## 속성의 기본 문법: get과 set

가장 기본적인 형태는 뒷단에 필드를 하나 두고, 그 필드를 읽고 쓰는 `get`/`set` 접근자를 정의하는 것입니다.

```csharp
public class Person
{
    private string _name;   // 실제 값을 저장하는 필드
    private int _age;

    public string Name
    {
        get { return _name; }
        set { _name = value; }   // value는 대입되는 값을 가리키는 예약어
    }

    public int Age
    {
        get { return _age; }
        set
        {
            if (value < 0)
            {
                throw new ArgumentOutOfRangeException(nameof(value), "나이는 음수일 수 없습니다.");
            }
            _age = value;
        }
    }
}
```

여기서 핵심은 `set` 접근자 안의 `value`입니다. `person.Age = 20;`이라고 쓰면 `value`에 20이 담긴 채로 `set` 블록이 실행됩니다. `Age` 속성처럼 `set` 안에서 유효성 검사를 넣을 수 있다는 점이 바로 속성이 단순한 필드보다 나은 이유입니다. 필드를 그대로 공개했다면 `person.Age = -5;`처럼 잘못된 값이 아무 검증 없이 들어갔겠지만, 속성을 쓰면 그 진입점을 코드로 통제할 수 있습니다.

사용하는 쪽은 메서드 호출이라는 느낌 없이 자연스럽게 값을 다룹니다.

```csharp
var p = new Person();
p.Name = "이서준";
p.Age = 20;
Console.WriteLine($"{p.Name}, {p.Age}세");
```

## 자동 구현 속성 (auto-property)

`Name`처럼 별다른 로직 없이 값을 그대로 저장하고 그대로 돌려주기만 하는 속성이라면, 뒷단 필드를 직접 선언하는 것조차 번거로운 반복입니다. C#은 이런 경우를 위해 자동 구현 속성을 제공합니다.

```csharp
public class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}
```

이렇게만 써도 컴파일러가 눈에 보이지 않는 필드를 알아서 만들어 줍니다. `Person` 클래스의 `Name` 속성도 검증이 필요 없다면 다음처럼 한 줄로 줄일 수 있습니다.

```csharp
public string Name { get; set; }
```

실무에서 작성하는 속성의 대다수는 이런 자동 구현 속성입니다. 검증이나 부가 로직이 필요해지는 순간에만 9장 방식처럼 필드를 직접 꺼내 쓰면 됩니다.

## 읽기 전용 속성

`set`을 아예 생략하면 그 속성은 외부에서 값을 바꿀 수 없는 읽기 전용 속성이 됩니다. 생성자에서만 값을 정해주고, 이후에는 절대 바뀌지 않아야 하는 값에 적합합니다.

```csharp
public class Circle
{
    public double Radius { get; }   // set이 없으므로 읽기 전용

    public Circle(double radius)
    {
        Radius = radius;   // 생성자 안에서는 대입이 허용된다
    }

    public double GetArea() => Math.PI * Radius * Radius;
}
```

읽기 전용 속성은 생성자 내부에서만 값을 넣을 수 있고, 객체가 만들어진 뒤에는 `circle.Radius = 10;`처럼 바꾸려고 하면 컴파일 오류가 발생합니다. "한 번 정해지면 바뀌지 않는 값"을 표현하고 싶을 때 유용합니다.

## init 접근자

`set` 대신 `init`을 쓰면, 객체를 생성하는 시점(객체 초기화 구문을 포함해서)에만 값을 설정할 수 있고 그 이후에는 읽기 전용 속성과 마찬가지로 값을 바꿀 수 없습니다.

```csharp
public class Employee
{
    public string Name { get; init; }
    public int EmployeeId { get; init; }
}

var e = new Employee { Name = "박지현", EmployeeId = 1001 };
// e.Name = "다른이름";  // 오류: init 접근자는 생성 시점 이후 대입을 허용하지 않는다
```

읽기 전용 속성은 반드시 생성자 코드 안에서 값을 정해야 하지만, `init`은 객체 초기화 구문(`new Employee { ... }`)처럼 좀 더 유연한 방식으로 값을 채울 수 있다는 점이 다릅니다. "생성 시점에만 자유롭게, 그 이후로는 불변"이라는 중간 지점을 원할 때 선택하는 문법이라고 기억해 두면 됩니다.

## 인덱서: 객체를 배열처럼 다루기

속성이 `객체.속성이름` 형태로 값 하나에 접근하는 문법이라면, 인덱서(indexer)는 `객체[인덱스]` 형태로 값에 접근하게 해주는 문법입니다. 클래스 내부에 배열이나 리스트를 감춰두고, 마치 그 클래스 자체가 배열인 것처럼 다루고 싶을 때 사용합니다.

다음은 재생목록을 표현하는 `Playlist` 클래스입니다. 내부적으로는 `List<string>`을 갖고 있지만, 바깥에서는 `playlist[0]`처럼 인덱스로 곧바로 접근할 수 있습니다.

```csharp
public class Playlist
{
    private readonly List<string> _tracks = new List<string>();

    public int Count => _tracks.Count;

    public void Add(string trackName)
    {
        _tracks.Add(trackName);
    }

    // 인덱서 선언: this[인덱스] 형태
    public string this[int index]
    {
        get { return _tracks[index]; }
        set { _tracks[index] = value; }
    }
}
```

사용하는 쪽 코드는 배열이나 `List<T>`를 쓸 때와 거의 구별되지 않습니다.

```csharp
var playlist = new Playlist();
playlist.Add("첫 번째 곡");
playlist.Add("두 번째 곡");

Console.WriteLine(playlist[0]);   // 첫 번째 곡
playlist[1] = "바뀐 두 번째 곡";
Console.WriteLine($"총 {playlist.Count}곡");
```

인덱서의 매개변수는 꼭 정수일 필요는 없습니다. 예를 들어 문자열을 키로 받는 인덱서를 만들면 딕셔너리처럼 쓸 수도 있고, 매개변수를 두 개 받으면 표(2차원 배열) 형태의 접근도 표현할 수 있습니다.

```csharp
public class Grid
{
    private readonly int[,] _cells = new int[5, 5];

    public int this[int row, int col]
    {
        get { return _cells[row, col]; }
        set { _cells[row, col] = value; }
    }
}

var grid = new Grid();
grid[1, 2] = 9;
Console.WriteLine(grid[1, 2]);   // 9
```

`this[int row, int col]`처럼 매개변수를 여러 개 나열하면, 사용하는 쪽에서 `grid[1, 2]`라고 쓴 것이 그대로 두 매개변수로 전달됩니다. 7장에서 다룬 다차원 배열을 클래스 안에 숨기고, 바깥으로는 더 단순한 표현만 노출하는 좋은 예입니다.

## 속성과 인덱서를 함께 쓰기

실제 클래스에서는 속성과 인덱서가 자연스럽게 함께 등장합니다. 위의 `Playlist`에서 `Count` 속성과 `this[int index]` 인덱서가 함께 있는 것처럼, 인덱서로 개별 항목에 접근하는 기능과 속성으로 전체 상태를 요약해서 보여주는 기능은 서로 다른 역할을 맡습니다. 클래스를 설계할 때 "바깥에서 이 객체를 어떻게 다루게 하고 싶은가"를 먼저 생각하면, 어떤 멤버를 속성으로, 어떤 멤버를 인덱서로 만들지 자연스럽게 결정됩니다.

## 요약

- 속성은 필드처럼 보이지만 실제로는 `get`/`set` 코드가 실행되는 멤버로, 캡슐화(9장)를 유지하면서도 필드처럼 편하게 쓸 수 있게 해줍니다.
- 자동 구현 속성(`{ get; set; }`)은 별다른 로직이 없는 속성을 짧게 표현하는 문법이며, 실무에서 가장 흔하게 쓰입니다.
- `set`을 생략하면 읽기 전용 속성이 되어, 생성자에서만 값을 정할 수 있습니다.
- `init` 접근자는 객체 생성 시점에만 값을 채울 수 있게 하여, 생성 후에는 불변인 객체를 만들 때 사용합니다.
- 인덱서는 `this[인덱스]` 문법으로 클래스의 인스턴스를 배열처럼 다루게 해주며, 매개변수의 개수나 타입은 필요에 따라 자유롭게 정할 수 있습니다.
