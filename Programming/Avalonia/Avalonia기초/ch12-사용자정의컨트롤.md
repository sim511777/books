# 12장. 사용자 정의 컨트롤(UserControl)

[◀ 이전: 11장. 컨트롤 템플릿과 데이터 템플릿](ch11-컨트롤템플릿과데이터템플릿.md) | [📖 목차](00-목차.md) | [다음: 13장. 커스텀 컨트롤과 속성 시스템 ▶](ch13-커스텀컨트롤과속성시스템.md)


지금까지 우리는 `Button`, `TextBox`, `ListBox`처럼 Avalonia가 이미 만들어 제공하는 컨트롤을 조합해서 화면을 만들어왔습니다. 그런데 실제 앱을 만들다 보면 같은 조합의 UI가 여러 화면에서 반복해서 등장하는 경우가 매우 흔합니다. "라벨과 값을 나란히 보여주는 한 줄", "제목과 설명이 있는 카드", "아이콘과 텍스트가 있는 메뉴 항목" 같은 것들이죠.

이런 반복되는 UI 조각을 매번 XAML로 새로 쓰는 대신, 하나의 재사용 가능한 컴포넌트로 만들어두고 필요한 곳마다 가져다 쓸 수 있다면 훨씬 편리할 것입니다. Avalonia에서 이것을 가장 쉽게 구현하는 방법이 바로 **UserControl**입니다.

## 12.1 UserControl이란 무엇인가

`UserControl`은 여러 개의 기존 컨트롤을 조합해서 하나의 재사용 가능한 화면 조각으로 묶는 가장 기본적인 방법입니다. 지금까지 작성해온 `Window`의 XAML 구조를 떠올려보면 이해가 빠릅니다. `Window`도 결국 그 안에 `Grid`, `StackPanel`, `TextBlock` 같은 요소들을 배치해서 하나의 화면을 구성하는 컨테이너입니다. `UserControl`은 이것과 거의 같은 방식으로 동작하지만, 창(Window) 전체가 아니라 **화면의 일부**로 사용하기 위해 만들어진 것이라는 점이 다릅니다.

`UserControl`로 만든 컴포넌트는 마치 `Button`이나 `TextBox`를 쓰듯이 다른 XAML 파일 안에 태그 하나로 가져다 쓸 수 있습니다. 내부적으로 무엇을 조합해서 만들었는지는 그것을 사용하는 쪽에서는 몰라도 됩니다. 이런 특성 덕분에 UI 코드의 중복을 줄이고, 같은 컴포넌트를 여러 화면에서 일관되게 유지보수할 수 있습니다.

11장에서 살펴봤듯이 `UserControl`은 내부 레이아웃을 XAML에 고정된 형태로 직접 작성하는 방식입니다. `Button` 같은 `TemplatedControl`처럼 겉모습을 통째로 갈아 끼우도록 설계된 것이 아니라, "이 조합은 항상 이런 모습이다"라고 못박아두는 용도에 적합합니다. 화면 한 귀퉁이에 들어갈 로그인 폼, 통계 카드, 목록의 한 행처럼 모양이 어느 정도 고정된 UI 조각을 만들 때 가장 먼저 떠올려야 할 도구입니다.

## 12.2 새 UserControl 만들기

2장에서 프로젝트 구조를 살펴볼 때 확인했듯이, Avalonia 프로젝트에서 화면 하나는 `.axaml` 파일과 그 코드 비하인드인 `.axaml.cs` 파일 한 쌍으로 이루어집니다. `UserControl`도 정확히 같은 방식으로 만듭니다.

프로젝트에 `Controls`라는 폴더를 만들고, 그 안에 `LabeledField.axaml`과 `LabeledField.axaml.cs` 두 파일을 추가한다고 가정해봅시다. 라벨 하나와 값 하나를 가로로 나란히 보여주는 간단한 컴포넌트를 만들 것입니다.

**LabeledField.axaml**

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="AvaloniaSample.Controls.LabeledField">
    <StackPanel Orientation="Horizontal" Spacing="8">
        <TextBlock Text="이름:" FontWeight="Bold" Width="80"/>
        <TextBlock Text="값"/>
    </StackPanel>
</UserControl>
```

**LabeledField.axaml.cs**

```csharp
using Avalonia.Controls;

namespace AvaloniaSample.Controls;

public partial class LabeledField : UserControl
{
    public LabeledField()
    {
        InitializeComponent();
    }
}
```

이 구조는 2장에서 살펴본 `MainWindow.axaml` / `MainWindow.axaml.cs`와 완전히 동일한 패턴입니다. `x:Class` 속성이 XAML과 코드 비하인드 클래스를 연결해주고, 생성자에서 `InitializeComponent()`를 호출해 XAML에 정의된 요소들을 실제 객체로 만들어 연결합니다. 다른 점은 루트 태그가 `<Window>`가 아니라 `<UserControl>`이라는 것뿐입니다.

지금 이 상태로는 `"이름:"`과 `"값"`이라는 글자가 고정되어 있어서 재사용할 수 없는 컴포넌트입니다. 이걸 바로잡는 것이 다음 절의 목표입니다.

### 다른 화면에서 가져다 쓰기

일단 고정된 형태로라도 어떻게 가져다 쓰는지 먼저 확인해봅시다. `MainWindow.axaml`에서 `LabeledField`를 사용하려면, 그 컴포넌트가 정의된 네임스페이스를 XML 네임스페이스로 선언해야 합니다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:controls="using:AvaloniaSample.Controls"
        x:Class="AvaloniaSample.MainWindow"
        Title="사용자 정의 컨트롤 예제">
    <StackPanel Margin="20" Spacing="8">
        <controls:LabeledField/>
    </StackPanel>
</Window>
```

`xmlns:controls="using:AvaloniaSample.Controls"`는 3장에서 살펴본 XAML 네임스페이스 선언과 같은 방식입니다. `using:` 뒤에 C# 네임스페이스를 적으면, 그 네임스페이스 안의 클래스를 `controls:` 접두사로 XAML에서 사용할 수 있습니다. 이제 `<controls:LabeledField/>`라고 쓰기만 하면 앞서 만든 `UserControl`이 그 자리에 그대로 삽입됩니다.

## 12.3 UserControl에 자체 속성 추가하기

지금 만든 `LabeledField`는 라벨과 값이 항상 `"이름:"`과 `"값"`으로 고정되어 있어서 쓸모가 없습니다. 사용하는 쪽에서 라벨과 값을 원하는 대로 지정할 수 있어야 진짜 재사용 가능한 컴포넌트가 됩니다.

`Button`의 `Content`, `TextBlock`의 `Text`처럼 외부에서 값을 전달받는 속성을 우리가 만든 `UserControl`에도 추가할 수 있습니다. Avalonia에서 이런 속성은 일반 C# 속성이 아니라 **`AvaloniaProperty`**라는 특별한 방식으로 등록합니다. 이렇게 등록된 속성이라야 XAML에서 값을 지정할 수 있고, 데이터 바인딩의 대상이 될 수 있고, 스타일의 `Setter`로 값을 줄 수 있습니다. 이 속성 시스템은 13장 "커스텀 컨트롤과 속성 시스템"에서 `StyledProperty`와 `DirectProperty`의 차이, 값 우선순위, 검증 로직까지 훨씬 자세히 다룰 예정입니다. 여기서는 가장 흔히 쓰이는 형태인 `StyledProperty`를 등록해서 당장 필요한 기능을 완성하는 데 집중합니다.

`LabeledField`에 `Label`과 `Value`라는 두 개의 속성을 추가해보겠습니다.

**LabeledField.axaml.cs**

```csharp
using Avalonia;
using Avalonia.Controls;

namespace AvaloniaSample.Controls;

public partial class LabeledField : UserControl
{
    public static readonly StyledProperty<string> LabelProperty =
        AvaloniaProperty.Register<LabeledField, string>(nameof(Label), defaultValue: string.Empty);

    public static readonly StyledProperty<string?> ValueProperty =
        AvaloniaProperty.Register<LabeledField, string?>(nameof(Value));

    public string Label
    {
        get => GetValue(LabelProperty);
        set => SetValue(LabelProperty, value);
    }

    public string? Value
    {
        get => GetValue(ValueProperty);
        set => SetValue(ValueProperty, value);
    }

    public LabeledField()
    {
        InitializeComponent();
    }
}
```

한 줄씩 살펴보겠습니다.

- `AvaloniaProperty.Register<LabeledField, string>(nameof(Label), ...)`는 `LabelProperty`라는 이름의 정적 필드에 새로운 속성을 등록합니다. 첫 번째 형식 인자(`LabeledField`)는 이 속성을 소유하는 클래스, 두 번째 형식 인자(`string`)는 속성 값의 형식입니다.
- `defaultValue: string.Empty`는 아무 값도 지정하지 않았을 때 사용할 기본값입니다.
- `public string Label { get; set; }`은 우리가 실제로 코드나 XAML에서 사용하는 일반적인 C# 속성처럼 보이지만, 내부적으로는 값을 직접 저장하지 않고 `GetValue`/`SetValue`를 통해 앞서 등록한 `LabelProperty`에 접근합니다. 이 패턴을 **CLR 래퍼(wrapper) 속성**이라고 부릅니다.

이렇게 등록된 속성은 일반 C# 자동 속성과 겉보기엔 비슷해 보이지만, 값이 바뀔 때 자동으로 화면을 다시 그리게 하거나, 스타일에서 값을 설정하거나, 데이터 바인딩의 대상이 되는 등 훨씬 많은 일을 할 수 있습니다. 이 차이와 원리는 13장에서 이어서 설명합니다.

### XAML에서 내부 요소와 연결하기

속성을 등록하는 것만으로는 부족합니다. `Label`과 `Value` 속성 값이 바뀔 때 실제로 화면의 `TextBlock`에 반영되도록 XAML을 연결해주어야 합니다. `UserControl` 자기 자신에 이름을 붙이고, 그 이름을 이용해 내부 요소를 바인딩하는 방법을 사용합니다.

**LabeledField.axaml**

```xml
<UserControl xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="AvaloniaSample.Controls.LabeledField"
             x:Name="Root">
    <StackPanel Orientation="Horizontal" Spacing="8">
        <TextBlock Text="{Binding Label, ElementName=Root}"
                   FontWeight="Bold"
                   Width="80"/>
        <TextBlock Text="{Binding Value, ElementName=Root}"/>
    </StackPanel>
</UserControl>
```

루트 `UserControl`에 `x:Name="Root"`를 지정한 뒤, 내부의 `TextBlock`에서 `{Binding Label, ElementName=Root}`처럼 `ElementName` 바인딩을 사용했습니다. 이 바인딩은 "이름이 `Root`인 요소의 `Label` 속성 값을 가져와라"는 뜻입니다. 즉 `UserControl` 자기 자신을 데이터 소스로 삼아 내부 요소에 값을 흘려보내는 것입니다. `ElementName` 바인딩은 7장에서 살펴본 바인딩 문법 중 하나로, 뷰모델이 아니라 같은 화면 안의 다른 요소를 데이터 소스로 지정할 때 사용합니다.

### 실제로 사용해보기

이제 `LabeledField`는 완전한 재사용 컴포넌트가 되었습니다. `MainWindow.axaml`에서 다음과 같이 여러 개를 배치해 사용할 수 있습니다.

```xml
<StackPanel Margin="20" Spacing="6">
    <controls:LabeledField Label="이름" Value="김민준"/>
    <controls:LabeledField Label="이메일" Value="minjun@example.com"/>
    <controls:LabeledField Label="가입일" Value="2024-03-15"/>
</StackPanel>
```

`Label`과 `Value`는 우리가 등록한 `AvaloniaProperty`이기 때문에, 리터럴 값을 직접 쓰는 것 말고도 데이터 바인딩의 대상이 될 수 있습니다. 8장에서 배운 MVVM 패턴을 적용한다면 이렇게 뷰모델의 속성과 직접 연결할 수도 있습니다.

```xml
<controls:LabeledField Label="이름" Value="{Binding UserName}"/>
<controls:LabeledField Label="이메일" Value="{Binding Email}"/>
```

`Button.Content`나 `TextBlock.Text`에 바인딩을 걸 때와 완전히 동일한 문법입니다. 우리가 직접 만든 `UserControl`이 Avalonia가 기본 제공하는 컨트롤과 똑같은 방식으로 동작한다는 점이 `AvaloniaProperty` 시스템의 핵심적인 장점입니다.

## 12.4 조금 더 다듬기 — 값이 없을 때 처리하기

실전에서는 `Value`가 비어 있을 때 아무것도 표시하지 않거나 대체 문구를 보여주고 싶은 경우가 많습니다. `TextBlock.Text`에 바로 바인딩하는 대신 `StringFormat`이나 `FallbackValue` 같은 바인딩 옵션을 활용할 수 있습니다.

```xml
<TextBlock Text="{Binding Value, ElementName=Root, TargetNullValue='(값 없음)'}"/>
```

`TargetNullValue`는 바인딩 소스 값이 `null`일 때 대신 표시할 값을 지정합니다. 이런 세부 옵션들은 7장에서 다룬 바인딩 기초의 연장선이며, `UserControl` 내부에서도 똑같이 자유롭게 사용할 수 있습니다. 결국 `UserControl`은 그 안에 무엇을 채워 넣든 지금까지 배운 XAML과 바인딩 지식을 그대로 재사용할 수 있는 그릇일 뿐입니다.

## 요약

- `UserControl`은 여러 컨트롤을 조합해 하나의 재사용 가능한 화면 조각으로 묶는 가장 쉬운 방법입니다. `.axaml`과 `.axaml.cs` 한 쌍으로 이루어지며 구조는 `Window`와 동일합니다.
- 다른 화면에서 사용하려면 `xmlns:접두사="using:네임스페이스"`로 네임스페이스를 선언한 뒤 태그로 삽입합니다.
- 외부에서 값을 전달받으려면 `AvaloniaProperty.Register`로 `StyledProperty`를 등록하고, `GetValue`/`SetValue`를 사용하는 CLR 래퍼 속성을 함께 작성합니다.
- `UserControl` 루트에 `x:Name`을 붙이고 내부 요소에서 `ElementName` 바인딩으로 참조하면, 등록한 속성 값을 내부 UI에 반영할 수 있습니다.
- 이렇게 만든 속성은 리터럴 값은 물론 데이터 바인딩의 대상도 될 수 있어, 내장 컨트롤과 동일한 방식으로 사용됩니다.
- Avalonia의 속성 시스템(`StyledProperty`, `DirectProperty`)에 대한 본격적인 내용과 `TemplatedControl` 기반의 커스텀 컨트롤 제작은 13장에서 이어집니다.

## 연습문제

1. 제목과 설명 두 줄을 세로로 보여주는 `InfoCard`라는 `UserControl`을 만들어보세요. `Title`, `Description` 두 개의 `StyledProperty`를 등록하고 XAML에서 `ElementName` 바인딩으로 연결하세요.
2. `LabeledField`에 `LabelWidth`라는 `double` 형식의 `StyledProperty`를 추가해서, 라벨 영역의 너비를 사용하는 쪽에서 조절할 수 있게 만들어보세요.
3. `LabeledField`의 `Value`가 빈 문자열이거나 `null`일 때 `"(값 없음)"`이라고 표시되도록 바인딩을 수정해보세요.
4. `MainWindow`에서 `LabeledField`를 세 개 이상 배치하고, 각각의 `Value`를 뷰모델의 서로 다른 속성에 바인딩해보세요. 뷰모델 속성 값이 바뀔 때 화면이 함께 갱신되는지 확인해보세요.
5. `UserControl`로 만든 컴포넌트와 11장에서 다룬 `ControlTemplate` 기반 컨트롤의 차이를 자신의 말로 정리하고, 지금 만든 `LabeledField`를 `TemplatedControl`로 다시 만든다면 무엇이 달라질지 예상해보세요.
