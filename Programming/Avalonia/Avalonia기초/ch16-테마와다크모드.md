# 16장. 테마와 다크 모드

[◀ 이전: 15장. 네비게이션과 다이얼로그](ch15-네비게이션과다이얼로그.md) | [📖 목차](00-목차.md) | [다음: 17장. 플랫폼별 배포 ▶](ch17-플랫폼별배포.md)


## 들어가며

요즘 사용자들은 애플리케이션이 다크 모드를 지원하는 것을 당연하게 여깁니다. 운영체제 자체가 라이트/다크 모드를 기본으로 제공하기 시작하면서, 데스크톱 애플리케이션도 시스템 설정에 맞춰 화면 색을 바꾸거나, 최소한 사용자가 직접 선택할 수 있는 옵션을 제공해야 한다는 기대가 자연스러워졌습니다.

Avalonia는 이런 요구를 프레임워크 차원에서 지원합니다. 기본 제공 테마인 Fluent 테마는 처음부터 라이트/다크 모드를 염두에 두고 설계되어 있고, `ThemeVariant`라는 개념을 통해 런타임에 테마를 전환하는 기능도 프레임워크에 내장되어 있습니다. 이번 장에서는 Fluent 테마를 애플리케이션에 적용하는 방법, 런타임에 라이트/다크 모드를 전환하는 방법, 그리고 10장에서 배운 `DynamicResource`가 왜 이 모든 과정에서 핵심적인 역할을 하는지를 살펴봅니다.

## Fluent 테마 적용하기

Avalonia 프로젝트를 새로 만들면 기본 템플릿의 `App.axaml`에는 이미 다음과 같은 설정이 들어 있습니다.

```xml
<Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="ThemeDemo.App">
    <Application.Styles>
        <FluentTheme />
    </Application.Styles>
</Application>
```

`FluentTheme`은 Avalonia가 기본으로 제공하는 테마로, 버튼, 체크박스, 슬라이더, 콤보박스 등 5장에서 다룬 기본 컨트롤들의 모양과 동작을 Microsoft의 Fluent Design 언어에 맞춰 정의해 둔 스타일 묶음입니다. `<Application.Styles>` 안에 이 한 줄을 넣는 것만으로 애플리케이션의 모든 컨트롤이 일관된 모양을 갖추게 됩니다. Avalonia는 Simple이라는 이름의 더 단순한 테마도 함께 제공하지만, 이 책에서는 실무에서 가장 널리 쓰이는 Fluent 테마를 기준으로 설명합니다.

여기서 중요한 점은, `FluentTheme`이 단순히 "예쁜 색"을 입히는 것을 넘어 `SystemAccentColor`, `ThemeBackgroundBrush`, `ThemeForegroundBrush`처럼 이름 붙은 리소스 집합을 함께 정의한다는 사실입니다. 각 컨트롤의 스타일은 자기 색을 직접 하드코딩하는 대신 이런 리소스 키를 참조하도록 만들어져 있습니다. 바로 이 구조 덕분에 잠시 후 살펴볼 라이트/다크 모드 전환이 가능해집니다.

## 라이트/다크 모드 전환: RequestedThemeVariant

Avalonia는 `Avalonia.Styling` 네임스페이스에 `ThemeVariant`라는 타입을 두고, 현재 어떤 테마 변형이 적용되어야 하는지를 이 값으로 표현합니다. 대표적인 값은 다음 세 가지입니다.

- `ThemeVariant.Light` - 라이트 모드로 고정
- `ThemeVariant.Dark` - 다크 모드로 고정
- `ThemeVariant.Default` - 운영체제의 설정을 따름(기본값)

애플리케이션 전체의 테마는 `Application.Current.RequestedThemeVariant` 속성으로 지정합니다. 예를 들어 메뉴에 있는 "다크 모드" 항목을 토글하는 코드는 다음처럼 작성할 수 있습니다.

```csharp
private void ToggleTheme_Click(object? sender, RoutedEventArgs e)
{
    var app = Application.Current!;

    app.RequestedThemeVariant = app.ActualThemeVariant == ThemeVariant.Dark
        ? ThemeVariant.Light
        : ThemeVariant.Dark;
}
```

`RequestedThemeVariant`가 사용자(또는 코드)가 "요청한" 값이라면, `ActualThemeVariant`는 그 요청이 실제로 어떻게 해석되었는지를 보여주는 읽기 전용 속성입니다. `RequestedThemeVariant`를 `ThemeVariant.Default`로 두면 `ActualThemeVariant`는 운영체제의 라이트/다크 설정을 반영한 값으로 계산됩니다. 두 속성을 구분해 두면, "사용자가 명시적으로 다크 모드를 선택했는지" 아니면 "시스템 설정을 따르는 중인지"를 코드에서 구분할 수 있습니다.

MVVM 관점에서 보면, 커맨드(9장)에 연결된 메서드 안에서 `Application.Current.RequestedThemeVariant`를 직접 바꾸는 것이 다소 어색하게 느껴질 수 있습니다. ViewModel이 `Application` 클래스를 직접 참조하기 때문입니다. 규모가 작은 애플리케이션에서는 이 정도의 결합은 실용적으로 받아들여지지만, 더 엄격하게 분리하고 싶다면 테마 전환을 전담하는 서비스 인터페이스를 두고, 그 구현체에서만 `Application.Current`에 접근하도록 만들 수도 있습니다. 이는 15장에서 다이얼로그를 열 때 살펴본 서비스 추상화와 같은 발상입니다.

```csharp
public partial class SettingsViewModel : ViewModelBase
{
    [ObservableProperty]
    private bool _isDarkMode;

    partial void OnIsDarkModeChanged(bool value)
    {
        Application.Current!.RequestedThemeVariant = value
            ? ThemeVariant.Dark
            : ThemeVariant.Light;
    }
}
```

이렇게 `IsDarkMode`라는 평범한 불리언 속성을 토글 스위치 컨트롤에 바인딩해 두면, 사용자는 스위치 하나로 테마를 즉시 전환할 수 있습니다.

## DynamicResource가 테마 전환에 필수적인 이유

10장에서 `StaticResource`와 `DynamicResource`의 차이를 다뤘습니다. `StaticResource`는 XAML이 파싱되는 시점에 리소스 값을 한 번 찾아 그대로 박아 넣고 끝나는 반면, `DynamicResource`는 그 값이 실제로 필요해질 때마다, 그리고 리소스 딕셔너리의 내용이 바뀔 때마다 다시 조회합니다.

이 차이가 왜 테마 전환에서 결정적인지 생각해 봅시다. `RequestedThemeVariant`를 `Dark`로 바꾼다고 해서 Avalonia가 화면의 모든 컨트롤을 새로 만들어 다시 그리는 것이 아닙니다. 실제로 벌어지는 일은, `SystemAccentColor`나 `ThemeBackgroundBrush` 같은 리소스 키가 가리키는 **값 자체가 바뀌는 것**입니다. Fluent 테마는 이런 리소스들을 라이트용 값과 다크용 값으로 각각 미리 정의해 두었다가, 테마 변형이 바뀌면 어떤 값 집합을 사용할지만 바꿔치기합니다.

만약 어떤 컨트롤의 배경색이 `StaticResource`로 연결되어 있었다면, 처음 화면이 그려질 때 리소스 값을 한 번 읽어온 뒤로는 그 값을 그대로 들고 있을 뿐, 리소스 딕셔너리에서 값이 바뀌었다는 사실을 전혀 알지 못합니다. 반대로 `DynamicResource`로 연결되어 있다면, 리소스 값이 바뀌는 순간 그 변경을 통지받아 화면을 즉시 다시 그립니다. Fluent 테마가 제공하는 브러시들은 모두 내부적으로 이런 방식으로 참조되기 때문에, 우리가 `RequestedThemeVariant` 하나만 바꿔도 버튼, 텍스트, 배경 등 테마 전반의 색상이 한 번에 자연스럽게 전환되는 것입니다.

같은 원리가 우리가 직접 정의하는 리소스에도 그대로 적용됩니다. 만약 애플리케이션 고유의 강조 색을 다음과 같이 `StaticResource`로 연결했다면,

```xml
<Border Background="{StaticResource AppHighlightBrush}">
```

테마가 바뀌어도 이 `Border`의 배경색은 절대 바뀌지 않습니다. 처음 로드될 때 값을 한 번 박아 넣고 끝났기 때문입니다. 라이트/다크 모드에 따라 함께 바뀌어야 하는 리소스라면 반드시 `DynamicResource`로 연결해야 합니다.

```xml
<Border Background="{DynamicResource AppHighlightBrush}">
```

정리하면, "테마에 따라 달라져야 하는 값은 무조건 `DynamicResource`"라는 원칙을 지키는 것이 다크 모드 대응의 절반을 차지합니다. 나머지 절반은 바로 다음에 살펴볼, 라이트/다크 각각의 값을 실제로 어떻게 정의하느냐입니다.

## ThemeDictionaries로 라이트/다크 팔레트 정의하기

Fluent 테마가 제공하는 기본 색상만으로 충분하지 않을 때, 즉 애플리케이션 고유의 색(카드 배경, 강조 텍스트 색 등)을 라이트 모드와 다크 모드에서 다르게 정의하고 싶을 때는 `ResourceDictionary`의 `ThemeDictionaries` 기능을 사용합니다. `ThemeDictionaries`는 하나의 리소스 키에 대해 테마 변형별로 서로 다른 값을 등록해 두는 자리입니다.

```xml
<ResourceDictionary xmlns="https://github.com/avaloniaui"
                     xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml">
    <ResourceDictionary.ThemeDictionaries>
        <ResourceDictionary x:Key="Light">
            <SolidColorBrush x:Key="AppCardBackgroundBrush" Color="#FFFFFFFF" />
            <SolidColorBrush x:Key="AppPrimaryTextBrush" Color="#FF1B1B1B" />
            <SolidColorBrush x:Key="AppHighlightBrush" Color="#FF2E7D32" />
        </ResourceDictionary>
        <ResourceDictionary x:Key="Dark">
            <SolidColorBrush x:Key="AppCardBackgroundBrush" Color="#FF2B2B2B" />
            <SolidColorBrush x:Key="AppPrimaryTextBrush" Color="#FFEDEDED" />
            <SolidColorBrush x:Key="AppHighlightBrush" Color="#FF66BB6A" />
        </ResourceDictionary>
    </ResourceDictionary.ThemeDictionaries>
</ResourceDictionary>
```

`x:Key="Light"`와 `x:Key="Dark"`는 각각 `ThemeVariant.Light`, `ThemeVariant.Dark`에 대응합니다. Avalonia는 리소스를 조회할 때 현재 `ActualThemeVariant`에 해당하는 딕셔너리를 먼저 찾아보고, 그 안에서 키를 찾습니다. 같은 `AppCardBackgroundBrush`라는 이름이라도 라이트 모드에서는 흰색에 가까운 배경을, 다크 모드에서는 어두운 회색 배경을 돌려주는 셈입니다.

이 리소스 딕셔너리는 보통 별도 파일(예: `Themes/AppPalette.axaml`)로 분리해 두고, `App.axaml`에서 병합해 사용합니다.

```xml
<Application.Resources>
    <ResourceDictionary>
        <ResourceDictionary.MergedDictionaries>
            <ResourceInclude Source="avares://ThemeDemo/Themes/AppPalette.axaml" />
        </ResourceDictionary.MergedDictionaries>
    </ResourceDictionary>
</Application.Resources>
```

이렇게 등록해 둔 색은 앞서 설명한 대로 반드시 `DynamicResource`로 사용해야 테마 전환에 반응합니다.

```xml
<Border Background="{DynamicResource AppCardBackgroundBrush}"
        Padding="16" CornerRadius="8">
    <TextBlock Text="카드 형태의 컨텐츠 영역"
               Foreground="{DynamicResource AppPrimaryTextBrush}" />
</Border>
```

이 구조를 갖춰 두면, 애플리케이션 어디에서든 `RequestedThemeVariant`를 `Dark`로 바꾸는 순간 Fluent 테마의 기본 컨트롤 색상은 물론, 우리가 `ThemeDictionaries`에 정의해 둔 고유 팔레트까지 한꺼번에 자연스럽게 다크 모드로 전환됩니다. 반대로 라이트 모드로 되돌리면 모든 색이 다시 라이트 팔레트 값으로 즉시 복원됩니다. 결국 다크 모드 지원이란 특별한 마법이 아니라, "테마별로 달라져야 할 값을 `ThemeDictionaries`에 미리 정의해 두고, 그 값을 참조하는 모든 곳에서 `DynamicResource`를 쓴다"는 두 가지 원칙을 일관되게 지키는 일이라고 정리할 수 있습니다.

## 요약

- Avalonia는 `FluentTheme`을 기본 제공 테마로 두며, `App.axaml`의 `Application.Styles`에 `<FluentTheme />`를 추가하는 것만으로 모든 컨트롤에 일관된 스타일을 적용할 수 있습니다.
- `Application.Current.RequestedThemeVariant`에 `ThemeVariant.Light`, `ThemeVariant.Dark`, `ThemeVariant.Default` 중 하나를 대입해 런타임에 테마를 전환할 수 있고, 실제로 적용된 테마는 `ActualThemeVariant`로 확인합니다.
- 테마 전환이 실제 화면에 반영되려면 색상 관련 리소스가 `DynamicResource`로 연결되어 있어야 합니다. `StaticResource`는 값을 한 번만 읽어오므로 테마가 바뀌어도 갱신되지 않습니다.
- `ResourceDictionary`의 `ThemeDictionaries`에 `Light`/`Dark` 키로 각각의 리소스 딕셔너리를 등록하면, 애플리케이션 고유의 색 팔레트도 테마 변형에 따라 자동으로 다른 값을 갖도록 만들 수 있습니다.
- 다크 모드 지원의 핵심은 "테마별 값을 `ThemeDictionaries`로 정의하고, 그 값을 참조하는 모든 곳에서 `DynamicResource`를 사용한다"는 두 원칙으로 요약됩니다.

## 연습문제

1. `RequestedThemeVariant`와 `ActualThemeVariant`의 차이를 설명하고, 각각이 언제 유용한지 예를 들어 보세요.
2. 어떤 컨트롤의 배경색이 `StaticResource`로 연결되어 있을 때, 라이트/다크 모드를 전환해도 색이 바뀌지 않는 이유를 설명해 보세요.
3. `ThemeDictionaries`를 사용해 애플리케이션 고유의 강조 색(하이라이트 브러시)을 라이트 모드에서는 초록색 계열로, 다크 모드에서는 좀 더 밝은 초록색 계열로 정의해 보세요.
4. 사용자가 애플리케이션을 다시 실행했을 때도 이전에 선택한 테마(라이트/다크)가 유지되도록 하려면 어떤 추가 작업이 필요할지 생각해 보세요.
5. ViewModel에서 `Application.Current.RequestedThemeVariant`를 직접 바꾸는 방식의 장단점을 설명하고, 이를 서비스 인터페이스로 추상화한다면 어떤 형태가 될지 설계해 보세요.
