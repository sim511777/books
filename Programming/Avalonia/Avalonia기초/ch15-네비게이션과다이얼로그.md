## 들어가며

지금까지 만든 예제는 대부분 창(Window) 하나 안에서 컨트롤을 배치하고 데이터를 바인딩하는 데 집중했습니다. 하지만 실제로 쓸모 있는 애플리케이션은 거의 항상 여러 화면으로 구성됩니다. 설정 화면을 별도 창으로 띄우기도 하고, "정말 삭제하시겠습니까?" 같은 확인창을 띄워 사용자의 의사를 다시 물어보기도 하며, 파일을 저장하거나 불러오기 위한 대화상자를 열어야 할 때도 있습니다.

Avalonia에서 "여러 화면"을 표현하는 방법은 크게 두 갈래로 나뉩니다. 하나는 실제로 새로운 운영체제 창을 여는 방법이고, 다른 하나는 창은 하나만 유지한 채 그 안에 표시되는 내용만 바꿔치기하는 "뷰 스위칭" 방법입니다. 이번 장에서는 두 방식을 모두 살펴보고, 여기에 더해 확인 다이얼로그와 파일 선택 대화상자처럼 실무에서 자주 마주치는 패턴까지 다룹니다.

## 새 창 열기: 비모달 창

가장 단순한 형태의 다중 창 애플리케이션은 버튼을 눌렀을 때 새 창을 하나 띄우는 것입니다. Avalonia에서 창은 `Window`를 상속하는 클래스이므로, 새 창을 여는 일은 그 클래스의 인스턴스를 만들고 `Show()`를 호출하는 것으로 끝납니다.

먼저 두 번째 창이 될 `SecondWindow.axaml`을 준비합니다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        x:Class="NavigationDemo.SecondWindow"
        Title="두 번째 창"
        Width="300" Height="200">
    <StackPanel Margin="16" Spacing="8">
        <TextBlock Text="이것은 별도의 창입니다." />
        <Button Content="닫기" Click="CloseButton_Click" />
    </StackPanel>
</Window>
```

```csharp
public partial class SecondWindow : Window
{
    public SecondWindow()
    {
        InitializeComponent();
    }

    private void CloseButton_Click(object? sender, RoutedEventArgs e)
    {
        Close();
    }
}
```

메인 창에서는 버튼 클릭 이벤트 핸들러(6장)에서 이 창을 생성하고 띄우기만 하면 됩니다.

```csharp
private void OpenSecondWindow_Click(object? sender, RoutedEventArgs e)
{
    var window = new SecondWindow();
    window.Show();
}
```

`Show()`로 띄운 창은 **비모달(non-modal)** 창입니다. 즉 새 창이 열려 있어도 원래 창을 계속 조작할 수 있고, 두 창은 서로 독립적으로 동작합니다. `Show()`에 소유자 창을 인자로 넘기면(`window.Show(this)`) 두 창 사이에 소유 관계가 생깁니다. 소유자 창이 최소화되면 소유된 창도 함께 최소화되고, 소유자 창을 닫으면 소유된 창도 함께 닫히는 등 운영체제 수준에서 두 창이 한 묶음처럼 취급됩니다. 도구 팔레트나 알림 창처럼 "메인 창과 함께 붙어 다녀야 하는" 보조 창을 만들 때 유용한 옵션입니다.

## 모달 다이얼로그: ShowDialog

설정 창이나 편집 창처럼 "사용자가 이 창을 닫기 전까지는 원래 창으로 돌아가지 못하게" 만들고 싶을 때는 **모달(modal) 다이얼로그**를 씁니다. Avalonia에서는 `ShowDialog` 메서드가 이 역할을 담당합니다.

```csharp
private async void OpenDialog_Click(object? sender, RoutedEventArgs e)
{
    var dialog = new SecondWindow();
    await dialog.ShowDialog(this);
}
```

`ShowDialog(Window owner)`는 `Task`를 반환하는 비동기 메서드입니다. 이 창이 닫힐 때까지 `await` 지점에서 대기하며, 소유자 창(`owner`)은 다이얼로그가 떠 있는 동안 입력을 받을 수 없게 비활성화됩니다. 이벤트 핸들러 시그니처를 `async void`로 바꿔야 `await`를 쓸 수 있다는 점을 기억해 두세요.

단순히 창을 닫는 것을 넘어, 다이얼로그에서 어떤 값을 골랐는지 결과로 돌려받고 싶은 경우가 많습니다. 이때는 제네릭 버전인 `ShowDialog<TResult>(Window owner)`를 사용하고, 다이얼로그 쪽에서는 `Close(result)`처럼 결과값을 넘기며 창을 닫습니다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        x:Class="NavigationDemo.EditNameWindow"
        Title="이름 편집"
        Width="300" Height="160">
    <StackPanel Margin="16" Spacing="8">
        <TextBox Name="NameTextBox" />
        <StackPanel Orientation="Horizontal" Spacing="8" HorizontalAlignment="Right">
            <Button Content="확인" Click="Ok_Click" />
            <Button Content="취소" Click="Cancel_Click" />
        </StackPanel>
    </StackPanel>
</Window>
```

```csharp
public partial class EditNameWindow : Window
{
    public EditNameWindow()
    {
        InitializeComponent();
    }

    private void Ok_Click(object? sender, RoutedEventArgs e)
    {
        Close(NameTextBox.Text);
    }

    private void Cancel_Click(object? sender, RoutedEventArgs e)
    {
        Close(null);
    }
}
```

호출하는 쪽에서는 다음과 같이 결과를 바로 받아 사용할 수 있습니다.

```csharp
private async void EditName_Click(object? sender, RoutedEventArgs e)
{
    var dialog = new EditNameWindow();
    var result = await dialog.ShowDialog<string?>(this);

    if (result is not null)
    {
        NameTextBlock.Text = result;
    }
}
```

여기서 한 가지 짚어야 할 문제가 있습니다. 이 예제는 코드 비하인드에서 `this`(현재 창)를 소유자로 넘기고 있는데, 8장에서 익힌 MVVM 구조에서는 ViewModel이 `Window` 타입을 직접 알아서는 안 됩니다. ViewModel은 UI 프레임워크에 의존하지 않는 순수한 C# 클래스여야 테스트가 쉬워지기 때문입니다. 그래서 실무에서는 보통 다음 두 가지 방식 중 하나를 씁니다.

- 다이얼로그를 여는 코드 자체는 View의 코드 비하인드(또는 코드 비하인드의 이벤트 핸들러)에 남겨두고, ViewModel은 커맨드(9장)를 통해 "다이얼로그를 열어라"라는 신호만 보내는 방식
- `IDialogService`처럼 ViewModel이 참조할 수 있는 추상화된 인터페이스를 정의하고, 실제 구현체(창을 직접 다루는 코드)는 애플리케이션 조립 단계에서 주입하는 방식

두 방식 모두 핵심은 같습니다. "창을 띄우고 닫는" 구체적인 코드는 View 계층에 남기고, ViewModel은 결과 데이터만 주고받는다는 원칙입니다. 이 책에서는 간단함을 위해 코드 비하인드에서 직접 창을 다루는 예제를 사용하지만, 프로젝트 규모가 커진다면 서비스 추상화를 도입하는 편이 유지보수에 유리합니다.

## 하나의 창 안에서 화면 전환하기: 뷰 스위칭 패턴

새 창을 여는 대신, 창 하나를 유지한 채 그 안의 내용만 바꾸는 방식도 많이 쓰입니다. 특히 사이드바에서 메뉴를 눌러 오른쪽 영역의 화면만 바뀌는 형태의 애플리케이션이라면, 매번 새 창을 띄우는 것보다 이 방식이 자연스럽습니다. 이 패턴을 흔히 **뷰 스위칭(view switching)**이라고 부르며, MVVM 기반 Avalonia 애플리케이션에서 가장 널리 쓰이는 네비게이션 방식입니다.

핵심 아이디어는 단순합니다. 화면에는 `ContentControl` 하나를 두고, 그 `Content`를 "현재 보여줄 화면"을 나타내는 ViewModel에 바인딩합니다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        x:Class="NavigationDemo.MainWindow"
        Title="뷰 스위칭 예제"
        Width="500" Height="350">
    <DockPanel>
        <StackPanel DockPanel.Dock="Left" Width="120" Spacing="4" Margin="8">
            <Button Content="홈" Command="{Binding NavigateToHomeCommand}" />
            <Button Content="설정" Command="{Binding NavigateToSettingsCommand}" />
        </StackPanel>
        <ContentControl Content="{Binding CurrentPage}" />
    </DockPanel>
</Window>
```

`CurrentPage`는 `HomeViewModel`이나 `SettingsViewModel` 같은 ViewModel 인스턴스를 담는 속성입니다.

```csharp
public partial class MainWindowViewModel : ViewModelBase
{
    private readonly HomeViewModel _homeViewModel = new();
    private readonly SettingsViewModel _settingsViewModel = new();

    [ObservableProperty]
    private ViewModelBase _currentPage;

    public MainWindowViewModel()
    {
        _currentPage = _homeViewModel;
    }

    [RelayCommand]
    private void NavigateToHome() => CurrentPage = _homeViewModel;

    [RelayCommand]
    private void NavigateToSettings() => CurrentPage = _settingsViewModel;
}
```

문제는 `ContentControl`이 `CurrentPage`에 담긴 ViewModel을 화면에 표시할 때, 그것을 어떤 View로 그려야 할지 스스로는 알지 못한다는 점입니다. 이를 해결하는 방법은 두 가지입니다.

첫 번째는 11장에서 다룬 데이터 템플릿을 이용해 ViewModel 타입과 View를 직접 연결하는 방법입니다.

```xml
<Window.Resources>
    <DataTemplate DataType="{x:Type vm:HomeViewModel}">
        <views:HomeView />
    </DataTemplate>
    <DataTemplate DataType="{x:Type vm:SettingsViewModel}">
        <views:SettingsView />
    </DataTemplate>
</Window.Resources>
```

두 번째는 이름 규칙을 기반으로 View를 자동으로 찾아주는 `ViewLocator`를 등록하는 방법입니다. Avalonia의 기본 애플리케이션 템플릿에도 포함되어 있는 방식으로, "OOViewModel"이라는 이름의 클래스가 있으면 "OOView"라는 이름의 View를 찾아 인스턴스화합니다.

```csharp
public class ViewLocator : IDataTemplate
{
    public Control? Build(object? data)
    {
        if (data is null)
        {
            return null;
        }

        var name = data.GetType().FullName!.Replace("ViewModel", "View");
        var type = Type.GetType(name);

        if (type is not null)
        {
            return (Control)Activator.CreateInstance(type)!;
        }

        return new TextBlock { Text = $"View를 찾을 수 없습니다: {name}" };
    }

    public bool Match(object? data) => data is ViewModelBase;
}
```

```csharp
// App.axaml.cs
public override void OnFrameworkInitializationCompleted()
{
    DataTemplates.Add(new ViewLocator());
    // ...
}
```

두 방식 모두 결과는 같습니다. `CurrentPage`가 바뀌면 `ContentControl`이 새 ViewModel에 맞는 View를 다시 그려주고, 화면에는 창을 새로 여는 깜빡임 없이 부드럽게 내용이 바뀝니다. 다만 이 패턴은 "현재 어떤 화면을 보고 있는가"만 관리할 뿐, 뒤로 가기 스택 같은 정교한 네비게이션 기능은 제공하지 않습니다. 뒤로 가기가 필요하다면 `CurrentPage`를 바꾸는 대신 방문 기록을 담는 스택 컬렉션을 직접 관리하는 방식으로 확장할 수 있습니다.

## 확인 다이얼로그 직접 만들기

WPF에는 `MessageBox.Show("정말 삭제하시겠습니까?", "확인", MessageBoxButton.YesNo)`처럼 한 줄로 메시지 상자를 띄울 수 있는 `System.Windows.MessageBox` 클래스가 기본 내장되어 있습니다. 그런데 Avalonia에는 이에 대응하는 클래스가 프레임워크에 기본으로 포함되어 있지 않습니다. 크로스플랫폼을 지향하는 프레임워크 특성상 운영체제마다 표준 메시지 상자 모양이 다르기도 하고, Avalonia 팀은 이 부분을 프레임워크 핵심이 아니라 애플리케이션이나 커뮤니티 라이브러리가 채울 영역으로 남겨두었기 때문입니다. 실제로 `MessageBox.Avalonia`처럼 NuGet에서 받아 쓸 수 있는 커뮤니티 패키지들이 존재하며, 프로젝트 성격에 따라 이런 라이브러리를 도입하는 것도 합리적인 선택입니다.

하지만 지금까지 배운 내용만으로도 확인 다이얼로그 정도는 직접 만들 수 있습니다. 앞서 살펴본 `ShowDialog<TResult>` 패턴을 그대로 활용하면 됩니다.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        x:Class="NavigationDemo.ConfirmDialog"
        Title="확인"
        Width="320" Height="150"
        WindowStartupLocation="CenterOwner"
        CanResize="False">
    <StackPanel Margin="20" Spacing="16">
        <TextBlock Name="MessageTextBlock" TextWrapping="Wrap" />
        <StackPanel Orientation="Horizontal" Spacing="8" HorizontalAlignment="Right">
            <Button Content="예" Click="Yes_Click" />
            <Button Content="아니오" Click="No_Click" />
        </StackPanel>
    </StackPanel>
</Window>
```

```csharp
public partial class ConfirmDialog : Window
{
    public ConfirmDialog()
    {
        InitializeComponent();
    }

    public ConfirmDialog(string message) : this()
    {
        MessageTextBlock.Text = message;
    }

    private void Yes_Click(object? sender, RoutedEventArgs e) => Close(true);

    private void No_Click(object? sender, RoutedEventArgs e) => Close(false);

    public static Task<bool> ShowAsync(Window owner, string message)
    {
        var dialog = new ConfirmDialog(message);
        return dialog.ShowDialog<bool>(owner);
    }
}
```

이렇게 정적 헬퍼 메서드까지 만들어 두면, 호출하는 쪽 코드는 WPF의 `MessageBox.Show`와 거의 비슷한 느낌으로 쓸 수 있습니다.

```csharp
private async void Delete_Click(object? sender, RoutedEventArgs e)
{
    var confirmed = await ConfirmDialog.ShowAsync(this, "정말 삭제하시겠습니까?");

    if (confirmed)
    {
        // 삭제 로직 수행
    }
}
```

`WindowStartupLocation="CenterOwner"`를 지정해 두면 다이얼로그가 소유자 창 한가운데에 뜨고, `CanResize="False"`로 크기 조절 핸들을 없애면 좀 더 메시지 상자다운 느낌을 줄 수 있습니다. 필요하다면 아이콘, 여러 버튼 조합(확인/취소/예/아니오/취소) 등을 추가해 나만의 다이얼로그 컴포넌트로 발전시킬 수도 있습니다.

## 파일 선택 대화상자: StorageProvider API

파일을 열거나 저장할 때 운영체제 표준 파일 대화상자를 띄우고 싶다면 `StorageProvider` API를 사용합니다. 이 API는 데스크톱뿐 아니라 브라우저(WASM)나 모바일 환경까지 아우르도록 설계되어 있어서, 플랫폼마다 파일 시스템 접근 방식이 크게 달라도 동일한 코드로 다룰 수 있다는 장점이 있습니다.

`StorageProvider`는 창 자체가 아니라 `TopLevel`(창이나 최상위 뷰를 추상화한 타입)에 달려 있습니다. 코드 비하인드에서는 현재 컨트롤이 속한 `TopLevel`을 다음과 같이 얻어올 수 있습니다.

```csharp
private async void OpenFile_Click(object? sender, RoutedEventArgs e)
{
    var topLevel = TopLevel.GetTopLevel(this);
    if (topLevel is null)
    {
        return;
    }

    var files = await topLevel.StorageProvider.OpenFilePickerAsync(new FilePickerOpenOptions
    {
        Title = "파일 선택",
        AllowMultiple = false,
        FileTypeFilter = new[]
        {
            new FilePickerFileType("텍스트 파일") { Patterns = new[] { "*.txt" } },
            FilePickerFileTypes.All
        }
    });

    if (files.Count > 0)
    {
        await using var stream = await files[0].OpenReadAsync();
        using var reader = new StreamReader(stream);
        var content = await reader.ReadToEndAsync();
        ContentTextBox.Text = content;
    }
}
```

저장 대화상자도 비슷한 방식으로 사용합니다.

```csharp
private async void SaveFile_Click(object? sender, RoutedEventArgs e)
{
    var topLevel = TopLevel.GetTopLevel(this);
    if (topLevel is null)
    {
        return;
    }

    var file = await topLevel.StorageProvider.SaveFilePickerAsync(new FilePickerSaveOptions
    {
        Title = "파일 저장",
        SuggestedFileName = "untitled.txt",
        DefaultExtension = "txt",
        FileTypeChoices = new[] { new FilePickerFileType("텍스트 파일") { Patterns = new[] { "*.txt" } } }
    });

    if (file is not null)
    {
        await using var stream = await file.OpenWriteAsync();
        await using var writer = new StreamWriter(stream);
        await writer.WriteAsync(ContentTextBox.Text);
    }
}
```

`OpenFilePickerAsync`는 사용자가 고른 파일들을 `IReadOnlyList<IStorageFile>`로 돌려주고, `SaveFilePickerAsync`는 사용자가 지정한 저장 위치를 `IStorageFile?` 하나로 돌려줍니다(취소하면 `null`). 두 경우 모두 반환된 `IStorageFile`에서 `OpenReadAsync()`나 `OpenWriteAsync()`로 스트림을 얻어 실제 파일 내용을 읽고 쓸 수 있습니다. 로컬 파일 시스템 경로가 꼭 필요하다면 `file.TryGetLocalPath()`로 얻을 수 있지만, 브라우저 환경처럼 전통적인 경로 개념이 없는 플랫폼도 있으므로 가능하면 스트림 기반 API를 우선 사용하는 것이 좋습니다. 폴더 하나를 선택하게 하고 싶을 때는 같은 방식으로 `OpenFolderPickerAsync`를 사용할 수 있습니다.

여기서도 앞서 다이얼로그에서 언급한 것과 같은 고민이 등장합니다. `TopLevel.GetTopLevel(this)`는 View 계층의 코드이므로, ViewModel에서 파일을 저장하는 로직을 실행하고 싶다면 View가 얻어온 `IStorageProvider`를 ViewModel에 전달하거나, 파일 접근을 전담하는 서비스 인터페이스를 두는 방식으로 설계하는 것이 일반적입니다. 지금 단계에서는 StorageProvider의 기본 동작 원리를 이해하는 데 집중하고, 실제 프로젝트에 적용할 때 이런 구조적 선택지를 함께 고려하면 됩니다.

## 요약

- 새 창을 열 때는 `Window` 인스턴스를 만들고 `Show()`를 호출하면 되며, 이렇게 뜬 창은 원래 창과 독립적으로 동작하는 비모달 창입니다.
- `ShowDialog(owner)`는 창이 닫힐 때까지 대기하는 모달 다이얼로그를 띄우고, `ShowDialog<TResult>(owner)`와 `Close(result)`를 조합하면 다이얼로그에서 선택한 값을 호출자에게 돌려줄 수 있습니다.
- 하나의 창 안에서 화면을 바꾸고 싶다면 `ContentControl`의 `Content`를 현재 ViewModel에 바인딩하는 뷰 스위칭 패턴을 사용하며, 데이터 템플릿이나 `ViewLocator`로 ViewModel과 View를 연결합니다.
- Avalonia에는 WPF의 `MessageBox` 같은 기본 내장 메시지 상자가 없으므로, 커뮤니티 라이브러리를 쓰거나 `ShowDialog<TResult>` 패턴으로 직접 확인 다이얼로그를 만들어야 합니다.
- 파일을 열고 저장하는 대화상자는 `TopLevel.StorageProvider`의 `OpenFilePickerAsync`/`SaveFilePickerAsync`로 띄우며, 이 API는 데스크톱과 브라우저 등 다양한 플랫폼에서 동일하게 동작하도록 설계되어 있습니다.

## 연습문제

1. `Show()`와 `ShowDialog()`의 차이를 설명하고, 각각 어떤 상황에 적합한지 예를 들어 보세요.
2. `ShowDialog<TResult>`를 사용해 사용자가 입력한 숫자를 반환하는 간단한 입력 다이얼로그를 만들어 보세요.
3. 뷰 스위칭 패턴에서 `ContentControl`의 `Content`에 바인딩된 ViewModel이 실제 View로 그려지기 위해 필요한 것은 무엇인지 설명해 보세요.
4. Avalonia에 `MessageBox` 클래스가 기본 내장되어 있지 않은 이유를 설명하고, 직접 확인 다이얼로그를 만드는 대안 외에 어떤 방법이 있는지 조사해 보세요.
5. `StorageProvider`가 창(Window)이 아니라 `TopLevel`에 종속된 API로 설계된 이유를 Avalonia가 지원하는 플랫폼의 다양성과 연결지어 생각해 보세요.
