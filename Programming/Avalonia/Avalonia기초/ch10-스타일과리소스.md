# 10장. 스타일과 리소스

[◀ 이전: 9장. 커맨드(ICommand)](ch09-커맨드ICommand.md) | [📖 목차](00-목차.md) | [다음: 11장. 컨트롤 템플릿과 데이터 템플릿 ▶](ch11-컨트롤템플릿과데이터템플릿.md)


지금까지 만든 예제들은 버튼의 배경색, 여백, 모서리 둥글기 같은 값을 필요할 때마다 XAML 안에 직접 적어 넣었다. 컨트롤이 몇 개뿐이라면 이 방식도 나쁘지 않지만, 화면이 늘어나고 버튼이 수십 개로 불어나면 같은 색상 코드를 수십 군데에 복사해 붙여 넣는 상황이 벌어진다. 나중에 브랜드 색상이 바뀌기라도 하면 그 수십 군데를 전부 찾아 고쳐야 한다.

이 장에서는 이런 문제를 해결하는 두 가지 도구, 리소스(Resources)와 스타일(Style)을 다룬다. 리소스는 색상이나 크기 같은 값을 한 곳에 정의해 두고 여러 곳에서 이름으로 재사용하는 방법이고, 스타일은 특정 조건에 맞는 컨트롤들에 속성 값을 한꺼번에 적용하는 방법이다. 둘 다 값을 반복해서 적지 않고 한 곳에서 관리한다는 목표는 같지만, 리소스는 "값 하나"를 재사용하는 것이고 스타일은 "속성 여러 개의 조합"을 재사용하는 것이라는 차이가 있다.

## 10.1 리소스란 무엇인가

리소스는 색상, 브러시, 두께, 여백 같은 값에 이름을 붙여 저장해 두고, XAML의 여러 위치에서 그 이름으로 값을 꺼내 쓸 수 있게 해 주는 저장소다. 웹 개발에서 CSS 변수를 사용해 본 적이 있다면 거의 같은 개념이라고 생각하면 된다.

리소스를 쓰지 않은 코드는 다음과 같이 같은 색상 값이 여러 번 반복된다.

```xml
<StackPanel Spacing="8">
    <Button Content="확인" Background="#3F51B5" Foreground="White" />
    <Border Background="#3F51B5" Padding="8">
        <TextBlock Text="안내" Foreground="White" />
    </Border>
</StackPanel>
```

`#3F51B5`라는 색상 코드가 두 번 등장한다. 이 색을 바꾸고 싶다면 두 곳을 모두 찾아 고쳐야 한다. 리소스를 사용하면 이 값을 한 번만 정의하고 이름으로 참조할 수 있다.

## 10.2 리소스 정의하기: Resources와 StaticResource

리소스는 `Resources`라는 속성을 가진 요소라면 어디에나 정의할 수 있다. 가장 흔하게 쓰이는 곳은 `Window.Resources`(또는 `UserControl.Resources`)와, 앱 전체에 적용하고 싶을 때 사용하는 `Application.Resources`다.

먼저 창 하나에서만 쓰는 리소스를 정의해 보자.

```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        x:Class="AvaloniaGuide.Views.MainWindow"
        Title="리소스 예제" Width="360" Height="200">
    <Window.Resources>
        <SolidColorBrush x:Key="PrimaryBrush" Color="#3F51B5" />
        <x:Double x:Key="DefaultSpacing">8</x:Double>
    </Window.Resources>

    <StackPanel Spacing="{StaticResource DefaultSpacing}" Margin="16">
        <Button Content="확인" Background="{StaticResource PrimaryBrush}" Foreground="White" />
        <Border Background="{StaticResource PrimaryBrush}" Padding="8">
            <TextBlock Text="안내" Foreground="White" />
        </Border>
    </StackPanel>
</Window>
```

`x:Key`는 리소스를 나중에 찾아올 때 쓰는 이름표다. 리소스를 사용하는 쪽에서는 `{StaticResource 키이름}` 마크업 확장으로 값을 가져온다. `PrimaryBrush`를 한 곳에서만 고치면 이 브러시를 참조하는 모든 컨트롤에 반영된다.

`{StaticResource ...}`의 "Static"이라는 이름 그대로, 이 값은 XAML이 로드되는 시점에 딱 한 번 해석되어 그 자리에 값이 박힌다. 즉 앱이 실행되는 도중에 `PrimaryBrush` 리소스 자체를 다른 값으로 바꿔치기해도, 이미 `StaticResource`로 값을 가져다 쓴 컨트롤에는 변경 사항이 반영되지 않는다.

## 10.3 DynamicResource: 실행 중에 바뀌는 리소스

리소스 값을 앱 실행 도중에 바꾸고, 그 변경을 이미 화면에 그려진 컨트롤에도 반영하고 싶은 경우가 있다. 대표적인 예가 16장에서 다룰 라이트/다크 테마 전환이다. 사용자가 설정 화면에서 테마를 바꾸는 순간, 이미 열려 있는 모든 창의 배경색과 글자색이 즉시 바뀌어야 한다.

이럴 때 사용하는 것이 `{DynamicResource ...}`다.

```xml
<Border Background="{DynamicResource ThemeBackgroundBrush}">
    <TextBlock Text="테마에 따라 배경이 바뀝니다"
               Foreground="{DynamicResource ThemeForegroundBrush}" />
</Border>
```

`StaticResource`가 값을 한 번 찾아서 그대로 복사해 두는 것과 달리, `DynamicResource`는 리소스 딕셔너리를 계속 지켜보는 일종의 구독을 걸어 둔다. 나중에 `ThemeBackgroundBrush`라는 키를 가진 리소스가 다른 값으로 교체되면, 이 값을 참조하고 있던 `Border`는 자동으로 새 값을 다시 적용한다.

두 방식의 차이를 정리하면 다음과 같다.

| 구분 | StaticResource | DynamicResource |
|---|---|---|
| 해석 시점 | 로드 시 한 번 | 값이 필요할 때마다, 변경 시에도 재해석 |
| 실행 중 값 교체 반영 | 반영 안 됨 | 반영됨 |
| 성능 | 상대적으로 가볍다 | 구독을 유지하므로 약간의 비용이 있다 |
| 대표 용도 | 변하지 않는 고정값 | 테마처럼 런타임에 바뀌는 값 |

일반적인 기준은 이렇다. 색상 팔레트처럼 앱 실행 중에는 절대 바뀌지 않는 값이라면 `StaticResource`로 충분하고, 오히려 그쪽이 가볍다. 반면 테마 전환처럼 리소스 자체가 런타임에 교체되어야 하는 값이라면 반드시 `DynamicResource`를 사용해야 한다. 이 주제는 16장에서 실제로 라이트 테마와 다크 테마 리소스 딕셔너리를 서로 바꿔 끼우는 예제로 다시 다룬다.

## 10.4 앱 전체 리소스: Application.Resources와 색상 팔레트

한 창에서만 쓰는 리소스는 `Window.Resources`로 충분하지만, 앱 전체에서 공유할 색상 팔레트라면 `App.axaml`의 `Application.Resources`에 정의하는 것이 자연스럽다.

```xml
<Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="AvaloniaGuide.App">
    <Application.Resources>
        <ResourceDictionary>
            <!-- 팔레트: 원색은 Color로, 실제 사용은 Brush로 -->
            <Color x:Key="PrimaryColor">#3F51B5</Color>
            <Color x:Key="PrimaryDarkColor">#303F9F</Color>
            <Color x:Key="AccentColor">#FF4081</Color>
            <Color x:Key="DangerColor">#E53935</Color>
            <Color x:Key="TextOnPrimaryColor">#FFFFFF</Color>

            <SolidColorBrush x:Key="PrimaryBrush" Color="{StaticResource PrimaryColor}" />
            <SolidColorBrush x:Key="PrimaryDarkBrush" Color="{StaticResource PrimaryDarkColor}" />
            <SolidColorBrush x:Key="AccentBrush" Color="{StaticResource AccentColor}" />
            <SolidColorBrush x:Key="DangerBrush" Color="{StaticResource DangerColor}" />
            <SolidColorBrush x:Key="TextOnPrimaryBrush" Color="{StaticResource TextOnPrimaryColor}" />
        </ResourceDictionary>
    </Application.Resources>
</Application>
```

`Color`와 `SolidColorBrush`를 분리해 둔 것은 실용적인 이유가 있다. `Color`는 순수한 색상값이라서 애니메이션이나 색상 계산에 활용하기 좋고, 실제 컨트롤의 `Background`나 `Foreground`에는 `Brush`가 필요하기 때문에 `SolidColorBrush`로 한 번 감싸 둔 것이다. 이렇게 정의해 두면 앱의 어느 XAML 파일에서든 다음처럼 사용할 수 있다.

```xml
<Button Content="저장"
        Background="{StaticResource PrimaryBrush}"
        Foreground="{StaticResource TextOnPrimaryBrush}" />
```

프로젝트가 커지면 리소스를 여러 파일로 나누고 `ResourceDictionary.MergedDictionaries`로 합쳐서 관리하기도 하는데, 이 구성은 16장에서 테마별 리소스 딕셔너리를 분리할 때 자세히 다룬다.

## 10.5 스타일(Style)로 여러 컨트롤에 공통 속성 적용하기

리소스가 "값 하나"를 재사용하는 도구라면, 스타일은 "속성 여러 개의 조합"을 재사용하는 도구다. 예를 들어 앱에 있는 모든 버튼의 안쪽 여백과 모서리 둥글기를 똑같이 맞추고 싶다면, 버튼마다 `Padding`과 `CornerRadius`를 일일이 적어 넣는 대신 스타일 하나로 정의해 두면 된다.

스타일은 `Styles`라는 속성을 가진 요소(`Window.Styles`, `UserControl.Styles`, 또는 `Application.Styles`) 안에 정의하며, `Selector`로 어떤 컨트롤에 적용할지를 지정하고 `Setter`로 속성 값을 지정한다.

```xml
<Window.Styles>
    <Style Selector="Button">
        <Setter Property="Padding" Value="12,6" />
        <Setter Property="CornerRadius" Value="4" />
    </Style>
</Window.Styles>
```

이 스타일이 정의된 범위 안에 있는 `Button` 컨트롤은 별도로 지정하지 않아도 `Padding="12,6"`과 `CornerRadius="4"`를 기본값으로 갖게 된다. 리소스와 마찬가지로, 여백 값을 바꾸고 싶다면 이 한 곳만 고치면 된다.

## 10.6 셀렉터 문법과 Classes로 스타일 범위 좁히기

`Selector="Button"`처럼 컨트롤 타입 전체를 대상으로 하는 스타일은 강력하지만, 앱에 있는 모든 버튼을 똑같이 꾸미고 싶은 것은 아닐 때가 많다. "확인" 버튼은 강조색으로, "취소" 버튼은 평범하게 두고 싶은 경우가 그렇다. 이럴 때는 컨트롤에 `Classes` 속성으로 이름표를 붙이고, 셀렉터에서 그 이름표를 가진 컨트롤만 선택하도록 지정한다.

```xml
<Window.Styles>
    <Style Selector="Button.accent">
        <Setter Property="Background" Value="{StaticResource AccentBrush}" />
        <Setter Property="Foreground" Value="White" />
        <Setter Property="FontWeight" Value="Bold" />
    </Style>
</Window.Styles>
```

`Selector="Button.accent"`는 "`accent`라는 클래스가 붙은 `Button`"만을 뜻한다. HTML/CSS의 클래스 선택자와 사용 방식이 매우 비슷하다. 이 스타일을 적용받으려면 버튼에 `Classes` 속성으로 같은 이름을 붙여 주면 된다.

```xml
<StackPanel Orientation="Horizontal" Spacing="8">
    <Button Content="확인" Classes="accent" />
    <Button Content="취소" />
</StackPanel>
```

"확인" 버튼만 `accent` 클래스를 가지므로 강조 스타일이 적용되고, "취소" 버튼은 타입 전체에 적용되는 기본 `Button` 스타일만 받는다. `Classes`에는 공백으로 구분해 여러 개의 클래스를 동시에 지정할 수도 있다.

```xml
<Button Content="위험" Classes="accent large" />
```

셀렉터는 이 외에도 다양한 조합을 지원한다. 몇 가지 자주 쓰이는 형태를 소개한다.

```xml
<!-- 컨트롤 타입만 지정 -->
<Style Selector="TextBlock">
    <Setter Property="FontSize" Value="14" />
</Style>

<!-- 클래스만 지정 (컨트롤 타입 무관) -->
<Style Selector=".danger">
    <Setter Property="Foreground" Value="{StaticResource DangerBrush}" />
</Style>

<!-- 의사 클래스(pseudo-class): 마우스가 올라가 있을 때 -->
<Style Selector="Button.accent:pointerover">
    <Setter Property="Background" Value="{StaticResource PrimaryDarkBrush}" />
</Style>

<!-- 특정 컨테이너 안에 있는 컨트롤만 선택 -->
<Style Selector="StackPanel > Button">
    <Setter Property="Margin" Value="0,0,0,4" />
</Style>
```

`:pointerover`처럼 콜론으로 시작하는 항목은 의사 클래스로, 컨트롤의 상태(마우스 오버, 눌림, 비활성화 등)에 따라 다른 스타일을 적용할 때 사용한다. 위 예제는 강조 버튼에 마우스를 올렸을 때 색이 진해지도록 만든다.

## 10.7 종합 예제: 팔레트와 스타일 함께 사용하기

지금까지 배운 리소스와 스타일을 하나의 예제로 합쳐 보자. `App.axaml`에 색상 팔레트를 정의하고, 그 팔레트를 참조하는 버튼 스타일 세 가지(기본, 강조, 위험)를 만든다.

```xml
<!-- App.axaml -->
<Application xmlns="https://github.com/avaloniaui"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             x:Class="AvaloniaGuide.App">
    <Application.Resources>
        <ResourceDictionary>
            <Color x:Key="PrimaryColor">#3F51B5</Color>
            <Color x:Key="AccentColor">#FF4081</Color>
            <Color x:Key="DangerColor">#E53935</Color>

            <SolidColorBrush x:Key="PrimaryBrush" Color="{StaticResource PrimaryColor}" />
            <SolidColorBrush x:Key="AccentBrush" Color="{StaticResource AccentColor}" />
            <SolidColorBrush x:Key="DangerBrush" Color="{StaticResource DangerColor}" />
        </ResourceDictionary>
    </Application.Resources>

    <Application.Styles>
        <FluentTheme />

        <Style Selector="Button">
            <Setter Property="Padding" Value="12,6" />
            <Setter Property="CornerRadius" Value="4" />
        </Style>

        <Style Selector="Button.primary">
            <Setter Property="Background" Value="{StaticResource PrimaryBrush}" />
            <Setter Property="Foreground" Value="White" />
        </Style>

        <Style Selector="Button.accent">
            <Setter Property="Background" Value="{StaticResource AccentBrush}" />
            <Setter Property="Foreground" Value="White" />
        </Style>

        <Style Selector="Button.danger">
            <Setter Property="Background" Value="{StaticResource DangerBrush}" />
            <Setter Property="Foreground" Value="White" />
        </Style>
    </Application.Styles>
</Application>
```

```xml
<!-- MainWindow.axaml -->
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        x:Class="AvaloniaGuide.Views.MainWindow"
        Title="스타일과 리소스" Width="360" Height="160">
    <StackPanel Margin="16" Spacing="8" Orientation="Horizontal">
        <Button Content="저장" Classes="primary" />
        <Button Content="추천" Classes="accent" />
        <Button Content="삭제" Classes="danger" />
    </StackPanel>
</Window>
```

세 버튼 모두 `Application.Styles`에 정의된 `Selector="Button"` 규칙(여백, 모서리)을 공통으로 받으면서, 각자 붙인 `Classes`에 따라 서로 다른 배경색을 갖는다. 색상을 바꾸고 싶다면 `App.axaml`의 `Color` 리소스 세 줄만 고치면 앱 전체의 버튼 색이 함께 바뀐다. 이처럼 리소스와 스타일을 조합하면 "어디에 어떤 값이 쓰였는지"를 일일이 추적하지 않고도 앱의 외관을 일관되게 유지하고 관리할 수 있다.

이 장에서 만든 `Application.Styles`와 `Classes` 조합은 이후 장에서 다룰 내용의 토대가 된다. 11장에서는 `Style` 안에 `Setter`로 단순한 속성값을 지정하는 것을 넘어, 컨트롤의 겉모습 자체를 통째로 새로 정의하는 컨트롤 템플릿을 배운다. 그리고 16장에서는 오늘 배운 `DynamicResource`를 활용해 라이트 테마와 다크 테마의 리소스 딕셔너리를 실행 중에 통째로 교체하는 방법을 다룬다.

## 요약

- 리소스는 색상, 브러시, 크기 같은 값을 한 곳에 이름으로 정의해 두고 여러 곳에서 재사용하는 저장소로, `Window.Resources`, `Application.Resources` 등에 정의한다.
- `{StaticResource ...}`는 로드 시점에 값을 한 번만 해석하며, `{DynamicResource ...}`는 리소스가 바뀔 때마다 값을 다시 반영한다. 후자는 16장에서 다룰 테마 전환의 핵심 도구다.
- 스타일은 `Setter`로 지정한 속성 값의 조합을 여러 컨트롤에 한꺼번에 적용하는 도구이며, `Selector`로 적용 대상을 지정한다.
- `Selector="Button.accent"`처럼 타입과 클래스를 조합하거나, `:pointerover` 같은 의사 클래스를 사용해 상태별 스타일도 지정할 수 있다.
- 컨트롤에 `Classes` 속성으로 이름표를 붙이면 해당 클래스를 대상으로 하는 스타일만 선택적으로 적용받는다.
- 색상 팔레트를 `Application.Resources`에 정의하고 스타일에서 `StaticResource`로 참조하면, 색상 하나를 바꾸는 것만으로 앱 전체의 외관을 일관되게 갱신할 수 있다.

## 연습문제

1. `StaticResource`와 `DynamicResource`의 차이를 해석 시점과 실행 중 변경 반영 여부를 기준으로 설명해 보라. 각각 어떤 상황에 적합한지 예를 들어 보라.
2. `Selector="Button"`과 `Selector=".danger"`, `Selector="Button.danger"`는 각각 어떤 컨트롤을 대상으로 하는지 설명해 보라.
3. `PrimaryColor`, `SecondaryColor`, `SuccessColor`, `WarningColor` 네 가지 색을 가진 팔레트를 `Application.Resources`에 정의하고, 각 색을 배경으로 쓰는 `SolidColorBrush` 리소스와 이를 활용하는 버튼 스타일 네 가지를 작성해 보라.
4. `TextBlock`에 `Classes="title"`을 붙였을 때 큰 글씨와 굵은 글꼴이 적용되도록 스타일을 작성해 보라. `FontSize`와 `FontWeight` 속성을 활용한다.
5. 의사 클래스 `:pointerover`와 `:pressed`를 사용해, 버튼에 마우스를 올렸을 때와 누르고 있을 때 배경색이 단계적으로 달라지도록 스타일을 작성해 보라.
