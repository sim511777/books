# 7장. 벡터와 수학

[◀ 이전: 6장. 입력 처리](ch06-입력처리.md) | [📖 목차](00-목차.md) | [다음: 8장. 텍스처와 스프라이트 애니메이션 ▶](ch08-텍스처와스프라이트애니메이션.md)


지금까지는 게임 오브젝트의 위치를 `X`, `Y` 두 개의 `float` 변수로 따로 다뤄 왔다고 상상해 보자. 위치를 옮기려면 `x += dx; y += dy;`처럼 두 줄을 써야 하고, 속도와 방향을 계산하려면 `Math.Sqrt(dx * dx + dy * dy)` 같은 식을 여기저기서 반복해야 한다. 게임 프로그래밍에서는 위치, 속도, 방향, 힘처럼 "크기와 방향을 함께 가지는 값"이 끊임없이 등장하는데, 이런 값을 숫자 두세 개의 묶음이 아니라 하나의 값으로 다루게 해 주는 것이 바로 벡터(vector)다. MonoGame은 `Microsoft.Xna.Framework` 네임스페이스에 `Vector2`, `Vector3`, `Vector4` 구조체를 제공하며, 2D 게임에서는 그중 `Vector2`를 가장 자주 사용하게 된다.

이번 장에서는 `Vector2`와 `Vector3`의 기본 구조와 연산자, 자주 쓰이는 메서드, 그리고 각도와 삼각함수를 조합해 발사체의 이동 방향을 계산하는 방법까지 살펴본다. 6장에서 입력을 처리해 캐릭터를 움직여 봤다면, 이번 장의 내용은 그 움직임을 훨씬 정돈된 코드로 표현하는 도구가 되어 줄 것이다.

## 7.1 Vector2와 Vector3

`Vector2`는 `X`, `Y` 두 개의 `float` 필드를 가진 구조체(struct)다. 구조체이므로 클래스와 달리 값 타입이며, 변수에 대입하거나 메서드에 전달할 때 참조가 아니라 값 자체가 복사된다.

```csharp
using Microsoft.Xna.Framework;

Vector2 position = new Vector2(100f, 200f);
Vector2 origin = Vector2.Zero;          // (0, 0)
Vector2 unitX = Vector2.UnitX;          // (1, 0)
Vector2 unitY = Vector2.UnitY;          // (0, 1)
Vector2 ones = Vector2.One;             // (1, 1)

float x = position.X; // 100
float y = position.Y; // 200
```

`Vector2.Zero`, `Vector2.One`, `Vector2.UnitX`, `Vector2.UnitY`는 자주 쓰이는 값을 미리 정의해 둔 정적 읽기 전용 속성이다. 2D 게임에서는 화면 위의 한 점을 나타낼 때도, 이동 속도를 나타낼 때도 모두 `Vector2`를 사용한다. 같은 타입이라도 문맥에 따라 "위치"를 뜻할 수도 있고 "이동량"을 뜻할 수도 있다는 점만 기억해 두면 된다.

3D 좌표나 색상, 회전축 등을 다룰 때는 `Vector3`를 사용한다. 구조는 동일하며 `Z` 필드가 하나 더 있을 뿐이다.

```csharp
Vector3 worldPosition = new Vector3(0f, 5f, -10f);
float depth = worldPosition.Z;
```

3D 관련 내용은 13장에서 카메라 및 3D 모델과 함께 본격적으로 다루므로, 이번 장에서는 `Vector2`를 중심으로 설명하고 `Vector3`는 구조가 같다는 정도만 알아 두어도 충분하다.

### 왜 벡터로 표현하는가

캐릭터의 위치와 속도를 각각 `float` 두 개씩, 총 네 개의 변수로 관리한다고 해 보자.

```csharp
float posX = 100f, posY = 100f;
float velX = 50f, velY = -20f;

// 매 프레임 위치 갱신
posX += velX * deltaTime;
posY += velY * deltaTime;
```

변수가 늘어날수록 이런 코드는 금방 지저분해진다. 반면 `Vector2`를 사용하면 위치와 속도라는 개념 자체를 하나의 값으로 다룰 수 있고, 다음 절에서 볼 연산자 오버로딩 덕분에 갱신 코드도 한 줄로 줄어든다.

```csharp
Vector2 position = new Vector2(100f, 100f);
Vector2 velocity = new Vector2(50f, -20f);

position += velocity * deltaTime;
```

코드가 짧아지는 것은 부수적인 효과고, 진짜 이점은 "위치"와 "속도"라는 개념이 코드 안에서도 하나의 이름과 하나의 값으로 존재하게 된다는 데 있다. 함수의 매개변수로 넘기거나, 여러 오브젝트의 위치를 배열에 저장하거나, 두 지점 사이의 거리를 구하는 등 이후에 나올 모든 작업이 훨씬 자연스러워진다.

## 7.2 벡터 연산자

`Vector2`는 `+`, `-`, `*`, `/` 연산자를 오버로딩해 제공한다. 각 연산은 필드별로 이루어진다.

```csharp
Vector2 a = new Vector2(10f, 20f);
Vector2 b = new Vector2(3f, 4f);

Vector2 sum = a + b;        // (13, 24)
Vector2 diff = a - b;       // (7, 16)
Vector2 scaled = a * 2f;    // (20, 40)  스칼라 곱
Vector2 halved = a / 2f;    // (5, 10)   스칼라 나눗셈
Vector2 negated = -a;       // (-10, -20)
```

두 벡터끼리의 곱셈(`a * b`)도 정의되어 있지만, 이는 수학에서 말하는 내적(dot product)이 아니라 `X`끼리, `Y`끼리 각각 곱하는 성분별(component-wise) 곱셈이다. 내적이 필요하면 뒤에서 볼 `Vector2.Dot` 메서드를 따로 사용해야 한다.

게임 루프에서 가장 많이 보게 될 패턴은 "속도에 경과 시간을 곱해 위치에 더하는" 것이다.

```csharp
protected override void Update(GameTime gameTime)
{
    float deltaTime = (float)gameTime.ElapsedGameTime.TotalSeconds;

    position += velocity * deltaTime;

    base.Update(gameTime);
}
```

3장에서 다뤘듯 `deltaTime`을 곱해 주면 프레임률과 무관하게 초당 이동 거리가 일정하게 유지된다. `velocity`의 단위를 "픽셀/초"로 정해 두면 `velocity * deltaTime`은 "이번 프레임 동안 이동한 거리(픽셀)"가 되고, 이를 위치에 더하는 것만으로 등속 이동이 완성된다.

## 7.3 거리, 길이, 정규화

### Vector2.Distance

두 점 사이의 거리는 `Vector2.Distance` 정적 메서드로 구한다.

```csharp
Vector2 player = new Vector2(100f, 100f);
Vector2 enemy = new Vector2(150f, 140f);

float dist = Vector2.Distance(player, enemy);
```

내부적으로는 두 벡터의 차를 구한 뒤 그 길이를 계산하는 것과 같다. 제곱근 계산은 비용이 드는 편이라, 단순히 "거리가 특정 값보다 가까운가"만 비교하고 싶다면 제곱근을 생략한 `Vector2.DistanceSquared`를 사용해 비교 대상 값도 제곱해서 비교하는 편이 더 효율적이다.

```csharp
float triggerRangeSquared = 200f * 200f;
if (Vector2.DistanceSquared(player, enemy) < triggerRangeSquared)
{
    // 200픽셀 이내로 접근했을 때의 처리
}
```

### Length와 정규화(Normalize)

벡터 하나만 놓고 "크기"를 구할 때는 `Length()` 인스턴스 메서드를 쓴다. 이는 원점에서 그 벡터가 가리키는 점까지의 거리, 즉 벡터의 길이다.

```csharp
Vector2 velocity = new Vector2(3f, 4f);
float speed = velocity.Length(); // 5
```

방향은 그대로 유지하면서 길이만 1로 만드는 것을 정규화(normalize)라고 한다. 정규화된 벡터를 단위 벡터(unit vector)라고 부르는데, "방향 정보만 순수하게 담고 있는 벡터"라고 이해하면 된다.

```csharp
Vector2 direction = enemy - player;   // player에서 enemy를 향하는 벡터
direction.Normalize();                // 길이를 1로 만듦 (인스턴스 메서드, 자기 자신을 변경)

float moveSpeed = 120f; // 초당 120픽셀
Vector2 enemyVelocity = direction * moveSpeed;
```

정규화가 필요한 이유는 명확하다. `enemy - player`로 구한 방향 벡터는 두 점이 멀리 떨어져 있을수록 길이도 커진다. 이 벡터에 그대로 속도를 곱하면 거리가 멀수록 더 빨리 움직이는 이상한 결과가 나온다. 정규화로 길이를 1로 고정해 두면, 방향은 유지하면서 속도(스칼라)만 곱해 원하는 빠르기로 움직이게 만들 수 있다.

`Normalize()`는 인스턴스 메서드로, 벡터 자기 자신의 값을 바꾼다는 점에 주의하자. 원본은 그대로 두고 정규화된 새 벡터를 얻고 싶다면 정적 메서드 `Vector2.Normalize`를 사용한다.

```csharp
Vector2 original = new Vector2(3f, 4f);
Vector2 normalized = Vector2.Normalize(original);
// original은 (3, 4) 그대로, normalized는 (0.6, 0.8)
```

길이가 0인 벡터(`Vector2.Zero`)를 정규화하면 0으로 나누는 상황이 되어 `NaN`이 발생한다. 두 지점이 같은 위치일 수 있는 경우라면 정규화 전에 길이가 0인지 검사하는 방어 코드를 넣어 두는 것이 안전하다.

```csharp
Vector2 ToEnemy(Vector2 from, Vector2 to)
{
    Vector2 direction = to - from;
    if (direction == Vector2.Zero)
        return Vector2.Zero;

    direction.Normalize();
    return direction;
}
```

## 7.4 MathHelper

`MathHelper`는 `Microsoft.Xna.Framework` 네임스페이스에 있는 정적 클래스로, 게임에서 자주 필요한 각도 변환, 값 제한, 보간 등을 위한 정적 메서드를 모아 둔다. `System.Math`와 함께 두고 쓰면 편리하다.

### 각도-라디안 변환

.NET의 삼각함수(`Math.Sin`, `Math.Cos` 등)는 모두 라디안 단위를 사용하지만, 사람이 게임 기획이나 디버깅 과정에서 각도를 다룰 때는 도(degree) 단위가 더 직관적이다. `MathHelper.ToRadians`와 `MathHelper.ToDegrees`는 이 둘을 서로 변환해 준다.

```csharp
float degrees = 90f;
float radians = MathHelper.ToRadians(degrees); // 약 1.5708 (π/2)

float backToDegrees = MathHelper.ToDegrees(radians); // 90
```

`MathHelper.Pi`, `MathHelper.TwoPi`, `MathHelper.PiOver2`, `MathHelper.PiOver4` 같은 상수도 함께 제공되므로, 원한다면 `Math.PI`를 직접 쓰는 대신 이 상수들을 사용해도 된다.

### Clamp

`MathHelper.Clamp(value, min, max)`는 값이 지정한 범위를 벗어나지 않도록 잘라 준다. 체력이 음수가 되거나 최대치를 넘지 않게 하는 것처럼, 게임에서 값의 범위를 강제해야 하는 상황은 매우 흔하다.

```csharp
health = MathHelper.Clamp(health - damage, 0f, maxHealth);

// 카메라가 맵 바깥으로 나가지 않도록 위치 제한
cameraPosition.X = MathHelper.Clamp(cameraPosition.X, minX, maxX);
cameraPosition.Y = MathHelper.Clamp(cameraPosition.Y, minY, maxY);
```

`Clamp`는 `float` 외에도 `int`, `double` 등 다양한 오버로드를 제공하므로 정수 값을 다룰 때도 그대로 사용할 수 있다.

### Lerp

`MathHelper.Lerp(value1, value2, amount)`는 선형 보간(linear interpolation)을 수행한다. `amount`가 0이면 `value1`, 1이면 `value2`를 반환하며, 그 사이 값이면 두 값 사이를 비율대로 나눈 값을 반환한다.

```csharp
float start = 0f;
float end = 100f;

float quarter = MathHelper.Lerp(start, end, 0.25f); // 25
float half = MathHelper.Lerp(start, end, 0.5f);     // 50
```

`Lerp`는 부드러운 카메라 이동이나 UI 요소의 자연스러운 등장/퇴장 효과에 자주 쓰인다. 매 프레임 현재 값을 목표 값 쪽으로 조금씩 끌어당기는 패턴을 만들 수 있다.

```csharp
// 카메라가 목표 위치를 부드럽게 뒤쫓아가는 예
float smoothing = 0.1f; // 0에 가까울수록 느리게, 1에 가까울수록 즉시 따라붙음
cameraX = MathHelper.Lerp(cameraX, targetX, smoothing);
```

`Vector2`에도 같은 개념의 `Vector2.Lerp(value1, value2, amount)` 정적 메서드가 있어, `X`와 `Y`를 각각 따로 보간할 필요 없이 벡터 전체를 한 번에 보간할 수 있다.

```csharp
Vector2 smoothedPosition = Vector2.Lerp(currentPosition, targetPosition, 0.1f);
```

`amount`에 1보다 크거나 0보다 작은 값을 넣으면 두 값 범위를 벗어난 외삽(extrapolation) 결과가 나온다는 점도 기억해 두면 디버깅에 도움이 된다.

## 7.5 삼각함수로 발사체 방향 계산하기

각도와 삼각함수를 조합하면 "특정 방향으로 특정 속도로 날아가는" 발사체를 자연스럽게 구현할 수 있다. 기본 아이디어는 각도(라디안)를 코사인과 사인에 넣어 X, Y 방향 성분을 얻고, 여기에 속도(스칼라)를 곱해 속도 벡터를 만드는 것이다.

```csharp
Vector2 DirectionFromAngle(float angleRadians)
{
    float x = (float)Math.Cos(angleRadians);
    float y = (float)Math.Sin(angleRadians);
    return new Vector2(x, y);
}
```

`Math.Cos`와 `Math.Sin`은 `double`을 받아 `double`을 반환하므로, `Vector2`의 필드인 `float`에 대입하려면 명시적으로 형변환해야 한다. 이렇게 얻은 벡터는 이미 길이가 1인 단위 벡터이므로 별도로 정규화할 필요가 없다.

이제 이를 이용해 플레이어가 바라보는 각도로 발사체를 쏘는 예제를 만들어 보자.

```csharp
public class Projectile
{
    public Vector2 Position;
    public Vector2 Velocity;
    public bool IsActive;

    private const float Speed = 400f; // 초당 400픽셀

    public void Fire(Vector2 startPosition, float angleRadians)
    {
        Position = startPosition;

        float dirX = (float)Math.Cos(angleRadians);
        float dirY = (float)Math.Sin(angleRadians);

        Velocity = new Vector2(dirX, dirY) * Speed;
        IsActive = true;
    }

    public void Update(GameTime gameTime)
    {
        if (!IsActive)
            return;

        float deltaTime = (float)gameTime.ElapsedGameTime.TotalSeconds;
        Position += Velocity * deltaTime;
    }
}
```

`angleRadians`가 0이면 코사인이 1, 사인이 0이 되어 오른쪽(+X 방향)으로 날아간다. MonoGame의 화면 좌표계는 Y축이 아래로 갈수록 증가하므로, 각도가 양수 방향(반시계 방향이 아니라 시계 방향)으로 커질수록 발사체는 화면상 아래쪽으로 회전하며 날아간다는 점도 함께 알아 두면 좋다.

두 지점 사이의 각도를 구하고 싶을 때는 `Math.Atan2`를 사용한다. 예를 들어 플레이어에서 마우스 커서를 향해 발사하고 싶다면 다음과 같이 계산한다.

```csharp
Vector2 toTarget = targetPosition - playerPosition;
float angle = (float)Math.Atan2(toTarget.Y, toTarget.X);

projectile.Fire(playerPosition, angle);
```

`Atan2(y, x)`는 X축 양의 방향을 기준으로 한 각도를 라디안 단위로 반환하며, 두 값의 부호를 함께 고려하기 때문에 `Atan(y / x)`와 달리 네 사분면 전체에서 올바른 각도를 계산해 준다.

각도 대신 방향 벡터가 이미 있는 경우에는 삼각함수 없이 정규화만으로도 같은 결과를 얻을 수 있다.

```csharp
Vector2 direction = targetPosition - playerPosition;
direction.Normalize();

projectile.Position = playerPosition;
projectile.Velocity = direction * Speed;
```

두 방식 모두 결과는 동일하다. 회전 각도 자체를 게임 로직에서 사용해야 한다면(예: 발사체 스프라이트를 회전시켜 그려야 하는 경우) `Atan2`로 각도를 구해 두는 편이 유리하고, 방향만 필요하다면 벡터 뺄셈과 정규화만으로 충분하다. 스프라이트를 실제로 회전시켜 그리는 방법은 8장에서 `SpriteBatch.Draw`의 회전 매개변수와 함께 다시 다룬다.

## 요약

- `Vector2`(`X`, `Y`)와 `Vector3`(`X`, `Y`, `Z`)는 위치, 속도, 방향처럼 크기와 방향을 함께 갖는 값을 하나의 단위로 다루게 해 주는 구조체다.
- `+`, `-`, `*`, `/` 연산자가 오버로딩되어 있어 `position += velocity * deltaTime`처럼 벡터 연산을 자연스러운 수식으로 표현할 수 있다.
- `Vector2.Distance`는 두 점 사이의 거리를, `Length()`는 벡터 자신의 크기를 구한다. 거리 비교만 필요하다면 제곱근 계산을 생략하는 `DistanceSquared`가 더 효율적이다.
- 정규화(`Normalize`)는 방향은 유지한 채 길이를 1로 만드는 연산으로, 방향 벡터에 원하는 속도를 곱해 등속으로 움직이려 할 때 반드시 필요하다.
- `MathHelper`는 `ToRadians`/`ToDegrees`(각도 변환), `Clamp`(범위 제한), `Lerp`(선형 보간) 등 게임에서 자주 쓰이는 수학 유틸리티를 정적 메서드로 제공한다.
- `Math.Cos`/`Math.Sin`에 라디안 각도를 넣어 방향 벡터를 만들고 속도를 곱하면 특정 방향으로 날아가는 발사체를 구현할 수 있으며, 반대로 두 지점 사이의 각도는 `Math.Atan2(dy, dx)`로 구한다.

## 연습문제

1. `Vector2 a = new Vector2(6, 8)`일 때 `a.Length()`의 값을 손으로 계산해 보고, 코드로 확인해 보자. 이 벡터를 정규화한 결과는 어떤 값이 되는가?
2. 플레이어 위치와 목표 위치가 주어졌을 때, `Vector2.DistanceSquared`를 이용해 "목표가 100픽셀 이내에 있는가"를 판정하는 메서드 `bool IsNear(Vector2 a, Vector2 b, float range)`를 작성해 보자. 제곱근을 직접 호출하지 않아야 한다.
3. `MathHelper.Lerp`를 이용해 체력바의 표시 값이 실제 체력 값을 향해 매 프레임 부드럽게 따라가도록(즉시 반영되지 않고 서서히 변하도록) 만드는 코드를 작성해 보자.
4. 화면 중앙에서 매 프레임 일정한 각도씩 회전하며 발사체를 하나씩 쏘는 "탄막" 패턴을 만들어 보자. 현재 각도를 라디안으로 누적시키고, `Math.Cos`/`Math.Sin`으로 방향을 구해 발사체를 생성하면 된다.
5. 두 오브젝트 `a`, `b`의 위치가 주어졌을 때, `a`가 `b`를 향해 회전해야 할 각도를 `Math.Atan2`로 구하고, 이를 `MathHelper.ToDegrees`로 변환해 도(degree) 단위로 출력해 보자.
