# 8장. 텍스처와 스프라이트 애니메이션

[◀ 이전: 7장. 벡터와 수학](ch07-벡터와수학.md) | [📖 목차](00-목차.md) | [다음: 9장. 충돌 감지 ▶](ch09-충돌감지.md)


4장에서는 콘텐츠 파이프라인을 통해 이미지 파일을 `Texture2D`로 불러오는 방법을, 5장에서는 `SpriteBatch.Draw`로 그 텍스처를 화면에 그리는 방법을 배웠다. 지금까지 사용한 `Draw` 호출은 텍스처 전체를 그대로 그리는 방식이었다. 하지만 실제 게임에서는 캐릭터가 걷고, 뛰고, 공격하는 여러 동작을 표현해야 하고, 이를 위해 하나의 이미지 파일 안에 여러 장의 그림(프레임)을 담아 두고 필요한 부분만 잘라서 그리는 기법을 사용한다.

이번 장에서는 텍스처의 일부 영역만 그리는 `sourceRectangle` 매개변수를 중심으로, 스프라이트 시트 개념과 프레임 전환 타이머, 그리고 좌우 반전까지 스프라이트 애니메이션에 필요한 요소를 하나씩 살펴본다.

## 8.1 복습: 텍스처 로드와 SpriteBatch.Draw

먼저 지금까지 배운 내용을 짧게 복습하자. `LoadContent`에서 `Content.Load<Texture2D>`로 텍스처를 불러오고, `Draw`에서 `SpriteBatch.Begin`/`End` 사이에 그리는 것이 기본 흐름이었다.

```csharp
private Texture2D _playerTexture;
private Vector2 _position = new Vector2(100f, 100f);

protected override void LoadContent()
{
    _spriteBatch = new SpriteBatch(GraphicsDevice);
    _playerTexture = Content.Load<Texture2D>("player");
}

protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.CornflowerBlue);

    _spriteBatch.Begin();
    _spriteBatch.Draw(_playerTexture, _position, Color.White);
    _spriteBatch.End();

    base.Draw(gameTime);
}
```

이 코드는 `_playerTexture`에 담긴 이미지 전체를 `_position` 위치에 그린다. 만약 `player.png` 파일이 캐릭터 한 장만 담고 있다면 이걸로 충분하지만, 걷는 동작을 표현하려면 캐릭터가 여러 자세를 취한 프레임 여러 장이 필요하고, 매 프레임 그중 하나만 골라서 그려야 한다. 이를 가능하게 하는 것이 `SpriteBatch.Draw`의 `sourceRectangle` 매개변수다.

## 8.2 sourceRectangle: 텍스처 일부만 그리기

`SpriteBatch.Draw`에는 여러 오버로드가 있는데, 그중 `Rectangle?` 타입의 `sourceRectangle` 매개변수를 받는 형태를 사용하면 텍스처 전체가 아니라 지정한 사각형 영역만 잘라서 그릴 수 있다.

```csharp
public void Draw(
    Texture2D texture,
    Vector2 position,
    Rectangle? sourceRectangle,
    Color color
);
```

`sourceRectangle`은 텍스처 내부의 픽셀 좌표를 기준으로 한 `Rectangle`이다. `Rectangle`은 `X`, `Y`, `Width`, `Height` 네 개의 `int` 필드를 가진 구조체로, `(X, Y)`는 잘라낼 영역의 왼쪽 위 모서리, `Width`와 `Height`는 그 영역의 가로세로 크기를 픽셀 단위로 나타낸다.

```csharp
// player.png가 가로로 4프레임(각 64x64)이 나열된 이미지라고 가정
Rectangle sourceRect = new Rectangle(0, 0, 64, 64);   // 첫 번째 프레임

_spriteBatch.Draw(_playerTexture, _position, sourceRect, Color.White);
```

`X`를 프레임 너비만큼씩 옮겨 가면 다음 프레임을 가리킬 수 있다.

```csharp
Rectangle secondFrame = new Rectangle(64, 0, 64, 64);  // 두 번째 프레임
Rectangle thirdFrame = new Rectangle(128, 0, 64, 64);  // 세 번째 프레임
```

`sourceRectangle`을 `null`로 넘기면(또는 이 매개변수 자체가 없는 오버로드를 쓰면) 텍스처 전체를 그리는 것과 동일하게 동작한다. 지금까지 써 온 `Draw(texture, position, color)` 형태는 사실 `sourceRectangle`에 `null`을 넘긴 것과 같다고 생각하면 된다.

여기서 중요한 점 하나는, `sourceRectangle`이 텍스처의 "원본 이미지 안에서 자를 위치"를 정할 뿐, 화면에 그려지는 크기나 위치와는 무관하다는 것이다. 화면 위 위치는 여전히 `position` 매개변수가 결정하며, 잘라낸 영역은 기본적으로 원본 픽셀 크기 그대로 그려진다(크기를 바꾸려면 별도의 `scale` 매개변수가 있는 오버로드를 사용해야 하는데, 이는 12장에서 카메라 변환과 함께 다시 다룬다).

## 8.3 스프라이트 시트와 프레임 계산

여러 장의 그림을 하나의 이미지 파일에 격자 형태로 배치한 것을 스프라이트 시트(sprite sheet)라고 부른다. 예를 들어 캐릭터가 걷는 동작을 4프레임으로 표현한다면, `player_walk.png`라는 하나의 파일 안에 64×64 크기의 프레임 4개를 가로로 나란히 배치해 두는 식이다. 이렇게 하면 텍스처 로드 호출을 프레임 수만큼 반복할 필요 없이 이미지 파일 하나만 불러오면 되고, `GraphicsDevice`에 텍스처를 전환하는 비용도 줄어든다.

스프라이트 시트에서 몇 번째 프레임인지(인덱스)만 알면 `sourceRectangle`을 계산으로 구할 수 있다.

```csharp
private const int FrameWidth = 64;
private const int FrameHeight = 64;
private const int FrameCount = 4;

private Rectangle GetSourceRectangle(int frameIndex)
{
    return new Rectangle(
        frameIndex * FrameWidth,
        0,
        FrameWidth,
        FrameHeight
    );
}
```

프레임이 한 줄로 다 들어가지 않고 여러 행에 걸쳐 배치되는 경우(예: 가로 4프레임씩 3줄, 총 12프레임)에는 행과 열을 함께 계산한다.

```csharp
private const int Columns = 4;

private Rectangle GetSourceRectangle(int frameIndex)
{
    int column = frameIndex % Columns;
    int row = frameIndex / Columns;

    return new Rectangle(
        column * FrameWidth,
        row * FrameHeight,
        FrameWidth,
        FrameHeight
    );
}
```

이처럼 프레임 인덱스 하나만 관리하면 `sourceRectangle` 계산은 항상 같은 공식으로 처리할 수 있다. 이제 필요한 것은 이 인덱스를 시간에 따라 자동으로 바꿔 주는 타이머다.

## 8.4 GameTime을 이용한 프레임 전환 타이머

애니메이션은 결국 "일정 시간마다 다음 프레임으로 넘어가는" 반복이다. 3장에서 다룬 `GameTime.ElapsedGameTime`을 이용해 경과 시간을 누적하고, 누적 시간이 한 프레임의 지속 시간을 넘어설 때마다 프레임 인덱스를 하나씩 진행시키는 방식으로 구현한다.

```csharp
public class SpriteAnimation
{
    private readonly Rectangle[] _frames;
    private readonly float _frameTime; // 한 프레임을 유지할 시간(초)

    private int _currentFrame;
    private float _timer;

    public SpriteAnimation(Rectangle[] frames, float frameTime)
    {
        _frames = frames;
        _frameTime = frameTime;
    }

    public Rectangle CurrentFrame => _frames[_currentFrame];

    public void Update(GameTime gameTime)
    {
        _timer += (float)gameTime.ElapsedGameTime.TotalSeconds;

        if (_timer >= _frameTime)
        {
            _timer -= _frameTime;
            _currentFrame = (_currentFrame + 1) % _frames.Length;
        }
    }

    public void Reset()
    {
        _currentFrame = 0;
        _timer = 0f;
    }
}
```

핵심은 두 부분이다. 첫째, `_timer -= _frameTime`처럼 타이머를 0으로 초기화하지 않고 초과분을 빼는 방식으로 처리하면, 한 프레임이 너무 오래 걸려 `_timer`가 `_frameTime`을 두 배 이상 넘어서더라도 시간이 누락되지 않는다(다만 프레임이 여러 번 밀린 경우 이 코드는 한 번에 한 프레임씩만 진행한다는 점은 알아 두자. 극단적으로 느린 환경이 아니라면 실용적으로 충분하다). 둘째, `(_currentFrame + 1) % _frames.Length`로 나머지 연산을 사용해 마지막 프레임 다음에는 다시 첫 프레임으로 돌아가도록(순환) 만든다.

이 클래스를 게임 오브젝트에서 사용하는 예는 다음과 같다.

```csharp
private Texture2D _walkTexture;
private SpriteAnimation _walkAnimation;
private Vector2 _position = new Vector2(100f, 100f);

protected override void LoadContent()
{
    _spriteBatch = new SpriteBatch(GraphicsDevice);
    _walkTexture = Content.Load<Texture2D>("player_walk");

    Rectangle[] frames = new Rectangle[4];
    for (int i = 0; i < frames.Length; i++)
    {
        frames[i] = new Rectangle(i * 64, 0, 64, 64);
    }

    // 프레임당 0.15초, 즉 초당 약 6.7프레임 속도로 재생
    _walkAnimation = new SpriteAnimation(frames, 0.15f);
}

protected override void Update(GameTime gameTime)
{
    _walkAnimation.Update(gameTime);

    base.Update(gameTime);
}

protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.CornflowerBlue);

    _spriteBatch.Begin();
    _spriteBatch.Draw(
        _walkTexture,
        _position,
        _walkAnimation.CurrentFrame,
        Color.White
    );
    _spriteBatch.End();

    base.Draw(gameTime);
}
```

`Update`에서는 애니메이션 타이머만 갱신하고, `Draw`에서는 `_walkAnimation.CurrentFrame`이 가리키는 `Rectangle`을 `sourceRectangle`로 그대로 넘기기만 하면 된다. 애니메이션 로직과 그리기 로직이 분리되어 있어, 나중에 캐릭터가 뛰는 애니메이션이나 공격 애니메이션을 추가할 때도 같은 `SpriteAnimation` 클래스를 재사용해 프레임 배열과 재생 속도만 다르게 넘기면 된다.

```csharp
Rectangle[] idleFrames = BuildFrames(row: 0, count: 2);
Rectangle[] walkFrames = BuildFrames(row: 1, count: 4);
Rectangle[] attackFrames = BuildFrames(row: 2, count: 6);

var idleAnimation = new SpriteAnimation(idleFrames, 0.4f);
var walkAnimation = new SpriteAnimation(walkFrames, 0.12f);
var attackAnimation = new SpriteAnimation(attackFrames, 0.08f);
```

이렇게 애니메이션별로 인스턴스를 만들어 두고, 캐릭터의 현재 상태(대기, 이동, 공격)에 따라 어떤 `SpriteAnimation`을 갱신하고 그릴지 골라 쓰는 방식은 14장에서 다룰 게임 상태 관리와도 자연스럽게 이어지는 패턴이다.

## 8.5 SpriteEffects.FlipHorizontally: 좌우 반전

캐릭터가 왼쪽으로 이동할 때와 오른쪽으로 이동할 때 서로 다른 스프라이트 시트를 따로 준비하는 것은 낭비다. 보통은 한쪽 방향(예: 오른쪽을 바라보는 프레임)만 그려 두고, 반대 방향으로 이동할 때는 같은 텍스처를 좌우로 뒤집어서 그린다. 다른 프레임워크, 예를 들어 raylib 계열에서는 소스 사각형의 너비에 음수 값을 넣어 뒤집는 트릭을 쓰기도 하지만, MonoGame은 이런 암묵적인 트릭 대신 `SpriteEffects`라는 열거형을 통해 반전 여부를 명시적으로 지정하도록 설계되어 있다.

`SpriteEffects`는 `None`, `FlipHorizontally`, `FlipVertically` 값을 가지며, 이를 사용하려면 이 값들을 매개변수로 받는 `SpriteBatch.Draw` 오버로드를 사용해야 한다.

```csharp
public void Draw(
    Texture2D texture,
    Vector2 position,
    Rectangle? sourceRectangle,
    Color color,
    float rotation,
    Vector2 origin,
    float scale,
    SpriteEffects effects,
    float layerDepth
);
```

매개변수가 많아 보이지만, 지금 당장 필요한 값 외에는 무난한 기본값을 넣으면 된다. `rotation`은 라디안 단위 회전각(0이면 회전 없음), `origin`은 회전과 위치 기준점이 되는 텍스처 내부 좌표(보통 `Vector2.Zero` 또는 프레임 중심), `scale`은 확대/축소 배율(1이면 원본 크기), `layerDepth`는 그리기 순서를 정하는 깊이 값(0~1 사이, 5장에서 다룬 `SpriteSortMode`와 함께 쓰인다)이다.

```csharp
private bool _facingLeft;

protected override void Update(GameTime gameTime)
{
    KeyboardState keyboard = Keyboard.GetState();
    float deltaTime = (float)gameTime.ElapsedGameTime.TotalSeconds;

    if (keyboard.IsKeyDown(Keys.Left))
    {
        _position.X -= 150f * deltaTime;
        _facingLeft = true;
    }
    else if (keyboard.IsKeyDown(Keys.Right))
    {
        _position.X += 150f * deltaTime;
        _facingLeft = false;
    }

    _walkAnimation.Update(gameTime);

    base.Update(gameTime);
}

protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.CornflowerBlue);

    SpriteEffects effects = _facingLeft
        ? SpriteEffects.FlipHorizontally
        : SpriteEffects.None;

    _spriteBatch.Begin();
    _spriteBatch.Draw(
        _walkTexture,
        _position,
        _walkAnimation.CurrentFrame,
        Color.White,
        0f,               // rotation
        Vector2.Zero,     // origin
        1f,               // scale
        effects,
        0f                // layerDepth
    );
    _spriteBatch.End();

    base.Draw(gameTime);
}
```

원본 스프라이트 시트가 오른쪽을 바라보는 캐릭터로 그려져 있다고 가정하면, 왼쪽 키를 누르는 동안에는 `_facingLeft`가 `true`가 되어 `SpriteEffects.FlipHorizontally`가 적용되고, 같은 프레임 데이터를 좌우로 뒤집어 그려서 캐릭터가 왼쪽을 보는 것처럼 표현된다. 프레임 인덱스나 `sourceRectangle` 계산은 전혀 건드릴 필요가 없다는 점이 이 방식의 장점이다. 반전은 순수하게 그리기 단계에서만 처리되는 옵션이므로, 애니메이션 로직(어떤 프레임을 보여줄지)과 방향 로직(어느 쪽을 보여줄지)이 서로 간섭하지 않고 깔끔하게 분리된다.

음수 크기로 반전을 표현하는 방식과 비교하면 이 차이가 더 뚜렷하다. 음수 너비/높이 방식은 사각형의 크기 자체를 부호로 오버로딩해 반전이라는 의미를 부여하지만, MonoGame의 `SpriteEffects`는 "이 프레임을 어떻게 뒤집어 그릴지"를 별도의 열거형 값으로 명시한다. 코드를 읽을 때 `sourceRectangle`은 언제나 "잘라낼 영역"만을 뜻하고, 반전 여부는 `effects` 인자만 보면 바로 알 수 있어 의도가 더 분명하게 드러난다.

## 요약

- `SpriteBatch.Draw`에 `Rectangle?` 타입의 `sourceRectangle`을 넘기면 텍스처 전체가 아니라 그 안의 특정 영역만 잘라서 그릴 수 있다. `null`을 넘기면 텍스처 전체를 그리는 것과 같다.
- 여러 프레임을 하나의 이미지에 격자로 배치한 것을 스프라이트 시트라고 하며, 프레임 인덱스로부터 `Rectangle`을 계산하는 공식(`열 * 프레임너비, 행 * 프레임높이, 프레임너비, 프레임높이`)만 정해 두면 어떤 프레임이든 잘라낼 수 있다.
- `GameTime.ElapsedGameTime`으로 경과 시간을 누적하고, 누적 시간이 프레임 지속 시간을 넘을 때마다 나머지 연산(`% frames.Length`)으로 다음 프레임으로 순환시키는 것이 프레임 전환 타이머의 기본 패턴이다.
- `SpriteEffects.FlipHorizontally`(또는 `FlipVertically`)를 `SpriteBatch.Draw`에 넘기면 같은 텍스처와 같은 `sourceRectangle`을 반전해서 그릴 수 있다. 이는 음수 크기로 반전을 흉내 내는 방식과 달리, 반전 여부를 별도의 명시적인 플래그로 표현하는 MonoGame 고유의 접근 방식이다.

3. 걷기 애니메이션(4프레임)과 대기 애니메이션(2프레임)을 각각 `SpriteAnimation` 인스턴스로 만들고, 키보드 입력 여부에 따라 두 애니메이션 중 하나를 골라 `Update`와 `Draw`에서 사용하도록 캐릭터 클래스를 작성해 보자. 애니메이션을 전환할 때 프레임 인덱스가 이상하게 튀지 않도록 `Reset()`을 언제 호출해야 할지도 고민해 보자.
4. `SpriteEffects.FlipVertically`를 이용해 캐릭터가 천장에 붙어 있는 것처럼 상하로 뒤집어 그리는 효과를 실험해 보자. `origin` 매개변수 값을 프레임의 중앙(예: `new Vector2(32, 32)`)으로 바꾸면 반전 결과가 어떻게 달라지는지도 관찰해 보자.
