# 6장. 입력 처리

[◀ 이전: 5장. SpriteBatch와 2D 그리기](ch05-SpriteBatch와2D그리기.md) | [📖 목차](00-목차.md) | [다음: 7장. 벡터와 수학 ▶](ch07-벡터와수학.md)


게임을 게임답게 만드는 것은 결국 플레이어의 입력에 반응하는 것입니다. 이번 장에서는 MonoGame이 키보드, 마우스, 게임패드 입력을 어떤 방식으로 다루는지 살펴보고, 이를 이용해 3장에서 배운 델타타임과 결합하여 스프라이트를 움직이는 실전 예제까지 만들어보겠습니다.

## 폴링 방식의 입력 처리

윈도우 프로그래밍이나 웹 프론트엔드에 익숙하다면 입력을 이벤트 콜백(예: `onKeyDown`, `onClick`)으로 처리하는 방식이 먼저 떠오를 수 있습니다. 키를 누르는 순간 이벤트가 발생하고, 등록해둔 콜백 함수가 호출되는 방식입니다.

MonoGame은 이와 다른 철학을 갖고 있습니다. 이벤트가 발생하기를 기다리는 대신, 매 프레임 `Update()`가 호출될 때마다 "지금 이 순간 입력 장치가 어떤 상태인가"를 통째로 스냅샷 형태로 가져옵니다. 이런 방식을 폴링(polling)이라고 부릅니다.

키보드, 마우스, 게임패드는 각각 `Keyboard.GetState()`, `Mouse.GetState()`, `GamePad.GetState()`라는 정적 메서드를 제공하며, 이 메서드들은 호출하는 순간의 입력 상태를 담은 구조체(`KeyboardState`, `MouseState`, `GamePadState`)를 반환합니다. 이 구조체는 불변의 스냅샷이므로, 한 프레임 안에서 여러 번 조회해도 항상 같은 값을 돌려줍니다.

폴링 방식의 장점은 게임 루프와 자연스럽게 맞아떨어진다는 점입니다. "이번 프레임에 캐릭터를 얼마나 움직여야 하는가?"라는 질문에 답하기 위해서는 결국 "지금 어떤 키가 눌려 있는가?"를 알아야 하는데, 이는 이벤트 큐를 뒤지는 것보다 상태를 한 번 물어보는 쪽이 훨씬 직관적입니다. 대신 "키를 누르는 순간"이나 "떼는 순간"처럼 순간적인 이벤트를 감지하려면, 이전 프레임의 상태와 현재 프레임의 상태를 직접 비교하는 관용적인 패턴이 필요합니다. 이 패턴은 뒤에서 자세히 다루겠습니다.

## 키보드 입력

키보드 상태는 `Keyboard.GetState()`로 얻습니다.

```csharp
KeyboardState state = Keyboard.GetState();

if (state.IsKeyDown(Keys.Right))
{
    // 오른쪽 방향키가 눌려 있는 동안 계속 실행된다.
}
```

`KeyboardState`는 `IsKeyDown(Keys key)`와 `IsKeyUp(Keys key)` 메서드를 제공합니다. `Keys`는 `Keys.Right`, `Keys.Left`, `Keys.Up`, `Keys.Down`, `Keys.Space`, `Keys.Escape`, `Keys.A`부터 `Keys.Z`까지 키보드의 물리적인 키를 나타내는 열거형입니다.

`IsKeyDown()`은 해당 키가 지금 눌려 있는 상태인지를 반환할 뿐, "방금 눌렸는지"는 알려주지 않습니다. 키를 누르고 있는 동안에는 매 프레임 계속 `true`를 반환하기 때문에, 예를 들어 이 값을 그대로 점프 동작에 사용하면 키를 누르고 있는 동안 계속 점프하려고 시도하는 문제가 생길 수 있습니다.

### 방금 눌렸는지 판별하기

"이번 프레임에 막 눌렸는지"를 알아내려면, 현재 프레임의 상태와 바로 이전 프레임의 상태를 비교해야 합니다. 조건은 다음과 같습니다.

- 현재 프레임에서 `IsKeyDown(key)`가 `true`이고
- 이전 프레임에서는 `IsKeyDown(key)`가 `false`였다면

바로 이번 프레임에 그 키가 처음 눌린 것입니다. 이를 구현하려면 이전 프레임의 `KeyboardState`를 필드로 저장해두어야 합니다.

```csharp
public class Game1 : Game
{
    private KeyboardState _previousKeyboardState;

    protected override void Update(GameTime gameTime)
    {
        KeyboardState currentKeyboardState = Keyboard.GetState();

        if (currentKeyboardState.IsKeyDown(Keys.Space) &&
            !_previousKeyboardState.IsKeyDown(Keys.Space))
        {
            // 스페이스바가 이번 프레임에 막 눌렸다.
            Jump();
        }

        // 반드시 Update의 마지막에 현재 상태를 저장해서
        // 다음 프레임에서 "이전 상태"로 사용할 수 있게 한다.
        _previousKeyboardState = currentKeyboardState;

        base.Update(gameTime);
    }
}
```

이 패턴에서 가장 중요한 점은 `_previousKeyboardState = currentKeyboardState;`를 `Update()`의 맨 마지막에 호출해야 한다는 것입니다. 만약 이 코드를 `Update()` 도중에 호출하면, 그 이후에 실행되는 로직은 이미 갱신된 "이전 상태"를 이전 상태로 잘못 사용하게 됩니다. `KeyboardState`는 값 타입(구조체)이므로 대입할 때 복사가 일어나며, 이후 `Keyboard.GetState()`를 다시 호출해도 이미 저장해둔 `_previousKeyboardState`는 변하지 않습니다.

같은 방식으로 "방금 뗐는지"도 판별할 수 있습니다. 조건만 반대로 하면 됩니다.

```csharp
bool justReleased = _previousKeyboardState.IsKeyDown(Keys.Space) &&
                     currentKeyboardState.IsKeyUp(Keys.Space);
```

## 마우스 입력

마우스 상태는 `Mouse.GetState()`로 얻습니다.

```csharp
MouseState mouseState = Mouse.GetState();

Point mousePosition = mouseState.Position;

if (mouseState.LeftButton == ButtonState.Pressed)
{
    // 왼쪽 버튼이 눌려 있다.
}
```

`MouseState.Position`은 게임 창 좌상단을 기준으로 한 마우스 커서의 픽셀 좌표를 `Point` 타입으로 담고 있습니다. `X`, `Y` 프로퍼티로 각 좌표에 개별적으로 접근할 수도 있습니다. `Vector2`로 변환해야 하는 경우 `mousePosition.ToVector2()`를 사용하면 됩니다.

마우스 버튼 상태는 `bool`이 아니라 `ButtonState` 열거형(`ButtonState.Pressed` 또는 `ButtonState.Released`)으로 표현됩니다. `LeftButton`, `RightButton`, `MiddleButton` 외에도 `XButton1`, `XButton2`(사이드 버튼)를 지원합니다. 키보드와 마찬가지로 "클릭한 순간"을 판별하려면 이전 프레임의 `MouseState`를 저장해두고 비교하는 동일한 패턴을 사용합니다.

```csharp
bool leftClickedThisFrame =
    mouseState.LeftButton == ButtonState.Pressed &&
    _previousMouseState.LeftButton == ButtonState.Released;
```

휠 스크롤 양은 `mouseState.ScrollWheelValue`로 확인할 수 있는데, 이 값은 누적값이므로 "이번 프레임에 얼마나 스크롤했는가"를 알려면 역시 이전 프레임 값과의 차이를 계산해야 합니다.

## 게임패드 입력

게임패드 상태는 `GamePad.GetState()`로 얻습니다. 이때 어느 플레이어의 컨트롤러인지 `PlayerIndex`로 지정해야 합니다.

```csharp
GamePadState gamePadState = GamePad.GetState(PlayerIndex.One);

if (gamePadState.IsConnected)
{
    Vector2 leftStick = gamePadState.ThumbSticks.Left;

    if (gamePadState.Buttons.A == ButtonState.Pressed)
    {
        // A 버튼이 눌려 있다.
    }
}
```

`PlayerIndex`는 `One`부터 `Four`까지 있어 최대 네 개의 컨트롤러를 구분할 수 있습니다. 컨트롤러가 연결되어 있지 않을 때 `GetState()`를 호출해도 예외가 발생하지는 않지만, 반환된 `GamePadState`의 값들은 의미가 없으므로 반드시 `IsConnected` 프로퍼티로 연결 여부를 먼저 확인하는 것이 안전합니다.

`ThumbSticks.Left`와 `ThumbSticks.Right`는 아날로그 스틱의 기울어진 정도를 `Vector2`로 반환합니다. 각 성분은 -1.0f에서 1.0f 사이의 값을 가지며, 오른쪽/위쪽이 양수 방향입니다. 스틱을 전혀 건드리지 않아도 미세한 값이 감지되는 경우가 있는데(스틱 드리프트), 이런 잡음을 걸러내기 위해 일정 크기 이하의 입력은 무시하는 데드존(dead zone) 처리를 함께 적용하는 것이 일반적입니다.

```csharp
Vector2 leftStick = gamePadState.ThumbSticks.Left;
if (leftStick.LengthSquared() < 0.01f)
{
    leftStick = Vector2.Zero;
}
```

버튼은 `gamePadState.Buttons.A`, `.B`, `.X`, `.Y`, `.Start`, `.Back` 등으로 접근하며, 마우스 버튼과 마찬가지로 `ButtonState.Pressed`/`Released` 값을 가집니다. 트리거(`Triggers.Left`, `Triggers.Right`)는 눌림 정도를 0.0f에서 1.0f 사이의 `float` 값으로 제공합니다. "방금 눌렸는지" 판별 패턴은 키보드, 마우스와 완전히 동일하게 이전 프레임의 `GamePadState`를 저장해서 비교하면 됩니다.

## 실전 예제: 키보드로 스프라이트 움직이기

이제 지금까지 배운 내용을 3장의 델타타임과 결합해서, 방향키로 스프라이트를 상하좌우로 이동시키는 예제를 만들어보겠습니다. 3장에서 다뤘듯이 이동 거리는 프레임 속도에 관계없이 일정하게 유지되어야 하므로, 초당 이동 속도에 `gameTime.ElapsedGameTime.TotalSeconds`를 곱해서 사용합니다.

```csharp
public class Game1 : Game
{
    private GraphicsDeviceManager _graphics;
    private SpriteBatch _spriteBatch;
    private Texture2D _playerTexture;

    private Vector2 _playerPosition;
    private const float MoveSpeed = 200f; // 초당 이동 속도 (픽셀/초)

    private KeyboardState _previousKeyboardState;

    public Game1()
    {
        _graphics = new GraphicsDeviceManager(this);
        Content.RootDirectory = "Content";
    }

    protected override void LoadContent()
    {
        _spriteBatch = new SpriteBatch(GraphicsDevice);
        _playerTexture = Content.Load<Texture2D>("player");

        _playerPosition = new Vector2(
            GraphicsDevice.Viewport.Width / 2f,
            GraphicsDevice.Viewport.Height / 2f);
    }

    protected override void Update(GameTime gameTime)
    {
        KeyboardState currentKeyboardState = Keyboard.GetState();
        float deltaTime = (float)gameTime.ElapsedGameTime.TotalSeconds;

        Vector2 direction = Vector2.Zero;

        if (currentKeyboardState.IsKeyDown(Keys.Right))
        {
            direction.X += 1f;
        }
        if (currentKeyboardState.IsKeyDown(Keys.Left))
        {
            direction.X -= 1f;
        }
        if (currentKeyboardState.IsKeyDown(Keys.Down))
        {
            direction.Y += 1f;
        }
        if (currentKeyboardState.IsKeyDown(Keys.Up))
        {
            direction.Y -= 1f;
        }

        if (direction != Vector2.Zero)
        {
            direction.Normalize();
            _playerPosition += direction * MoveSpeed * deltaTime;
        }

        // Esc 키를 방금 눌렀을 때만 게임을 종료한다.
        if (currentKeyboardState.IsKeyDown(Keys.Escape) &&
            !_previousKeyboardState.IsKeyDown(Keys.Escape))
        {
            Exit();
        }

        _previousKeyboardState = currentKeyboardState;

        base.Update(gameTime);
    }

    protected override void Draw(GameTime gameTime)
    {
        GraphicsDevice.Clear(Color.CornflowerBlue);

        _spriteBatch.Begin();
        _spriteBatch.Draw(_playerTexture, _playerPosition, Color.White);
        _spriteBatch.End();

        base.Draw(gameTime);
    }
}
```

이 예제에서 몇 가지 눈여겨볼 부분이 있습니다.

첫째, 네 방향키의 상태를 각각 확인해서 `direction` 벡터에 누적합니다. 이렇게 하면 위쪽과 오른쪽 방향키를 동시에 누를 때 자연스럽게 대각선 방향(`(1, -1)`)이 만들어집니다.

둘째, `direction.Normalize()`를 호출하는 이유는 대각선 이동 시 벡터의 길이가 `1`이 아니라 `√2`(약 1.41)가 되어, 대각선으로 이동할 때 상하좌우로만 이동할 때보다 더 빨리 움직이는 문제를 막기 위해서입니다. 정규화를 통해 어느 방향으로 움직이든 이동 속도는 항상 `MoveSpeed`로 일정하게 유지됩니다. 벡터 정규화에 대한 자세한 내용은 7장에서 다룹니다.

셋째, 이동 로직에는 `IsKeyDown()`을 그대로 사용해서 키를 누르고 있는 동안 계속 이동하도록 했지만, 게임 종료 로직에는 이전 프레임과 비교하는 패턴을 사용해서 Esc 키를 누르는 "그 순간"에만 한 번 실행되도록 했습니다. 이처럼 같은 `Update()` 메서드 안에서도 지속적인 입력(이동, 조준)과 순간적인 입력(점프, 메뉴 열기, 발사)을 서로 다른 방식으로 처리하는 것이 일반적입니다.

## 요약

- MonoGame은 이벤트 콜백이 아니라 폴링 방식으로 입력을 처리한다. `Update()`가 호출될 때마다 `Keyboard.GetState()`, `Mouse.GetState()`, `GamePad.GetState()`로 현재 입력 상태의 스냅샷을 가져온다.
- 키보드는 `KeyboardState.IsKeyDown(Keys key)`로 눌림 여부를 확인한다. "방금 눌렸는지" 판별하려면 이전 프레임의 `KeyboardState`를 필드에 저장해두고 현재 상태와 비교해야 하며, 저장은 반드시 `Update()`의 마지막에 해야 한다.
- 마우스는 `MouseState.Position`으로 좌표를, `LeftButton == ButtonState.Pressed`처럼 `ButtonState` 열거형으로 버튼 상태를 확인한다.
- 게임패드는 `GamePad.GetState(PlayerIndex.One)`으로 상태를 얻고, `IsConnected`로 연결 여부를 반드시 확인한 뒤 `ThumbSticks.Left` 같은 아날로그 스틱 값과 `Buttons.A` 같은 버튼 상태를 읽는다.
- 상하좌우 이동처럼 지속적인 입력은 `IsKeyDown()`을 그대로 사용하고, 델타타임을 곱해 프레임 속도와 무관한 일정한 이동 속도를 유지한다. 대각선 이동 속도가 빨라지지 않도록 방향 벡터는 정규화해서 사용한다.

## 연습문제

1. 이벤트 콜백 방식과 폴링 방식의 차이를 설명하고, MonoGame이 폴링 방식을 채택함으로써 게임 루프와 어떻게 자연스럽게 맞아떨어지는지 서술해보세요.
2. `_previousKeyboardState`를 `Update()`의 맨 앞에서 갱신하면 어떤 문제가 생기는지 설명해보세요.
3. 마우스 왼쪽 버튼을 "누르고 있는 동안"이 아니라 "뗀 순간"에만 실행되는 조건식을 작성해보세요.
4. 게임패드의 아날로그 스틱에 데드존 처리를 하지 않으면 어떤 문제가 발생할 수 있는지 설명하고, 위 예제의 데드존 코드를 응용해 오른쪽 스틱에도 동일하게 적용하는 코드를 작성해보세요.
5. 본문의 이동 예제를 확장하여, 스페이스바를 누르고 있는 동안 스프라이트가 두 배 속도로 이동하도록(대시 기능) 수정해보세요.
