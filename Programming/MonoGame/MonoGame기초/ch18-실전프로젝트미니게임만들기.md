# 18장. 실전 프로젝트: 미니 게임 만들기

[◀ 이전: 17장. 크로스플랫폼 배포](ch17-크로스플랫폼배포.md) | [📖 목차](00-목차.md) | [다음: 부록 ▶](appendix-부록.md)


지금까지 열여섯 개 장을 거치며 게임 루프(3장), 콘텐츠 파이프라인(4장), `SpriteBatch`를 이용한 2D 그리기(5장), 입력 처리(6장), 벡터와 수학(7장), 텍스처와 스프라이트 애니메이션(8장), 충돌 감지(9장), `SpriteFont`를 이용한 텍스트 렌더링(10장), 오디오(11장), 게임 상태 관리와 화면 전환(14장), 파티클 시스템(15장)까지 MonoGame으로 게임을 만드는 데 필요한 재료를 하나씩 배웠습니다. 이번 마지막 장에서는 이 재료들을 한데 모아, 시작 화면부터 승리·패배 화면까지 갖춘 완결된 미니 게임을 처음부터 끝까지 만들어 봅니다.

## 18.1 게임 기획: 벽돌깨기(Breakout)

만들 게임은 고전 아케이드 게임 "벽돌깨기(Breakout)"입니다. 같은 컨셉의 게임을 raylib(C)로 만드는 실전 프로젝트를 다룬 책도 있지만, 이번 장에서는 완전히 같은 방식이 아니라 MonoGame의 `Game` 클래스 수명주기와 `SpriteBatch`, `ContentManager` 같은 API를 중심으로 새로 구현합니다. 즉 만들어지는 결과물의 겉모습은 비슷하더라도, 코드 구조와 사용하는 API는 이 책에서 배운 MonoGame 고유의 방식을 그대로 따릅니다.

벽돌깨기를 고른 이유는 단순합니다. 사각형 충돌(9장), 벡터 기반 이동(7장), 여러 화면 사이의 상태 전환(14장), 타격 이펙트로서의 파티클(15장), 효과음(11장), 점수와 안내 문구 표시(10장)까지, 이 책에서 다룬 핵심 개념 대부분이 아주 자연스럽게 필요해지는 장르이기 때문입니다.

본격적으로 코드를 작성하기 전에 요구사항을 정리해봅시다.

- **공(ball)**: 화면 위를 일정한 속도로 움직이며, 벽·패들·벽돌에 부딪히면 방향을 반사한다.
- **패들(paddle)**: 화면 하단에서 좌우 화살표 키로 조작하는 사각형. 화면 밖으로 나가지 않는다.
- **벽돌 배열(bricks)**: 화면 상단에 행과 열로 배치된 사각형들. 공에 맞으면 사라지고 점수를 준다.
- **점수(score)**: 벽돌을 깰 때마다 증가하며 화면에 표시된다.
- **목숨(lives)**: 공을 패들로 받아내지 못하고 화면 아래로 떨어뜨리면 하나씩 줄어든다.
- **승리 조건**: 모든 벽돌을 다 깨면 승리.
- **패배 조건**: 목숨이 0이 되면 패배.
- **화면 전환**: 시작 화면 → 플레이 화면 → (승리 또는 패배 화면) → Enter 키로 재시작.

이 요구사항을 `Game1.cs` 하나에 담되, 필드 정의 → `LoadContent`에서 에셋 로드 → `Update`에서 입력·충돌·게임 로직 → `Draw`에서 렌더링의 순서로 단계적으로 구성하겠습니다. 아래 코드 조각들은 순서대로 이어 붙이면 그대로 하나의 `Game1` 클래스가 됩니다.

## 18.2 1단계: 필드 정의와 게임 상태 설계

가장 먼저 게임에 등장하는 요소들을 표현할 필드를 선언합니다. 게임의 진행 단계는 14장에서 다룬 패턴대로 열거형(`enum`)으로 표현해, 메뉴·플레이·게임오버·승리 네 화면을 하나의 값으로 구분합니다.

```csharp
using System;
using System.Collections.Generic;
using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Graphics;
using Microsoft.Xna.Framework.Input;
using Microsoft.Xna.Framework.Audio;

namespace BreakoutGame;

public class Game1 : Game
{
    // 14장: 게임이 거쳐가는 화면들을 하나의 상태로 표현
    private enum GameState
    {
        Menu,
        Playing,
        GameOver,
        Win
    }

    // 15장 스타일 파티클: 벽돌이 깨질 때 흩어지는 조각 이펙트
    private class Particle
    {
        public Vector2 Position;
        public Vector2 Velocity;
        public float Life;
        public float MaxLife;
        public Color Color;
    }

    private const int BrickRows = 5;
    private const int BrickCols = 10;
    private const int MaxLives = 3;
    private const int BallSize = 12;

    private GraphicsDeviceManager _graphics;
    private SpriteBatch _spriteBatch;

    private Texture2D _pixelTexture; // 5장: 1x1 흰색 텍스처로 단색 사각형을 그리는 관용 기법
    private SpriteFont _font;        // 10장: 점수·안내 문구 표시

    private SoundEffect _bounceSound;
    private SoundEffect _breakSound;
    private SoundEffect _loseLifeSound;

    private GameState _state;

    private Rectangle _paddle;
    private float _paddleSpeed;

    private Vector2 _ballPosition; // 7장: 위치를 Vector2로 관리
    private Vector2 _ballVelocity; // 7장: 이동 방향과 속력을 Vector2로 관리

    private readonly Rectangle[,] _brickRects = new Rectangle[BrickRows, BrickCols];
    private readonly bool[,] _brickAlive = new bool[BrickRows, BrickCols];
    private readonly Color[] _rowColors = new Color[BrickRows]
    {
        Color.IndianRed, Color.Orange, Color.Gold, Color.YellowGreen, Color.CornflowerBlue
    };

    private int _score;
    private int _lives;

    private readonly List<Particle> _particles = new List<Particle>();
    private readonly Random _random = new Random();

    public Game1()
    {
        _graphics = new GraphicsDeviceManager(this);
        Content.RootDirectory = "Content";
        IsMouseVisible = true;

        _graphics.PreferredBackBufferWidth = 800;
        _graphics.PreferredBackBufferHeight = 480;
    }
}
```

`Rectangle[,] _brickRects`와 `bool[,] _brickAlive`를 행/열 2차원 배열로 관리하는 이유는 "몇 번째 행, 몇 번째 열의 벽돌"을 자연스러운 인덱스로 다룰 수 있기 때문입니다. 공의 위치와 속도는 9장에서 다룬 것처럼 `Rectangle`로 감싼 바운딩 박스와, 7장에서 다룬 `Vector2`로 각각 표현합니다. 공을 텍스처가 아니라 `_pixelTexture`를 확대해서 그리는 단색 사각형으로 표현하기로 했으므로, 화면에 그릴 때와 충돌을 검사할 때 모두 `Rectangle` 하나로 위치와 크기를 함께 다룰 수 있어 코드가 단순해집니다.

## 18.3 2단계: LoadContent에서 에셋 불러오기

`LoadContent()`는 3장에서 배운 대로 `Initialize()` 직후 한 번 호출되며, `GraphicsDevice`가 준비를 마친 시점입니다. 여기서 `SpriteBatch`를 생성하고, 4장에서 다룬 콘텐츠 파이프라인을 통해 폰트와 효과음을 불러옵니다.

```csharp
protected override void LoadContent()
{
    _spriteBatch = new SpriteBatch(GraphicsDevice);

    // 5장: 단색 사각형을 그리기 위한 1x1 흰색 텍스처
    _pixelTexture = new Texture2D(GraphicsDevice, 1, 1);
    _pixelTexture.SetData(new[] { Color.White });

    // 10장: MGCB로 빌드해둔 SpriteFont를 불러온다
    _font = Content.Load<SpriteFont>("GameFont");

    // 11장: 짧은 효과음은 SoundEffect로 불러와 즉시 재생한다
    _bounceSound = Content.Load<SoundEffect>("bounce");
    _breakSound = Content.Load<SoundEffect>("break");
    _loseLifeSound = Content.Load<SoundEffect>("lose");

    InitializeGame();
}
```

`GameFont`, `bounce`, `break`, `lose`는 미리 `Content/Content.mgcb`에 등록해두고 MGCB로 빌드해야 하는 이름입니다(4장의 콘텐츠 파이프라인 절차를 그대로 따릅니다). 여기서는 벽돌과 공, 패들을 별도의 이미지 파일 없이 `_pixelTexture` 하나로 그리기 때문에, 텍스처 파일은 등록할 필요가 없습니다. 스프라이트 이미지를 쓰고 싶다면 8장에서 다룬 방식대로 `Texture2D`를 추가로 불러와 색 대신 텍스처를 그리도록 확장할 수 있습니다.

`InitializeGame()`은 게임을 새로 시작하거나 재시작할 때마다 필요한 모든 상태를 초기값으로 되돌리는 메서드입니다.

```csharp
private void InitializeGame()
{
    int screenWidth = GraphicsDevice.Viewport.Width;
    int screenHeight = GraphicsDevice.Viewport.Height;

    _paddle = new Rectangle(screenWidth / 2 - 50, screenHeight - 40, 100, 15);
    _paddleSpeed = 400f;

    ResetBall();

    float brickWidth = 70f;
    float brickHeight = 20f;
    float marginX = (screenWidth - BrickCols * (brickWidth + 4)) / 2f;

    for (int row = 0; row < BrickRows; row++)
    {
        for (int col = 0; col < BrickCols; col++)
        {
            _brickRects[row, col] = new Rectangle(
                (int)(marginX + col * (brickWidth + 4)),
                (int)(40 + row * (brickHeight + 4)),
                (int)brickWidth,
                (int)brickHeight);
            _brickAlive[row, col] = true;
        }
    }

    _particles.Clear();
    _score = 0;
    _lives = MaxLives;
    _state = GameState.Menu;
}

private void ResetBall()
{
    // 공을 패들 바로 위에 재배치하고 대각선 위쪽으로 발사한다
    _ballPosition = new Vector2(
        _paddle.X + _paddle.Width / 2f - BallSize / 2f,
        _paddle.Y - BallSize - 1);
    _ballVelocity = new Vector2(200f, -250f);
}
```

벽돌의 x 좌표를 계산하는 `marginX + col * (brickWidth + 4)` 부분은 열 번호(`col`)에 "벽돌 하나의 너비 + 여백"을 곱해 나가는 방식으로, 벽돌들이 나란히 일정한 간격을 두고 배치되도록 만듭니다. `ResetBall`을 별도 메서드로 분리해둔 이유는 게임을 처음 시작할 때뿐 아니라, 공을 놓쳐 목숨을 잃은 뒤 다시 발사할 때도 똑같은 코드가 필요하기 때문입니다.

## 18.4 3단계: Update에서 입력·충돌·게임 로직 처리하기

`Update`는 매 프레임 호출되며, 3장에서 배운 대로 여기서는 화면을 직접 그리지 않고 오직 게임 상태만 갱신합니다. 가장 바깥쪽은 현재 `_state`에 따라 분기하는 구조로 만듭니다.

```csharp
protected override void Update(GameTime gameTime)
{
    float dt = (float)gameTime.ElapsedGameTime.TotalSeconds; // 3장: 델타타임
    KeyboardState keyboard = Keyboard.GetState();            // 6장: 키보드 입력

    if (keyboard.IsKeyDown(Keys.Escape))
    {
        Exit();
    }

    switch (_state)
    {
        case GameState.Menu:
            if (keyboard.IsKeyDown(Keys.Enter))
            {
                _state = GameState.Playing;
            }
            break;

        case GameState.Playing:
            UpdatePlaying(dt, keyboard);
            break;

        case GameState.GameOver:
        case GameState.Win:
            UpdateParticles(dt);
            if (keyboard.IsKeyDown(Keys.Enter))
            {
                InitializeGame();
                _state = GameState.Playing;
            }
            break;
    }

    base.Update(gameTime);
}
```

핵심 로직은 `UpdatePlaying`에 담습니다.

```csharp
private void UpdatePlaying(float dt, KeyboardState keyboard)
{
    int screenWidth = GraphicsDevice.Viewport.Width;
    int screenHeight = GraphicsDevice.Viewport.Height;

    // 6장: 입력 처리 - 패들 이동
    int paddleX = _paddle.X;
    if (keyboard.IsKeyDown(Keys.Left)) paddleX -= (int)(_paddleSpeed * dt);
    if (keyboard.IsKeyDown(Keys.Right)) paddleX += (int)(_paddleSpeed * dt);

    // 7장: MathHelper.Clamp로 패들이 화면 밖으로 나가지 않도록 제한
    paddleX = (int)MathHelper.Clamp(paddleX, 0, screenWidth - _paddle.Width);
    _paddle.X = paddleX;

    // 7장: 델타타임을 곱해 프레임 레이트와 무관하게 공을 이동
    _ballPosition += _ballVelocity * dt;
    Rectangle ballRect = new Rectangle((int)_ballPosition.X, (int)_ballPosition.Y, BallSize, BallSize);

    // 좌우 벽 충돌
    if (ballRect.Left <= 0 || ballRect.Right >= screenWidth)
    {
        _ballVelocity.X = -_ballVelocity.X;
        _bounceSound.Play();
    }
    // 위쪽 벽 충돌
    if (ballRect.Top <= 0)
    {
        _ballVelocity.Y = -_ballVelocity.Y;
        _bounceSound.Play();
    }

    // 9장: 사각형 기반 AABB 충돌로 패들과의 충돌 판정
    if (_ballVelocity.Y > 0 && ballRect.Intersects(_paddle))
    {
        _ballVelocity.Y = -_ballVelocity.Y;

        // 패들 중심에서 얼마나 벗어난 지점에 맞았는지로 좌우 반사각을 조절한다
        float paddleCenter = _paddle.X + _paddle.Width / 2f;
        float ballCenter = ballRect.X + ballRect.Width / 2f;
        float hitOffset = (ballCenter - paddleCenter) / (_paddle.Width / 2f);
        _ballVelocity.X = hitOffset * 300f;

        _bounceSound.Play();
    }

    // 9장: 벽돌 배열을 순회하며 AABB 충돌 검사
    for (int row = 0; row < BrickRows; row++)
    {
        for (int col = 0; col < BrickCols; col++)
        {
            if (!_brickAlive[row, col]) continue;

            if (ballRect.Intersects(_brickRects[row, col]))
            {
                _brickAlive[row, col] = false;
                _score += 10;
                _ballVelocity.Y = -_ballVelocity.Y;

                // 15장: 벽돌이 있던 자리에서 파티클을 터뜨린다
                Rectangle brick = _brickRects[row, col];
                Vector2 brickCenter = new Vector2(
                    brick.X + brick.Width / 2f,
                    brick.Y + brick.Height / 2f);
                EmitParticles(brickCenter, 15, _rowColors[row]);
                _breakSound.Play();
                break;
            }
        }
    }

    UpdateParticles(dt);

    // 공을 놓쳤을 때: 목숨을 잃는다
    if (_ballPosition.Y > screenHeight)
    {
        _lives--;
        _loseLifeSound.Play();

        if (_lives <= 0)
        {
            _state = GameState.GameOver; // 14장: 상태 전환
        }
        else
        {
            ResetBall();
        }
    }

    // 승리 조건: 살아있는 벽돌이 하나도 없으면 승리
    bool anyBrickLeft = false;
    for (int row = 0; row < BrickRows && !anyBrickLeft; row++)
    {
        for (int col = 0; col < BrickCols; col++)
        {
            if (_brickAlive[row, col])
            {
                anyBrickLeft = true;
                break;
            }
        }
    }
    if (!anyBrickLeft)
    {
        _state = GameState.Win; // 14장: 상태 전환
    }

    _ballPosition = new Vector2(ballRect.X, ballRect.Y);
}
```

주목할 부분은 패들 충돌 시 `hitOffset`을 계산하는 코드입니다. 패들 정중앙에 맞으면 `hitOffset`이 0에 가까워 공이 거의 수직으로 튕기고, 패들 가장자리에 맞을수록 1 또는 -1에 가까워져 공이 더 비스듬히 튕겨 나갑니다. 이는 벡터의 각 성분(`X`, `Y`)을 상황에 맞게 독립적으로 조작하는 좋은 예시입니다. 또한 공의 충돌을 원이 아니라 사각형(`Rectangle.Intersects`)으로 단순화했다는 점도 눈여겨보세요. 9장에서 원형 충돌과 원-사각형 충돌을 직접 구현해보는 연습문제를 남겨두었는데, 관심 있다면 이 프로젝트의 공 충돌을 원-사각형 판정으로 바꿔 더 정교한 반사각을 만들어보는 것도 좋은 확장 연습이 됩니다.

이제 15장 스타일의 파티클 관리 메서드를 정의합니다. 벽돌이 깨질 때 그 자리에서 조각이 흩어지는 짧은 이펙트를 표현합니다.

```csharp
private void EmitParticles(Vector2 origin, int count, Color color)
{
    for (int i = 0; i < count; i++)
    {
        double angle = _random.NextDouble() * MathHelper.TwoPi;
        float speed = 40f + (float)_random.NextDouble() * 80f;

        var particle = new Particle
        {
            Position = origin,
            Velocity = new Vector2((float)Math.Cos(angle), (float)Math.Sin(angle)) * speed,
            MaxLife = 0.5f,
            Life = 0.5f,
            Color = color
        };
        _particles.Add(particle);
    }
}

private void UpdateParticles(float dt)
{
    for (int i = _particles.Count - 1; i >= 0; i--)
    {
        Particle particle = _particles[i];
        particle.Life -= dt;

        if (particle.Life <= 0f)
        {
            _particles.RemoveAt(i);
            continue;
        }

        particle.Position += particle.Velocity * dt;
    }
}
```

`MathHelper.TwoPi`(7장에서 다룬 `MathHelper`가 제공하는 상수)로 0부터 360도에 해당하는 라디안 범위 안에서 무작위 각도를 뽑고, `Math.Cos`/`Math.Sin`으로 방향 벡터를 만들어 파티클마다 제각기 다른 방향으로 흩어지도록 했습니다. `Life`가 0 이하로 떨어진 파티클은 `List<Particle>.RemoveAt`으로 즉시 제거해, 리스트가 무한정 늘어나지 않도록 관리합니다.

## 18.5 4단계: Draw로 렌더링하기

`Draw`는 5장에서 배운 `SpriteBatch.Begin()`/`End()` 패턴 안에서, 현재 `_state`에 따라 그릴 내용을 결정합니다. 플레이·게임오버·승리 화면은 벽돌·패들·공을 공통으로 그린 뒤, 그 위에 상태별 문구만 다르게 얹는 방식으로 중복을 줄였습니다.

```csharp
protected override void Draw(GameTime gameTime)
{
    GraphicsDevice.Clear(Color.Black);

    _spriteBatch.Begin();

    switch (_state)
    {
        case GameState.Menu:
            DrawCenteredText("벽돌깨기", 150, Color.White, 2f);
            DrawCenteredText("Enter 키를 눌러 시작하세요", 220, Color.Gray, 1f);
            break;

        case GameState.Playing:
        case GameState.GameOver:
        case GameState.Win:
            DrawPlayfield();

            if (_state == GameState.GameOver)
            {
                DrawOverlay();
                DrawCenteredText("GAME OVER", 180, Color.OrangeRed, 2f);
                DrawCenteredText("Enter 키를 눌러 다시 시작", 230, Color.White, 1f);
            }
            else if (_state == GameState.Win)
            {
                DrawOverlay();
                DrawCenteredText("YOU WIN!", 180, Color.LightGreen, 2f);
                DrawCenteredText("Enter 키를 눌러 다시 시작", 230, Color.White, 1f);
            }
            break;
    }

    _spriteBatch.End();

    base.Draw(gameTime);
}
```

실제로 벽돌, 패들, 공, 파티클, 점수/목숨 표시를 그리는 부분은 `DrawPlayfield`로 분리했습니다.

```csharp
private void DrawPlayfield()
{
    // 5장: SpriteBatch.Draw의 Rectangle 오버로드로 단색 사각형을 그린다
    for (int row = 0; row < BrickRows; row++)
    {
        for (int col = 0; col < BrickCols; col++)
        {
            if (_brickAlive[row, col])
            {
                _spriteBatch.Draw(_pixelTexture, _brickRects[row, col], _rowColors[row]);
            }
        }
    }

    _spriteBatch.Draw(_pixelTexture, _paddle, Color.LightGray);

    Rectangle ballRect = new Rectangle((int)_ballPosition.X, (int)_ballPosition.Y, BallSize, BallSize);
    _spriteBatch.Draw(_pixelTexture, ballRect, Color.White);

    // 15장: 파티클을 남은 수명 비율만큼 투명해지도록 그린다
    foreach (Particle particle in _particles)
    {
        float alpha = particle.Life / particle.MaxLife;
        Color color = particle.Color * alpha;
        _spriteBatch.Draw(_pixelTexture, new Rectangle((int)particle.Position.X, (int)particle.Position.Y, 4, 4), color);
    }

    // 10장: SpriteFont로 점수와 목숨을 표시한다
    _spriteBatch.DrawString(_font, $"점수: {_score}", new Vector2(10, 10), Color.White);
    string livesText = $"목숨: {_lives}";
    Vector2 livesSize = _font.MeasureString(livesText);
    _spriteBatch.DrawString(_font, livesText, new Vector2(GraphicsDevice.Viewport.Width - livesSize.X - 10, 10), Color.White);
}

private void DrawOverlay()
{
    Rectangle fullScreen = new Rectangle(0, 0, GraphicsDevice.Viewport.Width, GraphicsDevice.Viewport.Height);
    _spriteBatch.Draw(_pixelTexture, fullScreen, Color.Black * 0.5f);
}

private void DrawCenteredText(string text, int y, Color color, float scale)
{
    Vector2 size = _font.MeasureString(text) * scale;
    float x = (GraphicsDevice.Viewport.Width - size.X) / 2f;
    _spriteBatch.DrawString(_font, text, new Vector2(x, y), color, 0f, Vector2.Zero, scale, SpriteEffects.None, 0f);
}
```

`Color.Black * 0.5f`처럼 색상에 스칼라를 곱해 반투명한 검은 사각형을 화면 전체에 덮어 그리는 것은 흔히 쓰이는 트릭입니다(5장에서 다룬 색상과 알파값 조절 방식을 그대로 응용한 것입니다). 뒤에 있는 게임 장면이 살짝 비쳐 보이면서도 앞쪽 메시지가 잘 읽히는 효과를 아주 적은 코드로 얻을 수 있습니다. `DrawCenteredText`는 `SpriteFont.MeasureString`(10장)으로 문자열의 렌더링 크기를 미리 계산해, 화면 가로 중앙에 정확히 맞춰 그리는 헬퍼입니다.

## 18.6 완성된 구조 정리

`Game1` 클래스 전체를 놓고 보면, `LoadContent`가 에셋을 불러오고 `InitializeGame`을 호출해 첫 상태를 세팅하고, 이후로는 `Update`와 `Draw`가 매 프레임 번갈아 호출되며 `_state` 값에 따라 서로 다른 화면을 갱신하고 그려내는 구조입니다. `Program.cs`는 2장에서 만들어진 그대로 손댈 필요가 없습니다.

```csharp
using var game = new Game1();
game.Run();
```

게임의 모든 복잡함이 `Update`와 `Draw`, 그리고 이들이 위임하는 `UpdatePlaying`/`DrawPlayfield` 같은 보조 메서드 뒤로 숨어 있기 때문에 `Program.cs`는 매우 단순한 상태로 남아 있습니다. 이렇게 "업데이트"와 "그리기"를 명확히 분리하고, 그 아래에 다시 "상태별 분기"를 두는 구조는 게임이 커질수록 진가를 발휘합니다. 새로운 화면(일시정지, 옵션 메뉴 등)을 추가하고 싶다면 `GameState`에 항목을 하나 더 늘리고, `Update`와 `Draw`의 `switch` 문에 `case`를 하나씩 추가하기만 하면 됩니다.

## 18.7 완성된 게임 확장하기

기본 골격이 완성되었다면, 다음과 같은 방향으로 직접 확장해보는 것을 권합니다.

- **파워업 아이템**: 벽돌이 깨질 때 일정 확률로 아래로 천천히 떨어지는 아이템(예: `PowerUp` 클래스)을 만들고, 패들이 그 아이템과 충돌(9장의 `Rectangle.Intersects`)하면 패들이 일시적으로 넓어지거나, 공이 여러 개로 늘어나거나(`_ballPosition`/`_ballVelocity`를 리스트로 확장), 공 속도가 느려지는 등의 효과를 적용해보세요. 효과 지속시간은 3장에서 다룬 `GameTime` 누적 방식으로 관리할 수 있습니다.
- **여러 레벨**: 지금은 `InitializeGame` 안에서 행마다 같은 규칙으로 벽돌을 배치하지만, 레벨마다 다른 벽돌 배치를 문자열 배열(한 줄에 `"XXXX...XX"`처럼 벽돌 유무를 표현)로 미리 정의해두고, 레벨 번호에 따라 다른 배치를 불러오도록 확장할 수 있습니다. 레벨을 클리어하면 `GameState`에 `NextLevel` 같은 상태를 추가해 다음 레벨로 넘어가도록 만들어보세요.
- **사운드와 배경음악 강화**: 지금은 효과음 세 개만 사용했지만, 11장에서 다룬 `Song`과 `MediaPlayer.Play()`로 배경음악을 재생하고, 콤보(연속으로 벽돌을 깰 때)에 따라 `SoundEffectInstance.Pitch`를 조금씩 올려보는 것도 재미있는 시도입니다.
- **최고 점수 저장**: 16장에서 다룬 세이브/로드 패턴을 그대로 가져와, `GameState.GameOver`나 `GameState.Win`에 진입하는 순간 현재 `_score`가 기존 최고 점수보다 높으면 저장 파일을 갱신하고, `LoadContent`나 `Initialize` 시점에 저장된 최고 점수를 불러와 메뉴 화면에 표시해보세요.

## 요약

- 완결된 미니 게임은 필드 정의 → `LoadContent`(에셋 로딩) → `Update`(입력·충돌·게임 로직) → `Draw`(렌더링)의 순서로 단계적으로 구성하면 관리하기 쉽다.
- 벽돌깨기는 사각형 기반 충돌(9장), 벡터 기반 이동(7장), 상태 전환(14장), 파티클 이펙트(15장), 효과음(11장), 텍스트 렌더링(10장)이 자연스럽게 어우러지는 좋은 종합 실습 소재다.
- `Update`와 `Draw`를 현재 `GameState`에 따라 분기하는 구조로 설계하면, 시작 화면·플레이 화면·결과 화면처럼 여러 화면을 하나의 `Game1` 클래스 안에서 깔끔하게 관리할 수 있다.
- 공의 충돌 판정을 `Rectangle.Intersects` 기반의 AABB로 단순화하면 구현이 쉬워지며, 더 정교한 원-사각형 판정은 9장의 연습문제를 응용해 직접 확장해볼 수 있다.
- 완성된 게임에 파워업, 여러 레벨, 배경음악, 최고 점수 저장 같은 기능을 추가해보면 이 책에서 배운 개념들을 더 깊이 있게 응용해볼 수 있다.

## 연습문제

1. 이 장의 완성 코드를 직접 입력하고 실행해서, 벽돌을 모두 깨면 승리 화면이, 목숨을 모두 잃으면 게임오버 화면이 뜨는지 확인해보세요.
2. `UpdatePlaying`의 벽돌 충돌 검사 부분에서 `break`가 없다면 한 프레임에 여러 벽돌이 동시에 반응할 수 있습니다. 이 동작을 직접 관찰해보고, 왜 `break`를 넣어 한 프레임에 하나의 벽돌만 반응하도록 제한했는지 설명해보세요.
3. "완성된 게임 확장하기"에서 제안한 파워업 아이템 중 하나(패들 확장 또는 공 속도 감소)를 직접 구현해보세요. 아이템의 낙하, 패들과의 충돌 감지, 효과 지속시간 관리가 모두 필요합니다.
4. 벽돌 배열을 하드코딩하는 대신 문자열 배열로 레벨 데이터를 표현하고, 레벨을 두 개 이상 만들어 한 레벨을 클리어하면 다음 레벨로 넘어가도록 `GameState` 처리를 수정해보세요.
5. 16장에서 배운 세이브/로드 기법을 적용해, 게임을 종료했다가 다시 실행해도 최고 점수가 유지되도록 구현해보세요.
