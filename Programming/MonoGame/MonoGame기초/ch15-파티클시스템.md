# 15장. 파티클 시스템

[◀ 이전: 14장. 게임 상태 관리와 화면 전환](ch14-게임상태관리와화면전환.md) | [📖 목차](00-목차.md) | [다음: 16장. 세이브/로드 ▶](ch16-세이브로드.md)


게임 화면에서 폭발이 일어나거나, 캐릭터가 걸을 때 먼지가 피어오르거나, 마법 지팡이 끝에서 반짝이는 빛이 흩날리는 장면을 본 적이 있을 것이다. 이런 효과들은 하나의 정교한 스프라이트로 그려지는 것이 아니라, 아주 많은 수의 작고 단순한 점(또는 작은 스프라이트)들이 각자 조금씩 다른 방향과 속도로 움직이면서 만들어내는 집단적인 인상이다. 이런 기법을 파티클 시스템(particle system)이라고 부른다. 이번 장에서는 MonoGame의 `Vector2`와 `SpriteBatch` API만으로 파티클 시스템을 직접 설계하고 구현하면서, 9장에서 다룬 충돌 감지와 연결해 실제 게임에서 쓰일 법한 폭발 이펙트까지 만들어본다.

## 파티클이란 무엇인가

파티클(particle)은 우리말로 옮기면 "입자"다. 게임 그래픽스에서 파티클은 보통 위치, 이동 속도, 남은 수명, 색상 같은 몇 가지 단순한 속성만을 가진 아주 작은 시각 단위를 가리킨다. 개별 파티클 하나는 그저 작은 점이나 사각형, 혹은 작은 텍스처 조각일 뿐이어서 그 자체로는 특별할 것이 없다. 하지만 수십, 수백 개의 파티클이 동시에 생성되어 각자 조금씩 다른 방향으로 퍼져나가면서 서서히 사라지면, 우리 눈에는 그것이 "폭발"이나 "연기", "불꽃", "마법 효과"처럼 보이게 된다.

이 접근 방식이 강력한 이유는 단순함에 있다. 폭발 애니메이션을 미리 그려진 스프라이트 시트로 표현하려면 아티스트가 수십 장의 프레임을 손으로 그려야 하고, 그마저도 매번 똑같은 모양으로 재생될 뿐이다. 반면 파티클 시스템은 몇 가지 규칙(초기 속도의 범위, 색상 변화, 수명)만 정해주면 프로그램이 매번 조금씩 다른, 그러나 일관되게 그럴듯한 결과를 만들어낸다. 같은 폭발 코드를 재사용해도 실행할 때마다 파티클이 퍼지는 모양이 미묘하게 달라지기 때문에 반복해서 봐도 기계적으로 느껴지지 않는다는 것도 장점이다.

이 책의 다른 장에서 raylib 같은 저수준 그래픽스 라이브러리를 접해본 독자라면 개념 자체는 낯설지 않을 것이다. 파티클 시스템은 특정 프레임워크에 종속된 기능이 아니라, "많은 수의 단순한 객체를 관리하고 매 프레임 갱신한다"는 매우 일반적인 아이디어이기 때문이다. 다만 이번 장에서는 이 아이디어를 MonoGame이 제공하는 `Vector2` 구조체와 `SpriteBatch` 그리기 API 위에서 구현하는 방법에 집중한다.

## Particle 클래스 설계하기

파티클 하나가 가져야 할 최소한의 정보부터 정리해보자. 파티클은 화면 어딘가에 위치하고(`Position`), 매 프레임 일정한 방향과 속력으로 움직이며(`Velocity`), 시간이 지나면 사라져야 하고(`Life`), 화면에 그려질 때 특정 색으로 표현된다(`Color`). 이 네 가지만 있어도 꽤 그럴듯한 파티클 효과를 만들 수 있다.

```csharp
using Microsoft.Xna.Framework;

public class Particle
{
    public Vector2 Position;
    public Vector2 Velocity;
    public float Life;
    public Color Color;

    public bool IsAlive => Life > 0f;

    public void Update(float deltaTime)
    {
        Position += Velocity * deltaTime;
        Life -= deltaTime;
    }
}
```

`Position`과 `Velocity`는 7장에서 다룬 `Vector2`를 그대로 사용한다. `Position += Velocity * deltaTime` 한 줄이 바로 "속도만큼 위치를 이동시킨다"는 물리적인 규칙을 코드로 옮긴 것이다. `deltaTime`은 3장에서 살펴본 `GameTime.ElapsedGameTime.TotalSeconds`에서 얻어오는, 프레임 사이에 흐른 시간(초)이다. 프레임마다 걸리는 시간이 조금씩 달라지더라도 `deltaTime`을 곱해주면 파티클의 이동 속도가 실제 시간 기준으로 일정하게 유지된다.

`Life`는 파티클이 얼마나 더 살아있을지를 초 단위로 담아두는 값이다. 매 프레임 `deltaTime`만큼 줄어들다가 0 이하가 되면 파티클의 수명이 다한 것으로 간주한다. `IsAlive`라는 읽기 전용 속성을 따로 두면, 나중에 리스트를 순회하며 죽은 파티클을 걸러낼 때 `particle.Life <= 0`이라는 조건을 여기저기 반복해서 적지 않아도 되어 코드가 한결 읽기 편해진다.

`Color`는 5장에서 다룬 `Microsoft.Xna.Framework.Color` 구조체를 그대로 사용한다. 불꽃 파티클이라면 노란색에서 빨간색으로, 연기 파티클이라면 밝은 회색에서 점점 투명해지는 어두운 회색으로 색을 바꿔주면 훨씬 사실적인 느낌을 낼 수 있다. 이 부분은 이번 장 뒤에서 `Life` 값을 이용해 알파 값을 서서히 줄이는 방식으로 다시 다룬다.

## 여러 파티클을 List로 관리하기

파티클 하나만으로는 아무 효과도 나지 않는다. 진짜 재미있는 부분은 수십, 수백 개의 `Particle` 인스턴스를 동시에 관리하는 데서 시작된다. 이를 위해 `List<Particle>`을 파티클들의 컨테이너로 사용하는 `ParticleSystem` 클래스를 만들어보자.

```csharp
using System;
using System.Collections.Generic;
using Microsoft.Xna.Framework;
using Microsoft.Xna.Framework.Graphics;

public class ParticleSystem
{
    private readonly List<Particle> particles = new List<Particle>();
    private readonly Random random = new Random();
    private readonly Texture2D pixelTexture;

    public ParticleSystem(Texture2D pixelTexture)
    {
        this.pixelTexture = pixelTexture;
    }

    public void Emit(Vector2 position, int count, Color color)
    {
        for (int i = 0; i < count; i++)
        {
            float angle = (float)(random.NextDouble() * MathHelper.TwoPi);
            float speed = 50f + (float)random.NextDouble() * 150f;

            var particle = new Particle
            {
                Position = position,
                Velocity = new Vector2((float)Math.Cos(angle), (float)Math.Sin(angle)) * speed,
                Life = 0.6f + (float)random.NextDouble() * 0.4f,
                Color = color
            };

            particles.Add(particle);
        }
    }

    public void Update(GameTime gameTime)
    {
        float deltaTime = (float)gameTime.ElapsedGameTime.TotalSeconds;

        for (int i = particles.Count - 1; i >= 0; i--)
        {
            particles[i].Update(deltaTime);

            if (!particles[i].IsAlive)
            {
                particles.RemoveAt(i);
            }
        }
    }

    public void Draw(SpriteBatch spriteBatch)
    {
        foreach (var particle in particles)
        {
            float alpha = MathHelper.Clamp(particle.Life, 0f, 1f);
            Color drawColor = particle.Color * alpha;

            spriteBatch.Draw(pixelTexture, particle.Position, drawColor);
        }
    }
}
```

`Emit` 메서드는 지정한 위치에서 `count`개의 파티클을 한꺼번에 만들어낸다. `Random.NextDouble()`로 각도를 무작위로 정하고, `Math.Cos`와 `Math.Sin`으로 그 각도에 대응하는 단위 방향 벡터를 구한 뒤 속력을 곱해 `Velocity`를 결정한다. 이렇게 하면 파티클들이 사방으로 고르게 흩어지는 폭발 형태의 이펙트를 만들 수 있다. 속력과 수명에 약간의 무작위성을 섞어준 것도 중요한 디테일이다. 모든 파티클이 완전히 똑같은 속력과 수명을 가지면 화면에 규칙적인 원형 패턴이 드러나 부자연스러워 보이지만, 약간의 편차를 주는 것만으로 훨씬 유기적인 느낌을 얻을 수 있다.

`pixelTexture`는 1x1 크기의 흰색 텍스처 한 장으로, `Color.White` 한 픽셀만 담긴 텍스처를 `spriteBatch.Draw`로 그리면서 `Color` 매개변수로 원하는 색을 입히는 방식이다. 이렇게 하면 파티클마다 별도의 이미지 파일을 준비하지 않고도 색깔 있는 점을 자유롭게 그릴 수 있다. 물론 8장에서 다룬 스프라이트 텍스처를 파티클 이미지로 사용해도 무방하다. 불꽃이나 연기처럼 좀 더 사실적인 모양이 필요하다면 작은 원형이나 흐릿한 텍스처를 콘텐츠 파이프라인으로 불러와 `pixelTexture` 자리에 넣어주기만 하면 된다.

## Update에서 안전하게 파티클 제거하기: 역방향 반복문

`ParticleSystem.Update` 메서드에서 눈여겨봐야 할 부분은 반복문의 방향이다.

```csharp
for (int i = particles.Count - 1; i >= 0; i--)
{
    particles[i].Update(deltaTime);

    if (!particles[i].IsAlive)
    {
        particles.RemoveAt(i);
    }
}
```

`List<T>`를 순회하면서 조건에 따라 요소를 제거해야 할 때는 반드시 인덱스를 뒤에서부터 앞으로 감소시키는 역방향 반복문을 사용해야 한다. 그 이유를 이해하려면 반대의 경우, 즉 `for (int i = 0; i < particles.Count; i++)` 형태로 앞에서부터 순회하면서 `RemoveAt(i)`를 호출했을 때 무슨 일이 벌어지는지 생각해보면 된다. `List<T>.RemoveAt`은 지정한 인덱스의 요소를 제거한 뒤, 그 뒤에 있던 모든 요소를 한 칸씩 앞으로 당긴다. 그런데 반복문의 `i`는 다음 차례에 그대로 1 증가하기 때문에, 방금 당겨져 온 다음 요소를 건너뛰고 그다음 요소를 검사하게 된다. 결과적으로 죽은 파티클 바로 다음에 있던 파티클이 갱신되지 않고 누락되는 미묘한 버그가 생긴다.

반면 뒤에서부터 앞으로 순회하면 인덱스 `i`에서 요소를 제거해 뒤쪽 요소들이 한 칸씩 당겨지더라도, 그 변화는 이미 지나간(더 큰 인덱스를 가졌던) 요소들에만 영향을 주고 아직 검사하지 않은 앞쪽 요소들(더 작은 인덱스)의 위치는 전혀 바뀌지 않는다. 그래서 다음 차례에 `i`를 1 감소시켜도 정확히 그다음으로 검사해야 할 요소를 가리키게 된다. 이 역방향 반복문 관용구는 리스트를 순회하며 조건부로 요소를 제거해야 하는 상황이라면 파티클 시스템뿐 아니라 어디서든 유용하게 쓰이므로 반드시 손에 익혀두는 것이 좋다.

`List<T>`가 제공하는 `RemoveAll(Predicate<T>)` 메서드를 사용하면 이 반복문을 한 줄로 대체할 수도 있다(`particles.RemoveAll(p => !p.IsAlive)`). 다만 이번 장에서는 매 프레임 `Update`와 생존 여부 검사를 함께 수행해야 하므로, 역방향 반복문 방식이 각 파티클을 갱신하면서 동시에 제거 여부를 판단하기에 더 직관적이다. 두 방식 모두 알아두고 상황에 맞게 선택하면 된다.

## 충돌 지점에서 폭발 파티클 발생시키기

이제 9장에서 다룬 충돌 감지와 파티클 시스템을 연결해보자. 예를 들어 플레이어가 쏜 총알이 적과 충돌했을 때, 그 위치에서 작은 폭발 이펙트가 터지는 장면을 상상해보자. 9장에서는 `Rectangle.Intersects`나 원형 충돌 판정을 이용해 두 객체가 겹쳤는지를 검사하는 방법을 다뤘다. 그 판정 결과를 그대로 활용해 충돌이 발생한 위치에 `ParticleSystem.Emit`을 호출하기만 하면 된다.

```csharp
public class GameplayScreen
{
    private readonly ParticleSystem particleSystem;
    private readonly List<Bullet> bullets = new List<Bullet>();
    private readonly List<Enemy> enemies = new List<Enemy>();

    // ... 생성자 등 생략

    public void Update(GameTime gameTime)
    {
        for (int i = bullets.Count - 1; i >= 0; i--)
        {
            bullets[i].Update(gameTime);

            for (int j = enemies.Count - 1; j >= 0; j--)
            {
                bool collided = bullets[i].Bounds.Intersects(enemies[j].Bounds);

                if (collided)
                {
                    // 충돌 지점에서 노란색 계열의 폭발 파티클 20개를 발생시킨다.
                    particleSystem.Emit(enemies[j].Position, 20, Color.Orange);

                    bullets.RemoveAt(i);
                    enemies.RemoveAt(j);
                    break;
                }
            }
        }

        particleSystem.Update(gameTime);
    }

    public void Draw(SpriteBatch spriteBatch)
    {
        foreach (var bullet in bullets)
        {
            bullet.Draw(spriteBatch);
        }

        foreach (var enemy in enemies)
        {
            enemy.Draw(spriteBatch);
        }

        particleSystem.Draw(spriteBatch);
    }
}
```

여기서도 총알과 적을 담은 두 리스트 모두 역방향 반복문으로 순회하고 있다는 점에 주목하자. 충돌이 확인되는 즉시 두 리스트에서 각각 요소를 제거해야 하므로, 이번 장에서 익힌 안전한 제거 패턴이 그대로 적용된다. 충돌이 감지된 순간 `particleSystem.Emit(enemies[j].Position, 20, Color.Orange)`를 호출하면, 적이 있던 바로 그 자리에서 주황색 파티클 20개가 사방으로 흩어지며 짧은 순간 화면에 표시되다가 서서히 사라진다. 폭발음 같은 효과를 곁들이고 싶다면 11장에서 다룬 오디오 재생 코드를 이 지점에 함께 추가하면 된다.

이처럼 파티클 시스템은 그 자체로 독립된 기능이라기보다는, 게임의 다른 시스템(충돌 감지, 입력 처리, 상태 관리)이 만들어내는 "사건"에 반응해 시각적인 피드백을 더해주는 역할을 한다. 색상과 개수, 속력 범위, 수명 같은 파라미터를 조금씩 바꿔가며 실험해보면 폭발, 불꽃, 먼지, 반짝임 등 다양한 이펙트를 같은 `ParticleSystem` 코드로 표현할 수 있다는 것을 직접 확인할 수 있을 것이다.

## 요약

- 파티클 시스템은 폭발, 연기, 불꽃 같은 효과를 아주 많은 수의 작고 단순한 입자(파티클)의 집합으로 표현하는 기법이다.
- `Particle` 클래스는 `Vector2 Position`, `Vector2 Velocity`, `float Life`, `Color Color`처럼 최소한의 속성만으로 설계할 수 있으며, `Update`에서 `Position += Velocity * deltaTime`으로 이동시키고 `Life`를 감소시킨다.
- 여러 파티클은 `List<Particle>`로 관리하며, `Emit` 메서드에서 무작위 각도와 속력을 부여해 자연스럽게 사방으로 퍼지는 효과를 만든다.
- 수명이 다한 파티클을 리스트에서 제거할 때는 `for (int i = particles.Count - 1; i >= 0; i--)` 형태의 역방향 반복문을 사용해야 요소 제거로 인한 인덱스 밀림 문제 없이 안전하게 순회할 수 있다.
- 9장에서 다룬 충돌 감지 결과를 활용해, 충돌이 일어난 위치에서 `ParticleSystem.Emit`을 호출하면 실전 게임에서 흔히 볼 수 있는 폭발 이펙트를 구현할 수 있다.

## 연습문제

1. `Particle` 클래스에 `Life`라는 수명 필드가 없다면 어떤 문제가 생길지 설명해보자. 즉 파티클이 한 번 생성되면 영원히 사라지지 않는다면 게임에 어떤 영향을 미칠까?
2. 이번 장의 `ParticleSystem.Update`에서 역방향 반복문 대신 정방향 반복문(`for (int i = 0; ...)`)으로 바꾸고 `RemoveAt`을 그대로 사용했을 때 어떤 버그가 발생하는지 직접 코드를 작성해 확인해보자.
3. `Emit` 메서드에서 속력(`speed`)의 무작위 범위를 더 좁게(예: 90~110) 바꾸면 파티클이 퍼지는 모양이 어떻게 달라지는지 예상해보고 실행해서 확인해보자.
4. 파티클의 `Life` 값에 따라 색상을 노란색에서 빨간색으로 서서히 바꾸는 기능을 `Particle.Update` 또는 `ParticleSystem.Draw`에 추가해보자. `Color.Lerp`를 활용할 수 있다.
5. 9장의 충돌 감지 예제를 참고해, 플레이어 캐릭터가 아이템과 충돌했을 때 초록색 반짝임 파티클이 발생하도록 코드를 확장해보자. 폭발 파티클과는 다른 속력 범위와 수명을 사용해 차별화해보자.
