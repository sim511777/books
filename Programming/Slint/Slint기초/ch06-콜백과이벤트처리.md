# 6장. 콜백과 이벤트 처리

[◀ 이전: 5장. 프로퍼티와 바인딩](ch05-프로퍼티와바인딩.md) | [📖 목차](00-목차.md) | [다음: 7장. C++와 Slint 연동 기초 ▶](ch07-CPP와Slint연동기초.md)


5장에서는 프로퍼티가 "값 사이의 관계"를 선언하는 방법을 배웠습니다. 하지만 GUI는 값의 관계만으로 완성되지 않습니다. 사용자가 버튼을 누르거나 화면을 터치하는 "사건(event)"이 일어났을 때, 그에 반응해서 무언가를 실행해야 합니다. 이번 장에서는 Slint가 이런 사용자 상호작용을 다루는 두 가지 축인 **콜백(callback)**과 **`TouchArea`**를 살펴보고, 이 둘을 조합해서 나만의 버튼 컴포넌트를 직접 만들어보겠습니다.

## 6.1 콜백이란 무엇인가

콜백은 "특정 사건이 일어났을 때 호출되는 신호"입니다. 프로퍼티가 값을 나타낸다면, 콜백은 순간적으로 발생하는 사건을 나타냅니다. 콜백은 이렇게 선언합니다.

```slint
export component ConfirmDialog {
    callback confirmed();
    callback cancelled();
}
```

`callback confirmed();`는 "이 컴포넌트는 `confirmed`라는 이름의 사건을 일으킬 수 있다"는 선언일 뿐, 그 자체로 무슨 일이 일어나지는 않습니다. 실제로 이 콜백을 "쏘는(emit)" 코드와, 쏘아졌을 때 "반응하는" 코드가 따로 있어야 완전한 동작이 됩니다. 이번 장 뒷부분에서 이 둘을 직접 연결해보겠습니다.

## 6.2 인자와 반환값이 있는 콜백

콜백도 함수처럼 인자를 받고 값을 돌려줄 수 있습니다. 문법은 다음과 같습니다.

```slint
export component ItemList {
    callback item-selected(int) -> bool;
    callback item-removed(int);
}
```

`callback item-selected(int) -> bool;`은 "정수 하나(선택된 항목의 인덱스 같은 것)를 받아서, 불리언 값(예: 선택을 허용할지 여부)을 돌려주는 사건"이라는 뜻입니다. 인자가 여러 개라면 쉼표로 나열하고, 반환값이 없다면 `item-removed(int);`처럼 `-> 반환타입` 부분을 아예 생략합니다.

콜백에 이름을 붙인 인자를 쓸 수도 있어서, 콜백을 실제로 처리하는 코드에서 그 이름으로 값을 참조할 수 있습니다.

```slint
callback item-selected(index: int) -> bool;
```

## 6.3 TouchArea: 마우스와 터치를 하나로

콜백이 "무슨 사건이 있는지"를 정의하는 문법이라면, `TouchArea`는 그 사건 중에서도 가장 흔한 "사용자가 화면의 어떤 영역을 눌렀다"를 감지하는 엘리먼트입니다. `TouchArea`를 다른 엘리먼트와 겹쳐 놓으면 그 영역이 클릭/터치에 반응하는 영역이 됩니다.

```slint
export component ClickableBox {
    Rectangle {
        width: 120px;
        height: 60px;
        background: #4299e1;

        TouchArea {
            clicked => {
                debug("클릭됨!");
            }
        }
    }
}
```

`TouchArea`는 이름 그대로 데스크톱의 마우스 클릭과 모바일/임베디드 환경의 손가락 터치를 같은 방식으로 다룹니다. 즉 `clicked => { ... }` 하나만 작성해두면, 이 코드는 마우스로 클릭하든 터치스크린을 손가락으로 누르든 똑같이 실행됩니다. 입력 장치별로 별도의 처리 코드를 작성할 필요가 없다는 것이 `TouchArea`가 주는 큰 편의입니다.

`TouchArea`는 클릭 여부 외에도 눌려있는 동안 참인 `pressed`라는 프로퍼티를 자체적으로 가지고 있습니다. 이 프로퍼티는 버튼이 눌려있는 동안 시각적인 피드백(예: 색이 살짝 어두워지는 효과)을 주는 데 유용하며, 바로 다음 절의 예제에서 사용해보겠습니다.

## 6.4 실습: 원리부터 이해하는 커스텀 버튼

9장에서는 Slint가 기본으로 제공하는 `Button` 위젯을 배우게 됩니다. 하지만 그 전에, `Rectangle` + `Text` + `TouchArea`를 조합하면 버튼이라는 것이 결국 어떤 원리로 동작하는지 직접 만들어보면서 이해하고 넘어가겠습니다.

```slint
export component CustomButton {
    in property <string> text: "버튼";
    callback clicked();

    Rectangle {
        width: 140px;
        height: 44px;
        border-radius: 6px;
        background: area.pressed ? #2b6cb0 : #4299e1;

        Text {
            text: root.text;
            color: white;
            horizontal-alignment: center;
            vertical-alignment: center;
        }

        area := TouchArea {
            clicked => {
                root.clicked();
            }
        }
    }
}
```

이 컴포넌트를 뜯어보겠습니다.

- `in property <string> text: "버튼";`: 5장에서 배운 입력 프로퍼티입니다. 이 버튼을 사용하는 쪽에서 버튼에 표시할 글자를 정해줄 수 있습니다.
- `callback clicked();`: `CustomButton` 자신이 "나는 클릭됐다"는 사건을 바깥으로 알릴 수 있다는 선언입니다.
- `background: area.pressed ? #2b6cb0 : #4299e1;`: `area`라는 이름을 붙인 `TouchArea`의 `pressed` 프로퍼티를 참조하는 바인딩입니다. 5장에서 본 것처럼, `pressed`가 true가 되는 순간 이 식은 자동으로 다시 계산되어 배경색이 진한 파랑으로 바뀌고, 손을 떼면 다시 원래 색으로 돌아옵니다. 별도의 "색을 바꿔라"라는 명령형 코드가 전혀 없다는 점에 주목하세요.
- `area := TouchArea { ... }`: `TouchArea`에 `area`라는 이름을 붙여서, 같은 컴포넌트 안의 다른 곳(`background` 바인딩)에서 이 엘리먼트의 프로퍼티를 참조할 수 있게 했습니다.
- `clicked => { root.clicked(); }`: `TouchArea`가 클릭을 감지하면, 그 반응으로 `CustomButton` 자신이 선언한 `clicked` 콜백을 쏩니다. `root`는 현재 컴포넌트 자신을 가리키는 이름입니다.

즉 이 버튼은 내부적으로 발생한 `TouchArea`의 클릭 사건을 받아서, 다시 자신만의 `clicked` 콜백으로 "번역"해서 바깥으로 알려주는 역할을 합니다. 이 컴포넌트를 사용하는 쪽은 `TouchArea`가 있다는 사실조차 몰라도 되고, 그저 `clicked` 콜백 하나만 알면 됩니다.

이제 이 버튼을 실제로 사용해보겠습니다.

```slint
export component App {
    property <int> click-count: 0;

    VerticalLayout {
        spacing: 12px;
        padding: 20px;

        Text {
            text: "클릭 횟수: " + click-count;
        }

        CustomButton {
            text: "눌러보세요";
            clicked => {
                click-count += 1;
            }
        }
    }
}
```

`CustomButton`의 `clicked` 콜백이 발생할 때마다 `click-count`를 1씩 늘리고, 그 값은 5장에서 배운 바인딩 덕분에 `Text`에 자동으로 반영됩니다. 콜백(사건에 반응하는 명령형 코드)과 바인딩(값들 사이의 선언적 관계)이 어떻게 자연스럽게 어우러지는지 보여주는 예제입니다.

## 6.5 콜백은 어디서 처리하는가

지금까지의 예제처럼 콜백을 `.slint` 파일 안에서 `=> { ... }` 형태로 직접 처리하는 방식은, 버튼을 누르면 다른 프로퍼티를 갱신하는 것처럼 UI 자체의 상태만 바꾸면 되는 경우에 잘 어울립니다.

하지만 실제 애플리케이션에서는 "파일을 저장한다", "네트워크 요청을 보낸다", "데이터베이스를 조회한다"처럼 UI 바깥의 로직이 필요한 경우가 훨씬 많습니다. 이런 로직은 Slint 언어가 아니라 C++ 코드에서 처리하는 것이 자연스럽습니다. Slint는 `.slint` 파일에서 선언만 해둔 콜백을 C++ 쪽에서 연결해서 처리할 수 있는 방법을 제공하며, 이 경우 `.slint` 파일에는 `clicked => { ... }` 같은 본문을 아예 적지 않고 콜백 선언만 남겨두는 경우도 많습니다.

.slint 안에서 콜백을 직접 처리하는 방식과 C++에서 콜백을 연결하는 방식을 구체적으로 어떻게 오가는지는 7장 "C++와 Slint 연동 기초"에서 본격적으로 다룹니다. 지금은 "콜백의 처리 위치는 UI 파일 안일 수도, C++ 코드 안일 수도 있다"는 것과, 어느 쪽이든 콜백을 선언하는 문법 자체는 이번 장에서 배운 것과 똑같다는 점만 기억해두면 충분합니다.

## 요약

- 콜백은 `callback name();` 또는 `callback name(인자타입, ...) -> 반환타입;` 형태로 선언하는, 순간적으로 발생하는 사건입니다.
- `TouchArea`는 마우스 클릭과 터치를 구분 없이 하나의 방식(`clicked => { ... }`)으로 다루게 해주는 엘리먼트입니다.
- `TouchArea`의 `pressed` 프로퍼티처럼, 콜백과 프로퍼티 바인딩은 함께 사용될 때 진가를 발휘합니다. 상태 변화는 바인딩으로 자동 반영되고, 사건에 대한 반응은 콜백으로 처리됩니다.
- `Rectangle` + `Text` + `TouchArea`를 조합하면 커스텀 버튼을 직접 만들 수 있습니다. 컴포넌트가 자신만의 콜백(`clicked`)을 선언해서 내부의 `TouchArea` 클릭 사건을 바깥에 알리는 패턴은 재사용 가능한 컴포넌트를 만드는 기본기입니다.
- 콜백은 `.slint` 파일 안에서 직접 처리할 수도 있고, C++ 코드에서 연결해서 처리할 수도 있습니다. 후자는 7장에서 자세히 다룹니다.

## 연습문제

1. 클릭할 때마다 `on`과 `off` 상태를 번갈아 오가며 배경색이 바뀌는 토글 스위치 컴포넌트를 `Rectangle`, `Text`, `TouchArea`로 만들어보세요. (힌트: 클릭될 때마다 불리언 프로퍼티 값을 반전시키고, 배경색은 그 프로퍼티를 참조하는 바인딩으로 표현하세요.)
2. `callback value-changed(int) -> bool;`처럼 인자와 반환값을 모두 가진 콜백을 하나 설계하고, 이 콜백이 어떤 상황에서 쓰일 수 있을지(예: 값이 특정 범위를 벗어나면 반환값으로 거부 의사를 알리는 등) 시나리오를 설명해보세요.
3. 이번 장의 `CustomButton` 예제에서 `area := TouchArea { ... }`처럼 이름을 붙이지 않았다면 어떤 문제가 생겼을지 설명해보세요.
4. `CustomButton`을 두 개 배치해서 "증가" 버튼과 "감소" 버튼으로 카운터를 조작하는 작은 화면을 만들어보세요. 카운터 값이 0 미만으로 내려가지 않도록 감소 버튼의 콜백 처리 로직을 작성해보세요.
5. `.slint` 파일 안에서 콜백을 직접 처리하는 방식이 적합한 경우와, C++ 코드로 콜백 처리를 넘기는 것이 더 적합한 경우를 각각 예를 들어 설명해보세요.
