# 14장. 커스텀 스타일링과 테마

[◀ 이전: 13장. 다중 창과 팝업](ch13-다중창과팝업.md) | [📖 목차](00-목차.md) | [다음: 15장. 타이머와 비동기 작업 연동 ▶](ch15-타이머와비동기작업연동.md)


13장에서는 창을 여러 개 관리하는 방법을 다루면서, Global 싱글톤이 창 사이의 데이터를 잇는 다리 역할을 할 수 있다는 것을 확인했습니다. 이번 장에서는 Global 싱글톤을 조금 다른 용도로 씁니다. 바로 애플리케이션 전체의 색상과 폰트를 한 곳에 모아 관리하는 **테마(theme)**로 활용하는 것입니다. 색상 값을 컴포넌트마다 흩어진 하드코딩된 `#hex` 값으로 두는 대신, 5장에서 배운 프로퍼티 바인딩과 12장에서 배운 Global 싱글톤을 결합해 "이 앱의 주 색상은 무엇인가"라는 질문에 답이 하나뿐이도록 만드는 실전 패턴을 살펴봅니다. 여기에 10장에서 배운 `states`와 `animate`를 더해 라이트/다크 테마 전환이 부드럽게 일어나도록 마무리합니다.

## 색상을 하드코딩하면 생기는 문제

3장에서 `Rectangle`의 `background`나 `Text`의 `color`에 `#3498db` 같은 값을 직접 써넣는 방법을 배웠습니다. 작은 예제에서는 아무 문제가 없지만, 컴포넌트 수가 늘어나는 실제 애플리케이션에서는 이야기가 달라집니다.

```slint
// 버튼 컴포넌트
Rectangle { background: #3366ff; }

// 카드 컴포넌트
Rectangle { border-color: #3366ff; }

// 강조 텍스트
Text { color: #3366ff; }
```

브랜드 색상을 `#3366ff`에서 `#2255ee`로 바꾸기로 했다고 해 봅시다. 이 값이 몇 개 파일, 몇 개 컴포넌트에 흩어져 있는지 찾아서 하나하나 고쳐야 합니다. 하나라도 놓치면 화면 어딘가의 색이 미묘하게 어긋난 채로 남습니다. 게다가 나중에 다크 모드를 지원하려고 하면, 이렇게 흩어진 색상값 전부를 "밝을 때 색"과 "어두울 때 색"의 쌍으로 다시 손봐야 합니다.

이 문제의 해법은 색상값 자체를 컴포넌트에 직접 적지 않고, **이름이 붙은 하나의 출처**를 참조하도록 바꾸는 것입니다. 그 출처 역할에 12장에서 배운 Global 싱글톤이 정확히 들어맞습니다.

## Global 싱글톤을 테마 팔레트로 쓰기

애플리케이션이 사용할 색상들을 모아 놓은 `Theme`라는 Global을 선언합니다.

```slint
// theme.slint
export global Theme {
    property <color> primary: #3366ff;
    property <color> background: #ffffff;
    property <color> surface: #f5f5f5;
    property <color> text-color: #1a1a1a;
    property <length> spacing: 8px;
}
```

`export`를 붙여 이 Global을 다른 `.slint` 파일에서도 `import`해 쓸 수 있게 했습니다. 이제 색상이 필요한 모든 컴포넌트는 직접 `#hex` 값을 쓰는 대신 `Theme.프로퍼티이름`을 참조합니다.

```slint
import { Theme } from "theme.slint";

export component PrimaryButton inherits Rectangle {
    background: Theme.primary;
    border-radius: 6px;
    height: 40px;

    Text {
        text: "확인";
        color: Theme.background;
    }
}

export component InfoCard inherits Rectangle {
    background: Theme.surface;
    border-width: 1px;
    border-color: Theme.primary;

    Text {
        text: "안내 문구";
        color: Theme.text-color;
    }
}
```

5장에서 배운 것처럼 Slint의 프로퍼티 바인딩은 반응형입니다. `Theme.primary`를 참조하는 모든 곳은 `Theme.primary`의 값이 바뀌는 즉시 다시 계산됩니다. 즉 `Theme` 선언부의 기본값 하나만 `#2255ee`로 고치면, 이를 참조하는 `PrimaryButton`의 배경색과 `InfoCard`의 테두리색이 동시에 갱신됩니다. 색상값이 코드베이스 여기저기 흩어져 있던 문제가, "정답은 `Theme` 안에만 있다"는 단순한 규칙으로 정리됩니다.

`spacing`처럼 색상이 아닌 값도 같은 방식으로 테마에 포함시킬 수 있습니다. 여백이나 모서리 둥글기 같은 값도 앱 전체에서 일관되게 유지하고 싶다면 `Theme` 안에 함께 선언해 재사용하면 됩니다.

## 라이트/다크 테마 전환: dark-mode 플래그와 표현식 바인딩

이제 다크 모드를 지원해 보겠습니다. 핵심 아이디어는 `Theme`에 `bool` 타입의 스위치 프로퍼티 하나(`dark-mode`)를 두고, 나머지 색상 프로퍼티들이 이 스위치 값에 따라 둘 중 하나를 고르는 삼항 연산자 표현식으로 바인딩되게 만드는 것입니다.

```slint
export global Theme {
    property <bool> dark-mode: false;

    property <color> primary: #3366ff;
    property <color> background: dark-mode ? #1e1e1e : #ffffff;
    property <color> surface: dark-mode ? #2a2a2a : #f5f5f5;
    property <color> text-color: dark-mode ? #f0f0f0 : #1a1a1a;

    callback toggle-theme();
    toggle-theme => { dark-mode = !dark-mode; }
}
```

`background`, `surface`, `text-color`는 더 이상 고정된 값이 아니라 `dark-mode ? A : B` 형태의 표현식입니다. 5장에서 배웠듯 Slint 프로퍼티는 이런 표현식을 바인딩으로 그대로 받아들이고, `dark-mode`가 바뀔 때마다 표현식 전체를 자동으로 다시 평가합니다. `primary`처럼 라이트/다크에 상관없이 고정하고 싶은 색은 그냥 단일 값으로 남겨 두면 됩니다.

`toggle-theme`이라는 콜백도 함께 선언했는데, 이번에는 7장에서 다룬 것처럼 C++에서 구현을 채우는 대신 `.slint` 안에서 바로 구현을 붙였습니다(`toggle-theme => { dark-mode = !dark-mode; }`). 이렇게 하면 UI 어디에서든 이 콜백만 호출하면 다크 모드가 토글됩니다.

```slint
import { Button } from "std-widgets.slint";
import { Theme } from "theme.slint";

export component ThemeToggleButton inherits Button {
    text: Theme.dark-mode ? "라이트 모드로" : "다크 모드로";
    clicked => { Theme.toggle-theme(); }
}
```

물론 C++ 쪽에서 직접 전환하고 싶은 경우도 있습니다. 예를 들어 운영체제의 다크 모드 설정을 읽어와 앱 시작 시 초기값을 맞추고 싶다면, 8장과 12장에서 배운 것처럼 C++에서 Global 프로퍼티를 직접 설정하면 됩니다.

```cpp
auto ui = AppWindow::create();
ui->global<Theme>().set_dark_mode(system_prefers_dark_mode());
ui->run();
```

## 전환을 부드럽게: animate와 states 결합하기

지금까지 만든 것만으로도 다크 모드는 정상적으로 동작합니다. 다만 `dark-mode`가 바뀌는 순간 배경색이 뚝 하고 즉시 바뀝니다. 10장에서 배운 `animate`를 결합하면 이 전환을 부드러운 색상 보간으로 바꿀 수 있습니다.

`animate`는 특정 프로퍼티 바인딩 자리에 붙여, 그 프로퍼티의 값이 어떤 이유로든 바뀔 때마다 자동으로 애니메이션을 적용하도록 지시하는 문법입니다. 값이 바뀌는 원인이 로컬 상태 변화든, 지금처럼 다른 컴포넌트에 있는 Global 프로퍼티의 변화든 상관없이 동일하게 동작합니다.

```slint
import { Theme } from "theme.slint";

export component ThemedPanel inherits Rectangle {
    background: Theme.background;
    animate background { duration: 200ms; easing: ease-in-out; }

    Text {
        text: "테마가 적용된 패널";
        color: Theme.text-color;
        animate color { duration: 200ms; easing: ease-in-out; }
    }
}
```

`ThemedPanel`은 `Theme.background`를 참조하고 있을 뿐, `Theme.dark-mode`가 바뀌었는지 자기가 직접 알 필요가 없습니다. `Theme.dark-mode`가 토글되면 `Theme.background`의 값이 바뀌고, 그 값을 참조하고 있는 `ThemedPanel`의 `background`도 새 값으로 다시 계산되는데, 이때 `animate` 지시문 덕분에 즉시 바뀌는 대신 200밀리초에 걸쳐 색상이 자연스럽게 보간됩니다. 테마가 몇 개의 컴포넌트에서 쓰이든, 각 컴포넌트가 자기 바인딩 자리에 `animate`만 붙여 두면 전환 애니메이션은 저절로 따라옵니다.

여러 프로퍼티를 하나의 의미 있는 상태로 묶어 함께 전환하고 싶을 때는 10장에서 배운 `states`와 `transitions` 조합이 더 어울립니다.

```slint
export component ThemedCard inherits Rectangle {
    border-width: 1px;

    states [
        dark when Theme.dark-mode: {
            background: Theme.surface;
            border-color: #444444;
        }
        light when !Theme.dark-mode: {
            background: Theme.surface;
            border-color: #dddddd;
        }
    ]

    transitions [
        in dark: {
            animate background, border-color { duration: 200ms; }
        }
        in light: {
            animate background, border-color { duration: 200ms; }
        }
    ]
}
```

`states` 블록은 `Theme.dark-mode` 값에 따라 `dark` 또는 `light`라는 이름 붙은 상태 중 하나를 선택하고, 그 상태에 속한 여러 프로퍼티(`background`, `border-color`)를 한 번에 지정합니다. `transitions` 블록은 어떤 상태로 진입할 때(`in dark`, `in light`) 그 상태에서 바뀌는 프로퍼티들에 애니메이션을 적용하라고 지시합니다. 단순히 색상 하나만 바뀌는 경우라면 앞서 본 `animate` 한 줄로 충분하지만, 이번 예제처럼 배경색과 테두리색처럼 여러 프로퍼티가 하나의 의미 있는 이름(다크/라이트)으로 묶여 함께 바뀌어야 할 때는 `states`/`transitions` 조합이 의도를 더 분명하게 드러냅니다.

## 폰트도 테마의 일부로

색상뿐 아니라 폰트도 앱 전체에서 일관되게 관리하고 싶은 대상입니다. `Theme`에 폰트 관련 프로퍼티를 추가하고, 최상위 `Window`의 기본 폰트 프로퍼티에 연결하면 됩니다.

```slint
export global Theme {
    // ...색상 프로퍼티는 앞과 동일...

    property <string> font-family: "Noto Sans KR";
    property <length> base-font-size: 14px;
}
```

```slint
import { Theme } from "theme.slint";

export component AppWindow inherits Window {
    default-font-family: Theme.font-family;
    default-font-size: Theme.base-font-size;

    // 이 창 안의 Text 엘리먼트들은 별도로 font-family나
    // font-size를 지정하지 않는 한 위 기본값을 따른다
}
```

`Window`는 `default-font-family`, `default-font-size` 같은 프로퍼티를 제공하며, 이 값은 해당 창 안의 모든 `Text` 엘리먼트가 개별적으로 `font-family`나 `font-size`를 지정하지 않았을 때 사용하는 기본값이 됩니다. 이 기본값을 `Theme.font-family`, `Theme.base-font-size`에 연결해 두면, 색상과 마찬가지로 폰트 역시 `Theme` 한 곳만 고치면 앱 전체에 반영됩니다. 예를 들어 사용자가 "큰 글씨" 접근성 옵션을 켰을 때 `Theme.base-font-size`를 키워 주는 콜백 하나로 앱 전체의 글자 크기를 일괄 조정하는 식의 활용도 가능합니다.

## 종합 예제: 하나의 Theme로 앱 전체 꾸미기

지금까지 다룬 요소들을 하나로 모아 보겠습니다.

```slint
// theme.slint
export global Theme {
    property <bool> dark-mode: false;

    property <color> primary: #3366ff;
    property <color> background: dark-mode ? #1e1e1e : #ffffff;
    property <color> surface: dark-mode ? #2a2a2a : #f5f5f5;
    property <color> text-color: dark-mode ? #f0f0f0 : #1a1a1a;

    property <string> font-family: "Noto Sans KR";

    callback toggle-theme();
    toggle-theme => { dark-mode = !dark-mode; }
}
```

```slint
// app-window.slint
import { Button } from "std-widgets.slint";
import { Theme } from "theme.slint";

export component AppWindow inherits Window {
    title: "테마 예제";
    width: 360px;
    height: 220px;
    default-font-family: Theme.font-family;

    background: Theme.background;
    animate background { duration: 200ms; }

    VerticalLayout {
        padding: 20px;
        spacing: 12px;

        Text {
            text: "Slint 테마 데모";
            font-size: 18px;
            color: Theme.text-color;
            animate color { duration: 200ms; }
        }

        Rectangle {
            height: 60px;
            background: Theme.surface;
            border-width: 1px;
            border-color: Theme.primary;
            animate background, border-color { duration: 200ms; }

            Text {
                text: "테마가 적용된 카드";
                color: Theme.text-color;
            }
        }

        Button {
            text: Theme.dark-mode ? "라이트 모드로" : "다크 모드로";
            clicked => { Theme.toggle-theme(); }
        }
    }
}
```

버튼을 누르면 `Theme.toggle-theme()`이 `Theme.dark-mode`를 뒤집고, 이를 참조하는 `background`, `surface`, `text-color`가 모두 새 값으로 재계산됩니다. 이 창 안의 배경, 카드, 텍스트는 각자의 바인딩 자리에 붙은 `animate` 덕분에 색이 뚝 끊기지 않고 부드럽게 전환되며, 폰트는 `default-font-family`를 통해 `Theme.font-family` 하나로 통일되어 있습니다. C++ 쪽 코드는 이 예제에서 딱히 손댈 것이 없다는 점도 눈여겨볼 만합니다. 테마 전환 로직 전체가 `.slint` 쪽에, 그중에서도 `Theme` Global 하나에 모여 있기 때문입니다.

## 요약

- 색상을 컴포넌트마다 하드코딩하는 대신, `global Theme { property <color> ...; }` 형태로 팔레트를 선언하고 각 컴포넌트에서 `Theme.프로퍼티이름`을 참조하면 색상 관리의 출처가 하나로 모입니다.
- `Theme`에 `bool` 타입의 `dark-mode` 같은 스위치 프로퍼티를 두고, 나머지 색상 프로퍼티를 `dark-mode ? A : B` 형태의 표현식으로 바인딩하면 라이트/다크 테마가 자동으로 갈립니다.
- 테마 전환 콜백은 `.slint` 안에 직접 구현해 UI 어디서든 호출하게 만들 수도 있고, C++에서 `global<Theme>().set_dark_mode(...)`로 제어할 수도 있습니다.
- `animate` 지시문을 색상 바인딩 자리에 붙이면, 그 값이 Global 프로퍼티 변화로 인해 바뀌더라도 자동으로 부드럽게 보간됩니다. 여러 프로퍼티를 의미 있는 이름으로 묶어 함께 전환할 때는 `states`/`transitions` 조합이 더 적합합니다.
- 폰트 역시 `Theme`에 `font-family`, `font-size` 같은 프로퍼티로 포함시키고 `Window`의 `default-font-family`, `default-font-size`에 연결하면, 색상과 같은 방식으로 앱 전체 폰트를 한 곳에서 관리할 수 있습니다.

## 연습문제

1. `primary`, `background`, `text-color` 세 가지 색상 프로퍼티를 가진 `Theme` Global을 선언하고, 두 개 이상의 서로 다른 컴포넌트가 이 색상들을 참조하도록 만들어 보세요. `Theme`의 기본값만 바꿔서 두 컴포넌트의 색이 동시에 바뀌는지 확인해 보세요.
2. `Theme`에 `dark-mode` 불리언 프로퍼티를 추가하고, 최소 세 개의 색상 프로퍼티를 삼항 연산자로 다크/라이트 값을 갈라 바인딩해 보세요.
3. `toggle-theme` 콜백을 `Theme` 안에 구현하고, 버튼 클릭으로 이 콜백을 호출해 다크 모드가 토글되는지 확인해 보세요.
4. 배경색 바인딩에 `animate`를 붙인 컴포넌트와 붙이지 않은 컴포넌트를 나란히 두고 다크 모드를 전환해 보면서 시각적 차이를 비교해 보세요.
5. `Theme`에 `font-family` 프로퍼티를 추가하고 `Window`의 `default-font-family`에 연결한 뒤, 폰트를 다른 값으로 바꾸면 창 안의 모든 텍스트가 함께 바뀌는지 확인해 보세요.
