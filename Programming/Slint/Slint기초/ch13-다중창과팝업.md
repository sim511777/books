# 13장. 다중 창과 팝업

[◀ 이전: 12장. 전역 싱글톤(Global)](ch12-전역싱글톤.md) | [📖 목차](00-목차.md) | [다음: 14장. 커스텀 스타일링과 테마 ▶](ch14-커스텀스타일링과테마.md)


지금까지 우리가 다룬 예제는 대부분 창(window) 하나로 완결되는 애플리케이션이었습니다. 하지만 실제 프로그램은 그렇지 않은 경우가 많습니다. 메인 작업 창과 별도로 뜨는 설정 창, 파일마다 새로 열리는 편집기 창, 버튼을 누르면 나타나는 작은 드롭다운 메뉴처럼, 하나의 애플리케이션이 여러 개의 화면 영역을 동시에 혹은 필요할 때만 관리해야 하는 상황은 흔합니다. 이번 장에서는 Slint 애플리케이션이 여러 개의 독립된 창을 갖는 기본 패턴과, 부모 창 위에 떠 있는 작은 오버레이인 `PopupWindow`를 다룹니다. 두 주제 모두 7장과 8장에서 익힌 C++ 연동, 12장에서 익힌 Global 싱글톤, 6장에서 익힌 콜백과 `TouchArea`를 그대로 재료로 사용합니다.

## 여러 개의 창이 필요한 순간

먼저 "창을 여러 개 둔다"는 것이 정확히 어떤 의미인지 짚고 넘어가겠습니다. 지금까지 본 것처럼 하나의 `Window` 안에 여러 화면을 담고, `property <int> current-page`처럼 상태값에 따라 보이는 내용을 바꾸는 방식(10장에서 다룬 `states`와 궤를 같이합니다)도 여전히 유효한 선택지입니다. 이 방식은 사용자에게 하나의 창만 보이고, 그 안에서 화면 전환이 일어나는 형태입니다.

반면 진짜 여러 개의 **운영체제 수준 창**이 필요한 경우도 있습니다. 설정 화면을 메인 창과 독립적으로 움직이고 싶다거나, 사용자가 메인 창은 그대로 둔 채 설정 창만 닫고 싶다거나, 문서 편집기처럼 파일마다 별도의 창을 띄우고 싶은 경우입니다. 이럴 때는 각 창을 별도의 `Window` 파생 컴포넌트로 선언하고, C++ 쪽에서 이들을 독립적으로 생성·관리해야 합니다. 이번 장에서 다루는 것이 바로 이 두 번째 방식입니다.

## 창마다 별도의 컴포넌트로 선언하기

여러 창을 만드는 첫걸음은 단순합니다. `Window`를 상속하는 컴포넌트를 창의 개수만큼 선언하는 것입니다. 이때 한 컴포넌트 안에 다른 컴포넌트를 자식으로 중첩시키지 않고, 서로 독립적인 최상위 컴포넌트로 나란히 선언한다는 점이 핵심입니다.

```slint
import { Button } from "std-widgets.slint";

export component MainWindow inherits Window {
    title: "메인 창";
    width: 400px;
    height: 300px;

    callback open-settings();

    VerticalLayout {
        padding: 20px;
        spacing: 12px;

        Text {
            text: "메인 애플리케이션 창";
            font-size: 18px;
        }

        Button {
            text: "설정 열기";
            clicked => { open-settings(); }
        }
    }
}

export component SettingsWindow inherits Window {
    title: "설정";
    width: 320px;
    height: 240px;

    VerticalLayout {
        padding: 20px;
        spacing: 12px;

        Text {
            text: "설정 창";
            font-size: 16px;
        }
    }
}
```

`MainWindow`와 `SettingsWindow`는 둘 다 `Window`를 상속하지만, 한쪽이 다른 쪽 안에 중첩되어 있지 않습니다. 같은 `.slint` 파일(혹은 서로 다른 파일에 나눠 두고 `import`로 연결해도 됩니다) 안에 나란히 선언된 두 개의 독립된 최상위 컴포넌트입니다. 이렇게 선언된 각 컴포넌트는 Slint 컴파일러가 C++로 변환할 때 각각 별도의 클래스가 되고, 실제로 인스턴스화되면 각자 자기 제목표시줄과 크기, 위치를 가진 별개의 OS 창으로 나타납니다.

`MainWindow`에는 `open-settings`라는 콜백을 선언해 두었습니다. 이 콜백 자체는 아직 아무 동작도 정의하지 않았는데, 이는 "설정 창을 여는 행위"가 `MainWindow`만으로는 처리할 수 없는, C++ 쪽에서 다른 창의 존재를 알아야만 가능한 일이기 때문입니다. 이 부분은 잠시 후 C++ 코드에서 채웁니다.

## C++에서 각 창을 생성하고 관리하기

7장에서 배웠듯, `.slint` 파일의 최상위 컴포넌트는 C++ 쪽에서 `create()` 정적 함수로 인스턴스화합니다. 창이 여러 개라면 그만큼 `create()` 호출도 여러 번 필요합니다.

```cpp
#include "main-window.h"

int main() {
    auto main_window = MainWindow::create();
    auto settings_window = SettingsWindow::create();

    main_window->on_open_settings([&] {
        settings_window->show();
    });

    main_window->run();
}
```

`MainWindow::create()`와 `SettingsWindow::create()`는 각각 독립된 `slint::ComponentHandle`을 반환합니다. `main_window->on_open_settings(...)`로 `MainWindow`에서 선언한 `open-settings` 콜백에 C++ 람다를 연결하는 방식은 7장에서 다룬 것과 동일합니다. 다만 이번에는 그 람다 안에서 `settings_window->show()`를 호출해, 버튼 클릭이 다른 창을 화면에 띄우는 동작으로 이어지도록 만들었습니다.

`main_window->run()`은 `main_window`를 화면에 보여주고 이벤트 루프를 시작합니다. 이벤트 루프가 도는 동안에는 `settings_window->show()`처럼 다른 창을 추가로 보여주는 호출도 자연스럽게 처리됩니다. 즉 이벤트 루프는 애플리케이션 전체에 하나만 존재하며, 특정 창에 종속된 것이 아닙니다.

만약 두 창을 처음부터 동시에 보여주고 싶다면, 어느 한쪽에서 `run()`을 호출하는 대신 각각 `show()`한 뒤 별도의 함수로 이벤트 루프를 시작할 수 있습니다.

```cpp
int main() {
    auto main_window = MainWindow::create();
    auto settings_window = SettingsWindow::create();

    main_window->on_open_settings([&] {
        settings_window->show();
    });

    main_window->show();
    settings_window->show();
    slint::run_event_loop();
}
```

`slint::run_event_loop()`는 특정 창에 묶이지 않은 전역 함수로, 이미 `show()`로 화면에 띄워 둔 모든 창에 대해 이벤트 루프를 시작합니다. 화면에 보이는 창이 하나도 남지 않을 때까지 이 함수는 반환하지 않습니다.

여기서 반드시 기억해야 할 것이 하나 있습니다. `main_window`와 `settings_window`는 `main()` 함수의 지역 변수입니다. `ComponentHandle`이 스코프를 벗어나 소멸되면 그 창도 함께 파괴됩니다. 콜백 람다 안에서 다른 창의 핸들을 참조해야 하는 경우가 많으므로, 두 핸들 모두 이벤트 루프가 도는 동안 살아 있어야 한다는 점을 신경 써야 합니다. 위 예제처럼 `main()` 안의 지역 변수로 두거나, 애플리케이션을 감싸는 클래스의 멤버 변수로 두는 것이 일반적인 해법입니다.

## 창 사이에서 데이터 주고받기: Global 싱글톤의 함정과 활용

12장에서 Global 싱글톤을 사용해 애플리케이션 전역 상태를 한 곳에서 관리하는 방법을 배웠습니다. 여러 창을 다루는 지금, "그럼 `MainWindow`와 `SettingsWindow`가 같은 Global을 참조하면 자동으로 상태가 공유되지 않을까?"라는 질문이 자연스럽게 떠오를 수 있습니다.

여기서 중요한 함정이 하나 있습니다. `MainWindow::create()`와 `SettingsWindow::create()`는 서로 독립된 컴포넌트 트리를 만드는 별개의 호출입니다. 두 컴포넌트가 `.slint` 코드상으로 같은 이름의 Global을 참조하고 있더라도, 각각의 `create()` 호출은 그 Global의 **자기만의 인스턴스**를 만듭니다. 즉 `settings_window`에서 Global 프로퍼티를 바꿔도 `main_window`가 보고 있는 같은 이름의 Global 인스턴스는 자동으로 갱신되지 않습니다.

따라서 여러 창 사이에서 데이터를 공유하려면, C++ 코드가 두 창의 Global 인스턴스를 명시적으로 동기화하는 다리 역할을 해야 합니다. 8장과 12장에서 배운 것처럼 각 창의 핸들에서 `global<T>()`로 Global에 접근해 프로퍼티를 읽고 쓸 수 있다는 점을 그대로 활용합니다.

```slint
export global AppState {
    property <string> username: "손님";
}

export component MainWindow inherits Window {
    title: "메인 창";
    width: 400px;
    height: 300px;

    callback open-settings();

    Text {
        text: "환영합니다, " + AppState.username;
    }
}

export component SettingsWindow inherits Window {
    title: "설정";
    width: 320px;
    height: 240px;

    callback username-changed(string);

    VerticalLayout {
        padding: 20px;

        Text { text: "사용자 이름: " + AppState.username; }
    }
}
```

```cpp
auto main_window = MainWindow::create();
auto settings_window = SettingsWindow::create();

settings_window->on_username_changed([&](slint::SharedString new_name) {
    // settings_window 자신의 AppState뿐 아니라
    // main_window가 보고 있는 AppState도 함께 갱신해 준다
    settings_window->global<AppState>().set_username(new_name);
    main_window->global<AppState>().set_username(new_name);
});
```

`on_username_changed` 콜백 안에서 두 창의 `global<AppState>()`를 모두 갱신하는 이유가 바로 위에서 설명한 함정 때문입니다. 두 창은 같은 이름의 Global을 각자 별도로 갖고 있으므로, C++ 코드가 "이 값이 바뀌면 다른 창의 값도 이렇게 바꿔라"라고 명시적으로 연결해 주어야 합니다. 창이 늘어날수록 이런 동기화 코드도 늘어나므로, 실제 프로젝트에서는 이 동기화 로직을 한 함수나 클래스로 모아 두고 새 창을 추가할 때마다 그 목록에 등록하는 식으로 관리하는 것이 유지보수에 유리합니다.

## PopupWindow: 부모 창 위에 뜨는 작은 오버레이

지금까지 다룬 것은 각자 독립된 제목표시줄과 위치를 가진 "진짜" 별도의 창이었습니다. 하지만 툴팁이나 드롭다운 메뉴, 우클릭 컨텍스트 메뉴처럼 부모 창에 딱 붙어서 짧게 나타났다 사라지는 작은 UI 조각에는 이런 무거운 창이 어울리지 않습니다. Slint는 이런 용도를 위해 `PopupWindow`라는 전용 엘리먼트를 제공합니다.

`PopupWindow`는 이름에 "Window"가 들어가 있지만, 앞서 다룬 `Window` 상속 컴포넌트와는 성격이 다릅니다. 별도의 제목표시줄이나 독립된 데스크톱 창이 아니라, **부모 창의 좌표계 위에 떠 있는 오버레이**입니다. 부모 창 기준의 `x`, `y` 좌표에 나타나고, 필요할 때만 보였다가 사용자가 바깥쪽을 클릭하면 자동으로 사라지는 것이 기본 동작입니다.

```slint
import { Button } from "std-widgets.slint";

export component MainWindow inherits Window {
    width: 300px;
    height: 200px;

    menu-popup := PopupWindow {
        x: 20px;
        y: 50px;
        width: 140px;
        height: 100px;

        Rectangle {
            background: white;
            border-width: 1px;
            border-color: #cccccc;

            VerticalLayout {
                Text { text: "항목 1"; }
                Text { text: "항목 2"; }
            }
        }
    }

    Button {
        text: "메뉴 열기";
        clicked => { menu-popup.show(); }
    }
}
```

`menu-popup := PopupWindow { ... }`처럼 `:=` 문법으로 이름(id)을 붙여 두면, 같은 컴포넌트 안 다른 곳에서 이 이름으로 팝업을 제어할 수 있습니다. `PopupWindow`는 기본적으로 화면에 보이지 않는 상태로 시작하고, `menu-popup.show()`를 호출해야 비로소 나타납니다. `x`와 `y`는 부모 창(여기서는 `MainWindow`)의 왼쪽 위 모서리를 기준으로 한 상대 좌표입니다.

기본 동작으로 `PopupWindow`는 사용자가 어딘가를 클릭하면 자동으로 닫힙니다. 이 동작은 `close-policy` 프로퍼티로 조정할 수 있습니다. `PopupClosePolicy.close-on-click`(기본값, 팝업 안팎 어디를 클릭해도 닫힘), `PopupClosePolicy.close-on-click-outside`(팝업 바깥을 클릭했을 때만 닫힘), `PopupClosePolicy.no-auto-close`(자동으로 닫히지 않고 코드로만 닫을 수 있음) 세 가지 중 골라 쓸 수 있습니다. 코드에서 명시적으로 닫고 싶을 때는 `menu-popup.close()`를 호출합니다.

## 팝업을 열고 닫는 것을 콜백과 TouchArea로 제어하기

6장에서 배운 콜백과 `TouchArea`는 `PopupWindow`를 다룰 때도 똑같이 활용됩니다. 버튼 클릭으로 팝업을 여는 방금 예제를 조금 더 발전시켜, 팝업 안의 각 메뉴 항목을 클릭했을 때 항목을 선택하는 콜백을 부모 쪽으로 전달하면서 동시에 팝업을 닫는 예제를 만들어 보겠습니다. 11장에서 다룰 `for` 반복 문법을 살짝 앞당겨 써서 메뉴 항목을 나열합니다.

```slint
export component MainWindow inherits Window {
    width: 300px;
    height: 200px;

    callback item-selected(string);

    menu := PopupWindow {
        x: 20px;
        y: 60px;
        width: 120px;
        height: 80px;
        close-policy: PopupClosePolicy.close-on-click-outside;

        Rectangle {
            background: white;
            border-width: 1px;
            border-color: #cccccc;

            VerticalLayout {
                for label in ["복사", "붙여넣기"]: TouchArea {
                    clicked => {
                        item-selected(label);
                        menu.close();
                    }

                    Text {
                        text: label;
                        color: parent.has-hover ? #3366ff : #333333;
                    }
                }
            }
        }
    }

    TouchArea {
        width: 100%;
        height: 40px;

        clicked => { menu.show(); }

        Text { text: "메뉴 ▾"; }
    }
}
```

여기서 `close-policy`를 `close-on-click-outside`로 지정한 이유는, 항목 자체를 클릭했을 때 팝업이 먼저 저절로 닫혀 버리면 `TouchArea`의 `clicked` 안에서 `item-selected(label)`을 호출하는 순서가 꼬일 수 있기 때문입니다. 대신 각 항목의 `TouchArea`가 클릭되면 `item-selected` 콜백으로 어떤 항목이 선택되었는지 부모(여기서는 `MainWindow` 자신)에 알리고, 이어서 `menu.close()`를 명시적으로 호출해 팝업을 닫습니다. 바깥쪽을 클릭했을 때는 여전히 자동으로 닫힙니다.

이 `item-selected` 콜백은 다른 콜백과 마찬가지로 C++에서 `on_item_selected(...)`로 구독해, 실제로 "복사" 또는 "붙여넣기" 동작을 수행하는 로직과 연결하면 됩니다.

```cpp
auto main_window = MainWindow::create();

main_window->on_item_selected([](slint::SharedString label) {
    // 실제 복사/붙여넣기 로직 수행
});

main_window->run();
```

정리하면, `PopupWindow`를 다루는 흐름은 지금까지 배운 것들의 조합입니다. `TouchArea`나 `Button`의 `clicked`에서 `.show()`를 호출해 팝업을 열고, 팝업 안의 인터랙션에서 `.close()`를 호출해 닫으며, 팝업 안에서 일어난 선택 결과는 콜백을 통해 부모 컴포넌트와 C++ 코드로 전달합니다.

## 요약

- 진짜 독립된 OS 창이 여러 개 필요할 때는, 각 창을 서로 중첩되지 않은 별도의 `component ... inherits Window`로 선언하고 C++에서 각각 `create()`로 인스턴스화합니다.
- 하나의 창에서 `run()`을 호출하면 이벤트 루프가 시작되고, 그 안에서 다른 창의 `show()`를 호출해도 정상적으로 처리됩니다. 여러 창을 동시에 띄우고 싶다면 각각 `show()`한 뒤 `slint::run_event_loop()`를 호출하는 방식도 사용할 수 있습니다.
- 각 창의 `ComponentHandle`은 이벤트 루프가 도는 동안 살아 있어야 하므로, 지역 변수나 멤버 변수로 붙잡아 두어야 합니다.
- 같은 이름의 Global 싱글톤이라도 `create()` 호출마다 독립된 인스턴스가 생성됩니다. 창 사이에 데이터를 공유하려면 C++ 코드가 양쪽 창의 Global 인스턴스를 명시적으로 동기화해 주어야 합니다.
- `PopupWindow`는 별도의 데스크톱 창이 아니라 부모 창 좌표 위에 뜨는 오버레이입니다. `x`, `y`로 위치를, `close-policy`로 자동 닫힘 동작을 지정하며, `.show()`와 `.close()`로 열고 닫습니다.
- 팝업을 여닫는 로직은 6장에서 배운 콜백과 `TouchArea`의 `clicked` 핸들러로 자연스럽게 구현됩니다.

## 연습문제

1. `MainWindow`와 `AboutWindow`라는 두 개의 독립된 `Window` 파생 컴포넌트를 선언하고, `MainWindow`의 버튼을 클릭하면 `AboutWindow`가 열리도록 C++ 코드를 작성해 보세요.
2. 두 창을 동시에 화면에 띄운 채 시작하는 프로그램을, `run()` 한 번으로 구현하는 방식과 `show()` + `slint::run_event_loop()` 조합으로 구현하는 방식 두 가지로 각각 작성해 보세요.
3. 같은 이름의 Global을 두 개의 창이 참조하도록 만든 뒤, 한쪽 창에서 값을 바꿨을 때 다른 쪽 창에는 자동으로 반영되지 않는다는 사실을 직접 코드로 확인해 보세요. 그런 다음 C++ 동기화 코드를 추가해 두 창의 값이 일치하도록 고쳐 보세요.
4. 버튼을 클릭하면 근처에 나타나는 `PopupWindow`를 만들고, `close-policy`를 세 가지 값(`close-on-click`, `close-on-click-outside`, `no-auto-close`) 각각으로 바꿔가며 동작 차이를 관찰해 보세요.
5. `PopupWindow` 안에 메뉴 항목 세 개를 두고, 각 항목을 클릭하면 어떤 항목이 선택되었는지 콜백으로 C++에 알리면서 팝업이 닫히는 드롭다운 메뉴를 만들어 보세요.
