## A.1 설치와 빌드 환경 재정리

2장에서 다룬 Slint 개발 환경 구성을 간단히 다시 정리합니다. 세부 설명은 2장을 참고하세요.

Slint의 C++ 바인딩은 CMake를 통해 프로젝트에 통합하는 것이 표준적인 방법입니다. 어떤 방식으로 설치하든 최종적으로는 `find_package(Slint REQUIRED)`가 성공하고 `Slint::Slint`라는 CMake 타겟이 만들어져야 합니다.

```cmake
find_package(Slint REQUIRED)

add_executable(my_app main.cpp)
slint_target_sources(my_app ui/app-window.slint)
target_link_libraries(my_app PRIVATE Slint::Slint)
```

Slint를 시스템에 준비하는 방법은 크게 두 가지입니다.

- **vcpkg**: vcpkg로 Slint 패키지를 설치하고, vcpkg 툴체인 파일을 CMake에 넘겨주는 방식입니다.
- **CMake `FetchContent`**: 별도의 패키지 매니저 없이, CMake가 빌드 시점에 Slint 소스를 직접 내려받아 서브 프로젝트로 포함시키는 방식입니다.

UI 마크업만 빠르게 미리보고 싶을 때는 `slint-viewer` 도구에 `.slint` 파일을 인자로 넘겨 C++ 빌드 없이 곧바로 확인할 수 있습니다.

```bash
slint-viewer ui/app-window.slint
```

## A.2 주요 키워드/API 요약표

이 책 전체에서 등장한 핵심 문법과 C++ API를 장별로 정리합니다. 각 항목의 자세한 설명은 해당 장을 참고하세요.

| 장 | 키워드/API | 설명 |
|---|---|---|
| 3장 | `component 이름 inherits 부모 { ... }` | 컴포넌트를 선언하고 기존 엘리먼트나 컴포넌트를 상속받습니다. |
| 3장 | `property <타입> 이름: 기본값;` | 컴포넌트에 커스텀 프로퍼티를 선언합니다. |
| 3장 | `Rectangle`, `Text`, `Image` | 배경/컨테이너, 문자열 표시, 이미지 표시를 담당하는 기본 엘리먼트입니다. |
| 3장 | `@image-url("경로")` | 이미지 리소스를 컴파일 시점에 포함시키는 구문입니다. |
| 4장 | `VerticalLayout`, `HorizontalLayout`, `GridLayout` | 자식 엘리먼트를 세로, 가로, 격자로 배치하는 레이아웃 컨테이너입니다. |
| 5장 | `in`, `out`, `in-out` | 프로퍼티의 값이 어느 쪽 책임인지 나타내는 방향 키워드입니다. |
| 6장 | `callback 이름(인자타입): 반환타입;` | 컴포넌트가 발생시키는 이벤트를 선언합니다. |
| 6장 | `이벤트 => { ... }` | 위젯의 내장 이벤트(예: `clicked`)에 동작을 연결하는 문법입니다. |
| 7장 | `AppWindow::create()` | 생성된 컴포넌트 클래스의 인스턴스를 `slint::ComponentHandle<T>`로 만듭니다. |
| 7장 | `ui->run()` | 이벤트 루프를 시작해 창을 화면에 표시합니다. |
| 8장 | `set_*`/`get_*` | `.slint`의 프로퍼티를 C++에서 읽고 쓰는 생성된 메서드입니다(케밥 케이스는 밑줄로 변환). |
| 8장 | `on_*`/`invoke_*` | `.slint`의 콜백을 C++에서 처리하거나 직접 호출하는 생성된 메서드입니다. |
| 8장 | `slint::SharedString` | Slint의 `string` 타입에 대응하는 C++ 문자열 타입입니다. |
| 9장 | `Button`, `CheckBox`, `LineEdit`, `ListView` 등 | `std-widgets.slint`에서 제공하는 표준 위젯들입니다. |
| 10장 | `animate 프로퍼티 { duration: ...; }` | 프로퍼티 값이 바뀔 때 그 변화를 부드럽게 보간합니다. |
| 10장 | `states [ 이름 when 조건 : { ... } ]` | 조건에 따라 여러 프로퍼티 값을 한 번에 전환하는 상태 블록입니다. |
| 11장 | `[타입]` | 배열(모델) 타입을 나타내는 프로퍼티 타입 문법입니다. |
| 11장 | `for item[i] in 모델 : ...` | 모델의 각 항목에 대해 엘리먼트를 반복 생성합니다. |
| 11장 | `slint::VectorModel<T>` | `std::vector` 기반으로 구현된 C++ 쪽 모델 클래스입니다. |
| 11장 | `push_back`/`erase`/`row_data`/`set_row_data` | `VectorModel`에서 항목을 추가·삭제·조회·갱신하는 메서드입니다. |
| 12장 | `global 이름 { ... }` | 여러 컴포넌트가 공유하는 전역 싱글톤을 선언합니다. |
| 12장 | `ui->global<이름>()` | C++에서 전역 싱글톤의 프로퍼티/콜백에 접근하는 방법입니다. |
| 17장 | FemtoVG, Skia | 데스크톱에서 사용되는 GPU 가속 렌더링 백엔드의 이름입니다. |
| 17장 | 소프트웨어 렌더러 | GPU 없이 CPU로 픽셀을 직접 그리는, 임베디드 환경을 위한 렌더링 백엔드입니다. |

## A.3 참고할 만한 공식 자료

더 깊이 있는 내용이나 이 책에서 다루지 않은 최신 기능을 확인하고 싶다면 다음 공식 자료를 참고하시기 바랍니다. 실제 주소는 검색 엔진에서 이름 그대로 검색하면 쉽게 찾을 수 있습니다.

- **Slint 공식 웹사이트**: 언어 문법, C++/Rust/JavaScript/Python 각 바인딩의 API 문서, 튜토리얼을 제공하는 공식 채널입니다.
- **Slint GitHub 저장소**: 소스 코드, 이슈 트래커, 다양한 예제 프로젝트(임베디드 보드 예제 포함)를 확인할 수 있습니다.
- **slint-viewer**: 2장에서 소개한, `.slint` 파일을 C++ 빌드 없이 바로 열어볼 수 있는 커맨드라인 도구입니다.
- **Slint 릴리스 노트**: Slint는 활발히 개발되고 있는 프로젝트이므로, 새 버전이 나올 때마다 추가되거나 바뀌는 API를 확인하는 습관을 들이면 좋습니다.

## A.4 다음 학습 단계 제안

이 책 한 권으로 Slint와 C++를 이용한 GUI 프로그래밍의 기초를 모두 다졌습니다. 이후에는 다음과 같은 방향으로 학습을 이어가 볼 것을 제안합니다.

- **더 큰 실전 앱 만들기**: 18장의 Todo 앱보다 화면 수가 많고, 여러 창(13장)과 전역 상태(12장)가 복잡하게 얽히는 애플리케이션을 직접 설계하고 만들어 보세요. 규모가 커질수록 프로퍼티 방향(5장)과 전역 싱글톤 설계의 중요성이 체감됩니다.
- **다른 언어 바인딩과 비교해보기**: 1장에서 언급했듯 Slint는 C++ 외에도 Rust, JavaScript(Node.js), Python 바인딩을 공식 지원합니다. 같은 `.slint` UI를 Rust나 Python 애플리케이션 로직과 연결해보면, "UI 정의와 애플리케이션 로직이 분리되어 있다"는 Slint의 설계가 언어 경계를 넘어서도 얼마나 일관되는지 직접 체감할 수 있습니다.
- **임베디드 타겟 실습**: 17장에서 개념만 소개한 임베디드/MCU 타겟팅을 실제 보드(예: 라즈베리 파이 계열 보드나 개발용 MCU 보드)로 직접 실습해보세요. 크로스 컴파일 환경 구성부터 시작해야 하므로 별도의 학습 곡선이 있지만, 데스크톱에서 검증한 `.slint` UI가 실제 하드웨어의 작은 화면에 그대로 뜨는 경험은 이 책만으로는 얻기 어려운 감각을 줍니다.
- **커스텀 렌더링과 애니메이션 심화**: 16장에서 다룬 이미지·커스텀 렌더링과 10장의 애니메이션 시스템을 더 깊이 파고들어, 데이터 시각화나 커스텀 위젯처럼 표준 위젯만으로는 표현하기 어려운 화면에 도전해보세요.

Slint는 여전히 활발히 발전하고 있는 툴킷입니다. 이 책에서 다진 기초 문법과 C++ 연동 패턴을 발판 삼아, 공식 문서와 예제 저장소를 직접 탐험하면서 여러분만의 애플리케이션을 만들어 나가시기 바랍니다.
