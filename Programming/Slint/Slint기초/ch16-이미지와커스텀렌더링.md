# 16장. 이미지와 커스텀 렌더링

[◀ 이전: 15장. 타이머와 비동기 작업 연동](ch15-타이머와비동기작업연동.md) | [📖 목차](00-목차.md) | [다음: 17장. 임베디드/크로스플랫폼 타겟팅 ▶](ch17-임베디드크로스플랫폼타겟팅.md)


버튼과 텍스트만으로 이루어진 화면은 많지 않습니다. 앱 아이콘, 로고, 일러스트레이션처럼 이미 만들어진 그림 파일을 그대로 보여줘야 할 때도 있고, 반대로 어디에도 없는 그래프나 게이지처럼 데이터에 따라 모양이 달라지는 그림을 직접 그려야 할 때도 있습니다. 이번 장에서는 이 두 가지를 모두 다룹니다. 먼저 `Image` 엘리먼트로 이미지 파일을 화면에 표시하는 기본기를 익히고, 이어서 `Rectangle`이나 `Path` 같은 기본 도형 엘리먼트를 조합해서 이미지 파일 없이도 화면에 그림을 "그리는" 방법을 살펴봅니다.

## 16.1 Image 엘리먼트로 이미지 표시하기

Slint에서 이미지 파일을 화면에 보여주는 가장 기본적인 방법은 `Image` 엘리먼트에 `source` 프로퍼티를 지정하는 것입니다.

```slint
export component IconExample inherits Window {
    width: 200px;
    height: 200px;

    Image {
        source: @image-url("assets/icon.png");
    }
}
```

여기서 눈여겨봐야 할 것은 `@image-url("...")`이라는 문법입니다. 이것은 일반 문자열이 아니라 Slint 컴파일러가 이해하는 특수한 표기법으로, **컴파일 시점에 지정된 경로의 이미지 파일을 찾아서 애플리케이션 리소스로 포함시켜 줍니다.** 즉 `source: "assets/icon.png"`처럼 그냥 문자열 경로를 적는 것과는 다릅니다. 문자열 경로였다면 실행 시점에 그 경로에서 파일을 찾아 읽어야 하지만, `@image-url(...)`로 지정한 이미지는 컴파일 단계에서 이미지 데이터 자체가 애플리케이션에 엮여 들어가기 때문에, 실행 파일만 배포해도 이미지가 항상 함께 따라갑니다. 경로는 보통 `.slint` 파일을 기준으로 한 상대 경로를 사용합니다.

## 16.2 크기 조정과 이미지 맞춤 방식

`Image`도 다른 엘리먼트와 마찬가지로 `width`, `height`로 크기를 지정할 수 있습니다.

```slint
Image {
    source: @image-url("assets/photo.jpg");
    width: 150px;
    height: 100px;
}
```

문제는 지정한 크기의 가로세로 비율이 원본 이미지의 비율과 다를 때입니다. 이럴 때 이미지를 어떻게 채워 넣을지 결정하는 것이 `image-fit` 프로퍼티입니다. 자주 쓰는 값의 이름만 소개하면 다음과 같습니다.

- `contain`: 이미지 전체가 잘리지 않고 다 보이도록, 비율을 유지한 채 지정된 영역 안에 들어가도록 축소합니다. 영역보다 이미지 비율이 다르면 여백이 생길 수 있습니다.
- `cover`: 지정된 영역을 여백 없이 꽉 채우도록, 비율을 유지한 채 확대/축소합니다. 영역 밖으로 넘치는 부분은 잘려서 보이지 않습니다.
- `fill`: 원본 비율을 무시하고 지정된 `width`/`height`에 이미지를 그대로 늘리거나 줄여서 채웁니다.

```slint
Image {
    source: @image-url("assets/photo.jpg");
    width: 150px;
    height: 100px;
    image-fit: cover;
}
```

프로필 사진이나 썸네일처럼 정해진 영역을 항상 빈틈없이 채우고 싶다면 `cover`를, 로고처럼 잘리면 안 되는 이미지라면 `contain`을 선택하는 식으로 상황에 맞게 고르면 됩니다.

## 16.3 SVG 아이콘도 같은 방식으로

`Image`와 `@image-url(...)`은 PNG, JPEG 같은 래스터(비트맵) 이미지뿐 아니라 SVG 벡터 이미지에도 그대로 사용할 수 있습니다.

```slint
Image {
    source: @image-url("assets/menu-icon.svg");
    width: 24px;
    height: 24px;
}
```

벡터 이미지이기 때문에 `width`/`height`를 어떤 크기로 지정하든 계단 현상 없이 선명하게 렌더링된다는 것이 큰 장점입니다. 툴바 아이콘이나 메뉴 아이콘처럼 여러 해상도의 화면에서 항상 선명해야 하는 그림이라면 래스터 이미지보다 SVG 아이콘을 우선 고려할 만합니다. 사용하는 코드 자체는 PNG를 쓸 때와 다르지 않습니다.

## 16.4 이미지 파일 없이 그림 그리기: 도형 조합

시스템 사용량 게이지, 막대그래프, 원형 진행률처럼 데이터에 따라 실시간으로 모양이 바뀌어야 하는 그림은 애초에 고정된 이미지 파일로 준비해둘 수가 없습니다. 이런 경우 Slint에서는 `Rectangle`, `Path` 같은 기본 도형 엘리먼트를 여러 개 겹치고 조합해서 원하는 그림을 선언적으로 만들어냅니다. raylib이나 ImGui의 저수준 드로잉 API처럼 픽셀 하나하나를 명령형으로 찍어나가는 방식은 아니지만, 도형들의 크기·위치·색·회전 각도를 데이터에 바인딩해두면 값이 바뀔 때마다 그림이 자동으로 다시 그려지므로 상당히 수준 높은 커스텀 시각화도 충분히 구현할 수 있습니다.

가장 간단한 예로, 값에 따라 채워지는 막대그래프 하나를 `Rectangle` 두 개로 만들어보겠습니다.

```slint
export component ProgressBarCustom inherits Rectangle {
    in property <float> value: 0.5; // 0.0 ~ 1.0
    width: 200px;
    height: 20px;
    background: #e0e0e0;
    border-radius: 4px;

    Rectangle {
        x: 0;
        y: 0;
        width: parent.width * value;
        height: parent.height;
        background: #4caf50;
        border-radius: 4px;
    }
}
```

바깥쪽 `Rectangle`은 회색 배경(트랙)을, 안쪽 `Rectangle`은 `value`에 비례한 너비의 초록색 막대(채움)를 그립니다. `value`가 바뀌면 5장에서 배운 바인딩 메커니즘에 따라 안쪽 `Rectangle`의 `width`가 자동으로 재계산되어, 별도의 다시 그리기 코드 없이도 막대그래프가 부드럽게 갱신됩니다.

좀 더 복잡한 형태, 이를테면 원형 게이지의 바늘이나 곡선 그래프처럼 직선과 사각형만으로는 표현하기 어려운 모양은 `Path` 엘리먼트로 그립니다. `Path`는 SVG의 경로 표기법과 비슷한 방식으로 점과 선, 곡선을 조합해 임의의 형태를 선언적으로 정의할 수 있는 엘리먼트입니다.

```slint
export component SimpleArrow inherits Path {
    width: 40px;
    height: 40px;
    commands: "M 0 20 L 20 0 L 40 20 L 20 40 Z";
    fill: #2196f3;
}
```

`Rectangle`의 `rotation-angle` 프로퍼티와 조합하면 바늘이 값에 따라 돌아가는 원형 게이지 같은 표현도 가능합니다. 바늘 역할을 하는 얇고 긴 `Rectangle`을 하나 두고, 그 `rotation-angle`을 데이터 값에서 계산한 각도에 바인딩해두면, 값이 바뀔 때마다 바늘이 자동으로 그 각도까지 회전합니다.

```slint
export component GaugeNeedle inherits Rectangle {
    in property <float> ratio: 0.3; // 0.0 ~ 1.0
    property <angle> needle-angle: -90deg + 180deg * ratio;

    width: 100px;
    height: 100px;

    Rectangle {
        width: 4px;
        height: 40px;
        background: #e53935;
        x: parent.width / 2 - self.width / 2;
        y: parent.height / 2 - self.height;
        rotation-angle: needle-angle;
        rotation-origin-x: self.width / 2;
        rotation-origin-y: self.height;
    }
}
```

이 예제들의 공통점은, "지금 화면에 이런 도형들이 이런 크기와 각도로 놓여 있어야 한다"는 관계를 선언해두면 나머지는 Slint 런타임이 알아서 유지해준다는 점입니다. 명령형 드로잉 API처럼 매 프레임마다 직접 다시 그리는 코드를 작성할 필요가 없습니다. 다만 복잡한 애니메이션이나 부드러운 전환까지 함께 표현하고 싶다면, 10장에서 다룬 애니메이션 프로퍼티(`animate`)를 도형의 크기나 각도 바인딩에 그대로 결합할 수 있습니다.

## 요약

- `Image { source: @image-url("경로"); }`로 이미지 파일을 화면에 표시합니다. `@image-url(...)`은 컴파일 시점에 이미지를 애플리케이션 리소스로 포함시켜주는 특수 문법으로, 실행 시점에 파일 경로를 찾는 일반 문자열과는 다릅니다.
- `width`/`height`로 이미지 크기를 조정하고, 원본 비율과 지정 영역의 비율이 다를 때는 `image-fit`(`contain`, `cover`, `fill` 등)으로 이미지를 어떻게 채워 넣을지 결정합니다.
- `@image-url(...)`과 `Image`는 PNG 같은 래스터 이미지뿐 아니라 SVG 벡터 아이콘에도 그대로 쓸 수 있으며, 벡터 이미지는 어떤 크기로 표시하든 선명하게 렌더링됩니다.
- 고정된 이미지 파일로 표현할 수 없는, 데이터에 따라 실시간으로 모양이 바뀌는 그래프나 게이지 같은 그림은 `Rectangle`, `Path` 같은 기본 도형 엘리먼트를 조합하고 그 크기·위치·회전 각도를 프로퍼티 바인딩으로 표현해서 만듭니다.
- 이 방식은 raylib이나 ImGui 같은 저수준 드로잉 API의 완전히 자유로운 픽셀 단위 그리기는 아니지만, 도형들의 관계를 선언해두는 것만으로도 값이 바뀔 때마다 자동으로 다시 그려지는 상당히 수준 높은 커스텀 시각화를 만들 수 있습니다.

## 연습문제

1. `Image { source: "assets/icon.png"; }`처럼 `@image-url(...)` 없이 일반 문자열로 경로를 지정하면 `@image-url(...)`을 쓸 때와 어떻게 동작이 달라지는지 설명해보세요.
2. 정사각형 영역에 세로로 긴 인물 사진을 표시하려고 합니다. 사진이 잘리더라도 영역을 빈틈없이 채우고 싶을 때와, 잘리는 부분 없이 사진 전체를 보여주고 싶을 때 각각 어떤 `image-fit` 값을 선택해야 할지 근거와 함께 설명해보세요.
3. 16.4의 `ProgressBarCustom` 컴포넌트를 확장해서, `value`가 0.8 이상이면 채움 막대의 색이 초록색에서 빨간색으로 바뀌도록 만들어보세요. (힌트: 5장의 삼항 연산자 바인딩을 떠올려보세요.)
4. `GaugeNeedle` 예제에서 `ratio`가 0에서 1로 서서히 변할 때 바늘이 순간적으로 튀지 않고 부드럽게 회전하며 움직이도록 만들려면 어떤 요소를 추가해야 할지 10장의 내용을 참고해 설명해보세요.
5. 이미지 파일로 준비해두는 방식과 도형을 조합해 직접 그리는 방식 중 어느 쪽을 선택할지 판단하는 기준을 두 가지 이상 정리해보세요. (힌트: 그림이 데이터에 따라 바뀌는지, 그리고 그림의 형태가 얼마나 복잡한지를 생각해보세요.)
