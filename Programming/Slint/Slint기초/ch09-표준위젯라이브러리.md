# 9장. 표준 위젯 라이브러리

[◀ 이전: 8장. C++에서 프로퍼티 제어하기](ch08-CPP에서프로퍼티제어하기.md) | [📖 목차](00-목차.md) | [다음: 10장. 상태(states)와 애니메이션 ▶](ch10-상태와애니메이션.md)


## 버튼을 매번 새로 만들 필요는 없다

6장에서는 `TouchArea`와 `Rectangle`, `Text`를 조합해 클릭에 반응하는 버튼을 직접 만들어 보았습니다. 배경색이 눌림 상태에 따라 바뀌고, `clicked` 콜백을 스스로 정의해 외부에 노출하는 컴포넌트였습니다. 이 과정은 Slint의 프로퍼티와 콜백이 어떻게 맞물려 동작하는지 이해하는 데 꼭 필요한 연습이었지만, 실제 애플리케이션을 만들 때마다 버튼, 체크박스, 텍스트 입력창을 매번 밑바닥부터 조립하는 것은 비효율적입니다. 여백, 포커스 표시, 눌림 애니메이션, 비활성화 스타일처럼 신경 써야 할 세부사항이 위젯 종류마다 늘어나기 때문입니다.

Slint는 이런 반복 작업을 덜어주기 위해 자주 쓰이는 UI 부품을 미리 구현해 `std-widgets.slint`라는 모듈로 제공합니다. 이 장에서는 이 표준 위젯 라이브러리에 어떤 구성 요소가 있고, 이를 가져와 쓰는 방법과 여러 위젯을 조합해 실용적인 화면을 만드는 방법을 살펴봅니다.

## std-widgets.slint 가져오기

표준 위젯은 별도의 설치 없이 Slint 컴파일러에 내장되어 있으며, `import` 구문으로 필요한 것만 골라 가져옵니다. 3장에서 다룬 `import` 문법이 그대로 적용됩니다.

```slint
import { Button, CheckBox, LineEdit, Slider, ComboBox, SpinBox } from "std-widgets.slint";
```

이 한 줄만으로 버튼, 체크박스, 한 줄 텍스트 입력창, 슬라이더, 드롭다운 선택창, 숫자 스핀박스라는 여섯 가지 위젯을 곧바로 사용할 수 있게 됩니다. 실제로 필요한 위젯만 골라 가져오면 되고, 사용하지 않는 위젯까지 전부 가져올 필요는 없습니다.

## 표준 위젯도 결국 컴포넌트다

여기서 꼭 짚고 넘어가야 할 점이 있습니다. `Button`이나 `CheckBox` 같은 표준 위젯은 마법 같은 특별한 존재가 아니라, 여러분이 3장부터 6장까지 배운 것과 똑같은 방식으로 만들어진 평범한 Slint 컴포넌트라는 것입니다. 내부적으로는 `Rectangle`, `Text`, `TouchArea`를 조합하고, 5장에서 배운 `property`로 외부에 상태를 노출하며, 6장에서 배운 `callback`으로 이벤트를 알립니다. 다만 그 구현이 Slint 팀에 의해 미리 다듬어져서 `std-widgets.slint` 모듈에 담겨 있을 뿐입니다.

예를 들어 `Button`은 최소한 다음과 같은 인터페이스를 가진 컴포넌트라고 생각할 수 있습니다.

```slint
Button {
    text: "저장";
    clicked => {
        // 클릭 시 실행할 로직
    }
}
```

`text`는 버튼에 표시할 문자열을 받는 프로퍼티이고, `clicked`는 사용자가 버튼을 눌렀을 때 발생하는 콜백입니다. 7장과 8장에서 다룬 것처럼, 이 프로퍼티는 C++ 쪽에서 `set_text()`로 값을 밀어 넣을 수도 있고, 콜백은 `on_clicked()`로 C++ 함수를 연결할 수도 있습니다. 즉, 표준 위젯을 쓴다고 해서 지금까지 배운 규칙이 달라지는 것이 아니라, 오히려 그 규칙이 그대로 적용되는 완성된 컴포넌트를 가져다 쓰는 것에 가깝습니다.

이어지는 절에서는 여섯 가지 대표적인 표준 위젯을 하나씩 살펴봅니다.

## Button: 텍스트와 클릭 콜백

`Button`은 텍스트를 표시하고 클릭에 반응하는 가장 기본적인 위젯입니다.

```slint
import { Button } from "std-widgets.slint";

export component Demo inherits Window {
    width: 240px;
    height: 80px;

    Button {
        text: "확인";
        clicked => {
            debug("확인 버튼이 눌렸습니다");
        }
    }
}
```

`text` 프로퍼티로 표시 문자열을, `clicked` 콜백으로 클릭 이벤트를 처리합니다. `enabled: false;`를 지정하면 버튼을 비활성화할 수도 있습니다.

## CheckBox: 체크 상태

`CheckBox`는 켜짐/꺼짐 두 상태를 가지는 위젯입니다. `checked` 프로퍼티가 현재 체크 여부를 담고 있으며, 사용자가 상태를 바꿀 때마다 `toggled` 콜백이 발생합니다.

```slint
import { CheckBox } from "std-widgets.slint";

export component Demo inherits Window {
    width: 240px;
    height: 80px;

    CheckBox {
        text: "알림 받기";
        checked: true;
        toggled => {
            debug("체크 상태가 바뀌었습니다");
        }
    }
}
```

`checked`는 5장에서 배운 양방향 바인딩(`<=>`)의 대상으로도 자주 쓰입니다. 부모 컴포넌트의 프로퍼티와 연결해 두면, 사용자가 체크박스를 클릭할 때마다 그 값이 자동으로 동기화됩니다.

## LineEdit: 한 줄 텍스트 입력

`LineEdit`은 이름, 이메일처럼 한 줄짜리 텍스트를 입력받는 위젯입니다.

```slint
import { LineEdit } from "std-widgets.slint";

export component Demo inherits Window {
    width: 240px;
    height: 80px;

    LineEdit {
        placeholder-text: "이름을 입력하세요";
        edited(text) => {
            debug(text);
        }
    }
}
```

`text` 프로퍼티가 현재 입력된 문자열을 담고 있고, `placeholder-text`는 입력이 비어 있을 때 보여줄 안내 문구입니다. 사용자가 글자를 입력할 때마다 `edited` 콜백이 새 문자열과 함께 호출되고, 엔터 키를 누르면 `accepted` 콜백이 호출됩니다.

## Slider: 범위 값 선택

`Slider`는 최솟값과 최댓값 사이에서 값을 하나 고르는 위젯입니다.

```slint
import { Slider } from "std-widgets.slint";

export component Demo inherits Window {
    width: 240px;
    height: 80px;

    Slider {
        minimum: 0;
        maximum: 100;
        value: 50;
        changed(new-value) => {
            debug(new-value);
        }
    }
}
```

`minimum`, `maximum`으로 범위를 지정하고 `value`로 현재 값을 읽거나 씁니다. 사용자가 슬라이더를 드래그할 때마다 `changed` 콜백이 새 값과 함께 호출됩니다. 밝기 조절, 음량 조절처럼 연속적인 값을 다룰 때 적합합니다.

## ComboBox: 드롭다운 선택

`ComboBox`는 여러 항목 중 하나를 목록에서 골라 선택하는 위젯입니다.

```slint
import { ComboBox } from "std-widgets.slint";

export component Demo inherits Window {
    width: 240px;
    height: 80px;

    ComboBox {
        model: ["한국어", "English", "日本語"];
        current-index: 0;
        selected(text) => {
            debug(text);
        }
    }
}
```

`model`은 선택지 문자열의 배열이며, `current-index`는 현재 선택된 항목의 인덱스입니다. 항목 목록을 배열로 다루는 방식은 11장에서 다룰 모델(model) 개념과 이어지는데, 여기서는 우선 고정된 배열 리터럴로 간단히 사용해 봅니다.

## SpinBox: 숫자 증감

`SpinBox`는 화살표 버튼이나 직접 입력으로 숫자를 조절하는 위젯입니다.

```slint
import { SpinBox } from "std-widgets.slint";

export component Demo inherits Window {
    width: 240px;
    height: 80px;

    SpinBox {
        minimum: 1;
        maximum: 10;
        value: 3;
        edited(new-value) => {
            debug(new-value);
        }
    }
}
```

수량, 인원수처럼 정수 단위로 값을 조절할 때 `Slider`보다 `SpinBox`가 더 직관적인 경우가 많습니다.

## 실전 예제: 표준 위젯을 조합한 설정 폼

지금까지 살펴본 위젯들을 한 화면에 모아 간단한 "설정" 폼을 만들어 보겠습니다. 사용자 이름을 입력받고, 알림 여부를 체크박스로 받고, 화면 밝기를 슬라이더로 조절한 뒤, 저장 버튼을 누르면 그 값들을 콜백으로 한꺼번에 알려주는 구조입니다.

```slint
import { Button, CheckBox, LineEdit, Slider, VerticalBox } from "std-widgets.slint";

export component SettingsForm inherits Window {
    width: 320px;
    height: 260px;

    callback save-requested(string, bool, float);

    in-out property <string> user-name;
    in-out property <bool> notifications-enabled: true;
    in-out property <float> brightness: 70;

    VerticalBox {
        alignment: start;
        spacing: 12px;

        Text {
            text: "설정";
            font-size: 20px;
        }

        LineEdit {
            placeholder-text: "사용자 이름";
            text <=> user-name;
        }

        CheckBox {
            text: "알림 받기";
            checked <=> notifications-enabled;
        }

        Text {
            text: "화면 밝기: " + round(brightness) + "%";
        }

        Slider {
            minimum: 0;
            maximum: 100;
            value <=> brightness;
        }

        Button {
            text: "저장";
            clicked => {
                save-requested(user-name, notifications-enabled, brightness);
            }
        }
    }
}
```

이 예제에서 눈여겨볼 부분은 두 가지입니다. 첫째, `LineEdit`의 `text`, `CheckBox`의 `checked`, `Slider`의 `value`를 모두 `<=>`로 컴포넌트 자신의 프로퍼티에 양방향 바인딩해 두었다는 점입니다. 이렇게 하면 사용자가 위젯을 조작할 때마다 별도의 콜백 코드 없이도 `user-name`, `notifications-enabled`, `brightness` 값이 항상 최신 상태로 유지됩니다. 둘째, "저장" 버튼의 `clicked` 콜백에서는 개별 위젯의 값을 직접 다루지 않고, 이미 동기화되어 있는 세 프로퍼티를 모아 `save-requested`라는 하나의 콜백으로 바깥에 전달합니다. 8장에서 다룬 것처럼, C++ 쪽에서는 이 `save-requested` 콜백에 핸들러를 연결해 실제로 값을 저장하는 로직(파일에 쓰거나, 서버에 전송하는 등)을 구현하면 됩니다.

레이아웃에 쓰인 `VerticalBox`도 표준 위젯 모듈이 제공하는 컨테이너로, 4장에서 배운 `VerticalLayout`에 적당한 여백과 간격이 기본값으로 미리 설정되어 있는 버전입니다. 위젯을 세로로 나열하는 폼 화면에서 특히 유용합니다.

## 커스텀 위젯과 표준 위젯, 언제 무엇을 쓸까

이제 6장에서 만든 커스텀 버튼과 이 장에서 소개한 `Button`을 나란히 놓고 실무적인 선택 기준을 정리해 보겠습니다.

**표준 위젯을 우선 고려해야 하는 경우**

- 프로토타입이나 내부 도구처럼 개발 속도가 중요하고, 디자인이 플랫폼 기본 스타일에서 크게 벗어나지 않아도 되는 경우
- 접근성(키보드 포커스 이동, 스크린 리더 대응 등)까지 직접 구현할 여력이 없는 경우 — 표준 위젯은 이런 세부사항이 이미 처리되어 있습니다
- 체크박스, 콤보박스, 스핀박스처럼 플랫폼 관례가 뚜렷한 위젯일수록 사용자에게 익숙한 표준 동작을 그대로 유지하는 편이 유리합니다

**커스텀 위젯을 직접 만들어야 하는 경우**

- 제품 고유의 브랜드 아이덴티티를 반영해야 해서, 표준 위젯의 스타일을 덮어쓰는 것만으로는 부족한 경우
- 표준 위젯 목록에 없는 형태의 상호작용(예: 원형 다이얼, 커스텀 카드 스와이프)이 필요한 경우
- 6장에서처럼 프로퍼티와 콜백을 어떻게 설계할지부터 세밀하게 통제하고 싶은 경우

실제 프로젝트에서는 두 접근을 섞어 쓰는 경우가 흔합니다. 폼의 입력창이나 체크박스처럼 표준적인 부분은 `std-widgets.slint`에 맡기고, 브랜드를 드러내야 하는 핵심 버튼이나 특수한 시각 요소만 6장에서 배운 방식으로 직접 조립하는 식입니다. 14장에서는 표준 위젯의 시각적 스타일을 커스텀 테마로 바꾸는 방법도 다루는데, 이는 "표준 위젯의 동작은 그대로 두되 겉모습만 우리 제품에 맞게 바꾸고 싶다"는 요구에 대한 또 다른 답이 됩니다.

## 요약

- `std-widgets.slint` 모듈은 `Button`, `CheckBox`, `LineEdit`, `Slider`, `ComboBox`, `SpinBox` 등 자주 쓰이는 UI 부품을 미리 구현해 제공하며, `import { ... } from "std-widgets.slint";`로 필요한 것만 가져와 씁니다.
- 표준 위젯도 내부적으로는 `property`와 `callback`을 가진 평범한 Slint 컴포넌트이며, 3~6장에서 배운 프로퍼티 바인딩과 콜백 규칙이 그대로 적용됩니다.
- `Button`은 `text`/`clicked`, `CheckBox`는 `checked`/`toggled`, `LineEdit`은 `text`/`edited`, `Slider`는 `value`/`changed`, `ComboBox`는 `model`/`current-index`/`selected`, `SpinBox`는 `value`/`edited`가 핵심 인터페이스입니다.
- 여러 표준 위젯을 `<=>` 양방향 바인딩으로 하나의 컴포넌트 프로퍼티에 모아 두면, 콜백 코드 없이도 값이 항상 동기화된 상태를 유지할 수 있습니다.
- 개발 속도와 플랫폼 관례를 따라야 한다면 표준 위젯을, 브랜드 고유의 디자인이나 특수한 상호작용이 필요하다면 커스텀 위젯을 선택하는 것이 실무적인 기준입니다.

## 연습문제

1. `std-widgets.slint`에서 `Button`과 `CheckBox`만 가져와 쓰고 싶을 때 `import` 문을 어떻게 작성해야 하는지 써 보세요.
2. `Button`이 "마법 같은 특별한 위젯"이 아니라 평범한 Slint 컴포넌트라고 말할 수 있는 근거를 5장과 6장의 개념을 사용해 설명해 보세요.
3. 이 장의 설정 폼 예제에서 `LineEdit`의 `text`를 `<=>`로 바인딩하지 않고 `edited` 콜백만으로 같은 동작을 구현하려면 어떻게 코드를 바꿔야 할지 설명해 보세요.
4. `Slider`와 `SpinBox`는 둘 다 숫자 값을 다루는 위젯입니다. 어떤 상황에서 각각을 선택하는 것이 더 적절한지 예를 들어 비교해 보세요.
5. 여러분이 만들고 있는 애플리케이션에 표준 위젯 대신 커스텀 위젯을 써야 하는 화면 요소가 있다면 무엇일지, 그 이유와 함께 적어 보세요.
