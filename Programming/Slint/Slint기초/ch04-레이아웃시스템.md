# 4장. 레이아웃 시스템

[◀ 이전: 3장. Slint 언어(.slint) 기초 문법](ch03-Slint언어기초문법.md) | [📖 목차](00-목차.md) | [다음: 5장. 프로퍼티와 바인딩 ▶](ch05-프로퍼티와바인딩.md)


3장에서는 엘리먼트를 중첩시켜 트리 구조를 만드는 방법을 배웠습니다. 그런데 한 가지 짚고 넘어가지 않은 문제가 있습니다. 한 부모 안에 여러 자식 엘리먼트를 나란히 넣으면 어떻게 될까요? 직접 실험해 보면, 별도의 위치 지정 없이 `Rectangle` 안에 `Text` 두 개를 넣었을 때 두 텍스트가 같은 자리에 겹쳐 그려지는 것을 확인할 수 있습니다. Slint는 기본적으로 자식 엘리먼트에게 부모와 동일한 위치와 크기를 부여하기 때문입니다. 여러 엘리먼트를 원하는 자리에 가지런히 배치하려면 **레이아웃(layout)** 컨테이너가 필요합니다. 이번 장에서는 Slint가 제공하는 레이아웃 시스템을 살펴봅니다.

## 왜 절대 좌표 대신 레이아웃을 쓰는가

`x`, `y` 프로퍼티로 각 엘리먼트의 좌표를 직접 지정하는 절대 좌표 방식도 Slint에서 가능하기는 합니다.

```slint
Text {
    x: 20px;
    y: 20px;
    text: "제목";
}

Text {
    x: 20px;
    y: 50px;
    text: "부제목";
}
```

하지만 이 방식은 실무에서 거의 권장되지 않습니다. 이유는 명확합니다. 사용자가 창의 크기를 조절하거나, 다른 화면 밀도의 기기에서 앱이 실행되거나, 텍스트 콘텐츠의 길이가 달라지는 순간 절대 좌표는 어긋나기 시작합니다. 위 예제에서 창의 너비를 줄이면 텍스트들이 잘려 나가거나 엉뚱한 자리에 남게 되지만, 좌표 값 자체는 아무것도 이 변화에 반응하지 않습니다.

레이아웃 컨테이너를 사용하면 이 문제가 근본적으로 해결됩니다. 레이아웃은 "이 엘리먼트를 (10, 20) 위치에 둬라"가 아니라 "이 엘리먼트들을 세로로 순서대로 배치해라"처럼 **관계**를 선언합니다. 그러면 창 크기가 바뀌었을 때 레이아웃이 자동으로 각 자식의 위치와 크기를 다시 계산해 줍니다. 이것이 선언적 UI 프레임워크에서 레이아웃 시스템이 핵심적인 이유이며, 이후 이번 장에서 살펴볼 `VerticalLayout`, `HorizontalLayout`, `GridLayout`이 모두 이 원칙을 따릅니다.

## VerticalLayout과 HorizontalLayout

가장 기본적인 두 레이아웃 컨테이너는 `VerticalLayout`과 `HorizontalLayout`입니다. 이름 그대로 자식 엘리먼트들을 각각 세로 방향, 가로 방향으로 순서대로 배치합니다.

```slint
component MenuList inherits Window {
    width: 200px;
    height: 200px;

    VerticalLayout {
        Text { text: "홈"; }
        Text { text: "프로필"; }
        Text { text: "설정"; }
    }
}
```

`VerticalLayout` 안에 선언한 순서대로 세 개의 `Text`가 위에서 아래로 차곡차곡 쌓입니다. 코드에 등장하는 순서가 곧 화면에 배치되는 순서라는 점이 직관적입니다.

`HorizontalLayout`은 같은 원리로 자식들을 왼쪽에서 오른쪽으로 나란히 배치합니다.

```slint
component Toolbar inherits Window {
    width: 300px;
    height: 60px;

    HorizontalLayout {
        Rectangle { background: #e74c3c; width: 60px; }
        Rectangle { background: #f1c40f; width: 60px; }
        Rectangle { background: #2ecc71; width: 60px; }
    }
}
```

세 개의 색상 상자가 가로로 나란히 배치됩니다.

### spacing과 padding

레이아웃 컨테이너는 자식들 사이의 간격, 그리고 레이아웃 자체와 그 바깥 경계 사이의 여백을 조절하는 프로퍼티를 제공합니다.

```slint
component MenuList inherits Window {
    width: 200px;
    height: 200px;

    VerticalLayout {
        spacing: 12px;
        padding: 16px;

        Text { text: "홈"; }
        Text { text: "프로필"; }
        Text { text: "설정"; }
    }
}
```

`spacing`은 인접한 자식 엘리먼트 사이의 간격을 지정합니다. 위 예제에서는 "홈"과 "프로필" 사이, "프로필"과 "설정" 사이에 각각 12px의 틈이 생깁니다. `padding`은 레이아웃의 바깥 경계와 자식들 사이의 여백을 지정합니다. `padding-left`, `padding-right`, `padding-top`, `padding-bottom`처럼 방향별로 개별 지정하는 것도 가능합니다.

`spacing`과 `padding`은 이후에 다룰 `GridLayout`에서도 동일한 개념으로 등장하므로, 여기서 익혀 두면 계속 재사용하게 됩니다.

## GridLayout: 행과 열로 배치하기

세로나 가로로 한 줄로 배치하는 것만으로는 부족한 경우, 즉 표나 대시보드처럼 행과 열이 모두 있는 격자형 배치가 필요할 때는 `GridLayout`을 사용합니다.

```slint
component LoginForm inherits Window {
    width: 300px;
    height: 150px;

    GridLayout {
        spacing: 8px;
        padding: 16px;

        Text { row: 0; col: 0; text: "아이디:"; }
        Rectangle { row: 0; col: 1; background: #ecf0f1; }

        Text { row: 1; col: 0; text: "비밀번호:"; }
        Rectangle { row: 1; col: 1; background: #ecf0f1; }
    }
}
```

`GridLayout`의 자식 엘리먼트는 `row`와 `col` 프로퍼티로 자신이 격자의 몇 번째 행, 몇 번째 열에 위치할지를 직접 지정합니다. 행과 열 번호는 0부터 시작합니다. 위 예제는 2행 2열짜리 로그인 폼으로, 첫 번째 열에는 레이블("아이디:", "비밀번호:")이, 두 번째 열에는 입력창 역할을 하는 사각형이 각각의 행에 배치됩니다.

`row`나 `col`을 생략하면 이전 엘리먼트의 다음 칸에 자동으로 배치되므로, 격자가 단순한 순서를 따르는 경우에는 명시적으로 모든 셀에 좌표를 적지 않아도 됩니다. 다만 이 책에서는 의도를 명확히 드러내기 위해 `row`와 `col`을 명시하는 스타일을 기본으로 다룹니다.

## 정렬과 크기 조정: horizontal-stretch / vertical-stretch

레이아웃이 자식들을 배치하고 난 뒤, 화면에 남는 여유 공간을 어떻게 나눠 가질지가 다음 문제입니다. 이때 사용하는 프로퍼티가 `horizontal-stretch`와 `vertical-stretch`입니다.

```slint
component StatusBar inherits Window {
    width: 400px;
    height: 40px;

    HorizontalLayout {
        Text {
            text: "상태: 정상";
            horizontal-stretch: 0;
        }

        Rectangle {
            horizontal-stretch: 1;
        }

        Text {
            text: "버전 1.0";
            horizontal-stretch: 0;
        }
    }
}
```

`horizontal-stretch`(가로 레이아웃에서 남는 공간의 분배 비율)와 `vertical-stretch`(세로 레이아웃에서의 분배 비율)는 값이 클수록 그 엘리먼트가 여유 공간을 더 많이 차지하겠다는 의미입니다. 위 예제에서 양 끝의 `Text`는 `horizontal-stretch: 0`이라 자기 콘텐츠 크기만큼만 차지하고, 가운데의 빈 `Rectangle`은 `horizontal-stretch: 1`로 지정되어 남는 공간을 전부 흡수합니다. 그 결과 창 너비가 어떻게 바뀌든 "상태: 정상"은 왼쪽에, "버전 1.0"은 오른쪽에 붙어 있고, 그 사이의 여백만 늘어나거나 줄어드는 전형적인 상태 바 레이아웃이 만들어집니다.

여러 엘리먼트가 모두 `stretch` 값을 갖고 있다면, 남는 공간은 그 비율에 따라 나뉩니다. 예를 들어 두 엘리먼트의 `horizontal-stretch`가 각각 `1`과 `2`라면, 남는 공간은 1:2 비율로 분배됩니다. 이 방식은 창 크기 변화에 자동으로 대응하는 유연한 UI를 만드는 핵심 도구이며, 앞서 "왜 절대 좌표 대신 레이아웃을 쓰는가"에서 이야기한 이점이 실제로 구현되는 지점이기도 합니다.

## 레이아웃 중첩으로 실전 화면 구성하기

지금까지 배운 `VerticalLayout`, `HorizontalLayout`, `GridLayout`, 그리고 `stretch` 프로퍼티를 조합하면 실제 애플리케이션에서 흔히 볼 수 있는 화면 구조를 만들 수 있습니다. 상단에 툴바가 있고, 왼쪽에 사이드바가 있으며, 나머지 영역이 메인 콘텐츠인 전형적인 레이아웃을 만들어 보겠습니다.

```slint
component AppShell inherits Window {
    width: 640px;
    height: 400px;
    title: "실전 레이아웃 예제";

    VerticalLayout {
        // 1. 상단 툴바
        Rectangle {
            height: 48px;
            background: #34495e;
            vertical-stretch: 0;

            HorizontalLayout {
                padding: 8px;
                spacing: 8px;

                Text {
                    text: "내 애플리케이션";
                    color: Colors.white;
                    font-size: 16px;
                    horizontal-stretch: 0;
                }

                Rectangle {
                    horizontal-stretch: 1;
                }

                Text {
                    text: "로그아웃";
                    color: Colors.white;
                    horizontal-stretch: 0;
                }
            }
        }

        // 2. 사이드바 + 메인 콘텐츠
        HorizontalLayout {
            vertical-stretch: 1;

            // 좌측 사이드바
            Rectangle {
                width: 140px;
                background: #ecf0f1;
                horizontal-stretch: 0;

                VerticalLayout {
                    padding: 12px;
                    spacing: 12px;

                    Text { text: "대시보드"; }
                    Text { text: "주문 내역"; }
                    Text { text: "설정"; }
                }
            }

            // 메인 콘텐츠 영역
            Rectangle {
                background: #ffffff;
                horizontal-stretch: 1;

                GridLayout {
                    padding: 16px;
                    spacing: 12px;

                    Text { row: 0; col: 0; text: "오늘의 매출"; }
                    Text { row: 0; col: 1; text: "방문자 수"; }
                    Text { row: 1; col: 0; text: "1,204,000원"; }
                    Text { row: 1; col: 1; text: "358명"; }
                }
            }
        }
    }
}
```

이 예제가 어떻게 조립되는지 위에서부터 짚어 보겠습니다.

- 창 전체는 `VerticalLayout` 하나로 감싸, 상단 툴바 영역과 그 아래 본문 영역을 세로로 순서대로 배치합니다.
- 툴바를 감싼 `Rectangle`은 `vertical-stretch: 0`으로 지정되어 있어, 창 높이가 아무리 늘어나도 자신의 `height: 48px`만큼만 차지하고 늘어나지 않습니다. 반면 그 아래의 본문 `HorizontalLayout`은 `vertical-stretch: 1`이라 남는 세로 공간을 전부 차지합니다.
- 툴바 내부는 다시 `HorizontalLayout`으로, 왼쪽의 앱 이름과 오른쪽의 "로그아웃" 사이에 `horizontal-stretch: 1`인 빈 `Rectangle`을 끼워 넣어 둘을 양 끝으로 밀어냅니다. 앞서 살펴본 상태 바와 같은 기법입니다.
- 본문은 `HorizontalLayout`으로 사이드바와 메인 콘텐츠를 가로로 나눕니다. 사이드바는 `width: 140px`에 `horizontal-stretch: 0`이라 고정폭을 유지하고, 메인 콘텐츠는 `horizontal-stretch: 1`이라 창 너비 변화를 전부 흡수합니다.
- 사이드바 내부는 메뉴 항목들을 세로로 나열하는 `VerticalLayout`이, 메인 콘텐츠 내부는 통계 항목을 격자로 배치하는 `GridLayout`이 각각 담당합니다.

이렇게 레이아웃 컨테이너는 서로의 자식이 되어 자유롭게 중첩될 수 있으며, 이 중첩 구조가 곧 실전 애플리케이션의 뼈대가 됩니다. 창 크기를 조절해 보면 툴바 높이와 사이드바 너비는 고정된 채로, 메인 콘텐츠 영역만 유연하게 늘어나거나 줄어드는 것을 확인할 수 있을 것입니다. 이것이 바로 이번 장 도입부에서 이야기한 "절대 좌표 대신 레이아웃을 쓰는 이유"가 실제로 동작하는 모습입니다.

## 요약

- 절대 좌표(`x`, `y`)로 엘리먼트를 배치하면 창 크기가 바뀔 때 UI가 깨집니다. 레이아웃 컨테이너를 사용하면 크기 변화에 자동으로 대응하는 UI를 만들 수 있습니다.
- `VerticalLayout`은 자식을 세로로, `HorizontalLayout`은 자식을 가로로 순서대로 배치합니다. `spacing`으로 자식 간 간격을, `padding`으로 바깥 여백을 조절합니다.
- `GridLayout`은 자식의 `row`, `col` 프로퍼티를 이용해 행과 열 기반으로 격자 배치를 합니다.
- `horizontal-stretch`/`vertical-stretch`는 레이아웃에서 남는 공간을 자식들 사이에 어떤 비율로 분배할지 지정합니다.
- 레이아웃 컨테이너는 서로 자유롭게 중첩될 수 있으며, 이를 이용해 상단 툴바 + 좌측 사이드바 + 메인 콘텐츠 같은 실전적인 화면 구조를 구성할 수 있습니다.

## 연습문제

1. `HorizontalLayout` 안에 서로 다른 배경색을 가진 `Rectangle` 세 개를 나란히 배치하고, `spacing`을 20px로 지정해 간격을 벌려 보세요.
2. `GridLayout`을 사용해 3행 2열짜리 표 형태의 UI를 만들어 보세요. 첫 번째 열에는 레이블을, 두 번째 열에는 값을 표시하는 `Text`를 배치합니다.
3. `HorizontalLayout` 안에 세 개의 `Rectangle`을 두고, 각각 `horizontal-stretch`를 1, 2, 1로 지정해 보세요. 창 너비를 바꿔 가며 세 사각형의 너비가 어떤 비율로 변하는지 관찰해 보세요.
4. `VerticalLayout` 두 개를 `HorizontalLayout` 안에 나란히 중첩시켜, 왼쪽은 메뉴 목록을 세로로 나열하고 오른쪽은 본문 텍스트를 세로로 나열하는 2단 구성 화면을 만들어 보세요.
5. 이번 장의 "레이아웃 중첩으로 실전 화면 구성하기" 예제를 참고하여, 상단 툴바 대신 하단에 상태 바를 추가한 버전으로 바꿔 보세요. 어떤 `vertical-stretch` 조합이 필요한지 생각해 보세요.
