# 18장. 실전 프로젝트: 할 일 관리 앱 만들기

[◀ 이전: 17장. 임베디드/크로스플랫폼 타겟팅](ch17-임베디드크로스플랫폼타겟팅.md) | [📖 목차](00-목차.md) | [다음: 부록 ▶](appendix-부록.md)


지금까지 우리는 Slint 언어 문법(3장), 레이아웃(4장), 프로퍼티와 바인딩(5장), 콜백(6장), C++ 연동(7~8장), 표준 위젯(9장), 상태와 애니메이션(10장), 리스트와 모델(11장), 전역 싱글톤(12장)을 차례로 배웠습니다. 이번 장에서는 이 요소들을 하나로 모아, 할 일을 추가하고 완료 표시하고 지울 수 있는 **할 일 관리(Todo) 앱**을 처음부터 끝까지 완성해봅니다. 개별 문법을 배우는 것과 그 문법들을 조합해서 실제로 동작하는 애플리케이션을 만드는 것은 전혀 다른 경험입니다. 이 장을 따라가면서 그 차이를 직접 확인해보시기 바랍니다.

## 18.1 요구사항 정리

본격적으로 코드를 작성하기 전에, 이 앱이 갖춰야 할 기능을 명확히 정리해두겠습니다.

1. **할 일 추가**: 텍스트 입력창에 내용을 적고 버튼을 누르면(또는 엔터를 치면) 목록에 새 항목이 추가됩니다.
2. **목록 표시**: 추가된 할 일들이 화면에 목록 형태로 나열됩니다. 11장에서 배운 모델(model)을 사용합니다.
3. **완료 체크**: 각 항목 옆의 체크박스를 눌러 완료 여부를 표시할 수 있습니다.
4. **삭제**: 각 항목 옆의 삭제 버튼을 눌러 목록에서 제거할 수 있습니다.
5. **완료 항목의 시각적 구분**: 완료로 표시된 항목은 흐리게(반투명하게) 표시되어 한눈에 구분됩니다. 10장에서 배운 애니메이션을 적용해 부드럽게 흐려지도록 합니다.

이 다섯 가지를 구현하려면 "데이터를 어떻게 저장하고 갱신할 것인가"(C++/모델)와 "그 데이터를 화면에 어떻게 보여줄 것인가"(.slint/UI)를 나눠서 생각해야 합니다. 순서대로 하나씩 쌓아 올려보겠습니다.

## 18.2 프로젝트 구조

2장에서 다룬 것과 같은 방식으로 프로젝트를 구성합니다.

```
todo_app/
├── CMakeLists.txt
├── main.cpp
└── ui/
    └── todo-app.slint
```

`CMakeLists.txt`는 2장에서 만든 것과 본질적으로 같습니다.

```cmake
cmake_minimum_required(VERSION 3.21)
project(todo_app LANGUAGES CXX)

find_package(Slint REQUIRED)

add_executable(todo_app main.cpp)
slint_target_sources(todo_app ui/todo-app.slint)
target_link_libraries(todo_app PRIVATE Slint::Slint)
```

## 18.3 데이터 모델 설계: TodoItem 구조체

할 일 하나는 "내용(텍스트)"과 "완료 여부(참/거짓)"라는 두 정보로 이루어집니다. 3장에서 프로퍼티 타입을 다룰 때는 `int`, `string`, `bool` 같은 단일 값만 다뤘지만, Slint는 이렇게 여러 필드를 묶은 **구조체(struct)**도 정의할 수 있습니다. `ui/todo-app.slint`에 다음과 같이 선언합니다.

```slint
export struct TodoItem {
    text: string,
    checked: bool,
}
```

`export`를 붙였기 때문에 이 구조체는 C++ 쪽에서도 같은 이름(`TodoItem`)의 구조체로 자동 생성되어, 이후 `main.cpp`에서 그대로 사용할 수 있습니다. 이 자동 생성 원리는 7장에서 살펴본 "`.slint`의 컴포넌트가 C++ 클래스로 변환된다"는 규칙과 같은 맥락으로, 구조체 역시 같은 방식으로 C++ 쪽 타입으로 옮겨집니다.

## 18.4 UI 정의: 전체 레이아웃 구성하기

이제 `TodoItem`의 목록을 받아 화면에 그려줄 최상위 컴포넌트 `TodoApp`을 작성합니다. 11장에서 배운 대로, 목록 데이터는 컴포넌트 바깥(C++ 쪽)에서 채워 넣을 것이므로 `in property`로 선언합니다. 추가·삭제·완료 토글은 6장에서 배운 콜백으로 바깥에 알립니다.

```slint
import { Button, CheckBox, LineEdit, ListView } from "std-widgets.slint";

export struct TodoItem {
    text: string,
    checked: bool,
}

export component TodoApp inherits Window {
    width: 360px;
    height: 480px;
    title: "할 일 관리";

    in property <[TodoItem]> todo-model;
    callback add-item(string);
    callback remove-item(int);
    callback toggle-item(int);

    VerticalLayout {
        padding: 12px;
        spacing: 10px;

        HorizontalLayout {
            spacing: 8px;

            input := LineEdit {
                placeholder-text: "새 할 일을 입력하세요";
                accepted(text) => {
                    add-item(text);
                    input.text = "";
                }
            }

            Button {
                text: "추가";
                clicked => {
                    add-item(input.text);
                    input.text = "";
                }
            }
        }

        ListView {
            for item[i] in todo-model : Rectangle {
                height: 44px;
                opacity: item.checked ? 0.4 : 1.0;
                animate opacity { duration: 200ms; }

                HorizontalLayout {
                    padding: 6px;
                    spacing: 8px;

                    CheckBox {
                        checked: item.checked;
                        toggled => { toggle-item(i); }
                    }

                    Text {
                        text: item.text;
                        vertical-alignment: center;
                        horizontal-stretch: 1;
                    }

                    Button {
                        text: "삭제";
                        clicked => { remove-item(i); }
                    }
                }
            }
        }
    }
}
```

이 안에 지금까지 배운 요소들이 어떻게 모여 있는지 짚어보겠습니다.

- **9장의 표준 위젯**: `LineEdit`(텍스트 입력), `Button`(버튼), `CheckBox`(체크박스), `ListView`(스크롤 가능한 목록 컨테이너)를 `std-widgets.slint`에서 가져와 사용했습니다.
- **4장의 레이아웃**: `VerticalLayout`으로 전체를 세로로, 입력 행은 `HorizontalLayout`으로 가로로 배치하고, 각 할 일 항목의 내부도 `HorizontalLayout`으로 체크박스·텍스트·삭제 버튼을 나란히 놓았습니다.
- **11장의 모델과 반복문**: `for item[i] in todo-model : Rectangle { ... }`은 `todo-model`에 담긴 `TodoItem` 각각에 대해 `Rectangle`을 하나씩 만들어냅니다. `item`은 현재 반복 중인 항목의 값이고, `i`는 그 항목의 인덱스입니다.
- **6장의 콜백**: `add-item`, `remove-item`, `toggle-item` 세 콜백을 선언해서, 사용자가 버튼을 누르거나 체크박스를 토글할 때 C++ 쪽에 "무슨 일이 일어났는지"를 알립니다. 실제로 목록을 바꾸는 작업(항목 추가, 삭제, 완료 상태 변경)은 이 콜백을 받은 C++ 코드가 담당합니다.
- **10장의 상태와 애니메이션**: `opacity: item.checked ? 0.4 : 1.0;`으로 완료된 항목은 40% 불투명도로 흐리게 표시하고, 바로 아래 `animate opacity { duration: 200ms; }`로 그 변화가 순간적으로 튀지 않고 200밀리초에 걸쳐 부드럽게 흐려지도록 만들었습니다.
- **5장의 바인딩**: `checked: item.checked;`처럼 각 위젯의 프로퍼티는 모두 `item`의 필드를 참조하는 바인딩으로 연결되어 있어서, `todo-model`의 내용이 바뀌면 화면도 자동으로 갱신됩니다.

`LineEdit`의 `accepted(text)` 콜백은 사용자가 입력창에서 엔터 키를 눌렀을 때 그 시점의 텍스트를 인자로 넘겨주므로, "추가" 버튼을 누르는 것과 엔터를 치는 것 두 가지 방법 모두로 항목을 추가할 수 있게 했습니다. 두 경로 모두 항목을 추가한 뒤 `input.text = "";`로 입력창을 비워 다음 입력을 바로 받을 수 있도록 했습니다.

## 18.5 C++ 로직: VectorModel로 목록 관리하기

이제 `.slint` 쪽에서 선언한 `todo-model` 프로퍼티와 세 콜백을 `main.cpp`에서 실제로 채워 넣을 차례입니다. 11장에서 다룬 대로, Slint의 배열 타입(`[TodoItem]`) 프로퍼티에는 `slint::VectorModel`을 연결해서 C++ 쪽에서 목록을 관리합니다.

```cpp
#include "todo-app.h"
#include <vector>

int main() {
    auto app = TodoApp::create();

    auto todos = std::make_shared<slint::VectorModel<TodoItem>>(std::vector<TodoItem>{
        TodoItem{ .text = "Slint 문서 읽기", .checked = true },
        TodoItem{ .text = "18장 예제 따라 하기", .checked = false },
    });
    app->set_todo_model(todos);

    app->on_add_item([todos](slint::SharedString text) {
        if (text.empty()) {
            return;
        }
        todos->push_back(TodoItem{ .text = text, .checked = false });
    });

    app->on_remove_item([todos](int index) {
        if (index >= 0 && static_cast<std::size_t>(index) < todos->row_count()) {
            todos->erase(static_cast<std::size_t>(index));
        }
    });

    app->on_toggle_item([todos](int index) {
        if (index >= 0 && static_cast<std::size_t>(index) < todos->row_count()) {
            auto item = *todos->row_data(static_cast<std::size_t>(index));
            item.checked = !item.checked;
            todos->set_row_data(static_cast<std::size_t>(index), item);
        }
    });

    app->run();
    return 0;
}
```

이 코드가 하는 일을 콜백 단위로 정리해보겠습니다.

- **초기 데이터 준비**: `std::vector<TodoItem>`으로 시작 항목 몇 개를 준비하고, 이를 `slint::VectorModel<TodoItem>`으로 감싸서 `shared_ptr`로 관리합니다. 8장에서 다룬 `set_*` 계열 함수와 같은 규칙으로, `.slint`의 `todo-model` 프로퍼티는 `app->set_todo_model(...)`로 값을 채워 넣습니다.
- **`on_add_item`**: `.slint`에서 선언한 `add-item` 콜백은 C++ 쪽에서 `on_add_item`이라는 이름으로 노출됩니다(6장에서 다룬 것처럼 콜백 이름 앞에 `on_`이 붙습니다). 전달받은 문자열이 비어 있지 않으면 `todos->push_back(...)`으로 완료되지 않은 새 항목을 목록 끝에 추가합니다. `VectorModel`에 새 항목이 추가되면 그 사실이 자동으로 UI에 반영되어, `ListView` 안의 `for` 반복문이 항목 하나를 새로 그려냅니다.
- **`on_remove_item`**: 삭제 버튼이 눌리면 해당 인덱스가 전달됩니다. 인덱스가 유효한 범위인지 확인한 뒤 `todos->erase(...)`로 해당 항목을 목록에서 제거합니다.
- **`on_toggle_item`**: 체크박스가 토글되면 해당 인덱스가 전달됩니다. `todos->row_data(index)`로 현재 항목의 값을 읽어와 `checked` 필드를 반전시킨 뒤, `todos->set_row_data(index, item)`으로 다시 써넣습니다. `TodoItem`은 구조체이므로 필드 하나만 바꾸려 해도 항목 전체를 읽고, 고치고, 다시 저장하는 과정을 거칩니다.

세 콜백 모두 `todos`를 람다 캡처 목록에 `[todos]`로 넣어, 콜백이 호출되는 시점에도 같은 모델 인스턴스를 참조하도록 했습니다. `shared_ptr`로 관리되므로 `main` 함수 안에서 `todos` 변수 자체는 콜백들과 `app` 객체보다 먼저 스코프를 벗어나더라도, 실제 모델 데이터는 그것을 참조하는 대상이 모두 사라질 때까지 유지됩니다.

## 18.6 완성된 앱 살펴보기

여기까지 작성했다면 `todo_app`을 빌드해서 실행할 수 있습니다.

```bash
cmake -S . -B build
cmake --build build
./build/todo_app
```

실행하면 초기 항목 두 개가 표시된 창이 뜨고, 입력창에 새 할 일을 적고 "추가"를 누르면 목록 아래에 새 줄이 나타납니다. 체크박스를 누르면 해당 항목이 200밀리초에 걸쳐 부드럽게 흐려지고, 다시 누르면 원래대로 돌아옵니다. "삭제" 버튼을 누르면 그 항목이 목록에서 즉시 사라집니다.

이 짧은 애플리케이션 하나에 이 책에서 다룬 거의 모든 핵심 개념, 즉 컴포넌트와 프로퍼티(3장), 레이아웃(4장), 바인딩(5장), 콜백(6장), C++ 연동(7~8장), 표준 위젯(9장), 애니메이션(10장), 모델(11장)이 실제로 맞물려 동작하는 것을 확인할 수 있습니다. 12장에서 다룬 전역 싱글톤(Global)은 이번 예제에는 등장하지 않았는데, 지금은 상태가 `TodoApp` 컴포넌트 하나에만 관련되어 있어 굳이 전역으로 뺄 필요가 없었기 때문입니다. 다음 절에서 이 앱을 확장하다 보면 전역 상태가 다시 필요해지는 지점을 마주치게 됩니다.

## 18.7 앱을 확장하는 아이디어

지금 만든 앱은 프로그램을 종료하면 목록이 사라지는 등 실전에서 쓰기에는 아직 부족한 점이 많습니다. 배운 내용을 복습하고 응용해볼 겸, 다음과 같은 확장을 스스로 시도해보길 권합니다.

- **로컬 파일로 저장하기**: 프로그램이 시작될 때 이전에 저장해둔 할 일 목록을 파일에서 읽어 `VectorModel`을 채우고, 항목이 추가·삭제·토글될 때마다(또는 종료 시점에) 현재 목록을 파일에 다시 써서 다음 실행에도 유지되도록 만들어 보세요. 파일 입출력 자체는 표준 C++로 처리하고, 그 결과를 `TodoItem` 목록으로 바꿔 모델에 반영하는 부분에 지금까지 배운 내용을 그대로 활용할 수 있습니다.
- **카테고리 분류 추가하기**: `TodoItem` 구조체에 `category: string` 같은 필드를 추가하고, 카테고리별로 목록을 필터링해서 보여주는 기능을 만들어 보세요. "지금 어떤 카테고리를 보고 있는가"는 여러 화면 요소가 함께 참조해야 하는 상태이므로, 12장에서 배운 전역 싱글톤으로 관리하기 좋은 후보입니다.
- **다크 모드 적용하기**: 14장에서 다룬 커스텀 스타일링과 테마를 이 앱에 적용해, 밝은 테마와 어두운 테마를 전환할 수 있는 버튼을 추가해 보세요. 색상 값들을 전역 싱글톤의 프로퍼티로 모아두면 테마 전환 로직을 한곳에서 관리할 수 있습니다.

세 가지 모두 이 책에서 다룬 장들을 다시 들춰보며 응용해볼 수 있는 과제입니다. 직접 손으로 확장해보는 경험이 지금까지 배운 개별 장들의 내용을 하나로 잇는 가장 확실한 방법입니다.

## 요약

- 이번 장에서는 할 일 추가, 목록 표시, 완료 체크, 삭제, 완료 항목의 시각적 구분(흐리게 표시)이라는 다섯 가지 요구사항을 갖춘 Todo 앱을 만들었습니다.
- `export struct TodoItem { text: string, checked: bool, }`으로 정의한 구조체는 C++ 쪽에도 같은 이름의 구조체로 자동 생성됩니다.
- UI는 `in property <[TodoItem]> todo-model;`로 목록을 받고, `for item[i] in todo-model : ...`로 각 항목을 반복해서 그리며, `add-item`/`remove-item`/`toggle-item` 콜백으로 사용자 조작을 C++ 쪽에 알립니다.
- C++ 쪽에서는 `slint::VectorModel<TodoItem>`으로 목록을 관리하며, `push_back`으로 추가, `erase`로 삭제, `row_data`로 읽고 `set_row_data`로 다시 쓰는 방식으로 완료 상태를 토글합니다.
- 완료된 항목은 `opacity` 프로퍼티와 `animate` 지시자를 함께 사용해 부드럽게 흐려지도록 표시했습니다.
- 이 프로젝트 하나에 3장부터 12장까지 배운 핵심 개념 대부분이 실제로 맞물려 동작하는 것을 확인할 수 있으며, 파일 저장·카테고리 분류·다크 모드 같은 확장을 통해 더 깊이 응용해볼 수 있습니다.

## 연습문제

1. `TodoItem` 구조체에 `priority: int` 필드를 추가하고, 우선순위가 높은(숫자가 큰) 항목일수록 목록에서 먼저 보이도록 정렬해보세요. (힌트: C++ 쪽에서 `VectorModel`에 넣기 전에 `std::vector`를 정렬하거나, 새 항목을 추가할 때 삽입 위치를 계산해야 합니다.)
2. 현재는 "삭제" 버튼을 누르면 확인 없이 바로 항목이 사라집니다. 삭제 전에 확인을 한 번 거치도록 만들려면 어떤 요소가 추가로 필요할지 설계해보세요. (13장에서 다룬 팝업을 참고할 수 있습니다.)
3. 완료되지 않은 항목의 개수를 세어 창 제목이나 별도의 `Text`에 "남은 할 일: N개"처럼 표시하는 기능을 추가해보세요. 이 값은 `todo-model`로부터 계산되는 값이므로 어떤 방식으로 갱신하는 것이 자연스러울지 생각해보세요.
4. `on_toggle_item`에서 `row_data`로 항목을 읽고 `set_row_data`로 다시 쓰는 대신, 만약 `TodoItem`의 필드를 직접 수정할 수 있는 방법이 있다면 어떤 차이가 있을지 생각해보고, 왜 Slint의 모델 API가 "읽고 - 고치고 - 다시 쓰기" 패턴을 취하는지 추측해보세요.
5. 18.7절에서 제안한 세 가지 확장(파일 저장, 카테고리 분류, 다크 모드) 중 하나를 선택해 실제로 구현해보고, 어떤 장의 어떤 개념을 다시 참고했는지 정리해보세요.
