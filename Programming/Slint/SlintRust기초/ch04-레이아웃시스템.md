3장에서는 `Rectangle`, `Text`, `Image`, `TouchArea` 같은 엘리먼트를 하나씩 배치하는 법을 배웠습니다. 그런데 지금까지의 예제들은 `x`, `y` 좌표를 일일이 숫자로 지정하는 방식이었습니다. 창 크기가 바뀌거나 엘리먼트 개수가 늘어나면 이 좌표들을 전부 손으로 다시 계산해야 한다는 뜻입니다. 이번 장에서는 Slint가 제공하는 **레이아웃 엘리먼트**를 이용해, "몇 번째 자리에 몇 픽셀 띄워서"가 아니라 "세로로 순서대로 늘어놓아라", "격자 형태로 배치해라" 같은 규칙을 선언하는 방법을 배웁니다.

## 절대 좌표 배치 vs 레이아웃 엘리먼트

### 절대 좌표 배치

`Rectangle`(또는 다른 컨테이너 역할의 엘리먼트) 안에 자식 엘리먼트를 넣을 때, 아무런 레이아웃 엘리먼트도 쓰지 않으면 각 자식은 `x`, `y` 프로퍼티로 지정한 위치에 그대로 놓입니다. 지정하지 않으면 기본값 `0px`, 즉 부모의 왼쪽 위 모서리에 자식들이 서로 겹쳐서 놓이게 됩니다.

```slint
export component AbsoluteDemo inherits Window {
    width: 240px;
    height: 160px;

    Rectangle {
        background: #ecf0f1;

        Rectangle {
            x: 20px;
            y: 20px;
            width: 80px;
            height: 40px;
            background: #3498db;
        }

        Rectangle {
            x: 120px;
            y: 20px;
            width: 80px;
            height: 40px;
            background: #e74c3c;
        }

        Rectangle {
            x: 20px;
            y: 80px;
            width: 180px;
            height: 40px;
            background: #2ecc71;
        }
    }
}
```

이 방식은 화면이 어떻게 생겼는지 직관적으로 눈에 들어오지만, 세 번째 사각형의 너비를 바꾸거나 두 번째 사각형을 하나 더 추가하려면 뒤따르는 모든 좌표를 다시 계산해야 합니다. 창 크기가 사용자에 의해 바뀔 수 있는 실제 애플리케이션에서는 이런 고정 좌표 방식이 금방 한계에 부딪힙니다.

### 레이아웃 엘리먼트

같은 배치를 레이아웃 엘리먼트로 표현하면, 좌표 계산은 Slint 런타임이 대신 해줍니다.

```slint
export component LayoutDemo inherits Window {
    width: 240px;
    height: 160px;

    VerticalLayout {
        padding: 20px;
        spacing: 10px;

        HorizontalLayout {
            spacing: 10px;

            Rectangle {
                width: 80px;
                height: 40px;
                background: #3498db;
            }

            Rectangle {
                width: 80px;
                height: 40px;
                background: #e74c3c;
            }
        }

        Rectangle {
            height: 40px;
            background: #2ecc71;
        }
    }
}
```

세 번째 사각형은 `width`를 지정하지 않았는데도 자동으로 위쪽 `HorizontalLayout`과 같은 너비까지 늘어납니다. 자식 엘리먼트를 하나 더 추가해도 기존 좌표를 손댈 필요가 없습니다. 두 방식 모두 실제 프로젝트에서 쓰이지만, 화면 대부분을 차지하는 뼈대는 레이아웃 엘리먼트로 짜고, 그 안의 장식적인 요소(아이콘 위치 미세 조정 등)에만 절대 좌표를 국소적으로 쓰는 것이 일반적인 접근입니다.

## VerticalLayout과 HorizontalLayout

`VerticalLayout`은 자식들을 위에서 아래로, `HorizontalLayout`은 자식들을 왼쪽에서 오른쪽으로 순서대로 배치합니다. 두 엘리먼트가 지원하는 프로퍼티는 진행 방향만 다를 뿐 동일합니다.

```slint
export component ButtonRow inherits Window {
    width: 320px;
    height: 80px;

    HorizontalLayout {
        padding: 12px;
        spacing: 8px;
        alignment: center;

        Rectangle {
            width: 80px;
            height: 36px;
            background: #3498db;
        }

        Rectangle {
            width: 80px;
            height: 36px;
            background: #3498db;
        }

        Rectangle {
            width: 80px;
            height: 36px;
            background: #3498db;
        }
    }
}
```

- `spacing`: 자식들 사이의 간격
- `padding`: 레이아웃 안쪽 여백(네 방향 모두 동일하게 적용). `padding-left`, `padding-right`, `padding-top`, `padding-bottom`으로 방향별로 따로 지정할 수도 있습니다.
- `alignment`: 주 진행 방향으로 남는 공간을 자식들에게 어떻게 분배할지 결정하는 값입니다. `stretch`(기본값, 남는 공간만큼 늘어남), `start`, `center`, `end`, `space-between`, `space-around` 중 하나를 지정합니다.

위 예제에서 세 개의 `Rectangle`은 각각 `width: 80px`로 크기가 고정되어 있으므로, 남는 공간을 늘려서 채우는 대신 `alignment: center`에 따라 전체가 가운데로 모여 배치됩니다.

교차축(진행 방향에 수직인 축, `HorizontalLayout`이라면 세로 방향)에 대해서는 별도의 정렬 프로퍼티를 지정하지 않는 한, 자식이 자신의 `height`(또는 `width`)를 명시하지 않았다면 레이아웃의 두께에 맞춰 자동으로 늘어납니다.

## GridLayout

행과 열로 이루어진 격자 형태의 배치가 필요할 때는 `GridLayout`을 사용합니다. 가장 읽기 쉬운 방식은 `Row` 엘리먼트로 한 행씩 묶어주는 것입니다.

```slint
export component InfoGrid inherits Window {
    width: 260px;
    height: 140px;

    GridLayout {
        padding: 12px;
        spacing: 8px;

        Row {
            Text { text: "이름:"; vertical-alignment: center; }
            Text { text: "홍길동"; vertical-alignment: center; }
        }

        Row {
            Text { text: "나이:"; vertical-alignment: center; }
            Text { text: "30"; vertical-alignment: center; }
        }

        Row {
            Text { text: "도시:"; vertical-alignment: center; }
            Text { text: "서울"; vertical-alignment: center; }
        }
    }
}
```

`Row` 안에 나열한 엘리먼트들이 순서대로 그 행의 열을 채웁니다. 첫 번째 `Row`가 2개의 자식을 가지면 이 그리드는 2열짜리 격자가 되고, 이후의 모든 `Row`도 같은 열 구조를 공유합니다.

`Row`를 쓰지 않고 각 자식에 `row`, `col` 프로퍼티를 직접 지정할 수도 있습니다. 한 셀이 여러 칸을 차지해야 할 때는 `rowspan`, `colspan`을 함께 씁니다.

```slint
export component TitledGrid inherits Window {
    width: 260px;
    height: 140px;

    GridLayout {
        padding: 12px;
        spacing: 8px;

        Text {
            text: "사용자 정보";
            font-size: 16px;
            horizontal-alignment: center;
            row: 0;
            col: 0;
            colspan: 2;
        }

        Text { text: "이름:"; row: 1; col: 0; }
        Text { text: "홍길동"; row: 1; col: 1; }

        Text { text: "도시:"; row: 2; col: 0; }
        Text { text: "서울"; row: 2; col: 1; }
    }
}
```

`colspan: 2`로 지정한 제목 텍스트는 0번, 1번 열 두 칸을 모두 차지하며 격자의 맨 위를 가로지릅니다. 표 형태의 정보를 보여주거나 폼(form) UI를 만들 때 `GridLayout`이 특히 유용합니다.

## 크기 지정: 고정값, `preferred`, 백분율

레이아웃 안에서 각 자식의 크기는 여러 가지 방법으로 정할 수 있습니다.

```slint
Rectangle {
    width: 120px;       // 고정 크기: 언제나 정확히 120px
}

Rectangle {
    preferred-width: 120px; // 선호 크기: 공간이 넉넉하면 120px, 부족하면 줄어들 수 있음
}

Rectangle {
    width: 50%;          // 부모(또는 레이아웃 셀) 크기의 50%
}
```

- `width`/`height`를 직접 지정하면 그 값은 사실상 고정 크기로 취급됩니다. 레이아웃은 이 자식에게 남는 공간을 나눠줄 때 기본적으로 이 크기를 건드리지 않습니다.
- `preferred-width`/`preferred-height`는 "가능하다면 이 정도가 좋겠다"는 힌트입니다. `width`/`height`를 지정하지 않은 자식의 자연스러운 크기를 계산할 때 레이아웃이 참고합니다.
- `min-width`/`max-width`, `min-height`/`max-height`로 크기의 하한과 상한을 제한할 수 있습니다. 레이아웃이 아무리 공간을 늘리거나 줄여도 이 범위를 벗어나지 않습니다.
- `50%`처럼 백분율 값을 쓰면 부모(레이아웃을 쓰지 않는 경우) 또는 배치된 셀의 크기를 기준으로 한 상대적인 크기가 됩니다.

```slint
export component HalfSplit inherits Window {
    width: 300px;
    height: 100px;

    HorizontalLayout {
        Rectangle {
            width: 50%;
            background: #3498db;
        }

        Rectangle {
            width: 50%;
            background: #e74c3c;
        }
    }
}
```

## 반응형 배치를 위한 stretch

Slint에는 다른 UI 프레임워크의 "FlexLayout" 같은 이름을 가진 전용 엘리먼트는 따로 존재하지 않습니다. 대신 `VerticalLayout`/`HorizontalLayout`과 자식의 `horizontal-stretch`, `vertical-stretch` 프로퍼티를 조합해서 CSS의 flex-grow와 비슷한 유연한 배치를 만듭니다.

`horizontal-stretch`(가로 방향 레이아웃에서 사용)와 `vertical-stretch`(세로 방향 레이아웃에서 사용)는 "고정 크기를 지정하지 않은 자식들 사이에서, 남는 공간을 어떤 비율로 나눠 가질 것인가"를 정하는 값입니다.

```slint
export component StretchDemo inherits Window {
    width: 400px;
    height: 80px;

    HorizontalLayout {
        padding: 8px;
        spacing: 4px;

        Rectangle {
            width: 80px;
            background: #95a5a6;
        }

        Rectangle {
            background: #2ecc71;
            horizontal-stretch: 1;
        }

        Rectangle {
            background: #3498db;
            horizontal-stretch: 2;
        }
    }
}
```

첫 번째 사각형은 `width: 80px`로 고정되어 있으므로 창 크기가 바뀌어도 항상 80px를 유지합니다. 나머지 두 사각형은 너비를 지정하지 않았고 대신 `horizontal-stretch` 값을 1과 2로 각각 지정했습니다. `HorizontalLayout`은 고정 크기 자식을 제외한 나머지 공간을 이 비율(1:2)로 나누어, 파란색 사각형이 초록색 사각형보다 두 배 넓게 늘어나도록 배치합니다. 창 크기를 늘리거나 줄여도 이 1:2 비율은 그대로 유지되므로, 창 너비에 따라 자연스럽게 재배치되는 반응형 UI를 만들 수 있습니다.

## 중첩 레이아웃 예제: 간단한 폼 UI

지금까지 배운 `VerticalLayout`, `HorizontalLayout`, `GridLayout`, 그리고 크기 지정 프로퍼티를 모두 조합해서, 이름·이메일·전화번호를 입력받고 하단에 취소/등록 버튼을 배치하는 폼 화면을 만들어 보겠습니다. 입력 필드와 버튼은 Slint가 기본으로 제공하는 표준 위젯(`LineEdit`, `Button`)을 가져와 사용합니다. 표준 위젯의 자세한 종류와 속성은 이후 장에서 따로 다루므로, 지금은 "이런 것도 가져다 쓸 수 있구나" 정도로만 확인하고 넘어가도 충분합니다.

```slint
import { LineEdit, Button } from "std-widgets.slint";

export component RegistrationForm inherits Window {
    width: 360px;
    height: 260px;
    title: "회원 등록";

    callback register-requested(string, string, string);
    callback cancel-requested();

    VerticalLayout {
        padding: 16px;
        spacing: 16px;

        Text {
            text: "회원 등록";
            font-size: 18px;
            horizontal-alignment: center;
        }

        GridLayout {
            spacing: 8px;

            Row {
                Text { text: "이름:"; vertical-alignment: center; }
                name-input := LineEdit { placeholder-text: "홍길동"; }
            }

            Row {
                Text { text: "이메일:"; vertical-alignment: center; }
                email-input := LineEdit { placeholder-text: "example@mail.com"; }
            }

            Row {
                Text { text: "전화번호:"; vertical-alignment: center; }
                phone-input := LineEdit { placeholder-text: "010-0000-0000"; }
            }
        }

        HorizontalLayout {
            alignment: end;
            spacing: 8px;

            Button {
                text: "취소";
                clicked => { root.cancel-requested(); }
            }

            Button {
                text: "등록";
                clicked => {
                    root.register-requested(
                        name-input.text,
                        email-input.text,
                        phone-input.text
                    );
                }
            }
        }
    }
}
```

바깥쪽 `VerticalLayout`이 화면 전체를 제목 영역, 입력 영역, 버튼 영역 세 덩어리로 세로로 나누고, 그 가운데 입력 영역은 다시 `GridLayout`으로 "라벨 열 + 입력창 열"의 2열 격자를 이루며, 맨 아래 버튼 영역은 `HorizontalLayout`에 `alignment: end`를 주어 오른쪽으로 몰아 배치했습니다. 이렇게 레이아웃을 중첩시키면 복잡한 화면도 "세로로 나누고, 그 일부를 다시 격자로 나누고, 다른 일부를 가로로 나눈다"는 식으로 단계적으로 분해해서 구성할 수 있습니다.

이 폼을 Rust에서 실행하고, 등록 버튼을 눌렀을 때 입력값을 콘솔에 출력하는 코드는 다음과 같습니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = RegistrationForm::new()?;

    let ui_weak = ui.as_weak();
    ui.on_register_requested(move |name, email, phone| {
        let _ui = ui_weak.unwrap();
        println!("등록 요청: 이름={name}, 이메일={email}, 전화번호={phone}");
    });

    ui.on_cancel_requested(|| {
        println!("등록이 취소되었습니다");
    });

    ui.run()
}
```

`callback register-requested(string, string, string);`처럼 여러 개의 문자열 인자를 받는 콜백은 Rust 쪽에서 `on_register_requested(move |name, email, phone| { ... })`처럼 클로저 인자를 그대로 나열해서 받을 수 있습니다. `.slint`에서는 화면 구조와 레이아웃만 선언하고, "입력값으로 무엇을 할지"는 온전히 Rust 쪽 콜백 핸들러에 맡기는 구조가 여기서도 그대로 유지되고 있습니다.

## 요약

- 절대 좌표(`x`, `y`)로 자식을 배치하면 화면 구조를 직관적으로 파악할 수 있지만 크기 변경에 취약합니다. `VerticalLayout`, `HorizontalLayout`, `GridLayout` 같은 레이아웃 엘리먼트를 쓰면 좌표 계산을 Slint 런타임에 맡길 수 있습니다.
- `VerticalLayout`은 세로로, `HorizontalLayout`은 가로로 자식을 순서대로 배치하며, `spacing`(자식 간 간격)과 `padding`(안쪽 여백), `alignment`(남는 공간의 분배 방식)로 세부 배치를 조정합니다.
- `GridLayout`은 `Row` 엘리먼트로 행을 묶거나, 자식에 `row`/`col`/`rowspan`/`colspan`을 직접 지정해서 격자형 배치를 만듭니다.
- 크기는 `width`/`height`(고정), `preferred-width`/`preferred-height`(힌트), `min-`/`max-` 접두사(범위 제한), 백분율(`50%`, 부모나 셀 크기 기준 상대값) 등 여러 방식으로 지정할 수 있습니다.
- Slint에는 별도의 `FlexLayout` 엘리먼트가 없지만, `horizontal-stretch`/`vertical-stretch` 프로퍼티를 통해 CSS flex-grow와 비슷하게 남는 공간을 비율대로 나누는 반응형 배치를 구현할 수 있습니다.
- 레이아웃은 중첩해서 쓸 수 있으며, 복잡한 화면도 "세로로 나누고 그 일부를 격자나 가로 배치로 다시 나눈다"는 식으로 단계적으로 분해해서 구성하는 것이 일반적인 접근입니다.

1. `HorizontalLayout` 안에 서로 다른 배경색을 가진 `Rectangle` 세 개를 `spacing: 12px`, `padding: 10px`로 배치하고, `alignment` 값을 `start`, `center`, `space-between`으로 각각 바꿔가며 화면이 어떻게 달라지는지 비교해 보세요.
2. `GridLayout`과 `Row`를 이용해 3행 2열짜리 표를 만들고, 그중 한 행의 첫 번째 셀에 `colspan: 2`를 주어 그 행 전체를 가로지르는 제목 행으로 바꿔 보세요.
3. `HorizontalLayout` 안에 자식 세 개를 두되, 하나는 `width: 60px`로 고정하고 나머지 둘은 `horizontal-stretch` 값을 각각 1과 3으로 지정해서, 창 너비를 바꿔도 두 영역이 항상 1:3 비율을 유지하는지 확인해 보세요.
4. `VerticalLayout` 안에 `GridLayout`(입력 영역)과 `HorizontalLayout`(버튼 영역)을 중첩시킨 간단한 로그인 폼(아이디, 비밀번호 입력과 로그인/취소 버튼)을 직접 구성해 보세요.
5. 같은 화면을 한 번은 `x`, `y` 절대 좌표만으로, 한 번은 레이아웃 엘리먼트만으로 각각 만들어 보고, 창 크기(`width`, `height`)를 바꿨을 때 두 버전이 어떻게 다르게 반응하는지 비교해 보세요.
