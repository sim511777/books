13장에서는 여러 창이 같은 데이터를 보도록 Global 싱글톤을 동기화하는 방법을 다뤘습니다. 이번 장에서는 Global을 조금 다른 목적으로 씁니다. 애플리케이션 전체의 색상과 폰트를 한 곳에 모아 두는 **테마(theme)**로 활용하는 것입니다. 먼저 Slint가 기본 위젯(`Button`, `ListView` 등)의 겉모습을 통째로 바꿀 수 있게 해 주는 빌드 타임 스타일 설정을 살펴보고, 그다음 우리가 직접 만드는 컴포넌트의 색과 글꼴을 하드코딩에서 벗어나 하나의 출처로 모으는 방법을 다룹니다. 마지막으로 이 출처에 `dark-mode` 같은 스위치 프로퍼티를 두어, 앱 안의 토글 버튼 하나로 라이트/다크 테마를 전환하는 예제를 완성합니다.

## 위젯 스타일 시스템 개요

지금까지 예제에서 써 온 `Button`, `CheckBox` 같은 `std-widgets.slint`의 표준 위젯들은 사실 하나의 고정된 모양이 아닙니다. Slint는 이 표준 위젯 묶음을 여러 벌의 **스타일**로 미리 구현해 두고, 컴파일 시점에 그중 하나를 골라 쓰도록 되어 있습니다. 이 장의 뒷부분에서 다룰 "우리가 직접 만드는 색상 팔레트"와는 다른 층위의 이야기라는 점을 먼저 분명히 해 두겠습니다. 위젯 스타일은 표준 위젯 라이브러리 자체의 생김새를 바꾸는 것이고, 팔레트/테마는 우리가 만든 컴포넌트에 우리가 정한 색을 입히는 것입니다. 둘은 서로 다른 메커니즘이지만 한 앱 안에서 얼마든지 함께 쓸 수 있습니다.

Slint가 기본으로 제공하는 스타일 이름에는 `fluent`, `material`, `cupertino`, `cosmic`, `qt`가 있습니다. `fluent`, `material`, `cupertino`, `cosmic`은 각각 이름 뒤에 `-light` 또는 `-dark`를 붙여 밝은/어두운 변형을 구체적으로 지정할 수도 있습니다(예: `material-dark`). `qt`는 Qt 라이브러리가 설치되어 있어야 동작하는 스타일입니다. 스타일을 아무것도 지정하지 않으면 플랫폼에 맞춰 자동으로 고르는 기본값이 적용됩니다.

스타일은 `build.rs`에서 `slint_build::CompilerConfiguration`을 통해 지정합니다.

```rust
// build.rs
fn main() {
    let config = slint_build::CompilerConfiguration::new()
        .with_style("material-dark".to_string());

    slint_build::compile_with_config("ui/app.slint", config)
        .expect("Slint UI 컴파일 실패");
}
```

`with_style`을 호출하지 않고 그냥 `slint_build::compile("ui/app.slint")`만 쓰면, 컴파일러는 `SLINT_STYLE` 환경 변수를 대신 확인합니다. 즉 `build.rs`를 수정하지 않고도 `SLINT_STYLE=fluent-light cargo run`처럼 환경 변수만 바꿔서 실행해 보며 스타일 차이를 비교해 볼 수 있습니다. `build.rs`에 `with_style`로 명시적으로 지정하면 그 값이 우선하고, 환경 변수는 무시됩니다.

이 스타일 선택은 표준 위젯의 생김새(둥근 모서리인지 각진 모서리인지, 버튼을 눌렀을 때 그림자가 어떻게 지는지 등)를 통째로 바꾸는 것이지, 색상 하나하나를 세밀하게 조정하는 도구는 아닙니다. 우리 애플리케이션 고유의 색과 글꼴을 원하는 대로 조정하려면 지금부터 살펴볼 방법이 필요합니다.

## 색상을 하드코딩하면 생기는 문제

지금까지 예제에서는 `Rectangle`의 `background`나 `Text`의 `color`에 `#3366ff` 같은 값을 직접 적어 넣었습니다. 컴포넌트 몇 개짜리 예제에서는 문제가 없지만, 컴포넌트 수가 늘어나는 실제 애플리케이션에서는 사정이 달라집니다.

```slint
// 알림 배지
Rectangle { background: #3366ff; }

// 강조 텍스트
Text { color: #3366ff; }

// 카드 테두리
Rectangle { border-color: #3366ff; }
```

브랜드 색상을 `#3366ff`에서 `#1a4fd6`로 바꾸기로 했다면, 이 값이 몇 개 파일, 몇 개 컴포넌트에 흩어져 있는지 일일이 찾아 고쳐야 합니다. 하나라도 놓치면 화면 어딘가의 색이 미묘하게 어긋난 채로 남습니다. 나중에 다크 모드까지 지원하려면 이렇게 흩어진 색상값 전부를 "밝을 때 색"과 "어두울 때 색"의 쌍으로 다시 손봐야 합니다.

## 색과 폰트를 한 곳에 모으는 두 가지 방법

이 문제의 해법은 색상값을 컴포넌트에 직접 적지 않고, **이름 붙은 하나의 출처**를 참조하도록 바꾸는 것입니다. 이 출처를 만드는 방법은 크게 두 가지입니다.

첫 번째는 색과 크기 값만 담은 평범한 컴포넌트를 하나 만들어, 필요한 곳마다 이 컴포넌트를 자식으로 두고 그 프로퍼티를 참조하는 방식입니다.

```slint
component Palette {
    out property <color> primary: #3366ff;
    out property <color> surface: #f5f5f5;
    out property <color> text-color: #1a1a1a;
}

export component InfoCard inherits Rectangle {
    palette := Palette { }

    background: palette.surface;
    border-color: palette.primary;

    Text { color: palette.text-color; }
}
```

이 방식은 간단하지만 한계가 뚜렷합니다. `palette := Palette { }`는 `InfoCard`가 인스턴스화될 때마다 매번 새로 만들어지는 **자신만의** 팔레트 인스턴스입니다. 13장에서 여러 창이 같은 이름의 Global을 각자 독립적으로 갖게 되는 것과 똑같은 문제가, 이번에는 창이 아니라 컴포넌트 단위에서 벌어집니다. 게다가 값을 바꾸려면 `InfoCard`를 포함해 `Palette`를 참조하는 모든 컴포넌트에 일일이 새 값을 전달해야 합니다.

두 번째 방법이 바로 12장에서 배운 **Global 싱글톤**을 팔레트로 쓰는 것입니다. Global은 이름이 같으면 한 컴포넌트 트리 안에서 항상 같은 인스턴스를 가리키므로, 값을 한 번 바꾸면 그 Global을 참조하는 모든 컴포넌트에 자동으로 반영됩니다. 이번 장에서는 이 두 번째 방법을 중심으로 다룹니다.

## Global 싱글톤을 팔레트로 쓰기

애플리케이션이 사용할 색과 글꼴을 모아 놓은 `AppPalette`라는 Global을 선언합니다.

```slint
// palette.slint
export global AppPalette {
    in-out property <color> primary: #3366ff;
    in-out property <color> background: #ffffff;
    in-out property <color> surface: #f5f5f5;
    in-out property <color> text-color: #1a1a1a;
    in-out property <length> spacing: 8px;
}
```

`export`를 붙여 이 Global을 다른 `.slint` 파일에서도 `import`해 쓸 수 있게 했습니다. 이제 색이 필요한 컴포넌트는 직접 `#hex` 값을 쓰는 대신 `AppPalette.프로퍼티이름`을 참조합니다.

```slint
import { AppPalette } from "palette.slint";

export component PrimaryButton inherits Rectangle {
    background: AppPalette.primary;
    border-radius: 6px;
    height: 40px;

    Text {
        text: "확인";
        color: AppPalette.background;
    }
}

export component InfoCard inherits Rectangle {
    background: AppPalette.surface;
    border-width: 1px;
    border-color: AppPalette.primary;

    Text {
        text: "안내 문구";
        color: AppPalette.text-color;
    }
}
```

Slint의 프로퍼티 바인딩은 반응형이므로, `AppPalette.primary`를 참조하는 모든 곳은 `AppPalette.primary`의 값이 바뀌는 즉시 다시 계산됩니다. `AppPalette` 선언부의 기본값 하나만 고치면, 이를 참조하는 `PrimaryButton`의 배경색과 `InfoCard`의 테두리색이 동시에 갱신됩니다. `spacing`처럼 색이 아닌 값도 같은 방식으로 팔레트에 포함시켜, 여백이나 간격을 앱 전체에서 일관되게 유지할 수 있습니다.

## Rust에서 팔레트 값 다루기

12장에서 배웠듯, Global의 각 프로퍼티는 Rust 쪽에서 `global::<T>()`를 통해 `get_<프로퍼티명>`, `set_<프로퍼티명>`으로 접근할 수 있습니다. 앱을 시작할 때 팔레트 값을 한 번 조정하고 싶다면 이렇게 씁니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = AppWindow::new()?;

    app.global::<AppPalette>()
        .set_primary(slint::Color::from_rgb_u8(0x1a, 0x4f, 0xd6));

    app.run()
}
```

`slint::Color::from_rgb_u8`은 0에서 255 사이의 R, G, B 값으로 `slint::Color`를 만드는 함수입니다. 이런 식으로 사용자 설정 파일에서 읽어온 브랜드 색을 실행 시점에 반영하는 것도 가능합니다. 다만 이번 장의 핵심 예제인 다크/라이트 전환은 `.slint` 쪽 로직만으로 충분하므로, Rust 코드는 대부분 창을 생성하고 실행하는 정도로 짧게 유지됩니다.

## 다크/라이트 테마 전환: dark-mode 스위치와 표현식 바인딩

이제 다크 모드를 지원해 보겠습니다. 핵심 아이디어는 `AppPalette`에 `bool` 타입의 스위치 프로퍼티 `dark-mode`를 두고, 나머지 색상 프로퍼티들이 이 스위치 값에 따라 둘 중 하나를 고르는 삼항 연산자 표현식으로 바인딩되게 만드는 것입니다.

```slint
export global AppPalette {
    in-out property <bool> dark-mode: false;

    in-out property <color> primary: #3366ff;
    out property <color> background: dark-mode ? #1e1e1e : #ffffff;
    out property <color> surface: dark-mode ? #2a2a2a : #f5f5f5;
    out property <color> text-color: dark-mode ? #f0f0f0 : #1a1a1a;

    callback toggle-theme();
    toggle-theme => { dark-mode = !dark-mode; }
}
```

`background`, `surface`, `text-color`는 더 이상 고정된 값이 아니라 `dark-mode ? A : B` 형태의 표현식입니다. Slint 프로퍼티는 이런 표현식을 바인딩으로 그대로 받아들이고, `dark-mode`가 바뀔 때마다 표현식 전체를 자동으로 다시 계산합니다. 이 세 프로퍼티는 `dark-mode`에서 파생되는 값이므로 `in-out` 대신 읽기 전용에 가까운 `out`으로 선언했고, `primary`처럼 라이트/다크에 상관없이 앱이 직접 바꿀 수도 있는 색은 `in-out`으로 남겨 두었습니다.

`toggle-theme`이라는 콜백도 함께 선언했는데, Rust에서 구현을 채우는 대신 `.slint` 안에서 바로 구현을 붙였습니다(`toggle-theme => { dark-mode = !dark-mode; }`). 이렇게 하면 UI 어디에서든 이 콜백만 호출하면 다크 모드가 토글됩니다.

## 앱 자체 토글 버튼으로 테마 바꾸기

운영체제의 다크 모드 설정을 읽어 와 앱 시작 시 자동으로 맞추는 기능은 플랫폼마다 별도의 API가 필요한 주제이므로 이 책의 범위 밖입니다. 대신 이번 장에서는 앱 안에 토글 버튼을 하나 두고, 그 버튼을 눌러 `AppPalette.toggle-theme()`을 호출하는 방식으로 테마를 바꿉니다. 실제 제품에서 시스템 설정과 연동하고 싶다면, 지금 이 버튼이 하는 일(즉 `dark-mode` 프로퍼티를 뒤집는 일)을 운영체제 API가 알려 주는 값으로 대신 채워 넣으면 됩니다.

```slint
import { Button } from "std-widgets.slint";
import { AppPalette } from "palette.slint";

export component ThemeToggleButton inherits Button {
    text: AppPalette.dark-mode ? "라이트 모드로" : "다크 모드로";
    clicked => { AppPalette.toggle-theme(); }
}
```

Rust 쪽에서 직접 전환하고 싶다면, 12장에서 배운 것처럼 `global::<AppPalette>()`로 프로퍼티를 설정하거나 콜백을 호출할 수 있습니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = AppWindow::new()?;

    // 예: 저장해 둔 설정값을 읽어 앱 시작 시 다크 모드로 맞추기
    app.global::<AppPalette>().set_dark_mode(true);

    // 또는 콜백을 직접 호출해 토글 로직을 재사용하기
    // app.global::<AppPalette>().invoke_toggle_theme();

    app.run()
}
```

`set_dark_mode(true)`처럼 프로퍼티를 직접 값으로 설정할 수도 있고, `invoke_toggle_theme()`처럼 `.slint` 안에 구현된 콜백을 그대로 호출할 수도 있습니다. 두 방식 모두 결과적으로 `AppPalette.dark-mode`를 바꾸고, 이를 참조하는 모든 색상 프로퍼티가 자동으로 다시 계산되게 만듭니다.

## 여러 컴포넌트가 같은 팔레트를 참조하도록 구성하기

`AppPalette`가 한 곳에 자리 잡으면, 서로 다른 컴포넌트 여러 개가 이를 함께 참조하도록 만드는 것이 자연스러워집니다.

```slint
import { AppPalette } from "palette.slint";

export component Header inherits Rectangle {
    height: 48px;
    background: AppPalette.primary;

    Text {
        text: "내 애플리케이션";
        color: AppPalette.background;
        font-size: 16px;
    }
}

export component Card inherits Rectangle {
    background: AppPalette.surface;
    border-width: 1px;
    border-color: AppPalette.primary;

    Text {
        color: AppPalette.text-color;
    }
}
```

`Header`와 `Card`는 서로 존재를 모르는 별개의 컴포넌트지만, 둘 다 `AppPalette`를 통해 같은 색 출처를 바라보고 있습니다. `AppPalette.dark-mode`가 토글되면 `Header`의 배경과 텍스트 색, `Card`의 배경과 테두리색이 모두 같은 순간에 새 값으로 바뀝니다. 컴포넌트를 새로 추가할 때도 그 컴포넌트가 `AppPalette`를 참조하기만 하면, 이미 만들어 둔 다크/라이트 전환 로직을 그대로 물려받습니다.

색상이 즉시 바뀌는 것이 딱딱하게 느껴진다면, 색상 바인딩 자리에 `animate` 지시문을 붙여 부드러운 전환을 줄 수도 있습니다.

```slint
export component Card inherits Rectangle {
    background: AppPalette.surface;
    animate background { duration: 200ms; }

    border-width: 1px;
    border-color: AppPalette.primary;
    animate border-color { duration: 200ms; }
}
```

`Card`는 `AppPalette.dark-mode`가 바뀌었는지 스스로 알 필요가 없습니다. `AppPalette.surface`의 값이 바뀌면 이를 참조하는 `background`가 새로 계산되는데, 이때 `animate` 덕분에 값이 뚝 끊기지 않고 정해진 시간에 걸쳐 보간됩니다.

## 폰트도 팔레트의 일부로

색상뿐 아니라 폰트도 앱 전체에서 일관되게 관리하고 싶은 대상입니다. `AppPalette`에 폰트 관련 프로퍼티를 추가하고, 최상위 `Window`의 기본 폰트 프로퍼티에 연결하면 됩니다.

```slint
export global AppPalette {
    // ...앞서 다룬 색상 프로퍼티는 그대로...

    in-out property <string> font-family: "Noto Sans KR";
    in-out property <length> base-font-size: 14px;
}
```

```slint
import { AppPalette } from "palette.slint";

export component AppWindow inherits Window {
    default-font-family: AppPalette.font-family;
    default-font-size: AppPalette.base-font-size;

    // 이 창 안의 Text 엘리먼트는 스스로 font-family나 font-size를
    // 지정하지 않는 한 위에서 정한 기본값을 따른다
}
```

`Window`는 `default-font-family`, `default-font-size`라는 프로퍼티를 제공하며, 이 값은 그 창 안의 `Text` 엘리먼트가 개별적으로 폰트를 지정하지 않았을 때 쓰이는 기본값이 됩니다. 이 기본값을 `AppPalette.font-family`, `AppPalette.base-font-size`에 연결해 두면, 색상과 마찬가지로 폰트 역시 `AppPalette` 한 곳만 고치면 앱 전체에 반영됩니다. 예를 들어 접근성을 위한 "큰 글씨" 옵션을 켰을 때 `AppPalette.base-font-size`를 키워 주는 콜백 하나로 앱 전체의 글자 크기를 일괄 조정할 수도 있습니다.

## 종합 예제: 토글 버튼 하나로 앱 전체 테마 바꾸기

지금까지 다룬 요소를 하나로 모아 보겠습니다.

```slint
// palette.slint
export global AppPalette {
    in-out property <bool> dark-mode: false;

    in-out property <color> primary: #3366ff;
    out property <color> background: dark-mode ? #1e1e1e : #ffffff;
    out property <color> surface: dark-mode ? #2a2a2a : #f5f5f5;
    out property <color> text-color: dark-mode ? #f0f0f0 : #1a1a1a;

    in-out property <string> font-family: "Noto Sans KR";

    callback toggle-theme();
    toggle-theme => { dark-mode = !dark-mode; }
}
```

```slint
// app-window.slint
import { Button } from "std-widgets.slint";
import { AppPalette } from "palette.slint";

export component AppWindow inherits Window {
    title: "테마 데모";
    width: 340px;
    height: 220px;
    default-font-family: AppPalette.font-family;

    background: AppPalette.background;
    animate background { duration: 200ms; }

    VerticalLayout {
        padding: 20px;
        spacing: 12px;

        Text {
            text: "Slint 테마 데모";
            font-size: 18px;
            color: AppPalette.text-color;
            animate color { duration: 200ms; }
        }

        Rectangle {
            height: 60px;
            background: AppPalette.surface;
            border-width: 1px;
            border-color: AppPalette.primary;
            animate background, border-color { duration: 200ms; }

            Text {
                text: "테마가 적용된 카드";
                color: AppPalette.text-color;
            }
        }

        Button {
            text: AppPalette.dark-mode ? "라이트 모드로" : "다크 모드로";
            clicked => { AppPalette.toggle-theme(); }
        }
    }
}
```

```rust
// main.rs
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let app = AppWindow::new()?;
    app.run()
}
```

버튼을 누르면 `AppPalette.toggle-theme()`이 `dark-mode`를 뒤집고, 이를 참조하는 `background`, `surface`, `text-color`가 모두 새 값으로 재계산됩니다. 배경과 카드, 텍스트는 각자의 바인딩 자리에 붙은 `animate` 덕분에 색이 부드럽게 전환되며, 폰트는 `default-font-family`를 통해 `AppPalette.font-family` 하나로 통일되어 있습니다. `main.rs`가 `AppWindow::new()?`와 `run()` 두 줄뿐이라는 점도 눈여겨볼 만합니다. 테마 전환 로직 전체가 `.slint` 쪽, 그중에서도 `AppPalette` Global 하나에 모여 있어서 Rust 코드는 손댈 것이 거의 없습니다.

## 요약

- 표준 위젯의 겉모습은 `build.rs`에서 `slint_build::CompilerConfiguration::new().with_style(...)`로 고를 수 있으며, `fluent`, `material`, `cupertino`, `cosmic`, `qt` 중에서 고르고 `-light`/`-dark` 접미사로 밝기 변형도 지정할 수 있습니다. 명시적으로 지정하지 않으면 `SLINT_STYLE` 환경 변수를 대신 확인합니다.
- 컴포넌트마다 색을 하드코딩하는 대신 `global AppPalette { property <color> ...; }` 형태로 팔레트를 선언하고 각 컴포넌트에서 `AppPalette.프로퍼티이름`을 참조하면, 색 관리의 출처가 하나로 모입니다. 컴포넌트 자체를 팔레트로 쓰는 방식은 인스턴스마다 독립된 값을 갖게 되어 이런 공유에는 적합하지 않습니다.
- `AppPalette`에 `bool` 타입의 `dark-mode` 스위치를 두고 나머지 색상 프로퍼티를 `dark-mode ? A : B` 형태로 바인딩하면 라이트/다크 테마가 자동으로 갈립니다.
- 운영체제 다크 모드 감지는 이 책의 범위 밖이며, 대신 앱 안의 토글 버튼이 `AppPalette.toggle-theme()`을 호출해 테마를 바꾸는 방식으로 실습합니다. Rust에서는 `global::<AppPalette>().set_dark_mode(...)`나 `invoke_toggle_theme()`으로 같은 일을 할 수 있습니다.
- 색상 바인딩 자리에 `animate`를 붙이면, 그 값이 Global 프로퍼티 변화로 인해 바뀌더라도 자동으로 부드럽게 보간됩니다.
- 폰트 역시 `AppPalette`에 `font-family`, `base-font-size` 같은 프로퍼티로 포함시키고 `Window`의 `default-font-family`, `default-font-size`에 연결하면, 색상과 같은 방식으로 앱 전체 폰트를 한 곳에서 관리할 수 있습니다.

## 연습문제

1. `primary`, `background`, `text-color` 세 가지 색상 프로퍼티를 가진 `AppPalette` Global을 선언하고, 서로 다른 컴포넌트 두 개 이상이 이 색들을 참조하도록 만들어 보세요. `AppPalette`의 기본값만 바꿔서 두 컴포넌트의 색이 동시에 바뀌는지 확인해 보세요.
2. `build.rs`에서 `with_style("cosmic-dark".to_string())`처럼 스타일을 명시적으로 지정해 보고, `SLINT_STYLE` 환경 변수로 다른 스타일을 지정했을 때 어느 쪽이 우선하는지 직접 확인해 보세요.
3. `AppPalette`에 `dark-mode` 불리언 프로퍼티를 추가하고, 최소 세 개의 색상 프로퍼티를 삼항 연산자로 다크/라이트 값을 갈라 바인딩해 보세요. 그런 다음 `toggle-theme` 콜백을 `.slint` 안에 구현하고 버튼 클릭으로 호출해 보세요.
4. 배경색 바인딩에 `animate`를 붙인 컴포넌트와 붙이지 않은 컴포넌트를 나란히 두고 다크 모드를 전환해 보면서 시각적 차이를 비교해 보세요.
5. Rust의 `main` 함수에서 `app.global::<AppPalette>().set_dark_mode(true)`를 호출해 앱을 항상 다크 모드로 시작하게 만든 뒤, 화면의 토글 버튼으로 다시 라이트 모드로 되돌릴 수 있는지 확인해 보세요.
