지금까지 우리는 Slint 언어 문법, 레이아웃, 프로퍼티와 바인딩, 콜백, Rust 연동, 표준 위젯, 상태와 애니메이션, 리스트와 모델(11장), 전역 싱글톤(12장), 커스텀 스타일링(14장), 타이머와 비동기 작업(15장)을 차례로 배웠습니다. 이번 장에서는 이 요소들을 하나로 모아, 할 일을 추가하고 완료 표시하고 지울 수 있으며 프로그램을 껐다 켜도 목록이 그대로 남아 있는 **할 일 관리(Todo) 앱**을 처음부터 끝까지 완성해봅니다. 개별 문법을 배우는 것과 그 문법들을 조합해서 실제로 동작하는 애플리케이션을 만드는 것은 전혀 다른 경험입니다. 이 장을 따라가면서 그 차이를 직접 확인해보시기 바랍니다.

## 18.1 요구사항 정리

본격적으로 코드를 작성하기 전에, 이 앱이 갖춰야 할 기능을 명확히 정리해두겠습니다.

1. **할 일 추가**: 텍스트 입력창에 내용을 적고 버튼을 누르면(또는 엔터를 치면) 목록에 새 항목이 추가됩니다.
2. **목록 표시**: 추가된 할 일들이 화면에 목록 형태로 나열됩니다. 11장에서 배운 모델(model)을 사용합니다.
3. **완료 체크**: 각 항목 옆의 체크박스를 눌러 완료 여부를 표시할 수 있고, 완료된 항목은 흐리게 표시됩니다.
4. **삭제**: 각 항목 옆의 삭제 버튼을 눌러 목록에서 제거할 수 있습니다.
5. **영속화(persistence)**: 프로그램을 시작할 때 이전에 저장해둔 목록을 파일에서 불러오고, 종료할 때 현재 목록을 파일에 저장해서 다음 실행에도 내용이 유지됩니다.

앞의 네 가지는 11장에서 다룬 모델과 6장에서 다룬 콜백만으로 구현할 수 있지만, 다섯 번째 영속화는 이 책에서 처음 다루는 주제입니다. `.slint` 쪽에는 파일 입출력이라는 개념 자체가 없으므로, 이 부분은 전적으로 Rust 쪽 책임입니다. "데이터를 어떻게 저장하고 갱신할 것인가"(Rust/모델/파일)와 "그 데이터를 화면에 어떻게 보여줄 것인가"(.slint/UI)를 나눠서 생각하며 순서대로 하나씩 쌓아 올려보겠습니다.

## 18.2 프로젝트 구조

2장에서 다룬 것과 같은 방식으로 프로젝트를 구성합니다.

```
todo_app/
├── Cargo.toml
├── build.rs
├── ui/
│   └── todo.slint
└── src/
    └── main.rs
```

`build.rs`는 2장에서 만든 것과 본질적으로 같습니다. `.slint` 파일을 컴파일해서 Rust 코드로 바꿔주는 역할을 합니다.

```rust
// build.rs
fn main() {
    slint_build::compile("ui/todo.slint").unwrap();
}
```

`Cargo.toml`에는 UI를 위한 `slint` 크레이트 외에, 영속화를 위한 `serde`와 `serde_json`을 추가합니다.

```toml
# Cargo.toml
[package]
name = "todo_app"
version = "0.1.0"
edition = "2021"

[dependencies]
slint = "1"
serde = { version = "1", features = ["derive"] }
serde_json = "1"

[build-dependencies]
slint-build = "1"
```

## 18.3 데이터 모델 설계: TodoItem 구조체

할 일 하나는 "내용(텍스트)"과 "완료 여부(참/거짓)"라는 두 정보로 이루어집니다. 3장에서 프로퍼티 타입을 다룰 때는 `int`, `string`, `bool` 같은 단일 값만 다뤘지만, Slint는 이렇게 여러 필드를 묶은 **구조체(struct)**도 정의할 수 있습니다. `ui/todo.slint`에 다음과 같이 선언합니다.

```slint
export struct TodoItem {
    text: string,
    checked: bool,
}
```

`export`를 붙였기 때문에 이 구조체는 `slint::include_modules!()`가 생성하는 Rust 코드 안에도 같은 이름(`TodoItem`)의 구조체로 자동 생성됩니다. `text` 필드는 Rust 쪽에서 `slint::SharedString` 타입으로, `checked` 필드는 `bool` 그대로 대응합니다. 이후 `src/main.rs`에서 이 `TodoItem`을 그대로 가져다 쓸 수 있습니다.

## 18.4 UI 정의: 전체 레이아웃 구성하기

이제 `TodoItem`의 목록을 받아 화면에 그려줄 최상위 컴포넌트 `TodoApp`을 작성합니다. 11장에서 배운 대로, 목록 데이터는 컴포넌트 바깥(Rust 쪽)에서 채워 넣을 것이므로 `in property`로 선언합니다. 추가·삭제·완료 토글은 6장에서 배운 콜백으로 바깥에 알립니다. 남은 할 일 개수는 Rust 쪽에서 계산해서 넣어줄 것이므로 별도의 `in property`로 받습니다.

```slint
// ui/todo.slint
import { Button, CheckBox, LineEdit, ListView } from "std-widgets.slint";

export struct TodoItem {
    text: string,
    checked: bool,
}

export component TodoApp inherits Window {
    width: 360px;
    height: 480px;
    title: "할 일 관리";

    in property <[TodoItem]> todo-model;
    in property <int> remaining-count: 0;

    callback add-item(string);
    callback remove-item(int);
    callback toggle-item(int);

    VerticalLayout {
        padding: 12px;
        spacing: 10px;

        HorizontalLayout {
            spacing: 8px;

            input := LineEdit {
                placeholder-text: "새 할 일을 입력하세요";
                accepted(text) => {
                    add-item(text);
                    input.text = "";
                }
            }

            Button {
                text: "추가";
                clicked => {
                    add-item(input.text);
                    input.text = "";
                }
            }
        }

        ListView {
            for item[i] in todo-model : Rectangle {
                height: 44px;
                opacity: item.checked ? 0.4 : 1.0;
                animate opacity { duration: 200ms; }

                HorizontalLayout {
                    padding: 6px;
                    spacing: 8px;

                    CheckBox {
                        checked: item.checked;
                        toggled => { toggle-item(i); }
                    }

                    Text {
                        text: item.text;
                        vertical-alignment: center;
                        horizontal-stretch: 1;
                    }

                    Button {
                        text: "삭제";
                        clicked => { remove-item(i); }
                    }
                }
            }
        }

        Text {
            text: "남은 할 일: " + remaining-count + "개";
            horizontal-alignment: right;
        }
    }
}
```

이 안에 지금까지 배운 요소들이 어떻게 모여 있는지 짚어보겠습니다.

- **9장의 표준 위젯**: `LineEdit`(텍스트 입력), `Button`(버튼), `CheckBox`(체크박스), `ListView`(스크롤 가능한 목록 컨테이너)를 `std-widgets.slint`에서 가져와 사용했습니다.
- **4장의 레이아웃**: `VerticalLayout`으로 전체를 세로로, 입력 행은 `HorizontalLayout`으로 가로로 배치하고, 각 할 일 항목의 내부도 `HorizontalLayout`으로 체크박스·텍스트·삭제 버튼을 나란히 놓았습니다.
- **11장의 모델과 반복문**: `for item[i] in todo-model : Rectangle { ... }`은 `todo-model`에 담긴 `TodoItem` 각각에 대해 `Rectangle`을 하나씩 만들어냅니다. `item`은 현재 반복 중인 항목의 값이고, `i`는 그 항목의 인덱스입니다.
- **6장의 콜백**: `add-item`, `remove-item`, `toggle-item` 세 콜백을 선언해서, 사용자가 버튼을 누르거나 체크박스를 토글할 때 Rust 쪽에 "무슨 일이 일어났는지"를 알립니다. 실제로 목록을 바꾸는 작업은 이 콜백을 받은 Rust 코드가 담당합니다.
- **10장의 상태와 애니메이션**: `opacity: item.checked ? 0.4 : 1.0;`으로 완료된 항목은 40% 불투명도로 흐리게 표시하고, `animate opacity { duration: 200ms; }`로 그 변화가 순간적으로 튀지 않고 부드럽게 흐려지도록 만들었습니다.
- **5장의 바인딩**: `checked: item.checked;`처럼 각 위젯의 프로퍼티는 모두 `item`의 필드를 참조하는 바인딩으로 연결되어 있어서, `todo-model`의 내용이 바뀌면 화면도 자동으로 갱신됩니다.

`LineEdit`의 `accepted(text)` 콜백은 사용자가 입력창에서 엔터 키를 눌렀을 때 그 시점의 텍스트를 인자로 넘겨주므로, "추가" 버튼을 누르는 것과 엔터를 치는 것 두 가지 방법 모두로 항목을 추가할 수 있게 했습니다.

## 18.5 Rust에서 모델 만들고 연결하기

`.slint` 쪽에서 선언한 `todo-model` 프로퍼티에 실제 데이터를 채워 넣을 차례입니다. 11장에서 다룬 대로, Slint의 배열 타입(`[TodoItem]`) 프로퍼티에는 `slint::VecModel`을 연결해서 Rust 쪽에서 목록을 관리합니다. 여러 콜백 클로저가 같은 모델을 공유해야 하므로 `Rc`로 감쌉니다.

```rust
// src/main.rs (일부)
slint::include_modules!();

use slint::{Model, ModelRc, VecModel};
use std::rc::Rc;

fn main() -> Result<(), slint::PlatformError> {
    let ui = TodoApp::new()?;

    let initial = vec![
        TodoItem { text: "Slint 문서 읽기".into(), checked: true },
        TodoItem { text: "18장 예제 따라 하기".into(), checked: false },
    ];
    let todos = Rc::new(VecModel::from(initial));
    ui.set_todo_model(ModelRc::from(todos.clone()));

    ui.run()
}
```

`AppWindow::create()` 같은 이름을 쓰던 다른 언어 바인딩과 달리, Rust 쪽 생성 함수는 `TodoApp::new() -> Result<TodoApp, slint::PlatformError>`라는 이름과 시그니처를 갖습니다. 창을 만드는 과정에서 렌더링 백엔드 초기화처럼 실패할 수 있는 작업이 있기 때문에 `Result`로 감싸져 있으며, `?` 연산자로 곧바로 전파할 수 있도록 `main` 함수 자체도 `Result<(), slint::PlatformError>`를 반환하게 만들었습니다.

`VecModel::from(initial)`은 `Vec<TodoItem>`을 감싸서 Slint의 `Model` 트레이트를 구현하는 `VecModel<TodoItem>`을 만들어냅니다. 이를 `Rc`로 감싼 뒤, `ModelRc::from(todos.clone())`으로 타입이 지워진 `ModelRc<TodoItem>`으로 변환해서 `set_todo_model`에 넘깁니다. `ModelRc`는 서로 다른 구체 모델 타입(`VecModel`, 나중에 직접 만들 수도 있는 커스텀 모델 등)을 하나의 공통 타입으로 다루기 위한 래퍼로, `.slint`의 `in property <[TodoItem]> todo-model;`이 Rust 쪽에서는 정확히 이 `ModelRc<TodoItem>` 타입의 `set_todo_model`/`get_todo_model` 메서드로 노출됩니다.

## 18.6 콜백 구현: Weak 캡처 패턴으로 추가·삭제·토글 연결하기

이제 `add-item`, `remove-item`, `toggle-item` 세 콜백을 Rust 쪽에서 처리할 차례입니다. 콜백 하나마다 두 가지가 필요합니다. 목록을 바꿀 `todos` 모델과, 화면의 "남은 할 일" 개수를 갱신하기 위해 다시 UI로 값을 써 넣을 `ui` 자신입니다.

여기서 주의할 점이 있습니다. `ui.on_add_item(move |text| { ... })`처럼 콜백 클로저 안에서 `ui` 값 자체(강한 참조)를 직접 캡처하면, `ui`가 콜백을 소유하고 그 콜백이 다시 `ui`를 소유하는 순환 참조가 생겨 메모리가 해제되지 않습니다. 이를 피하기 위해 `ComponentHandle` 트레이트가 제공하는 `as_weak()`으로 약한 참조(`slint::Weak<TodoApp>`)를 얻어 캡처하고, 콜백이 실제로 호출되는 시점에 `.unwrap()`으로 다시 강한 참조를 얻어 쓰는 것이 Slint에서 권장하는 표준 패턴입니다.

먼저 남은 개수를 계산해서 UI에 반영하는 함수를 하나 만들어둡니다.

```rust
fn update_remaining_count(ui: &TodoApp, todos: &VecModel<TodoItem>) {
    let remaining = todos.iter().filter(|item| !item.checked).count() as i32;
    ui.set_remaining_count(remaining);
}
```

`todos.iter()`는 `Model` 트레이트가 제공하는 메서드로, 앞서 `use slint::Model;`을 가져왔기 때문에 사용할 수 있습니다. 이제 이 함수를 이용해 세 콜백을 등록합니다.

```rust
let ui_weak = ui.as_weak();
let todos_for_add = todos.clone();
ui.on_add_item(move |text| {
    if text.trim().is_empty() {
        return;
    }
    todos_for_add.push(TodoItem { text, checked: false });
    let ui = ui_weak.unwrap();
    update_remaining_count(&ui, &todos_for_add);
});

let ui_weak = ui.as_weak();
let todos_for_remove = todos.clone();
ui.on_remove_item(move |index| {
    if index >= 0 && (index as usize) < todos_for_remove.row_count() {
        todos_for_remove.remove(index as usize);
    }
    let ui = ui_weak.unwrap();
    update_remaining_count(&ui, &todos_for_remove);
});

let ui_weak = ui.as_weak();
let todos_for_toggle = todos.clone();
ui.on_toggle_item(move |index| {
    if index >= 0 {
        if let Some(mut item) = todos_for_toggle.row_data(index as usize) {
            item.checked = !item.checked;
            todos_for_toggle.set_row_data(index as usize, item);
        }
    }
    let ui = ui_weak.unwrap();
    update_remaining_count(&ui, &todos_for_toggle);
});
```

콜백 세 개를 하나씩 정리해보겠습니다.

- **`on_add_item`**: `.slint`에서 선언한 `add-item` 콜백은 Rust 쪽에서 `on_add_item`이라는 이름으로 노출됩니다(6장에서 다룬 것처럼 콜백 이름 앞에 `on_`이 붙습니다). 전달받은 문자열이 비어 있지 않으면 `todos_for_add.push(...)`로 완료되지 않은 새 항목을 목록 끝에 추가합니다. `VecModel`에 새 항목이 추가되면 그 사실이 자동으로 UI에 반영되어, `ListView` 안의 `for` 반복문이 항목 하나를 새로 그려냅니다.
- **`on_remove_item`**: 삭제 버튼이 눌리면 해당 인덱스가 전달됩니다. 인덱스가 유효한 범위인지 `row_count()`로 확인한 뒤 `todos_for_remove.remove(...)`로 해당 항목을 목록에서 제거합니다.
- **`on_toggle_item`**: 체크박스가 토글되면 해당 인덱스가 전달됩니다. `row_data(index)`로 현재 항목의 값을 읽어와 `checked` 필드를 반전시킨 뒤, `set_row_data(index, item)`으로 다시 써넣습니다. `TodoItem`은 구조체이므로 필드 하나만 바꾸려 해도 항목 전체를 읽고, 고치고, 다시 저장하는 과정을 거칩니다.

세 콜백 모두 마지막에 `ui_weak.unwrap()`으로 강한 참조를 잠깐 얻어 `update_remaining_count`를 호출합니다. 콜백은 항상 UI 이벤트 루프가 살아있는 스레드에서 호출되므로 `TodoApp`이 이미 사라졌을 가능성은 사실상 없고, 그래서 `Option`을 반환하는 `upgrade()` 대신 곧바로 패닉하는 `unwrap()`을 써도 안전합니다. 다만 컴포넌트가 이미 닫혔을 수도 있는 상황(예: 15장에서 다룬 별도 스레드에서 UI 상태를 확인하려는 경우)이라면 `upgrade()`가 반환하는 `Option<TodoApp>`을 그대로 다루는 편이 더 안전합니다.

## 18.7 영속화: 시작할 때 불러오고 종료할 때 저장하기

이제 마지막 요구사항인 영속화를 구현합니다. `TodoItem`은 `.slint`에서 자동 생성된 구조체라 `serde`의 `Serialize`/`Deserialize`를 derive하지 않습니다. 따라서 파일에 저장할 형태의 별도 구조체 `TodoRecord`를 Rust 쪽에 정의하고, `TodoItem`과 서로 변환하는 방식을 씁니다.

```rust
use serde::{Deserialize, Serialize};
use std::path::PathBuf;

#[derive(Serialize, Deserialize)]
struct TodoRecord {
    text: String,
    checked: bool,
}

fn save_path() -> PathBuf {
    PathBuf::from("todo_data.json")
}

fn load_todos() -> Vec<TodoItem> {
    let default_todos = || {
        vec![
            TodoItem { text: "Slint 문서 읽기".into(), checked: true },
            TodoItem { text: "18장 예제 따라 하기".into(), checked: false },
        ]
    };

    let Ok(content) = std::fs::read_to_string(save_path()) else {
        return default_todos();
    };

    match serde_json::from_str::<Vec<TodoRecord>>(&content) {
        Ok(records) => records
            .into_iter()
            .map(|r| TodoItem { text: r.text.into(), checked: r.checked })
            .collect(),
        Err(_) => default_todos(),
    }
}

fn save_todos(todos: &VecModel<TodoItem>) {
    let records: Vec<TodoRecord> = todos
        .iter()
        .map(|item| TodoRecord { text: item.text.to_string(), checked: item.checked })
        .collect();

    if let Ok(json) = serde_json::to_string_pretty(&records) {
        let _ = std::fs::write(save_path(), json);
    }
}
```

- **`load_todos`**: `std::fs::read_to_string`으로 저장 파일을 읽어봅니다. 파일이 아직 없다면(첫 실행이라면) `Err`가 반환되므로 `let ... else` 패턴으로 기본 항목 두 개를 대신 돌려줍니다. 파일이 있다면 `serde_json::from_str`로 `Vec<TodoRecord>`로 파싱하고, `TodoRecord`의 `text: String`을 `SharedString`으로 변환(`.into()`)하면서 `TodoItem` 목록으로 바꿔줍니다.
- **`save_todos`**: 반대로 현재 `VecModel`의 내용을 `todos.iter()`로 순회하면서 `TodoRecord` 목록으로 바꾸고, `serde_json::to_string_pretty`로 사람이 읽기 좋은 JSON 문자열을 만든 뒤 `std::fs::write`로 파일에 씁니다. 두 함수 모두 파일 입출력이 실패할 가능성이 있는 자리(권한 문제, 디스크 오류 등)이므로 `Result`를 그대로 무시하지 않고 `if let Ok(...)`으로 처리해, 저장에 실패하더라도 앱이 패닉으로 죽지 않도록 했습니다.

이제 시작 시 `load_todos()`로 초기 데이터를 채우고, 창이 닫힐 때 `save_todos(...)`를 호출하도록 연결합니다. 창이 닫히는 시점을 잡는 데는 `slint::Window`의 `on_close_requested` 콜백을 사용합니다.

```rust
use slint::CloseRequestedResponse;

let todos_for_close = todos.clone();
ui.window().on_close_requested(move || {
    save_todos(&todos_for_close);
    CloseRequestedResponse::HideWindow
});
```

`ui.window()`는 이 컴포넌트가 속한 `slint::Window`에 대한 참조를 돌려줍니다. `on_close_requested`에 등록한 클로저는 사용자가 창을 닫으려 할 때(닫기 버튼 클릭 등) 호출되며, 저장을 마친 뒤 `CloseRequestedResponse::HideWindow`를 반환해 창을 닫아도 좋다고 알려줍니다. 이 앱에는 창이 하나뿐이므로, 그 창이 닫히면 `ui.run()`으로 시작한 이벤트 루프도 함께 끝나고 `main` 함수가 반환됩니다.

```rust
// src/main.rs
slint::include_modules!();

use serde::{Deserialize, Serialize};
use slint::{CloseRequestedResponse, Model, ModelRc, VecModel};
use std::path::PathBuf;
use std::rc::Rc;

#[derive(Serialize, Deserialize)]
struct TodoRecord {
    text: String,
    checked: bool,
}

fn save_path() -> PathBuf {
    PathBuf::from("todo_data.json")
}

fn load_todos() -> Vec<TodoItem> {
    let default_todos = || {
        vec![
            TodoItem { text: "Slint 문서 읽기".into(), checked: true },
            TodoItem { text: "18장 예제 따라 하기".into(), checked: false },
        ]
    };

    let Ok(content) = std::fs::read_to_string(save_path()) else {
        return default_todos();
    };

    match serde_json::from_str::<Vec<TodoRecord>>(&content) {
        Ok(records) => records
            .into_iter()
            .map(|r| TodoItem { text: r.text.into(), checked: r.checked })
            .collect(),
        Err(_) => default_todos(),
    }
}

fn save_todos(todos: &VecModel<TodoItem>) {
    let records: Vec<TodoRecord> = todos
        .iter()
        .map(|item| TodoRecord { text: item.text.to_string(), checked: item.checked })
        .collect();

    if let Ok(json) = serde_json::to_string_pretty(&records) {
        let _ = std::fs::write(save_path(), json);
    }
}

fn update_remaining_count(ui: &TodoApp, todos: &VecModel<TodoItem>) {
    let remaining = todos.iter().filter(|item| !item.checked).count() as i32;
    ui.set_remaining_count(remaining);
}

fn main() -> Result<(), slint::PlatformError> {
    let ui = TodoApp::new()?;

    let todos = Rc::new(VecModel::from(load_todos()));
    ui.set_todo_model(ModelRc::from(todos.clone()));
    update_remaining_count(&ui, &todos);

    {
        let ui_weak = ui.as_weak();
        let todos = todos.clone();
        ui.on_add_item(move |text| {
            if text.trim().is_empty() {
                return;
            }
            todos.push(TodoItem { text, checked: false });
            let ui = ui_weak.unwrap();
            update_remaining_count(&ui, &todos);
        });
    }

    {
        let ui_weak = ui.as_weak();
        let todos = todos.clone();
        ui.on_remove_item(move |index| {
            if index >= 0 && (index as usize) < todos.row_count() {
                todos.remove(index as usize);
            }
            let ui = ui_weak.unwrap();
            update_remaining_count(&ui, &todos);
        });
    }

    {
        let ui_weak = ui.as_weak();
        let todos = todos.clone();
        ui.on_toggle_item(move |index| {
            if index >= 0 {
                if let Some(mut item) = todos.row_data(index as usize) {
                    item.checked = !item.checked;
                    todos.set_row_data(index as usize, item);
                }
            }
            let ui = ui_weak.unwrap();
            update_remaining_count(&ui, &todos);
        });
    }

    {
        let todos = todos.clone();
        ui.window().on_close_requested(move || {
            save_todos(&todos);
            CloseRequestedResponse::HideWindow
        });
    }

    ui.run()
}
```

`cargo run`으로 실행하면 저장 파일이 없는 첫 실행에서는 기본 항목 두 개가 표시된 창이 뜹니다. 입력창에 새 할 일을 적고 "추가"를 누르거나 엔터를 치면 목록 아래에 새 줄이 나타나고, 화면 아래의 "남은 할 일" 숫자도 함께 바뀝니다. 체크박스를 누르면 해당 항목이 200밀리초에 걸쳐 부드럽게 흐려지고, "삭제" 버튼을 누르면 그 항목이 목록에서 즉시 사라집니다. 창을 닫으면 그 시점의 목록이 실행 디렉터리의 `todo_data.json` 파일에 저장되고, 다시 실행하면 그 파일을 읽어와 마지막으로 종료했던 상태 그대로 이어서 시작합니다.

이 짧은 애플리케이션 하나에 이 책에서 다룬 거의 모든 핵심 개념, 즉 컴포넌트와 프로퍼티, 레이아웃, 바인딩, 콜백, Rust 연동(`ComponentHandle`, `Weak`), 표준 위젯, 애니메이션, 모델(`VecModel`, `ModelRc`)이 실제로 맞물려 동작하는 것을 확인할 수 있습니다. 12장에서 다룬 전역 싱글톤(Global)은 이번 예제에는 등장하지 않았는데, 지금은 상태가 `TodoApp` 컴포넌트 하나에만 관련되어 있어 굳이 전역으로 뺄 필요가 없었기 때문입니다. 다음 절에서 이 앱을 확장하다 보면 전역 상태가 다시 필요해지는 지점을 마주치게 됩니다.

## 18.9 앱을 확장하는 아이디어

지금 만든 앱은 이미 파일 저장까지 갖췄지만, 실전에서 더 쓸모 있게 만들 여지가 여전히 많습니다. 배운 내용을 복습하고 응용해볼 겸, 다음과 같은 확장을 스스로 시도해보길 권합니다.

- **카테고리 분류 추가하기**: `TodoItem` 구조체에 `category: string` 같은 필드를 추가하고(`TodoRecord`에도 대응하는 필드를 함께 추가해야 합니다), 카테고리별로 목록을 필터링해서 보여주는 기능을 만들어 보세요. "지금 어떤 카테고리를 보고 있는가"는 여러 화면 요소가 함께 참조해야 하는 상태이므로, 12장에서 배운 전역 싱글톤으로 관리하기 좋은 후보입니다.
- **다크 모드 토글 연동하기**: 14장에서 다룬 커스텀 스타일링과 테마를 이 앱에 적용해, 밝은 테마와 어두운 테마를 전환할 수 있는 버튼을 추가해 보세요. 색상 값들을 전역 싱글톤의 프로퍼티로 모아두면 테마 전환 로직을 한곳에서 관리할 수 있고, 어떤 테마를 선택했는지도 지금 만든 영속화 로직을 응용해 `todo_data.json`과는 별도의 설정 파일에 저장해두면 다음 실행에도 그대로 유지할 수 있습니다.
- **마감일 표시하기**: `TodoItem`에 `due-date: string` 필드를 추가해서 각 항목 옆에 마감일을 함께 표시해 보세요. 오늘 날짜와 비교해서 마감이 지난 항목은 글자 색을 다르게 바꾸는 것도 좋은 연습이 됩니다. 날짜 비교 로직은 Rust 쪽에서 계산한 뒤 별도의 `in property`(예: `is-overdue: bool`을 포함하도록 `TodoItem` 자체를 확장)로 UI에 전달하는 방식을 생각해볼 수 있습니다.
- **저장 시점 다듬기**: 지금은 창을 닫을 때만 저장합니다. 항목을 추가·삭제·토글할 때마다 즉시 저장하도록 바꾸면 프로그램이 비정상 종료되어도 데이터를 잃지 않습니다. 15장에서 다룬 `slint::Timer`를 이용해 일정 주기로 자동 저장하는 방식도 함께 고려해볼 수 있습니다.

네 가지 모두 이 책에서 다룬 장들을 다시 들춰보며 응용해볼 수 있는 과제입니다. 직접 손으로 확장해보는 경험이 지금까지 배운 개별 장들의 내용을 하나로 잇는 가장 확실한 방법입니다.

## 요약

- 이번 장에서는 할 일 추가, 목록 표시, 완료 체크, 삭제, 그리고 파일을 통한 영속화까지 갖춘 Todo 앱을 만들었습니다.
- `export struct TodoItem { text: string, checked: bool, }`으로 정의한 구조체는 Rust 쪽에도 같은 이름의 구조체로 자동 생성되며, `text` 필드는 `SharedString`으로 대응합니다.
- UI는 `in property <[TodoItem]> todo-model;`로 목록을 받고, `for item[i] in todo-model : ...`로 각 항목을 반복해서 그리며, `add-item`/`remove-item`/`toggle-item` 콜백으로 사용자 조작을 Rust 쪽에 알립니다.
- Rust 쪽에서는 `Rc<VecModel<TodoItem>>`으로 목록을 관리하고 `ModelRc::from(...)`으로 감싸 `set_todo_model`에 연결하며, `push`로 추가, `remove`로 삭제, `row_data`/`set_row_data`로 완료 상태를 토글합니다.
- 콜백 클로저에서 UI 프로퍼티를 다시 설정해야 할 때는 `ui.as_weak()`으로 얻은 `Weak<TodoApp>`을 캡처하고 콜백 안에서 `.unwrap()`으로 다시 강한 참조를 얻는 패턴을 사용해, `ui`를 직접 캡처했을 때 생길 수 있는 순환 참조를 피했습니다.
- 영속화는 `serde`/`serde_json`으로 별도의 `TodoRecord` 구조체를 직렬화·역직렬화하고, `std::fs::read_to_string`/`std::fs::write`로 파일을 읽고 쓰는 방식으로 구현했으며, `Window::on_close_requested`로 창이 닫히는 시점을 잡아 저장을 트리거했습니다.
- 이 프로젝트 하나에 이 책에서 배운 핵심 개념 대부분이 실제로 맞물려 동작하는 것을 확인할 수 있으며, 카테고리 분류·다크 모드·마감일 표시 같은 확장을 통해 더 깊이 응용해볼 수 있습니다.

## 연습문제

1. `TodoItem` 구조체에 `priority: int` 필드를 추가하고, 우선순위가 높은(숫자가 큰) 항목일수록 목록에서 먼저 보이도록 정렬해보세요. (힌트: Rust 쪽에서 `VecModel`에 넣기 전에 `Vec`을 정렬하거나, 새 항목을 추가할 때 `insert`로 삽입 위치를 계산해야 합니다.)
2. 콜백 클로저 안에서 `ui.as_weak()`으로 얻은 `Weak<TodoApp>` 대신 `ui` 자신을 직접 캡처하면 어떤 문제가 생기는지 설명하고, `Weak`을 사용하는 것이 왜 이 문제를 해결하는지 정리해보세요.
3. 완료되지 않은 항목의 개수를 세는 `update_remaining_count` 함수는 매번 전체 모델을 순회합니다. 항목이 아주 많아진다면 이 방식에 어떤 한계가 있을지, 그리고 대안이 있다면 무엇일지 생각해보세요.
4. 현재는 창을 닫을 때만 `save_todos`를 호출합니다. 항목이 추가·삭제·토글될 때마다 즉시 저장하도록 코드를 바꿔보고, 어떤 장단점이 있는지 비교해보세요.
5. 18.9절에서 제안한 확장(카테고리 분류, 다크 모드 연동, 마감일 표시, 저장 시점 다듬기) 중 하나를 선택해 실제로 구현해보고, 이 책의 어떤 장의 개념을 다시 참고했는지 정리해보세요.
