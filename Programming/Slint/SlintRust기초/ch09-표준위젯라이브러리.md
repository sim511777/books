## 매번 버튼을 새로 만들 필요는 없다

지금까지는 `Rectangle`과 `TouchArea`, `Text`를 조합해 직접 버튼을 만들거나, `property`와 `callback`을 선언해 Rust 쪽에 상태를 노출하는 방법을 다뤄왔습니다. 이 방식은 Slint의 프로퍼티 바인딩과 콜백, 그리고 Rust 쪽 생성 코드가 서로 어떻게 맞물리는지 이해하는 데는 더할 나위 없이 좋은 훈련입니다. 하지만 실제 애플리케이션의 설정 화면이나 입력 폼을 만들 때마다 버튼, 체크박스, 텍스트 입력창을 밑바닥부터 새로 조립하는 것은 낭비입니다. 포커스 표시, 눌림 애니메이션, 비활성화 스타일, 키보드 탐색처럼 위젯마다 챙겨야 할 세부사항이 한둘이 아니기 때문입니다.

Slint는 이런 반복 작업을 줄이기 위해 자주 쓰이는 UI 부품을 미리 구현한 `std-widgets.slint` 모듈을 함께 배포합니다. 이 장에서는 이 모듈에 어떤 위젯이 들어 있는지, 각 위젯의 프로퍼티와 콜백을 어떻게 다루는지, 그리고 Rust 코드에서 이 위젯들의 상태를 읽고 쓰는 방법을 살펴봅니다.

## std-widgets.slint 가져오기

표준 위젯은 별도의 크레이트 설치 없이 Slint 컴파일러에 내장되어 있으며, `import` 구문으로 필요한 것만 가져와 씁니다.

```slint
import { Button, CheckBox, LineEdit, Slider, ComboBox, SpinBox } from "std-widgets.slint";
```

이 한 줄로 버튼, 체크박스, 한 줄 텍스트 입력창, 슬라이더, 드롭다운 선택창, 숫자 스핀박스라는 여섯 가지 위젯을 곧바로 사용할 수 있습니다. 실제로 쓰는 위젯만 골라 가져오면 되고, 쓰지 않는 위젯까지 전부 가져올 필요는 없습니다.

## 표준 위젯도 결국 컴포넌트다 — 그리고 Rust에는 딱 그만큼만 보인다

`Button`이나 `CheckBox` 같은 표준 위젯은 특별한 마법이 아니라, 여러분이 지금까지 배운 것과 같은 방식으로 만들어진 평범한 Slint 컴포넌트입니다. 내부적으로 `Rectangle`, `Text`, `TouchArea`를 조합하고, `property`로 상태를 외부에 드러내며, `callback`으로 이벤트를 알립니다. 다만 그 구현이 Slint 팀에 의해 미리 다듬어져 `std-widgets.slint` 모듈에 담겨 있을 뿐입니다.

여기서 Rust와 연동할 때 반드시 기억해야 할 규칙이 하나 있습니다. `slint::include_modules!()`가 생성하는 Rust 구조체는 **최상위 컴포넌트(루트 컴포넌트)가 직접 선언한 `property`와 `callback`에 대해서만** 접근자 함수를 만들어 줍니다. `Button`을 화면 어딘가에 배치했다고 해서 그 `Button`의 `checked`나 `clicked`가 Rust 코드에 저절로 나타나는 것은 아닙니다. 위젯의 상태를 Rust에서 읽거나 쓰려면, 그 위젯의 프로퍼티나 콜백을 루트 컴포넌트 자신의 `property`/`callback`에 연결해 두어야 합니다.

```slint
import { Button } from "std-widgets.slint";

export component ButtonDemo inherits Window {
    width: 240px;
    height: 80px;

    // Button.clicked를 루트 컴포넌트의 콜백으로 그대로 연결한다
    callback confirmed <=> ok-button.clicked;

    ok-button := Button {
        text: "확인";
    }
}
```

`callback confirmed <=> ok-button.clicked;`는 루트에 새 콜백 `confirmed`를 선언하는 동시에, 그것을 `ok-button`이라는 이름을 붙인 `Button` 인스턴스의 `clicked` 콜백과 양방향으로 연결합니다. 이렇게 하면 Rust 쪽에서는 `confirmed`라는 이름으로 이 버튼의 클릭 이벤트를 받아볼 수 있습니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = ButtonDemo::new()?;

    ui.on_confirmed(|| {
        println!("확인 버튼이 눌렸습니다");
    });

    ui.run()
}
```

`slint::include_modules!()`는 빌드 스크립트가 `.slint` 파일로부터 생성한 Rust 코드를 현재 모듈에 포함시키는 매크로입니다. `ButtonDemo::new()`는 이 컴포넌트의 인스턴스를 만들고, `ui.on_confirmed(...)`는 `confirmed` 콜백에 대한 핸들러를 등록하며, `ui.run()`은 창을 띄우고 이벤트 루프를 실행합니다.

프로퍼티와 콜백 이름에 대시(`-`)가 들어 있다면, Rust 쪽 함수 이름에서는 모두 밑줄(`_`)로 바뀝니다. 예를 들어 `user-name`이라는 프로퍼티는 `get_user_name()` / `set_user_name(...)`이 되고, `save-requested`라는 콜백은 `on_save_requested(...)` / `invoke_save_requested(...)`가 됩니다. 이어지는 절에서는 이 규칙을 염두에 두고 여섯 가지 대표적인 표준 위젯을 하나씩 살펴봅니다.

## Button: 텍스트와 클릭

`Button`은 텍스트를 표시하고 클릭에 반응하는 가장 기본적인 위젯입니다. `text`(표시 문자열), `enabled`(활성화 여부), `primary`(강조 색상 적용 여부), `checkable`/`checked`(토글 버튼으로 쓸 때의 눌림 상태 유지) 등의 프로퍼티와 `clicked` 콜백이 핵심입니다.

```slint
import { Button } from "std-widgets.slint";

export component ToggleDemo inherits Window {
    width: 240px;
    height: 80px;

    Button {
        text: "알림 음소거";
        checkable: true;
        checked: false;
    }
}
```

`checkable: true;`를 지정하면 버튼이 눌린 상태를 계속 유지하는 토글 버튼처럼 동작하며, `checked` 프로퍼티로 그 상태를 읽거나 미리 설정할 수 있습니다. 단순히 한 번 눌리는 동작만 필요하다면 `checkable`은 생략해도 됩니다.

## CheckBox: 체크 상태

`CheckBox`는 켜짐/꺼짐 두 상태를 가지는 위젯입니다. `checked` 프로퍼티가 현재 체크 여부를 담고 있으며, 사용자가 상태를 바꿀 때마다 `toggled` 콜백이 호출됩니다.

```slint
import { CheckBox } from "std-widgets.slint";

export component CheckBoxDemo inherits Window {
    width: 240px;
    height: 80px;

    in-out property <bool> notify: true;

    CheckBox {
        text: "알림 받기";
        checked <=> notify;
    }
}
```

`checked <=> notify;`처럼 루트 프로퍼티에 양방향으로 묶어두면, Rust 쪽에서는 `CheckBox`가 아니라 루트가 노출한 `notify`를 통해 값을 주고받으면 됩니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = CheckBoxDemo::new()?;

    println!("초기값: {}", ui.get_notify());
    ui.set_notify(false);

    ui.run()
}
```

`get_notify()`는 `bool` 값을 그대로 돌려주고, `set_notify(false)`는 체크박스 화면까지 즉시 갱신합니다. Slint의 프로퍼티는 어느 쪽에서 값을 바꾸든 항상 화면과 동기화된다는 원칙이 표준 위젯에도 그대로 적용됩니다.

## LineEdit: 한 줄 텍스트 입력

`LineEdit`은 이름, 이메일처럼 한 줄짜리 텍스트를 입력받는 위젯입니다. `text`(입력된 문자열, in-out), `placeholder-text`(빈 칸일 때 안내 문구), `read-only`, `input-type` 등의 프로퍼티와 `edited(string)`, `accepted(string)` 콜백을 가집니다.

```slint
import { LineEdit } from "std-widgets.slint";

export component LineEditDemo inherits Window {
    width: 240px;
    height: 80px;

    callback name-edited <=> input.edited;

    input := LineEdit {
        placeholder-text: "이름을 입력하세요";
    }
}
```

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = LineEditDemo::new()?;

    ui.on_name_edited(move |text| {
        println!("입력 중: {text}");
    });

    ui.run()
}
```

`edited`는 사용자가 글자를 입력하거나 지울 때마다 새 문자열과 함께 호출되고, 엔터 키를 누르면 `accepted`가 호출됩니다. `text` 타입인 Slint의 `string`은 Rust에서 `slint::SharedString`으로 넘어오는데, `Display`가 구현되어 있어 `println!("{text}")`처럼 그대로 출력할 수 있습니다.

## Slider: 범위 값 선택

`Slider`는 `minimum`과 `maximum` 사이에서 값을 하나 고르는 위젯입니다. `value`(현재 값, in-out, `float`)와 `changed(float)`, `released(float)` 콜백이 핵심입니다.

```slint
import { Slider } from "std-widgets.slint";

export component SliderDemo inherits Window {
    width: 240px;
    height: 80px;

    callback brightness-changed <=> slider.changed;
    in-out property <float> brightness <=> slider.value;

    slider := Slider {
        minimum: 0;
        maximum: 100;
        value: 50;
    }
}
```

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = SliderDemo::new()?;

    ui.on_brightness_changed(move |value| {
        println!("밝기: {value}");
    });

    ui.run()
}
```

Slint의 `float`는 Rust의 `f32`로 대응됩니다. 슬라이더를 드래그하는 동안에는 `changed`가 계속 호출되고, 손을 뗀 순간에만 값을 확정하고 싶다면 `released` 콜백을 대신 연결하면 됩니다.

## ComboBox: 드롭다운 선택

`ComboBox`는 여러 항목 중 하나를 목록에서 고르는 위젯입니다. `model`(선택지 문자열 배열), `current-index`(선택된 인덱스, `int`), `current-value`(선택된 문자열, `string`)가 프로퍼티이고, `selected(string)`이 콜백입니다.

```slint
import { ComboBox } from "std-widgets.slint";

export component ComboBoxDemo inherits Window {
    width: 240px;
    height: 80px;

    callback language-selected <=> combo.selected;

    combo := ComboBox {
        model: ["한국어", "English", "日本語"];
        current-index: 0;
    }
}
```

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = ComboBoxDemo::new()?;

    ui.on_language_selected(move |value| {
        println!("선택된 언어: {value}");
    });

    ui.run()
}
```

목록 자체를 다루는 더 유연한 방법(항목을 늘리거나 줄이는 모델)은 이후 장의 리스트/모델 주제에서 다시 다룹니다. 여기서는 우선 고정된 배열 리터럴로 간단히 사용합니다.

## SpinBox: 숫자 증감

`SpinBox`는 화살표 버튼이나 직접 입력으로 정수를 조절하는 위젯입니다. `value`(`int`, in-out), `minimum`, `maximum`, `step-size`가 프로퍼티이고, `edited(int)`가 콜백입니다.

```slint
import { SpinBox } from "std-widgets.slint";

export component SpinBoxDemo inherits Window {
    width: 240px;
    height: 80px;

    in-out property <int> quantity <=> spin.value;

    spin := SpinBox {
        minimum: 1;
        maximum: 10;
        value: 3;
    }
}
```

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = SpinBoxDemo::new()?;

    println!("초기 수량: {}", ui.get_quantity());
    ui.set_quantity(5);

    ui.run()
}
```

`Slider`가 연속적인 값(밝기, 음량)에 어울린다면, `SpinBox`는 수량이나 횟수처럼 정수 단위로 딱 떨어지는 값에 더 직관적입니다.

## 실전 예제: 위젯을 조합한 환경설정 패널

이제 여섯 위젯 중 다섯 가지(`Button`, `CheckBox`, `LineEdit`, `Slider`, `ComboBox`, `SpinBox`)를 한 화면에 모아 "환경설정" 패널을 만들어 보겠습니다. 표시 이름과 언어, 효과음 여부, 음량, 재시도 횟수를 입력받고, "적용" 버튼을 누르면 그 값을 한꺼번에 Rust 쪽으로 전달하는 구조입니다.

```slint
// ui/preferences_panel.slint
import { Button, CheckBox, ComboBox, LineEdit, SpinBox, Slider, VerticalBox } from "std-widgets.slint";

export component PreferencesPanel inherits Window {
    width: 340px;
    height: 380px;
    title: "환경설정";

    callback apply-requested(string, string, bool, float, int);

    in-out property <string> display-name;
    in-out property <string> language: "한국어";
    in-out property <bool> sound-enabled: true;
    in-out property <float> volume: 60;
    in-out property <int> retry-count: 3;
    in-out property <string> status-text;

    VerticalBox {
        alignment: start;
        spacing: 10px;

        Text {
            text: "환경설정";
            font-size: 20px;
            font-weight: 700;
        }

        LineEdit {
            placeholder-text: "표시 이름";
            text <=> display-name;
        }

        ComboBox {
            model: ["한국어", "English", "日本語"];
            current-value <=> language;
        }

        CheckBox {
            text: "효과음 사용";
            checked <=> sound-enabled;
        }

        Text {
            text: "음량: " + round(volume) + "%";
        }

        Slider {
            minimum: 0;
            maximum: 100;
            value <=> volume;
        }

        Text {
            text: "재시도 횟수: " + retry-count;
        }

        SpinBox {
            minimum: 0;
            maximum: 10;
            value <=> retry-count;
        }

        Button {
            text: "적용";
            primary: true;
            clicked => {
                apply-requested(display-name, language, sound-enabled, volume, retry-count);
            }
        }

        Text {
            text: status-text;
            color: #2e7d32;
        }
    }
}
```

이 화면을 Rust에서 띄우려면 먼저 빌드 스크립트에서 이 파일을 컴파일하도록 등록해야 합니다.

```rust
// build.rs
fn main() {
    slint_build::compile("ui/preferences_panel.slint").unwrap();
}
```

```toml
# Cargo.toml (일부)
[dependencies]
slint = "1"

[build-dependencies]
slint-build = "1"
```

그리고 `main.rs`에서는 다음과 같이 `apply-requested` 콜백을 연결합니다.

```rust
// src/main.rs
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = PreferencesPanel::new()?;

    ui.on_apply_requested({
        let ui_weak = ui.as_weak();
        move |name, language, sound_enabled, volume, retry_count| {
            println!("표시 이름: {name}");
            println!("언어: {language}");
            println!("효과음 사용: {sound_enabled}");
            println!("음량: {volume}");
            println!("재시도 횟수: {retry_count}");

            if let Some(ui) = ui_weak.upgrade() {
                ui.set_status_text("적용되었습니다.".into());
            }
        }
    });

    ui.run()
}
```

이 코드에서 눈여겨볼 부분이 몇 가지 있습니다.

첫째, `.slint` 쪽에서는 `LineEdit`의 `text`, `ComboBox`의 `current-value`, `CheckBox`의 `checked`, `Slider`의 `value`, `SpinBox`의 `value`를 모두 `<=>`로 루트 컴포넌트의 프로퍼티에 양방향 바인딩해 두었습니다. 그 덕분에 사용자가 어떤 위젯을 조작하든 `display-name`, `language`, `sound-enabled`, `volume`, `retry-count` 값은 항상 최신 상태로 유지되고, "적용" 버튼의 `clicked` 핸들러는 그 다섯 값을 모아 `apply-requested` 콜백 하나로 밖에 전달하기만 하면 됩니다.

둘째, Rust 쪽 `on_apply_requested` 클로저는 `ui`를 직접 캡처하지 않고 `ui.as_weak()`로 얻은 약한 참조(`Weak<PreferencesPanel>`)를 캡처합니다. `ui`가 소유한 콜백 핸들러 안에서 다시 `ui` 자신을 강하게 캡처하면 서로가 서로를 붙잡는 참조 순환이 생길 수 있기 때문입니다. 콜백이 실제로 호출되는 시점에만 `ui_weak.upgrade()`로 강한 참조를 잠깐 얻어 `set_status_text(...)`를 호출하고, 창이 이미 닫혀 `upgrade()`가 `None`을 돌려주는 경우에는 그냥 아무 일도 하지 않도록 자연스럽게 처리됩니다.

셋째, 콜백에 실려 오는 인자들의 타입은 `.slint`에서 선언한 `callback apply-requested(string, string, bool, float, int);` 순서 그대로 `SharedString`, `SharedString`, `bool`, `f32`, `i32`로 대응됩니다.

## 다크/라이트 테마를 자동으로 따라가는 std-widgets

표준 위젯의 또 다른 장점은 운영체제의 다크/라이트 모드를 별도의 Rust 코드 없이 자동으로 따라간다는 점입니다. `std-widgets.slint`는 `Palette`라는 전역 싱글톤을 통해 배경색, 글자색 같은 팔레트를 관리하는데, 이 팔레트의 `color-scheme` 프로퍼티(`ColorScheme` 열거형, `unknown`/`dark`/`light`)가 기본값인 `unknown`으로 남아 있으면 시스템 전역 설정을 그대로 따라갑니다. 즉 사용자가 OS 설정에서 다크 모드를 켜면, 코드를 전혀 건드리지 않아도 `Button`, `CheckBox`, `LineEdit` 등 표준 위젯의 색상이 어두운 배색으로 자동 전환됩니다.

굳이 앱 자체적으로 라이트/다크 모드를 강제하고 싶다면 `.slint` 쪽에서 `Palette`를 가져와 명시적으로 지정할 수 있습니다.

```slint
import { Palette } from "std-widgets.slint";

export component ForcedDarkDemo inherits Window {
    init => {
        Palette.color-scheme = ColorScheme.dark;
    }
}
```

(`color-scheme` 프로퍼티는 Slint 1.8 이상에서 제공됩니다. `Qt` 스타일에서는 시스템 설정을 그대로 사용하므로 이 프로퍼티로 강제 전환할 수 없습니다.)

빌드 시점에 위젯 스타일 자체를 고정하고 싶다면 `build.rs`에서 `CompilerConfiguration`을 사용합니다.

```rust
// build.rs
fn main() {
    let config = slint_build::CompilerConfiguration::new()
        .with_style("fluent".into());
    slint_build::compile_with_config("ui/preferences_panel.slint", config).unwrap();
}
```

`"fluent"`, `"material"`, `"cosmic"` 같은 스타일은 모두 `Palette`를 기반으로 다크/라이트 모드를 자동 지원하며, 여러분이 만든 애플리케이션은 별도의 분기 코드 없이도 플랫폼의 외형 설정에 자연스럽게 녹아듭니다.

## 요약

- `std-widgets.slint` 모듈은 `Button`, `CheckBox`, `LineEdit`, `Slider`, `ComboBox`, `SpinBox` 등 자주 쓰이는 UI 부품을 미리 구현해 제공하며, `import { ... } from "std-widgets.slint";`로 필요한 것만 가져와 씁니다.
- 표준 위젯도 내부적으로는 `property`와 `callback`을 가진 평범한 Slint 컴포넌트입니다. 다만 `slint::include_modules!()`가 생성하는 Rust 접근자는 루트 컴포넌트가 직접 선언한 `property`/`callback`에만 만들어지므로, 위젯의 상태를 Rust에서 다루려면 `<=>`로 루트에 연결해 두어야 합니다.
- 대표 인터페이스는 `Button`의 `text`/`clicked`, `CheckBox`의 `checked`/`toggled`, `LineEdit`의 `text`/`edited`/`accepted`, `Slider`의 `value`/`changed`, `ComboBox`의 `model`/`current-index`/`current-value`/`selected`, `SpinBox`의 `value`/`edited`입니다.
- Rust 쪽 프로퍼티 접근자는 `get_<이름>()` / `set_<이름>(값)`, 콜백 접근자는 `on_<이름>(핸들러)` / `invoke_<이름>(인자...)` 형태이며, 대시(`-`)는 모두 밑줄(`_`)로 바뀝니다. `string`은 `SharedString`, `bool`은 `bool`, `float`는 `f32`, `int`는 `i32`로 대응됩니다.
- 콜백 핸들러 안에서 컴포넌트 자신을 다시 조작해야 한다면, 참조 순환을 피하기 위해 `ui.as_weak()`로 얻은 `Weak` 참조를 캡처하고 호출 시점에 `.upgrade()`로 강한 참조를 얻는 패턴을 사용합니다.
- `Palette` 전역 싱글톤 덕분에 `fluent`/`material`/`cosmic` 같은 표준 위젯 스타일은 별도 코드 없이도 OS의 다크/라이트 모드를 자동으로 따라갑니다.

## 연습문제

1. `std-widgets.slint`에서 `Button`과 `CheckBox`만 가져오는 `import` 문을 작성해 보세요.
2. `Button`을 화면에 배치하기만 하고 루트 컴포넌트의 `callback`에 연결하지 않으면 Rust 쪽에서 어떤 문제가 생기는지 설명해 보세요.
3. `callback apply-requested(string, bool, int);`처럼 선언된 콜백이 있을 때, 이를 처리하는 Rust 클로저의 매개변수 타입을 순서대로 써 보세요.
4. 이 장의 환경설정 패널 예제에서 `on_apply_requested` 클로저가 `ui`를 직접 캡처하지 않고 `ui.as_weak()`를 캡처하는 이유를 설명해 보세요.
5. `Slider`와 `SpinBox`는 둘 다 숫자를 다루는 위젯입니다. 여러분이 만들고 있는(또는 만들 예정인) 화면에서 각각이 더 잘 어울리는 예를 하나씩 들어 보세요.
