로고, 아이콘, 썸네일, 사용자가 선택한 사진처럼 화면에 그림을 보여줘야 하는 경우는 매우 흔합니다. Slint는 `.slint` 파일 안에서 정적인 이미지 파일을 간단히 표시하는 방법과, Rust 코드에서 이미지를 동적으로 불러오거나 픽셀 단위로 직접 생성해 화면에 반영하는 방법을 함께 제공합니다. 이번 장에서는 `Image` 엘리먼트의 기본기부터 `slint::Image`와 `slint::SharedPixelBuffer`를 이용한 Rust 쪽 이미지 처리, 그리고 아이콘 리소스를 실제 프로젝트에 배치하는 실무 구성까지 살펴봅니다.

## 16.1 `Image` 엘리먼트와 지원 이미지 포맷

Slint 언어에는 이미지를 표시하는 내장 엘리먼트 `Image`가 있습니다. 가장 기본적인 사용법은 `source` 프로퍼티에 이미지를 지정하는 것입니다.

```slint
import { VerticalBox } from "std-widgets.slint";

export component AppWindow inherits Window {
    VerticalBox {
        padding: 16px;

        Image {
            source: @image-url("assets/logo.png");
            width: 96px;
            height: 96px;
        }
    }
}
```

`@image-url("...")`는 파일 경로를 이미지 리소스로 불러오는 컴파일 타임 매크로로, `source` 프로퍼티(타입은 `image`)에 대입할 값을 만들어 냅니다. Slint는 일반적으로 PNG, JPEG, GIF, BMP 같은 래스터 이미지 포맷과, 정적으로 래스터화되는 SVG를 `@image-url`로 불러올 수 있도록 지원합니다. 정확히 어떤 포맷까지 지원하는지는 사용 중인 Slint 버전과 빌드 설정에 따라 달라질 수 있으므로, 특수한 포맷을 다뤄야 한다면 해당 버전의 공식 문서에서 지원 목록을 확인하는 것이 안전합니다. 실무에서는 PNG(투명 배경이 필요한 아이콘·로고)와 JPEG(사진)만으로도 대부분의 요구를 충족합니다.

`Image` 엘리먼트가 가진 주요 프로퍼티는 다음과 같습니다.

- `source: image` — 표시할 이미지. `@image-url(...)`로 얻은 정적 리소스이거나, Rust에서 넘겨준 `slint::Image` 값입니다.
- `image-fit: fill | contain | cover` — 이미지 원본 크기와 `Image` 엘리먼트의 표시 영역 크기가 다를 때 맞추는 방식입니다.
- `image-rendering: smooth | pixelated` — 확대·축소 시 보간 방식입니다. 픽셀 아트처럼 각진 모양을 유지하고 싶다면 `pixelated`를 사용합니다.
- `colorize: brush` — 이미지의 알파 채널은 유지한 채 지정한 색으로 덧칠합니다. 단색 아이콘을 테마 색상에 맞춰 물들일 때 유용합니다.

## 16.2 이미지 맞춤: `image-fit` 비교

`image-fit`의 세 값은 웹 CSS의 `object-fit`과 비슷한 개념입니다. 같은 이미지를 세 가지 방식으로 나란히 놓고 비교해 보겠습니다.

```slint
import { HorizontalBox, VerticalBox, Text } from "std-widgets.slint";

export component AppWindow inherits Window {
    width: 640px;
    height: 260px;

    HorizontalBox {
        padding: 16px;
        spacing: 16px;

        for fit-name[i] in ["fill", "contain", "cover"]: VerticalBox {
            Text {
                text: fit-name;
                horizontal-alignment: center;
            }

            Rectangle {
                width: 160px;
                height: 160px;
                border-width: 1px;
                border-color: #888888;
                clip: true;

                Image {
                    source: @image-url("assets/sample.jpg");
                    width: 100%;
                    height: 100%;
                    image-fit: i == 0 ? fill : (i == 1 ? contain : cover);
                }
            }
        }
    }
}
```

- `fill`은 원본 비율을 무시하고 표시 영역을 가득 채웁니다. 이미지가 늘어나거나 눌릴 수 있습니다.
- `contain`은 원본 비율을 유지하면서 표시 영역 안에 완전히 들어가도록 축소합니다. 남는 공간은 여백으로 남습니다.
- `cover`는 원본 비율을 유지하면서 표시 영역을 완전히 덮도록 확대합니다. 넘치는 부분은 잘려 나갑니다.

아이콘처럼 정사각형 이미지를 정확한 크기로만 쓴다면 `image-fit`의 차이가 잘 드러나지 않지만, 사용자가 올린 임의 비율의 사진을 고정 크기 썸네일로 보여줘야 하는 화면에서는 이 세 가지 중 무엇을 고르느냐가 결과물의 인상을 크게 바꿉니다.

## 16.3 Rust에서 파일로부터 이미지를 동적으로 불러오기

`@image-url`은 컴파일 시점에 경로가 고정된 정적 리소스에만 쓸 수 있습니다. 사용자가 파일을 선택하거나, 서버에서 내려받은 이미지처럼 실행 중에 경로가 정해지는 이미지는 Rust 쪽에서 `slint::Image`를 만들어 프로퍼티에 대입해야 합니다. 이때 쓰는 함수가 `slint::Image::load_from_path`입니다.

```slint
// ui/photo_viewer.slint
import { VerticalBox, Button } from "std-widgets.slint";

export component AppWindow inherits Window {
    in property <image> photo;
    in property <string> status-text: "이미지를 불러와 보세요";
    callback load-clicked();

    VerticalBox {
        padding: 16px;
        spacing: 12px;

        Image {
            source: photo;
            width: 320px;
            height: 220px;
            image-fit: contain;
        }

        Text { text: status-text; }

        Button {
            text: "샘플 이미지 불러오기";
            clicked => { load-clicked(); }
        }
    }
}
```

```rust
// src/main.rs
use slint::ComponentHandle;
use std::path::Path;

slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = AppWindow::new()?;

    let ui_weak = ui.as_weak();
    ui.on_load_clicked(move || {
        let Some(ui) = ui_weak.upgrade() else { return };

        let path = Path::new("assets/sample.jpg");
        match slint::Image::load_from_path(path) {
            Ok(image) => {
                ui.set_photo(image);
                ui.set_status_text("이미지를 불러왔습니다".into());
            }
            Err(err) => {
                ui.set_status_text(format!("이미지를 불러오지 못했습니다: {err}").into());
            }
        }
    });

    ui.run()
}
```

`load_from_path`는 `Result`를 반환하므로 파일이 없거나 지원하지 않는 포맷일 때를 대비해 항상 오류 처리를 해 주는 것이 좋습니다. 실제 애플리케이션에서는 이 경로를 파일 선택 대화상자(운영체제 네이티브 다이얼로그를 감싸는 `rfd` 같은 별도 크레이트)를 통해 사용자가 직접 고르게 하는 경우가 많은데, 이런 파일 시스템 대화상자 자체는 Slint의 영역이 아니라 별도 크레이트가 담당하는 부분이므로 이 책에서는 다루지 않습니다. 핵심은 "경로 문자열만 있으면 `slint::Image::load_from_path`로 언제든 이미지를 불러와 프로퍼티에 넣을 수 있다"는 사실입니다.

## 16.4 `SharedPixelBuffer`로 픽셀을 직접 그려서 이미지 만들기

파일에서 불러오는 것이 아니라, 계산 결과로 이미지를 직접 만들어야 하는 경우도 있습니다. 그래프를 픽셀 단위로 그리거나, 카메라·센서에서 들어온 원시 프레임 데이터를 그대로 표시하거나, 이번 절의 예제처럼 그러데이션 같은 절차적 이미지를 생성하는 경우입니다. 이럴 때 쓰는 타입이 `slint::SharedPixelBuffer`입니다.

`SharedPixelBuffer<Pixel>`은 픽셀 데이터를 담는 버퍼로, 픽셀 타입으로는 `slint::Rgb8Pixel`(`r`, `g`, `b` 각 1바이트)과 `slint::Rgba8Pixel`(`r`, `g`, `b`, `a` 각 1바이트)을 사용할 수 있습니다. 버퍼를 만든 뒤 `make_mut_slice()`로 픽셀 슬라이스를 얻어 값을 채우고, 다 채운 버퍼를 `slint::Image::from_rgba8` 또는 `slint::Image::from_rgb8`로 감싸면 `Image` 엘리먼트의 `source`에 바로 대입할 수 있는 `slint::Image`가 됩니다.

```slint
// ui/gradient.slint
import { VerticalBox, Button } from "std-widgets.slint";

export component AppWindow inherits Window {
    in property <image> canvas;
    callback regenerate-clicked();

    VerticalBox {
        padding: 16px;
        spacing: 12px;

        Image {
            source: canvas;
            width: 256px;
            height: 256px;
            image-rendering: pixelated;
        }

        Button {
            text: "다시 그리기";
            clicked => { regenerate-clicked(); }
        }
    }
}
```

```rust
// src/main.rs
use slint::{ComponentHandle, Rgba8Pixel, SharedPixelBuffer};

slint::include_modules!();

const SIZE: u32 = 256;

/// 매개변수 `seed`에 따라 색이 조금씩 달라지는 대각선 그러데이션을 생성합니다.
fn render_gradient(seed: u32) -> slint::Image {
    let mut buffer = SharedPixelBuffer::<Rgba8Pixel>::new(SIZE, SIZE);
    let width = buffer.width();
    let pixels = buffer.make_mut_slice();

    for (index, pixel) in pixels.iter_mut().enumerate() {
        let x = (index as u32) % width;
        let y = (index as u32) / width;

        *pixel = Rgba8Pixel {
            r: ((x + seed) % 256) as u8,
            g: ((y + seed) % 256) as u8,
            b: (((x + y) / 2 + seed) % 256) as u8,
            a: 255,
        };
    }

    slint::Image::from_rgba8(buffer)
}

fn main() -> Result<(), slint::PlatformError> {
    let ui = AppWindow::new()?;
    ui.set_canvas(render_gradient(0));

    let ui_weak = ui.as_weak();
    // 버튼을 누를 때마다 시드 값을 바꿔 다른 그러데이션을 그립니다.
    let mut seed: u32 = 0;
    ui.on_regenerate_clicked(move || {
        let Some(ui) = ui_weak.upgrade() else { return };
        seed = seed.wrapping_add(37);
        ui.set_canvas(render_gradient(seed));
    });

    ui.run()
}
```

`make_mut_slice()`는 이름에서 짐작할 수 있듯 필요할 때만 내부 버퍼를 복제하는 방식으로 동작하며, 반환된 `&mut [Rgba8Pixel]`을 자유롭게 순회하며 원하는 값을 채울 수 있습니다. 이 방식은 15장에서 배운 백그라운드 스레드 패턴과도 자연스럽게 결합됩니다. 예를 들어 무거운 이미지 처리 연산을 `std::thread::spawn`으로 실행하고, 완료되면 `slint::invoke_from_event_loop` 안에서 `ui.set_canvas(image)`를 호출하는 식으로 두 장의 내용을 함께 응용할 수 있습니다.

## 16.5 이미지·아이콘 리소스를 프로젝트에 포함하는 실무 구성

`@image-url("assets/logo.png")`에 적은 경로는 실행 파일 기준이 아니라, **그 코드가 들어 있는 `.slint` 파일을 기준으로 한 상대 경로**로 해석됩니다. 따라서 프로젝트 폴더를 구성할 때는 `.slint` 파일과 그 파일이 참조하는 이미지 폴더를 가까이 두는 것이 헷갈리지 않는 방법입니다. 일반적인 구조는 다음과 같습니다.

```
my_app/
├── Cargo.toml
├── build.rs
├── ui/
│   ├── app.slint
│   └── assets/
│       ├── logo.png
│       └── icon-save.png
└── src/
    └── main.rs
```

`ui/app.slint` 안에서는 `@image-url("assets/logo.png")`라고만 적으면 `ui/assets/logo.png`를 가리키게 됩니다. `build.rs`는 지금까지의 장에서 계속 써 온 것과 같은 형태로, `.slint` 파일을 컴파일하도록 지정하기만 하면 됩니다.

```rust
// build.rs
fn main() {
    slint_build::compile("ui/app.slint").unwrap();
}
```

```toml
# Cargo.toml (발췌)
[dependencies]
slint = "1"

[build-dependencies]
slint-build = "1"
```

여기서 실무적으로 알아 두면 좋은 점은, `@image-url`로 참조한 이미지 파일은 개발자가 따로 신경 쓰지 않아도 빌드 과정에서 실행 파일 배포에 필요한 형태로 처리된다는 것입니다. 즉 완성된 바이너리를 다른 컴퓨터로 옮길 때 `ui/assets` 폴더를 함께 들고 다녀야 하는지, 아니면 이미지가 이미 실행 파일 안에 들어 있는지는 빌드 설정에 따라 달라질 수 있는 부분입니다. 배포용 바이너리의 용량이나 임베디드 타깃처럼 저장 공간이 민감한 환경을 다뤄야 한다면, 사용 중인 Slint 버전의 `slint-build` 문서에서 리소스 처리 관련 옵션을 확인해 두는 것을 권합니다. 이 주제는 17장에서 다룰 임베디드·크로스 플랫폼 타기팅과도 맞닿아 있습니다.

## 16.6 실전 예제: 아이콘이 있는 버튼 컴포넌트 만들기

`Image`와 `TouchArea`를 조합하면 표준 위젯에 없는 형태의 아이콘 버튼을 직접 만들 수 있습니다. 아이콘 경로와 라벨 문자열을 프로퍼티로 받는 재사용 가능한 컴포넌트를 작성해 보겠습니다.

```slint
// ui/icon_button.slint
import { HorizontalBox } from "std-widgets.slint";

export component IconButton inherits Rectangle {
    in property <image> icon;
    in property <string> label;
    callback clicked <=> touch.clicked;

    height: 40px;
    border-radius: 6px;
    background: touch.pressed
        ? #d0d0d0
        : (touch.has-hover ? #e8e8e8 : transparent);

    animate background { duration: 100ms; }

    touch := TouchArea {}

    HorizontalLayout {
        padding: 10px;
        spacing: 8px;
        alignment: center;

        Image {
            source: icon;
            width: 18px;
            height: 18px;
        }

        Text {
            text: label;
            vertical-alignment: center;
        }
    }
}

export component AppWindow inherits Window {
    width: 240px;
    height: 100px;

    HorizontalBox {
        padding: 16px;

        IconButton {
            icon: @image-url("assets/icon-save.png");
            label: "저장";
            clicked => { debug("저장 버튼 클릭"); }
        }
    }
}
```

`callback clicked <=> touch.clicked;`는 `IconButton`이 가진 `clicked` 콜백을 내부 `TouchArea`인 `touch`의 `clicked` 콜백과 그대로 연결합니다. 이렇게 해 두면 `IconButton`을 사용하는 쪽에서는 내부에 `TouchArea`가 있다는 사실을 몰라도 표준 `Button`처럼 `clicked => { ... }`만 작성하면 됩니다. `touch.pressed`와 `touch.has-hover`는 `TouchArea`가 제공하는 상태 프로퍼티로, 각각 "지금 눌려 있는지"와 "마우스 포인터가 위에 있는지"를 나타내며, 이 값을 이용해 버튼의 배경색을 상태에 따라 바꿔 눌림·호버 효과를 표현했습니다.

## 16.7 이 장의 범위를 넘어서는 고급 렌더링 주제

`Image` 엘리먼트와 `SharedPixelBuffer`만으로도 아이콘 표시부터 절차적 이미지 생성까지 대부분의 실무 요구를 해결할 수 있습니다. 하지만 Slint가 화면을 그리는 방식 자체에 더 깊이 개입해야 하는 고급 시나리오도 존재합니다. 이런 주제는 이 책이 다루는 "Rust API로 Slint 다루기 기초"의 범위를 분명히 벗어나므로, 이름과 용도만 짚어 두고 넘어갑니다.

- **`Window::set_rendering_notifier`**: Slint가 프레임을 렌더링하는 시점 전후로 콜백을 걸어, 기반 그래픽 API(예: OpenGL) 위에 직접 그림을 겹쳐 그리는 "언더레이/오버레이" 렌더링을 구현할 때 쓰는 저수준 API입니다.
- **`slint::platform` 모듈**: 창 시스템이나 입력 장치가 표준적이지 않은 환경(마이크로컨트롤러, 자체 디스플레이 드라이버를 쓰는 임베디드 기기 등)을 위해 Slint의 플랫폼 통합 계층 자체를 새로 구현할 때 쓰는 API입니다.
- **커스텀 렌더링 백엔드/아이템**: Slint 내부의 렌더링 트리에 완전히 새로운 종류의 그리기 항목을 추가하는 것은 공식적으로 안정된 공개 API로 제공되는 영역이 아니며, 필요하다면 Slint 저장소의 예제와 최신 공식 문서를 직접 확인해야 합니다.

이 세 가지는 모두 "Slint가 이미 잘 그려 주는 것"을 넘어 "Slint의 그리기 파이프라인 자체를 확장하는" 작업이라는 공통점이 있습니다. 일반적인 데스크톱 애플리케이션이라면 이번 장에서 배운 `Image`/`SharedPixelBuffer` 수준에서 대부분 해결되며, 더 깊은 통합이 필요해지는 시점은 대개 임베디드 타기팅이나 게임에 가까운 실시간 그래픽을 다룰 때입니다.

## 요약

- `Image` 엘리먼트는 `source` 프로퍼티에 `@image-url(...)`로 불러온 정적 리소스나 Rust에서 만든 `slint::Image`를 대입해 이미지를 표시합니다. `image-fit`(fill/contain/cover), `image-rendering`(smooth/pixelated), `colorize` 프로퍼티로 표시 방식을 조정할 수 있습니다.
- `@image-url`의 경로는 실행 파일이 아니라 그 코드가 있는 `.slint` 파일 기준 상대 경로로 해석됩니다.
- 실행 중에 경로가 정해지는 이미지는 `slint::Image::load_from_path(path)`로 불러와 `in property <image>`에 대입합니다. 이 함수는 `Result`를 반환하므로 오류 처리를 빠뜨리지 않아야 합니다.
- 픽셀을 직접 채워 이미지를 생성해야 할 때는 `slint::SharedPixelBuffer<Rgba8Pixel>`(또는 `Rgb8Pixel`)을 만들고 `make_mut_slice()`로 값을 채운 뒤, `slint::Image::from_rgba8`(또는 `from_rgb8`)로 변환해 프로퍼티에 대입합니다.
- 이미지·아이콘 리소스는 `.slint` 파일과 가까운 폴더(예: `ui/assets/`)에 두고, `build.rs`의 `slint_build::compile(...)`로 컴파일하는 기존 프로젝트 구조를 그대로 활용하면 됩니다. 배포 시 리소스 임베딩 세부 옵션은 버전별 공식 문서를 참고합니다.
- `Image`와 `TouchArea`를 조합하면 아이콘 버튼처럼 표준 위젯에 없는 커스텀 UI 요소를 직접 구성할 수 있습니다.
- `Window::set_rendering_notifier`, `slint::platform` 모듈, 커스텀 렌더링 백엔드처럼 렌더링 파이프라인 자체를 확장하는 주제는 이 책의 범위 밖이며, 필요할 때 공식 문서를 참고하도록 이름만 소개했습니다.

## 연습문제

1. 16.1절의 예제를 확장해 `colorize` 프로퍼티로 아이콘 이미지의 색을 시간이 지남에 따라 바꿔 보세요. (힌트: `in property <brush>`를 하나 두고 15장에서 배운 `Timer`로 값을 주기적으로 바꿔 봅니다.)
2. 16.2절의 `image-fit` 비교 예제에서 가로세로 비율이 3:1인 넓은 이미지를 사용하면 `fill`, `contain`, `cover` 결과가 각각 어떻게 달라지는지 직접 실행해 확인하고 설명해 보세요.
3. 16.3절의 `load_from_path` 예제에서, 존재하지 않는 경로를 일부러 지정했을 때 `status-text`에 어떤 오류 메시지가 표시되는지 확인하고, 사용자에게 더 친절한 문구로 바꿔 보세요.
4. 16.4절의 그러데이션 예제를 변형해, 좌우 대각선이 아니라 원형(중심에서 바깥으로 갈수록 색이 진해지는) 그러데이션을 그려 보세요.
5. 16.6절의 `IconButton`을 두 개 이상 나열해 툴바를 구성하고, 그중 하나가 눌렸을 때 나머지 버튼은 `enabled: false`로 비활성화되도록 상태를 관리해 보세요.
