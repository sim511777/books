# 6장. 콜백과 이벤트 처리

📖 [◀ 목차](00-목차.md) | [◀ 이전: 5장. 프로퍼티와 바인딩](ch05-프로퍼티와바인딩.md) | [다음: 7장. Rust와 Slint 연동 기초 ▶](ch07-Rust와Slint연동기초.md)

---

5장에서는 값 사이의 관계를 선언하는 프로퍼티와 바인딩을 다뤘습니다. 하지만 버튼 클릭처럼 "특정 순간에 한 번 일어나는 사건"은 값의 관계만으로 표현할 수 없습니다. Slint는 이런 사건을 **콜백(callback)**으로 표현하고, Rust 쪽에서 그 콜백에 원하는 처리를 등록하는 방식으로 UI와 애플리케이션 로직을 연결합니다. 이번 장에서는 `.slint`에서 콜백을 선언하고 `TouchArea`에 연결하는 방법부터, Rust에서 그 콜백을 처리하는 방법, 그리고 콜백 안에서 UI 상태를 안전하게 되돌려 바꾸는 `Weak` 패턴까지 다룹니다.

## 6.1 .slint에서 콜백 선언하고 TouchArea에 연결하기

콜백은 `callback` 키워드로 선언합니다. 프로퍼티가 "값"을 나타낸다면, 콜백은 "사건"을 나타냅니다.

```slint
export component AppWindow inherits Window {
    callback clicked();
}
```

이 선언만으로는 아무 일도 일어나지 않습니다. `clicked`라는 이름의 콜백이 존재한다는 것을 알렸을 뿐, 실제로 이 콜백을 언제 "쏠지(emit)"와, 쏘아졌을 때 "무엇을 할지"는 따로 정해줘야 합니다.

화면에서 클릭을 감지하는 표준적인 방법은 `TouchArea`입니다. `TouchArea`는 자체적으로 `clicked`라는 내장 콜백을 가지고 있어서, 이 영역이 마우스로 클릭되거나 손가락으로 터치되면 자동으로 발생합니다.

```slint
export component AppWindow inherits Window {
    width: 200px;
    height: 120px;

    callback clicked();

    Rectangle {
        background: #4299e1;

        TouchArea {
            clicked => {
                // TouchArea 자신의 clicked 이벤트가 발생하면,
                // AppWindow가 선언한 clicked 콜백을 호출(emit)한다.
                root.clicked();
            }
        }
    }
}
```

여기서 `TouchArea { clicked => { ... } }`는 `TouchArea`가 내장하고 있는 `clicked` 콜백에 처리 코드를 붙이는 문법입니다. 그 처리 코드 안에서 `root.clicked();`를 호출하는데, 이것은 `AppWindow`가 직접 선언한 `clicked` 콜백을 실행(emit)하라는 명령문입니다. `root`는 현재 컴포넌트 자기 자신을 가리키는 이름입니다. 즉 `TouchArea`가 감지한 클릭 사건을, `AppWindow` 자신의 `clicked` 콜백으로 "중계"하는 구조입니다.

이렇게 중계 구조를 만들어 두면, `AppWindow`를 사용하는 Rust 쪽 코드는 내부에 `TouchArea`가 있다는 사실을 몰라도 되고, `AppWindow`가 `clicked`라는 콜백을 가지고 있다는 것만 알면 됩니다.

## 6.2 Rust에서 콜백 처리기 등록하기: on_x

`slint-build`는 최상위 컴포넌트의 각 `callback` 선언마다 `on_이름`이라는 Rust 메서드를 생성합니다. 이 메서드에 클로저를 넘기면, `.slint` 쪽에서 그 콜백이 발생(emit)할 때마다 이 클로저가 호출됩니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = AppWindow::new()?;

    ui.on_clicked(move || {
        println!("버튼이 클릭되었습니다!");
    });

    ui.run()
}
```

`on_clicked`가 받는 클로저의 타입은 `impl Fn() + 'static`입니다. `FnMut`이 아니라 `Fn`이라는 점에 주의해야 합니다. 콜백은 여러 번 반복해서 호출될 수 있는데, Slint 런타임은 이 클로저를 공유 참조로만 들고 있기 때문에 클로저 스스로 상태를 변경(mutate)할 수는 없습니다. 클릭 횟수를 세는 것처럼 클로저 내부에서 상태를 바꿔야 한다면, `Cell`이나 `RefCell`로 감싸서 내부 가변성을 이용하거나(로컬 카운터가 필요할 때), 혹은 6.5절에서 볼 것처럼 UI 쪽의 `in-out property`에 값을 직접 넣고 빼는 방식을 사용합니다.

콜백에 인자와 반환값이 있는 경우도 있습니다.

```slint
callback item-selected(index: int) -> bool;
```

이 경우 생성되는 Rust 메서드는 `on_item_selected(&self, handler: impl Fn(i32) -> bool + 'static)`입니다. 프로퍼티와 마찬가지로 콜백 이름의 하이픈도 밑줄로 바뀌어 `on_item_selected`가 됩니다.

## 6.3 콜백 안에서 UI 상태를 바꾸려면: Weak와 as_weak

`on_clicked`에 등록한 클로저 안에서, 콜백이 발생했다는 이유로 다른 프로퍼티 값을 바꿔야 하는 경우가 매우 흔합니다. 그런데 이때 클로저 안에서 `ui` 변수를 그대로 캡처하면 문제가 생깁니다.

```rust
// 이렇게 작성하면 안 된다 (컴파일은 되지만 메모리 누수가 생긴다)
let ui = AppWindow::new()?;
ui.on_clicked(move || {
    ui.set_counter(ui.get_counter() + 1); // ui를 강한 참조로 캡처
});
```

`AppWindow` 같은 Slint 컴포넌트 핸들은 내부적으로 참조 카운트 방식으로 관리되는 객체입니다. `ui.on_clicked(...)`로 등록한 클로저는 `ui`가 가리키는 그 객체 내부에 저장됩니다. 만약 그 클로저가 다시 `ui`(강한 참조)를 캡처하고 있다면, "객체가 클로저를 소유하고, 그 클로저가 다시 객체를 소유하는" 순환 참조가 만들어집니다. 참조 카운트 기반 메모리 관리에서 순환 참조는 참조 카운트가 0이 될 기회를 영영 주지 않으므로, 창을 닫아도 `AppWindow`가 메모리에서 해제되지 않는 누수로 이어집니다.

이 문제를 피하기 위해 Slint는 `ComponentHandle` 트레이트에 `as_weak()` 메서드를 제공합니다. 이 메서드는 강한 참조 대신, 참조 카운트에 영향을 주지 않는 `slint::Weak<T>`를 돌려줍니다. 클로저에는 이 `Weak`를 캡처하고, 실제로 필요한 순간에만 `.upgrade()`를 호출해 일시적으로 강한 참조를 얻습니다.

```rust
use slint::ComponentHandle;

slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = AppWindow::new()?;

    let ui_weak = ui.as_weak();
    ui.on_clicked(move || {
        // upgrade()는 Option<AppWindow>를 돌려준다.
        // 창이 이미 닫혀서 실제 객체가 사라졌다면 None이 반환된다.
        if let Some(ui) = ui_weak.upgrade() {
            let next = ui.get_counter() + 1;
            ui.set_counter(next);
        }
    });

    ui.run()
}
```

`ui_weak.upgrade()`는 `Option<AppWindow>`를 돌려줍니다. `AppWindow` 객체가 아직 살아있다면 `Some(ui)`로 강한 참조를 잠깐 빌려주고, 창이 이미 닫혀서 내부 객체가 해제된 뒤라면 `None`을 돌려줍니다. 이 `if let Some(ui) = ... { ... }` 블록이 끝나면 그 강한 참조는 다시 사라지므로, 클로저 자신은 여전히 `Weak`만 들고 있는 상태로 남습니다. 순환 참조가 생기지 않는 이유가 바로 여기에 있습니다.

정리하면 규칙은 다음과 같습니다.

- 콜백 클로저 **안에서** UI 핸들을 사용해야 한다면, 클로저를 등록하기 **전에** `as_weak()`로 `Weak`를 만들어 캡처합니다.
- 클로저가 실행될 때마다 `.upgrade()`로 임시 강한 참조를 얻어 그 안에서만 사용하고, 블록을 벗어나면 자연스럽게 놓아줍니다.
- 반대로 `main` 함수처럼 클로저 바깥, 즉 콜백 등록 코드와 `ui.run()`을 호출하는 지점에서는 원래의 강한 참조(`ui`)를 그대로 사용해도 됩니다. 순환 참조는 "객체가 자기 자신을 참조하는 클로저를 들고 있을 때"만 문제가 됩니다.

## 6.4 Rust에서 콜백을 직접 호출하기: invoke_x

콜백은 `.slint` 쪽 이벤트(예: `TouchArea`의 클릭)에 의해서만 발생하는 것이 아닙니다. `slint-build`는 `on_x`와 함께 `invoke_x`라는 메서드도 생성하는데, 이 메서드를 호출하면 마치 `.slint` 안에서 그 콜백이 실제로 발생한 것과 똑같은 효과를 냅니다. 즉 `on_x`로 등록해 둔 처리기가 그 자리에서 즉시 실행됩니다.

```rust
slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = AppWindow::new()?;

    ui.on_clicked(move || {
        println!("클릭 처리 로직 실행!");
    });

    // 사용자가 아직 아무것도 누르지 않았지만, 프로그램이 시작할 때
    // 한 번 클릭된 것과 동일한 효과를 Rust 코드에서 직접 낼 수 있다.
    ui.invoke_clicked();

    ui.run()
}
```

`invoke_clicked()`는 인자도 반환값도 없는 `callback clicked();`에 대응하는 메서드입니다. 만약 `callback item-selected(index: int) -> bool;`처럼 인자와 반환값이 있는 콜백이라면, 생성되는 메서드는 `invoke_item_selected(&self, index: i32) -> bool`처럼 인자를 전달하고 반환값을 그대로 돌려받는 형태가 됩니다.

`invoke_x`는 키보드 단축키 처리, 타이머, 다른 콜백의 처리 로직 재사용 등 "UI에서 직접 클릭한 것은 아니지만 클릭했을 때와 같은 동작을 실행하고 싶은" 모든 상황에서 유용합니다.

## 6.5 종합 예제: 클릭할 때마다 증가하는 카운터

지금까지 배운 내용, 즉 콜백 선언, `TouchArea` 연결, `on_x` 등록, `Weak` 캡처 패턴을 하나로 모아, 버튼을 누를 때마다 화면의 숫자가 늘어나는 카운터 앱을 완성해 보겠습니다.

```slint
// ui/app-window.slint
export component AppWindow inherits Window {
    width: 220px;
    height: 140px;

    in-out property <int> counter: 0;
    callback clicked();

    VerticalLayout {
        padding: 16px;
        spacing: 12px;

        Text {
            text: "클릭 횟수: " + counter;
            horizontal-alignment: center;
        }

        Rectangle {
            height: 44px;
            border-radius: 6px;
            background: area.pressed ? #2b6cb0 : #4299e1;

            Text {
                text: "여기를 클릭하세요";
                color: white;
                horizontal-alignment: center;
                vertical-alignment: center;
            }

            area := TouchArea {
                clicked => {
                    root.clicked();
                }
            }
        }
    }
}
```

`counter`는 `in-out`이므로 Rust에서 읽고 쓸 수 있고, `clicked`는 `TouchArea`의 클릭을 중계하는 콜백입니다. 이제 Rust 쪽에서 이 콜백에 "카운터를 1 증가시킨다"는 로직을 등록합니다.

```rust
// src/main.rs
use slint::ComponentHandle;

slint::include_modules!();

fn main() -> Result<(), slint::PlatformError> {
    let ui = AppWindow::new()?;

    // ui를 클로저 안에 강한 참조로 그대로 캡처하지 않기 위해
    // Weak 핸들을 미리 만들어 둔다.
    let ui_weak = ui.as_weak();
    ui.on_clicked(move || {
        let Some(ui) = ui_weak.upgrade() else {
            // 창이 이미 닫혔다면 할 일이 없다.
            return;
        };
        let current = ui.get_counter();
        ui.set_counter(current + 1);
    });

    ui.run()
}
```

동작 순서를 정리하면 다음과 같습니다.

1. 사용자가 사각형 영역을 클릭하면, 그 영역을 덮고 있는 `TouchArea`의 내장 `clicked` 콜백이 발생합니다.
2. `.slint`에 적어 둔 `clicked => { root.clicked(); }`가 실행되어, `AppWindow` 자신의 `clicked` 콜백을 호출(emit)합니다.
3. Rust에서 `ui.on_clicked(...)`로 등록해 둔 클로저가 실행됩니다.
4. 클로저는 `ui_weak.upgrade()`로 잠깐 강한 참조를 얻어 `get_counter()`로 현재 값을 읽고, `set_counter()`로 1 늘린 값을 다시 넣습니다.
5. `counter`는 `in-out property`이므로, 이 변경은 곧바로 화면의 `Text { text: "클릭 횟수: " + counter; }` 바인딩에 반영되어 숫자가 갱신됩니다.

프로퍼티 바인딩(5장)과 콜백(6장)이 함께 맞물려 동작하는 전형적인 패턴입니다. "값이 어떻게 화면에 반영되는가"는 선언적 바인딩이 책임지고, "언제 그 값을 바꿀 것인가"는 명령형 콜백 처리기가 책임집니다.

## 요약

- `callback name();`으로 사건을 선언하고, `TouchArea { clicked => { root.name(); } }`처럼 내장 콜백 처리기 안에서 호출(emit)하는 방식으로 UI 이벤트를 컴포넌트 자신의 콜백으로 중계할 수 있습니다.
- `slint-build`는 각 콜백마다 `on_이름(handler)`과 `invoke_이름(인자...)` 두 Rust 메서드를 생성합니다. `on_x`는 콜백이 발생했을 때 실행할 처리기를 등록하고, `invoke_x`는 Rust 코드에서 그 콜백을 직접 발생시킵니다.
- `on_x`가 받는 클로저는 `Fn` 트레이트를 요구하므로, 클로저 내부에서 상태를 바꾸려면 내부 가변성(`Cell`/`RefCell`)이나 UI 프로퍼티를 경유해야 합니다.
- 콜백 클로저 안에서 UI 핸들을 다시 사용해야 한다면, `ComponentHandle::as_weak()`로 얻은 `Weak`를 캡처하고 `.upgrade()`로 그때그때 강한 참조를 얻어야 합니다. 강한 참조를 클로저에 직접 캡처하면 "객체가 클로저를 소유하고 클로저가 다시 객체를 참조하는" 순환 참조가 생겨 메모리가 해제되지 않습니다.
- 버튼 클릭으로 카운터를 증가시키는 패턴은 콜백(사건 처리)과 `in-out property`(상태 저장 및 화면 반영)가 함께 맞물려 동작하는 대표적인 예입니다.

## 연습문제

1. `callback` 선언과 `in-out property` 선언이 근본적으로 어떻게 다른 대상을 표현하는지, 그리고 각각 Rust에서 어떤 메서드가 생성되는지 비교해서 설명해보세요.
2. `on_clicked`에 등록하는 클로저의 타입이 `FnMut`이 아니라 `Fn`인 이유를 설명하고, 클로저 안에서 지역 상태(예: 호출 횟수)를 누적하고 싶다면 어떤 방법을 쓸 수 있는지 예시 코드를 작성해보세요.
3. 이번 장의 카운터 예제에서 `let ui_weak = ui.as_weak();` 없이 `ui.on_clicked(move || { ui.set_counter(...); })`처럼 `ui`를 직접 캡처했다면 어떤 문제가 생기는지, 그리고 그 문제가 눈에 바로 띄지 않는 이유(컴파일은 된다는 점)를 설명해보세요.
4. `callback reset();`을 추가로 선언하고, `TouchArea`를 하나 더 두어 이 영역을 클릭하면 `counter`를 0으로 되돌리는 기능을 완성해보세요. Rust 쪽에서는 `on_reset`을 어떻게 등록해야 할까요?
5. 프로그램이 시작되자마자 `ui.invoke_clicked()`를 한 번 호출해서 카운터가 1부터 시작하도록 만들어보고, 이때 `on_clicked` 처리기가 정확히 몇 번 실행되는지 실행해서 확인해보세요.
