# 2장. 개발 환경 설정과 첫 창

1장에서 살펴본 것처럼 Slint 애플리케이션은 `.slint` 파일과 Rust 코드 두 부분으로 나뉘고, `.slint` 파일은 빌드 시점에 Rust 코드로 변환됩니다. 이 장에서는 그 두 부분을 실제로 하나의 Cargo 프로젝트로 묶어, 창 하나만 띄우는 가장 단순한 Slint 애플리케이션을 빌드하고 실행해 봅니다.

## Rust 툴체인 준비하기

Slint의 Rust 바인딩을 사용하려면 먼저 Rust 개발 환경이 갖추어져 있어야 합니다. Rust 진영에서는 툴체인 설치와 버전 관리를 `rustup`이라는 도구가 담당하고, 프로젝트 생성·빌드·의존성 관리는 `cargo`라는 빌드 도구 겸 패키지 매니저가 담당합니다. 이 책은 두 도구가 이미 시스템에 설치되어 있고, 터미널에서 `cargo --version` 명령이 정상적으로 버전을 출력하는 상태를 전제로 진행합니다. 아직 설치하지 않았다면 rustup 공식 배포 채널을 통해 먼저 설치를 마치기 바랍니다.

이 책의 예제는 Rust 2021 edition과 Slint 1.x 버전대를 기준으로 작성되었습니다.

## cargo new로 프로젝트 만들기

터미널에서 다음 명령으로 새 바이너리 프로젝트를 생성합니다.

```bash
cargo new hello-slint
cd hello-slint
```

`cargo new`는 다음과 같은 기본 구조를 만들어 줍니다.

```
hello-slint/
├── Cargo.toml
└── src/
    └── main.rs
```

여기에 Slint 전용으로 두 가지를 더 추가합니다. 하나는 `.slint` 파일을 담을 `ui` 디렉터리이고, 다른 하나는 빌드 시점에 `.slint` 파일을 처리할 `build.rs` 파일입니다.

```bash
mkdir ui
```

## Cargo.toml에 Slint 의존성 추가하기

Slint를 Rust 프로젝트에서 사용하려면 두 개의 크레이트가 필요합니다.

- `slint`: 런타임에 링크되는 일반 의존성(`[dependencies]`)입니다. `.slint`에서 생성된 코드가 참조하는 타입, 트레이트, 그리고 `include_modules!` 매크로가 여기서 제공됩니다.
- `slint-build`: 빌드 스크립트(`build.rs`) 안에서만 사용되는 빌드 의존성(`[build-dependencies]`)입니다. `.slint` 파일을 Rust 코드로 컴파일하는 함수를 제공합니다.

`Cargo.toml`을 다음과 같이 채웁니다.

```toml
[package]
name = "hello-slint"
version = "0.1.0"
edition = "2021"

[dependencies]
slint = "1"

[build-dependencies]
slint-build = "1"
```

`[dependencies]`와 `[build-dependencies]`는 서로 다른 빌드 단계에서 사용되는 별개의 의존성 목록이라는 점에 주의하세요. `slint-build`는 애플리케이션 실행 코드에는 포함되지 않고, 오직 빌드 스크립트를 컴파일하고 실행하는 단계에서만 쓰입니다.

## 첫 .slint 파일 작성하기

`ui/app.slint` 파일을 다음과 같이 작성합니다. 창(Window) 하나를 정의하고, 그 안에 텍스트 하나를 표시하는 것이 전부입니다.

```slint
component AppWindow inherits Window {
    width: 320px;
    height: 200px;
    title: "Hello, Slint!";

    Text {
        text: "Hello, Slint!";
        font-size: 24px;
        horizontal-alignment: center;
        vertical-alignment: center;
    }
}
```

`component AppWindow inherits Window { ... }`는 `AppWindow`라는 이름의 컴포넌트를 선언하면서, 이 컴포넌트가 `Window`(최상위 창)의 성질을 상속받는다는 뜻입니다. 중괄호 안에는 창의 프로퍼티(`width`, `height`, `title`)와 그 자식 요소인 `Text`가 나열되어 있습니다. `.slint` 문법 자체의 세부 규칙은 이후 장에서 다시 차근차근 다룰 것이므로, 지금은 "이 파일 하나가 창 하나를 정의한다"는 전체 그림만 파악하고 넘어가도 충분합니다.

## build.rs: .slint 파일을 빌드에 연결하기

Cargo는 프로젝트 루트에 `build.rs`라는 파일이 있으면 실제 컴파일에 앞서 그 파일을 먼저 컴파일하고 실행합니다. Slint는 바로 이 지점을 이용해 `.slint` 파일을 Rust 코드로 변환합니다. 프로젝트 루트(`Cargo.toml`과 같은 위치)에 `build.rs`를 다음과 같이 작성합니다.

```rust
fn main() {
    slint_build::compile("ui/app.slint").unwrap();
}
```

`slint_build::compile`은 인자로 받은 경로의 `.slint` 파일을 파싱하고, 그 안에서 선언된 컴포넌트를 Rust 구조체와 메서드로 변환한 코드를 생성합니다. 생성된 코드는 Cargo가 관리하는 빌드 출력 디렉터리(`OUT_DIR`)에 저장되며, 이 과정이 성공하면 `Ok(())`를, `.slint` 파일에 문법 오류가 있는 등 실패하면 `Err`를 반환합니다. 지금 단계에서는 `.unwrap()`으로 처리해, 컴파일 오류가 있을 경우 빌드 자체가 즉시 실패하며 원인을 알려주도록 합니다.

프로젝트에 `.slint` 파일이 여러 개라면 `slint_build::compile`을 파일마다 한 번씩 호출하면 됩니다.

## main.rs: include_modules!로 생성된 코드 가져오기

`build.rs`가 생성한 Rust 코드를 `main.rs`에서 직접 `#include`하듯 가져오려면 `slint::include_modules!()` 매크로를 사용합니다. 이 매크로는 `build.rs`에서 `slint_build::compile`을 호출할 때 함께 기록해 둔 위치 정보를 읽어, 생성된 코드를 현재 모듈 안에 그대로 삽입합니다.

`src/main.rs`를 다음과 같이 작성합니다.

```rust
slint::include_modules!();

fn main() {
    let app_window = AppWindow::new().unwrap();
    app_window.run().unwrap();
}
```

`slint::include_modules!()`는 파일 최상단, `fn main` 바깥에 위치해야 합니다. 이 한 줄로 `ui/app.slint`에서 선언한 `AppWindow` 컴포넌트가 같은 이름의 Rust 구조체로 `main.rs`의 스코프 안에 들어옵니다.

`AppWindow::new()`는 이 구조체의 인스턴스를 생성합니다. 반환 타입은 `Result<AppWindow, slint::PlatformError>`로, 창을 표시할 플랫폼 백엔드를 초기화하는 과정에서 실패할 가능성을 표현합니다. 예제에서는 `.unwrap()`으로 실패 시 패닉하도록 처리했습니다. 인스턴스를 얻은 뒤 `.run()`을 호출하면 이벤트 루프가 시작되어 창이 화면에 표시되고, 사용자가 창을 닫을 때까지 프로그램이 그 자리에서 대기합니다. `run()` 역시 `Result<(), slint::PlatformError>`를 반환하므로 `.unwrap()`으로 받습니다.

이 짧은 `main.rs`와 앞서 작성한 `ui/app.slint`, `Cargo.toml`, `build.rs` 네 파일만으로 텍스트 하나가 표시된 창을 여는 완전한 애플리케이션이 완성됩니다. `.slint`에 정의한 프로퍼티를 Rust 코드에서 읽고 쓰는 방법, 즉 생성된 구조체의 `get_*`/`set_*` 메서드는 이후 프로퍼티와 바인딩을 다루는 장에서 자세히 살펴봅니다.

지금까지 만든 프로젝트의 전체 파일 구조를 정리하면 다음과 같습니다.

```
hello-slint/
├── Cargo.toml
├── build.rs
├── src/
│   └── main.rs
└── ui/
    └── app.slint
```

## cargo run으로 빌드하고 실행하기

프로젝트 루트에서 다음 명령을 실행합니다.

```bash
cargo run
```

`cargo run`은 다음 순서로 동작합니다.

1. `build.rs`를 컴파일하고 실행합니다. 이 과정에서 `slint_build::compile`이 `ui/app.slint`를 읽어 Rust 코드를 생성합니다.
2. `src/main.rs`를 비롯한 나머지 소스를 컴파일합니다. 이때 `slint::include_modules!()`가 1단계에서 생성된 코드를 끌어옵니다.
3. 링크가 끝난 실행 파일을 곧바로 실행합니다.

빌드가 성공하면 "Hello, Slint!"라는 제목의 작은 창이 화면 가운데에 같은 문구를 표시하며 나타납니다. 창을 닫으면 `run()`이 반환되고 `main` 함수가 종료되면서 프로그램이 끝납니다.

`ui/app.slint`의 내용을 수정한 뒤에는 `cargo run`을 다시 실행하기만 하면 됩니다. `build.rs`가 매번 다시 실행되면서 최신 `.slint` 파일 내용을 반영한 코드를 새로 생성하기 때문에, 별도의 캐시 삭제 과정 없이도 변경 사항이 곧바로 반영됩니다.

## 요약

- Rust 툴체인은 `rustup`(설치·버전 관리)과 `cargo`(빌드·의존성 관리) 두 도구로 이루어집니다.
- `cargo new`로 프로젝트를 생성한 뒤, `.slint` 파일을 담을 `ui` 디렉터리와 `build.rs` 파일을 추가로 준비합니다.
- `Cargo.toml`에는 런타임용 `slint` 크레이트를 `[dependencies]`에, 빌드 시점용 `slint-build` 크레이트를 `[build-dependencies]`에 각각 추가합니다.
- `build.rs`에서 `slint_build::compile("ui/app.slint").unwrap()`을 호출하면 빌드 시점에 `.slint` 파일이 Rust 코드로 컴파일됩니다.
- `main.rs` 최상단의 `slint::include_modules!()`가 그 생성된 코드를 현재 모듈로 가져옵니다.
- `component AppWindow inherits Window { ... }` 형태로 창 하나를 선언하는 것이 가장 단순한 `.slint` 파일입니다.
- `AppWindow::new().unwrap()`으로 인스턴스를 만들고 `.run().unwrap()`으로 이벤트 루프를 시작합니다. 두 메서드 모두 `Result<_, slint::PlatformError>`를 반환합니다.
- `cargo run`은 `build.rs` 실행, 소스 컴파일, 실행 파일 구동을 한 번에 처리합니다.

## 연습문제

1. `Cargo.toml`에서 `slint`는 `[dependencies]`에, `slint-build`는 `[build-dependencies]`에 넣는 이유를 설명해 보세요.
2. `build.rs`에서 `slint_build::compile`이 하는 일을 한 문단으로 설명하고, 이 함수가 반환하는 타입이 무엇인지 적어 보세요.
3. `slint::include_modules!()`를 `fn main` 안이 아니라 파일 최상단에 두어야 하는 이유를 생각해 보세요.
4. `ui/greeting.slint`에 `component Greeting inherits Window { ... }`를 정의했다면, `build.rs`와 `main.rs`를 각각 어떻게 고쳐야 이 컴포넌트로 창을 띄울 수 있을지 코드로 작성해 보세요.
5. 이 장의 `app.slint`를 그대로 사용하되 창 크기를 400x300으로 바꾸고 `cargo run`으로 확인해 보세요. (힌트: `width`, `height` 프로퍼티는 `.slint` 쪽에서 수정합니다.)
