# 9장. 다이얼로그와 팝업

[◀ 이전: 8장. 테이블](ch08-테이블.md) | [📖 목차](00-목차.md) | [다음: 10장. 도킹과 멀티 뷰포트 ▶](ch10-도킹과멀티뷰포트.md)


지금까지 살펴본 위젯들은 모두 창(window)의 본문 안에 고정된 자리를 차지하고 있었습니다. 하지만 실제 애플리케이션에서는 "정말 삭제하시겠습니까?" 같은 확인 창, 우클릭했을 때 나타나는 컨텍스트 메뉴, 마우스를 올렸을 때 살짝 떠오르는 도움말처럼 평소에는 화면에 없다가 특정 시점에만 나타나는 UI 요소가 자주 필요합니다.

이런 요소들을 ImGui는 크게 세 가지로 나눠서 제공합니다. 일반 팝업(popup), 모달 다이얼로그(modal dialog), 그리고 툴팁(tooltip)입니다. 셋 다 "평소에는 그려지지 않다가 조건이 맞을 때만 그려진다"는 점은 같지만, 사용자의 입력을 어떻게 가로채는지에서 성격이 갈립니다. 이번 장에서는 이 세 가지를 하나씩 살펴보고, 실무에서 가장 자주 마주치는 "삭제 확인" 패턴을 처음부터 끝까지 만들어 봅니다.

즉시 모드 GUI에서 팝업이 어떻게 동작하는지 이해하려면 3장에서 다룬 ID 스택과 위젯 상태 관리 개념을 다시 떠올리는 것이 도움이 됩니다. ImGui는 위젯을 객체로 들고 있지 않으므로, 팝업 역시 "지금 열려 있는가"라는 상태를 내부적으로 문자열 ID에 연결해 기억해 두고, 매 프레임 여러분이 호출하는 `BeginPopup` 계열 함수가 그 상태를 확인해서 내용을 그릴지 말지를 결정하는 구조입니다.

## 9.1 팝업의 기본 흐름: OpenPopup과 BeginPopup

ImGui에서 팝업은 두 단계로 동작합니다.

1. `ImGui::OpenPopup("popup_id")`를 호출해서 "이 ID를 가진 팝업을 열어라"라고 표시합니다.
2. 이후 프레임부터 `ImGui::BeginPopup("popup_id")`가 `true`를 반환하기 시작하고, 그 안에서 그린 내용이 화면 위에 떠 있는 작은 창처럼 표시됩니다.

여기서 중요한 점은 `OpenPopup`은 "지금 당장 그려라"가 아니라 "다음부터 이 팝업을 열린 상태로 취급하라"는 예약에 가깝다는 것입니다. 그리고 `BeginPopup`/`EndPopup` 쌍은 여러분이 매 프레임 반복해서 호출해야 하며, `BeginPopup`이 `false`를 반환하면 그 사이의 위젯 호출 코드는 아예 실행할 필요가 없습니다(실행해도 무시되지만, 보통은 `if` 블록으로 감싸서 건너뜁니다).

가장 단순한 예로, 버튼을 눌렀을 때 작은 선택 목록을 띄워 보겠습니다.

```cpp
if (ImGui::Button("옵션 열기"))
{
    ImGui::OpenPopup("옵션팝업");
}

if (ImGui::BeginPopup("옵션팝업"))
{
    ImGui::Text("작업을 선택하세요");
    ImGui::Separator();
    if (ImGui::Selectable("이름 바꾸기")) { /* ... */ }
    if (ImGui::Selectable("복제하기"))   { /* ... */ }
    if (ImGui::Selectable("삭제하기"))   { /* ... */ }
    ImGui::EndPopup();
}
```

이 코드는 매 프레임 실행됩니다. 버튼을 누르지 않은 평범한 프레임에서는 `OpenPopup`이 호출되지 않으므로 `BeginPopup`은 `false`를 반환하고, `Selectable`들은 그려지지 않습니다. 버튼을 누른 그 프레임(그리고 팝업이 닫히기 전까지의 모든 후속 프레임)에는 `BeginPopup`이 `true`를 반환해서 팝업 내용이 그려집니다.

`BeginPopup`으로 만든 일반 팝업은 사용자가 팝업 바깥 영역을 클릭하거나 `Esc` 키를 누르면 ImGui가 알아서 닫아줍니다. 별도로 "닫기" 처리를 해 줄 필요가 없다는 뜻입니다. 이 자동 닫힘 동작이 바로 컨텍스트 메뉴나 드롭다운 같은 가벼운 팝업에 딱 맞는 이유이기도 합니다. 실제로 6장에서 다룬 메뉴바의 하위 메뉴들도 내부적으로는 이와 비슷한 팝업 메커니즘 위에서 동작합니다.

> 참고로 마우스 오른쪽 버튼 클릭에 반응하는 컨텍스트 메뉴는 `ImGui::BeginPopupContextItem()`, `ImGui::BeginPopupContextWindow()` 같은 보조 함수로 `OpenPopup` 호출까지 한 번에 처리할 수 있습니다. 동작 원리는 지금 배운 `OpenPopup` + `BeginPopup` 조합과 동일합니다.

## 9.2 모달 다이얼로그: BeginPopupModal

일반 팝업은 "바깥을 클릭하면 조용히 사라지는" 가벼운 UI에 적합하지만, "저장하지 않은 변경사항이 있습니다. 계속하시겠습니까?"처럼 사용자가 반드시 명시적으로 선택해야 하는 상황에는 어울리지 않습니다. 실수로 다른 곳을 클릭했다가 다이얼로그가 사라져 버리면 곤란하기 때문입니다.

이런 경우를 위해 ImGui는 `ImGui::BeginPopupModal()`을 제공합니다. 사용법은 `BeginPopup`과 비슷하지만 동작 방식에 결정적인 차이가 있습니다.

- 모달이 열려 있는 동안에는 화면의 다른 모든 창이 흐릿하게 처리되거나 최소한 입력을 받지 못하게 되어, 사용자가 모달 뒤의 UI를 조작할 수 없습니다.
- 모달 바깥을 클릭해도 저절로 닫히지 않습니다. 반드시 팝업 내부에서 `ImGui::CloseCurrentPopup()`을 호출해야 닫힙니다.

`BeginPopupModal`의 첫 번째 인자는 창 제목처럼 화면에 표시되는 문자열이자 동시에 팝업의 ID로도 쓰입니다. 두 번째 인자로 `bool*`을 넘기면 모달 오른쪽 위에 닫기 버튼(x)이 표시되고, 사용자가 그 버튼을 누르면 넘긴 `bool` 값이 `false`로 바뀝니다.

```cpp
if (ImGui::Button("모달 열기"))
{
    ImGui::OpenPopup("경고");
}

// 화면 중앙에 뜨도록 위치를 지정 (선택 사항이지만 자주 쓰이는 관용구)
ImVec2 center = ImGui::GetMainViewport()->GetCenter();
ImGui::SetNextWindowPos(center, ImGuiCond_Appearing, ImVec2(0.5f, 0.5f));

if (ImGui::BeginPopupModal("경고", nullptr, ImGuiWindowFlags_AlwaysAutoResize))
{
    ImGui::Text("저장하지 않은 변경사항이 있습니다.");
    ImGui::Separator();

    if (ImGui::Button("확인"))
    {
        ImGui::CloseCurrentPopup();
    }
    ImGui::EndPopup();
}
```

`SetNextWindowPos`를 `ImGuiCond_Appearing` 조건과 함께 호출하면, 팝업이 "이제 막 나타나는" 프레임에만 위치가 적용되고 이후 사용자가 창을 옮기면 그 위치가 유지됩니다. 모달을 화면 중앙에 띄우는 이 관용구는 매우 자주 쓰이므로 눈에 익혀 두면 좋습니다.

## 9.3 팝업 닫기: CloseCurrentPopup

`ImGui::CloseCurrentPopup()`은 이름 그대로 지금 그리고 있는(가장 안쪽의) 팝업이나 모달을 닫으라고 요청하는 함수입니다. 반드시 `BeginPopup`/`BeginPopupModal`과 `EndPopup` 사이, 즉 팝업이 실제로 열려서 내용을 그리고 있는 코드 블록 안에서 호출해야 합니다.

일반 팝업에서는 사용자가 바깥을 클릭하기만 해도 자동으로 닫히므로 `CloseCurrentPopup`을 안 써도 되는 경우가 많지만, "선택지를 골랐으니 이제 닫아야 하는" 상황에서는 명시적으로 호출해 주는 것이 자연스럽습니다. 예를 들어 앞서 본 옵션 목록에서 항목을 하나 고르면 팝업이 즉시 닫히게 하려면 이렇게 씁니다.

```cpp
if (ImGui::BeginPopup("옵션팝업"))
{
    if (ImGui::Selectable("이름 바꾸기"))
    {
        // 이름 바꾸기 로직
        ImGui::CloseCurrentPopup();
    }
    if (ImGui::Selectable("삭제하기"))
    {
        // 삭제 로직
        ImGui::CloseCurrentPopup();
    }
    ImGui::EndPopup();
}
```

모달의 경우는 반드시 이 함수를 호출해야만 닫힌다는 점을 다시 강조해 둡니다. "확인"이나 "취소" 버튼 각각에 `CloseCurrentPopup()`을 빼먹으면 사용자는 영원히 그 모달에 갇히게 됩니다.

## 9.4 실전 예제: 삭제 확인 다이얼로그

이제 배운 내용을 하나로 묶어서, 실무에서 정말 자주 쓰이는 "삭제 확인" 흐름을 처음부터 끝까지 만들어 보겠습니다. 목표는 다음과 같습니다.

1. "항목 삭제" 버튼을 누르면 확인용 모달이 뜬다.
2. 모달에는 "예"와 "아니오" 두 개의 버튼이 있다.
3. "예"를 누르면 실제 삭제 로직이 실행되고 모달이 닫힌다.
4. "아니오"를 누르거나 오른쪽 위 닫기 버튼을 눌러도 아무 일도 일어나지 않고 모달만 닫힌다.

```cpp
bool showDeleteModal = false; // OpenPopup 호출을 다음 프레임으로 미루기 위한 플래그

// --- 메인 UI ---
if (ImGui::Button("항목 삭제"))
{
    showDeleteModal = true;
}

if (showDeleteModal)
{
    ImGui::OpenPopup("삭제 확인");
    showDeleteModal = false;
}

// --- 모달 정의 ---
ImVec2 center = ImGui::GetMainViewport()->GetCenter();
ImGui::SetNextWindowPos(center, ImGuiCond_Appearing, ImVec2(0.5f, 0.5f));

bool modalOpen = true;
if (ImGui::BeginPopupModal("삭제 확인", &modalOpen, ImGuiWindowFlags_AlwaysAutoResize))
{
    ImGui::Text("정말 이 항목을 삭제하시겠습니까?");
    ImGui::TextDisabled("이 작업은 되돌릴 수 없습니다.");
    ImGui::Separator();

    if (ImGui::Button("예", ImVec2(120, 0)))
    {
        DeleteSelectedItem(); // 실제 삭제 로직
        ImGui::CloseCurrentPopup();
    }
    ImGui::SameLine();
    if (ImGui::Button("아니오", ImVec2(120, 0)))
    {
        ImGui::CloseCurrentPopup();
    }

    ImGui::EndPopup();
}
```

이 예제에서 몇 가지 눈여겨볼 부분이 있습니다.

먼저 `OpenPopup`을 버튼 클릭 바로 그 자리에서 호출하지 않고 `showDeleteModal`이라는 플래그를 하나 거쳐서 호출했습니다. 이렇게 한 이유는, `OpenPopup`은 `BeginPopupModal` 호출과 같은 스코프(정확히는 같은 ID 스택 위치)에서 호출되는 것이 가장 안전하기 때문입니다. 버튼과 모달 정의가 서로 다른 함수나 다른 조건문 안에 떨어져 있는 실제 프로젝트에서는 이런 식으로 "열어야 한다"는 요청만 플래그로 기록해 두고, 실제 `OpenPopup` 호출은 모달을 정의하는 코드 바로 앞으로 모아주는 패턴이 유용합니다. 이런 상태 관리 패턴은 14장에서 조금 더 폭넓게 다룹니다.

또한 "예"와 "아니오" 버튼을 `ImGui::SameLine()`으로 한 줄에 나란히 배치했습니다. 이런 버튼 배치나 크기 지정은 5장에서 다룬 레이아웃 함수들과 그대로 이어지는 내용입니다.

마지막으로, 두 버튼 모두 마지막에 `CloseCurrentPopup()`을 호출한다는 점도 기억해 둘 만합니다. 삭제를 실행하든 취소하든, 결과와 상관없이 모달은 닫혀야 하기 때문입니다.

## 9.5 툴팁: 마우스를 올리면 나타나는 도움말

팝업과 모달이 클릭으로 열리는 UI라면, 툴팁은 마우스를 위젯 위에 잠시 올려두기만 해도 나타나는 훨씬 가벼운 도움말입니다. 아이콘만 있는 버튼이 무슨 기능인지 설명하거나, 값이 잘려서 보이는 텍스트의 전체 내용을 보여줄 때 유용합니다.

툴팁을 띄우는 기본 패턴은 위젯을 그린 직후 `ImGui::IsItemHovered()`로 "방금 그린 위젯 위에 마우스가 있는가"를 확인하고, `true`라면 `ImGui::SetTooltip()`을 호출하는 것입니다.

```cpp
ImGui::Button("저장");
if (ImGui::IsItemHovered())
{
    ImGui::SetTooltip("현재 문서를 파일로 저장합니다 (Ctrl+S)");
}
```

`IsItemHovered()`는 바로 직전에 그린 위젯에 대해 마우스 호버 여부를 알려주는 함수로, 13장에서 다룰 입력 상태 조회 함수들 중 가장 자주 쓰이는 함수이기도 합니다. `SetTooltip`은 `printf` 스타일의 서식 문자열을 받기 때문에 다음처럼 동적인 내용도 쉽게 넣을 수 있습니다.

```cpp
ImGui::ColorButton("색상", color);
if (ImGui::IsItemHovered())
{
    ImGui::SetTooltip("R:%.2f G:%.2f B:%.2f", color.x, color.y, color.z);
}
```

텍스트 한 줄로는 부족하고 이미지나 여러 위젯을 조합한 좀 더 복잡한 툴팁을 만들고 싶다면, `SetTooltip` 대신 `BeginTooltip()`/`EndTooltip()` 쌍을 사용합니다. 이 둘 사이는 일반 창 본문처럼 자유롭게 위젯을 그릴 수 있는 영역입니다.

```cpp
if (ImGui::IsItemHovered())
{
    ImGui::BeginTooltip();
    ImGui::Text("선택한 텍스처");
    ImGui::Image(textureId, ImVec2(64, 64));
    ImGui::Text("512 x 512, RGBA");
    ImGui::EndTooltip();
}
```

툴팁은 `OpenPopup` 같은 별도의 "열기" 호출이 필요 없다는 점에서 팝업/모달과 다릅니다. 매 프레임 `IsItemHovered()`로 조건을 확인해서 그때그때 바로 그리면 되는, 상태를 따로 기억할 필요가 없는 가장 단순한 형태의 오버레이라고 볼 수 있습니다.

## 요약

- ImGui의 팝업은 `OpenPopup("id")`로 열림을 예약하고, 이후 프레임의 `BeginPopup("id")` / `EndPopup()`이 실제 내용을 그리는 2단계 구조로 동작합니다.
- 일반 팝업은 바깥을 클릭하거나 `Esc`를 누르면 자동으로 닫히지만, `BeginPopupModal()`로 만든 모달 다이얼로그는 다른 창의 입력을 차단하며 명시적으로 `CloseCurrentPopup()`을 호출해야만 닫힙니다.
- 모달을 화면 중앙에 띄우려면 `GetMainViewport()->GetCenter()`와 `SetNextWindowPos(..., ImGuiCond_Appearing, ImVec2(0.5f, 0.5f))` 조합을 관용구처럼 사용합니다.
- "삭제 확인" 같은 실전 다이얼로그는 버튼 클릭 → 플래그 설정 → `OpenPopup` → 모달 안 예/아니오 버튼 → 각 버튼에서 `CloseCurrentPopup` 호출의 흐름으로 구성합니다.
- 툴팁은 `IsItemHovered()`로 호버 상태를 확인한 뒤 `SetTooltip()`으로 간단히, 또는 `BeginTooltip()`/`EndTooltip()`으로 복잡한 내용을 띄울 수 있는 가장 가벼운 오버레이입니다.

## 연습문제
