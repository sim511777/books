# 4장. 기본 위젯

[◀ 이전: 3장. Immediate Mode의 핵심 개념](ch03-ImmediateMode의핵심개념.md) | [📖 목차](00-목차.md) | [다음: 5장. 창과 레이아웃 ▶](ch05-창과레이아웃.md)


3장에서 우리는 ImGui 위젯이 어떤 방식으로 상태를 읽고 쓰는지, 그리고 여러 위젯을 구분하기 위한 ID 시스템이 왜 필요한지 살펴보았습니다. 이제 그 지식을 바탕으로 실제로 자주 사용하는 기본 위젯들을 하나씩 살펴보겠습니다. 이 장에서 다루는 위젯들은 이후 5장 이후에서 소개할 창, 테이블, 트리 같은 더 복잡한 구성 요소를 만들 때도 계속 재료로 쓰이므로, 각 함수의 시그니처와 동작 방식을 정확히 익혀두는 것이 좋습니다.

## 4.1 텍스트 출력

가장 기본이 되는 위젯은 텍스트입니다. `ImGui::Text()`는 `printf` 스타일의 서식 문자열을 받습니다.

```cpp
ImGui::Text("현재 프레임 시간: %.3f ms", frame_time_ms);
ImGui::Text("플레이어 이름: %s", player_name.c_str());
```

내부적으로 `printf` 계열 함수와 동일한 방식으로 서식을 처리하므로, `%`로 시작하는 서식 지정자를 그대로 사용할 수 있습니다. 다만 사용자가 직접 입력한 문자열을 그대로 서식 문자열 자리에 넣는 것은 피해야 합니다. 문자열 안에 `%`가 포함되어 있으면 예기치 않게 해석될 수 있기 때문입니다. 사용자 입력을 그대로 출력하고 싶다면 다음처럼 `%s`를 통해 인자로 넘기는 편이 안전합니다.

```cpp
ImGui::Text("%s", user_input.c_str()); // 안전
// ImGui::Text(user_input.c_str());    // 위험: user_input 안에 %d 등이 있으면 문제가 생긴다
```

색을 입힌 텍스트가 필요하면 `ImGui::TextColored()`를 사용합니다. 색상은 `ImVec4(r, g, b, a)`로, 각 성분은 0.0~1.0 범위입니다.

```cpp
ImGui::TextColored(ImVec4(1.0f, 0.3f, 0.3f, 1.0f), "경고: 값이 범위를 벗어났습니다");
```

기본적으로 `Text()`는 창 폭을 넘어가도 줄바꿈을 하지 않고 그대로 잘려서 넘칩니다. 긴 문장을 창 폭에 맞춰 자동으로 줄바꿈하고 싶다면 `ImGui::TextWrapped()`를 사용합니다.

```cpp
ImGui::TextWrapped(
    "이 문장은 매우 길게 작성되었으며, 창의 폭이 충분하지 않을 경우 "
    "TextWrapped는 단어 단위로 줄을 바꿔서 여러 줄에 걸쳐 표시합니다.");
```

이 밖에도 회색으로 흐리게 표시하는 `ImGui::TextDisabled()`, 라벨을 붙이듯 앞에 굵게 표시되는 `ImGui::LabelText()` 등이 있지만, 실무에서는 `Text`, `TextColored`, `TextWrapped` 세 가지만으로도 대부분의 상황을 충분히 처리할 수 있습니다.

## 4.2 버튼

3장에서 이미 살펴본 것처럼 `ImGui::Button()`은 클릭 여부를 `bool`로 반환하는 위젯입니다.

```cpp
if (ImGui::Button("저장"))
{
    SaveFile();
}
```

버튼의 크기는 두 번째 인자로 명시적으로 지정할 수 있습니다. `ImVec2(0, 0)`을 넘기면(생략 시 기본값) 텍스트 크기에 여백을 더한 기본 크기가 적용됩니다.

```cpp
if (ImGui::Button("적용", ImVec2(120, 0)))
{
    ApplySettings();
}
```

버튼을 가로로 나란히 배치하고 싶을 때는 다음 위젯을 호출하기 전에 `ImGui::SameLine()`을 호출합니다. 레이아웃에 대한 자세한 내용은 5장에서 다루지만, 지금 단계에서는 "다음 위젯을 새 줄로 내리지 말고 같은 줄에 이어 그려라"는 지시라고 이해하면 충분합니다.

```cpp
if (ImGui::Button("확인")) { /* ... */ }
ImGui::SameLine();
if (ImGui::Button("취소")) { /* ... */ }
```

일반 버튼보다 작은, 여백이 거의 없는 버튼이 필요할 때는 `ImGui::SmallButton()`을 사용합니다. 텍스트 한 줄 옆에 작은 액션 버튼을 붙이는 용도로 자주 쓰입니다.

```cpp
ImGui::Text("항목 A");
ImGui::SameLine();
if (ImGui::SmallButton("삭제"))
{
    // 항목 A 삭제
}
```

리스트의 각 행마다 `SmallButton`을 반복해서 그릴 때는 라벨이 겹치므로, 3장에서 배운 `PushID`/`PopID`나 `##숨김ID`를 함께 사용해야 한다는 점을 기억해두세요.

## 4.3 체크박스와 라디오 버튼

`ImGui::Checkbox()`는 `bool` 변수의 주소를 받아 켜고 끄는 상태를 표현합니다.

```cpp
static bool enable_vsync = true;
ImGui::Checkbox("수직 동기화", &enable_vsync);
```

여러 옵션 중 하나만 선택하는 UI에는 `ImGui::RadioButton()`을 사용합니다. `RadioButton`에는 두 가지 형태가 있는데, 하나는 `bool` 하나를 직접 넘기는 형태이고, 다른 하나는 정수 변수와 각 버튼이 나타내는 값을 비교하는 형태입니다. 여러 옵션 중 하나를 고르는 일반적인 경우에는 후자가 더 편리합니다.

```cpp
enum class Quality { Low, Medium, High };
static int quality = (int)Quality::Medium;

ImGui::RadioButton("낮음", &quality, (int)Quality::Low);
ImGui::SameLine();
ImGui::RadioButton("중간", &quality, (int)Quality::Medium);
ImGui::SameLine();
ImGui::RadioButton("높음", &quality, (int)Quality::High);
```

`RadioButton("낮음", &quality, (int)Quality::Low)`는 내부적으로 "`quality`가 `Quality::Low`와 같으면 선택된 상태로 그리고, 클릭되면 `quality`에 `Quality::Low` 값을 대입하라"는 뜻입니다. 세 개의 `RadioButton`이 같은 `quality` 변수를 공유하기 때문에, 이 중 하나를 클릭하면 자연스럽게 나머지는 선택 해제된 것처럼 보입니다. 별도의 "그룹" 개념을 따로 만들 필요 없이, 같은 변수를 가리키게 하는 것만으로 상호 배타적인 선택지를 구현할 수 있다는 점이 Immediate Mode다운 특징입니다.

## 4.4 슬라이더와 드래그

값을 특정 범위 안에서 조절할 때는 슬라이더 계열 위젯을 사용합니다. 대표적으로 `ImGui::SliderFloat()`와 `ImGui::SliderInt()`가 있으며, 둘 다 최소값과 최대값을 명시적으로 지정해야 합니다.

```cpp
static float brightness = 1.0f;
ImGui::SliderFloat("밝기", &brightness, 0.0f, 2.0f);

static int max_particles = 500;
ImGui::SliderInt("최대 파티클 수", &max_particles, 0, 2000);
```

슬라이더는 마우스로 핸들을 드래그하는 방식뿐 아니라, `Ctrl`을 누른 채 클릭하면 숫자를 직접 입력할 수도 있습니다. 표시 형식은 `printf` 서식을 그대로 받는 네 번째 인자로 지정할 수 있습니다.

```cpp
ImGui::SliderFloat("밝기", &brightness, 0.0f, 2.0f, "%.2f");
```

반면 최소/최대 범위를 굳이 정해두지 않고, 마우스를 좌우로 움직인 양만큼 값을 자유롭게 늘리거나 줄이고 싶을 때는 `ImGui::DragFloat()`(혹은 `DragInt()`)를 사용합니다.

```cpp
static float speed = 1.0f;
ImGui::DragFloat("이동 속도", &speed, 0.01f); // 세 번째 인자: 마우스 1픽셀당 값 변화량(속도)
```

`DragFloat`도 범위를 지정하는 오버로드를 제공합니다(`ImGui::DragFloat("이동 속도", &speed, 0.01f, 0.0f, 10.0f)`처럼 네 번째, 다섯 번째 인자로 최소/최대를 줄 수 있습니다). 슬라이더는 "핸들의 위치가 곧 값의 절대적인 크기를 시각적으로 나타내야 하는 경우"(예: 볼륨, 밝기)에 적합하고, 드래그는 "정확한 상한/하한보다는 세밀하게 조절하는 감각이 중요한 경우"(예: 3D 오브젝트의 위치, 회전각)에 더 자연스럽습니다.

## 4.5 텍스트 입력

`ImGui::InputText()`는 사용자로부터 문자열을 입력받는 위젯입니다. 다른 위젯과 달리, `std::string`이 아니라 **고정 크기의 `char` 배열**을 버퍼로 사용해야 한다는 점이 중요합니다.

```cpp
static char name_buffer[128] = "플레이어1";

ImGui::InputText("이름", name_buffer, IM_ARRAYSIZE(name_buffer));
```

세 번째 인자는 버퍼 전체의 바이트 크기입니다. `IM_ARRAYSIZE()` 매크로는 배열의 원소 개수를 계산해주는 ImGui 제공 헬퍼로, `sizeof(name_buffer) / sizeof(name_buffer[0])`와 같은 역할을 합니다. `InputText`는 사용자가 타이핑하는 동안 이 버퍼를 직접 수정하면서, 절대 지정된 크기를 넘어서 쓰지 않도록 내부적으로 길이를 확인합니다.

왜 `std::string&`을 직접 받지 않고 이런 방식을 택했을까요? Dear ImGui는 C++ 표준 라이브러리에 대한 의존을 최소화하도록 설계된 C 스타일에 가까운 API를 지향하며, 입력 도중 문자열이 늘어나거나 줄어들 때 메모리를 재할당하는 책임을 라이브러리가 지지 않도록 하기 위함입니다. 그래서 애플리케이션이 미리 충분한 크기의 버퍼를 마련해두고, ImGui는 그 버퍼 안에서만 문자를 채우고 지우는 역할을 맡습니다.

`std::string`을 편하게 사용하고 싶다면, `misc/cpp/imgui_stdlib.h`에서 제공하는 `ImGui::InputText(const char* label, std::string* str, ...)` 오버로드를 사용할 수도 있습니다. 이 헬퍼는 내부적으로 콜백을 통해 `std::string`의 버퍼를 필요에 따라 늘려줍니다. 다만 이 장에서는 기본 API의 동작 원리를 이해하는 것이 먼저이므로, 고정 크기 배열을 사용하는 기본형에 집중합니다.

숫자를 텍스트로 직접 입력받고 싶을 때는 `ImGui::InputFloat()`, `ImGui::InputInt()`를 사용합니다.

```cpp
static float threshold = 0.75f;
ImGui::InputFloat("임계값", &threshold, 0.01f, 0.1f, "%.3f");
// 세 번째, 네 번째 인자는 각각 +/- 버튼을 눌렀을 때의 증감 단위(step, step_fast)

static int retry_count = 3;
ImGui::InputInt("재시도 횟수", &retry_count);
```

`InputFloat`/`InputInt`는 슬라이더와 달리 범위 제한이 없고, 위젯 오른쪽에 작은 `-`/`+` 버튼이 함께 표시되어 클릭으로도 값을 조절할 수 있습니다. 정확한 값을 직접 타이핑해서 입력해야 하는 상황(좌표, 배율 등)에 적합합니다.

## 4.6 색상 선택

색상을 편집할 때는 `ImGui::ColorEdit3()`(RGB)와 `ImGui::ColorEdit4()`(RGBA)를 사용합니다. 둘 다 `float` 배열을 버퍼로 받습니다.

```cpp
static float clear_color[3] = { 0.1f, 0.2f, 0.3f };
ImGui::ColorEdit3("배경색", clear_color);

static float tint_color[4] = { 1.0f, 1.0f, 1.0f, 1.0f };
ImGui::ColorEdit4("틴트 색상", tint_color);
```

`ColorEdit3`는 `float[3]`, `ColorEdit4`는 `float[4]`를 기대하며, 각 성분은 0.0~1.0 범위의 실수로 표현됩니다. 위젯을 클릭하면 색상 값을 세밀하게 조절할 수 있는 팝업이 열리고, 위젯 자체는 평소에는 현재 색을 보여주는 작은 사각형과 함께 RGB(A) 값을 텍스트로 표시합니다. `ImVec4`를 사용하는 코드와 함께 쓸 때는 `&color.x`처럼 첫 번째 성분의 주소를 넘겨서 4개의 연속된 `float`로 취급하게 할 수도 있습니다.

```cpp
static ImVec4 tint = ImVec4(1.0f, 1.0f, 1.0f, 1.0f);
ImGui::ColorEdit4("틴트", (float*)&tint);
```

`ImVec4`는 `x, y, z, w`가 메모리상에 연속으로 배치되어 있으므로 이런 캐스팅이 안전합니다. 다만 가독성을 위해 배열을 직접 쓰는 편이 더 명확할 때가 많습니다. 스타일과 테마를 색상으로 커스터마이즈하는 방법은 12장에서 더 자세히 다룹니다.

## 4.7 콤보 박스

여러 선택지 중 하나를 드롭다운 형태로 고르게 하고 싶을 때는 콤보 박스를 사용합니다. 가장 간단한 방법은 `ImGui::Combo()`에 문자열 배열을 넘기는 것입니다.

```cpp
static int current_item = 0;
const char* items[] = { "낮음", "중간", "높음", "매우 높음" };

ImGui::Combo("품질", &current_item, items, IM_ARRAYSIZE(items));
```

`current_item`은 현재 선택된 항목의 인덱스를 담는 `int` 변수이고, 세 번째 인자로 넘긴 `items` 배열에서 사용자가 새로운 항목을 클릭하면 그 인덱스로 갱신됩니다. 항목의 목록이 컴파일 시점에 고정되어 있고 단순한 문자열 목록일 때는 이 형태로 충분합니다.

목록을 매 프레임 동적으로 구성해야 하거나, 각 항목을 단순 텍스트가 아니라 다른 위젯(아이콘, 색상 표시 등)과 함께 그리고 싶을 때는 `ImGui::BeginCombo()`/`ImGui::EndCombo()` 쌍을 직접 사용합니다.

```cpp
static std::string current_tag = "전체";
std::vector<std::string> tags = { "전체", "긴급", "진행중", "완료" };

if (ImGui::BeginCombo("태그", current_tag.c_str()))
{
    for (int i = 0; i < (int)tags.size(); i++)
    {
        bool is_selected = (current_tag == tags[i]);

        ImGui::PushID(i);
        if (ImGui::Selectable(tags[i].c_str(), is_selected))
        {
            current_tag = tags[i];
        }
        ImGui::PopID();

        // 처음 열렸을 때 현재 선택된 항목으로 스크롤 및 포커스를 맞춘다
        if (is_selected)
        {
            ImGui::SetItemDefaultFocus();
        }
    }
    ImGui::EndCombo();
}
```

`BeginCombo()`는 콤보 박스를 열고 닫는 상태를 관리하며, 드롭다운이 열려 있을 때만 `true`를 반환합니다. `true`인 동안 내부에서 `ImGui::Selectable()`을 이용해 각 항목을 원하는 방식대로 자유롭게 그릴 수 있습니다. 항목이 문자열이 아니라 동적으로 생성되는 리스트(예: 파일 목록, 태그 목록)일 때는 `Combo()`의 `const char**` 형태보다 `BeginCombo`/`EndCombo` 쌍을 사용하는 편이 훨씬 유연합니다. `Selectable`을 포함해 리스트 형태의 위젯은 7장에서 좀 더 깊이 다룹니다.

## 4.8 실전 예제: 여러 위젯을 조합한 설정 패널

지금까지 배운 위젯들을 하나로 모아, 체크박스로 기능을 켜고, 슬라이더로 값을 조절하고, 색상 선택기로 배경색을 바꾸는 작은 설정 패널을 만들어보겠습니다.

```cpp
void ShowSettingsPanel()
{
    static bool enable_animation = true;
    static float animation_speed = 1.0f;
    static int quality = 1; // 0: 낮음, 1: 중간, 2: 높음
    static float clear_color[3] = { 0.10f, 0.10f, 0.12f };
    static char profile_name[64] = "기본 프로필";

    ImGui::Begin("설정");

    ImGui::Text("프로필 이름");
    ImGui::InputText("##profile_name", profile_name, IM_ARRAYSIZE(profile_name));

    ImGui::Separator();

    ImGui::Checkbox("애니메이션 사용", &enable_animation);

    // 애니메이션이 꺼져 있으면 속도 슬라이더는 의미가 없으므로 비활성화한다
    if (!enable_animation)
    {
        ImGui::BeginDisabled();
    }
    ImGui::SliderFloat("애니메이션 속도", &animation_speed, 0.1f, 3.0f, "%.2fx");
    if (!enable_animation)
    {
        ImGui::EndDisabled();
    }

    ImGui::Separator();

    ImGui::Text("렌더링 품질");
    ImGui::RadioButton("낮음", &quality, 0);
    ImGui::SameLine();
    ImGui::RadioButton("중간", &quality, 1);
    ImGui::SameLine();
    ImGui::RadioButton("높음", &quality, 2);

    ImGui::Separator();

    ImGui::ColorEdit3("배경색", clear_color);

    ImGui::Separator();

    if (ImGui::Button("기본값으로 초기화"))
    {
        enable_animation = true;
        animation_speed = 1.0f;
        quality = 1;
        clear_color[0] = 0.10f; clear_color[1] = 0.10f; clear_color[2] = 0.12f;
    }

    ImGui::End();
}
```

이 함수 하나에 이 장에서 배운 요소가 대부분 들어 있습니다. `InputText`는 라벨을 화면에 보이지 않게 하기 위해 `##profile_name`을 사용했고(라벨은 바로 위 `Text`로 대신 표시), `Checkbox`의 현재 값을 `if`로 검사해서 슬라이더를 비활성화할지 결정하며(`ImGui::BeginDisabled()`/`ImGui::EndDisabled()`는 그 사이의 위젯을 회색으로 흐리게 하고 입력을 막아주는 함수입니다), 같은 `quality` 변수를 공유하는 세 개의 `RadioButton`으로 상호 배타적인 선택지를 만들고, `ColorEdit3`로 배경색을, 마지막으로 `Button`으로 모든 값을 초기화합니다.

이 코드에서 특히 눈여겨볼 부분은 `RunApplication()` 같은 메인 루프에서 `ShowSettingsPanel()`을 매 프레임 호출하기만 하면, 함수 안의 `static` 변수들이 프레임 사이의 값을 그대로 유지해준다는 점입니다. 이는 3장에서 다룬 원칙, 즉 "ImGui는 데이터를 소유하지 않고 애플리케이션이 소유한 변수를 읽고 쓸 뿐"이라는 사실을 보여주는 구체적인 예입니다. 다만 실무에서는 이런 설정 값들을 함수 지역 `static` 변수보다는 별도의 구조체나 클래스 멤버로 모아서 관리하는 경우가 많은데, 그 이유와 구체적인 패턴은 14장 "상태 관리 패턴"에서 다룹니다.

또한 여러 개의 위젯을 세로로 쌓고, `Separator()`로 구획을 나누고, `SameLine()`으로 가로 배치를 만드는 방식은 5장 "창과 레이아웃"에서 본격적으로 다룰 레이아웃 시스템의 맛보기이기도 합니다.

## 요약

- `ImGui::Text()`는 `printf` 스타일 서식을 지원하며, 사용자 입력을 그대로 서식 문자열로 넘기지 않도록 주의해야 합니다. 색을 입힐 때는 `TextColored()`, 자동 줄바꿈이 필요할 때는 `TextWrapped()`를 사용합니다.
- `Button()`은 클릭 이벤트를, `SmallButton()`은 더 작은 형태의 같은 동작을 제공합니다.
- `Checkbox()`는 `bool*`을, `RadioButton()`은 같은 `int*` 변수를 여러 버튼이 공유하는 방식으로 상호 배타적인 선택을 구현합니다.
- 슬라이더(`SliderFloat`/`SliderInt`)는 정해진 범위 안에서, 드래그(`DragFloat`/`DragInt`)는 범위에 덜 얽매인 채로 마우스 이동량에 비례해 값을 조절합니다.
- `InputText()`는 `std::string`이 아니라 고정 크기 `char` 버퍼와 `IM_ARRAYSIZE()`로 그 크기를 함께 넘겨야 합니다. `InputFloat`/`InputInt`는 슬라이더와 달리 정확한 값을 직접 타이핑해 입력하기에 적합합니다.
- `ColorEdit3`/`ColorEdit4`는 각각 `float[3]`, `float[4]` 버퍼로 색상을 편집합니다.
- 항목이 정적인 문자열 배열이면 `Combo()`로 간단히, 동적이거나 항목마다 커스텀 렌더링이 필요하면 `BeginCombo()`/`EndCombo()`와 `Selectable()`을 조합해서 처리합니다.
- 이 모든 위젯은 하나의 함수 안에서 자유롭게 조합할 수 있으며, `static` 변수(또는 클래스 멤버, 전역 변수)에 값을 담아두는 것만으로 프레임 간 상태 유지가 자연스럽게 이루어집니다.

## 연습문제

1. 사용자가 입력한 문자열을 `ImGui::Text()`로 그대로 출력하려고 합니다. `ImGui::Text(input.c_str())`처럼 작성하면 안 되는 이유를 설명하고, 안전한 코드로 고쳐보세요.
2. `SliderFloat`와 `DragFloat`는 둘 다 `float` 값을 조절하는 위젯입니다. 각각 어떤 상황에 더 적합한지, 이 장에서 제시한 기준을 근거로 설명하세요.
3. `char buffer[32]`를 사용하는 `InputText`가 있다고 할 때, 세 번째 인자에 `32` 대신 실수로 `sizeof(buffer) * 2`처럼 실제 버퍼 크기보다 큰 값을 넘기면 어떤 문제가 발생할 수 있는지 설명하세요.
4. 세 개의 `enum class`(예: `Easy`, `Normal`, `Hard`) 난이도 값 중 하나를 고르는 UI를, (a) `RadioButton` 세 개로 구현하는 버전과 (b) `BeginCombo`/`EndCombo`로 구현하는 버전 두 가지로 각각 작성해보세요.
5. 4.8절의 `ShowSettingsPanel()` 함수에 "최대 파티클 수"를 조절하는 `SliderInt` 또는 `DragInt`를 추가하고, `enable_animation`이 꺼져 있을 때는 이 값도 함께 비활성화되도록 코드를 확장해보세요.
