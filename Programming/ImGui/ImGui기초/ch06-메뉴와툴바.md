# 6장. 메뉴와 툴바

[◀ 이전: 5장. 창과 레이아웃](ch05-창과레이아웃.md) | [📖 목차](00-목차.md) | [다음: 7장. 트리와 리스트 ▶](ch07-트리와리스트.md)


거의 모든 데스크톱 애플리케이션은 화면 맨 위에 "파일", "편집", "보기" 같은 메뉴가 늘어선 메뉴 바를 가지고 있습니다. 그 아래에는 자주 쓰는 기능을 아이콘 버튼으로 모아둔 툴바가 이어지는 경우도 많습니다. 이번 장에서는 ImGui로 이런 익숙한 UI 구성 요소를 만드는 방법을 다룹니다.

먼저 짚어둘 것이 있습니다. ImGui에는 "툴바"를 위한 전용 API가 따로 존재하지 않습니다. 메뉴 바는 `BeginMainMenuBar()`, `BeginMenu()`, `MenuItem()` 같은 이름이 붙은 명확한 API가 있지만, 툴바는 그저 작은 버튼들을 `SameLine()`으로 나란히 붙여놓은 하나의 창일 뿐입니다. 이 장의 뒷부분에서 그 이유와 구현 방법을 자세히 살펴보겠습니다.

## 메인 메뉴 바: BeginMainMenuBar

애플리케이션 전체를 아우르는 메뉴 바, 즉 화면 최상단에 고정되어 항상 보이는 메뉴 바를 만들 때는 `ImGui::BeginMainMenuBar()`를 사용합니다. 이 함수는 `Begin()`/`End()`처럼 반드시 `ImGui::EndMainMenuBar()`와 짝을 이루며, 다른 창들과 별개로 화면 전체 너비를 차지하는 특수한 바를 만들어줍니다.

```cpp
if (ImGui::BeginMainMenuBar())
{
    if (ImGui::BeginMenu("파일"))
    {
        ImGui::MenuItem("새로 만들기");
        ImGui::MenuItem("열기");
        ImGui::EndMenu();
    }

    if (ImGui::BeginMenu("편집"))
    {
        ImGui::MenuItem("실행 취소");
        ImGui::MenuItem("다시 실행");
        ImGui::EndMenu();
    }

    ImGui::EndMainMenuBar();
}
```

`Begin()` 계열 함수들과 마찬가지로 `BeginMainMenuBar()`도 `bool`을 반환합니다. 반환값이 `false`이면(예: 메뉴 바가 화면에 그려지지 않는 상황) 내부 로직 실행을 건너뛰어도 되지만, `EndMainMenuBar()`는 `BeginMainMenuBar()`가 `true`를 반환했을 때만 호출해야 한다는 점에 주의하세요. 이는 `BeginMenu()`/`EndMenu()`에도 그대로 적용됩니다. 반면 `Begin()`/`End()`나 `BeginChild()`/`EndChild()`는 반환값과 무관하게 항상 짝을 맞춰 호출해야 했던 것과는 다른 규칙이므로 헷갈리지 않도록 주의하세요.

메인 메뉴 바는 프로그램 전체에서 보통 한 번만 호출하며, 화면 최상단에 배치되어 다른 모든 창의 콘텐츠 영역 계산에도 영향을 줍니다(메뉴 바가 차지하는 높이만큼 나머지 화면 영역이 줄어듭니다).

## 창 안의 메뉴 바: BeginMenuBar

메인 메뉴 바가 애플리케이션 전체에 하나만 존재하는 것과 달리, 특정 창 안에 그 창 전용 메뉴 바를 넣고 싶을 때는 `ImGui::BeginMenuBar()`를 사용합니다. 이 함수를 쓰려면 반드시 해당 창을 `Begin()`으로 열 때 `ImGuiWindowFlags_MenuBar` 플래그를 지정해야 합니다. 이 플래그가 없으면 창에 메뉴 바가 들어갈 공간 자체가 확보되지 않습니다.

```cpp
ImGui::Begin("텍스트 에디터", nullptr, ImGuiWindowFlags_MenuBar);

if (ImGui::BeginMenuBar())
{
    if (ImGui::BeginMenu("파일"))
    {
        ImGui::MenuItem("저장");
        ImGui::EndMenu();
    }
    ImGui::EndMenuBar();
}

ImGui::Text("여기에 에디터 내용이 표시됩니다.");

ImGui::End();
```

`BeginMenuBar()` 역시 `bool`을 반환하며, `true`일 때만 `EndMenuBar()`를 호출하는 것이 규칙입니다. 이런 창 단위 메뉴 바는 MDI(다중 문서 인터페이스) 스타일로 여러 문서 창을 동시에 띄우는 애플리케이션에서, 각 문서 창마다 독립적인 메뉴를 두고 싶을 때 특히 유용합니다.

## 메뉴와 메뉴 아이템: BeginMenu와 MenuItem

`BeginMainMenuBar()`나 `BeginMenuBar()` 안에서는 `ImGui::BeginMenu()`로 드롭다운 메뉴를 열고, 그 안에 `ImGui::MenuItem()`으로 실제 클릭 가능한 항목을 채워 넣습니다.

```cpp
if (ImGui::BeginMenu("파일"))
{
    if (ImGui::MenuItem("열기", "Ctrl+O"))
    {
        // 파일 열기 처리
    }
    if (ImGui::MenuItem("저장", "Ctrl+S"))
    {
        // 파일 저장 처리
    }
    ImGui::EndMenu();
}
```

`MenuItem()`의 전체 시그니처는 다음과 같습니다.

```cpp
bool ImGui::MenuItem(const char* label, const char* shortcut = nullptr,
                      bool selected = false, bool enabled = true);
```

- `label`: 메뉴에 표시할 텍스트입니다.
- `shortcut`: 오른쪽에 옅게 표시되는 단축키 문자열입니다. 여기서 주의할 점은, 이 문자열은 **순수하게 시각적인 표시일 뿐**이라는 것입니다. `"Ctrl+O"`라고 적어도 ImGui가 실제로 Ctrl+O 키 입력을 감지해서 이 메뉴 아이템을 자동으로 실행해주지 않습니다. 실제 단축키 동작을 원한다면 13장에서 다룰 `ImGui::IsKeyPressed()` 등을 이용해 직접 키 입력을 검사하고, 그 결과에 따라 동일한 함수를 호출하도록 별도로 구현해야 합니다.
- `selected`: `true`로 주면 항목 왼쪽에 체크 표시가 나타납니다. 아래에서 설명할 체크 가능한 메뉴 아이템 패턴에 사용됩니다.
- `enabled`: `false`로 주면 항목이 흐리게 표시되고 클릭할 수 없게 됩니다. 조건에 따라 특정 메뉴 항목을 비활성화하고 싶을 때 사용합니다.

`MenuItem()`은 사용자가 그 항목을 클릭한 프레임에 한해 `true`를 반환합니다. 따라서 `if (ImGui::MenuItem("열기")) { ... }` 형태로 클릭 처리를 그 자리에서 바로 작성하는 것이 일반적인 패턴입니다.

### 체크 가능한 메뉴 아이템

`MenuItem()`은 `bool*`을 받는 오버로드도 제공합니다. 이 오버로드를 쓰면 클릭할 때마다 가리키는 변수의 값을 자동으로 반전시키고, 그 값에 따라 체크 표시를 그려줍니다.

```cpp
bool ImGui::MenuItem(const char* label, const char* shortcut,
                      bool* p_selected, bool enabled = true);
```

```cpp
static bool show_toolbar = true;
static bool show_status_bar = true;

if (ImGui::BeginMenu("보기"))
{
    ImGui::MenuItem("툴바 표시", nullptr, &show_toolbar);
    ImGui::MenuItem("상태 표시줄 표시", nullptr, &show_status_bar);
    ImGui::EndMenu();
}
```

이 코드는 "툴바 표시" 항목을 클릭할 때마다 `show_toolbar`가 `true`와 `false` 사이를 오가며, 현재 값에 따라 체크 표시가 자동으로 켜지거나 꺼집니다. 다른 곳에서 `if (show_toolbar) { /* 툴바 그리기 */ }`처럼 이 변수를 검사하기만 하면, 메뉴를 통해 UI 요소의 표시 여부를 토글하는 전형적인 패턴이 완성됩니다. 5장에서 살펴본, 창을 여닫는 `bool` 변수 패턴과 정확히 같은 발상입니다.

### 메뉴는 중첩할 수 있습니다

`BeginMenu()` 안에서 다시 `BeginMenu()`를 호출하면 하위 메뉴(submenu)를 만들 수 있습니다.

```cpp
if (ImGui::BeginMenu("파일"))
{
    ImGui::MenuItem("열기");

    if (ImGui::BeginMenu("최근 파일"))
    {
        ImGui::MenuItem("report.txt");
        ImGui::MenuItem("notes.md");
        ImGui::EndMenu();
    }

    ImGui::EndMenu();
}
```

"최근 파일" 위에 마우스를 올리면 오른쪽으로 하위 메뉴가 펼쳐집니다. 중첩 깊이에 특별한 제한은 없지만, 사용자 경험을 고려하면 2~3단계를 넘지 않는 것이 좋습니다.

## 툴바 흉내내기: 전용 API는 없다

이제 툴바 이야기로 넘어가겠습니다. Windows의 오래된 데스크톱 프로그램이나 다양한 IDE에서 흔히 보던 "아이콘 버튼이 가로로 늘어선 얇은 막대"를 ImGui에서 만들고 싶다면, `BeginToolbar()` 같은 함수를 찾게 될 수 있습니다. 하지만 그런 함수는 존재하지 않습니다.

ImGui의 철학에서 툴바는 특별한 위젯이 아니라, 그저 **일반적인 창(혹은 메인 메뉴 바 바로 아래에 위치한 얇은 창) 안에 작은 버튼들을 SameLine()으로 나란히 배치한 것**에 지나지 않습니다. 다음은 흔히 쓰이는 패턴입니다.

```cpp
ImGui::Begin("툴바", nullptr,
              ImGuiWindowFlags_NoTitleBar |
              ImGuiWindowFlags_NoResize |
              ImGuiWindowFlags_NoMove |
              ImGuiWindowFlags_NoScrollbar);

if (ImGui::Button("새로 만들기")) { /* ... */ }
ImGui::SameLine();
if (ImGui::Button("열기")) { /* ... */ }
ImGui::SameLine();
if (ImGui::Button("저장")) { /* ... */ }
ImGui::SameLine();
ImGui::Separator(); // 시각적 구분을 위한 세로 여백 대용
ImGui::SameLine();
if (ImGui::Button("실행")) { /* ... */ }

ImGui::End();
```

제목 표시줄, 크기 조절, 이동, 스크롤바를 모두 꺼서 마치 화면에 고정된 하나의 띠처럼 보이게 만들었습니다. 버튼 사이에 `Separator()`를 넣어 그룹을 나누는 것도 5장에서 배운 것과 동일한 방식입니다. 실제로 툴바를 만들 때 새로 배워야 할 API는 하나도 없습니다. 5장의 `SameLine()`, `Separator()`와 4장의 `Button()`을 조합하는 것이 전부입니다.

아이콘을 버튼에 넣고 싶다면 텍스트 대신 이미지를 그리는 `ImGui::ImageButton()`을 사용하거나, 유니코드 아이콘 폰트(예: Font Awesome 계열)를 붙여 텍스트처럼 아이콘 문자를 출력하는 방법을 씁니다. 아이콘 폰트를 불러오는 절차는 폰트와 텍스처 관리를 다루는 범위이므로 이 책에서는 다루지 않지만, 버튼을 나란히 배치하는 레이아웃 원리 자체는 텍스트 버튼과 완전히 동일합니다.

메인 메뉴 바 바로 아래에 툴바를 붙이고 싶다면, 메인 메뉴 바가 차지한 높이를 고려해 툴바 창의 위치를 계산해야 합니다. 다음처럼 `GetFrameHeight()`를 활용하면 메뉴 바 바로 아래에 위치를 맞출 수 있습니다.

```cpp
float menu_bar_height = ImGui::GetFrameHeight();
ImGui::SetNextWindowPos(ImVec2(0, menu_bar_height));
ImGui::SetNextWindowSize(ImVec2(ImGui::GetIO().DisplaySize.x, 40));

ImGui::Begin("MainToolbar", nullptr,
              ImGuiWindowFlags_NoTitleBar |
              ImGuiWindowFlags_NoResize |
              ImGuiWindowFlags_NoMove |
              ImGuiWindowFlags_NoScrollbar |
              ImGuiWindowFlags_NoSavedSettings);

if (ImGui::Button("New")) { /* ... */ }
ImGui::SameLine();
if (ImGui::Button("Open")) { /* ... */ }

ImGui::End();
```

`ImGuiWindowFlags_NoSavedSettings`를 추가하면 이 창의 위치·크기 정보가 `imgui.ini`에 저장되지 않습니다. 어차피 매 프레임 `SetNextWindowPos()`/`SetNextWindowSize()`로 위치를 강제로 고정하고 있으므로, 저장된 값이 남아있어도 의미가 없을뿐더러 불필요한 파일 기록을 줄일 수 있습니다.

## 실전 예제: 파일 메뉴와 보기 메뉴를 가진 메인 메뉴 바

지금까지 배운 내용을 종합해, 파일 메뉴(열기/저장/종료)와 보기 메뉴(창 표시 토글)를 가진 메인 메뉴 바를 완성해 보겠습니다.

```cpp
#include "imgui.h"

// 메뉴에서 토글할 창들의 표시 상태
static bool show_inventory_window = true;
static bool show_log_window = false;
static bool app_should_quit = false;

void RenderMenuBar()
{
    if (ImGui::BeginMainMenuBar())
    {
        if (ImGui::BeginMenu("파일"))
        {
            if (ImGui::MenuItem("열기", "Ctrl+O"))
            {
                // 파일 열기 다이얼로그 호출 (9장에서 다룰 내용)
            }
            if (ImGui::MenuItem("저장", "Ctrl+S"))
            {
                // 현재 문서 저장
            }

            ImGui::Separator();

            if (ImGui::MenuItem("종료", "Alt+F4"))
            {
                app_should_quit = true;
            }

            ImGui::EndMenu();
        }

        if (ImGui::BeginMenu("보기"))
        {
            ImGui::MenuItem("인벤토리 창", nullptr, &show_inventory_window);
            ImGui::MenuItem("로그 창", nullptr, &show_log_window);
            ImGui::EndMenu();
        }

        ImGui::EndMainMenuBar();
    }
}

void RenderUI()
{
    RenderMenuBar();

    if (show_inventory_window)
    {
        ImGui::Begin("인벤토리", &show_inventory_window);
        ImGui::Text("아이템 12개 보유 중");
        ImGui::End();
    }

    if (show_log_window)
    {
        ImGui::Begin("로그", &show_log_window);
        ImGui::Text("[정보] 애플리케이션이 시작되었습니다.");
        ImGui::End();
    }
}
```

이 예제는 메뉴 바 하나로 여러 흐름을 함께 보여줍니다. "파일" 메뉴의 "열기"와 "저장"은 클릭 시 즉시 어떤 동작을 수행하는 일반적인 `MenuItem()`이고, "종료"는 그 결과를 플래그(`app_should_quit`)에 담아 애플리케이션의 메인 루프 쪽에서 실제 종료 처리를 하도록 위임합니다. "보기" 메뉴의 두 항목은 `bool*`을 넘기는 오버로드를 사용해 각 창의 표시 여부를 직접 토글합니다.

주목할 부분은 "인벤토리" 창과 "로그" 창을 여닫는 방법이 두 가지라는 점입니다. 메뉴의 체크 항목을 클릭해서 끌 수도 있고, 각 창 자체에 `&show_inventory_window`를 넘겨두었기 때문에 창의 닫기 버튼(X)을 눌러서 끌 수도 있습니다. 두 경로 모두 같은 `bool` 변수를 공유하므로 상태가 항상 일치합니다. 이렇게 하나의 상태 변수를 메뉴와 창이 함께 참조하게 만드는 패턴은 ImGui 애플리케이션 전반에서 매우 자주 쓰이며, 14장에서 상태 관리 패턴을 더 체계적으로 다룰 때 다시 등장합니다.

## 요약

- 애플리케이션 전체에 걸친 상단 메뉴 바는 `ImGui::BeginMainMenuBar()`/`ImGui::EndMainMenuBar()`로 만듭니다.
- 특정 창 안에 메뉴 바를 넣으려면 그 창을 `ImGuiWindowFlags_MenuBar` 플래그로 열고, `ImGui::BeginMenuBar()`/`ImGui::EndMenuBar()`를 사용합니다.
- 드롭다운 메뉴는 `ImGui::BeginMenu()`/`ImGui::EndMenu()`로 열고, 그 안에 `ImGui::MenuItem()`으로 실제 항목을 채웁니다. 단축키 문자열은 표시 전용이며 실제 키 입력 처리는 별도로 구현해야 합니다.
- `ImGui::MenuItem(label, shortcut, &bool_변수)` 형태를 쓰면 클릭할 때마다 변수를 토글하고 체크 표시를 자동으로 그려주는, 창 표시 토글에 적합한 패턴을 만들 수 있습니다.
- ImGui에는 전용 "툴바" API가 없습니다. 툴바는 제목 표시줄과 크기 조절을 끈 얇은 창 안에 작은 버튼들을 `SameLine()`으로 나란히 배치한 관용적 구성일 뿐입니다.
- 메뉴의 체크 항목과 창의 닫기 버튼이 같은 `bool` 변수를 공유하게 하면, 두 경로 어느 쪽으로 조작해도 상태가 일관되게 유지됩니다.

2. `ImGuiWindowFlags_MenuBar` 플래그 없이 어떤 창 안에서 `BeginMenuBar()`를 호출하면 어떤 일이 일어나는지 직접 확인해 보세요.
3. `MenuItem()`의 `enabled` 매개변수를 이용해, 어떤 `bool` 변수(예: `has_unsaved_changes`)가 `false`일 때는 "저장" 메뉴 항목이 비활성화되도록 만들어 보세요.
4. "보기" 메뉴에 세 개의 체크 가능한 메뉴 아이템(툴바 표시, 상태 표시줄 표시, 미니맵 표시)을 추가하고, 각각의 상태에 따라 해당 UI 요소가 실제로 나타나거나 사라지는지 확인해 보세요.
5. 제목 표시줄 없는 창에 5개의 버튼을 `SameLine()`으로 나란히 배치해 툴바를 만들고, `ImGui::SetNextWindowPos()`로 메인 메뉴 바 바로 아래에 고정해 보세요.
