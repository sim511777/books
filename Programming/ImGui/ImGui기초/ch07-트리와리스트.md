# 7장. 트리와 리스트

[◀ 이전: 6장. 메뉴와 툴바](ch06-메뉴와툴바.md) | [📖 목차](00-목차.md) | [다음: 8장. 테이블 ▶](ch08-테이블.md)


지금까지 살펴본 위젯들은 대부분 하나의 값을 표시하거나 편집하는 데 쓰였습니다. 하지만 실제 애플리케이션에서는 파일 시스템처럼 계층적인 데이터를 보여주거나, 수십 개의 항목 중 하나를 선택하게 만들어야 하는 경우가 훨씬 많습니다. 씬 그래프의 오브젝트 목록, 프로젝트의 폴더 구조, 로그 뷰어의 항목 리스트 같은 것들이 대표적인 예입니다.

이번 장에서는 계층 구조를 표현하는 트리 노드와 접이식 헤더, 그리고 여러 항목 중 하나 또는 여럿을 선택하게 해주는 리스트 박스와 `Selectable`을 다룹니다. 이 위젯들은 공통적으로 "반복문 안에서 여러 개를 그린다"는 특징이 있어서, 3장에서 배운 ID 시스템이 왜 필요한지 다시 한번 뼈저리게 느끼게 되는 지점이기도 합니다.

## 트리 노드로 계층 구조 표현하기

`ImGui::TreeNode()`는 클릭하면 펼쳐지고 접히는 노드를 만듭니다. 가장 단순한 형태는 다음과 같습니다.

```cpp
if (ImGui::TreeNode("월드"))
{
    ImGui::Text("여기는 펼쳐졌을 때만 보입니다.");
    ImGui::TreePop();
}
```

`TreeNode()`가 `true`를 반환하면 노드가 펼쳐진 상태라는 뜻이고, 이때 반드시 대응하는 `ImGui::TreePop()`을 호출해야 합니다. `TreeNode()`가 `false`를 반환하면(즉 접혀 있으면) 내부 블록이 실행되지 않으므로 `TreePop()`도 호출되지 않는데, 이게 정상적인 동작입니다. `if` 문 없이 `TreePop()`을 무조건 호출해버리면 트리 깊이 카운터가 어긋나서 들여쓰기가 이상해지거나 다음 프레임에서 어설션에 걸릴 수 있으니 주의하세요.

### 중첩된 트리: 파일 탐색기 스타일 예제

트리 노드의 진짜 장점은 중첩이 자유롭다는 것입니다. `TreeNode` 안에서 또 다른 `TreeNode`를 열면 자연스럽게 계층 구조가 만들어집니다. 간단한 파일 탐색기를 흉내 내보겠습니다.

```cpp
struct FileNode
{
    std::string name;
    bool isFolder;
    std::vector<FileNode> children;
};

void DrawFileNode(const FileNode& node)
{
    if (node.isFolder)
    {
        // 폴더는 TreeNode로, 펼쳐졌을 때만 자식을 그린다.
        if (ImGui::TreeNode(node.name.c_str()))
        {
            for (const FileNode& child : node.children)
                DrawFileNode(child);
            ImGui::TreePop();
        }
    }
    else
    {
        // 파일은 펼칠 내용이 없으므로 리프 노드로 표시한다.
        ImGuiTreeNodeFlags leafFlags =
            ImGuiTreeNodeFlags_Leaf | ImGuiTreeNodeFlags_NoTreePushOnOpen |
            ImGuiTreeNodeFlags_Bullet;
        ImGui::TreeNodeEx(node.name.c_str(), leafFlags);
    }
}
```

여기서 파일(리프 노드)은 `TreeNode` 대신 더 세밀한 제어가 가능한 `ImGui::TreeNodeEx()`를 사용했습니다. `ImGuiTreeNodeFlags_Leaf`는 화살표 아이콘을 없애 "더 펼칠 게 없다"는 것을 시각적으로 알려주고, `ImGuiTreeNodeFlags_NoTreePushOnOpen`은 이 노드가 클릭되어도 트리 깊이를 증가시키지 않도록 해서 `TreePop()`을 호출할 필요가 없게 만듭니다. `ImGuiTreeNodeFlags_Bullet`은 화살표 대신 작은 점 아이콘을 표시해 리프라는 느낌을 더해줍니다.

이 함수는 재귀적으로 호출되므로, 루트 노드부터 시작하면 폴더 안에 폴더가 있는 깊은 구조도 그대로 그려집니다.

```cpp
if (ImGui::CollapsingHeader("탐색기", ImGuiTreeNodeFlags_DefaultOpen))
{
    DrawFileNode(rootNode);
}
```

자주 쓰이는 `TreeNodeEx` 플래그 몇 가지를 정리하면 다음과 같습니다.

| 플래그 | 의미 |
|---|---|
| `ImGuiTreeNodeFlags_DefaultOpen` | 처음 그려질 때 펼쳐진 상태로 시작 |
| `ImGuiTreeNodeFlags_Selected` | 선택된 것처럼 배경을 강조 표시 |
| `ImGuiTreeNodeFlags_Leaf` | 화살표 없이 리프 노드로 표시 |
| `ImGuiTreeNodeFlags_OpenOnArrow` | 화살표 아이콘 부분만 클릭해야 펼쳐지도록 제한 |
| `ImGuiTreeNodeFlags_SpanAvailWidth` | 클릭 가능 영역을 창 너비 전체로 확장 |

`ImGuiTreeNodeFlags_OpenOnArrow`는 특히 유용한데, 이 플래그가 없으면 노드 라벨을 클릭했을 때 트리가 펼쳐지는 것과 동시에 "선택" 동작(예: 파일을 클릭해서 여는 것)이 겹쳐 버릴 수 있습니다. 화살표 클릭과 라벨 클릭의 역할을 분리하면 이런 충돌을 피할 수 있습니다.

## 접이식 헤더: TreeNode의 사촌

`ImGui::CollapsingHeader()`는 `TreeNode`와 시각적으로 비슷하지만 용도가 조금 다릅니다. 여러 개의 설정 섹션을 접었다 펼쳤다 하면서 보여줄 때 주로 사용하며, 5장에서 봤던 것처럼 헤더 하나가 독립된 "패널"처럼 동작합니다.

```cpp
if (ImGui::CollapsingHeader("그래픽 설정"))
{
    ImGui::Checkbox("수직 동기화", &vsync);
    ImGui::SliderInt("안티에일리어싱", &msaa, 0, 8);
}

if (ImGui::CollapsingHeader("오디오 설정"))
{
    ImGui::SliderFloat("볼륨", &volume, 0.0f, 1.0f);
}
```

`TreeNode`와 가장 큰 차이는 **`TreePop()`이 필요 없다**는 점입니다. `CollapsingHeader`는 내부적으로 트리 깊이를 증가시키지 않으므로, `if` 블록이 끝나면 그걸로 끝입니다. 이 차이를 헷갈려서 `CollapsingHeader` 뒤에 `TreePop()`을 호출하면 트리 스택이 어긋나 버리니 주의하세요.

`CollapsingHeader`도 `ImGuiTreeNodeFlags_DefaultOpen`을 받아들여 처음부터 펼쳐진 상태로 시작할 수 있고, 두 번째 인자로 `bool* p_visible`을 넘기면 헤더 오른쪽에 닫기(x) 버튼이 생겨 그 섹션 자체를 완전히 숨기는 용도로도 쓸 수 있습니다.

```cpp
static bool showAdvanced = true;
if (showAdvanced &&
    ImGui::CollapsingHeader("고급 설정", &showAdvanced))
{
    ImGui::Text("고급 사용자를 위한 옵션입니다.");
}
```

정리하면, "계층 구조를 표현하고 그 안에 또 다른 트리 노드가 들어갈 수도 있다"면 `TreeNode`를, "여러 섹션을 나란히 접었다 펼쳤다 하는 정도"라면 `CollapsingHeader`를 선택하는 것이 자연스럽습니다.

## 리스트 박스와 Selectable

여러 항목 중 하나를 선택하게 만드는 가장 기본적인 방법은 `ImGui::BeginListBox()` / `ImGui::EndListBox()` 쌍으로 스크롤 가능한 영역을 만들고, 그 안을 `ImGui::Selectable()`로 채우는 것입니다.

```cpp
static int selectedIndex = -1;
const char* items[] = { "사과", "바나나", "체리", "포도", "딸기" };

if (ImGui::BeginListBox("과일 목록"))
{
    for (int i = 0; i < IM_ARRAYSIZE(items); i++)
    {
        bool isSelected = (selectedIndex == i);
        if (ImGui::Selectable(items[i], isSelected))
            selectedIndex = i;

        // 리스트가 열릴 때 현재 선택 항목이 보이도록 스크롤 위치를 맞춘다.
        if (isSelected)
            ImGui::SetItemDefaultFocus();
    }
    ImGui::EndListBox();
}
```

이 코드가 바로 ImGui에서 "선택 상태를 관리하는" 관용적인 패턴입니다. 핵심은 다음 세 가지입니다.

1. **선택된 인덱스는 애플리케이션(여러분의 코드) 쪽에서 변수로 들고 있습니다.** ImGui는 위젯 자체의 그리기와 클릭 감지만 담당할 뿐, "지금 몇 번이 선택되어 있는가"라는 상태를 기억해주지 않습니다. 이는 3장에서 배운 즉시 모드의 철학과 정확히 일치합니다.
2. **`Selectable()`의 두 번째 인자는 "지금 이 항목이 선택된 상태로 보여야 하는가"를 알려주는 입력값입니다.** 이 값이 `true`면 배경이 강조되어 그려집니다.
3. **`Selectable()`이 `true`를 반환하면 "이번 프레임에 클릭되었다"는 뜻이므로**, 그 자리에서 `selectedIndex`를 갱신합니다. 다음 프레임에는 갱신된 `selectedIndex`가 다시 2번 단계에 입력으로 들어가면서 강조 표시가 유지됩니다.

이 "현재 값을 읽어서 그리고, 클릭되면 그 자리에서 애플리케이션 상태를 갱신한다"는 흐름은 4장에서 봤던 체크박스나 슬라이더와 본질적으로 같은 패턴입니다. `Selectable`은 결국 "값이 bool 하나뿐인 위젯"이라고 생각하면 이해하기 쉽습니다.

### BeginListBox의 크기 지정

`BeginListBox()`는 두 번째 인자로 `ImVec2` 크기를 받을 수 있습니다.

```cpp
if (ImGui::BeginListBox("과일 목록", ImVec2(200, 150)))
{
    // ...
    ImGui::EndListBox();
}
```

크기를 0으로 두면(기본값) ImGui가 항목 개수와 사용 가능한 영역을 고려해 적당한 높이를 자동으로 계산합니다. 높이를 음수로 주면 "창 하단에서 얼마나 떨어진 위치까지"라는 의미가 되어, 5장에서 다룬 `-FLT_MIN` 관용구처럼 남은 공간을 꽉 채우는 레이아웃을 만들 수도 있습니다.

### Selectable을 직접 나열하기

리스트 박스 틀 없이 `Selectable`만 죽 늘어놓는 것도 흔한 패턴입니다. 사이드바 메뉴나 탭 목록처럼 보이게 하고 싶을 때 유용합니다.

```cpp
static int currentPage = 0;
const char* pages[] = { "홈", "프로필", "설정", "정보" };

for (int i = 0; i < IM_ARRAYSIZE(pages); i++)
{
    if (ImGui::Selectable(pages[i], currentPage == i))
        currentPage = i;
}
```

`Selectable`은 두 번째 인자로 플래그도 받을 수 있는데, `ImGuiSelectableFlags_AllowDoubleClick`을 주면 더블클릭을 별도로 감지할 수 있고, `ImGuiSelectableFlags_SpanAllColumns`는 8장에서 배울 테이블 안에서 한 행 전체를 선택 영역으로 확장할 때 사용합니다.

## 반복문 속의 ID 문제: 왜 다시 중요해진가

3장에서 ImGui는 라벨 문자열을 바탕으로 위젯의 ID를 만든다고 배웠습니다. 트리와 리스트는 거의 항상 반복문으로 그려지기 때문에, 이 ID 충돌 문제가 실전에서 가장 먼저 부딪히는 위젯이기도 합니다.

다음 코드를 봅시다.

```cpp
for (int i = 0; i < enemyCount; i++)
{
    if (ImGui::TreeNode("적 유닛"))   // 문제: 라벨이 모두 동일하다!
    {
        ImGui::Text("체력: %d", enemies[i].hp);
        ImGui::TreePop();
    }
}
```

`enemyCount`가 3이라면 ImGui는 "적 유닛"이라는 똑같은 라벨을 가진 `TreeNode`를 세 번 만나게 됩니다. 내부 ID가 라벨 텍스트에서 유도되기 때문에 세 노드가 같은 ID를 갖게 되고, 그 결과 하나를 펼치면 나머지도 같이 펼쳐지거나 접히는 등 예상치 못한 동작이 벌어집니다.

해결 방법은 3장에서 배운 것과 동일합니다. `%d` 같은 서식을 활용해 라벨 자체를 유니크하게 만들거나, `##` 뒤에 인덱스를 붙여 화면에 보이지 않는 고유 식별자를 추가하거나, `ImGui::PushID()` / `ImGui::PopID()`로 반복문 구간 전체를 감싸는 것입니다.

```cpp
for (int i = 0; i < enemyCount; i++)
{
    ImGui::PushID(i);
    if (ImGui::TreeNode("적 유닛"))
    {
        ImGui::Text("체력: %d", enemies[i].hp);
        ImGui::TreePop();
    }
    ImGui::PopID();
}
```

`PushID(i)`는 정수 `i`를 ID 스택에 밀어 넣어, 화면에 보이는 라벨은 똑같이 "적 유닛"이지만 내부적으로는 서로 다른 ID를 갖도록 만들어줍니다. 라벨을 직접 바꾸는 방식보다 이 편이 나을 때가 많은데, 화면에 표시되는 텍스트를 오염시키지 않고도 문제를 해결할 수 있기 때문입니다.

리스트 박스 안의 `Selectable`도 마찬가지 위험을 안고 있습니다. 만약 목록에 이름이 같은 항목이 두 개 있다면(예: 서로 다른 폴더에 있는 동명의 파일 "readme.txt") 역시 ID가 충돌합니다.

```cpp
for (int i = 0; i < fileCount; i++)
{
    ImGui::PushID(i);
    if (ImGui::Selectable(files[i].name.c_str(), selectedIndex == i))
        selectedIndex = i;
    ImGui::PopID();
}
```

이처럼 "반복문 + 같은 라벨을 가질 가능성이 있는 위젯"이라는 조합을 보면 반사적으로 ID 충돌을 의심하는 습관을 들이는 것이 좋습니다. 이 문제는 다음 장에서 배울 테이블 안에서 버튼이나 입력 필드를 행마다 그릴 때도 똑같이 등장하며, 9장에서 다이얼로그를 여러 개 동적으로 띄울 때도 다시 마주치게 됩니다.

## 요약

- `ImGui::TreeNode("라벨")`은 펼침/접힘이 가능한 계층 노드를 만들며, `true`를 반환했을 때만 내부 블록을 그리고 반드시 `ImGui::TreePop()`으로 짝을 맞춰야 합니다.
- `TreeNode` 안에서 다시 `TreeNode`를 호출하면 자연스럽게 중첩된 트리(파일 탐색기 같은 구조)를 만들 수 있고, 리프 노드는 `TreeNodeEx()`에 `ImGuiTreeNodeFlags_Leaf | ImGuiTreeNodeFlags_NoTreePushOnOpen`을 주어 표현합니다.
- `ImGui::CollapsingHeader("라벨")`는 `TreeNode`와 비슷하지만 `TreePop()`이 필요 없으며, 여러 설정 섹션을 나란히 접었다 펼치는 용도에 적합합니다.
- `ImGui::BeginListBox()` / `EndListBox()`로 스크롤 영역을 만들고 그 안에 `ImGui::Selectable()`을 반복 호출해 리스트를 구성하며, 선택 상태는 애플리케이션이 정수 인덱스 변수로 직접 관리합니다.
- 반복문 안에서 동일한 라벨을 가진 `TreeNode`나 `Selectable`을 여러 개 그릴 때는 `PushID()` / `PopID()`나 `##` 접미사로 ID 충돌을 반드시 방지해야 합니다.

## 연습문제

1. 폴더와 파일로 구성된 트리 구조를 재귀 함수로 그리되, 폴더를 클릭하면 콘솔에 폴더 경로를 출력하도록 확장해보세요. (힌트: `ImGuiTreeNodeFlags_OpenOnArrow`를 활용하면 펼침 동작과 클릭 동작을 분리할 수 있습니다.)
2. `ImGui::CollapsingHeader()`에 `bool* p_visible` 인자를 넘겨서, 사용자가 닫기 버튼을 누르면 해당 설정 섹션이 완전히 사라지고 "섹션 복원" 버튼이 나타나 다시 켤 수 있는 UI를 만들어보세요.
3. 100개의 항목을 가진 리스트 박스를 만들고, 위쪽에 텍스트 입력 필드를 추가해 입력한 문자열이 포함된 항목만 필터링해서 보여주도록 구현해보세요.
