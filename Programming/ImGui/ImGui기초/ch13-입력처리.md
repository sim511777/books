# 13장. 입력 처리

[◀ 이전: 12장. 스타일링과 테마](ch12-스타일링과테마.md) | [📖 목차](00-목차.md) | [다음: 14장. 상태 관리 패턴 ▶](ch14-상태관리패턴.md)


지금까지 우리는 버튼을 누르면 `if` 문 안으로 들어가고, 슬라이더를 움직이면 변수가 바뀌는 식으로 ImGui의 입력 처리를 아주 자연스럽게 사용해 왔다. 위젯 함수가 `bool`을 반환하고 그 값으로 분기하는 패턴은 3장에서부터 계속 등장했다. 그런데 실전 애플리케이션을 만들다 보면 이보다 더 세밀한 질문에 답해야 하는 순간이 온다. 사용자가 지금 이 항목 위에 마우스를 올리고 있는가? 드래그 중인 슬라이더에서 손을 뗀 순간을 어떻게 알아채는가? 텍스트 입력 창에 포커스가 있을 때 애플리케이션의 전역 단축키가 오작동하지 않게 하려면 어떻게 해야 하는가? 3D 뷰포트 위에 떠 있는 오버레이 패널을 클릭했는데 카메라가 같이 회전해버리는 문제는 어떻게 막는가?

이번 장에서는 ImGui가 입력을 어떻게 받아들이고, 그 상태를 애플리케이션에 어떤 방식으로 노출하는지 체계적으로 살펴본다. `ImGuiIO` 구조체부터 시작해서 위젯 단위의 상호작용 질의 함수들, 키보드 단축키 구현, 그리고 ImGui와 애플리케이션이 입력을 두고 경쟁하지 않도록 하는 입력 캡처 플래그까지 순서대로 다룬다.

## ImGuiIO: 입력의 관문

ImGui는 자체적으로 운영체제나 윈도우 시스템에 접근하지 않는다. 2장에서 설정했듯이, 백엔드(GLFW, Win32, SDL 등)가 매 프레임 마우스 좌표나 키 입력을 수집해서 `ImGuiIO` 구조체에 채워 넣고, ImGui는 그 구조체만 읽어서 동작한다. 이 구조체는 `ImGui::GetIO()`로 언제든 참조를 얻을 수 있다.

```cpp
ImGuiIO& io = ImGui::GetIO();

// 마우스 관련
ImVec2 mousePos = io.MousePos;          // 현재 마우스 좌표(화면 기준)
bool leftDown   = io.MouseDown[0];      // 왼쪽 버튼이 눌려 있는가
float wheel     = io.MouseWheel;        // 이번 프레임의 휠 스크롤 양

// 키보드 모디파이어
bool ctrl  = io.KeyCtrl;
bool shift = io.KeyShift;
bool alt   = io.KeyAlt;

// 프레임 정보
float dt = io.DeltaTime;                // 이전 프레임과의 시간 간격(초)
float fps = io.Framerate;               // ImGui가 추정한 평균 프레임레이트
```

`io.MouseDown[0..4]`처럼 배열로 직접 접근하는 방법도 있지만, 실무에서는 뒤에서 소개할 `ImGui::IsMouseDown()`, `ImGui::IsMouseClicked()` 같은 함수형 API를 쓰는 편이 의도가 더 분명하게 드러난다. `ImGuiIO`를 직접 읽는 건 주로 마우스 좌표, 휠 값, 프레임 시간처럼 "값 자체"가 필요할 때이고, "지금 클릭됐는가" 같은 판정은 전용 질의 함수에 맡기는 것이 관례다.

```cpp
if (ImGui::IsMouseClicked(ImGuiMouseButton_Left))
    printf("왼쪽 버튼 클릭!\n");

if (ImGui::IsMouseDoubleClicked(ImGuiMouseButton_Left))
    printf("더블클릭!\n");

if (ImGui::IsMouseDragging(ImGuiMouseButton_Left))
{
    ImVec2 delta = ImGui::GetMouseDragDelta(ImGuiMouseButton_Left);
    printf("드래그 거리: (%.1f, %.1f)\n", delta.x, delta.y);
}
```

이 함수들은 전역적인 마우스 상태를 묻는다는 점에서, 다음 절에서 다룰 "특정 위젯" 단위의 질의와는 결이 다르다. 화면 아무 곳에서나 드래그를 감지하고 싶다면 위 함수들을, 특정 버튼이나 이미지 위에서 일어나는 상호작용만 알고 싶다면 다음 절의 `IsItem*` 계열 함수를 쓴다.

## 위젯 상호작용 상태 확인하기

ImGui의 위젯 함수는 그리는 동시에 내부적으로 "이 항목이 지금 어떤 상태인가"를 기록해 둔다. 이 상태는 바로 다음 줄에서 `IsItem*` 계열 함수로 질의할 수 있다. 핵심은 **직전에 호출한 위젯**에 대해서만 유효하다는 점이다. 즉 아래처럼 위젯을 그린 바로 다음 줄에서 물어봐야 한다.

```cpp
ImGui::Button("저장");
if (ImGui::IsItemHovered())
    ImGui::SetTooltip("Ctrl+S로도 저장할 수 있습니다");
```

### IsItemHovered: 마우스를 올렸는가

가장 자주 쓰는 함수다. 마우스 커서가 직전 위젯의 사각 영역 안에 있고, 그 위젯을 다른 창이나 팝업이 가리고 있지 않을 때 `true`를 반환한다.

```cpp
ImGui::ImageButton("icon", texture, ImVec2(32, 32));
if (ImGui::IsItemHovered())
{
    ImGui::BeginTooltip();
    ImGui::Text("아이콘을 클릭하면 파일을 엽니다");
    ImGui::EndTooltip();
}
```

주의할 점은 마우스가 버튼 위에 있어도 다른 모달 팝업이 열려 있거나, 다른 위젯이 입력을 독점(active)하고 있으면 `IsItemHovered()`가 `false`를 반환할 수 있다는 것이다. 이는 의도된 동작으로, 예를 들어 슬라이더를 드래그하는 도중 마우스가 실수로 다른 버튼 위를 지나가더라도 그 버튼이 호버 상태로 오인되지 않도록 막아준다. 이런 기본 동작을 바꾸고 싶다면 `ImGuiHoveredFlags`를 인자로 넘길 수 있다.

```cpp
// 다른 위젯이 활성 상태여도, 겹치는 창이 있어도 강제로 호버 판정
if (ImGui::IsItemHovered(ImGuiHoveredFlags_AllowWhenBlockedByActiveItem))
{
    // ...
}
```

### IsItemClicked: 클릭됐는가

`IsItemClicked()`는 직전 위젯이 이번 프레임에 클릭됐는지를 알려준다. 기본은 왼쪽 버튼이며, 인자로 다른 버튼을 지정할 수 있다.

```cpp
ImGui::Text("항목 A");
if (ImGui::IsItemClicked(ImGuiMouseButton_Right))
    ImGui::OpenPopup("항목_컨텍스트메뉴");

if (ImGui::BeginPopup("항목_컨텍스트메뉴"))
{
    ImGui::MenuItem("이름 바꾸기");
    ImGui::MenuItem("삭제");
    ImGui::EndPopup();
}
```

`ImGui::Text()`처럼 원래 클릭에 반응하지 않는 위젯에도 `IsItemClicked()`를 걸어 클릭 가능한 라벨을 흉내 낼 수 있다는 점이 유용하다. 다만 이 경우 `Text()` 자체는 호버 판정을 자동으로 지원하지 않으므로, 클릭 가능한 영역임을 시각적으로 보여주려면 `IsItemHovered()`와 함께 색을 바꿔주는 처리를 직접 추가해야 한다(색상 조작은 12장에서 다룬 `PushStyleColor` 패턴을 그대로 사용하면 된다).

### IsItemActive: 지금 조작 중인가

`IsItemActive()`는 위젯이 "현재 사용자의 입력을 붙잡고 있는" 상태인지를 알려준다. 버튼이라면 마우스 버튼을 누르고 있는 동안, 슬라이더나 드래그 위젯이라면 드래그하는 동안, 텍스트 입력창이라면 포커스를 받아 타이핑 중인 동안 `true`가 된다. 단순히 마우스를 올린 것(hover)과는 분명히 다르다.

```cpp
static float volume = 0.5f;
ImGui::SliderFloat("볼륨", &volume, 0.0f, 1.0f);
if (ImGui::IsItemActive())
{
    // 드래그하는 동안 실시간으로 프리뷰 사운드를 재생하는 등의 처리
    PreviewVolumeChange(volume);
}
```

이 함수는 "지금 사용자가 이 위젯을 붙잡고 씨름하는 중이니 다른 값 갱신 로직을 잠시 멈춰라" 같은 판단에 자주 쓰인다. 예를 들어 외부 소스(네트워크, 센서 등)에서 값을 주기적으로 덮어써야 하는 슬라이더가 있다면, `IsItemActive()`가 `true`인 동안은 덮어쓰기를 건너뛰어야 사용자의 드래그가 매 프레임 끊기지 않는다.

```cpp
static float sensorValue = 0.0f;
if (!ImGui::IsItemActive())
    sensorValue = ReadLatestSensorValue();  // 사용자가 조작 중이 아닐 때만 갱신
ImGui::SliderFloat("센서 값", &sensorValue, 0.0f, 100.0f);
```

### IsItemDeactivatedAfterEdit: 편집을 막 끝냈는가

슬라이더나 텍스트 입력창처럼 값이 연속적으로 바뀌는 위젯은 드래그하거나 타이핑하는 동안 매 프레임 `true`를 반환한다(위젯 반환값 자체가 "이번 프레임에 값이 바뀌었는가"를 뜻한다는 점은 14장에서 다시 자세히 다룬다). 하지만 값이 바뀔 때마다 파일에 저장하거나 서버에 전송하는 건 비효율적이다. "사용자가 슬라이더를 조작하다가 손을 뗀 순간", 즉 값 편집이 방금 끝난 시점만 잡고 싶다면 `IsItemDeactivatedAfterEdit()`을 쓴다.

```cpp
static float brightness = 1.0f;
ImGui::SliderFloat("밝기", &brightness, 0.0f, 2.0f);
if (ImGui::IsItemDeactivatedAfterEdit())
{
    // 드래그 도중에는 호출되지 않고, 마우스를 뗀 바로 그 프레임에 한 번만 호출된다
    SaveSettingToDisk("brightness", brightness);
}
```

이 함수는 값이 실제로 바뀐 채로 편집이 끝났을 때만 반응한다는 점도 기억해 둘 만하다. 위젯을 클릭했다가 값 변화 없이 그대로 뗀 경우에는 호출되지 않는다. 비슷하게 생긴 `IsItemDeactivated()`는 값 변화 여부와 무관하게 위젯이 비활성화되는 모든 순간에 반응하므로, 용도에 따라 골라 쓰면 된다.

정리하면 네 함수는 서로 다른 시점을 가리킨다.

| 함수 | 의미 | 대표 사용처 |
|---|---|---|
| `IsItemHovered()` | 마우스가 위에 있다 | 툴팁, 호버 하이라이트 |
| `IsItemClicked()` | 이번 프레임에 클릭됐다 | 컨텍스트 메뉴 열기 |
| `IsItemActive()` | 지금 조작(입력 캡처) 중이다 | 실시간 프리뷰, 외부 갱신 억제 |
| `IsItemDeactivatedAfterEdit()` | 편집이 방금 끝났다 | 값 확정, 저장, 커밋 |

## 키보드 입력과 단축키

마우스만큼이나 자주 필요한 것이 키보드 단축키다. ImGui는 `ImGuiKey`라는 플랫폼 독립적인 열거형으로 키를 표현하며, `IsKeyPressed()`, `IsKeyDown()`, `IsKeyReleased()`로 상태를 질의한다.

```cpp
if (ImGui::IsKeyPressed(ImGuiKey_Escape))
    CloseCurrentDialog();

if (ImGui::IsKeyDown(ImGuiKey_Space))
    isCharging = true;   // 누르고 있는 동안 계속 true

if (ImGui::IsKeyReleased(ImGuiKey_Space))
    FireChargedShot();
```

`IsKeyPressed()`는 기본적으로 키를 누른 첫 프레임에만 `true`를 반환하지만, 두 번째 인자로 `repeat` 여부를 지정할 수 있어 키를 계속 누르고 있을 때 OS 수준의 반복 입력처럼 동작하게 만들 수도 있다(기본값은 `true`, 즉 반복을 허용).

### Ctrl+S 단축키 구현하기

가장 흔한 요구사항인 "Ctrl+S로 저장"은 모디파이어 상태와 키 입력을 함께 검사하는 방식으로 구현한다.

```cpp
ImGuiIO& io = ImGui::GetIO();
if (io.KeyCtrl && ImGui::IsKeyPressed(ImGuiKey_S))
{
    SaveDocument();
}
```

여기서 `IsKeyPressed(ImGuiKey_S)`가 아니라 `io.KeyCtrl`을 조건에 먼저 넣은 이유가 있다. `IsKeyPressed()`는 "이번 프레임에 눌렸는가"를 판정하는데, 모디파이어 키(Ctrl, Shift, Alt)는 눌려 있는 상태가 유지되는 시간이 길기 때문에 `io.KeyCtrl`처럼 매 프레임 갱신되는 불리언 값으로 검사하는 것이 자연스럽다. 여러 단축키를 등록해야 한다면 헬퍼 함수로 묶어두면 코드가 훨씬 읽기 쉬워진다.

```cpp
bool IsShortcutPressed(ImGuiKey key, bool ctrl = false, bool shift = false)
{
    ImGuiIO& io = ImGui::GetIO();
    if (ctrl != io.KeyCtrl || shift != io.KeyShift)
        return false;
    return ImGui::IsKeyPressed(key);
}

// 사용 예
if (IsShortcutPressed(ImGuiKey_S, /*ctrl=*/true))
    SaveDocument();
if (IsShortcutPressed(ImGuiKey_Z, /*ctrl=*/true))
    Undo();
if (IsShortcutPressed(ImGuiKey_N, /*ctrl=*/true, /*shift=*/true))
    NewProjectFromTemplate();
```

메뉴 항목에 단축키를 표시하고 실제 동작도 단축키로 연결하고 싶다면, 6장에서 다룬 `MenuItem()`의 마지막 인자(표시용 문자열)와 위와 같은 키 검사 코드를 함께 배치하는 것이 일반적인 관례다.

```cpp
bool doSave = false;
if (ImGui::BeginMenu("파일"))
{
    if (ImGui::MenuItem("저장", "Ctrl+S"))
        doSave = true;
    ImGui::EndMenu();
}
if (io.KeyCtrl && ImGui::IsKeyPressed(ImGuiKey_S))
    doSave = true;

if (doSave)
    SaveDocument();
```

`MenuItem()`의 단축키 문자열("Ctrl+S")은 어디까지나 화면에 표시되는 텍스트일 뿐, ImGui가 그 표시를 보고 자동으로 키 입력을 감지해주지는 않는다는 점을 꼭 기억해 두자. 실제 단축키 동작은 위처럼 `IsKeyPressed()`로 직접 구현해야 한다.

## WantCaptureMouse와 WantCaptureKeyboard

지금까지의 함수들은 모두 "ImGui 위젯" 관점에서 입력을 다뤘다. 그런데 ImGui는 대개 3D 렌더러나 게임 엔진, 혹은 다른 입력 시스템과 한 화면을 공유한다. 사용자가 ImGui로 만든 설정 패널의 슬라이더를 드래그하고 있는데, 그 마우스 움직임이 동시에 3D 뷰의 카메라 회전으로도 해석되어버리면 곤란하다. 이 충돌을 막기 위해 `ImGuiIO`는 두 개의 플래그를 매 프레임 갱신해서 제공한다.

```cpp
ImGuiIO& io = ImGui::GetIO();

if (!io.WantCaptureMouse)
{
    UpdateCameraFromMouse();   // ImGui가 마우스를 쓰고 있지 않을 때만 카메라 조작
}

if (!io.WantCaptureKeyboard)
{
    UpdatePlayerMovementFromKeyboard();  // ImGui가 키보드를 쓰고 있지 않을 때만 게임 입력 처리
}
```

`io.WantCaptureMouse`는 마우스 커서가 ImGui 창 위에 있거나, ImGui 위젯이 현재 마우스 입력을 붙잡고 있을 때(`IsItemActive()`와 유사한 상황) `true`가 된다. `io.WantCaptureKeyboard`는 텍스트 입력창에 포커스가 있어서 타이핑을 받고 있을 때 `true`가 된다. 두 플래그 모두 `ImGui::NewFrame()` 호출 이후, 그 프레임의 위젯들을 실제로 그리고 난 뒤에 값이 확정되므로, 애플리케이션 쪽 입력 처리는 ImGui 프레임을 다 그린 다음에 이 값을 확인하는 순서로 구성해야 한다.

```cpp
while (!glfwWindowShouldClose(window))
{
    glfwPollEvents();

    ImGui_ImplOpenGL3_NewFrame();
    ImGui_ImplGlfw_NewFrame();
    ImGui::NewFrame();

    DrawUI(appState);   // 모든 ImGui 창과 위젯을 그린다

    ImGuiIO& io = ImGui::GetIO();
    if (!io.WantCaptureMouse && !io.WantCaptureKeyboard)
    {
        HandleGameInput();   // ImGui가 입력을 쓰지 않을 때만 게임 로직 실행
    }

    ImGui::Render();
    // ... 렌더링 백엔드 호출 ...
}
```

이 패턴은 ImGui를 기존 게임 엔진이나 3D 애플리케이션에 오버레이로 끼워 넣을 때 사실상 필수다. 특히 여러 개발자가 참여하는 프로젝트에서는 "왜 설정 창을 열면 카메라가 같이 돌아가나요?" 같은 버그 리포트가 `WantCaptureMouse` 체크 누락에서 비롯되는 경우가 흔하다. 반대로 이 플래그를 지나치게 넓게 적용해서, ImGui 창이 화면 한구석에 조그맣게 떠 있을 뿐인데 전체 화면의 마우스 입력을 게임 쪽에서 완전히 무시해버리는 실수도 주의해야 한다. `WantCaptureMouse`는 정확히 "이번 프레임에 ImGui가 마우스를 사용했는가"만을 나타내므로, 이 값 하나만 정직하게 따르면 대부분의 충돌은 자연스럽게 해결된다.

## 호버 기반 인터랙션 패턴 정리

9장에서 팝업과 다이얼로그를 다루면서 툴팁을 잠깐 살펴봤다. `IsItemHovered()`는 사실 그 툴팁 패턴의 핵심 부품이었다. 이번 장에서 배운 상태 질의 함수들을 조합하면, 툴팁을 넘어 다양한 호버 기반 인터랙션을 만들 수 있다.

**기본 툴팁**은 이미 익숙한 패턴이다.

```cpp
ImGui::Button("삭제");
if (ImGui::IsItemHovered())
    ImGui::SetTooltip("이 항목을 영구적으로 삭제합니다");
```

**지연된 툴팁**은 마우스를 올리자마자가 아니라 일정 시간 머물렀을 때만 표시하고 싶을 때 쓴다. `ImGuiHoveredFlags_DelayNormal`을 넘기면 ImGui가 기본 지연 시간(설정 가능)만큼 기다렸다가 호버 판정을 내려준다.

```cpp
ImGui::Button("고급 옵션");
if (ImGui::IsItemHovered(ImGuiHoveredFlags_DelayNormal))
    ImGui::SetTooltip("실험적인 기능이 포함되어 있습니다");
```

**호버 하이라이트**는 마우스를 올린 항목의 배경색을 바꿔서 클릭 가능함을 알려주는 패턴이다. 12장에서 다룬 스타일 색상 푸시와 결합하면 자연스럽게 구현된다.

```cpp
for (int i = 0; i < items.size(); i++)
{
    ImGui::PushID(i);
    bool selected = (selectedIndex == i);
    if (ImGui::Selectable(items[i].c_str(), selected))
        selectedIndex = i;
    ImGui::PopID();
}
```

`Selectable()`처럼 호버·선택 상태를 이미 내장한 위젯을 쓸 수 있다면 그쪽이 훨씬 간단하지만, `Text()`나 커스텀 렌더링(11장에서 다룬 `ImDrawList`) 기반의 항목이라면 `IsItemHovered()`로 직접 상태를 판정하고 색을 칠해야 한다.

**우클릭 컨텍스트 메뉴**는 앞서 본 `IsItemClicked(ImGuiMouseButton_Right)` 대신 `ImGui::BeginPopupContextItem()`이라는 전용 헬퍼를 쓰면 한 줄로 끝난다. 이 헬퍼는 내부적으로 오른쪽 클릭을 감지해 팝업을 여는 과정을 캡슐화한 것이다.

```cpp
ImGui::Selectable("파일.txt");
if (ImGui::BeginPopupContextItem())
{
    if (ImGui::MenuItem("이름 바꾸기")) { /* ... */ }
    if (ImGui::MenuItem("삭제")) { /* ... */ }
    ImGui::EndPopup();
}
```

**드래그 미리보기**는 `IsItemActive()`와 `GetMouseDragDelta()`를 조합한다.

```cpp
ImGui::Button("크기 조절 핸들");
if (ImGui::IsItemActive())
{
    ImVec2 delta = ImGui::GetMouseDragDelta(ImGuiMouseButton_Left);
    panelSize.x = std::max(50.0f, baseSize.x + delta.x);
    ImGui::ResetMouseDragDelta(ImGuiMouseButton_Left);
}
```

이렇게 놓고 보면 `IsItemHovered()`, `IsItemClicked()`, `IsItemActive()`, `IsItemDeactivatedAfterEdit()`은 서로 경쟁하는 함수가 아니라, "마우스가 닿는 순간부터 조작이 끝나는 순간까지"의 각기 다른 단계를 담당하는 한 세트의 도구라는 걸 알 수 있다. 어떤 UI 인터랙션을 구현하든, 결국은 이 네 단계 중 어느 시점에 반응해야 하는지를 정확히 짚어내는 문제로 귀결된다.

## 요약

- `ImGui::GetIO()`로 얻는 `ImGuiIO` 구조체는 마우스 좌표, 버튼 상태, 키보드 모디파이어, 프레임 시간 등 입력의 원본 데이터를 담고 있다.
- 위젯 단위의 상호작용은 `IsItemHovered()`(마우스 오버), `IsItemClicked()`(클릭), `IsItemActive()`(조작 중), `IsItemDeactivatedAfterEdit()`(편집 완료)로 각 단계를 구분해서 질의한다. 이 함수들은 직전에 그린 위젯 하나에 대해서만 유효하다.
- 키보드 단축키는 `ImGui::IsKeyPressed(ImGuiKey_...)`와 `io.KeyCtrl`/`KeyShift`/`KeyAlt` 조합으로 구현하며, `MenuItem()`에 표시되는 단축키 문자열은 실제 키 감지와는 별개로 직접 연결해줘야 한다.
- `io.WantCaptureMouse`와 `io.WantCaptureKeyboard`는 ImGui가 이번 프레임에 마우스/키보드 입력을 사용했는지를 알려주며, 게임이나 3D 애플리케이션에 ImGui를 통합할 때 두 입력 시스템이 충돌하지 않도록 걸러주는 역할을 한다.
- `IsItemHovered()`를 축으로 한 툴팁, 호버 하이라이트, 컨텍스트 메뉴, 드래그 미리보기 등은 모두 같은 원리를 응용한 패턴이다.

## 연습문제

1. `ImGui::Button()`으로 만든 버튼 위에 마우스를 3초 이상 올리고 있을 때만 "자세히 보기" 툴팁이 뜨도록 `ImGuiHoveredFlags_DelayNormal`을 이용해 구현해 보라.
2. Ctrl+Z(실행 취소), Ctrl+Y(다시 실행), Ctrl+Shift+S(다른 이름으로 저장) 세 가지 단축키를 이번 장에서 소개한 `IsShortcutPressed()` 헬퍼 함수를 확장해서 구현해 보라.
3. `ImGui::SliderInt()`로 만든 슬라이더 옆에 "드래그 중" / "대기 중" 텍스트를 표시하고, `IsItemActive()` 값에 따라 실시간으로 전환되도록 만들어 보라.
4. 3D 뷰포트와 ImGui 설정 패널이 공존하는 가상의 애플리케이션을 가정하고, `io.WantCaptureMouse`를 확인하지 않았을 때 발생할 수 있는 구체적인 버그 시나리오를 하나 서술하고, 이를 방지하는 코드를 작성해 보라.
5. 리스트의 각 항목에 대해 왼쪽 클릭은 선택, 오른쪽 클릭은 컨텍스트 메뉴, 마우스 오버는 툴팁을 띄우는 하나의 항목 렌더링 함수를 `IsItemHovered()`, `IsItemClicked()`, `BeginPopupContextItem()`을 조합해서 작성해 보라.
