# 5장. 창과 레이아웃

[◀ 이전: 4장. 기본 위젯](ch04-기본위젯.md) | [📖 목차](00-목차.md) | [다음: 6장. 메뉴와 툴바 ▶](ch06-메뉴와툴바.md)


지금까지는 `ImGui::Begin()`과 `ImGui::End()` 사이에 위젯을 한 줄씩 쌓아 올리는 정도로만 창을 다뤘습니다. 하지만 실제 애플리케이션은 창이 하나뿐인 경우가 거의 없고, 그 하나의 창 안에서도 위젯들이 세로로만 나열되어서는 쓸모 있는 화면을 만들기 어렵습니다. 버튼 여러 개를 한 줄에 나란히 놓아야 하고, 항목들을 구역별로 구분해야 하며, 목록이 길어지면 창 전체가 아니라 그 목록만 스크롤되도록 가둬야 합니다.

이번 장에서는 ImGui가 제공하는 레이아웃 도구들을 살펴봅니다. 창을 정의하는 플래그, 같은 줄에 위젯을 배치하는 `SameLine()`, 시각적 구분을 위한 `Separator()`, 들여쓰기, 그리고 스크롤 가능한 서브 영역을 만드는 자식 창(child window)까지 다룹니다. 이 도구들을 조합하면 여러 패널로 나뉜 복잡한 화면도 무리 없이 구성할 수 있습니다.

## 창을 여는 두 가지 인자: Begin의 재발견

3장에서 이미 살펴봤듯이 `ImGui::Begin()`은 세 가지 형태의 반환값과 매개변수를 받습니다. 여기서는 레이아웃과 직접 관련된 두 번째, 세 번째 매개변수에 집중해 보겠습니다.

```cpp
bool ImGui::Begin(const char* name, bool* p_open = nullptr, ImGuiWindowFlags flags = 0);
```

`p_open`은 창 오른쪽 위에 닫기 버튼(X)을 그리고, 사용자가 그 버튼을 누르면 가리키는 `bool` 변수를 `false`로 바꿔줍니다. `flags`는 창의 동작 방식 자체를 바꾸는 비트 플래그입니다. 다음은 실무에서 자주 쓰는 몇 가지입니다.

```cpp
static bool show_settings = true;

if (show_settings)
{
    ImGui::Begin("설정", &show_settings,
                  ImGuiWindowFlags_NoResize |
                  ImGuiWindowFlags_NoCollapse);

    ImGui::Text("이 창은 크기를 조절할 수 없습니다.");
    ImGui::End();
}
```

자주 사용하는 창 플래그는 다음과 같습니다.

| 플래그 | 효과 |
|---|---|
| `ImGuiWindowFlags_NoResize` | 창 가장자리를 드래그해 크기를 바꿀 수 없게 합니다 |
| `ImGuiWindowFlags_NoMove` | 제목 표시줄을 드래그해도 창이 움직이지 않습니다 |
| `ImGuiWindowFlags_NoCollapse` | 제목 표시줄을 더블클릭해도 창이 접히지 않습니다 |
| `ImGuiWindowFlags_NoTitleBar` | 제목 표시줄 자체를 그리지 않습니다 |
| `ImGuiWindowFlags_NoScrollbar` | 내용이 넘쳐도 스크롤바를 그리지 않습니다 |
| `ImGuiWindowFlags_AlwaysAutoResize` | 내용물 크기에 맞춰 창 크기가 자동으로 조절됩니다 |
| `ImGuiWindowFlags_MenuBar` | 창 안에 메뉴 바를 넣을 수 있게 합니다 (6장에서 사용) |

플래그는 `|` 연산자로 여러 개를 조합할 수 있습니다. 위 예제처럼 크기 조절과 접기를 동시에 막아 사용자가 실수로 창을 망가뜨리지 못하게 고정된 대시보드용 창을 만드는 식으로 자주 활용합니다.

`p_open`을 넘기지 않고 `nullptr`을 기본값으로 두면 닫기 버튼 자체가 나타나지 않으며, 프로그램이 종료될 때까지 항상 떠 있는 창이 됩니다. 반대로 여러 개의 보조 창을 사용자가 마음대로 켜고 끄게 하고 싶다면, 각 창마다 `bool` 변수를 하나씩 두고 `if (show_xxx) { ImGui::Begin(...); ... ImGui::End(); }` 패턴을 반복하는 것이 ImGui에서 가장 흔한 관용구입니다.

## 같은 줄에 위젯 배치하기: SameLine

기본적으로 ImGui는 위젯을 그릴 때마다 다음 줄로 커서를 내립니다. 버튼 세 개를 연속으로 호출하면 세로로 쌓인 버튼 세 개가 나옵니다. 이를 가로로 나란히 놓으려면 다음 위젯을 그리기 *전에* `ImGui::SameLine()`을 호출합니다.

```cpp
ImGui::Button("확인");
ImGui::SameLine();
ImGui::Button("취소");
ImGui::SameLine();
ImGui::Button("도움말");
```

`SameLine()`은 "지금 막 그린 위젯이 끝난 지점 오른쪽에서 다음 위젯을 시작하라"는 뜻으로 이해하면 됩니다. 그래서 항상 *두 번째 위젯 앞에* 호출한다는 점을 기억해두세요. 첫 번째 위젯 앞에 호출하면 아무 효과가 없습니다.

`SameLine()`은 위치를 더 세밀하게 지정하는 매개변수도 받습니다.

```cpp
void ImGui::SameLine(float offset_from_start_x = 0.0f, float spacing_x = -1.0f);
```

- `offset_from_start_x`: 0보다 크면, 이전 위젯의 끝이 아니라 현재 줄이 시작된 x 좌표(창의 왼쪽 여백 기준)로부터 정확히 이 픽셀만큼 떨어진 지점에서 다음 위젯을 시작합니다. 레이블과 값을 세로로 정렬된 열처럼 보이게 만들 때 유용합니다.
- `spacing_x`: 이전 위젯과의 간격을 직접 지정합니다. 음수(기본값)를 넘기면 스타일에 정의된 기본 간격을 사용합니다.

```cpp
ImGui::Text("이름:");
ImGui::SameLine(100.0f);
ImGui::Text("홍길동");

ImGui::Text("나이:");
ImGui::SameLine(100.0f);
ImGui::Text("29");
```

두 `Text()` 호출 모두 두 번째 텍스트가 x = 100 지점에서 시작하므로, 마치 표처럼 값들이 세로로 줄맞춰 보입니다. 다만 이런 정렬이 여러 열로 늘어나거나 정렬 기준이 복잡해지면 수작업으로 오프셋을 계산하는 대신 8장에서 다룰 테이블 API를 쓰는 편이 훨씬 편합니다.

체크박스나 슬라이더처럼 왼쪽에 자체 레이블을 갖는 위젯을 나란히 놓을 때는 `SameLine()` 뒤에 위젯의 레이블이 겹쳐 보이지 않도록 `##`을 이용한 숨김 레이블(4장 참고)을 함께 쓰는 경우가 많습니다.

## 구분선: Separator

관련 없는 내용을 시각적으로 나누고 싶을 때는 `ImGui::Separator()`를 호출합니다. 현재 커서 위치에 가로선 하나를 긋고 다음 줄로 넘어갑니다.

```cpp
ImGui::Text("파일 정보");
ImGui::Text("이름: report.txt");
ImGui::Text("크기: 128 KB");

ImGui::Separator();

ImGui::Text("작업");
if (ImGui::Button("삭제")) { /* ... */ }
```

`SameLine()`과 함께 쓰면 세로 구분선도 만들 수 있습니다.

```cpp
ImGui::Text("A");
ImGui::SameLine();
ImGui::SeparatorText("B"); // 텍스트가 포함된 구분선
```

참고로 `ImGui::SeparatorText("제목")`은 구분선 가운데(또는 왼쪽)에 짧은 레이블을 끼워 넣어, 설정 창 등에서 섹션 제목처럼 쓸 수 있는 변형입니다. 단순한 가로선만 필요하면 `Separator()`, 섹션에 이름을 붙이고 싶으면 `SeparatorText()`를 선택하면 됩니다.

## 들여쓰기: Indent와 Unindent

트리 구조나 계층적인 정보를 표현할 때, 하위 항목을 오른쪽으로 밀어 넣고 싶다면 `ImGui::Indent()`를 사용합니다. 이후 그려지는 모든 위젯의 왼쪽 여백이 늘어나며, `ImGui::Unindent()`를 호출하기 전까지 그 상태가 유지됩니다.

```cpp
ImGui::Text("항목 1");
ImGui::Indent();
ImGui::Text("항목 1.1");
ImGui::Text("항목 1.2");
ImGui::Unindent();
ImGui::Text("항목 2");
```

`Indent()`와 `Unindent()`는 둘 다 선택적으로 픽셀 단위 오프셋을 받을 수 있습니다(`ImGui::Indent(20.0f)`). 인자를 생략하면 스타일에 정의된 기본 들여쓰기 폭(`style.IndentSpacing`)만큼 이동합니다.

이 두 함수는 반드시 짝을 맞춰 호출해야 합니다. `Indent()`를 부른 만큼 `Unindent()`를 부르지 않으면, 이후 그려지는 모든 위젯이 계속 오른쪽으로 밀린 채로 남습니다. 실제로는 7장에서 다룰 `ImGui::TreeNode()`가 이 들여쓰기 작업을 자동으로 처리해주므로, 트리 형태의 UI를 만들 때는 `Indent()`/`Unindent()`를 직접 쓰기보다 `TreeNode()` 계열 API를 쓰는 경우가 더 많습니다. 지금은 원리를 이해하는 정도로 충분합니다.

## 여러 창을 동시에 띄우기

ImGui의 즉시 모드 특성상, 창을 여러 개 띄우는 것은 그저 `Begin()`/`End()` 블록을 여러 번 작성하는 것뿐입니다.

```cpp
void RenderUI()
{
    ImGui::Begin("인벤토리");
    ImGui::Text("아이템 12개");
    ImGui::End();

    ImGui::Begin("캐릭터 정보");
    ImGui::Text("체력: 87/100");
    ImGui::End();

    ImGui::Begin("미니맵");
    ImGui::Text("(지도가 표시될 자리)");
    ImGui::End();
}
```

이 코드는 프레임마다 세 개의 창을 각각 새로 정의합니다. 겉보기에는 매 프레임 창을 "새로 만드는" 것 같지만, 실제로는 창 제목("인벤토리", "캐릭터 정보", "미니맵")을 키로 삼아 내부적으로 위치와 크기 같은 상태를 계속 기억하고 있습니다. 그래서 사용자가 "인벤토리" 창을 화면 오른쪽으로 드래그해 옮기면, 다음 프레임에도 그 위치가 그대로 유지됩니다. 각 창은 서로 완전히 독립적으로 이동하고 크기를 조절할 수 있으며, 창 사이의 순서(어느 창이 위에 그려지는지)도 사용자가 클릭한 창이 자동으로 맨 앞으로 올라오는 방식으로 관리됩니다.

주의할 점은 창 제목이 식별자 역할을 겸한다는 것입니다. 같은 이름으로 `Begin()`을 두 번 부르면 ImGui는 그것을 같은 창으로 취급합니다. 만약 이름이 같은 창을 여러 개 만들어야 한다면(예: 목록의 각 항목마다 창을 하나씩 띄우는 경우), 4장에서 다룬 `##` 표기를 창 이름에도 그대로 적용해 `"상세 정보##1"`, `"상세 정보##2"`처럼 눈에 보이는 제목은 같지만 내부 ID는 다르게 만들어야 합니다.

## 스크롤 가능한 서브 영역: BeginChild / EndChild

지금까지 다룬 도구들은 창 하나 안에서 위젯의 배치를 조정하는 데 쓰입니다. 하지만 때로는 창의 일부 영역만 별도로 스크롤되게 만들고 싶을 때가 있습니다. 예를 들어 위쪽에는 항상 보이는 툴바를, 아래쪽에는 길게 이어지는 로그 목록을 두고 싶다면, 로그 목록만 자체 스크롤바를 갖는 영역으로 분리해야 합니다. 이때 사용하는 것이 자식 창(child window)입니다.

```cpp
ImGui::Begin("로그 뷰어");

ImGui::Text("필터:");
ImGui::SameLine();
static char filter[64] = "";
ImGui::InputText("##filter", filter, sizeof(filter));

ImGui::Separator();

ImGui::BeginChild("LogScrollRegion", ImVec2(0, 200), true);
for (int i = 0; i < 100; ++i)
{
    ImGui::Text("[%03d] 로그 메시지 예시입니다.", i);
}
ImGui::EndChild();

if (ImGui::Button("지우기"))
{
    // 로그 비우기 처리
}

ImGui::End();
```

`BeginChild()`의 시그니처는 다음과 같습니다.

```cpp
bool ImGui::BeginChild(const char* str_id, const ImVec2& size = ImVec2(0, 0),
                        ImGuiChildFlags child_flags = 0,
                        ImGuiWindowFlags window_flags = 0);
```

- `str_id`: 자식 영역을 구분하는 고유 식별자입니다. 같은 부모 창 안에 자식 창이 여러 개 있다면 서로 다른 이름을 지정해야 합니다.
- `size`: 자식 영역의 크기입니다. 위 예제의 `ImVec2(0, 200)`처럼 너비를 0으로 주면 부모의 남은 너비를 그대로 채우고, 높이는 200픽셀로 고정됩니다. 반대로 높이를 0으로 두면 부모 창의 남은 세로 공간을 채웁니다.
- `child_flags`: `ImGuiChildFlags_Border`(테두리를 그림) 같은 자식 창 전용 옵션입니다. 위 예제의 세 번째 인자 `true`는 과거 버전과의 호환을 위해 남아있는 "테두리 표시 여부"의 축약 형태이며, 최신 코드에서는 `ImGuiChildFlags_Border`를 명시적으로 넘기는 방식을 권장합니다.
- `window_flags`: `Begin()`과 마찬가지로 스크롤바 숨김, 크기 자동 조절 같은 창 플래그를 그대로 적용할 수 있습니다.

자식 영역 안에 그려지는 내용이 지정한 `size`보다 커지면 자동으로 세로 스크롤바가 나타나며, 부모 창을 스크롤해도 자식 영역의 스크롤 위치는 별도로 유지됩니다. 자식 영역은 사실상 그 자체로 하나의 작은 ImGui 창처럼 동작하기 때문에, 내부에서 다시 `SameLine()`, `Separator()`, 심지어 또 다른 `BeginChild()`를 중첩해서 쓰는 것도 가능합니다.

`Begin()`/`End()`와 마찬가지로 `BeginChild()`를 호출했다면 반환값과 관계없이 반드시 `EndChild()`를 짝지어 호출해야 합니다. 부모 창이 접혀 있거나 화면 밖에 있어도 자식 영역 처리를 건너뛰면 안 된다는 규칙은 3장에서 설명한 `Begin()`/`End()` 규칙과 동일합니다.

## 여러 자식 영역으로 화면 분할하기

`BeginChild()`를 여러 번 사용하면 한 창을 좌우 또는 상하로 나눈 패널 레이아웃도 만들 수 있습니다.

```cpp
ImGui::Begin("탐색기");

// 왼쪽 패널: 폴더 목록
ImGui::BeginChild("LeftPanel", ImVec2(150, 0), true);
ImGui::Text("폴더");
ImGui::Separator();
ImGui::Text("문서");
ImGui::Text("사진");
ImGui::Text("다운로드");
ImGui::EndChild();

ImGui::SameLine();

// 오른쪽 패널: 파일 목록
ImGui::BeginChild("RightPanel", ImVec2(0, 0), true);
ImGui::Text("파일");
ImGui::Separator();
for (int i = 0; i < 30; ++i)
    ImGui::Text("file_%02d.txt", i);
ImGui::EndChild();

ImGui::End();
```

왼쪽 패널은 너비 150픽셀로 고정하고, 오른쪽 패널은 너비를 0으로 두어 남은 공간을 모두 차지하게 했습니다. 두 자식 영역 사이에 `SameLine()`을 호출했기 때문에 나란히 배치됩니다. 각 패널의 높이도 0으로 지정했으므로 부모 창의 남은 세로 공간을 채우며, 내용이 넘치면 각자 독립적으로 스크롤됩니다.

이런 식으로 자식 영역을 조합하면 파일 탐색기, 코드 에디터, 이메일 클라이언트처럼 여러 패널로 구성된 화면의 기본 골격을 어렵지 않게 만들 수 있습니다. 다만 패널 개수가 늘어나고 각 패널의 크기를 사용자가 드래그로 조절할 수 있어야 한다면, 직접 크기를 계산하는 대신 10장에서 소개할 도킹(docking) 기능을 쓰는 편이 훨씬 자연스러운 결과를 냅니다. 자식 창은 어디까지나 하나의 창 내부를 분할하는 용도이고, 도킹은 창과 창 사이의 배치 자체를 사용자가 자유롭게 재구성하게 해주는 상위 개념입니다.

## 표 형태 레이아웃을 향해

지금까지 소개한 `SameLine()`과 고정 오프셋 조합은 열이 두세 개뿐인 간단한 정렬에는 충분합니다. 하지만 열 개수가 늘어나거나, 각 열의 너비를 내용에 맞춰 자동으로 조절해야 하거나, 정렬·크기 조절·헤더 고정 같은 기능까지 필요해지면 `SameLine()`만으로는 감당하기 어려워집니다.

이런 요구를 위해 ImGui는 `ImGui::BeginTable()`을 필두로 한 전용 테이블 API를 제공합니다. 열 너비 자동 계산, 헤더 정렬, 행 단위 배경색, 스크롤 고정 등 표 형태의 UI에서 필요한 기능 대부분을 내장하고 있어, 데이터를 격자 형태로 보여줘야 하는 상황이라면 지금 배운 수동 정렬보다 테이블 API 쪽이 훨씬 적은 코드로 더 견고한 결과를 만듭니다. 자세한 내용은 8장에서 본격적으로 다룹니다.

## 요약

- `ImGui::Begin()`의 두 번째 인자로 `bool*`을 넘기면 닫기 버튼이 생기고, 세 번째 인자인 `ImGuiWindowFlags`로 크기 조절 금지, 이동 금지, 제목 표시줄 숨김 등 창의 동작을 세밀하게 제어할 수 있습니다.
- `ImGui::SameLine()`은 다음 위젯을 이전 위젯과 같은 줄에 배치하며, `offset_from_start_x` 인자로 특정 x 좌표에 맞춰 정렬할 수도 있습니다.
- `ImGui::Separator()`는 가로 구분선을, `ImGui::SeparatorText()`는 레이블이 붙은 구분선을 그립니다.
- `ImGui::Indent()`/`ImGui::Unindent()`는 이후 위젯의 왼쪽 여백을 조정하며 반드시 짝을 맞춰 호출해야 합니다.
- `Begin()`/`End()` 블록을 여러 번 작성하는 것만으로 여러 창을 동시에 띄울 수 있고, 각 창은 이름을 키로 위치와 크기를 독립적으로 기억합니다.
- `ImGui::BeginChild()`/`ImGui::EndChild()`는 창 내부에 독립적으로 스크롤되는 서브 영역을 만들며, 여러 개를 나란히 배치해 패널 형태의 레이아웃을 구성할 수 있습니다.
- 열이 많거나 정교한 정렬이 필요한 표 형태의 UI는 8장에서 다룰 테이블 API로 훨씬 효율적으로 구현할 수 있습니다.

## 연습문제

1. `ImGuiWindowFlags_NoResize`와 `ImGuiWindowFlags_NoMove`를 함께 적용한 창을 만들고, 실행 중 실제로 크기 조절과 이동이 모두 막히는지 확인해 보세요.
2. 세 개의 버튼("이전", "다음", "완료")을 한 줄에 나란히 배치하되, 마지막 버튼만 `SameLine(0.0f, 40.0f)`을 사용해 앞의 두 버튼과 간격을 더 넓게 띄워 보세요.
3. `Indent()`/`Unindent()`를 이용해 2단계 깊이의 목록(대분류 3개, 각 대분류 아래 소항목 2~3개)을 텍스트만으로 표현해 보세요.
4. 동시에 세 개의 독립된 창("A", "B", "C")을 띄우고, 각 창을 자유롭게 옮겨보면서 위치가 서로 영향을 주지 않는지 확인해 보세요.
5. 하나의 창 안에 `BeginChild()`로 높이 100픽셀짜리 스크롤 영역을 만들고, 그 안에 50줄의 텍스트를 출력해 스크롤이 자동으로 생기는지 확인해 보세요. 이어서 같은 창에 두 번째 자식 영역을 `SameLine()`으로 나란히 추가해 좌우 분할 레이아웃을 만들어 보세요.
