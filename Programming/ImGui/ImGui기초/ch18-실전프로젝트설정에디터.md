# 18장. 실전 프로젝트: 설정 에디터 만들기

[◀ 이전: 17장. 성능 최적화와 디버깅](ch17-성능최적화와디버깅.md) | [📖 목차](00-목차.md) | [다음: 부록 ▶](appendix-부록.md)


지금까지 열일곱 개의 장을 거치며 창, 위젯, 레이아웃, 트리와 테이블, 팝업, 도킹, 커스텀 렌더링, 스타일링, 입력 처리, 상태 관리, 플롯, 성능 최적화까지 Dear ImGui의 거의 모든 영역을 하나씩 익혀왔습니다. 이번 마지막 장에서는 이 조각들을 한데 모아 하나의 완결된 프로그램을 만들어 보겠습니다.

만들어 볼 프로그램은 실제 애플리케이션에서 흔히 필요한 **설정 에디터(Settings Editor)**입니다. 애플리케이션의 각종 설정 항목(해상도, 볼륨, 플레이어 이름 등)을 목록으로 보여주고, 항목을 선택하면 값을 편집할 수 있으며, 변경 사항을 저장하기 전에 확인 창을 띄우는 프로그램입니다. 규모는 작지만 다음 요소들을 모두 담고 있습니다.

- 메인 메뉴 바 (6장)
- 도킹 가능한 여러 패널 (10장)
- 테이블로 표시되는 항목 목록 (8장)
- 다양한 타입의 값을 편집하는 위젯들 (4장)
- 저장 확인 모달 다이얼로그 (9장)
- 이 모든 것을 지탱하는 구조체 기반 상태 관리 (14장)

## 프로젝트 구조 잡기: 상태부터 설계한다

14장에서 강조했던 원칙을 다시 떠올려 봅시다. 즉시 모드에서는 위젯이 스스로 상태를 기억하지 않으므로, 여러 프레임에 걸쳐 유지되어야 하는 값은 전부 애플리케이션 쪽 변수가 들고 있어야 합니다. 위젯 몇 개짜리 작은 예제라면 지역 `static` 변수로도 충분하지만, 패널이 여러 개로 늘어나고 그 패널들이 서로 데이터를 공유해야 하는 지금 같은 상황에서는 상태를 구조체로 묶어 한곳에서 관리하는 편이 압도적으로 다루기 쉽습니다.

먼저 편집 대상이 되는 "설정 항목 하나"를 표현하는 구조체를 정의합니다. 실전에서는 불리언, 정수, 실수, 문자열처럼 서로 다른 타입의 설정값을 한 목록 안에 섞어 보여줘야 하는 경우가 흔합니다.

```cpp
enum class SettingType
{
    Bool,
    Int,
    Float,
    String,
};

struct SettingItem
{
    std::string name;          // 설정 항목의 이름 (예: "수직 동기화")
    SettingType type;          // 값의 종류
    bool        boolValue   = false;
    int         intValue    = 0;
    float       floatValue  = 0.0f;
    char        stringValue[128] = "";

    bool dirty = false;        // 마지막 저장 이후 이 항목이 바뀌었는가
};
```

값 자체를 `union`으로 합치지 않고 타입별 필드를 모두 펼쳐 둔 이유는, ImGui의 편집 위젯들이 각각 `bool*`, `int*`, `float*`, `char*` 같은 서로 다른 포인터 타입을 요구하기 때문입니다. `union`을 쓰면 메모리는 절약되지만 `std::string`처럼 생성자/소멸자가 있는 타입과 섞어 쓰기가 번거로워지므로, 설정 항목처럼 개수가 많지 않은 데이터에서는 이렇게 필드를 모두 갖는 편이 코드를 훨씬 단순하게 유지해 줍니다.

다음으로, 이 항목들의 목록과 프로그램 전체에서 공유되는 UI 상태를 묶는 최상위 구조체를 정의합니다.

```cpp
struct AppState
{
    std::vector<SettingItem> items;

    int  selectedIndex = -1;      // 항목 목록에서 현재 선택된 항목의 인덱스
    bool hasUnsavedChanges = false;

    // 패널 표시 여부 (View 메뉴에서 토글)
    bool showItemListPanel   = true;
    bool showValueEditorPanel = true;

    // 저장 확인 모달 관련 상태
    bool showSaveConfirmModal = false;
    bool exitAfterSaveDecision = false; // 저장 여부를 결정한 뒤 종료할지
    bool requestExit = false;           // 애플리케이션 종료 요청 플래그
};
```

`AppState` 하나만 메인 함수에서 만들어서 각 패널을 그리는 함수에 참조로 넘겨주면, 어떤 패널에서 값을 바꾸든 그 변경이 다른 패널에도 즉시 반영됩니다. 이것이 14장에서 다룬 "상태를 한곳에 모으고 위젯 함수들은 그 상태를 읽고 쓰기만 한다"는 패턴을 그대로 프로젝트 규모로 확장한 것입니다.

초기 데이터를 채우는 함수도 하나 준비해 둡니다.

```cpp
void InitializeDefaultSettings(AppState& state)
{
    state.items.push_back({ "수직 동기화",      SettingType::Bool,   true });
    state.items.push_back({ "안티에일리어싱",    SettingType::Int,    false, 4 });
    state.items.push_back({ "마스터 볼륨",       SettingType::Float,  false, 0, 0.8f });
    state.items.push_back({ "플레이어 이름",     SettingType::String });
    std::strncpy(state.items[3].stringValue, "Player1",
                 sizeof(state.items[3].stringValue) - 1);
    state.items.push_back({ "화면 밝기",         SettingType::Float,  false, 0, 1.0f });
}
```

## 메인 메뉴 바와 도킹 스페이스

애플리케이션의 뼈대는 메인 메뉴 바와, 그 아래로 여러 패널을 자유롭게 재배치할 수 있는 도킹 스페이스입니다. 10장에서 다룬 것처럼, 뷰포트 전체를 덮는 도킹 스페이스는 매 프레임 시작 부분에서 한 번 만들어주면 됩니다.

```cpp
void DrawMainMenuBar(AppState& state)
{
    if (ImGui::BeginMainMenuBar())
    {
        if (ImGui::BeginMenu("파일"))
        {
            if (ImGui::MenuItem("저장", "Ctrl+S"))
                state.showSaveConfirmModal = true;

            ImGui::Separator();

            if (ImGui::MenuItem("종료"))
            {
                state.requestExit = true;
                if (state.hasUnsavedChanges)
                    state.showSaveConfirmModal = true;
            }
            ImGui::EndMenu();
        }

        if (ImGui::BeginMenu("보기"))
        {
            ImGui::MenuItem("항목 목록", nullptr, &state.showItemListPanel);
            ImGui::MenuItem("값 편집기", nullptr, &state.showValueEditorPanel);
            ImGui::EndMenu();
        }

        // 저장되지 않은 변경 사항이 있으면 메뉴 바 오른쪽에 표시를 남긴다.
        if (state.hasUnsavedChanges)
        {
            const char* label = "* 저장되지 않은 변경 사항";
            float textWidth = ImGui::CalcTextSize(label).x;
            ImGui::SameLine(ImGui::GetWindowWidth() - textWidth - 16.0f);
            ImGui::TextColored(ImVec4(1.0f, 0.7f, 0.3f, 1.0f), "%s", label);
        }

        ImGui::EndMainMenuBar();
    }
}

void DrawDockSpace()
{
    ImGuiDockNodeFlags dockFlags = ImGuiDockNodeFlags_PassthruCentralNode;
    ImGui::DockSpaceOverViewport(0, nullptr, dockFlags);
}
```

`DrawDockSpace()`는 `ImGui::DockSpaceOverViewport()` 한 줄로, 뷰포트 전체 크기의 보이지 않는 도킹 대상 영역을 만듭니다. 이후 그려지는 창들은 사용자가 제목 표시줄을 드래그해서 이 영역 위 어디로든 도킹시킬 수 있게 됩니다. `ImGuiDockNodeFlags_PassthruCentralNode`는 중앙의 빈 공간을 클릭했을 때 그 뒤에 있는 배경(예: 3D 렌더링 결과)까지 입력이 통과되도록 해주는 옵션으로, 에디터류 애플리케이션에서 자주 사용합니다.

## 항목 목록 패널: 테이블로 보여주기

첫 번째 패널은 모든 설정 항목을 테이블로 나열하고, 행을 클릭하면 그 항목이 "선택된" 상태가 되도록 만듭니다. 8장에서 다룬 `BeginTable()` / `EndTable()`과 7장에서 다룬 `Selectable()`의 선택 패턴을 함께 사용합니다.

```cpp
const char* SettingTypeToString(SettingType type)
{
    switch (type)
    {
        case SettingType::Bool:   return "Bool";
        case SettingType::Int:    return "Int";
        case SettingType::Float:  return "Float";
        case SettingType::String: return "String";
    }
    return "?";
}

void DrawItemListPanel(AppState& state)
{
    if (!state.showItemListPanel)
        return;

    ImGui::Begin("항목 목록", &state.showItemListPanel);

    ImGuiTableFlags tableFlags =
        ImGuiTableFlags_Borders | ImGuiTableFlags_RowBg |
        ImGuiTableFlags_Resizable | ImGuiTableFlags_ScrollY;

    if (ImGui::BeginTable("settings_table", 3, tableFlags,
                           ImVec2(0.0f, -1.0f)))
    {
        ImGui::TableSetupColumn("이름", ImGuiTableColumnFlags_WidthStretch);
        ImGui::TableSetupColumn("타입", ImGuiTableColumnFlags_WidthFixed, 70.0f);
        ImGui::TableSetupColumn("현재 값", ImGuiTableColumnFlags_WidthStretch);
        ImGui::TableHeadersRow();

        for (int i = 0; i < (int)state.items.size(); i++)
        {
            const SettingItem& item = state.items[i];

            ImGui::PushID(i);
            ImGui::TableNextRow();

            ImGui::TableNextColumn();
            bool isSelected = (state.selectedIndex == i);
            ImGuiSelectableFlags flags =
                ImGuiSelectableFlags_SpanAllColumns |
                ImGuiSelectableFlags_AllowOverlap;
            if (ImGui::Selectable(item.name.c_str(), isSelected, flags))
                state.selectedIndex = i;

            ImGui::TableNextColumn();
            ImGui::TextUnformatted(SettingTypeToString(item.type));

            ImGui::TableNextColumn();
            switch (item.type)
            {
                case SettingType::Bool:
                    ImGui::TextUnformatted(item.boolValue ? "true" : "false");
                    break;
                case SettingType::Int:
                    ImGui::Text("%d", item.intValue);
                    break;
                case SettingType::Float:
                    ImGui::Text("%.2f", item.floatValue);
                    break;
                case SettingType::String:
                    ImGui::TextUnformatted(item.stringValue);
                    break;
            }

            ImGui::PopID();
        }

        ImGui::EndTable();
    }

    ImGui::End();
}
```

행마다 이름이 겹칠 가능성은 낮지만, 17장에서 강조했듯이 "반복문 안에서 위젯을 그린다"는 조건만으로도 ID 충돌을 습관적으로 경계하는 것이 좋으므로 `PushID(i)` / `PopID()`로 각 행을 감쌌습니다. `ImGuiSelectableFlags_SpanAllColumns`는 이름 칸뿐 아니라 행 전체를 클릭 가능한 영역으로 확장해 주는 플래그로, 표 형태의 선택 UI에서 사용자 경험을 크게 개선해 줍니다.

## 값 편집 패널: 타입에 따라 다른 위젯

두 번째 패널은 목록에서 선택된 항목 하나를 실제로 편집하는 곳입니다. 항목의 타입에 따라 4장에서 배운 서로 다른 위젯을 보여줍니다.

```cpp
void DrawValueEditorPanel(AppState& state)
{
    if (!state.showValueEditorPanel)
        return;

    ImGui::Begin("값 편집기", &state.showValueEditorPanel);

    if (state.selectedIndex < 0 || state.selectedIndex >= (int)state.items.size())
    {
        ImGui::TextDisabled("왼쪽 목록에서 편집할 항목을 선택하세요.");
        ImGui::End();
        return;
    }

    SettingItem& item = state.items[state.selectedIndex];

    ImGui::Text("항목: %s", item.name.c_str());
    ImGui::Text("타입: %s", SettingTypeToString(item.type));
    ImGui::Separator();

    bool changed = false;
    switch (item.type)
    {
        case SettingType::Bool:
            changed = ImGui::Checkbox("값", &item.boolValue);
            break;

        case SettingType::Int:
            changed = ImGui::SliderInt("값", &item.intValue, 0, 16);
            break;

        case SettingType::Float:
            changed = ImGui::SliderFloat("값", &item.floatValue, 0.0f, 1.0f);
            break;

        case SettingType::String:
            changed = ImGui::InputText("값", item.stringValue,
                                        sizeof(item.stringValue));
            break;
    }

    if (changed)
    {
        item.dirty = true;
        state.hasUnsavedChanges = true;
    }

    if (item.dirty)
    {
        ImGui::SameLine();
        ImGui::TextColored(ImVec4(1.0f, 0.7f, 0.3f, 1.0f), "(수정됨)");
    }

    ImGui::End();
}
```

여기서 핵심은 각 위젯이 반환하는 `bool` 값을 그대로 활용하는 것입니다. 1장과 4장에서 배운 것처럼, ImGui의 편집 위젯은 값이 실제로 바뀐 프레임에만 `true`를 반환합니다. 이를 이용해 "값이 바뀐 그 순간에만" `item.dirty`와 `state.hasUnsavedChanges`를 세워주면, 불필요하게 매 프레임 더티 플래그를 다시 계산하는 낭비 없이 정확한 시점에 상태를 갱신할 수 있습니다. 이 값은 앞서 만든 메인 메뉴 바의 "저장되지 않은 변경 사항" 표시와 곧이어 만들 저장 확인 모달의 동작 조건으로 그대로 이어집니다.

## 저장 확인 모달 다이얼로그

마지막 조각은 저장 버튼을 누르거나, 저장되지 않은 변경 사항이 있는 상태에서 종료를 시도했을 때 뜨는 확인 창입니다. 9장에서 다룬 `BeginPopupModal()` 패턴을 사용합니다.

```cpp
void SaveSettingsToDisk(AppState& state)
{
    // 실제 프로젝트라면 여기서 파일이나 레지스트리 등에 값을 기록합니다.
    for (SettingItem& item : state.items)
        item.dirty = false;

    state.hasUnsavedChanges = false;
}

void DrawSaveConfirmModal(AppState& state)
{
    if (state.showSaveConfirmModal)
    {
        ImGui::OpenPopup("변경 사항 저장");
        state.showSaveConfirmModal = false; // OpenPopup은 한 번만 호출하면 된다.
    }

    ImVec2 center = ImGui::GetMainViewport()->GetCenter();
    ImGui::SetNextWindowPos(center, ImGuiCond_Appearing, ImVec2(0.5f, 0.5f));

    if (ImGui::BeginPopupModal("변경 사항 저장", nullptr,
                                ImGuiWindowFlags_AlwaysAutoResize))
    {
        if (state.hasUnsavedChanges)
            ImGui::Text("저장하지 않은 변경 사항이 있습니다. 저장하시겠습니까?");
        else
            ImGui::Text("현재 설정을 저장하시겠습니까?");

        ImGui::Separator();

        if (ImGui::Button("저장", ImVec2(100, 0)))
        {
            SaveSettingsToDisk(state);
            ImGui::CloseCurrentPopup();
            if (state.requestExit)
                state.exitAfterSaveDecision = true;
        }
        ImGui::SetItemDefaultFocus();
        ImGui::SameLine();

        if (ImGui::Button("저장 안 함", ImVec2(100, 0)))
        {
            ImGui::CloseCurrentPopup();
            if (state.requestExit)
                state.exitAfterSaveDecision = true;
        }
        ImGui::SameLine();

        if (ImGui::Button("취소", ImVec2(100, 0)))
        {
            state.requestExit = false; // 종료 시도 자체를 취소한다.
            ImGui::CloseCurrentPopup();
        }

        ImGui::EndPopup();
    }
}
```

`ImGui::OpenPopup()`은 매 프레임 호출하면 안 되고 "지금 막 창을 열어야 하는 그 프레임에만" 호출해야 하므로, `showSaveConfirmModal` 플래그가 켜진 순간에만 호출하고 곧바로 꺼주는 방식을 사용했습니다. 반면 `BeginPopupModal()`은 팝업이 열려 있는 동안 계속 호출되어야 하므로 조건 없이 매 프레임 호출합니다. 이는 9장에서 다룬 모달 팝업의 표준적인 사용 패턴입니다.

"취소"를 누르면 `requestExit`를 다시 꺼서 종료 시도 자체를 무효화하고, "저장" 또는 "저장 안 함"을 누르면 종료가 요청된 상태였을 경우에 한해 `exitAfterSaveDecision`을 세워 실제 종료로 이어지게 했습니다. 이렇게 "저장 여부 확인"과 "종료 여부 결정"을 분리해 두면, 같은 모달을 "그냥 저장 버튼을 눌렀을 때"와 "종료하려는데 미저장 항목이 있을 때" 양쪽 모두에 재사용할 수 있습니다.

## 전체 조립하기

이제 각 패널을 매 프레임 순서대로 호출하는 메인 루프의 UI 갱신 부분을 완성합니다. 2장에서 만든 GLFW + OpenGL3 백엔드의 렌더 루프 안에, 매 프레임 다음 함수를 호출한다고 가정합니다.

```cpp
void DrawSettingsEditorUI(AppState& state)
{
    DrawDockSpace();
    DrawMainMenuBar(state);
    DrawItemListPanel(state);
    DrawValueEditorPanel(state);
    DrawSaveConfirmModal(state);
}
```

그리고 메인 함수에서는 다음과 같이 초기화하고, 매 프레임 이 함수를 호출하며, `exitAfterSaveDecision`이나 (저장할 것이 없는 상태에서의) `requestExit`를 확인해 루프를 빠져나갑니다.

```cpp
int main()
{
    // ... GLFW, OpenGL3, ImGui 초기화는 2장 참고 ...

    AppState state;
    InitializeDefaultSettings(state);

    while (!glfwWindowShouldClose(window))
    {
        glfwPollEvents();

        ImGui_ImplOpenGL3_NewFrame();
        ImGui_ImplGlfw_NewFrame();
        ImGui::NewFrame();

        DrawSettingsEditorUI(state);

        bool shouldExit =
            state.exitAfterSaveDecision ||
            (state.requestExit && !state.hasUnsavedChanges);
        if (shouldExit)
            glfwSetWindowShouldClose(window, true);

        ImGui::Render();
        // ... 프레임버퍼 클리어, ImGui_ImplOpenGL3_RenderDrawData 등은 2장 참고 ...
        glfwSwapBuffers(window);
    }

    // ... ImGui, GLFW 정리 ...
    return 0;
}
```

`state.requestExit && !state.hasUnsavedChanges` 조건은 "종료를 요청했는데 애초에 저장할 변경 사항이 없었던 경우" 확인 절차 없이 곧바로 종료되도록 해줍니다. 이렇게 완성된 프로그램은 메뉴 바로 항목 목록/값 편집기 패널을 켜고 끌 수 있고, 두 패널을 도킹 스페이스 위에서 자유롭게 재배치할 수 있으며, 테이블에서 항목을 선택해 값을 바꾸고, 종료하거나 저장 버튼을 누르면 확인 모달을 거치는, 이 책에서 배운 요소들이 유기적으로 맞물린 하나의 작은 애플리케이션이 됩니다.

## 회고: 열여덟 개 장을 돌아보며

여기까지 오는 동안 다룬 내용을 짧게 되짚어 보겠습니다.

1장에서는 유지 모드와 대비되는 즉시 모드의 철학을, 2장에서는 실제로 창을 하나 띄우는 개발 환경을 갖췄습니다. 4장부터 9장까지는 버튼과 슬라이더 같은 기본 위젯부터 트리, 테이블, 팝업까지 실무에서 쓰이는 위젯들을 하나씩 익혔고, 10장부터는 도킹, 커스텀 렌더링, 스타일링, 입력 처리, 상태 관리, 플롯, 다양한 렌더링 백엔드, 성능 최적화라는 심화 주제로 나아갔습니다.

이 많은 내용 중에서도 이 책 전체를 관통하는 두 가지 뼈대를 다시 한번 짚고 넘어갈 필요가 있습니다.

**첫째는 3장에서 다룬 즉시 모드의 원칙입니다.** 위젯은 객체로 존재하지 않고, 매 프레임 함수 호출로 그려지고 사라집니다. ID 스택을 통해 각 위젯이 프레임 간에 자신의 정체성을 유지한다는 사실, 그리고 위젯의 상태는 위젯 스스로가 아니라 여러분의 프로그램이 들고 있어야 한다는 원칙은, 이 책에서 다룬 그 어떤 고급 기능(도킹, 커스텀 렌더링, 플롯)을 이해할 때도 결국 다시 돌아가게 되는 가장 근본적인 토대였습니다.

**둘째는 14장에서 다룬 상태 관리 패턴, 그리고 이번 장에서 실전 규모로 확장해 본 구조체 기반 설계입니다.** 위젯 하나짜리 예제에서는 `static bool` 변수 하나로 충분하지만, 여러 패널이 서로 데이터를 주고받아야 하는 실제 애플리케이션에서는 상태를 어떻게 조직하느냐가 코드의 유지보수성을 좌우합니다. 이번 장의 `AppState` 구조체와 그 안의 `items`, `selectedIndex`, `hasUnsavedChanges`처럼 "이 프로그램이 프레임 간에 기억해야 하는 모든 것"을 한곳에 모아두고, 각 패널을 그리는 함수는 그 상태를 참조로 받아 읽고 쓰기만 하는 구조는 즉시 모드 애플리케이션을 확장 가능하게 만드는 가장 실전적인 답입니다.

결국 Dear ImGui로 무언가를 만든다는 것은, 매 프레임 "지금 이 상태를 화면에 어떻게 보여줄 것인가"를 함수 호출로 선언하고, 그 상태 자체는 여러분이 설계한 자료구조가 온전히 책임지는 작업이라고 요약할 수 있습니다. 위젯의 종류가 늘어나고 화면 구성이 복잡해져도 이 두 원칙만 놓치지 않는다면, 어떤 규모의 도구든 무리 없이 만들어 나갈 수 있을 것입니다.

## 더 공부할 방향

이 책은 Dear ImGui의 입문 과정을 다루지만, 실제로 이 라이브러리를 프로덕션에서 쓰기 시작하면 더 넓은 세계가 기다리고 있습니다. 몇 가지 방향을 짧게 소개하며 이 책을 마무리합니다.

- **실제 게임 엔진에 통합하기**: 이 책에서는 GLFW와 OpenGL3라는 비교적 단순한 조합을 사용했지만, 실무에서는 Unreal Engine, Unity(네이티브 플러그인 경유), 또는 자체 엔진의 렌더링 파이프라인 한가운데에 ImGui를 끼워 넣어야 하는 경우가 많습니다. 16장에서 살펴본 다양한 렌더링 백엔드에 대한 이해는 이런 통합 작업의 출발점이 되어 줍니다.
- **커스텀 위젯 라이브러리 만들기**: 11장에서 다룬 `ImDrawList`를 활용하면 ImGui가 기본으로 제공하지 않는 노드 에디터, 커브 편집기, 커스텀 게이지 같은 위젯을 직접 만들 수 있습니다. 자신의 프로젝트에서 반복적으로 필요한 UI 패턴을 재사용 가능한 함수로 뽑아내는 연습을 해보는 것을 권합니다.
- **ImGui 소스 코드 자체를 읽어보기**: 17장에서 언급했듯이 `imgui_demo.cpp`는 훌륭한 사용법 참고서이지만, 조금 더 시간을 들일 수 있다면 `imgui.cpp`와 `imgui_internal.h`를 직접 열어 ID 스택, 드로우 리스트, 레이아웃 커서가 내부적으로 어떻게 구현되어 있는지 따라가 보는 것을 추천합니다. 라이브러리 코드 자체의 양이 그리 많지 않아서, 이 책에서 다진 기초를 바탕으로 하면 생각보다 어렵지 않게 읽어낼 수 있을 것입니다.

즉시 모드라는 개념 하나로 시작해 여기까지 온 여정을 마칩니다. 이제 여러분의 손에는 여러분만의 도구를 만들 준비가 되어 있습니다.

## 요약

- 이번 장에서는 메인 메뉴 바, 도킹 가능한 패널, 테이블 기반 항목 목록, 타입별 값 편집 위젯, 저장 확인 모달을 하나로 엮어 설정 에디터를 완성했습니다.
- 14장의 상태 관리 원칙에 따라 모든 UI 상태를 `AppState` 구조체 하나로 묶고, 각 패널 함수는 이 구조체를 참조로 받아 읽고 쓰는 방식으로 설계했습니다.
- `ImGui::OpenPopup()`은 팝업을 열어야 하는 그 프레임에만 호출하고, `BeginPopupModal()`은 팝업이 열려 있는 동안 매 프레임 호출한다는 9장의 원칙을 실전 예제에 그대로 적용했습니다.
- 이 책 전체를 관통하는 두 가지 뼈대는 3장의 즉시 모드 원칙(위젯은 상태를 갖지 않는다)과 14장의 상태 관리 패턴(상태는 구조체로 모아 애플리케이션이 직접 관리한다)입니다.
- 앞으로는 실제 엔진과의 통합, 커스텀 위젯 라이브러리 제작, ImGui 소스 코드 직접 읽기 등을 통해 더 깊이 있는 활용으로 나아갈 수 있습니다.

## 연습문제

1. 이번 장의 설정 에디터에 "기본값으로 재설정" 버튼을 추가해, 클릭하면 모든 항목이 `InitializeDefaultSettings()`가 만든 초기값으로 되돌아가도록 구현해보세요. (단, `hasUnsavedChanges`도 적절히 갱신해야 합니다.)
2. `SettingItem`에 열거형(enum) 타입을 하나 추가해서, `ImGui::Combo()`로 여러 선택지 중 하나를 고르는 설정 항목을 만들어보세요.
3. 항목 목록 테이블 위에 텍스트 입력 필드를 추가해서, 입력한 문자열이 이름에 포함된 항목만 필터링해서 보여주는 기능을 구현해보세요. (7장 연습문제에서 다룬 필터링 아이디어를 참고하세요.)
4. 값 편집기 패널에서 편집 중인 항목이 하나도 저장되지 않았을 때, 창을 닫으려는 시도(운영체제의 창 닫기 버튼) 자체를 가로채서 저장 확인 모달을 띄우도록 확장해보세요.
5. `AppState`를 JSON이나 간단한 텍스트 포맷으로 실제 파일에 저장하고 프로그램 시작 시 다시 불러오도록 `SaveSettingsToDisk()`와 `LoadSettingsFromDisk()`를 완성해보세요.
