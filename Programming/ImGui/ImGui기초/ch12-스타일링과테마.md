# 12장. 스타일링과 테마

[◀ 이전: 11장. 커스텀 렌더링과 ImDrawList](ch11-커스텀렌더링과ImDrawList.md) | [📖 목차](00-목차.md) | [다음: 13장. 입력 처리 ▶](ch13-입력처리.md)


지금까지 만든 예제들은 모두 ImGui 기본 회색 톤 그대로였다. 기능을 검증하는 단계에서는 이 정도로 충분하지만, 실제 제품에 들어갈 도구창이라면 여백, 모서리, 색상 하나하나가 완성도를 좌우한다. 다행히 ImGui는 이런 시각적 요소를 거의 모두 하나의 구조체로 노출해두었기 때문에, 코드 몇 줄만으로도 전혀 다른 느낌의 UI를 만들 수 있다.

이 장에서는 `ImGuiStyle` 구조체를 통해 여백과 둥근 모서리 같은 수치를 조정하는 방법, `style.Colors` 배열로 색상을 바꾸는 방법, ImGui가 기본 제공하는 세 가지 테마, 그리고 한글을 화면에 표시하기 위한 폰트 로딩 방법을 차례로 다룬다.

## 12.1 ImGuiStyle 구조체

ImGui의 모든 시각적 파라미터는 `ImGuiStyle`이라는 하나의 구조체에 모여 있다. 이 구조체는 다음 함수로 접근한다.

```cpp
ImGuiStyle& style = ImGui::GetStyle();
```

반환값이 참조형이라는 점에 주목하자. 이 참조를 통해 값을 바로 수정하면 이후 그려지는 모든 위젯에 그 값이 즉시 반영된다. `ImGuiStyle`에는 수십 개의 필드가 있지만, 실무에서 자주 손을 대는 항목은 크게 여백류와 둥근 모서리류로 나뉜다.

**여백 관련 필드**

```cpp
style.WindowPadding   = ImVec2(12.0f, 12.0f); // 창 안쪽 여백
style.FramePadding    = ImVec2(8.0f, 4.0f);   // 버튼·입력창 등 프레임 내부 여백
style.ItemSpacing     = ImVec2(8.0f, 6.0f);   // 위젯 사이 간격
style.ItemInnerSpacing = ImVec2(6.0f, 6.0f);  // 위젯 내부 요소 간 간격(예: 체크박스와 라벨)
style.IndentSpacing   = 20.0f;                // 트리 노드 들여쓰기 폭
```

**둥근 모서리 관련 필드**

```cpp
style.WindowRounding    = 6.0f;  // 창 모서리
style.FrameRounding     = 4.0f;  // 버튼, 입력창, 체크박스 등
style.PopupRounding     = 6.0f;  // 팝업, 콤보 박스 드롭다운
style.ScrollbarRounding = 9.0f;  // 스크롤바
style.GrabRounding      = 4.0f;  // 슬라이더/스크롤바의 손잡이(grab)
```

**테두리 두께**

```cpp
style.WindowBorderSize = 1.0f;
style.FrameBorderSize  = 0.0f; // 0이면 테두리가 그려지지 않는다
```

이 값들은 프로그램 시작 시 한 번만 설정해도 되고, 특정 위젯 구간에서만 잠깐 바꿨다가 되돌리고 싶을 수도 있다. 후자의 경우 값을 직접 대입하는 대신 `PushStyleVar()` / `PopStyleVar()`를 짝으로 사용한다.

```cpp
ImGui::PushStyleVar(ImGuiStyleVar_FrameRounding, 12.0f);
ImGui::Button("둥근 버튼");
ImGui::PopStyleVar();
```

`Push`로 바꾼 값은 반드시 같은 개수만큼 `Pop`으로 되돌려야 한다. 이 짝 맞추기 규칙은 9장에서 다이얼로그나 팝업을 열고 닫을 때 스택을 다루던 방식과 동일한 원리이며, 이후 13장과 14장에서 상태에 따라 스타일을 임시로 바꾸는 패턴을 다룰 때도 계속 등장한다.

## 12.2 색상 커스터마이징

색상은 여백이나 둥근 모서리와 달리 하나의 필드가 아니라 배열로 관리된다.

```cpp
ImVec4* colors = style.Colors;
colors[ImGuiCol_Button] = ImVec4(0.20f, 0.45f, 0.80f, 1.00f);
```

`style.Colors`는 `ImGuiCol_` 열거형 값을 인덱스로 쓰는 `ImVec4` 배열이며, 전체 항목 개수는 `ImGuiCol_COUNT`다. 색상은 4장에서 다룬 컬러 위젯과 마찬가지로 R, G, B, A 각각 0.0~1.0 범위의 실수로 표현한다.

자주 다루게 되는 대표적인 항목은 다음과 같다.

| 열거자 | 대상 |
|---|---|
| `ImGuiCol_Text` | 기본 텍스트 색상 |
| `ImGuiCol_WindowBg` | 창 배경 |
| `ImGuiCol_FrameBg` / `FrameBgHovered` / `FrameBgActive` | 입력창, 콤보 박스 등의 배경 |
| `ImGuiCol_TitleBgActive` | 활성 창의 타이틀바 |
| `ImGuiCol_Button` / `ButtonHovered` / `ButtonActive` | 버튼의 기본/호버/눌림 상태 |
| `ImGuiCol_Header` / `HeaderHovered` / `HeaderActive` | 셀렉터블, 트리 노드, 메뉴 항목 등 |
| `ImGuiCol_CheckMark` | 체크박스 표시 |
| `ImGuiCol_SliderGrab` / `SliderGrabActive` | 슬라이더 손잡이 |
| `ImGuiCol_Tab` / `TabHovered` / `TabActive` | 탭 바 |

특정 버튼 하나만 잠깐 다른 색으로 강조하고 싶다면, 여백 값과 마찬가지로 `PushStyleColor()` / `PopStyleColor()`를 사용한다.

```cpp
ImGui::PushStyleColor(ImGuiCol_Button, ImVec4(0.80f, 0.20f, 0.20f, 1.00f));
ImGui::PushStyleColor(ImGuiCol_ButtonHovered, ImVec4(0.90f, 0.30f, 0.30f, 1.00f));
if (ImGui::Button("삭제"))
{
    // 삭제 처리
}
ImGui::PopStyleColor(2); // 두 번 Push했으므로 인자로 2를 넘겨 한 번에 되돌린다
```

`PopStyleColor()`와 `PopStyleVar()`는 정수 인자를 받아 여러 개를 한 번에 pop할 수 있다는 점도 기억해두면 코드가 한결 간결해진다.

## 12.3 내장 테마

매번 색상을 하나하나 지정하기보다, ImGui가 기본 제공하는 세 가지 프리셋에서 시작해 필요한 부분만 고치는 방식이 훨씬 효율적이다.

```cpp
ImGui::StyleColorsDark();    // 어두운 테마 (기본값)
ImGui::StyleColorsLight();   // 밝은 테마
ImGui::StyleColorsClassic(); // 예전 ImGui의 반투명한 보라빛 테마
```

세 함수 모두 `ImGuiStyle* dst = NULL`이라는 선택적 인자를 받는다. 인자를 생략하면 현재 활성 스타일(`GetStyle()`이 반환하는 것과 동일한 객체)에 바로 적용되고, 다른 `ImGuiStyle` 인스턴스를 넘기면 그 객체만 해당 프리셋 값으로 채워진다. 예를 들어 라이트/다크 테마를 런타임에 전환하는 기능을 만든다면 다음과 같이 쓸 수 있다.

```cpp
static bool dark_mode = true;
if (ImGui::Checkbox("다크 모드", &dark_mode))
{
    if (dark_mode)
        ImGui::StyleColorsDark();
    else
        ImGui::StyleColorsLight();
}
```

보통은 이 세 프리셋 중 하나를 기본값으로 호출한 다음, 12.5절처럼 회사나 프로젝트 고유의 색상 몇 가지만 덧씌우는 방식으로 테마를 완성한다.

## 12.4 폰트 로딩과 한글 지원

ImGui는 별도 설정이 없으면 내장된 기본 폰트를 사용하는데, 이 폰트는 라틴 알파벳과 기본 기호만 포함하고 있어 한글은 물론 한자, 일본어 등도 표시하지 못한다. 커스텀 TTF 폰트를 추가하려면 `ImGuiIO`의 `Fonts` 아틀라스를 사용한다.

```cpp
ImGuiIO& io = ImGui::GetIO();
ImFont* font = io.Fonts->AddFontFromFileTTF("C:/Windows/Fonts/malgun.ttf", 18.0f);
```

이 상태로는 여전히 한글이 깨져 보인다. TTF 파일 자체는 한글 글리프를 담고 있어도, ImGui는 메모리와 텍스처 용량을 아끼기 위해 **어떤 유니코드 범위의 글리프를 텍스처 아틀라스에 구울지**를 명시적으로 지정해야 하기 때문이다. 이 범위를 글리프 범위(glyph range)라고 하며, `ImFontAtlas`는 언어별로 미리 정의된 범위를 함수 형태로 제공한다.

```cpp
ImGuiIO& io = ImGui::GetIO();
ImFont* font = io.Fonts->AddFontFromFileTTF(
    "C:/Windows/Fonts/malgun.ttf",
    18.0f,
    nullptr,
    io.Fonts->GetGlyphRangesKorean());
```

`GetGlyphRangesKorean()`은 한글 자모와 완성형 한글 음절, 그리고 기본 라틴 문자까지 포함하는 범위를 반환한다. 이 밖에도 언어별로 다음과 같은 함수들이 준비되어 있다.

- `GetGlyphRangesJapanese()` — 일본어(히라가나, 가타카나, 상용 한자)
- `GetGlyphRangesChineseFull()` — 중국어 간체/번체 전체 (텍스처 용량이 크게 늘어난다)
- `GetGlyphRangesCyrillic()` — 키릴 문자
- `GetGlyphRangesThai()`, `GetGlyphRangesVietnamese()` 등

폰트를 여러 개 등록할 수도 있다. 이때 가장 먼저 추가한 폰트가 기본 폰트가 되고, 이후 추가한 폰트는 `ImGui::PushFont(font)` / `ImGui::PopFont()`로 특정 구간에서만 전환해 사용한다.

```cpp
ImGui::PushFont(font);
ImGui::Text("이 텍스트만 다른 폰트로 그려진다");
ImGui::PopFont();
```

폰트 로딩과 관련해 반드시 기억해야 할 순서가 하나 있다. 폰트를 추가하는 코드는 반드시 **렌더링 백엔드 초기화 이후, 그리고 메인 루프의 첫 `NewFrame()` 호출 이전**에 실행되어야 한다. `AddFontFromFileTTF()`가 호출되면 ImGui는 등록된 모든 폰트의 글리프를 하나의 텍스처 아틀라스 이미지로 합치는데, 이 아틀라스가 실제 GPU 텍스처로 업로드되는 시점은 백엔드의 초기화 루틴에서 처리되기 때문이다. 2장에서 다룬 초기화 순서를 다시 떠올려보면, 폰트 등록은 `ImGui_ImplXXX_Init()` 계열 함수 호출 직후, 메인 루프 진입 직전에 넣는 것이 가장 안전하다.

## 12.5 실전 예제: 커스텀 테마 함수 작성

여백, 둥근 모서리, 색상, 폰트를 각각 낱개로 설정하는 코드를 메인 함수에 흩어놓기보다, 하나의 함수로 묶어두면 유지보수가 훨씬 쉬워진다. 아래는 차분한 청록색 계열의 커스텀 테마를 적용하는 예제다.

```cpp
void ApplyCustomTheme()
{
    ImGuiStyle& style = ImGui::GetStyle();

    // 1. 어두운 테마를 기본값으로 깔고 시작한다
    ImGui::StyleColorsDark();

    // 2. 여백과 둥근 모서리 조정
    style.WindowPadding     = ImVec2(10.0f, 10.0f);
    style.FramePadding      = ImVec2(8.0f, 4.0f);
    style.ItemSpacing       = ImVec2(8.0f, 6.0f);
    style.WindowRounding    = 6.0f;
    style.FrameRounding     = 4.0f;
    style.PopupRounding     = 6.0f;
    style.ScrollbarRounding = 8.0f;
    style.GrabRounding      = 4.0f;
    style.WindowBorderSize  = 1.0f;
    style.FrameBorderSize   = 0.0f;

    // 3. 청록색 계열 색상으로 덮어쓰기
    ImVec4* colors = style.Colors;
    colors[ImGuiCol_WindowBg]        = ImVec4(0.10f, 0.12f, 0.13f, 1.00f);
    colors[ImGuiCol_TitleBgActive]   = ImVec4(0.10f, 0.35f, 0.38f, 1.00f);
    colors[ImGuiCol_FrameBg]         = ImVec4(0.16f, 0.18f, 0.20f, 1.00f);
    colors[ImGuiCol_FrameBgHovered]  = ImVec4(0.20f, 0.30f, 0.32f, 1.00f);
    colors[ImGuiCol_FrameBgActive]   = ImVec4(0.14f, 0.40f, 0.42f, 1.00f);
    colors[ImGuiCol_Button]          = ImVec4(0.14f, 0.45f, 0.48f, 1.00f);
    colors[ImGuiCol_ButtonHovered]   = ImVec4(0.18f, 0.55f, 0.58f, 1.00f);
    colors[ImGuiCol_ButtonActive]    = ImVec4(0.10f, 0.38f, 0.40f, 1.00f);
    colors[ImGuiCol_Header]          = ImVec4(0.14f, 0.45f, 0.48f, 0.60f);
    colors[ImGuiCol_HeaderHovered]   = ImVec4(0.18f, 0.55f, 0.58f, 0.80f);
    colors[ImGuiCol_HeaderActive]    = ImVec4(0.14f, 0.45f, 0.48f, 1.00f);
    colors[ImGuiCol_CheckMark]       = ImVec4(0.30f, 0.85f, 0.75f, 1.00f);
    colors[ImGuiCol_SliderGrab]      = ImVec4(0.30f, 0.75f, 0.70f, 1.00f);
    colors[ImGuiCol_SliderGrabActive] = ImVec4(0.35f, 0.85f, 0.80f, 1.00f);
    colors[ImGuiCol_Tab]             = ImVec4(0.12f, 0.30f, 0.32f, 1.00f);
    colors[ImGuiCol_TabHovered]      = ImVec4(0.18f, 0.55f, 0.58f, 1.00f);
    colors[ImGuiCol_TabActive]       = ImVec4(0.14f, 0.45f, 0.48f, 1.00f);
}
```

그리고 초기화 코드에서는 이렇게 한 줄만 호출하면 된다.

```cpp
// 백엔드 초기화(ImGui_ImplXXX_Init 등) 이후, 메인 루프 진입 이전
ApplyCustomTheme();

ImGuiIO& io = ImGui::GetIO();
io.Fonts->AddFontFromFileTTF("C:/Windows/Fonts/malgun.ttf", 18.0f,
                              nullptr, io.Fonts->GetGlyphRangesKorean());
```

이렇게 스타일 설정을 하나의 함수로 분리해두면, 이후 18장의 실전 프로젝트처럼 여러 화면과 위젯이 얽힌 규모 있는 앱에서도 테마 일관성을 유지하기 쉽고, 다크/라이트 두 벌의 테마 함수를 만들어 두었다가 런타임에 스위칭하는 것도 간단해진다.

## 요약

- `ImGui::GetStyle()`로 얻는 `ImGuiStyle` 참조를 통해 여백(`WindowPadding`, `FramePadding` 등)과 둥근 모서리(`WindowRounding`, `FrameRounding` 등) 같은 전역 수치를 조정할 수 있다.
- 색상은 `style.Colors[ImGuiCol_XXX]` 배열에 `ImVec4` 값을 대입해 바꾼다. 특정 구간에서만 임시로 바꾸려면 `PushStyleVar()`/`PopStyleVar()`, `PushStyleColor()`/`PopStyleColor()`를 짝으로 사용한다.
- `StyleColorsDark()`, `StyleColorsLight()`, `StyleColorsClassic()`은 ImGui가 기본 제공하는 세 가지 색상 프리셋이며, 보통 이 중 하나를 기본값으로 삼고 필요한 색상만 덮어써서 테마를 완성한다.
- 한글 등 비영어권 문자를 표시하려면 `io.Fonts->AddFontFromFileTTF()`에 `GetGlyphRangesKorean()` 같은 글리프 범위를 함께 전달해야 하며, 폰트 등록은 백엔드 초기화 이후 첫 프레임이 시작되기 전에 이뤄져야 한다.
- 여백, 색상, 폰트 설정을 `ApplyCustomTheme()` 같은 함수 하나로 모아두면 프로젝트 전체에 일관된 테마를 유지하기 쉽다.

## 연습문제

1. `ImGui::ShowStyleEditor()`를 호출해 ImGui가 기본 제공하는 스타일 편집 창을 열어보고, 그 창에서 값을 바꿨을 때 `ImGuiStyle`의 어떤 필드가 바뀌는지 몇 가지를 직접 대응시켜보자.
2. `StyleColorsLight()`를 호출한 뒤 `ImGuiCol_WindowBg`와 `ImGuiCol_Text` 색상만 골라 어두운 값으로 덮어써서, 밝은 테마 기반의 부분적 다크 UI를 만들어보자.
3. `PushStyleColor()`와 `PopStyleColor()`의 개수가 서로 맞지 않으면 어떤 문제가 발생할지 예상해보고, 실제로 개수를 다르게 호출해 결과를 확인해보자.
4. 한글 폰트를 로드할 때 `GetGlyphRangesKorean()` 인자를 빼고 실행하면 어떤 현상이 나타나는지 확인하고, 그 이유를 설명해보자.
5. 12.5절의 `ApplyCustomTheme()`를 참고하여 자신만의 색상 팔레트로 `ApplyMyTheme()` 함수를 작성하고, 체크박스로 기본 다크 테마와 서로 전환할 수 있게 만들어보자.
