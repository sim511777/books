# 15장. 플롯과 데이터 시각화

[◀ 이전: 14장. 상태 관리 패턴](ch14-상태관리패턴.md) | [📖 목차](00-목차.md) | [다음: 16장. 다양한 렌더링 백엔드 ▶](ch16-다양한렌더링백엔드.md)


지금까지 우리는 버튼, 슬라이더, 테이블처럼 사용자가 값을 입력하거나 목록을 훑어보는 위젯을 다뤘습니다. 하지만 프로그램이 다루는 데이터 중에는 표나 텍스트보다 그래프로 봐야 의미가 드러나는 것들이 있습니다. 초당 프레임 수의 변화, 센서에서 들어오는 값의 추이, 오디오 파형, 함수의 개형 같은 것들이죠. 이런 데이터를 그래프로 그리려면 Dear ImGui 코어만으로는 부족합니다. 이번 장에서는 Dear ImGui의 확장 라이브러리인 **ImPlot**을 사용해 실시간으로 갱신되는 그래프를 그리는 방법을 배웁니다.

## 15.1 ImGui 코어에는 그래프 기능이 없다

먼저 짚고 넘어가야 할 사실이 있습니다. Dear ImGui 코어 라이브러리에는 `ImGui::PlotLines()`와 `ImGui::PlotHistogram()`이라는 아주 단순한 함수가 이미 들어 있습니다. `float` 배열을 넘기면 선 그래프나 막대 그래프 모양의 위젯 하나를 그려 주는 함수인데, 축 눈금도 마음대로 조절할 수 없고 여러 시리즈를 겹쳐 그리거나 마우스로 확대·축소하는 것도 불가능합니다. 디버그 오버레이에 값 하나의 대략적인 추세를 보여 주는 용도로는 쓸 만하지만, "데이터 시각화"라고 부르기에는 기능이 너무 제한적입니다.

본격적인 그래프, 즉 여러 축과 여러 데이터 시리즈를 가지고, 범례를 표시하고, 드래그로 확대·축소하고, 마우스를 올리면 좌표를 읽어 주는 그래프가 필요하다면 **ImPlot**이라는 별도 라이브러리를 가져와야 합니다. ImPlot은 Dear ImGui와 마찬가지로 Omar Cornut이 만든 코어에 기여해 온 개발자 커뮤니티의 산물로, Dear ImGui의 저자와 같은 계열의 개발 문화에서 나온 확장 라이브러리입니다. Dear ImGui 위에서 동작하도록 설계되었지만 별도의 GitHub 저장소로 배포되며, 프로젝트에 직접 추가하고 초기화해 주어야 사용할 수 있습니다.

즉 우리가 2장에서 GLFW와 OpenGL3 백엔드를 별도로 초기화했던 것처럼, ImPlot도 "ImGui를 쓰면 자동으로 딸려 오는 기능"이 아니라 "필요하면 명시적으로 연동해야 하는 기능"이라는 점을 기억해 두시기 바랍니다.

## 15.2 ImPlot 프로젝트에 추가하기

ImPlot은 [https://github.com/epezent/implot](https://github.com/epezent/implot) 저장소에서 받을 수 있습니다. 구조는 Dear ImGui 본체와 비슷합니다. `implot.h`, `implot.cpp`, `implot_internal.h`, `implot_items.cpp` 몇 개의 파일로 구성되어 있고, 별도의 빌드 시스템 없이 여러분의 프로젝트 소스에 그대로 포함시켜 컴파일하면 됩니다. 2장에서 `imgui.h`, `imgui_impl_glfw.h`, `imgui_impl_opengl3.h`를 프로젝트에 추가했던 것과 같은 방식으로, ImPlot 소스 파일들을 빌드 대상에 추가하기만 하면 됩니다.

단, ImPlot은 Dear ImGui 코어에 의존하므로 반드시 Dear ImGui보다 나중에, 그리고 같은 버전 계열의 Dear ImGui와 함께 사용해야 합니다. Dear ImGui의 내부 구조가 바뀌면 ImPlot도 이에 맞춰 갱신되므로, 두 라이브러리의 버전을 너무 동떨어지게 섞어 쓰지 않도록 주의합니다.

## 15.3 컨텍스트 생성과 해제

Dear ImGui가 `ImGui::CreateContext()`로 전역 상태를 초기화했던 것을 기억하실 겁니다. ImPlot도 동일한 패턴을 따릅니다. ImGui 컨텍스트를 만든 뒤, ImPlot 컨텍스트를 별도로 하나 더 만들어 주어야 합니다.

```cpp
// 초기화 단계 (2장의 초기화 코드 이후)
IMGUI_CHECKVERSION();
ImGui::CreateContext();
ImPlot::CreateContext();   // ImPlot 컨텍스트 추가 생성

ImGuiIO& io = ImGui::GetIO();
// ... 플랫폼/렌더러 백엔드 초기화 (ImGui_ImplGlfw_InitForOpenGL 등) ...
```

프로그램을 종료할 때도 마찬가지로 짝을 맞춰 컨텍스트를 정리합니다. ImPlot 컨텍스트는 ImGui 컨텍스트를 내부적으로 참조하므로, ImGui 컨텍스트보다 먼저 소멸시켜야 합니다.

```cpp
// 종료 단계
ImPlot::DestroyContext();
ImGui::DestroyContext();
```

이 두 줄만 추가하면 준비는 끝입니다. 별도의 렌더러 초기화는 필요 없습니다. ImPlot은 내부적으로 Dear ImGui의 `ImDrawList`에 그림을 그리기 때문에, 우리가 이미 갖추고 있는 렌더링 파이프라인을 그대로 재사용합니다.

## 15.4 첫 번째 플롯 그리기

ImPlot의 기본 사용 패턴은 Dear ImGui의 창 사용법과 놀랍도록 닮아 있습니다. `ImGui::Begin()` / `ImGui::End()` 쌍이 창 하나를 나타냈던 것처럼, `ImPlot::BeginPlot()` / `ImPlot::EndPlot()` 쌍이 플롯(그래프 좌표 영역) 하나를 나타냅니다. `BeginPlot()`이 `false`를 반환하면 플롯이 화면에 보이지 않는 상태(접혀 있거나 가려진 상태)이므로, 그 사이의 그리기 함수들을 건너뛰어야 합니다.

```cpp
static float xs[100], ys[100];
for (int i = 0; i < 100; ++i) {
    xs[i] = i * 0.1f;
    ys[i] = sinf(xs[i]);
}

if (ImPlot::BeginPlot("사인 곡선")) {
    ImPlot::PlotLine("sin(x)", xs, ys, 100);
    ImPlot::EndPlot();
}
```

이 코드는 반드시 `ImGui::Begin()` / `ImGui::End()`로 만든 창 안, 그리고 매 프레임 반복되는 GUI 코드 흐름 속에 위치해야 합니다. ImPlot 역시 즉시 모드 방식이므로 3장에서 배운 원칙, 즉 "그리려는 상태를 매 프레임 다시 선언한다"는 원칙이 그대로 적용됩니다.

`BeginPlot()`을 호출하면 자동으로 X축과 Y축, 격자선, 마우스 드래그를 이용한 팬(pan)과 확대·축소, 마우스 오버 시 좌표 표시 기능까지 함께 제공됩니다. 별도로 구현할 필요 없이 기본으로 딸려 오는 기능들입니다.

## 15.5 다양한 플롯 유형

ImPlot은 선 그래프 외에도 여러 종류의 플롯 함수를 제공합니다. `BeginPlot()`과 `EndPlot()` 사이에서는 이런 함수들을 여러 번 호출해서 하나의 좌표계 위에 여러 데이터 시리즈를 겹쳐 그릴 수 있습니다.

```cpp
static float xs[50], bar_ys[50], scatter_ys[50];
for (int i = 0; i < 50; ++i) {
    xs[i] = (float)i;
    bar_ys[i] = 10.0f + (i % 5);
    scatter_ys[i] = 8.0f + sinf(i * 0.3f) * 3.0f;
}

if (ImPlot::BeginPlot("혼합 플롯")) {
    ImPlot::PlotBars("막대", xs, bar_ys, 50, 0.6f);
    ImPlot::PlotScatter("산점도", xs, scatter_ys, 50);
    ImPlot::EndPlot();
}
```

- `ImPlot::PlotLine()`: 점들을 선으로 이어 그리는 선 그래프. 시간에 따른 값 변화를 보여 줄 때 가장 많이 쓰입니다.
- `ImPlot::PlotBars()`: 막대 그래프. 네 번째 인자로 넘긴 폭만큼 각 막대의 너비가 정해집니다.
- `ImPlot::PlotScatter()`: 점만 찍는 산점도. 선으로 잇지 않고 개별 데이터 포인트의 분포를 보고 싶을 때 사용합니다.

각 플롯 함수의 첫 번째 인자는 시리즈 이름입니다. 이 이름은 플롯 우측 상단(또는 설정한 위치)의 범례에 표시되며, 동시에 4장에서 배운 위젯 ID 규칙과 마찬가지로 시리즈를 구분하는 식별자 역할도 합니다. 같은 플롯 안에서 이름이 겹치는 시리즈는 같은 범례 항목으로 취급되니 주의합니다.

이 외에도 ImPlot에는 `PlotShaded()`(영역 채우기), `PlotStems()`(줄기 그래프), `PlotPieChart()`(원 그래프), `PlotHeatmap()`(히트맵) 등 다양한 함수가 준비되어 있습니다. 필요에 따라 공식 저장소의 `implot_demo.cpp`를 참고해 원하는 유형을 찾아 쓰면 됩니다.

## 15.6 실전 예제: 실시간으로 갱신되는 라인 그래프

ImPlot이 가장 빛을 발하는 상황은 정적인 데이터를 한 번 그려 놓고 끝내는 것이 아니라, 매 프레임 새로운 값이 들어오는 데이터를 실시간으로 갱신해서 보여 줄 때입니다. 프레임레이트 모니터, 센서 값 추이 그래프 같은 것이 대표적인 예입니다. 이번 절에서는 순환 버퍼(circular buffer)에 최근 N개의 값을 저장하고, 매 프레임 새 값을 밀어 넣으면서 그래프를 갱신하는 방법을 만들어 보겠습니다.

### 순환 버퍼 구조 설계

전체 이력을 계속 배열에 쌓다 보면 시간이 지날수록 배열이 무한히 커집니다. 실시간 모니터링에는 "최근 N개"만 있으면 충분하므로, 크기가 고정된 순환 버퍼를 사용하는 것이 일반적입니다.

```cpp
struct ScrollingBuffer {
    int MaxSize;
    int Offset;
    ImVector<ImVec2> Data;

    ScrollingBuffer(int max_size = 2000) {
        MaxSize = max_size;
        Offset = 0;
        Data.reserve(MaxSize);
    }

    void AddPoint(float x, float y) {
        if (Data.size() < MaxSize) {
            Data.push_back(ImVec2(x, y));
        } else {
            Data[Offset] = ImVec2(x, y);
            Offset = (Offset + 1) % MaxSize;
        }
    }

    void Erase() {
        Data.shrink(0);
        Offset = 0;
    }
};
```

`ImVector`는 Dear ImGui가 내부적으로 사용하는 가벼운 동적 배열 컨테이너로, `implot.h`가 `imgui.h`를 포함하고 있으므로 별도 헤더 없이 바로 사용할 수 있습니다. 데이터가 `MaxSize`에 도달하기 전까지는 뒤에 계속 추가하다가, 가득 차면 가장 오래된 항목이 있던 자리를 덮어쓰는 방식으로 동작합니다.

### 프레임타임 그래프 예제

이 순환 버퍼를 이용해 프레임레이트 변화를 그리는 예제를 완성해 보겠습니다.

```cpp
void ShowFrameRatePlot()
{
    static ScrollingBuffer buffer;
    static float t = 0.0f;

    ImGuiIO& io = ImGui::GetIO();
    t += io.DeltaTime;
    buffer.AddPoint(t, io.Framerate);

    ImGui::Begin("프레임레이트 모니터");
    ImGui::Text("현재 FPS: %.1f", io.Framerate);

    if (ImPlot::BeginPlot("##FPS", ImVec2(-1, 200))) {
        ImPlot::SetupAxes("시간(초)", "FPS",
                           ImPlotAxisFlags_None,
                           ImPlotAxisFlags_AutoFit);
        // X축은 항상 최근 10초 구간만 보여 준다
        ImPlot::SetupAxisLimits(ImAxis_X1, t - 10.0, t, ImGuiCond_Always);

        ImPlot::PlotLine("FPS", &buffer.Data[0].x, &buffer.Data[0].y,
                          buffer.Data.size(), 0, buffer.Offset, sizeof(ImVec2));
        ImPlot::EndPlot();
    }
    ImGui::End();
}
```

몇 가지 눈여겨볼 부분이 있습니다.

첫째, `ImGuiIO`의 `DeltaTime`과 `Framerate`는 13장에서 다룬 것처럼 Dear ImGui가 매 프레임 자동으로 계산해 주는 값입니다. 이 값을 그대로 순환 버퍼에 밀어 넣기만 하면 데이터 소스로 충분합니다.

둘째, `ImPlot::SetupAxisLimits()`에 `ImGuiCond_Always`를 넘겨서 X축의 범위를 매 프레임 "현재 시각부터 10초 전까지"로 강제로 고정했습니다. 이렇게 하면 그래프가 마치 오실로스코프처럼 최근 구간만 계속 보여 주면서 오른쪽으로 흘러가는 형태가 됩니다.

셋째, `PlotLine()`의 오버로드 중 스트라이드(stride)를 지정하는 버전을 사용했습니다. `buffer.Data`는 `ImVec2` 배열이므로 `x`와 `y`가 메모리에 나란히 붙어 있는데, `sizeof(ImVec2)`를 스트라이드로 넘기면 이 배열에서 바로 x, y 좌표 쌍을 읽어 낼 수 있습니다. 별도로 x 배열과 y 배열을 분리해서 관리할 필요가 없어 코드가 한결 간결해집니다. 마지막에서 두 번째 인자로 넘긴 `buffer.Offset`은 순환 버퍼에서 가장 오래된 데이터가 시작되는 위치로, ImPlot이 버퍼를 올바른 시간 순서로 이어 그릴 수 있게 해 줍니다.

이 패턴은 프레임레이트뿐 아니라 메모리 사용량, 네트워크 지연 시간, 온도 센서 값 등 "시간에 따라 흐르는 숫자 하나"를 다루는 모든 상황에 그대로 재사용할 수 있습니다. 버퍼 구조체와 갱신 로직은 그대로 두고 `AddPoint()`에 넘기는 값의 출처만 바꾸면 되기 때문입니다.

## 15.7 게임과 툴 개발에서의 활용

ImPlot은 학술적인 데이터 분석 도구로만 쓰이는 것이 아닙니다. 오히려 실무에서는 게임이나 실시간 애플리케이션의 **디버그 오버레이**로 사용되는 경우가 아주 흔합니다. 프레임 시간이 어느 구간에서 튀는지, 특정 서브시스템의 메모리 사용량이 시간이 지나며 어떻게 변하는지, 물리 시뮬레이션의 특정 변수가 발산하고 있지는 않은지를 실시간 그래프로 지켜보면, 로그를 텍스트로 훑어보는 것보다 훨씬 빠르게 이상 징후를 포착할 수 있습니다.

11장에서 다룬 `ImDrawList`를 이용해 이런 그래프를 직접 그릴 수도 있겠지만, 축 스케일 조정, 범례, 확대·축소, 여러 시리즈 겹쳐 그리기 같은 기능을 매번 손으로 구현하는 것은 비효율적입니다. ImPlot은 이런 기능을 이미 검증된 형태로 제공하므로, "지금 이 순간 프로그램 내부에서 무슨 일이 벌어지고 있는가"를 보여 주는 진단 도구를 아주 적은 코드로 붙일 수 있습니다. 14장에서 다룬 상태 관리 패턴과 결합하면, 애플리케이션의 핵심 상태 값 몇 가지를 골라 항상 떠 있는 디버그 창에 실시간 그래프로 띄워 두는 구성도 어렵지 않게 만들 수 있습니다.

## 요약

- Dear ImGui 코어에는 `PlotLines()`, `PlotHistogram()` 같은 아주 단순한 그래프 함수만 있으며, 본격적인 데이터 시각화에는 별도 확장 라이브러리인 **ImPlot**이 필요합니다.
- ImPlot은 Dear ImGui 코어와 별도의 저장소로 배포되며, 프로젝트에 소스를 직접 추가하고 `ImPlot::CreateContext()` / `ImPlot::DestroyContext()`로 컨텍스트를 초기화·해제해야 합니다.
- 플롯 하나는 `ImPlot::BeginPlot()` / `ImPlot::EndPlot()` 쌍으로 감싸며, 그 사이에서 `PlotLine()`, `PlotBars()`, `PlotScatter()` 등을 호출해 데이터를 그립니다.
- 실시간 그래프는 고정 크기 순환 버퍼에 최근 N개의 값을 저장하고, 매 프레임 새 값을 추가한 뒤 `SetupAxisLimits()`로 표시 구간을 갱신하는 방식으로 구현합니다.
- ImPlot은 게임이나 툴 개발에서 프레임타임, 메모리 사용량 같은 값을 실시간 디버그 그래프로 시각화하는 용도로 특히 유용합니다.

## 연습문제

1. `ImGui::PlotLines()`와 ImPlot의 `PlotLine()`은 무엇이 다른지, 각각 어떤 상황에 적합한지 설명해 보세요.
2. 15.6절의 `ScrollingBuffer`를 참고하여, 마우스 커서의 초당 이동 거리를 계산해 실시간 그래프로 그려 보세요.
3. 하나의 `BeginPlot()`/`EndPlot()` 안에 `PlotLine()`을 두 번 호출해서 서로 다른 두 데이터 시리즈를 겹쳐 그리고, 범례가 어떻게 표시되는지 확인해 보세요.
4. `SetupAxisLimits()`에 `ImGuiCond_Always` 대신 `ImGuiCond_Once`를 넘기면 15.6절의 예제 동작이 어떻게 달라지는지 실행해서 비교해 보세요.
5. 8장에서 배운 테이블과 이번 장의 플롯을 같은 창 안에 나란히 배치해서, 표 형태의 원본 수치와 그래프를 동시에 보여 주는 화면을 구성해 보세요.
