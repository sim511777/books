# 18장. 실전 프로젝트: 미니 게임 만들기

[◀ 이전: 17장. 파일 입출력과 세이브/로드](ch17-파일입출력과세이브로드.md) | [📖 목차](00-목차.md) | [다음: 부록 ▶](appendix-부록.md)


지금까지 열일곱 개 장을 거치며 게임 루프, 입력 처리, 벡터, 텍스처와 애니메이션, 충돌 감지, 오디오, 상태 관리, 파티클, 세이브/로드까지 raylib로 게임을 만드는 데 필요한 재료를 하나씩 배웠습니다. 이번 마지막 장에서는 이 재료들을 한데 모아, 시작 화면부터 승리·패배 화면까지 갖춘 완결된 미니 게임을 처음부터 끝까지 만들어 봅니다.

## 게임 기획: 벽돌깨기(Breakout)

만들 게임은 고전 아케이드 게임 "벽돌깨기(Breakout)"입니다. 벽돌깨기를 고른 이유는 단순합니다. 원-사각형 충돌(8장), 벡터 기반 이동(5장), 여러 화면 사이의 상태 전환(15장), 타격 이펙트로서의 파티클(16장), 효과음(9장)까지 이 책에서 다룬 핵심 개념 대부분이 아주 자연스럽게 필요해지는 장르이기 때문입니다.

본격적으로 코드를 작성하기 전에, 요구사항을 먼저 정리해 봅시다.

- **공(ball)**: 화면 위를 일정한 속도로 움직이며, 벽·패들·벽돌에 부딪히면 방향을 반사한다.
- **패들(paddle)**: 화면 하단에서 좌우 화살표 키로 조작하는 사각형. 화면 밖으로 나가지 않는다.
- **벽돌 배열(bricks)**: 화면 상단에 행과 열로 배치된 사각형들. 공에 맞으면 사라지고 점수를 준다.
- **점수(score)**: 벽돌을 깰 때마다 증가하며 화면에 표시된다.
- **목숨(lives)**: 공을 패들로 받아내지 못하고 화면 아래로 떨어뜨리면 하나씩 줄어든다.
- **승리 조건**: 모든 벽돌을 다 깨면 승리.
- **패배 조건**: 목숨이 0이 되면 패배.
- **화면 전환**: 시작 화면 → 플레이 화면 → (승리 또는 패배 화면) → Enter 키로 재시작.

이 요구사항을 하나씩 코드로 옮기되, 자료구조 정의 → 초기화 → 업데이트 로직 → 그리기 로직 → 메인 루프 순서로 단계적으로 구성하겠습니다. 아래 코드 조각들은 순서대로 이어 붙이면 그대로 컴파일되는 하나의 프로그램이 됩니다.

## 1단계: 자료구조 정의

가장 먼저 게임에 등장하는 개체들을 구조체로 정의하고, 게임 전체의 상태를 담을 전역 변수를 선언합니다. 게임의 진행 단계는 15장에서 다룬 것처럼 열거형(`enum`)으로 표현합니다.

```c
#include "raylib.h"
#include "raymath.h"
#include <math.h>

#define SCREEN_WIDTH  800
#define SCREEN_HEIGHT 450
#define BRICK_ROWS    5
#define BRICK_COLS    10
#define MAX_PARTICLES 150
#define MAX_LIVES     3

// 15장: 게임 진행 단계를 나타내는 상태 열거형
typedef enum {
    STATE_MENU,
    STATE_PLAYING,
    STATE_GAMEOVER,
    STATE_WIN
} GameState;

typedef struct {
    Rectangle rect;
    Color color;
    bool alive;
} Brick;

typedef struct {
    Rectangle rect;
    float speed;
} Paddle;

typedef struct {
    Vector2 position;   // 5장: 위치를 Vector2로 관리
    Vector2 velocity;   // 5장: 이동 방향과 속력을 Vector2로 관리
    float radius;
} Ball;

// 16장 스타일의 파티클: 벽돌이 깨질 때 흩어지는 조각 이펙트
typedef struct {
    Vector2 position;
    Vector2 velocity;
    float life;
    float maxLife;
    Color color;
    bool active;
} Particle;

// 전역 게임 상태
GameState state = STATE_MENU;
Paddle paddle;
Ball ball;
Brick bricks[BRICK_ROWS][BRICK_COLS];
Particle particles[MAX_PARTICLES];
int score = 0;
int lives = MAX_LIVES;

Sound sfxBounce;
Sound sfxBreak;
Sound sfxLoseLife;

// 함수 프로토타입
void InitGame(void);
void ResetBall(void);
void EmitParticles(Vector2 origin, int count, Color color);
void UpdateParticles(void);
void DrawParticles(void);
void UpdateGame(void);
void DrawGame(void);
```

`Brick`, `Paddle`, `Ball`은 각각 게임에 등장하는 물체 하나를 표현하는 작은 구조체입니다. `Rectangle`과 `Vector2`는 이미 3장과 5장에서 익숙해진 raylib의 기본 타입을 그대로 재사용하고 있습니다. 벽돌은 5행 10열의 2차원 배열 `bricks[BRICK_ROWS][BRICK_COLS]`로 관리하는데, 이렇게 하면 "몇 번째 행, 몇 번째 열의 벽돌"을 자연스러운 인덱스로 다룰 수 있습니다.

## 2단계: 초기화

`InitGame` 함수는 게임을 새로 시작할 때 필요한 모든 것을 처음 상태로 되돌립니다. 패들과 공의 위치를 정하고, 벽돌 배열을 행마다 다른 색으로 채웁니다.

```c
void InitGame(void)
{
    paddle.rect = (Rectangle){ SCREEN_WIDTH / 2.0f - 50, SCREEN_HEIGHT - 30, 100, 15 };
    paddle.speed = 400.0f;

    ball.radius = 8.0f;
    ResetBall();

    // 행마다 다른 색을 입혀 시각적으로 구분한다
    Color rowColors[BRICK_ROWS] = { RED, ORANGE, GOLD, LIME, SKYBLUE };
    float brickWidth = 70.0f;
    float brickHeight = 20.0f;
    float marginX = (SCREEN_WIDTH - BRICK_COLS * (brickWidth + 4)) / 2.0f;

    for (int row = 0; row < BRICK_ROWS; row++)
    {
        for (int col = 0; col < BRICK_COLS; col++)
        {
            bricks[row][col].rect = (Rectangle){
                marginX + col * (brickWidth + 4),
                40.0f + row * (brickHeight + 4),
                brickWidth, brickHeight
            };
            bricks[row][col].color = rowColors[row];
            bricks[row][col].alive = true;
        }
    }

    for (int i = 0; i < MAX_PARTICLES; i++) particles[i].active = false;

    score = 0;
    lives = MAX_LIVES;
}

void ResetBall(void)
{
    // 공을 패들 바로 위에 재배치하고 대각선 위쪽으로 발사한다
    ball.position = (Vector2){ paddle.rect.x + paddle.rect.width / 2, paddle.rect.y - ball.radius - 1 };
    ball.velocity = (Vector2){ 200.0f, -250.0f };
}
```

벽돌의 x 좌표를 계산하는 `marginX + col * (brickWidth + 4)` 부분은 3장에서 익힌 사각형 좌표 계산의 연장선입니다. 열 번호(`col`)에 "벽돌 하나의 너비 + 여백"을 곱해 나가면 벽돌들이 나란히, 일정한 간격으로 배치됩니다. `ResetBall`을 별도 함수로 분리해둔 이유는 게임을 처음 시작할 때뿐 아니라, 공을 놓쳐 목숨을 잃은 뒤 다시 발사할 때도 똑같은 코드가 필요하기 때문입니다.

## 3단계: 업데이트 로직

업데이트 로직은 이 게임에서 가장 복잡한 부분이지만, 잘게 나누어 보면 지금까지 배운 개념들이 조합되어 있을 뿐입니다. 먼저 16장 스타일의 파티클 관리 함수를 정의합니다.

```c
void EmitParticles(Vector2 origin, int count, Color color)
{
    int emitted = 0;
    for (int i = 0; i < MAX_PARTICLES && emitted < count; i++)
    {
        if (particles[i].active) continue;

        float angle = (float)GetRandomValue(0, 360) * DEG2RAD;
        float speed = (float)GetRandomValue(40, 120);

        particles[i].position = origin;
        particles[i].velocity = (Vector2){ cosf(angle) * speed, sinf(angle) * speed };
        particles[i].maxLife = 0.5f;
        particles[i].life = particles[i].maxLife;
        particles[i].color = color;
        particles[i].active = true;
        emitted++;
    }
}

void UpdateParticles(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (!particles[i].active) continue;

        particles[i].life -= GetFrameTime();
        if (particles[i].life <= 0.0f) { particles[i].active = false; continue; }

        particles[i].position = Vector2Add(particles[i].position,
            Vector2Scale(particles[i].velocity, GetFrameTime()));
    }
}

void DrawParticles(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (!particles[i].active) continue;
        float alpha = particles[i].life / particles[i].maxLife;
        DrawCircleV(particles[i].position, 3.0f, Fade(particles[i].color, alpha));
    }
}
```

이제 게임의 심장부인 `UpdateGame`입니다. 15장에서 배운 대로, 가장 바깥쪽은 현재 상태에 따라 분기하는 `switch` 문으로 구성합니다.

```c
void UpdateGame(void)
{
    switch (state)
    {
        case STATE_MENU:
        {
            if (IsKeyPressed(KEY_ENTER)) state = STATE_PLAYING;
        } break;

        case STATE_PLAYING:
        {
            // 4장: 입력 처리 - 패들 이동
            if (IsKeyDown(KEY_LEFT))  paddle.rect.x -= paddle.speed * GetFrameTime();
            if (IsKeyDown(KEY_RIGHT)) paddle.rect.x += paddle.speed * GetFrameTime();
            paddle.rect.x = Clamp(paddle.rect.x, 0, SCREEN_WIDTH - paddle.rect.width);

            // 5장: 벡터에 델타타임을 곱해 프레임레이트와 무관하게 공을 이동
            ball.position = Vector2Add(ball.position, Vector2Scale(ball.velocity, GetFrameTime()));

            // 좌우 벽 충돌
            if ((ball.position.x - ball.radius <= 0) || (ball.position.x + ball.radius >= SCREEN_WIDTH))
            {
                ball.velocity.x *= -1;
                PlaySound(sfxBounce);
            }
            // 위쪽 벽 충돌
            if (ball.position.y - ball.radius <= 0)
            {
                ball.velocity.y *= -1;
                PlaySound(sfxBounce);
            }

            // 8장: 원-사각형 충돌 감지로 패들과의 충돌 판정
            if ((ball.velocity.y > 0) && CheckCollisionCircleRec(ball.position, ball.radius, paddle.rect))
            {
                ball.velocity.y *= -1;

                // 패들의 중심에서 얼마나 벗어난 지점에 맞았는지로 좌우 반사각을 조절한다
                float hitOffset = (ball.position.x - (paddle.rect.x + paddle.rect.width / 2))
                                   / (paddle.rect.width / 2);
                ball.velocity.x = hitOffset * 300.0f;
                PlaySound(sfxBounce);
            }

            // 8장: 벽돌 배열을 순회하며 원-사각형 충돌 검사
            for (int row = 0; row < BRICK_ROWS; row++)
            {
                for (int col = 0; col < BRICK_COLS; col++)
                {
                    Brick *brick = &bricks[row][col];
                    if (!brick->alive) continue;

                    if (CheckCollisionCircleRec(ball.position, ball.radius, brick->rect))
                    {
                        brick->alive = false;
                        score += 10;
                        ball.velocity.y *= -1;

                        // 16장: 벽돌이 있던 자리에서 파티클을 터뜨린다
                        Vector2 brickCenter = {
                            brick->rect.x + brick->rect.width / 2,
                            brick->rect.y + brick->rect.height / 2
                        };
                        EmitParticles(brickCenter, 15, brick->color);
                        PlaySound(sfxBreak);
                    }
                }
            }

            UpdateParticles();

            // 공을 놓쳤을 때: 목숨을 잃는다
            if (ball.position.y - ball.radius > SCREEN_HEIGHT)
            {
                lives--;
                PlaySound(sfxLoseLife);
                if (lives <= 0) state = STATE_GAMEOVER;  // 15장: 상태 전환
                else ResetBall();
            }

            // 승리 조건 검사: 살아있는 벽돌이 하나도 없으면 승리
            bool anyBrickLeft = false;
            for (int row = 0; row < BRICK_ROWS && !anyBrickLeft; row++)
            {
                for (int col = 0; col < BRICK_COLS; col++)
                {
                    if (bricks[row][col].alive) { anyBrickLeft = true; break; }
                }
            }
            if (!anyBrickLeft) state = STATE_WIN;   // 15장: 상태 전환
        } break;

        case STATE_GAMEOVER:
        case STATE_WIN:
        {
            UpdateParticles();   // 남은 파티클은 화면에서 계속 사그라들도록 갱신
            if (IsKeyPressed(KEY_ENTER))
            {
                InitGame();
                state = STATE_PLAYING;
            }
        } break;
    }
}
```

주목할 부분은 패들 충돌 시 `hitOffset`을 계산하는 코드입니다. 패들 정중앙에 맞으면 `hitOffset`이 0에 가까워 공이 거의 수직으로 튕기고, 패들 가장자리에 맞을수록 1 또는 -1에 가까워져 공이 더 비스듬히 튕겨 나갑니다. 이는 원작 벽돌깨기 게임들이 공통적으로 채택한 조작감으로, 5장에서 배운 벡터의 성분(`x`, `y`)을 상황에 맞게 독립적으로 조작하는 좋은 예시이기도 합니다.

또한 벽돌 충돌 검사에서 한 프레임에 여러 벽돌이 동시에 맞는 경우를 정교하게 처리하지 않고 단순히 `for` 루프를 끝까지 도는 점도 눈여겨보세요. 실전에서는 이 정도의 단순화로도 대부분 자연스럽게 동작하며, 더 정확한 충돌 처리(한 프레임에 하나의 벽돌만 반응하도록 `break`로 즉시 루프를 빠져나가는 방식 등)는 연습문제에서 직접 시도해 볼 수 있습니다.

## 4단계: 그리기 로직

`DrawGame`은 현재 상태에 따라 화면에 그릴 내용을 결정합니다. 플레이 화면, 게임오버 화면, 승리 화면은 벽돌·패들·공을 공통으로 그린 뒤 그 위에 상태별 오버레이만 다르게 얹는 방식으로 중복을 줄였습니다.

```c
void DrawGame(void)
{
    ClearBackground(RAYWHITE);

    switch (state)
    {
        case STATE_MENU:
        {
            const char *title = "벽돌깨기";
            int titleWidth = MeasureText(title, 40);
            DrawText(title, SCREEN_WIDTH / 2 - titleWidth / 2, 150, 40, DARKBLUE);

            const char *hint = "Enter 키를 눌러 시작하세요";
            int hintWidth = MeasureText(hint, 20);
            DrawText(hint, SCREEN_WIDTH / 2 - hintWidth / 2, 220, 20, GRAY);
        } break;

        case STATE_PLAYING:
        case STATE_GAMEOVER:
        case STATE_WIN:
        {
            // 3장: 사각형과 원을 이용한 기본 도형 그리기
            for (int row = 0; row < BRICK_ROWS; row++)
                for (int col = 0; col < BRICK_COLS; col++)
                    if (bricks[row][col].alive) DrawRectangleRec(bricks[row][col].rect, bricks[row][col].color);

            DrawRectangleRec(paddle.rect, DARKGRAY);
            DrawCircleV(ball.position, ball.radius, MAROON);
            DrawParticles();

            DrawText(TextFormat("점수: %d", score), 10, 10, 20, DARKGRAY);
            DrawText(TextFormat("목숨: %d", lives), SCREEN_WIDTH - 100, 10, 20, DARKGRAY);

            if (state == STATE_GAMEOVER)
            {
                DrawRectangle(0, 0, SCREEN_WIDTH, SCREEN_HEIGHT, Fade(BLACK, 0.5f));
                const char *msg = "GAME OVER";
                DrawText(msg, SCREEN_WIDTH / 2 - MeasureText(msg, 40) / 2, 180, 40, RED);
                const char *hint = "Enter 키를 눌러 다시 시작";
                DrawText(hint, SCREEN_WIDTH / 2 - MeasureText(hint, 20) / 2, 230, 20, RAYWHITE);
            }
            else if (state == STATE_WIN)
            {
                DrawRectangle(0, 0, SCREEN_WIDTH, SCREEN_HEIGHT, Fade(BLACK, 0.5f));
                const char *msg = "YOU WIN!";
                DrawText(msg, SCREEN_WIDTH / 2 - MeasureText(msg, 40) / 2, 180, 40, GREEN);
                const char *hint = "Enter 키를 눌러 다시 시작";
                DrawText(hint, SCREEN_WIDTH / 2 - MeasureText(hint, 20) / 2, 230, 20, RAYWHITE);
            }
        } break;
    }
}
```

게임오버·승리 화면에서 반투명한 검은 사각형(`Fade(BLACK, 0.5f)`)을 화면 전체에 덮어 그리는 것은 흔히 쓰이는 트릭입니다. 뒤에 있는 게임 장면이 살짝 비쳐 보이면서도 앞쪽 메시지가 잘 읽히는 효과를 아주 적은 코드로 얻을 수 있습니다.

## 5단계: 메인 루프로 통합하기

마지막으로 지금까지 만든 조각들을 하나의 `main` 함수로 엮습니다. 2~3장에서 배운 기본 게임 루프 구조(`InitWindow` → `while (!WindowShouldClose())` → `CloseWindow`) 위에, 9장에서 배운 오디오 초기화와 사운드 로딩을 추가합니다.

```c
int main(void)
{
    InitWindow(SCREEN_WIDTH, SCREEN_HEIGHT, "18장 - 벽돌깨기");

    InitAudioDevice();
    sfxBounce   = LoadSound("resources/bounce.wav");
    sfxBreak    = LoadSound("resources/break.wav");
    sfxLoseLife = LoadSound("resources/lose.wav");

    InitGame();

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        UpdateGame();

        BeginDrawing();
            DrawGame();
        EndDrawing();
    }

    UnloadSound(sfxBounce);
    UnloadSound(sfxBreak);
    UnloadSound(sfxLoseLife);
    CloseAudioDevice();

    CloseWindow();
    return 0;
}
```

`main` 함수 자체는 매우 짧습니다. 게임의 모든 복잡함이 `UpdateGame`과 `DrawGame`이라는 두 함수 뒤로 숨어 있기 때문입니다. 이렇게 "업데이트"와 "그리기"를 명확히 분리하고, 그 아래에 다시 "상태별 분기"를 두는 구조는 게임이 커질수록 진가를 발휘합니다. 새로운 화면(일시정지, 옵션 메뉴 등)을 추가하고 싶다면 `GameState`에 항목을 하나 더 늘리고, `UpdateGame`과 `DrawGame`의 `switch` 문에 `case`를 하나씩 추가하기만 하면 됩니다.

## 완성된 게임 확장하기

기본 골격이 완성되었다면, 다음과 같은 방향으로 직접 확장해 보는 것을 권합니다.

- **파워업 아이템**: 벽돌이 깨질 때 일정 확률로 아래로 천천히 떨어지는 아이템(예: `PowerUp` 구조체)을 만들고, 패들이 그 아이템과 충돌(8장)하면 패들이 일시적으로 넓어지거나, 공이 두 개로 늘어나거나(`Ball` 배열로 확장), 공 속도가 느려지는 등의 효과를 적용해 보세요. 효과 지속시간은 7장에서 다룬 타이머 누적 방식으로 관리할 수 있습니다.
- **여러 레벨**: 지금은 `InitGame` 안에서 행마다 같은 규칙으로 벽돌을 배치하지만, 레벨마다 다른 벽돌 배치를 2차원 배열이나 문자열(예: 한 줄에 `"XXXX...XX"`처럼 벽돌 유무를 표현)로 미리 정의해두고 레벨 번호에 따라 다른 배치를 불러오도록 확장할 수 있습니다. 17장에서 배운 `LoadFileText`를 이용해 레벨 데이터를 텍스트 파일로 분리해두면, 코드를 다시 컴파일하지 않고도 레벨을 추가하거나 수정할 수 있습니다.
- **사운드와 배경음악 강화**: 지금은 효과음 세 개만 사용했지만, 9장에서 다룬 `LoadMusicStream`/`UpdateMusicStream`으로 배경음악을 재생하고, 콤보(연속으로 벽돌을 깰 때)에 따라 효과음의 음높이(`SetSoundPitch`)를 조금씩 올려보는 것도 재미있는 시도입니다.
- **최고 점수 저장**: 17장에서 만든 세이브/로드 패턴을 그대로 가져와, `STATE_GAMEOVER`나 `STATE_WIN`에 진입하는 순간 현재 점수가 기존 최고 점수보다 높으면 `SaveFileData`로 갱신하고, 게임을 시작할 때 `LoadFileData`로 최고 점수를 불러와 화면에 표시해 보세요.

## 요약

- 완결된 미니 게임은 자료구조 정의 → 초기화 → 업데이트 로직 → 그리기 로직 → 메인 루프의 순서로 단계적으로 구성하면 관리하기 쉽습니다.
- 벽돌깨기는 원-사각형 충돌(8장), 벡터 기반 이동(5장), 상태 전환(15장), 파티클 이펙트(16장), 효과음(9장)이 자연스럽게 어우러지는 좋은 종합 실습 소재입니다.
- `UpdateGame`과 `DrawGame`을 현재 `GameState`에 따라 분기하는 구조로 설계하면, 시작 화면·플레이 화면·결과 화면처럼 여러 화면을 하나의 프로그램 안에서 깔끔하게 관리할 수 있습니다.
- 완성된 게임에 파워업, 여러 레벨, 배경음악, 최고 점수 저장 같은 기능을 추가해보면 이 책에서 배운 개념들을 더 깊이 있게 응용해볼 수 있습니다.

## 연습문제

1. 이 장의 완성 코드를 직접 입력하고 컴파일해서, 벽돌을 모두 깨면 승리 화면이, 목숨을 모두 잃으면 게임오버 화면이 뜨는지 확인해 보세요.
2. 벽돌 충돌 판정 부분을 수정해, 한 프레임에 하나의 벽돌만 반응하도록(`break`로 안쪽 루프를 즉시 빠져나가도록) 바꾸고, 수정 전후로 공의 움직임이 어떻게 달라지는지 관찰해 보세요.
3. "확장 아이디어"에서 제안한 파워업 아이템 중 하나(패들 확장 또는 공 속도 감소)를 직접 구현해 보세요. 아이템의 낙하, 패들과의 충돌 감지, 효과 지속시간 관리가 모두 필요합니다.
4. 벽돌 배열을 하드코딩하는 대신 문자열 배열로 레벨 데이터를 표현하고, 레벨을 두 개 이상 만들어 한 레벨을 클리어하면 다음 레벨로 넘어가도록 `STATE_WIN` 처리를 수정해 보세요.
5. 17장에서 배운 세이브/로드 기법을 적용해, 게임을 종료했다가 다시 실행해도 최고 점수가 유지되도록 구현해 보세요.
