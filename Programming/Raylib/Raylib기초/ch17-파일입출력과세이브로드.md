# 17장. 파일 입출력과 세이브/로드

[◀ 이전: 16장. 파티클 시스템과 이펙트](ch16-파티클시스템과이펙트.md) | [📖 목차](00-목차.md) | [다음: 18장. 실전 프로젝트: 미니 게임 만들기 ▶](ch18-실전프로젝트미니게임만들기.md)


지금까지 만든 예제들은 프로그램을 껐다 켜면 모든 것이 처음 상태로 돌아갔습니다. 점수도, 캐릭터 위치도, 애써 깬 벽돌도 다시 시작해야 했지요. 실제 게임이라면 플레이어가 "저장하기"를 누르고 나중에 이어서 할 수 있어야 합니다. 이번 장에서는 raylib가 제공하는 파일 입출력 유틸리티 함수를 이용해 게임 상태를 디스크에 저장하고 다시 불러오는 방법을 다룹니다. 마지막에는 8장의 충돌 감지와 16장의 파티클 이펙트가 들어간 작은 게임 상태를 통째로 세이브/로드하는 예제로 마무리합니다.

## raylib이 제공하는 파일 유틸리티

raylib는 표준 C의 `fopen`/`fread`/`fwrite`를 직접 다루지 않아도 되도록, 파일 하나를 통째로 읽고 쓰는 간단한 함수들을 제공합니다. 크게 "바이너리(이진) 파일용"과 "텍스트 파일용" 두 쌍으로 나뉩니다.

```c
// 바이너리 파일
unsigned char *LoadFileData(const char *fileName, int *dataSize);   // 파일 전체를 메모리로 읽어온다
void UnloadFileData(unsigned char *data);                           // LoadFileData로 읽은 메모리를 해제한다
bool SaveFileData(const char *fileName, void *data, int dataSize);  // 메모리 내용을 파일로 저장한다

// 텍스트 파일
char *LoadFileText(const char *fileName);        // 텍스트 파일 전체를 문자열로 읽어온다 ('\0'로 끝남)
void UnloadFileText(char *text);                 // LoadFileText로 읽은 메모리를 해제한다
bool SaveFileText(const char *fileName, char *text); // 문자열을 텍스트 파일로 저장한다

// 파일 존재 여부 확인
bool FileExists(const char *fileName);
```

이름 짓는 규칙이 눈에 익을 것입니다. `LoadTexture`/`UnloadTexture`, `LoadSound`/`UnloadSound`처럼, raylib는 리소스를 얻어오는 함수와 그 리소스를 해제하는 함수를 항상 `Load`/`Unload` 쌍으로 제공합니다. `LoadFileData`가 돌려주는 `unsigned char *`도 내부적으로 `malloc`으로 할당된 메모리이므로, 다 쓴 뒤에는 반드시 `UnloadFileData`로 해제해야 메모리 누수가 생기지 않습니다.

`SaveFileData`와 `SaveFileText`는 성공 여부를 `bool`로 돌려줍니다. 디스크가 꽉 찼거나 경로에 쓰기 권한이 없는 등, 저장이 실패할 수 있는 상황은 실제로 종종 벌어지므로 반환값을 확인하는 습관을 들이는 것이 좋습니다.

## 표준 C의 fopen/fwrite와의 관계

이 함수들이 하는 일은 사실 표준 C 라이브러리로도 똑같이 할 수 있습니다.

```c
#include <stdio.h>

bool SaveBytesManually(const char *fileName, void *data, int dataSize)
{
    FILE *f = fopen(fileName, "wb");
    if (f == NULL) return false;

    fwrite(data, dataSize, 1, f);
    fclose(f);
    return true;
}
```

`SaveFileData` 내부는 실제로 이와 거의 같은 `fopen`/`fwrite`/`fclose` 호출로 구현되어 있습니다. 그렇다면 왜 raylib가 감싸놓은 버전을 쓰는 것이 좋을까요?

- **플랫폼 차이를 감춰준다.** 안드로이드에서는 앱 리소스가 일반 파일 시스템이 아니라 APK 내부의 에셋으로 취급되고, 웹(Emscripten) 빌드에서는 브라우저의 가상 파일 시스템을 거쳐야 합니다. `LoadFileData`/`SaveFileData`는 이런 플랫폼별 차이를 함수 내부에서 처리해주므로, 같은 코드를 데스크톱과 모바일, 웹에 그대로 재사용할 수 있습니다.
- **실패 상황을 raylib의 로그 시스템으로 알려준다.** 파일을 못 열었을 때 `TraceLog`를 통해 경고 메시지를 자동으로 남겨주므로 디버깅이 편합니다.
- **나머지 raylib API와 일관된 스타일을 유지한다.** `Load`/`Unload` 쌍이라는 익숙한 패턴을 그대로 따르므로 배우기 쉽습니다.

즉 "표준 C로도 할 수 있는 일을 raylib 스타일로 감싸놓은 것"이며, 데스크톱 전용 프로그램을 만든다면 어느 쪽을 써도 결과는 같습니다. 이 책에서는 앞으로도 계속 raylib 함수 위주로 설명하지만, `fopen` 계열에 이미 익숙하다면 그대로 사용해도 전혀 문제가 없습니다.

## 게임 데이터를 구조체로 묶어 저장하기

가장 단순하고 실전에서도 흔히 쓰이는 방법은, 저장하고 싶은 값들을 구조체 하나로 묶은 뒤 그 구조체를 통째로 이진 데이터로 저장하는 것입니다.

```c
typedef struct {
    int score;
    int level;
    Vector2 playerPos;
} SaveData;
```

저장할 때는 이 구조체의 주소와 크기를 그대로 `SaveFileData`에 넘깁니다.

```c
SaveData data = { 1200, 3, (Vector2){ 350.0f, 220.0f } };

bool ok = SaveFileData("savegame.dat", &data, sizeof(SaveData));
if (!ok) TraceLog(LOG_WARNING, "세이브 파일을 저장하지 못했습니다.");
```

불러올 때는 `LoadFileData`로 파일 전체를 바이트 배열로 읽은 뒤, 그 크기가 구조체 크기와 맞는지 확인하고 `memcpy`로 복사합니다.

```c
#include <string.h>   // memcpy

SaveData LoadGame(void)
{
    SaveData data = { 0 };   // 파일이 없으면 돌려줄 기본값

    if (FileExists("savegame.dat"))
    {
        int bytesRead = 0;
        unsigned char *fileData = LoadFileData("savegame.dat", &bytesRead);

        if (fileData != NULL)
        {
            if (bytesRead == sizeof(SaveData)) memcpy(&data, fileData, sizeof(SaveData));
            else TraceLog(LOG_WARNING, "세이브 파일 크기가 예상과 다릅니다. 무시합니다.");

            UnloadFileData(fileData);
        }
    }

    return data;
}
```

이 방식이 편리한 이유는 구조체 안에 `int`, `float`, `Vector2`처럼 크기가 고정된 값들만 있다면, C 컴파일러가 메모리에 그 값들을 나란히 배치해두기 때문입니다. 그래서 구조체를 통째로 바이트 덩어리로 봐도, 나중에 같은 구조체 타입으로 다시 읽어들이면 값이 그대로 복원됩니다. 문자열처럼 크기가 가변적인 필드(`char *`)가 구조체 안에 있다면 이 방식은 그대로 쓸 수 없다는 점만 주의하면 됩니다(포인터 값 자체를 저장해봐야 다음 실행에서는 의미가 없는 주소이기 때문입니다). 고정 길이 배열(`char name[32]`)이라면 문제없이 함께 저장할 수 있습니다.

## 텍스트로 저장하기: 사람이 읽을 수 있는 설정 파일

점수나 위치처럼 자주 바뀌는 데이터는 이진 저장이 간편하지만, 옵션(음량, 전체화면 여부, 키 바인딩)처럼 사람이 직접 열어보거나 수정할 일이 있는 데이터라면 텍스트로 저장하는 편이 낫습니다. `TextFormat`으로 문자열을 조립해 `SaveFileText`로 저장할 수 있습니다.

```c
void SaveOptions(int volume, bool fullscreen)
{
    const char *content = TextFormat("volume=%d\nfullscreen=%d\n", volume, fullscreen ? 1 : 0);
    SaveFileText("options.txt", (char *)content);
}
```

`TextFormat`은 raylib가 내부적으로 관리하는 임시 버퍼에 문자열을 만들어 돌려주는 편의 함수로, `printf`처럼 서식 문자열을 쓸 수 있습니다. 반환된 포인터는 다음 `TextFormat` 호출 전까지만 유효하므로, 여기서처럼 곧바로 사용하고 오래 보관하지 않는 것이 원칙입니다.

불러올 때는 `LoadFileText`로 문자열 전체를 읽은 뒤, `sscanf` 같은 표준 C 함수로 직접 파싱합니다.

```c
void LoadOptions(int *volume, bool *fullscreen)
{
    *volume = 100;
    *fullscreen = false;

    if (!FileExists("options.txt")) return;

    char *text = LoadFileText("options.txt");
    if (text != NULL)
    {
        int vol = 100, full = 0;
        sscanf(text, "volume=%d\nfullscreen=%d", &vol, &full);
        *volume = vol;
        *fullscreen = (full != 0);
        UnloadFileText(text);
    }
}
```

raylib는 JSON이나 INI 같은 형식을 직접 파싱해주지 않으므로, 형식이 복잡해지면 직접 파서를 작성하거나 외부 라이브러리를 붙여야 합니다. 이 책의 범위에서는 `key=value` 한 줄짜리 형식 정도로도 충분한 경우가 많습니다.

## 저장 파일 버전 관리

구조체를 통째로 저장하는 방식에는 한 가지 실무적인 함정이 있습니다. 게임을 업데이트하면서 `SaveData` 구조체에 필드를 추가하거나 순서를 바꾸면, 예전 버전으로 저장된 세이브 파일은 더 이상 새 구조체와 맞지 않게 됩니다. 예를 들어 `level` 필드 뒤에 `int coins`를 새로 추가했다고 합시다.

```c
typedef struct {
    int score;
    int level;
    int coins;        // 새로 추가된 필드
    Vector2 playerPos;
} SaveData;
```

이전 버전으로 저장된 파일은 `sizeof(SaveData)`가 이제 달라졌으므로, 앞서 작성한 `bytesRead == sizeof(SaveData)` 검사에 걸려 통째로 무시됩니다. 최악의 경우 크기 검사를 하지 않았다면, 파일의 바이트가 엉뚱한 필드에 잘못 매핑되어 말이 안 되는 값(음수 점수, 화면 밖 좌표 등)이 들어올 수도 있습니다.

이를 막는 가장 간단한 방법은 구조체 맨 앞에 버전 번호를 두는 것입니다.

```c
#define SAVE_VERSION 2

typedef struct {
    int version;
    int score;
    int level;
    int coins;
    Vector2 playerPos;
} SaveData;
```

파일을 불러올 때 크기뿐 아니라 `version` 필드도 함께 확인해서, 예상한 버전이 아니면 과감히 기본값으로 되돌리거나(가장 단순한 대응), 옛 버전 구조체로 다시 한번 읽어서 새 구조체로 옮겨주는 마이그레이션 코드를 추가합니다. 상용 게임까지는 아니더라도, 습작 프로젝트에서 구조체를 자주 고치게 될 이 책의 실습 단계에서도 버전 필드 하나 정도는 처음부터 넣어두는 습관을 들이는 것을 권합니다. 나중에 "왜 세이브 파일을 불러오면 캐릭터가 화면 밖으로 튕겨 나가지?" 같은 문제를 디버깅하는 시간을 크게 줄여줍니다.

## 통합 예제: 게임 상태 세이브/로드

지금까지 배운 내용을 모아, 8장의 원형-사각형 충돌과 16장 스타일의 파티클 이펙트가 있는 작은 장면을 만들고, 그 상태를 F5로 저장하고 F9로 불러오는 예제를 완성해 보겠습니다. 플레이어는 사각형으로, 보석은 원으로 표현하고, 보석을 먹을 때마다 점수가 오르며 파티클이 흩어집니다. 위쪽에서 떨어지는 위험 요소에 닿으면 목숨이 줄어듭니다.

```c
#include "raylib.h"
#include "raymath.h"
#include <string.h>
#include <math.h>

#define SAVE_VERSION 1
#define SAVE_FILE_NAME "savegame.dat"
#define MAX_PARTICLES 200

typedef struct {
    int version;
    int score;
    int lives;
    Vector2 playerPos;
} SaveData;

typedef struct {
    Vector2 position;
    Vector2 velocity;
    float life;
    float maxLife;
    Color color;
    bool active;
} Particle;

Particle particles[MAX_PARTICLES] = { 0 };

void EmitParticles(Vector2 origin, int count, Color color)
{
    int emitted = 0;
    for (int i = 0; i < MAX_PARTICLES && emitted < count; i++)
    {
        if (particles[i].active) continue;

        float angle = (float)GetRandomValue(0, 360) * DEG2RAD;
        float speed = (float)GetRandomValue(60, 160);

        particles[i].position = origin;
        particles[i].velocity = (Vector2){ cosf(angle) * speed, sinf(angle) * speed };
        particles[i].maxLife = 0.6f;
        particles[i].life = particles[i].maxLife;
        particles[i].color = color;
        particles[i].active = true;
        emitted++;
    }
}

void UpdateParticles(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (!particles[i].active) continue;

        particles[i].life -= GetFrameTime();
        if (particles[i].life <= 0.0f) { particles[i].active = false; continue; }

        particles[i].position = Vector2Add(particles[i].position,
            Vector2Scale(particles[i].velocity, GetFrameTime()));
    }
}

void DrawParticles(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (!particles[i].active) continue;
        float alpha = particles[i].life / particles[i].maxLife;
        DrawCircleV(particles[i].position, 4.0f, Fade(particles[i].color, alpha));
    }
}

bool SaveGame(int score, int lives, Vector2 playerPos)
{
    SaveData data = { SAVE_VERSION, score, lives, playerPos };
    return SaveFileData(SAVE_FILE_NAME, &data, sizeof(SaveData));
}

bool LoadGame(int *score, int *lives, Vector2 *playerPos)
{
    if (!FileExists(SAVE_FILE_NAME)) return false;

    int bytesRead = 0;
    unsigned char *fileData = LoadFileData(SAVE_FILE_NAME, &bytesRead);
    if (fileData == NULL) return false;

    bool success = false;
    if (bytesRead == sizeof(SaveData))
    {
        SaveData data;
        memcpy(&data, fileData, sizeof(SaveData));

        if (data.version == SAVE_VERSION)
        {
            *score = data.score;
            *lives = data.lives;
            *playerPos = data.playerPos;
            success = true;
        }
    }

    UnloadFileData(fileData);
    return success;
}

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;
    InitWindow(screenWidth, screenHeight, "17장 - 세이브 & 로드");

    Rectangle player = { 375, 380, 50, 20 };
    Vector2 gem = { (float)GetRandomValue(50, 750), (float)GetRandomValue(50, 300) };
    Vector2 hazard = { (float)GetRandomValue(50, 750), 0 };
    float hazardSpeed = 120.0f;

    int score = 0;
    int lives = 3;

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        // 입력 처리 (4장)
        float moveSpeed = 300.0f * GetFrameTime();
        if (IsKeyDown(KEY_LEFT))  player.x -= moveSpeed;
        if (IsKeyDown(KEY_RIGHT)) player.x += moveSpeed;
        player.x = Clamp(player.x, 0, screenWidth - player.width);

        // 위험 요소 낙하
        hazard.y += hazardSpeed * GetFrameTime();
        if (hazard.y > screenHeight)
        {
            hazard.x = (float)GetRandomValue(50, 750);
            hazard.y = 0;
        }

        // 충돌 감지 (8장): 보석 획득
        Vector2 playerCenter = { player.x + player.width / 2, player.y + player.height / 2 };
        if (CheckCollisionCircleRec(gem, 12.0f, player))
        {
            score += 10;
            EmitParticles(gem, 20, GOLD);
            gem = (Vector2){ (float)GetRandomValue(50, 750), (float)GetRandomValue(50, 300) };
        }

        // 충돌 감지 (8장): 위험 요소에 닿으면 목숨 감소
        if (CheckCollisionCircleRec(hazard, 10.0f, player))
        {
            lives--;
            EmitParticles(hazard, 25, RED);
            hazard.y = 0;
            hazard.x = (float)GetRandomValue(50, 750);
            if (lives < 0) lives = 0;
        }

        UpdateParticles();

        // 세이브 / 로드
        if (IsKeyPressed(KEY_F5))
        {
            if (SaveGame(score, lives, playerCenter)) TraceLog(LOG_INFO, "게임을 저장했습니다.");
        }
        if (IsKeyPressed(KEY_F9))
        {
            Vector2 loadedPos;
            if (LoadGame(&score, &lives, &loadedPos))
            {
                player.x = loadedPos.x - player.width / 2;
                player.y = loadedPos.y - player.height / 2;
                TraceLog(LOG_INFO, "세이브 파일을 불러왔습니다.");
            }
        }

        BeginDrawing();
            ClearBackground(RAYWHITE);

            DrawRectangleRec(player, DARKBLUE);
            DrawCircleV(gem, 12.0f, GOLD);
            DrawCircleV(hazard, 10.0f, RED);
            DrawParticles();

            DrawText(TextFormat("점수: %d", score), 10, 10, 20, DARKGRAY);
            DrawText(TextFormat("목숨: %d", lives), 10, 35, 20, DARKGRAY);
            DrawText("F5: 저장   F9: 불러오기", 10, screenHeight - 30, 18, GRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

이 예제에서 세이브/로드 코드는 게임 로직과 완전히 분리되어 있습니다. `SaveGame`과 `LoadGame`은 `SaveData` 구조체 하나만 알면 되고, 게임 루프는 그저 알맞은 순간(F5, F9 입력 시점)에 이 두 함수를 호출할 뿐입니다. 이렇게 저장 로직을 게임 로직에서 분리해두면, 나중에 저장 방식을 이진 파일에서 클라우드 세이브나 텍스트 포맷으로 바꾸더라도 게임 루프 쪽 코드는 거의 건드릴 필요가 없습니다.

또한 `LoadGame`이 실패(파일 없음, 크기 불일치, 버전 불일치)하는 모든 경우에 `false`를 돌려주고 호출한 쪽의 기존 값을 그대로 두도록 설계했다는 점도 눈여겨보세요. 세이브 파일을 불러오는 코드는 "파일이 깨져 있거나 존재하지 않을 수 있다"는 것을 항상 전제로 작성해야, 게임이 예상치 못한 크래시 없이 안전하게 새 게임으로 넘어갈 수 있습니다.

## 요약

- raylib는 `LoadFileData`/`UnloadFileData`/`SaveFileData`로 바이너리 파일을, `LoadFileText`/`UnloadFileText`/`SaveFileText`로 텍스트 파일을 다룰 수 있는 유틸리티 함수를 제공합니다. `FileExists`로 파일 존재 여부를 미리 확인할 수 있습니다.
- 이 함수들이 하는 일은 표준 C의 `fopen`/`fwrite`/`fread`로도 똑같이 구현할 수 있지만, raylib 버전은 안드로이드나 웹 같은 플랫폼의 파일 시스템 차이를 감춰주고 실패 시 자동으로 로그를 남겨준다는 이점이 있습니다.
- 저장할 데이터를 고정 크기 필드로만 이루어진 구조체(`SaveData`)로 정의하면, 그 구조체를 통째로 `SaveFileData`로 저장하고 `LoadFileData` + `memcpy`로 복원하는 가장 단순한 방식을 쓸 수 있습니다.
- 구조체가 나중에 바뀌면 예전 세이브 파일과 크기·레이아웃이 달라질 수 있으므로, 구조체 맨 앞에 버전 번호 필드를 두고 불러올 때 크기와 버전을 함께 검사하는 습관을 들이는 것이 안전합니다.
- 저장/불러오기 로직을 게임 루프와 분리된 함수로 만들어두면, 저장 방식이 바뀌어도 게임 로직 쪽 코드에 영향이 거의 없습니다.

## 연습문제

1. 이 장의 통합 예제에 `int highScore` 필드를 추가하고, 게임을 시작할 때 세이브 파일이 있으면 자동으로 불러오도록(F9를 누르지 않아도) 수정해 보세요.
2. `SaveOptions`/`LoadOptions` 예제를 확장해, 음량과 전체화면 여부 외에 "마지막으로 선택한 캐릭터 이름"(문자열)도 함께 저장하고 불러오는 코드를 작성해 보세요. 문자열은 고정 길이 배열(`char name[32]`)로 구조체에 포함시키면 이진 저장 방식을 그대로 쓸 수 있습니다.
3. 통합 예제의 `SaveData`에 새로운 필드(예: `int gemsCollected`)를 추가해 `SAVE_VERSION`을 2로 올린 뒤, 버전 1로 저장된 예전 세이브 파일을 불러오려고 하면 어떤 일이 일어나는지 직접 확인해 보세요. 그리고 버전이 다를 때 예전 파일을 삭제하지 않고 기본값으로 안전하게 대체하는 코드가 실제로 동작하는지 테스트해 보세요.
4. `SaveFileData`가 `false`를 반환하는 상황을 인위적으로 만들어 보세요(예: 존재하지 않는 폴더 경로에 저장 시도). 실패 시 화면에 오류 메시지를 잠깐 표시하는 기능을 추가해 보세요.
5. 통합 예제를 응용해, 여러 개의 세이브 슬롯(`save1.dat`, `save2.dat`, `save3.dat`)을 지원하도록 `SaveGame`/`LoadGame` 함수에 슬롯 번호 매개변수를 추가해 보세요.
