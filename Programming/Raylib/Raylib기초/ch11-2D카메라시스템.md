지금까지 이 책의 예제들은 대부분 화면 좌표를 그대로 사용해왔다. `DrawRectangle(100, 100, 50, 50)`이라고 쓰면 화면의 왼쪽 위에서 오른쪽으로 100픽셀, 아래로 100픽셀 떨어진 자리에 사각형이 그려졌고, 그 좌표는 곧 게임 세계의 좌표이기도 했다. 작은 화면 하나에 게임의 모든 내용이 담기는 간단한 예제라면 이 방식으로도 충분하다.

하지만 실제 게임은 대부분 화면보다 훨씬 넓은 세계를 갖는다. 플레이어가 옆으로 걸어가면 배경이 함께 스크롤되는 횡스크롤 게임, 마우스 휠로 확대·축소하는 전략 게임의 맵, 플레이어를 화면 중앙에 고정한 채 주변 지형이 흘러가는 탑다운 게임을 떠올려보자. 이런 게임들은 모두 "게임 세계 안에서의 위치"와 "화면 위에 실제로 그려지는 위치"를 분리해서 다뤄야 한다. raylib는 이 문제를 `Camera2D`라는 구조체와 `BeginMode2D`/`EndMode2D` 함수 쌍으로 해결한다. 이번 장에서는 2D 카메라의 개념을 이해하고, 스크롤링과 줌, 좌표 변환까지 실전에서 자주 쓰이는 패턴을 하나씩 익혀본다.

## 왜 카메라가 필요한가

카메라 없이 게임 세계를 화면에 표시하는 방법을 상상해보자. 플레이어가 오른쪽으로 이동할 때 배경이 왼쪽으로 흐르는 것처럼 보이게 하려면, 화면에 그리는 모든 오브젝트의 좌표에서 플레이어의 이동량만큼을 일일이 빼주는 계산을 직접 해야 한다. 오브젝트가 수십, 수백 개라면 이 계산을 매 프레임 반복하는 코드는 금세 지저분해진다. 줌 기능까지 추가하려 하면 모든 좌표에 배율을 곱하는 계산까지 더해야 하니 코드는 더욱 복잡해진다.

`Camera2D`는 이런 반복적인 계산을 라이브러리 차원에서 대신 처리해준다. 개발자는 게임 세계 좌표 그대로 도형과 텍스처를 그리는 코드를 작성하고, raylib가 카메라 설정에 따라 그 좌표를 화면 좌표로 자동 변환해준다. 즉 "세계 좌표로 그리기"와 "그 결과를 어떻게 화면에 투영할지 결정하기"라는 두 가지 관심사를 깔끔하게 분리할 수 있다.

## Camera2D 구조체

`Camera2D`는 2D 카메라의 상태를 표현하는 구조체로, 다음 네 개의 필드를 갖는다.

```c
typedef struct Camera2D {
    Vector2 offset;     // 화면상에서 카메라 target이 위치할 지점
    Vector2 target;     // 카메라가 바라보는 게임 세계 좌표
    float rotation;     // 카메라 회전 각도 (도 단위)
    float zoom;         // 카메라 줌 배율 (1.0f가 기본)
} Camera2D;
```

각 필드의 역할을 하나씩 살펴보자.

- **target**: 카메라가 게임 세계에서 "바라보고 있는" 좌표다. 대부분의 경우 플레이어의 위치를 그대로 대입해서, 카메라가 플레이어를 중심에 두고 따라다니게 만든다.
- **offset**: `target`으로 지정한 세계 좌표가 화면의 어느 지점에 그려질지를 정한다. 예를 들어 화면 크기가 800×450이고 플레이어를 화면 정중앙에 두고 싶다면 `offset`을 `(400, 225)`로 설정한다. 그러면 `target`에 해당하는 세계 좌표가 화면 좌표 `(400, 225)`에 그려지고, 그 주변의 다른 오브젝트들은 상대적인 위치에 맞춰 배치된다.
- **rotation**: 카메라 자체를 회전시킨다. 도(degree) 단위이며, 값이 커질수록 시계 방향으로 세계 전체가 회전하는 것처럼 보인다. 레이싱 게임에서 차량의 진행 방향에 맞춰 화면을 기울이는 연출 등에 쓰인다.
- **zoom**: 카메라의 확대·축소 배율이다. 기본값은 `1.0f`이며, `2.0f`를 주면 세계가 두 배로 확대되어 보이고 `0.5f`를 주면 절반 크기로 축소되어 더 넓은 영역이 화면에 들어온다.

카메라를 사용하기 전에는 반드시 이 네 필드를 초기화해야 한다. 특히 `zoom`을 `0`으로 둔 채 그대로 사용하면 세계가 한 점으로 수축해 아무것도 보이지 않게 되므로 주의한다.

```c
Camera2D camera = { 0 };
camera.target = (Vector2){ 0.0f, 0.0f };
camera.offset = (Vector2){ 400.0f, 225.0f };
camera.rotation = 0.0f;
camera.zoom = 1.0f;
```

## BeginMode2D와 EndMode2D

카메라 설정을 실제로 그리기에 적용하려면 `BeginMode2D(camera)`와 `EndMode2D()` 사이에 그리기 함수를 호출하면 된다.

```c
void BeginMode2D(Camera2D camera);
void EndMode2D(void);
```

`BeginMode2D`와 `EndMode2D` 사이에서 호출한 `DrawRectangle`, `DrawCircle`, `DrawTexture` 같은 함수들은 모두 카메라가 적용된 좌표계, 즉 게임 세계 좌표를 기준으로 그려진다. 반대로 이 블록 밖에서 그린 것은 카메라의 영향을 받지 않고 화면 좌표 그대로 그려진다.

이 구분은 실전에서 매우 중요한 패턴으로 이어진다. 체력 바, 점수, 미니맵, 메뉴 같은 UI 요소는 카메라가 어디를 비추든 항상 화면의 같은 위치에 고정되어 있어야 한다. 반면 플레이어, 적, 배경, 아이템 같은 게임 세계의 실제 구성 요소는 카메라를 따라 함께 움직여야 한다. 따라서 실제 게임 코드는 보통 다음과 같은 구조를 취한다.

```c
BeginDrawing();
ClearBackground(RAYWHITE);

BeginMode2D(camera);
    // 게임 세계 좌표로 그리는 것들: 카메라를 따라 이동/확대된다
    DrawRectangle(worldX, worldY, 40, 40, BLUE);   // 플레이어
    DrawCircle(200, 150, 20, RED);                 // 적
    DrawRectangleLines(0, 0, 2000, 1200, GRAY);    // 맵 경계
EndMode2D();

// 화면 좌표로 그리는 것들: 카메라와 무관하게 항상 같은 자리에 표시
DrawText(TextFormat("Score: %d", score), 10, 10, 20, BLACK);
DrawRectangle(10, 40, 200, 20, LIGHTGRAY);         // 체력 바 배경
DrawRectangle(10, 40, healthPercent * 2, 20, RED); // 체력 바

EndDrawing();
```

이렇게 카메라 안쪽과 바깥쪽을 명확히 나누는 습관을 들이면, 이후 UI가 복잡해지더라도 "이 요소는 세계 좌표인가, 화면 좌표인가"를 헷갈리지 않고 코드를 구성할 수 있다.

## 플레이어를 따라다니는 카메라

가장 흔히 쓰이는 카메라 활용법은 플레이어를 계속 따라다니는 스크롤링 카메라다. 원리는 단순하다. 매 프레임 카메라의 `target`을 플레이어의 현재 위치로 갱신해주기만 하면 된다.

```c
#include "raylib.h"

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;

    InitWindow(screenWidth, screenHeight, "2D 카메라 - 플레이어 추적");

    Vector2 playerPosition = { 400.0f, 225.0f };
    float playerSpeed = 200.0f;

    Camera2D camera = { 0 };
    camera.target = playerPosition;
    camera.offset = (Vector2){ screenWidth / 2.0f, screenHeight / 2.0f };
    camera.rotation = 0.0f;
    camera.zoom = 1.0f;

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        float dt = GetFrameTime();

        if (IsKeyDown(KEY_RIGHT)) playerPosition.x += playerSpeed * dt;
        if (IsKeyDown(KEY_LEFT))  playerPosition.x -= playerSpeed * dt;
        if (IsKeyDown(KEY_DOWN))  playerPosition.y += playerSpeed * dt;
        if (IsKeyDown(KEY_UP))    playerPosition.y -= playerSpeed * dt;

        // 카메라가 매 프레임 플레이어를 그대로 따라간다
        camera.target = playerPosition;

        BeginDrawing();
        ClearBackground(RAYWHITE);

        BeginMode2D(camera);
            // 넓은 세계임을 보여주기 위한 격자 배경
            for (int x = -1000; x < 1000; x += 100)
                DrawLine(x, -1000, x, 1000, LIGHTGRAY);
            for (int y = -1000; y < 1000; y += 100)
                DrawLine(-1000, y, 1000, y, LIGHTGRAY);

            DrawRectangle((int)playerPosition.x - 20, (int)playerPosition.y - 20,
                          40, 40, BLUE);
        EndMode2D();

        DrawText("화살표 키로 이동", 10, 10, 20, BLACK);

        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

이 코드에서 눈여겨볼 점은 `playerPosition`을 계산할 때 화면 크기를 전혀 신경 쓰지 않는다는 것이다. 플레이어는 그냥 세계 좌표 위를 자유롭게 움직이고, `camera.offset`을 화면 중앙으로 고정해 두었기 때문에 `camera.target`이 곧 화면 중앙에 그려진다. 결과적으로 플레이어는 항상 화면 중앙에 머무르고, 격자 배경이 플레이어의 반대 방향으로 흘러가는 것처럼 보인다.

카메라가 딱딱하게 플레이어 위치를 그대로 따라가는 대신 부드럽게 뒤쫓아가게 만들고 싶다면, `camera.target`을 플레이어 위치로 즉시 대입하는 대신 선형 보간(lerp)을 이용해 서서히 다가가게 할 수 있다.

```c
float cameraSpeed = 4.0f;
camera.target.x += (playerPosition.x - camera.target.x) * cameraSpeed * dt;
camera.target.y += (playerPosition.y - camera.target.y) * cameraSpeed * dt;
```

벡터 연산을 raymath의 `Vector2Lerp` 같은 함수로 더 깔끔하게 표현하는 방법은 5장에서 다룬 벡터 수학 내용을 참고하면 좋다.

## 줌 인/아웃과 마우스 휠 연동

`camera.zoom` 값을 조절하면 화면에 보이는 세계의 범위를 확대하거나 축소할 수 있다. 마우스 휠 입력은 `GetMouseWheelMove()`로 얻을 수 있으며, 이 값을 줌 배율에 더해주는 방식으로 손쉽게 줌 기능을 구현할 수 있다.

```c
float wheel = GetMouseWheelMove();
if (wheel != 0.0f)
{
    camera.zoom += wheel * 0.1f;
    if (camera.zoom < 0.1f) camera.zoom = 0.1f;   // 너무 작아지지 않도록 제한
    if (camera.zoom > 3.0f) camera.zoom = 3.0f;   // 너무 커지지 않도록 제한
}
```

여기서 `zoom`의 최솟값과 최댓값을 제한하는 것이 중요하다. `zoom`이 `0`에 가까워지면 화면에 아무것도 보이지 않을 정도로 작게 그려지고, 음수가 되면 상하좌우가 뒤집힌 채로 그려져 예상치 못한 결과를 낳는다.

카메라 회전도 같은 방식으로 다룰 수 있다. 예를 들어 `Q`, `E` 키로 카메라를 좌우로 회전시키고 싶다면 다음처럼 작성한다.

```c
if (IsKeyDown(KEY_Q)) camera.rotation--;
if (IsKeyDown(KEY_E)) camera.rotation++;
```

`rotation`은 도 단위이므로 값이 누적되면서 계속 커지거나 작아질 수 있지만, 각도 계산 자체는 raylib 내부에서 알아서 처리하므로 별도의 정규화 없이 그대로 사용해도 된다.

## 화면 좌표와 월드 좌표 변환하기

카메라를 적용한 상태에서 마우스로 게임 세계의 오브젝트를 클릭하려면 문제가 하나 생긴다. `GetMousePosition()`이 돌려주는 좌표는 항상 화면 좌표이지, 카메라가 확대·축소·이동된 게임 세계의 좌표가 아니다. 예를 들어 카메라가 2배 확대되어 있고 오른쪽으로 이동한 상태라면, 화면의 `(400, 300)`이라는 지점이 실제 게임 세계에서는 전혀 다른 좌표를 가리킨다.

이 변환을 수동으로 계산하는 것은 번거롭고 실수하기 쉬운 작업이므로, raylib는 이를 위한 전용 함수 두 개를 제공한다.

```c
Vector2 GetScreenToWorld2D(Vector2 position, Camera2D camera);
Vector2 GetWorldToScreen2D(Vector2 position, Camera2D camera);
```

`GetScreenToWorld2D`는 화면 좌표를 카메라 설정을 반영한 게임 세계 좌표로 변환한다. 마우스 클릭 위치가 세계의 어느 오브젝트를 가리키는지 판별할 때 이 함수를 사용한다.

```c
Vector2 mouseScreenPos = GetMousePosition();
Vector2 mouseWorldPos = GetScreenToWorld2D(mouseScreenPos, camera);

if (IsMouseButtonPressed(MOUSE_BUTTON_LEFT))
{
    // mouseWorldPos를 이용해 세계 좌표 기준으로 충돌 판정을 수행한다
    if (CheckCollisionPointRec(mouseWorldPos, enemyRect))
    {
        // 적 클릭 처리
    }
}
```

반대로 `GetWorldToScreen2D`는 게임 세계 좌표를 현재 카메라 설정에 따른 화면 좌표로 변환한다. 예를 들어 세계 좌표에 있는 적 캐릭터의 머리 위에 화면 고정 UI로 이름표나 체력 바를 그리고 싶을 때 유용하다. 적의 위치는 `BeginMode2D` 안에서 자연스럽게 그려지지만, 이름표 텍스트는 항상 일정한 크기로 표시하고 싶다면 `BeginMode2D` 바깥에서 변환된 화면 좌표를 이용해 그리면 된다.

```c
Vector2 enemyWorldPos = { 500.0f, 300.0f };
Vector2 enemyScreenPos = GetWorldToScreen2D(enemyWorldPos, camera);

// BeginMode2D/EndMode2D 바깥, 즉 화면 좌표 기준으로 그린다
DrawText("Goblin", (int)enemyScreenPos.x - 20, (int)enemyScreenPos.y - 30, 14, BLACK);
```

이렇게 하면 카메라가 아무리 확대되거나 회전해도 이름표의 글자 크기는 항상 14픽셀로 일정하게 유지되면서, 위치만 적 캐릭터를 정확히 따라간다.

## 요약

- `Camera2D`는 `offset`, `target`, `rotation`, `zoom` 네 필드로 게임 세계 좌표와 화면 좌표 사이의 변환 규칙을 정의한다.
- `BeginMode2D(camera)`와 `EndMode2D()` 사이에서 그린 것은 카메라의 영향을 받고, 그 바깥에서 그린 것은 화면에 고정된다. 게임 오브젝트는 카메라 안에서, UI는 카메라 밖에서 그리는 것이 실전에서의 기본 패턴이다.
- 매 프레임 `camera.target`을 플레이어 위치로 갱신하면 카메라가 플레이어를 따라다니는 스크롤링을 구현할 수 있으며, 선형 보간을 곁들이면 더 부드러운 카메라 움직임을 만들 수 있다.
- `camera.zoom`을 `GetMouseWheelMove()`와 연동하면 마우스 휠 줌을, `camera.rotation`을 조절하면 카메라 회전을 구현할 수 있다. 이때 `zoom` 값의 범위를 적절히 제한해야 한다.
- `GetScreenToWorld2D`와 `GetWorldToScreen2D`는 화면 좌표와 게임 세계 좌표를 상호 변환한다. 마우스 클릭이 가리키는 세계 좌표를 알아내거나, 세계 좌표의 오브젝트에 화면 고정 UI를 붙일 때 사용한다.

2. `BeginMode2D`/`EndMode2D` 안쪽과 바깥쪽에 그리는 내용을 구분하는 이유는 무엇인가? 체력 바와 플레이어 캐릭터를 예로 들어 설명해보자.
3. 카메라가 플레이어를 딱딱하게 따라가는 방식과, 선형 보간을 이용해 부드럽게 따라가는 방식의 차이를 코드 수준에서 비교해보자.
4. 마우스 휠로 줌을 구현할 때 `camera.zoom`의 최솟값과 최댓값을 제한해야 하는 이유를 설명해보자.
