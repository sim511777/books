# 3장. 게임 루프와 기본 도형 그리기

[◀ 이전: 2장. 개발 환경 설정과 첫 창](ch02-개발환경설정과첫창.md) | [📖 목차](00-목차.md) | [다음: 4장. 입력 처리(키보드, 마우스, 게임패드) ▶](ch04-입력처리.md)


2장에서는 raylib 개발 환경을 구성하고, `InitWindow`로 창을 띄운 뒤 `BeginDrawing`과 `EndDrawing` 사이에서 화면을 채우는 첫 번째 프로그램을 작성했습니다. 이번 장에서는 그 게임 루프 구조를 다시 자세히 들여다보고, raylib가 제공하는 기본 도형 그리기 함수들을 하나씩 익힙니다. 장 끝에서는 시간의 흐름에 따라 부드럽게 움직이는 사각형을 직접 만들어 보면서, 프레임 속도와 무관하게 일정한 속도로 움직이는 애니메이션의 원리를 이해하게 됩니다.

## 게임 루프 다시 보기

모든 raylib 프로그램의 뼈대는 다음과 같은 구조를 가집니다.

```c
#include "raylib.h"

int main(void)
{
    InitWindow(800, 450, "raylib 예제");
    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        // 1. 갱신(Update): 게임 상태를 변경한다
        // 2. 그리기(Draw): 변경된 상태를 화면에 표시한다
        BeginDrawing();

            ClearBackground(RAYWHITE);
            // 여기에서 도형, 텍스트, 이미지 등을 그린다

        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

`while (!WindowShouldClose())` 블록 안의 내용은 프로그램이 실행되는 동안 초당 수십 번(보통 60번) 반복해서 실행됩니다. 이 한 번의 반복을 **프레임(frame)**이라고 부릅니다. 게임이든 애니메이션이든, 화면에 움직임이 보이는 이유는 사실 매 프레임마다 정지된 그림 한 장을 그리고, 그 그림들을 빠르게 연속으로 보여주기 때문입니다. 마치 종이를 빠르게 넘기면 그림이 움직이는 것처럼 보이는 플립북과 같은 원리입니다.

### 즉시 모드 렌더링이란

여기서 중요한 개념이 하나 있습니다. raylib는 **즉시 모드(immediate mode)** 방식으로 그림을 그립니다. 즉시 모드란, 이전 프레임에 무엇을 그렸는지 기억하지 않고 **매 프레임마다 화면을 완전히 지우고 처음부터 다시 그린다**는 뜻입니다.

```c
BeginDrawing();

    ClearBackground(RAYWHITE);   // 화면 전체를 지운다
    DrawRectangle(100, 100, 50, 50, RED);   // 다시 그린다

EndDrawing();
```

만약 `ClearBackground`를 호출하지 않으면 어떻게 될까요? 이전 프레임에 그렸던 도형들이 지워지지 않고 화면에 남아있는 상태에서 새 도형이 그 위에 겹쳐 그려집니다. 사각형이 움직이는 애니메이션을 만들고 싶은데 `ClearBackground`를 빼먹으면, 사각형이 지나간 자리마다 잔상이 남아 마치 붓으로 선을 그은 것처럼 보이게 됩니다. 즉, **"움직임"이라는 착각은 사실 매 프레임마다 화면을 지우고 위치를 조금씩 바꿔서 다시 그리는 작업의 반복일 뿐**입니다.

이 방식은 게임 상태(변수)와 화면에 그려진 결과(픽셀)를 분리해서 생각하게 해줍니다. 프로그래머는 "지금 이 물체가 어디에 있어야 하는가"라는 논리만 신경 쓰면 되고, 그 상태를 화면에 어떻게 옮길지는 매 프레임 새로 그리는 것으로 해결됩니다. 이 사고방식은 앞으로 이 책 전체에서 반복해서 등장하므로 잘 기억해 두기 바랍니다.

## 기본 도형 그리기 함수

raylib는 `raylib.h`에 다양한 2D 도형 그리기 함수를 제공합니다. 이 함수들은 모두 `BeginDrawing()`과 `EndDrawing()` 사이에서 호출해야 화면에 실제로 반영됩니다.

### 사각형: DrawRectangle, DrawRectangleLines

```c
void DrawRectangle(int posX, int posY, int width, int height, Color color);
void DrawRectangleLines(int posX, int posY, int width, int height, Color color);
```

`DrawRectangle`은 `(posX, posY)`를 왼쪽 위 모서리로 하는 `width × height` 크기의 사각형을 `color` 색으로 채워서 그립니다. `DrawRectangleLines`는 내부를 채우지 않고 윤곽선만 그립니다.

```c
DrawRectangle(50, 50, 200, 100, BLUE);        // 채워진 파란 사각형
DrawRectangleLines(300, 50, 200, 100, BLUE);  // 윤곽선만 있는 파란 사각형
```

### 원: DrawCircle, DrawCircleLines

```c
void DrawCircle(int centerX, int centerY, float radius, Color color);
void DrawCircleLines(int centerX, int centerY, float radius, Color color);
```

원은 중심 좌표와 반지름으로 정의합니다. 사각형과 마찬가지로 채워진 원과 윤곽선만 있는 원 두 가지 버전이 있습니다.

```c
DrawCircle(150, 250, 40, GREEN);
DrawCircleLines(350, 250, 40, GREEN);
```

### 선: DrawLine

```c
void DrawLine(int startPosX, int startPosY, int endPosX, int endPosY, Color color);
```

시작점과 끝점 두 좌표를 받아 그 사이를 잇는 직선을 그립니다.

```c
DrawLine(0, 0, 800, 450, BLACK);
```

### 삼각형: DrawTriangle

```c
void DrawTriangle(Vector2 v1, Vector2 v2, Vector2 v3, Color color);
```

삼각형은 세 개의 꼭짓점을 `Vector2` 구조체로 받습니다. `Vector2`는 `x`, `y` 두 개의 `float` 멤버를 가진 간단한 구조체로, 5장에서 자세히 다룰 예정입니다. 지금은 좌표 하나를 담는 그릇이라고 생각하면 충분합니다.

```c
DrawTriangle((Vector2){ 400, 50 }, (Vector2){ 350, 150 }, (Vector2){ 450, 150 }, ORANGE);
```

여기서 `(Vector2){ 400, 50 }`처럼 쓴 부분은 C99부터 지원하는 **복합 리터럴(compound literal)** 문법입니다. 임시로 구조체 변수를 만들지 않고 그 자리에서 바로 값을 채워 넘길 수 있어 raylib 코드에서 자주 사용됩니다.

주의할 점은, `DrawTriangle`은 세 꼭짓점을 **시계 방향**으로 지정해야 정상적으로 그려진다는 것입니다. 반시계 방향으로 지정하면 도형이 그려지지 않거나 예상과 다르게 보일 수 있습니다.

### 텍스트: DrawText

```c
void DrawText(const char *text, int posX, int posY, int fontSize, Color color);
```

`text`는 출력할 문자열, `(posX, posY)`는 텍스트 왼쪽 위 모서리 좌표, `fontSize`는 글자 크기(픽셀 단위), `color`는 글자 색입니다. raylib는 기본 내장 폰트를 가지고 있어서 별도의 폰트 파일 없이도 바로 텍스트를 그릴 수 있습니다.

```c
DrawText("Hello, raylib!", 190, 200, 20, BLACK);
```

폰트를 직접 불러와 더 다양한 스타일의 텍스트를 그리는 방법은 10장에서 다룹니다.

## Color 구조체와 색상 상수

raylib에서 색은 `Color` 구조체로 표현합니다.

```c
typedef struct Color {
    unsigned char r;   // 빨강 성분, 0~255
    unsigned char g;   // 초록 성분, 0~255
    unsigned char b;   // 파랑 성분, 0~255
    unsigned char a;   // 불투명도(alpha), 0~255
} Color;
```

각 성분은 0부터 255까지의 값을 가지는 `unsigned char`입니다. `a` 값이 255면 완전히 불투명, 0이면 완전히 투명합니다. 직접 값을 지정해서 나만의 색을 만들 수도 있습니다.

```c
Color myColor = { 100, 180, 220, 255 };
DrawRectangle(10, 10, 100, 100, myColor);
```

매번 이렇게 값을 나열하는 것은 번거롭기 때문에, raylib는 자주 쓰이는 색을 미리 상수로 정의해 두었습니다. 대표적인 것들은 다음과 같습니다.

| 상수 | 설명 |
|---|---|
| `RAYWHITE` | raylib의 상징색에 가까운 밝은 회백색. 배경으로 자주 사용 |
| `WHITE` | 흰색 |
| `BLACK` | 검은색 |
| `RED` | 빨강 |
| `GREEN` | 초록 |
| `BLUE` | 파랑 |
| `YELLOW` | 노랑 |
| `ORANGE` | 주황 |
| `PINK` | 분홍 |
| `PURPLE` | 보라 |
| `GRAY` / `LIGHTGRAY` / `DARKGRAY` | 회색 계열 |
| `SKYBLUE` / `DARKBLUE` | 파랑 계열 |
| `LIME` | 밝은 연두색 |
| `GOLD` | 금색 |
| `BROWN` / `DARKBROWN` | 갈색 계열 |
| `MAGENTA` | 마젠타 |

이 상수들은 모두 `Color` 타입이므로 도형을 그리는 함수의 `color` 인자 자리에 그대로 넣으면 됩니다. 처음 예제 코드에서 `ClearBackground(RAYWHITE)`를 사용한 이유도 여기에 있습니다. raylib 공식 문서나 예제 대부분이 배경을 `RAYWHITE`로, 도형이나 텍스트는 `BLACK` 계열로 그리는 관례를 따르고 있습니다.

### Fade로 투명도 적용하기

기존 색상에서 투명도만 조절하고 싶을 때는 색상 성분을 일일이 다시 계산할 필요 없이 `Fade` 함수를 사용합니다.

```c
Color Fade(Color color, float alpha);
```

`alpha`는 0.0f(완전 투명)부터 1.0f(원래 불투명도) 사이의 값입니다. `Fade`는 `color`의 `r`, `g`, `b` 값은 그대로 두고 `a` 값만 `alpha`에 비례하게 조정한 새 `Color`를 반환합니다.

```c
DrawRectangle(100, 100, 200, 200, Fade(RED, 0.5f));   // 반투명한 빨간 사각형
DrawCircle(400, 200, 60, Fade(BLUE, 0.2f));            // 아주 옅은 파란 원
```

여러 도형이 겹쳐서 그려질 때 뒤쪽 도형이 살짝 비쳐 보이게 하거나, 깜빡이는 경고 효과, 서서히 사라지는 이펙트 등을 만들 때 `Fade`가 유용하게 쓰입니다. 16장에서 파티클 시스템을 다룰 때도 입자가 사라지는 연출에 `Fade`를 활용합니다.

## 여러 도형 조합해 보기

지금까지 배운 함수들을 하나의 프로그램에 모아보겠습니다.

```c
#include "raylib.h"

int main(void)
{
    InitWindow(800, 450, "3장 - 기본 도형 그리기");
    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        BeginDrawing();

            ClearBackground(RAYWHITE);

            DrawText("raylib 기본 도형", 20, 20, 24, DARKGRAY);

            DrawRectangle(50, 80, 150, 100, BLUE);
            DrawRectangleLines(220, 80, 150, 100, BLUE);

            DrawCircle(450, 130, 50, GREEN);
            DrawCircleLines(600, 130, 50, GREEN);

            DrawLine(50, 220, 700, 220, GRAY);

            DrawTriangle((Vector2){ 400, 260 },
                         (Vector2){ 350, 360 },
                         (Vector2){ 450, 360 }, ORANGE);

            DrawRectangle(500, 260, 150, 100, Fade(RED, 0.4f));

        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

이 예제는 매 프레임마다 같은 도형들을 같은 위치에 다시 그리기 때문에 화면은 정지된 것처럼 보입니다. 하지만 실제로는 초당 60번씩 화면을 지우고 다시 그리는 작업이 반복되고 있습니다. 이제 이 도형들의 위치를 시간에 따라 바꾸면 애니메이션이 됩니다.

## GetFrameTime으로 일정한 속도 유지하기

도형을 움직이려면 매 프레임마다 좌표 값을 조금씩 바꿔주면 됩니다. 가장 단순하게 생각하면 이렇게 할 수 있을 것 같습니다.

```c
rectX = rectX + 1;   // 프레임마다 오른쪽으로 1픽셀씩 이동
```

하지만 이 방식에는 문제가 있습니다. `SetTargetFPS(60)`으로 초당 60프레임을 목표로 설정했더라도, 실행 중인 컴퓨터의 성능이나 부하 상황에 따라 실제 프레임 속도는 60이 아닐 수 있습니다. 저사양 컴퓨터에서 초당 30프레임만 나온다면, 위 코드로 움직이는 사각형은 초당 60프레임이 나오는 컴퓨터에 비해 절반 속도로 움직이게 됩니다. 즉, **프레임 단위로 이동 거리를 고정하면 실행 환경에 따라 게임 속도가 달라지는 문제**가 생깁니다.

이 문제를 해결하는 방법이 **델타 타임(delta time)**입니다. 델타 타임은 "바로 이전 프레임을 그리는 데 걸린 시간"을 초 단위로 나타낸 값입니다. raylib는 이 값을 `GetFrameTime` 함수로 제공합니다.

```c
float GetFrameTime(void);
```

이동 거리를 "픽셀/프레임"이 아니라 "픽셀/초"로 정의하고, 매 프레임 `GetFrameTime()`이 반환하는 값을 곱해주면 프레임 속도가 얼마든 상관없이 일정한 속도로 움직이게 됩니다.

```c
float speed = 200.0f;               // 초당 200픽셀 이동
rectX = rectX + speed * GetFrameTime();
```

초당 60프레임이 나오는 환경에서는 `GetFrameTime()`이 대략 `1/60`초(약 0.0167)를 반환하므로 한 프레임에 `200 * 0.0167 ≈ 3.3`픽셀씩, 60번 반복하면 초당 총 200픽셀을 이동합니다. 초당 30프레임만 나오는 환경에서는 `GetFrameTime()`이 대략 `1/30`초(약 0.0333)를 반환하므로 한 프레임에 `200 * 0.0333 ≈ 6.6`픽셀씩, 30번 반복해도 결국 초당 200픽셀을 이동합니다. 프레임 수는 다르지만 1초 동안 이동한 총 거리는 같습니다. 이것이 델타 타임 기반 이동의 핵심입니다.

### 예제: 화면을 가로지르는 사각형

이제 사각형이 화면 왼쪽에서 오른쪽으로 일정한 속도로 이동하다가, 화면 오른쪽 끝에 도달하면 다시 왼쪽으로 되돌아가는 예제를 만들어 보겠습니다.

```c
#include "raylib.h"

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;

    InitWindow(screenWidth, screenHeight, "3장 - 델타 타임으로 이동하기");
    SetTargetFPS(60);

    float rectX = 0.0f;
    float rectWidth = 50.0f;
    float rectHeight = 50.0f;
    float rectY = screenHeight / 2.0f - rectHeight / 2.0f;

    float speed = 300.0f;   // 초당 300픽셀 이동

    while (!WindowShouldClose())
    {
        // --- 갱신 ---
        float deltaTime = GetFrameTime();
        rectX += speed * deltaTime;

        // 화면 오른쪽 끝에 닿으면 왼쪽으로, 왼쪽 끝에 닿으면 오른쪽으로 방향 전환
        if ((rectX + rectWidth) >= screenWidth || rectX <= 0)
        {
            speed = -speed;
        }

        // --- 그리기 ---
        BeginDrawing();

            ClearBackground(RAYWHITE);

            DrawText("델타 타임으로 이동하는 사각형", 20, 20, 20, DARKGRAY);
            DrawRectangle((int)rectX, (int)rectY, (int)rectWidth, (int)rectHeight, MAROON);

        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

이 예제에서 눈여겨볼 부분은 크게 두 가지입니다.

첫째, 갱신 로직과 그리기 로직을 명확히 분리했습니다. `deltaTime`을 구하고 `rectX`를 갱신하는 코드는 `BeginDrawing()`보다 앞에 있습니다. raylib의 그리기 함수 자체는 상태를 바꾸지 않고 화면에 표시만 하므로, "다음 위치를 계산하는 일"과 "그 위치를 화면에 그리는 일"을 나누어 생각하는 습관을 들이는 것이 좋습니다. 이 구조는 앞으로 4장에서 입력을 처리하고, 7장에서 애니메이션을 다룰 때도 그대로 이어집니다.

둘째, `rectX`, `rectWidth`, `rectHeight`, `speed`를 모두 `float`로 선언했습니다. `DrawRectangle`은 `int` 좌표를 받지만, 델타 타임을 곱한 값은 소수점 이하가 계속 누적되므로 계산 과정에서는 `float`를 유지하다가 그리기 직전에만 `(int)`로 변환하는 것이 정밀도 손실을 줄이는 방법입니다. 만약 `rectX` 자체를 `int`로 선언했다면, `speed * deltaTime` 값이 1보다 작을 때(예: 매우 빠른 프레임 속도) 매번 0으로 반올림되어 사각형이 전혀 움직이지 않는 문제가 생길 수 있습니다.

## 요약

- raylib의 게임 루프는 `while (!WindowShouldClose())` 안에서 `BeginDrawing()`과 `EndDrawing()` 사이에 그리기 코드를 두는 구조를 가집니다.
- raylib는 **즉시 모드** 렌더링을 사용합니다. 매 프레임 `ClearBackground`로 화면을 지우고 도형을 처음부터 다시 그리며, 이 반복이 움직임으로 인식됩니다.
- 기본 도형은 `DrawRectangle`/`DrawRectangleLines`, `DrawCircle`/`DrawCircleLines`, `DrawLine`, `DrawTriangle`, `DrawText` 함수로 그립니다. `...Lines` 접미사가 붙은 함수는 윤곽선만 그립니다.
- 색은 `Color` 구조체(`r`, `g`, `b`, `a`, 각 0~255)로 표현하며, `RAYWHITE`, `BLACK`, `RED`처럼 미리 정의된 상수를 바로 사용할 수 있습니다. `Fade(color, alpha)`로 기존 색의 투명도만 바꾼 새 색을 얻을 수 있습니다.
- `GetFrameTime()`은 직전 프레임에 걸린 시간을 초 단위로 반환합니다. 이동 거리를 "초당 픽셀 수 × 델타 타임"으로 계산하면 실행 환경의 프레임 속도와 무관하게 일정한 속도로 움직이는 애니메이션을 만들 수 있습니다.

## 연습문제

1. `DrawRectangle`과 `DrawRectangleLines`를 같은 위치, 같은 크기로 겹쳐 그리되 색을 다르게 지정해 보세요. 윤곽선이 채워진 사각형 위에 어떻게 겹쳐 보이는지 관찰하세요.
2. 화면 중앙에 원을 하나 그리고, `Fade` 함수를 이용해 반지름은 그대로 두고 알파 값만 0.1f 단위로 바꿔가며 여러 개를 겹쳐 그려보세요. 알파 값에 따라 원이 얼마나 다르게 보이는지 확인해 보세요.
3. 본문의 델타 타임 예제를 수정해서, 사각형이 좌우뿐 아니라 상하로도 동시에 움직이며 화면 네 모서리에서 튕기도록 만들어 보세요. (힌트: `x`, `y` 방향 속도를 각각 따로 관리하세요.)
4. `speed` 값을 `GetFrameTime()`을 곱하지 않고 그대로 좌표에 더하도록 바꾼 뒤, `SetTargetFPS`를 60에서 15로 바꿔가며 실행해 보세요. 델타 타임을 사용했을 때와 사용하지 않았을 때 체감 속도가 어떻게 달라지는지 비교해 보세요.
5. `DrawTriangle`에 전달하는 세 꼭짓점의 순서를 시계 방향에서 반시계 방향으로 바꿔 실행해 보고 어떤 차이가 나타나는지 확인해 보세요.
