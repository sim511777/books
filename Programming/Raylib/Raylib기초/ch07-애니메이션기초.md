# 7장. 애니메이션 기초

[◀ 이전: 6장. 텍스처와 스프라이트](ch06-텍스처와스프라이트.md) | [📖 목차](00-목차.md) | [다음: 8장. 충돌 감지 ▶](ch08-충돌감지.md)


6장에서는 스프라이트 시트 한 장에서 `Rectangle`로 특정 영역만 잘라 `DrawTextureRec`로 그리는 방법을 배웠습니다. 이번 장에서는 그 잘라내는 사각형을 시간에 따라 옆으로 옮겨가며, 정지된 그림 한 장을 살아 움직이는 캐릭터로 바꾸는 방법을 다룹니다. 애니메이션의 원리는 사실 아주 단순합니다. 여러 장의 그림을 빠르게 순서대로 보여주면 우리 눈은 그것을 움직임으로 인식합니다. 이 장을 마치면 걷기, 대기, 점프 같은 여러 동작을 자연스럽게 전환하는 캐릭터를 만들 수 있습니다.

## 프레임 애니메이션의 원리

스프라이트 시트는 보통 같은 크기의 칸으로 나뉘어 있고, 한 칸이 애니메이션의 한 "프레임"이 됩니다. 예를 들어 가로로 6칸짜리 걷기 애니메이션 스프라이트 시트가 있다면, 0번 프레임부터 5번 프레임까지 순서대로 보여주었다가 다시 0번으로 돌아가는 식으로 반복하면 걷는 모습처럼 보입니다.

핵심은 "지금 몇 번째 프레임을 보여줄 차례인가"를 기억하는 변수 하나와, "얼마나 자주 다음 프레임으로 넘어갈 것인가"를 결정하는 타이머입니다. 이 두 가지만 있으면 됩니다.

```c
#include "raylib.h"

int main(void)
{
    InitWindow(800, 450, "7장 - 기본 프레임 애니메이션");

    Texture2D texture = LoadTexture("resources/character_walk.png");

    const int frameCount = 6;              // 스프라이트 시트의 프레임 수
    int frameWidth = texture.width / frameCount;
    int frameHeight = texture.height;

    int currentFrame = 0;
    float frameTimer = 0.0f;
    const float frameDuration = 0.1f;      // 프레임당 0.1초씩 보여준다

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        // 시간을 누적해서 다음 프레임으로 넘어갈지 판단
        frameTimer += GetFrameTime();
        if (frameTimer >= frameDuration)
        {
            frameTimer -= frameDuration;
            currentFrame = (currentFrame + 1) % frameCount;
        }

        Rectangle source = {
            (float)(frameWidth * currentFrame), 0.0f,
            (float)frameWidth, (float)frameHeight
        };

        BeginDrawing();
            ClearBackground(RAYWHITE);
            DrawTextureRec(texture, source, (Vector2){ 300, 200 }, WHITE);
        EndDrawing();
    }

    UnloadTexture(texture);
    CloseWindow();
    return 0;
}
```

여기서 `source.x`가 `frameWidth * currentFrame`으로 계산되는 부분이 애니메이션의 핵심입니다. `currentFrame`이 0에서 5까지 순환하면서 스프라이트 시트 위를 오른쪽으로 훑고 지나가고, 6번째 프레임에 도달하면 나머지 연산자 `%`에 의해 다시 0번으로 돌아갑니다.

## 왜 델타타임을 누적하는가

애니메이션 속도를 조절하는 방법으로 흔히 떠올리는 것이 "프레임 카운터" 방식입니다. 즉, 매 루프마다 카운터를 하나씩 늘리다가 특정 값(예: 6프레임마다)에 도달하면 다음 애니메이션 프레임으로 넘어가는 방식입니다.

```c
// 프레임 카운터 방식 - 프레임레이트에 의존하는 문제가 있다
int counter = 0;
counter++;
if (counter >= 6)   // 6번의 루프마다 다음 프레임
{
    counter = 0;
    currentFrame = (currentFrame + 1) % frameCount;
}
```

이 방식의 문제는 "게임 루프가 초당 몇 번 도는가"에 애니메이션 속도가 그대로 종속된다는 점입니다. `SetTargetFPS(60)`으로 설정한 환경에서는 6프레임마다 전환되면 초당 10번 전환되어 자연스럽지만, 만약 사용자의 컴퓨터가 성능 제한이나 다른 이유로 30fps밖에 내지 못한다면 애니메이션은 절반 속도로 느려집니다. 반대로 모니터 주사율이 144Hz라 프레임이 더 자주 돈다면 애니메이션은 더 빨라져 버립니다. 즉 게임 로직의 속도와 화면 그리기 속도가 뒤섞여 버리는 것입니다.

`GetFrameTime()`은 라이브러리가 계산해주는, 바로 직전 프레임을 그리는 데 실제로 걸린 시간(초 단위)을 돌려줍니다. 이 값을 누적해서 "0.1초가 지났는가?"를 판단하면, 루프가 초당 30번 돌든 300번 돌든 상관없이 다음 프레임으로 넘어가는 시점은 항상 실제 시간 기준 0.1초 뒤가 됩니다. 프레임레이트가 변해도 애니메이션 재생 속도는 그대로 유지되는 것이지요. 이런 식으로 시간 기반으로 로직을 처리하는 방식은 5장에서 다룬 벡터 연산에 델타타임을 곱해 이동 속도를 프레임레이트와 무관하게 만드는 원리와 정확히 같은 발상입니다.

한 가지 더 눈여겨볼 부분은 `frameTimer -= frameDuration`이지 `frameTimer = 0`이 아니라는 점입니다. 만약 한 프레임이 유난히 오래 걸려서 `frameTimer`가 `frameDuration`보다 훨씬 커졌다면(예를 들어 잠깐 렉이 걸린 경우), 초과된 시간을 그냥 버리지 않고 다음 판정에 이어서 반영해야 누적 오차가 쌓이지 않습니다. 아주 정교한 상황에서는 while 문으로 여러 프레임을 한 번에 건너뛰게 만들 수도 있지만, 대부분의 2D 게임에서는 위 방식으로 충분합니다.

## 여러 애니메이션 상태 관리하기

실제 게임 캐릭터는 한 가지 동작만 하지 않습니다. 가만히 서 있을 때는 `idle` 애니메이션을, 걸을 때는 `walk` 애니메이션을, 점프할 때는 `jump` 애니메이션을 보여줘야 합니다. 각 상태마다 프레임 수, 재생 속도, 스프라이트 시트에서의 위치가 다를 수 있으므로 이 정보들을 구조체로 묶어서 관리하면 코드가 훨씬 깔끔해집니다.

```c
#include "raylib.h"

typedef enum {
    ANIM_IDLE,
    ANIM_WALK,
    ANIM_JUMP,
    ANIM_COUNT
} AnimState;

typedef struct {
    Texture2D texture;
    int frameCount;
    float frameDuration;
    int currentFrame;
    float frameTimer;
} Animation;

Animation LoadAnimation(const char *path, int frameCount, float frameDuration)
{
    Animation anim = { 0 };
    anim.texture = LoadTexture(path);
    anim.frameCount = frameCount;
    anim.frameDuration = frameDuration;
    anim.currentFrame = 0;
    anim.frameTimer = 0.0f;
    return anim;
}

void UpdateAnimation(Animation *anim)
{
    anim->frameTimer += GetFrameTime();
    if (anim->frameTimer >= anim->frameDuration)
    {
        anim->frameTimer -= anim->frameDuration;
        anim->currentFrame = (anim->currentFrame + 1) % anim->frameCount;
    }
}

Rectangle GetAnimationFrameRect(const Animation *anim)
{
    int frameWidth = anim->texture.width / anim->frameCount;
    return (Rectangle){
        (float)(frameWidth * anim->currentFrame), 0.0f,
        (float)frameWidth, (float)anim->texture.height
    };
}

int main(void)
{
    InitWindow(800, 450, "7장 - 애니메이션 상태 관리");

    Animation animations[ANIM_COUNT];
    animations[ANIM_IDLE] = LoadAnimation("resources/idle.png", 4, 0.2f);
    animations[ANIM_WALK] = LoadAnimation("resources/walk.png", 6, 0.1f);
    animations[ANIM_JUMP] = LoadAnimation("resources/jump.png", 2, 0.15f);

    AnimState currentState = ANIM_IDLE;

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        // 입력에 따라 상태 전환 (15장에서 다룰 상태 머신의 축소판)
        AnimState newState = currentState;
        if (IsKeyPressed(KEY_SPACE)) newState = ANIM_JUMP;
        else if (IsKeyDown(KEY_RIGHT) || IsKeyDown(KEY_LEFT)) newState = ANIM_WALK;
        else if (!IsKeyDown(KEY_RIGHT) && !IsKeyDown(KEY_LEFT)) newState = ANIM_IDLE;

        if (newState != currentState)
        {
            currentState = newState;
            animations[currentState].currentFrame = 0;   // 상태가 바뀌면 처음 프레임부터
            animations[currentState].frameTimer = 0.0f;
        }

        UpdateAnimation(&animations[currentState]);

        BeginDrawing();
            ClearBackground(RAYWHITE);
            Rectangle source = GetAnimationFrameRect(&animations[currentState]);
            DrawTextureRec(animations[currentState].texture, source, (Vector2){ 350, 200 }, WHITE);
        EndDrawing();
    }

    for (int i = 0; i < ANIM_COUNT; i++) UnloadTexture(animations[i].texture);
    CloseWindow();
    return 0;
}
```

이 구조에서 중요한 설계 포인트가 두 가지 있습니다. 첫째, `Animation` 구조체가 "이 애니메이션을 재생하는 데 필요한 모든 정보"를 캡슐화하고 있어서, 상태가 몇 개로 늘어나든 배열 하나로 관리할 수 있습니다. 둘째, 상태가 바뀌는 순간 `currentFrame`과 `frameTimer`를 0으로 되돌리고 있습니다. 이렇게 하지 않으면 예를 들어 `walk` 애니메이션의 4번째 프레임에서 `idle`로 전환했을 때 `idle` 애니메이션에도 4번째 프레임이 존재하지 않아 잘못된 영역을 그리거나, 어색하게 중간부터 재생되는 문제가 생깁니다.

여기서 보여준 `if`/`else if` 연쇄는 상태 전환 로직치고는 아주 단순한 형태입니다. 게임이 커지면 상태의 개수와 전환 조건이 훨씬 복잡해지는데, 이런 상태 전환을 체계적으로 다루는 방법은 15장 "게임 상태 관리와 씬 전환"에서 본격적으로 다룹니다. 지금은 "애니메이션도 결국 하나의 상태이고, 조건에 따라 전환된다"는 감각만 잡아두면 충분합니다.

## 좌우 반전으로 방향 표현하기

캐릭터가 오른쪽으로 걸을 때와 왼쪽으로 걸을 때 각각 다른 스프라이트 시트를 준비하는 것은 낭비입니다. 대부분의 2D 게임은 한 방향(보통 오른쪽을 보는 그림)만 그려두고, 반대 방향으로 이동할 때는 그림을 좌우로 뒤집어서 그립니다.

raylib에서는 별도의 "반전" 함수를 호출할 필요 없이, `DrawTextureRec`에 넘기는 `source` 사각형의 `width`를 음수로 지정하는 것만으로 좌우 반전을 구현할 수 있습니다. 텍스처 좌표를 읽어오는 방향이 반대가 되면서 그림이 뒤집혀 그려지는 원리입니다.

```c
#include "raylib.h"
#include "raymath.h"

int main(void)
{
    InitWindow(800, 450, "7장 - 좌우 반전");

    Texture2D texture = LoadTexture("resources/character_walk.png");
    const int frameCount = 6;
    int frameWidth = texture.width / frameCount;
    int frameHeight = texture.height;

    int currentFrame = 0;
    float frameTimer = 0.0f;
    const float frameDuration = 0.1f;

    Vector2 position = { 350, 200 };
    bool facingLeft = false;

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        float speed = 200.0f * GetFrameTime();
        if (IsKeyDown(KEY_RIGHT)) { position.x += speed; facingLeft = false; }
        if (IsKeyDown(KEY_LEFT))  { position.x -= speed; facingLeft = true;  }

        frameTimer += GetFrameTime();
        if (frameTimer >= frameDuration)
        {
            frameTimer -= frameDuration;
            currentFrame = (currentFrame + 1) % frameCount;
        }

        Rectangle source = {
            (float)(frameWidth * currentFrame), 0.0f,
            (float)(facingLeft ? -frameWidth : frameWidth),   // 음수 폭 = 좌우 반전
            (float)frameHeight
        };

        BeginDrawing();
            ClearBackground(RAYWHITE);
            DrawTextureRec(texture, source, position, WHITE);
        EndDrawing();
    }

    UnloadTexture(texture);
    CloseWindow();
    return 0;
}
```

`source.width`를 `-frameWidth`로 지정하면 raylib은 해당 프레임 영역을 오른쪽 끝에서부터 왼쪽으로 읽어가며 그리므로, 결과적으로 이미지가 좌우로 뒤집혀 보입니다. `source.x` 계산 자체는 그대로 두고 `width`의 부호만 바꾸면 되기 때문에, 방향 전환 로직이 프레임 계산 로직과 뒤섞이지 않고 깔끔하게 분리된다는 장점이 있습니다.

주의할 점은 이 트릭이 `DrawTextureRec`뿐 아니라 더 일반적인 `DrawTexturePro(texture, source, dest, origin, rotation, tint)`에서도 동일하게 동작한다는 것입니다. 회전이나 크기 조절까지 함께 필요한 경우에는 `DrawTexturePro`를 쓰고, 이때도 `source.width`의 부호로 좌우 반전을, `source.height`의 부호로 상하 반전을 표현할 수 있습니다.

## 요약

- 스프라이트 시트 애니메이션은 "지금 몇 번째 프레임인가"를 나타내는 정수 변수와, 언제 다음 프레임으로 넘어갈지를 결정하는 타이머로 구현합니다.
- 프레임 카운터(루프 횟수)로 애니메이션 속도를 정하면 프레임레이트에 따라 재생 속도가 달라지는 문제가 생깁니다. `GetFrameTime()`이 반환하는 델타타임을 누적해서 "N초 경과"를 판정하면 프레임레이트와 무관하게 일정한 속도를 유지할 수 있습니다.
- 여러 애니메이션 상태(idle, walk, jump 등)는 `Animation` 구조체 배열로 관리하면 코드가 깔끔해지며, 상태 전환 시 `currentFrame`과 타이머를 초기화해야 어색한 전환을 막을 수 있습니다. 본격적인 상태 관리 기법은 15장에서 다룹니다.
- `DrawTextureRec`나 `DrawTexturePro`의 `source` 사각형에서 `width`를 음수로 지정하면 별도의 반전 함수 없이 텍스처를 좌우로 뒤집어 그릴 수 있습니다.

## 연습문제

1. 이 장의 첫 예제 코드를 수정해, 스페이스바를 누르고 있는 동안에만 애니메이션이 재생되고 떼면 첫 프레임에서 멈추도록 만들어 보세요.
2. `frameDuration` 값을 0.1초에서 0.02초로, 그리고 0.5초로 각각 바꿔서 실행해보고 애니메이션 재생 속도가 어떻게 달라지는지 관찰해 보세요.
3. "여러 애니메이션 상태 관리하기" 절의 예제에 `ANIM_ATTACK` 상태를 추가하고, 공격 애니메이션이 한 번 끝까지 재생되면 자동으로 `ANIM_IDLE` 상태로 돌아가도록 구현해 보세요. (힌트: 애니메이션이 마지막 프레임에 도달했는지 확인하는 조건이 필요합니다.)
4. "좌우 반전으로 방향 표현하기" 절의 예제를 응용해, 캐릭터가 위/아래로도 이동할 수 있게 하고 `DrawTexturePro`를 사용해 상하 반전도 함께 지원하도록 수정해 보세요.
5. 프레임 카운터 방식과 델타타임 누적 방식을 각각 구현한 뒤, `SetTargetFPS`를 30과 144로 바꿔가며 두 방식의 애니메이션 속도가 어떻게 달라지는지 직접 비교해 보세요.
