# 5장. 벡터와 기본 수학(raymath)

[◀ 이전: 4장. 입력 처리(키보드, 마우스, 게임패드)](ch04-입력처리.md) | [📖 목차](00-목차.md) | [다음: 6장. 텍스처와 스프라이트 ▶](ch06-텍스처와스프라이트.md)


지금까지 우리는 `DrawCircle(400, 300, 20, RED)`처럼 위치를 `x`, `y` 두 개의 숫자로 따로따로 다뤘습니다. 도형 하나를 그릴 때는 이 정도로 충분하지만, 게임에서는 곧 한계에 부딪힙니다. 캐릭터의 위치, 이동 속도, 목표 지점까지의 방향, 중력의 영향 — 이 모든 것을 매번 `x`, `y` 두 변수로 따로 계산하다 보면 코드가 금세 지저분해집니다.

이번 장에서는 raylib가 제공하는 벡터 타입과, `raymath.h`에 들어있는 벡터 연산 함수들을 익힙니다. 벡터는 이후 8장의 충돌 감지, 11장의 카메라 시스템, 16장의 파티클 시스템까지 책 전체에서 계속 사용할 핵심 도구입니다.

## 벡터란 무엇인가

벡터(vector)는 크기와 방향을 함께 가진 값입니다. 게임 프로그래밍에서는 보통 다음 세 가지를 표현하는 데 사용합니다.

- **위치(position)**: 화면 또는 3D 공간에서 물체가 있는 좌표
- **속도(velocity)**: 물체가 한 프레임(또는 1초)에 얼마나, 어느 방향으로 움직이는가
- **방향(direction)**: 크기 없이 "어느 쪽을 향하는가"만 나타내는 값

raylib는 `raymath.h`가 아니라 `raylib.h`에 이미 다음과 같은 벡터 구조체를 정의해 두고 있습니다.

```c
typedef struct Vector2 {
    float x;
    float y;
} Vector2;

typedef struct Vector3 {
    float x;
    float y;
    float z;
} Vector3;
```

`Vector2`는 2D 게임에서 위치와 속도를 다룰 때, `Vector3`는 12장부터 다룰 3D 공간에서 사용합니다. 지금은 2D에 집중하므로 `Vector2`가 주인공입니다.

`Vector2`를 직접 만들 때는 다음처럼 중괄호 초기화 구문을 씁니다.

```c
Vector2 position = { 100.0f, 200.0f };
Vector2 velocity = { 3.0f, 0.0f };
```

이렇게 위치와 속도를 각각 하나의 변수로 묶어두면, "이 물체를 한 프레임 동안 이동시킨다"는 동작을 다음처럼 간단히 표현할 수 있습니다.

```c
position.x += velocity.x;
position.y += velocity.y;
```

아직은 `x`, `y`를 따로 더하고 있지만, 이제 곧 이 두 줄을 한 줄로 줄여주는 함수를 소개합니다.

## raymath.h와 벡터 연산 함수

raylib 프로젝트에는 `raymath.h`라는 보조 헤더가 함께 제공됩니다. 이 헤더는 `Vector2`, `Vector3`, `Matrix`, `Quaternion` 등을 다루는 수학 함수들을 인라인 함수로 제공하며, 사용하려면 소스 파일 상단에 다음과 같이 포함하면 됩니다.

```c
#include "raylib.h"
#include "raymath.h"
```

가장 자주 쓰게 될 `Vector2` 관련 함수들을 하나씩 살펴보겠습니다.

### Vector2Add, Vector2Subtract

두 벡터를 더하거나 뺍니다. 앞서 손으로 풀어 썼던 위치 갱신 코드는 `Vector2Add`로 다음처럼 간결하게 바꿀 수 있습니다.

```c
Vector2 Vector2Add(Vector2 v1, Vector2 v2);
Vector2 Vector2Subtract(Vector2 v1, Vector2 v2);
```

```c
position = Vector2Add(position, velocity);
```

두 위치 사이의 차이(변위)를 구할 때는 `Vector2Subtract`를 씁니다. 예를 들어 "적에서 플레이어로 향하는 벡터"는 다음처럼 구합니다.

```c
Vector2 toPlayer = Vector2Subtract(playerPos, enemyPos);
```

### Vector2Scale

벡터의 크기를 일정 배율로 늘리거나 줄입니다.

```c
Vector2 Vector2Scale(Vector2 v, float scale);
```

속도 벡터에 `deltaTime`을 곱해 "초당 이동 속도"를 프레임마다 적용하고 싶을 때 유용합니다.

```c
Vector2 speed = { 200.0f, 0.0f };  // 초당 200픽셀
float dt = GetFrameTime();
position = Vector2Add(position, Vector2Scale(speed, dt));
```

이렇게 하면 3장에서 다뤘던 프레임 독립적인 이동을, `x`와 `y`를 따로 계산하지 않고 벡터 하나로 처리할 수 있습니다.

### Vector2Length, Vector2Distance

`Vector2Length`는 벡터의 크기(원점으로부터의 거리)를 구하고, `Vector2Distance`는 두 점 사이의 거리를 직접 구합니다.

```c
float Vector2Length(Vector2 v);
float Vector2Distance(Vector2 v1, Vector2 v2);
```

두 점 사이의 거리를 구하는 것은 게임에서 정말 자주 쓰이는 연산입니다. "플레이어가 아이템 근처에 왔는가?", "총알이 적에게 닿았는가?" 같은 질문에 답할 때 기본이 되기 때문입니다. `Vector2Distance`는 내부적으로 두 벡터를 뺀 뒤 그 결과의 길이를 구하는 것과 같습니다. 즉 다음 두 표현은 동일합니다.

```c
float dist1 = Vector2Distance(a, b);
float dist2 = Vector2Length(Vector2Subtract(a, b));
```

### Vector2Normalize

정규화(normalize)는 벡터의 **방향은 그대로 유지하면서 크기(길이)만 1로 만드는** 연산입니다.

```c
Vector2 Vector2Normalize(Vector2 v);
```

왜 이런 연산이 필요할까요? 예를 들어 플레이어가 대각선 방향으로 이동할 때를 생각해봅시다. 4장에서처럼 상하좌우 입력을 그대로 더하면, 대각선으로 이동할 때 `x`와 `y`가 동시에 변하면서 실제 이동 거리가 가로/세로로만 이동할 때보다 더 길어져 버립니다(피타고라스 정리에 의해 대각선 속도가 `sqrt(2)`배, 즉 약 1.41배 빨라집니다).

```c
Vector2 direction = { 0 };
if (IsKeyDown(KEY_RIGHT)) direction.x += 1.0f;
if (IsKeyDown(KEY_LEFT))  direction.x -= 1.0f;
if (IsKeyDown(KEY_DOWN))  direction.y += 1.0f;
if (IsKeyDown(KEY_UP))    direction.y -= 1.0f;

// 정규화하지 않으면 대각선 이동 시 direction의 길이가 sqrt(2) ≈ 1.41이 된다
if (Vector2Length(direction) > 0.0f) {
    direction = Vector2Normalize(direction);
}

float moveSpeed = 200.0f;  // 초당 200픽셀
position = Vector2Add(position, Vector2Scale(direction, moveSpeed * GetFrameTime()));
```

정규화를 거치면 `direction`은 "어느 방향인가"만 담은, 길이가 정확히 1인 벡터가 됩니다. 여기에 원하는 속력(`moveSpeed`)을 곱하면, 이동 방향과 상관없이 항상 일정한 속력으로 움직이게 됩니다. 이것이 정규화가 필요한 핵심 이유입니다 — **방향과 크기를 분리해서, 크기(속력)를 내가 원하는 값으로 자유롭게 통제하기 위해서**입니다.

길이가 0인 벡터(즉 입력이 전혀 없는 상태)를 정규화하면 0으로 나누는 문제가 생길 수 있으므로, 위 코드처럼 `Vector2Length(direction) > 0.0f`로 먼저 검사하는 습관을 들이는 것이 안전합니다.

## 예제: 거리 기반 반응 (8장 충돌 감지 예고)

두 점 사이의 거리를 활용하면 아주 간단한 형태의 "충돌"을 흉내 낼 수 있습니다. 플레이어가 마우스 커서로부터 일정 거리 안에 들어오면 원의 색이 바뀌는 예제를 만들어봅시다.

```c
#include "raylib.h"
#include "raymath.h"

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;

    InitWindow(screenWidth, screenHeight, "5장 - 거리 기반 반응");

    Vector2 playerPos = { 400.0f, 225.0f };
    float playerRadius = 25.0f;
    float reactRange = 100.0f;  // 이 거리 안에 마우스가 들어오면 반응

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        Vector2 mousePos = GetMousePosition();
        float dist = Vector2Distance(playerPos, mousePos);
        bool isNear = (dist <= reactRange);

        BeginDrawing();
            ClearBackground(RAYWHITE);

            DrawCircleLines((int)playerPos.x, (int)playerPos.y, reactRange, LIGHTGRAY);
            DrawCircleV(playerPos, playerRadius, isNear ? RED : BLUE);

            DrawText(TextFormat("거리: %.1f", dist), 10, 10, 20, DARKGRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

`DrawCircleV`는 `DrawCircle`과 기능은 같지만 중심 좌표를 `int x, int y` 대신 `Vector2`로 받는 버전입니다. raylib의 많은 그리기 함수는 이렇게 `x, y`를 따로 받는 버전과 `Vector2`를 받는 `...V` 버전을 함께 제공합니다.

이 예제에서 핵심은 "거리가 특정 값 이하인가"라는 조건 하나로 반응 여부를 판단했다는 점입니다. 8장에서는 여기에 사각형 겹침 판정(`CheckCollisionRecs`)이나 원-원 겹침 판정(`CheckCollisionCircles`) 같은, raylib가 미리 만들어 둔 충돌 감지 함수들을 더해 본격적인 충돌 시스템을 다룹니다.

## 각도와 라디안, 그리고 발사체 움직이기

지금까지는 벡터의 덧셈, 뺄셈, 거리처럼 좌표 자체를 다뤘습니다. 이번에는 "각도"로 방향을 표현하고, 그 방향으로 물체를 움직이는 방법을 봅니다.

C 표준 수학 함수인 `sinf`, `cosf`는 라디안(radian) 단위의 각도를 인자로 받습니다. 하지만 사람은 보통 도(degree) 단위로 생각하는 것이 더 직관적입니다("45도 방향으로 발사"처럼). raylib는 이 변환을 위해 `raymath.h`에 다음과 같은 매크로를 정의해 둡니다.

```c
#define DEG2RAD (PI / 180.0f)
#define RAD2DEG (180.0f / PI)
```

즉 도 단위 각도에 `DEG2RAD`를 곱하면 라디안으로 바뀝니다.

```c
float angleDeg = 45.0f;
float angleRad = angleDeg * DEG2RAD;
```

각도와 삼각함수를 이용하면, 특정 방향을 가리키는 단위 벡터를 다음처럼 만들 수 있습니다.

```c
Vector2 direction;
direction.x = cosf(angleRad);
direction.y = sinf(angleRad);
```

이 `direction`은 길이가 1인(정규화된) 벡터이므로, 앞서 배운 것처럼 원하는 속력을 곱해서 이동에 바로 사용할 수 있습니다. 이 원리로 마우스를 클릭한 방향으로 발사체를 쏘는 예제를 만들어보겠습니다.

```c
#include "raylib.h"
#include "raymath.h"
#include <math.h>

#define MAX_BULLETS 64

typedef struct Bullet {
    Vector2 position;
    Vector2 velocity;
    bool active;
} Bullet;

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;

    InitWindow(screenWidth, screenHeight, "5장 - 각도로 발사체 쏘기");

    Vector2 cannonPos = { 400.0f, 225.0f };
    float bulletSpeed = 300.0f;  // 초당 300픽셀

    Bullet bullets[MAX_BULLETS] = { 0 };

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        float dt = GetFrameTime();

        // 마우스 클릭 방향으로 발사체 생성
        if (IsMouseButtonPressed(MOUSE_BUTTON_LEFT))
        {
            Vector2 mousePos = GetMousePosition();
            Vector2 toMouse = Vector2Subtract(mousePos, cannonPos);
            float angleRad = atan2f(toMouse.y, toMouse.x);

            Vector2 dir = { cosf(angleRad), sinf(angleRad) };

            for (int i = 0; i < MAX_BULLETS; i++)
            {
                if (!bullets[i].active)
                {
                    bullets[i].position = cannonPos;
                    bullets[i].velocity = Vector2Scale(dir, bulletSpeed);
                    bullets[i].active = true;
                    break;
                }
            }
        }

        // 발사체 이동
        for (int i = 0; i < MAX_BULLETS; i++)
        {
            if (bullets[i].active)
            {
                bullets[i].position = Vector2Add(bullets[i].position, Vector2Scale(bullets[i].velocity, dt));

                // 화면 밖으로 나가면 비활성화
                if (bullets[i].position.x < 0 || bullets[i].position.x > screenWidth ||
                    bullets[i].position.y < 0 || bullets[i].position.y > screenHeight)
                {
                    bullets[i].active = false;
                }
            }
        }

        BeginDrawing();
            ClearBackground(RAYWHITE);

            DrawCircleV(cannonPos, 15.0f, DARKGRAY);

            for (int i = 0; i < MAX_BULLETS; i++)
            {
                if (bullets[i].active)
                {
                    DrawCircleV(bullets[i].position, 5.0f, MAROON);
                }
            }

            DrawText("마우스 왼쪽 버튼을 클릭해 발사", 10, 10, 20, DARKGRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

여기서 각도를 직접 구하는 데 `atan2f(toMouse.y, toMouse.x)`를 사용했습니다. `atan2f`는 `sinf`, `cosf`와 마찬가지로 표준 C 라이브러리(`math.h`) 함수로, 벡터의 `x`, `y` 성분으로부터 "그 벡터가 가리키는 각도(라디안)"를 직접 구해줍니다. 사실 이 예제에서는 `toMouse`를 `Vector2Normalize`로 정규화해서 바로 속도로 써도 결과는 같습니다. 각도를 굳이 구한 이유는, "45도마다 여러 방향으로 동시에 발사"처럼 각도 자체를 조작해야 하는 경우를 대비해 각도와 벡터를 오가는 방법을 함께 보여주기 위해서입니다.

`MAX_BULLETS`개의 고정 배열을 미리 만들어두고 `active` 플래그로 사용 여부를 관리하는 방식은, `malloc`/`free` 없이 발사체 같은 반복적으로 생성/소멸되는 객체를 다루는 아주 흔한 패턴입니다. 이 패턴은 16장의 파티클 시스템에서 훨씬 큰 규모로 다시 등장합니다.

## 요약

- `Vector2`(`{float x, y;}`)와 `Vector3`(`{float x, y, z;}`)는 raylib가 제공하는 벡터 구조체로, 위치·속도·방향을 하나의 값으로 묶어 다룰 수 있게 해준다.
- `raymath.h`를 포함하면 `Vector2Add`, `Vector2Subtract`, `Vector2Scale`, `Vector2Length`, `Vector2Distance`, `Vector2Normalize` 같은 벡터 연산 함수를 쓸 수 있다.
- `Vector2Normalize`는 방향은 유지하면서 길이를 1로 만드는 연산으로, 대각선 이동이 더 빨라지는 문제를 막고 속력을 별도로 통제할 수 있게 해준다.
- `Vector2Distance`로 두 점 사이의 거리를 구하면, "일정 범위 안에 들어왔는가"를 판단하는 간단한 반응/충돌 로직을 만들 수 있다(8장에서 본격적인 충돌 감지로 이어진다).
- `DEG2RAD` 매크로로 도 단위 각도를 라디안으로 바꾸고, `cosf`/`sinf`(또는 `atan2f`)로 특정 방향을 가리키는 단위 벡터를 만들어 발사체 등의 이동에 활용할 수 있다.

## 연습문제

1. `Vector2Add`, `Vector2Subtract`, `Vector2Scale`, `Vector2Length`, `Vector2Distance`, `Vector2Normalize` 각 함수의 매개변수와 반환값을 설명하고, 각각을 실제로 사용할 법한 상황을 하나씩 예로 들어보세요.
2. 정규화(`Vector2Normalize`)를 하지 않고 대각선 이동 예제를 실행하면 어떤 현상이 발생하는지 직접 코드를 수정해 확인하고, 왜 그런 현상이 생기는지 벡터의 길이 관점에서 설명하세요.
3. 거리 기반 반응 예제를 수정하여, 마우스가 원 안에 들어왔을 때 원의 색뿐 아니라 크기도 함께 커지도록(예: 반지름이 서서히 증가) 만들어보세요.
4. 발사체 예제에서 `MAX_BULLETS`개를 모두 사용 중일 때 새로 발사를 시도하면 어떤 일이 일어나는지 설명하고, 이를 개선할 방법을 제안해보세요.
5. 발사체가 화면 가장자리에 닿았을 때 사라지는 대신 반대 방향으로 튕겨 나가도록(반사) 코드를 수정해보세요. 힌트: 화면 좌우 벽에 부딪히면 속도의 `x` 성분 부호를, 위아래 벽에 부딪히면 `y` 성분 부호를 뒤집으면 됩니다.
