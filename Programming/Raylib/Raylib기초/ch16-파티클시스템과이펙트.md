# 16장. 파티클 시스템과 이펙트

[◀ 이전: 15장. 게임 상태 관리와 씬 전환](ch15-게임상태관리와씬전환.md) | [📖 목차](00-목차.md) | [다음: 17장. 파일 입출력과 세이브/로드 ▶](ch17-파일입출력과세이브로드.md)


폭발, 연기, 불꽃, 흩날리는 먼지 — 게임을 화려하게 만드는 이런 시각 효과들은 대부분 하나의 정교한 그림이 아니라, 아주 작고 단순한 도형 수십에서 수백 개가 동시에 움직이는 것으로 만들어집니다. 이렇게 작은 조각 하나하나를 **파티클(particle)**이라 부르고, 이 파티클들을 대량으로 생성하고 관리하는 구조를 **파티클 시스템(particle system)**이라 합니다. 원리를 알고 나면 놀랄 만큼 단순합니다. 각 파티클은 자기 위치와 속도, 그리고 얼마나 더 살아있을지를 나타내는 수명만 가지고 있으며, 매 프레임 그 값에 따라 조금씩 움직이다 사라질 뿐입니다.

이번 장에서는 파티클 하나를 표현하는 구조체를 설계하고, 5장에서 다룬 발사체 풀(pool)과 같은 방식으로 여러 파티클을 고정 배열로 관리하는 방법을 익힙니다. 그리고 8장에서 다루는 충돌 감지 결과에 반응해, 총알이 적에게 맞는 순간 그 자리에서 작은 폭발 이펙트를 만들어내는 실전 예제로 마무리합니다.

## 파티클이란 무엇인가

폭발 하나를 상상해 봅시다. 화면에 미리 그려둔 "폭발 그림" 한 장을 재생하는 방법도 있지만(이런 방식은 7장에서 다룬 스프라이트 애니메이션에 해당합니다), 훨씬 유연하고 다양한 결과를 낼 수 있는 방법은 폭발 지점에서 작은 점들이 사방으로 튀어나가 점점 옅어지며 사라지는 모습을 직접 시뮬레이션하는 것입니다. 이때 튀어나가는 점 하나하나가 파티클입니다.

파티클 하나가 가져야 할 정보는 단순합니다.

- **위치(position)**: 지금 이 파티클이 화면 어디에 있는가
- **속도(velocity)**: 매 초 어느 방향으로 얼마나 움직이는가
- **수명(life)**: 앞으로 얼마나 더 살아있을 것인가(초 단위)
- **색(color)**: 이 파티클을 어떤 색으로 그릴 것인가

이 네 가지만으로도 폭발, 불꽃, 연기 같은 다양한 효과를 표현할 수 있습니다. 폭발은 사방으로 빠르게 퍼지는 밝은 색 파티클들로, 연기는 위로 천천히 떠오르는 회색 파티클들로, 불꽃놀이는 위로 솟았다가 중력에 의해 떨어지는 파티클들로 만들 수 있습니다. 결국 파티클 시스템의 핵심은 "각 파티클을 어떻게 초기화하고, 매 프레임 어떻게 움직이는가"라는 규칙을 정하는 데 있습니다.

## Particle 구조체 설계

앞서 정리한 정보를 그대로 구조체로 옮기면 다음과 같습니다.

```c
typedef struct Particle {
    Vector2 position;   // 현재 위치
    Vector2 velocity;   // 초당 이동량
    float life;         // 남은 수명(초). 0 이하이면 비활성 상태로 취급
    Color color;        // 그릴 색상
} Particle;
```

여기서 눈여겨볼 부분은 파티클이 "활성 상태인지"를 나타내는 별도의 `bool` 변수를 두지 않았다는 점입니다. 대신 `life`가 0보다 큰지 여부로 활성 상태를 판단합니다. 수명이 다한 파티클은 어차피 더 이상 존재할 이유가 없으므로, `life <= 0.0f`라는 조건 하나가 "이 파티클은 비활성 상태다"라는 의미를 자연스럽게 대신합니다. 변수를 하나 줄이면서도 의미는 그대로 유지하는 셈입니다.

## 파티클 풀: 미리 만들어두고 재사용하기

파티클 하나짜리 폭발은 볼품이 없습니다. 그럴듯한 효과를 내려면 폭발 한 번에 수십 개, 화면에 여러 폭발이 동시에 일어나면 수백 개의 파티클이 동시에 존재해야 합니다. 그렇다고 폭발이 일어날 때마다 `malloc`으로 파티클을 새로 할당하고, 수명이 다하면 `free`로 해제하는 방식은 좋지 않습니다. 매 프레임 수십, 수백 번씩 할당과 해제를 반복하면 성능에도 부담이 되고, 해제를 깜빡하면 메모리 누수로 이어지기도 쉽습니다.

5장에서 발사체를 다룰 때 이미 이 문제의 해법을 사용해 본 적이 있습니다. `MAX_BULLETS`개의 고정 크기 배열을 미리 만들어두고, 각 칸이 "지금 사용 중인지"만 표시해 재사용하는 방식이었습니다. 파티클도 정확히 같은 방식으로 관리합니다.

```c
#define MAX_PARTICLES 256

static Particle particles[MAX_PARTICLES];
```

프로그램을 시작할 때는 모든 칸을 비활성 상태(`life = 0`)로 초기화해 둡니다.

```c
static void InitParticlePool(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        particles[i].life = 0.0f;
    }
}
```

새 파티클이 필요할 때는 배열을 훑으면서 비활성 상태인 칸(`life <= 0.0f`)을 찾아 그 자리를 재사용합니다. 새 메모리를 할당하지 않고, 이미 있던 칸의 값을 덮어쓰는 것뿐입니다.

```c
static void EmitParticle(Vector2 position, Vector2 velocity, float lifeTime, Color color)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (particles[i].life <= 0.0f)
        {
            particles[i].position = position;
            particles[i].velocity = velocity;
            particles[i].life = lifeTime;
            particles[i].color = color;
            return;   // 빈 칸을 찾아 채웠으므로 종료
        }
    }
    // 모든 칸이 사용 중이면 이번 요청은 무시한다 (MAX_PARTICLES를 늘리는 것도 방법)
}
```

`MAX_PARTICLES`를 다 채운 상태에서 새 파티클을 요청하면 그냥 무시됩니다. 화면에 동시에 존재할 수 있는 파티클 수에 상한선을 둠으로써, 아무리 폭발이 연달아 일어나도 메모리 사용량과 처리 시간이 예측 가능한 범위 안에 머물게 됩니다. 이 상한선은 만들려는 효과의 화려함과 목표 성능 사이에서 적절히 조절하면 됩니다.

## 파티클 갱신: 이동과 수명 관리

매 프레임 해야 할 일은 두 가지뿐입니다. 활성 상태인 파티클의 위치를 속도만큼 이동시키고, 남은 수명에서 델타 타임만큼을 뺍니다.

```c
static void UpdateParticles(float dt)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (particles[i].life > 0.0f)
        {
            particles[i].position.x += particles[i].velocity.x * dt;
            particles[i].position.y += particles[i].velocity.y * dt;
            particles[i].life -= dt;
        }
    }
}
```

`life`가 갱신 도중 0 이하로 떨어지면, 그 즉시 다음 프레임부터 이 파티클은 "비활성"으로 취급됩니다. 별도로 "삭제"하는 코드가 필요 없다는 점에 주목하세요. `life` 값 하나가 낮아지는 것만으로 자연스럽게 비활성화되고, 그 칸은 다음번 `EmitParticle` 호출에서 다시 채워질 후보가 됩니다.

이 구조는 3장에서 다룬 델타 타임 기반 이동, 즉 "초당 이동 거리 × 델타 타임"으로 프레임 속도와 무관하게 일정한 속도를 유지하는 원리를 파티클에도 그대로 적용한 것입니다.

## 파티클 그리기: 사라질수록 옅어지는 효과

파티클을 그릴 때 `color`를 그대로 사용하면, 수명이 막 시작된 파티클이나 거의 다 된 파티클이나 똑같이 진하게 보입니다. 실제 폭발이나 연기 효과는 시간이 지날수록 점점 옅어지다 사라지는 것이 훨씬 자연스럽습니다. 3장에서 배운 `Fade(color, alpha)` 함수를 이용하면 이 효과를 손쉽게 낼 수 있습니다.

파티클이 처음 생성될 때의 수명을 알고 있다면, 지금 남은 수명의 비율을 알파 값으로 사용하면 됩니다.

```c
#define PARTICLE_LIFETIME 0.6f

static void DrawParticles(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (particles[i].life > 0.0f)
        {
            float alpha = particles[i].life / PARTICLE_LIFETIME;   // 1.0(방금 생성) ~ 0.0(소멸 직전)
            DrawCircleV(particles[i].position, 3.0f, Fade(particles[i].color, alpha));
        }
    }
}
```

파티클이 막 생성되었을 때는 `life`가 `PARTICLE_LIFETIME`과 같으므로 `alpha`가 1.0(완전 불투명)이고, 수명이 다 되어갈수록 `alpha`가 0에 가까워지면서 점점 투명해집니다. `DrawCircleV`는 5장에서 살펴본 것처럼 `Vector2` 좌표를 그대로 받는 원 그리기 함수이므로, 파티클의 `position`을 변환 없이 바로 넘길 수 있습니다.

## 폭발처럼 사방으로 퍼지는 파티클 만들기

`EmitParticle`은 파티클 하나를 지정한 속도로 생성할 뿐, "어느 방향으로 퍼질지"는 호출하는 쪽에서 정해야 합니다. 폭발 효과는 보통 한 지점에서 사방으로 무작위 방향, 무작위 속력으로 파티클들이 튀어나가는 모습입니다. 5장에서 다룬 각도와 삼각함수(`cosf`, `sinf`, `DEG2RAD`)를 이용하면 이런 방향을 손쉽게 만들 수 있습니다.

```c
#include <math.h>

static void EmitExplosion(Vector2 origin, int count, Color color)
{
    for (int i = 0; i < count; i++)
    {
        float angleDeg = (float)GetRandomValue(0, 360);
        float speed = (float)GetRandomValue(80, 220);

        Vector2 velocity = {
            cosf(angleDeg * DEG2RAD) * speed,
            sinf(angleDeg * DEG2RAD) * speed
        };

        EmitParticle(origin, velocity, PARTICLE_LIFETIME, color);
    }
}
```

`GetRandomValue(min, max)`는 `min`과 `max` 사이(양 끝 포함)의 정수 하나를 무작위로 반환하는 raylib 함수입니다. 여기서는 이 함수로 0도에서 360도 사이의 각도와, 80~220픽셀/초 사이의 속력을 무작위로 뽑아 파티클마다 서로 다른 방향과 속력을 부여합니다. `count`개의 파티클을 한 번에 요청하므로, `EmitExplosion(origin, 40, ORANGE)`처럼 호출하면 그 자리에서 주황색 파티클 40개가 사방으로 흩어지는 폭발이 만들어집니다.

## 실전 예제: 총알이 적에 맞았을 때 폭발 이펙트

이제 8장에서 다루는 원-원 충돌 감지 함수 `CheckCollisionCircles`를 이용해, 총알이 적에게 명중하는 순간 폭발 파티클을 발생시키는 완전한 예제를 만들어 보겠습니다.

```c
bool CheckCollisionCircles(Vector2 center1, float radius1, Vector2 center2, float radius2);
```

`CheckCollisionCircles`는 두 원의 중심 좌표와 반지름을 받아, 두 원이 겹치면 `true`를 반환합니다. 총알과 적을 모두 원으로 근사하면, 이 함수 하나로 "맞았는가"를 매 프레임 간단히 검사할 수 있습니다.

```c
#include "raylib.h"
#include "raymath.h"
#include <math.h>

#define MAX_PARTICLES     256
#define PARTICLE_LIFETIME 0.6f

typedef struct Particle {
    Vector2 position;
    Vector2 velocity;
    float life;
    Color color;
} Particle;

static Particle particles[MAX_PARTICLES];

static void InitParticlePool(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++) particles[i].life = 0.0f;
}

static void EmitParticle(Vector2 position, Vector2 velocity, float lifeTime, Color color)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (particles[i].life <= 0.0f)
        {
            particles[i].position = position;
            particles[i].velocity = velocity;
            particles[i].life = lifeTime;
            particles[i].color = color;
            return;
        }
    }
}

static void EmitExplosion(Vector2 origin, int count, Color color)
{
    for (int i = 0; i < count; i++)
    {
        float angleDeg = (float)GetRandomValue(0, 360);
        float speed = (float)GetRandomValue(80, 220);

        Vector2 velocity = {
            cosf(angleDeg * DEG2RAD) * speed,
            sinf(angleDeg * DEG2RAD) * speed
        };

        EmitParticle(origin, velocity, PARTICLE_LIFETIME, color);
    }
}

static void UpdateParticles(float dt)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (particles[i].life > 0.0f)
        {
            particles[i].position.x += particles[i].velocity.x * dt;
            particles[i].position.y += particles[i].velocity.y * dt;
            particles[i].life -= dt;
        }
    }
}

static void DrawParticles(void)
{
    for (int i = 0; i < MAX_PARTICLES; i++)
    {
        if (particles[i].life > 0.0f)
        {
            float alpha = particles[i].life / PARTICLE_LIFETIME;
            DrawCircleV(particles[i].position, 3.0f, Fade(particles[i].color, alpha));
        }
    }
}

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;

    InitWindow(screenWidth, screenHeight, "16장 - 파티클 시스템과 이펙트");
    SetTargetFPS(60);

    InitParticlePool();

    Vector2 enemyPos = { 400.0f, 100.0f };
    float enemyRadius = 20.0f;
    bool enemyAlive = true;
    float respawnTimer = 0.0f;

    Vector2 bulletPos = { 0 };
    float bulletRadius = 5.0f;
    bool bulletAlive = false;
    float bulletSpeed = 400.0f;

    while (!WindowShouldClose())
    {
        float dt = GetFrameTime();

        // 스페이스바로 화면 아래에서 위로 총알 발사
        if (IsKeyPressed(KEY_SPACE) && !bulletAlive)
        {
            bulletPos = (Vector2){ screenWidth / 2.0f, screenHeight - 30.0f };
            bulletAlive = true;
        }

        if (bulletAlive)
        {
            bulletPos.y -= bulletSpeed * dt;
            if (bulletPos.y < 0.0f) bulletAlive = false;   // 화면 밖으로 나가면 소멸
        }

        // 8장에서 다루는 원-원 충돌 감지: 총알이 적에게 명중했는가
        if (bulletAlive && enemyAlive &&
            CheckCollisionCircles(bulletPos, bulletRadius, enemyPos, enemyRadius))
        {
            EmitExplosion(enemyPos, 40, ORANGE);
            enemyAlive = false;
            bulletAlive = false;
        }

        // 적이 죽은 뒤 1초 후 다른 위치에 다시 등장
        if (!enemyAlive)
        {
            respawnTimer += dt;
            if (respawnTimer >= 1.0f)
            {
                enemyPos = (Vector2){ (float)GetRandomValue(50, screenWidth - 50), 100.0f };
                enemyAlive = true;
                respawnTimer = 0.0f;
            }
        }

        UpdateParticles(dt);

        BeginDrawing();

            ClearBackground(RAYWHITE);

            if (enemyAlive) DrawCircleV(enemyPos, enemyRadius, RED);
            if (bulletAlive) DrawCircleV(bulletPos, bulletRadius, DARKGRAY);

            DrawParticles();

            DrawText("스페이스바로 발사", 20, 20, 20, GRAY);

        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

이 예제를 실행하면 스페이스바를 누를 때마다 총알이 위로 발사되고, 총알이 빨간 원(적)에 닿는 순간 그 위치에서 주황색 파티클 40개가 사방으로 퍼지며 점점 옅어지다 사라집니다. 총알과 적 모두 파티클과 마찬가지로 `bool` 플래그(`bulletAlive`, `enemyAlive`)로 활성 여부를 관리한다는 점도 눈여겨볼 만합니다. 규모는 다르지만 "필요할 때 켜고, 조건이 되면 끄는" 사고방식은 총알 하나든 파티클 수백 개든 동일하게 적용됩니다.

이 구조에 살을 붙이면 다양한 이펙트로 확장할 수 있습니다. 예를 들어 `EmitExplosion`에서 속도에 아래 방향 성분을 더하면 중력의 영향을 받는 파편처럼 보이게 만들 수 있고, 파티클마다 크기를 무작위로 다르게 주면 더 불규칙한 느낌을 낼 수 있습니다. 연기 효과를 만들고 싶다면 속도를 위쪽으로만 천천히 주고, 수명을 훨씬 길게(`PARTICLE_LIFETIME`을 2~3초로) 설정한 뒤 색을 회색 계열로 바꾸면 됩니다.

## 요약

- 파티클은 위치, 속도, 남은 수명, 색만으로 표현되는 아주 단순한 단위이며, 여러 개가 모여 폭발·연기·불꽃 같은 효과를 만듭니다.
- `Particle` 구조체는 별도의 활성 플래그 없이 `life <= 0.0f`인지로 활성/비활성 상태를 판단할 수 있습니다.
- 5장의 발사체 풀과 마찬가지로, 파티클도 `MAX_PARTICLES`개의 고정 배열을 미리 만들어두고 빈 칸(`life <= 0`)을 찾아 재사용하는 풀 패턴으로 관리하면 `malloc`/`free` 없이 대량의 파티클을 안정적으로 다룰 수 있습니다.
- 매 프레임 활성 파티클의 위치를 `velocity * dt`만큼 이동시키고 `life`에서 `dt`를 빼는 것이 갱신 로직의 전부이며, 그리기 단계에서 `life` 비율을 `Fade`의 알파 값으로 사용하면 사라질수록 옅어지는 자연스러운 효과를 얻을 수 있습니다.
- 8장에서 다루는 `CheckCollisionCircles` 같은 충돌 감지 함수의 결과에 반응해 그 위치에서 `EmitExplosion`을 호출하면, 총알이 적에게 맞는 순간 폭발 이펙트를 재생하는 식으로 게임 로직과 파티클 시스템을 연결할 수 있습니다.

## 연습문제

1. 본문의 `EmitExplosion`을 응용해, 파티클이 위쪽 방향으로만 천천히 퍼지고 회색 계열 색을 가지며 수명이 2초 이상인 `EmitSmoke` 함수를 만들어 굴뚝에서 피어오르는 연기 효과를 구현해 보세요.
2. `UpdateParticles`에 중력 효과를 추가해, 매 프레임 `velocity.y`에 일정한 값(예: `500.0f * dt`)을 더함으로써 파티클이 포물선을 그리며 떨어지도록 만들어 보세요.
3. `MAX_PARTICLES`를 16처럼 작은 값으로 바꾸고 `EmitExplosion`을 짧은 시간 안에 여러 번 호출해 보세요. 파티클 풀이 가득 찼을 때 어떤 현상이 나타나는지 관찰하고, 이 현상이 왜 발생하는지 설명해 보세요.
4. 파티클 색상과 크기를 무작위로 다르게 만들어 보세요. (힌트: `Particle` 구조체에 `float radius` 필드를 추가하고, `EmitParticle`에서 `GetRandomValue`로 반지름을 정합니다.)
5. 본문 예제에서 적이 파티클과 충돌하는지도 검사하도록 확장해, 폭발 파티클 중 하나가 다시 살아있는 적에 닿으면 연쇄적으로 또 다른 폭발이 일어나도록 만들어 보세요. 이때 파티클 수가 과도하게 늘어나지 않도록 어떤 제약을 둘지도 함께 고민해 보세요.
