# 14장. 셰이더 기초

[◀ 이전: 13장. 모델과 메시](ch13-모델과메시.md) | [📖 목차](00-목차.md) | [다음: 15장. 게임 상태 관리와 씬 전환 ▶](ch15-게임상태관리와씬전환.md)


지금까지 이 책에서 그려온 모든 도형과 텍스처, 3D 모델은 결국 화면의 픽셀 하나하나에 색을 정하는 과정을 거쳐 그려집니다. 이 "픽셀마다 어떤 색을 칠할 것인가"를 계산하는 작업은 사실 CPU가 아니라 그래픽카드(GPU)가 담당하며, 그 계산 방법을 정의하는 작은 프로그램을 **셰이더(shader)**라고 부릅니다.

13장까지는 raylib가 내부적으로 기본 셰이더를 자동으로 사용해주었기 때문에 셰이더의 존재를 신경 쓸 필요가 없었습니다. 이번 장에서는 그 기본 셰이더를 우리가 직접 만든 셰이더로 바꿔치기해서, 색이 시간에 따라 서서히 변하는 간단한 효과를 만들어봅니다. 셰이더는 그 자체로 하나의 프로그래밍 언어이자 매우 방대한 주제이므로, 이 장의 목표는 GLSL 문법 자체를 깊이 파고드는 것이 아니라 **raylib에서 셰이더를 "적용하는 방법"에 집중해 큰 그림을 잡는 것**입니다. 이렇게 잡아둔 기본기는 16장의 파티클 이펙트처럼 화면 전체에 시각 효과를 입히고 싶을 때 유용한 출발점이 되어 줍니다.

## 셰이더란 무엇인가

셰이더는 GPU에서 실행되는 작은 프로그램입니다. CPU에서 실행되는 `main` 함수가 순차적으로 한 번 실행되는 것과 달리, 셰이더는 그리기 명령 한 번에 화면의 정점(vertex)이나 픽셀(fragment) 수만큼 **병렬로** 실행됩니다. 예를 들어 800x450 크기의 텍스처 하나를 그린다면, 프래그먼트 셰이더는 (이론적으로) 36만 개의 픽셀 각각에 대해 동시에 실행되어 그 픽셀의 색을 계산합니다. 이런 대규모 병렬 처리 덕분에 GPU는 CPU보다 훨씬 빠르게 그래픽 연산을 처리할 수 있습니다.

셰이더 프로그램은 보통 두 종류로 나뉩니다.

- **정점 셰이더(vertex shader)**: 메시를 이루는 정점 하나하나에 대해 실행되며, 그 정점이 화면의 어느 위치에 그려질지를 계산합니다. 3D 모델을 카메라 시점에 맞게 투영하는 계산이 여기서 일어납니다.
- **프래그먼트 셰이더(fragment shader)**: 화면에 실제로 칠해질 픽셀 하나하나에 대해 실행되며, 그 픽셀의 최종 색상을 계산합니다. 텍스처에서 색을 읽어오거나, 조명 효과를 계산하거나, 이번 장 예제처럼 시간에 따라 색을 바꾸는 것도 모두 여기서 이루어집니다.

raylib는 셰이더를 **GLSL(OpenGL Shading Language)**이라는 언어로 작성합니다. GLSL은 C와 문법이 상당히 비슷해서 이 책을 따라온 독자라면 낯설지 않게 읽을 수 있지만, 어디까지나 GPU에서 동작하는 별도의 언어이며 C 코드와는 컴파일되는 방식도, 실행되는 곳도 다릅니다.

## 셰이더 불러오기: LoadShader와 UnloadShader

raylib에서 셰이더를 사용하려면 먼저 GLSL로 작성된 셰이더 코드를 파일에서 읽어 컴파일해야 합니다. 이 역할을 하는 함수가 `LoadShader`입니다.

```c
Shader LoadShader(const char *vsFileName, const char *fsFileName);
void UnloadShader(Shader shader);
```

`vsFileName`은 정점 셰이더 파일 경로, `fsFileName`은 프래그먼트 셰이더 파일 경로입니다. 두 파일 모두 지정할 수도 있지만, 정점 셰이더는 대부분의 경우 raylib의 기본 정점 셰이더만으로 충분합니다(정점을 화면에 투영하는 계산 자체는 특별히 커스터마이즈할 이유가 적기 때문입니다). 이런 경우 `vsFileName` 자리에 `NULL`을 넘기면 raylib가 내장하고 있는 기본 정점 셰이더를 대신 사용합니다.

```c
// 정점 셰이더는 raylib 기본값을 쓰고, 프래그먼트 셰이더만 직접 작성한 것을 사용한다
Shader shader = LoadShader(NULL, "resources/shaders/color_shift.fs");
```

이렇게 만든 `Shader`는 다 사용한 뒤 `UnloadShader`로 반드시 해제해야 합니다. 이는 6장에서 텍스처를 `UnloadTexture`로 해제했던 것, 13장에서 모델을 `UnloadModel`로 해제했던 것과 같은 이유입니다 — GPU 쪽 자원은 raylib가 자동으로 정리해주지 않기 때문입니다.

## BeginShaderMode와 EndShaderMode: 원하는 그리기에만 셰이더 적용하기

셰이더를 불러왔다고 해서 이후의 모든 그리기에 자동으로 적용되지는 않습니다. raylib는 기본적으로 내장된 기본 셰이더를 사용해 도형과 텍스처를 그리며, 우리가 만든 셰이더를 쓰고 싶은 구간만 `BeginShaderMode`와 `EndShaderMode`로 감싸주어야 합니다.

```c
void BeginShaderMode(Shader shader);
void EndShaderMode(void);
```

`BeginDrawing`/`EndDrawing`이나 `BeginMode3D`/`EndMode3D`와 사용법이 완전히 동일한 짝 함수입니다. 이 구간 안에서 이루어지는 그리기 호출(`DrawTexture`, `DrawRectangle`, `DrawModel` 등 무엇이든)은 모두 지정한 셰이더로 렌더링됩니다.

```c
BeginDrawing();
    ClearBackground(RAYWHITE);

    BeginShaderMode(shader);
        DrawTexture(texture, 0, 0, WHITE);
    EndShaderMode();

    DrawText("이 텍스트는 기본 셰이더로 그려진다", 10, 10, 20, BLACK);
EndDrawing();
```

`BeginShaderMode` 구간을 벗어난 `DrawText` 호출은 다시 raylib의 기본 셰이더로 그려진다는 점에 주목하세요. 이렇게 셰이더 적용 범위를 명시적으로 지정할 수 있기 때문에, 화면의 특정 요소(예: 배경)에만 특수 효과를 주고 UI 텍스트 같은 나머지 요소는 평범하게 그리는 식의 조합이 가능합니다.

## 셰이더에 값 전달하기: 유니폼 변수

GLSL 셰이더 코드는 C 프로그램과 완전히 분리되어 GPU에서 실행되지만, C 코드에서 셰이더 안으로 값을 흘려보낼 방법이 필요합니다. 예를 들어 "지금이 몇 초째인지"를 셰이더가 알아야 시간에 따라 색이 변하는 효과를 만들 수 있습니다. 이렇게 CPU에서 GPU의 셰이더로 전달하는 값을 GLSL에서는 **유니폼(uniform) 변수**라고 부릅니다.

raylib에서 유니폼 변수를 다루는 과정은 두 단계입니다. 먼저 유니폼 변수의 "위치(location)"를 알아낸 뒤, 그 위치에 값을 써넣습니다.

```c
int GetShaderLocation(Shader shader, const char *uniformName);
void SetShaderValue(Shader shader, int locIndex, const void *value, int uniformType);
```

`GetShaderLocation`은 셰이더 코드 안에 선언된 유니폼 변수의 이름을 문자열로 받아, GPU 내부에서 그 변수를 가리키는 정수 위치값을 돌려줍니다. 이 위치값은 셰이더가 컴파일된 이후에는 바뀌지 않으므로, 매 프레임 다시 조회할 필요 없이 게임 루프 시작 전에 한 번만 구해두면 됩니다.

```c
int timeLoc = GetShaderLocation(shader, "time");
```

`SetShaderValue`는 이렇게 구한 위치에 실제 값을 써넣습니다. `value`는 값의 주소, `uniformType`은 그 값이 어떤 타입인지를 raylib에게 알려주는 열거형 값입니다.

```c
float time = (float)GetTime();
SetShaderValue(shader, timeLoc, &time, SHADER_UNIFORM_FLOAT);
```

`uniformType`으로 가장 자주 쓰이는 값은 다음과 같습니다.

- `SHADER_UNIFORM_FLOAT`: `float` 하나
- `SHADER_UNIFORM_VEC2`, `SHADER_UNIFORM_VEC3`, `SHADER_UNIFORM_VEC4`: `float` 2개/3개/4개로 이루어진 벡터(5장에서 다룬 `Vector2`, `Vector3` 등과 대응됩니다)
- `SHADER_UNIFORM_INT`: `int` 하나

값의 타입이 GLSL 쪽 선언과 정확히 일치해야 한다는 점이 중요합니다. GLSL에서 `uniform float time;`으로 선언했다면 C 쪽에서도 `float` 변수의 주소와 `SHADER_UNIFORM_FLOAT`를 함께 넘겨야 합니다.

## 예제: 시간에 따라 색이 변하는 셰이더

지금까지 배운 내용을 모아, 화면을 시간에 따라 무지개처럼 색이 서서히 변하는 텍스처로 채우는 예제를 만들어보겠습니다. 먼저 프래그먼트 셰이더 코드를 작성합니다. 아래 코드를 `resources/shaders/color_shift.fs` 라는 이름으로 저장한다고 가정합니다.

```glsl
#version 330

// 정점 셰이더로부터 픽셀마다 보간되어 전달되는 입력값
// (raylib의 기본 정점 셰이더가 채워준다)
in vec2 fragTexCoord;
in vec4 fragColor;

// raylib가 그리기 호출 시 자동으로 채워주는 기본 유니폼
uniform sampler2D texture0;
uniform vec4 colDiffuse;

// C 코드에서 SetShaderValue로 직접 채워주는 사용자 정의 유니폼
uniform float time;

// 이 프래그먼트 셰이더가 최종적으로 계산해야 하는 출력값
out vec4 finalColor;

void main()
{
    vec4 texelColor = texture(texture0, fragTexCoord);

    vec3 color;
    color.r = 0.5 + 0.5 * sin(time);
    color.g = 0.5 + 0.5 * sin(time + 2.0);
    color.b = 0.5 + 0.5 * sin(time + 4.0);

    finalColor = vec4(color, 1.0) * texelColor * colDiffuse;
}
```

`sin` 함수에 `time`을 그대로, 또는 `2.0`이나 `4.0`만큼 위상을 어긋나게 더한 값을 넣어 R, G, B 세 채널을 서로 다른 타이밍으로 진동시켰습니다. `sin`의 결과값 범위는 -1.0에서 1.0 사이이므로 `0.5 + 0.5 * sin(...)`으로 변환해 0.0에서 1.0 사이의 색상값 범위로 맞춰주었습니다. `texture0`와 `colDiffuse`는 이름과 위치가 정해진 raylib의 표준 유니폼으로, `DrawTexture` 계열 함수를 호출하면 raylib가 알아서 채워줍니다. 우리가 직접 신경 써야 하는 것은 `time` 하나뿐입니다.

이제 이 셰이더를 불러와 적용하는 C 코드를 작성합니다.

```c
#include "raylib.h"

int main(void)
{
    const int screenWidth = 800;
    const int screenHeight = 450;

    InitWindow(screenWidth, screenHeight, "14장 - 시간에 따라 색이 변하는 셰이더");

    // 정점 셰이더는 raylib 기본값을 사용하고, 프래그먼트 셰이더만 직접 작성한 것을 불러온다
    Shader shader = LoadShader(NULL, "resources/shaders/color_shift.fs");
    int timeLoc = GetShaderLocation(shader, "time");

    // 셰이더 효과를 눈으로 확인할 화면 전체 크기의 흰색 텍스처를 하나 만든다
    Image blankImage = GenImageColor(screenWidth, screenHeight, WHITE);
    Texture2D blank = LoadTextureFromImage(blankImage);
    UnloadImage(blankImage);

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        float time = (float)GetTime();
        SetShaderValue(shader, timeLoc, &time, SHADER_UNIFORM_FLOAT);

        BeginDrawing();
            ClearBackground(RAYWHITE);

            BeginShaderMode(shader);
                DrawTexture(blank, 0, 0, WHITE);
            EndShaderMode();

            DrawText("셰이더 바깥의 텍스트는 영향을 받지 않는다", 10, 10, 20, BLACK);
        EndDrawing();
    }

    UnloadTexture(blank);
    UnloadShader(shader);
    CloseWindow();
    return 0;
}
```

매 프레임 `GetTime()`으로 프로그램이 시작된 이후 흐른 시간을 초 단위로 가져와 `time` 유니폼에 갱신해주는 부분이 핵심입니다. `GetTime()`은 `double`을 반환하므로 `SHADER_UNIFORM_FLOAT`에 맞춰 `float`로 형변환했습니다. 이 값이 `sin` 함수 안으로 들어가면서 화면 전체가 서서히 무지개색으로 물드는 것을 확인할 수 있습니다.

`GenImageColor`는 지정한 크기와 단색으로 채워진 `Image`를 만드는 함수로, 6장에서 다룬 텍스처 로딩과 마찬가지로 `LoadTextureFromImage`와 짝을 이뤄 사용합니다. 여기서는 외부 이미지 파일 없이 셰이더 효과 자체에 집중할 수 있도록 흰색 텍스처를 코드로 즉석에서 만들어 사용했습니다. 실제 게임에서는 이 자리에 캐릭터나 배경 스프라이트 텍스처를 넣어, 예를 들어 "피격 시 잠깐 붉게 물드는 효과" 같은 것을 이런 방식으로 구현할 수 있습니다.

## 셰이더, 이 책의 범위 밖에 있는 넓은 세계

셰이더는 그 자체로 책 한 권을 채우고도 남을 만큼 깊은 주제입니다. 조명 계산, 그림자, 후처리(post-processing) 효과, 물리 기반 렌더링(PBR) 등 현대적인 그래픽스의 화려한 기능 대부분이 결국 셰이더 코드로 구현됩니다. GLSL 문법 자체(자료형, 내장 함수, `varying`/`in`/`out` 사이의 데이터 흐름 등)를 제대로 익히려면 별도의 그래픽스 프로그래밍 학습이 필요합니다.

이번 장의 목표는 그 넓은 세계로 들어가는 문 앞까지 안내하는 것이었습니다. `LoadShader`로 셰이더를 불러오고, `BeginShaderMode`/`EndShaderMode`로 원하는 그리기에만 적용하고, `GetShaderLocation`과 `SetShaderValue`로 C 코드와 셰이더 사이에 값을 주고받는 이 네 가지 흐름만 잘 기억해두면, 나중에 더 복잡한 GLSL 코드를 인터넷이나 raylib 예제 저장소에서 가져다 쓸 때도 "이걸 내 프로그램에 어떻게 연결해야 하는지" 헤매지 않을 수 있습니다.

## 요약

- 셰이더는 GPU에서 정점 또는 픽셀 단위로 병렬 실행되는 프로그램으로, raylib에서는 GLSL로 작성한다. 정점 셰이더는 정점의 화면 위치를, 프래그먼트 셰이더는 픽셀의 최종 색상을 계산한다.
- `LoadShader(vsFileName, fsFileName)`으로 셰이더를 불러온다. 정점 셰이더 자리에 `NULL`을 넘기면 raylib의 기본 정점 셰이더가 대신 쓰인다. 다 쓴 셰이더는 `UnloadShader`로 해제한다.
- `BeginShaderMode(shader)`와 `EndShaderMode()`로 감싼 구간의 그리기 호출에만 해당 셰이더가 적용되며, 그 바깥의 그리기는 raylib의 기본 셰이더를 그대로 사용한다.
- `GetShaderLocation(shader, name)`으로 유니폼 변수의 위치를 구하고, `SetShaderValue(shader, loc, &value, uniformType)`로 값을 써넣어 C 코드에서 셰이더로 값을 전달할 수 있다. `SHADER_UNIFORM_FLOAT`, `SHADER_UNIFORM_VEC3` 등 값의 타입은 GLSL 쪽 선언과 일치해야 한다.
- 셰이더와 GLSL은 이 책의 범위를 크게 넘어서는 깊은 주제이므로, 이 장에서는 문법 자체보다 raylib에서 셰이더를 "적용하는 방법"에 집중했다.

2. `LoadShader`를 호출할 때 정점 셰이더 자리에 `NULL`을 넘기면 어떤 일이 일어나는지 설명하고, 왜 대부분의 경우 이렇게 해도 충분한지 생각해보세요.
3. 이번 장의 색 변화 예제에서 `sin(time + 2.0)`, `sin(time + 4.0)`처럼 위상을 다르게 준 이유가 무엇인지, 만약 세 채널 모두 `sin(time)`을 그대로 썼다면 결과가 어떻게 달라졌을지 설명해보세요.
4. `GetShaderLocation`을 매 프레임 반복 호출하지 않고 게임 루프 시작 전에 한 번만 호출해도 되는 이유를 설명해보세요.
5. 이번 장 예제의 GLSL 코드를 수정하여, 색이 변하는 속도를 조절할 수 있는 `speed`라는 유니폼 변수를 추가해보세요. C 코드에서 `SetShaderValue`로 `speed` 값을 설정하고, GLSL 코드에서는 `sin(time * speed)`처럼 활용하면 됩니다.
