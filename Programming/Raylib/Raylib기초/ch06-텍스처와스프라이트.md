# 6장. 텍스처와 스프라이트

[◀ 이전: 5장. 벡터와 기본 수학(raymath)](ch05-벡터와기본수학.md) | [📖 목차](00-목차.md) | [다음: 7장. 애니메이션 기초 ▶](ch07-애니메이션기초.md)


3장에서는 `DrawRectangle`, `DrawCircle` 같은 함수로 색깔 있는 도형만 그렸습니다. 실제 게임의 캐릭터와 배경은 대부분 그림 파일, 즉 이미지로 되어 있습니다. 이번 장에서는 이미지 파일을 화면에 그리는 방법과, 하나의 이미지 파일 안에 여러 장의 그림을 담아두고 필요한 부분만 잘라 쓰는 스프라이트 시트(sprite sheet) 기법을 다룹니다. 이 내용은 7장 애니메이션의 바로 앞 단계입니다.

## 텍스처란 무엇인가

**텍스처(Texture)** 는 이미지 파일을 읽어서 GPU(그래픽 카드) 메모리에 올려둔 것입니다. CPU 메모리에 있는 일반적인 데이터(raylib에서는 이를 `Image`라는 별도의 구조체로 다룹니다)와 달리, 텍스처는 GPU가 즉시 사용할 수 있는 형태로 저장되어 있어서 화면에 매우 빠르게 그릴 수 있습니다.

raylib에서 텍스처는 `Texture2D` 구조체로 표현됩니다.

```c
typedef struct Texture2D {
    unsigned int id;    // GPU 텍스처 ID
    int width;           // 가로 크기(픽셀)
    int height;           // 세로 크기(픽셀)
    int mipmaps;          // 밉맵 레벨 수
    int format;            // 픽셀 포맷
} Texture2D;
```

`Texture`는 `Texture2D`의 별칭(alias)이므로 두 이름 모두 같은 타입을 가리킵니다. 텍스처는 다음처럼 `LoadTexture` 함수로 파일에서 직접 로드합니다.

```c
Texture2D LoadTexture(const char *fileName);
```

```c
Texture2D playerTexture = LoadTexture("resources/player.png");
```

raylib는 PNG, JPG, BMP, GIF, TGA 등 다양한 이미지 포맷을 별도의 라이브러리 설치 없이 바로 읽을 수 있습니다. 경로는 프로그램을 실행하는 위치(작업 디렉터리) 기준의 상대 경로이므로, 리소스 폴더를 실행 파일과 같은 위치에 두거나 `SetWorkingDirectory` 등으로 경로를 관리하는 것이 일반적입니다.

### 반드시 해제해야 한다: UnloadTexture

텍스처는 GPU 메모리를 차지하는 자원입니다. 사용이 끝나면 반드시 다음 함수로 해제해주어야 합니다.

```c
void UnloadTexture(Texture2D texture);
```

`LoadTexture`로 로드한 텍스처는 프로그램이 끝나거나 더 이상 필요 없어질 때 `UnloadTexture`로 짝을 맞춰 해제해야 합니다. 이는 2장에서 `InitWindow`와 `CloseWindow`를 항상 짝지어 호출했던 것과 같은 원칙입니다 — **raylib에서 "Load"로 시작하는 함수는 대부분 그에 대응하는 "Unload" 함수를 가지며, 자원 누수를 막으려면 반드시 짝을 맞춰야 합니다.** 텍스처를 해제하지 않고 계속 새로 로드하면, 프로그램을 오래 실행할수록 GPU 메모리 사용량이 계속 늘어나는 메모리 누수가 발생합니다.

일반적인 패턴은 다음과 같습니다.

```c
#include "raylib.h"

int main(void)
{
    InitWindow(800, 450, "6장 - 텍스처 로드");

    Texture2D playerTexture = LoadTexture("resources/player.png");

    SetTargetFPS(60);

    while (!WindowShouldClose())
    {
        BeginDrawing();
            ClearBackground(RAYWHITE);
            DrawTexture(playerTexture, 350, 200, WHITE);
        EndDrawing();
    }

    UnloadTexture(playerTexture);  // 로드했던 텍스처는 반드시 해제
    CloseWindow();

    return 0;
}
```

`InitWindow`가 먼저 호출된 뒤에 `LoadTexture`를 호출해야 한다는 점에 유의하세요. 창(그래픽 컨텍스트)이 만들어지기 전에는 GPU에 텍스처를 올릴 수 없습니다.

## 텍스처 그리기: DrawTexture, DrawTextureEx, DrawTextureRec

### DrawTexture — 기본 그리기

가장 단순한 형태로, 텍스처를 원본 크기 그대로 지정한 좌표에 그립니다.

```c
void DrawTexture(Texture2D texture, int posX, int posY, Color tint);
```

```c
DrawTexture(playerTexture, 100, 100, WHITE);
```

`posX`, `posY`는 텍스처의 왼쪽 위 모서리가 그려질 좌표입니다. `tint`는 텍스처에 색을 입히는 매개변수로, 원본 색을 그대로 쓰고 싶다면 `WHITE`를 넘기면 됩니다(흰색은 곱해도 색이 변하지 않으므로 "색을 입히지 않음"과 같은 효과입니다). 예를 들어 `RED`를 넘기면 텍스처 전체에 붉은 색조가 섞여 그려집니다.

### DrawTextureEx — 크기와 회전 지정

크기를 확대/축소하거나 회전시켜 그리고 싶을 때 사용합니다.

```c
void DrawTextureEx(Texture2D texture, Vector2 position, float rotation, float scale, Color tint);
```

```c
Vector2 pos = { 300.0f, 200.0f };
DrawTextureEx(playerTexture, pos, 45.0f, 2.0f, WHITE);  // 45도 회전, 2배 확대
```

`rotation`은 도(degree) 단위이며, `scale`은 배율입니다(1.0이 원본 크기). 위치는 `Vector2`로 받으므로 5장에서 배운 벡터 연산과 자연스럽게 어울립니다.

### DrawTextureRec — 텍스처의 일부 영역만 그리기

`DrawTextureRec`는 텍스처 전체가 아니라 `Rectangle`로 지정한 일부 영역만 잘라서 그립니다. 이 함수가 바로 스프라이트 시트를 다루는 핵심 도구입니다.

```c
void DrawTextureRec(Texture2D texture, Rectangle source, Vector2 position, Color tint);
```

`Rectangle`은 raylib가 제공하는 사각형 구조체입니다.

```c
typedef struct Rectangle {
    float x;
    float y;
    float width;
    float height;
} Rectangle;
```

여기서 `source`의 `x`, `y`, `width`, `height`는 화면 좌표가 아니라, **텍스처 이미지 내부의 좌표**입니다. 예를 들어 텍스처의 왼쪽 위 64x64 픽셀 영역만 잘라서 화면의 (400, 300) 위치에 그리고 싶다면 다음처럼 씁니다.

```c
Rectangle sourceRec = { 0.0f, 0.0f, 64.0f, 64.0f };
Vector2 drawPos = { 400.0f, 300.0f };
DrawTextureRec(playerTexture, sourceRec, drawPos, WHITE);
```

## 스프라이트 시트란 무엇인가

**스프라이트 시트(sprite sheet)** 는 여러 장의 그림(주로 애니메이션의 각 프레임)을 하나의 이미지 파일 안에 격자 형태로 배치해 둔 것입니다. 파일을 하나로 합쳐두면, 프레임마다 텍스처를 따로 로드/해제할 필요 없이 텍스처 하나만 로드해서 `DrawTextureRec`로 필요한 칸만 잘라 그리면 됩니다. 텍스처를 자주 전환하는 것보다 하나의 텍스처로 여러 그림을 그리는 쪽이 GPU 입장에서도 더 효율적입니다.

예를 들어 캐릭터가 걷는 모습을 4프레임으로 그린, 가로로 나란히 배치된 스프라이트 시트가 있다고 합시다. 각 프레임이 가로 32픽셀, 세로 32픽셀이라면, 전체 텍스처는 가로 128픽셀(32 × 4), 세로 32픽셀이 됩니다.

```
+--------+--------+--------+--------+
| frame0 | frame1 | frame2 | frame3 |
+--------+--------+--------+--------+
0       32       64       96      128
```

이때 `n`번째 프레임의 `source` 사각형은 다음과 같은 규칙으로 계산할 수 있습니다.

```c
int frameWidth = 32;
int frameHeight = 32;
int frameIndex = 2;  // 예: 세 번째 프레임(0부터 시작)

Rectangle sourceRec = {
    (float)(frameIndex * frameWidth),  // x
    0.0f,                                // y (한 줄짜리 시트이므로 항상 0)
    (float)frameWidth,
    (float)frameHeight
};

DrawTextureRec(spriteSheet, sourceRec, playerPos, WHITE);
```

`frameIndex`에 넣는 값만 0, 1, 2, 3으로 바꾸면 같은 텍스처에서 서로 다른 프레임을 그릴 수 있습니다. 다음 장(7장)에서는 이 `frameIndex`를 시간에 따라 자동으로 증가시켜서 실제로 걷는 것처럼 보이는 애니메이션을 완성합니다. 즉, 스프라이트 시트 자체는 "정지된 여러 그림을 한 파일에 모아둔 것"이고, 애니메이션은 여기에 "시간이 지나면 다음 프레임으로 넘어간다"는 규칙을 더한 것입니다.

여러 방향(위/아래/좌/우로 걷는 모습 등)을 함께 담은 시트라면 행(row)과 열(column)을 모두 사용해 2차원 격자로 구성하기도 합니다. 이 경우 `source.y`도 `row * frameHeight`처럼 계산해주면 됩니다.

```c
int row = 1;    // 예: 아래를 보고 걷는 애니메이션이 두 번째 줄에 있다면
int col = 2;

Rectangle sourceRec = {
    (float)(col * frameWidth),
    (float)(row * frameHeight),
    (float)frameWidth,
    (float)frameHeight
};
```

## 텍스처 필터링: SetTextureFilter

텍스처를 원본보다 크게 또는 작게 그리면, GPU는 픽셀 사이 값을 어떻게 채울지 결정해야 합니다. 이 방식을 필터링(filtering)이라고 하며, raylib에서는 다음 함수로 지정합니다.

```c
void SetTextureFilter(Texture2D texture, int filter);
```

대표적인 필터 값은 다음 두 가지입니다.

- `TEXTURE_FILTER_POINT`: 가장 가까운 픽셀 색을 그대로 사용(점 필터링). 확대해도 픽셀이 각지고 선명하게 유지됩니다.
- `TEXTURE_FILTER_BILINEAR`: 주변 픽셀들을 부드럽게 섞어서 채웁니다. 확대 시 경계가 흐릿하게 번집니다.

도트(픽셀 아트) 스타일의 게임에서 스프라이트를 확대해서 그릴 때, 기본 필터링을 그대로 두면 픽셀 경계가 뭉개져 흐릿해지는 문제가 생깁니다. 이럴 때는 다음처럼 점 필터링을 지정해서 픽셀이 또렷하게 유지되도록 합니다.

```c
Texture2D spriteSheet = LoadTexture("resources/player_sheet.png");
SetTextureFilter(spriteSheet, TEXTURE_FILTER_POINT);
```

`SetTextureFilter`는 `LoadTexture`로 텍스처를 로드한 **이후에** 호출해야 합니다. 아직 GPU에 올라가지 않은 텍스처에는 필터를 지정할 수 없기 때문입니다. 필터링에는 이 외에도 여러 단계의 옵션이 있지만, 지금 단계에서는 "픽셀 아트에는 점 필터링, 부드러운 그래픽에는 기본값(양선형)"이라는 정도만 기억해두면 충분합니다.

## 요약

- 텍스처(`Texture2D`)는 이미지 파일을 GPU 메모리에 올려둔 것으로, `LoadTexture("경로")`로 로드하고 사용이 끝나면 반드시 `UnloadTexture()`로 해제해야 한다.
- `DrawTexture`는 원본 크기 그대로, `DrawTextureEx`는 크기(`scale`)와 회전(`rotation`)을 지정해서, `DrawTextureRec`는 `Rectangle`로 지정한 텍스처 일부 영역만 잘라서 그린다.
- 스프라이트 시트는 여러 프레임을 하나의 텍스처 파일에 격자로 배치해둔 것으로, `Rectangle` 좌표를 프레임 번호에 따라 계산해 `DrawTextureRec`로 원하는 프레임만 선택해 그린다.
- `SetTextureFilter`로 필터링 방식을 지정할 수 있으며, 픽셀 아트 게임에서는 흐림을 방지하기 위해 `TEXTURE_FILTER_POINT`를 로드 직후에 적용하는 것이 일반적이다.

## 연습문제

1. `LoadTexture`와 `UnloadTexture`를 반드시 짝지어 호출해야 하는 이유를 설명하고, 짝을 맞추지 않았을 때 실제로 어떤 문제가 발생할 수 있는지 서술하세요.
2. `DrawTexture`, `DrawTextureEx`, `DrawTextureRec` 세 함수의 매개변수 차이를 표로 정리하고, 각각을 사용해야 하는 상황을 예로 들어보세요.
3. 가로 4프레임, 세로 2프레임(총 8프레임)으로 구성되고 각 프레임이 48x48 픽셀인 스프라이트 시트가 있을 때, 여섯 번째 프레임(0번부터 세면 인덱스 5, 두 번째 줄의 두 번째 칸)을 그리기 위한 `Rectangle sourceRec` 값을 직접 계산해보세요.
4. 임의의 이미지 파일을 하나 불러와 `DrawTexture`로 원본 크기로 그리는 프로그램과, `DrawTextureEx`로 3배 확대해서 그리는 프로그램을 각각 작성하고, `TEXTURE_FILTER_POINT`와 기본 필터링(따로 지정하지 않은 상태)일 때 확대된 이미지가 어떻게 다르게 보이는지 비교해보세요.
5. 스프라이트 시트에서 `frameIndex`를 프로그램 실행 중 키보드 오른쪽 화살표를 누를 때마다 1씩 증가시켜(마지막 프레임에서는 다시 0으로 돌아가도록) 화면에 다른 프레임이 표시되도록 만들어보세요. 이 방식이 7장에서 다룰 자동 애니메이션과 어떻게 다른지도 함께 생각해보세요.
