# 7장. 사용자 입력과 이벤트 처리

---

지금까지 만든 앱들은 화면에 무언가를 보여주는 데 집중했습니다. 하지만 진짜 애플리케이션은 사용자와 상호작용합니다. 버튼을 누르면 동작이 실행되고, 텍스트를 입력하면 그 값이 프로그램 안으로 들어오고, 화면을 쓸어넘기면 다음 항목이 나타납니다. 이번 장에서는 Flutter에서 사용자의 터치와 입력을 받아들이는 방법을 살펴봅니다.

버튼 위젯들의 종류와 쓰임새, `GestureDetector`로 버튼보다 더 세밀한 터치 동작을 감지하는 방법, `TextField`로 문자를 입력받고 그 값을 코드에서 읽어오는 방법을 차례로 다룹니다. 그리고 6장에서 배운 `setState`와 이 내용들을 결합해, 사용자가 입력한 내용에 따라 화면이 실시간으로 바뀌는 예제를 완성해 봅니다.

## 버튼 위젯: 강조 정도에 따른 선택

Flutter의 Material 위젯 라이브러리는 버튼을 하나로 통일하지 않고, 시각적 강조 수준이 다른 여러 종류로 나누어 제공합니다. 어떤 동작이 화면에서 얼마나 중요한지에 따라 알맞은 버튼을 골라 쓰는 것이 자연스러운 Material 디자인입니다.

### ElevatedButton

`ElevatedButton`은 배경색이 채워지고 약간의 그림자(elevation)가 있는 버튼입니다. 화면에서 가장 눈에 띄어야 하는 주요 동작, 예를 들어 "저장", "제출", "다음"처럼 사용자가 반드시 인지하고 눌러야 하는 동작에 사용합니다.

```dart
ElevatedButton(
  onPressed: () {
    print('저장되었습니다');
  },
  child: Text('저장'),
)
```

`onPressed`는 `VoidCallback` 타입, 즉 매개변수와 반환값이 없는 함수를 받습니다. 이 콜백이 눌렸을 때 실행할 코드입니다. 특이한 점은 `onPressed`에 `null`을 전달하면 버튼이 자동으로 비활성화된다는 것입니다. 색이 흐려지고 터치해도 반응하지 않습니다.

```dart
ElevatedButton(
  onPressed: isLoading ? null : () {
    submitForm();
  },
  child: Text('제출'),
)
```

이렇게 조건에 따라 `onPressed`를 `null`로 바꾸는 패턴은 "로딩 중에는 중복 제출을 막는다"처럼 실무에서 매우 자주 쓰입니다.

### TextButton

`TextButton`은 배경색도 그림자도 없이 텍스트만 표시되는 버튼입니다. `ElevatedButton`보다 시각적 무게가 가벼워서, 다이얼로그의 "취소" 버튼이나 "더 알아보기"처럼 부차적인 동작, 또는 여러 버튼이 나란히 있을 때 덜 중요한 쪽에 사용합니다.

```dart
TextButton(
  onPressed: () {
    Navigator.pop(context);
  },
  child: Text('취소'),
)
```

`Navigator.pop`이 무엇인지는 8장에서 자세히 다룹니다. 여기서는 "화면을 닫는 동작에는 가벼운 버튼이 어울린다" 정도로 기억해 두면 됩니다.

`ElevatedButton`과 `TextButton`을 나란히 두면 강조 정도의 차이가 뚜렷하게 드러납니다.

```dart
Row(
  mainAxisAlignment: MainAxisAlignment.end,
  children: [
    TextButton(
      onPressed: () {},
      child: Text('취소'),
    ),
    SizedBox(width: 8),
    ElevatedButton(
      onPressed: () {},
      child: Text('확인'),
    ),
  ],
)
```

### IconButton

`IconButton`은 텍스트 대신 아이콘 하나로 이루어진 버튼입니다. 뒤로 가기, 검색, 더보기(점 세 개), 좋아요처럼 의미가 아이콘만으로도 충분히 전달되는 동작, 특히 `AppBar`처럼 공간이 좁은 곳에서 자주 사용됩니다.

```dart
IconButton(
  icon: Icon(Icons.favorite_border),
  onPressed: () {
    setState(() {
      isFavorite = !isFavorite;
    });
  },
  tooltip: '좋아요',
)
```

`icon` 속성에 `child` 대신 표시할 위젯(보통 `Icon`)을 전달합니다. `tooltip`은 사용자가 버튼을 길게 눌렀을 때 나타나는 설명 텍스트로, 아이콘만으로 뜻이 애매할 수 있는 버튼에 접근성을 더해 줍니다.

세 버튼의 차이를 정리하면 다음과 같습니다.

| 위젯 | 시각적 강조 | 주로 쓰이는 곳 |
|---|---|---|
| `ElevatedButton` | 강함 (배경색 + 그림자) | 주요 동작 (제출, 저장) |
| `TextButton` | 약함 (텍스트만) | 부차적 동작 (취소, 더보기) |
| `IconButton` | 아이콘에 따라 다름 | 좁은 공간, 툴바, 반복되는 동작 |

이 외에도 테두리만 있는 `OutlinedButton`처럼 중간 강조의 버튼도 있지만, 기본 원리는 동일합니다. `onPressed`에 콜백을 전달하고, `child`(또는 `icon`)로 내용을 지정하는 방식입니다.

## GestureDetector: 버튼을 넘어선 제스처 인식

버튼 위젯들은 모두 "탭(tap)"이라는 한 가지 제스처만 처리합니다. 하지만 실제 앱을 만들다 보면 더 다양한 터치 동작이 필요할 때가 있습니다. 이미지를 더블탭하면 확대하거나, 카드를 길게 누르면 메뉴가 뜨거나, 특정 영역을 드래그해서 옮기는 식입니다. 이런 커스텀 터치 영역을 만들 때 쓰는 위젯이 `GestureDetector`입니다.

`GestureDetector`는 그 자체로는 화면에 아무것도 그리지 않는 위젯입니다. 대신 `child`로 감싼 위젯 위에서 발생하는 다양한 제스처를 감지해서 콜백을 호출해 줍니다.

```dart
GestureDetector(
  onTap: () {
    print('탭했습니다');
  },
  onDoubleTap: () {
    print('더블탭했습니다');
  },
  onLongPress: () {
    print('길게 눌렀습니다');
  },
  child: Container(
    width: 150,
    height: 150,
    color: Colors.blue,
    alignment: Alignment.center,
    child: Text(
      '터치해 보세요',
      style: TextStyle(color: Colors.white),
    ),
  ),
)
```

`GestureDetector`가 감지할 수 있는 대표적인 제스처는 다음과 같습니다.

- `onTap`: 한 번 탭했을 때
- `onDoubleTap`: 짧은 시간 안에 두 번 탭했을 때
- `onLongPress`: 길게 눌렀을 때
- `onPanUpdate`: 손가락을 화면에 대고 움직일 때(드래그) 반복적으로 호출되며, 이동한 거리 정보(`details.delta`)를 담은 `DragUpdateDetails`를 전달받음
- `onPanStart` / `onPanEnd`: 드래그가 시작되거나 끝났을 때

드래그로 위젯을 움직이는 예제를 보면 `onPanUpdate`의 쓰임을 더 잘 이해할 수 있습니다.

```dart
class DraggableBox extends StatefulWidget {
  const DraggableBox({super.key});

  @override
  State<DraggableBox> createState() => _DraggableBoxState();
}

class _DraggableBoxState extends State<DraggableBox> {
  double offsetX = 0;
  double offsetY = 0;

  @override
  Widget build(BuildContext context) {
    return Stack(
      children: [
        Positioned(
          left: offsetX,
          top: offsetY,
          child: GestureDetector(
            onPanUpdate: (details) {
              setState(() {
                offsetX += details.delta.dx;
                offsetY += details.delta.dy;
              });
            },
            child: Container(
              width: 80,
              height: 80,
              color: Colors.orange,
            ),
          ),
        ),
      ],
    );
  }
}
```

손가락이 움직일 때마다 `onPanUpdate`가 호출되면서 이동한 거리(`delta`)만큼 상자의 위치를 갱신하고, `setState`로 화면을 다시 그립니다. 이렇게 `GestureDetector`와 `setState`를 결합하면 버튼으로는 표현할 수 없는 자유로운 터치 상호작용을 만들 수 있습니다.

버튼이 필요한 상황이라면 굳이 `GestureDetector`를 쓸 필요는 없습니다. `ElevatedButton`이나 `TextButton`은 내부적으로 이미 탭 감지, 시각적 눌림 효과(ripple), 접근성 처리를 다 해 주기 때문입니다. `GestureDetector`는 그런 기본 제공 위젯으로 표현되지 않는, 임의의 영역에 임의의 제스처를 붙이고 싶을 때 사용하는 도구라고 기억해 두세요.

## TextField: 텍스트 입력받기

사용자로부터 문자를 입력받아야 할 때는 `TextField` 위젯을 사용합니다. 가장 단순한 형태는 다음과 같습니다.

```dart
TextField(
  decoration: InputDecoration(
    labelText: '이름',
    border: OutlineInputBorder(),
  ),
)
```

`decoration` 속성에 `InputDecoration`을 지정하면 라벨, 테두리, 힌트 텍스트 등을 꾸밀 수 있습니다. 하지만 이것만으로는 사용자가 입력한 값을 코드에서 알 수가 없습니다. 입력값을 읽으려면 두 가지 방법이 있습니다: `TextEditingController`를 사용하거나 `onChanged` 콜백을 사용하는 것입니다.

### TextEditingController로 입력값 제어하기

`TextEditingController`는 `TextField`의 내용을 프로그램에서 읽고, 쓰고, 지울 수 있게 해 주는 객체입니다. `StatefulWidget`의 상태로 만들어 `TextField`의 `controller` 속성에 연결합니다.

```dart
class NameForm extends StatefulWidget {
  const NameForm({super.key});

  @override
  State<NameForm> createState() => _NameFormState();
}

class _NameFormState extends State<NameForm> {
  final TextEditingController _nameController = TextEditingController();

  @override
  void dispose() {
    _nameController.dispose();
    super.dispose();
  }

  void _showName() {
    print('입력된 이름: ${_nameController.text}');
  }

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        TextField(
          controller: _nameController,
          decoration: InputDecoration(
            labelText: '이름',
            border: OutlineInputBorder(),
          ),
        ),
        ElevatedButton(
          onPressed: _showName,
          child: Text('확인'),
        ),
      ],
    );
  }
}
```

여기서 몇 가지 중요한 점이 있습니다.

- 컨트롤러는 `State` 클래스의 필드로 선언하고, 보통 `final`로 한 번만 생성합니다.
- 현재 입력된 텍스트는 `_nameController.text`로 언제든지 읽을 수 있습니다. 반대로 `_nameController.text = '초기값'`처럼 값을 대입하면 `TextField`의 내용을 코드에서 바꿀 수도 있습니다.
- 컨트롤러는 내부적으로 리스너와 리소스를 가지고 있어서, 위젯이 화면에서 사라질 때 반드시 `dispose()` 메서드를 호출해 정리해야 합니다. 이를 위해 `State` 클래스의 `dispose()`를 오버라이드합니다. 6장에서 살펴본 위젯 생명주기 중 마지막 단계가 바로 이 시점입니다.

### onChanged 콜백으로 변화 감지하기

컨트롤러가 "언제든 필요할 때 값을 꺼내 보는" 방식이라면, `onChanged`는 "값이 바뀔 때마다 즉시 알림을 받는" 방식입니다. `TextField`의 `onChanged`는 글자가 입력되거나 삭제될 때마다 현재까지의 전체 문자열을 매개변수로 전달하며 호출됩니다.

```dart
TextField(
  onChanged: (value) {
    print('현재 입력값: $value');
  },
)
```

`onChanged`는 컨트롤러 없이도 사용할 수 있지만, 실무에서는 둘을 함께 쓰는 경우도 많습니다. 컨트롤러로 초기값 설정이나 지우기 버튼 같은 제어를 하면서, 동시에 `onChanged`로 매 순간의 변화에 즉각 반응하는 식입니다.

## setState와 결합하기: 실시간으로 반응하는 화면

이제 6장에서 배운 `setState`와 `TextField`를 결합해 보겠습니다. 목표는 사용자가 입력하는 글자 수를 실시간으로 화면에 표시하는 것입니다.

```dart
import 'package:flutter/material.dart';

class CharacterCounter extends StatefulWidget {
  const CharacterCounter({super.key});

  @override
  State<CharacterCounter> createState() => _CharacterCounterState();
}

class _CharacterCounterState extends State<CharacterCounter> {
  final TextEditingController _controller = TextEditingController();
  int _characterCount = 0;

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  void _onTextChanged(String value) {
    setState(() {
      _characterCount = value.length;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('글자 수 세기')),
      body: Padding(
        padding: const EdgeInsets.all(16.0),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            TextField(
              controller: _controller,
              onChanged: _onTextChanged,
              decoration: InputDecoration(
                labelText: '메시지를 입력하세요',
                border: OutlineInputBorder(),
              ),
            ),
            SizedBox(height: 12),
            Text(
              '입력한 글자 수: $_characterCount',
              style: TextStyle(fontSize: 18),
            ),
          ],
        ),
      ),
    );
  }
}
```

이 예제가 동작하는 흐름을 짚어 보면 다음과 같습니다.

1. 사용자가 `TextField`에 글자를 입력하거나 지웁니다.
2. `TextField`는 내용이 바뀔 때마다 `onChanged`로 등록된 `_onTextChanged` 함수를 현재 문자열과 함께 호출합니다.
3. `_onTextChanged`는 `setState`를 호출해 `_characterCount` 값을 새 문자열의 길이(`value.length`)로 갱신합니다.
4. `setState`가 호출되면 Flutter는 이 위젯의 `build` 메서드를 다시 실행합니다.
5. 다시 그려진 화면에서 `Text('입력한 글자 수: $_characterCount')`는 갱신된 값을 표시합니다.

여기서 `TextEditingController`는 굳이 값을 직접 읽는 데 쓰이지 않고 `TextField`에 연결만 되어 있습니다. 이런 식으로 컨트롤러는 "나중에 필요할 때 값을 읽거나 초기화하는 용도"로, `onChanged`는 "매 변화마다 반응하는 용도"로 역할을 나누어 함께 쓰는 것이 자연스럽습니다. 예를 들어 "지우기" 버튼을 추가하고 싶다면 컨트롤러의 `clear()` 메서드를 활용할 수 있습니다.

```dart
IconButton(
  icon: Icon(Icons.clear),
  onPressed: () {
    _controller.clear();
    setState(() {
      _characterCount = 0;
    });
  },
)
```

`_controller.clear()`는 `TextField`에 보이는 텍스트를 지우고, 뒤이은 `setState`는 글자 수 표시도 함께 0으로 되돌립니다. 이처럼 입력 위젯, 컨트롤러, `setState`를 조합하는 패턴은 폼(form)을 다루는 12장에서 더 정교한 형태로 발전합니다.

## 요약

- `ElevatedButton`, `TextButton`, `IconButton`은 모두 `onPressed` 콜백을 받는 버튼이지만 시각적 강조 정도가 다릅니다. 주요 동작에는 `ElevatedButton`, 부차적 동작에는 `TextButton`, 아이콘 하나로 표현되는 동작에는 `IconButton`이 어울립니다.
- `onPressed`에 `null`을 전달하면 버튼이 비활성화되며, 이를 이용해 조건부로 버튼을 켜고 끌 수 있습니다.
- `GestureDetector`는 화면을 직접 그리지 않고, `child` 위젯 위에서 발생하는 탭, 더블탭, 길게 누르기, 드래그(`onPanUpdate`) 등 버튼으로 표현할 수 없는 세밀한 제스처를 감지합니다.
- `TextField`로 텍스트를 입력받을 수 있으며, `TextEditingController`를 연결하면 `.text`로 현재 값을 읽거나 `.clear()`로 지우는 등 프로그램에서 입력 내용을 제어할 수 있습니다. 컨트롤러는 사용이 끝나면 `dispose()`로 반드시 정리해야 합니다.
- `onChanged` 콜백은 입력값이 바뀔 때마다 호출되어, 매 순간의 변화에 반응하는 로직을 작성할 수 있게 해 줍니다.
- `onChanged`(또는 `GestureDetector`의 콜백)에서 `setState`를 호출하면, 사용자의 입력에 따라 화면의 다른 부분을 실시간으로 갱신할 수 있습니다.
