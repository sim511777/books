## 들어가며

지금까지 만들어본 화면들은 앱 안에 미리 준비해둔 데이터, 혹은 사용자가 그 자리에서 입력한 데이터만 다뤘다. 하지만 실제로 쓰이는 앱 대부분은 인터넷 너머 서버에서 데이터를 가져와 화면에 보여준다. 날씨 앱은 기상 서버에서 오늘의 기온을 받아오고, 쇼핑 앱은 상품 목록을 서버 데이터베이스에서 조회하며, SNS 앱은 다른 사용자가 올린 게시물을 실시간으로 내려받는다. 이런 기능을 만들려면 앱이 네트워크를 통해 서버와 데이터를 주고받는 방법을 알아야 한다.

14장에서 배운 `Future`와 `FutureBuilder`는 사실 이 장을 위한 준비 과정이었다. 네트워크 요청은 즉시 끝나지 않고 시간이 걸리는 비동기 작업의 대표적인 예이기 때문이다. 이 장에서는 `http` 패키지로 실제 REST API를 호출하고, 응답으로 받은 JSON 데이터를 Dart 객체로 변환한 뒤, `FutureBuilder`를 이용해 로딩·에러·성공 상태를 모두 처리하는 화면을 끝까지 완성해본다.

## http 패키지 추가하기

Flutter SDK는 네트워크 통신을 위한 기본 기능을 `dart:io`의 `HttpClient` 형태로 제공하지만, 실무에서는 훨씬 다루기 쉬운 `http`라는 패키지를 표준처럼 사용한다. pub.dev에 공개된 이 패키지는 Google Dart 팀이 관리하며, GET·POST 같은 HTTP 요청을 몇 줄의 코드로 처리할 수 있게 해준다.

패키지를 사용하려면 먼저 프로젝트의 `pubspec.yaml` 파일에 의존성을 추가해야 한다.

```yaml
dependencies:
  flutter:
    sdk: flutter
  http: ^1.2.0
```

`dependencies` 항목 아래에 `http`를 추가한 뒤 저장하면, VS Code나 Android Studio 같은 IDE는 자동으로 `flutter pub get`을 실행해 패키지를 내려받는다. 터미널에서 직접 실행하고 싶다면 프로젝트 루트에서 다음 명령을 입력한다.

```dart
// 터미널 명령이므로 dart 코드는 아니지만 편의상 표기
flutter pub get
```

설치가 끝나면 코드에서 다음과 같이 임포트해서 사용한다.

```dart
import 'package:http/http.dart' as http;
```

`as http`로 이름을 붙이는 이유는 패키지 안의 `get`, `post` 같은 함수 이름이 짧고 일반적이어서, 다른 곳에서 쓰이는 동일한 이름과 충돌하지 않도록 구분하기 위해서다. 이후 코드에서는 `http.get(...)`처럼 접두사를 붙여 호출한다.

## GET 요청으로 데이터 가져오기

가장 기본적인 통신 방식은 서버에 "이 데이터를 보내달라"고 요청하는 GET 요청이다. `http` 패키지의 `get` 함수는 `Uri` 객체를 인자로 받아 요청을 보내고, 결과를 `Future<Response>`로 돌려준다.

```dart
import 'package:http/http.dart' as http;

Future<void> fetchData() async {
  final response = await http.get(
    Uri.parse('https://jsonplaceholder.typicode.com/posts'),
  );

  print('상태 코드: ${response.statusCode}');
  print('응답 본문: ${response.body}');
}
```

여기서 몇 가지 눈여겨볼 부분이 있다.

- `Uri.parse(url)`은 문자열 형태의 URL을 `Uri` 객체로 변환한다. `http.get`은 문자열이 아니라 `Uri`를 요구하므로 이 변환 과정이 꼭 필요하다.
- `await`를 사용했으므로 이 함수는 반드시 `async`로 선언되어야 한다. `async`와 `await`의 기본 동작 원리는 14장에서 다뤘다.
- `response.statusCode`는 HTTP 상태 코드다. 200이면 요청이 성공했다는 뜻이고, 404는 리소스를 찾을 수 없다는 뜻이며, 500번대는 서버 쪽 오류를 의미한다.
- `response.body`는 서버가 돌려준 응답 본문을 문자열로 담고 있다. REST API는 대부분 이 본문을 JSON 형식의 문자열로 채워서 보낸다.

즉 `http.get`을 호출한 시점에는 아직 아무 데이터도 손에 들어오지 않고, 서버가 응답을 보내올 때까지 `await`가 기다린 뒤에야 `response`에 실제 값이 채워진다. 이 흐름은 정확히 14장에서 살펴본 `Future`의 동작 방식 그대로다.

## JSON 파싱: 문자열에서 Dart 객체로

`response.body`는 어디까지나 문자열이다. 예를 들어 위 요청의 응답 본문은 다음과 비슷한 모양의 텍스트다.

```dart
// 실제로는 문자열이지만 이해를 돕기 위해 형태만 표기
// [
//   {"id": 1, "title": "첫 번째 글", "userId": 7},
//   {"id": 2, "title": "두 번째 글", "userId": 3}
// ]
```

이 문자열 안에서 `title`이나 `userId` 값을 꺼내 쓰려면, 문자열을 Dart가 다룰 수 있는 `Map`이나 `List` 형태로 변환해야 한다. 이때 사용하는 것이 Dart 코어 라이브러리에 포함된 `dart:convert`의 `jsonDecode` 함수다.

```dart
import 'dart:convert';

void parseExample(String jsonString) {
  final decoded = jsonDecode(jsonString);
  print(decoded.runtimeType); // List<dynamic> 또는 Map<String, dynamic>
}
```

`jsonDecode`는 JSON 문자열의 최상위 구조가 배열이면 `List<dynamic>`을, 객체면 `Map<String, dynamic>`을 반환한다. 위 예시처럼 배열 안에 여러 객체가 들어있는 경우라면 다음과 같이 접근할 수 있다.

```dart
final decoded = jsonDecode(jsonString) as List<dynamic>;
final firstItem = decoded[0] as Map<String, dynamic>;
print(firstItem['title']); // 첫 번째 글
```

반대로 Dart의 `Map`이나 `List`를 JSON 문자열로 바꿔야 할 때는 `jsonEncode`를 사용한다. 서버로 데이터를 전송할 때(POST 요청의 본문을 구성할 때) 주로 쓰인다.

```dart
final map = {'title': '새 글', 'userId': 7};
final jsonString = jsonEncode(map);
print(jsonString); // {"title":"새 글","userId":7}
```

## 커스텀 모델 클래스로 변환하기

`Map<String, dynamic>`을 직접 다뤄도 동작은 하지만, 코드 곳곳에서 `data['title']`, `data['userId']` 처럼 문자열 키로 값을 꺼내다 보면 오타를 컴파일 시점에 잡아낼 수 없고, 어떤 필드가 존재하는지 한눈에 파악하기도 어렵다. 그래서 실무에서는 API 응답 구조에 맞춘 모델 클래스를 정의하고, JSON을 이 클래스의 인스턴스로 변환하는 패턴을 사용한다.

```dart
class Post {
  final int id;
  final String title;
  final int userId;

  Post({required this.id, required this.title, required this.userId});

  factory Post.fromJson(Map<String, dynamic> json) {
    return Post(
      id: json['id'] as int,
      title: json['title'] as String,
      userId: json['userId'] as int,
    );
  }
}
```

`factory` 생성자로 선언한 `fromJson`은 `Map<String, dynamic>`을 입력받아 `Post` 인스턴스를 만들어 돌려준다. `factory` 키워드는 일반 생성자와 달리, 항상 새 인스턴스를 만드는 대신 필요에 따라 다른 로직을 거쳐 인스턴스를 생성할 수 있게 해준다는 정도로 이해하면 충분하다.

이 패턴을 활용하면 GET 요청으로 받은 JSON 배열 전체를 `List<Post>`로 변환하는 함수를 다음처럼 작성할 수 있다.

```dart
Future<List<Post>> fetchPosts() async {
  final response = await http.get(
    Uri.parse('https://jsonplaceholder.typicode.com/posts'),
  );

  final decoded = jsonDecode(response.body) as List<dynamic>;
  return decoded
      .map((item) => Post.fromJson(item as Map<String, dynamic>))
      .toList();
}
```

`decoded`의 각 원소는 `Map<String, dynamic>` 형태이므로, `map` 함수로 하나하나를 `Post.fromJson`에 통과시켜 `Post` 객체로 바꾸고, `toList()`로 최종 리스트를 만든다. 이렇게 만든 `fetchPosts` 함수는 반환 타입이 `Future<List<Post>>`로 명확하게 드러나기 때문에, 이 함수를 호출하는 쪽에서는 JSON 파싱 과정을 전혀 신경 쓰지 않고 바로 `Post` 객체 리스트를 다룰 수 있다.

## FutureBuilder와 결합해 화면 완성하기

이제 `fetchPosts` 함수를 14장에서 배운 `FutureBuilder`와 연결해, 로딩 중·에러·성공 세 가지 상태를 모두 처리하는 화면을 만들어보자.

```dart
import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;
import 'dart:convert';

class Post {
  final int id;
  final String title;
  final int userId;

  Post({required this.id, required this.title, required this.userId});

  factory Post.fromJson(Map<String, dynamic> json) {
    return Post(
      id: json['id'] as int,
      title: json['title'] as String,
      userId: json['userId'] as int,
    );
  }
}

Future<List<Post>> fetchPosts() async {
  final response = await http.get(
    Uri.parse('https://jsonplaceholder.typicode.com/posts'),
  );

  if (response.statusCode != 200) {
    throw Exception('게시물을 불러오지 못했습니다 (상태 코드: ${response.statusCode})');
  }

  final decoded = jsonDecode(response.body) as List<dynamic>;
  return decoded
      .map((item) => Post.fromJson(item as Map<String, dynamic>))
      .toList();
}

class PostListScreen extends StatefulWidget {
  const PostListScreen({super.key});

  @override
  State<PostListScreen> createState() => _PostListScreenState();
}

class _PostListScreenState extends State<PostListScreen> {
  late Future<List<Post>> _postsFuture;

  @override
  void initState() {
    super.initState();
    _postsFuture = fetchPosts();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('게시물 목록')),
      body: FutureBuilder<List<Post>>(
        future: _postsFuture,
        builder: (context, snapshot) {
          // 1. 로딩 중
          if (snapshot.connectionState == ConnectionState.waiting) {
            return const Center(child: CircularProgressIndicator());
          }

          // 2. 에러 발생
          if (snapshot.hasError) {
            return Center(
              child: Text('오류가 발생했습니다: ${snapshot.error}'),
            );
          }

          // 3. 성공적으로 데이터를 받아온 경우
          final posts = snapshot.data ?? [];
          if (posts.isEmpty) {
            return const Center(child: Text('게시물이 없습니다.'));
          }

          return ListView.builder(
            itemCount: posts.length,
            itemBuilder: (context, index) {
              final post = posts[index];
              return ListTile(
                leading: CircleAvatar(child: Text('${post.userId}')),
                title: Text(post.title),
                subtitle: Text('게시물 #${post.id}'),
              );
            },
          );
        },
      ),
    );
  }
}
```

이 코드에서 핵심이 되는 결정 하나는 `_postsFuture`를 `initState`에서 딱 한 번 생성해 필드에 저장해두었다는 점이다. 만약 `build` 메서드 안에서 매번 `fetchPosts()`를 새로 호출한다면, 화면이 다시 그려질 때마다(예를 들어 다른 상태 변화로 `setState`가 호출될 때마다) 네트워크 요청이 새로 발생해서 로딩 스피너가 계속 반복해서 나타나는 문제가 생긴다. `Future`를 필드에 캐싱해두고 `FutureBuilder`의 `future` 매개변수에 그 필드를 넘기는 것이 정석적인 패턴이다. 10장에서 살펴본 `ListView.builder`가 여기서도 그대로 활용되어, 받아온 게시물 목록을 스크롤 가능한 리스트로 보여준다.

`FutureBuilder`의 `builder` 콜백은 `snapshot`의 상태에 따라 세 갈래로 분기한다.

- `snapshot.connectionState == ConnectionState.waiting`: 아직 응답을 기다리는 중이므로 로딩 인디케이터를 보여준다.
- `snapshot.hasError`: `fetchPosts` 안에서 예외가 발생했다면 이 값이 `true`가 되고, `snapshot.error`로 예외 내용을 확인할 수 있다.
- 그 외의 경우: 요청이 성공했다는 뜻이므로 `snapshot.data`에 담긴 `List<Post>`를 화면에 그린다.

## 네트워크 오류 처리하기

서버가 정상적으로 응답을 준다는 보장은 없다. 인터넷 연결이 끊겨 있을 수도 있고, 서버가 응답하는 데 너무 오래 걸려 타임아웃이 발생할 수도 있으며, 서버는 응답했지만 404나 500 같은 오류 상태 코드를 돌려줄 수도 있다. 이런 상황들을 구분해서 처리하려면 `try`/`catch`를 활용한다.

```dart
Future<List<Post>> fetchPostsSafely() async {
  try {
    final response = await http
        .get(Uri.parse('https://jsonplaceholder.typicode.com/posts'))
        .timeout(const Duration(seconds: 5));

    if (response.statusCode != 200) {
      throw Exception('서버 오류: 상태 코드 ${response.statusCode}');
    }

    final decoded = jsonDecode(response.body) as List<dynamic>;
    return decoded
        .map((item) => Post.fromJson(item as Map<String, dynamic>))
        .toList();
  } on TimeoutException {
    throw Exception('요청 시간이 초과되었습니다. 네트워크 상태를 확인해주세요.');
  } catch (e) {
    throw Exception('데이터를 불러오는 중 문제가 발생했습니다: $e');
  }
}
```

몇 가지 짚어둘 점이 있다.

- `.timeout(const Duration(seconds: 5))`는 5초 안에 응답이 오지 않으면 `TimeoutException`을 발생시킨다. `dart:async`에 포함된 이 기능은 서버가 응답 없이 무한정 붙잡고 있는 상황을 방지해준다.
- 인터넷 연결 자체가 끊겨 있으면 `http.get`은 `SocketException`(또는 이를 감싼 `ClientException`) 계열의 예외를 던진다. 위 코드처럼 `catch (e)`로 폭넓게 잡아서 사용자에게 이해하기 쉬운 메시지로 바꿔주는 것이 일반적이다.
- 여기서 다시 던진 예외는 `FutureBuilder`의 `snapshot.hasError`와 `snapshot.error`로 고스란히 전달된다. 즉 `fetchPostsSafely`가 어떤 이유로 실패하든, 화면 쪽 코드는 앞서 작성한 것과 동일한 에러 처리 분기 하나로 대응할 수 있다.

실제 앱에서는 이렇게 다듬어진 함수를 `PostListScreen`의 `fetchPosts` 대신 사용해서, 사용자가 비행기 모드를 켜두었거나 서버 점검 중이더라도 앱이 멈추거나 알 수 없는 에러 화면을 띄우는 대신 "오류가 발생했습니다"라는 명확한 안내를 보여주도록 만든다.

## 요약

- `http` 패키지는 pub.dev에서 널리 쓰이는 표준 HTTP 클라이언트로, `pubspec.yaml`의 `dependencies`에 추가한 뒤 `http.get(Uri.parse(url))` 형태로 GET 요청을 보낼 수 있다.
- 요청 결과인 `Response` 객체의 `statusCode`로 성공 여부를, `body`로 JSON 문자열 형태의 응답 본문을 확인한다.
- `dart:convert`의 `jsonDecode`는 JSON 문자열을 `Map<String, dynamic>` 또는 `List<dynamic>`으로, `jsonEncode`는 그 반대 방향으로 변환한다.
- `factory ClassName.fromJson(Map<String, dynamic> json)` 패턴으로 커스텀 모델 클래스를 정의하면, JSON 데이터를 타입이 명확한 Dart 객체로 다룰 수 있다.
- `FutureBuilder`의 `connectionState`와 `hasError`를 검사해 로딩 중·에러·성공 세 가지 상태를 모두 처리하는 것이 API 연동 화면의 기본 골격이다.
- `timeout`과 `try`/`catch`를 함께 사용하면 연결 실패나 응답 지연 같은 네트워크 오류를 사용자에게 안전하게 안내할 수 있다.

## 연습문제

1. `pubspec.yaml`에 `http` 패키지를 추가하는 과정을 설명하고, `import 'package:http/http.dart' as http;`에서 `as http`가 왜 필요한지 서술해보라.
2. `jsonDecode`와 `jsonEncode`가 각각 어떤 방향의 변환을 담당하는지 설명하고, 두 함수를 사용하는 간단한 예제 코드를 작성해보라.
3. 다음 JSON 응답을 파싱할 수 있는 `User` 모델 클래스와 `fromJson` 팩토리 생성자를 작성해보라: `{"id": 1, "name": "홍길동", "email": "hong@example.com"}`.
4. 이 장의 `PostListScreen` 예제에서 `_postsFuture`를 `initState`가 아니라 `build` 메서드 안에서 매번 새로 생성하면 어떤 문제가 생기는지 설명해보라.
5. `fetchPostsSafely` 함수를 참고해, 응답 상태 코드가 404일 때와 네트워크 연결이 아예 끊겼을 때 사용자에게 서로 다른 안내 메시지를 보여주도록 코드를 확장해보라.
