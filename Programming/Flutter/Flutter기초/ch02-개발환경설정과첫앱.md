## 들어가며

1장에서 Flutter가 무엇이고 왜 다른 크로스플랫폼 기술과 다른지 살펴보았다. 이제 직접 손을 움직일 차례다. 이 장에서는 Flutter SDK를 설치하고, `flutter create` 명령으로 프로젝트를 하나 만들어본 뒤, 그 안에 자동으로 생성된 코드를 뜯어보면서 Flutter 앱의 가장 기본적인 골격을 이해한다. 마지막으로는 직접 화면 문구를 수정해보면서 1장에서 예고했던 핫 리로드를 실제로 체험해본다.

## Flutter SDK 설치하기

Flutter 앱을 만들려면 먼저 Flutter SDK가 컴퓨터에 설치되어 있어야 한다. Flutter SDK에는 Dart SDK, Flutter 프레임워크 소스, 그리고 `flutter`라는 커맨드라인 도구가 함께 포함되어 있다. 설치 방법은 운영체제마다 조금씩 다르지만 큰 흐름은 같다.

1. 공식 사이트(flutter.dev)에서 사용 중인 운영체제(Windows, macOS, Linux)에 맞는 SDK를 내려받는다.
2. 압축을 푼 뒤, `flutter` 명령을 어디서든 실행할 수 있도록 SDK 안의 `bin` 디렉터리를 시스템의 `PATH` 환경 변수에 등록한다.
3. 모바일 앱을 빌드하려면 Android 앱 개발을 위한 Android Studio(또는 Android SDK 커맨드라인 도구)를, iOS 앱을 빌드하려면(macOS 한정) Xcode를 추가로 설치해야 한다.

설치가 끝났는지, 그리고 개발에 필요한 나머지 도구들이 제대로 갖춰졌는지 확인할 때 쓰는 명령이 `flutter doctor`다.

```
flutter doctor
```

`flutter doctor`는 Flutter SDK 자체의 설치 상태뿐 아니라, Android 툴체인, (macOS라면) Xcode와 iOS 툴체인, 연결된 에디터(Android Studio, VS Code 확장 등), 그리고 연결된 기기나 에뮬레이터까지 하나씩 점검하고 그 결과를 체크리스트 형태로 보여준다. 항목 옆에 초록색 체크 표시가 아니라 느낌표나 x 표시가 있다면, 그 항목에 필요한 조치를 안내하는 메시지가 함께 출력되므로 그 안내를 따라가면 된다. Flutter 개발을 진행하다가 뭔가 환경이 꼬인 것 같다는 느낌이 들 때마다 가장 먼저 실행해볼 명령이 바로 `flutter doctor`라고 기억해두자.

## 프로젝트 생성하기: flutter create

환경 준비가 끝났다면 이제 프로젝트를 만들 차례다. 터미널에서 프로젝트를 만들고 싶은 위치로 이동한 뒤, 다음 명령을 실행한다.

```
flutter create my_app
```

이 명령은 `my_app`이라는 이름의 디렉터리를 새로 만들고, 그 안에 바로 실행 가능한 최소한의 Flutter 프로젝트 한 벌을 생성해준다. 생성이 끝나면 디렉터리 구조는 대략 다음과 같은 모습이다.

```
my_app/
  android/          # Android 플랫폼용 네이티브 프로젝트
  ios/              # iOS 플랫폼용 네이티브 프로젝트
  web/              # 웹 플랫폼용 리소스
  windows/          # Windows 데스크톱용 네이티브 프로젝트
  macos/            # macOS 데스크톱용 네이티브 프로젝트
  linux/            # Linux 데스크톱용 네이티브 프로젝트
  lib/
    main.dart       # 앱의 진입점(entry point)
  test/
    widget_test.dart
  pubspec.yaml      # 프로젝트 설정, 의존성, 에셋 관리 파일
```

이 구조에서 지금 당장 눈여겨봐야 할 파일은 두 개뿐이다.

**`lib/main.dart`**는 이 앱이 실행될 때 가장 먼저 호출되는 코드, 즉 진입점이다. Flutter 개발의 대부분은 결국 `lib` 디렉터리 아래에 Dart 파일을 작성하는 일이며, `main.dart`는 그 시작점 역할을 한다.

**`pubspec.yaml`**은 이 프로젝트의 설정 파일이다. 프로젝트 이름과 설명, 이 프로젝트가 사용할 외부 패키지(의존성) 목록, 그리고 이미지나 폰트 같은 에셋(asset)을 앱에 포함시키려면 어떤 파일을 등록해야 하는지가 이 파일에 명시된다. 예를 들어 나중에 외부 패키지를 하나 추가하고 싶다면, 이 파일의 `dependencies` 항목에 패키지 이름과 버전을 적어 넣게 된다. 패키지를 실제로 활용하는 방법은 15장(네트워크 통신)과 16장(로컬 데이터 저장)에서 구체적으로 다룬다.

`android`, `ios`, `web`, `windows`, `macos`, `linux` 디렉터리에는 각 플랫폼에서 이 Flutter 앱을 실행하기 위한 네이티브 프로젝트 파일들이 들어 있다. 1장에서 설명했듯 화면을 그리는 로직 자체는 Flutter가 전담하지만, 앱을 실제 기기에 설치하고 실행 파일로 패키징하는 과정은 각 플랫폼의 고유한 방식을 따라야 하기 때문에 이런 디렉터리가 필요하다. 이 디렉터리들의 내용을 직접 건드릴 일은 입문 단계에서는 거의 없으므로, 지금은 "이런 것들이 있구나" 정도로만 알아두면 충분하다.

## main.dart 뜯어보기

`flutter create`가 만들어준 `lib/main.dart`에는 카운터를 증가시키는 예제 앱이 들어 있지만, 여기서는 그 핵심 골격만 최대한 단순화해서 살펴본다.

```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'My App',
      home: Scaffold(
        appBar: AppBar(
          title: const Text('첫 번째 Flutter 앱'),
        ),
        body: const Center(
          child: Text('환영합니다!'),
        ),
      ),
    );
  }
}
```

이 코드를 위에서부터 하나씩 뜯어보자.

**`import 'package:flutter/material.dart';`** 는 머티리얼 디자인 스타일의 위젯들(`MaterialApp`, `Scaffold`, `AppBar`, `Text` 등)을 사용하기 위한 임포트다. 1장에서 언급했듯 Flutter는 머티리얼 디자인과 iOS 스타일(Cupertino) 위젯 세트를 모두 제공하는데, 대부분의 입문 예제와 이 책의 예제들은 `material.dart`를 기준으로 진행한다.

**`void main() { runApp(const MyApp()); }`** 은 Dart 프로그램의 진입점이다. Dart 언어 자체에서 `main()` 함수가 프로그램의 시작점이라는 사실은 이미 알고 있을 텐데, Flutter 앱에서는 이 `main()` 함수 안에서 `runApp()`이라는 Flutter 프레임워크 함수를 호출하는 것이 정해진 패턴이다. `runApp()`은 인자로 받은 위젯을 화면 전체를 채우는 최상위 위젯으로 등록하고, 그 위젯을 화면에 그리는 과정을 시작시킨다. 즉 "이 위젯을 루트(root)로 삼아 앱을 그려라"라고 Flutter에게 지시하는 한 줄이다.

**`class MyApp extends StatelessWidget`** 은 이 앱의 최상위 위젯을 정의하는 클래스다. `StatelessWidget`은 Flutter가 제공하는 위젯의 한 종류로, 시간이 지나도 스스로 내부 상태가 바뀌지 않는 위젯을 만들 때 상속받는 클래스다(상태가 바뀌는 위젯은 `StatefulWidget`이며, 이는 6장에서 자세히 다룬다). `MyApp({super.key})`처럼 생성자에서 `super.key`를 받는 것은 Flutter 위젯의 관례적인 패턴으로, 위젯 트리에서 각 위젯을 식별하는 데 쓰이는 `key`를 부모 클래스에 그대로 전달하는 역할을 한다.

**`Widget build(BuildContext context)`** 은 `StatelessWidget`을 상속받는 모든 클래스가 반드시 재정의(override)해야 하는 메서드다. Flutter는 화면을 그려야 할 때마다 이 `build()` 메서드를 호출하고, 이 메서드가 반환하는 위젯을 실제로 화면에 그린다. 즉 "이 위젯이 화면에 어떻게 보여야 하는가"를 설명하는 코드가 바로 이 메서드 안에 들어간다.

**`MaterialApp`** 은 머티리얼 디자인 기반 앱을 만들 때 가장 바깥쪽에 놓는 위젯이다. 앱 전체의 제목, 테마, 라우팅(화면 전환 경로) 설정 등을 이 위젯에서 관리하며, `home` 속성에 앱이 처음 보여줄 화면을 지정한다. `MaterialApp`은 9장(테마와 스타일링)과 8장(네비게이션과 라우팅)에서 다시 자세히 등장한다.

**`Scaffold`** 는 화면 하나의 기본 뼈대를 잡아주는 위젯이다. 상단 앱 바(`appBar`), 화면의 주요 내용(`body`), 필요하다면 하단 내비게이션 바나 플로팅 액션 버튼까지, 일반적인 앱 화면이 갖추는 구조를 미리 마련해준다.

**`Center`와 `Text`** 는 각각 자식 위젯을 화면(또는 부모 영역)의 정중앙에 배치하는 위젯, 그리고 문자열을 화면에 표시하는 위젯이다. 이런 기본 위젯들의 종류와 쓰임새는 4장에서 폭넓게 다룬다.

지금 이 코드의 세부 위젯 하나하나를 완벽히 이해할 필요는 없다. 지금 단계에서 꼭 기억해야 할 흐름은 다음 한 가지다. **`main()`에서 `runApp()`을 호출하고, `runApp()`에 넘겨준 위젯의 `build()` 메서드가 반환하는 위젯 트리가 화면에 그려진다.** 이 흐름은 앞으로 이 책 전체에서 마주치는 모든 Flutter 앱의 공통된 뼈대이며, 위젯과 위젯 트리라는 개념 자체는 3장에서 본격적으로 파헤친다.

## flutter run으로 앱 실행하기

프로젝트를 만들었으니 실제로 실행해볼 차례다. 먼저 에뮬레이터나 시뮬레이터를 하나 켜두거나, USB로 실제 기기를 연결해둔다(데스크톱이나 웹 대상으로 실행한다면 별도 기기 없이도 가능하다). 그런 다음 프로젝트 디렉터리에서 다음 명령을 실행한다.

```
flutter run
```

연결된 기기(또는 에뮬레이터)가 여러 개라면 `flutter run`은 어떤 기기에서 실행할지 선택하라는 목록을 보여준다. 기기를 선택하면 Flutter는 프로젝트를 빌드하고, 빌드된 앱을 선택한 기기에 설치한 뒤 실행한다. 처음 실행할 때는 빌드 과정 때문에 다소 시간이 걸릴 수 있지만, 일단 앱이 실행되고 나면 터미널은 대기 상태로 전환되면서 몇 가지 단축키를 안내해준다. 이 중 가장 자주 쓰게 될 것이 바로 `r` 키, 핫 리로드다.

## 핫 리로드 직접 체험해보기

`flutter run`으로 앱이 실행 중인 상태에서, 에디터로 돌아가 `lib/main.dart`를 열어보자. 화면에 표시되는 문구를 바꿔본다.

```dart
body: const Center(
  child: Text('환영합니다!'), // 이 문구를 바꿔보자
),
```

예를 들어 위 문구를 다음과 같이 바꿔보자.

```dart
body: const Center(
  child: Text('Flutter, 반가워!'),
),
```

파일을 저장한 뒤, 앱을 실행 중인 터미널로 돌아가 `r` 키를 눌러본다(에디터에 따라 저장과 동시에 자동으로 핫 리로드가 트리거되기도 한다). 앱을 껐다가 다시 켜는 과정 없이, 화면에 보이는 문구가 곧바로 "Flutter, 반가워!"로 바뀌는 것을 확인할 수 있을 것이다. 만약 이전에 버튼을 눌러 어떤 상태를 바꿔둔 화면이었다면, 그 상태 역시 초기화되지 않고 그대로 유지된 채 텍스트만 바뀐다. 이것이 1장에서 이야기했던 핫 리로드의 실체다. 코드를 고치고 저장하는 것만으로 몇 초 안에 결과를 눈으로 확인할 수 있으니, 레이아웃이나 색상, 문구를 다듬는 작업을 반복할 때 이 루프가 얼마나 큰 차이를 만드는지 직접 느껴보길 권한다.

앱을 완전히 종료하고 싶다면 터미널에서 `q` 키를 누르면 된다. 참고로 코드를 수정한 뒤 상태까지 완전히 초기화하고 다시 시작하고 싶을 때는 `r`이 아니라 대문자 `R`(핫 리스타트, hot restart)을 사용한다는 점도 함께 기억해두자.

## Hello, Flutter! 최소 예제

지금까지 살펴본 내용을 바탕으로, `flutter create`가 만들어준 카운터 예제를 걷어내고 정말 필요한 것만 남긴 최소한의 앱을 하나 완성해보자. 화면 중앙에 "Hello, Flutter!"라는 문구 하나만 표시하는 앱이다. `lib/main.dart`의 내용을 다음 코드로 통째로 바꿔보자.

```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Hello Flutter',
      home: Scaffold(
        body: Center(
          child: Text(
            'Hello, Flutter!',
            style: TextStyle(fontSize: 28),
          ),
        ),
      ),
    );
  }
}
```

이 예제는 `AppBar` 없이 `Scaffold`의 `body`만 사용했고, `Text` 위젯에 `TextStyle`로 글자 크기를 지정해서 "Hello, Flutter!"라는 문구가 화면 정중앙에 도드라지게 보이도록 했다. `flutter run`으로 실행하면 흰 배경 화면 한가운데에 문구가 표시되는 것을 확인할 수 있다. 겨우 스무 줄 남짓한 이 코드가 iOS와 Android는 물론, 별도의 수정 없이 웹과 Windows, macOS, Linux에서도 그대로 실행된다는 사실을 다시 한번 떠올려보자. 이것이 1장에서 이야기한 "하나의 코드베이스"가 실제로 눈앞에 구현된 모습이다.

## 요약

- Flutter SDK를 설치한 뒤 `flutter doctor`로 개발 환경(SDK, Android/iOS 툴체인, 에디터, 연결된 기기)이 제대로 갖춰졌는지 점검한다.
- `flutter create my_app`으로 프로젝트를 생성하면 `lib/main.dart`(진입점)와 `pubspec.yaml`(의존성·에셋 설정 파일)을 포함한 실행 가능한 프로젝트가 만들어진다.
- Flutter 앱은 `void main() { runApp(const MyApp()); }` 형태로 시작하며, `MyApp`은 보통 `StatelessWidget`을 상속받아 `build()` 메서드에서 `MaterialApp`을 반환한다.
- `MaterialApp`은 앱 전체를 감싸는 위젯, `Scaffold`는 화면 하나의 기본 뼈대(앱 바, 본문 등)를 잡아주는 위젯이다.
- `flutter run`으로 앱을 실행한 뒤 코드를 수정하고 `r` 키를 누르면 앱의 상태를 유지한 채 변경 사항이 즉시 반영되는 핫 리로드를 체험할 수 있다.
- `Center`와 `Text` 같은 기본 위젯만으로도 화면 중앙에 문구를 표시하는 완전한 Flutter 앱을 만들 수 있다.

## 연습문제

1. `flutter doctor` 명령이 점검해주는 항목들을 나열하고, 이 명령을 실행해야 하는 시점은 언제인지 설명해보라.
2. `flutter create`로 생성된 프로젝트에서 `lib/main.dart`와 `pubspec.yaml`은 각각 어떤 역할을 하는지 설명해보라.
3. `void main() { runApp(const MyApp()); }`에서 `runApp()`이 하는 일을 자신의 언어로 설명해보라.
4. `MaterialApp`과 `Scaffold`의 역할 차이를 설명해보라.
5. 자신의 컴퓨터에서 "Hello, Flutter!" 예제를 직접 작성하고 실행한 뒤, 문구와 글자 크기를 수정하고 핫 리로드로 즉시 반영되는 과정을 확인해보라.
