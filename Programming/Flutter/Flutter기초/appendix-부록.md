## A. Flutter 설치와 개발 환경 요약

2장에서 자세히 다룬 개발 환경 설정 내용을 빠르게 참조할 수 있도록 요약한다.

**설치 확인**

Flutter SDK를 내려받아 경로(PATH)에 등록한 뒤에는, 다음 명령으로 개발 환경이 제대로 갖춰졌는지 점검하는 것이 가장 먼저 할 일이다.

```bash
flutter doctor
```

`flutter doctor`는 Flutter SDK 자체의 상태뿐 아니라, Android 툴체인, (macOS라면) Xcode, 연결된 IDE, 사용 가능한 기기 목록까지 함께 점검해준다. 항목 옆에 체크 표시가 아니라 느낌표나 X 표시가 뜬다면, 그 항목의 안내 메시지를 따라 부족한 구성 요소(예: Android SDK 라이선스 동의, Xcode Command Line Tools 등)를 채워 넣으면 된다.

**IDE 선택지**

Flutter 개발에 널리 쓰이는 IDE는 다음 두 가지이며, 어느 쪽을 쓰더라도 이 책의 실습을 따라가는 데는 지장이 없다.

- **Android Studio**: Google의 공식 Android 개발 도구를 기반으로 하며, Flutter 및 Dart 플러그인을 설치하면 위젯 미리보기, 위젯 트리 검사, 에뮬레이터 관리 등을 통합된 화면에서 다룰 수 있다.
- **VS Code + Flutter 확장**: 가볍고 빠른 편집기를 선호한다면 VS Code에 "Flutter" 확장(및 이에 딸려오는 "Dart" 확장)을 설치해서 사용할 수 있다. 명령 팔레트를 통한 프로젝트 생성, 디버깅, 핫 리로드 단축키를 모두 지원한다.

**자주 쓰는 CLI 명령 모음**

| 명령 | 용도 |
|---|---|
| `flutter create <프로젝트명>` | 새 Flutter 프로젝트 생성 |
| `flutter run` | 연결된 기기/에뮬레이터에서 앱 실행 |
| `flutter pub get` | `pubspec.yaml`에 명시한 의존성 설치 |
| `flutter pub add <패키지명>` | 패키지를 의존성에 추가하고 설치 |
| `flutter test` | 테스트 실행 |
| `flutter build <플랫폼>` | 배포용 빌드 생성(17장 참고) |
| `flutter clean` | 빌드 캐시 삭제(빌드 문제 발생 시 초기화용) |
| `flutter doctor` | 개발 환경 진단 |

## B. 주요 위젯/클래스 요약표

이 책 전체에서 등장한 핵심 위젯과 클래스를 장별로 정리했다. 이름과 역할을 한눈에 복습하는 용도로 활용하자.

| 장 | 이름 | 역할 |
|---|---|---|
| 3장 | `StatelessWidget` | 상태를 갖지 않는, 한 번 그려지면 변하지 않는 위젯의 기반 클래스 |
| 3장 | `StatefulWidget` | 내부 상태를 가지며 상태 변화에 따라 다시 그려질 수 있는 위젯의 기반 클래스 |
| 3장 | `BuildContext` | 위젯 트리 안에서 현재 위젯의 위치 정보를 담은 객체 |
| 4장 | `Text` | 문자열을 화면에 표시하는 위젯 |
| 4장 | `Icon` | 아이콘을 표시하는 위젯 |
| 4장 | `Image` | 이미지를 표시하는 위젯 |
| 5장 | `Container` | 여백, 배경, 크기, 정렬 등을 지정할 수 있는 범용 박스 위젯 |
| 5장 | `Row` / `Column` | 자식 위젯을 각각 가로/세로로 배치하는 레이아웃 위젯 |
| 5장 | `Expanded` | `Row`/`Column`/`Flex` 안에서 남는 공간을 비율대로 차지하게 하는 위젯 |
| 5장 | `Stack` | 자식 위젯들을 겹쳐서 배치하는 레이아웃 위젯 |
| 6장 | `setState` | `StatefulWidget`의 상태를 변경하고 화면 갱신을 요청하는 메서드 |
| 7장 | `GestureDetector` | 탭, 드래그 등 다양한 제스처를 감지하는 위젯 |
| 7장 | `TextEditingController` | 텍스트 입력 필드의 값을 읽고 제어하는 컨트롤러 |
| 8장 | `Navigator` | 화면 간 이동(push/pop)을 관리하는 클래스 |
| 8장 | `MaterialPageRoute` | 머티리얼 디자인 스타일의 화면 전환 애니메이션을 제공하는 라우트 |
| 9장 | `ThemeData` | 앱 전체의 색상, 글꼴, 컴포넌트 스타일을 정의하는 클래스 |
| 9장 | `Theme.of(context)` | 현재 컨텍스트에 적용된 테마 값을 조회하는 메서드 |
| 10장 | `ListView` | 스크롤 가능한 목록을 표시하는 위젯 |
| 10장 | `ListView.builder` | 항목을 필요한 만큼만 지연 생성해 대량의 목록을 효율적으로 렌더링하는 생성자 |
| 10장 | `Dismissible` | 스와이프 제스처로 자식 위젯을 화면에서 제거할 수 있게 하는 위젯 |
| 11장 | `AnimationController` | 애니메이션의 진행 값과 재생을 제어하는 컨트롤러 |
| 11장 | `AnimatedContainer` | 속성 변화가 있을 때 자동으로 보간 애니메이션을 적용하는 컨테이너 |
| 12장 | `Form` | 여러 입력 필드를 하나의 단위로 묶어 유효성 검사를 관리하는 위젯 |
| 12장 | `TextFormField` | 유효성 검사 기능이 내장된 텍스트 입력 위젯 |
| 13장 | `ChangeNotifier` | 상태 변경을 구독자에게 알리는 옵저버 패턴 기반 클래스 |
| 13장 | `Provider` | 위젯 트리 하위에 상태 객체를 제공하고 접근하게 해주는 상태 관리 패키지의 핵심 위젯 |
| 14장 | `Future` | 나중에 완료될 비동기 작업의 결과를 표현하는 타입 |
| 14장 | `FutureBuilder` | `Future`의 진행 상태에 따라 다른 화면을 그려주는 위젯 |
| 15장 | `http` 패키지 | HTTP 요청을 보내고 응답을 받는 데 사용하는 네트워크 통신 패키지 |
| 16장 | `shared_preferences` | 간단한 키-값 데이터를 기기에 영속적으로 저장하는 패키지 |
| 16장 | `sqflite` | 로컬 SQLite 데이터베이스를 다루는 패키지 |
| 17장 | `flutter build` | 각 플랫폼용 배포 가능한 결과물을 생성하는 CLI 명령 |
| 18장 | `Checkbox` | 참/거짓 값을 체크박스 형태로 표시하고 토글하는 위젯 |

## C. 참고할 만한 공식 자료

이 책을 마친 뒤에도 계속 참고할 만한 공식 자료를 이름 위주로 소개한다. 실제 접속 주소는 검색을 통해 쉽게 찾을 수 있으므로 여기서는 URL을 하이퍼링크로 걸지 않고 명칭만 안내한다.

- **Flutter 공식 웹사이트**: Flutter의 최신 소식, 설치 가이드, 공식 블로그를 확인할 수 있는 시작점이다.
- **Flutter 공식 문서의 위젯 카탈로그(Widget Catalog)**: 이 책에서 다룬 위젯 외에도 Flutter가 기본 제공하는 수백 개의 위젯을 범주별로 정리해둔 참고 자료다. 새로운 UI 요소가 필요할 때 가장 먼저 찾아볼 곳이다.
- **pub.dev**: Dart와 Flutter의 공식 패키지 저장소다. `shared_preferences`, `http`, `provider`처럼 이 책에서 사용한 패키지를 포함해, 커뮤니티가 공개한 수많은 패키지를 검색하고 버전별 문서를 확인할 수 있다.
- **Dart 공식 언어 문서**: Flutter의 기반이 되는 Dart 언어 자체의 문법과 라이브러리를 다루는 공식 문서로, 이 책의 자매편인 "Dart 기초부터 응용까지"와 함께 참고하면 좋다.

## D. 다음 학습 단계 제안

이 책은 Flutter의 기초를 다지는 데 목적을 두었다. 여기서 더 나아가고 싶다면 다음과 같은 방향을 고려해볼 만하다.

- **상태 관리 라이브러리 심화**: 13장에서 `Provider`의 기본 개념을 다뤘지만, 실무에서는 `Riverpod`이나 `Bloc` 같은 라이브러리도 널리 쓰인다. 각 라이브러리가 상태를 다루는 철학과 보일러플레이트의 양이 다르므로, 여러 개를 비교해보며 프로젝트 성격에 맞는 도구를 고르는 안목을 기르는 것이 좋다.
- **더 큰 규모의 실전 앱 만들기**: 18장에서 만든 할 일 관리 앱은 의도적으로 작게 설계되었다. 화면이 여러 개로 늘어나고, 기능 간 의존 관계가 복잡해지는 더 큰 프로젝트를 직접 만들어보면서 폴더 구조 설계, 코드 재사용, 테스트 작성 같은 실무 감각을 키울 수 있다.
- **백엔드 연동**: 15장에서 다룬 HTTP 통신의 다음 단계로, Firebase(Firestore, Authentication, Cloud Functions 등)나 직접 구축한 REST/GraphQL 서버와 앱을 연동해보는 경험은 실제 서비스형 앱을 만드는 데 필수적이다.
- **테스트와 CI/CD**: 위젯 테스트, 통합 테스트를 작성하고, 이를 자동화된 빌드 파이프라인과 연결하는 것도 실무 수준의 앱 개발로 나아가는 중요한 단계다.

Flutter는 배워야 할 것이 끝없이 이어지는 생태계이지만, 이 책에서 다진 위젯과 상태 관리에 대한 기본기가 있다면 어떤 새로운 라이브러리나 패턴을 마주하더라도 그 위에 자연스럽게 쌓아 올릴 수 있을 것이다.
