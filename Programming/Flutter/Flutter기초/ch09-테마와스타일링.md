## 이 장에서 만들 것

지금까지 만든 화면들을 떠올려 보면, 버튼 하나하나에 색상을 지정하고, 텍스트마다 `TextStyle`을 따로 붙이고, `Container`의 배경색을 그때그때 입력해 왔습니다. 화면이 몇 개 안 될 때는 이런 방식도 크게 불편하지 않습니다. 하지만 앱의 화면이 20개, 30개로 늘어나고, 어느 날 디자이너가 "브랜드 컬러를 파란색에서 초록색으로 바꿔주세요"라고 요청한다면 어떻게 될까요? 코드 곳곳에 흩어진 `Colors.blue`를 전부 찾아서 바꿔야 하고, 하나라도 놓치면 화면마다 색이 미묘하게 어긋나는 앱이 됩니다.

Flutter는 이런 문제를 **테마(Theme)**라는 개념으로 해결합니다. 앱 전체의 색상, 글꼴, 버튼 모양 같은 디자인 값을 한 곳에 모아두고, 위젯 트리 어디서든 그 값을 꺼내 쓰는 방식입니다. 이번 장에서는 `MaterialApp`의 `theme` 속성으로 테마를 정의하는 방법, `Theme.of(context)`로 테마 값을 읽어오는 방법, 그리고 시스템 설정에 따라 자동으로 전환되는 다크 모드를 구현하는 방법을 다룹니다.

## 9.1 테마 없이 스타일링할 때의 문제

먼저 테마 없이 스타일을 지정한 코드를 보겠습니다.

```dart
import 'package:flutter/material.dart';

class ProductCard extends StatelessWidget {
  const ProductCard({super.key, required this.title});

  final String title;

  @override
  Widget build(BuildContext context) {
    return Card(
      color: Colors.blue,
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Text(
          title,
          style: const TextStyle(
            color: Colors.white,
            fontSize: 18,
            fontWeight: FontWeight.bold,
          ),
        ),
      ),
    );
  }
}
```

이 위젯을 사용하는 화면이 열 곳이라면, `Colors.blue`라는 하드코딩된 값이 열 군데에 반복됩니다. 이 값을 바꾸려면 열 곳을 모두 찾아 고쳐야 하고, 실수로 한 곳을 놓치면 앱의 일관성이 깨집니다. 이제 이 문제를 테마로 풀어보겠습니다.

## 9.2 ThemeData와 MaterialApp의 theme 속성

`MaterialApp`은 `theme`이라는 속성을 받는데, 여기에 `ThemeData` 객체를 전달하면 그 값이 앱 전체 위젯 트리에 전파됩니다. 2장에서 처음 `MaterialApp`을 사용했을 때는 이 속성을 비워두었지만, 이제 본격적으로 채워보겠습니다.

```dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: '테마 예제',
      theme: ThemeData(
        primarySwatch: Colors.blue,
        textTheme: const TextTheme(
          headlineMedium: TextStyle(
            fontSize: 24,
            fontWeight: FontWeight.bold,
          ),
          bodyMedium: TextStyle(fontSize: 16),
        ),
      ),
      home: const HomeScreen(),
    );
  }
}
```

`primarySwatch`에 지정한 `Colors.blue`는 단순한 색 하나가 아니라, 밝기가 다른 10단계의 파란색 묶음(`MaterialColor`)입니다. Flutter는 이 묶음을 이용해 앱바 배경, 버튼 색, 강조 색 등을 자동으로 조합해 줍니다. `textTheme`은 앱에서 사용할 글꼴 스타일들의 이름표를 미리 정의해 두는 곳으로, `headlineMedium`은 제목급 텍스트, `bodyMedium`은 본문 텍스트처럼 용도별로 이름이 붙어 있습니다.

> **참고**: 최신 Flutter는 `primarySwatch` 대신 `ColorScheme.fromSeed(seedColor: Colors.blue)`를 `ThemeData(colorScheme: ...)`에 전달하는 방식을 권장합니다. 이 방식은 Material 3 디자인 가이드에 맞춰 하나의 시드 색상으로부터 조화로운 색상 팔레트 전체를 자동 생성해 줍니다. `primarySwatch`는 여전히 동작하며 개념을 이해하기에 직관적이므로 이 책에서는 기본 예제로 사용하지만, 실무 프로젝트를 시작한다면 `ColorScheme.fromSeed`를 먼저 검토해 보길 권합니다.

```dart
ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: Colors.blue),
  useMaterial3: true,
)
```

### 버튼 스타일도 테마로

버튼의 모양도 앱마다, 혹은 버튼 종류마다 반복해서 지정하는 대신 테마에 등록할 수 있습니다. `ElevatedButtonThemeData`를 사용하면 앱에 있는 모든 `ElevatedButton`이 같은 모양을 갖게 됩니다.

```dart
ThemeData(
  primarySwatch: Colors.blue,
  elevatedButtonTheme: ElevatedButtonThemeData(
    style: ElevatedButton.styleFrom(
      backgroundColor: Colors.blue,
      foregroundColor: Colors.white,
      padding: const EdgeInsets.symmetric(horizontal: 24, vertical: 12),
      shape: RoundedRectangleBorder(
        borderRadius: BorderRadius.circular(8),
      ),
    ),
  ),
)
```

이렇게 하면 코드 어디에서 `ElevatedButton(onPressed: ..., child: ...)`를 만들더라도 별도로 스타일을 지정하지 않는 이상 동일한 모양이 적용됩니다.

## 9.3 Theme.of(context)로 테마 값 읽기

테마를 정의했다면, 이제 위젯 안에서 그 값을 꺼내 써야 합니다. 이때 사용하는 함수가 `Theme.of(context)`입니다. 3장에서 배운 것처럼 `BuildContext`는 위젯이 트리의 어느 위치에 있는지를 나타내는 정보인데, `Theme.of(context)`는 이 컨텍스트를 기준으로 가장 가까운 `Theme` 위젯(결국 `MaterialApp`이 설정한 테마)을 찾아 그 안의 `ThemeData`를 반환합니다.

앞서 하드코딩했던 `ProductCard`를 테마 기반으로 다시 작성해 보겠습니다.

```dart
class ProductCard extends StatelessWidget {
  const ProductCard({super.key, required this.title});

  final String title;

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);

    return Card(
      color: theme.colorScheme.primary,
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Text(
          title,
          style: theme.textTheme.headlineMedium?.copyWith(
            color: theme.colorScheme.onPrimary,
          ),
        ),
      ),
    );
  }
}
```

`theme.colorScheme.primary`는 테마의 주 색상을, `theme.colorScheme.onPrimary`는 그 색 위에 올려도 잘 읽히는 대비 색(보통 흰색)을 의미합니다. `theme.textTheme.headlineMedium`은 `MaterialApp`에서 정의해 둔 스타일을 그대로 가져오고, `copyWith`로 색상만 살짝 덮어씁니다. 이제 브랜드 컬러를 바꾸고 싶다면 `MaterialApp`의 `ThemeData` 한 곳만 고치면 됩니다. `ProductCard`를 비롯해 테마 값을 참조하는 모든 위젯이 자동으로 새 색상을 따라갑니다.

자주 쓰는 테마 접근 경로를 정리하면 다음과 같습니다.

| 접근 경로 | 의미 |
|---|---|
| `Theme.of(context).colorScheme.primary` | 앱의 주 색상 |
| `Theme.of(context).colorScheme.secondary` | 보조 강조 색상 |
| `Theme.of(context).colorScheme.surface` | 카드, 시트 등 표면 색상 |
| `Theme.of(context).textTheme.headlineMedium` | 제목급 텍스트 스타일 |
| `Theme.of(context).textTheme.bodyMedium` | 본문 텍스트 스타일 |
| `Theme.of(context).scaffoldBackgroundColor` | `Scaffold`의 배경색 |

## 9.4 다크 모드 지원하기

요즘 대부분의 앱은 시스템 설정이 다크 모드일 때 자동으로 어두운 화면을 보여줍니다. Flutter에서는 `MaterialApp`에 밝은 테마와 어두운 테마를 각각 등록하고, 어떤 기준으로 전환할지를 `themeMode`로 지정하는 방식으로 이를 구현합니다.

```dart
import 'package:flutter/material.dart';

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: '다크 모드 예제',
      theme: ThemeData.light().copyWith(
        primaryColor: Colors.blue,
        colorScheme: ColorScheme.fromSeed(
          seedColor: Colors.blue,
          brightness: Brightness.light,
        ),
      ),
      darkTheme: ThemeData.dark().copyWith(
        primaryColor: Colors.blueGrey,
        colorScheme: ColorScheme.fromSeed(
          seedColor: Colors.blue,
          brightness: Brightness.dark,
        ),
      ),
      themeMode: ThemeMode.system,
      home: const HomeScreen(),
    );
  }
}
```

`ThemeData.light()`와 `ThemeData.dark()`는 각각 밝은 배경/어두운 텍스트, 어두운 배경/밝은 텍스트를 기본으로 갖춘 완성된 테마를 만들어 줍니다. 여기에 `copyWith`를 사용하면 기본값을 유지하면서 원하는 속성만 덮어쓸 수 있습니다. `themeMode: ThemeMode.system`으로 설정하면 Flutter가 운영체제(iOS, Android)의 다크 모드 설정을 감지해서 `theme`과 `darkTheme` 중 알맞은 쪽을 자동으로 선택합니다.

`ThemeMode`에는 세 가지 값이 있습니다.

- `ThemeMode.system`: 시스템 설정을 따라 자동 전환 (기본값)
- `ThemeMode.light`: 항상 밝은 테마 사용
- `ThemeMode.dark`: 항상 어두운 테마 사용

### 사용자가 직접 다크 모드를 켜고 끄는 예제

앱 안에 "다크 모드 전환" 스위치를 두고 싶다면, 6장에서 배운 상태 관리를 그대로 활용할 수 있습니다. `themeMode` 값을 `StatefulWidget`의 상태로 관리하고, 값이 바뀔 때마다 `setState`로 화면을 다시 그리면 됩니다.

```dart
class MyApp extends StatefulWidget {
  const MyApp({super.key});

  @override
  State<MyApp> createState() => _MyAppState();
}

class _MyAppState extends State<MyApp> {
  ThemeMode _themeMode = ThemeMode.system;

  void _toggleDarkMode(bool useDark) {
    setState(() {
      _themeMode = useDark ? ThemeMode.dark : ThemeMode.light;
    });
  }

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      theme: ThemeData.light(),
      darkTheme: ThemeData.dark(),
      themeMode: _themeMode,
      home: SettingsScreen(onDarkModeChanged: _toggleDarkMode),
    );
  }
}
```

여기서 `_themeMode`가 바뀔 때마다 `MaterialApp`이 다시 빌드되면서 앱 전체 색상이 즉시 전환됩니다. 사용자 입력을 다루는 `Switch` 위젯 자체는 7장에서 다룬 내용을 참고하세요.

## 9.5 커스텀 색상 팔레트를 앱 전역에서 재사용하기

프로젝트가 커지면 `Colors.blue` 같은 기본 색상만으로는 부족하고, 브랜드에 맞는 고유 색상을 여러 화면에서 일관되게 써야 할 때가 많습니다. 이때 가장 단순하면서도 실전에서 널리 쓰이는 방법은, 색상들을 하나의 클래스에 정적 상수로 모아두는 것입니다.

```dart
import 'package:flutter/material.dart';

class AppColors {
  AppColors._(); // 인스턴스 생성 방지

  static const Color primary = Color(0xFF3D5AFE);
  static const Color secondary = Color(0xFFFF6E40);
  static const Color background = Color(0xFFF5F5F5);
  static const Color error = Color(0xFFD32F2F);
}
```

`Color(0xFF3D5AFE)`처럼 16진수 값을 직접 지정하면 디자이너가 전달한 정확한 색상 코드를 그대로 반영할 수 있습니다. 앞의 두 자리 `FF`는 불투명도(alpha)를 의미합니다. 이렇게 정의한 색상은 `ThemeData`를 구성할 때 사용합니다.

```dart
ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: AppColors.primary),
  scaffoldBackgroundColor: AppColors.background,
)
```

더 정교하게 관리하고 싶다면, Flutter가 제공하는 `ThemeExtension`을 사용해 커스텀 색상 자체를 테마 시스템에 등록할 수도 있습니다. 이렇게 하면 다크 모드에서 색상이 다르게 적용되도록 확장하기도 쉽고, `Theme.of(context)`와 같은 방식으로 커스텀 값을 꺼내 쓸 수 있습니다.

```dart
class AppColorsExtension extends ThemeExtension<AppColorsExtension> {
  const AppColorsExtension({required this.success, required this.warning});

  final Color success;
  final Color warning;

  @override
  AppColorsExtension copyWith({Color? success, Color? warning}) {
    return AppColorsExtension(
      success: success ?? this.success,
      warning: warning ?? this.warning,
    );
  }

  @override
  AppColorsExtension lerp(AppColorsExtension? other, double t) {
    if (other is! AppColorsExtension) return this;
    return AppColorsExtension(
      success: Color.lerp(success, other.success, t)!,
      warning: Color.lerp(warning, other.warning, t)!,
    );
  }
}
```

이 확장은 `ThemeData(extensions: [const AppColorsExtension(success: Colors.green, warning: Colors.orange)])`처럼 등록하고, `Theme.of(context).extension<AppColorsExtension>()!.success`로 꺼내 씁니다. 처음 앱을 만들 때는 `AppColors` 같은 단순한 상수 클래스로 시작해도 충분하며, 다크 모드별로 색상을 세밀하게 다르게 관리해야 하는 시점이 오면 `ThemeExtension`으로 확장하는 것을 권합니다.

## 9.6 Material Design과 Cupertino

지금까지 사용해 온 `ElevatedButton`, `Card`, `AppBar` 같은 위젯들의 둥근 모서리, 그림자, 색상 사용 방식은 모두 구글이 만든 디자인 시스템인 **Material Design**을 따르고 있습니다. `MaterialApp`이라는 이름도 여기서 나온 것이며, `ThemeData`가 정의하는 값들 역시 Material Design의 규칙을 기반으로 합니다.

그런데 iOS 사용자에게는 안드로이드 느낌의 Material 위젯보다 iOS 고유의 디자인이 더 자연스럽게 느껴질 수 있습니다. Flutter는 이를 위해 **Cupertino** 위젯 세트도 함께 제공합니다. `CupertinoApp`, `CupertinoButton`, `CupertinoNavigationBar`처럼 이름에 `Cupertino`가 붙은 위젯들을 사용하면 iOS 네이티브 앱과 흡사한 모양을 낼 수 있습니다. 이 책에서는 Material Design 위젯을 중심으로 다루지만, 플랫폼별로 다른 디자인을 적용하고 싶다면 `Platform.isIOS` 같은 조건으로 Material과 Cupertino 위젯을 선택적으로 사용하는 방법이 있다는 정도만 기억해 두면 충분합니다.

## 요약

- `MaterialApp`의 `theme` 속성에 `ThemeData`를 전달하면 색상, 글꼴, 버튼 모양 같은 디자인 값을 앱 전체에서 한 곳에서 관리할 수 있습니다.
- `ThemeData(primarySwatch: Colors.blue, textTheme: ...)`처럼 기본값을 지정하며, 최신 방식으로는 `ColorScheme.fromSeed`를 사용해 Material 3 색상 체계를 자동 생성할 수 있습니다.
- 위젯 트리 어디서든 `Theme.of(context)`를 호출하면 가장 가까운 테마의 `ThemeData`를 가져와 `colorScheme`, `textTheme` 등의 값을 일관되게 사용할 수 있습니다.
- `theme`과 `darkTheme`을 함께 등록하고 `themeMode: ThemeMode.system`으로 설정하면 시스템의 다크 모드 설정에 따라 앱이 자동으로 전환됩니다. `themeMode`를 상태로 관리하면 사용자가 직접 켜고 끌 수도 있습니다.
- 색상을 `AppColors`처럼 상수 클래스에 모아두거나, 더 나아가 `ThemeExtension`을 사용하면 브랜드 색상을 앱 전역에서 재사용 가능한 형태로 관리할 수 있습니다.
- Flutter의 기본 위젯 스타일은 구글의 Material Design을 기반으로 하며, iOS 스타일이 필요하면 `Cupertino` 계열 위젯을 사용할 수 있습니다.

## 연습문제

1. `ThemeData`의 `primarySwatch`와 `ColorScheme.fromSeed`의 차이를 설명하고, 각각을 사용한 `MaterialApp` 코드를 작성해 보세요.
2. `Theme.of(context)`를 사용해 화면의 배경색을 `theme.colorScheme.surface`로, 제목 텍스트를 `theme.textTheme.headlineMedium`으로 지정하는 `StatelessWidget`을 만들어 보세요.
3. `theme`과 `darkTheme`을 모두 정의하고 `themeMode: ThemeMode.system`으로 설정한 앱을 만든 뒤, 기기의 다크 모드 설정을 바꿔가며 화면이 자동으로 전환되는지 확인해 보세요.
4. `Switch` 위젯과 `setState`를 이용해 사용자가 직접 라이트/다크 모드를 전환할 수 있는 설정 화면을 만들어 보세요.
5. `AppColors`라는 이름의 상수 클래스를 만들어 최소 3가지 색상(`primary`, `secondary`, `error`)을 정의하고, 이를 활용해 커스텀 버튼 위젯을 스타일링해 보세요.
