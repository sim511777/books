## 이 장에서 만들 것

5장에서 `Column`과 `Row`로 여러 위젯을 나열하는 방법을 배웠습니다. 항목이 서너 개뿐이라면 `Column` 안에 자식 위젯을 하나씩 나열해도 충분합니다. 하지만 연락처 목록, 상품 카탈로그, 채팅 메시지처럼 수십 개에서 수백, 수천 개에 이르는 데이터를 보여줘야 한다면 이야기가 달라집니다. 이번 장에서는 많은 양의 데이터를 효율적으로 스크롤 가능한 목록으로 표시하는 `ListView`와 `GridView`, 그리고 항목을 스와이프로 삭제하는 `Dismissible`을 다룹니다. 마지막에는 6장의 상태 관리를 결합해 버튼을 누르면 항목이 추가되는 실전 예제를 만들어 보겠습니다.

## 10.1 문제 제기: 항목이 많아지면 무엇이 문제인가

먼저 `Column`으로 긴 목록을 만들어 보겠습니다.

```dart
class NaiveList extends StatelessWidget {
  const NaiveList({super.key, required this.items});

  final List<String> items;

  @override
  Widget build(BuildContext context) {
    return SingleChildScrollView(
      child: Column(
        children: items.map((item) => ListTile(title: Text(item))).toList(),
      ),
    );
  }
}
```

`items`에 담긴 문자열이 10개 정도라면 이 코드는 아무 문제 없이 동작합니다. `SingleChildScrollView`가 스크롤을 지원하므로 화면 밖으로 넘치는 항목도 볼 수 있습니다. 하지만 `items`가 5,000개라면 어떻게 될까요?

`Column`은 `children`으로 전달된 위젯을 **한 번에 전부** 만듭니다. `items.map(...)`이 실행되는 순간 5,000개의 `ListTile` 위젯 객체가 즉시 생성되고, `build` 메서드는 이 5,000개를 모두 배치하기 위한 계산을 수행합니다. 사용자는 스크롤을 조금만 내려서 화면에 보이는 10여 개의 항목만 보고 있을 뿐인데, 화면에 보이지도 않는 나머지 4,990개까지 미리 만들어 메모리에 올려두는 셈입니다. 항목 수가 많아질수록 앱 시작이 느려지고 메모리 사용량이 늘어나며, 스크롤이 버벅이는 원인이 됩니다.

Flutter는 이 문제를 **지연 생성(lazy build)**으로 해결합니다. 화면에 실제로 보이는 항목과 그 주변 일부만 위젯으로 만들고, 스크롤해서 새로운 항목이 보일 때 그 항목을 그때그때 만드는 방식입니다. 화면 밖으로 사라진 항목은 위젯을 폐기해 메모리를 회수합니다. 이 방식을 구현한 위젯이 바로 `ListView.builder`입니다.

## 10.2 ListView.builder로 지연 생성하기

```dart
class LazyList extends StatelessWidget {
  const LazyList({super.key, required this.items});

  final List<String> items;

  @override
  Widget build(BuildContext context) {
    return ListView.builder(
      itemCount: items.length,
      itemBuilder: (context, index) {
        return ListTile(
          leading: const Icon(Icons.person),
          title: Text(items[index]),
        );
      },
    );
  }
}
```

`ListView.builder`는 두 가지 핵심 매개변수를 받습니다.

- `itemCount`: 전체 항목의 개수입니다. `items.length`처럼 목록의 길이를 전달합니다.
- `itemBuilder`: `(BuildContext context, int index)`를 받아 해당 인덱스에 표시할 위젯을 반환하는 함수입니다. 이 함수는 항목이 화면에 나타나기 직전에 호출되며, 화면 밖으로 사라진 항목에 대해서는 호출되지 않습니다.

이렇게 하면 `items`에 5,000개의 문자열이 있어도, 실제로 위젯이 만들어지는 것은 화면에 보이는 10여 개 안팎뿐입니다. 사용자가 스크롤하면 새로 보이는 인덱스에 대해서만 `itemBuilder`가 호출되어 위젯을 만들고, 화면에서 멀어진 위젯은 Flutter가 알아서 정리합니다. 항목이 몇 개든 성능이 거의 일정하게 유지되는 이유가 여기에 있습니다.

> **참고**: 항목 사이에 구분선을 넣고 싶다면 `ListView.builder` 대신 `ListView.separated`를 사용할 수 있습니다. `itemBuilder`와 `itemCount` 외에 `separatorBuilder: (context, index) => const Divider()`를 추가로 지정하면, 각 항목 사이에 지정한 위젯이 자동으로 삽입됩니다.

### 스크롤 방향과 패딩

`ListView.builder`도 `scrollDirection: Axis.horizontal`을 지정하면 가로 스크롤 목록을 만들 수 있고, `padding: EdgeInsets.all(16)`으로 목록 전체에 여백을 줄 수 있습니다.

```dart
ListView.builder(
  scrollDirection: Axis.horizontal,
  padding: const EdgeInsets.symmetric(horizontal: 12),
  itemCount: banners.length,
  itemBuilder: (context, index) => BannerCard(banner: banners[index]),
)
```

## 10.3 GridView.builder로 격자 목록 만들기

사진 갤러리나 상품 목록처럼 항목을 격자(그리드) 형태로 보여줘야 할 때는 `GridView.builder`를 사용합니다. 사용법은 `ListView.builder`와 거의 같지만, 격자의 열 개수와 항목 크기를 정의하는 `gridDelegate`를 추가로 지정해야 합니다.

```dart
class PhotoGrid extends StatelessWidget {
  const PhotoGrid({super.key, required this.photoUrls});

  final List<String> photoUrls;

  @override
  Widget build(BuildContext context) {
    return GridView.builder(
      padding: const EdgeInsets.all(8),
      gridDelegate: const SliverGridDelegateWithFixedCrossAxisCount(
        crossAxisCount: 3,
        crossAxisSpacing: 8,
        mainAxisSpacing: 8,
      ),
      itemCount: photoUrls.length,
      itemBuilder: (context, index) {
        return Container(
          color: Colors.grey[300],
          child: Center(child: Text('${index + 1}')),
        );
      },
    );
  }
}
```

`SliverGridDelegateWithFixedCrossAxisCount`는 가장 널리 쓰이는 그리드 배치 방식으로, 주요 속성은 다음과 같습니다.

- `crossAxisCount`: 한 줄에 배치할 열(또는 행)의 개수입니다. 위 예제에서는 3열 격자를 만듭니다.
- `crossAxisSpacing`: 같은 줄에 있는 항목들 사이의 간격입니다.
- `mainAxisSpacing`: 스크롤 방향으로 이어지는 줄과 줄 사이의 간격입니다.
- `childAspectRatio`: 각 항목의 가로/세로 비율입니다. 기본값은 1.0(정사각형)입니다.

열 개수를 화면 너비에 따라 유동적으로 바꾸고 싶다면 `crossAxisCount` 대신 `maxCrossAxisExtent`(항목의 최대 너비)를 기준으로 열 개수를 자동 계산해 주는 `SliverGridDelegateWithMaxCrossAxisExtent`를 사용할 수도 있습니다.

`GridView.builder` 역시 `ListView.builder`와 마찬가지로 화면에 보이는 항목만 지연 생성하므로, 수백 장의 사진이 있는 갤러리도 부드럽게 스크롤됩니다.

## 10.4 Dismissible로 스와이프 삭제 구현하기

목록에서 항목을 옆으로 밀어서 삭제하는 동작은 메일 앱이나 할 일 목록 앱에서 흔히 볼 수 있습니다. Flutter는 이 동작을 `Dismissible` 위젯으로 간단히 구현할 수 있게 해줍니다.

```dart
ListView.builder(
  itemCount: items.length,
  itemBuilder: (context, index) {
    final item = items[index];
    return Dismissible(
      key: ValueKey(item),
      direction: DismissDirection.endToStart,
      background: Container(
        color: Colors.red,
        alignment: Alignment.centerRight,
        padding: const EdgeInsets.symmetric(horizontal: 20),
        child: const Icon(Icons.delete, color: Colors.white),
      ),
      onDismissed: (direction) {
        setState(() {
          items.removeAt(index);
        });
      },
      child: ListTile(title: Text(item)),
    );
  },
)
```

`Dismissible`을 사용할 때 눈여겨볼 속성은 다음과 같습니다.

- `key`: 목록의 각 항목을 구분하는 고유한 키입니다. `Dismissible`은 반드시 `key`가 필요한데, 항목이 삭제되어 목록에서 사라질 때 Flutter가 "어떤 위젯이 없어졌는지"를 정확히 추적해야 하기 때문입니다. 인덱스 대신 항목 자체의 값(`ValueKey(item)`)이나 고유 ID를 키로 사용하는 것이 안전합니다.
- `direction`: 스와이프를 허용할 방향입니다. `DismissDirection.endToStart`는 오른쪽에서 왼쪽으로 미는 동작만 허용합니다.
- `background`: 스와이프하는 동안 위젯 뒤로 드러나는 배경 화면으로, 보통 삭제를 암시하는 빨간색과 휴지통 아이콘을 배치합니다.
- `onDismissed`: 스와이프가 끝까지 완료되어 항목이 실제로 사라질 때 호출되는 콜백입니다. 여기서 데이터 목록에서 해당 항목을 제거하고 `setState`를 호출해 화면을 갱신합니다.

`onDismissed`에서 목록 데이터를 갱신하지 않으면, 화면에서는 항목이 사라진 것처럼 보이지만 실제 데이터에는 여전히 남아 있어 다음 빌드에서 오류가 발생할 수 있습니다. 반드시 실제 데이터 소스(`items` 리스트 등)에서도 항목을 제거해야 합니다.

## 10.5 실전 예제: 항목을 추가할 수 있는 목록

이제 6장에서 배운 `StatefulWidget`과 `setState`를 이 장의 내용과 결합해, 텍스트를 입력하고 버튼을 누르면 목록에 새 항목이 추가되는 화면을 만들어 보겠습니다. 이 구조는 18장에서 다룰 할 일 목록(Todo List) 실전 프로젝트의 뼈대와 그대로 이어집니다.

```dart
import 'package:flutter/material.dart';

class TaskListScreen extends StatefulWidget {
  const TaskListScreen({super.key});

  @override
  State<TaskListScreen> createState() => _TaskListScreenState();
}

class _TaskListScreenState extends State<TaskListScreen> {
  final List<String> _tasks = ['Flutter 공부하기', '9장 예제 따라 하기'];
  final TextEditingController _controller = TextEditingController();

  void _addTask() {
    final text = _controller.text.trim();
    if (text.isEmpty) return;

    setState(() {
      _tasks.add(text);
    });
    _controller.clear();
  }

  void _removeTask(int index) {
    setState(() {
      _tasks.removeAt(index);
    });
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('할 일 목록')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(16),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _controller,
                    decoration: const InputDecoration(
                      hintText: '할 일을 입력하세요',
                      border: OutlineInputBorder(),
                    ),
                    onSubmitted: (_) => _addTask(),
                  ),
                ),
                const SizedBox(width: 8),
                ElevatedButton(
                  onPressed: _addTask,
                  child: const Text('추가'),
                ),
              ],
            ),
          ),
          Expanded(
            child: _tasks.isEmpty
                ? const Center(child: Text('할 일이 없습니다.'))
                : ListView.builder(
                    itemCount: _tasks.length,
                    itemBuilder: (context, index) {
                      final task = _tasks[index];
                      return Dismissible(
                        key: ValueKey(task + index.toString()),
                        direction: DismissDirection.endToStart,
                        background: Container(
                          color: Colors.red,
                          alignment: Alignment.centerRight,
                          padding: const EdgeInsets.symmetric(horizontal: 20),
                          child: const Icon(Icons.delete, color: Colors.white),
                        ),
                        onDismissed: (_) => _removeTask(index),
                        child: ListTile(
                          leading: const Icon(Icons.check_box_outline_blank),
                          title: Text(task),
                        ),
                      );
                    },
                  ),
          ),
        ],
      ),
    );
  }
}
```

이 예제가 동작하는 흐름을 정리하면 다음과 같습니다.

1. `_tasks`라는 `List<String>`이 화면의 상태(state)이며, 이 목록이 바뀔 때마다 화면이 새로 그려져야 합니다.
2. 사용자가 `TextField`에 문자열을 입력하고 "추가" 버튼(또는 키보드의 완료 버튼)을 누르면 `_addTask`가 호출됩니다.
3. `_addTask`는 `setState` 안에서 `_tasks.add(text)`를 실행합니다. 6장에서 배웠듯, `setState`로 감싸지 않고 리스트만 수정하면 데이터는 바뀌어도 화면은 갱신되지 않습니다. `setState`를 호출해야 Flutter에게 "상태가 바뀌었으니 `build`를 다시 실행해 달라"고 알릴 수 있습니다.
4. `build`가 다시 실행되면 `ListView.builder`의 `itemCount`가 늘어난 `_tasks.length`를 기준으로 다시 계산되고, 새 항목에 대해서만 `itemBuilder`가 호출되어 위젯이 추가됩니다.
5. 항목을 왼쪽으로 스와이프하면 `Dismissible`의 `onDismissed`가 호출되어 `_removeTask`가 실행되고, 역시 `setState`를 통해 목록에서 항목이 제거되며 화면이 갱신됩니다.

지금은 앱을 껐다 켜면 입력한 목록이 사라지지만, 16장에서 로컬 데이터 저장을 배우고 나면 이 목록을 기기에 영구히 저장하는 방법을 다룰 것입니다. 그리고 18장에서는 이 구조에 완료 표시, 카테고리 분류, 마감일 같은 기능을 더해 완전한 할 일 목록 앱으로 확장합니다.

## 요약

- 항목 수가 많은 목록을 `Column`으로 한 번에 만들면 화면에 보이지 않는 위젯까지 전부 생성되어 메모리와 성능에 부담을 줍니다.
- `ListView.builder(itemCount: ..., itemBuilder: ...)`는 화면에 보이는 항목만 그때그때 만드는 지연 생성 방식으로, 항목 수와 관계없이 일정한 성능을 유지합니다.
- `GridView.builder`는 `gridDelegate`(대표적으로 `SliverGridDelegateWithFixedCrossAxisCount`)로 열 개수와 간격을 지정해 격자 형태의 지연 생성 목록을 만듭니다.
- `Dismissible` 위젯은 고유한 `key`, 스와이프 방향(`direction`), 배경(`background`), 완료 콜백(`onDismissed`)을 조합해 스와이프 삭제 동작을 구현합니다.
- `setState`와 `ListView.builder`, `Dismissible`을 함께 사용하면 항목을 추가·삭제할 때마다 목록이 즉시 갱신되는 동적인 목록 화면을 만들 수 있으며, 이 구조는 18장의 할 일 목록 프로젝트로 이어집니다.

## 연습문제

1. `Column`과 `SingleChildScrollView`로 100개의 항목을 표시하는 코드와, `ListView.builder`로 같은 목록을 표시하는 코드를 각각 작성하고 두 방식의 차이를 설명해 보세요.
2. `GridView.builder`와 `SliverGridDelegateWithFixedCrossAxisCount`를 사용해 `crossAxisCount`가 2인 격자 목록을 만들고, 각 칸에 숫자를 표시해 보세요.
3. `ListView.separated`를 사용해 항목 사이에 `Divider`가 표시되는 목록을 만들어 보세요.
4. 이 장의 할 일 목록 예제에 `Dismissible`의 `direction`을 `DismissDirection.horizontal`로 바꾸면 어떤 차이가 생기는지 실행해서 확인해 보세요.
5. 할 일 목록 예제를 확장해, 각 `ListTile`을 탭하면 `Checkbox`가 토글되어 완료 여부를 표시하도록 만들어 보세요. (힌트: 항목을 `String` 대신 완료 여부를 담은 클래스로 바꾸고, `setState`로 상태를 갱신합니다.)
