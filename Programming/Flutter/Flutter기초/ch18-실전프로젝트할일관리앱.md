## 들어가며

지금까지 이 책은 위젯과 레이아웃(3~5장), 상태 관리(6장, 13장), 사용자 입력(7장), 네비게이션(8장), 테마(9장), 리스트(10장), 애니메이션(11장), 폼과 유효성 검사(12장), 비동기 프로그래밍(14장), 네트워크 통신(15장), 로컬 데이터 저장(16장)까지 Flutter 앱을 구성하는 요소들을 한 장씩 따로 떼어 살펴봤다. 이 마지막 실전 장에서는 그 조각들을 한데 모아 실제로 쓸 수 있는 앱 하나를 처음부터 끝까지 완성한다. 주제는 누구나 한 번쯤 만들어봤을 법한 **할 일 관리(Todo) 앱**이다. 단순해 보이지만 이 앱 하나에 위젯 트리 구성, 상태 관리, 사용자 입력 처리, 리스트 렌더링, 로컬 데이터 저장까지 이 책에서 다룬 핵심 주제 대부분이 자연스럽게 녹아 있다.

## 요구사항 정리

본격적으로 코드를 작성하기 전에, 이 앱이 갖춰야 할 기능을 명확히 정리해두자.

1. **할 일 추가**: 텍스트 입력 필드와 추가 버튼을 통해 새로운 할 일 항목을 등록할 수 있다.
2. **목록 표시**: 등록된 할 일 목록을 `ListView.builder`로 화면에 표시한다.
3. **완료 체크**: 각 항목 앞에 `Checkbox`를 두어, 체크하면 완료 상태로 표시된다(취소선 등으로 시각적 구분).
4. **스와이프 삭제**: 항목을 좌우로 스와이프하면 `Dismissible` 위젯을 이용해 목록에서 삭제할 수 있다.
5. **데이터 영속성**: 앱을 완전히 종료했다가 다시 실행해도 이전에 등록한 할 일 목록이 그대로 유지되어야 한다.

로컬 저장 방식은 16장에서 다룬 `shared_preferences`와 `sqflite` 중 하나를 선택해야 한다. 이 프로젝트에서는 **`shared_preferences`**를 사용한다. 할 일 목록처럼 항목 수가 많지 않고 구조가 단순한 데이터는, 관계형 데이터베이스인 `sqflite`까지 도입하지 않아도 목록 전체를 JSON 문자열로 직렬화해서 키-값 형태로 저장하는 것으로 충분하기 때문이다. 데이터 구조가 훨씬 복잡해지거나 검색·정렬이 잦아진다면 그때는 `sqflite`로 옮겨가는 편이 낫다는 점을 기억해두자.

## 프로젝트 준비

새 Flutter 프로젝트를 만들고(`flutter create todo_app`), `pubspec.yaml`의 `dependencies` 항목에 `shared_preferences`를 추가한다.

```yaml
dependencies:
  flutter:
    sdk: flutter
  shared_preferences: ^2.2.0
```

패키지를 추가한 뒤에는 다음 명령으로 의존성을 내려받는다.

```bash
flutter pub get
```

## 1단계: TodoItem 모델 클래스 정의

가장 먼저 할 일 하나를 표현하는 모델 클래스를 정의한다. 각 할 일은 고유 식별자(`id`), 내용(`title`), 완료 여부(`isDone`)를 갖는다. `id`는 삭제나 토글 시 어떤 항목을 대상으로 할지 정확히 구분하기 위해 필요하며, 여기서는 생성 시점의 타임스탬프를 문자열로 변환해 사용한다.

```dart
class TodoItem {
  final String id;
  String title;
  bool isDone;

  TodoItem({
    required this.id,
    required this.title,
    this.isDone = false,
  });

  // SharedPreferences에는 문자열만 저장할 수 있으므로,
  // 객체를 Map으로, 다시 JSON 문자열로 변환할 수 있어야 한다.
  Map<String, dynamic> toJson() {
    return {
      'id': id,
      'title': title,
      'isDone': isDone,
    };
  }

  factory TodoItem.fromJson(Map<String, dynamic> json) {
    return TodoItem(
      id: json['id'] as String,
      title: json['title'] as String,
      isDone: json['isDone'] as bool,
    );
  }
}
```

`toJson`과 `fromJson`은 각각 객체를 저장 가능한 형태로 바꾸고, 저장된 데이터를 다시 객체로 복원하는 역할을 한다. 16장에서 살펴본 것처럼 `shared_preferences`는 문자열, 정수, 불리언 같은 원시 타입만 저장할 수 있기 때문에, 목록 전체는 `dart:convert`의 `jsonEncode`/`jsonDecode`를 이용해 하나의 JSON 문자열 리스트로 변환해서 저장한다.

## 2단계: 메인 화면의 상태 설계

할 일 목록 화면은 사용자 입력에 따라 화면이 계속 바뀌어야 하므로 `StatefulWidget`으로 만든다. 상태로 관리해야 할 값은 다음 두 가지다.

- `List<TodoItem> _todos`: 현재 할 일 목록
- `TextEditingController _textController`: 입력 필드의 텍스트를 읽고 초기화하기 위한 컨트롤러

```dart
import 'dart:convert';
import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

class TodoListScreen extends StatefulWidget {
  const TodoListScreen({super.key});

  @override
  State<TodoListScreen> createState() => _TodoListScreenState();
}

class _TodoListScreenState extends State<TodoListScreen> {
  final List<TodoItem> _todos = [];
  final TextEditingController _textController = TextEditingController();
  static const String _storageKey = 'todo_items';

  @override
  void initState() {
    super.initState();
    _loadTodos();
  }

  @override
  void dispose() {
    _textController.dispose();
    super.dispose();
  }

  // 이어서 데이터 로드/저장, 추가/삭제/토글 메서드를 구현한다.
}
```

`initState`에서 `_loadTodos`를 호출해 화면이 처음 만들어질 때 저장된 데이터를 불러오고, `dispose`에서 컨트롤러를 정리하는 것도 잊지 않는다.

## 3단계: 데이터 불러오기와 저장하기

`shared_preferences`의 `SharedPreferences.getInstance()`는 `Future`를 반환하므로, 14장에서 다룬 `async`/`await`를 사용해 비동기로 처리한다.

```dart
Future<void> _loadTodos() async {
  final prefs = await SharedPreferences.getInstance();
  final storedList = prefs.getStringList(_storageKey) ?? [];

  setState(() {
    _todos.clear();
    _todos.addAll(
      storedList.map((jsonString) => TodoItem.fromJson(jsonDecode(jsonString))),
    );
  });
}

Future<void> _saveTodos() async {
  final prefs = await SharedPreferences.getInstance();
  final storedList = _todos.map((todo) => jsonEncode(todo.toJson())).toList();
  await prefs.setStringList(_storageKey, storedList);
}
```

`getStringList`/`setStringList`를 사용하면 할 일 항목마다 JSON 문자열 하나씩을 리스트로 저장할 수 있어, 목록 전체를 하나의 큰 문자열로 다루는 것보다 다루기 쉽다. 목록에 변화가 생길 때마다(`_addTodo`, `_deleteTodo`, `_toggleTodo` 내부에서) `_saveTodos`를 호출해 즉시 저장하는 것이 이 앱의 핵심 아이디어다.

## 4단계: 추가/삭제/토글 로직

```dart
void _addTodo(String title) {
  final trimmed = title.trim();
  if (trimmed.isEmpty) return;

  setState(() {
    _todos.add(
      TodoItem(
        id: DateTime.now().microsecondsSinceEpoch.toString(),
        title: trimmed,
      ),
    );
  });
  _textController.clear();
  _saveTodos();
}

void _deleteTodo(String id) {
  setState(() {
    _todos.removeWhere((todo) => todo.id == id);
  });
  _saveTodos();
}

void _toggleTodo(String id) {
  setState(() {
    final todo = _todos.firstWhere((todo) => todo.id == id);
    todo.isDone = !todo.isDone;
  });
  _saveTodos();
}
```

세 메서드 모두 `setState`로 화면을 즉시 갱신한 뒤, `_saveTodos`를 호출해 변경 사항을 영속화하는 동일한 패턴을 따른다. 빈 문자열을 추가하지 않도록 `_addTodo`에서 `trim()` 후 비어 있는지 검사하는 것도 놓치기 쉬운 부분이니 주의하자.

## 5단계: UI 조립

이제 위 로직을 실제 화면으로 엮는다. 상단에는 입력 필드와 추가 버튼을, 아래에는 `ListView.builder`로 렌더링한 할 일 목록을 배치한다.

```dart
@override
Widget build(BuildContext context) {
  return Scaffold(
    appBar: AppBar(title: const Text('할 일 관리')),
    body: Column(
      children: [
        Padding(
          padding: const EdgeInsets.all(16.0),
          child: Row(
            children: [
              Expanded(
                child: TextField(
                  controller: _textController,
                  decoration: const InputDecoration(
                    hintText: '할 일을 입력하세요',
                    border: OutlineInputBorder(),
                  ),
                  onSubmitted: _addTodo,
                ),
              ),
              const SizedBox(width: 8),
              ElevatedButton(
                onPressed: () => _addTodo(_textController.text),
                child: const Text('추가'),
              ),
            ],
          ),
        ),
        Expanded(
          child: _todos.isEmpty
              ? const Center(child: Text('등록된 할 일이 없습니다.'))
              : ListView.builder(
                  itemCount: _todos.length,
                  itemBuilder: (context, index) {
                    final todo = _todos[index];
                    return Dismissible(
                      key: ValueKey(todo.id),
                      direction: DismissDirection.endToStart,
                      background: Container(
                        color: Colors.redAccent,
                        alignment: Alignment.centerRight,
                        padding: const EdgeInsets.symmetric(horizontal: 20),
                        child: const Icon(Icons.delete, color: Colors.white),
                      ),
                      onDismissed: (direction) => _deleteTodo(todo.id),
                      child: ListTile(
                        leading: Checkbox(
                          value: todo.isDone,
                          onChanged: (_) => _toggleTodo(todo.id),
                        ),
                        title: Text(
                          todo.title,
                          style: TextStyle(
                            decoration: todo.isDone
                                ? TextDecoration.lineThrough
                                : TextDecoration.none,
                            color: todo.isDone ? Colors.grey : null,
                          ),
                        ),
                      ),
                    );
                  },
                ),
        ),
      ],
    ),
  );
}
```

몇 가지 눈여겨볼 부분이 있다. `Dismissible`은 자식 위젯을 스와이프해서 없앨 수 있게 해주는 위젯으로, 목록 안에서 각 항목을 고유하게 구분할 `key`가 반드시 필요하다. 여기서는 `TodoItem.id`를 `ValueKey`로 감싸 사용했다. `direction`을 `DismissDirection.endToStart`로 지정해 오른쪽에서 왼쪽으로 스와이프할 때만 삭제되도록 했고, `background`에는 스와이프 도중 드러나는 빨간 배경과 휴지통 아이콘을 배치해 사용자에게 삭제 동작임을 시각적으로 알려준다. `onDismissed` 콜백이 실제로 `_deleteTodo`를 호출하는 지점이다.

`Checkbox`의 `onChanged`는 체크 여부와 무관하게 항상 `_toggleTodo`를 호출하도록 했는데, 이는 토글 로직 자체가 현재 값을 반전시키기 때문이다. 완료된 항목은 `TextDecoration.lineThrough`로 취소선을 그어 시각적으로 구분했다.

## 6단계: 앱 진입점 연결

마지막으로 `main.dart`에서 `MaterialApp`을 통해 이 화면을 앱의 홈으로 지정한다.

```dart
void main() {
  runApp(const TodoApp());
}

class TodoApp extends StatelessWidget {
  const TodoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: '할 일 관리 앱',
      theme: ThemeData(
        colorSchemeSeed: Colors.teal,
        useMaterial3: true,
      ),
      home: const TodoListScreen(),
    );
  }
}
```

여기까지 작성했다면 `flutter run`으로 앱을 실행해 실제 동작을 확인해보자. 할 일을 몇 개 추가하고, 체크박스를 토글하고, 스와이프로 하나를 지운 뒤 앱을 완전히 종료했다가 다시 실행해보면, `shared_preferences`에 저장된 데이터가 그대로 복원되어 마지막 상태가 유지되는 것을 확인할 수 있다.

## 완성한 앱 되짚어보기

이 짧은 앱 안에 이 책에서 다룬 여러 장의 내용이 실제로 어떻게 맞물려 있는지 정리해보자.

- **3~5장(위젯과 레이아웃)**: `Scaffold`, `Column`, `Row`, `Expanded`, `Padding` 같은 기본 위젯을 조합해 화면 구조를 잡았다.
- **6장(상태 관리 기초)**: `StatefulWidget`과 `setState`로 할 일 목록이라는 상태를 관리하고, 상태가 바뀔 때마다 화면이 다시 그려지도록 했다.
- **7장(사용자 입력)**: `TextField`와 `TextEditingController`로 사용자의 텍스트 입력을 읽어들였다.
- **9장(테마)**: `ThemeData`의 `colorSchemeSeed`로 앱 전체의 색상 톤을 지정했다.
- **10장(리스트와 스크롤)**: `ListView.builder`로 항목 수에 관계없이 효율적으로 목록을 렌더링했다.
- **16장(로컬 데이터 저장)**: `shared_preferences`와 `dart:convert`를 이용해 앱을 재실행해도 데이터가 유지되도록 만들었다.

## 앱을 확장하는 아이디어

지금 만든 앱은 동작하는 최소 기능(MVP) 수준이다. 여기서 더 나아갈 수 있는 방향을 몇 가지 제안하며 이 책을 마무리한다.

- **카테고리 분류**: `TodoItem`에 `category` 필드를 추가하고, 할 일을 "업무", "개인", "쇼핑" 같은 카테고리별로 묶어서 보여주거나 필터링하는 기능을 붙여볼 수 있다. 이 경우 항목 수가 많아지고 조건별 조회가 잦아지므로, `shared_preferences` 대신 16장에서 다룬 `sqflite`로 전환하는 것을 고려할 만하다.
- **다크 모드 적용**: 9장에서 다룬 테마 시스템을 확장해, `ThemeMode.system`이나 사용자가 직접 전환할 수 있는 스위치를 두어 라이트/다크 테마를 지원하도록 만들 수 있다.
- **Provider로 상태 관리 리팩터링**: 지금은 `TodoListScreen` 하나가 상태와 UI를 모두 갖고 있지만, 13장에서 다룬 `Provider`와 `ChangeNotifier`를 도입해 할 일 목록 상태를 별도의 클래스(예: `TodoListNotifier`)로 분리하면, 나중에 화면이 여러 개로 늘어나거나 위젯 트리 깊숙한 곳에서 목록에 접근해야 할 때 `context.watch`나 `Provider.of`만으로 손쉽게 접근할 수 있다.

이 확장들은 어느 것 하나 정답이 정해져 있지 않다. 이 책에서 배운 개념들을 바탕으로 직접 시도해보면서, Flutter로 앱을 키워나가는 감각을 익히는 것이 다음 단계다.

## 요약

- 할 일 관리 앱은 위젯/레이아웃, 상태 관리, 사용자 입력, 리스트, 로컬 저장 등 이 책에서 다룬 핵심 주제를 종합하는 실전 프로젝트다.
- `TodoItem` 모델은 `id`, `title`, `isDone` 필드를 가지며, `toJson`/`fromJson`으로 `shared_preferences`에 저장 가능한 형태로 직렬화된다.
- 메인 화면은 `StatefulWidget`으로 구현하며, `List<TodoItem>` 상태와 `TextEditingController`를 함께 관리한다.
- 추가·삭제·토글 로직은 모두 `setState`로 화면을 갱신한 뒤 `_saveTodos`를 호출해 변경 사항을 즉시 영속화하는 동일한 패턴을 따른다.
- `ListView.builder`로 목록을 표시하고, `Dismissible`로 스와이프 삭제를, `Checkbox`로 완료 토글을 구현한다.
- 앱은 카테고리 분류, 다크 모드, Provider 기반 상태 관리 리팩터링 등으로 얼마든지 확장할 수 있다.

## 연습문제

1. `TodoItem`에 `dueDate`(마감일) 필드를 추가하려면 모델 클래스와 `toJson`/`fromJson`을 각각 어떻게 수정해야 할지 설계해보라.
2. 이 장의 코드에서 `_addTodo`, `_deleteTodo`, `_toggleTodo`가 공통적으로 따르는 패턴(상태 변경 후 저장)을 설명하고, 만약 저장에 실패했을 때 사용자에게 어떻게 알려줄 수 있을지 아이디어를 제시해보라.
3. `Dismissible`의 `key`로 `ValueKey(todo.id)`가 아니라 `ValueKey(index)`를 사용하면 어떤 문제가 발생할 수 있는지 설명하라.
4. 할 일 항목이 수천 개로 늘어난다고 가정할 때, `shared_preferences` 대신 `sqflite`로 전환하면 어떤 이점이 있을지 16장의 내용을 참고해 서술하라.
5. 13장에서 배운 `ChangeNotifier`와 `Provider`를 이용해 이 앱의 상태 관리를 리팩터링한다면, 어떤 클래스를 새로 만들고 `TodoListScreen`의 책임을 어떻게 나눌지 설계해보라.
