## 4.1 분류 문제

분류(classification)는 입력을 미리 정해진 몇 개의 **클래스**(class, 범주) 중 하나로 배정하는 문제입니다.

- **이진 분류**(binary classification): 클래스가 두 개입니다. 스팸/정상 메일, 합격/불합격, 양성/악성 종양처럼 "예/아니오"로 답할 수 있는 문제입니다. 관례적으로 두 클래스를 0과 1로 나타내고, 우리가 찾고 싶은 쪽(예: 스팸)을 1, 즉 **양성 클래스**(positive class)로 둡니다.
- **다중 클래스 분류**(multiclass classification): 클래스가 세 개 이상입니다. 손글씨 숫자(0~9), 붓꽃의 품종(3종)이 그 예입니다.

이름은 "로지스틱 회귀"지만 회귀가 아니라 분류 모델입니다. 역사적인 이유로 이름이 그렇게 붙었을 뿐이니, 이름에 속지 마세요. 이 장은 이진 분류부터 시작해서 4.7절에서 다중 클래스로 확장합니다.

## 4.2 선형 회귀로 분류하면 안 되는 이유

가장 먼저 떠오르는 방법은 이것입니다. "정답이 0 또는 1이니, 3장의 선형 회귀로 0/1을 예측한 다음 예측값이 0.5 이상이면 1, 아니면 0이라고 하면 되지 않을까?" 실제로 해 보면서 무엇이 문제인지 확인해 봅시다.

공부한 시간(0~10시간)에 따른 시험 합격 여부 데이터를 만듭니다. 대략 5시간을 기준으로 합격 가능성이 갈리지만 운이나 컨디션 같은 잡음도 있습니다.

```python
import numpy as np
from sklearn.linear_model import LinearRegression

rng = np.random.default_rng(7)
hours = rng.uniform(0, 10, size=40)
passed = (hours + rng.normal(0, 1.0, size=40) > 5).astype(int)   # 1: 합격, 0: 불합격

print("공부 시간 앞 6개:", hours[:6].round(1))
print("합격 여부 앞 6개:", passed[:6])
print("합격 비율:", passed.mean())

def linear_classifier(x, y, x_eval, y_eval):
    """선형 회귀로 0/1을 예측하고, 예측값이 0.5가 되는 지점을 기준선으로 쓴다."""
    lr = LinearRegression().fit(x.reshape(-1, 1), y)
    w, b = lr.coef_[0], lr.intercept_
    threshold = (0.5 - b) / w                      # w*x + b = 0.5 인 x
    pred = (lr.predict(x_eval.reshape(-1, 1)) >= 0.5).astype(int)
    return lr, threshold, (pred == y_eval).mean()

lr1, thr1, acc1 = linear_classifier(hours, passed, hours, passed)
print(f"[원래 데이터] 기준선 x = {thr1:.2f}시간, 정확도 = {acc1:.3f}")
print("x = -2, 0, 10, 14 에서의 예측값:",
      lr1.predict(np.array([[-2], [0], [10], [14]])).round(2))
```

```text
공부 시간 앞 6개: [6.3 9.  7.8 2.3 3.  8.7]
합격 여부 앞 6개: [1 1 1 0 0 1]
합격 비율: 0.45
[원래 데이터] 기준선 x = 5.08시간, 정확도 = 0.900
x = -2, 0, 10, 14 에서의 예측값: [-0.46 -0.19  1.17  1.72]
```

원래 데이터에서는 기준선이 약 5시간으로 잘 잡혔고 정확도도 0.90입니다. 그런데 이상한 점이 보입니다. 공부 시간이 14시간이면 예측값이 1.72, 0시간이면 -0.19입니다. 확률로 해석하려 해도 1.72나 -0.19는 확률이 될 수 없습니다. 이것이 첫 번째 문제입니다. 선형 회귀의 출력은 범위에 제한이 없습니다.

두 번째 문제는 더 심각합니다. 아주 열심히 공부해서 당연히 합격한 학생 5명(30~40시간)을 데이터에 추가해 봅시다. 이 학생들은 정답을 틀리게 만드는 이상한 데이터가 아니라, 오히려 "많이 공부하면 합격한다"는 사실을 더 강하게 뒷받침하는 데이터입니다.

```python
hours2 = np.concatenate([hours, [30, 32, 35, 38, 40]])
passed2 = np.concatenate([passed, [1, 1, 1, 1, 1]])

lr2, thr2, acc2 = linear_classifier(hours2, passed2, hours, passed)
print(f"[극단값 추가 전] 기준선 x = {thr1:.2f}시간, 원래 데이터 정확도 = {acc1:.3f}")
print(f"[극단값 추가 후] 기준선 x = {thr2:.2f}시간, 원래 데이터 정확도 = {acc2:.3f}")
```

```text
[극단값 추가 전] 기준선 x = 5.08시간, 원래 데이터 정확도 = 0.900
[극단값 추가 후] 기준선 x = 7.66시간, 원래 데이터 정확도 = 0.800
```

기준선이 5시간에서 7.7시간으로 밀려났고, 원래 데이터에 대한 정확도는 0.90에서 0.80으로 떨어졌습니다. 선형 회귀는 직선을 0과 1 사이에 억지로 걸치려고 하기 때문에, 멀리 있는 "너무나 확실한" 데이터가 직선의 기울기를 낮춰 기준선을 흔들어 버립니다. 우리는 "충분히 확실하면 더 확실할 필요가 없다"는 성질을 가진 모델이 필요합니다. 즉, 점수가 아무리 커져도 출력이 1을 넘지 않고, 아무리 작아져도 0 아래로 내려가지 않는 모델입니다.

## 4.3 시그모이드 함수와 확률 해석

해결책은 선형 모델의 출력을 0과 1 사이로 눌러 주는 함수를 한 번 더 통과시키는 것입니다. 먼저 선형 모델처럼 점수를 계산합니다.

```text
z = w1*x1 + w2*x2 + ... + wd*xd + b
```

이 `z`는 -∞부터 +∞까지 어떤 값이든 될 수 있습니다. 여기에 **시그모이드 함수**(sigmoid function)를 적용합니다.

```text
sigmoid(z) = 1 / (1 + e^(-z))
```

```python
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

z = np.array([-6, -2, -1, 0, 1, 2, 6])
print("z      :", z)
print("sigmoid:", sigmoid(z).round(4))
```

```text
z      : [-6 -2 -1  0  1  2  6]
sigmoid: [0.0025 0.1192 0.2689 0.5    0.7311 0.8808 0.9975]
```

시그모이드의 성질은 다음과 같습니다.

- `z`가 아무리 커져도 1을 넘지 않고, 아무리 작아져도 0 아래로 내려가지 않습니다. 항상 0과 1 사이이므로 **확률로 해석**할 수 있습니다.
- `z = 0`이면 정확히 0.5입니다. 점수가 양수이면 0.5보다 크고, 음수이면 0.5보다 작습니다.
- 0 근처에서는 가파르게 변하고, 양끝으로 갈수록 평평해집니다. 이미 확실한 경우에는 더 확실해지는 것에 무관심해진다는 의미입니다. 4.2절에서 필요하다고 했던 성질이 바로 이것입니다.

> **구현상의 주의.** `z`가 -1000처럼 아주 작은 값이면 `np.exp(-z)`가 `exp(1000)`이 되어 오버플로 경고가 나옵니다. 결과(0에 수렴)는 올바르지만 경고가 거슬릴 수 있습니다. 이 장의 데이터에서는 문제가 되지 않으므로 가장 단순한 형태를 쓰고, 실전 라이브러리는 이런 경우를 안정적으로 처리하는 구현(예: `scipy.special.expit`)을 쓴다는 것만 알아 두세요.

이제 로지스틱 회귀 모델은 다음과 같이 정의됩니다. 모델의 출력 `p`는 "이 샘플이 클래스 1일 확률"로 해석합니다.

```text
p = sigmoid(w1*x1 + ... + wd*xd + b)
```

### 결정 경계

확률이 나왔다면 최종 클래스는 어떻게 정할까요? 가장 흔한 방법은 `p >= 0.5`이면 클래스 1, 아니면 클래스 0으로 정하는 것입니다. 그런데 시그모이드에서 `p = 0.5`는 `z = 0`일 때입니다. 따라서 클래스가 갈리는 경계는 다음 식이 만족되는 지점입니다.

```text
w1*x1 + w2*x2 + ... + wd*xd + b = 0
```

특성이 하나이면 이는 한 점(`x = -b/w`), 특성이 둘이면 직선, 셋 이상이면 평면입니다. 이 경계를 **결정 경계**(decision boundary)라고 부릅니다. 로지스틱 회귀의 결정 경계는 항상 직선(또는 평면)이므로 "선형 분류기"입니다. 경계 한쪽은 클래스 1, 반대쪽은 클래스 0입니다. 시그모이드는 경계의 위치를 바꾸지 않고, 경계에서 멀어질수록 확신이 커진다는 정보를 확률로 덧붙여 줍니다.

공부 시간 예제에 적용해 봅시다. `w = 1.2`, `b = -6`이면 경계는 `x = 6 / 1.2 = 5`시간입니다.

```python
w_demo, b_demo = 1.2, -6.0
study = np.array([0, 2, 4, 5, 6, 8, 10])
p_demo = sigmoid(w_demo * study + b_demo)

for h, p in zip(study, p_demo):
    print(f"공부 {h:2d}시간 -> 합격 확률 {p:.3f} -> 예측 {int(p >= 0.5)}")
```

```text
공부  0시간 -> 합격 확률 0.002 -> 예측 0
공부  2시간 -> 합격 확률 0.027 -> 예측 0
공부  4시간 -> 합격 확률 0.231 -> 예측 0
공부  5시간 -> 합격 확률 0.500 -> 예측 1
공부  6시간 -> 합격 확률 0.769 -> 예측 1
공부  8시간 -> 합격 확률 0.973 -> 예측 1
공부 10시간 -> 합격 확률 0.998 -> 예측 1
```

경계인 5시간에서 합격 확률이 정확히 0.5이고, 멀어질수록 확률이 0이나 1에 가까워집니다. `w`의 크기는 이 전환이 얼마나 급격한지를 정하고, `-b/w`는 전환이 일어나는 위치를 정합니다. 학습이란 데이터에 가장 잘 맞는 `w`와 `b`를 찾는 일입니다. 그러려면 손실 함수가 필요합니다.

## 4.4 로그 손실: 확률에 대한 벌점

선형 회귀에서 쓴 MSE를 그대로 쓸 수도 있지만, 시그모이드와 함께 쓰면 손실 곡선의 모양이 나빠져서 학습이 더딘 구간이 생깁니다. 분류에서는 확률을 다루는 데 더 어울리는 손실이 있습니다. **로그 손실**(log loss), 또는 **교차 엔트로피**(cross-entropy)입니다.

정답이 1인 샘플이라고 해 봅시다. 모델이 "클래스 1일 확률"을 `p`라고 답했다면, 좋은 모델은 `p`가 1에 가까워야 합니다. 이때의 손실을 `-log(p)`로 정의합니다.

```python
p = np.array([0.99, 0.9, 0.7, 0.5, 0.3, 0.1, 0.01])
print("정답이 1일 때 모델이 준 확률 p:", p)
print("손실 -log(p)                  :", (-np.log(p)).round(3))
```

```text
정답이 1일 때 모델이 준 확률 p: [0.99 0.9  0.7  0.5  0.3  0.1  0.01]
손실 -log(p)                  : [0.01  0.105 0.357 0.693 1.204 2.303 4.605]
```

표를 보면 직관이 생깁니다.

- 정답이 1인데 `p = 0.99`로 거의 확신했다면 손실이 0.01로 거의 없습니다.
- `p = 0.5`처럼 모른다고 답하면 손실이 0.69입니다.
- 정답이 1인데 `p = 0.01`로 자신 있게 0이라고 답하면 손실이 4.6으로 치솟습니다. `p`가 0에 가까워질수록 손실은 한없이 커집니다.

즉 로그 손실은 틀리는 것 자체보다 **자신만만하게 틀리는 것**을 아주 크게 벌줍니다. 정답이 0인 샘플에는 반대로 "클래스 0일 확률" `1 - p`에 같은 식을 적용해 `-log(1 - p)`를 씁니다. 두 경우를 하나로 합치면 다음과 같습니다.

```text
샘플 하나의 손실 = -( y * log(p) + (1 - y) * log(1 - p) )
```

`y = 1`이면 뒤쪽 항이 사라져 `-log(p)`가, `y = 0`이면 앞쪽 항이 사라져 `-log(1 - p)`가 남습니다. 전체 손실은 모든 샘플의 평균입니다. 코드로 구현해 네 가지 상황을 비교해 봅시다. `np.log(0)`이 `-inf`가 되는 것을 막기 위해 `p`를 아주 작은 값으로 잘라 줍니다(`np.clip`).

```python
def log_loss(y, p, eps=1e-12):
    p = np.clip(p, eps, 1 - eps)                 # log(0) 방지
    return -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))

y_true = np.array([1, 1, 0, 0])
cases = {
    "좋은 예측":              [0.9, 0.8, 0.2, 0.1],
    "애매한 예측":            [0.6, 0.5, 0.5, 0.4],
    "절반을 자신만만하게 틀림": [0.01, 0.99, 0.99, 0.01],
    "전부 맞고 자신만만":      [0.99, 0.99, 0.01, 0.01],
}
for name, p_pred in cases.items():
    print(f"{name:14s}: {log_loss(y_true, np.array(p_pred)):.4f}")
```

```text
좋은 예측         : 0.1643
애매한 예측        : 0.6020
절반을 자신만만하게 틀림 : 2.3076
전부 맞고 자신만만    : 0.0101
```

"전부 맞고 자신만만"이 가장 낮고, 맞히더라도 애매하면 손실이 큽니다. 그리고 4개 중 2개를 자신만만하게 틀린 경우는 손실이 2.3으로 가장 큽니다. 정확도로 보면 "절반을 틀림"이지만, 로그 손실은 모델이 자신의 확률에 얼마나 책임을 지는지까지 반영합니다.

### 기울기

이 손실의 기울기를 구하면 놀랍도록 깔끔한 결과가 나옵니다. 유도는 생략하지만 결과만 보면 다음과 같습니다.

```text
w의 기울기 = mean( (p - y) * x )
b의 기울기 = mean( p - y )
```

3장의 선형 회귀 기울기 `2 * mean((y_hat - y) * x)`와 비교해 보세요. 예측값 `y_hat` 자리에 확률 `p`가 들어갔을 뿐 형태가 똑같습니다(앞의 상수 2는 학습률에 흡수해도 됩니다). 그래서 3장의 `LinearRegressionGD`에서 예측 부분에 시그모이드를 하나 끼우고 손실 기록만 바꾸면 로지스틱 회귀가 됩니다.

## 4.5 NumPy로 로지스틱 회귀 구현하기

특성이 두 개인 인공 데이터로 직접 구현해 봅시다. `make_blobs`는 지정한 중심 주변에 점들이 뭉쳐 있는 데이터를 만들어 줍니다. 클래스 0은 (0, 0), 클래스 1은 (3, 3) 근처에 흩어져 있고, 두 무리는 약간 겹칩니다.

```python
from sklearn.datasets import make_blobs

X, y = make_blobs(n_samples=200, centers=[[0, 0], [3, 3]],
                  cluster_std=1.2, random_state=0)
print("X 모양:", X.shape, " 클래스별 개수:", np.bincount(y))

class LogisticRegressionGD:
    """경사하강법으로 학습하는 로지스틱 회귀 (이진 분류, NumPy 구현)."""

    def __init__(self, lr=0.1, n_iter=1000):
        self.lr = lr
        self.n_iter = n_iter

    def fit(self, X, y):
        n_samples, n_features = X.shape
        self.w_ = np.zeros(n_features)
        self.b_ = 0.0
        self.history_ = []
        for _ in range(self.n_iter):
            p = sigmoid(X @ self.w_ + self.b_)      # 점수 -> 확률
            error = p - y                           # 확률 - 정답
            self.w_ -= self.lr * (X.T @ error) / n_samples
            self.b_ -= self.lr * np.mean(error)
            self.history_.append(log_loss(y, p))    # 갱신 전 손실
        return self

    def predict_proba(self, X):
        return sigmoid(X @ self.w_ + self.b_)       # 클래스 1일 확률

    def predict(self, X):
        return (self.predict_proba(X) >= 0.5).astype(int)
```

```text
X 모양: (200, 2)  클래스별 개수: [100 100]
```

3장의 `LinearRegressionGD`와 거의 한 줄씩 대응되는 것을 확인해 보세요. 달라진 곳은 확률을 만드는 `sigmoid`, 오차의 정의(`p - y`), 손실 기록용 `log_loss`, 그리고 확률을 클래스로 바꾸는 `predict`뿐입니다. 학습해 보겠습니다.

```python
model = LogisticRegressionGD(lr=0.5, n_iter=5000).fit(X, y)

for i in [0, 9, 99, 999, 4999]:
    print(f"반복 {i+1:4d}: 로그 손실 = {model.history_[i]:.4f}")
print("w =", model.w_.round(3), " b =", round(model.b_, 3))
print("훈련 정확도:", (model.predict(X) == y).mean())
```

```text
반복   10: 로그 손실 = 0.3260
반복  100: 로그 손실 = 0.1538
반복 1000: 로그 손실 = 0.1227
반복 5000: 로그 손실 = 0.1222
w = [1.903 2.091]  b = -6.241
훈련 정확도: 0.945
```

손실이 `0.6931`에서 시작하는 것에 주목하세요. 이는 `ln 2`로, 가중치가 모두 0일 때 모델이 모든 샘플에 확률 0.5를 주기 때문입니다. 즉 아무것도 모르는 상태의 손실입니다. 학습이 진행되면서 0.12 수준까지 내려갑니다. 훈련 정확도가 0.945인 것은 두 무리가 겹쳐 있어 완벽한 분류가 불가능하기 때문입니다.

학습된 `w`와 `b`로 결정 경계를 계산해 봅시다. 경계는 `w1*x1 + w2*x2 + b = 0`이므로, `x1`이 주어지면 경계 위의 `x2`는 `-(w1*x1 + b) / w2`입니다. 이어서 몇몇 점의 확률도 확인합니다.

```python
w1, w2 = model.w_
for x1 in [-1, 0, 1, 2, 3, 4]:
    x2 = -(w1 * x1 + model.b_) / w2
    print(f"x1 = {x1:2d} 일 때 경계 위의 x2 = {x2:6.3f}")

pts = np.array([[0.0, 0.0], [1.0, 2.075], [3.0, 3.0], [0.0, 3.0]])
print("\n점:", pts.tolist())
print("클래스 1일 확률:", model.predict_proba(pts).round(3))
```

```text
x1 =  0 일 때 경계 위의 x2 =  2.985
x1 =  1 일 때 경계 위의 x2 =  2.075
x1 =  2 일 때 경계 위의 x2 =  1.165
```

`x1`이 1 늘 때마다 경계의 `x2`가 약 0.91씩 줄어드는 우하향 직선입니다. 직선의 위쪽은 클래스 1(중심 (3, 3) 쪽), 아래쪽은 클래스 0(중심 (0, 0) 쪽)입니다. 확률도 이 그림과 맞아떨어집니다. 클래스 0의 중심 (0, 0)은 확률이 0.002로 거의 확실히 클래스 0이고, 클래스 1의 중심 (3, 3)은 0.997입니다. 위 표에서 `x1 = 1`일 때 경계 위의 `x2`가 2.075였는데, 점 (1, 2.075)의 확률이 0.5로 나온 것은 경계 위의 점이 곧 `p = 0.5`인 점이라는 정의 그대로입니다. 점 (0, 3)은 경계(`x1 = 0`일 때 `x2 = 2.985`)를 아주 조금 넘어선 위쪽이라 확률이 0.508입니다. 이처럼 경계에서 멀어질수록 확률이 0이나 1로 빠르게 쏠립니다.

scikit-learn의 `LogisticRegression`과 비교해 봅시다. scikit-learn은 기본적으로 **규제**(regularization)를 적용합니다. 규제는 과대적합을 막기 위해 가중치가 지나치게 커지지 않도록 벌점을 주는 장치이고, 세기는 매개변수 `C`로 조절합니다. `C`가 작을수록 규제가 강하고, `C=np.inf`이면 규제를 끕니다. 여기서는 "가중치를 작게 유지하려는 힘" 정도로만 이해해 두세요. 우리 구현에는 규제가 없으므로, 같은 조건으로 비교하려면 `C=np.inf`로 규제를 끕니다.

```python
from sklearn.linear_model import LogisticRegression

sk_free = LogisticRegression(C=np.inf).fit(X, y)       # 규제 없음
sk_default = LogisticRegression().fit(X, y)            # 기본값 C=1.0 (규제 있음)

print("직접 구현        w =", model.w_.round(3), " b =", round(model.b_, 3))
print("sklearn (C=inf)  w =", sk_free.coef_[0].round(3), " b =", sk_free.intercept_.round(3))
print("sklearn (C=1)    w =", sk_default.coef_[0].round(3), " b =", sk_default.intercept_.round(3))
```

```text
직접 구현        w = [1.903 2.091]  b = -6.241
sklearn (C=inf)  w = [1.903 2.091]  b = [-6.241]
sklearn (C=1)    w = [1.607 1.726]  b = [-5.149]
```

규제를 끈 scikit-learn과 우리 구현은 소수점 셋째 자리까지 같은 답을 냅니다. 기본값(`C=1`)은 규제 때문에 가중치가 조금 작아졌습니다. 결정 경계의 방향은 거의 같지만 확률의 "확신 정도"가 약간 누그러집니다. 이처럼 직접 구현이 라이브러리와 일치하는 것을 확인하면, 라이브러리가 내부에서 무엇을 하는지에 대해 자신감이 생깁니다.

### 훈련/테스트 분할과 표준화

3장에서 배운 대로 데이터를 훈련용과 테스트용으로 나누고 표준화합니다. 분류에서는 한 가지 옵션이 추가됩니다. `stratify=y`를 주면 훈련/테스트 양쪽에서 클래스 비율이 원본과 같게 유지됩니다. 클래스 비율이 쏠려 있을 때 특히 중요합니다.

표준화와 모델을 따로 호출하면 "훈련 데이터로만 `fit`하고 `transform`은 양쪽에"라는 규칙을 매번 신경 써야 합니다. 이를 하나로 묶어 주는 것이 `Pipeline`입니다. `make_pipeline(StandardScaler(), LogisticRegression())`은 `fit`을 부르면 훈련 데이터로 스케일러를 학습시킨 뒤 변환된 데이터로 모델을 학습시키고, `predict`나 `score`를 부르면 같은 변환을 자동으로 적용합니다. 먼저 표준화의 효과를 보기 위해 표준화를 뺀 모델과 비교합니다.

```python
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

X_train, X_test, y_train, y_test = train_test_split(
    X_bc, y_bc, test_size=0.2, stratify=y_bc, random_state=42)
print("훈련/테스트:", X_train.shape, X_test.shape)
print(f"훈련 중 클래스 1 비율: {y_train.mean():.3f}, 테스트 중 클래스 1 비율: {y_test.mean():.3f}")

raw = LogisticRegression(max_iter=10000).fit(X_train, y_train)
print(f"[표준화 없음]      훈련 {raw.score(X_train, y_train):.4f} / 테스트 {raw.score(X_test, y_test):.4f}")

clf = make_pipeline(StandardScaler(), LogisticRegression())
clf.fit(X_train, y_train)
print(f"[표준화 + 로지스틱] 훈련 {clf.score(X_train, y_train):.4f} / 테스트 {clf.score(X_test, y_test):.4f}")
```

```text
훈련/테스트: (455, 30) (114, 30)
훈련 중 클래스 1 비율: 0.626, 테스트 중 클래스 1 비율: 0.632
[표준화 없음]      훈련 0.9560 / 테스트 0.9649
[표준화 + 로지스틱] 훈련 0.9890 / 테스트 0.9825
```

여기서 `score`는 **정확도**(accuracy), 즉 맞힌 샘플의 비율입니다. 표준화를 하자 테스트 정확도가 0.965에서 0.982로 올랐고, 114개 중 110개에서 112개로 두 개 더 맞힌 셈입니다. 표준화 없이 학습하려면 `max_iter`를 10000까지 올려야 수렴 경고 없이 끝납니다(기본값 100이나 1000에서는 경고가 나옵니다). 표준화는 로지스틱 회귀처럼 기울기를 따라 학습하는 모델에서 사실상 기본 전처리라고 생각하면 됩니다.

> `LogisticRegression`의 `max_iter`는 최적화 알고리즘의 최대 반복 횟수입니다. 기본값은 100이고, 데이터에 따라 수렴하기 전에 반복이 끝나 `ConvergenceWarning`이 나올 수 있습니다. 그럴 때는 표준화를 먼저 점검하고, 그래도 필요하면 `max_iter`를 늘립니다. scikit-learn은 기본적으로 경사하강법이 아니라 L-BFGS라는 더 영리한 최적화 방법을 쓰지만, "손실을 줄이는 방향으로 파라미터를 반복해서 갱신한다"는 큰 틀은 같습니다.

### predict_proba로 확률 확인하기

분류 모델은 `predict`로 클래스를 바로 내놓지만, 로지스틱 회귀는 `predict_proba`로 **확률**도 알려 줍니다. 결과는 `(샘플 수, 클래스 수)` 모양이며, 각 행이 "클래스 0일 확률, 클래스 1일 확률"이고 합은 1입니다. 열의 순서는 `classes_` 속성의 순서와 같습니다.

```python
proba = clf.predict_proba(X_test[:5])
print("predict_proba (앞 5개):\n", proba.round(3))
print("predict  :", clf.predict(X_test[:5]))
print("실제 정답:", y_test[:5])
print("classes_ :", clf.classes_)
```

```text
predict_proba (앞 5개):
 [[1.    0.   ]
 [0.    1.   ]
 [0.994 0.006]
 [0.466 0.534]
 [1.    0.   ]]
predict  : [0 1 0 1 0]
실제 정답: [0 1 0 1 0]

```

첫째, 셋째, 다섯째 샘플은 악성(0)일 확률이 거의 1에 가깝습니다. 넷째 샘플은 `[0.466, 0.534]`로 양성일 확률이 겨우 0.534입니다. `predict`는 이 확률이 0.5를 넘으면 1이라고 답하지만, 실제로는 거의 반반인 아슬아슬한 판단입니다. `predict`의 0/1 답만 보면 이런 정보가 사라집니다. 확률을 보면 "이 예측은 얼마나 믿을 만한가"를 알 수 있습니다. 의료 진단처럼 불확실성이 중요한 분야에서 확률을 함께 보는 것이 중요한 이유입니다.

### 학습된 가중치 읽기

선형 모델의 장점은 학습된 가중치를 들여다볼 수 있다는 것입니다. 표준화한 데이터로 학습했으므로 가중치의 크기를 서로 비교할 수 있습니다. 양의 가중치는 해당 특성이 클수록 클래스 1(양성 종양)일 확률이 올라간다는 뜻이고, 음의 가중치는 반대입니다.

```python
lr = clf[-1]                                  # 파이프라인의 마지막 단계(LogisticRegression)
coef = lr.coef_[0]
order = np.argsort(coef)

print("가중치가 가장 작은(음수) 특성 3개 -> 클수록 악성(0) 쪽:")
for i in order[:3]:
    print(f"  {data.feature_names[i]:22s} {coef[i]:7.3f}")
print("가중치가 가장 큰(양수) 특성 3개 -> 클수록 양성 종양(1) 쪽:")
for i in order[::-1][:3]:
    print(f"  {data.feature_names[i]:22s} {coef[i]:7.3f}")
```

```text
  worst texture           -1.255
  radius error            -1.083
  worst concave points    -0.954
가중치가 가장 큰(양수) 특성 3개 -> 클수록 양성 종양(1) 쪽:

  fractal dimension error   0.438
```

가장 작은 쪽에는 "가장 나쁜 질감(worst texture)", "반지름 오차(radius error)", "가장 나쁜 오목점(worst concave points)"이 있습니다. 이 값이 클수록 악성일 확률이 올라간다는, 의학적으로도 그럴듯한 해석이 가능합니다. 다만 3장에서 보았듯이 특성들이 서로 비슷한 정보를 담고 있으면(반지름, 둘레, 면적은 서로 강하게 연관됩니다) 가중치가 개별 특성의 중요도를 그대로 말해 주지는 않습니다. 가중치는 "참고 자료"로만 읽으세요.

### 규제 강도 C 살펴보기

앞에서 소개한 `C`를 바꿔 가며 훈련/테스트 정확도를 비교해 봅시다.

```python
for C in [0.01, 0.1, 1, 10, 100]:
    m = make_pipeline(StandardScaler(), LogisticRegression(C=C, max_iter=1000))
    m.fit(X_train, y_train)
    print(f"C={C:<6} 훈련 {m.score(X_train, y_train):.4f}  테스트 {m.score(X_test, y_test):.4f}")
```

```text
C=0.01   훈련 0.9560  테스트 0.9474
C=0.1    훈련 0.9868  테스트 0.9737
C=1      훈련 0.9890  테스트 0.9825
C=10     훈련 0.9912  테스트 0.9649
C=100    훈련 0.9934  테스트 0.9474
```

`C`가 커질수록(규제가 약해질수록) 훈련 정확도는 계속 오르지만, 테스트 정확도는 `C=1`에서 최고점을 찍고 이후 떨어집니다. 모델이 훈련 데이터의 세부 잡음까지 따라가는 **과대적합**(overfitting)의 신호입니다. 반대로 `C=0.01`처럼 규제가 너무 강하면 훈련과 테스트 모두 낮은, **과소적합**(underfitting) 상태입니다. 기본값 `C=1`이 이 데이터에서는 좋은 선택이었지만, 일반적으로는 데이터에 맞춰 조정해야 합니다. 테스트 데이터가 114개뿐이므로 0.01 차이는 샘플 한두 개 차이임을 염두에 두세요. 이런 작은 차이로 모델을 단정하지 않고 더 믿을 만하게 평가하는 방법은 5장에서 이어서 다룹니다.

마지막으로 4.5절에서 만든 직접 구현을 같은 데이터에 적용해 봅시다. 표준화된 데이터가 필요하므로 파이프라인에서 스케일러를 꺼내 씁니다.

```python
scaler = clf[0]                                 # 파이프라인의 첫 단계(StandardScaler)
Xtr_s, Xte_s = scaler.transform(X_train), scaler.transform(X_test)

own = LogisticRegressionGD(lr=0.1, n_iter=1000).fit(Xtr_s, y_train)
print(f"직접 구현: 로그 손실 {own.history_[0]:.4f} -> {own.history_[-1]:.4f}")
print(f"직접 구현: 훈련 {(own.predict(Xtr_s) == y_train).mean():.4f} / "
      f"테스트 {(own.predict(Xte_s) == y_test).mean():.4f}")
```

```text
직접 구현: 로그 손실 0.6931 -> 0.0566
직접 구현: 훈련 0.9890 / 테스트 0.9737
```

30개 특성을 가진 실제 데이터에서도 NumPy로 짠 몇 줄짜리 코드가 scikit-learn과 비슷한 성능을 냅니다(테스트 정확도는 114개 중 한 개 차이로, 규제와 최적화 방식이 다르기 때문입니다).

## 4.7 다중 클래스 분류: softmax와 one-vs-rest

클래스가 세 개 이상이면 어떻게 할까요? 이진 분류를 확장하는 방법이 두 가지 있습니다.

### softmax 회귀(다항 로지스틱 회귀)

클래스마다 점수를 하나씩 계산합니다. 클래스가 `K`개이면 `z1, z2, ..., zK`가 나옵니다. 이 점수들을 **softmax 함수**에 통과시키면 모두 0 이상이고 합이 1인 확률 `p1, ..., pK`가 됩니다.

```text
p_k = e^(z_k) / ( e^(z_1) + e^(z_2) + ... + e^(z_K) )
```

시그모이드가 "점수 하나를 확률 하나로" 바꾸었다면, softmax는 "점수 여러 개를 확률 분포 하나로" 바꿉니다. 점수가 높은 클래스에 더 큰 확률이 배정되고, 지수 함수 덕분에 점수 차이가 확률에서는 더 증폭됩니다. 클래스가 둘일 때 softmax는 시그모이드와 같아집니다. 손실도 로그 손실의 자연스러운 확장입니다. 정답 클래스의 확률 `p`에 대해 `-log(p)`를 쓰면 됩니다.

```python
def softmax(z):
    z = z - np.max(z, axis=-1, keepdims=True)    # 가장 큰 값을 빼서 오버플로 방지
    e = np.exp(z)
    return e / np.sum(e, axis=-1, keepdims=True)

scores = np.array([2.0, 1.0, 0.1])
print("점수:", scores, "-> softmax:", softmax(scores).round(3), " 합:", softmax(scores).sum())
print("모든 점수에 100을 더해도:", softmax(scores + 100).round(3))
```

```text
점수: [2.  1.  0.1] -> softmax: [0.659 0.242 0.099]  합: 1.0
모든 점수에 100을 더해도: [0.659 0.242 0.099]
```

점수 `[2.0, 1.0, 0.1]`이 확률 `[0.659, 0.242, 0.099]`로 바뀌었고, 합은 1입니다. 구현에서 `z`의 최댓값을 먼저 빼는 것은 오버플로를 막는 흔한 요령입니다. softmax는 모든 점수에서 같은 값을 빼거나 더해도 결과가 변하지 않으므로, 최댓값을 빼도 확률은 그대로입니다. 마지막 줄이 그 성질을 보여 줍니다.

### one-vs-rest(OvR)

다른 방법은 이진 분류기를 `K`개 만드는 것입니다. "클래스 1 대 나머지", "클래스 2 대 나머지", ... 식으로 각각 학습시키고, 새 샘플이 오면 `K`개의 분류기를 모두 돌려 가장 높은 확률을 준 클래스를 고릅니다. 이진 분류기만 있으면 어떤 분류 문제든 풀 수 있다는 장점이 있습니다.

scikit-learn의 `LogisticRegression`은 클래스가 세 개 이상일 때 기본적으로 softmax 방식으로 학습합니다. OvR로 학습하고 싶다면 `sklearn.multiclass.OneVsRestClassifier`로 감싸 줍니다. 붓꽃(iris) 데이터셋으로 두 방식을 비교해 봅시다. 붓꽃 데이터는 꽃받침/꽃잎의 길이와 너비 4개 특성으로 세 품종(setosa, versicolor, virginica)을 구분하는 고전적인 데이터입니다.

```python
from sklearn.datasets import load_iris
from sklearn.multiclass import OneVsRestClassifier

iris = load_iris()
X_ir, y_ir = iris.data, iris.target
print("클래스:", iris.target_names, np.bincount(y_ir))

Xtr_i, Xte_i, ytr_i, yte_i = train_test_split(
    X_ir, y_ir, test_size=0.2, stratify=y_ir, random_state=42)

soft = make_pipeline(StandardScaler(), LogisticRegression()).fit(Xtr_i, ytr_i)
ovr = make_pipeline(StandardScaler(),
                    OneVsRestClassifier(LogisticRegression())).fit(Xtr_i, ytr_i)

print(f"softmax 테스트 정확도: {soft.score(Xte_i, yte_i):.4f}")
print(f"OvR     테스트 정확도: {ovr.score(Xte_i, yte_i):.4f}")
print("softmax의 coef_ 모양:", soft[-1].coef_.shape, " intercept_ 모양:", soft[-1].intercept_.shape)
print("OvR 안의 이진 분류기 개수:", len(ovr[-1].estimators_))
```

```text
클래스: ['setosa' 'versicolor' 'virginica'] [50 50 50]
softmax 테스트 정확도: 0.9333
OvR     테스트 정확도: 0.9000
softmax의 coef_ 모양: (3, 4)  intercept_ 모양: (3,)
OvR 안의 이진 분류기 개수: 3
```

softmax 쪽의 `coef_`가 `(3, 4)`인 것은 "클래스 3개 x 특성 4개"의 가중치가 있다는 뜻입니다. 클래스마다 가중치 벡터가 하나씩이고, OvR도 내부적으로 이진 분류기 3개를 갖습니다. 정확도는 30개 테스트 샘플 중 28개(0.933)와 27개(0.900)로, 한 샘플 차이일 뿐이므로 어느 쪽이 낫다고 결론 내릴 수는 없습니다.

다중 클래스에서도 `predict_proba`는 `(샘플 수, 클래스 수)` 모양이고, 열 순서는 `classes_`를 따릅니다.

```python
proba = soft.predict_proba(Xte_i[:4])
print("softmax predict_proba:\n", proba.round(3))
print("각 행의 합:", proba.sum(axis=1))
print("predict:", soft.predict(Xte_i[:4]), " 정답:", yte_i[:4])

# 우리가 만든 softmax 함수로 같은 확률을 직접 계산해 보기
lr_i = soft[-1]
Z = soft[0].transform(Xte_i[:4]) @ lr_i.coef_.T + lr_i.intercept_   # (4, 3) 점수
print("직접 계산한 softmax와 predict_proba가 일치:", np.allclose(softmax(Z), proba))

print("\nOvR predict_proba:\n", ovr.predict_proba(Xte_i[:4]).round(3))
```

```text
softmax predict_proba:
 [[0.979 0.021 0.   ]
 [0.004 0.369 0.627]
 [0.149 0.842 0.009]
 [0.095 0.895 0.01 ]]
각 행의 합: [1. 1. 1. 1.]
predict: [0 2 1 1]  정답: [0 2 1 1]
직접 계산한 softmax와 predict_proba가 일치: True

OvR predict_proba:
 [[0.774 0.226 0.   ]
 [0.006 0.318 0.676]
 [0.149 0.838 0.013]

```

각 행이 하나의 샘플이고 각 열이 클래스(setosa, versicolor, virginica)입니다. 첫 샘플은 setosa일 확률이 0.979로 확실하고, 두 번째 샘플은 virginica 0.627, versicolor 0.369로 두 클래스 사이에서 고민하고 있습니다(정답은 virginica). 마지막 줄 바로 위의 `True`는 `predict_proba`의 정체가 "클래스별 점수 `X @ coef_.T + intercept_`를 softmax에 넣은 것"임을 확인해 줍니다. 3장에서 `X @ w + b`로 예측값을 만든 것과 같은 구조입니다. OvR은 클래스별로 독립적으로 학습한 이진 분류기의 확률을 합이 1이 되도록 정규화해서 내놓기 때문에 확률 값이 softmax 결과와 조금 다릅니다.

## 4.8 정확도만으로는 부족하다

지금까지 모델의 성능을 정확도 하나로 평가했습니다. 정확도는 직관적이지만 위험한 지표가 될 수 있습니다. 예를 들어 "카드 거래 중 5%가 사기"인 데이터를 생각해 봅시다. 무엇이 들어오든 "정상"이라고만 답하는 모델은 정확도가 95%입니다. 사기를 단 하나도 못 잡는데도 말입니다. 실제로 확인해 봅시다. 클래스 비율이 95 대 5인 데이터를 만들고, 항상 다수 클래스만 예측하는 `DummyClassifier`와 로지스틱 회귀를 비교합니다.

```python
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.metrics import confusion_matrix

Xi, yi = make_classification(n_samples=1000, n_features=10, n_informative=5,
                             weights=[0.95, 0.05], flip_y=0, class_sep=1.0,
                             random_state=0)
print("클래스별 개수:", np.bincount(yi))

Xa, Xb, ya, yb = train_test_split(Xi, yi, test_size=0.3, stratify=yi, random_state=0)

dummy = DummyClassifier(strategy="most_frequent").fit(Xa, ya)
logit = LogisticRegression(max_iter=1000).fit(Xa, ya)
print(f"항상 0만 예측하는 모델 정확도: {dummy.score(Xb, yb):.3f}")
print(f"로지스틱 회귀 정확도         : {logit.score(Xb, yb):.3f}")

print("\n혼동 행렬 (행: 실제 클래스, 열: 예측 클래스)")
print("항상 0만 예측:\n", confusion_matrix(yb, dummy.predict(Xb)))
print("로지스틱 회귀:\n", confusion_matrix(yb, logit.predict(Xb)))
```

```text
클래스별 개수: [950  50]
항상 0만 예측하는 모델 정확도: 0.950
로지스틱 회귀 정확도         : 0.980

혼동 행렬 (행: 실제 클래스, 열: 예측 클래스)
항상 0만 예측:
 [[285   0]
 [ 15   0]]
로지스틱 회귀:
 [[285   0]
 [  6   9]]
```

아무것도 학습하지 않은 더미 모델의 정확도가 0.95이고, 진짜 모델의 0.98과 큰 차이가 없어 보입니다. 하지만 **혼동 행렬**(confusion matrix)을 보면 속사정이 드러납니다. 혼동 행렬은 실제 클래스별로 모델이 무엇이라고 예측했는지를 세어 놓은 표입니다(행이 실제, 열이 예측). 더미 모델은 소수 클래스(1) 15개를 전부 놓쳤고, 로지스틱 회귀는 15개 중 9개를 찾았습니다. 정확도의 차이는 3%p 남짓이지만 "잡아야 할 것을 잡았는가"의 차이는 0개 대 9개입니다.

비슷한 문제는 클래스 비율이 비교적 고른 데이터에서도 생깁니다. 4.6절의 유방암 모델에서 확률이 0.95 이상일 때만 양성 종양(1)이라고 판정하도록 기준(임계값)을 기본값 0.5에서 0.95로 올려 봅시다. 악성 종양을 놓치지 않기 위해 "확실히 안전할 때만 안전하다고 하라"고 모델을 보수적으로 만드는 셈입니다.

```python
p_benign = clf.predict_proba(X_test)[:, 1]          # 양성 종양(1)일 확률

for threshold in [0.5, 0.95]:
    pred = (p_benign >= threshold).astype(int)
    cm = confusion_matrix(y_test, pred)
    print(f"기준 {threshold}: 정확도 {(pred == y_test).mean():.4f}")
    print(cm)
    print(f"  악성인데 양성 종양이라고 한 경우: {cm[0, 1]}건")
```

```text
기준 0.5: 정확도 0.9825
[[41  1]
 [ 1 71]]
  악성인데 양성 종양이라고 한 경우: 1건
기준 0.95: 정확도 0.8421
[[42  0]
 [18 54]]
  악성인데 양성 종양이라고 한 경우: 0건
```

기준 0.5에서는 정확도가 0.9825이고, 악성인데 양성 종양이라고 한 위험한 실수가 1건 있습니다. 기준을 0.95로 올리면 그 실수가 0건으로 사라집니다. 대신 정확도가 0.842로 떨어지고, 실제로는 양성 종양인데 악성이라고 판정한 경우가 1건에서 18건으로 늘어납니다. 병원이라면 어느 쪽이 더 좋은 모델일까요? 놓친 악성 종양 1건은 치명적일 수 있지만, 불필요한 추가 검사 18건도 환자에게는 부담입니다. 정답은 정확도 숫자 하나로는 나오지 않고, "어떤 종류의 오류가 더 치명적인가"에 달려 있습니다. 이처럼 오류의 종류를 구분해서 봐야 할 때는 정확도 말고 다른 지표가 필요합니다. 5장에서는 혼동 행렬을 제대로 읽는 법과 정밀도(precision), 재현율(recall), F1 점수, ROC 곡선과 AUC 같은 평가 지표를 배우면서, 분류 모델을 좀 더 정직하게 평가하는 방법을 살펴봅니다.

## 4.9 정리하며

- **분류**는 입력을 정해진 클래스 중 하나로 배정하는 문제이며, 클래스가 둘이면 이진 분류, 셋 이상이면 다중 클래스 분류입니다.
- 선형 회귀의 출력은 범위가 제한되지 않고, 극단적인 데이터에 기준선이 쉽게 흔들립니다. 그래서 분류에는 적합하지 않습니다.
- **시그모이드 함수**는 점수 `z`를 0과 1 사이의 확률로 바꿉니다. 로지스틱 회귀는 선형 모델의 점수를 시그모이드에 통과시킨 것이며, `z = 0`(즉 `p = 0.5`)인 지점이 **결정 경계**입니다.
- **로그 손실**(교차 엔트로피)은 정답에 낮은 확률을 준 예측, 특히 자신만만하게 틀린 예측을 크게 벌줍니다.
- 로지스틱 회귀의 기울기는 `mean((p - y) * x)`로 선형 회귀와 거의 같은 형태이며, 3장의 경사하강법 코드에서 시그모이드와 손실만 바꾸면 구현됩니다.
- scikit-learn의 `LogisticRegression`은 기본적으로 규제(`C`)를 적용하고, `predict_proba`로 클래스별 확률을 줍니다. 표준화와 함께 `make_pipeline`으로 묶어 쓰면 편합니다.
- 클래스가 셋 이상이면 **softmax**(클래스별 점수를 합이 1인 확률로 변환)나 **one-vs-rest**(이진 분류기 K개)를 씁니다. 현재의 `LogisticRegression`은 기본이 softmax입니다.
- **정확도**는 불균형 데이터나 오류의 비용이 다른 문제에서 모델의 성능을 잘못 보여 줄 수 있습니다. 다음 장에서 더 나은 평가 방법을 배웁니다.

## 연습문제

1. **시그모이드 손계산.** `sigmoid(0)`은 얼마일까요? `z = ln 3`(약 1.0986)이면 `sigmoid(z)`가 정확히 0.75가 됩니다. 식 `1 / (1 + e^(-z))`에 대입해 이유를 설명하고, `sigmoid(np.log(3))`을 계산해 확인하세요. 그다음 `sigmoid(-z)`와 `1 - sigmoid(z)`가 같다는 것도 몇 개의 `z` 값으로 확인해 보세요.
2. **로그 손실의 의미.** 정답이 1인 샘플에 대해 모델이 `p = 0.8`이라고 답했을 때와 `p = 0.2`라고 답했을 때의 샘플 하나당 손실을 각각 계산해 보세요. 두 값의 비율은 얼마인가요? 같은 오차 크기(0.2)라도 한쪽이 훨씬 큰 벌점을 받는 이유를 "자신만만하게 틀린다"는 표현을 써서 설명해 보세요.
3. **표준화하지 않으면?** 4.6절의 `LogisticRegressionGD(lr=0.1, n_iter=1000)`을 표준화하지 않은 `X_train`에 적용해 보세요. 손실이 어떻게 변하나요? 경고 메시지가 나오나요? 그 이유를 3장에서 배운 학습률, 특성의 크기와 연결해 설명해 보세요. 표준화한 데이터에서는 `lr=0.1`로 잘 되었는데 말입니다.
4. **기준값 조정.** 4.8절의 유방암 예제에서 기준(threshold)을 0.1, 0.3, 0.5, 0.7, 0.9, 0.99로 바꿔 가며 정확도와 "악성인데 양성 종양이라고 한 경우"의 개수를 표로 출력해 보세요. 기준과 두 숫자 사이에 어떤 관계가 있나요? 만약 여러분이 병원의 의사라면 어떤 기준을 택하겠습니까?
5. **붓꽃, 특성 두 개만.** 붓꽃 데이터에서 꽃잎 길이와 꽃잎 너비(3, 4번째 열)만 사용해 `LogisticRegression`을 학습하고 테스트 정확도를 구해 보세요. 4개 특성을 모두 썼을 때와 비교하면 어떤가요? 또 꽃잎 길이 5.0, 너비 1.8인 꽃의 `predict_proba`를 출력해 어느 품종과 어느 품종 사이에서 고민하는지 확인해 보세요. (힌트: 2차원 입력을 줄 때는 `[[5.0, 1.8]]`처럼 이중 리스트로 줍니다.)
