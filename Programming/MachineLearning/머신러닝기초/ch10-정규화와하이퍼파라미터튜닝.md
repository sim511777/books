이 장을 마치면 다음을 할 수 있습니다.

- NumPy로 릿지와 라쏘를 직접 구현해 scikit-learn과 같은 결과를 얻을 수 있습니다.

- 파라미터와 하이퍼파라미터를 구분할 수 있습니다.

- 튜닝에 테스트 세트를 쓰면 안 되는 이유를 설명하고, 올바른 모델 선택 순서를 따를 수 있습니다.

## 10.1 정규화가 필요한 이유

### 10.1.1 특성은 많고 표본은 적을 때

선형 회귀는 훈련 데이터의 오차를 최소로 만드는 계수를 찾습니다. 그런데 특성이 많고 표본이 적으면 **오차를 0에 가깝게 만드는 계수가 너무 쉽게 존재**합니다. 표본이 50개인데 특성이 50개라면, 잡음까지 포함해 50개의 정답을 정확히 통과하는 직선(정확히는 초평면)을 얼마든지 그릴 수 있습니다. 이때 모델은 진짜 규칙이 아니라 잡음을 외우고, 그 대가로 계수가 비정상적으로 커집니다.

이를 확인하기 위한 데이터를 만들어 봅시다. 특성은 50개이지만 실제로 정답에 영향을 주는 것은 **5개뿐**이고, 나머지 45개는 정답과 무관한 잡음 특성입니다. 훈련 표본은 50개뿐입니다.

```python
import numpy as np
from sklearn.datasets import make_regression
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LinearRegression, Ridge

# 특성 50개 중 실제로 y에 영향을 주는 것은 5개뿐인 데이터
X, y, true_coef = make_regression(n_samples=100, n_features=50, n_informative=5,
                                  noise=20.0, coef=True, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.5, random_state=0)
print("훈련 데이터:", X_tr.shape, "/ 진짜 영향을 주는 특성 번호:", np.flatnonzero(true_coef))

for name, reg in [("LinearRegression", LinearRegression()), ("Ridge(alpha=10)", Ridge(alpha=10))]:
    model = make_pipeline(StandardScaler(), reg).fit(X_tr, y_tr)
    w = model[-1].coef_
    print(f"{name:<17} 훈련 R2={model.score(X_tr, y_tr):6.3f}  테스트 R2={model.score(X_te, y_te):6.3f}"
          f"  |계수| 합={np.abs(w).sum():7.1f}")
```

```text
훈련 데이터: (50, 50) / 진짜 영향을 주는 특성 번호: [10 27 36 38 46]
LinearRegression  훈련 R2= 1.000  테스트 R2=-3.030  |계수| 합= 1188.2
Ridge(alpha=10)   훈련 R2= 0.972  테스트 R2= 0.709  |계수| 합=  344.1
```

(R2는 결정계수로, 1에 가까울수록 좋고 0은 "평균만 예측하는 모델" 수준입니다. 음수이면 평균만 찍는 것보다 못하다는 뜻입니다.)

`LinearRegression`은 훈련 데이터를 완벽하게 설명하지만(R2 = 1.000) 새 데이터에서는 -3.03으로 형편없습니다. 평균만 찍는 모델보다 오차 제곱이 약 4배 큰 예측입니다. 반면 정규화를 더한 `Ridge(alpha=10)`은 훈련 점수가 약간 낮아졌지만 테스트 R2가 0.709로 극적으로 좋아졌습니다. 계수의 절댓값 합도 1188에서 344로 줄었습니다.

### 10.1.2 정규화의 아이디어: 손실에 벌점을 더한다

정규화의 아이디어는 간단합니다. 원래는 "훈련 오차"만 줄이려 했다면, 이제는 **"훈련 오차 + 계수가 커지는 데 대한 벌점"** 을 줄이도록 합니다.

> 최소화할 값 = 훈련 오차 + $\alpha \times$ (계수의 크기를 재는 벌점)

- $\alpha$(`alpha`)는 벌점의 세기를 정하는 값입니다. 0이면 정규화가 없는 원래 모델이고, 클수록 계수를 강하게 누릅니다.
- 계수가 커서 얻는 이득(훈련 오차 감소)이 벌점보다 작으면 계수가 커지지 못합니다. 그래서 잡음 하나하나를 맞추려고 계수를 크게 키우는 일이 줄어듭니다.
- 벌점을 어떻게 정의하느냐에 따라 모델이 달라집니다. 계수의 **제곱합**이면 릿지(L2), **절댓값 합**이면 라쏘(L1)입니다.

> **정규화 전에는 반드시 스케일링하세요.** 벌점은 계수의 크기를 재는데, 계수의 크기는 특성의 단위에 따라 달라집니다. 같은 효과를 내는 특성도 단위가 작으면(예: cm 대신 mm) 계수가 커져서 더 큰 벌점을 받습니다. 단위가 결과를 좌우하지 않도록 `StandardScaler`로 먼저 표준화합니다(6장). 위 코드에서 `make_pipeline(StandardScaler(), ...)`를 쓴 이유입니다.

## 10.2 릿지, 라쏘, 엘라스틱넷

### 10.2.1 릿지 회귀 (L2 정규화)

릿지(Ridge) 회귀는 계수의 **제곱합**에 벌점을 줍니다. 오차 제곱합과 $\alpha \sum w_j^2$을 더한 값을 최소화합니다. 릿지는 계수를 모두 조금씩 0 쪽으로 **끌어당깁니다.** 정답이 크게 달라질 때 계수가 휘청거리는 것을 막아 주는 효과입니다.

릿지 회귀는 경사하강법 없이 한 번에 풀 수 있습니다. 특성과 정답에서 각각 평균을 뺀 뒤(절편은 벌점 대상이 아니기 때문입니다), 평균을 뺀 특성 행렬을 $Z$, 정답을 $y$라고 하면 다음 식으로 계수를 구합니다.

$$w = (Z^\top Z + \alpha I)^{-1} Z^\top y$$

벌점이 없는 선형 회귀의 해에서 $Z^\top Z$에 $\alpha I$를 더한 것이 전부입니다. 이 한 줄이 중요한 일을 합니다. 특성이 많거나 서로 비슷할 때 $Z^\top Z$는 거의 역행렬이 없는(불안정한) 행렬이 되는데, 대각선에 양수 $\alpha$를 더하면 안정적으로 풀립니다. NumPy로 직접 구현해서 scikit-learn과 비교해 봅시다.

```python
sc = StandardScaler().fit(X_tr)
Z_tr, Z_te = sc.transform(X_tr), sc.transform(X_te)    # 표준화된 특성

def ridge_fit(Z, y, alpha):
    z_mean, y_mean = Z.mean(axis=0), y.mean()
    Zc, yc = Z - z_mean, y - y_mean                    # 절편은 벌점에서 빼려고 중심화
    w = np.linalg.solve(Zc.T @ Zc + alpha * np.eye(Z.shape[1]), Zc.T @ yc)
    return w, y_mean - z_mean @ w

w, b = ridge_fit(Z_tr, y_tr, alpha=10.0)
sk = Ridge(alpha=10.0).fit(Z_tr, y_tr)
print("직접 구현과 sklearn의 계수 최대 차이:", np.abs(w - sk.coef_).max())
print("절편 차이:", abs(b - sk.intercept_))
```

```text
직접 구현과 sklearn의 계수 최대 차이: 5.684341886080802e-14
절편 차이: 0.0
```

차이가 $10^{-13}$ 수준이므로 사실상 같은 값입니다. 릿지는 이 몇 줄이 전부입니다. 이제 `alpha`를 바꾸며 어떻게 변하는지 봅시다.

```python
print("alpha     훈련R2  테스트R2   |계수| 합   0이 아닌 계수 수")
for alpha in [0.1, 1, 10, 100, 1000, 10000]:
    m = Ridge(alpha=alpha).fit(Z_tr, y_tr)
    print(f"{alpha:<8} {m.score(Z_tr, y_tr):7.3f} {m.score(Z_te, y_te):8.3f} {np.abs(m.coef_).sum():10.1f} {np.sum(m.coef_ != 0):10d}")
```

```text
0.1        0.999    0.206      615.1         50
1          0.997    0.690      441.0         50

```

표에서 세 가지를 읽을 수 있습니다.

- `alpha`가 커질수록 **계수의 크기(절댓값 합)가 계속 줄어듭니다.** 615 -> 4.5까지 내려갑니다.
- 훈련 R2는 계속 내려가지만 테스트 R2는 올라갔다가(alpha=10에서 0.709) 다시 내려갑니다. 정규화가 약하면 과대적합이고, 너무 강하면 모델이 아무것도 못 배우는 **과소적합**입니다. 5장에서 본 편향-분산 트레이드오프가 `alpha` 하나로 조절되는 셈입니다.
- 마지막 열을 보세요. **릿지는 계수를 0에 가깝게 만들 뿐 정확히 0으로 만들지는 않습니다.** 모든 `alpha`에서 50개 계수가 모두 0이 아닙니다.

> 이 표에서 테스트 R2를 보고 `alpha`를 비교한 것은 `alpha`의 효과를 눈으로 보기 위한 것입니다. 실제로 `alpha`를 고를 때는 테스트 세트가 아니라 교차 검증을 써야 합니다. 이유는 10.4절에서 실험으로 확인합니다.

### 10.2.2 라쏘 회귀 (L1 정규화)

라쏘(Lasso)는 계수의 **절댓값 합**에 벌점을 줍니다. 제곱 대신 절댓값을 쓰는 작은 차이가 큰 결과의 차이를 만듭니다. **라쏘는 중요하지 않은 계수를 정확히 0으로 만듭니다.** 그러므로 라쏘는 정규화와 **특성 선택**을 동시에 수행합니다.

왜 0이 될까요? 라쏘는 닫힌 식이 없어서 계수를 하나씩 번갈아 갱신하는 **좌표 하강법(coordinate descent)** 으로 풉니다. 계수 하나의 갱신식에 "소프트 임계값(soft thresholding)"이라는 연산이 등장하는데, 직관은 이렇습니다.

> 이 특성이 설명해 주는 몫(`rho`)이 벌점 $\alpha$보다 작으면 계수를 0으로 두고, 크면 $\alpha$만큼 깎아서 쓴다.

즉 기여가 벌점보다 작은 특성은 "쓸 가치가 없다"며 아예 꺼 버립니다. 릿지가 비율로 줄이는 것과 대비됩니다. 직접 구현해 봅시다.

```python
def soft_threshold(r, t):
    return np.sign(r) * np.maximum(np.abs(r) - t, 0.0)

def lasso_fit(Z, y, alpha, n_iter=1000):
    n, p = Z.shape
    z_mean, y_mean = Z.mean(axis=0), y.mean()
    Zc, yc = Z - z_mean, y - y_mean
    w = np.zeros(p)
    col_sq = (Zc ** 2).sum(axis=0) / n
    resid = yc.copy()                                  # 현재 잔차 y - Zw
    for _ in range(n_iter):
        for j in range(p):                             # 계수를 하나씩 순서대로 갱신
            resid += Zc[:, j] * w[j]                   # j번 특성의 기여를 잠시 뺀다
            rho = Zc[:, j] @ resid / n
            w[j] = soft_threshold(rho, alpha) / col_sq[j]   # 작은 값은 정확히 0으로
            resid -= Zc[:, j] * w[j]
    return w, y_mean - z_mean @ w

from sklearn.linear_model import Lasso

w, b = lasso_fit(Z_tr, y_tr, alpha=3.0)
sk = Lasso(alpha=3.0, tol=1e-10, max_iter=100000).fit(Z_tr, y_tr)
print("계수 최대 차이:", np.abs(w - sk.coef_).max())
print("0이 아닌 계수 수 (직접 / sklearn):", np.sum(w != 0), "/", np.sum(sk.coef_ != 0))
```

```text
계수 최대 차이: 3.117481828240898e-09
0이 아닌 계수 수 (직접 / sklearn): 15 / 15
```

우리 구현과 scikit-learn이 같은 계수, 같은 15개의 0이 아닌 계수를 찾았습니다. (scikit-learn의 `Lasso`는 오차 제곱합을 표본 수의 2배로 나눈 값에 $\alpha \sum |w_j|$를 더한 목적식을 최소화하는데, 위 구현은 같은 목적식을 풉니다. 이 때문에 릿지의 `alpha`와 라쏘의 `alpha`는 **값이 같아도 세기가 같지 않으니** 서로 비교하면 안 됩니다.)

이제 `alpha`를 바꿔 가며 살펴봅시다. 이번에는 "0이 아닌 계수 중 진짜 영향을 주는 특성이 몇 개인가"도 같이 셉니다. 진짜 특성은 5개입니다.

```python
true_idx = set(np.flatnonzero(true_coef))
print("alpha    훈련R2  테스트R2  0이 아닌 계수  그중 진짜 특성")
for alpha in [0.01, 0.1, 1, 3, 10, 30, 100]:
    m = Lasso(alpha=alpha, max_iter=100000).fit(Z_tr, y_tr)
    chosen = set(np.flatnonzero(m.coef_))
    print(f"{alpha:<7} {m.score(Z_tr, y_tr):7.3f} {m.score(Z_te, y_te):8.3f} {len(chosen):12d} {len(chosen & true_idx):12d}")
```

```text

0.01      1.000   -0.781           49            5
0.1       0.999    0.594           45            5
```

- `alpha`가 커질수록 0이 아닌 계수의 수가 49 -> 45 -> 31 -> 15 -> 5 -> 3 -> 0으로 **차례로 줄어듭니다.** 릿지와 달리 계수가 정말로 사라집니다.
- `alpha=10`에서는 0이 아닌 계수가 정확히 5개이고, 그 5개가 모두 진짜 영향을 주는 특성입니다. 라쏘가 50개 중에서 잡음 특성 45개를 걸러내고 진짜 5개를 찾아낸 것입니다.
- `alpha=3`에서도 5개의 진짜 특성은 모두 살아 있지만 10개의 잡음 특성이 함께 남아 있습니다. 그럼에도 테스트 R2는 0.924로 가장 높습니다. "특성을 정확히 골라내는 alpha"와 "예측이 가장 좋은 alpha"가 일치하지 않을 수 있다는 점을 기억해 두세요.
- `alpha=30`부터는 진짜 특성까지 지우기 시작하고, `alpha=100`에서는 모든 계수가 0이 되어 평균만 예측합니다.

### 10.2.3 계수를 직접 비교하기

네 모델의 계수를 한 표에 놓고 봅시다. 진짜 영향을 주는 5개 특성(10, 27, 36, 38, 46번)과 영향이 없는 특성 3개(0, 1, 2번)만 골랐습니다. "진짜값"은 표준화된 특성 기준의 실제 계수입니다. 엘라스틱넷은 바로 다음 절에서 설명하니 지금은 릿지와 라쏘 사이의 모델 정도로 봐 두세요.

```python
from sklearn.linear_model import ElasticNet

models = {
    "OLS": LinearRegression(),
    "Ridge(10)": Ridge(alpha=10),
    "Lasso(3)": Lasso(alpha=3, max_iter=100000),
    "ElasticNet": ElasticNet(alpha=3, l1_ratio=0.9, max_iter=100000),
}
for m in models.values():
    m.fit(Z_tr, y_tr)

true_std = true_coef * sc.scale_          # 표준화된 특성 기준의 진짜 계수
shown = list(np.flatnonzero(true_coef)) + [0, 1, 2]
print("특성   진짜값 " + "".join(f"{k:>12}" for k in models))
for j in shown:
    row = "".join(f"{m.coef_[j] + 0.0:12.2f}" for m in models.values())
    print(f"{j:>4} {true_std[j]:8.1f}" + row)
print("0인 계수 수:", {k: int(np.sum(m.coef_ == 0)) for k, m in models.items()})
```

- **Ridge(10)**: 모든 계수가 안쪽으로 끌려와서 잡음 특성의 계수가 작아졌습니다. 다만 0은 아니고, 진짜 특성의 계수도 함께 작아졌습니다(36번이 69.9 -> 41.3, 46번이 69.3 -> 51.4). 릿지는 잡음 특성과 진짜 특성을 가리지 않고 눌러서 전체적으로 안정시킵니다.
- **Lasso(3)**: 잡음 특성 0, 1, 2번이 정확히 0이고, 진짜 특성의 계수(11.6, 40.4, 60.8, 16.6, 72.7)가 대체로 진짜값에 가깝습니다(38번만 27.2보다 낮은 16.6으로 추정했습니다). 50개 중 35개가 0이 되었습니다. 이처럼 **정답에 영향을 주는 특성이 소수일 때** 라쏘가 매우 효과적입니다.

특성 선택으로서의 라쏘는 해석에도 도움이 됩니다. "이 모델은 50개 중 15개 특성만 쓴다"는 설명이 가능해지고, 선택된 특성만 따로 모아 다음 단계에서 다른 모델에 쓸 수도 있습니다(`coef_ != 0`으로 고르면 됩니다).

### 10.2.4 엘라스틱넷과 상관이 높은 특성

라쏘에는 약점이 하나 있습니다. **서로 거의 같은 정보를 담은(상관이 높은) 특성이 있으면, 그중 하나를 거의 임의로 고르고 나머지는 버립니다.** 어느 쪽을 고르는지는 데이터가 조금만 달라져도 바뀔 수 있습니다. 엘라스틱넷(ElasticNet)은 라쏘의 L1 벌점과 릿지의 L2 벌점을 **섞어서** 이 문제를 완화합니다. scikit-learn에서는 전체 세기를 `alpha`로, L1의 비중을 `l1_ratio`로 정합니다. `l1_ratio=1`이면 라쏘이고, 0에 가까울수록 릿지에 가까워집니다.

확인해 봅시다. `x1`과 `x2`는 거의 같은 특성(상관계수 0.999)이고, 정답은 `3*x1 + 3*x2 + 잡음`입니다. 즉 진짜 계수는 `(3, 3)`입니다. 데이터를 조금씩 다르게 만들어 네 번 학습합니다.

```python
def make_correlated(seed, n=100):
    r = np.random.RandomState(seed)
    x1 = r.normal(size=n)
    x2 = x1 + r.normal(scale=0.05, size=n)      # x1과 거의 똑같은 특성
    x3 = r.normal(size=n)                       # 무관한 특성
    return np.c_[x1, x2, x3], 3 * x1 + 3 * x2 + r.normal(size=n)   # 진짜 계수 (3, 3, 0)

print("진짜 계수 (x1, x2) = (3, 3)")
for seed in range(10, 14):
    Xs, ys = make_correlated(seed)
    lasso = Lasso(alpha=0.5).fit(Xs, ys)
    enet = ElasticNet(alpha=0.5, l1_ratio=0.5).fit(Xs, ys)
    print(f"데이터 {seed}: Lasso (x1, x2) = ({lasso.coef_[0]:5.2f}, {lasso.coef_[1]:5.2f})   "
          f"ElasticNet = ({enet.coef_[0]:5.2f}, {enet.coef_[1]:5.2f})")
```

```text
진짜 계수 (x1, x2) = (3, 3)
데이터 10: Lasso (x1, x2) = ( 2.71,  2.84)   ElasticNet = ( 2.56,  2.57)
데이터 11: Lasso (x1, x2) = ( 4.27,  1.33)   ElasticNet = ( 2.58,  2.57)
데이터 12: Lasso (x1, x2) = ( 2.62,  2.86)   ElasticNet = ( 2.56,  2.56)
데이터 13: Lasso (x1, x2) = ( 2.40,  2.98)   ElasticNet = ( 2.47,  2.48)
```

라쏘는 데이터 11에서 (4.27, 1.33)처럼 한쪽에 몰아주는 모습을 보였고, 데이터마다 배분이 들쭉날쭉합니다. 반면 엘라스틱넷은 어느 데이터에서든 두 계수를 거의 똑같이 나눠 가집니다(약 2.5씩). 둘 다 정규화 때문에 진짜 값 3보다는 작아졌지만, "비슷한 특성은 비슷한 계수를 받는다"는 안정적인 성질은 엘라스틱넷의 장점입니다. 10.2.3절의 표에서 엘라스틱넷의 0이 라쏘보다 적었던(23개 대 35개) 것도 L2 벌점이 섞여 계수가 덜 꺼지기 때문입니다. (두 모델의 `alpha`와 `l1_ratio` 설정이 달라서 엄밀한 비교는 아닙니다.)

세 모델을 언제 쓸지 정리하면 다음과 같습니다.

| 모델 | 벌점 | 계수가 정확히 0이 되는가 | 이럴 때 |
| --- | --- | --- | --- |
| 릿지 (`Ridge`) | 계수 제곱합 (L2) | 아니오 (작아지기만 함) | 대부분의 특성이 조금씩 기여하고, 상관이 높은 특성이 많을 때 |
| 라쏘 (`Lasso`) | 계수 절댓값 합 (L1) | 예 | 소수의 특성만 중요하다고 의심될 때, 특성 선택이 필요할 때 |
| 엘라스틱넷 (`ElasticNet`) | L1과 L2의 혼합 | 예 (L1 비중만큼) | 라쏘를 쓰고 싶지만 상관이 높은 특성이 있을 때 |

### 10.2.5 다른 모델의 정규화

정규화는 선형 회귀만의 도구가 아닙니다. 이름과 방향만 다를 뿐 거의 모든 모델에 있습니다.

| 모델 | 정규화 장치 | 방향 |
| --- | --- | --- |
| 로지스틱 회귀 (4장), SVM (8장) | `C` | `C`가 **작을수록** 정규화가 강함 (`alpha`의 역수 느낌) |
| 릿지/라쏘 | `alpha` | `alpha`가 **클수록** 강함 |
| 결정 트리 (9장) | `max_depth`, `min_samples_leaf` 등 | 값을 제한할수록 강함 |
| 그래디언트 부스팅 (9장) | `learning_rate`, `n_estimators`, `HistGradientBoostingClassifier`의 `l2_regularization` | 학습률이 작을수록, 트리를 덜 쌓을수록 강함 |
| 신경망 (13장) | L2 벌점 (`alpha`) | `alpha`가 클수록 강함 |

방향이 모델마다 달라서 헷갈리기 쉽습니다. 새 모델을 쓸 때는 "이 값을 키우면 모델이 더 복잡해지는가 단순해지는가"를 먼저 확인하는 습관을 들이세요.

## 10.3 파라미터와 하이퍼파라미터

지금까지 `alpha`, `C`, `max_depth`처럼 "사람이 정해 주는 값"을 계속 만났습니다. 이를 데이터로 학습되는 값과 구분하는 용어가 있습니다.

- **파라미터(parameter)**: 모델이 **학습 과정에서 데이터로부터 구하는** 값입니다. 선형 모델의 계수와 절편, 트리의 분할 특성과 임계값이 여기에 해당합니다.
- **하이퍼파라미터(hyperparameter)**: 학습을 시작하기 **전에 사람이 정해 주는** 설정값입니다. 릿지의 `alpha`, 트리의 `max_depth`, k-NN의 `n_neighbors`가 해당합니다. 학습으로 구해지는 것이 아니라 학습 방식 자체를 정합니다.

scikit-learn에서는 이 둘을 다음과 같이 구분할 수 있습니다. 하이퍼파라미터는 객체를 만들 때 생성자 인자로 넣고(`get_params()`로 확인), `fit` 후에 생기는 파라미터는 이름 끝에 밑줄이 붙습니다(`coef_`, `intercept_`).

```python
ridge = Ridge(alpha=10)                  # alpha: 하이퍼파라미터 (fit 전에 사람이 정함)
print("fit 전 설정:", ridge.get_params())
print("fit 전에 coef_가 있는가:", hasattr(ridge, "coef_"))

ridge.fit(Z_tr, y_tr)                    # coef_, intercept_: 파라미터 (fit이 데이터로 구함)
print("fit 후 coef_ 앞 3개:", ridge.coef_[:3].round(2), "/ intercept_:", round(float(ridge.intercept_), 2))
```

```text
fit 전 설정: {'alpha': 10, 'copy_X': True, 'fit_intercept': True, 'max_iter': None, 'positive': False, 'random_state': None, 'solver': 'auto', 'tol': 0.0001}
fit 전에 coef_가 있는가: False
fit 후 coef_ 앞 3개: [-1.18 -5.06 -7.5 ] / intercept_: 6.89
```

| 모델 | 파라미터 (학습으로 결정) | 하이퍼파라미터 (사람이 결정) |
| --- | --- | --- |
| 릿지/라쏘 | `coef_`, `intercept_` | `alpha`, `l1_ratio` |
| 결정 트리 | 각 노드의 분할 특성과 임계값, 리프의 예측값 | `max_depth`, `min_samples_leaf`, `criterion` |
| 랜덤 포레스트 | 각 트리의 구조 | `n_estimators`, `max_features`, 트리의 하이퍼파라미터들 |
| 그래디언트 부스팅 | 각 트리의 구조 | `n_estimators`, `learning_rate`, `max_depth` |
| 서포트 벡터 머신 | 서포트 벡터와 그 계수 | `C`, `kernel`, `gamma` |
| k-NN | (따로 없음, 훈련 데이터 자체가 모델) | `n_neighbors`, 거리 척도 |

두 값은 **구하는 방법이 다릅니다.** 파라미터는 `fit`이 알아서 구해 주지만, 하이퍼파라미터는 `fit`이 구해 주지 못합니다. 예를 들어 릿지의 `fit`은 주어진 `alpha`에서 최선의 계수를 구할 뿐이고, `alpha`가 10이 좋은지 100이 좋은지는 알지 못합니다. 그 결정은 "`fit`을 감싸는 바깥쪽 반복문"의 몫이고, 그 반복문이 곧 하이퍼파라미터 튜닝입니다.

## 10.4 하이퍼파라미터 튜닝

### 10.4.1 테스트 세트로 고르면 안 되는 이유

하이퍼파라미터 후보를 비교하려면 점수가 필요합니다. 가장 손쉬운 방법은 후보마다 테스트 세트 점수를 재서 가장 높은 것을 고르는 것입니다. 5.2절에서 이것이 왜 문제인지 이미 배웠습니다. 테스트 점수를 보고 고르는 순간 테스트 세트는 "처음 보는 데이터"가 아니기 때문입니다. 이 문제가 얼마나 심각한지 실험으로 확인해 보겠습니다.

실험 설계는 이렇습니다. **라벨이 완전한 무작위**인 데이터를 만듭니다. 배울 규칙이 아예 없으므로 어떤 모델의 진짜 정확도도 0.5(동전 던지기)입니다. 이 데이터에 하이퍼파라미터(여기서는 난수 시드)만 다른 결정 트리 300개를 학습시키고, 테스트 점수가 가장 높은 모델을 "튜닝 결과"로 고릅니다. 마지막으로 그 모델을 **한 번도 보지 않은 새 데이터**로 평가합니다.

```python
from sklearn.tree import DecisionTreeClassifier

rng = np.random.RandomState(0)
Xn = rng.normal(size=(3000, 20))
yn = rng.randint(0, 2, size=3000)          # 라벨이 완전한 무작위: 배울 수 있는 규칙이 없다
Xn_tr, yn_tr = Xn[:100], yn[:100]          # 훈련용
Xn_te, yn_te = Xn[100:200], yn[100:200]    # "테스트" 세트 (튜닝에 잘못 사용할 것)
Xn_new, yn_new = Xn[200:], yn[200:]        # 한 번도 보지 않은 새 데이터

models = [DecisionTreeClassifier(max_depth=3, max_features=5, random_state=seed).fit(Xn_tr, yn_tr)
          for seed in range(300)]          # 하이퍼파라미터(시드)만 다른 300개 모델
test_scores = np.array([m.score(Xn_te, yn_te) for m in models])
best = int(test_scores.argmax())

print(f"300개 모델의 테스트 정확도 평균: {test_scores.mean():.3f}")
print(f"테스트 점수로 고른 최고 모델:    {test_scores[best]:.3f}")
print(f"그 모델의 새 데이터 정확도:      {models[best].score(Xn_new, yn_new):.3f}")
```

```text
300개 모델의 테스트 정확도 평균: 0.505
테스트 점수로 고른 최고 모델:    0.620
그 모델의 새 데이터 정확도:      0.502
```

300개 모델의 평균은 0.505로 예상대로 동전 던지기입니다. 그런데 그중 **테스트 점수가 가장 좋은 모델을 고르면 0.620**이라는 그럴듯한 점수가 나옵니다. 마치 62%를 맞히는 모델을 찾은 것 같지만, 새 데이터에서는 0.502로 동전 던지기 수준입니다. 62%는 **운 좋게 테스트 세트에 잘 맞은 모델을 골라낸 결과**일 뿐입니다.

이것이 **선택 편향**입니다. 후보가 많을수록, 테스트 세트가 작을수록 "우연히 좋은 점수"를 얻는 후보가 하나쯤 생깁니다. 그 후보를 골라서 보고하면 점수는 실제보다 낙관적으로 부풀려집니다. 실제 튜닝에서도 같은 일이 일어납니다. 효과는 이 극단적인 예보다 작지만, 후보를 많이 시험할수록 같은 방향으로 작용합니다.

해결책은 5.2절에서 배운 대로 역할을 나누는 것입니다.

- **훈련 데이터** 안에서 하이퍼파라미터를 비교한다(교차 검증 사용).
- **테스트 세트**는 모든 선택이 끝난 뒤 마지막에 **딱 한 번**만 쓴다.

데이터가 작으면 검증 세트를 따로 떼기 아까우므로, 5.6절의 **교차 검증**이 검증 세트의 역할을 대신합니다. 이를 후보 설정 전체에 대해 자동으로 해 주는 도구가 `GridSearchCV`입니다.

### 10.4.2 GridSearchCV: 격자 탐색

`GridSearchCV`는 하이퍼파라미터 후보를 격자(grid)로 나열하면 **모든 조합을 교차 검증으로 평가**하고 가장 좋은 조합을 골라 줍니다. 과정은 다음과 같습니다.

1. `param_grid`의 모든 조합을 만든다.
2. 조합마다 `cv`겹 교차 검증을 수행해 평균 점수를 구한다.
3. 평균 점수가 가장 높은 조합을 `best_params_`로 정한다.
4. 그 조합으로 **전체 훈련 데이터**에 다시 학습한 모델을 `best_estimator_`로 보관한다(`refit=True`가 기본값).

유방암 데이터로 로지스틱 회귀의 `C`를 골라 봅시다. 먼저 테스트 세트를 떼어 두고, 이후 모든 탐색은 훈련 세트에서만 합니다. 스케일러와 모델을 `Pipeline`으로 묶으면 교차 검증의 폴드마다 스케일러가 **그 폴드의 훈련 부분으로만** 학습되어 5.3절의 전처리 누수가 생기지 않습니다. 파이프라인 안의 하이퍼파라미터는 `단계이름__파라미터이름`으로 지정합니다.

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import GridSearchCV, StratifiedKFold
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

cancer = load_breast_cancer()
Xc_tr, Xc_te, yc_tr, yc_te = train_test_split(
    cancer.data, cancer.target, test_size=0.25, stratify=cancer.target, random_state=42)
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

pipe_lr = Pipeline([("scaler", StandardScaler()),
                    ("clf", LogisticRegression(max_iter=5000))])
param_grid = {"clf__C": [0.001, 0.01, 0.1, 1, 10, 100]}      # "단계이름__파라미터이름"

grid_lr = GridSearchCV(pipe_lr, param_grid, cv=cv)
grid_lr.fit(Xc_tr, yc_tr)                                     # 훈련 세트만 사용

print("best_params_:", grid_lr.best_params_)
print("best_score_: ", round(grid_lr.best_score_, 4))
res = grid_lr.cv_results_
for C, mean, std, rank in zip(res["param_clf__C"], res["mean_test_score"],
                              res["std_test_score"], res["rank_test_score"]):
    print(f"C={C:<6} 평균 {mean:.4f}  표준편차 {std:.4f}  순위 {rank}")
```

```text
best_params_: {'clf__C': 1}
best_score_:  0.9789
C=0.001  평균 0.8802  표준편차 0.0383  순위 6
C=0.01   평균 0.9507  표준편차 0.0292  순위 5
C=0.1    평균 0.9766  표준편차 0.0128  순위 2
C=1.0    평균 0.9789  표준편차 0.0088  순위 1
C=10.0   평균 0.9671  표준편차 0.0115  순위 3
C=100.0  평균 0.9648  표준편차 0.0128  순위 4
```

결과를 읽는 방법은 다음과 같습니다.

- `best_params_`는 가장 좋은 조합(`C=1`), `best_score_`는 그 조합의 **교차 검증 평균 점수**(0.9789)입니다. 테스트 세트 점수가 아니라는 점에 주의하세요. 이 시점까지 테스트 세트는 한 번도 쓰이지 않았습니다.
- `cv_results_`에는 조합별 평균(`mean_test_score`), 표준편차(`std_test_score`), 순위(`rank_test_score`)가 들어 있습니다. 정규화가 너무 강한 `C=0.001`은 과소적합이라 0.8802로 낮고, 폴드마다 점수도 크게 흔들립니다(표준편차 0.0383). `C=0.1`, `1`, `10`, `100`은 점수가 0.965~0.979로 서로 가깝습니다. 이처럼 **최고 점수와 표준편차를 함께** 보면 "이 값이 뚜렷하게 좋은가, 아니면 비슷한 후보가 여럿인가"를 알 수 있습니다.
- `C`를 넓은 범위에서 **10배씩 로그 간격**으로 나열한 점에 주목하세요. `C`처럼 크기가 자릿수 단위로 달라지는 값은 `[1, 2, 3, 4, 5]`처럼 일정한 간격이 아니라 `[0.01, 0.1, 1, 10, 100]`처럼 곱셈 간격으로 훑는 것이 관례입니다. `alpha`, `learning_rate`도 마찬가지입니다.
- `GridSearchCV` 객체 자체도 모델처럼 `predict`, `score`를 쓸 수 있고, 내부적으로 `best_estimator_`를 호출합니다.

하이퍼파라미터가 여러 개일 때는 격자가 곱셈으로 커집니다. 9장의 랜덤 포레스트로 3개 하이퍼파라미터를 동시에 탐색해 봅시다.

```python
from sklearn.ensemble import RandomForestClassifier

param_grid = {"max_depth": [3, 5, None],
              "min_samples_leaf": [1, 3, 5],
              "max_features": ["sqrt", 0.5]}
grid_rf = GridSearchCV(RandomForestClassifier(n_estimators=100, random_state=0),
                       param_grid, cv=cv)
grid_rf.fit(Xc_tr, yc_tr)
print("조합 수:", len(grid_rf.cv_results_["params"]), "-> 학습 횟수:", len(grid_rf.cv_results_["params"]) * 5)
print("best_params_:", grid_rf.best_params_)
print("best_score_: ", round(grid_rf.best_score_, 4))

res = grid_rf.cv_results_
print("\n상위 5개 조합")
for i in np.argsort(res["rank_test_score"])[:5]:
    print(f"  순위 {res['rank_test_score'][i]}  평균 {res['mean_test_score'][i]:.4f}  {res['params'][i]}")
```

```text
조합 수: 18 -> 학습 횟수: 90
best_params_: {'max_depth': 5, 'max_features': 0.5, 'min_samples_leaf': 3}
best_score_:  0.9625

상위 5개 조합
  순위 1  평균 0.9625  {'max_depth': 5, 'max_features': 0.5, 'min_samples_leaf': 3}
  순위 1  평균 0.9625  {'max_depth': None, 'max_features': 0.5, 'min_samples_leaf': 3}
  순위 3  평균 0.9578  {'max_depth': 3, 'max_features': 0.5, 'min_samples_leaf': 3}
  순위 4  평균 0.9578  {'max_depth': None, 'max_features': 'sqrt', 'min_samples_leaf': 3}
  순위 5  평균 0.9554  {'max_depth': 5, 'max_features': 0.5, 'min_samples_leaf': 1}
```

조합이 3 x 3 x 2 = 18개이고 5겹 교차 검증이므로 모델을 90번 학습했습니다. 여기서 알아 둘 점이 몇 가지 있습니다.

- **격자 탐색의 비용은 곱셈으로 늘어납니다.** 하이퍼파라미터가 하나 늘어 후보가 4개씩이라면 조합은 4배가 됩니다. 후보 수 x 폴드 수 x (모델 한 번 학습하는 시간)이 총 비용입니다. `GridSearchCV(..., n_jobs=-1)`로 여러 CPU 코어에 나눠 돌리면 시간을 줄일 수 있습니다.
- 1위가 둘입니다(`max_depth`가 5일 때와 `None`일 때 평균이 같음). 교차 검증 점수는 맞힌 표본 수를 평균한 값이라 동점이 흔합니다. 동점이면 **더 단순한 쪽(여기서는 `max_depth=5`)** 을 고르는 편이 안전하고, `best_params_`도 동점이면 먼저 나온 조합을 돌려줍니다.
- 상위 5개 조합의 점수 차이는 0.7%p 이내입니다. 위 로지스틱 회귀의 폴드 간 표준편차가 1%p 안팎이었던 것과 비교하면 작은 차이이므로, "1위가 확실히 낫다"가 아니라 "상위 몇 개는 사실상 비슷하다"로 읽어야 합니다.

`cv_results_`는 딕셔너리라서 `pandas.DataFrame(grid.cv_results_)`로 바꾸면 표로 보기 편합니다.

릿지와 라쏘처럼 **`alpha`를 교차 검증으로 고르는 일은 아주 흔해서**, scikit-learn은 이를 내장한 `RidgeCV`, `LassoCV`, `ElasticNetCV` 같은 클래스를 따로 제공합니다. 10.2절의 회귀 데이터로 써 봅시다. `LassoCV`는 `alpha` 후보를 스스로 만들어 교차 검증으로 최적값을 찾습니다.

```python
from sklearn.linear_model import LassoCV, RidgeCV

lasso_cv = LassoCV(cv=5, random_state=0, max_iter=100000).fit(Z_tr, y_tr)   # alpha 후보를 스스로 만들어 5겹 교차 검증
ridge_cv = RidgeCV(alphas=np.logspace(-2, 3, 20)).fit(Z_tr, y_tr)
print(f"LassoCV  고른 alpha = {lasso_cv.alpha_:.3f}, 테스트 R2 = {lasso_cv.score(Z_te, y_te):.3f}, 0이 아닌 계수 {np.sum(lasso_cv.coef_ != 0)}개")
print(f"RidgeCV  고른 alpha = {ridge_cv.alpha_:.3f}, 테스트 R2 = {ridge_cv.score(Z_te, y_te):.3f}")
```

```text
LassoCV  고른 alpha = 4.680, 테스트 R2 = 0.922, 0이 아닌 계수 6개
RidgeCV  고른 alpha = 1.274, 테스트 R2 = 0.708
```

테스트 세트를 보지 않고 교차 검증만으로 고른 `alpha`가 앞의 표에서 눈으로 찾은 최적 구간(라쏘 3~10, 릿지 1~10) 안에 들어갔고, 테스트 R2도 0.922, 0.708로 표의 최고점(0.924, 0.709)과 거의 같습니다. 교차 검증이 테스트 세트를 훔쳐보지 않고도 좋은 선택을 해 줍니다.

### 10.4.3 RandomizedSearchCV: 무작위 탐색

격자 탐색은 하이퍼파라미터가 많아지면 감당하기 어려워집니다. 예를 들어 부스팅 모델의 하이퍼파라미터 5개를 각각 5개 값으로 훑으면 5^5 = 3,125개 조합에 5겹이면 15,625번의 학습입니다. 게다가 격자는 **각 하이퍼파라미터를 몇 개 안 되는 값으로만** 시험합니다.

`RandomizedSearchCV`는 격자 대신 **분포에서 무작위로 조합을 뽑아** `n_iter`개만 평가합니다. 이 방법이 좋은 이유는 다음과 같습니다.

- 예산(시도 횟수)을 `n_iter`로 직접 정할 수 있습니다.
- 하이퍼파라미터마다 영향력이 다릅니다. 어떤 값은 점수에 거의 영향이 없고 어떤 값은 크게 영향을 줍니다. 격자는 영향이 없는 값에도 똑같이 시도 횟수를 쓰는 반면, 무작위 탐색은 **매번 모든 하이퍼파라미터에 새로운 값을 시험하므로** 중요한 하이퍼파라미터의 서로 다른 값을 더 많이 만나게 됩니다.
- `scipy.stats`의 분포로 연속 범위를 지정할 수 있습니다. 학습률처럼 크기가 자릿수로 달라지는 값은 `loguniform`(로그 척도에서 균일), 정수 범위는 `randint`를 씁니다.

9장의 `HistGradientBoostingClassifier`를 5개 하이퍼파라미터에 대해 20번만 무작위 탐색해 봅시다.

```python
from scipy.stats import loguniform, randint
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.model_selection import RandomizedSearchCV

param_dist = {
    "learning_rate": loguniform(0.01, 0.3),        # 로그 척도로 고르게 뽑는다
    "max_leaf_nodes": randint(4, 64),
    "min_samples_leaf": randint(5, 50),
    "l2_regularization": loguniform(1e-3, 10),
    "max_iter": randint(50, 300),
}
rand_hgb = RandomizedSearchCV(HistGradientBoostingClassifier(random_state=0),
                              param_dist, n_iter=20, cv=cv, random_state=0)
rand_hgb.fit(Xc_tr, yc_tr)

print("best_score_:", round(rand_hgb.best_score_, 4))
for k, v in rand_hgb.best_params_.items():
    print(f"  {k}: {v:.4g}")
scores = rand_hgb.cv_results_["mean_test_score"]
print(f"20개 후보의 교차 검증 점수: 최저 {scores.min():.4f} ~ 최고 {scores.max():.4f}")
```

```text
best_score_: 0.9695
  l2_regularization: 0.002652
  learning_rate: 0.05007
  max_iter: 253
  max_leaf_nodes: 54
  min_samples_leaf: 33
20개 후보의 교차 검증 점수: 최저 0.9366 ~ 최고 0.9695
```

20개 조합(100번 학습)만으로 교차 검증 점수 0.9695를 얻었습니다. 20개 후보의 점수는 0.9366~0.9695로 하이퍼파라미터에 따라 3.3%p나 차이가 나서, 튜닝이 의미 있다는 것도 알 수 있습니다. 찾은 값(`learning_rate`가 약 0.05, `max_iter`가 253)은 9.4.2절에서 본 "학습률은 작게, 트리는 충분히"와 일치합니다. `random_state`를 주면 어떤 조합이 뽑히는지도 재현할 수 있습니다.

실무에서는 보통 다음 순서로 합니다. 먼저 `RandomizedSearchCV`로 넓은 범위를 대충 훑어 좋은 영역을 찾고, 그 주변을 좁혀 `GridSearchCV`나 두 번째 무작위 탐색으로 다듬습니다.

### 10.4.4 튜닝할 때 알아 둘 점

**1) `best_score_`도 완전히 정직하지는 않습니다.** 여러 후보 중 가장 높은 값을 골랐기 때문에, 그 값은 10.4.1절의 선택 편향을 약하게나마 포함합니다. 튜닝 과정까지 포함한 정직한 성능을 추정하고 싶다면 **중첩 교차 검증(nested cross-validation)** 을 씁니다. 바깥 교차 검증이 데이터를 나누고, 각 바깥 폴드의 훈련 부분 안에서 `GridSearchCV`가 안쪽 교차 검증으로 하이퍼파라미터를 고릅니다. 바깥 폴드의 테스트 부분은 튜닝에 전혀 쓰이지 않습니다. `GridSearchCV` 객체를 `cross_val_score`에 그대로 넣으면 됩니다.

```python
from sklearn.model_selection import cross_val_score

inner = GridSearchCV(RandomForestClassifier(n_estimators=100, random_state=0),
                     {"max_depth": [3, 5, None], "min_samples_leaf": [1, 3, 5]},
                     cv=StratifiedKFold(3, shuffle=True, random_state=1))
outer = cross_val_score(inner, cancer.data, cancer.target,
                        cv=StratifiedKFold(5, shuffle=True, random_state=2))
print("바깥 5겹 점수:", outer.round(3))
print(f"튜닝 과정까지 포함한 성능 추정: {outer.mean():.3f}")
```

```text
바깥 5겹 점수: [0.947 0.956 0.912 0.982 0.973]
튜닝 과정까지 포함한 성능 추정: 0.954
```

바깥 5개 폴드 각각에서 안쪽 `GridSearchCV`가 처음부터 다시 하이퍼파라미터를 골랐습니다(총 5 x (9 x 3 + 1) = 140번 학습). 폴드별 점수가 0.912~0.982로 꽤 흔들린다는 것도 보입니다. 연산량이 크므로 모델을 비교하는 단계가 아니라 "최종 파이프라인의 성능을 보고할 때"에 주로 씁니다.

**2) 탐색 범위가 끝값에 걸리면 범위를 넓히세요.** `best_params_`가 격자의 가장자리 값이면(예: `C`의 후보가 `[0.001, ..., 100]`인데 100이 뽑힘) 더 좋은 값이 범위 밖에 있을 수 있습니다. 위 `C` 탐색에서 최적값 1이 가운데에 있는 것은 범위가 적절했다는 신호입니다.

**3) 값의 종류에 맞는 척도를 쓰세요.** `C`, `alpha`, `learning_rate`는 로그 간격, `max_depth`, `n_estimators`는 정수 간격이 자연스럽습니다.

**4) 시간 예산을 계산하고 시작하세요.** 후보 수 x 폴드 수 x 한 번 학습하는 시간이 총 비용입니다. 큰 모델이나 큰 데이터에서는 `n_jobs`로 병렬화하고, 작은 `n_iter`의 무작위 탐색부터 시작하세요. scikit-learn에는 후보를 줄여가며 경쟁시키는 `HalvingGridSearchCV`, `HalvingRandomSearchCV`도 있습니다(`sklearn.experimental.enable_halving_search_cv`를 먼저 import해야 쓸 수 있는 실험적 기능입니다). 이 책에서는 이름만 소개합니다.

**5) 파이프라인 전체를 탐색하세요.** 전처리 단계의 설정(예: 결측치 대체 방식)도 같은 방식으로 `단계이름__파라미터이름`으로 함께 탐색할 수 있습니다. 파이프라인을 `GridSearchCV`에 넣는 더 자세한 방법은 17.3절에서 다룹니다.

## 10.5 모델 선택 워크플로

지금까지의 내용을 하나의 순서로 정리해 봅시다. 5.6.4절에서 4단계로 소개한 흐름을, 모델 비교와 기준선까지 포함해 확장한 것입니다.

1. **테스트 세트를 먼저 떼어 두고 잊어버립니다.** 가장 먼저, 다른 어떤 작업보다 먼저입니다. 이후의 모든 탐색은 나머지(훈련 세트)에서만 합니다.
2. **기준선(baseline)을 만듭니다.** 아무것도 배우지 않고 가장 흔한 클래스만 찍는 `DummyClassifier`의 점수를 구합니다. 내 모델이 이 점수를 넘지 못한다면 아직 아무것도 배우지 못한 것입니다.
3. **전처리와 모델을 `Pipeline`으로 묶습니다.** 전처리가 폴드마다 훈련 부분에서만 학습되어 누수를 막습니다.
4. **후보 모델을 몇 가지 정합니다.** 단순한 모델(선형 모델)부터 시작해 복잡한 모델(앙상블)로 갑니다. 복잡한 모델이 항상 이기는 것은 아닙니다.
5. **후보마다 훈련 세트 안에서 교차 검증으로 하이퍼파라미터를 튜닝합니다.** `GridSearchCV`(후보가 적을 때) 또는 `RandomizedSearchCV`(후보가 많을 때).
6. **교차 검증 점수(와 표준편차)로 후보를 비교해 하나를 고릅니다.** 점수가 비슷하면 더 단순하고 빠른 모델을 고릅니다.
7. **고른 모델의 `best_estimator_`로 테스트 세트를 딱 한 번 평가합니다.** 이 점수가 최종 성능 보고서입니다. 이 점수가 마음에 들지 않는다고 다시 모델을 고르러 돌아가면, 테스트 세트는 또 다시 훈련 과정의 일부가 되어 버립니다.
8. **서비스에 쓸 모델은 설정을 고정한 채 전체 데이터로 다시 학습할 수 있습니다.** 데이터가 많을수록 보통 더 좋기 때문입니다. 이 경우 성능은 7단계에서 구한 값으로 보고합니다. 저장과 배포는 17장에서 다룹니다.

앞에서 학습한 세 탐색 결과(`grid_lr`, `grid_rf`, `rand_hgb`)로 이 순서를 마무리해 봅시다.

```python
from sklearn.dummy import DummyClassifier

# 1) 기준선: 아무것도 배우지 않고 가장 흔한 클래스만 찍는 모델
baseline = cross_val_score(DummyClassifier(strategy="most_frequent"), Xc_tr, yc_tr, cv=cv)
print(f"기준선(Dummy)            CV {baseline.mean():.4f}")

# 2) 후보들은 모두 훈련 세트 안에서 교차 검증으로 비교한다 (이미 위에서 학습함)
candidates = {
    "로지스틱 회귀 (GridSearch)": grid_lr,
    "랜덤 포레스트 (GridSearch)": grid_rf,
    "HistGB (RandomizedSearch)": rand_hgb,
}
for name, search in candidates.items():
    print(f"{name:<26} CV {search.best_score_:.4f}")

# 3) 교차 검증 점수가 가장 높은 후보를 고른다 (테스트 세트는 아직 보지 않았다)
best_name = max(candidates, key=lambda k: candidates[k].best_score_)
final_model = candidates[best_name].best_estimator_      # refit=True 덕분에 전체 훈련 세트로 재학습된 모델
print("\n선택된 모델:", best_name)

# 4) 테스트 세트는 마지막에 딱 한 번
print(f"최종 테스트 정확도: {final_model.score(Xc_te, yc_te):.4f}")
```

```text
기준선(Dummy)            CV 0.6268
로지스틱 회귀 (GridSearch)       CV 0.9789
랜덤 포레스트 (GridSearch)       CV 0.9625
HistGB (RandomizedSearch)  CV 0.9695

선택된 모델: 로지스틱 회귀 (GridSearch)
최종 테스트 정확도: 0.9860
```

- 기준선은 0.6268입니다. 양성 종양이 약 63%라서 "무조건 양성 종양"이라고만 해도 그만큼 맞습니다. 세 후보 모두 이 기준선을 크게 넘었습니다.
- 교차 검증 점수는 로지스틱 회귀(0.9789)가 가장 높고, 부스팅(0.9695), 랜덤 포레스트(0.9625)가 뒤를 잇습니다. **가장 단순한 선형 모델이 가장 복잡한 모델을 이겼습니다.** 이 데이터는 스케일링만 하면 선형으로 잘 구분되기 때문입니다. 모델의 복잡도와 성능은 비례하지 않으므로, 단순한 후보를 처음부터 후보에 넣어야 합니다.
- 선택된 로지스틱 회귀의 테스트 정확도는 0.9860(143개 중 141개)입니다. 교차 검증 점수(0.9789)와 비슷해서 선택 과정에서 크게 부풀려지지 않았다는 점을 확인할 수 있습니다. 테스트 표본이 143개뿐이라 한두 개의 차이로 점수가 크게 변한다는 점은 염두에 두세요.

다음은 모델 선택 과정에서 자주 저지르는 실수를 정리한 표입니다.

| 실수 | 왜 문제인가 | 올바른 방법 |
| --- | --- | --- |
| 튜닝 결과가 마음에 안 들어 테스트 점수를 보고 다시 고름 | 테스트 세트가 선택 과정의 일부가 되어 점수가 부풀려짐 (10.4.1) | 테스트는 한 번만. 개선은 훈련 세트의 교차 검증에서 |
| 전체 데이터로 스케일링한 뒤 분할 | 전처리 누수 (5.3) | `Pipeline`으로 묶어 폴드마다 학습 |
| 최고 점수만 보고 우열 판단 | 폴드 간 변동이 큼 | `std_test_score`와 함께 보고, 비슷하면 단순한 쪽 |
| 탐색 범위의 끝값이 최적으로 나옴 | 더 좋은 값이 범위 밖에 있을 수 있음 | 범위를 넓혀 다시 탐색 |
| 정규화 전에 스케일링을 안 함 | 단위에 따라 벌점이 달라짐 (10.1.2) | `StandardScaler`와 함께 사용 |
| 기준선 없이 점수만 봄 | 0.9가 좋은 점수인지 알 수 없음 | `DummyClassifier`와 비교 |

## 요약

- **정규화**는 "훈련 오차 + 계수 벌점"을 최소화해 과대적합을 억제합니다. 특성이 많고 표본이 적을 때 정규화가 없는 선형 회귀는 훈련 R2가 1.000이어도 테스트 R2가 -3.03으로 무너졌고, 릿지는 0.709를 얻었습니다.
- 벌점은 특성의 단위에 영향을 받으므로 **정규화 전에 스케일링**해야 합니다.
- **릿지(L2)** 는 계수를 모두 작게 만들되 0으로 만들지는 않습니다. $w = (Z^\top Z + \alpha I)^{-1} Z^\top y$로 한 번에 풀립니다. **라쏘(L1)** 는 중요하지 않은 계수를 정확히 0으로 만들어 **특성 선택** 효과를 냅니다. 좌표 하강법과 소프트 임계값으로 풉니다. 둘 다 NumPy로 구현해 scikit-learn과 일치함을 확인했습니다.
- **엘라스틱넷**은 L1과 L2를 섞어, 상관이 높은 특성이 있을 때 라쏘처럼 한쪽만 임의로 고르지 않고 계수를 나눠 갖게 합니다.
- 릿지의 `alpha`와 라쏘의 `alpha`는 목적식의 정의가 달라 같은 값이어도 세기가 다릅니다. 로지스틱 회귀와 SVM의 `C`는 작을수록 정규화가 강합니다. 방향을 항상 확인하세요.
- **파라미터**는 `fit`이 데이터로 구하는 값(`coef_` 등 밑줄로 끝남)이고, **하이퍼파라미터**는 `fit` 전에 사람이 정하는 값(`alpha`, `max_depth` 등)입니다. 하이퍼파라미터는 `fit`이 구해 주지 못하므로 바깥에서 탐색해야 합니다.
- **테스트 세트로 하이퍼파라미터를 고르면 안 됩니다.** 후보 300개 중 테스트 점수로 고른 모델이 0.620을 기록했지만 새 데이터에서는 0.502(동전 던지기)였습니다. 선택 편향이 점수를 부풀립니다.
- `GridSearchCV`는 모든 조합을 교차 검증으로 평가해 `best_params_`, `best_score_`(교차 검증 점수, 테스트 점수가 아님), `best_estimator_`(전체 훈련 세트로 재학습됨), `cv_results_`를 줍니다. 비용은 후보 수 x 폴드 수로 늘어납니다.
- `RandomizedSearchCV`는 분포에서 `n_iter`개만 뽑아 평가해 예산을 직접 정할 수 있고, 하이퍼파라미터가 많을 때 유리합니다. 크기가 자릿수로 달라지는 값은 `loguniform`을 씁니다. `RidgeCV`, `LassoCV`처럼 교차 검증을 내장한 모델도 있습니다.
- **모델 선택 워크플로**: 테스트 세트 분리 -> 기준선 -> 파이프라인 -> 후보 모델 -> 훈련 세트에서 교차 검증으로 튜닝 -> 교차 검증 점수로 선택 -> 테스트 세트 딱 한 번 -> (필요하면) 전체 데이터로 재학습. 단순한 모델이 복잡한 모델을 이길 수도 있습니다.

## 연습문제

1. **alpha의 효과.** 10.1절의 회귀 데이터(`make_regression`, `random_state=0`)에서 `Ridge`의 `alpha`를 `np.logspace(-2, 4, 13)`으로 바꿔 가며 표준화된 훈련 데이터로 학습하고, 각 `alpha`에서 훈련 R2, 테스트 R2, `np.abs(coef_).sum()`을 출력하세요. 훈련 R2가 항상 감소하는데 테스트 R2는 왜 어느 지점까지 오르다가 내려가는지 두세 문장으로 설명하세요.

2. **라쏘로 특성 선택.** 유방암 데이터(30개 특성)를 표준화한 뒤 `Lasso`(회귀로 쓰고 라벨 0/1을 그대로 정답으로 사용)를 `alpha=0.01, 0.03, 0.1`로 학습하고, 각 경우 0이 아닌 계수가 몇 개이고 어떤 특성이 마지막까지 남는지 출력하세요. 남은 특성들이 9장의 랜덤 포레스트 특성 중요도 상위 특성(`worst perimeter`, `worst concave points` 등)과 겹치는지 확인하세요. 단, 라벨이 0/1인 분류 문제에 `Lasso`를 쓰는 것이 왜 "특성 선택 용도로만" 적절한지 생각해 보세요.

3. **라쏘를 NumPy로 확장.** 10.2.2절의 `lasso_fit`에서 `n_iter`를 1, 2, 5, 20, 100으로 바꿔 가며 sklearn(`tol=1e-10`) 결과와의 계수 최대 차이를 출력하세요. 좌표 하강법이 몇 번째 반복부터 사실상 수렴하는지 확인하고, `alpha`를 0.3으로 줄이면 수렴이 더 느려지는지 비교해 보세요.

4. **GridSearchCV 읽기.** 유방암 데이터에서 `Pipeline([StandardScaler, KNeighborsClassifier])`을 만들고 `n_neighbors`를 `[1, 3, 5, 7, 9, 15, 25]`, `weights`를 `["uniform", "distance"]`로 `GridSearchCV`(5겹, `StratifiedKFold`)로 탐색하세요(`param_grid` 키는 `"단계이름__n_neighbors"` 형태입니다). `best_params_`, `best_score_`를 출력하고, `cv_results_`에서 상위 5개 조합과 표준편차를 확인해 "1위가 확실히 나은가?"에 대해 답하세요. 마지막으로 테스트 세트에서 점수를 한 번만 구하세요.

5. **선택 편향 재현.** 10.4.1절의 실험에서 "테스트" 세트의 크기를 100에서 1000으로 바꾸고(`Xn[100:1100]`, 새 데이터는 그 뒤), 후보 모델 수를 30, 300, 3000으로 바꿔 보세요. 후보 수와 테스트 세트 크기가 각각 "테스트 점수로 고른 최고 점수"의 부풀려짐 정도에 어떤 영향을 주는지 표로 정리하고, 왜 그런 경향이 나타나는지 설명하세요.
