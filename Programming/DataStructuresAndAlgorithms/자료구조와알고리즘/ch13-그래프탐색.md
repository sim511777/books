12장에서 정점과 간선으로 이루어진 그래프를 인접 리스트로 표현하는 방법을 배웠습니다. 하지만 그래프를 표현할 수 있다는 것과, 그 그래프 안에서 "A에서 B까지 갈 수 있는가", "모든 정점을 빠짐없이 방문하려면 어떻게 해야 하는가" 같은 질문에 답하는 것은 별개의 문제입니다. 이런 질문에 답하려면 그래프를 체계적으로 **탐색(traversal)**하는 방법이 필요합니다. 이 장에서는 그래프 탐색의 양대 산맥인 너비 우선 탐색(BFS)과 깊이 우선 탐색(DFS)을 직접 구현하면서, 6장의 큐와 5장의 스택이 여기서 어떻게 재활용되는지 확인합니다.

## 13.1 탐색을 위한 준비: 인접 리스트와 방문 표시

12장에서 만든 그래프를 다음과 같은 형태라고 가정하겠습니다. 정점은 정수 ID로 표현하고, 각 정점이 어떤 정점들과 연결되어 있는지를 `Dictionary<int, List<int>>`로 관리합니다.

```csharp
public class Graph
{
    private readonly Dictionary<int, List<int>> _adjacency = new();

    public void AddVertex(int vertex)
    {
        if (!_adjacency.ContainsKey(vertex))
        {
            _adjacency[vertex] = new List<int>();
        }
    }

    // 방향 없는 그래프: 양쪽에 서로를 추가
    public void AddEdge(int from, int to)
    {
        AddVertex(from);
        AddVertex(to);
        _adjacency[from].Add(to);
        _adjacency[to].Add(from);
    }

    public IReadOnlyList<int> GetNeighbors(int vertex) => _adjacency[vertex];

    public IEnumerable<int> Vertices => _adjacency.Keys;
}
```

그래프 탐색에서 가장 먼저 마주치는 문제는 **같은 정점을 두 번 방문하지 않도록 막는 것**입니다. 트리(7장)와 달리 그래프에는 사이클이 있을 수 있어서, 방문 여부를 기록해 두지 않으면 A → B → A → B ... 처럼 무한히 순환하게 됩니다. 이때 11장에서 다룬 해시셋(`HashSet<int>`)이 정확히 필요한 도구입니다. "이 정점을 이미 방문했는가?"라는 질문에 O(1)로 답할 수 있어야 하기 때문입니다.

```csharp
var visited = new HashSet<int>();

if (!visited.Contains(vertex))
{
    visited.Add(vertex);
    // 방문 처리
}
```

정점이 0부터 N-1까지의 정수로 촘촘하게 붙어 있다는 것을 미리 안다면 `bool[]` 배열로도 같은 역할을 할 수 있고, 그 편이 더 빠릅니다. 하지만 정점 ID가 문자열이거나 듬성듬성한 정수라면 해시셋이 더 유연합니다. 이 장의 예제에서는 범용성을 위해 `HashSet<int>`를 사용합니다.

## 13.2 너비 우선 탐색(BFS): 큐로 가까운 정점부터

너비 우선 탐색은 출발 정점에서 가까운 정점부터 순서대로 방문합니다. "가깝다"는 것은 거쳐야 하는 간선의 수가 적다는 뜻입니다. 즉 출발점의 바로 이웃(거리 1)을 모두 방문한 다음, 그 이웃의 이웃(거리 2)을 방문하고, 이런 식으로 물결이 퍼지듯 바깥으로 확장해 나갑니다.

이 "먼저 발견한 것을 먼저 처리한다"는 순서는 정확히 6장에서 다룬 큐(FIFO)의 동작 방식과 일치합니다. 그래서 BFS는 큐를 이용해 다음과 같이 구현합니다.

1. 출발 정점을 큐에 넣고 방문 표시한다.
2. 큐가 빌 때까지: 큐에서 정점 하나를 꺼내(Dequeue) 처리하고, 그 정점의 이웃 중 아직 방문하지 않은 정점을 모두 큐에 넣으면서(Enqueue) 방문 표시한다.

```csharp
public List<int> Bfs(Graph graph, int start)
{
    var visited = new HashSet<int>();
    var order = new List<int>();       // 방문 순서 기록
    var queue = new Queue<int>();

    queue.Enqueue(start);
    visited.Add(start);

    while (queue.Count > 0)
    {
        int current = queue.Dequeue();
        order.Add(current);

        foreach (int neighbor in graph.GetNeighbors(current))
        {
            if (!visited.Contains(neighbor))
            {
                visited.Add(neighbor);   // 큐에 넣는 시점에 바로 방문 표시
                queue.Enqueue(neighbor);
            }
        }
    }

    return order;
}
```

한 가지 중요한 구현 세부사항이 있습니다. 방문 표시를 큐에서 **꺼낼 때**가 아니라 **넣을 때** 하고 있다는 점입니다. 만약 꺼낼 때 표시한다면, 같은 정점이 여러 이웃으로부터 중복으로 큐에 들어갈 수 있어서 불필요한 중복 처리가 생깁니다. 넣는 시점에 바로 방문 표시를 하면 각 정점이 큐에 정확히 한 번만 들어가는 것이 보장되고, 전체 시간 복잡도가 O(V + E)로 유지됩니다(V는 정점 수, E는 간선 수).

BFS의 대표적인 활용은 **가중치가 없는 그래프에서의 최단 경로**입니다. 모든 간선의 "비용"이 동일하다면, BFS가 어떤 정점을 처음 방문하는 순간의 경로가 곧 최단 경로입니다. 물결이 가까운 곳부터 균등하게 퍼져나가기 때문입니다. 최단 경로 자체를 복원하려면 각 정점을 방문할 때 "누구를 거쳐 왔는지"를 함께 기록하면 됩니다.

```csharp
public List<int> BfsShortestPath(Graph graph, int start, int target)
{
    var visited = new HashSet<int> { start };
    var parent = new Dictionary<int, int>();
    var queue = new Queue<int>();
    queue.Enqueue(start);

    while (queue.Count > 0)
    {
        int current = queue.Dequeue();
        if (current == target) break;

        foreach (int neighbor in graph.GetNeighbors(current))
        {
            if (!visited.Contains(neighbor))
            {
                visited.Add(neighbor);
                parent[neighbor] = current;
                queue.Enqueue(neighbor);
            }
        }
    }

    // target부터 parent를 거슬러 올라가 경로 복원
    if (!visited.Contains(target)) return new List<int>(); // 도달 불가

    var path = new List<int> { target };
    int node = target;
    while (node != start)
    {
        node = parent[node];
        path.Add(node);
    }
    path.Reverse();
    return path;
}
```

아래 그림은 BFS가 큐를 이용해 출발 정점에서 가까운 정점부터 물결처럼 퍼져나가며 방문하는 과정을 보여줍니다.

```text
BFS 탐색 순서: 큐를 이용해 가까운 정점부터 방문

     거리 0        거리 1        거리 2        거리 3

                  B(2) -------- D(4)
                 /    \
       A(1)             E(5) -------- G(7)
                 \    /
                  C(3) -------- F(6)

간선: A-B, A-C, B-D, B-E, C-E, C-F, E-G
(괄호 안 숫자는 BFS 방문 순번)

큐(Queue)의 변화: 앞에서 꺼내고(Dequeue) 뒤에 이웃을 넣는다(Enqueue)
  [A]        : A 꺼냄 -> 이웃 B, C 넣음
  [B, C]     : B 꺼냄 -> 이웃 D, E 넣음
  [C, D, E]  : C 꺼냄 -> 이웃 F 넣음
  (이후 D, E, F, G를 차례로 꺼내며, 이미 방문/큐에 있는 이웃은 다시 넣지 않는다)

방문 순서: A -> B -> C -> D -> E -> F -> G
```

## 13.3 깊이 우선 탐색(DFS): 스택 또는 재귀로 끝까지 파고들기

깊이 우선 탐색은 BFS와 정반대의 전략을 씁니다. 이웃들을 골고루 방문하는 대신, 한 방향을 정해 갈 수 있는 데까지 끝까지 파고들다가 더 갈 곳이 없으면 되돌아와서(백트래킹) 다른 방향을 시도합니다. 이 "마지막에 간 곳부터 되돌아간다"는 동작은 5장에서 다룬 스택(LIFO)과 정확히 맞아떨어집니다.

DFS는 두 가지 방식으로 구현할 수 있습니다. 하나는 명시적인 스택을 직접 사용하는 반복문 방식이고, 다른 하나는 함수 호출 스택을 이용하는 재귀 방식입니다. 사실 재귀 함수는 호출될 때마다 시스템이 관리하는 콜 스택에 쌓이므로, 재귀 DFS도 내부적으로는 스택을 쓰고 있는 셈입니다.

**재귀 방식**은 코드가 가장 짧고 직관적입니다.

```csharp
public List<int> DfsRecursive(Graph graph, int start)
{
    var visited = new HashSet<int>();
    var order = new List<int>();
    DfsVisit(graph, start, visited, order);
    return order;
}

private void DfsVisit(Graph graph, int current, HashSet<int> visited, List<int> order)
{
    visited.Add(current);
    order.Add(current);

    foreach (int neighbor in graph.GetNeighbors(current))
    {
        if (!visited.Contains(neighbor))
        {
            DfsVisit(graph, neighbor, visited, order); // 재귀 호출 = 콜 스택에 쌓임
        }
    }
}
```

**반복 방식**은 `Stack<int>`을 직접 다룹니다. 이 방식은 그래프가 매우 커서 재귀 깊이가 콜 스택의 한계를 넘을 위험이 있을 때 유용합니다.

```csharp
public List<int> DfsIterative(Graph graph, int start)
{
    var visited = new HashSet<int>();
    var order = new List<int>();
    var stack = new Stack<int>();

    stack.Push(start);

    while (stack.Count > 0)
    {
        int current = stack.Pop();

        if (visited.Contains(current)) continue; // 중복으로 쌓였던 정점은 건너뜀
        visited.Add(current);
        order.Add(current);

        foreach (int neighbor in graph.GetNeighbors(current))
        {
            if (!visited.Contains(neighbor))
            {
                stack.Push(neighbor);
            }
        }
    }

    return order;
}
```

반복 방식에서는 BFS와 달리 스택에 넣는 시점이 아니라 **꺼낼 때** 방문 처리를 합니다. 그 이유는 스택은 나중에 넣은 것이 먼저 나오기 때문에, 넣는 시점에 방문 표시를 해버리면 아직 실제로 처리하지 않은 정점인데도 이후에 다른 경로로 다시 발견됐을 때 무시되어 버릴 수 있기 때문입니다. 그래서 같은 정점이 스택에 중복으로 들어갈 수 있다는 것을 허용하고, 대신 꺼낼 때 이미 방문했는지 한 번 더 확인합니다. 이 때문에 반복 DFS의 이웃 순회 순서는 재귀 DFS와 정확히 일치하지 않을 수 있지만(스택의 후입선출 특성상 이웃을 넣은 역순으로 방문하게 됨), 두 방식 모두 "한 방향으로 끝까지 파고든다"는 본질은 동일합니다.

DFS의 대표적인 활용은 **사이클 탐지**와 **전체 순회(연결 요소 확인, 위상 정렬의 기반)**입니다. 그래프를 방문하다가 이미 방문한 정점(단, 바로 직전에 온 부모 정점은 제외)을 다시 만난다면 사이클이 존재한다는 뜻입니다.

```csharp
public bool HasCycle(Graph graph, int start)
{
    var visited = new HashSet<int>();
    return DfsDetectCycle(graph, start, parent: -1, visited);
}

private bool DfsDetectCycle(Graph graph, int current, int parent, HashSet<int> visited)
{
    visited.Add(current);

    foreach (int neighbor in graph.GetNeighbors(current))
    {
        if (!visited.Contains(neighbor))
        {
            if (DfsDetectCycle(graph, neighbor, current, visited))
                return true;
        }
        else if (neighbor != parent)
        {
            // 방문한 적 있는데 그게 부모가 아니라면 사이클 발견
            return true;
        }
    }
    return false;
}
```

## 13.4 BFS와 DFS, 언제 무엇을 쓸까

두 탐색 모두 시간 복잡도는 O(V + E)로 동일합니다. 모든 정점과 모든 간선을 정확히 한 번씩 확인하기 때문입니다. 차이는 **탐색 순서**와 그로 인한 **적합한 문제**에 있습니다.

| 상황 | 적합한 탐색 | 이유 |
|---|---|---|
| 가중치 없는 그래프의 최단 경로 | BFS | 가까운 정점부터 균등하게 퍼져나가므로 처음 도달한 경로가 최단 경로 |
| 두 정점의 최단 거리(간선 수) | BFS | 위와 동일한 원리 |
| 그래프 전체를 빠짐없이 순회 | DFS 또는 BFS | 둘 다 가능하지만 DFS가 재귀로 구현하기 간결 |
| 사이클 탐지 | DFS | 부모-자식 관계를 스택(콜 스택)에 자연스럽게 유지 |
| 위상 정렬(17장 이후 응용) | DFS | 완료 순서를 스택에 쌓는 방식과 잘 맞음 |
| 미로에서 아무 경로나 하나 찾기 | DFS | 끝까지 파고들다 막히면 되돌아오는 방식이 자연스러움 |

메모리 사용 측면에서도 차이가 있습니다. BFS는 한 "층"에 속한 정점들을 모두 큐에 담아두어야 하므로, 그래프가 넓고 얕은 형태(허브처럼 한 정점에 연결이 많은 경우)라면 큐가 커집니다. DFS는 현재 경로 상의 정점만 스택(또는 콜 스택)에 쌓이므로, 그래프가 좁고 깊은 형태라면 상대적으로 메모리를 덜 씁니다.

## .NET BCL에서 찾아보기

여기서 분명히 짚고 넘어가야 할 점이 있습니다. **BCL에는 그래프 자체를 표현하는 클래스도, BFS/DFS 같은 그래프 탐색 알고리즘도 직접 내장되어 있지 않습니다.** `List<T>`(3장), `Queue<T>`(6장), `Stack<T>`(5장), `HashSet<T>`(11장), `Dictionary<TKey, TValue>`(11장)처럼 그래프를 표현하고 탐색하는 데 필요한 "부품"들은 BCL에 잘 갖춰져 있지만, 그 부품을 조립해서 그래프 탐색 로직을 완성하는 것은 온전히 개발자의 몫입니다.

이는 그래프가 트리나 리스트보다 형태가 훨씬 다양하기 때문입니다. 방향 그래프인지 무방향 그래프인지, 가중치가 있는지, 정점을 정수로 표현할지 객체로 표현할지에 따라 최적의 자료구조와 탐색 방식이 달라지므로, 범용 라이브러리 하나로 모든 경우를 만족시키기 어렵습니다. 실무에서 복잡한 그래프 알고리즘이 필요하다면 이 장에서 배운 원리를 바탕으로 문제에 맞게 직접 구현하거나, 그래프 알고리즘에 특화된 서드파티 라이브러리(예: QuikGraph)를 검토하게 됩니다. 이 책에서는 BCL에 포함된 표준 컴포넌트만을 기준으로 설명하므로, 그런 서드파티 라이브러리의 구체적인 API는 다루지 않습니다.

## 요약

- 그래프 탐색은 모든 정점을 체계적으로 방문하기 위한 절차이며, 사이클이 존재할 수 있으므로 방문 여부를 `HashSet<int>`나 `bool[]`로 반드시 기록해야 한다.
- BFS는 `Queue<int>`를 이용해 출발 정점에서 가까운 정점부터 순서대로 방문하며, 가중치 없는 그래프의 최단 경로를 구하는 데 적합하다. 큐에 넣는 시점에 방문 표시를 해야 중복 처리를 막을 수 있다.
- DFS는 재귀(콜 스택) 또는 명시적 `Stack<int>`를 이용해 한 방향으로 끝까지 파고들며, 사이클 탐지나 전체 순회에 적합하다.
- 두 탐색 모두 시간 복잡도는 O(V + E)로 동일하며, 선택 기준은 문제의 성격(최단 경로 vs 전체 탐색/사이클 탐지)과 메모리 사용 패턴에 있다.
- BCL은 큐, 스택, 해시셋 같은 부품은 제공하지만 그래프 자료구조나 탐색 알고리즘 자체는 제공하지 않으므로, 문제에 맞게 직접 구현해야 한다.

## 연습문제

1. `Bfs` 함수에서 방문 표시를 `Dequeue` 시점으로 옮기면 어떤 문제가 발생하는지, 구체적인 그래프 예시를 들어 설명해 보세요.
2. `DfsRecursive`와 `DfsIterative`를 같은 그래프에 대해 실행했을 때 방문 순서가 다를 수 있는 이유를 스택의 후입선출 특성과 연결 지어 설명해 보세요.
3. `BfsShortestPath`를 응용하여, 시작 정점에서 그래프 내 모든 정점까지의 최단 거리(간선 수)를 담은 `Dictionary<int, int>`를 반환하는 함수를 작성해 보세요.
4. 방향 그래프(간선이 한쪽 방향으로만 존재)에서는 `HasCycle`의 사이클 판정 로직(부모 정점 제외)이 그대로 성립하지 않습니다. 왜 그런지, 그리고 방향 그래프에서는 사이클을 어떻게 탐지해야 할지 생각해 보세요.
5. 연결되어 있지 않은 그래프(하나의 BFS/DFS로 모든 정점을 방문할 수 없는 그래프)에서 전체 연결 요소(connected component)의 개수를 세는 함수를 작성해 보세요. (힌트: 아직 방문하지 않은 정점이 남아 있다면 그 정점에서 새로운 탐색을 다시 시작합니다.)
