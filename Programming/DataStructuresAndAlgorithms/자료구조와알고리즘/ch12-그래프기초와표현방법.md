# 12장. 그래프 기초와 표현 방법

## 시작하며

7장에서 다룬 트리는 부모-자식 관계로 계층을 이루는 특별한 형태의 구조였습니다. 그런데 현실의 관계는 트리처럼 깔끔한 계층으로만 이루어지지 않습니다. 친구 관계, 도시 간 도로망, 웹 페이지 사이의 링크, 항공 노선도 등은 어떤 노드에서든 다른 여러 노드로 자유롭게 연결될 수 있고, 서로 순환하는 관계도 흔합니다. 이런 자유로운 연결 관계를 표현하는 자료구조가 바로 **그래프(graph)**입니다. 사실 트리는 그래프의 특수한 경우(순환이 없고 계층이 명확한 그래프)라고 볼 수 있습니다.

이번 장에서는 그래프의 기본 용어를 정리하고, 그래프를 코드로 표현하는 두 가지 대표적인 방법인 **인접 행렬**과 **인접 리스트**를 직접 구현해봅니다. 그래프를 실제로 탐색하는 알고리즘(너비 우선 탐색, 깊이 우선 탐색)은 13장에서 이어서 다룹니다.

## 그래프 용어 정리

그래프는 **정점(vertex, node)**의 집합과 정점들을 잇는 **간선(edge)**의 집합으로 이루어집니다. 예를 들어 도시들을 정점으로, 도시 사이의 도로를 간선으로 생각하면 도로망 전체가 하나의 그래프가 됩니다.

- **방향 그래프(directed graph)**: 간선에 방향이 있는 그래프입니다. "A에서 B로 갈 수 있다"고 해서 "B에서 A로 갈 수 있다"는 보장이 없습니다. 트위터의 팔로우 관계, 웹 페이지 링크가 대표적인 예입니다.
- **무방향 그래프(undirected graph)**: 간선에 방향이 없는 그래프입니다. A와 B가 연결되어 있으면 양쪽 방향 모두 이동할 수 있습니다. 페이스북의 친구 관계, 도로가 양방향인 지도가 예입니다.
- **가중치 그래프(weighted graph)**: 각 간선에 비용이나 거리 같은 숫자(가중치, weight)가 붙은 그래프입니다. 예를 들어 도시 간 도로망에서 간선의 가중치는 두 도시 사이의 거리가 될 수 있습니다. 가중치가 없는 그래프는 모든 간선의 비용이 동일(보통 1)하다고 가정합니다.
- **인접(adjacent)**: 두 정점이 간선으로 직접 연결되어 있으면 서로 인접하다고 말합니다.
- **차수(degree)**: 한 정점에 연결된 간선의 개수입니다. 방향 그래프에서는 나가는 간선의 수(진출 차수, out-degree)와 들어오는 간선의 수(진입 차수, in-degree)를 구분합니다.

## 그래프를 코드로 표현하는 두 가지 방법

그래프를 표현하려면 "어떤 정점들이 있는가"와 "어떤 정점들이 서로 연결되어 있는가"를 모두 저장해야 합니다. 정점에는 보통 0부터 시작하는 정수 번호를 붙여 관리합니다. 정점 사이의 연결 관계를 저장하는 방식에 따라 크게 두 가지로 나뉩니다.

### 방법 1: 인접 행렬 (Adjacency Matrix)

**인접 행렬**은 3장에서 배운 2차원 배열을 이용해, `matrix[i][j]`가 정점 i에서 정점 j로 가는 간선이 있는지(또는 가중치가 얼마인지)를 저장하는 방식입니다. 정점이 n개면 n×n 크기의 배열이 필요합니다.

```csharp
public class GraphByMatrix
{
    private int[,] _matrix;
    private int _vertexCount;

    public GraphByMatrix(int vertexCount)
    {
        _vertexCount = vertexCount;
        _matrix = new int[vertexCount, vertexCount]; // 0으로 초기화됨 = 간선 없음
    }

    // 방향 그래프에 간선을 추가한다 (가중치가 없으면 1로 표시)
    public void AddDirectedEdge(int from, int to, int weight = 1)
    {
        _matrix[from, to] = weight;
    }

    // 무방향 그래프는 양방향에 모두 표시한다
    public void AddUndirectedEdge(int a, int b, int weight = 1)
    {
        _matrix[a, b] = weight;
        _matrix[b, a] = weight;
    }

    // 두 정점이 연결되어 있는지 O(1)로 확인한다
    public bool HasEdge(int from, int to)
    {
        return _matrix[from, to] != 0;
    }

    // 정점 v와 연결된 모든 정점을 찾는다
    public List<int> GetNeighbors(int v)
    {
        var neighbors = new List<int>();
        for (int j = 0; j < _vertexCount; j++)
        {
            if (_matrix[v, j] != 0)
            {
                neighbors.Add(j);
            }
        }
        return neighbors;
    }
}
```

인접 행렬의 가장 큰 장점은 "정점 i와 정점 j가 연결되어 있는가?"를 `_matrix[i, j]`로 바로 확인할 수 있어 O(1)이라는 점입니다. 하지만 정점이 n개면 무조건 n² 크기의 배열이 필요하므로, 정점 수는 많지만 간선은 적은 **희소 그래프(sparse graph)**에서는 메모리 대부분이 0으로 낭비됩니다. 예를 들어 정점 10,000개에 간선이 20,000개뿐인 그래프라도 인접 행렬은 1억 칸을 차지합니다.

### 방법 2: 인접 리스트 (Adjacency List)

**인접 리스트**는 정점마다 "내가 연결된 정점들의 목록"만 저장하는 방식입니다. 정점 번호를 인덱스로 쓸 수 있다면 배열(또는 `List<T>`)의 배열로, 정점이 문자열 등 임의의 키라면 11장에서 배운 해시 테이블(`Dictionary<TKey, TValue>`)을 활용해 정점을 키로, 이웃 목록을 값으로 저장할 수 있습니다.

```csharp
public class GraphByAdjacencyList
{
    // 정점 번호 -> 그 정점과 연결된 (이웃 정점, 가중치) 목록
    private Dictionary<int, List<(int neighbor, int weight)>> _adjacency;

    public GraphByAdjacencyList()
    {
        _adjacency = new Dictionary<int, List<(int, int)>>();
    }

    // 정점을 그래프에 등록한다
    public void AddVertex(int v)
    {
        if (!_adjacency.ContainsKey(v))
        {
            _adjacency[v] = new List<(int, int)>();
        }
    }

    public void AddDirectedEdge(int from, int to, int weight = 1)
    {
        AddVertex(from);
        AddVertex(to);
        _adjacency[from].Add((to, weight)); // from의 이웃 목록 끝에 추가
    }

    public void AddUndirectedEdge(int a, int b, int weight = 1)
    {
        AddDirectedEdge(a, b, weight);
        AddDirectedEdge(b, a, weight); // 양쪽 모두에 등록
    }

    // 두 정점이 연결되어 있는지 확인하려면 이웃 목록을 순회해야 한다
    public bool HasEdge(int from, int to)
    {
        if (!_adjacency.ContainsKey(from))
        {
            return false;
        }
        foreach (var (neighbor, _) in _adjacency[from])
        {
            if (neighbor == to)
            {
                return true;
            }
        }
        return false;
    }

    // 정점 v와 연결된 이웃 정점 목록을 그대로 반환한다
    public List<(int neighbor, int weight)> GetNeighbors(int v)
    {
        return _adjacency.ContainsKey(v) ? _adjacency[v] : new List<(int, int)>();
    }
}
```

인접 리스트는 실제로 존재하는 간선의 수(m)만큼만 메모리를 사용하므로, 정점은 많지만 간선이 적은 희소 그래프에서 훨씬 효율적입니다. 다만 "정점 i와 정점 j가 연결되어 있는가?"를 확인하려면 `HasEdge`에서 보듯 정점 i의 이웃 목록 전체를 순회해야 하므로, 최악의 경우 O(차수)만큼 시간이 걸립니다. 4장에서 살펴본 것처럼 연결 리스트(또는 `List<T>`) 기반 구조는 임의 접근보다 순차 접근에 가까운 특성을 가지기 때문입니다.

## 두 방식의 트레이드오프 비교

| 항목 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 메모리 사용 | O(n²) — 정점 수의 제곱 | O(n + m) — 정점 수 + 간선 수 |
| 간선 존재 확인 | O(1) | O(차수), 최악의 경우 O(n) |
| 특정 정점의 모든 이웃 조회 | O(n) (행 전체를 순회) | O(차수) (이웃 목록만 순회) |
| 적합한 상황 | 정점 수가 적거나 간선이 촘촘한 밀집 그래프 | 정점 수가 많고 간선이 적은 희소 그래프 (실전에서 압도적으로 많음) |

실전에서 다루는 그래프(소셜 네트워크, 도로망, 웹 그래프 등)는 대부분 정점 수에 비해 간선 수가 훨씬 적은 희소 그래프입니다. 정점이 100만 개인 소셜 네트워크에서 인접 행렬을 쓰면 1조 칸짜리 배열이 필요해 현실적으로 불가능합니다. 그래서 실무에서는 인접 리스트를 기본으로 선택하고, 간선 존재 확인이 매우 잦고 정점 수가 작은 특수한 경우에만 인접 행렬을 고려합니다.

## .NET BCL에서 찾아보기

여기서 짚고 넘어가야 할 중요한 사실이 있습니다. **.NET의 BCL(`System.Collections.Generic` 등)에는 범용 그래프를 표현하는 `Graph<T>` 같은 클래스가 존재하지 않습니다.** `List<T>`, `Dictionary<TKey, TValue>`, `Queue<T>` 같은 컬렉션은 기본 제공되지만, 그래프는 표현 방식(인접 행렬 vs. 인접 리스트)과 용도(방향/무방향, 가중치 유무)가 워낙 다양해서 표준 라이브러리 하나로 일반화하기 어렵기 때문입니다.

대신 이번 장에서처럼 `int[,]`(2차원 배열, 3장 참고)나 `Dictionary<TKey, List<T>>`(11장의 해시 테이블과 4장의 리스트 조합) 같은 기본 컬렉션을 조합해 필요에 맞는 그래프 구조를 직접 만드는 것이 일반적인 방법입니다. 그래프 알고리즘이 특히 중요한 영역(수치 계산, 그래픽스, 최적화 등)에서는 `QuikGraph` 같은 서드파티 라이브러리를 쓰기도 하지만, 이는 BCL의 일부가 아니라는 점을 분명히 알아두어야 합니다.

## 요약

- 그래프는 정점과 간선으로 이루어지며, 방향 유무(방향/무방향)와 가중치 유무에 따라 여러 종류로 나뉩니다.
- 인접 행렬은 n×n 2차원 배열로 간선 존재 여부를 O(1)에 확인할 수 있지만, 정점 수가 많은 희소 그래프에서는 메모리를 크게 낭비합니다.
- 인접 리스트는 정점마다 이웃 목록만 저장해 메모리를 O(n + m)으로 아낄 수 있지만, 특정 두 정점의 연결 여부를 확인하려면 이웃 목록을 순회해야 합니다.
- 실전의 그래프는 대부분 희소 그래프이므로 인접 리스트가 기본 선택지가 되는 경우가 많습니다.
- .NET BCL에는 범용 그래프 클래스가 없으며, 배열과 해시 테이블 같은 기본 컬렉션을 조합해 직접 구현하는 것이 일반적입니다.

## 연습문제

1. 정점 5개(0~4)로 이루어진 무방향 그래프에서 간선이 (0,1), (1,2), (2,3), (3,4), (4,0)로 원 모양을 이룬다고 할 때, 이를 `GraphByMatrix`와 `GraphByAdjacencyList` 두 가지 방식으로 각각 구성하는 코드를 작성해보세요.
2. 위 문제의 그래프에서 각 표현 방식이 사용하는 메모리 양을 어림잡아 비교해보세요. 정점 수가 100, 1000, 10000으로 늘어날 때 인접 행렬과 인접 리스트의 메모리 사용량이 어떻게 달라지는지 설명해보세요.
3. 도시 간 항공 노선을 그래프로 표현한다고 가정합니다. 노선에 방향성이 있는지(왕복 여부), 가중치가 필요한지(운임이나 비행 시간) 판단하고, 어떤 표현 방식이 더 적합할지 근거를 들어 설명해보세요.
4. `GraphByAdjacencyList`에 특정 정점을 그래프에서 완전히 제거하는 `RemoveVertex(int v)` 메서드를 추가해보세요. 이 정점을 가리키는 다른 정점들의 이웃 목록에서도 함께 제거해야 한다는 점에 유의하세요.
5. 인접 행렬에서 `HasEdge`는 O(1)인데 반해 인접 리스트에서는 O(차수)입니다. 반대로 "그래프의 모든 간선을 한 번씩 순회하라"는 연산은 두 방식 중 어느 쪽이 더 효율적인지 분석해보세요.
