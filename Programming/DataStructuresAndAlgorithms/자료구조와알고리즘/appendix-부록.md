본문에서 다룬 자료구조와 알고리즘의 복잡도를 한눈에 비교할 수 있도록 정리하고, 이 책에서 직접 구현한 자료구조들이 .NET 기본 클래스 라이브러리(BCL)의 어떤 클래스에 대응하는지 표로 모았습니다. 마지막으로 이 책을 마친 뒤 학습을 이어갈 때 참고하면 좋을 자료 유형을 안내합니다.

## A.1 자료구조별 시간 복잡도 총정리표

아래 표는 3장부터 11장까지 다룬 자료구조들의 대표 연산에 대한 시간 복잡도를 정리한 것입니다. "탐색"은 정렬 여부와 무관하게 "특정 값이 있는지 확인하는" 임의 검색을 기준으로 하며, 이진 탐색 트리 이상의 구조에서는 그 구조가 유지하는 정렬/조직화 규칙을 활용한 탐색을 의미합니다.

| 자료구조 | 삽입 (평균) | 삽입 (최악) | 삭제 (평균) | 삭제 (최악) | 탐색 (평균) | 탐색 (최악) | 비고 |
|---|---|---|---|---|---|---|---|
| 배열 / 동적 배열 (3장) | O(1) — 맨 뒤 기준, 상각 | O(n) — 재할당 또는 중간 삽입 | O(n) | O(n) | O(n) | O(n) | 인덱스로 임의 접근은 항상 O(1) |
| 연결 리스트 (4장) | O(1) — 위치를 알고 있을 때 | O(1) | O(1) — 위치를 알고 있을 때 | O(1) | O(n) | O(n) | 특정 위치를 "찾는" 데는 O(n)이 들지만, 이미 가리키고 있는 노드 앞뒤 삽입/삭제 자체는 O(1) |
| 스택 (5장) | O(1) — Push | O(1) | O(1) — Pop | O(1) | O(n) | O(n) | 맨 위(top) 외의 원소는 탐색 시 순차 접근 필요 |
| 큐 (6장) | O(1) — Enqueue | O(1) | O(1) — Dequeue | O(1) | O(n) | O(n) | 앞(front)과 뒤(rear)만 O(1)로 접근 가능 |
| 이진 탐색 트리 (8장) | O(log n) | O(n) | O(log n) | O(n) | O(log n) | O(n) | 삽입 순서가 편향되면 사실상 연결 리스트로 퇴화(최악 O(n)) |
| 균형 트리 (9장) | O(log n) | O(log n) | O(log n) | O(log n) | O(log n) | O(log n) | 회전 등으로 균형을 유지해 최악의 경우에도 O(log n) 보장 |
| 힙 (10장) | O(log n) | O(log n) | O(log n) — 루트 삭제 | O(log n) | O(n) — 임의 원소 | O(n) | 최솟값/최댓값 조회(Peek)는 O(1); 임의 원소 탐색은 힙 구조상 O(n) |
| 해시 테이블 (11장) | O(1) | O(n) | O(1) | O(n) | O(1) | O(n) | 최악의 경우는 해시 충돌이 심하게 몰릴 때; 좋은 해시 함수와 적절한 부하율(load factor) 관리로 회피 |

이 표에서 두 가지 패턴을 눈여겨볼 만합니다. 첫째, **"평균"과 "최악"의 차이가 큰 구조**(이진 탐색 트리, 해시 테이블)는 입력 분포나 삽입 순서에 따라 성능이 크게 달라질 수 있으므로, 실무에서는 이 차이를 방지하는 장치(균형 유지, 해시 함수 품질)가 함께 따라옵니다. 둘째, **배열과 연결 리스트는 정확히 대칭적인 트레이드오프**를 보여줍니다. 배열은 임의 접근이 빠른 대신 중간 삽입/삭제가 느리고, 연결 리스트는 그 반대입니다.

## A.2 정렬 알고리즘 복잡도 총정리표

아래 표는 14장과 15장에서 다룬 정렬 알고리즘들을 시간 복잡도, 추가 공간 복잡도, 안정성(stable) 여부 기준으로 정리한 것입니다. **안정 정렬(stable sort)**이란 정렬 기준값이 동일한 두 원소의 상대적인 순서가 정렬 후에도 그대로 유지되는 정렬을 말합니다.

| 정렬 알고리즘 | 최선 | 평균 | 최악 | 공간 복잡도 | 안정 정렬 여부 |
|---|---|---|---|---|---|
| 버블 정렬 | O(n) (조기 종료 최적화 시) | O(n²) | O(n²) | O(1) | 예 |
| 선택 정렬 | O(n²) | O(n²) | O(n²) | O(1) | 아니요 |
| 삽입 정렬 | O(n) (이미 정렬된 경우) | O(n²) | O(n²) | O(1) | 예 |
| 병합 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) | 예 |
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) (피벗 선택이 계속 나쁠 때) | O(log n) (재귀 호출 스택) | 아니요 |

몇 가지 보충하면, 버블 정렬과 삽입 정렬은 "이미 거의 정렬된 데이터"에 대해서는 최선의 경우 O(n)까지 빨라질 수 있다는 공통점이 있습니다. 반면 선택 정렬은 남은 구간에서 최솟값(또는 최댓값)을 찾는 과정을 데이터 상태와 무관하게 항상 전부 수행하므로 최선의 경우조차 O(n²)입니다. 병합 정렬은 입력 상태와 무관하게 항상 O(n log n)을 보장하는 대신 병합 과정에서 원본과 같은 크기의 보조 배열이 필요해 O(n)의 추가 공간을 씁니다. 퀵 정렬은 평균적으로 병합 정렬과 같은 O(n log n)이면서 추가 공간을 훨씬 적게 쓰지만(제자리 분할), 피벗이 계속 최솟값이나 최댓값으로만 뽑히는 최악의 경우에는 O(n²)까지 나빠질 수 있어 피벗 선택 전략(예: 무작위 선택, 세 값의 중앙값)이 중요합니다.

안정성이 왜 중요한지도 짚어볼 만합니다. 예를 들어 학생 명단을 이름순으로 미리 정렬해 둔 뒤 점수순으로 다시 정렬한다고 합시다. 안정 정렬을 쓰면 점수가 같은 학생들은 이름순으로 정렬되어 있던 순서를 그대로 유지합니다. 반면 불안정 정렬(선택 정렬, 퀵 정렬)을 쓰면 점수가 같은 학생들 사이의 순서가 뒤섞일 수 있어, "여러 기준으로 순차 정렬"해야 하는 상황에서는 안정 정렬이 유리합니다.

## A.3 자료구조 → .NET BCL 대응표

이 책에서는 각 자료구조를 밑바닥부터 직접 구현하며 원리를 익혔지만, 실제 C# 프로젝트에서는 대부분 .NET이 이미 제공하는 검증된 구현을 사용합니다. 아래 표는 본문에서 소개한 직접 구현체와 그에 대응하는 BCL 클래스를 정리한 것입니다.

| 이 책에서 다룬 자료구조 | 관련 장 | 대응하는 .NET BCL 클래스 |
|---|---|---|
| 동적 배열 | 3장 | `List<T>` |
| 연결 리스트 | 4장 | `LinkedList<T>` |
| 스택 | 5장 | `Stack<T>` |
| 큐 | 6장 | `Queue<T>` |
| 이진 탐색 트리 / 균형 트리 | 8장, 9장 | `SortedSet<T>`, `SortedDictionary<TKey, TValue>` |
| 힙 / 우선순위 큐 | 10장 | `PriorityQueue<TElement, TPriority>` |
| 해시 테이블 (키-값 저장) | 11장 | `Dictionary<TKey, TValue>` |
| 해시 테이블 (집합, 중복 없는 저장) | 11장 | `HashSet<T>` |
| 그래프 (인접 리스트 표현) | 12장, 13장 | 전용 클래스는 없으며, 보통 `Dictionary<TNode, List<TNode>>`처럼 이미 소개한 자료구조를 조합해서 표현 |
| 정렬 | 14장, 15장 | `Array.Sort`, `List<T>.Sort`, LINQ의 `OrderBy`/`OrderByDescending` |
| 탐색 (정렬된 데이터의 이진 탐색) | 16장 | `Array.BinarySearch`, `List<T>.BinarySearch` |

정리하면서 기억해 둘 점이 있습니다. `SortedSet<T>`와 `SortedDictionary<TKey, TValue>`는 내부적으로 균형 트리(레드-블랙 트리 계열)로 구현되어 있어 9장에서 배운 대로 삽입·삭제·탐색이 모두 O(log n)으로 보장됩니다. 단순히 "정렬된 상태를 유지하는 컬렉션"이 필요할 뿐 트리 구조 자체가 중요하지 않다면, 대부분의 경우 8장에서 직접 만든 이진 탐색 트리보다 이 BCL 클래스들을 사용하는 편이 안전하고 효율적입니다. 마찬가지로 `PriorityQueue<TElement, TPriority>`는 10장에서 만든 힙을 그대로 감싼 것이라 보아도 무방하며, `Dictionary<TKey, TValue>`와 `HashSet<T>`은 11장에서 다룬 해시 테이블의 실제 운영용 구현체입니다.

이 책에서 자료구조를 직접 구현해본 이유는 이런 BCL 클래스들을 대체하기 위해서가 아니라, 그 안에서 실제로 어떤 일이 벌어지는지 이해함으로써 **언제 어떤 클래스를 선택해야 하는지**, 그리고 **성능 문제가 생겼을 때 왜 그런 일이 벌어지는지**를 판단할 수 있는 안목을 기르기 위해서였습니다.

## A.4 앞으로 학습을 이어가려면: 참고할 만한 자료 유형

이 책은 자료구조와 알고리즘의 기초를 다지는 입문서입니다. 여기서 다룬 내용을 실전 감각으로 발전시키고 싶다면 다음과 같은 유형의 자료를 참고하는 것을 권합니다.

- **공식 문서**: `List<T>`, `Dictionary<TKey, TValue>`, `PriorityQueue<TElement, TPriority>` 등 이 책에서 언급한 BCL 클래스들이 내부적으로 어떤 성능 특성을 갖는지, 어떤 메서드를 제공하는지는 .NET 공식 API 문서에서 가장 정확하고 최신 정보를 확인할 수 있습니다. 특히 각 타입 문서의 "Remarks" 항목에는 시간 복잡도와 구현상의 주의사항이 명시되어 있는 경우가 많습니다.
- **온라인 저지 및 문제 풀이 플랫폼**: 정렬, 탐색, 그래프 탐색, 동적 프로그래밍 등 이 책에서 다룬 개념을 실제 문제에 적용해보는 연습은 온라인 저지(judge) 사이트나 코딩 테스트 연습 플랫폼을 통해 할 수 있습니다. 난이도별로 문제가 분류되어 있는 경우가 많으므로, 이 책의 각 장에서 다룬 주제(스택을 활용하는 문제, 그래프 탐색 문제, DP 문제 등)와 매칭해서 풀어보면 개념이 훨씬 단단해집니다.
- **오픈소스 코드 저장소**: 실무에서 자료구조와 알고리즘이 어떻게 응용되는지 보고 싶다면, 잘 알려진 오픈소스 라이브러리나 .NET 런타임 자체의 소스 코드를 살펴보는 것도 좋은 방법입니다. 예를 들어 `List<T>`나 `Dictionary<TKey, TValue>`의 실제 내부 구현이 이 책에서 만든 단순화된 버전과 어떻게 다른지(용량 증가 배수, 해시 충돌 처리 방식 등) 비교해보면 실무 코드의 최적화 기법을 배울 수 있습니다.
- **알고리즘 시각화 도구**: 정렬 과정이나 트리/그래프 순회 과정을 애니메이션으로 보여주는 시각화 도구를 활용하면, 코드만으로는 잘 와닿지 않는 "왜 이 알고리즘이 이렇게 동작하는가"를 직관적으로 이해하는 데 도움이 됩니다.
- **커뮤니티와 코드 리뷰**: 스스로 구현한 코드를 다른 개발자와 함께 리뷰하거나, 같은 문제를 다른 사람은 어떻게 풀었는지 비교해보는 과정에서 이 책이 다루지 못한 관점(가독성, 유지보수성, 실제 운영 환경에서의 제약)을 배울 수 있습니다.

무엇을 참고하든 가장 중요한 것은 **직접 손으로 구현해보고, 성능을 직접 측정해보는 습관**입니다. 이 책 전체에서 강조했듯, 자료구조와 알고리즘에 대한 이해는 이론을 읽는 것만으로는 완성되지 않으며 코드를 작성하고 그 동작을 눈으로 확인하는 과정에서 비로소 단단해집니다.
