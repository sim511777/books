## 들어가며

5장에서 살펴본 스택이 "가장 나중에 넣은 것을 가장 먼저 꺼내는" 자료구조였다면, 이번 장에서 다룰 큐(Queue)는 정반대의 규칙을 따른다. 먼저 들어온 데이터를 먼저 꺼낸다. 이것을 FIFO(First In First Out)라고 부른다.

은행 창구 앞에 줄을 서 있는 사람들을 떠올려 보자. 줄의 맨 뒤에 새로 도착한 사람이 서고, 처리는 항상 줄의 맨 앞에서부터 이루어진다. 중간에 끼어들거나 순서를 건너뛰는 일은 없다. 큐는 정확히 이 대기줄과 같은 방식으로 동작하는 자료구조다.

## FIFO 원리와 큐의 인터페이스

큐가 지원하는 기본 연산은 스택과 마찬가지로 단순하다.

- `Enqueue(item)`: 큐의 맨 뒤(Rear)에 새 데이터를 추가한다.
- `Dequeue()`: 큐의 맨 앞(Front)에 있는 데이터를 제거하고 그 값을 반환한다.
- `Peek()`: 맨 앞 데이터를 제거하지 않고 값만 확인한다.
- `IsEmpty`: 큐가 비어 있는지 확인한다.

스택과 다른 점은 데이터가 드나드는 지점이 두 곳(앞과 뒤)이라는 것이다. 넣는 곳과 꺼내는 곳이 분리되어 있다는 점이 바로 FIFO 순서를 만들어내는 핵심이다.

다음 그림은 큐의 Enqueue와 Dequeue 연산 전후 상태를 보여준다.

```text
[초기 상태]
+------+------+------+
|  10  |  20  |  30  |
+------+------+------+
 Front           Rear

  Enqueue(40) 실행 (Rear 쪽에 추가)
        |
        v

[Enqueue(40) 이후]
+------+------+------+------+
|  10  |  20  |  30  |  40  |
+------+------+------+------+
 Front                  Rear

  Dequeue() 실행 (Front 쪽에서 제거하여 반환) -> 10 반환
        |
        v

[Dequeue() 이후]
+------+------+
|  20  |  30  |
+------+------+
 Front    Rear
```

## 연결 리스트로 큐 구현하기

4장에서 다룬 연결 리스트를 이용해 큐를 구현해 보자. 스택은 머리 한쪽만 있으면 충분했지만, 큐는 앞뒤 양쪽에서 각각 O(1)에 접근할 수 있어야 하므로 머리(Front)와 꼬리(Rear)를 모두 참조로 들고 있어야 한다. Enqueue는 꼬리에 새 노드를 추가하고 `_rear`를 갱신하며, Dequeue는 머리 노드를 제거하고 `_front`를 다음 노드로 옮긴다.

```csharp
using System;

namespace DataStructures
{
    internal class QueueNode<T>
    {
        public T Value { get; }
        public QueueNode<T>? Next { get; set; }

        public QueueNode(T value)
        {
            Value = value;
        }
    }

    // 연결 리스트 기반 큐 구현
    public class LinkedQueue<T>
    {
        private QueueNode<T>? _front; // 가장 먼저 나갈 노드
        private QueueNode<T>? _rear;  // 가장 마지막에 들어온 노드
        private int _count;

        public int Count => _count;
        public bool IsEmpty => _count == 0;

        // 맨 뒤에 값을 추가한다. O(1)
        public void Enqueue(T value)
        {
            var node = new QueueNode<T>(value);

            if (_rear is null)
            {
                // 큐가 비어 있었다면 새 노드가 앞이자 뒤가 된다
                _front = node;
                _rear = node;
            }
            else
            {
                _rear.Next = node;
                _rear = node;
            }

            _count++;
        }

        // 맨 앞 값을 제거하고 반환한다. O(1)
        public T Dequeue()
        {
            if (_front is null)
                throw new InvalidOperationException("큐가 비어 있습니다.");

            T value = _front.Value;
            _front = _front.Next;

            if (_front is null)
                _rear = null; // 마지막 요소를 꺼냈다면 꼬리도 비워준다

            _count--;
            return value;
        }

        // 맨 앞 값을 제거하지 않고 확인한다. O(1)
        public T Peek()
        {
            if (_front is null)
                throw new InvalidOperationException("큐가 비어 있습니다.");

            return _front.Value;
        }
    }
}
```

여기서 `_rear.Next = node`로 새 노드를 연결한 뒤 `_rear`를 그 노드로 옮기는 부분이 핵심이다. 만약 꼬리 참조를 따로 관리하지 않았다면, Enqueue할 때마다 맨 앞부터 끝까지 순회해서 마지막 노드를 찾아야 했을 것이고, 그러면 시간 복잡도가 O(n)으로 늘어난다. 큐를 연결 리스트로 구현할 때는 반드시 머리와 꼬리를 모두 유지해야 한다는 점을 기억하자.

동적 배열로도 큐를 구현할 수는 있지만, 배열의 맨 앞에서 요소를 제거하면 나머지 요소를 전부 한 칸씩 앞으로 옮겨야 하므로 Dequeue가 O(n)이 되어 버린다. 이 문제를 O(1)로 해결하려면 배열을 원형(circular)으로 사용해 앞뒤 인덱스를 따로 관리하는 기법이 필요한데, 이는 11장에서 다룰 해시테이블의 내부 구조와도 맞닿아 있는 아이디어이니 기억해 두자. 지금 단계에서는 연결 리스트 기반 구현만으로도 큐의 핵심 동작을 충분히 이해할 수 있다.

## 큐가 실제로 쓰이는 곳

**작업 대기열(Job Queue).** 프린터에 여러 사람이 동시에 인쇄를 요청하면, 요청은 들어온 순서대로 큐에 쌓이고 프린터는 맨 앞의 작업부터 하나씩 처리한다. 웹 서버가 동시에 몰려드는 요청을 처리하는 방식이나 메시지 브로커가 이벤트를 순서대로 전달하는 방식도 근본적으로 같은 원리다. 먼저 요청한 작업이 먼저 처리되어야 공정하기 때문에 큐가 자연스러운 선택이 된다.

**너비 우선 탐색(BFS).** 그래프나 트리에서 "가까운 노드부터 차례로" 방문하는 너비 우선 탐색 알고리즘은 큐 없이는 구현할 수 없다. 시작 노드를 큐에 넣고, 큐에서 하나를 꺼낼 때마다 그 노드와 인접한 아직 방문하지 않은 노드들을 큐에 다시 넣는 과정을 반복한다. 이렇게 하면 시작 노드로부터 거리가 가까운 노드일수록 먼저 큐에 들어오고 먼저 처리되므로, 자연스럽게 가까운 순서대로 탐색이 이루어진다. 이 알고리즘은 13장 그래프 탐색에서 본격적으로 구현해 본다.

## 스택과 큐 비교

두 자료구조는 겉모습(연산 개수, 접근 방식의 단순함)은 비슷하지만 처리 순서와 어울리는 문제의 성격이 정반대다.

| 구분 | 스택(Stack) | 큐(Queue) |
|---|---|---|
| 순서 원칙 | LIFO (후입선출) | FIFO (선입선출) |
| 데이터 추가 | Push (한쪽 끝) | Enqueue (뒤쪽 끝) |
| 데이터 제거 | Pop (같은 쪽 끝) | Dequeue (반대쪽 끝) |
| 접근 지점 | 한 곳 (Top) | 두 곳 (Front, Rear) |
| 대표 활용 | 함수 호출, 괄호 검사, Undo | 작업 대기열, 너비 우선 탐색 |
| 비유 | 접시 더미 | 대기줄 |

간단히 정리하면, "가장 최근 것부터 되짚어야 하는 문제"에는 스택이, "들어온 순서를 공정하게 지켜야 하는 문제"에는 큐가 적합하다.

## .NET BCL에서 찾아보기

.NET에는 `System.Collections.Generic.Queue<T>`라는 이름으로 이미 완성된 큐 구현이 준비되어 있다.

```csharp
using System.Collections.Generic;

var queue = new Queue<string>();
queue.Enqueue("첫 번째 작업");
queue.Enqueue("두 번째 작업");
queue.Enqueue("세 번째 작업");

string next = queue.Dequeue();   // "첫 번째 작업"이 반환되고 큐에서 제거됨
string front = queue.Peek();     // "두 번째 작업"을 반환하지만 제거하지는 않음

if (queue.TryDequeue(out string? result))
{
    // 큐가 비어 있지 않았다면 result에 꺼낸 값이 들어온다
}
```

`Queue<T>`는 `Enqueue`, `Dequeue`, `Peek`과 함께, 큐가 비어 있을 때 예외 대신 `false`를 반환하는 `TryDequeue`를 제공한다.

한 가지 정직하게 짚고 넘어갈 부분이 있다. .NET 표준 라이브러리에는 양쪽 끝에서 모두 자유롭게 넣고 뺄 수 있는 "덱(Deque, Double-Ended Queue)" 전용 클래스가 별도로 존재하지 않는다. 앞쪽과 뒤쪽 모두에서 O(1)로 삽입·삭제가 필요한 상황이라면, 4장에서 다룬 `LinkedList<T>`를 대신 활용할 수 있다. `LinkedList<T>`는 `AddFirst`, `AddLast`, `RemoveFirst`, `RemoveLast` 메서드를 모두 제공하므로, 이 네 메서드만으로 덱과 동일한 기능을 구현할 수 있다.

```csharp
using System.Collections.Generic;

var deque = new LinkedList<int>();
deque.AddLast(1);      // 뒤에 추가: [1]
deque.AddLast(2);      // 뒤에 추가: [1, 2]
deque.AddFirst(0);     // 앞에 추가: [0, 1, 2]

int fromFront = deque.First!.Value; // 0
deque.RemoveFirst();                 // [1, 2]

int fromBack = deque.Last!.Value;   // 2
deque.RemoveLast();                  // [1]
```

## 요약

- 큐는 FIFO(First In First Out) 원칙에 따라 동작하며, 데이터는 항상 Rear로 들어와 Front로 나간다.
- 연결 리스트로 큐를 구현할 때는 머리(Front)와 꼬리(Rear)를 모두 참조로 유지해야 Enqueue와 Dequeue가 각각 O(1)에 끝난다.
- 동적 배열로 큐를 구현하면 Dequeue 시 요소를 앞으로 옮겨야 해 O(n)이 되므로, O(1)을 유지하려면 원형 배열 같은 별도 기법이 필요하다.
- 작업 대기열과 너비 우선 탐색(BFS)은 큐의 FIFO 성질을 활용하는 대표적인 사례이며, BFS는 13장에서 자세히 구현한다.
- 스택과 큐는 연산의 형태는 비슷하지만 처리 순서가 정반대이며, 문제의 성격(되짚기 vs 공정한 순서 유지)에 따라 선택이 갈린다.
- BCL의 `Queue<T>`는 `Enqueue`, `Dequeue`, `Peek`, `TryDequeue`를 제공하며, 양쪽 끝을 모두 다루는 덱이 필요하다면 `LinkedList<T>`의 `AddFirst`/`AddLast`/`RemoveFirst`/`RemoveLast`로 대체할 수 있다.

## 연습문제

1. `LinkedQueue<T>`에서 `_rear`를 따로 관리하지 않고 매번 `_front`부터 끝까지 순회해서 꼬리를 찾도록 구현했다면 Enqueue의 시간 복잡도는 어떻게 바뀌는지 설명해 보자.
2. 배열 두 개나 하나의 원형 배열을 이용해 Enqueue와 Dequeue를 모두 O(1)에 처리하는 `CircularArrayQueue<T>`를 설계해 보자. 배열이 가득 찼을 때 어떻게 크기를 늘릴 것인지도 함께 고민해 보자.
3. 스택 두 개만을 이용해 큐를 흉내 내는 방법을 5장 연습문제에서 반대로 뒤집어, 이번에는 큐 두 개만을 이용해 스택의 Push/Pop을 구현해 보자.
4. 회전목마처럼 마지막 사람이 표를 다 팔면 다시 대기열 맨 뒤로 돌아가는 "순환 대기열" 시뮬레이션을 `LinkedQueue<T>`로 구현해 보자. (힌트: Dequeue한 값을 곧바로 다시 Enqueue한다.)
5. 정수 배열과 정수 k가 주어졌을 때, 큐(또는 덱)를 이용해 크기 k인 모든 부분 윈도우의 최댓값을 O(n)에 구하는 방법을 구상해 보자. (힌트: 덱에 인덱스를 저장하면서 불필요한 값을 앞뒤에서 제거한다.)
