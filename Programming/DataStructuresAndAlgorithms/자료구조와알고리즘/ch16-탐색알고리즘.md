## 들어가며: 데이터가 정렬되어 있는가

지금까지 우리는 배열, 연결 리스트, 트리, 해시 테이블 등 다양한 자료구조를 배우면서 자연스럽게 "이 안에 원하는 값이 있는가?"라는 질문을 자주 다루었습니다. 이번 장에서는 그 질문에 답하는 방법 자체, 즉 탐색(search) 알고리즘을 정면으로 다룹니다.

탐색 알고리즘을 고를 때 가장 먼저 던져야 할 질문은 "데이터가 정렬되어 있는가?"입니다. 정렬 여부에 따라 선택할 수 있는 전략과 성능이 완전히 달라지기 때문입니다. 15장에서 배운 정렬 알고리즘들은 바로 이 질문에 "예"라고 답할 수 있게 만들어주는 준비 작업이라고 볼 수 있습니다.

## 선형 탐색: 순서와 무관하게 하나씩 확인한다

가장 단순하고 가장 범용적인 탐색 방법은 처음부터 끝까지 하나씩 확인하는 **선형 탐색(linear search)**입니다. 데이터가 정렬되어 있든 아니든 상관없이 항상 사용할 수 있다는 것이 가장 큰 장점입니다.

```csharp
public static class LinearSearch
{
    // target을 찾으면 인덱스를, 없으면 -1을 반환한다.
    public static int Search(int[] array, int target)
    {
        for (int i = 0; i < array.Length; i++)
        {
            if (array[i] == target)
            {
                return i;
            }
        }

        return -1;
    }
}
```

선형 탐색은 최악의 경우(찾는 값이 배열의 맨 끝에 있거나 아예 없는 경우) 배열 전체를 훑어야 하므로 시간 복잡도는 O(n)입니다. 데이터 규모가 크지 않거나, 데이터가 자주 바뀌어 정렬 상태를 유지하는 비용이 더 클 때는 선형 탐색이 오히려 합리적인 선택입니다.

## 이진 탐색: 정렬된 데이터에서 절반씩 좁혀나간다

데이터가 정렬되어 있다면 훨씬 똑똑한 방법을 쓸 수 있습니다. 사전에서 단어를 찾을 때 처음부터 한 장씩 넘기지 않고 중간을 펼쳐 찾는 단어와 비교한 뒤, 그 결과에 따라 앞부분이나 뒷부분으로만 범위를 좁혀나가는 것과 같은 원리입니다. 이것이 **이진 탐색(binary search)**입니다.

이진 탐색은 매 단계마다 탐색 범위를 절반으로 줄이기 때문에, 범위가 1이 될 때까지 걸리는 단계 수는 log₂n에 비례합니다. 시간 복잡도는 O(log n)으로, 원소가 100만 개여도 약 20번의 비교만으로 원하는 값을 찾거나 없다는 것을 확인할 수 있습니다.

```csharp
public static class BinarySearch
{
    // array는 반드시 오름차순으로 정렬되어 있어야 한다.
    public static int Search(int[] array, int target)
    {
        int low = 0;
        int high = array.Length - 1;

        while (low <= high)
        {
            int mid = low + (high - low) / 2; // 오버플로를 피하기 위한 계산 방식

            if (array[mid] == target)
            {
                return mid;
            }
            else if (array[mid] < target)
            {
                low = mid + 1; // 오른쪽 절반만 탐색
            }
            else
            {
                high = mid - 1; // 왼쪽 절반만 탐색
            }
        }

        return -1; // 탐색 범위가 비어버리면 존재하지 않는 것
    }
}
```

`mid`를 `(low + high) / 2`가 아니라 `low + (high - low) / 2`로 계산한 이유에 주목하세요. 배열이 매우 크면 `low + high`가 `int`의 표현 범위를 넘어 오버플로가 발생할 수 있는데, 이렇게 계산하면 그런 문제를 피할 수 있습니다.

이진 탐색은 재귀로도 자연스럽게 표현할 수 있습니다. 매 호출마다 탐색 범위를 절반으로 줄여 자기 자신을 호출하는 구조는 17장에서 다룰 분할 정복 패턴과 정확히 같은 모양입니다.

```csharp
public static int SearchRecursive(int[] array, int target, int low, int high)
{
    if (low > high)
    {
        return -1;
    }

    int mid = low + (high - low) / 2;

    if (array[mid] == target)
    {
        return mid;
    }

    return array[mid] < target
        ? SearchRecursive(array, target, mid + 1, high)
        : SearchRecursive(array, target, low, mid - 1);
}
```

## 전제조건: 정렬되어 있지 않으면 틀린 답이 나온다

이진 탐색을 쓸 때 절대 잊지 말아야 할 전제조건이 하나 있습니다. **대상 배열이 미리 정렬되어 있어야 한다**는 것입니다. 정렬되지 않은 배열에 이진 탐색을 적용하면, 알고리즘은 여전히 답을 내놓지만 그 답이 틀릴 수 있습니다. 예를 들어 배열이 `{5, 1, 8, 3, 9}`처럼 정렬되어 있지 않다면, 중간값과 비교해 왼쪽 또는 오른쪽으로 범위를 좁히는 판단 자체가 근거를 잃습니다. 실제로 존재하는 값인데도 "찾을 수 없다"는 잘못된 결과를 반환할 수 있습니다.

따라서 이진 탐색은 항상 15장에서 배운 정렬 알고리즘(또는 이미 정렬된 상태로 데이터가 들어오는 상황)과 짝을 이루어 사용됩니다. 한 번만 탐색할 데이터라면 정렬 비용(O(n log n))을 들이는 것보다 선형 탐색 한 번(O(n))이 더 저렴할 수 있지만, 같은 데이터에 대해 탐색을 여러 번 반복해야 한다면 처음에 한 번 정렬해두고 매번 이진 탐색을 쓰는 쪽이 훨씬 유리합니다.

## 선형 탐색과 이진 탐색 비교

| 항목 | 선형 탐색 | 이진 탐색 |
|---|---|---|
| 전제조건 | 없음 | 데이터가 정렬되어 있어야 함 |
| 시간 복잡도 | O(n) | O(log n) |
| 구현 난이도 | 매우 단순 | 단순하지만 경계 조건에 주의 필요 |
| 적합한 상황 | 데이터가 작거나 자주 바뀌는 경우 | 정렬된 데이터에 반복적으로 탐색이 필요한 경우 |

## .NET BCL에서 찾아보기

이진 탐색도 매번 직접 구현할 필요는 없습니다. `Array.BinarySearch()`와 `List<T>.BinarySearch()`가 이미 BCL에 내장되어 있습니다.

```csharp
int[] numbers = { 1, 3, 5, 7, 9, 11 };
int index = Array.BinarySearch(numbers, 7); // 3

var list = new List<int> { 1, 3, 5, 7, 9, 11 };
int listIndex = list.BinarySearch(9); // 4
```

단, 이 메서드들 역시 이번 장에서 강조한 전제조건을 그대로 물려받습니다. 즉 대상 배열이나 리스트가 미리 정렬되어 있어야만 올바르게 동작합니다. 정렬되지 않은 데이터에 `Array.BinarySearch()`를 호출하면 예외가 발생하지는 않지만, 신뢰할 수 없는 결과를 반환할 수 있습니다. 값을 찾지 못했을 때는 음수를 반환하는데, 이 값은 "정렬 순서를 유지한 채 삽입해야 할 위치"에 대한 정보를 담고 있어 단순히 -1 하나만 돌려주는 것보다 더 많은 정보를 제공합니다.

한편 탐색이라는 목적 자체만 놓고 보면, 11장에서 배운 `Dictionary<TKey, TValue>`나 `HashSet<T>`를 사용하는 방법도 있습니다. 해시 테이블 기반의 이 자료구조들은 평균적으로 O(1)에 조회를 수행하므로, 정렬을 유지하는 비용이나 O(log n)의 비교조차 필요 없습니다.

```csharp
var lookup = new HashSet<int> { 1, 3, 5, 7, 9, 11 };
bool found = lookup.Contains(7); // true, 평균 O(1)
```

그렇다면 이진 탐색은 왜 여전히 필요할까요? 해시 테이블은 "이 값이 있는가"를 빠르게 답할 수 있지만, 값들 사이의 순서 정보를 보존하지 않습니다. 특정 값 이상/이하의 범위를 조회하거나, 정렬된 순서로 데이터를 순회해야 하는 경우에는 정렬된 배열과 이진 탐색(또는 8장의 이진 탐색 트리)이 여전히 더 적합합니다. 결국 무엇을 선택할지는 "값의 존재 여부만 빠르게 알고 싶은가, 아니면 순서와 범위도 함께 다뤄야 하는가"에 달려 있습니다.

## 요약

- 선형 탐색은 정렬 여부와 무관하게 처음부터 끝까지 확인하는 O(n) 알고리즘이다.
- 이진 탐색은 정렬된 데이터에서 탐색 범위를 절반씩 줄여나가는 O(log n) 알고리즘이며, 데이터가 미리 정렬되어 있어야 한다는 전제조건이 반드시 필요하다.
- 정렬되지 않은 데이터에 이진 탐색을 적용하면 잘못된 결과를 얻을 수 있으므로, 15장의 정렬 알고리즘과 함께 사용해야 한다.
- `Array.BinarySearch()`/`List<T>.BinarySearch()`는 BCL에 내장된 이진 탐색 구현이지만, 역시 사전 정렬이 필요하다.
- 순서 정보 없이 존재 여부만 빠르게 확인하면 된다면 `Dictionary<TKey,TValue>`나 `HashSet<T>`로 평균 O(1) 조회를 활용할 수 있다.

## 연습문제

1. 정렬되지 않은 배열 `{5, 1, 8, 3, 9}`에 본문의 `BinarySearch.Search`를 그대로 적용해 `target = 3`을 찾아보고, 어떤 값이 반환되는지 직접 손으로 계산해 실제 정답 여부와 비교해 보세요.
2. 배열에 중복된 값이 여러 개 있을 때, 이진 탐색으로 그 값이 "처음 등장하는 위치"를 찾도록 `Search` 메서드를 수정해 보세요.
3. 데이터가 총 1,000번 탐색될 예정이라고 가정할 때, "정렬 후 이진 탐색"과 "정렬 없이 매번 선형 탐색"의 총 비교 횟수를 n에 대한 식으로 각각 세워 비교해 보세요.
4. 같은 데이터를 정렬된 배열과 `HashSet<int>`에 각각 담아 두고 특정 값의 존재 여부를 확인하는 두 코드를 작성한 뒤, 어떤 상황에서 배열 쪽이 더 유리할 수 있는지 서술해 보세요.
5. 회전된 정렬 배열(예: `{4, 5, 6, 7, 0, 1, 2}`처럼 정렬된 배열을 어느 지점에서 잘라 앞뒤를 바꾼 형태)에서도 이진 탐색과 비슷한 O(log n) 방식으로 특정 값을 찾을 수 있을지 생각해 보고, 가능하다면 그 아이디어를 스케치해 보세요.
