# 7장. 이진 트리 기초

---

지금까지 살펴본 배열, 연결 리스트, 스택, 큐는 모두 데이터를 한 줄로 늘어놓는 **선형 자료구조**였습니다. 이번 장부터는 데이터를 계층적으로 조직하는 **트리(tree)** 자료구조를 다룹니다. 트리는 파일 시스템의 폴더 구조, 조직도, HTML 문서의 DOM, 데이터베이스 인덱스 등 우리 주변 어디에나 존재하는 구조이며, 뒤에서 배울 이진 탐색 트리(8장), 균형 트리(9장), 힙(10장)의 기반이 됩니다.

## 트리의 기본 용어

트리는 **노드(node)**들이 부모-자식 관계로 연결된 구조입니다. 다음 용어들은 앞으로 계속 등장하므로 확실히 짚고 넘어갑시다.

- **노드(node)**: 트리를 구성하는 하나의 단위. 값(데이터)과 다른 노드로의 연결 정보를 가집니다.
- **루트(root)**: 트리의 맨 위에 있는, 부모가 없는 유일한 노드.
- **부모(parent)**와 **자식(child)**: 어떤 노드에서 아래로 직접 연결된 노드가 자식이고, 그 자식에서 보면 원래 노드가 부모입니다.
- **형제(sibling)**: 같은 부모를 가진 노드들.
- **리프(leaf, 외부 노드)**: 자식이 하나도 없는 노드.
- **내부 노드(internal node)**: 자식이 하나 이상 있는 노드.
- **조상(ancestor)/자손(descendant)**: 루트에서 어떤 노드까지 가는 경로 위에 있는 노드들이 그 노드의 조상이고, 반대로 어떤 노드 아래로 연결된 모든 노드는 그 노드의 자손입니다.
- **깊이(depth)**: 루트에서 해당 노드까지 내려가는 데 거친 간선(edge)의 개수. 루트의 깊이는 0입니다.
- **높이(height)**: 해당 노드에서 가장 먼 리프까지 내려가는 간선의 개수. 트리 전체의 높이는 루트의 높이를 말합니다. 리프만 있는 노드의 높이는 0입니다.
- **레벨(level)**: 흔히 깊이와 같은 의미로 쓰이며, 같은 깊이의 노드들을 "같은 레벨"이라고 부릅니다.

아래 그림은 이 용어들을 하나의 트리 위에 표시한 것입니다.

```text
                    8              <- 루트(root)              (깊이 0)
                   / \
                  3   10                                      (깊이 1)
                 / \    \                <- 10은 왼쪽 자식 없음(형제 없음)
                1   6    14                                    (깊이 2)
                   / \   /
                  4   7 13                                     (깊이 3)

부모/자식 예: 3은 6의 부모, 6은 3의 자식
리프(leaf, 자식 없음): 1, 4, 7, 13
트리의 높이 = 3
```

## 이진 트리란

**이진 트리(binary tree)**는 각 노드가 자식을 **최대 2개**까지만 가질 수 있고, 그 두 자식이 각각 **왼쪽 자식(left child)**과 **오른쪽 자식(right child)**으로 구분되는 트리입니다. 자식이 하나뿐이어도 그것이 왼쪽인지 오른쪽인지가 의미를 가진다는 점이 일반 트리와의 차이입니다.

몇 가지 특수한 형태도 이름이 붙어 있습니다.

- **정이진트리(full binary tree)**: 모든 노드의 자식 수가 0개 또는 2개인 트리(자식이 1개인 노드가 없음).
- **포화이진트리(perfect binary tree)**: 모든 리프의 깊이가 같고, 모든 내부 노드가 자식을 2개씩 가진 트리.
- **완전이진트리(complete binary tree)**: 마지막 레벨을 제외한 모든 레벨이 꽉 차 있고, 마지막 레벨의 노드들은 왼쪽부터 채워진 트리. 10장에서 배열로 힙을 구현할 때 이 성질을 활용합니다.

## TreeNode&lt;T&gt;로 이진 트리 표현하기

이진 트리는 각 노드가 값 하나와 왼쪽·오른쪽 자식에 대한 참조를 갖는 노드 클래스로 표현합니다. 4장에서 만든 연결 리스트의 노드가 `Next` 하나만 가졌던 것과 비교하면, 이진 트리 노드는 참조가 두 개로 늘어난 셈입니다.

```csharp
// 이진 트리를 구성하는 노드
public class TreeNode<T>
{
    public T Value { get; set; }
    public TreeNode<T>? Left { get; set; }
    public TreeNode<T>? Right { get; set; }

    public TreeNode(T value)
    {
        Value = value;
    }
}
```

이 노드들을 직접 연결하면 트리를 만들 수 있습니다.

```csharp
// 그림과 같은 모양의 트리를 직접 구성
var root = new TreeNode<int>(8);
root.Left = new TreeNode<int>(3);
root.Right = new TreeNode<int>(10);
root.Left.Left = new TreeNode<int>(1);
root.Left.Right = new TreeNode<int>(6);
root.Right.Right = new TreeNode<int>(14);
root.Left.Right.Left = new TreeNode<int>(4);
root.Left.Right.Right = new TreeNode<int>(7);
root.Right.Right.Left = new TreeNode<int>(13);
```

## 트리 순회: 노드를 방문하는 순서

배열이나 리스트는 앞에서부터 순서대로 훑으면 되지만, 트리는 노드가 여러 방향으로 갈라져 있어서 "어떤 순서로 방문할 것인가"를 정해야 합니다. 이를 **순회(traversal)**라고 하며, 대표적으로 네 가지 방식이 있습니다.

### 전위 순회 (Preorder: 노드 → 왼쪽 → 오른쪽)

현재 노드를 먼저 방문하고, 그다음 왼쪽 서브트리, 오른쪽 서브트리 순서로 방문합니다. 트리를 복사하거나 직렬화(트리 구조를 파일이나 문자열로 저장)할 때 유용합니다. 부모를 자식보다 먼저 만나야 트리를 그대로 재구성할 수 있기 때문입니다.

```csharp
public static void PreOrder<T>(TreeNode<T>? node, List<T> result)
{
    if (node is null) return;

    result.Add(node.Value);          // 노드
    PreOrder(node.Left, result);      // 왼쪽
    PreOrder(node.Right, result);     // 오른쪽
}
```

### 중위 순회 (Inorder: 왼쪽 → 노드 → 오른쪽)

왼쪽 서브트리를 모두 방문한 뒤 현재 노드, 그다음 오른쪽 서브트리를 방문합니다. 8장에서 배울 이진 탐색 트리에서는 중위 순회를 하면 값이 오름차순으로 정렬되어 나온다는 중요한 성질이 있습니다.

```csharp
public static void InOrder<T>(TreeNode<T>? node, List<T> result)
{
    if (node is null) return;

    InOrder(node.Left, result);       // 왼쪽
    result.Add(node.Value);           // 노드
    InOrder(node.Right, result);      // 오른쪽
}
```

### 후위 순회 (Postorder: 왼쪽 → 오른쪽 → 노드)

자식들을 모두 방문한 뒤에 현재 노드를 방문합니다. 노드를 삭제하거나(자식을 먼저 정리해야 안전하게 부모를 지울 수 있으므로), 디렉토리의 전체 용량을 계산하는 것처럼 "하위 결과를 먼저 알아야 상위 결과를 계산할 수 있는" 문제에 적합합니다.

```csharp
public static void PostOrder<T>(TreeNode<T>? node, List<T> result)
{
    if (node is null) return;

    PostOrder(node.Left, result);     // 왼쪽
    PostOrder(node.Right, result);    // 오른쪽
    result.Add(node.Value);           // 노드
}
```

세 순회 모두 시간 복잡도는 O(n)입니다. 노드마다 정확히 한 번씩 방문하기 때문입니다. 다만 재귀 호출 깊이가 트리의 높이만큼 쌓이므로, 공간 복잡도는 O(h)(h는 트리의 높이)이며 매우 편향된 트리에서는 이 h가 n에 가까워질 수 있습니다.

### 레벨 순회 (Level-order, BFS)

앞의 세 순회는 모두 "한쪽 방향으로 최대한 깊이 내려갔다가 돌아오는" 방식, 즉 **깊이 우선 탐색(DFS)**이었습니다. 이와 달리 **레벨 순회**는 같은 깊이의 노드들을 왼쪽부터 차례로 방문한 뒤 다음 깊이로 내려가는 **너비 우선 탐색(BFS)** 방식입니다. 그림의 트리라면 8 → 3, 10 → 1, 6, 14 → 4, 7, 13 순서로 방문합니다.

재귀 대신 5장에서 배운 큐(Queue)를 사용합니다. 노드를 방문할 때마다 그 자식들을 큐에 넣고, 큐에서 하나씩 꺼내 방문하는 방식으로 "먼저 들어온 레벨을 먼저 처리"하게 됩니다.

```csharp
public static List<T> LevelOrder<T>(TreeNode<T>? root)
{
    var result = new List<T>();
    if (root is null) return result;

    var queue = new Queue<TreeNode<T>>();
    queue.Enqueue(root);

    while (queue.Count > 0)
    {
        var node = queue.Dequeue();
        result.Add(node.Value);

        if (node.Left is not null) queue.Enqueue(node.Left);
        if (node.Right is not null) queue.Enqueue(node.Right);
    }

    return result;
}
```

여기서 큐를 쓰는 이유는 6장에서 설명한 큐의 선입선출(FIFO) 성질과 정확히 맞아떨어지기 때문입니다. 만약 큐 대신 스택을 사용하면 방문 순서가 레벨 순서가 아니라 DFS의 변형이 되어 버립니다.

## .NET BCL에서 찾아보기

.NET BCL에는 지금 만든 `TreeNode<T>`나 이진 트리 자체를 표현하는 범용 대표 클래스가 직접 노출되어 있지 않습니다. 트리는 배열이나 리스트처럼 "그 자체로 완성된 컬렉션"이라기보다는 문제에 맞게 커스터마이징해서 쓰는 구조에 가깝기 때문에, 필요할 때 지금처럼 직접 노드 클래스를 정의해 쓰는 것이 일반적입니다.

다만 트리 구조가 완전히 감춰진 채로 활용되는 경우는 있습니다. 9장에서 다룰 `SortedSet<T>`와 `SortedDictionary<TKey, TValue>`는 내부적으로 균형 이진 탐색 트리를 사용해 데이터를 항상 정렬된 상태로 유지합니다. 지금 단계에서는 "정렬된 컬렉션 뒤에는 트리가 숨어 있을 수 있다" 정도만 기억해 두고, 자세한 내용은 8장과 9장에서 이어가겠습니다.

## 요약

- 트리는 노드들이 부모-자식 관계로 연결된 계층적 자료구조이며, 루트, 리프, 부모/자식, 깊이, 높이 같은 용어로 그 구조를 설명합니다.
- 이진 트리는 각 노드가 왼쪽·오른쪽으로 구분되는 자식을 최대 2개까지 가지는 트리이며, `TreeNode<T>`처럼 `Value`, `Left`, `Right`를 가진 클래스로 표현합니다.
- 전위·중위·후위 순회는 모두 재귀로 자연스럽게 구현되는 깊이 우선 탐색이며, 방문 순서에 따라 용도가 다릅니다(복사/직렬화, 정렬된 출력, 삭제/집계).
- 레벨 순회는 큐를 이용한 너비 우선 탐색으로, 같은 깊이의 노드를 먼저 모두 방문합니다.
- BCL에는 범용 이진 트리 클래스가 없지만, 정렬된 컬렉션인 `SortedSet<T>`/`SortedDictionary<TKey, TValue>`가 내부적으로 트리를 활용합니다.

## 연습문제

1. 트리의 전체 노드 개수를 세는 `CountNodes<T>(TreeNode<T>? root)` 메서드를 재귀로 작성하세요.
2. 트리의 높이를 계산하는 `Height<T>(TreeNode<T>? root)` 메서드를 작성하세요. 빈 트리(`null`)의 높이는 -1로 정의합니다.
3. 두 트리가 구조와 값이 완전히 같은지 비교하는 `IsSameTree<T>(TreeNode<T>? a, TreeNode<T>? b)` 메서드를 작성하세요.
4. 트리를 좌우 대칭으로 뒤집는 `Mirror<T>(TreeNode<T>? root)` 메서드를 작성하세요. (왼쪽과 오른쪽 자식을 재귀적으로 맞바꿉니다.)
5. 레벨 순회를 응용해, 각 레벨의 노드들을 별도의 리스트로 묶어 반환하는 `LevelOrderByLevel<T>(TreeNode<T>? root)`를 작성하세요. 힌트: `while` 루프를 돌 때마다 그 시점의 큐 크기를 미리 저장해 "이번 레벨에 몇 개를 처리할지" 기준으로 삼으세요.
