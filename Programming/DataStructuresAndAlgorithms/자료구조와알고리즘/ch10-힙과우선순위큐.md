# 10장. 힙과 우선순위 큐

## 시작하며

6장에서 배운 큐(Queue)는 "먼저 들어온 데이터가 먼저 나간다(FIFO)"는 원칙으로 동작했습니다. 그런데 실무에서는 순서가 아니라 "중요도"나 "긴급도"에 따라 먼저 처리해야 할 데이터가 정해지는 경우가 훨씬 많습니다. 응급실에서는 접수 순서가 아니라 위급한 환자를 먼저 봅니다. 운영체제는 우선순위가 높은 프로세스에 먼저 CPU 시간을 할당합니다. 이런 요구를 만족시키는 자료구조가 바로 **우선순위 큐(priority queue)**이고, 우선순위 큐를 효율적으로 구현하는 표준적인 방법이 이번 장의 주제인 **힙(heap)**입니다.

힙은 9장에서 다룬 균형 트리와는 성격이 다릅니다. 균형 트리는 "정렬된 순서로 아무 값이나 빠르게 찾기" 위한 자료구조였다면, 힙은 "가장 작은 값(또는 가장 큰 값) 하나를 빠르게 꺼내기"에 특화된 자료구조입니다. 목적이 다르기 때문에 요구하는 성질도, 구현 방법도 다릅니다.

## 힙이란 무엇인가

**힙(heap)**은 두 가지 조건을 만족하는 완전 이진 트리입니다.

첫째, **완전 이진 트리(complete binary tree)**여야 합니다. 즉 마지막 레벨을 제외한 모든 레벨이 노드로 꽉 차 있고, 마지막 레벨의 노드들은 왼쪽부터 순서대로 채워져 있어야 합니다. 7장에서 다룬 일반적인 이진 트리와 달리, 힙은 아무렇게나 노드를 매달 수 없습니다.

둘째, **힙 속성(heap property)**을 만족해야 합니다. **최소 힙(min-heap)**에서는 모든 부모 노드의 값이 자식 노드의 값보다 작거나 같아야 합니다. 이 규칙 때문에 최소 힙에서는 루트 노드가 항상 트리 전체에서 가장 작은 값을 가지게 됩니다. 반대로 **최대 힙(max-heap)**은 부모가 항상 자식보다 크거나 같아서, 루트가 항상 가장 큰 값을 가집니다.

주의할 점은, 힙은 8장의 이진 탐색 트리와 다르다는 것입니다. 이진 탐색 트리는 "왼쪽 서브트리 전체 < 부모 < 오른쪽 서브트리 전체"라는 강한 순서 규칙을 가졌지만, 힙은 오직 "부모와 자식 사이"의 대소 관계만 보장합니다. 같은 레벨에 있는 두 노드 사이의 대소 관계나, 왼쪽 서브트리와 오른쪽 서브트리 사이의 대소 관계는 정해져 있지 않습니다. 이 느슨한 규칙 덕분에 힙은 이진 탐색 트리보다 훨씬 간단하고 빠르게 유지될 수 있습니다.

## 배열로 힙을 표현하기

힙의 가장 흥미로운 특징은, 완전 이진 트리라는 조건 덕분에 포인터나 노드 클래스 없이 **배열 하나만으로** 트리 구조 전체를 표현할 수 있다는 점입니다. 노드가 왼쪽부터 빈틈없이 채워지므로, 트리를 위에서 아래로, 같은 레벨에서는 왼쪽에서 오른쪽으로 읽으면서 배열에 순서대로 담으면 됩니다.

배열의 인덱스 `i`에 저장된 노드를 기준으로, 부모와 자식의 인덱스는 다음 공식으로 계산됩니다.

- 왼쪽 자식의 인덱스: `2i + 1`
- 오른쪽 자식의 인덱스: `2i + 2`
- 부모의 인덱스: `(i - 1) / 2` (정수 나눗셈)

예를 들어 배열 `[1, 3, 2, 7, 5, 4, 8]`은 다음과 같은 최소 힙을 나타냅니다. 인덱스 0의 값 1이 루트이고, 인덱스 1(값 3)과 인덱스 2(값 2)가 그 자식입니다. 인덱스 1의 자식은 공식에 따라 인덱스 3(값 7)과 인덱스 4(값 5)가 됩니다.

```text
[트리 형태]                                루트가 항상 최솟값(1)을 가진다

                1  (idx 0)
              /            \
        3 (idx 1)          2 (idx 2)
        /       \           /       \
   7(idx 3)  5(idx 4)  4(idx 5)  8(idx 6)

[배열 형태]
 idx :   0     1     2     3     4     5     6
       +-----+-----+-----+-----+-----+-----+-----+
 val : |  1  |  3  |  2  |  7  |  5  |  4  |  8  |
       +-----+-----+-----+-----+-----+-----+-----+

부모 인덱스 i의 자식 인덱스:
  왼쪽 자식 = 2i + 1
  오른쪽 자식 = 2i + 2
  (반대로) 자식 j의 부모 = (j - 1) / 2

예: idx 1(값 3)의 자식은 idx 3(값 7), idx 4(값 5)

완전 이진 트리이기 때문에 포인터 없이 배열 인덱스 계산만으로
부모-자식 관계를 표현할 수 있다.
```

3장에서 배운 동적 배열이 있으면 이 구조를 그대로 활용할 수 있습니다. 트리를 위한 별도의 노드 클래스나 참조(포인터)가 전혀 필요 없다는 점이 힙 구현을 간결하게 만드는 핵심입니다.

## 최소 힙 직접 구현하기

이제 배열 기반 최소 힙을 직접 구현해봅시다. 핵심 연산은 값을 넣는 `Insert`와 최솟값을 꺼내는 `ExtractMin` 두 가지입니다.

```csharp
using System;
using System.Collections.Generic;

public class MinHeap
{
    private readonly List<int> _items = new List<int>();

    public int Count => _items.Count;

    // 힙에 새 값을 추가한다
    public void Insert(int value)
    {
        // 1. 일단 배열의 맨 끝(트리의 마지막 자리)에 추가한다
        _items.Add(value);

        // 2. 힙 속성이 깨졌을 수 있으므로, 부모와 비교하며 위로 올려보낸다
        SiftUp(_items.Count - 1);
    }

    // 위로 올리기: 자신이 부모보다 작으면 부모와 자리를 바꾸는 과정을 반복한다
    private void SiftUp(int index)
    {
        while (index > 0)
        {
            int parentIndex = (index - 1) / 2;

            if (_items[index] >= _items[parentIndex])
            {
                // 부모가 이미 더 작거나 같으면 힙 속성이 만족된 것이므로 멈춘다
                break;
            }

            Swap(index, parentIndex);
            index = parentIndex;
        }
    }

    // 최솟값을 꺼내고 힙에서 제거한다
    public int ExtractMin()
    {
        if (_items.Count == 0)
        {
            throw new InvalidOperationException("힙이 비어 있습니다.");
        }

        int min = _items[0];
        int lastIndex = _items.Count - 1;

        // 1. 마지막 원소를 루트 자리로 옮기고, 마지막 자리는 비운다
        _items[0] = _items[lastIndex];
        _items.RemoveAt(lastIndex);

        // 2. 루트에서 힙 속성이 깨졌을 수 있으므로, 자식과 비교하며 아래로 내려보낸다
        if (_items.Count > 0)
        {
            SiftDown(0);
        }

        return min;
    }

    // 아래로 내리기: 자신보다 작은 자식이 있으면 그 자식과 자리를 바꾸는 과정을 반복한다
    private void SiftDown(int index)
    {
        int count = _items.Count;

        while (true)
        {
            int leftChild = 2 * index + 1;
            int rightChild = 2 * index + 2;
            int smallest = index;

            if (leftChild < count && _items[leftChild] < _items[smallest])
            {
                smallest = leftChild;
            }

            if (rightChild < count && _items[rightChild] < _items[smallest])
            {
                smallest = rightChild;
            }

            if (smallest == index)
            {
                // 두 자식보다 자신이 더 작으면 힙 속성이 만족된 것이므로 멈춘다
                break;
            }

            Swap(index, smallest);
            index = smallest;
        }
    }

    // 힙을 비우지 않고 최솟값만 확인한다
    public int PeekMin()
    {
        if (_items.Count == 0)
        {
            throw new InvalidOperationException("힙이 비어 있습니다.");
        }

        return _items[0];
    }

    private void Swap(int i, int j)
    {
        // 튜플 구조 분해를 이용한 값 맞바꾸기
        (_items[i], _items[j]) = (_items[j], _items[i]);
    }
}
```

`Insert`와 `ExtractMin` 모두 트리의 높이만큼만 이동하면 되고, 힙은 완전 이진 트리이므로 높이가 항상 log n입니다. 따라서 두 연산 모두 O(log n)입니다. 최솟값을 확인만 하는 `PeekMin`은 배열의 첫 번째 원소를 보기만 하면 되므로 O(1)입니다. 편향될 걱정이 없는 이유는, 배열에 왼쪽부터 순서대로 채우는 완전 이진 트리 조건 자체가 힙의 모양을 항상 균형 잡힌 형태로 강제하기 때문입니다. 9장에서 이진 탐색 트리가 편향될 수 있다는 문제를 봤지만, 힙은 애초에 그런 걱정이 필요 없는 구조입니다.

## 우선순위 큐: 힙의 대표적인 활용

**우선순위 큐(priority queue)**는 "우선순위가 가장 높은 원소를 먼저 꺼낼 수 있는" 자료구조입니다. 앞서 만든 `MinHeap`이 이미 우선순위 큐의 동작 그 자체입니다. 우선순위를 숫자가 작을수록 급한 것으로 정하면, `Insert`는 새로운 작업을 등록하는 것이고 `ExtractMin`은 가장 급한 작업을 꺼내는 것이 됩니다.

6장의 일반 큐와 비교하면 차이가 분명해집니다. 일반 큐는 데이터가 들어온 순서만으로 꺼낼 순서가 정해집니다. 먼저 들어오면 먼저 나갑니다. 반면 우선순위 큐는 들어온 순서와 무관하게, 오직 우선순위 값에 따라 꺼낼 순서가 정해집니다. 방금 막 들어온 데이터라도 우선순위가 가장 높다면 가장 먼저 나갈 수 있습니다.

```csharp
// 우선순위 큐처럼 사용하는 예: 값이 작을수록 우선순위가 높다고 가정
var jobQueue = new MinHeap();

jobQueue.Insert(5);  // 우선순위 5인 작업 등록
jobQueue.Insert(1);  // 우선순위 1인 작업 등록 (가장 급함)
jobQueue.Insert(3);  // 우선순위 3인 작업 등록

// 들어온 순서(5, 1, 3)와 무관하게 우선순위가 낮은 숫자부터 나온다
Console.WriteLine(jobQueue.ExtractMin()); // 1
Console.WriteLine(jobQueue.ExtractMin()); // 3
Console.WriteLine(jobQueue.ExtractMin()); // 5
```

실제 서비스에서는 우선순위와 실제로 처리할 데이터를 함께 저장해야 하는 경우가 대부분입니다. 예를 들어 "작업 이름"과 "우선순위"를 같이 넣고 싶다면, 힙에 저장하는 원소를 정수 하나가 아니라 (우선순위, 데이터) 쌍으로 확장하면 됩니다. 잠시 후 살펴볼 BCL의 `PriorityQueue<TElement, TPriority>`가 정확히 이 방식을 채택하고 있습니다.

## .NET BCL에서 찾아보기

.NET 6부터는 힙을 직접 구현할 필요 없이 `System.Collections.Generic.PriorityQueue<TElement, TPriority>`를 바로 사용할 수 있습니다. 이름 그대로 우선순위 큐이며, 내부적으로 이진 힙 기반으로 구현되어 있어서 방금 살펴본 `MinHeap`과 동일한 원리로 동작합니다.

```csharp
using System.Collections.Generic;

// TElement는 실제로 꺼낼 데이터의 타입, TPriority는 우선순위 값의 타입
var jobQueue = new PriorityQueue<string, int>();

// Enqueue(element, priority): 데이터와 우선순위를 함께 넣는다
jobQueue.Enqueue("보고서 작성", 5);
jobQueue.Enqueue("서버 장애 대응", 1); // 숫자가 작을수록 먼저 나온다
jobQueue.Enqueue("코드 리뷰", 3);

// Dequeue(): 가장 우선순위가 높은(기본적으로 가장 작은 값의) 요소부터 꺼낸다
Console.WriteLine(jobQueue.Dequeue()); // 서버 장애 대응
Console.WriteLine(jobQueue.Dequeue()); // 코드 리뷰
Console.WriteLine(jobQueue.Dequeue()); // 보고서 작성
```

`PriorityQueue<TElement, TPriority>`가 등장하기 전에는 힙이 필요할 때마다 직접 구현하거나 `SortedSet<T>` 같은 다른 자료구조로 대신 흉내 내야 했습니다. 이제는 표준 라이브러리만으로 작업 스케줄링, 다익스트라 최단 경로 알고리즘(13장에서 다시 만나게 됩니다), 이벤트 시뮬레이션 등 우선순위 기반 처리가 필요한 다양한 문제를 바로 해결할 수 있습니다. 직접 힙을 구현해본 경험이 있으면, `Enqueue`와 `Dequeue`가 내부에서 어떤 방식(sift-up, sift-down)으로 동작하고 왜 O(log n)의 비용이 드는지 정확히 이해한 채로 사용할 수 있습니다.

## 요약

- 힙은 완전 이진 트리이면서 부모와 자식 사이의 대소 관계(힙 속성)를 만족하는 자료구조로, 최소 힙은 항상 루트에 최솟값을, 최대 힙은 항상 루트에 최댓값을 가집니다.
- 완전 이진 트리라는 성질 덕분에 힙은 포인터 없이 배열 하나로 표현할 수 있으며, 인덱스 `i`의 자식은 `2i + 1`, `2i + 2`, 부모는 `(i - 1) / 2`로 계산됩니다.
- `Insert`는 배열 끝에 값을 추가한 뒤 위로 올리기(sift-up)로, `ExtractMin`은 루트를 꺼내고 마지막 값을 루트로 옮긴 뒤 아래로 내리기(sift-down)로 힙 속성을 되찾으며, 두 연산 모두 O(log n)입니다.
- 우선순위 큐는 들어온 순서가 아니라 우선순위에 따라 꺼낼 원소가 정해지는 자료구조이며, 힙으로 효율적으로 구현할 수 있습니다. 6장의 일반 큐(입력 순서 기준)와는 이 점에서 근본적으로 다릅니다.
- .NET 6부터 제공되는 `PriorityQueue<TElement, TPriority>`는 이진 힙 기반의 우선순위 큐로, `Enqueue(element, priority)`와 `Dequeue()`만으로 우선순위 기반 처리를 바로 구현할 수 있습니다.

## 연습문제

1. 빈 최소 힙에 순서대로 10, 4, 15, 1, 8을 `Insert`했을 때, 각 단계마다 배열이 어떻게 변하는지 손으로 그려서 확인해보세요.
2. 배열 `[2, 4, 3, 8, 9, 7, 5]`가 올바른 최소 힙인지 판별하고, 이유를 설명해보세요.
3. 본문의 `MinHeap`을 참고해, 부모가 항상 자식보다 크거나 같은 `MaxHeap`을 직접 구현해보세요. `SiftUp`과 `SiftDown`에서 부등호 방향만 바꾸면 됩니다.
4. `ExtractMin`에서 왜 마지막 원소를 루트로 옮긴 뒤 아래로 내리는 방식을 쓰는지, 대신 두 번째로 작은 원소를 루트로 바로 옮기면 안 되는 이유를 생각해보세요.
5. `PriorityQueue<TElement, TPriority>`를 사용해, 여러 손님의 "이름"과 "대기 순번 우선순위"를 넣고 우선순위가 높은 손님부터 호출하는 간단한 대기열 프로그램을 작성해보세요.
