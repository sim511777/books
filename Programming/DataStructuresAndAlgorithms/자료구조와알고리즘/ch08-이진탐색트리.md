7장에서 이진 트리의 구조와 순회 방법을 배웠지만, 그 자체로는 "값을 어디에 둘지"에 대한 규칙이 없었습니다. 값을 아무 자리에나 넣을 수 있다면 특정 값을 찾으려 할 때 결국 트리 전체를 훑어봐야 하므로 O(n)이 걸립니다. 이번 장에서는 값을 저장하는 위치에 규칙을 하나 추가해서, 탐색·삽입·삭제를 평균 O(log n)에 해낼 수 있는 **이진 탐색 트리(Binary Search Tree, BST)**를 만들어 보겠습니다.

## 이진 탐색 트리의 규칙

이진 탐색 트리는 다음 한 가지 규칙을 모든 노드에서 만족하는 이진 트리입니다.

> 각 노드에 대해, **왼쪽 서브트리에 있는 모든 값은 그 노드의 값보다 작고**, **오른쪽 서브트리에 있는 모든 값은 그 노드의 값보다 크다.**

중요한 점은 이 규칙이 바로 아래 자식뿐 아니라 **서브트리 전체**에 재귀적으로 적용된다는 것입니다. 즉 어떤 노드의 왼쪽 자식의 오른쪽 자식이라도, 그 값은 여전히 최상위 노드보다 작아야 합니다. (중복 값을 허용할지는 구현에 따라 다르지만, 이 장에서는 중복 값이 없다고 가정합니다.)

이 규칙 덕분에 값을 찾을 때마다 "찾는 값이 현재 노드보다 작은가, 큰가"만 비교하면 왼쪽과 오른쪽 중 어느 쪽을 볼지 즉시 알 수 있습니다. 마치 이진 탐색(16장에서 다시 다룹니다)을 트리 구조 위에서 수행하는 것과 같습니다.

또한 이 규칙의 자연스러운 결과로, **BST를 중위 순회(inorder)하면 값이 항상 오름차순으로 나열됩니다.** 왼쪽(더 작은 값들) → 노드 → 오른쪽(더 큰 값들) 순서로 방문하기 때문입니다. 이는 나중에 정렬된 목록이 필요할 때 유용하게 쓰입니다.

## BinarySearchTree&lt;T&gt; 구현하기

BST의 노드는 7장의 `TreeNode<T>`를 그대로 재사용할 수 있습니다. 다만 값들을 비교해야 하므로, `T`가 `IComparable<T>`를 구현한다는 제약을 둡니다.

```csharp
public class BinarySearchTree<T> where T : IComparable<T>
{
    private TreeNode<T>? _root;

    public int Count { get; private set; }
}
```

### 탐색: Contains

탐색은 규칙을 그대로 따라가면 됩니다. 현재 노드와 찾는 값을 비교해서 같으면 발견, 작으면 왼쪽으로, 크면 오른쪽으로 내려갑니다. 재귀 대신 반복문으로 작성하면 불필요한 함수 호출 오버헤드 없이 구현할 수 있습니다.

```csharp
public bool Contains(T value)
{
    var current = _root;

    while (current is not null)
    {
        int cmp = value.CompareTo(current.Value);

        if (cmp == 0) return true;
        current = cmp < 0 ? current.Left : current.Right;
    }

    return false;
}
```

### 삽입: Insert

삽입도 탐색과 같은 방식으로 내려가다가, 더 내려갈 자리가 없는 지점(즉 `null`을 만나는 지점)에 새 노드를 붙입니다.

```csharp
public void Insert(T value)
{
    _root = InsertRecursive(_root, value);
}

private TreeNode<T> InsertRecursive(TreeNode<T>? node, T value)
{
    if (node is null)
    {
        Count++;
        return new TreeNode<T>(value);
    }

    int cmp = value.CompareTo(node.Value);

    if (cmp < 0)
        node.Left = InsertRecursive(node.Left, value);
    else if (cmp > 0)
        node.Right = InsertRecursive(node.Right, value);
    // cmp == 0이면 이미 존재하는 값이므로 아무 것도 하지 않음(중복 무시)

    return node;
}
```

`InsertRecursive`가 노드를 반환하고 호출한 쪽에서 그 결과를 다시 `Left`나 `Right`에 대입하는 패턴에 주목하세요. 이렇게 하면 "부모의 어느 쪽 자식 링크를 갱신해야 하는가"를 부모 노드 쪽 코드가 아니라 재귀 호출의 반환값이 자동으로 처리해 주므로, 삭제처럼 더 복잡한 연산에서도 같은 패턴을 재사용할 수 있습니다.

### 중위 순회로 정렬된 값 뽑기

7장에서 만든 중위 순회를 그대로 가져와, BST 안의 모든 값을 오름차순으로 얻을 수 있습니다.

```csharp
public List<T> InOrderTraversal()
{
    var result = new List<T>();
    InOrder(_root, result);
    return result;
}

private void InOrder(TreeNode<T>? node, List<T> result)
{
    if (node is null) return;

    InOrder(node.Left, result);
    result.Add(node.Value);
    InOrder(node.Right, result);
}
```

### 삭제: Delete

삭제는 BST 연산 중 가장 까다롭습니다. 삭제하려는 노드의 자식이 몇 개인지에 따라 세 가지 경우로 나뉘기 때문입니다.

1. **자식이 없는 경우(리프)**: 그냥 그 노드를 제거하면 됩니다. 부모의 해당 자식 링크를 `null`로 만듭니다.
2. **자식이 하나인 경우**: 그 노드를 지우고, 있는 자식을 부모에게 직접 연결합니다.
3. **자식이 둘인 경우**: 노드를 그냥 지워버리면 왼쪽·오른쪽 서브트리를 다시 연결할 방법이 마땅치 않습니다. 대신 **오른쪽 서브트리에서 가장 작은 값(중위 후속자, in-order successor)**을 찾아 그 값을 현재 노드에 복사하고, 그다음 오른쪽 서브트리에서 그 후속자 노드를 삭제합니다. 후속자는 정의상 왼쪽 자식이 없으므로, 이 삭제는 경우 1이나 2로 환원되어 재귀적으로 간단히 처리됩니다.

```csharp
public void Delete(T value)
{
    _root = DeleteRecursive(_root, value);
}

private TreeNode<T>? DeleteRecursive(TreeNode<T>? node, T value)
{
    if (node is null) return null;

    int cmp = value.CompareTo(node.Value);

    if (cmp < 0)
    {
        node.Left = DeleteRecursive(node.Left, value);
    }
    else if (cmp > 0)
    {
        node.Right = DeleteRecursive(node.Right, value);
    }
    else
    {
        // 찾았다: node가 삭제 대상

        if (node.Left is null && node.Right is null)
        {
            // 경우 1: 자식 없음
            Count--;
            return null;
        }

        if (node.Left is null)
        {
            // 경우 2: 오른쪽 자식만 있음
            Count--;
            return node.Right;
        }

        if (node.Right is null)
        {
            // 경우 2: 왼쪽 자식만 있음
            Count--;
            return node.Left;
        }

        // 경우 3: 자식이 둘 다 있음
        // 오른쪽 서브트리에서 가장 작은 값(중위 후속자)을 찾는다.
        TreeNode<T> successor = FindMin(node.Right);
        node.Value = successor.Value;

        // 후속자는 왼쪽 자식이 없으므로, 이 삭제는 경우 1이나 2로 처리된다.
        // Count는 이 재귀 호출 안에서 감소한다.
        node.Right = DeleteRecursive(node.Right, successor.Value);
    }

    return node;
}

private TreeNode<T> FindMin(TreeNode<T> node)
{
    while (node.Left is not null)
        node = node.Left;

    return node;
}
```

## 성능: 평균은 빠르지만 최악은 느리다

탐색·삽입·삭제 모두 루트에서 시작해 트리의 높이만큼만 내려가면 되므로, 시간 복잡도는 **O(h)** (h는 트리의 높이)입니다. 값이 무작위 순서로 들어온다면 트리는 대체로 균형 잡힌 모양이 되어 h가 log₂(n)에 가까워지고, 결과적으로 평균 **O(log n)** 성능을 얻습니다. n이 100만이어도 높이는 20 정도에 불과하다는 뜻입니다.

문제는 값이 이미 정렬된 순서(또는 정렬에 가까운 순서)로 삽입될 때입니다. 예를 들어 1, 2, 3, 4, 5, 6, 7을 순서대로 `Insert`하면, 각 값은 항상 이전 값보다 크므로 매번 오른쪽 자식으로만 내려가게 되어 트리가 사실상 오른쪽으로 늘어진 연결 리스트 모양이 됩니다. 이런 트리를 **편향 트리(skewed tree)**라고 하며, 높이가 n-1이 되어 탐색·삽입·삭제가 모두 **O(n)**으로 나빠집니다. 애써 트리를 쓴 의미가 사라지는 최악의 시나리오인 셈입니다.

이 문제를 해결하려면 삽입·삭제 과정에서 트리가 항상 균형을 유지하도록 스스로 재조정하는 장치가 필요합니다. 9장에서는 AVL 트리와 레드-블랙 트리를 통해, 이 장의 BST에 회전(rotation)이라는 연산을 추가해서 높이를 항상 O(log n)으로 묶어두는 방법을 다룹니다.

## .NET BCL에서 찾아보기

.NET BCL에서 BST의 개념을 직접 실무에 활용하고 싶다면, 이 장에서 만든 것과 같은 이진 탐색 트리를 직접 구현하기보다 `System.Collections.Generic` 네임스페이스의 `SortedSet<T>`와 `SortedDictionary<TKey, TValue>`를 사용하는 것이 일반적입니다. 이 두 컬렉션은 항상 정렬된 상태를 유지하면서 삽입·삭제·탐색을 로그 시간에 처리하도록 구현되어 있으며, 내부적으로 균형 이진 탐색 트리의 한 종류인 레드-블랙 트리를 사용하는 것으로 알려져 있습니다. 즉 이 장에서 겪은 "편향 트리로 성능이 나빠지는" 문제를, BCL의 정렬된 컬렉션들은 이미 내부적으로 해결해 둔 상태로 제공합니다. 이 균형 유지 메커니즘의 원리는 9장에서 이어서 다룹니다.

## 요약

- 이진 탐색 트리는 모든 노드에서 "왼쪽 서브트리 < 노드 < 오른쪽 서브트리" 규칙을 만족하는 이진 트리입니다.
- 이 규칙 덕분에 탐색과 삽입은 현재 노드와 값을 비교해 왼쪽/오른쪽으로 내려가기만 하면 되고, 중위 순회는 항상 오름차순 결과를 만듭니다.
- 삭제는 자식 개수(0개/1개/2개)에 따라 세 가지 경우로 나뉘며, 자식이 둘인 경우는 중위 후속자(오른쪽 서브트리의 최솟값)로 값을 대체한 뒤 후속자를 재귀적으로 삭제해 처리합니다.
- 평균적으로 트리의 높이가 log₂(n)에 가까워 O(log n) 성능을 내지만, 정렬된 순서로 삽입하면 편향 트리가 되어 최악의 경우 O(n)까지 나빠질 수 있습니다.
- BCL의 `SortedSet<T>`, `SortedDictionary<TKey, TValue>`는 내부적으로 균형 이진 탐색 트리(레드-블랙 트리)를 사용해 이 편향 문제를 이미 해결한 상태로 제공합니다. 균형을 유지하는 원리는 9장에서 다룹니다.

## 연습문제

1. 트리에서 최솟값과 최댓값을 반환하는 `FindMin()`, `FindMax()` 메서드를 `BinarySearchTree<T>`에 추가하세요. (본문의 `Delete`에서 쓰인 `FindMin`을 참고하되, 공개 메서드로 만들어 보세요.)
2. 주어진 이진 트리가 유효한 이진 탐색 트리인지 검사하는 `IsValidBst<T>(TreeNode<T>? root)`를 작성하세요. 단순히 "왼쪽 자식 < 노드 < 오른쪽 자식"만 확인하면 안 되고, 서브트리 전체에 대해 허용 가능한 값의 범위를 재귀적으로 좁혀가며 검사해야 함에 유의하세요.
3. 중위 순회를 활용해 BST에서 k번째로 작은 값을 찾는 `KthSmallest(int k)` 메서드를 작성하세요.
4. 1부터 7까지의 값을 정렬된 순서로 `Insert`했을 때와, 4, 2, 6, 1, 3, 5, 7 순서(균형 잡힌 순서)로 `Insert`했을 때 각각 트리의 높이가 어떻게 되는지 직접 그려서 비교하고, 왜 차이가 나는지 설명해 보세요.
5. 두 값 `low`, `high`가 주어졌을 때 그 범위 안에 속하는 노드의 개수를 세는 `CountInRange(T low, T high)` 메서드를 작성하세요. BST의 규칙을 이용하면 범위를 벗어나는 서브트리 전체를 건너뛸 수 있다는 점을 활용해 보세요.
