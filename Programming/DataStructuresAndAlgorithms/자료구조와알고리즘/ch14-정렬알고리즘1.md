지금까지 배운 자료구조들은 대부분 데이터를 "어떻게 저장하고 접근할 것인가"에 관한 것이었습니다. 이 장부터는 저장된 데이터를 "어떤 순서로 재배열할 것인가"라는 문제, 즉 **정렬(sorting)**을 다룹니다. 정렬은 그 자체로 실용적인 문제일 뿐 아니라, 8장의 이진 탐색 트리나 16장의 이진 탐색처럼 "정렬되어 있다"는 전제 위에서 동작하는 다른 알고리즘의 기반이 되기도 합니다. 이 장에서는 원리를 이해하기 쉬운 기초 정렬 알고리즘 세 가지 — 버블 정렬, 선택 정렬, 삽입 정렬 — 을 직접 구현하고, 이들이 왜 실무에서 그대로 쓰이지는 않는지 살펴봅니다.

## 14.1 정렬 문제 정의하기

정렬 문제는 간단히 말해 다음과 같습니다.

> 원소들의 목록이 주어졌을 때, 이를 특정 기준(예: 오름차순)에 따라 순서대로 재배열하라.

이 책의 모든 예제에서는 정수 배열을 오름차순으로 정렬하는 것을 기본으로 삼습니다. 실제로는 문자열, 사용자 정의 객체 등 무엇이든 정렬 대상이 될 수 있고, 비교 기준도 오름차순뿐 아니라 내림차순이나 임의의 규칙일 수 있습니다. 이런 일반화는 알고리즘의 핵심 원리를 이해한 뒤에 `IComparable`이나 델리게이트로 얼마든지 확장할 수 있으므로, 이 장에서는 `int[]`를 오름차순으로 정렬하는 데 집중합니다.

정렬 알고리즘을 평가할 때 보는 기준은 다음과 같습니다.

- **시간 복잡도**: 원소 개수 n에 비례해 비교와 교환이 몇 번 일어나는가.
- **공간 복잡도**: 정렬을 위해 원본 배열 외에 추가 메모리가 얼마나 필요한가. 추가 메모리를 거의 쓰지 않는 정렬을 **제자리 정렬(in-place sort)**이라 부릅니다.
- **안정성(stability)**: 값이 같은 두 원소의 상대적 순서가 정렬 후에도 유지되는가.

이 장에서 다루는 세 알고리즘은 모두 제자리 정렬이며, 모두 O(n²) 시간이 걸립니다. 다음 15장에서는 이보다 빠른 O(n log n) 알고리즘들을 다룰 것입니다.

## 14.2 버블 정렬: 인접한 원소를 비교하며 교환하기

버블 정렬(bubble sort)의 아이디어는 배열을 처음부터 끝까지 훑으면서, 인접한 두 원소가 순서에 어긋나 있으면(왼쪽이 오른쪽보다 크면) 서로 교환하는 것입니다. 이 과정을 한 번 끝내면 가장 큰 원소가 물방울처럼 배열 맨 끝까지 밀려 올라갑니다. 이런 "한 바퀴 훑기"를 배열 전체가 정렬될 때까지 반복합니다.

```csharp
public void BubbleSort(int[] arr)
{
    int n = arr.Length;
    for (int pass = 0; pass < n - 1; pass++)
    {
        bool swapped = false;

        // 매 회전이 끝날 때마다 뒤쪽 pass개는 이미 정렬 완료된 상태
        for (int i = 0; i < n - 1 - pass; i++)
        {
            if (arr[i] > arr[i + 1])
            {
                (arr[i], arr[i + 1]) = (arr[i + 1], arr[i]); // 튜플 교환
                swapped = true;
            }
        }

        // 한 바퀴 도는 동안 교환이 한 번도 없었다면 이미 정렬된 상태
        if (!swapped) break;
    }
}
```

`swapped` 플래그는 최적화를 위한 장치입니다. 만약 어느 한 바퀴에서 교환이 전혀 일어나지 않았다면 배열은 이미 정렬된 상태이므로, 남은 바깥 반복을 모두 건너뛰고 즉시 종료할 수 있습니다. 이 덕분에 이미 정렬된 배열이나 거의 정렬된 배열에 대해서는 버블 정렬이 O(n)까지 빨라질 수 있습니다.

**시간 복잡도**: 최악의 경우(역순 배열)와 평균적인 경우 모두 O(n²)입니다. 바깥 루프가 n번, 안쪽 루프가 매번 최대 n번 실행되기 때문입니다. 최선의 경우(이미 정렬됨)는 위 최적화 덕분에 O(n)입니다.

## 14.3 선택 정렬: 매번 최솟값을 찾아 앞으로

선택 정렬(selection sort)은 버블 정렬과 다른 전략을 씁니다. 매 단계마다 "아직 정렬되지 않은 구간에서 가장 작은 원소"를 찾아서, 그 구간의 맨 앞과 교환합니다. 이렇게 하면 정렬된 구간이 앞에서부터 한 칸씩 늘어납니다.

```csharp
public void SelectionSort(int[] arr)
{
    int n = arr.Length;
    for (int i = 0; i < n - 1; i++)
    {
        int minIndex = i;

        // [i, n-1] 구간에서 최솟값의 인덱스를 찾는다
        for (int j = i + 1; j < n; j++)
        {
            if (arr[j] < arr[minIndex])
            {
                minIndex = j;
            }
        }

        // 최솟값을 구간의 맨 앞(i)과 교환
        if (minIndex != i)
        {
            (arr[i], arr[minIndex]) = (arr[minIndex], arr[i]);
        }
    }
}
```

선택 정렬의 특징은 **교환 횟수가 최대 n-1번으로 고정**되어 있다는 점입니다. 버블 정렬은 원소마다 여러 번 교환이 일어날 수 있지만, 선택 정렬은 매 바깥 반복에서 교환이 딱 한 번(또는 이미 제자리라면 0번)만 일어납니다. 그래서 교환 자체의 비용이 크다면(예: 원소 크기가 매우 큰 구조체) 선택 정렬이 유리할 수 있습니다. 반면 비교 횟수는 버블 정렬과 마찬가지로 항상 대략 n²/2번이 필요하며, 이미 정렬된 배열이라도 최솟값을 찾기 위해 안쪽 루프를 전부 순회해야 하므로 버블 정렬과 달리 조기 종료 최적화가 없습니다.

**시간 복잡도**: 최선, 평균, 최악 모든 경우에 O(n²)입니다. 비교 횟수가 입력 상태와 무관하게 항상 일정하기 때문입니다.

## 14.4 삽입 정렬: 정렬된 부분에 하나씩 끼워넣기

삽입 정렬(insertion sort)은 카드 게임에서 손에 든 카드를 정렬할 때 사람이 자연스럽게 하는 방식과 비슷합니다. 배열의 왼쪽 부분은 이미 정렬되어 있다고 가정하고, 그 오른쪽에 있는 다음 원소를 꺼내어 정렬된 부분의 올바른 위치에 끼워 넣습니다.

```csharp
public void InsertionSort(int[] arr)
{
    int n = arr.Length;
    for (int i = 1; i < n; i++)
    {
        int key = arr[i];      // 끼워 넣을 원소
        int j = i - 1;

        // key보다 큰 원소들을 한 칸씩 오른쪽으로 밀어낸다
        while (j >= 0 && arr[j] > key)
        {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;       // 빈 자리에 key를 삽입
    }
}
```

`arr[0]`은 길이 1짜리 배열이므로 이미 "정렬된 상태"로 취급하고, `i = 1`부터 시작해서 오른쪽 원소를 하나씩 정렬된 부분에 끼워 넣습니다. 이 과정은 3장에서 다룬 동적 배열의 `InsertAt` 연산과 본질적으로 같습니다. 삽입할 위치를 찾을 때까지 원소들을 한 칸씩 뒤로 미는 것입니다.

**시간 복잡도**: 최악의 경우(역순 배열)는 O(n²)이지만, **최선의 경우(이미 정렬된 배열)는 O(n)**입니다. 이미 정렬되어 있다면 `while` 루프의 조건(`arr[j] > key`)이 매번 즉시 거짓이 되어 안쪽 루프가 사실상 실행되지 않기 때문입니다.

이 특성 덕분에 삽입 정렬은 세 알고리즘 중 유일하게 **실전에서도 여전히 쓰임새가 있습니다.**

- **데이터 크기가 작을 때**: n이 작으면 O(n²)과 O(n log n)의 차이가 무시할 만한 수준이고, 삽입 정렬은 구현이 단순해서 상수 계수가 작습니다. 그래서 15장에서 배울 병합 정렬이나 퀵 정렬 같은 고급 알고리즘도, 내부적으로 아주 작은 구간을 처리할 때는 삽입 정렬로 전환하는 하이브리드 전략을 쓰는 경우가 많습니다.
- **데이터가 거의 정렬되어 있을 때**: 실시간으로 들어오는 데이터를 정렬된 목록에 하나씩 추가해야 하는 상황(예: 정렬된 로그에 새 항목 삽입)에서는 삽입 정렬이 O(n)에 가까운 성능을 보입니다.

## 14.5 세 알고리즘 비교와 왜 실무에서 잘 안 쓰이는가

세 알고리즘을 정리하면 다음과 같습니다.

| 알고리즘 | 최선 | 평균 | 최악 | 안정성 | 특징 |
|---|---|---|---|---|---|
| 버블 정렬 | O(n) | O(n²) | O(n²) | 안정 | 구현이 가장 직관적, 교환이 잦음 |
| 선택 정렬 | O(n²) | O(n²) | O(n²) | 불안정* | 교환 횟수가 최대 n-1번으로 적음 |
| 삽입 정렬 | O(n) | O(n²) | O(n²) | 안정 | 거의 정렬된 데이터·작은 데이터에 강함 |

\* 선택 정렬은 최솟값을 먼 위치에서 가져와 앞과 교환하는 과정에서 같은 값을 가진 원소들의 상대적 순서가 뒤바뀔 수 있어 일반적으로 불안정한 정렬로 분류됩니다.

세 알고리즘 모두 평균과 최악의 경우 O(n²)이라는 한계를 갖습니다. n이 1,000이면 백만 번, n이 100만이면 1조 번에 가까운 연산이 필요할 수 있다는 뜻입니다. 반면 15장에서 배울 병합 정렬이나 퀵 정렬 같은 알고리즘은 "분할 정복" 전략(17장에서 더 깊이 다룰 개념)을 이용해 평균적으로 O(n log n)의 시간 복잡도를 달성합니다. n이 100만일 때 n²은 10¹²이지만 n log n은 약 2천만 정도로, 그 격차는 데이터가 커질수록 압도적으로 벌어집니다.

그렇다고 이 장에서 배운 알고리즘이 무의미한 것은 아닙니다. 원리가 단순해서 정렬이라는 문제 자체를 이해하기에 좋은 출발점이고, 앞서 언급했듯 삽입 정렬은 작은 데이터나 거의 정렬된 데이터라는 특수한 상황에서는 여전히 실전에서 선택되는 알고리즘입니다. 반면 버블 정렬과 선택 정렬은 그런 이점조차 뚜렷하지 않아, 교육적 목적을 넘어서는 실무 사용은 드뭅니다.

## .NET BCL에서 찾아보기

`Array.Sort`와 `List<T>.Sort`는 내부적으로 이 장에서 다룬 O(n²) 알고리즘이 아니라, 훨씬 빠른 정렬 알고리즘(introspective sort 계열)을 사용합니다. 다만 그 구현체도 원소 개수가 아주 적은 구간에 대해서는 내부적으로 삽입 정렬과 유사한 방식으로 전환해 상수 계수를 줄이는 최적화를 적용하는 것으로 알려져 있습니다. 즉 이 장에서 배운 삽입 정렬의 아이디어가 실제 BCL 구현의 세부 전략 안에도 녹아 있는 셈입니다.

```csharp
int[] numbers = { 5, 2, 8, 1, 9 };
Array.Sort(numbers);
// numbers는 이제 { 1, 2, 5, 8, 9 }

var list = new List<int> { 5, 2, 8, 1, 9 };
list.Sort();
// list는 이제 { 1, 2, 5, 8, 9 }
```

`Array.Sort`와 `List<T>.Sort`가 구체적으로 어떤 알고리즘을 어떻게 조합해서 O(n log n) 성능을 내는지는 다음 15장에서 병합 정렬과 퀵 정렬을 직접 구현해 본 뒤에 자세히 살펴보겠습니다.

## 요약

- 정렬은 원소들을 정해진 기준에 따라 재배열하는 문제이며, 시간 복잡도·공간 복잡도(제자리 정렬 여부)·안정성이 알고리즘을 평가하는 기준이 된다.
- 버블 정렬은 인접한 원소를 비교·교환하며 큰 값을 뒤로 밀어내는 방식으로, 평균·최악 O(n²)이지만 조기 종료 최적화로 이미 정렬된 데이터에는 O(n)까지 빨라진다.
- 선택 정렬은 매번 최솟값을 찾아 앞으로 가져오는 방식으로, 교환 횟수가 최대 n-1번으로 적지만 비교 횟수는 항상 O(n²)로 고정되어 최선의 경우 최적화가 없다.
- 삽입 정렬은 정렬된 부분에 원소를 하나씩 끼워 넣는 방식으로, 최악은 O(n²)지만 이미 정렬되었거나 거의 정렬된 데이터에는 O(n)에 가까워 실전에서도 여전히 쓰인다.
- 세 알고리즘 모두 평균 O(n²)의 한계 때문에 대용량 데이터에는 부적합하며, 15장에서 다룰 O(n log n) 알고리즘(병합 정렬, 퀵 정렬)이 실무의 기본 선택지가 된다.

## 연습문제

2. 선택 정렬에서 "최댓값을 찾아 맨 뒤와 교환"하는 방식으로 바꿔도 정렬이 똑같이 동작할까요? 코드를 수정해서 확인해 보세요.
