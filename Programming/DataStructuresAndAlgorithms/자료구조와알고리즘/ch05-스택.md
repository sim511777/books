## 들어가며

앞선 두 장에서 우리는 데이터를 순서대로 저장하는 두 가지 방법, 즉 배열과 연결 리스트를 살펴봤다. 이번 장에서 다룰 스택(Stack)은 그 자체로 새로운 저장 방식이라기보다는, 배열이나 연결 리스트 위에 "데이터를 넣고 빼는 규칙"을 하나 얹은 자료구조다. 그 규칙은 단순하다. 가장 나중에 넣은 데이터를 가장 먼저 꺼낸다. 이것을 LIFO(Last In First Out)라고 부른다.

책상 위에 쌓아 올린 접시 더미를 떠올려 보자. 새 접시는 항상 맨 위에 올려놓고, 접시를 쓸 때도 맨 위에서부터 집어 든다. 맨 아래에 깔린 접시를 꺼내려면 위에 있는 접시를 전부 치워야 한다. 스택은 정확히 이 접시 더미와 같은 방식으로 동작한다.

## LIFO 원리와 스택의 인터페이스

스택이 지원하는 연산은 놀라울 만큼 적다.

- `Push(item)`: 스택의 맨 위에 새 데이터를 추가한다.
- `Pop()`: 스택의 맨 위 데이터를 제거하고 그 값을 반환한다.
- `Peek()`: 맨 위 데이터를 제거하지 않고 값만 확인한다.
- `IsEmpty`: 스택이 비어 있는지 확인한다.

중요한 점은 스택은 중간이나 맨 아래 데이터에 직접 접근하는 방법을 제공하지 않는다는 것이다. 오직 맨 위(Top)에서만 데이터가 드나든다. 이 제약이 오히려 스택을 유용하게 만든다. "가장 최근 작업을 되돌린다", "가장 안쪽 괄호부터 확인한다"처럼 순서를 거꾸로 되짚어야 하는 문제들이 이 제약과 정확히 들어맞기 때문이다.

## 연결 리스트로 스택 구현하기

4장에서 만든 연결 리스트의 구조를 그대로 재활용하면 스택을 아주 자연스럽게 구현할 수 있다. 핵심 아이디어는 연결 리스트의 머리(Head) 부분을 스택의 Top으로 삼는 것이다. 머리에 노드를 추가하고 제거하는 연산은 두 경우 모두 O(1)이므로, Push와 Pop 모두 상수 시간에 끝난다.

```csharp
using System;

namespace DataStructures
{
    // 스택 전용 단일 연결 리스트 노드
    internal class StackNode<T>
    {
        public T Value { get; }
        public StackNode<T>? Next { get; set; }

        public StackNode(T value, StackNode<T>? next = null)
        {
            Value = value;
            Next = next;
        }
    }

    // 연결 리스트 기반 스택 구현
    public class LinkedStack<T>
    {
        private StackNode<T>? _top; // 스택의 맨 위를 가리키는 참조
        private int _count;

        public int Count => _count;
        public bool IsEmpty => _count == 0;

        // 맨 위에 새 값을 추가한다. O(1)
        public void Push(T value)
        {
            _top = new StackNode<T>(value, _top);
            _count++;
        }

        // 맨 위 값을 제거하고 반환한다. O(1)
        public T Pop()
        {
            if (_top is null)
                throw new InvalidOperationException("스택이 비어 있습니다.");

            T value = _top.Value;
            _top = _top.Next;
            _count--;
            return value;
        }

        // 맨 위 값을 제거하지 않고 확인한다. O(1)
        public T Peek()
        {
            if (_top is null)
                throw new InvalidOperationException("스택이 비어 있습니다.");

            return _top.Value;
        }
    }
}
```

`_top`이 항상 가장 최근에 Push된 노드를 가리키고, `Pop`은 그 노드를 떼어내면서 `Next`로 참조를 옮기기만 하면 된다. 배열처럼 요소를 옮기거나 크기를 조정할 필요가 전혀 없다.

## 동적 배열로 스택 구현하기

3장에서 만든 동적 배열을 이용해도 스택을 구현할 수 있다. 이번에는 배열의 끝(마지막 인덱스)을 Top으로 삼는다. 배열 끝에 요소를 추가하거나 제거하는 연산은 평균적으로 O(1)이기 때문에(용량이 가득 차서 재할당이 일어나는 순간만 O(n)), 스택의 동작 방식과 잘 맞는다.

```csharp
public class ArrayStack<T>
{
    private T[] _items = new T[4];
    private int _count;

    public int Count => _count;
    public bool IsEmpty => _count == 0;

    public void Push(T value)
    {
        if (_count == _items.Length)
        {
            // 용량이 가득 차면 두 배로 늘려 재할당한다 (3장 참고)
            Array.Resize(ref _items, _items.Length * 2);
        }

        _items[_count] = value;
        _count++;
    }

    public T Pop()
    {
        if (_count == 0)
            throw new InvalidOperationException("스택이 비어 있습니다.");

        _count--;
        T value = _items[_count];
        _items[_count] = default!; // 참조를 정리해 메모리 누수를 방지
        return value;
    }

    public T Peek()
    {
        if (_count == 0)
            throw new InvalidOperationException("스택이 비어 있습니다.");

        return _items[_count - 1];
    }
}
```

두 구현 모두 Push와 Pop의 시간 복잡도는 O(1)(배열 쪽은 상환 분석 기준)로 동일하다. 실제 차이는 메모리 사용 패턴에 있다. 배열 기반 구현은 요소들이 메모리에 연속으로 배치되어 캐시 지역성이 좋고 노드마다 참조를 저장할 필요가 없어 오버헤드가 적다. 연결 리스트 기반 구현은 재할당으로 인한 순간적인 지연이 없고, 스택 크기를 예측하기 어려운 상황에서 메모리를 유연하게 사용할 수 있다. 실무에서는 대부분 배열 기반 구현을 사용하는데, 잠시 후 살펴볼 BCL의 `Stack<T>` 역시 배열 기반이다.

## 스택이 실제로 쓰이는 곳

스택은 눈에 잘 띄지 않지만 프로그램 곳곳에서 동작하고 있다.

**함수 호출 스택.** 프로그램이 함수를 호출하면 실행 중이던 위치와 지역 변수 정보가 스택에 쌓이고, 함수가 반환되면 그 정보가 다시 꺼내지며 원래 지점으로 돌아간다. 재귀 함수가 너무 깊이 호출되면 발생하는 `StackOverflowException`도 바로 이 호출 스택이 가득 찼다는 신호다. 이 주제는 17장 재귀와 분할정복에서 다시 자세히 다룬다.

**괄호 짝 검사.** 코드 편집기가 괄호, 중괄호, 대괄호의 짝이 맞는지 실시간으로 검사하는 기능도 스택으로 구현된다. 아래에서 직접 구현해 본다.

**실행 취소(Undo) 기능.** 문서 편집기의 실행 취소는 사용자의 작업을 순서대로 스택에 쌓아 두었다가, Ctrl+Z를 누를 때마다 가장 최근 작업부터 하나씩 꺼내 되돌리는 방식으로 동작한다. 가장 나중에 한 일을 가장 먼저 취소한다는 점에서 전형적인 LIFO 문제다.

## 괄호 짝 검사 알고리즘 구현하기

문자열에 등장하는 `()`, `{}`, `[]`가 올바르게 짝지어져 있는지 검사하는 문제를 생각해 보자. 예를 들어 `"{[()()]}"`는 올바르지만 `"{[(])}"`는 올바르지 않다. 여는 괄호는 스택에 쌓아 두고, 닫는 괄호를 만날 때마다 스택 맨 위와 짝이 맞는지 확인하면 된다.

```csharp
public static class BracketChecker
{
    // 문자열의 괄호 짝이 올바른지 검사한다
    public static bool IsBalanced(string expression)
    {
        var stack = new LinkedStack<char>();
        var pairs = new Dictionary<char, char>
        {
            [')'] = '(',
            [']'] = '[',
            ['}'] = '{'
        };

        foreach (char ch in expression)
        {
            if (ch == '(' || ch == '[' || ch == '{')
            {
                stack.Push(ch);
            }
            else if (pairs.ContainsKey(ch))
            {
                // 닫는 괄호인데 스택이 비어 있으면 짝이 없는 것
                if (stack.IsEmpty || stack.Pop() != pairs[ch])
                    return false;
            }
            // 괄호가 아닌 문자는 무시한다
        }

        // 마지막에 스택이 비어 있어야 모든 괄호가 짝지어진 것
        return stack.IsEmpty;
    }
}
```

동작 원리를 짚어 보자. 여는 괄호를 만나면 일단 스택에 넣어 "짝을 기다리는 중"으로 표시한다. 닫는 괄호를 만나면 지금 가장 최근에 열려 있는 괄호, 즉 스택 맨 위와 짝이 맞아야 한다. `"{[(])}"`가 틀린 이유는 `]`를 만났을 때 스택 맨 위가 `(`라서 짝이 맞지 않기 때문이다. 이 알고리즘은 문자열을 한 번만 순회하므로 시간 복잡도는 O(n)이고, 최악의 경우 모든 문자가 여는 괄호라면 공간 복잡도도 O(n)이다.

## .NET BCL에서 찾아보기

지금까지 직접 만들어 본 스택은 실무에서 매번 새로 구현할 필요가 없다. .NET에는 `System.Collections.Generic.Stack<T>`라는 이름으로 이미 완성된 스택 구현이 들어 있다.

```csharp
using System.Collections.Generic;

var stack = new Stack<int>();
stack.Push(10);
stack.Push(20);
stack.Push(30);

int top = stack.Pop();      // 30 반환, 스택에는 10, 20만 남음
int peek = stack.Peek();    // 20을 반환하지만 제거하지는 않음

if (stack.TryPop(out int value))
{
    // 스택이 비어 있지 않았다면 value에 꺼낸 값이 들어온다
}
```

`Stack<T>`는 `Push`, `Pop`, `Peek` 외에도 `TryPop`, `TryPeek`을 제공한다. 이 두 메서드는 스택이 비어 있을 때 예외를 던지는 대신 `false`를 반환하므로, 예외 처리 없이 안전하게 값을 꺼내고 싶을 때 유용하다. 그리고 앞서 살펴본 것처럼 `Stack<T>`는 내부적으로 배열을 기반으로 구현되어 있어서, 우리가 만든 `ArrayStack<T>`와 동작 방식이 매우 비슷하다.

## 요약

- 스택은 LIFO(Last In First Out) 원칙에 따라 동작하는 자료구조로, `Push`, `Pop`, `Peek` 연산만을 통해 맨 위 데이터에만 접근할 수 있다.
- 연결 리스트의 머리를 Top으로 삼거나, 동적 배열의 끝을 Top으로 삼아 스택을 구현할 수 있으며 두 방식 모두 Push/Pop이 O(1)이다.
- 함수 호출 스택, 괄호 짝 검사, 실행 취소 기능은 모두 "가장 최근 것부터 처리한다"는 LIFO 성질을 활용하는 대표적인 사례다.
- 괄호 짝 검사는 여는 괄호를 스택에 쌓아 두고 닫는 괄호를 만날 때마다 짝을 확인하는 방식으로 O(n)에 해결할 수 있다.
- BCL의 `Stack<T>`는 배열 기반으로 구현되어 있으며 `Push`, `Pop`, `Peek`과 함께 예외 없이 안전하게 사용할 수 있는 `TryPop`, `TryPeek`을 제공한다.

## 연습문제

1. `ArrayStack<T>`에 `Contains(T value)` 메서드를 추가해 보자. 단, Peek처럼 스택의 상태를 변경해서는 안 된다. 시간 복잡도는 얼마인가?
2. 두 개의 스택만을 이용해 큐(먼저 넣은 것을 먼저 꺼내는 자료구조)를 구현할 수 있을까? 가능하다면 `Enqueue`와 `Dequeue`를 어떻게 구현할지 설계해 보자. (힌트: 하나는 입력 전용, 하나는 출력 전용으로 사용한다.)
3. `BracketChecker.IsBalanced`를 확장하여, 괄호가 짝이 맞지 않을 때 몇 번째 문자에서 문제가 발생했는지도 함께 반환하도록 수정해 보자.
4. 정수 배열이 주어졌을 때, 스택을 이용해 각 원소보다 오른쪽에서 처음으로 더 큰 값이 나타나는 위치를 O(n)에 찾는 알고리즘("다음으로 더 큰 원소" 문제)을 설계해 보자.
5. `LinkedStack<T>`와 `ArrayStack<T>` 중 하나를 골라, 100만 개의 정수를 Push한 뒤 모두 Pop하는 데 걸리는 시간을 측정하는 벤치마크 코드를 작성하고 두 구현의 성능을 비교해 보자.
