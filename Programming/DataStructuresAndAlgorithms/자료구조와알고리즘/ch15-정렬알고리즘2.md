## 들어가며: O(n²)의 벽

14장에서는 버블 정렬, 선택 정렬, 삽입 정렬을 살펴보았습니다. 세 알고리즘 모두 구현이 간단하고 작은 데이터에는 충분히 실용적이지만, 최악의 경우는 물론 평균적인 경우에도 O(n²)라는 한계를 벗어나지 못합니다. 원소가 10개일 때는 100번 비교하면 끝나지만, 100만 개가 되면 1조 번에 가까운 비교가 필요합니다. 데이터가 커질수록 이 차이는 감당할 수 없는 수준으로 벌어집니다.

이번 장에서는 "전체를 통째로 정렬하지 말고, 문제를 잘게 쪼개서 정렬하자"는 발상의 전환으로 O(n log n)을 달성하는 두 알고리즘, 병합 정렬과 퀵 정렬을 다룹니다. 두 알고리즘 모두 17장에서 본격적으로 다룰 "분할 정복(divide and conquer)" 전략의 대표적인 예시이기도 합니다. 지금은 정렬이라는 구체적인 문제를 통해 분할 정복의 감각을 먼저 익힌다고 생각하면 됩니다.

## 병합 정렬: 나누고, 정렬하고, 합친다

병합 정렬(merge sort)의 핵심 아이디어는 단순합니다. 배열을 절반으로 나누고, 각 절반을 재귀적으로 정렬한 다음, 이미 정렬된 두 절반을 하나로 합칩니다. "정렬된 두 배열을 합치는 것"이 "정렬되지 않은 배열 전체를 정렬하는 것"보다 훨씬 쉽다는 점을 이용하는 것입니다.

원소가 하나뿐인 배열은 이미 정렬된 상태이므로, 재귀는 배열의 길이가 1 이하가 될 때 멈춥니다. 이후 병합(merge) 단계에서 두 정렬된 부분을 앞에서부터 비교하며 더 작은 값을 순서대로 꺼내 담습니다.

```csharp
public static class MergeSort
{
    public static void Sort(int[] array)
    {
        if (array.Length <= 1)
        {
            return;
        }

        int[] buffer = new int[array.Length];
        SortRange(array, buffer, 0, array.Length - 1);
    }

    // [left, right] 범위를 재귀적으로 정렬한다.
    private static void SortRange(int[] array, int[] buffer, int left, int right)
    {
        if (left >= right)
        {
            return; // 원소가 0개 또는 1개면 이미 정렬된 상태
        }

        int mid = left + (right - left) / 2;
        SortRange(array, buffer, left, mid);
        SortRange(array, buffer, mid + 1, right);
        Merge(array, buffer, left, mid, right);
    }

    // 정렬된 두 구간 [left, mid], [mid+1, right]를 하나로 합친다.
    private static void Merge(int[] array, int[] buffer, int left, int mid, int right)
    {
        int i = left;      // 왼쪽 구간 포인터
        int j = mid + 1;   // 오른쪽 구간 포인터
        int k = left;      // buffer에 채울 위치

        while (i <= mid && j <= right)
        {
            if (array[i] <= array[j])
            {
                buffer[k++] = array[i++];
            }
            else
            {
                buffer[k++] = array[j++];
            }
        }

        // 한쪽 구간에 남은 원소를 마저 복사한다.
        while (i <= mid) buffer[k++] = array[i++];
        while (j <= right) buffer[k++] = array[j++];

        // 병합 결과를 원본 배열에 되돌려 쓴다.
        for (int p = left; p <= right; p++)
        {
            array[p] = buffer[p];
        }
    }
}
```

`array[i] <= array[j]`에서 등호(`<=`)를 사용한 점에 주목하세요. 값이 같을 때 왼쪽 구간의 원소를 먼저 꺼내도록 하면, 원래 배열에서의 상대적 순서가 그대로 유지됩니다. 이런 성질을 **안정 정렬(stable sort)**이라고 부릅니다. 예를 들어 학생 명단을 이름순으로 정렬한 뒤 다시 학년순으로 정렬했을 때, 같은 학년 안에서는 이름순이 그대로 보존되는 것이 안정 정렬의 효과입니다.

병합 정렬의 시간 복잡도를 따져보면, 배열을 절반으로 나누는 깊이는 log n이고, 각 깊이에서 병합에 드는 총 비용은 n입니다. 따라서 전체 시간 복잡도는 O(n log n)이며, 이는 최선, 평균, 최악의 경우 모두 동일합니다. 다만 병합 과정에서 원본과 같은 크기의 `buffer` 배열을 추가로 사용하므로 공간 복잡도는 O(n)입니다. 이 추가 메모리가 병합 정렬의 가장 큰 단점입니다.

## 퀵 정렬: 피벗을 기준으로 나눈다

퀵 정렬(quick sort)도 분할 정복을 사용하지만 방식이 다릅니다. 배열에서 피벗(pivot)이라는 기준값을 하나 고른 뒤, 피벗보다 작은 값은 왼쪽으로, 큰 값은 오른쪽으로 옮기는 **분할(partition)** 작업을 수행합니다. 분할이 끝나면 피벗은 자신의 최종 위치에 놓이고, 왼쪽 부분과 오른쪽 부분을 각각 재귀적으로 정렬하면 전체가 정렬됩니다.

병합 정렬과 달리 퀵 정렬은 별도의 병합 단계가 없고, 분할 자체가 배열 안에서 값을 교환하는 방식으로 이루어지기 때문에 추가 메모리를 거의 쓰지 않는 제자리(in-place) 정렬입니다.

```csharp
public static class QuickSort
{
    public static void Sort(int[] array)
    {
        SortRange(array, 0, array.Length - 1);
    }

    private static void SortRange(int[] array, int low, int high)
    {
        if (low >= high)
        {
            return;
        }

        int pivotIndex = Partition(array, low, high);
        SortRange(array, low, pivotIndex - 1);
        SortRange(array, pivotIndex + 1, high);
    }

    // 로무토(Lomuto) 분할: 마지막 원소를 피벗으로 사용한다.
    private static int Partition(int[] array, int low, int high)
    {
        int pivot = array[high];
        int boundary = low; // pivot보다 작은 값들이 모일 경계

        for (int i = low; i < high; i++)
        {
            if (array[i] < pivot)
            {
                Swap(array, i, boundary);
                boundary++;
            }
        }

        Swap(array, boundary, high); // 피벗을 제자리에 배치
        return boundary;
    }

    private static void Swap(int[] array, int a, int b)
    {
        int temp = array[a];
        array[a] = array[b];
        array[b] = temp;
    }
}
```

퀵 정렬의 성능은 피벗을 얼마나 잘 고르는지에 달려 있습니다. 피벗이 매번 배열을 절반씩 나눠준다면 병합 정렬처럼 O(n log n)이 되지만, 이미 정렬된 배열에서 마지막 원소를 피벗으로 고르는 경우처럼 한쪽으로만 치우친 분할이 계속되면 재귀 깊이가 n에 달해 최악의 경우 O(n²)까지 나빠질 수 있습니다. 실무에서는 피벗을 무작위로 고르거나, 맨 앞·중간·맨 뒤 세 값의 중앙값을 사용하는 방법으로 이런 최악의 상황을 피합니다.

## 병합 정렬과 퀵 정렬 비교

| 항목 | 병합 정렬 | 퀵 정렬 |
|---|---|---|
| 평균 시간 복잡도 | O(n log n) | O(n log n) |
| 최악 시간 복잡도 | O(n log n) | O(n²) |
| 공간 복잡도 | O(n) 추가 메모리 필요 | O(log n) (재귀 스택) |
| 안정성 | 안정 정렬 | 불안정 정렬 |
| 특징 | 성능이 항상 일정하다 | 평균적으로 빠르고 캐시 친화적이다 |

병합 정렬은 데이터가 어떻게 주어지든 성능이 예측 가능하고, 안정성이 중요한 상황(예: 여러 기준으로 순차 정렬해야 할 때)에 적합합니다. 반면 퀵 정렬은 추가 메모리가 거의 필요 없고 실제 데이터에서 평균적으로 매우 빠르게 동작하지만, 최악의 경우를 항상 염두에 두어야 합니다.

## .NET BCL에서 찾아보기

C#에서 정수 배열을 정렬할 때 우리가 직접 만든 `MergeSort.Sort`나 `QuickSort.Sort`를 쓸 필요는 거의 없습니다. `Array.Sort()`와 `List<T>.Sort()`가 이미 고도로 최적화된 정렬을 제공하기 때문입니다.

```csharp
int[] numbers = { 5, 3, 8, 1, 9, 2 };
Array.Sort(numbers); // { 1, 2, 3, 5, 8, 9 }

var list = new List<int> { 5, 3, 8, 1, 9, 2 };
list.Sort(); // { 1, 2, 3, 5, 8, 9 }
```

흥미로운 점은 이 메서드들이 내부적으로 **인트로소트(introspective sort)**라는 하이브리드 알고리즘을 사용한다는 것입니다. 인트로소트는 이번 장에서 배운 퀵 정렬로 정렬을 시작하되, 재귀 호출 깊이가 지나치게 깊어져 최악의 경우처럼 느려질 조짐이 보이면 10장에서 다룬 힙(heap)을 이용한 힙 정렬로 전환하여 O(n log n)을 보장합니다. 그리고 분할을 거듭하다 부분 배열의 크기가 아주 작아지면, 14장에서 배운 삽입 정렬로 전환합니다. 작은 배열에서는 삽입 정렬의 오버헤드가 퀵 정렬의 재귀 호출보다 오히려 저렴하기 때문입니다.

즉 `Array.Sort()` 한 줄 안에는 14장의 삽입 정렬, 이번 장의 퀵 정렬, 10장의 힙 정렬이 상황에 맞게 조합되어 있는 셈입니다. "평균적으로 가장 빠른 방법을 쓰되, 최악의 경우를 다른 알고리즘으로 보완한다"는 이 설계는 실전 알고리즘 설계에서 매우 흔한 패턴이므로 기억해 둘 만합니다. 참고로 안정성이 필요하다면 `Array.Sort()` 대신 `Enumerable.OrderBy()`처럼 안정 정렬을 보장하는 LINQ 메서드를 사용하는 것이 안전합니다.

## 요약

- 병합 정렬은 배열을 절반씩 나누어 재귀적으로 정렬한 뒤 병합하는 분할 정복 알고리즘으로, 항상 O(n log n)의 안정적인 성능을 보장하지만 O(n)의 추가 메모리가 필요하다.
- 퀵 정렬은 피벗을 기준으로 배열을 분할하는 방식으로, 평균 O(n log n)이지만 피벗 선택이 나쁘면 최악의 경우 O(n²)까지 나빠질 수 있다.
- 병합 정렬은 안정 정렬이고, 퀵 정렬은 일반적으로 불안정 정렬이다.
- 두 알고리즘 모두 17장에서 다룰 분할 정복 전략의 대표 사례다.
- .NET의 `Array.Sort()`/`List<T>.Sort()`는 퀵 정렬, 힙 정렬, 삽입 정렬을 상황에 맞게 조합한 인트로소트를 사용한다.

## 연습문제

1. 병합 정렬에서 `Merge` 단계의 비교 연산자를 `<=`가 아니라 `<`로 바꾸면 어떤 문제가 생기는지, 안정성 관점에서 설명해 보세요.
2. 이미 정렬된 배열 `{1, 2, 3, 4, 5}`를 본문의 `Partition`(항상 마지막 원소를 피벗으로 사용)에 넣으면 재귀 깊이가 어떻게 되는지, 그리고 이를 개선하려면 피벗을 어떻게 골라야 하는지 서술하세요.
3. 병합 정렬을 재귀 없이 반복문만으로 구현하는 상향식(bottom-up) 병합 정렬을 설계해 보세요. (힌트: 부분 배열의 크기를 1, 2, 4, 8, ... 로 두 배씩 늘려가며 병합합니다.)
4. 퀵 정렬의 `Partition` 함수를 응용하면, 정렬을 끝까지 하지 않고도 배열에서 k번째로 작은 값을 O(n) 평균 시간에 찾을 수 있습니다(퀵 셀렉트, quickselect). 이 아이디어를 코드로 구현해 보세요.
5. 원소가 100만 개인 배열에 중복값이 매우 많다고 가정합니다. 이런 경우 병합 정렬과 퀵 정렬 중 어느 쪽이 유리할지, 그리고 왜 그런지 생각해 보세요.
