## 시작하며

8장에서 이진 탐색 트리(BST)를 배우면서 삽입, 삭제, 탐색이 모두 O(log n)에 가능하다고 이야기했습니다. 하지만 여기에는 조건이 하나 숨어 있었습니다. 바로 트리의 높이가 log n 수준으로 낮게 유지된다는 전제입니다. 이 조건이 무너지면 어떤 일이 벌어지는지, 그리고 그 문제를 해결하기 위해 등장한 균형 트리(self-balancing tree)라는 아이디어를 이번 장에서 살펴봅니다.

이번 장은 지금까지의 장들과 다르게 자료구조를 처음부터 끝까지 직접 구현하지 않습니다. 대신 "왜 이런 자료구조가 필요한가"와 "어떤 원리로 동작하는가"에 집중합니다. 실무에서는 이미 검증된 라이브러리 구현을 가져다 쓰는 경우가 대부분이기 때문에, 여기서는 개념을 정확히 이해하고 필요할 때 올바른 도구를 고를 수 있는 안목을 기르는 것을 목표로 합니다.

## 편향 트리 문제 다시 보기

8장에서 만든 이진 탐색 트리에 1, 2, 3, 4, 5를 순서대로 삽입하면 어떤 모양이 될까요? 이진 탐색 트리의 삽입 규칙은 "작으면 왼쪽, 크면 오른쪽"이므로, 오름차순으로 값을 넣으면 모든 노드가 오른쪽 자식만 가지는 모양이 됩니다.

```csharp
// 8장에서 만든 이진 탐색 트리에 오름차순으로 삽입
var tree = new BinarySearchTree<int>();
tree.Insert(1);
tree.Insert(2);
tree.Insert(3);
tree.Insert(4);
tree.Insert(5);

// 결과적으로 만들어지는 모양:
// 1
//  \
//   2
//    \
//     3
//      \
//       4
//        \
//         5
```

이 모양은 사실상 연결 리스트와 다르지 않습니다. 4장에서 배운 연결 리스트에서 특정 값을 찾으려면 처음부터 하나씩 따라가야 했던 것처럼, 이 편향된 트리에서 5를 찾으려면 루트부터 시작해 노드 5개를 모두 거쳐야 합니다.

이진 탐색 트리의 탐색, 삽입, 삭제 연산은 모두 "트리의 높이"에 비례하는 시간이 걸립니다. 균형 잡힌 트리라면 높이가 log n이지만, 편향된 트리라면 높이가 n이 되어버립니다. 즉 최선의 경우 O(log n)이라고 자신 있게 말했던 연산들이, 입력 데이터의 순서에 따라 최악의 경우 O(n)으로 떨어질 수 있다는 뜻입니다. 데이터 100만 개를 순서대로 삽입하기만 해도 탐색 트리가 순식간에 순차 탐색 수준으로 느려질 수 있다는 것이 8장에서 남겨둔 숙제였습니다.

## 균형 트리란 무엇인가

**균형 트리(balanced tree)**는 삽입이나 삭제가 일어날 때마다 트리 스스로 구조를 조정해서, 왼쪽 서브트리와 오른쪽 서브트리의 높이 차이가 일정 범위를 넘지 않도록 유지하는 이진 탐색 트리입니다. "자가 균형 이진 탐색 트리(self-balancing binary search tree)"라고도 부릅니다.

핵심 아이디어는 간단합니다. 트리가 한쪽으로 치우치려는 순간, 노드를 재배치해서 높이를 다시 낮춰줍니다. 이 재배치 덕분에 데이터를 어떤 순서로 넣더라도 트리의 높이가 항상 log n 수준으로 유지되고, 그 결과 삽입, 삭제, 탐색이 항상 O(log n)을 보장받습니다. "최선의 경우"가 아니라 "항상"이라는 점이 일반 이진 탐색 트리와의 결정적인 차이입니다.

균형을 맞추는 구체적인 방법은 자료구조마다 다르지만, 대표적으로 AVL 트리와 레드-블랙 트리 두 가지를 살펴보겠습니다.

## 회전: 균형을 맞추는 기본 동작

균형 트리들이 공통으로 사용하는 핵심 연산이 **회전(rotation)**입니다. 회전은 트리에 들어 있는 노드들 사이의 부모-자식 관계를 재배치하되, 이진 탐색 트리의 성질(왼쪽은 작은 값, 오른쪽은 큰 값)은 그대로 유지하는 연산입니다.

예를 들어 노드가 오른쪽으로만 치우쳐서 A - B - C 순서로 한 줄로 이어져 있다고 합시다.

```
A
 \
  B
   \
    C
```

이 상태에서 "왼쪽 회전(left rotation)"을 수행하면, B가 새로운 루트가 되고 A는 B의 왼쪽 자식, C는 B의 오른쪽 자식이 되어 다음과 같은 균형 잡힌 모양으로 바뀝니다.

```
   B
  / \
 A   C
```

노드 3개짜리 예시라 극적으로 보이지 않을 수 있지만, 노드 수천, 수만 개짜리 트리에서도 이런 회전을 국소적으로 반복하면 전체 높이를 낮출 수 있습니다. 회전은 상수 시간(O(1))에 끝나는 가벼운 연산이라는 점이 중요합니다. 즉, 삽입이나 삭제 한 번에 회전을 몇 차례 곁들이는 정도의 추가 비용만으로 트리 전체의 균형을 되찾을 수 있습니다.

이 책에서는 회전을 이용해 균형을 재조정하는 알고리즘을 직접 구현하지는 않습니다. 대신 이 아이디어를 바탕으로 만들어진 두 가지 대표적인 균형 트리를 개념 수준에서 소개합니다.

## AVL 트리: 높이 차이로 균형 판단

**AVL 트리**는 1962년에 고안된 최초의 자가 균형 이진 탐색 트리입니다. 이름은 고안자인 Adelson-Velsky와 Landis의 이름에서 따왔습니다.

AVL 트리의 규칙은 명확합니다. 모든 노드에 대해 왼쪽 서브트리의 높이와 오른쪽 서브트리의 높이 차이(이를 균형 인수라고 부릅니다)가 항상 -1, 0, 1 중 하나여야 합니다. 노드를 삽입하거나 삭제해서 이 규칙이 깨지면, 규칙이 깨진 지점을 찾아 회전을 수행해서 균형을 되돌립니다.

이 규칙 덕분에 AVL 트리는 매우 엄격하게 균형이 잡혀 있습니다. 그만큼 탐색 속도는 균형 트리 중에서도 가장 빠른 편에 속하지만, 삽입과 삭제 때마다 균형 인수를 확인하고 필요하면 회전을 여러 차례 수행해야 하므로 삽입과 삭제 비용이 상대적으로 더 듭니다. "탐색이 삽입/삭제보다 훨씬 자주 일어나는 상황"에 적합한 선택입니다.

## 레드-블랙 트리: 색상 규칙으로 균형 판단

**레드-블랙 트리(red-black tree)**는 각 노드에 빨강 또는 검정이라는 색상을 부여하고, 다음과 같은 몇 가지 색상 규칙을 항상 만족하도록 유지하는 균형 트리입니다.

- 루트는 항상 검정이다.
- 빨강 노드의 자식은 항상 검정이다(빨강이 연속으로 나올 수 없다).
- 루트에서 리프까지 가는 모든 경로에 포함된 검정 노드의 개수는 동일하다.

이 규칙들을 지키면 수학적으로 트리의 높이가 log n의 상수 배를 넘지 않는다는 사실이 보장됩니다. AVL 트리만큼 엄격하게 균형을 맞추지는 않지만, 그 대신 삽입과 삭제 시 회전과 색상 변경 횟수가 평균적으로 더 적어서 삽입/삭제가 잦은 상황에서 유리합니다.

AVL 트리와 레드-블랙 트리 모두 결국 "왜 다음 삽입에서도 트리 높이가 log n으로 유지되는가"라는 같은 질문에 답하려는 서로 다른 전략입니다. 어느 쪽이든 목표는 동일합니다. 데이터를 어떤 순서로 넣더라도 탐색, 삽입, 삭제가 O(log n)을 벗어나지 않도록 만드는 것입니다.

## 왜 직접 구현하지 않는가

AVL 트리와 레드-블랙 트리의 회전 로직은 경계 조건이 매우 많고, 삽입 후 균형이 깨지는 경우의 수, 삭제 후 균형이 깨지는 경우의 수가 각각 여러 갈래로 나뉩니다. 한 줄이라도 조건을 놓치면 트리가 깨지거나 성능이 도로 O(n)으로 떨어질 수 있는데, 이런 버그는 데이터가 특정 순서로 들어올 때만 드러나기 때문에 발견하기도 어렵습니다.

그래서 실무에서는 이 자료구조를 처음부터 직접 구현하는 경우가 거의 없습니다. 대신 이미 수십 년간 검증된 라이브러리 구현을 가져다 씁니다. 이 책에서 트리 구조를 직접 만들어보는 이유는 "내부에서 어떤 원리로 동작하는지"를 이해하기 위함이지, 실무 코드에 균형 트리를 직접 구현해 넣기 위함이 아닙니다. 원리를 이해하고 나면, 언제 균형 트리가 필요한지, 그리고 라이브러리가 제공하는 어떤 클래스를 골라야 하는지 판단할 수 있게 됩니다.

## .NET BCL에서 찾아보기

.NET에는 이미 레드-블랙 트리로 구현된 컬렉션이 준비되어 있습니다. `System.Collections.Generic.SortedDictionary<TKey, TValue>`와 `System.Collections.Generic.SortedSet<T>`가 바로 그것입니다.

```csharp
using System.Collections.Generic;

// SortedDictionary<TKey, TValue>는 내부적으로 균형 이진 탐색 트리(레드-블랙 트리)로 구현되어 있다
var scores = new SortedDictionary<string, int>();
scores["charlie"] = 88;
scores["alice"] = 95;
scores["bob"] = 91;

// 삽입 순서와 상관없이 키를 기준으로 정렬된 순서로 순회할 수 있다
// 이는 내부가 트리 구조이기 때문에 가능한 특징이다
foreach (var pair in scores)
{
    System.Console.WriteLine($"{pair.Key}: {pair.Value}");
}
// 출력 순서: alice, bob, charlie (키 기준 정렬)

// SortedSet<T> 역시 같은 원리로 동작하며, 중복 없는 정렬된 집합을 유지한다
var uniqueScores = new SortedSet<int>();
uniqueScores.Add(95);
uniqueScores.Add(88);
uniqueScores.Add(91);
// uniqueScores를 순회하면 88, 91, 95 순으로 나온다
```

두 클래스 모두 내부가 균형 이진 탐색 트리이기 때문에 삽입(`Add`), 삭제(`Remove`), 탐색(`Contains`, 인덱서 접근)이 모두 O(log n)을 보장합니다. 8장에서 본 일반 이진 탐색 트리라면 입력 순서에 따라 이 보장이 깨질 수 있었지만, `SortedDictionary<TKey, TValue>`와 `SortedSet<T>`는 내부적으로 회전을 수행해 항상 균형을 유지하므로 어떤 순서로 데이터를 넣어도 성능이 보장됩니다.

또한 정렬된 순서로 순회할 수 있다는 점도 이 자료구조들이 트리 기반이기 때문에 얻어지는 특징입니다. 만약 정렬 순서 순회가 필요 없고 단순히 키로 값을 찾기만 하면 된다면, 11장에서 배울 해시 테이블 기반의 `Dictionary<TKey, TValue>`나 `HashSet<T>`가 평균적으로 더 빠른 O(1) 탐색을 제공하므로 더 적합할 수 있습니다. "정렬 순서가 필요한가"가 두 계열의 컬렉션을 고르는 중요한 기준입니다.

## 요약

- 이진 탐색 트리는 데이터가 특정 순서(예: 오름차순)로 삽입되면 한쪽으로 치우친 편향 트리가 되어, 높이가 n에 가까워지고 연산 속도가 O(n)으로 떨어질 수 있습니다.
- 균형 트리는 삽입/삭제가 일어날 때마다 스스로 구조를 재조정해서 트리 높이를 항상 log n 수준으로 유지하는 이진 탐색 트리입니다.
- 회전은 이진 탐색 트리의 순서 성질을 유지하면서 노드들의 부모-자식 관계를 재배치하는 O(1) 연산이며, 균형 트리들이 균형을 되찾는 데 공통으로 사용하는 도구입니다.
- AVL 트리는 모든 노드의 좌우 서브트리 높이 차이를 최대 1로 엄격하게 유지하며, 탐색이 잦은 상황에 유리합니다. 레드-블랙 트리는 색상 규칙으로 대략적인 균형을 유지하며, 삽입/삭제가 잦은 상황에 유리합니다.
- 실무에서는 균형 트리를 직접 구현하기보다 `SortedDictionary<TKey, TValue>`, `SortedSet<T>`처럼 이미 검증된 라이브러리 구현을 사용하는 것이 일반적입니다.
