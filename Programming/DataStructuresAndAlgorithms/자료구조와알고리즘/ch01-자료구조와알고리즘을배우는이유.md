# 1장. 자료구조와 알고리즘을 배우는 이유

## 시작하며

프로그래밍을 배우다 보면 "일단 동작하는 코드"를 만드는 것과 "잘 동작하는 코드"를 만드는 것 사이에 큰 차이가 있다는 사실을 깨닫게 됩니다. 변수 몇 개와 반복문만으로도 웬만한 프로그램은 만들 수 있습니다. 하지만 데이터가 수백 개에서 수백만 개로 늘어나는 순간, 어떤 코드는 여전히 매끄럽게 동작하고 어떤 코드는 눈에 띄게 느려지거나 아예 멈춰버립니다. 이 차이를 만드는 것이 바로 **자료구조**와 **알고리즘**입니다.

이 책은 C#을 사용해 자료구조와 알고리즘의 핵심 개념을 처음부터 직접 구현해보면서 배우는 입문서입니다. 이론만 나열하지 않고, 왜 그 자료구조가 필요한지, 어떤 상황에서 어떤 선택을 해야 하는지를 실제 코드와 함께 설명합니다.

## 자료구조란 무엇인가

**자료구조(data structure)**는 데이터를 컴퓨터 메모리에 저장하고 조직화하는 방법입니다. 같은 데이터라도 어떻게 담느냐에 따라 데이터를 추가하고, 찾고, 삭제하는 작업의 효율이 완전히 달라집니다.

예를 들어 학생 100명의 이름을 저장한다고 생각해봅시다. 단순히 순서 없이 나열한 목록에 담을 수도 있고, 이름 순으로 정렬해서 담을 수도 있고, 이름의 첫 글자를 기준으로 분류해서 담을 수도 있습니다. 데이터 자체는 동일하지만, 저장 방식에 따라 "김민수라는 학생이 있는가?"라는 질문에 답하는 속도가 크게 달라집니다.

C#에서 우리가 흔히 사용하는 `List<T>`, `Dictionary<TKey, TValue>`, `Queue<T>`, `Stack<T>` 같은 컬렉션 클래스들이 모두 자료구조입니다. 이 책에서는 이런 클래스들이 내부적으로 어떻게 동작하는지 직접 구현해보면서, 언제 무엇을 골라야 하는지 판단하는 안목을 기릅니다.

## 알고리즘이란 무엇인가

**알고리즘(algorithm)**은 주어진 문제를 해결하기 위한 명확하고 유한한 절차입니다. 정렬, 탐색, 최단 경로 찾기 등은 모두 알고리즘으로 해결하는 대표적인 문제입니다.

중요한 점은, 같은 문제를 푸는 방법이 하나만 있는 것이 아니라는 것입니다. 배열에서 특정 값을 찾는 문제만 해도 처음부터 끝까지 하나씩 확인하는 방법도 있고, 데이터가 정렬되어 있다면 절반씩 범위를 좁혀가는 방법도 있습니다. 두 방법 모두 "정답"을 찾아내지만, 데이터 양이 많아질수록 걸리는 시간에는 하늘과 땅 차이가 생깁니다.

## 왜 선택이 성능을 좌우하는가: 구체적인 예

말로만 설명하면 와닿지 않으니, 실제 코드로 비교해봅시다. 1부터 1,000,000까지의 정수가 들어 있는 데이터에서 특정 숫자를 찾는 상황을 가정합니다.

### 방법 1: 정렬되지 않은 리스트에서 순차 탐색

```csharp
// 리스트를 처음부터 끝까지 하나씩 확인하는 방법
public static bool ContainsBySequentialSearch(List<int> numbers, int target)
{
    // 최악의 경우 리스트의 모든 원소를 다 확인해야 한다
    foreach (var number in numbers)
    {
        if (number == target)
        {
            return true;
        }
    }
    return false;
}
```

이 방법은 데이터가 정렬되어 있든 아니든 상관없이 동작합니다. 하지만 찾는 값이 리스트의 맨 끝에 있거나 아예 없는 경우, 100만 개의 원소를 전부 확인해야 합니다. 데이터가 1,000만 개, 1억 개로 늘어나면 확인해야 할 횟수도 그만큼 늘어납니다.

### 방법 2: 정렬된 배열에서 이진 탐색

```csharp
// 정렬된 배열에서 절반씩 범위를 좁혀가며 찾는 방법
public static bool ContainsByBinarySearch(int[] sortedNumbers, int target)
{
    int low = 0;
    int high = sortedNumbers.Length - 1;

    while (low <= high)
    {
        int mid = low + (high - low) / 2;

        if (sortedNumbers[mid] == target)
        {
            return true;
        }
        else if (sortedNumbers[mid] < target)
        {
            low = mid + 1; // 오른쪽 절반만 탐색
        }
        else
        {
            high = mid - 1; // 왼쪽 절반만 탐색
        }
    }

    return false;
}
```

배열이 정렬되어 있다는 조건만 만족하면, 이 방법은 매번 탐색 범위를 절반으로 줄입니다. 100만 개의 원소 중에서 원하는 값을 찾는 데 최악의 경우에도 약 20번의 비교면 충분합니다. 데이터가 100만 개에서 10억 개로 1,000배 늘어나도 비교 횟수는 겨우 10번 정도만 늘어납니다.

이 두 방법의 차이는 2장에서 배울 **Big-O 표기법**으로 각각 O(n)과 O(log n)이라고 표현합니다. 숫자로 보면 그 차이가 더욱 분명해집니다.

| 데이터 개수 | 순차 탐색 (최악) | 이진 탐색 (최악) |
|---|---|---|
| 1,000 | 1,000번 | 약 10번 |
| 1,000,000 | 1,000,000번 | 약 20번 |
| 1,000,000,000 | 1,000,000,000번 | 약 30번 |

물론 이진 탐색을 쓰려면 배열이 미리 정렬되어 있어야 한다는 전제 조건이 붙습니다. 정렬 자체에도 비용이 들기 때문에, "한 번 정렬해두고 여러 번 검색할 것인가", "한 번만 검색하고 말 것인가"에 따라 어떤 방법이 유리한지가 달라집니다. 이것이 바로 자료구조와 알고리즘 선택에서 항상 등장하는 **트레이드오프(trade-off)**의 예입니다. 정답은 하나가 아니라 "상황에 맞는 답"을 찾는 것입니다.

## 왜 지금 이것을 배워야 하는가

현업에서 실제로 자료구조를 처음부터 직접 구현할 일은 드뭅니다. C#의 `System.Collections.Generic` 네임스페이스에는 이미 잘 만들어진 `List<T>`, `Dictionary<TKey, TValue>`, `LinkedList<T>`, `Queue<T>`, `Stack<T>`, `SortedSet<T>` 등이 준비되어 있습니다. 그런데도 이 개념을 배워야 하는 이유는 다음과 같습니다.

첫째, **어떤 컬렉션을 골라야 하는지 판단하려면 내부 동작을 알아야 합니다.** `List<T>`의 맨 앞에 원소를 추가하는 것과 `LinkedList<T>`의 맨 앞에 원소를 추가하는 것은 성능이 완전히 다릅니다. 이유를 모르면 항상 익숙한 것만 쓰게 되고, 데이터가 커졌을 때 원인 모를 성능 저하에 부딪히게 됩니다.

둘째, **면접과 실무 문제 해결 능력의 기초입니다.** 캐시 설계, 데이터베이스 인덱스, 네트워크 라우팅, 추천 시스템 등 실무의 굵직한 문제들은 결국 자료구조와 알고리즘의 조합으로 해결됩니다.

셋째, **성능 문제를 진단하고 개선하는 능력**은 자료구조와 알고리즘에 대한 이해 없이는 생기지 않습니다. "왜 이 코드가 느린가"를 설명할 수 있어야 "어떻게 고칠 것인가"도 답할 수 있습니다.

## 이 책의 학습 방향

이 책은 다음과 같은 순서로 구성되어 있습니다.

먼저 **2장에서 복잡도 분석(Big-O)**을 배웁니다. 이는 이후 모든 장에서 성능을 이야기할 때 사용하는 공통 언어입니다.

이어서 **3장부터 6장까지는 선형 자료구조**(배열, 연결 리스트, 스택, 큐)를 다룹니다. 가장 기본적이면서도 이후 모든 자료구조의 토대가 됩니다.

**7장부터 10장까지는 트리 기반 자료구조**(이진 트리, 이진 탐색 트리, 균형 트리, 힙)를 다루며, 계층적인 데이터를 효율적으로 다루는 방법을 배웁니다.

**11장은 해시 테이블**, **12장과 13장은 그래프**를 다룹니다. 그래프는 네트워크, 지도, 소셜 관계 등 현실 문제를 모델링하는 강력한 도구입니다.

**14장부터 16장까지는 정렬과 탐색 알고리즘**을 깊이 있게 다루고, **17장과 18장에서는 재귀, 분할 정복, 그리디, 동적 프로그래밍**이라는 문제 해결 전략을 배웁니다.

각 장은 개념 설명 → 직접 구현하는 C# 코드 → .NET 기본 클래스 라이브러리(BCL)에서의 대응물 소개 → 요약과 연습문제 순서로 진행됩니다. 자료구조를 직접 만들어보는 과정을 통해 왜 BCL의 클래스들이 그렇게 설계되었는지 이해하게 될 것입니다.

## .NET BCL에서 찾아보기

이번 장은 개념 소개 장이므로 특정 자료구조나 알고리즘을 다루지 않습니다. 다만 앞서 언급한 `List<T>`, `Dictionary<TKey, TValue>`, `Queue<T>`, `Stack<T>`, `LinkedList<T>`, `SortedSet<T>`, `SortedDictionary<TKey, TValue>` 등은 모두 `System.Collections.Generic` 네임스페이스에 있으며, 앞으로 각 장에서 하나씩 그 내부 원리를 대응시켜 살펴볼 것입니다.

## 요약

- 자료구조는 데이터를 저장하고 조직화하는 방법이며, 같은 데이터라도 저장 방식에 따라 연산 효율이 크게 달라집니다.
- 알고리즘은 문제를 해결하는 절차이며, 같은 문제도 여러 알고리즘으로 풀 수 있고 그 성능 차이는 데이터가 커질수록 극명해집니다.
- 정렬되지 않은 리스트의 순차 탐색과 정렬된 배열의 이진 탐색을 비교하면, 데이터가 커질수록 알고리즘 선택의 중요성이 분명하게 드러납니다.
- 자료구조와 알고리즘을 배우는 이유는 적절한 컬렉션을 선택하는 판단력, 실무 문제 해결 능력, 성능 문제를 진단하고 개선하는 능력을 기르기 위함입니다.
- 이 책은 선형 자료구조 → 트리 → 해시 테이블 → 그래프 → 정렬/탐색 → 문제 해결 전략 순서로 진행되며, 매 장마다 직접 구현과 .NET BCL 대응물을 함께 살펴봅니다.

## 연습문제

1. 자료구조와 알고리즘의 차이를 자신의 언어로 한 문단으로 설명해보세요.
2. 전화번호부 애플리케이션에서 이름으로 전화번호를 찾는 기능을 만든다고 할 때, 데이터를 정렬하지 않은 리스트로 저장하는 경우와 정렬된 배열로 저장하는 경우 각각의 장단점을 생각해보세요.

4. 일상생활에서 "정렬해두면 나중에 찾기 편한" 경험(책장, 옷장, 서류함 등)을 하나 떠올리고, 이를 이진 탐색 개념과 연결해 설명해보세요.
