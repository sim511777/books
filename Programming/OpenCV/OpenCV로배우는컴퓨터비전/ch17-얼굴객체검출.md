## 17.1 "검출"이라는 문제

지금까지 다룬 기법들—색공간 변환, 필터링, 임계처리, 컨투어, 특징점 매칭—은 대부분 이미지 안의 "어떤 패턴"을 수학적으로 다루는 도구였다. 이번 장에서는 이 도구들의 자연스러운 응용 사례 중 하나인 **객체 검출(object detection)**, 그중에서도 가장 널리 쓰이는 예시인 **얼굴 검출(face detection)**을 다룬다.

먼저 용어를 정리해두자. "얼굴 검출"은 이미지 안에 얼굴이 어디에 있는지(사각형 좌표)를 찾아내는 작업이고, "얼굴 인식(face recognition)"은 그 얼굴이 누구인지 식별하는 작업이다. 이 장에서 다루는 것은 전자, 즉 검출이다. 누구의 얼굴인지는 관심 없고, "이 사각형 영역에 얼굴이 있다"는 사실만 판단한다.

얼굴 검출에 접근하는 방법은 크게 두 갈래로 나뉜다.

1. **특징 기반의 고전적 방법**: 이미지의 밝기 패턴에서 사람이 미리 설계한 특징(feature)을 뽑아내고, 그 특징들을 조합한 분류기로 "얼굴이다/아니다"를 판단한다. 이 장에서 다룰 **Haar Cascade**가 대표적이다.
2. **딥러닝 기반 방법**: 대량의 데이터로 학습한 신경망이 특징을 스스로 학습해서 얼굴(또는 다른 객체)을 찾아낸다. 최근 실무에서는 이 방식이 정확도 면에서 압도적으로 우세하다.

`opencv-python`은 이 두 갈래를 모두 지원한다. `cv2.CascadeClassifier`로 대표되는 전통적인 API와, `cv2.dnn` 모듈로 대표되는 딥러닝 추론 API다. 이 장에서는 먼저 Haar Cascade로 얼굴 검출의 기본 흐름을 익히고, 얼굴 안에서 눈을 다시 찾는 계층적 검출로 확장한 뒤, 파라미터 튜닝이 결과에 미치는 영향을 깊이 살펴보고, 마지막으로 `cv2.dnn` 모듈로 사전 학습된 딥러닝 얼굴 검출기를 실제로 동작시켜본다.

## 17.2 Haar Cascade: 밝기 패턴으로 얼굴을 찾는 고전적 방법

Haar Cascade는 2000년대 초반에 제안된 얼굴 검출 알고리즘으로, 지금 기준으로는 오래된 기법이지만 계산이 매우 가볍고 별도의 GPU나 무거운 런타임 없이도 실시간으로 동작한다는 장점 때문에 여전히 임베디드 환경이나 빠른 프로토타이핑에서 종종 쓰인다.

핵심 아이디어는 단순하다. 얼굴에는 "눈 부위는 이마보다 어둡다", "콧대 양옆은 콧대보다 어둡다"처럼 밝기가 대비되는 국소적인 패턴들이 규칙적으로 나타난다. Haar Cascade는 이런 밝기 대비 패턴(Haar-like feature)을 수천 개 정의해두고, 작은 이미지 윈도우 안에서 이 패턴들이 얼마나 들어맞는지를 검사한다. 한 번에 모든 패턴을 다 검사하는 것이 아니라, 계산이 가장 간단하고 걸러내는 효율이 좋은 패턴부터 순서대로 여러 단계(stage)로 나눠 검사하고, 어느 단계에서든 "얼굴이 아니다"라는 판정이 나오면 즉시 그 윈도우를 버리고 다음 위치로 넘어간다. 이렇게 단계를 순차적으로 통과시키는 구조를 "cascade(직렬로 이어진 폭포)"라고 부르며, 배경처럼 명백히 얼굴이 아닌 영역을 초반 몇 단계에서 빠르게 걸러낼 수 있어 전체 탐색이 빨라진다.

이 분류기는 미리 방대한 얼굴/비얼굴 이미지로 학습되어 있고, 그 학습 결과(어떤 패턴을, 어떤 순서로, 어떤 기준값으로 검사할지)가 XML 파일 하나에 통째로 저장되어 있다. 우리가 할 일은 이 XML 파일을 읽어서 분류기를 만들고, 검사하고 싶은 이미지를 넘겨주는 것뿐이다. 모델을 직접 학습시킬 필요가 없다는 점에서, 이는 이미 학습된 모델을 가져와 추론만 수행하는 이 책의 다른 예제들과 성격이 같다.

`opencv-python` 패키지 자체에 대표적인 Haar Cascade XML 파일들이 함께 설치되며, `cv2.data.haarcascades`라는 경로 변수로 그 위치를 바로 얻을 수 있어 별도로 파일을 내려받지 않아도 된다. 이 폴더에는 정면 얼굴용(`haarcascade_frontalface_default.xml`, `haarcascade_frontalface_alt.xml` 등) 외에도 눈(`haarcascade_eye.xml`), 안경을 낀 눈(`haarcascade_eye_tree_eyeglasses.xml`), 웃는 얼굴(`haarcascade_smile.xml`) 등 다양한 용도의 XML 파일이 함께 들어 있다.

```python
import cv2

# 설치된 opencv-python 패키지 안에 내장된 Haar Cascade 폴더 경로를 확인해본다.
print(cv2.data.haarcascades)
# 예: C:\...\site-packages\cv2\data\
```

이 폴더 안의 파일 목록을 직접 확인해보면, 얼굴 검출 하나만으로도 여러 XML 파일 중 상황에 맞는 것을 골라 쓸 수 있다는 사실을 알 수 있다.

## 17.3 슬라이딩 윈도우와 스케일 피라미드

Haar Cascade가 이미지 전체에서 얼굴을 찾는 방식을 좀 더 구체적으로 살펴보자. 분류기 하나는 "고정된 크기의 정사각형(또는 정해진 종횡비의 사각형) 윈도우 안에 얼굴이 있는가"만 판단할 수 있다. 그런데 실제 이미지 속 얼굴은 위치도 다르고 크기도 제각각이다. 그래서 검출기는 다음 두 가지를 반복한다.

- **슬라이딩(sliding)**: 작은 윈도우를 이미지의 왼쪽 위부터 오른쪽 아래까지 조금씩 이동시키며 매 위치마다 "얼굴인가?"를 검사한다.
- **스케일(scale)**: 한 가지 윈도우 크기로 이미지 전체를 다 훑은 다음, 윈도우 크기를 키우거나(또는 이미지를 축소하고 윈도우는 고정한 채) 같은 과정을 반복한다. 이렇게 여러 크기로 반복 검사하는 것을 흔히 "스케일 피라미드를 훑는다"고 표현한다.

이 두 과정을 거치면 같은 얼굴 하나에 대해서도 서로 조금씩 겹치는 여러 개의 사각형이 "얼굴 후보"로 검출되는 경우가 많다. `detectMultiScale`은 이렇게 겹쳐서 나온 후보들을 내부적으로 그룹으로 묶어, 충분히 많은 후보가 겹친 영역만 최종 결과로 남기고 나머지는 걸러낸다.

이 검색 과정은 본질적으로 "같은 연산을 아주 많은 위치·크기 조합에 대해 반복 실행"하는 작업이므로, 이미지 해상도가 커지거나 스케일을 촘촘하게 훑을수록 연산량이 급격히 늘어난다. 다음 절에서 다루는 파라미터들은 결국 이 탐색 범위와 정밀도 사이의 트레이드오프를 조절하는 손잡이라고 이해하면 된다.

## 17.4 `detectMultiScale`의 주요 파라미터 깊게 이해하기

`detectMultiScale`의 시그니처는 다음과 같다.

```python
faces = face_cascade.detectMultiScale(
    image,
    scaleFactor=1.1,
    minNeighbors=3,
    flags=0,
    minSize=None,
    maxSize=None,
)
```

각 파라미터가 실제로 어떤 방식으로 검출 결과(오탐/미탐)에 영향을 주는지 하나씩 짚어보자.

### `scaleFactor`: 스케일 피라미드의 촘촘함

`scaleFactor`는 다음 스케일로 넘어갈 때 검색 윈도우(또는 이미지)를 얼마나 축소·확대할지를 결정하는 비율이다. 예를 들어 1.1이면 각 단계마다 크기를 10%씩 바꿔가며 검사한다.

| `scaleFactor` 값 | 스케일 간격 | 영향 |
|---|---|---|
| 1.03 ~ 1.05 (작음) | 촘촘함 | 다양한 크기의 얼굴을 세밀하게 잡아낼 확률이 높아 미검출이 줄지만, 검사해야 할 스케일 수가 많아져 처리 시간이 크게 늘어난다 |
| 1.1 (기본값 근처) | 중간 | 속도와 검출률 사이의 무난한 절충점으로 가장 흔히 사용된다 |
| 1.3 ~ 1.5 (큼) | 넓음 | 처리 속도는 빨라지지만 스케일 간격 사이에 딱 걸리는 크기의 얼굴을 건너뛰어 미검출이 늘어날 수 있다 |

### `minNeighbors`: 얼굴로 인정하는 기준

슬라이딩+스케일 탐색 과정에서 같은 얼굴 주변에 서로 겹치는 후보 사각형이 여러 개 나오는데, `minNeighbors`는 이 후보들이 최소 몇 개 이상 겹쳐야 하나의 "확정된 얼굴"로 인정할지를 정한다.

| `minNeighbors` 값 | 영향 |
|---|---|
| 0 ~ 2 (작음) | 겹치는 후보가 적어도 얼굴로 인정하므로 검출률(재현율)은 높아지지만, 배경의 복잡한 무늬나 옷 주름 등을 얼굴로 잘못 판정하는 오검출(false positive)이 크게 늘어난다 |
| 4 ~ 6 (중간) | 실무에서 가장 흔히 쓰이는 범위로, 오검출과 미검출이 비교적 균형을 이룬다 |
| 8 ~ 12 (큼) | 아주 많은 후보가 겹쳐야만 인정하므로 오검출은 확실히 줄지만, 조명이 어둡거나 각도가 살짝 기울어져 후보가 적게 나오는 진짜 얼굴까지 함께 놓치는(미검출) 부작용이 생기기 쉽다 |

### `minSize`, `maxSize`: 검출할 얼굴 크기의 범위

`minSize`는 검출할 얼굴의 최소 픽셀 크기이고, `maxSize`는 최대 크기다(튜플 `(width, height)`로 지정).

| 설정 | 영향 |
|---|---|
| `minSize`를 작게(예: `(10, 10)`) | 멀리 있거나 작게 찍힌 얼굴까지 찾으려 하지만, 탐색해야 할 작은 윈도우 개수가 늘어나 느려지고, 작은 배경 무늬를 얼굴로 착각하는 오검출도 늘어난다 |
| `minSize`를 크게(예: `(80, 80)`) | 작은 얼굴(멀리 있는 사람 등)은 확실히 놓치지만, 오검출 후보 자체가 줄어들고 처리 속도가 빨라진다 |
| `maxSize` 지정 | 이미지 안에 있을 수 없는 비정상적으로 큰 후보(예: 배경 전체를 얼굴로 착각한 경우)를 미리 걸러낼 때 유용하다 |

### 실전 튜닝 절차

파라미터에 정답은 없으며, 다음과 같은 순서로 실험적으로 좁혀가는 것이 일반적이다.

1. 먼저 기본값(`scaleFactor=1.1`, `minNeighbors=5` 근처)으로 실행해서 결과를 눈으로 확인한다.
2. **오검출(배경을 얼굴로 잘못 잡음)이 많다면** `minNeighbors`를 올리거나 `minSize`를 키운다.
3. **미검출(진짜 얼굴을 놓침)이 많다면** `minNeighbors`를 낮추거나 `scaleFactor`를 더 작은 값(1.05 등)으로 낮춘다.
4. 2번과 3번은 서로 반대 방향으로 작용하므로, 실제 입력 이미지의 특성(해상도, 얼굴 크기 분포, 조명)에 맞는 값을 여러 번 실행해가며 절충해야 한다.

## 17.5 실전 예제: 얼굴 검출 후 사각형으로 표시하기

이제 위 개념을 실제 코드로 구현해보자. 흐름은 다음과 같다.

1. 이미지를 읽고 그레이스케일로 변환한다(Haar Cascade는 흑백 밝기 패턴만 사용하므로 컬러 정보가 필요 없다).
2. 미리 학습된 XML 모델로 `CascadeClassifier`를 만든다.
3. `detectMultiScale`로 얼굴 사각형 목록을 얻는다.
4. 6장에서 배운 사각형 그리기로 각 얼굴 위치를 원본 컬러 이미지 위에 표시한다.

```python
import cv2

# opencv-python에 내장된 Haar Cascade 경로를 사용한다.
cascade_path = cv2.data.haarcascades + "haarcascade_frontalface_default.xml"
face_cascade = cv2.CascadeClassifier(cascade_path)

if face_cascade.empty():
    raise IOError("Cascade 파일을 불러오지 못했습니다. 경로를 확인하세요.")

img = cv2.imread("people.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

# 필요하다면 14장에서 배운 equalizeHist로 대비를 보정하면 검출률이 좋아질 수 있다.
# gray = cv2.equalizeHist(gray)

faces = face_cascade.detectMultiScale(
    gray,
    scaleFactor=1.1,
    minNeighbors=5,
    minSize=(30, 30),
)

print(f"검출된 얼굴 수: {len(faces)}")

for (x, y, w, h) in faces:
    cv2.rectangle(img, (x, y), (x + w, y + h), (255, 0, 0), 2)

cv2.imshow("Faces", img)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

`detectMultiScale`이 돌려주는 값은 결국 "왼쪽 위 좌표(x, y)와 너비·높이(w, h)"로 구성된 사각형들의 NumPy 배열이며, 이는 3장과 6장에서 이미 다룬 사각형 좌표 표현을 그대로 재사용한 것이다. 검출 결과가 하나도 없을 때 `faces`는 빈 튜플 `()`이 아니라 빈 NumPy 배열이 될 수 있으므로, `len(faces)`로 개수를 확인하는 습관을 들이면 이후 코드에서 `for` 루프를 돌 때 안전하다.

## 17.6 계층적 검출: 얼굴 안에서 눈 찾기

Haar Cascade는 얼굴뿐 아니라 눈, 코, 입처럼 더 작은 부위를 검출하는 전용 XML도 제공한다. 그런데 눈 검출기(`haarcascade_eye.xml`)를 사진 전체에 곧바로 적용하면 어떤 문제가 생길까? 사진 속에는 눈과 비슷한 밝기 대비를 가진 영역(장신구, 배경 무늬, 옷의 단추 등)이 얼굴 바깥에도 많기 때문에 오검출이 크게 늘어난다. 게다가 이미지 전체를 대상으로 눈 크기만한 윈도우를 촘촘히 훑어야 하므로 속도도 느려진다.

이 문제를 해결하는 자연스러운 방법이 **계층적 검출(hierarchical detection)**이다. 먼저 얼굴을 검출하고, 그 얼굴 사각형 "안쪽"만 잘라내어 그 좁은 영역 안에서만 눈을 다시 검출하는 2단계 파이프라인이다. 이렇게 하면 다음과 같은 이점이 생긴다.

- **탐색 공간이 극적으로 줄어든다**: 사진 전체가 아니라 얼굴 크기만한 작은 영역만 훑으므로 훨씬 빠르다.
- **오검출이 크게 줄어든다**: 얼굴이 아닌 배경에는 눈 검출기를 적용하지 않으므로, 배경의 눈과 비슷한 무늬가 걸러질 일이 없다.
- **위치 관계를 활용할 수 있다**: 검출된 눈 좌표는 얼굴 영역 기준 상대 좌표이므로, 필요하면 원본 이미지 좌표로 쉽게 환산해 얼굴 안에서 눈의 상대적 위치(정렬 여부 등)를 분석하는 다음 단계로 이어갈 수 있다.

이 접근은 NumPy 배열 슬라이싱만으로 구현할 수 있다. 얼굴 사각형 `(fx, fy, fw, fh)`가 주어지면, 그레이스케일 이미지에서 `gray[fy:fy+fh, fx:fx+fw]`가 곧 "얼굴만 잘라낸 작은 이미지"가 되고, 이 작은 이미지 위에 눈 검출기를 다시 돌리면 된다.

```python
import cv2

cascade_dir = cv2.data.haarcascades
face_cascade = cv2.CascadeClassifier(cascade_dir + "haarcascade_frontalface_default.xml")
eye_cascade = cv2.CascadeClassifier(cascade_dir + "haarcascade_eye.xml")

img = cv2.imread("people.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

faces = face_cascade.detectMultiScale(
    gray, scaleFactor=1.1, minNeighbors=5, minSize=(60, 60)
)

for (fx, fy, fw, fh) in faces:
    # 1단계: 얼굴 사각형을 원본 이미지에 그린다.
    cv2.rectangle(img, (fx, fy), (fx + fw, fy + fh), (255, 0, 0), 2)

    # 2단계: 얼굴 영역만 잘라낸 뒤, 그 좁은 영역 안에서만 눈을 검출한다.
    face_gray = gray[fy:fy + fh, fx:fx + fw]
    face_color = img[fy:fy + fh, fx:fx + fw]

    # 얼굴 안에서는 눈이 상대적으로 작고 촘촘하므로 minNeighbors를 조금 더 높여
    # 눈썹이나 안경테를 눈으로 잘못 잡는 오검출을 줄인다.
    eyes = eye_cascade.detectMultiScale(
        face_gray, scaleFactor=1.05, minNeighbors=8, minSize=(15, 15)
    )

    for (ex, ey, ew, eh) in eyes:
        # face_color는 img의 뷰(view)이므로, 여기에 그리면 원본 img에도 그대로 반영된다.
        cv2.rectangle(face_color, (ex, ey), (ex + ew, ey + eh), (0, 255, 0), 2)

print(f"검출된 얼굴 수: {len(faces)}")

cv2.imshow("Face + Eyes", img)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

여기서 `face_color = img[fy:fy+fh, fx:fx+fw]`는 데이터를 복사하지 않고 원본 배열의 **뷰(view)**를 만든다는 점이 중요하다. 7장에서 다룬 NumPy 슬라이싱의 특성 그대로, `face_color`에 `cv2.rectangle`로 그림을 그리면 그 결과가 곧바로 원본 `img`의 해당 영역에도 반영된다. 만약 얼굴 영역을 독립적인 이미지로 다루고 싶다면(원본에 영향을 주지 않고 싶다면) `img[fy:fy+fh, fx:fx+fw].copy()`처럼 명시적으로 복사해야 한다.

같은 얼굴 영역 안에서 코나 입 검출기(`haarcascade_mcs_nose.xml`, `haarcascade_mcs_mouth.xml` 등, OpenCV contrib나 별도 배포본에 포함되는 경우가 있다)를 추가하면, "얼굴 → 눈/코/입" 순서로 점점 더 세밀한 부위를 찾아 들어가는 다단계 계층적 검출로 확장할 수 있다. 이런 구조는 뒤에서 다룰 딥러닝 기반 얼굴 랜드마크 검출의 전신에 해당하는 아이디어이기도 하다.

## 17.7 Haar Cascade의 한계

Haar Cascade는 가볍고 빠르지만 몇 가지 뚜렷한 한계를 가진다.

- **정면 얼굴에 편향**: `haarcascade_frontalface_default.xml`은 정면을 바라보는 얼굴을 기준으로 학습되었다. 얼굴이 옆으로 크게 돌아가거나 기울어지면 검출률이 급격히 떨어진다(측면용 별도 XML이 존재하지만 역시 완벽하지 않다).
- **조명 민감성**: 강한 역광이나 부분 음영이 있으면 밝기 패턴 자체가 흐트러져 검출에 실패하기 쉽다.
- **오검출과 미검출의 트레이드오프**: 17.4절에서 살펴본 것처럼, `minNeighbors`나 `scaleFactor` 같은 파라미터를 조정해도 오검출(배경을 얼굴로 착각)과 미검출(진짜 얼굴을 놓침) 사이의 균형을 완벽히 맞추기는 어렵다. 한쪽을 줄이면 다른 쪽이 늘어나는 근본적인 트레이드오프가 존재한다.
- **얼굴 외 객체로 일반화하기 어려움**: 다른 종류의 객체(자동차, 특정 상품 등)를 검출하려면 그 객체에 맞는 별도의 Haar Cascade를 새로 학습시켜야 하는데, 이 과정이 번거롭고 성능도 딥러닝 기반 방법에 비해 떨어지는 경우가 많다.

이런 한계 때문에 최근의 실무 환경에서는 얼굴이든 다른 객체든, 검출 정확도가 중요한 경우 딥러닝 기반 검출기를 사용하는 것이 일반적이다. 다행히 OpenCV는 이런 딥러닝 모델을 직접 학습시키는 도구는 아니지만, 이미 학습된 모델을 불러와 추론에 활용할 수 있는 통로를 제공한다.

## 17.8 OpenCV의 DNN 모듈: 딥러닝 모델을 추론에만 활용하기

`cv2.dnn` 모듈은 TensorFlow, PyTorch(ONNX로 변환), Caffe, Darknet 등 다양한 프레임워크에서 학습된 모델 파일을 읽어들여, OpenCV 안에서 순전파(forward pass)만 실행할 수 있게 해주는 추론 전용 인터페이스다. 모델을 설계하거나 학습시키는 기능은 없으며, 그 부분은 각 딥러닝 프레임워크의 몫이다. 즉 "누군가 이미 학습시켜 파일로 내보낸 모델을, 별도의 무거운 프레임워크 설치 없이 OpenCV 하나로 돌려볼 수 있게 해주는 다리" 정도로 이해하면 된다.

모델 파일을 불러오는 함수는 원본 프레임워크에 따라 나뉜다.

| 원본 프레임워크 | 로드 함수 |
|---|---|
| ONNX(PyTorch 등에서 변환) | `cv2.dnn.readNetFromONNX(onnxFile)` |
| Caffe | `cv2.dnn.readNetFromCaffe(prototxt, caffeModel)` |
| TensorFlow | `cv2.dnn.readNetFromTensorflow(model, config)` |
| Darknet(YOLO) | `cv2.dnn.readNetFromDarknet(cfgFile, darknetModel)` |

이렇게 불러온 네트워크에 이미지를 넣어 추론하는 흐름은 항상 다음과 같은 세 단계를 따른다.

1. **전처리(`cv2.dnn.blobFromImage`)**: 이미지를 신경망이 기대하는 입력 형태(고정된 크기로 리사이즈, 픽셀값 정규화, 채널 순서 변경 등)로 변환해 "블롭(blob)"이라는 4차원 배열(`(N, C, H, W)`)을 만든다.
2. **입력 설정(`net.setInput`)**: 만든 블롭을 네트워크의 입력으로 지정한다.
3. **순전파(`net.forward`)**: 네트워크를 실행해 출력(클래스 확률, 검출 사각형 등 모델마다 다른 형식)을 얻는다.

`blobFromImage`의 시그니처를 조금 더 자세히 보면 다음과 같다.

```python
blob = cv2.dnn.blobFromImage(
    image,
    scalefactor=1.0,   # 픽셀값에 곱할 배율. 예: 1/255.0이면 0~1로 정규화
    size=(0, 0),       # 신경망이 기대하는 입력 크기 (width, height)
    mean=(0, 0, 0),    # 채널별로 빼줄 평균값 (학습 시 사용한 정규화와 맞춰야 함)
    swapRB=False,      # True면 BGR을 RGB로 바꿔서 블롭을 만든다
    crop=False,        # 종횡비가 다를 때 크롭할지 여부
)
```

여기서 `scalefactor`, `size`, `mean`, `swapRB` 값은 모델을 학습할 때 사용한 전처리 방식과 정확히 일치해야 한다. 값이 하나라도 다르면 네트워크가 학습 때와 다른 분포의 입력을 받게 되어 추론 결과가 크게 어긋난다. 이 값들은 보통 모델을 배포하는 쪽(공식 문서나 샘플 코드)에서 함께 안내한다.

## 17.9 실전: 사전 학습된 DNN 얼굴 검출기 동작시키기

이제 개념을 실제로 동작하는 코드로 옮겨보자. 여기서는 OpenCV 프로젝트가 예제로 배포하는 res10 SSD 계열 얼굴 검출 모델(Caffe로 학습됨)을 예로 든다. 이 모델은 300×300 크기의 입력을 받아, 이미지 안에 있는 얼굴들의 위치와 신뢰도(confidence)를 한 번의 순전파로 출력한다.

> **모델 파일은 책에 포함되어 있지 않다.** `deploy.prototxt`(네트워크 구조 설명 파일)와 `res10_300x300_ssd_iter_140000_fp16.caffemodel`(학습된 가중치 파일) 두 개를 별도로 준비해야 한다. 이 두 파일은 OpenCV 공식 GitHub 저장소의 `samples/dnn/face_detector` 폴더에서 받을 수 있으며, `opencv-python`을 설치한다고 해서 함께 설치되지는 않는다. 저작권과 파일 용량 문제로 pip 패키지에는 모델 가중치가 포함되지 않기 때문이다.

두 파일을 스크립트와 같은 폴더에 두었다고 가정하고, 전체 흐름을 코드로 작성해보자.

```python
import cv2
import numpy as np

# 1) 사전 학습된 Caffe 모델을 불러온다.
config_path = "deploy.prototxt"
model_path = "res10_300x300_ssd_iter_140000_fp16.caffemodel"
net = cv2.dnn.readNetFromCaffe(config_path, model_path)

# 2) 입력 이미지를 읽고, 모델이 기대하는 블롭으로 전처리한다.
img = cv2.imread("people.jpg")
h, w = img.shape[:2]

blob = cv2.dnn.blobFromImage(
    img,
    scalefactor=1.0,
    size=(300, 300),
    mean=(104.0, 177.0, 123.0),  # 이 모델의 학습 시 사용된 채널 평균값
    swapRB=False,                # 이 모델은 BGR 순서 그대로 학습되었다
    crop=False,
)

# 3) 블롭을 입력으로 설정하고 순전파를 실행한다.
net.setInput(blob)
detections = net.forward()

# detections의 형태는 (1, 1, N, 7)이며, 마지막 축 7개 값은
# [배치 인덱스, 클래스 인덱스, 신뢰도, x1, y1, x2, y2] (좌표는 0~1로 정규화됨)이다.
conf_threshold = 0.5

for i in range(detections.shape[2]):
    confidence = float(detections[0, 0, i, 2])
    if confidence < conf_threshold:
        continue

    box = detections[0, 0, i, 3:7] * np.array([w, h, w, h])
    x1, y1, x2, y2 = box.astype(int)

    cv2.rectangle(img, (x1, y1), (x2, y2), (0, 255, 0), 2)
    label = f"{confidence * 100:.1f}%"
    cv2.putText(
        img, label, (x1, max(y1 - 10, 0)),
        cv2.FONT_HERSHEY_SIMPLEX, 0.5, (0, 255, 0), 2,
    )

cv2.imshow("DNN Face Detection", img)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

이 예제에서 눈여겨볼 부분은 다음과 같다.

- **출력 해석은 모델마다 다르다**: 이 모델의 출력 `(1, 1, N, 7)`은 SSD(Single Shot MultiBox Detector) 계열 검출 모델들이 흔히 채택하는 형식이지만, 다른 모델(YOLO 계열, 분류 모델 등)은 완전히 다른 형태의 출력을 낸다. 새로운 모델을 쓸 때는 항상 그 모델의 출력 규약을 먼저 확인해야 한다.
- **좌표는 0~1로 정규화되어 있다**: `detections[0, 0, i, 3:7]`은 원본 이미지 크기와 무관한 비율 값이므로, 실제 픽셀 좌표로 바꾸려면 원본 이미지의 `(w, h, w, h)`를 곱해줘야 한다.
- **`conf_threshold`로 약한 검출을 걸러낸다**: Haar Cascade의 `minNeighbors`가 겹치는 후보 수로 신뢰도를 판단했다면, DNN 계열 검출기는 대개 0~1 사이의 신뢰도 점수를 직접 출력하므로 이 값을 임계값으로 걸러내는 방식이 일반적이다. `conf_threshold`를 낮추면 더 많은(약한) 후보까지 검출되고, 높이면 확실한 후보만 남는다는 점에서 `minNeighbors`와 비슷한 역할을 한다.

## 17.10 Haar Cascade와 DNN 기반 검출 비교

지금까지 살펴본 두 접근을 실무 관점에서 정리하면 다음과 같다.

| 항목 | Haar Cascade | DNN 기반 검출(예: SSD) |
|---|---|---|
| 필요한 파일 | XML 하나(패키지에 내장) | 구조 파일 + 가중치 파일(별도 다운로드) |
| 연산량 | 가볍다, CPU만으로도 실시간 가능 | 상대적으로 무겁다(모델에 따라 GPU가 유리) |
| 정면 외 각도 대응 | 약함 | 상대적으로 강함(학습 데이터에 다양한 각도가 포함된 경우) |
| 조명 변화 대응 | 약함 | 상대적으로 강함 |
| 출력 형식 | 항상 사각형 좌표 배열로 통일 | 모델마다 다름(직접 해석 필요) |
| 튜닝 파라미터 | `scaleFactor`, `minNeighbors`, `minSize` | `conf_threshold`, 입력 크기, 전처리 값 |
| 적합한 상황 | 빠른 프로토타입, 저사양 환경, 실시간성이 최우선 | 정확도가 중요한 실무, 다양한 각도·조명 대응 필요 시 |

두 방법은 배타적이지 않다. 예를 들어 저사양 임베디드 장치의 1차 필터링에는 Haar Cascade를 쓰고, 서버 쪽에서 더 정밀한 확인이 필요할 때 DNN 모델을 추가로 돌리는 하이브리드 구성도 실무에서 흔히 볼 수 있다.

## 17.11 실전 확장: 웹캠 영상에서 실시간으로 얼굴 검출하기

16장에서 다룬 `cv2.VideoCapture`와 이 장의 `detectMultiScale`을 결합하면, 정지 이미지가 아니라 실시간 웹캠 영상에서 얼굴을 계속 검출하는 프로그램을 만들 수 있다. 원리는 단순하다. 매 프레임마다 이번 장에서 다룬 정지 이미지 검출 코드를 반복 실행하는 것뿐이다.

```python
import cv2

cascade_path = cv2.data.haarcascades + "haarcascade_frontalface_default.xml"
face_cascade = cv2.CascadeClassifier(cascade_path)

cap = cv2.VideoCapture(0)
if not cap.isOpened():
    raise IOError("웹캠을 열 수 없습니다.")

while True:
    ok, frame = cap.read()
    if not ok:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    faces = face_cascade.detectMultiScale(
        gray, scaleFactor=1.1, minNeighbors=5, minSize=(60, 60)
    )

    for (x, y, w, h) in faces:
        cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

    cv2.putText(
        frame, f"Faces: {len(faces)}", (10, 30),
        cv2.FONT_HERSHEY_SIMPLEX, 0.8, (0, 255, 0), 2,
    )

    cv2.imshow("Realtime Face Detection", frame)
    if cv2.waitKey(1) & 0xFF == 27:  # Esc로 종료
        break

cap.release()
cv2.destroyAllWindows()
```

이 코드에서 눈여겨볼 실전 포인트가 몇 가지 있다.

- **매 프레임 새로 검출한다**: Haar Cascade에는 "이전 프레임의 결과를 기억해서 다음 프레임의 위치를 예측"하는 기능이 없다. 즉 이 코드는 트래킹이 아니라, 프레임마다 완전히 새로 검출을 수행하는 것이다. 18장에서 잠깐 언급하는 `cv2.TrackerCSRT_create()` 같은 전용 트래커는 검출된 객체의 이전 위치를 바탕으로 다음 프레임에서 더 적은 연산으로 위치를 추적한다는 점에서 다르다.
- **해상도가 속도를 좌우한다**: `detectMultiScale`은 프레임 해상도가 커질수록 스케일 피라미드 전체를 훑는 데 걸리는 시간이 늘어난다. 실시간성이 중요하다면 프레임을 축소한 뒤 검출하고, 결과 좌표만 원본 크기로 환산하는 방식이 흔히 쓰인다.
- **`minSize`를 넉넉히 잡는다**: 정지 이미지와 달리 웹캠 프레임에서는 얼굴이 화면의 상당 부분을 차지하는 경우가 많으므로, `minSize`를 너무 작게 잡으면 불필요한 소형 스케일 탐색에 시간을 낭비하게 된다.

프레임을 축소해서 검출 속도를 높이는 방법은 다음과 같다.

```python
scale = 0.5
small = cv2.resize(gray, None, fx=scale, fy=scale, interpolation=cv2.INTER_AREA)
faces_small = face_cascade.detectMultiScale(small, scaleFactor=1.1, minNeighbors=5)

for (x, y, w, h) in faces_small:
    # 축소된 좌표를 원본 프레임 좌표로 환산한다.
    x, y, w, h = int(x / scale), int(y / scale), int(w / scale), int(h / scale)
    cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)
```

이렇게 절반 크기로 줄여 검출한 뒤 좌표만 2배로 환산하면, 검출 정확도의 큰 손실 없이 탐색해야 할 픽셀 수를 4분의 1로 줄여 눈에 띄는 속도 향상을 얻을 수 있다.

## 요약

- 얼굴 "검출"은 위치만 찾는 작업이고, 얼굴 "인식"은 신원까지 식별하는 작업으로 서로 다른 문제다.
- `cv2.CascadeClassifier`는 미리 학습된 Haar Cascade XML 모델을 불러와 얼굴 등을 검출하는 전통적인 방법이며, `cv2.data.haarcascades` 경로에 다양한 용도의 XML이 함께 설치되어 있다.
- `detectMultiScale`은 이미지 위에서 다양한 위치(슬라이딩)와 다양한 크기(스케일 피라미드)로 윈도우를 반복 검사해 얼굴 후보 사각형들을 찾고, `minNeighbors` 기준으로 겹치는 후보를 묶어 최종 결과를 걸러낸다. `scaleFactor`·`minNeighbors`·`minSize`는 각각 탐색 정밀도, 오검출/미검출 균형, 검출 크기 범위를 조절하며, 서로 트레이드오프 관계에 있다.
- 얼굴을 먼저 검출하고 그 영역 안에서만 눈을 다시 검출하는 계층적 접근은 탐색 공간을 줄여 속도를 높이고 오검출을 크게 줄인다.
- Haar Cascade는 계산이 가볍지만 정면 얼굴 위주로 학습되었고 조명·각도 변화에 민감하다는 한계가 있어, 정확도가 중요한 실무에서는 딥러닝 기반 검출로 옮겨가는 경우가 많다.
- `cv2.dnn` 모듈(`readNetFromCaffe`, `readNetFromONNX` 등)은 모델을 직접 학습시키지는 못하지만, 다른 프레임워크에서 학습된 모델을 불러와 `blobFromImage → setInput → forward`의 흐름으로 추론을 실행할 수 있는 통로를 제공한다. 모델 파일(구조 + 가중치)은 `opencv-python` 설치와 별도로 직접 준비해야 한다.

## 연습문제

1. `detectMultiScale`의 `minNeighbors` 값을 1, 5, 10으로 각각 바꿔가며 같은 이미지에 적용해보고, 검출되는 얼굴 사각형의 개수와 오검출 여부가 어떻게 달라지는지 관찰해 보라.
2. 여러 사람이 함께 나온 사진과, 얼굴이 옆으로 돌아간(측면) 사진을 각각 준비해 Haar Cascade로 검출해보고, 정면 사진과 비교했을 때 검출률이 어떻게 달라지는지 확인해 보라.
3. 검출된 얼굴 사각형 영역만 잘라내어(크롭) 별도의 이미지 파일로 저장하는 기능을 추가해 보라. (힌트: NumPy 배열 슬라이싱과 `cv2.imwrite`를 활용한다.)
4. 17.6절의 얼굴+눈 검출 코드에서 `haarcascade_eye.xml` 대신 `haarcascade_eye_tree_eyeglasses.xml`을 사용해보고, 안경을 쓴 사람의 사진에서 검출 결과가 어떻게 달라지는지 비교해 보라.
5. 17.9절의 DNN 얼굴 검출 코드에서 `conf_threshold` 값을 0.2, 0.5, 0.8로 바꿔가며 실행해보고, 검출되는 얼굴 수와 오검출 여부가 어떻게 달라지는지 관찰한 뒤, 같은 이미지에 대해 Haar Cascade와 DNN 검출의 처리 시간을 `time` 모듈로 측정해 비교해 보라.
