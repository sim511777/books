## 4.1 이미지 파일 읽기: imread

OpenCV는 `.jpg`, `.png`, `.bmp`를 비롯해 `.tiff`, `.webp` 등 다양한 포맷의 이미지를 읽고 쓸 수 있는 기능을 제공한다. 흥미로운 점은, 파일을 읽는 함수를 호출할 때 포맷을 직접 지정할 필요가 없다는 것이다. OpenCV는 파일의 내용(헤더)을 검사해서 포맷을 자동으로 판별하고, 그에 맞는 디코더를 사용해 파일을 해석한 뒤, 그 결과를 3장에서 다룬 것과 동일한 형태의 배열(픽셀의 3차원 NumPy 배열)로 돌려준다. 즉 `.jpg`로 읽었든 `.png`로 읽었든, 한 번 메모리에 올라온 뒤에는 완전히 동일한 방식으로 다룰 수 있다.

```python
import cv2

img_jpg = cv2.imread("photo.jpg")
img_png = cv2.imread("photo.png")
img_bmp = cv2.imread("photo.bmp")

print(type(img_jpg))   # <class 'numpy.ndarray'>
print(img_jpg.shape)    # (높이, 너비, 3)
```

`cv2.imread()`는 파일 경로를 문자열로 받아, 성공하면 3장에서 살펴본 `numpy.ndarray`를 반환한다. 경로는 상대 경로(현재 작업 디렉터리 기준)와 절대 경로 모두 사용할 수 있으며, 한글이 포함된 경로도 대부분의 환경에서 문제없이 동작하지만 운영체제나 OpenCV 빌드에 따라 예외가 있을 수 있으므로, 실무에서 문제가 생긴다면 경로에 비ASCII 문자가 포함되어 있는지부터 의심해 보는 것도 좋다.

## 4.2 컬러/그레이스케일로 읽기 옵션

`imread`는 두 번째 인자로 "어떤 방식으로 이미지를 해석해서 읽어 올 것인가"를 지정하는 플래그를 받을 수 있다. 기본값은 컬러(3채널, BGR)로 읽어 오는 것이지만, 원본 파일이 흑백이든 컬러든 상관없이 그레이스케일(1채널)로 강제 변환해서 읽어 오도록 지정할 수도 있다. 이렇게 하면 나중에 직접 `cv2.cvtColor()` 등으로 색공간을 변환하는 단계를 생략할 수 있어 편리하다. 색공간 변환 자체는 5장에서 자세히 다룬다.

```python
import cv2

# 기본값: 컬러(BGR, 3채널)로 읽기
img_color = cv2.imread("photo.jpg", cv2.IMREAD_COLOR)

# 그레이스케일(1채널)로 읽기
img_gray = cv2.imread("photo.jpg", cv2.IMREAD_GRAYSCALE)

# 파일에 알파 채널이 있다면 그대로 유지해서 읽기 (없으면 3채널로 읽힘)
img_unchanged = cv2.imread("photo_with_alpha.png", cv2.IMREAD_UNCHANGED)

print(img_color.shape)      # (480, 640, 3)
print(img_gray.shape)       # (480, 640)  -> 채널 차원이 사라짐
print(img_unchanged.shape)  # (480, 640, 4) -> BGRA, 알파 채널까지 포함

# 두 번째 인자를 생략하면 IMREAD_COLOR가 기본값으로 적용된다
img_default = cv2.imread("photo.jpg")
```

주요 읽기 모드를 정리하면 다음과 같다.

| 플래그 | 의미 |
|---|---|
| `cv2.IMREAD_COLOR` | 항상 3채널 컬러(BGR)로 읽는다. 원본이 그레이스케일이거나 알파 채널이 있어도 무시하고 3채널로 맞춘다. 생략 시 기본값. |
| `cv2.IMREAD_GRAYSCALE` | 항상 1채널 그레이스케일로 읽는다. 컬러 사진이라도 강제로 흑백으로 변환해서 읽어 들인다. |
| `cv2.IMREAD_UNCHANGED` | 파일에 있는 채널 구성을 그대로 유지한다. 알파 채널(PNG의 투명도 정보 등)이 필요하다면 반드시 이 옵션을 사용해야 한다. |
| `cv2.IMREAD_REDUCED_COLOR_2` 등 | 이미지를 읽으면서 동시에 1/2, 1/4, 1/8 크기로 축소한다. 큰 이미지를 빠르게 미리보기만 하고 싶을 때 디코딩 자체를 줄여 속도를 아낄 수 있다. |

## 4.3 파일을 읽지 못했을 때: None 반환과 안전한 예외 처리

실무에서 가장 자주 발생하는 실수 중 하나가, 파일 경로를 잘못 지정했거나 파일이 손상되었을 때 이를 확인하지 않고 바로 다음 처리를 진행하는 것이다. 이 경우 프로그램은 이상한 위치에서 알아보기 힘든 오류를 내며 멈추기 때문에, 원인을 찾는 데 시간을 낭비하기 쉽다.

Python에서 `cv2.imread()`가 파일을 열지 못하면 예외(exception)를 던지지 않고 조용히 **`None`을 반환**한다. 따라서 반환값이 `None`인지를 반드시 확인해야 한다.

```python
import cv2
import sys

img = cv2.imread("존재하지않는파일.jpg")

if img is None:
    print("이미지를 읽을 수 없습니다. 경로를 확인하세요.", file=sys.stderr)
    sys.exit(1)

print(img.shape)  # None을 확인하지 않고 이 줄에 도달하면 AttributeError 발생
```

만약 `None` 확인을 생략하고 곧바로 `img.shape`에 접근하면, `NoneType` 객체에는 `shape` 속성이 없으므로 `AttributeError: 'NoneType' object has no attribute 'shape'` 오류가 발생한다. 이 오류 메시지가 나온다면 대부분의 경우 `imread`가 파일을 찾지 못했다는 뜻이니, 경로나 파일명을 먼저 점검해야 한다.

### 함수/모듈 단위로 안전하게 감싸기

작은 스크립트라면 매번 `if img is None:`을 검사하는 것으로 충분하지만, 여러 곳에서 이미지를 읽어야 하는 프로그램이라면 아예 실패 자체를 예외로 승격시키는 헬퍼 함수를 만들어 두면 실수를 줄일 수 있다.

```python
import cv2

def imread_safe(path, flags=cv2.IMREAD_COLOR):
    """파일을 읽지 못하면 None 대신 명확한 예외를 던지는 imread 래퍼."""
    img = cv2.imread(path, flags)
    if img is None:
        raise FileNotFoundError(
            f"이미지를 읽을 수 없습니다: '{path}' "
            "(경로가 잘못되었거나 파일이 손상되었을 수 있습니다.)"
        )
    return img

try:
    img = imread_safe("photo.jpg")
    print("읽기 성공:", img.shape)
except FileNotFoundError as e:
    print("오류:", e)
```

이렇게 만들어 두면 호출하는 쪽에서는 `try/except`로 한 번에 오류를 처리할 수 있고, `None`을 깜빡하고 확인하지 않아서 나중에 알아보기 힘든 `AttributeError`가 튀어나오는 상황을 원천적으로 막을 수 있다. 이 책의 이후 예제들에서도 이런 방어적 패턴을 종종 활용한다.

## 4.4 glob으로 폴더 안의 여러 이미지 한 번에 처리하기

실무에서는 이미지 한 장을 읽고 끝나는 경우보다, 폴더 안에 있는 수십~수천 장의 이미지를 순서대로 읽어서 동일한 처리를 반복하는 경우가 훨씬 많다. 예를 들어 데이터셋 전체를 그레이스케일로 변환하거나, 크기를 일괄적으로 리사이즈하거나, 파일명을 정리하는 작업이 대표적이다. 이런 작업에는 표준 라이브러리의 `glob` 모듈이 매우 유용하다.

```python
import cv2
import glob
import os

# 현재 폴더의 images 하위 폴더에서 jpg 확장자를 가진 모든 파일 경로를 가져온다
image_paths = glob.glob("images/*.jpg")
print(image_paths)   # ['images/photo1.jpg', 'images/photo2.jpg', ...]

# 여러 확장자를 한꺼번에 다루려면 확장자별로 glob을 여러 번 호출해 합친다
image_paths = []
for ext in ("*.jpg", "*.jpeg", "*.png", "*.bmp"):
    image_paths.extend(glob.glob(os.path.join("images", ext)))

print(f"총 {len(image_paths)}장의 이미지를 찾았습니다.")
```

### 일괄 처리 실전 패턴: 그레이스케일 변환 후 저장

```python
import cv2
import glob
import os

input_dir = "images"
output_dir = "images_gray"
os.makedirs(output_dir, exist_ok=True)   # 결과를 저장할 폴더가 없으면 생성

for path in glob.glob(os.path.join(input_dir, "*.jpg")):
    img = cv2.imread(path)

    if img is None:
        print(f"[건너뜀] 읽기 실패: {path}")
        continue

    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)  # 5장에서 자세히 다룰 색공간 변환

    filename = os.path.basename(path)              # 예: 'photo1.jpg'
    output_path = os.path.join(output_dir, filename)
    cv2.imwrite(output_path, gray)
    print(f"처리 완료: {path} -> {output_path}")

print("모든 이미지 처리가 끝났습니다.")
```

이 패턴, 즉 **"glob으로 경로 목록 얻기 → for 문으로 순회하며 읽기 → None 확인 → 처리 → 결과 저장"**은 이 책 후반부의 여러 실전 예제(일괄 리사이즈, 데이터 증강, 얼굴 검출 등)에서 계속 재사용되는 골격이므로 지금 확실히 익혀 두는 것이 좋다. `glob.glob()`은 파일이 발견되는 순서를 보장하지 않으므로, 처리 순서가 중요한 작업이라면 `sorted(glob.glob(...))`으로 정렬해서 사용하는 것이 안전하다.

```python
# 파일명 순서대로 정렬해서 처리하고 싶을 때
for path in sorted(glob.glob("images/*.jpg")):
    ...
```

재귀적으로 하위 폴더까지 모두 탐색하고 싶다면 `glob.glob("images/**/*.jpg", recursive=True)`처럼 `**`와 `recursive=True`를 함께 사용한다.

## 4.5 이미지 포맷별 특징 비교: JPEG, PNG, BMP

이미지를 저장할 때 어떤 포맷을 선택할지는 단순한 취향의 문제가 아니라, 용량과 품질, 그리고 투명도 지원 여부 등 실질적인 트레이드오프를 이해하고 결정해야 하는 문제다.

| 포맷 | 압축 방식 | 특징 | 알파 채널 | 주로 쓰는 상황 |
|---|---|---|---|---|
| **JPEG (`.jpg`)** | 손실 압축(lossy) | 사람 눈이 잘 인지하지 못하는 정보를 버려서 파일 용량을 크게 줄인다. 압축률이 높을수록 화질이 저하되고, 특히 경계선 주변에 특유의 블록/노이즈 아티팩트가 생긴다. | 지원하지 않음 | 사진처럼 색이 부드럽게 변하는 이미지, 웹 게시용, 용량이 중요한 경우 |
| **PNG (`.png`)** | 무손실 압축(lossless) | 압축해도 원본 픽셀 값이 손상되지 않는다. 같은 해상도라면 대체로 JPEG보다 용량이 크지만, 도형이나 텍스트처럼 단색 영역이 많은 이미지는 오히려 JPEG보다 작아질 수도 있다. | 지원함(RGBA) | 스크린샷, 로고, 투명 배경이 필요한 이미지, 반복 편집이 필요한 중간 결과물 |
| **BMP (`.bmp`)** | 비압축(원본 그대로, 혹은 매우 단순한 무손실 압축) | 압축을 거의 하지 않으므로 파일 용량이 가장 크지만, 읽고 쓰는 속도가 빠르고 구조가 단순하다. | 제한적 | 임시 저장, 디버깅용 중간 결과, 압축 오버헤드 없이 빠르게 저장해야 할 때 |

경험적으로 정리하면, **최종 배포용 사진**에는 JPEG, **투명도가 필요하거나 무손실이 중요한 결과물**(중간 처리 결과, 마스크 이미지, 스크린샷)에는 PNG, **디버깅 중 빠르게 저장하고 지울 임시 파일**에는 BMP를 쓰는 것이 합리적인 기본 선택이다. 특히 이미지 처리 알고리즘을 검증하는 중간 단계에서는 JPEG의 손실 압축이 픽셀 값을 미세하게 바꿔 버려서(재압축 아티팩트) 결과 분석에 혼란을 줄 수 있으므로, 파이프라인 중간 산출물은 PNG로 저장하는 습관을 들이는 것이 좋다.

## 4.6 이미지 파일 쓰기: imwrite와 포맷별 옵션

처리한 이미지를 다시 파일로 저장할 때는 `cv2.imwrite()`를 사용한다. 저장할 파일의 확장자를 보고 OpenCV가 자동으로 인코딩 방식을 결정하므로, 원하는 포맷에 맞는 확장자를 파일명에 붙여 주기만 하면 된다.

```python
import cv2

img = cv2.imread("photo.jpg")

success_png = cv2.imwrite("output.png", img)
success_jpg = cv2.imwrite("output.jpg", img)
success_bmp = cv2.imwrite("output.bmp", img)

print(success_png, success_jpg, success_bmp)  # 모두 True면 저장 성공
```

`cv2.imwrite()`는 저장에 성공하면 `True`, 실패하면 `False`를 반환하므로(예외를 던지지 않으므로) 이 값을 확인하는 것도 4.3절에서 다룬 것과 같은 종류의 안전장치가 된다. 저장이 실패하는 대표적인 원인은 저장하려는 디렉터리가 존재하지 않는 경우이므로, 필요하다면 `os.makedirs(디렉터리, exist_ok=True)`로 미리 디렉터리를 만들어 두는 것이 안전하다.

### JPEG 품질 옵션: IMWRITE_JPEG_QUALITY

JPEG로 저장할 때는 손실 압축의 강도, 즉 품질을 0~100 사이의 정수로 지정할 수 있다. 값이 클수록 원본에 가깝고 파일 용량이 커지며, 값이 작을수록 용량은 작아지지만 화질 손실(블록 아티팩트)이 심해진다. 기본값은 대략 95 정도다.

```python
import cv2

img = cv2.imread("photo.jpg")

cv2.imwrite("output_q95.jpg", img, [cv2.IMWRITE_JPEG_QUALITY, 95])  # 고품질, 큰 용량
cv2.imwrite("output_q50.jpg", img, [cv2.IMWRITE_JPEG_QUALITY, 50])  # 중간 품질
cv2.imwrite("output_q10.jpg", img, [cv2.IMWRITE_JPEG_QUALITY, 10])  # 저품질, 작은 용량, 아티팩트 심함
```

옵션은 `[플래그, 값, 플래그, 값, ...]` 형태의 리스트로 전달한다는 점에 유의한다. 여러 옵션을 동시에 지정하고 싶다면 리스트를 더 길게 이어 붙이면 된다.

### PNG 압축 레벨: IMWRITE_PNG_COMPRESSION

PNG는 무손실이므로 압축 레벨을 바꿔도 **화질은 전혀 손상되지 않는다.** 다만 압축 레벨이 높을수록(압축을 더 열심히 할수록) 파일 용량은 줄어들지만 인코딩 시간이 늘어난다는 트레이드오프가 있다. 레벨은 0(압축 안 함, 가장 빠름)부터 9(최대 압축, 가장 느림)까지 지정할 수 있다.

```python
import cv2
import os

img = cv2.imread("photo.jpg")

cv2.imwrite("output_c0.png", img, [cv2.IMWRITE_PNG_COMPRESSION, 0])  # 빠르지만 용량 큼
cv2.imwrite("output_c9.png", img, [cv2.IMWRITE_PNG_COMPRESSION, 9])  # 느리지만 용량 작음

print(os.path.getsize("output_c0.png"), "바이트")
print(os.path.getsize("output_c9.png"), "바이트")
# 두 파일을 다시 imread로 읽어 비교하면 픽셀 값은 완전히 동일하다 (무손실이므로)
```

### 자주 쓰는 imwrite 플래그 정리

| 플래그 | 대상 포맷 | 값의 범위 | 의미 |
|---|---|---|---|
| `cv2.IMWRITE_JPEG_QUALITY` | JPEG | 0~100 (기본 약 95) | 값이 클수록 고품질/큰 용량 |
| `cv2.IMWRITE_PNG_COMPRESSION` | PNG | 0~9 (기본 3) | 값이 클수록 느리지만 작은 용량, 화질 손상 없음 |
| `cv2.IMWRITE_WEBP_QUALITY` | WebP | 1~100 | JPEG 품질 옵션과 유사하지만 WebP 포맷에 적용 |

## 4.7 비디오 캡처 기초

지금까지 다룬 이미지는 한 장의 정지된 프레임이었다. 비디오는 이런 프레임이 초당 수십 장씩 연속으로 이어진 것이라고 생각하면 된다. OpenCV는 웹캠 장치와 동영상 파일을 동일한 인터페이스로 다룰 수 있게 해 주는 `cv2.VideoCapture` 클래스를 제공한다. 이 절에서는 카메라(또는 파일)를 열고, 한 프레임씩 읽어서 화면에 보여 주다가 키 입력으로 종료하는 가장 기본적인 패턴을 익힌다.

`VideoCapture`를 열 때 정수를 넘기면 그 번호에 해당하는 카메라 장치(보통 `0`은 컴퓨터에 기본으로 연결된 첫 번째 웹캠)를 열고, 문자열(파일 경로)을 넘기면 그 경로의 동영상 파일을 연다.

```python
import cv2

cap = cv2.VideoCapture(0)  # 0번 웹캠. 파일을 열려면 "video.mp4" 같은 경로를 넘긴다.

if not cap.isOpened():
    print("카메라(또는 파일)를 열 수 없습니다.")
    exit(1)

while True:
    ret, frame = cap.read()  # ret: 성공 여부(bool), frame: 프레임 이미지

    if not ret:
        print("더 이상 프레임을 읽을 수 없습니다.")
        break

    cv2.imshow("Camera", frame)

    # 1ms 대기하며 키 입력을 받는다. 'q' 키를 누르면 종료.
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

`cap.read()`는 두 개의 값을 튜플로 반환한다. 첫 번째 `ret`은 프레임을 성공적으로 읽었는지를 나타내는 불리언 값이고, 두 번째 `frame`은 실제 이미지(3장에서 다룬 것과 동일한 `ndarray`)다. 파일의 끝에 도달했거나 카메라 연결이 끊기면 `ret`이 `False`가 되므로, 반복문에서 이를 확인해 탈출하는 것이 정석이다. `cv2.waitKey(1)`은 1밀리초 동안 키 입력을 기다리는 함수로, 화면을 갱신할 시간을 벌어 주는 동시에 사용자의 키 입력을 받는 역할도 한다. 작업이 끝나면 `cap.release()`로 장치(또는 파일)를 반드시 해제해야 한다. 해제하지 않으면 다른 프로그램(또는 같은 프로그램을 다시 실행했을 때)이 카메라 장치를 열지 못하는 문제가 생길 수 있다.

## 4.8 여러 카메라 장치 다루기

컴퓨터에 웹캠이 여러 대 연결되어 있는 경우(내장 카메라 + 외장 USB 카메라 등), `VideoCapture`의 인덱스 번호로 원하는 장치를 선택할 수 있다. 일반적으로 `0`은 시스템의 기본 카메라이고, `1`, `2`, ... 순서로 추가 장치가 인식된다. 다만 이 번호는 운영체제와 드라이버가 장치를 인식하는 순서에 따라 달라지므로, 어떤 번호가 어떤 물리적 카메라에 대응하는지는 실제로 하나씩 열어서 화면을 확인해 보는 것이 가장 확실하다.

```python
import cv2

def list_available_cameras(max_index=5):
    """0번부터 max_index-1번까지 순서대로 열어 보며 실제 사용 가능한 카메라 번호를 찾는다."""
    available = []
    for index in range(max_index):
        cap = cv2.VideoCapture(index)
        if cap.isOpened():
            available.append(index)
            cap.release()
    return available

print("사용 가능한 카메라 번호:", list_available_cameras())
# 예: [0, 1]  -> 0번과 1번 카메라가 연결되어 있다는 뜻
```

이렇게 사용 가능한 번호를 먼저 확인해 두면, 사용자가 여러 카메라 중 하나를 선택하게 하거나, 프로그램 시작 시 자동으로 첫 번째로 열리는 카메라를 사용하도록 만드는 등의 견고한 처리가 가능해진다.

## 4.9 카메라 속성 설정: 해상도와 FPS

`cap.set()`과 `cap.get()`을 사용하면 카메라(또는 비디오 파일)의 다양한 속성을 읽고 설정할 수 있다. 대표적으로 프레임의 가로/세로 해상도와 초당 프레임 수(FPS, Frames Per Second)를 조정할 수 있다.

```python
import cv2

cap = cv2.VideoCapture(0)

if not cap.isOpened():
    print("카메라를 열 수 없습니다.")
    exit(1)

# 해상도를 1280x720으로 설정 시도
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 1280)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 720)

# 초당 프레임 수를 30으로 설정 시도
cap.set(cv2.CAP_PROP_FPS, 30)

# 실제로 적용된 값을 다시 읽어서 확인한다 (요청한 값이 그대로 적용되지 않을 수 있음!)
actual_width = cap.get(cv2.CAP_PROP_FRAME_WIDTH)
actual_height = cap.get(cv2.CAP_PROP_FRAME_HEIGHT)
actual_fps = cap.get(cv2.CAP_PROP_FPS)

print(f"요청: 1280x720 @ 30fps")
print(f"실제 적용: {actual_width:.0f}x{actual_height:.0f} @ {actual_fps:.1f}fps")

cap.release()
```

> **주의**: `cap.set()`은 요청이 성공했는지 보장하지 않는다. 카메라 하드웨어와 드라이버가 지원하지 않는 해상도나 FPS를 요청하면, 요청 값이 무시되고 카메라가 지원하는 가장 가까운 값으로 조용히 대체되는 경우가 많다. 따라서 속성을 설정한 뒤에는 반드시 `cap.get()`으로 실제 적용된 값을 다시 확인하는 습관을 들여야 한다.

자주 쓰는 카메라/비디오 속성 플래그를 정리하면 다음과 같다.

| 속성 플래그 | 의미 |
|---|---|
| `cv2.CAP_PROP_FRAME_WIDTH` | 프레임의 가로 폭(픽셀) |
| `cv2.CAP_PROP_FRAME_HEIGHT` | 프레임의 세로 높이(픽셀) |
| `cv2.CAP_PROP_FPS` | 초당 프레임 수 |
| `cv2.CAP_PROP_BRIGHTNESS` | 밝기(카메라가 지원하는 경우) |
| `cv2.CAP_PROP_POS_FRAMES` | (동영상 파일에서) 현재 읽고 있는 프레임 번호 |

## 4.10 동영상 파일의 메타데이터 읽기

웹캠이 아니라 이미 저장된 동영상 파일을 열었을 때는, 그 파일이 전체 몇 프레임으로 이루어져 있는지, 재생 시간이 얼마인지 같은 메타데이터를 미리 알아 두면 유용하다. 이런 정보 역시 `cap.get()`으로 조회할 수 있다.

```python
import cv2

cap = cv2.VideoCapture("video.mp4")

if not cap.isOpened():
    print("동영상 파일을 열 수 없습니다.")
    exit(1)

frame_count = cap.get(cv2.CAP_PROP_FRAME_COUNT)   # 전체 프레임 수
fps = cap.get(cv2.CAP_PROP_FPS)                     # 초당 프레임 수
width = cap.get(cv2.CAP_PROP_FRAME_WIDTH)
height = cap.get(cv2.CAP_PROP_FRAME_HEIGHT)

# 재생 시간(초) = 전체 프레임 수 / FPS
duration_sec = frame_count / fps if fps > 0 else 0
minutes, seconds = divmod(duration_sec, 60)

print(f"해상도: {width:.0f}x{height:.0f}")
print(f"FPS: {fps:.2f}")
print(f"전체 프레임 수: {frame_count:.0f}")
print(f"재생 시간: {int(minutes)}분 {seconds:.1f}초")

cap.release()
```

`CAP_PROP_FRAME_COUNT`를 `CAP_PROP_FPS`로 나누면 대략적인 재생 시간(초)을 계산할 수 있다. 다만 이 값들은 파일의 메타데이터(헤더)에 기록된 값을 그대로 읽어 오는 것이기 때문에, 손상된 파일이거나 인코딩 방식에 따라 실제 재생 가능한 프레임 수와 정확히 일치하지 않을 수도 있다는 점을 참고로 알아 두면 좋다. 정확한 프레임 수가 반드시 필요한 작업(예: 전체 프레임을 미리 순회하며 저장하는 경우)이라면, 실제로 `cap.read()`를 끝까지 반복해서 직접 세어 보는 방법이 더 확실하다.

### 특정 프레임 위치로 이동하기

`CAP_PROP_POS_FRAMES`는 읽기뿐 아니라 쓰기(설정)도 가능해서, 동영상 파일의 특정 프레임 위치로 바로 이동(seek)할 수 있다.

```python
import cv2

cap = cv2.VideoCapture("video.mp4")

# 100번째 프레임으로 바로 이동
cap.set(cv2.CAP_PROP_POS_FRAMES, 100)

ret, frame = cap.read()  # 100번째 프레임을 읽음
if ret:
    cv2.imwrite("frame_100.png", frame)

cap.release()
```

이 기능은 동영상 전체를 처음부터 순서대로 읽지 않고, 특정 구간만 골라서 처리하고 싶을 때(예: 썸네일 추출, 특정 장면 미리보기) 유용하다.

## 4.11 안전한 예외 처리: 카메라와 파일이 없을 때

4.3절에서 이미지 파일을 다룰 때의 안전한 예외 처리를 살펴봤다면, 비디오/카메라를 다룰 때도 동일한 원칙이 적용된다. `cv2.VideoCapture()`는 장치나 파일을 열지 못해도 예외를 던지지 않고, `cap.isOpened()`가 `False`를 반환하는 방식으로 실패를 알린다. 이를 확인하지 않고 `cap.read()`를 호출하면 계속 실패만 반복하거나, 빈 프레임을 붙잡고 원인을 알 수 없는 오류로 프로그램이 멈추게 된다.

```python
import cv2

def open_capture_safe(source):
    """카메라 인덱스 또는 파일 경로를 열지 못하면 명확한 예외를 던지는 헬퍼."""
    cap = cv2.VideoCapture(source)
    if not cap.isOpened():
        raise RuntimeError(
            f"비디오 소스를 열 수 없습니다: {source!r} "
            "(카메라가 연결되어 있는지, 파일 경로가 올바른지 확인하세요.)"
        )
    return cap

try:
    cap = open_capture_safe(0)          # 웹캠 열기 시도
    # cap = open_capture_safe("video.mp4")  # 또는 파일 열기 시도

    ret, frame = cap.read()
    if not ret:
        raise RuntimeError("카메라는 열렸지만 첫 프레임을 읽지 못했습니다.")

    print("첫 프레임 읽기 성공:", frame.shape)
    cap.release()

except RuntimeError as e:
    print("오류 발생:", e)
```

이 헬퍼 함수는 4.3절에서 만든 `imread_safe()`와 정확히 같은 철학을 따른다. **OpenCV가 조용히 실패를 나타내는 특수한 값(`None`, 빈 배열, `False`)을 반환하는 지점마다, 이를 즉시 확인해서 명확한 예외나 에러 메시지로 바꾸어 준다.** 이런 습관을 들이면 실패 원인을 찾기 위해 스택 추적(traceback)을 한참 거슬러 올라가는 대신, 문제가 발생한 바로 그 지점에서 곧바로 원인을 알 수 있게 된다.

정리하면 다음과 같은 확인 지점들을 항상 습관적으로 넣어야 한다.

| 상황 | 확인 방법 | 실패 시 반환값 |
|---|---|---|
| 이미지 파일 읽기 (`cv2.imread`) | `if img is None:` | `None` |
| 이미지 파일 저장 (`cv2.imwrite`) | `if not success:` | `False` |
| 카메라/동영상 열기 (`cv2.VideoCapture`) | `if not cap.isOpened():` | (열림 상태가 `False`) |
| 프레임 읽기 (`cap.read()`) | `if not ret:` | `ret == False` |

## 4.12 앞으로 이어질 내용: 16장에서 더 깊이 다룰 비디오 처리

이 장에서는 비디오를 다루는 가장 기초적인 골격, 즉 **"열기 → `isOpened()` 확인 → 반복문에서 `read()` → 화면 표시 → 키 입력으로 종료 → `release()`로 자원 해제"**만 익혔다. 이 패턴은 이후 웹캠이나 동영상을 다루는 모든 예제의 출발점이 된다.

16장 "비디오 처리 심화"에서는 여기서 다루지 않은 다음과 같은 주제들을 훨씬 깊이 파고들 것이다.

- `cv2.VideoWriter`를 이용해 처리한 프레임들을 다시 동영상 파일로 인코딩해서 저장하는 방법
- 코덱(FourCC) 선택과 그에 따른 호환성, 파일 용량의 차이
- 프레임 간 차이를 이용한 움직임 감지, 배경 제거(background subtraction) 알고리즘
- 여러 프레임에 걸친 객체 추적(tracking)의 기초
- 실시간 처리 성능을 높이기 위한 프레임 스킵, 스레딩, 큐를 이용한 파이프라인 구성

지금은 이 장에서 배운 읽기/쓰기/캡처의 기본 골격을 확실히 다지는 데에 집중하고, 더 실용적인 응용은 16장에서 이어가도록 하자.

## 요약

- `cv2.imread()`는 파일 확장자와 무관하게 내부 헤더를 분석해 자동으로 포맷을 판별하며, 결과는 3장에서 다룬 것과 동일한 NumPy 배열로 반환된다.
- 읽기 모드는 `IMREAD_COLOR`(기본값, 컬러), `IMREAD_GRAYSCALE`(그레이스케일), `IMREAD_UNCHANGED`(알파 채널 포함 원본 그대로) 등으로 지정할 수 있다.
- 파일을 읽지 못하면 `cv2.imread()`는 예외 없이 `None`을 반환하므로, 항상 `if img is None:`으로 확인하는 습관이 필요하다. 필요하다면 `None`을 예외로 승격시키는 헬퍼 함수를 만들어 두는 것이 안전하다.
- `glob` 모듈로 폴더 안의 여러 이미지 경로를 한 번에 가져와 `for` 문으로 일괄 처리하는 패턴은 실전에서 매우 자주 쓰인다.
- JPEG는 손실 압축으로 용량이 작지만 화질이 저하될 수 있고, PNG는 무손실이며 알파 채널을 지원하고, BMP는 비압축으로 용량이 크지만 구조가 단순하다.
- `cv2.imwrite()`는 `IMWRITE_JPEG_QUALITY`(0~100), `IMWRITE_PNG_COMPRESSION`(0~9) 같은 옵션으로 포맷별 압축 강도를 세밀하게 조절할 수 있다.
- `cv2.VideoCapture`는 웹캠과 동영상 파일을 동일한 인터페이스로 다루며, 여러 카메라가 있을 때는 인덱스 번호로 장치를 선택한다.
- `cap.set()`/`cap.get()`으로 해상도(`CAP_PROP_FRAME_WIDTH/HEIGHT`), FPS(`CAP_PROP_FPS`) 등 속성을 설정/조회할 수 있으며, 설정이 실제로 적용되었는지는 다시 `get()`으로 확인해야 한다.
- 동영상 파일은 `CAP_PROP_FRAME_COUNT`와 `CAP_PROP_FPS`로 전체 프레임 수와 재생 시간을 계산할 수 있다.
- 카메라나 파일을 열지 못했을 때는 `cap.isOpened()`가 `False`를 반환하며, 프레임을 더 읽을 수 없을 때는 `cap.read()`의 첫 번째 반환값(`ret`)이 `False`가 된다. 두 경우 모두 예외 없이 조용히 실패를 알리므로 직접 확인해야 한다.

## 연습문제

1. 존재하지 않는 파일 경로를 `cv2.imread()`에 넘겼을 때 어떤 값이 반환되는지 직접 실행해서 확인하고, 그 값을 확인하지 않고 `.shape`에 접근하면 어떤 오류가 발생하는지 관찰해 보아라. 이어서 4.3절의 `imread_safe()` 헬퍼 함수를 직접 작성해 같은 상황에서 어떤 예외가 발생하는지 비교해 보아라.
2. `glob`을 이용해 어떤 폴더 안의 모든 `.png` 파일을 찾아, 각각을 `IMREAD_GRAYSCALE`로 다시 읽어서 `_gray` 접미사를 붙인 새 파일명으로 저장하는 일괄 처리 스크립트를 작성해 보아라.
3. 같은 사진을 JPEG 품질 90, 50, 10으로 각각 저장한 뒤 `os.path.getsize()`로 세 파일의 용량을 비교하고, 육안으로 화질 차이를 관찰해 보아라. 이어서 같은 사진을 PNG 압축 레벨 0과 9로 각각 저장했을 때 용량 차이는 있지만 화질 차이는 없다는 것을 `cv2.imread()`로 다시 읽어 픽셀 값을 비교(`np.array_equal()`)해 확인해 보아라.
4. 자신의 컴퓨터에 있는 웹캠을 열어, 화면에 실시간 영상을 띄우고 스페이스바를 누르면 현재 프레임을 `capture.png`로 저장하는 프로그램을 작성해 보아라. 프로그램 시작 시 해상도를 1280x720으로 설정을 시도하고, 실제로 적용된 해상도를 화면에 출력하는 코드도 포함하라.
5. 동영상 파일 하나를 준비해 `CAP_PROP_FRAME_COUNT`와 `CAP_PROP_FPS`로 재생 시간을 계산해 출력하고, `CAP_PROP_POS_FRAMES`를 이용해 정확히 중간 지점의 프레임 하나만 이미지 파일로 저장하는 코드를 작성해 보아라.
