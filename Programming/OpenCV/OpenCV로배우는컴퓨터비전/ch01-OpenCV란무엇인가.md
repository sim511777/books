컴퓨터 비전(Computer Vision)은 카메라나 이미지 파일로부터 얻은 픽셀 데이터를 분석해서, 그 안에 무엇이 있는지, 어떤 변화가 일어나고 있는지를 컴퓨터가 이해하도록 만드는 분야입니다. 사람은 사진 한 장을 보고 즉시 "고양이가 소파 위에 앉아 있다"거나 "이 문서는 기울어져 스캔되었다"는 사실을 파악하지만, 컴퓨터에게 이미지란 그저 숫자로 가득 찬 배열일 뿐입니다. 이 숫자 더미에서 의미 있는 정보를 뽑아내는 도구 모음이 바로 컴퓨터 비전 라이브러리이고, 그중 가장 널리 쓰이는 것이 OpenCV입니다.

이 책은 OpenCV를 Python으로, 그리고 NumPy와 함께 다룹니다. 이 장에서는 OpenCV가 어떤 배경에서 만들어졌고 왜 지금까지도 업계 표준처럼 쓰이는지, 그리고 왜 그 많은 언어 바인딩 중에서도 Python이 압도적으로 널리 쓰이는지를 살펴봅니다. 이어서 `opencv-python`, `opencv-contrib-python`, `opencv-python-headless`라는 이름이 비슷한 세 패키지가 각각 무엇을 위한 것인지 정리하고, OpenCV가 실제로 산업 현장에서 어떤 문제를 풀고 있는지 구체적인 사례로 확인합니다. 마지막으로 이 책 전체에서 계속 마주치게 될 아주 중요한 규칙 하나, 바로 "OpenCV의 이미지는 RGB가 아니라 BGR 순서로 저장된다"는 사실을 실수 사례와 함께 확인하고 넘어갑니다.

## 이 책의 예제 코드를 읽는 방법

본격적으로 시작하기 전에, 이 책 전체에서 지켜지는 몇 가지 표기 규칙을 미리 짚어두겠습니다. 모든 코드 예제는 다음 두 줄이 이미 실행된 상태를 기본으로 가정합니다.

```python
import cv2
import numpy as np
```

즉 개별 예제에서 매번 이 두 줄을 다시 적지 않더라도, `cv2`와 `np`라는 이름은 항상 이 두 모듈을 가리킵니다. `matplotlib`이 필요한 예제에서는 `import matplotlib.pyplot as plt`를 별도로 표시합니다. 또한 예제 코드에서 `"sample.jpg"`처럼 등장하는 파일명은 여러분이 가진 임의의 이미지 파일로 자유롭게 바꿔서 실습해도 되는 자리 표시자(placeholder)입니다. 실제로 실행해보려면 코드와 같은 폴더에 그 이름의 이미지 파일을 준비해두거나, 코드의 파일명을 여러분이 가진 이미지의 실제 경로로 바꿔주면 됩니다.

화면에 결과를 표시하는 부분(`cv2.imshow()`)은 기본적으로 데스크톱에서 `.py` 파일을 직접 실행하는 환경을 기준으로 작성합니다. Jupyter Notebook이나 Google Colab처럼 GUI 창을 띄울 수 없는 환경에서 실습하고 있다면, 이 부분만 `matplotlib.pyplot.imshow()`로 바꿔 쓰면 되는데, 그 구체적인 방법은 다음 장에서 곧바로 다룹니다.

마지막으로, 이 책의 코드는 특정 OpenCV 버전에 종속되지 않도록 안정적으로 유지되어 온 핵심 API만을 사용합니다. 다만 컴퓨터 비전 라이브러리는 활발히 개발되고 있는 프로젝트인 만큼, 여러분이 실습하는 시점의 `opencv-python` 버전에 따라 일부 함수의 기본 매개변수 값이 이 책의 설명과 미세하게 다를 수 있습니다. 이런 차이를 만났을 때는 앞서 소개한 공식 문서에서 여러분이 설치한 버전의 시그니처를 다시 확인해보는 것이 가장 정확합니다.

## OpenCV의 탄생과 발전

OpenCV(Open Source Computer Vision Library)는 1999년 인텔(Intel)의 내부 연구 프로젝트로 시작되었습니다. 당시 인텔은 CPU 성능을 끌어올릴 수 있는 애플리케이션 영역을 넓히려는 목적으로 컴퓨터 비전 연구를 지원하고 있었는데, 문제는 연구자들이 실시간 영상 처리 알고리즘을 논문마다 각자 다른 방식으로, 그것도 최적화가 거의 되지 않은 형태로 구현하고 있었다는 점이었습니다. 이런 중복과 비효율을 줄이기 위해, 인텔은 표준적인 컴퓨터 비전 알고리즘들을 하나의 최적화된 오픈소스 라이브러리로 묶어 무료로 공개하기로 했습니다. 이것이 OpenCV의 출발점입니다.

2000년에 알파 버전이 처음 공개된 이후, OpenCV는 여러 차례 소유권과 관리 주체가 바뀌는 굴곡을 겪었습니다. 초기에는 인텔이 직접 관리했지만, 이후 Willow Garage(로봇 운영체제 ROS를 만든 곳으로도 유명한 로보틱스 연구소)가 개발을 이어받아 1.0 버전을 정식으로 출시했고, 뒤이어 Itseez라는 회사가 개발을 주도하며 2.x와 3.x 버전을 발전시켰습니다. 2016년 Itseez가 인텔에 인수된 뒤, 2012년에 설립된 비영리 재단인 **OpenCV Foundation**이 프로젝트의 장기적인 방향을 관리하는 구심점 역할을 맡아 지금까지 이어지고 있습니다. 즉 OpenCV는 특정 기업 하나의 소유물이 아니라, 여러 기업과 개인 기여자가 함께 유지하는 커뮤니티 프로젝트로 자리 잡은 셈입니다.

라이선스 측면에서도 OpenCV는 처음부터 상업적 이용에 매우 개방적인 태도를 취했습니다. 3.x 버전까지는 BSD 라이선스를 사용했고, 4.5.0부터는 **Apache 2.0 라이선스**로 전환되었습니다. 두 라이선스 모두 소스 코드를 공개하지 않고도 상업 제품에 자유롭게 포함시킬 수 있다는 공통점이 있으며, Apache 2.0은 여기에 특허 관련 조항이 추가되어 대기업들이 법적으로 더 안심하고 채택할 수 있게 되었습니다. 이런 개방적인 라이선스 정책 덕분에 스타트업의 프로토타입부터 자동차 회사의 첨단 운전자 보조 시스템(ADAS)까지, OpenCV는 규모와 업종을 가리지 않고 널리 채택되었습니다.

OpenCV는 핵심 연산 부분이 C와 C++로 작성되어 있습니다. 이미지 한 장은 수십만~수백만 개의 픽셀로 이루어져 있고, 비디오라면 초당 수십 장의 이미지를 실시간으로 처리해야 합니다. 이런 작업을 빠르게 처리하려면 하드웨어에 가까운 저수준 언어로 메모리와 연산을 직접 제어할 수 있어야 했고, C++가 그 요구에 가장 잘 맞았습니다. 이 C++ 코어 위에 Python, Java, JavaScript 등 다양한 언어를 위한 바인딩(연결 계층)이 얹혀 있는데, 이 책에서 우리가 `import cv2`로 불러와 쓰는 `opencv-python`도 바로 그 바인딩 중 하나입니다. 즉 Python 코드로 `cv2.GaussianBlur()`를 호출해도, 실제 블러 연산은 컴파일된 C++ 코드가 수행합니다. 이 구조 덕분에 Python처럼 상대적으로 느린 인터프리터 언어에서도 네이티브 코드 수준의 처리 속도를 낼 수 있습니다.

### 버전으로 보는 OpenCV의 발전 과정

OpenCV의 주요 버전을 따라가 보면, 이 라이브러리가 어떤 방향으로 성숙해왔는지가 뚜렷하게 드러납니다.

- **1999~2000년, 알파 단계**: 인텔 내부 연구 프로젝트로 시작되어 C 언어 기반의 API가 먼저 만들어졌습니다.
- **2006년, OpenCV 1.0**: Willow Garage의 지원 아래 첫 정식 버전이 나왔습니다. 이때까지는 `IplImage`라는 C 스타일 구조체로 이미지를 표현했습니다.
- **2009년, OpenCV 2.0**: `cv::Mat` 클래스를 도입한 C++ API가 새로 추가되었습니다. 메모리를 직접 관리해야 했던 C API의 번거로움이 크게 줄어들었고, 이후 OpenCV 코드의 주류 스타일이 되었습니다.
- **2015년, OpenCV 3.0**: 라이브러리가 여러 모듈로 잘게 나뉘었고, 특허나 실험적 성격 때문에 논란이 될 수 있는 알고리즘들은 `opencv_contrib`라는 별도 저장소로 분리되었습니다. 오늘날 `opencv-contrib-python`이 별도 패키지로 존재하는 이유가 바로 이 시점의 결정에서 비롯됩니다.
- **2018년, OpenCV 4.0**: 오래된 C API가 완전히 제거되어 `cv::Mat` 기반 C++ API로 통일되었고, 그래프 기반 실행 엔진인 G-API가 추가되었으며, 딥러닝 추론을 담당하는 DNN 모듈이 본격적으로 강화되기 시작했습니다.
- **2020년, OpenCV 4.5.0**: 라이선스가 BSD에서 Apache 2.0으로 전환되었습니다.
- **현재**: OpenCV Foundation의 관리 아래, DNN 모듈의 성능 개선과 최신 신경망 아키텍처 지원, 하드웨어 가속 확대를 중심으로 개발이 계속되고 있습니다.

이 흐름에서 알 수 있듯, OpenCV는 "고전적인 영상 처리 알고리즘 모음"에서 출발해 지금은 "고전적 기법과 딥러닝 기법이 공존하는 통합 비전 툴킷"으로 성격이 확장되어 왔습니다. 이 책의 앞부분(3~14장)은 여전히 유효하고 중요한 고전적 기법을, 뒷부분(15~17장)은 매칭·추적과 딥러닝 추론을 다루면서 이런 확장의 흐름을 그대로 따라갑니다.

## OpenCV가 지금까지 표준으로 남아있는 이유

OpenCV가 20년 넘게 컴퓨터 비전의 기본 도구로 남아있는 데는 몇 가지 이유가 있습니다.

첫째, **다루는 범위가 매우 넓습니다.** 단순한 이미지 파일 입출력부터 색공간 변환, 필터링, 기하 변환, 엣지 검출, 컨투어 분석, 특징점 매칭, 얼굴 검출, 최근에는 딥러닝 모델을 불러와 추론하는 DNN 모듈까지 하나의 라이브러리 안에 다 들어 있습니다. 이 책의 목차만 봐도 5장 색공간 변환부터 17장 얼굴·객체 검출까지, 컴퓨터 비전에서 실무적으로 쓰이는 거의 모든 기법이 OpenCV 하나로 커버된다는 것을 알 수 있습니다.

둘째, **성능이 뛰어납니다.** 핵심 연산이 최적화된 C++ 코드로 구현되어 있고, 많은 함수가 내부적으로 멀티스레딩, SIMD(단일 명령 다중 데이터) 명령어, 그리고 가능한 경우 GPU 가속(CUDA, OpenCL)까지 활용합니다. Python에서 `for` 반복문으로 픽셀을 하나씩 순회하며 직접 연산을 짜면 매우 느리지만, 같은 연산을 `cv2` 함수 하나로 호출하면 내부적으로 최적화된 C++ 루프가 돌기 때문에 체감 속도가 수십 배에서 수백 배까지 차이 날 수 있습니다.

셋째, **플랫폼을 가리지 않습니다.** Windows, Linux, macOS는 물론 안드로이드와 iOS까지 지원하며, 라즈베리 파이 같은 임베디드 보드에서도 문제없이 동작합니다. 같은 Python 코드가 데스크톱에서 개발되어 그대로 엣지 디바이스에 배포되는 사례도 흔합니다.

넷째, **커뮤니티와 생태계가 거대합니다.** 수십 년간 쌓인 튜토리얼, 스택오버플로우 질문, 예제 코드가 존재하고, 최신 딥러닝 프레임워크(TensorFlow, PyTorch, ONNX 등)로 학습한 모델을 OpenCV의 DNN 모듈로 바로 불러와 실행할 수도 있습니다. 이 내용은 17장에서 자세히 다룹니다.

다섯째, **다양한 하드웨어 가속을 지원합니다.** OpenCV는 CPU의 멀티코어와 SIMD 명령어뿐 아니라, 조건이 맞으면 CUDA(NVIDIA GPU)나 OpenCL 기반 가속도 활용할 수 있도록 설계되어 있습니다. 딥러닝 모델 추론처럼 연산량이 많은 작업에서는 이런 하드웨어 가속이 실시간 처리 여부를 가르는 결정적인 요인이 되기도 합니다. `opencv-python`을 기본 설치로 쓰는 경우 CUDA 가속은 보통 비활성화되어 있고, GPU 가속이 필요하다면 CUDA를 지원하도록 직접 빌드한 OpenCV를 사용해야 하는데, 이 내용은 18장 성능 최적화에서 더 다룹니다.

## 왜 Python 바인딩이 이렇게 널리 쓰이는가

OpenCV는 여러 언어에서 사용할 수 있지만, 실제 학습 자료와 실무 프로젝트를 보면 Python 바인딩인 `opencv-python`이 압도적으로 많이 쓰입니다. 여기에는 몇 가지 뚜렷한 이유가 있습니다.

**첫째, NumPy 생태계와 완벽하게 맞물립니다.** OpenCV의 Python 바인딩은 이미지를 `np.ndarray`(NumPy 배열)로 표현합니다. 이는 단순한 구현상의 선택이 아니라, Python 데이터 과학 생태계 전체와 자연스럽게 연결되는 결정적인 지점입니다. `cv2.imread()`로 읽은 이미지를 곧바로 NumPy의 슬라이싱, 브로드캐스팅, 통계 함수(`np.mean()`, `np.std()` 등)에 넘길 수 있고, 반대로 NumPy로 생성하거나 가공한 배열을 다시 `cv2` 함수에 넘길 수도 있습니다. 예를 들어 이미지의 특정 영역만 잘라내는 일은 별도의 OpenCV 함수 없이 그냥 배열 슬라이싱으로 끝납니다.

```python
import cv2

img = cv2.imread("sample.jpg")

# NumPy 슬라이싱으로 관심 영역(ROI)을 그대로 잘라낸다
roi = img[100:300, 200:500]

# 배열의 형태(shape)와 자료형(dtype)도 NumPy의 속성 그대로 확인한다
print(roi.shape, roi.dtype)
```

**둘째, 데이터 과학·머신러닝 파이프라인과 통합이 매끄럽습니다.** 오늘날 컴퓨터 비전 프로젝트의 상당수는 PyTorch나 TensorFlow 같은 딥러닝 프레임워크와 함께 진행되는데, 이 프레임워크들 역시 Python 생태계 위에서 NumPy 배열이나 그와 호환되는 텐서를 데이터 교환 형식으로 삼습니다. 즉 OpenCV로 이미지를 전처리하고(리사이즈, 정규화, 색공간 변환), 그 결과를 곧바로 딥러닝 모델의 입력으로 넘기는 흐름이 언어를 바꾸거나 데이터를 직렬화·역직렬화하는 과정 없이 이어집니다. `pandas`로 라벨 데이터를 관리하고, `matplotlib`으로 결과를 시각화하고, `scikit-learn`으로 후처리 분류기를 돌리는 것도 모두 같은 Python 프로세스 안에서 자연스럽게 이어집니다.

**셋째, 프로토타이핑 속도가 압도적으로 빠릅니다.** C++로 아이디어 하나를 검증하려면 헤더를 포함하고, 빌드 시스템을 구성하고, 컴파일하고 링크하는 과정을 거쳐야 합니다. Python에서는 인터프리터에 몇 줄을 입력하거나 Jupyter Notebook 셀 하나를 실행하는 것으로 즉시 결과를 확인할 수 있습니다. 이런 빠른 반복(iteration) 주기는 "이 필터를 적용하면 어떻게 보일까", "이 임계값을 조금 낮추면 결과가 나아질까"처럼 시행착오가 많은 컴퓨터 비전 작업의 특성과 특히 잘 맞습니다. 연구자와 실무자 대부분이 아이디어를 빠르게 실험해보는 초기 단계에서 Python을 선택하고, 정말 실시간 성능이 중요한 최종 배포 단계에서만 일부를 C++로 옮기는 경우가 많습니다.

**넷째, 학습 자료가 가장 풍부합니다.** 위 세 가지 이유가 맞물려 Python이 사실상 OpenCV 학습의 기본 언어가 되었고, 그 결과 튜토리얼, 강좌, 스택오버플로우 답변, 오픈소스 예제 프로젝트 대부분이 Python으로 작성됩니다. 이는 다시 더 많은 사람이 Python으로 OpenCV를 배우게 만드는 선순환으로 이어졌습니다.

**다섯째, Python 특유의 성능 제약(GIL)에서 비교적 자유롭습니다.** Python 인터프리터는 GIL(Global Interpreter Lock)이라는 잠금 장치 때문에 한 프로세스 안에서 순수 Python 코드를 여러 스레드가 동시에 실행할 수 없습니다. 그런데 `cv2` 함수는 대부분 호출되는 순간 실행 흐름이 C++ 코드로 넘어가고, 이 무거운 연산을 수행하는 동안에는 OpenCV 바인딩이 내부적으로 GIL을 해제합니다. 그래서 한 스레드가 `cv2.GaussianBlur()`처럼 시간이 걸리는 연산을 수행하는 동안, 다른 스레드는 그 결과를 기다리지 않고 자신의 Python 코드를 계속 실행할 수 있습니다. 이 덕분에 "카메라에서 프레임을 읽는 스레드"와 "읽은 프레임을 처리하는 스레드"를 나누는 식의 병렬 구조가 Python에서도 비교적 자연스럽게 동작합니다.

## 미니 파이프라인으로 보는 Python 생태계의 힘

앞서 말한 "NumPy 생태계와의 결합"과 "데이터 과학 파이프라인과의 통합"이 실제로 어떤 모습인지, 짧은 예제로 직접 확인해보겠습니다. 다음 코드는 이미지를 읽고, OpenCV로 전처리한 다음, 그 결과를 matplotlib으로 한 화면에 나란히 비교해서 보여주는 아주 작은 파이프라인입니다.

```python
import cv2
import numpy as np
import matplotlib.pyplot as plt

# 1. OpenCV로 이미지를 읽고 전처리한다
img_bgr = cv2.imread("sample.jpg")
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)
img_gray = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2GRAY)
img_blur = cv2.GaussianBlur(img_rgb, (9, 9), 0)

# 2. NumPy로 간단한 통계를 계산한다 (별도의 OpenCV 함수 없이)
brightness = np.mean(img_gray)
print(f"평균 밝기: {brightness:.1f} (0~255)")

# 3. matplotlib으로 원본, 그레이스케일, 블러 처리 결과를 나란히 비교한다
fig, axes = plt.subplots(1, 3, figsize=(12, 4))
axes[0].imshow(img_rgb)
axes[0].set_title("원본")
axes[1].imshow(img_gray, cmap="gray")
axes[1].set_title("그레이스케일")
axes[2].imshow(img_blur)
axes[2].set_title("가우시안 블러")
for ax in axes:
    ax.axis("off")
plt.tight_layout()
plt.show()
```

이 짧은 코드 안에서 이미지 데이터는 한 번도 형식을 바꾸지 않고 그대로 흘러갑니다. `cv2.imread()`가 반환한 NumPy 배열을 `cv2.cvtColor()`와 `cv2.GaussianBlur()`가 받아 처리하고, 그 결과를 다시 `np.mean()`이 통계로 요약하고, 마지막으로 `matplotlib`이 화면에 그립니다. C++나 다른 언어였다면 라이브러리마다 자료형을 서로 변환해주는 코드가 곳곳에 필요했을 자리인데, Python에서는 "이미지 = NumPy 배열"이라는 하나의 규약 덕분에 그런 변환 코드가 전혀 필요 없습니다. 딥러닝 프레임워크로 이 파이프라인을 확장할 때도 마찬가지입니다. `img_blur`를 PyTorch의 `torch.from_numpy()`나 TensorFlow의 `tf.convert_to_tensor()`에 그대로 넘길 수 있는 것도 결국 이 배열 표현이 공통 언어 역할을 하기 때문입니다.

## opencv-python, opencv-contrib-python, opencv-python-headless

PyPI에서 OpenCV를 검색하면 이름이 비슷한 패키지가 여러 개 나와 혼란스러울 수 있습니다. 이 셋의 차이를 정확히 알아두면 나중에 설치 오류를 만났을 때도 원인을 빠르게 짚어낼 수 있습니다.

| 패키지 | 포함 내용 | GUI 의존성 | 주된 용도 |
|---|---|---|---|
| `opencv-python` | OpenCV의 핵심 모듈(이미지 입출력, 필터링, 기하 변환, 컨투어, 특징점 매칭 등) | 있음(`cv2.imshow` 등 GUI 함수 사용 가능) | 데스크톱 환경에서의 일반적인 개발·학습 |
| `opencv-contrib-python` | 핵심 모듈 + 특허·실험적 성격으로 별도 관리되는 확장 모듈(추가 특징점 검출기, 일부 트래킹 알고리즘 등) | 있음 | 확장 모듈의 특정 알고리즘이 꼭 필요한 경우 |
| `opencv-python-headless` | `opencv-python`과 동일한 핵심 모듈 | **없음**(GUI 관련 함수 호출 시 오류) | 서버, 도커 컨테이너, CI 파이프라인처럼 화면 출력이 불가능하거나 불필요한 환경 |

세 패키지 모두 같은 `cv2`라는 이름으로 임포트되며, 내부적으로 서로 파일을 덮어쓰기 때문에 **한 가상환경에는 반드시 하나만 설치**해야 합니다. `headless` 버전은 이름 그대로 "머리(디스플레이)가 없는" 환경, 즉 GUI 라이브러리(X11, GTK 등)에 대한 의존성을 완전히 제거한 빌드입니다. 우분투 기반의 도커 컨테이너에 `opencv-python`을 설치하고 실행했을 때 `ImportError: libGL.so.1: cannot open shared object file`처럼 그래픽 관련 공유 라이브러리를 찾지 못했다는 오류가 나는 경우가 매우 흔한데, 이는 대부분 GUI가 없는 서버 환경에 GUI 의존 패키지를 설치했기 때문입니다. 이때는 그래픽 라이브러리를 추가로 설치하는 대신, `opencv-python`을 지우고 `opencv-python-headless`를 설치하는 것이 훨씬 깔끔한 해결책입니다. 이 오류와 해결 방법은 2장에서 실제 설치 과정을 다룰 때 다시 자세히 짚습니다.

## OpenCV로 무엇을 할 수 있는가: 실전 활용 분야

컴퓨터 비전이 실제로 어떤 문제를 풀어내는지 감을 잡기 위해, OpenCV가 산업 현장에서 쓰이는 구체적인 사례를 코드와 함께 살펴보겠습니다. 아래 코드들은 뒤에서 배울 함수들을 미리 살짝 맛보는 용도이므로, 지금 당장 모든 함수의 의미를 이해하지 못해도 괜찮습니다. "OpenCV로 이런 일이 가능하구나"라는 감각을 얻는 것이 이 절의 목표입니다.

### 산업 자동화 검사: 불량품 검출

제조업 생산라인에서는 컨베이어 벨트 위를 지나가는 제품을 카메라로 촬영하고, 표면의 스크래치, 찌그러짐, 색상 불균일 같은 결함을 실시간으로 검출합니다. 예를 들어 PCB(인쇄 회로 기판) 조립 라인에서는 컨투어 검출(12~13장)로 각 부품의 위치와 크기를 확인하고, 정상 범위를 벗어나는 크기의 영역을 결함으로 판정합니다. 사람의 눈으로 하루 수만 개를 검사하는 것은 피로도에 따라 정확도가 떨어지지만, OpenCV 기반 검사 시스템은 일관된 기준으로 24시간 동작할 수 있습니다.

```python
import cv2

img = cv2.imread("part.jpg", cv2.IMREAD_GRAYSCALE)

# 배경과 부품을 흑백으로 분리한다
_, binary = cv2.threshold(img, 127, 255, cv2.THRESH_BINARY)

# 분리된 영역의 윤곽선을 모두 찾는다
contours, _ = cv2.findContours(binary, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

# 정상 범위(예: 1500~3000 픽셀)를 벗어나는 영역을 결함으로 표시한다
for c in contours:
    area = cv2.contourArea(c)
    if area < 1500 or area > 3000:
        print(f"결함 의심 영역 발견 (면적={area:.1f})")
```

### 의료 영상 분석

X-ray, CT, MRI, 초음파 영상에서 관심 영역을 분리하고 정량적으로 분석하는 데 OpenCV가 널리 쓰입니다. 예를 들어 세포 이미지에서 임계처리(10장)와 모폴로지 연산(11장)으로 개별 세포를 분리해 개수를 세는 연구용 파이프라인이 흔합니다. 실제 임상 진단 자체는 반드시 전문 의료기기 규제를 통과한 소프트웨어가 담당해야 하지만, 연구·전처리 단계에서는 OpenCV가 사실상 표준 도구로 쓰입니다.

```python
import cv2

img = cv2.imread("cells.jpg", cv2.IMREAD_GRAYSCALE)

# Otsu 방법으로 임계값을 자동으로 계산해 이진화한다
_, binary = cv2.threshold(img, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)

# 열림 연산으로 작은 노이즈를 제거해 세포 영역을 정리한다
kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (3, 3))
cleaned = cv2.morphologyEx(binary, cv2.MORPH_OPEN, kernel)

# 서로 붙어 있지 않은 영역에 번호를 붙여 개수를 센다
num_labels, labels = cv2.connectedComponents(cleaned)
print(f"검출된 세포 수: {num_labels - 1}")  # 배경(0번 레이블)을 제외
```

### 자율주행: 차선과 객체 인식

자동차에 장착된 카메라 영상에서 차선을 검출하려면 엣지 검출(12장)과 허프 변환으로 직선 성분을 찾아냅니다. 앞차나 보행자, 신호등 같은 객체를 인식하는 데는 OpenCV의 DNN 모듈(17장)로 딥러닝 기반 객체 검출 모델을 불러와 실시간으로 추론합니다. Tesla를 비롯한 여러 ADAS(첨단 운전자 보조 시스템) 스타트업의 초기 프로토타입에서 OpenCV가 핵심 도구로 쓰인 사례가 잘 알려져 있습니다.

```python
import cv2

frame = cv2.imread("road.jpg", cv2.IMREAD_GRAYSCALE)

# 엣지를 검출해 밝기가 급격히 변하는 경계선을 찾는다
edges = cv2.Canny(frame, 50, 150)

# 허프 변환으로 엣지 위에서 직선 성분(차선 후보)을 찾는다
lines = cv2.HoughLinesP(
    edges, rho=1, theta=3.14159 / 180, threshold=50,
    minLineLength=40, maxLineGap=10
)
print(f"검출된 직선 후보 개수: {0 if lines is None else len(lines)}")
```

### AR/VR: 평면 인식과 추적

스마트폰 카메라로 바닥이나 벽 같은 평면을 인식하고 그 위에 가상의 3D 물체를 자연스럽게 올려놓으려면, 특징점 검출과 매칭(15장)으로 카메라의 위치와 방향을 실시간으로 추적하는 기술(SLAM, Simultaneous Localization and Mapping)이 필요합니다. OpenCV는 이런 특징점 기반 추적에 쓰이는 대표적인 검출기 중 하나인 ORB(Oriented FAST and Rotated BRIEF)를 기본 모듈에 포함하고 있습니다.

```python
import cv2

img = cv2.imread("desk.jpg", cv2.IMREAD_GRAYSCALE)

# ORB 검출기를 만들어 특징점과 그 설명자(descriptor)를 함께 계산한다
orb = cv2.ORB_create(nfeatures=500)
keypoints, descriptors = orb.detectAndCompute(img, None)

print(f"검출된 특징점 개수: {len(keypoints)}")
print(f"설명자 배열 형태: {descriptors.shape}")
```

### 보안·감시: 사람 계수와 이상행동 감지

매장이나 공공장소에 설치된 CCTV 영상에서 배경 제거(16장)로 움직이는 객체만 분리해내고, 그 객체의 궤적을 추적해 사람 수를 세거나 특정 구역에 오래 머무는 이상 행동을 감지하는 시스템이 많습니다. 예를 들어 매장 입구 카메라로 시간대별 방문객 수를 집계하거나, 공장의 위험 구역에 작업자가 진입했는지를 실시간으로 감지해 경보를 울리는 안전 시스템에 OpenCV가 쓰입니다.

```python
import cv2

cap = cv2.VideoCapture("store_entrance.mp4")
bg_subtractor = cv2.createBackgroundSubtractorMOG2(detectShadows=True)

ret, frame = cap.read()
while ret:
    # 현재 프레임에서 배경과 다른(움직이는) 영역만 마스크로 얻는다
    fg_mask = bg_subtractor.apply(frame)
    moving_pixels = cv2.countNonZero(fg_mask)
    ret, frame = cap.read()

cap.release()
```

### 로보틱스: 비전 기반 제어

로봇 팔이 컨베이어 벨트 위의 물체를 집어 올리려면, 먼저 카메라로 물체의 위치와 자세를 인식해야 합니다. 컨투어와 모양 분석(13장)으로 물체를 감싸는 최소 회전 사각형을 계산하면, 그 중심점과 회전 각도를 그리퍼(집는 부분)의 목표 좌표로 바로 활용할 수 있습니다. 물류 창고의 자동 분류 로봇, 농업용 과일 수확 로봇 등에서 이런 "비전 기반 제어(vision-guided control)" 방식이 널리 활용됩니다.

```python
import cv2

img = cv2.imread("object_on_belt.jpg", cv2.IMREAD_GRAYSCALE)
_, binary = cv2.threshold(img, 127, 255, cv2.THRESH_BINARY)
contours, _ = cv2.findContours(binary, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

largest = max(contours, key=cv2.contourArea)

# 물체를 감싸는 최소 회전 사각형: (중심 좌표), (너비, 높이), 회전 각도
(cx, cy), (w, h), angle = cv2.minAreaRect(largest)
print(f"물체 중심: ({cx:.1f}, {cy:.1f}), 회전 각도: {angle:.1f}도")
```

## 다른 Python 이미지 라이브러리와의 비교

Python에는 이미지를 다루는 라이브러리가 OpenCV 말고도 여럿 있습니다. 각각의 강점이 다르므로, 프로젝트 성격에 맞게 골라 쓰는 것이 좋습니다.

**Pillow(PIL Fork).** 이미지 파일을 열고, 크기를 조절하고, 자르고, 회전시키고, 텍스트를 그려 넣는 등 단순하고 직관적인 이미지 조작에 특화되어 있습니다. API가 매우 간결해서 "썸네일 만들기", "워터마크 넣기" 같은 가벼운 작업에는 OpenCV보다 오히려 코드가 짧아지는 경우가 많습니다. 다만 임계처리, 컨투어 검출, 특징점 매칭 같은 본격적인 컴퓨터 비전 알고리즘은 제공하지 않습니다.

**scikit-image.** 과학 연구 용도에 특화된 이미지 처리 라이브러리로, NumPy·SciPy 생태계와 깊이 통합되어 있고 알고리즘의 수학적 정확성과 문서화 수준이 높습니다. 새로운 이미지 처리 알고리즘을 연구하거나 논문을 재현할 때 자주 선택되지만, 실시간 비디오 처리 성능이나 산업용 API의 폭 넓은 커버리지는 OpenCV에 못 미칩니다.

**OpenCV.** 위 두 라이브러리와 비교했을 때 OpenCV의 가장 뚜렷한 강점은 **실시간 성능**과 **방대한 컴퓨터 비전 알고리즘 커버리지**입니다. C++ 코어 기반이라 비디오 스트림처럼 초당 수십 프레임을 처리해야 하는 작업에 적합하고, 이미지 처리를 넘어 객체 검출, 추적, 카메라 캘리브레이션, 3D 재구성, 딥러닝 추론까지 하나의 라이브러리로 다룰 수 있습니다.

세 라이브러리의 성격을 표로 정리하면 다음과 같습니다.

| 라이브러리 | 강점 | 대표적인 용도 | 비디오/실시간 처리 |
|---|---|---|---|
| Pillow | 간결한 API, 빠른 학습 곡선 | 리사이즈, 자르기, 회전, 포맷 변환, 워터마크 | 지원하지 않음(정지 이미지 중심) |
| scikit-image | 수학적 정확성, 풍부한 문서와 논문 재현성 | 알고리즘 연구, 과학적 이미지 분석 | 제한적 |
| OpenCV | 실시간 성능, 방대한 알고리즘 커버리지 | 실시간 비전 파이프라인, 산업/로보틱스/딥러닝 통합 | 강력하게 지원 |

정리하면, 간단한 이미지 편집에는 Pillow, 알고리즘 연구에는 scikit-image, 실시간 성능과 폭넓은 컴퓨터 비전 기능이 필요할 때는 OpenCV를 선택하는 것이 실무적인 기준입니다. 세 라이브러리는 서로 배타적이지 않아서, 실제 프로젝트에서는 파일 포맷 변환은 Pillow로, 본격적인 비전 알고리즘은 OpenCV로 처리하는 식으로 함께 쓰이기도 합니다.

![OpenCV Python 생태계와 활용 분야](images/ch01-opencv-bindings.svg)

`opencv-python` 패키지 안에는 이미지 입출력을 담당하는 `imgcodecs`, 필터링과 기하 변환을 담당하는 `imgproc`, 비디오/카메라 입출력을 담당하는 `videoio`, 얼굴·객체 검출을 담당하는 `objdetect`, 딥러닝 추론을 담당하는 `dnn`, 특징점 검출·매칭을 담당하는 `features2d` 같은 모듈들이 함께 들어 있습니다. 이 모듈들이 다루는 이미지 데이터는 모두 NumPy 배열로 표현되기 때문에, OpenCV의 결과물을 곧바로 데이터 분석·시각화·머신러닝 도구로 넘길 수 있습니다. 그 결과가 앞서 살펴본 산업 검사, 의료 영상, 자율주행, AR/VR, 보안, 로보틱스 같은 실제 응용 분야로 이어지는 것입니다.

각 모듈이 이 책의 어느 장과 연결되는지 미리 표시해두면 앞으로의 학습 경로가 더 뚜렷해집니다. `imgcodecs`는 4장(이미지 입출력)에서, `imgproc`은 5장·8~11장(색공간 변환, 기하 변환, 필터링, 임계처리, 모폴로지)에서, `videoio`는 4장과 16장(비디오·배경 제거)에서, `features2d`는 15장(특징점 매칭)에서, `objdetect`와 `dnn`은 17장(얼굴·객체 검출)에서 각각 본격적으로 다룹니다. 즉 이 다이어그램의 중간 층에 있는 모듈 하나하나가 곧 이 책의 한 챕터 묶음에 대응한다고 볼 수 있습니다.

## 채널 순서에 대한 중요한 사실: BGR

OpenCV를 처음 접하는 사람들이 가장 자주 놀라는 지점이 하나 있습니다. 컬러 이미지를 불러오면 색상 채널이 우리가 흔히 생각하는 R-G-B(빨강-초록-파랑) 순서가 아니라 **B-G-R(파랑-초록-빨강)** 순서로 저장된다는 점입니다.

이 순서는 OpenCV 전체에서 동일하게 적용되는 기본 관례입니다. `cv2.imread()`는 이미지를 BGR 순서로 메모리에 채워 넣습니다. 이는 OpenCV가 처음 만들어질 당시 널리 쓰이던 Windows 비트맵 포맷 등에서 BGR 순서가 관례였던 역사적 배경 때문인데, 지금까지도 하위 호환성을 위해 그대로 유지되고 있습니다.

이 사실이 왜 중요한지는 아주 흔한 실수 사례로 확인해보겠습니다. 다음 코드는 OpenCV로 이미지를 읽고 곧바로 matplotlib으로 띄워보는, 초보자가 가장 많이 저지르는 실수입니다.

```python
import cv2
import matplotlib.pyplot as plt

img = cv2.imread("sample.jpg")  # BGR 순서로 읽힌다

plt.imshow(img)  # matplotlib은 RGB 순서를 기대한다
plt.show()
```

이 코드를 실행하면 창이 뜨긴 하지만, 원본 사진에서 붉었던 부분이 파랗게, 파랬던 부분이 붉게 뒤바뀐 이상한 색으로 보입니다. 원인은 명확합니다. `cv2.imread()`가 반환한 배열은 채널이 B, G, R 순서로 쌓여 있는데, `matplotlib.pyplot.imshow()`는 배열의 채널을 R, G, B 순서로 해석하기 때문입니다. 즉 실제로는 B 채널의 값이 R 채널 자리에서, R 채널의 값이 B 채널 자리에서 해석되어 색이 뒤집혀 보이는 것입니다. OpenCV 자체에는 아무 문제가 없고, 단지 두 라이브러리가 채널 순서에 대해 서로 다른 관례를 쓰고 있을 뿐입니다.

해결 방법은 matplotlib에 넘기기 전에 `cv2.cvtColor()`로 명시적으로 색공간을 변환해주는 것입니다.

```python
import cv2
import matplotlib.pyplot as plt

img = cv2.imread("sample.jpg")
img_rgb = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)  # BGR -> RGB로 채널 순서 변경

plt.imshow(img_rgb)
plt.show()
```

`cv2.COLOR_BGR2RGB`는 "채널 순서를 뒤집어라"는 뜻의 변환 코드로, 실제로는 B 채널과 R 채널의 위치를 서로 바꿔주는 연산입니다. 이 한 줄만 추가하면 matplotlib에서도 원본과 같은 색으로 이미지가 표시됩니다. 이 변환은 OpenCV로 읽은 이미지를 딥러닝 프레임워크나 웹 프레임워크, 다른 시각화 도구로 넘길 때도 똑같이 필요한 경우가 많으므로, "OpenCV는 기본적으로 BGR을 쓰고, 다른 대부분의 도구는 RGB를 기대한다"는 규칙을 이번 장에서 확실히 기억해두는 것이 좋습니다.

이 문제는 반대 방향에서도 똑같이 일어납니다. 예를 들어 다른 라이브러리(Pillow, 또는 딥러닝 프레임워크의 텐서)에서 RGB 순서로 만들어진 배열을 `cv2.imwrite()`로 그대로 저장하면, OpenCV는 이 배열이 이미 BGR 순서라고 가정하고 파일에 그대로 써버립니다. 그 결과 저장된 이미지 파일을 다른 뷰어로 열어보면 역시 색이 뒤바뀐 채로 보입니다.

```python
import cv2
import numpy as np

# RGB 순서로 만들어졌다고 가정한 배열(예: 다른 라이브러리에서 받아온 결과)
rgb_array = np.zeros((100, 100, 3), dtype=np.uint8)
rgb_array[:, :, 0] = 255  # R 채널을 채워 "빨간 이미지"를 의도했다고 하자

# 변환 없이 그대로 저장하면 OpenCV는 이 배열을 BGR로 해석해버린다
cv2.imwrite("wrong_color.png", rgb_array)  # 실제로는 "파란 이미지"로 저장된다

# 올바르게 저장하려면 저장하기 전에 RGB -> BGR로 변환해야 한다
bgr_array = cv2.cvtColor(rgb_array, cv2.COLOR_RGB2BGR)
cv2.imwrite("correct_color.png", bgr_array)
```

정리하면, OpenCV의 함수(`imread`, `imshow`, `imwrite` 등)는 항상 BGR을 전제로 동작하고, OpenCV 바깥의 대부분의 도구는 RGB를 전제로 동작합니다. 이 경계를 넘어갈 때마다 `cv2.cvtColor()`로 순서를 맞춰주는 것이 안전합니다. 이 내용은 5장 색공간 변환에서 더 다양한 변환 코드와 함께 자세히 다루고, 2장과 4장에서 이미지를 처음 읽고 화면에 띄워볼 때도 다시 한번 짚고 넘어갑니다.

## OpenCV 문서와 커뮤니티 자료 활용하기

앞서 OpenCV가 널리 쓰이는 이유 중 하나로 거대한 커뮤니티를 꼽았는데, 학습 초기에 이 자료들을 어디서 찾아야 하는지 미리 알아두면 이후 장을 훨씬 수월하게 따라갈 수 있습니다.

**공식 문서(docs.opencv.org).** 모든 `cv2` 함수의 정확한 매개변수와 반환값, 각 매개변수가 받을 수 있는 상수 값이 정리되어 있습니다. 다만 공식 문서는 C++ 시그니처를 기준으로 작성된 경우가 많으므로, Python에서 인자를 어떤 순서로 넘겨야 하는지는 실제로 한 번 실행해보며 확인하는 것이 안전합니다.

**GitHub의 opencv/opencv_extra, opencv/opencv 저장소.** 실제 테스트 코드와 예제 이미지들이 공개되어 있어, "이 함수를 실제로 어떤 입력에 어떻게 쓰는지" 참고하기에 좋습니다.

**Stack Overflow의 `opencv`와 `python` 태그.** 수만 건의 질문과 답변이 누적되어 있어, 오류 메시지를 그대로 검색해보면 대부분 비슷한 사례를 찾을 수 있습니다.

**릴리스 노트 확인 습관.** OpenCV는 버전마다 함수의 기본값이나 반환값 형식이 조금씩 바뀌는 경우가 있습니다(예: `cv2.findContours()`가 반환하는 값의 개수는 OpenCV 3.x와 4.x에서 다릅니다). 설치된 버전을 `cv2.__version__`으로 확인해두고, 예상과 다른 동작을 만났을 때는 버전 차이를 의심해보는 습관이 유용합니다.

기초 다지기 구간(1~2장)에서는 지금 읽고 있는 이 장과, 바로 다음 장에서 개발 환경을 갖추는 과정을 다룹니다. 이미지의 표현과 입출력 구간(3~4장)은 이후 모든 장에서 계속 등장할 "이미지는 곧 NumPy 배열"이라는 관점을 확립하는 단계로, 여기서 배열의 형태(shape)와 자료형(dtype)에 익숙해지지 않으면 뒤의 장에서 오류를 마주쳤을 때 원인을 진단하기가 어려워집니다. 변환의 기초 구간(5~8장)은 색공간, 산술·비트 연산, 기하 변환처럼 이미지 자체를 다른 형태로 바꾸는 연산들을 다루는데, 이 구간의 함수들은 뒤의 필터링·구조 분석 단계에서 전처리 도구로 계속 재사용됩니다. 필터링과 이진화 구간(9~11장), 구조 분석 구간(12~14장)은 이 책에서 가장 "고전적인 컴퓨터 비전"에 해당하는 부분으로, 이미지를 의미 있는 영역과 도형으로 분해하는 방법을 다룹니다. 매칭과 움직임 구간(15~16장), 인식 구간(17장)은 정지 이미지 한 장을 넘어 여러 이미지·비디오·딥러닝 모델을 다루는 좀 더 응용적인 주제로 나아갑니다. 마지막 성능과 마무리 구간(18장)은 지금까지 배운 내용을 실제 프로젝트에 적용할 때 마주치게 될 속도 문제를 정리합니다.

다음 장에서는 Python 개발 환경을 실제로 구성하고, 이미지 한 장을 불러와 화면에 띄워보는 첫 프로그램을 함께 작성해보겠습니다.

## 요약

- OpenCV는 1999년 인텔에서 시작된 오픈소스 컴퓨터 비전 라이브러리로, Willow Garage와 Itseez를 거쳐 현재는 비영리 재단인 OpenCV Foundation이 관리하며, Apache 2.0 라이선스로 배포됩니다.
- OpenCV는 1.0의 C API, 2.0의 `cv::Mat` 기반 C++ API 도입, 3.0의 모듈 분리와 `opencv_contrib` 분리, 4.0의 C API 제거와 DNN 강화를 거치며 "고전적 영상 처리 라이브러리"에서 "고전 기법과 딥러닝이 공존하는 통합 비전 툴킷"으로 성격이 확장되어 왔습니다.
- 다루는 알고리즘의 범위가 넓고, C++ 코어 기반의 네이티브 성능을 내며, 여러 플랫폼과 하드웨어 가속을 지원하고, 거대한 커뮤니티를 갖고 있어 컴퓨터 비전의 사실상 표준 라이브러리로 자리 잡았습니다.
- Python 바인딩이 널리 쓰이는 이유는 이미지를 NumPy 배열로 표현해 데이터 과학·머신러닝 생태계와 매끄럽게 통합되고, 프로토타이핑 속도가 빠르며, 학습 자료가 가장 풍부하고, 무거운 연산 중 GIL이 해제되어 멀티스레딩과도 잘 어울리기 때문입니다.
- `opencv-python`은 GUI를 포함한 핵심 모듈, `opencv-contrib-python`은 핵심 모듈에 확장 모듈을 더한 것, `opencv-python-headless`는 GUI 의존성 없이 서버 환경에 적합한 패키지입니다. 한 가상환경에는 이 중 하나만 설치해야 합니다.
- OpenCV는 산업 검사, 의료 영상, 자율주행, AR/VR, 보안·감시, 로보틱스 등 다양한 산업 현장에서 실제로 활용되고 있으며, Pillow(간단한 편집)와 scikit-image(과학 연구)에 비해 실시간 성능과 폭넓은 알고리즘 커버리지가 강점입니다.
- OpenCV는 컬러 이미지를 RGB가 아닌 **BGR** 순서로 다룹니다. matplotlib 등 RGB를 기대하는 도구와 데이터를 주고받을 때는 항상 `cv2.cvtColor()`로 방향에 맞게(`COLOR_BGR2RGB` 또는 `COLOR_RGB2BGR`) 명시적으로 변환해야 합니다.
