## 15.1 특징점이란 무엇인가

지금까지 다룬 엣지 검출(12장)이나 컨투어 검출(13장)은 이미지 안에서 "경계"나 "윤곽"을 찾는 방법이었습니다. 이번 장에서 다룰 특징점(keypoint)은 조금 다른 관점에서 이미지를 바라봅니다. 특징점은 이미지 안에서 유독 눈에 띄는 지점, 즉 주변과 뚜렷하게 구별되는 지점을 가리킵니다. 대표적으로 코너(corner)처럼 두 방향으로 밝기가 급격히 변하는 지점이나, 무늬가 독특한 얼룩(blob) 같은 지점이 특징점이 됩니다.

특징점이 유용한 이유는 단순히 "눈에 띈다"는 데 있지 않습니다. 좋은 특징점은 다음과 같은 조건을 만족해야 합니다.

- **반복 가능성(repeatability)**: 같은 물체를 다른 각도, 다른 거리, 다른 조명에서 찍어도 같은 지점이 다시 특징점으로 검출되어야 합니다.
- **구별 가능성(distinctiveness)**: 각 특징점은 주변 영역의 패턴을 담은 고유한 서술자(디스크립터)를 가져서, 다른 이미지에 있는 같은 지점과 짝을 지을 수 있어야 합니다.
- **효율성**: 실시간 처리를 위해 검출과 매칭이 빨라야 합니다.

예를 들어 평평한 벽面이나 하늘처럼 아무 변화가 없는 영역은 어느 지점을 찍어도 주변과 구별되지 않으므로 특징점이 될 수 없습니다. 반면 책상 모서리, 창문 틀의 코너, 로고의 꼭짓점처럼 두 방향으로 밝기 변화가 뚜렷한 지점은 회전하거나 확대해도 다시 찾아내기 쉬운 좋은 특징점입니다.

특징점을 찾는 작업은 크게 두 단계로 나뉩니다.

1. **검출(detection)**: 이미지에서 특징점의 위치(그리고 스케일, 방향 등)를 찾는 단계
2. **서술(description)**: 각 특징점 주변의 픽셀 패턴을 숫자 벡터로 표현하는 단계. 이 벡터를 디스크립터(descriptor)라고 부르며, 두 이미지의 특징점을 비교할 때는 위치가 아니라 이 디스크립터 값을 비교합니다.

OpenCV는 SIFT, SURF, ORB, AKAZE 등 다양한 특징점 검출·서술 알고리즘을 제공합니다. 이 중 SIFT와 SURF는 한때 특허로 보호받아 상업적 사용에 제약이 있었지만(SIFT는 2020년 특허가 만료되었습니다), 이 장에서는 처음부터 특허 문제가 없어 자유롭게 사용할 수 있고 속도도 빨라 실전에서 널리 쓰이는 **ORB**를 중심으로 다룹니다.

## 15.2 ORB 특징점 검출기

ORB(Oriented FAST and Rotated BRIEF)는 이름에서 알 수 있듯 두 가지 기존 기법을 결합한 알고리즘입니다.

- **FAST**: 코너를 매우 빠르게 검출하는 알고리즘에 방향(orientation) 정보를 추가한 것
- **BRIEF**: 특징점 주변 픽셀들의 밝기를 비교해 이진 디스크립터를 만드는 알고리즘을 회전에 강인하게(rotation-invariant) 개선한 것

ORB는 계산이 가볍고, 이진 디스크립터를 사용하기 때문에 매칭 속도도 빠르며, 특허 문제가 없어 상업용 프로젝트에서도 걱정 없이 사용할 수 있습니다. 이런 장점 덕분에 실시간 애플리케이션이나 임베디드 환경에서 특징점 매칭이 필요할 때 가장 먼저 검토되는 알고리즘입니다.

세 언어에서 ORB 검출기를 만드는 방법은 다음과 같습니다.

### Python

```python
import cv2

# ORB 검출기 생성 (기본 최대 특징점 수는 500개)
orb = cv2.ORB_create(nfeatures=500)
```

### C++

```cpp
#include <opencv2/opencv.hpp>
#include <opencv2/features2d.hpp>

// ORB 검출기 생성
cv::Ptr<cv::ORB> orb = cv::ORB::create(500);
```

### C#

```csharp
using OpenCvSharp;
using OpenCvSharp.Features2D;

// ORB 검출기 생성
using ORB orb = ORB.Create(nFeatures: 500);
```

`nfeatures`(또는 `nFeatures`)는 검출할 특징점의 최대 개수를 지정합니다. 이 값이 클수록 더 많은 특징점을 찾지만 계산 시간과 매칭 시 잘못된 짝이 생길 가능성도 함께 늘어나므로, 용도에 맞게 조절하는 것이 좋습니다.

## 15.3 특징점 검출과 디스크립터 계산

특징점을 다루는 작업은 보통 세 가지 메서드로 이루어집니다.

- `detect()`: 특징점의 위치만 찾습니다.
- `compute()`: 이미 찾은 특징점 위치를 바탕으로 디스크립터를 계산합니다.
- `detectAndCompute()`: 위 두 단계를 한 번에 수행합니다. 실전에서는 대부분 이 메서드를 사용합니다.

다음 예제는 이미지를 읽어 ORB로 특징점을 검출하고, 그 결과를 `drawKeypoints`로 시각화하는 전체 흐름을 보여줍니다.

### Python

```python
import cv2

img = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("box.jpg 파일을 찾을 수 없습니다.")

orb = cv2.ORB_create(nfeatures=500)

# 검출과 디스크립터 계산을 한 번에 수행
keypoints, descriptors = orb.detectAndCompute(img, None)

print(f"검출된 특징점 개수: {len(keypoints)}")
print(f"디스크립터 배열 크기: {descriptors.shape}")  # (N, 32)

# 특징점을 원본 이미지 위에 시각화
result = cv2.drawKeypoints(
    img, keypoints, None,
    color=(0, 255, 0),
    flags=cv2.DRAW_MATCHES_FLAGS_DRAW_RICH_KEYPOINTS
)

cv2.imshow("ORB Keypoints", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>
#include <opencv2/features2d.hpp>
#include <iostream>

int main() {
    cv::Mat img = cv::imread("box.jpg", cv::IMREAD_GRAYSCALE);
    if (img.empty()) {
        std::cerr << "box.jpg 파일을 찾을 수 없습니다." << std::endl;
        return -1;
    }

    cv::Ptr<cv::ORB> orb = cv::ORB::create(500);

    std::vector<cv::KeyPoint> keypoints;
    cv::Mat descriptors;

    // 검출과 디스크립터 계산을 한 번에 수행
    orb->detectAndCompute(img, cv::noArray(), keypoints, descriptors);

    std::cout << "검출된 특징점 개수: " << keypoints.size() << std::endl;
    std::cout << "디스크립터 크기: " << descriptors.size() << std::endl;

    cv::Mat result;
    cv::drawKeypoints(
        img, keypoints, result, cv::Scalar(0, 255, 0),
        cv::DrawMatchesFlags::DRAW_RICH_KEYPOINTS
    );

    cv::imshow("ORB Keypoints", result);
    cv::waitKey(0);
    return 0;
}
```

각 특징점(`KeyPoint`)은 위치(`pt`), 특징점 반경에 해당하는 크기(`size`), 방향(`angle`) 등의 정보를 담고 있습니다. `DRAW_RICH_KEYPOINTS` 플래그를 사용하면 이 크기와 방향까지 원과 방향선으로 함께 그려주어, 각 특징점이 어느 스케일과 방향에서 검출되었는지 한눈에 확인할 수 있습니다. 반면 기본 플래그(`DrawMatchesFlags.Default`)로 그리면 위치만 작은 점으로 표시됩니다.

디스크립터는 ORB의 경우 특징점 하나당 32바이트(256비트) 크기의 이진 벡터로 표현됩니다. 이 32라는 숫자는 `descriptors`의 열(column) 개수로 확인할 수 있으며, 행(row) 개수는 검출된 특징점의 개수와 같습니다.

## 15.4 두 이미지 간 특징점 매칭

특징점 검출의 진짜 목적은 대개 "이 두 이미지가 같은 물체를 담고 있는가?" 또는 "이 물체가 다른 각도에서 찍힌 이미지에서 어디에 있는가?"를 알아내는 것입니다. 이를 위해서는 첫 번째 이미지의 각 특징점 디스크립터를 두 번째 이미지의 특징점 디스크립터들과 비교해서, 가장 비슷한 짝을 찾아야 합니다.

이 비교 작업을 수행하는 것이 **매처(matcher)**입니다. OpenCV에서 가장 기본적인 매처는 `BFMatcher`(Brute-Force Matcher)로, 첫 번째 이미지의 디스크립터 하나를 두 번째 이미지의 모든 디스크립터와 일일이 비교해 거리가 가장 가까운 것을 찾는 전수 탐색 방식입니다. ORB처럼 이진 디스크립터를 사용할 때는 두 벡터 사이의 비트가 다른 개수를 세는 해밍 거리(Hamming distance)를 사용합니다.

다음 예제는 같은 물체를 다른 각도에서 찍은 두 장의 사진(`box.jpg`와 `box_in_scene.jpg`)에서 특징점을 각각 검출하고, `BFMatcher`로 서로 대응하는 특징점 쌍을 찾은 뒤 `drawMatches`로 연결선을 그려 시각화합니다.

### Python

```python
import cv2

img1 = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)          # 기준 물체 이미지
img2 = cv2.imread("box_in_scene.jpg", cv2.IMREAD_GRAYSCALE)  # 다른 각도에서 찍은 장면

orb = cv2.ORB_create(nfeatures=1000)

kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)

# 이진 디스크립터이므로 해밍 거리를 사용하는 BFMatcher 생성
bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)

matches = bf.match(des1, des2)

# 거리(distance)가 작을수록 더 좋은 매칭이므로 오름차순 정렬
matches = sorted(matches, key=lambda m: m.distance)

# 상위 30개 매칭만 시각화
result = cv2.drawMatches(
    img1, kp1, img2, kp2, matches[:30], None,
    flags=cv2.DRAW_MATCHES_FLAGS_NOT_DRAW_SINGLE_POINTS
)

cv2.imshow("ORB Matches", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>
#include <opencv2/features2d.hpp>
#include <algorithm>

int main() {
    cv::Mat img1 = cv::imread("box.jpg", cv::IMREAD_GRAYSCALE);
    cv::Mat img2 = cv::imread("box_in_scene.jpg", cv::IMREAD_GRAYSCALE);

    cv::Ptr<cv::ORB> orb = cv::ORB::create(1000);

    std::vector<cv::KeyPoint> kp1, kp2;
    cv::Mat des1, des2;
    orb->detectAndCompute(img1, cv::noArray(), kp1, des1);
    orb->detectAndCompute(img2, cv::noArray(), kp2, des2);

    // 이진 디스크립터이므로 해밍 거리를 사용하는 BFMatcher 생성
    cv::Ptr<cv::BFMatcher> matcher = cv::BFMatcher::create(cv::NORM_HAMMING, true);

    std::vector<cv::DMatch> matches;
    matcher->match(des1, des2, matches);

    // 거리가 작을수록 더 좋은 매칭이므로 오름차순 정렬
    std::sort(matches.begin(), matches.end(),
              [](const cv::DMatch& a, const cv::DMatch& b) {
                  return a.distance < b.distance;
              });

    std::vector<cv::DMatch> best(matches.begin(),
                                  matches.begin() + std::min<size_t>(30, matches.size()));

    cv::Mat result;
    cv::drawMatches(
        img1, kp1, img2, kp2, best, result,
        cv::Scalar::all(-1), cv::Scalar::all(-1), std::vector<char>(),
        cv::DrawMatchesFlags::NOT_DRAW_SINGLE_POINTS
    );

    cv::imshow("ORB Matches", result);
    cv::waitKey(0);
    return 0;
}
```

### C#

```csharp
using System;
using System.Linq;
using OpenCvSharp;
using OpenCvSharp.Features2D;

using Mat img1 = Cv2.ImRead("box.jpg", ImreadModes.Grayscale);
using Mat img2 = Cv2.ImRead("box_in_scene.jpg", ImreadModes.Grayscale);

using ORB orb = ORB.Create(nFeatures: 1000);

orb.DetectAndCompute(img1, null, out KeyPoint[] kp1, out Mat des1);
orb.DetectAndCompute(img2, null, out KeyPoint[] kp2, out Mat des2);

// 이진 디스크립터이므로 해밍 거리를 사용하는 BFMatcher 생성
using BFMatcher matcher = new BFMatcher(NormTypes.Hamming, crossCheck: true);

DMatch[] matches = matcher.Match(des1, des2);

// 거리가 작을수록 더 좋은 매칭이므로 오름차순 정렬
DMatch[] best = matches.OrderBy(m => m.Distance).Take(30).ToArray();

using Mat result = new Mat();
Cv2.DrawMatches(
    img1, kp1, img2, kp2, best, result,
    flags: DrawMatchesFlags.NotDrawSinglePoints
);

Cv2.ImShow("ORB Matches", result);
Cv2.WaitKey(0);
```

몇 가지 눈여겨볼 부분이 있습니다.

- `crossCheck=True`(또는 `true`)로 설정하면, A 이미지의 특징점 a가 B 이미지의 특징점 b와 가장 가깝게 매칭될 뿐만 아니라 b 역시 A 이미지에서 a와 가장 가깝게 매칭되는 경우만 결과로 남깁니다. 즉 양방향으로 서로가 최선의 짝이라고 인정하는 경우만 채택하므로, 잘못된 매칭(오매칭)을 크게 줄여줍니다.
- `DMatch` 객체는 `queryIdx`(첫 번째 이미지 특징점 인덱스), `trainIdx`(두 번째 이미지 특징점 인덱스), `distance`(디스크립터 간 거리)를 담고 있습니다. `distance`가 작을수록 더 확실한 매칭이라고 볼 수 있습니다.
- 모든 매칭 결과를 그리면 화면이 선으로 뒤덮여 알아보기 어렵기 때문에, 거리 기준으로 정렬한 뒤 상위 N개만 그리는 것이 일반적입니다.
- `DrawMatchesFlags`의 `NOT_DRAW_SINGLE_POINTS`(또는 `NotDrawSinglePoints`) 옵션은 매칭에 참여하지 않은 나머지 특징점은 그리지 않아 결과를 더 깔끔하게 보여줍니다.

> **참고**: 매칭 결과에는 실제로는 서로 다른 지점인데 우연히 디스크립터가 비슷해서 매칭된 오매칭(outlier)이 섞여 있을 수 있습니다. 더 정교한 애플리케이션에서는 `findHomography`(8장에서 다룬 원근 변환과 관련된 함수)에 RANSAC 옵션을 함께 사용해 기하학적으로 일관성 있는 매칭만 남기는 후처리를 추가합니다. 이 책에서는 특징점 매칭의 기본 흐름에 집중하고, 이런 고급 후처리는 다루지 않습니다.

## 15.5 특징점 매칭은 어디에 쓰이는가

특징점 검출과 매칭은 화려해 보이는 기술이 아니라, 실전 컴퓨터 비전 애플리케이션 곳곳에서 조용히 핵심 역할을 하는 기법입니다. 대표적인 활용 사례는 다음과 같습니다.

- **이미지 스티칭(image stitching)**: 여러 장의 사진을 이어붙여 파노라마를 만들 때, 인접한 두 사진에서 겹치는 영역의 특징점을 매칭해 두 이미지가 어떻게 겹쳐야 하는지(변환 관계)를 계산합니다.
- **객체 인식과 추적**: 미리 등록해 둔 물체 이미지의 특징점과 카메라로 들어오는 실시간 프레임의 특징점을 매칭해서, 그 물체가 화면의 어디에 있는지 찾아냅니다.
- **이미지 정합(image registration)**: 서로 다른 시점이나 센서로 찍은 두 이미지를 같은 좌표계로 정렬할 때 특징점 매칭 결과를 기준으로 변환 행렬을 계산합니다.
- **SLAM(동시적 위치추정 및 지도작성)**: 로봇이나 자율주행차가 연속된 카메라 프레임 사이의 특징점을 매칭해 카메라(또는 로봇)가 얼마나 움직였는지 추정하는 데 사용됩니다.

이 장에서 익힌 "검출 → 서술 → 매칭"이라는 흐름은 알고리즘이 SIFT, AKAZE 등으로 바뀌어도 그대로 유지되는 특징점 기반 비전의 공통 골격입니다.

## 요약

- 특징점(keypoint)은 이미지에서 주변과 뚜렷이 구별되며, 이미지가 회전하거나 크기가 변해도 다시 찾아낼 수 있는 지점입니다.
- ORB는 FAST 코너 검출과 BRIEF 디스크립터를 결합한 알고리즘으로, 특허 문제가 없고 속도가 빨라 실전에서 널리 사용됩니다. `cv2.ORB_create()`(Python), `cv::ORB::create()`(C++), `ORB.Create()`(C#)로 생성합니다.
- `detect()`는 특징점 위치만, `compute()`는 디스크립터만 계산하며, `detectAndCompute()`는 두 단계를 한 번에 처리합니다.
- `drawKeypoints`로 검출된 특징점을 이미지 위에 원과 방향선으로 시각화할 수 있습니다.
- `BFMatcher`는 두 이미지의 디스크립터를 전수 비교해 대응 관계를 찾으며, ORB의 이진 디스크립터에는 해밍 거리(`NORM_HAMMING`)를 사용합니다. `crossCheck` 옵션으로 오매칭을 줄일 수 있습니다.
- `drawMatches`로 두 이미지 사이의 매칭 결과를 연결선으로 시각화할 수 있으며, 거리 기준 정렬 후 상위 N개만 그리는 것이 일반적입니다.
- 특징점 매칭은 이미지 스티칭, 객체 인식, 이미지 정합, SLAM 등 실전 컴퓨터 비전 애플리케이션의 핵심 구성 요소입니다.

## 연습문제

1. ORB의 `nfeatures` 값을 100, 500, 2000으로 바꿔가며 같은 이미지에서 검출되는 특징점 개수와 처리 시간이 어떻게 달라지는지 비교해 보세요.
2. `crossCheck=True`를 켰을 때와 껐을 때 매칭 결과(매칭 개수, 잘못된 매칭의 비율)가 어떻게 달라지는지 두 이미지로 실험해 보세요.
3. 평평한 벽만 찍힌 사진과 체크무늬 담요가 찍힌 사진에 각각 ORB를 적용해 검출되는 특징점 개수를 비교하고, 왜 그런 차이가 나는지 15.1절의 내용을 바탕으로 설명해 보세요.
4. `BFMatcher` 대신 `distance` 값이 특정 임계값(예: 40) 이하인 매칭만 걸러내는 필터를 추가로 구현해, 상위 N개를 뽑는 방식과 결과를 비교해 보세요.
5. 같은 물체를 회전시켜 찍은 두 사진으로 매칭을 수행하고, `drawKeypoints`의 `DRAW_RICH_KEYPOINTS` 옵션으로 각 특징점의 방향(angle)이 회전 전후에 어떻게 달라지는지 시각적으로 확인해 보세요.
