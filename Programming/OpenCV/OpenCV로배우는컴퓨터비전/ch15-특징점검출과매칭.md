## 15.1 특징점이란 무엇인가

지금까지 다룬 엣지 검출(12장)이나 컨투어 검출(13장)은 이미지 안에서 "경계"나 "윤곽"을 찾는 방법이었습니다. 이번 장에서 다룰 특징점(keypoint)은 조금 다른 관점에서 이미지를 바라봅니다. 특징점은 이미지 안에서 유독 눈에 띄는 지점, 즉 주변과 뚜렷하게 구별되는 지점을 가리킵니다. 대표적으로 코너(corner)처럼 두 방향으로 밝기가 급격히 변하는 지점이나, 무늬가 독특한 얼룩(blob) 같은 지점이 특징점이 됩니다.

특징점이 유용한 이유는 단순히 "눈에 띈다"는 데 있지 않습니다. 좋은 특징점은 다음과 같은 조건을 만족해야 합니다.

- **반복 가능성(repeatability)**: 같은 물체를 다른 각도, 다른 거리, 다른 조명에서 찍어도 같은 지점이 다시 특징점으로 검출되어야 합니다.
- **불변성(invariance)**: 이미지가 회전하거나 크기가 바뀌거나 조명이 달라져도 특징점의 위치와 디스크립터가 크게 흔들리지 않아야 합니다. 이를 위해 대부분의 알고리즘은 특징점마다 스케일(크기)과 방향(각도) 정보를 함께 추정합니다.
- **구별 가능성(distinctiveness)**: 각 특징점은 주변 영역의 패턴을 담은 고유한 서술자(디스크립터)를 가져서, 다른 이미지에 있는 같은 지점과 짝을 지을 수 있어야 합니다.
- **효율성**: 실시간 처리를 위해 검출과 매칭이 빨라야 합니다.

예를 들어 평평한 벽이나 하늘처럼 아무 변화가 없는 영역은 어느 지점을 찍어도 주변과 구별되지 않으므로 특징점이 될 수 없습니다. 직선으로 뻗은 엣지 위의 한 점도 마찬가지입니다. 그 점을 엣지 방향을 따라 살짝 이동시켜도 주변 패턴이 거의 똑같이 보이기 때문에, "정확히 이 지점"이라고 특정하기가 어렵습니다. 반면 책상 모서리, 창문 틀의 코너, 로고의 꼭짓점처럼 두 방향으로 밝기 변화가 뚜렷한 지점은 어느 방향으로 이동해도 주변 패턴이 달라지므로, 회전하거나 확대해도 다시 찾아내기 쉬운 좋은 특징점입니다.

특징점을 찾는 작업은 크게 두 단계로 나뉩니다.

1. **검출(detection)**: 이미지에서 특징점의 위치(그리고 스케일, 방향 등)를 찾는 단계
2. **서술(description)**: 각 특징점 주변의 픽셀 패턴을 숫자 벡터로 표현하는 단계. 이 벡터를 디스크립터(descriptor)라고 부르며, 두 이미지의 특징점을 비교할 때는 위치가 아니라 이 디스크립터 값을 비교합니다.

디스크립터는 크게 두 종류로 나뉩니다.

- **부동소수점 디스크립터(float descriptor)**: SIFT처럼 각 차원이 실수 값으로 표현되는 방식입니다. 표현력이 풍부해 구별 성능이 좋지만, 벡터 하나의 크기가 크고 거리 계산(주로 유클리드 거리, `NORM_L2`)에 비용이 더 듭니다.
- **이진 디스크립터(binary descriptor)**: ORB, BRIEF처럼 각 차원이 0 또는 1인 비트로 표현되는 방식입니다. 벡터가 작고 두 벡터를 비교할 때 XOR 연산과 비트 카운트만으로 거리(해밍 거리, `NORM_HAMMING`)를 계산할 수 있어 매우 빠릅니다.

OpenCV는 SIFT, ORB, AKAZE, BRISK 등 다양한 특징점 검출·서술 알고리즘을 제공합니다. 이 중 SIFT는 한때 특허로 보호받아 상업적 사용에 제약이 있었지만 2020년에 특허가 만료되었고, 그 결과 오늘날의 `opencv-python` 기본 배포판에는 SIFT가 별도의 확장 패키지(`opencv-contrib-python`) 없이 포함되어 있습니다. 이 장에서는 가볍고 빠른 **ORB**로 기본 흐름을 익힌 뒤, 더 정교한 **SIFT**로 넘어가고, 마지막에는 매칭 결과를 실제로 활용해 두 이미지를 정렬하는 실전 예제까지 다룹니다.

## 15.2 ORB 특징점 검출기

ORB(Oriented FAST and Rotated BRIEF)는 이름에서 알 수 있듯 두 가지 기존 기법을 결합한 알고리즘입니다.

- **FAST**: 코너를 매우 빠르게 검출하는 알고리즘에 방향(orientation) 정보를 추가한 것
- **BRIEF**: 특징점 주변 픽셀들의 밝기를 비교해 이진 디스크립터를 만드는 알고리즘을 회전에 강인하게(rotation-invariant) 개선한 것

ORB는 계산이 가볍고, 이진 디스크립터를 사용하기 때문에 매칭 속도도 빠르며, 특허 문제가 없어 상업용 프로젝트에서도 걱정 없이 사용할 수 있습니다. 이런 장점 덕분에 실시간 애플리케이션이나 임베디드 환경에서 특징점 매칭이 필요할 때 가장 먼저 검토되는 알고리즘입니다.

```python
import cv2

# ORB 검출기 생성 (기본 최대 특징점 수는 500개)
orb = cv2.ORB_create(nfeatures=500)
```

`cv2.ORB_create()`는 여러 옵션을 받을 수 있습니다. 자주 조절하는 값들은 다음과 같습니다.

| 매개변수 | 의미 | 기본값 |
|---|---|---|
| `nfeatures` | 검출할 특징점의 최대 개수 | 500 |
| `scaleFactor` | 피라미드 레벨 간 크기 축소 비율. 1에 가까울수록 레벨이 많아져 더 세밀하지만 느려짐 | 1.2 |
| `nlevels` | 피라미드 레벨(스케일 단계) 개수 | 8 |
| `edgeThreshold` | 이미지 가장자리에서 특징점을 무시할 픽셀 폭 | 31 |
| `fastThreshold` | 내부 FAST 코너 검출의 밝기 차이 임계값 | 20 |

`nfeatures` 값이 클수록 더 많은 특징점을 찾지만 계산 시간과 매칭 시 잘못된 짝이 생길 가능성도 함께 늘어나므로, 용도에 맞게 조절하는 것이 좋습니다. `scaleFactor`와 `nlevels`는 ORB가 다양한 크기(스케일)의 특징점을 검출하기 위해 이미지 피라미드를 구성하는 방식을 결정합니다. 즉 원본 이미지를 `scaleFactor`만큼씩 축소한 이미지를 `nlevels`개 만들고, 각 축소 이미지마다 FAST 코너를 검출한 뒤 다시 원본 좌표계로 환산합니다. 이 덕분에 물체가 이미지에서 크게 찍히든 작게 찍히든 어느 정도 같은 특징점을 다시 찾아낼 수 있습니다.

## 15.3 특징점 검출과 디스크립터 계산

특징점을 다루는 작업은 보통 세 가지 메서드로 이루어집니다.

- `detect()`: 특징점의 위치만 찾습니다.
- `compute()`: 이미 찾은 특징점 위치를 바탕으로 디스크립터를 계산합니다.
- `detectAndCompute()`: 위 두 단계를 한 번에 수행합니다. 실전에서는 대부분 이 메서드를 사용합니다.

다음 예제는 이미지를 읽어 ORB로 특징점을 검출하고, 그 결과를 `drawKeypoints`로 시각화하는 전체 흐름을 보여줍니다.

```python
import cv2

img = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("box.jpg 파일을 찾을 수 없습니다.")

orb = cv2.ORB_create(nfeatures=500)

# 검출과 디스크립터 계산을 한 번에 수행
keypoints, descriptors = orb.detectAndCompute(img, None)

print(f"검출된 특징점 개수: {len(keypoints)}")
print(f"디스크립터 배열 크기: {descriptors.shape}")  # (N, 32)
print(f"디스크립터 자료형: {descriptors.dtype}")       # uint8 (이진 디스크립터)

# 특징점 하나의 속성 확인
kp = keypoints[0]
print(f"위치: {kp.pt}, 크기: {kp.size:.1f}, 방향: {kp.angle:.1f}도, 응답 강도: {kp.response:.4f}")

# 특징점을 원본 이미지 위에 시각화
result = cv2.drawKeypoints(
    img, keypoints, None,
    color=(0, 255, 0),
    flags=cv2.DRAW_MATCHES_FLAGS_DRAW_RICH_KEYPOINTS
)

cv2.imshow("ORB Keypoints", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

각 특징점(`cv2.KeyPoint`)은 다음과 같은 정보를 담고 있습니다.

- `pt`: 이미지 안에서의 (x, y) 위치
- `size`: 특징점 주변 영역의 지름에 해당하는 크기. 이 값은 어느 피라미드 레벨(스케일)에서 검출되었는지를 반영합니다.
- `angle`: 특징점의 지배적인 방향(도 단위). ORB는 이 방향을 기준으로 BRIEF 디스크립터를 회전시켜 계산하기 때문에, 이미지가 회전해도 같은 디스크립터가 나오도록 보정됩니다.
- `response`: 특징점으로서의 강도(코너 응답 값). 값이 클수록 더 뚜렷한 특징점입니다.
- `octave`: 어느 피라미드 레벨에서 검출되었는지를 나타내는 정수

`DRAW_RICH_KEYPOINTS` 플래그를 사용하면 이 크기와 방향까지 원과 방향선으로 함께 그려주어, 각 특징점이 어느 스케일과 방향에서 검출되었는지 한눈에 확인할 수 있습니다. 반면 기본 플래그(`cv2.DrawMatchesFlags_DEFAULT`)로 그리면 위치만 작은 점으로 표시됩니다.

디스크립터는 ORB의 경우 특징점 하나당 32바이트(256비트) 크기의 이진 벡터로 표현됩니다. 이 32라는 숫자는 `descriptors`의 열(column) 개수로 확인할 수 있으며, 행(row) 개수는 검출된 특징점의 개수와 같습니다.

## 15.4 SIFT: 특허가 풀린 정교한 검출기

SIFT(Scale-Invariant Feature Transform)는 2004년에 발표된, 특징점 검출 분야에서 가장 널리 인용되는 알고리즘입니다. 원리를 간단히 요약하면, 이미지를 여러 스케일로 흐리게(가우시안 블러) 만든 뒤 인접한 스케일끼리 차이를 구하는 **DoG(Difference of Gaussians)** 방식으로 스케일 공간을 만들고, 이 스케일 공간에서 극값(주변보다 뚜렷하게 밝거나 어두운 지점)을 특징점으로 검출합니다. 이후 각 특징점 주변의 그래디언트(밝기 변화) 방향을 히스토그램으로 모아 128차원의 부동소수점 디스크립터를 만듭니다.

SIFT는 2020년 3월 마지막 관련 특허가 만료되기 전까지는 상업적으로 자유롭게 사용할 수 없어, OpenCV에서도 `opencv-contrib-python`이라는 별도 확장 패키지를 설치해야만 쓸 수 있었습니다. 특허가 만료된 이후로는 표준 `opencv-python` 패키지에 SIFT가 기본으로 포함되어, 별도 설치 없이 `cv2.SIFT_create()`만으로 바로 사용할 수 있습니다.

```python
import cv2

img = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)

# SIFT 검출기 생성. nfeatures=0이면 개수 제한 없이 검출
sift = cv2.SIFT_create(nfeatures=0)

keypoints, descriptors = sift.detectAndCompute(img, None)

print(f"검출된 특징점 개수: {len(keypoints)}")
print(f"디스크립터 배열 크기: {descriptors.shape}")  # (N, 128)
print(f"디스크립터 자료형: {descriptors.dtype}")       # float32

result = cv2.drawKeypoints(
    img, keypoints, None,
    flags=cv2.DRAW_MATCHES_FLAGS_DRAW_RICH_KEYPOINTS
)

cv2.imshow("SIFT Keypoints", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

`cv2.SIFT_create()`가 받는 주요 매개변수는 다음과 같습니다.

| 매개변수 | 의미 | 기본값 |
|---|---|---|
| `nfeatures` | 반환할 특징점의 최대 개수(0이면 제한 없음, 응답 강도 기준 상위 N개만 남김) | 0 |
| `nOctaveLayers` | 한 옥타브(스케일 구간) 안에서 사용하는 레이어 수 | 3 |
| `contrastThreshold` | 대비가 낮은(약한) 특징점을 걸러내는 임계값. 클수록 특징점이 줄어듦 | 0.04 |
| `edgeThreshold` | 엣지 형태의 불안정한 특징점을 걸러내는 임계값. 클수록 더 많이 남김(직관과 반대이므로 주의) | 10 |
| `sigma` | 첫 옥타브에 적용하는 가우시안 블러의 표준편차 | 1.6 |

ORB의 디스크립터가 32바이트짜리 이진 벡터인 데 비해 SIFT의 디스크립터는 128개의 32비트 실수(총 512바이트)로 훨씬 큽니다. 이 때문에 SIFT는 메모리도 더 많이 쓰고, 매칭 시 거리 계산도 유클리드 거리(`cv2.NORM_L2`)를 사용해야 해서 ORB보다 느립니다. 대신 스케일 공간을 정밀하게 탐색하고 그래디언트 히스토그램 기반의 풍부한 정보를 담기 때문에, 조명 변화나 확대·축소, 약간의 시점 변화가 있는 상황에서도 ORB보다 안정적으로 같은 지점을 다시 찾아내는 경향이 있습니다.

## 15.5 ORB와 SIFT, 무엇을 선택할까

두 알고리즘 모두 "검출 → 서술" 흐름을 따르지만 설계 목표와 특성이 다릅니다. 실전에서 선택할 때 참고할 수 있는 비교표는 다음과 같습니다.

| 항목 | ORB | SIFT |
|---|---|---|
| 디스크립터 종류 | 이진(256비트, 32바이트) | 부동소수점(128차원, 512바이트) |
| 거리 척도 | 해밍 거리(`NORM_HAMMING`) | 유클리드 거리(`NORM_L2`) |
| 검출 속도 | 매우 빠름 | ORB보다 느림(스케일 공간 전체를 탐색) |
| 매칭 속도 | 매우 빠름(비트 연산) | 상대적으로 느림(실수 벡터 거리 계산) |
| 메모리 사용량 | 작음 | 큼(디스크립터가 16배 큼) |
| 정확도·구별력 | 양호. 시점 변화가 크면 성능이 떨어질 수 있음 | 우수. 조명·스케일·약한 시점 변화에도 안정적 |
| 라이선스 역사 | 처음부터 특허 없음(2011년 공개) | 1999년 발표, 여러 특허로 보호되다 2020년 3월 완전 만료 |
| 현재 opencv-python 포함 여부 | 항상 기본 포함 | 특허 만료 이후 기본 포함(과거에는 opencv-contrib-python 필요) |
| 적합한 상황 | 실시간 처리, 임베디드 기기, 대량의 프레임 처리 | 정확도가 중요한 오프라인 처리, 이미지 스티칭, 정밀한 정합 |

간단히 정리하면, **속도가 중요하면 ORB, 정확도가 중요하면 SIFT**를 우선 검토하는 것이 합리적인 출발점입니다. 실시간 객체 추적이나 초당 수십 프레임을 처리해야 하는 애플리케이션에는 ORB가 적합하고, 몇 장의 사진을 오프라인으로 정밀하게 이어붙이거나 정합하는 작업에는 SIFT가 더 안정적인 결과를 줍니다. 두 알고리즘의 처리 시간을 직접 비교해보는 것도 좋은 실험입니다.

```python
import cv2
import time

img = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)

orb = cv2.ORB_create(nfeatures=1000)
sift = cv2.SIFT_create(nfeatures=1000)

t0 = time.perf_counter()
kp_orb, des_orb = orb.detectAndCompute(img, None)
t1 = time.perf_counter()
kp_sift, des_sift = sift.detectAndCompute(img, None)
t2 = time.perf_counter()

print(f"ORB : {len(kp_orb)}개 특징점, {(t1 - t0) * 1000:.1f}ms")
print(f"SIFT: {len(kp_sift)}개 특징점, {(t2 - t1) * 1000:.1f}ms")
```

일반적인 해상도의 사진에서 이 코드를 실행하면 ORB가 SIFT보다 눈에 띄게 빠르게 끝나는 것을 확인할 수 있습니다. 정확한 배수는 이미지 크기, 특징점 개수, 하드웨어에 따라 달라지므로 직접 측정해 보는 것이 중요합니다.

## 15.6 두 이미지 간 특징점 매칭: BFMatcher

특징점 검출의 진짜 목적은 대개 "이 두 이미지가 같은 물체를 담고 있는가?" 또는 "이 물체가 다른 각도에서 찍힌 이미지에서 어디에 있는가?"를 알아내는 것입니다. 이를 위해서는 첫 번째 이미지의 각 특징점 디스크립터를 두 번째 이미지의 특징점 디스크립터들과 비교해서, 가장 비슷한 짝을 찾아야 합니다.

이 비교 작업을 수행하는 것이 **매처(matcher)**입니다. OpenCV에서 가장 기본적인 매처는 `cv2.BFMatcher`(Brute-Force Matcher)로, 첫 번째 이미지의 디스크립터 하나를 두 번째 이미지의 모든 디스크립터와 일일이 비교해 거리가 가장 가까운 것을 찾는 전수 탐색 방식입니다. 어떤 거리 척도를 쓸지는 디스크립터 종류에 따라 달라집니다. ORB처럼 이진 디스크립터를 사용할 때는 해밍 거리(`cv2.NORM_HAMMING`)를, SIFT처럼 부동소수점 디스크립터를 사용할 때는 유클리드 거리(`cv2.NORM_L2`)를 지정해야 합니다.

다음 예제는 같은 물체를 다른 각도에서 찍은 두 장의 사진(`box.jpg`와 `box_in_scene.jpg`)에서 ORB 특징점을 각각 검출하고, `BFMatcher`로 서로 대응하는 특징점 쌍을 찾은 뒤 `drawMatches`로 연결선을 그려 시각화합니다.

```python
import cv2

img1 = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)          # 기준 물체 이미지
img2 = cv2.imread("box_in_scene.jpg", cv2.IMREAD_GRAYSCALE)  # 다른 각도에서 찍은 장면

orb = cv2.ORB_create(nfeatures=1000)

kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)

# 이진 디스크립터이므로 해밍 거리를 사용하는 BFMatcher 생성
bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=True)

matches = bf.match(des1, des2)

# 거리(distance)가 작을수록 더 좋은 매칭이므로 오름차순 정렬
matches = sorted(matches, key=lambda m: m.distance)

# 상위 30개 매칭만 시각화
result = cv2.drawMatches(
    img1, kp1, img2, kp2, matches[:30], None,
    flags=cv2.DRAW_MATCHES_FLAGS_NOT_DRAW_SINGLE_POINTS
)

cv2.imshow("ORB Matches", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

몇 가지 눈여겨볼 부분이 있습니다.

- `crossCheck=True`로 설정하면, A 이미지의 특징점 a가 B 이미지의 특징점 b와 가장 가깝게 매칭될 뿐만 아니라 b 역시 A 이미지에서 a와 가장 가깝게 매칭되는 경우만 결과로 남깁니다. 즉 양방향으로 서로가 최선의 짝이라고 인정하는 경우만 채택하므로, 잘못된 매칭(오매칭)을 크게 줄여줍니다.
- `cv2.DMatch` 객체는 `queryIdx`(첫 번째 이미지 특징점 인덱스), `trainIdx`(두 번째 이미지 특징점 인덱스), `distance`(디스크립터 간 거리)를 담고 있습니다. `distance`가 작을수록 더 확실한 매칭이라고 볼 수 있습니다.
- 모든 매칭 결과를 그리면 화면이 선으로 뒤덮여 알아보기 어렵기 때문에, 거리 기준으로 정렬한 뒤 상위 N개만 그리는 것이 일반적입니다.
- `cv2.DRAW_MATCHES_FLAGS_NOT_DRAW_SINGLE_POINTS` 옵션은 매칭에 참여하지 않은 나머지 특징점은 그리지 않아 결과를 더 깔끔하게 보여줍니다.

SIFT 디스크립터로 같은 작업을 하려면 매처 생성 시 거리 척도만 바꿔주면 됩니다.

```python
sift = cv2.SIFT_create()
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

# 부동소수점 디스크립터이므로 유클리드 거리를 사용
bf = cv2.BFMatcher(cv2.NORM_L2, crossCheck=True)
matches = bf.match(des1, des2)
```

## 15.7 FLANN 기반 매처: 대규모 특징점 집합을 위한 빠른 근사 탐색

`BFMatcher`는 정확하지만, 두 이미지에 특징점이 각각 수천 개 이상이라면 모든 쌍을 일일이 비교하는 전수 탐색 비용이 빠르게 커집니다. 특징점 수가 많거나 여러 이미지를 대상으로 반복적으로 매칭해야 하는 상황(예: 대규모 이미지 검색, 다중 이미지 스티칭)에서는 **FLANN(Fast Library for Approximate Nearest Neighbors)** 기반 매처인 `cv2.FlannBasedMatcher`를 사용하는 것이 유리합니다.

FLANN은 모든 디스크립터를 일일이 비교하는 대신, 검색에 특화된 인덱스 자료구조(트리나 해시 테이블)를 미리 만들어 두고 그 인덱스를 통해 "거의 가장 가까운" 이웃을 근사적으로 빠르게 찾아냅니다. 데이터 규모가 커질수록 이 근사 탐색이 전수 탐색보다 훨씬 빠르게 동작하며, 그 대가로 아주 드물게 진짜 최근접 이웃이 아닌 결과를 내놓을 수 있지만 실전에서는 대부분 무시할 수 있는 수준입니다.

FLANN을 사용할 때는 디스크립터의 종류(이진 vs 부동소수점)에 따라 서로 다른 인덱스 알고리즘을 지정해야 합니다.

- **부동소수점 디스크립터(SIFT 등)**: KD-트리 기반 인덱스를 사용합니다.
- **이진 디스크립터(ORB 등)**: LSH(Locality-Sensitive Hashing) 기반 인덱스를 사용합니다. KD-트리는 이진 벡터에는 적합하지 않습니다.

다음은 SIFT 디스크립터에 FLANN(KD-트리)을 사용하는 예제입니다.

```python
import cv2

img1 = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)
img2 = cv2.imread("box_in_scene.jpg", cv2.IMREAD_GRAYSCALE)

sift = cv2.SIFT_create()
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

# KD-트리 기반 인덱스 (부동소수점 디스크립터용)
FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
search_params = dict(checks=50)  # 인덱스를 탐색할 때 확인할 후보 개수. 클수록 정확하지만 느림

flann = cv2.FlannBasedMatcher(index_params, search_params)

# 각 디스크립터마다 가장 가까운 2개의 후보를 찾음 (Lowe's ratio test를 위해)
knn_matches = flann.knnMatch(des1, des2, k=2)

# 최근접 거리가 2번째로 가까운 거리보다 충분히 작을 때만 신뢰할 수 있는 매칭으로 채택
good_matches = []
for m, n in knn_matches:
    if m.distance < 0.75 * n.distance:
        good_matches.append(m)

print(f"전체 매칭 후보: {len(knn_matches)}개, 신뢰할 수 있는 매칭: {len(good_matches)}개")

result = cv2.drawMatches(
    img1, kp1, img2, kp2, good_matches, None,
    flags=cv2.DRAW_MATCHES_FLAGS_NOT_DRAW_SINGLE_POINTS
)

cv2.imshow("FLANN + SIFT Matches", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

이 예제에서 사용한 **Lowe's ratio test**는 SIFT를 처음 제안한 David Lowe가 함께 소개한 매칭 검증 기법입니다. 특징점 하나에 대해 가장 가까운 매칭(`m`)과 두 번째로 가까운 매칭(`n`)을 함께 찾은 뒤, `m`이 `n`보다 충분히(예: 25% 이상, 즉 `m.distance < 0.75 * n.distance`) 더 가까울 때만 신뢰할 수 있는 매칭으로 인정합니다. 만약 1등과 2등의 거리가 비슷하다면, 그 특징점은 여러 후보와 비슷하게 매칭되는 애매한 지점이라는 뜻이므로 오매칭일 가능성이 높아 걸러내는 것입니다. 이 기법은 `crossCheck`와는 별개의 검증 방식으로, `BFMatcher`에도 똑같이 적용할 수 있습니다.

ORB의 이진 디스크립터에 FLANN을 사용하려면 인덱스 알고리즘을 LSH로 바꿔주어야 합니다.

```python
import cv2

orb = cv2.ORB_create(nfeatures=1000)
kp1, des1 = orb.detectAndCompute(img1, None)
kp2, des2 = orb.detectAndCompute(img2, None)

# LSH 기반 인덱스 (이진 디스크립터용)
FLANN_INDEX_LSH = 6
index_params = dict(
    algorithm=FLANN_INDEX_LSH,
    table_number=6,       # 사용할 해시 테이블 개수
    key_size=12,           # 해시 키의 비트 길이
    multi_probe_level=1,   # 인접한 해시 버킷까지 함께 탐색할 범위
)
search_params = dict(checks=50)

flann = cv2.FlannBasedMatcher(index_params, search_params)
knn_matches = flann.knnMatch(des1, des2, k=2)

good_matches = []
for pair in knn_matches:
    if len(pair) != 2:
        continue  # 후보가 2개보다 적으면 ratio test를 적용할 수 없으므로 건너뜀
    m, n = pair
    if m.distance < 0.75 * n.distance:
        good_matches.append(m)
```

`BFMatcher`와 `FlannBasedMatcher` 중 무엇을 선택할지는 다음 기준으로 판단하면 됩니다.

| | BFMatcher | FlannBasedMatcher |
|---|---|---|
| 탐색 방식 | 전수 탐색(정확한 최근접 이웃) | 인덱스 기반 근사 탐색 |
| 특징점 수가 적을 때(수백 개) | 빠르고 정확함 | 인덱스 구성 오버헤드 때문에 오히려 불리할 수 있음 |
| 특징점 수가 많을 때(수천~수만 개) | 느려짐 | 훨씬 빠름 |
| 정확도 | 항상 진짜 최근접 이웃 | 매우 근접하지만 드물게 근사 오차 발생 가능 |
| 사용 난이도 | 간단함 | 디스크립터 종류에 맞는 인덱스 파라미터 설정 필요 |

## 15.8 실전: 호모그래피로 두 이미지 정렬하기

특징점을 매칭하는 것 자체는 목적이 아니라 수단입니다. 실전에서는 매칭된 특징점 쌍을 이용해 "두 이미지가 어떤 기하학적 변환 관계에 있는가"를 계산하고, 그 변환을 실제로 적용하는 것까지 나아갑니다. 이 절에서는 매칭 결과로부터 **호모그래피(homography)**, 즉 한 평면을 다른 평면으로 대응시키는 원근 변환 행렬을 계산하고, 이를 이용해 한 이미지를 다른 이미지의 시점으로 정렬하는 과정을 다룹니다. 이는 파노라마를 만드는 **이미지 스티칭(image stitching)**의 첫 단계이기도 합니다.

전체 흐름은 다음과 같습니다.

1. 두 이미지에서 특징점과 디스크립터를 검출합니다.
2. FLANN(또는 BFMatcher)과 ratio test로 신뢰할 수 있는 매칭 쌍을 찾습니다.
3. 매칭된 특징점들의 좌표를 이용해 `cv2.findHomography()`로 호모그래피 행렬을 계산합니다. 이때 `cv2.RANSAC` 플래그를 지정해 이상치(잘못된 매칭)를 자동으로 걸러냅니다.
4. 계산된 호모그래피 행렬을 `cv2.warpPerspective()`에 넘겨 한 이미지를 다른 이미지의 시점으로 변형합니다.

```python
import cv2
import numpy as np

MIN_MATCH_COUNT = 10  # 호모그래피를 안정적으로 계산하려면 최소 이 정도의 매칭이 필요

img1 = cv2.imread("box.jpg", cv2.IMREAD_GRAYSCALE)           # 정렬 대상(기준 물체)
img2 = cv2.imread("box_in_scene.jpg", cv2.IMREAD_GRAYSCALE)   # 목표 시점(장면)

sift = cv2.SIFT_create()
kp1, des1 = sift.detectAndCompute(img1, None)
kp2, des2 = sift.detectAndCompute(img2, None)

FLANN_INDEX_KDTREE = 1
index_params = dict(algorithm=FLANN_INDEX_KDTREE, trees=5)
search_params = dict(checks=50)
flann = cv2.FlannBasedMatcher(index_params, search_params)

knn_matches = flann.knnMatch(des1, des2, k=2)

good_matches = [m for m, n in knn_matches if m.distance < 0.75 * n.distance]
print(f"신뢰할 수 있는 매칭: {len(good_matches)}개")

if len(good_matches) >= MIN_MATCH_COUNT:
    # 매칭된 특징점들의 (x, y) 좌표를 float32 배열로 추출
    src_pts = np.float32([kp1[m.queryIdx].pt for m in good_matches]).reshape(-1, 1, 2)
    dst_pts = np.float32([kp2[m.trainIdx].pt for m in good_matches]).reshape(-1, 1, 2)

    # RANSAC으로 이상치를 제거하며 호모그래피 행렬 계산
    # ransacReprojThreshold(여기서는 5.0)는 정상치로 인정할 재투영 오차의 허용 범위(픽셀)
    H, mask = cv2.findHomography(src_pts, dst_pts, cv2.RANSAC, 5.0)

    inlier_count = int(mask.sum())
    print(f"RANSAC 정상치(inlier)로 채택된 매칭: {inlier_count}개 / {len(good_matches)}개")

    # img1의 네 모서리가 img2 좌표계에서 어디에 대응하는지 계산해 사각형으로 표시
    h, w = img1.shape
    corners = np.float32([[0, 0], [0, h - 1], [w - 1, h - 1], [w - 1, 0]]).reshape(-1, 1, 2)
    projected_corners = cv2.perspectiveTransform(corners, H)

    img2_color = cv2.cvtColor(img2, cv2.COLOR_GRAY2BGR)
    cv2.polylines(img2_color, [np.int32(projected_corners)], True, (0, 255, 0), 3, cv2.LINE_AA)
    cv2.imshow("Detected Object", img2_color)

    # img1을 img2의 좌표계(시점)로 정렬(warp)
    h2, w2 = img2.shape
    warped = cv2.warpPerspective(img1, H, (w2, h2))
    cv2.imshow("box.jpg warped into box_in_scene's perspective", warped)

    # RANSAC 정상치만 표시한 매칭 결과
    matches_mask = mask.ravel().tolist()
    result = cv2.drawMatches(
        img1, kp1, img2, kp2, good_matches, None,
        matchColor=(0, 255, 0),
        matchesMask=matches_mask,
        flags=cv2.DRAW_MATCHES_FLAGS_NOT_DRAW_SINGLE_POINTS
    )
    cv2.imshow("RANSAC Inlier Matches", result)

    cv2.waitKey(0)
    cv2.destroyAllWindows()
else:
    print(f"매칭이 충분하지 않습니다: {len(good_matches)}/{MIN_MATCH_COUNT}")
```

이 예제에서 특히 중요한 함수는 `cv2.findHomography()`입니다.

- 첫 번째와 두 번째 인자로 대응하는 점들의 좌표 배열을 받습니다. 이 좌표들은 앞서 얻은 `good_matches`의 `queryIdx`, `trainIdx`를 이용해 각 이미지의 `KeyPoint.pt`에서 추출합니다.
- 세 번째 인자 `cv2.RANSAC`은 이 좌표 쌍들 중 실제로 기하학적으로 일관된 것(정상치, inlier)과 잘못된 매칭(이상치, outlier)을 구분하는 방법을 지정합니다. RANSAC(RANdom SAmple Consensus)은 무작위로 몇 개의 점 쌍을 뽑아 호모그래피를 계산해보고, 그 호모그래피가 전체 점들을 얼마나 잘 설명하는지(재투영 오차가 허용 범위 안에 드는 점이 몇 개인지)를 반복적으로 평가해서, 가장 많은 점을 설명하는 호모그래피를 최종적으로 채택하는 방식입니다. 이 과정에서 소수의 잘못된 매칭은 자연스럽게 이상치로 배제됩니다.
- 네 번째 인자(`5.0`)는 `ransacReprojThreshold`로, 한 점이 "정상치"로 인정받기 위해 허용되는 재투영 오차(픽셀 단위)입니다. 이 값이 작을수록 더 엄격하게 정상치를 판별합니다.
- 반환값 `H`는 3×3 호모그래피 행렬이고, `mask`는 각 입력 점 쌍이 정상치(1)인지 이상치(0)인지를 나타내는 배열입니다. 이 `mask`를 `drawMatches`의 `matchesMask` 인자로 넘기면 RANSAC이 걸러낸 정상치 매칭만 초록색으로 그려주어, 매칭의 품질을 시각적으로 검증할 수 있습니다.

`cv2.warpPerspective()`는 이렇게 얻은 호모그래피 행렬을 이용해 이미지 전체를 변형합니다. `img1`의 각 픽셀이 호모그래피 변환을 거치면 `img2`의 좌표계에서 어디에 위치하는지를 계산해 새로운 이미지를 만들어내므로, 결과적으로 `img1`이 `img2`를 찍은 카메라의 시점으로 "다시 찍은 것처럼" 정렬됩니다. 이 정렬된 이미지를 `img2`와 나란히 겹쳐 놓으면, 겹치는 영역의 화소들을 이어 붙여 하나의 넓은 이미지(파노라마)를 만드는 이미지 스티칭으로 발전시킬 수 있습니다. OpenCV는 이 전체 과정을 자동화한 고수준 API(`cv2.Stitcher`)도 제공하지만, 그 내부에서 실제로 일어나는 일이 바로 지금까지 살펴본 "검출 → 매칭 → 호모그래피 → 워프"의 흐름입니다.

> **참고**: `findHomography`는 두 이미지가 같은 평면(또는 카메라가 같은 위치에서 회전만 했을 때)을 다른 시점에서 찍었다는 가정 위에서 성립하는 변환입니다. 두 이미지 속 장면이 3차원적으로 크게 다르게 배치되어 있다면(예: 서로 다른 깊이의 물체들이 섞여 있는 일반적인 3D 장면) 하나의 호모그래피로는 정확히 정렬되지 않을 수 있습니다. 이런 경우를 다루려면 카메라의 내·외부 파라미터를 함께 추정하는 더 복잡한 기법(예: 에센셜/펀더멘털 행렬, 스테레오 비전)이 필요합니다.

## 15.9 특징점 매칭은 어디에 쓰이는가

특징점 검출과 매칭은 화려해 보이는 기술이 아니라, 실전 컴퓨터 비전 애플리케이션 곳곳에서 조용히 핵심 역할을 하는 기법입니다. 대표적인 활용 사례는 다음과 같습니다.

- **이미지 스티칭(image stitching)**: 여러 장의 사진을 이어붙여 파노라마를 만들 때, 인접한 두 사진에서 겹치는 영역의 특징점을 매칭해 15.8절에서 다룬 것처럼 호모그래피를 계산하고, 이를 바탕으로 이미지들을 정렬한 뒤 이어붙입니다.
- **객체 인식과 추적**: 미리 등록해 둔 물체 이미지의 특징점과 카메라로 들어오는 실시간 프레임의 특징점을 매칭해서, 그 물체가 화면의 어디에 있는지 찾아냅니다. 15.8절 예제에서 `polylines`로 그린 사각형이 바로 이런 방식으로 물체의 위치를 표시한 것입니다.
- **이미지 정합(image registration)**: 서로 다른 시점이나 센서로 찍은 두 이미지를 같은 좌표계로 정렬할 때 특징점 매칭 결과를 기준으로 변환 행렬을 계산합니다. 의료 영상에서 서로 다른 시점에 찍은 MRI 영상을 정렬하는 것도 같은 원리입니다.
- **SLAM(동시적 위치추정 및 지도작성)**: 로봇이나 자율주행차가 연속된 카메라 프레임 사이의 특징점을 매칭해 카메라(또는 로봇)가 얼마나 움직였는지 추정하는 데 사용됩니다.

이 장에서 익힌 "검출 → 서술 → 매칭 → (필요하다면) 기하학적 변환 추정"이라는 흐름은 알고리즘이 ORB, SIFT, AKAZE 등으로 바뀌어도 그대로 유지되는 특징점 기반 비전의 공통 골격입니다.

## 요약

- 특징점(keypoint)은 이미지에서 주변과 뚜렷이 구별되며, 이미지가 회전하거나 크기가 변해도 다시 찾아낼 수 있는 지점입니다. 좋은 특징점은 반복 가능성, 불변성, 구별 가능성, 효율성을 만족해야 합니다.
- ORB는 FAST 코너 검출과 BRIEF 디스크립터를 결합한 알고리즘으로, 처음부터 특허 문제가 없고 속도가 빨라 실전에서 널리 사용됩니다. `cv2.ORB_create()`로 생성하며, 디스크립터는 32바이트 이진 벡터입니다.
- SIFT는 스케일 공간에서 DoG 극값을 찾아 128차원 부동소수점 디스크립터를 만드는 알고리즘으로, 2020년 특허가 만료되어 이제 `opencv-python` 기본 패키지의 `cv2.SIFT_create()`로 바로 사용할 수 있습니다. ORB보다 느리지만 더 정교하고 안정적입니다.
- `detect()`는 특징점 위치만, `compute()`는 디스크립터만 계산하며, `detectAndCompute()`는 두 단계를 한 번에 처리합니다. `drawKeypoints`로 검출된 특징점을 위치·크기·방향과 함께 시각화할 수 있습니다.
- `BFMatcher`는 디스크립터를 전수 비교해 대응 관계를 찾으며, ORB에는 `NORM_HAMMING`, SIFT에는 `NORM_L2`를 사용합니다. `crossCheck` 옵션으로 오매칭을 줄일 수 있습니다.
- `FlannBasedMatcher`는 인덱스 기반 근사 탐색으로 대규모 디스크립터 집합에서 `BFMatcher`보다 훨씬 빠르게 동작합니다. 부동소수점 디스크립터에는 KD-트리, 이진 디스크립터에는 LSH 인덱스를 사용해야 합니다. `knnMatch`와 Lowe's ratio test를 함께 쓰면 신뢰도 높은 매칭만 걸러낼 수 있습니다.
- 매칭된 특징점 좌표로 `cv2.findHomography()`(RANSAC 플래그로 이상치 제거)를 이용해 두 이미지 사이의 원근 변환 관계를 계산하고, `cv2.warpPerspective()`로 한 이미지를 다른 이미지의 시점에 맞춰 정렬할 수 있습니다. 이는 이미지 스티칭의 첫 단계입니다.
- 특징점 매칭은 이미지 스티칭, 객체 인식, 이미지 정합, SLAM 등 실전 컴퓨터 비전 애플리케이션의 핵심 구성 요소입니다.

## 연습문제

1. ORB의 `nfeatures` 값을 100, 500, 2000으로 바꿔가며 같은 이미지에서 검출되는 특징점 개수와 처리 시간이 어떻게 달라지는지 비교해 보세요.
2. 같은 이미지 쌍에 ORB와 SIFT를 각각 적용해 `time.perf_counter()`로 검출·매칭 시간을 측정하고, 검출된 특징점 개수와 매칭 품질(정상치 비율)을 함께 비교해 보세요.
3. `BFMatcher`와 `FlannBasedMatcher`(SIFT + KD-트리)로 같은 두 이미지를 매칭한 뒤, 매칭 개수와 소요 시간이 특징점 개수(500개, 2000개, 5000개)에 따라 어떻게 달라지는지 실험해 보세요.
4. Lowe's ratio test의 임계값을 0.6, 0.75, 0.9로 바꿔가며 `good_matches`의 개수가 어떻게 달라지는지, 그리고 임계값이 너무 낮거나 높을 때 어떤 문제가 생기는지 설명해 보세요.
5. 15.8절의 호모그래피 예제에서 `ransacReprojThreshold` 값을 1.0과 10.0으로 각각 바꿔 실행하고, RANSAC이 정상치로 채택하는 매칭 개수와 최종 `warpPerspective` 결과의 정렬 품질이 어떻게 달라지는지 비교해 보세요.
