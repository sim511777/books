9장에서는 이미지를 부드럽게 만들거나 선명하게 만드는 필터링을 다뤘습니다. 이번 장에서는 이미지를 아예 흑과 백, 두 가지 값만 가지는 이진 이미지(binary image)로 바꾸는 임계처리(thresholding)를 살펴봅니다. 임계처리는 문서에서 글자만 골라내거나, 배경에서 물체를 분리하거나, 이후 13장에서 다룰 컨투어 검출의 입력을 준비하는 등 컴퓨터 비전 파이프라인 곳곳에서 사용되는 기본 기술입니다. 이번 장에서는 기본적인 임계처리 함수들을 다루는 것에서 나아가, Otsu 알고리즘이 임계값을 "어떻게" 자동으로 찾아내는지 그 원리를 조금 더 깊이 들여다보고, 조명 조건을 인위적으로 만들어 단순 임계처리와 적응형 임계처리의 차이를 실험으로 확인하고, 컬러 이미지를 이진화하는 몇 가지 접근 방식도 비교해 봅니다.

## 10.1 단순 임계처리: threshold

임계처리의 가장 단순한 형태는 픽셀 값을 하나의 기준값(임계값, threshold)과 비교해서 그보다 크면 한 값으로, 작으면 다른 값으로 바꾸는 것입니다. OpenCV는 이를 `threshold` 함수로 제공합니다.

```
retval, dst = cv2.threshold(src, thresh, maxval, type)
```

`src`는 보통 그레이스케일 이미지, `thresh`는 임계값, `maxval`은 조건을 만족했을 때 부여할 값, `type`은 어떤 방식으로 비교할지를 결정하는 플래그입니다. 대표적인 플래그는 다음과 같습니다.

| 플래그 | 동작 |
|---|---|
| `THRESH_BINARY` | 픽셀 값이 `thresh`보다 크면 `maxval`, 아니면 0 |
| `THRESH_BINARY_INV` | `THRESH_BINARY`의 반대: 크면 0, 아니면 `maxval` |
| `THRESH_TRUNC` | `thresh`보다 크면 `thresh`로 자르고, 작으면 원래 값 유지 |
| `THRESH_TOZERO` | `thresh`보다 크면 원래 값 유지, 작으면 0 |
| `THRESH_TOZERO_INV` | `THRESH_TOZERO`의 반대: 크면 0, 작으면 원래 값 유지 |

`THRESH_BINARY`는 밝은 물체를 흰색으로, 어두운 배경을 검은색으로 만드는 가장 흔한 용도에 쓰이고, `THRESH_BINARY_INV`는 반대로 어두운 물체를 강조하고 싶을 때(예: 흰 종이 위의 검은 글자) 사용합니다. `THRESH_TRUNC`와 `THRESH_TOZERO` 계열은 이진화가 아니라 밝기를 특정 범위로 제한하거나 어두운 영역을 배경으로 지워버리는 용도로 종종 쓰입니다.

### 예제 10-1. 다섯 가지 임계처리 플래그 비교

```python
import cv2

img = cv2.imread('document.jpg', cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError('document.jpg를 찾을 수 없습니다.')

thresh_val = 127
_, binary = cv2.threshold(img, thresh_val, 255, cv2.THRESH_BINARY)
_, binary_inv = cv2.threshold(img, thresh_val, 255, cv2.THRESH_BINARY_INV)
_, trunc = cv2.threshold(img, thresh_val, 255, cv2.THRESH_TRUNC)
_, tozero = cv2.threshold(img, thresh_val, 255, cv2.THRESH_TOZERO)
_, tozero_inv = cv2.threshold(img, thresh_val, 255, cv2.THRESH_TOZERO_INV)

cv2.imshow('Original (gray)', img)
cv2.imshow('THRESH_BINARY', binary)
cv2.imshow('THRESH_BINARY_INV', binary_inv)
cv2.imshow('THRESH_TRUNC', trunc)
cv2.imshow('THRESH_TOZERO', tozero)
cv2.imshow('THRESH_TOZERO_INV', tozero_inv)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

`threshold`는 사용한 실제 임계값을 첫 번째 반환값(`retval`)으로 돌려줍니다. 일반적인 `THRESH_BINARY` 등을 사용할 때는 `retval`이 그냥 우리가 넘겨준 `thresh_val`과 같지만, 잠시 뒤에 살펴볼 `THRESH_OTSU`를 함께 지정하면 이 값이 자동으로 계산된 임계값으로 바뀝니다. 지금까지는 직접 127을 지정했지만, 항상 127이 최적의 값이라는 보장은 없습니다. 이미지마다 밝기 분포가 다르기 때문입니다.

## 10.2 Otsu의 방법: 임계값을 자동으로 찾는 원리

적절한 임계값을 사람이 하나씩 눈으로 확인하며 찾는 것은 비효율적입니다. Otsu의 방법(Otsu's method)은 이미지의 히스토그램(각 밝기 값이 몇 번 나타나는지를 나타낸 분포, 14장에서 자세히 다룹니다)을 분석해서 최적의 임계값을 자동으로 계산해 줍니다.

### 10.2.1 직관적으로 이해하기: 두 그룹으로 가장 잘 나누는 경계선

흑백 문서 사진을 생각해 보면, 히스토그램은 대개 두 개의 봉우리(bimodal)를 가집니다. 하나는 어두운 글자 픽셀들이 모여 만드는 봉우리, 다른 하나는 밝은 종이 배경 픽셀들이 모여 만드는 봉우리입니다. 우리가 찾고자 하는 좋은 임계값은 바로 이 두 봉우리 "사이의 골짜기" 어딘가에 있을 것입니다.

Otsu의 방법은 이 골짜기를 다음과 같은 방식으로 수치화해서 찾아냅니다. 어떤 후보 임계값 t를 하나 정하면, 이미지의 모든 픽셀은 t보다 작은 그룹(배경이라고 하자)과 t보다 큰 그룹(전경이라고 하자) 두 개로 나뉩니다. 이때 다음 두 가지를 계산할 수 있습니다.

- **클래스 내 분산(within-class variance)**: 각 그룹 내부에서 픽셀 값들이 얼마나 퍼져 있는지. 그룹이 순수하게 한 종류의 물체로만 이루어져 있다면 이 값은 작아야 합니다.
- **클래스 간 분산(between-class variance)**: 두 그룹의 평균값이 서로 얼마나 멀리 떨어져 있는지. 두 그룹이 실제로 서로 다른 물체(글자 vs. 배경)를 잘 대표하고 있다면 이 값은 커야 합니다.

전체 분산은 이 두 가지의 합으로 고정되어 있기 때문에(전체 분산 = 클래스 내 분산 + 클래스 간 분산), 클래스 내 분산을 최소화하는 것과 클래스 간 분산을 최대화하는 것은 결국 같은 목표입니다. Otsu의 방법은 계산이 더 간단한 클래스 간 분산을 최대화하는 t를 0부터 255까지 모두 시도해서 찾아냅니다.

클래스 간 분산은 다음과 같이 정의됩니다. 임계값 t로 나뉜 배경 그룹의 픽셀 비율을 w0, 평균 밝기를 μ0, 전경 그룹의 픽셀 비율을 w1, 평균 밝기를 μ1이라고 하면,

```
클래스 간 분산(t) = w0 × w1 × (μ0 − μ1)²
```

이 값이 최대가 되는 t가 바로 Otsu가 찾는 임계값입니다. 직관적으로 보면, 두 그룹의 크기가 어느 정도 균형 잡혀 있으면서(w0와 w1이 모두 너무 작지 않으면서) 두 그룹의 평균 밝기 차이(μ0 − μ1)가 가장 큰 지점을 고르는 것입니다.

### 10.2.2 NumPy로 Otsu 알고리즘 직접 구현해 보기

이 원리를 직접 코드로 확인해 보겠습니다. 이미지의 히스토그램을 구한 뒤, 가능한 모든 임계값(0~255)에 대해 클래스 간 분산을 계산하고, 그 값이 최대가 되는 지점을 찾아 `cv2.threshold`의 `THRESH_OTSU` 결과와 비교합니다.

```python
import cv2
import numpy as np

img = cv2.imread('document.jpg', cv2.IMREAD_GRAYSCALE)

def otsu_threshold_manual(gray):
    hist, _ = np.histogram(gray.ravel(), bins=256, range=(0, 256))
    hist = hist.astype(np.float64)
    total = hist.sum()

    best_t = 0
    best_variance = -1.0

    for t in range(1, 256):
        w0 = hist[:t].sum() / total
        w1 = hist[t:].sum() / total
        if w0 == 0 or w1 == 0:
            continue

        mu0 = np.sum(np.arange(t) * hist[:t]) / hist[:t].sum()
        mu1 = np.sum(np.arange(t, 256) * hist[t:]) / hist[t:].sum()

        between_class_variance = w0 * w1 * (mu0 - mu1) ** 2
        if between_class_variance > best_variance:
            best_variance = between_class_variance
            best_t = t

    return best_t

manual_t = otsu_threshold_manual(img)
opencv_t, _ = cv2.threshold(img, 0, 255, cv2.THRESH_BINARY | cv2.THRESH_OTSU)

print(f'직접 구현한 Otsu 임계값: {manual_t}')
print(f'cv2.THRESH_OTSU가 계산한 임계값: {opencv_t}')
```

두 값은 대개 정확히 같거나 1 정도의 아주 작은 차이만 보입니다(구현 방식에 따른 반올림 차이 정도). 이 실험을 통해 Otsu의 방법이 신비한 블랙박스가 아니라, "가능한 모든 경계선을 다 시도해 보고 두 그룹을 가장 잘 갈라놓는 경계선을 고르는" 무차별 탐색(brute-force search)에 가까운 알고리즘이라는 것을 확인할 수 있습니다.

### 10.2.3 threshold에서 THRESH_OTSU 사용하기

실무에서는 물론 직접 구현할 필요 없이 `threshold`에 `THRESH_OTSU` 플래그를 추가로 지정하면 됩니다. 이때 `thresh` 매개변수로 넘긴 값은 무시되고 자동으로 계산된 값이 대신 사용되므로, 관례상 0을 넘겨줍니다. `THRESH_BINARY`와 `THRESH_OTSU`는 비트 OR(`|`)로 함께 지정합니다.

### 예제 10-2. Otsu의 방법으로 임계값 자동 결정하기

```python
import cv2

img = cv2.imread('document.jpg', cv2.IMREAD_GRAYSCALE)

# 노이즈가 있으면 Otsu의 결과가 흔들릴 수 있어 가벼운 블러를 먼저 적용합니다.
blurred = cv2.GaussianBlur(img, (5, 5), 0)

otsu_thresh, otsu_binary = cv2.threshold(
    blurred, 0, 255, cv2.THRESH_BINARY | cv2.THRESH_OTSU
)

print(f'Otsu가 찾은 임계값: {otsu_thresh}')

cv2.imshow('Original', img)
cv2.imshow('Otsu Binary', otsu_binary)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

Otsu의 방법은 이미지의 밝기 분포가 배경과 전경, 두 개의 봉우리로 뚜렷하게 나뉘어 있을 때 특히 잘 동작합니다. 반대로 밝기 분포가 하나의 봉우리에만 몰려 있거나(예: 배경과 물체의 밝기 차이가 거의 없는 이미지), 조명이 불균일해서 같은 물체인데도 위치에 따라 밝기가 크게 다르다면, 전역적으로 하나의 임계값만 찾는 Otsu의 방법으로는 만족스러운 결과를 얻기 어렵습니다. 바로 이런 상황을 해결하기 위한 것이 다음 절의 적응형 임계처리입니다.

## 10.3 적응형 임계처리: adaptiveThreshold

`threshold`와 Otsu의 방법은 모두 이미지 전체에 대해 단 하나의 임계값을 사용합니다. 그런데 조명이 균일하지 않은 이미지, 예를 들어 한쪽은 밝고 다른 쪽은 그림자가 진 문서 사진이라면 어떨까요? 전체에 적용할 하나의 임계값으로는 밝은 영역과 어두운 영역을 동시에 만족시킬 수 없습니다. 밝은 쪽에 맞춰 임계값을 낮추면 어두운 쪽 글자가 몽땅 사라지고, 어두운 쪽에 맞춰 임계값을 높이면 밝은 쪽 배경까지 글자로 인식되어 버립니다.

적응형 임계처리(`adaptiveThreshold`)는 이 문제를 픽셀마다 서로 다른 임계값을 적용하는 방식으로 해결합니다. 각 픽셀의 임계값을 그 픽셀 주변의 작은 영역(블록)에서 계산한 통계값을 기준으로 결정하기 때문에, 이미지의 왼쪽과 오른쪽이 밝기가 크게 다르더라도 각자의 지역적인 밝기 기준에 맞춰 이진화됩니다.

```
dst = cv2.adaptiveThreshold(src, maxValue, adaptiveMethod, thresholdType, blockSize, C)
```

- `adaptiveMethod`: 지역 임계값을 계산하는 방법. `ADAPTIVE_THRESH_MEAN_C`는 블록 내 픽셀의 단순 평균을, `ADAPTIVE_THRESH_GAUSSIAN_C`는 가우시안 가중 평균을 사용합니다.
- `blockSize`: 임계값을 계산할 지역 영역의 한 변 길이(홀수).
- `C`: 계산된 지역 평균에서 추가로 빼주는 상수. 결과가 너무 밝거나 어둡게 나올 때 미세 조정하는 용도입니다.

### 예제 10-3. adaptiveThreshold의 기본 사용법

```python
import cv2

img = cv2.imread('uneven_light_document.jpg', cv2.IMREAD_GRAYSCALE)

adaptive_mean = cv2.adaptiveThreshold(
    img, 255, cv2.ADAPTIVE_THRESH_MEAN_C, cv2.THRESH_BINARY,
    blockSize=25, C=10
)
adaptive_gaussian = cv2.adaptiveThreshold(
    img, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C, cv2.THRESH_BINARY,
    blockSize=25, C=10
)

cv2.imshow('Adaptive Mean', adaptive_mean)
cv2.imshow('Adaptive Gaussian', adaptive_gaussian)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

`blockSize`가 너무 작으면 지역 잡음에 민감해지고, 너무 크면 전역 임계처리와 비슷해지므로 이미지의 글자 크기나 조명 변화 폭에 맞춰 실험적으로 조정하는 것이 좋습니다. `ADAPTIVE_THRESH_MEAN_C`와 `ADAPTIVE_THRESH_GAUSSIAN_C`의 차이는 9.3절에서 다룬 평균 블러와 가우시안 블러의 차이와 정확히 같은 맥락입니다. 후자는 블록 중심에 가까운 픽셀에 더 큰 가중치를 주기 때문에, 블록 경계 부근에서 조금 더 부드러운 임계값 변화를 만들어 냅니다.

## 10.4 실전 실험: 균일한 조명 vs. 불균일한 조명

이제 실제 문서 사진 없이도, NumPy와 OpenCV의 그림 그리기 함수만으로 조명 조건을 인위적으로 시뮬레이션해서 단순 임계처리와 적응형 임계처리의 차이를 직접 관찰해 보겠습니다.

### 10.4.1 테스트 이미지 만들기

먼저 흰 배경 위에 검은 글자 모양의 도형(사각형, 원, 텍스트)을 그려서 "이상적인 문서"를 만듭니다. 그런 다음 여기에 왼쪽에서 오른쪽으로 밝기가 점점 어두워지는 그라디언트를 곱해서 "불균일한 조명" 버전을 만들어 보겠습니다.

```python
import cv2
import numpy as np

def make_document_like_image(size=(400, 600)):
    """흰 배경에 검은 도형/글자를 그려 문서와 비슷한 이미지를 만듭니다."""
    img = np.full(size, 255, dtype=np.uint8)  # 흰 배경

    cv2.putText(img, 'OpenCV Thresholding', (40, 80),
                cv2.FONT_HERSHEY_SIMPLEX, 1.2, 0, 2, cv2.LINE_AA)
    cv2.rectangle(img, (40, 150), (250, 230), 0, thickness=-1)
    cv2.circle(img, (400, 190), 60, 0, thickness=-1)
    cv2.putText(img, 'sample text line', (40, 300),
                cv2.FONT_HERSHEY_SIMPLEX, 0.9, 0, 2, cv2.LINE_AA)

    return img

def apply_uneven_lighting(gray_img, min_factor=0.35, max_factor=1.0):
    """왼쪽에서 오른쪽으로 어두워지는 조명 그라디언트를 곱해줍니다."""
    h, w = gray_img.shape
    gradient = np.linspace(max_factor, min_factor, w, dtype=np.float32)
    gradient = np.tile(gradient, (h, 1))

    img_f = gray_img.astype(np.float32)
    # 흰 배경(255)이 곱해지면 어두워지고, 검은 글자(0)는 곱해도 그대로 0입니다.
    lit = img_f * gradient
    return np.clip(lit, 0, 255).astype(np.uint8)

uniform_img = make_document_like_image()
uneven_img = apply_uneven_lighting(uniform_img)

cv2.imshow('Uniform Lighting', uniform_img)
cv2.imshow('Uneven Lighting', uneven_img)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### 10.4.2 두 이미지에 전역 Otsu와 adaptiveThreshold 적용해 비교하기

```python
import cv2

def compare_thresholding(gray_img, label):
    _, otsu_binary = cv2.threshold(gray_img, 0, 255, cv2.THRESH_BINARY_INV | cv2.THRESH_OTSU)
    adaptive_binary = cv2.adaptiveThreshold(
        gray_img, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C, cv2.THRESH_BINARY_INV,
        blockSize=51, C=10
    )

    cv2.imshow(f'{label} - Original', gray_img)
    cv2.imshow(f'{label} - Global Otsu', otsu_binary)
    cv2.imshow(f'{label} - Adaptive Gaussian', adaptive_binary)

compare_thresholding(uniform_img, 'Uniform')
compare_thresholding(uneven_img, 'Uneven')
cv2.waitKey(0)
cv2.destroyAllWindows()
```

이 실험을 실행해 보면 다음과 같은 결과를 확인할 수 있습니다.

- **균일한 조명** 이미지에서는 전역 Otsu 이진화와 적응형 임계처리의 결과가 거의 동일합니다. 조명이 균일하다면 지역별로 다른 임계값을 쓸 필요 자체가 없기 때문입니다.
- **불균일한 조명** 이미지에서는 두 방법의 차이가 뚜렷하게 드러납니다. 전역 Otsu는 이미지 전체에서 단 하나의 임계값만 찾기 때문에, 오른쪽의 어두워진 흰 배경까지도 임계값보다 어두워 보여서 전경(글자)으로 잘못 분류되는 경우가 생깁니다. 반면 적응형 임계처리는 오른쪽 영역에서는 그 지역의 상대적으로 어두운 배경 기준으로, 왼쪽 영역에서는 그 지역의 밝은 배경 기준으로 각각 임계값을 계산하기 때문에, 조명이 달라도 도형과 글자 모양이 두 영역 모두에서 비교적 온전하게 유지됩니다.

이 실험은 "왜 조명이 불균일한 실제 사진(예: 스마트폰으로 대충 찍은 문서, 그림자가 걸친 표지판)에서는 반드시 적응형 임계처리를 고려해야 하는가"를 코드로 직접 보여줍니다.

## 10.5 컬러 이미지의 임계처리: 채널별 처리 vs. 그레이스케일 변환

지금까지의 예제는 모두 그레이스케일 이미지를 다뤘습니다. 컬러 이미지를 이진화해야 할 때는 크게 두 가지 접근 방식이 있습니다. 그레이스케일로 변환한 뒤 밝기만으로 이진화하는 방법과, B/G/R 각 채널을 따로 이진화한 뒤 조합하는 방법입니다. 두 방법은 결과가 상당히 다를 수 있습니다.

### 10.5.1 그레이스케일 변환의 한계

밝기(luminance)는 같지만 색상(hue)이 다른 두 물체가 있다면, 그레이스케일로 변환하는 순간 그 둘을 구분할 정보가 사라집니다. 예를 들어 채도가 높은 빨간색 사각형과 초록색 사각형을 밝기가 거의 같도록 만들어 보면, 그레이스케일 변환 후에는 두 도형이 거의 같은 밝기 값으로 보이게 됩니다.

```python
import cv2
import numpy as np

def make_color_test_image():
    img = np.full((300, 400, 3), 255, dtype=np.uint8)  # 흰 배경 (BGR)
    # 밝기가 비슷하도록 맞춘 빨간 사각형과 초록 사각형
    cv2.rectangle(img, (40, 60), (170, 190), (40, 40, 180), thickness=-1)   # 빨강 계열(BGR)
    cv2.rectangle(img, (220, 60), (350, 190), (40, 160, 40), thickness=-1)  # 초록 계열(BGR)
    return img

color_img = make_color_test_image()
gray = cv2.cvtColor(color_img, cv2.COLOR_BGR2GRAY)

print('빨간 사각형 영역 평균 밝기(그레이):', gray[60:190, 40:170].mean())
print('초록 사각형 영역 평균 밝기(그레이):', gray[60:190, 220:350].mean())

_, gray_otsu = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY_INV | cv2.THRESH_OTSU)

cv2.imshow('Color Original', color_img)
cv2.imshow('Grayscale', gray)
cv2.imshow('Grayscale + Otsu', gray_otsu)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

두 사각형의 밝기를 의도적으로 비슷하게 맞췄기 때문에, `gray_otsu` 결과에서는 두 사각형이 모두 "전경"으로 뭉뚱그려져서 뽑혀 나올 뿐, 색상으로 둘을 구분할 방법이 없습니다. 즉 그레이스케일 변환 후 이진화는 "밝기 차이"만 활용할 수 있고, 색상 차이는 활용하지 못합니다.

### 10.5.2 채널별로 이진화해서 특정 색상만 골라내기

색상 정보를 활용하려면 채널을 나눠서 각각 조건을 걸고 조합해야 합니다. `cv2.split`으로 B, G, R 채널을 분리한 뒤, 원하는 색상 조건(예: "R 채널은 높고, G와 B 채널은 낮다" → 빨간색 계열)을 각 채널에 대한 `threshold`로 표현하고 `bitwise_and`로 결합합니다.

```python
import cv2

b, g, r = cv2.split(color_img)

# "빨간색"의 조건: R은 밝고(값이 큼), G와 B는 상대적으로 어두움(값이 작음)
_, r_high = cv2.threshold(r, 100, 255, cv2.THRESH_BINARY)
_, g_low = cv2.threshold(g, 100, 255, cv2.THRESH_BINARY_INV)
_, b_low = cv2.threshold(b, 100, 255, cv2.THRESH_BINARY_INV)

red_mask = cv2.bitwise_and(r_high, g_low)
red_mask = cv2.bitwise_and(red_mask, b_low)

red_only = cv2.bitwise_and(color_img, color_img, mask=red_mask)

cv2.imshow('Red Mask (channel-wise threshold)', red_mask)
cv2.imshow('Red Region Extracted', red_only)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

이 방식은 그레이스케일로는 구분할 수 없었던 빨간 사각형만 정확히 골라냅니다. 다만 채널별 임계처리는 "R, G, B 각각의 절대적인 밝기 조건"으로 색상을 정의하기 때문에, 조명이 바뀌어 전체적으로 밝아지거나 어두워지면 조건이 깨지기 쉽다는 한계가 있습니다. 실무에서 특정 색상 범위를 좀 더 안정적으로 지정하고 싶다면, `cv2.cvtColor`로 HSV 색공간으로 변환한 뒤 색상(Hue) 채널만으로 조건을 걸거나 `cv2.inRange`를 사용하는 방법이 조명 변화에 더 안정적입니다. 다만 `inRange`는 임계처리라는 주제의 범위를 넘어서는 별도의 도구이므로, 여기서는 "채널별 `threshold` 조합으로도 색상 기반 분리가 가능하다"는 원리를 이해하는 데 집중합니다.

### 10.5.3 두 접근 방식 정리

| 접근 방식 | 장점 | 단점 |
|---|---|---|
| 그레이스케일 변환 후 이진화 | 구현이 단순하고 빠름, Otsu 등 자동 임계값 계산과 잘 맞음 | 색상 차이는 활용하지 못하고 밝기 차이만 구분함 |
| 채널별(B/G/R) 임계처리 후 결합 | 색상 조건을 직접 표현할 수 있어 특정 색상만 분리 가능 | 조명 변화에 취약, 채널마다 임계값을 따로 튜닝해야 함 |

일반적으로 문서 이진화처럼 "글자냐 배경이냐"를 밝기로 구분하는 작업이라면 그레이스케일 변환이 훨씬 간단하고 충분합니다. 반대로 "빨간 부품만 찾기"처럼 색상 자체가 구분 기준이 되는 작업이라면 채널별 처리(또는 HSV 기반 처리)가 필요합니다.

## 10.6 실전 예제: 문서 스캔 이미지 이진화하기

지금까지 배운 내용을 종합해서, 휴대폰 카메라로 찍은 손글씨나 문서 이미지를 텍스트와 배경이 뚜렷하게 구분되는 이진 이미지로 변환하는 실전 파이프라인을 만들어 보겠습니다. 일반적으로 다음 순서를 따릅니다.

1. 그레이스케일로 변환한다.
2. 노이즈를 줄이기 위해 가벼운 블러(가우시안 또는 미디안)를 적용한다.
3. 조명이 균일하다면 Otsu, 불균일하다면 적응형 임계처리를 적용한다.
4. 필요하다면 결과를 반전시켜 글자를 흰색(전경)으로 맞춘다.

### 예제 10-4. 문서 이미지에서 글자만 분리하기

```python
import cv2

def binarize_document(path, uneven_light=True):
    img = cv2.imread(path, cv2.IMREAD_GRAYSCALE)
    if img is None:
        raise FileNotFoundError(f'{path}를 찾을 수 없습니다.')

    # 1. 스캔 노이즈 완화 (미디안 블러는 종이의 얼룩이나 점 잡음에 강합니다.)
    denoised = cv2.medianBlur(img, 3)

    # 2. 조명 상태에 따라 적응형 또는 Otsu 이진화 선택
    if uneven_light:
        binary = cv2.adaptiveThreshold(
            denoised, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C,
            cv2.THRESH_BINARY_INV, blockSize=31, C=15
        )
    else:
        _, binary = cv2.threshold(
            denoised, 0, 255, cv2.THRESH_BINARY_INV | cv2.THRESH_OTSU
        )

    return binary

result = binarize_document('handwritten_note.jpg', uneven_light=True)
cv2.imshow('Binarized Document', result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

여기서는 `THRESH_BINARY_INV`를 사용해 글자(원래 어두운 픽셀)가 흰색(255)으로, 배경(원래 밝은 픽셀)이 검은색(0)으로 나오도록 했습니다. 이렇게 전경을 흰색으로 맞춰두면 13장에서 배울 `findContours`가 글자 영역을 훨씬 자연스럽게 검출할 수 있습니다.

조명 조건을 미리 알 수 없는 경우라면, 10.4절의 실험처럼 이미지의 밝기 표준편차나 좌우/상하 영역의 평균 밝기 차이를 계산해서 "조명이 균일한지"를 자동으로 판단하고 그 결과에 따라 `uneven_light` 값을 정하는 방식으로 파이프라인을 확장할 수도 있습니다.

```python
import cv2
import numpy as np

def is_lighting_uneven(gray_img, block=4, std_threshold=15.0):
    """이미지를 block x block 그리드로 나눠 각 블록 평균 밝기의 표준편차로 조명 균일성을 추정합니다."""
    h, w = gray_img.shape
    means = []
    for i in range(block):
        for j in range(block):
            y0, y1 = i * h // block, (i + 1) * h // block
            x0, x1 = j * w // block, (j + 1) * w // block
            means.append(gray_img[y0:y1, x0:x1].mean())
    return np.std(means) > std_threshold
```

## 10.7 다음 장 예고: 모폴로지 연산과의 조합

실전에서 이진화 결과를 그대로 사용하는 경우는 많지 않습니다. 스캔 과정의 작은 잡음이 점처럼 남아 있거나, 글자의 획이 얇게 끊어져 보이는 경우가 흔하기 때문입니다. 11장에서 배울 모폴로지 연산(팽창, 침식, 열림, 닫힘)은 바로 이런 이진 이미지의 잡티를 정리하고 끊어진 획을 이어주는 후처리 단계로, 임계처리와 거의 항상 짝을 이루어 사용됩니다. 예를 들어 이번 장의 `binarize_document` 결과에 열림 연산을 적용하면 작은 점 잡음이 사라지고, 닫힘 연산을 적용하면 끊어진 글자의 획이 이어지는 것을 다음 장에서 직접 확인해 보겠습니다.

## 요약

- `threshold`는 픽셀 값을 하나의 전역 임계값과 비교해 이진 이미지를 만들며, `THRESH_BINARY`, `THRESH_BINARY_INV`, `THRESH_TRUNC`, `THRESH_TOZERO`, `THRESH_TOZERO_INV` 등의 옵션으로 비교 방식을 바꿀 수 있습니다.
- Otsu의 방법(`THRESH_OTSU`)은 클래스 내 분산을 최소화(=클래스 간 분산을 최대화)하는 임계값을 히스토그램 전체를 탐색해서 자동으로 찾아주며, 배경과 전경이 뚜렷이 구분되는(히스토그램이 두 봉우리를 갖는) 이미지에서 특히 효과적입니다.
- `adaptiveThreshold`는 픽셀 주변의 작은 영역마다 서로 다른 임계값을 적용해, 조명이 불균일한 이미지에서 전역 임계처리보다 훨씬 안정적인 결과를 냅니다. 균일한 조명에서는 전역 Otsu와 결과가 거의 같아집니다.
- 컬러 이미지를 이진화할 때 그레이스케일 변환은 간단하지만 색상 정보를 버리고 밝기만 사용하며, 채널별(B/G/R) 임계처리를 조합하면 밝기가 비슷해도 색상이 다른 물체를 구분할 수 있습니다.
- 문서나 손글씨 이미지를 이진화할 때는 그레이스케일 변환 → 노이즈 제거 → (전역 또는 적응형) 임계처리의 순서로 파이프라인을 구성하는 것이 일반적입니다.
- 이진화 결과는 11장의 모폴로지 연산과 결합해 잡음을 제거하거나 끊어진 획을 잇는 후처리를 거치는 경우가 많습니다.
