## 18.1 실전 프로젝트: 스마트폰으로 찍은 문서를 정면으로 펴기

스마트폰 스캐너 앱들이 흔히 하는 일을 그대로 재현해보자. 비스듬한 각도에서 찍은 문서 사진 한 장을 입력받아, 문서의 네 꼭짓점을 찾아내고, 그 사각형을 정면에서 본 것처럼 펴서 출력하는 프로그램이다. 이 작업은 지금까지 배운 기법들을 다음과 같은 순서로 연결한 것에 불과하다.

| 단계 | 사용 기법 | 관련 장 |
|---|---|---|
| 1. 이미지 읽기 | `imread` | 4장 |
| 2. 그레이스케일 변환 | `cvtColor` | 5장 |
| 3. 노이즈 완화 | `GaussianBlur` | 9장 |
| 4. 경계 검출 | `Canny` | 12장 |
| 5. 윤곽선 검출 | `findContours` | 13장 |
| 6. 사각형 근사 | `approxPolyDP` | 13장 |
| 7. 원근 변환으로 펴기 | `getPerspectiveTransform` + `warpPerspective` | 8장 |

한 걸음씩 뜯어보면, 이 파이프라인의 핵심 논리는 이렇다. 먼저 엣지 검출로 문서와 배경의 경계선을 도드라지게 만든다. 그 경계선들로부터 윤곽선을 뽑아내고, 그중 가장 넓은 면적을 차지하면서 꼭짓점이 정확히 4개인 다각형을 "문서의 테두리"로 간주한다. 마지막으로 그 4개의 꼭짓점을 목표 사각형(가로세로가 딱 맞는 반듯한 직사각형)의 네 꼭짓점으로 매핑하는 원근 변환 행렬을 구해, 이미지 전체를 그 변환으로 다시 그리면 기울어져 찍힌 문서가 정면 스캔본처럼 펴진다.

### Python

```python
import cv2
import numpy as np


def order_points(pts):
    """4개의 점을 top-left, top-right, bottom-right, bottom-left 순서로 정렬한다."""
    pts = pts.reshape(4, 2).astype(np.float32)
    s = pts.sum(axis=1)          # x+y가 가장 작으면 top-left, 가장 크면 bottom-right
    diff = np.diff(pts, axis=1).flatten()  # x-y가 가장 작으면 top-right, 가장 크면 bottom-left

    ordered = np.zeros((4, 2), dtype=np.float32)
    ordered[0] = pts[np.argmin(s)]
    ordered[2] = pts[np.argmax(s)]
    ordered[1] = pts[np.argmin(diff)]
    ordered[3] = pts[np.argmax(diff)]
    return ordered


def scan_document(path):
    img = cv2.imread(path)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    blurred = cv2.GaussianBlur(gray, (5, 5), 0)
    edges = cv2.Canny(blurred, 75, 200)

    contours, _ = cv2.findContours(edges, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    contours = sorted(contours, key=cv2.contourArea, reverse=True)

    doc_corners = None
    for c in contours:
        peri = cv2.arcLength(c, True)
        approx = cv2.approxPolyDP(c, 0.02 * peri, True)
        if len(approx) == 4:
            doc_corners = approx
            break

    if doc_corners is None:
        raise RuntimeError("문서 경계를 찾지 못했습니다.")

    tl, tr, br, bl = order_points(doc_corners)

    width = int(max(np.linalg.norm(br - bl), np.linalg.norm(tr - tl)))
    height = int(max(np.linalg.norm(tr - br), np.linalg.norm(tl - bl)))

    dst = np.array(
        [[0, 0], [width - 1, 0], [width - 1, height - 1], [0, height - 1]],
        dtype=np.float32,
    )
    src = np.array([tl, tr, br, bl], dtype=np.float32)

    M = cv2.getPerspectiveTransform(src, dst)
    return cv2.warpPerspective(img, M, (width, height))


if __name__ == "__main__":
    scanned = scan_document("document.jpg")
    cv2.imshow("Scanned", scanned)
    cv2.waitKey(0)
    cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>
#include <algorithm>
#include <iostream>
#include <vector>

std::vector<cv::Point2f> orderPoints(const std::vector<cv::Point>& pts) {
    std::vector<float> sums, diffs;
    for (const auto& p : pts) {
        sums.push_back(static_cast<float>(p.x + p.y));
        diffs.push_back(static_cast<float>(p.x - p.y));
    }
    int tl = static_cast<int>(std::distance(sums.begin(), std::min_element(sums.begin(), sums.end())));
    int br = static_cast<int>(std::distance(sums.begin(), std::max_element(sums.begin(), sums.end())));
    int tr = static_cast<int>(std::distance(diffs.begin(), std::max_element(diffs.begin(), diffs.end())));
    int bl = static_cast<int>(std::distance(diffs.begin(), std::min_element(diffs.begin(), diffs.end())));

    return { cv::Point2f(pts[tl]), cv::Point2f(pts[tr]), cv::Point2f(pts[br]), cv::Point2f(pts[bl]) };
}

cv::Mat scanDocument(const std::string& path) {
    cv::Mat img = cv::imread(path);
    cv::Mat gray, blurred, edges;
    cv::cvtColor(img, gray, cv::COLOR_BGR2GRAY);
    cv::GaussianBlur(gray, blurred, cv::Size(5, 5), 0);
    cv::Canny(blurred, edges, 75, 200);

    std::vector<std::vector<cv::Point>> contours;
    cv::findContours(edges, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
    std::sort(contours.begin(), contours.end(), [](const auto& a, const auto& b) {
        return cv::contourArea(a) > cv::contourArea(b);
    });

    std::vector<cv::Point> docCorners;
    for (const auto& c : contours) {
        double peri = cv::arcLength(c, true);
        std::vector<cv::Point> approx;
        cv::approxPolyDP(c, approx, 0.02 * peri, true);
        if (approx.size() == 4) {
            docCorners = approx;
            break;
        }
    }

    if (docCorners.empty()) {
        throw std::runtime_error("문서 경계를 찾지 못했습니다.");
    }

    auto ordered = orderPoints(docCorners);
    const auto& tl = ordered[0]; const auto& tr = ordered[1];
    const auto& br = ordered[2]; const auto& bl = ordered[3];

    int width = static_cast<int>(std::max(cv::norm(br - bl), cv::norm(tr - tl)));
    int height = static_cast<int>(std::max(cv::norm(tr - br), cv::norm(tl - bl)));

    std::vector<cv::Point2f> dst = {
        {0, 0}, {(float)width - 1, 0}, {(float)width - 1, (float)height - 1}, {0, (float)height - 1}
    };

    cv::Mat M = cv::getPerspectiveTransform(ordered, dst);
    cv::Mat scanned;
    cv::warpPerspective(img, scanned, M, cv::Size(width, height));
    return scanned;
}

int main() {
    cv::Mat scanned = scanDocument("document.jpg");
    cv::imshow("Scanned", scanned);
    cv::waitKey(0);
    return 0;
}
```

### C#

```csharp
using OpenCvSharp;

static Point2f[] OrderPoints(Point[] pts)
{
    var sums = pts.Select(p => (float)(p.X + p.Y)).ToArray();
    var diffs = pts.Select(p => (float)(p.X - p.Y)).ToArray();

    int tl = Array.IndexOf(sums, sums.Min());
    int br = Array.IndexOf(sums, sums.Max());
    int tr = Array.IndexOf(diffs, diffs.Max());
    int bl = Array.IndexOf(diffs, diffs.Min());

    return new[]
    {
        new Point2f(pts[tl].X, pts[tl].Y),
        new Point2f(pts[tr].X, pts[tr].Y),
        new Point2f(pts[br].X, pts[br].Y),
        new Point2f(pts[bl].X, pts[bl].Y),
    };
}

static float Dist(Point2f a, Point2f b)
{
    double dx = a.X - b.X, dy = a.Y - b.Y;
    return (float)Math.Sqrt(dx * dx + dy * dy);
}

static Mat ScanDocument(string path)
{
    Mat img = Cv2.ImRead(path);
    Mat gray = new Mat();
    Mat blurred = new Mat();
    Mat edges = new Mat();
    Cv2.CvtColor(img, gray, ColorConversionCodes.BGR2Gray);
    Cv2.GaussianBlur(gray, blurred, new Size(5, 5), 0);
    Cv2.Canny(blurred, edges, 75, 200);

    Cv2.FindContours(edges, out Point[][] contours, out HierarchyIndex[] _,
        RetrievalModes.External, ContourApproximationModes.ApproxSimple);
    var sorted = contours.OrderByDescending(c => Cv2.ContourArea(c)).ToArray();

    Point[]? docCorners = null;
    foreach (var c in sorted)
    {
        double peri = Cv2.ArcLength(c, true);
        Point[] approx = Cv2.ApproxPolyDP(c, 0.02 * peri, true);
        if (approx.Length == 4)
        {
            docCorners = approx;
            break;
        }
    }

    if (docCorners is null)
    {
        throw new InvalidOperationException("문서 경계를 찾지 못했습니다.");
    }

    Point2f[] ordered = OrderPoints(docCorners);
    Point2f tl = ordered[0], tr = ordered[1], br = ordered[2], bl = ordered[3];

    int width = (int)Math.Max(Dist(br, bl), Dist(tr, tl));
    int height = (int)Math.Max(Dist(tr, br), Dist(tl, bl));

    Point2f[] dst =
    {
        new Point2f(0, 0), new Point2f(width - 1, 0),
        new Point2f(width - 1, height - 1), new Point2f(0, height - 1),
    };

    Mat M = Cv2.GetPerspectiveTransform(ordered, dst);
    Mat scanned = new Mat();
    Cv2.WarpPerspective(img, scanned, M, new Size(width, height));
    return scanned;
}

Mat result = ScanDocument("document.jpg");
Cv2.ImShow("Scanned", result);
Cv2.WaitKey(0);
```

세 코드 모두 동일한 7단계를 그대로 밟는다. 언어별로 다른 부분은 사실상 "4개의 꼭짓점을 정렬하는 방법"과 "예외 처리 문법" 정도이며, OpenCV 함수 호출의 순서와 의미는 완전히 같다. 이는 이 책 전체에서 반복해서 확인한 사실—OpenCV의 핵심 개념은 언어에 독립적이고, 각 언어는 그 개념을 자신의 문법과 관용구로 감싸는 껍질일 뿐이라는 점—을 마지막 예제에서 다시 한번 보여준다.

## 18.2 성능 특성: 같은 결과, 다른 비용

세 언어로 똑같은 파이프라인을 짤 수 있다고 해서 세 언어의 실행 성능이 같다는 뜻은 아니다. OpenCV의 핵심 알고리즘(Canny, findContours 등) 자체는 세 언어 모두 동일한 C++ 네이티브 코드를 호출하므로 그 부분의 속도는 사실상 동일하다. 차이가 벌어지는 지점은 "OpenCV 함수 호출과 호출 사이에서, 우리가 직접 작성하는 코드"다.

### Python: 벡터화가 곧 성능이다

Python은 인터프리터 언어라서 `for` 루프로 픽셀 하나하나에 접근하면 매우 느리다. 예를 들어 이미지의 밝기를 50만큼 올리는 작업을 비교해보자.

```python
import cv2
import numpy as np
import time

img = cv2.imread("photo.jpg").astype(np.int16)

# 느린 방식: 픽셀 단위로 순회하는 순수 Python 루프
start = time.time()
slow = img.copy()
h, w, c = slow.shape
for y in range(h):
    for x in range(w):
        for ch in range(c):
            slow[y, x, ch] = min(slow[y, x, ch] + 50, 255)
print("루프 방식:", time.time() - start, "초")

# 빠른 방식: NumPy 벡터화 연산 (7장에서 다룬 클리핑과 동일한 원리)
start = time.time()
fast = np.clip(img + 50, 0, 255)
print("벡터화 방식:", time.time() - start, "초")
```

두 코드는 정확히 같은 결과를 만들지만, 벡터화된 두 번째 방식은 내부적으로 컴파일된 NumPy의 C 반복문을 사용하기 때문에 순수 Python 삼중 루프보다 수십~수백 배 빠른 경우가 흔하다. Python으로 OpenCV를 쓸 때 지켜야 할 원칙은 단순하다. **"픽셀 단위 반복문을 직접 작성해야 하는 순간이 오면, 먼저 NumPy나 OpenCV 함수로 대체할 방법이 있는지부터 찾아본다."** 7장에서 다룬 산술 연산, 9장의 필터링, 10장의 임계처리 모두 내부적으로 이런 벡터화(또는 그 이상의 최적화)가 적용된 함수들이다.

### C++: 네이티브 성능을 그대로

C++는 OpenCV 라이브러리 자체가 구현된 언어이므로, 함수 호출에 별도의 변환 계층이 끼지 않는다. 다만 C++ 안에서도 성능 차이가 나는 지점이 있다. `Mat::at<T>(y, x)`로 픽셀에 접근하는 방식은 매번 경계 검사와 타입 검사를 거치므로 안전하지만 느리고, 대량의 픽셀을 반복 처리해야 한다면 `Mat::ptr<T>(y)`로 행의 시작 포인터를 얻어 포인터 연산으로 순회하는 방식이 훨씬 빠르다. 더 나아가 `cv::parallel_for_`를 사용하면 반복 작업을 여러 스레드에 자동으로 분산시킬 수 있다. 물론 대부분의 경우 OpenCV가 이미 제공하는 함수(`GaussianBlur`, `threshold` 등)가 이런 최적화를 내부적으로 다 갖추고 있으므로, 직접 픽셀 루프를 작성하는 것은 OpenCV에 없는 연산을 새로 구현해야 할 때만 고려하면 된다.

### C#: 관리형/비관리형 경계의 비용

C#에서 OpenCvSharp를 사용할 때는 .NET의 관리형(managed) 세계와 OpenCV의 비관리형(unmanaged, 네이티브 C++) 세계 사이의 경계를 건너다니는 비용을 의식해야 한다. `Cv2.GaussianBlur`처럼 이미지 전체를 한 번에 넘기는 호출은 경계를 한 번만 건너므로 오버헤드가 미미하다. 반대로 `Mat.At<T>(y, x)`나 `Mat.Set<T>(y, x, value)`로 픽셀 하나씩 읽고 쓰는 루프를 작성하면, 픽셀 개수만큼 관리형/비관리형 경계를 반복해서 건너게 되어 상대적으로 큰 오버헤드가 쌓인다. 대량의 픽셀을 직접 다뤄야 한다면 `Mat.GetArray`/`SetArray`로 데이터를 한 번에 관리형 배열로 복사해 처리하거나, OpenCvSharp가 제공하는 배치 연산 API를 우선적으로 활용하는 것이 좋다.

### 요약: 세 언어의 성능 성향

| 언어 | 성능 특징 | 실무 팁 |
|---|---|---|
| Python | 인터프리터 오버헤드가 크지만, NumPy/OpenCV 벡터화 함수는 네이티브 속도에 근접 | 픽셀 단위 `for` 루프를 피하고 벡터화된 연산으로 재작성 |
| C++ | OpenCV 네이티브 성능을 별도 계층 없이 그대로 사용 | 대량 반복 시 `at<T>` 대신 포인터 접근, 필요하면 `parallel_for_` |
| C# | 관리형/비관리형 경계를 건널 때마다 약간의 오버헤드 발생 | 이미지 전체 단위 API 호출을 우선하고, 픽셀 단위 루프는 최소화 |

## 18.3 메모리 관리 차이

세 언어는 메모리를 해제하는 방식도 다르다.

- **Python**: 모든 객체(NumPy 배열을 감싸는 `Mat`에 대응하는 객체 포함)는 참조 카운팅과 가비지 컬렉터(GC)에 의해 자동으로 회수된다. 개발자가 명시적으로 메모리를 해제할 일은 거의 없다.
- **C++**: `cv::Mat`은 완전한 스마트 포인터는 아니지만 그와 비슷하게 동작한다. `Mat` 객체를 복사하면 실제 픽셀 데이터를 복사하는 것이 아니라 같은 데이터 버퍼를 가리키는 참조 카운트만 증가시키고, 마지막으로 그 버퍼를 참조하던 `Mat`이 소멸할 때 자동으로 메모리가 해제된다. 데이터를 실제로 복제하고 싶다면 `clone()`을 명시적으로 호출해야 한다. 대부분의 경우 이 자동 참조 카운팅만으로 충분하지만, 매우 큰 이미지를 반복적으로 다루는 루프에서 의도치 않게 참조가 계속 유지되어 메모리 사용량이 늘어나는 경우도 있으므로, 더 이상 필요 없는 `Mat`은 스코프를 벗어나게 하거나 `release()`로 명시적으로 해제해주는 습관이 도움이 된다.
- **C#**: .NET의 GC가 `Mat` 래퍼 객체 자체는 관리하지만, 그 래퍼가 감싸고 있는 실제 픽셀 버퍼는 비관리 영역(네이티브 메모리)에 존재한다. GC는 관리형 객체가 얼마나 많은 비관리 메모리를 차지하는지 정확히 알지 못하기 때문에, `Mat`을 `using`으로 감싸지 않고 계속 새로 생성만 하면 비관리 메모리가 예상보다 오래 쌓여 있다가 한꺼번에 해제되는 현상이 생길 수 있다. 그래서 OpenCvSharp의 `Mat`, `CascadeClassifier` 등 `IDisposable`을 구현한 타입은 가능하면 `using` 문으로 감싸서 스코프를 벗어나는 즉시 비관리 메모리를 해제하도록 명시하는 것이 안전하다.

이 흐름을 보면 뒤쪽 장일수록 앞쪽 장의 결과물을 입력으로 삼는 경우가 많다는 것을 알 수 있다. 임계처리(10장)는 그레이스케일(5장) 위에서, 컨투어(13장)는 엣지나 이진 이미지(10, 12장) 위에서, 문서 스캐너(18장)는 이 모든 것 위에서 동작한다. 결국 컴퓨터 비전 파이프라인을 설계하는 능력은 이 책의 개별 장을 얼마나 잘 아는가보다, 그 장들을 목적에 맞게 얼마나 잘 이어붙이는가에 더 가깝다.

세 언어 중 어떤 것을 선택할지는 "어떤 상황인가"에 따라 달라진다.

- **빠른 프로토타이핑, 연구, 데이터 분석과의 연동**: Python. NumPy·matplotlib·딥러닝 프레임워크 등 주변 생태계가 가장 풍부하고, 코드를 짜고 결과를 확인하는 순환이 가장 짧다.
- **최고 성능이 필요한 프로덕션, 임베디드/모바일 배포**: C++. 별도의 런타임 오버헤드 없이 OpenCV의 성능을 그대로 끌어낼 수 있고, 배포 환경을 세밀하게 제어할 수 있다.
- **.NET 생태계와의 통합(WPF/WinForms 데스크톱 앱, ASP.NET 백엔드 등)**: C#. OpenCvSharp를 통해 기존 .NET 프로젝트에 비전 기능을 자연스럽게 끼워 넣을 수 있다.

실무에서는 이 셋이 배타적이지 않다. 예를 들어 Python으로 알고리즘을 빠르게 검증한 뒤, 같은 로직을 C++로 옮겨 성능이 중요한 서비스에 배포하는 흐름도 흔하다. 이 책이 세 언어를 나란히 보여준 이유도, 어느 하나만 정답으로 배우기보다 상황에 맞게 언어를 골라 쓸 수 있는 유연함을 갖추길 바라기 때문이다.

## 18.5 앞으로 더 공부할 방향

이 책은 OpenCV의 전통적인 이미지 처리 기법을 중심으로 다뤘지만, 컴퓨터 비전 분야는 이보다 훨씬 넓다. 다음 방향들을 이어서 살펴보면 좋다.

- **딥러닝 기반 객체 검출/세그멘테이션**: YOLO, SSD, Mask R-CNN 계열의 모델들은 17장에서 다룬 `dnn` 모듈이나 각 프레임워크의 전용 런타임(ONNX Runtime, TensorRT 등)을 통해 실제 서비스에 적용할 수 있다. 객체의 위치뿐 아니라 픽셀 단위로 영역을 구분하는 세그멘테이션까지 다루는 모델도 많다.
- **GPU 가속**: OpenCV는 `cv::cuda` 네임스페이스와 CUDA 지원 빌드를 통해 NVIDIA GPU에서 연산을 가속할 수 있고, `UMat`을 활용한 OpenCL 기반 투명 가속(Transparent API)도 지원한다. 대량의 이미지나 고해상도 비디오를 실시간으로 처리해야 한다면 이 방향을 검토할 만하다.
- **실시간 트래킹 알고리즘**: 이 책의 16장에서는 프레임 간 배경 제거를 다뤘지만, 특정 객체를 프레임마다 계속 추적하는 것은 별도의 문제다. KCF, CSRT 같은 OpenCV 내장 트래커부터, 딥러닝 기반 검출과 결합한 DeepSORT 같은 다중 객체 추적 기법까지 다양한 선택지가 있다.

이 책에서 다진 기초—이미지가 배열이라는 감각, 각 처리 단계가 무엇을 입력받고 무엇을 내놓는지에 대한 이해, 그리고 세 언어를 오가며 API를 읽어내는 능력—는 이런 더 발전된 주제들을 공부할 때도 그대로 밑바탕이 되어줄 것이다.

## 요약

- 문서 스캐너 예제는 4장(입출력), 5장(색공간), 9장(블러), 12장(엣지), 13장(컨투어), 8장(원근 변환)의 기법을 하나의 파이프라인으로 연결한 결과이며, 세 언어의 코드는 API 이름과 문법만 다를 뿐 논리적 흐름은 동일하다.
- Python에서는 픽셀 단위 `for` 루프 대신 NumPy 벡터화 연산을 쓰는 것이 성능에 결정적이고, C++는 OpenCV의 네이티브 성능을 그대로 누리지만 `at<T>` 대신 포인터 접근이 유리한 경우가 있으며, C#은 관리형/비관리형 경계를 자주 건너는 픽셀 단위 접근에서 오버헤드가 발생하기 쉽다.
- 메모리 관리는 Python·C#이 가비지 컬렉션에 의존하는 반면, C++의 `Mat`은 참조 카운팅 기반으로 대부분 자동 해제되지만 `clone()`/`release()`로 명시적 제어가 필요한 경우가 있고, C#의 `Mat`은 비관리 메모리를 감싸고 있어 `using`으로 명시적으로 해제하는 습관이 중요하다.
- 빠른 프로토타이핑에는 Python, 최고 성능의 프로덕션 배포에는 C++, .NET 생태계 통합에는 C#이 각각 강점을 가지며, 실무에서는 이들을 상황에 맞게 조합해서 쓰는 것이 일반적이다.
- 딥러닝 기반 검출/세그멘테이션, GPU 가속, 실시간 트래킹은 이 책의 범위를 넘어서는 다음 학습 주제로 이어진다.
