## 5.1 다시 짚는 BGR 순서

1장에서 이미 언급했듯이, OpenCV는 컬러 이미지를 저장할 때 우리에게 익숙한 RGB(Red-Green-Blue) 순서가 아니라 **BGR(Blue-Green-Red)** 순서로 채널을 저장한다. 이는 OpenCV가 처음 만들어질 당시 널리 쓰이던 Windows의 비트맵(BMP) 코덱과 일부 카메라 하드웨어가 픽셀을 BGR 순서로 다뤘던 관습을 그대로 이어받은 결과다. 지금은 사실상 역사적 유산에 가깝지만, OpenCV의 모든 입출력·디스플레이 함수(`imread`, `imwrite`, `imshow`)는 여전히 이 순서를 기준으로 동작하므로, 이 책 전체에서 색상을 다룰 때는 항상 "지금 이 배열이 BGR인가, RGB인가?"를 의식적으로 확인하는 습관을 들이는 것이 좋다.

문제는 OpenCV 바깥의 세계는 대부분 RGB 순서를 기본으로 삼고 있다는 점이다. matplotlib, PIL/Pillow, 웹 브라우저의 캔버스, 대부분의 이미지 포맷 명세, 심지어 딥러닝 프레임워크의 기본 전처리 파이프라인도 RGB를 가정한다. 그래서 OpenCV로 읽어들인 이미지를 다른 라이브러리와 함께 사용하려면 채널 순서를 명시적으로 바꿔주는 변환 과정이 필요하다. 이번 장에서 다룰 `cvtColor`가 바로 그 변환을 담당하는 함수다.

이미지 처리에서 "색공간(color space)"이란 색을 수치로 표현하는 좌표계를 의미한다. BGR/RGB는 빛의 3원색을 그대로 축으로 삼는 색공간이고, 뒤에서 다룰 그레이스케일과 HSV는 각각 다른 목적을 위해 설계된 색공간이다. 같은 이미지라도 어떤 색공간으로 표현하느냐에 따라 특정 작업(밝기 계산, 색상 필터링 등)이 훨씬 쉬워지거나 어려워질 수 있다. 그래서 색공간 변환은 단순한 포맷 변환이 아니라, 뒤에 이어질 처리 단계를 쉽게 만들어주는 전처리 기법으로 이해해야 한다.

## 5.2 `cvtColor`: 색공간 변환의 관문

OpenCV에서 색공간을 변환하는 함수는 거의 예외 없이 `cvtColor` 하나로 통일되어 있다. 이 함수는 입력 이미지와 "변환 코드(conversion code)"를 받아서, 그 코드가 지정하는 규칙에 따라 픽셀 값을 다른 색공간으로 다시 계산해준다. 변환 코드는 각 언어에서 다음과 같이 표현된다.

| 언어 | 함수 | 변환 코드 예시 |
|---|---|---|
| Python | `cv2.cvtColor(img, code)` | `cv2.COLOR_BGR2GRAY` |
| C++ | `cv::cvtColor(img, dst, code)` | `cv::COLOR_BGR2GRAY` |
| C# | `Cv2.CvtColor(src, dst, code)` | `ColorConversionCodes.BGR2Gray` |

이름 규칙은 세 언어 모두 "원본색공간2목표색공간" 형태를 따른다. `BGR2GRAY`는 BGR에서 그레이스케일로, `BGR2HSV`는 BGR에서 HSV로, `BGR2RGB`는 BGR에서 RGB로 바꾼다는 뜻이다. Python과 C++는 이 이름을 그대로 대문자 상수로 쓰지만, C#의 OpenCvSharp는 열거형 `ColorConversionCodes`를 통해 PascalCase(`BGR2Gray`, `BGR2HSV`, `BGR2RGB`)로 노출한다는 점만 다르다. 실제로 어떤 이름이 존재하는지 헷갈릴 때는 각 언어의 자동완성(IntelliSense)이나 공식 열거형 목록을 살펴보면 된다.

## 5.3 BGR → 그레이스케일

가장 흔하게 쓰이는 변환은 컬러 이미지를 흑백(그레이스케일)으로 바꾸는 것이다. 그레이스케일 변환은 3개 채널(B, G, R)의 정보를 밝기 하나로 압축하는 과정이며, 뒤에서 다룰 엣지 검출·임계처리·특징점 검출 같은 알고리즘 대부분은 연산량을 줄이고 색상 정보에 흔들리지 않기 위해 그레이스케일 이미지를 입력으로 받는다.

OpenCV는 단순히 세 채널의 평균을 내는 것이 아니라, 사람의 눈이 초록색에 더 민감하다는 점을 반영한 가중합(대략 R에 0.299, G에 0.587, B에 0.114의 비중)으로 밝기를 계산한다. 이 가중치를 외울 필요는 없지만, "단순 평균이 아니다"라는 사실은 기억해 둘 만하다.

### Python

```python
import cv2

img = cv2.imread("photo.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

print(img.shape)   # (H, W, 3)
print(gray.shape)  # (H, W)  -- 채널 축이 사라진다

cv2.imshow("Gray", gray)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>

int main() {
    cv::Mat img = cv::imread("photo.jpg");
    cv::Mat gray;
    cv::cvtColor(img, gray, cv::COLOR_BGR2GRAY);

    // img.channels() == 3, gray.channels() == 1
    cv::imshow("Gray", gray);
    cv::waitKey(0);
    return 0;
}
```

### C#

```csharp
using OpenCvSharp;

Mat img = Cv2.ImRead("photo.jpg");
Mat gray = new Mat();
Cv2.CvtColor(img, gray, ColorConversionCodes.BGR2Gray);

// img.Channels() == 3, gray.Channels() == 1
Cv2.ImShow("Gray", gray);
Cv2.WaitKey(0);
```

세 코드 모두 결과는 동일하다. 변환 후의 배열은 채널이 하나뿐인 2차원(또는 1채널) 이미지가 되며, 이는 3장에서 다룬 `Mat`/NumPy 배열의 구조와 정확히 대응된다.

### `imshow`는 그레이스케일을 어떻게 표시하는가

세 언어 모두에서 `imshow`(`cv2.imshow`, `cv::imshow`, `Cv2.ImShow`)는 입력 배열의 채널 수를 보고 표시 방식을 스스로 결정한다. 3채널 이미지는 BGR 컬러로 해석해서 보여주고, 1채널 이미지는 자동으로 회색조 팔레트를 적용해 흑백으로 보여준다. 즉 `cvtColor`로 그레이스케일로 바꾼 이미지는 메모리 상에서도, 화면에 그릴 때도 계속 1채널로 유지되며, `imshow`가 이것을 3채널처럼 억지로 부풀리는 과정은 없다. 다만 이후 장에서 그레이스케일 이미지에 색깔 있는 도형이나 마스크를 겹쳐 그리고 싶을 때는, `COLOR_GRAY2BGR` 코드로 다시 3채널로 되돌려주는 변환이 필요하다는 점을 기억해 두면 좋다.

## 5.4 BGR → RGB: 다른 라이브러리와 연동하기

OpenCV 바깥의 파이썬 생태계, 특히 matplotlib은 이미지를 RGB 순서로 가정하고 그린다. `cv2.imread`로 읽은 배열을 그대로 `plt.imshow`에 넘기면 파랑과 빨강이 뒤바뀐 이상한 색으로 보이는데, 이는 OpenCV나 matplotlib 어느 쪽의 버그가 아니라 두 라이브러리가 서로 다른 채널 순서를 기본값으로 삼고 있기 때문이다. 이 문제는 `COLOR_BGR2RGB` 변환으로 간단히 해결된다.

### Python

```python
import cv2
import matplotlib.pyplot as plt

img_bgr = cv2.imread("photo.jpg")
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)

plt.imshow(img_rgb)
plt.axis("off")
plt.show()
```

### C++

```cpp
#include <opencv2/opencv.hpp>

int main() {
    cv::Mat img_bgr = cv::imread("photo.jpg");
    cv::Mat img_rgb;
    cv::cvtColor(img_bgr, img_rgb, cv::COLOR_BGR2RGB);

    // 다른 그래픽 라이브러리(RGB 기반)로 넘기기 전에 순서를 맞춰준다.
    cv::imwrite("photo_rgb_order.png", img_rgb);
    return 0;
}
```

### C#

```csharp
using OpenCvSharp;

Mat imgBgr = Cv2.ImRead("photo.jpg");
Mat imgRgb = new Mat();
Cv2.CvtColor(imgBgr, imgRgb, ColorConversionCodes.BGR2RGB);

// 예: WPF의 BitmapSource 등 RGB 순서를 기대하는 API에 넘길 때 사용한다.
imgRgb.SaveImage("photo_rgb_order.png");
```

C++와 C#에서는 화면 표시에 여전히 OpenCV의 `imshow`를 쓴다면 BGR 그대로 두는 것이 맞다. `BGR2RGB` 변환은 OpenCV 바깥의, RGB를 기대하는 API(matplotlib, 웹 캔버스, 일부 GUI 프레임워크의 비트맵 클래스 등)로 이미지를 넘겨줄 때만 필요하다는 점을 기억하자. 실제로 `imwrite`로 파일에 저장할 때는 OpenCV가 내부적으로 다시 BGR을 표준 이미지 포맷의 채널 순서로 올바르게 바꿔주므로, 파일 저장 자체를 위해서는 `BGR2RGB` 변환이 필요 없다는 점도 함께 알아두면 좋다.

## 5.5 BGR → HSV: 색상을 다루기 편한 좌표계

### HSV란 무엇인가

HSV는 색을 세 가지 축으로 표현하는 색공간이다.

- **H(Hue, 색상)**: 빨강, 초록, 파랑 등 "어떤 색인지"를 나타내며 0~360도의 원형 값으로 표현된다(OpenCV는 8비트 이미지에서 이를 0~179 범위로 절반 축소해서 저장한다).
- **S(Saturation, 채도)**: 색이 얼마나 선명한지, 즉 회색이 얼마나 섞여 있는지를 나타낸다.
- **V(Value, 명도)**: 색이 얼마나 밝은지를 나타낸다.

BGR/RGB는 "빛을 얼마나 섞어야 이 색이 나오는가"를 표현하는 데는 유용하지만, "이 픽셀이 빨간색 계열인가?"라는 질문에 답하기에는 불편하다. 빨간 사과를 예로 들면, 밝은 곳에 있는 빨간 사과와 그늘진 곳에 있는 빨간 사과는 R, G, B 값이 모두 크게 다르다. 조명이 강해지면 세 채널의 값이 대체로 함께 커지고, 그림자가 지면 세 채널이 함께 작아지기 때문이다.

### Hue가 조명 변화에 덜 민감한 이유

반면 HSV로 표현하면 이야기가 달라진다. 조명의 세기가 달라져도 "빨간 사과"라는 색상 자체(Hue)는 거의 변하지 않고, 대신 명도(V)와 채도(S)만 변한다. 즉 조명 변화는 주로 V(그리고 어느 정도는 S) 축을 따라 픽셀을 이동시킬 뿐, H 축 위의 위치는 비교적 안정적으로 유지한다. 그래서 "빨간색만 찾아내고 싶다"처럼 색상 자체를 기준으로 픽셀을 분류하는 작업에서는, R·G·B 세 채널을 모두 조건에 넣어야 하는 BGR 공간보다 H 채널 하나(필요하면 S를 더해서)만 조건에 넣으면 되는 HSV 공간이 훨씬 다루기 쉽고 조명 변화에도 강건하다.

이 특성 때문에 색상 기반 객체 추적, 특정 색 표지판 검출, 피부색 검출 등 "색으로 무언가를 골라내는" 대부분의 고전적인 컴퓨터 비전 기법은 BGR이 아니라 HSV(또는 이와 유사한 성질을 가진 다른 색공간)에서 이루어진다.

## 5.6 실전 예제: `inRange`로 특정 색상만 마스킹하기

이제 배운 내용을 실제로 활용해서, 이미지에서 빨간색 영역만 골라내는 마스크를 만들어보자. 핵심은 다음 세 단계다.

1. BGR 이미지를 HSV로 변환한다.
2. 원하는 색상의 H(그리고 S, V) 범위를 정해서 `inRange`로 마스크를 만든다.
3. 마스크를 원본 이미지에 `bitwise_and`(비트 AND) 방식으로 적용해, 마스크가 켜진(255) 픽셀만 남긴다.

빨간색은 Hue의 양쪽 끝(0 근처와 180 근처)에 걸쳐 있으므로, 아래 예제에서는 두 개의 범위를 각각 마스킹한 뒤 합쳐주는 방식을 사용한다.

### Python

```python
import cv2
import numpy as np

img = cv2.imread("fruits.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

# 빨간색은 Hue의 양쪽 끝에 걸쳐 있으므로 두 범위를 각각 마스킹한다.
lower_red1 = np.array([0, 100, 100])
upper_red1 = np.array([10, 255, 255])
lower_red2 = np.array([160, 100, 100])
upper_red2 = np.array([179, 255, 255])

mask1 = cv2.inRange(hsv, lower_red1, upper_red1)
mask2 = cv2.inRange(hsv, lower_red2, upper_red2)
mask = cv2.bitwise_or(mask1, mask2)

result = cv2.bitwise_and(img, img, mask=mask)

cv2.imshow("Original", img)
cv2.imshow("Mask", mask)
cv2.imshow("Red Only", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>

int main() {
    cv::Mat img = cv::imread("fruits.jpg");
    cv::Mat hsv;
    cv::cvtColor(img, hsv, cv::COLOR_BGR2HSV);

    cv::Mat mask1, mask2, mask, result;
    cv::inRange(hsv, cv::Scalar(0, 100, 100), cv::Scalar(10, 255, 255), mask1);
    cv::inRange(hsv, cv::Scalar(160, 100, 100), cv::Scalar(179, 255, 255), mask2);
    cv::bitwise_or(mask1, mask2, mask);

    cv::bitwise_and(img, img, result, mask);

    cv::imshow("Original", img);
    cv::imshow("Mask", mask);
    cv::imshow("Red Only", result);
    cv::waitKey(0);
    return 0;
}
```

### C#

```csharp
using OpenCvSharp;

Mat img = Cv2.ImRead("fruits.jpg");
Mat hsv = new Mat();
Cv2.CvtColor(img, hsv, ColorConversionCodes.BGR2HSV);

Mat mask1 = new Mat();
Mat mask2 = new Mat();
Mat mask = new Mat();
Cv2.InRange(hsv, new Scalar(0, 100, 100), new Scalar(10, 255, 255), mask1);
Cv2.InRange(hsv, new Scalar(160, 100, 100), new Scalar(179, 255, 255), mask2);
Cv2.BitwiseOr(mask1, mask2, mask);

Mat result = new Mat();
Cv2.BitwiseAnd(img, img, result, mask);

Cv2.ImShow("Original", img);
Cv2.ImShow("Mask", mask);
Cv2.ImShow("Red Only", result);
Cv2.WaitKey(0);
```

`inRange`는 H, S, V 각각이 지정한 하한과 상한 사이에 있는 픽셀을 255(흰색), 그렇지 않은 픽셀을 0(검은색)으로 채운 1채널 마스크를 만들어준다. 채도(S)와 명도(V)의 하한을 100 정도로 설정한 것은, 채도나 명도가 너무 낮은(거의 무채색이거나 너무 어두운) 픽셀은 색상 판단 자체가 불안정하기 때문에 걸러내기 위함이다. 이 마스크를 원본 이미지와 `bitwise_and`로 결합하면, 마스크가 흰색인 위치의 원본 픽셀만 남고 나머지는 검은색이 되는 결과를 얻는다.

여기서 만든 마스크는 12장의 컨투어 검출과 결합하면 "빨간 물체의 위치와 크기"를 찾아내는 파이프라인으로 자연스럽게 확장할 수 있으며, 17장에서 다룰 객체 검출의 전 단계로도 자주 쓰이는 패턴이다.

## 요약

- OpenCV는 컬러 이미지를 BGR 순서로 다루며, RGB를 기대하는 외부 라이브러리(matplotlib 등)와 연동할 때는 `COLOR_BGR2RGB`로 순서를 바꿔줘야 한다.
- `cvtColor`(Python: `cv2.cvtColor`, C++: `cv::cvtColor`, C#: `Cv2.CvtColor`)는 색공간 변환을 담당하는 공통 함수이며, 변환 코드는 "원본2목표" 이름 규칙을 따른다.
- `COLOR_BGR2GRAY`로 그레이스케일 변환을 하면 채널이 1개로 줄어들며, `imshow`는 채널 수에 따라 컬러 또는 흑백으로 자동 표시한다.
- HSV 색공간은 색상(H), 채도(S), 명도(V)를 분리해서 표현하며, 조명 변화가 주로 V(와 어느 정도의 S)에만 영향을 주기 때문에 H를 기준으로 하면 색상 기반 필터링이 BGR보다 훨씬 안정적이다.
- `inRange`로 HSV 범위를 지정해 마스크를 만들고, `bitwise_and`로 원본에 적용하면 특정 색상 영역만 추출할 수 있다. 빨간색처럼 Hue의 양 끝에 걸친 색은 두 범위를 `bitwise_or`로 합쳐야 한다.

## 연습문제

1. `COLOR_BGR2GRAY` 변환 시 OpenCV가 단순 평균이 아니라 가중합을 사용하는 이유를 사람의 시각 특성과 연관지어 설명해 보라.
2. 파란색 계열 물체만 추출하는 마스킹 프로그램을 세 언어 중 하나로 작성하고, `lower_blue`와 `upper_blue`의 HSV 범위를 실험적으로 조정해 보라.
3. 같은 사진을 조명이 밝은 곳과 어두운 곳에서 각각 촬영했다고 가정할 때, BGR 값과 HSV의 H 값이 각각 어떻게 달라질지 예상해 보고, 왜 H가 더 안정적인지 자신의 말로 설명해 보라.
4. 그레이스케일로 변환한 이미지에 빨간색 사각형을 그리고 싶다면 어떤 변환이 먼저 필요한지 조사하고, `COLOR_GRAY2BGR`을 사용해 실제로 구현해 보라.
5. `inRange`로 만든 마스크에 남아있는 작은 잡티(노이즈)를 없애려면 어떤 후속 처리가 필요할지 11장(모폴로지 연산)의 내용을 미리 찾아보고 예상해 보라.
