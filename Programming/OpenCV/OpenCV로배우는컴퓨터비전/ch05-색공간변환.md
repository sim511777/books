## 5.1 다시 짚는 BGR 순서

1장에서 이미 언급했듯이, OpenCV는 컬러 이미지를 저장할 때 우리에게 익숙한 RGB(Red-Green-Blue) 순서가 아니라 **BGR(Blue-Green-Red)** 순서로 채널을 저장한다. 이는 OpenCV가 처음 만들어질 당시 널리 쓰이던 Windows의 비트맵(BMP) 코덱과 일부 카메라 하드웨어가 픽셀을 BGR 순서로 다뤘던 관습을 그대로 이어받은 결과다. 지금은 사실상 역사적 유산에 가깝지만, OpenCV의 모든 입출력·디스플레이 함수(`imread`, `imwrite`, `imshow`)는 여전히 이 순서를 기준으로 동작하므로, 이 책 전체에서 색상을 다룰 때는 항상 "지금 이 배열이 BGR인가, RGB인가?"를 의식적으로 확인하는 습관을 들이는 것이 좋다.

문제는 OpenCV 바깥의 세계는 대부분 RGB 순서를 기본으로 삼고 있다는 점이다. matplotlib, PIL/Pillow, 웹 브라우저의 캔버스, 대부분의 이미지 포맷 명세, 심지어 딥러닝 프레임워크의 기본 전처리 파이프라인도 RGB를 가정한다. 그래서 OpenCV로 읽어들인 이미지를 다른 라이브러리와 함께 사용하려면 채널 순서를 명시적으로 바꿔주는 변환 과정이 필요하다. 이번 장에서 다룰 `cv2.cvtColor`가 바로 그 변환을 담당하는 함수다.

이미지 처리에서 "색공간(color space)"이란 색을 수치로 표현하는 좌표계를 의미한다. BGR/RGB는 빛의 3원색을 그대로 축으로 삼는 색공간이고, 뒤에서 다룰 그레이스케일·HSV·LAB·YCrCb는 각각 다른 목적을 위해 설계된 색공간이다. 같은 이미지라도 어떤 색공간으로 표현하느냐에 따라 특정 작업(밝기 계산, 색상 필터링, 색 보정, 피부색 검출 등)이 훨씬 쉬워지거나 어려워질 수 있다. 그래서 색공간 변환은 단순한 포맷 변환이 아니라, 뒤에 이어질 처리 단계를 쉽게 만들어주는 전처리 기법으로 이해해야 한다.

이번 장에서는 먼저 가장 기본적인 그레이스케일·RGB·HSV 변환을 다시 짚고, 이어서 실무에서 자주 마주치는 두 가지 색공간인 LAB과 YCrCb를 소개한다. 그 다음에는 색상 범위를 실제로 어떻게 "찾아내는지"를 보여주는 트랙바 기반 튜닝 도구를 만들고, 마지막으로 여러 색상을 동시에 마스킹하는 예제와 웹캠에서 색상 기반으로 물체를 추적하는 실전 예제로 마무리한다.

## 5.2 `cv2.cvtColor`: 색공간 변환의 관문

OpenCV에서 색공간을 변환하는 함수는 거의 예외 없이 `cv2.cvtColor` 하나로 통일되어 있다.

```python
dst = cv2.cvtColor(src, code)
```

이 함수는 입력 이미지 `src`와 "변환 코드(conversion code)"를 받아서, 그 코드가 지정하는 규칙에 따라 픽셀 값을 다른 색공간으로 다시 계산해준다. 변환 코드의 이름 규칙은 항상 "원본색공간2목표색공간" 형태를 따른다. `cv2.COLOR_BGR2GRAY`는 BGR에서 그레이스케일로, `cv2.COLOR_BGR2HSV`는 BGR에서 HSV로, `cv2.COLOR_BGR2LAB`은 BGR에서 LAB으로 바꾼다는 뜻이다.

opencv-python에는 이런 변환 코드가 수백 개 정의되어 있는데, 전부 외울 필요는 없다. 실제로 어떤 이름이 존재하는지 헷갈릴 때는 파이썬 인터프리터에서 다음처럼 직접 검색해보는 것이 가장 빠르다.

```python
import cv2

# "BGR2"로 시작하는 변환 코드를 전부 나열해보기
codes = [name for name in dir(cv2) if name.startswith("COLOR_BGR2")]
for name in sorted(codes):
    print(name)
```

이 스니펫을 실행하면 `COLOR_BGR2GRAY`, `COLOR_BGR2HSV`, `COLOR_BGR2LAB`, `COLOR_BGR2YCrCb`, `COLOR_BGR2RGB` 등 실제로 존재하는 코드 목록을 즉시 확인할 수 있다. 문서를 뒤지는 대신 코드 자체를 살펴보는 습관은 opencv-python처럼 방대한 API를 가진 라이브러리를 다룰 때 특히 유용하다.

## 5.3 BGR → 그레이스케일

가장 흔하게 쓰이는 변환은 컬러 이미지를 흑백(그레이스케일)으로 바꾸는 것이다. 그레이스케일 변환은 3개 채널(B, G, R)의 정보를 밝기 하나로 압축하는 과정이며, 뒤에서 다룰 엣지 검출·임계처리·특징점 검출 같은 알고리즘 대부분은 연산량을 줄이고 색상 정보에 흔들리지 않기 위해 그레이스케일 이미지를 입력으로 받는다.

OpenCV는 단순히 세 채널의 평균을 내는 것이 아니라, 사람의 눈이 초록색에 더 민감하다는 점을 반영한 가중합(대략 R에 0.299, G에 0.587, B에 0.114의 비중)으로 밝기를 계산한다.

```
Gray = 0.299 * R + 0.587 * G + 0.114 * B
```

이 가중치를 외울 필요는 없지만, "단순 평균이 아니다"라는 사실은 기억해 둘 만하다.

```python
import cv2

img = cv2.imread("photo.jpg")
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)

print(img.shape)   # (H, W, 3)
print(gray.shape)  # (H, W)  -- 채널 축이 사라진다

cv2.imshow("Gray", gray)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

변환 후의 배열은 채널이 하나뿐인 2차원 NumPy 배열이 되며, 이는 3장에서 다룬 NumPy 배열의 구조와 정확히 대응된다.

### `imshow`는 그레이스케일을 어떻게 표시하는가

`cv2.imshow`는 입력 배열의 채널 수를 보고 표시 방식을 스스로 결정한다. 3채널 이미지는 BGR 컬러로 해석해서 보여주고, 1채널(또는 2차원) 이미지는 자동으로 회색조 팔레트를 적용해 흑백으로 보여준다. 즉 `cvtColor`로 그레이스케일로 바꾼 이미지는 메모리 상에서도, 화면에 그릴 때도 계속 2차원 배열로 유지되며, `imshow`가 이것을 3채널처럼 억지로 부풀리는 과정은 없다. 다만 이후 장에서 그레이스케일 이미지에 색깔 있는 도형이나 마스크를 겹쳐 그리고 싶을 때는, `cv2.COLOR_GRAY2BGR` 코드로 다시 3채널로 되돌려주는 변환이 필요하다는 점을 기억해 두면 좋다.

```python
gray_bgr = cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)
print(gray_bgr.shape)  # (H, W, 3) -- 세 채널 값이 모두 같은 흑백 컬러 이미지
```

## 5.4 BGR → RGB: 다른 라이브러리와 연동하기

OpenCV 바깥의 파이썬 생태계, 특히 matplotlib은 이미지를 RGB 순서로 가정하고 그린다. `cv2.imread`로 읽은 배열을 그대로 `plt.imshow`에 넘기면 파랑과 빨강이 뒤바뀐 이상한 색으로 보이는데, 이는 OpenCV나 matplotlib 어느 쪽의 버그가 아니라 두 라이브러리가 서로 다른 채널 순서를 기본값으로 삼고 있기 때문이다. 이 문제는 `cv2.COLOR_BGR2RGB` 변환으로 간단히 해결된다.

```python
import cv2
import matplotlib.pyplot as plt

img_bgr = cv2.imread("photo.jpg")
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)

plt.imshow(img_rgb)
plt.axis("off")
plt.show()
```

화면 표시에 `cv2.imshow`를 계속 쓴다면 BGR 그대로 두는 것이 맞다. `BGR2RGB` 변환은 OpenCV 바깥의, RGB를 기대하는 API(matplotlib, 웹 캔버스, 딥러닝 모델의 전처리 파이프라인 등)로 이미지를 넘겨줄 때만 필요하다는 점을 기억하자. 실제로 `cv2.imwrite`로 파일에 저장할 때는 OpenCV가 내부적으로 다시 BGR을 표준 이미지 포맷의 채널 순서로 올바르게 바꿔주므로, 파일 저장 자체를 위해서는 `BGR2RGB` 변환이 필요 없다는 점도 함께 알아두면 좋다.

한 가지 자주 쓰이는 트릭도 함께 소개한다. NumPy 배열의 슬라이싱만으로도 채널 순서를 뒤집을 수 있다.

```python
img_rgb_slice = img_bgr[:, :, ::-1]  # 채널 축을 역순으로 슬라이싱
```

`cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`와 `img[:, :, ::-1]`은 결과적으로 동일한 배열을 만들어내지만, `cvtColor`는 새 메모리를 할당해 명시적으로 복사본을 만드는 반면 슬라이싱은 "뷰(view)"를 만든다는 차이가 있다. 슬라이싱으로 얻은 뷰는 원본과 메모리를 공유하므로, 이후 이 배열에 OpenCV 함수로 그림을 그리거나 값을 수정하려 하면 "배열이 연속적이지 않다"는 오류가 날 수 있다. 그럴 때는 `np.ascontiguousarray(img_rgb_slice)`로 명시적으로 연속된 메모리 복사본을 만들어주면 된다.

## 5.5 BGR → HSV: 색상을 다루기 편한 좌표계

### HSV란 무엇인가

HSV는 색을 세 가지 축으로 표현하는 색공간이다.

- **H(Hue, 색상)**: 빨강, 초록, 파랑 등 "어떤 색인지"를 나타내며 0~360도의 원형 값으로 표현된다(OpenCV는 8비트 이미지에서 이를 0~179 범위로 절반 축소해서 저장한다).
- **S(Saturation, 채도)**: 색이 얼마나 선명한지, 즉 회색이 얼마나 섞여 있는지를 나타낸다. 0에 가까울수록 무채색(회색)에 가깝다.
- **V(Value, 명도)**: 색이 얼마나 밝은지를 나타낸다. 0이면 완전한 검정이다.

BGR/RGB는 "빛을 얼마나 섞어야 이 색이 나오는가"를 표현하는 데는 유용하지만, "이 픽셀이 빨간색 계열인가?"라는 질문에 답하기에는 불편하다. 빨간 사과를 예로 들면, 밝은 곳에 있는 빨간 사과와 그늘진 곳에 있는 빨간 사과는 R, G, B 값이 모두 크게 다르다. 조명이 강해지면 세 채널의 값이 대체로 함께 커지고, 그림자가 지면 세 채널이 함께 작아지기 때문이다.

### Hue가 조명 변화에 덜 민감한 이유

반면 HSV로 표현하면 이야기가 달라진다. 조명의 세기가 달라져도 "빨간 사과"라는 색상 자체(Hue)는 거의 변하지 않고, 대신 명도(V)와 채도(S)만 변한다. 즉 조명 변화는 주로 V(그리고 어느 정도는 S) 축을 따라 픽셀을 이동시킬 뿐, H 축 위의 위치는 비교적 안정적으로 유지한다. 그래서 "빨간색만 찾아내고 싶다"처럼 색상 자체를 기준으로 픽셀을 분류하는 작업에서는, R·G·B 세 채널을 모두 조건에 넣어야 하는 BGR 공간보다 H 채널 하나(필요하면 S를 더해서)만 조건에 넣으면 되는 HSV 공간이 훨씬 다루기 쉽고 조명 변화에도 강건하다.

이 특성 때문에 색상 기반 객체 추적, 특정 색 표지판 검출, 피부색 검출 등 "색으로 무언가를 골라내는" 대부분의 고전적인 컴퓨터 비전 기법은 BGR이 아니라 HSV(또는 이와 유사한 성질을 가진 다른 색공간)에서 이루어진다.

```python
import cv2

img = cv2.imread("fruits.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

h, s, v = cv2.split(hsv)
print(h.min(), h.max())  # 0 ~ 179 범위
print(s.min(), s.max())  # 0 ~ 255 범위
print(v.min(), v.max())  # 0 ~ 255 범위
```

`cv2.split`은 다채널 배열을 채널별 2차원 배열의 튜플로 분리해준다. 반대로 채널을 다시 합치고 싶을 때는 `cv2.merge((h, s, v))`를 사용한다.

## 5.6 실전 예제: `inRange`로 특정 색상만 마스킹하기

이제 배운 내용을 실제로 활용해서, 이미지에서 빨간색 영역만 골라내는 마스크를 만들어보자. 핵심은 다음 세 단계다.

1. BGR 이미지를 HSV로 변환한다.
2. 원하는 색상의 H(그리고 S, V) 범위를 정해서 `cv2.inRange`로 마스크를 만든다.
3. 마스크를 원본 이미지에 `cv2.bitwise_and`(비트 AND) 방식으로 적용해, 마스크가 켜진(255) 픽셀만 남긴다.

빨간색은 Hue의 양쪽 끝(0 근처와 180 근처)에 걸쳐 있으므로, 아래 예제에서는 두 개의 범위를 각각 마스킹한 뒤 합쳐주는 방식을 사용한다.

```python
import cv2
import numpy as np

img = cv2.imread("fruits.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

# 빨간색은 Hue의 양쪽 끝에 걸쳐 있으므로 두 범위를 각각 마스킹한다.
lower_red1 = np.array([0, 100, 100])
upper_red1 = np.array([10, 255, 255])
lower_red2 = np.array([160, 100, 100])
upper_red2 = np.array([179, 255, 255])

mask1 = cv2.inRange(hsv, lower_red1, upper_red1)
mask2 = cv2.inRange(hsv, lower_red2, upper_red2)
mask = cv2.bitwise_or(mask1, mask2)

result = cv2.bitwise_and(img, img, mask=mask)

cv2.imshow("Original", img)
cv2.imshow("Mask", mask)
cv2.imshow("Red Only", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

`inRange`는 H, S, V 각각이 지정한 하한과 상한 사이에 있는 픽셀을 255(흰색), 그렇지 않은 픽셀을 0(검은색)으로 채운 1채널 마스크를 만들어준다. 채도(S)와 명도(V)의 하한을 100 정도로 설정한 것은, 채도나 명도가 너무 낮은(거의 무채색이거나 너무 어두운) 픽셀은 색상 판단 자체가 불안정하기 때문에 걸러내기 위함이다. 이 마스크를 원본 이미지와 `bitwise_and`로 결합하면, 마스크가 흰색인 위치의 원본 픽셀만 남고 나머지는 검은색이 되는 결과를 얻는다.

여기서 만든 마스크는 12장의 컨투어 검출과 결합하면 "빨간 물체의 위치와 크기"를 찾아내는 파이프라인으로 자연스럽게 확장할 수 있으며, 17장에서 다룰 객체 검출의 전 단계로도 자주 쓰이는 패턴이다. 이번 장 후반부에서도 이 원리를 그대로 활용해 객체 추적 예제를 만들어본다.

## 5.7 LAB 색공간: 인간의 색 지각에 가까운 표현

### LAB이란 무엇인가

LAB(정확히는 CIE L\*a\*b\*)은 사람의 색 지각 방식을 수치적으로 모델링하기 위해 설계된 색공간이다. 세 축의 의미는 다음과 같다.

- **L(Lightness, 명도)**: 0(검정)부터 100(흰색)까지의 밝기. OpenCV는 8비트 이미지를 다룰 때 이를 0~255 범위로 스케일링해서 저장한다.
- **a**: 초록(-) ↔ 빨강/마젠타(+) 축.
- **b**: 파랑(-) ↔ 노랑(+) 축.

LAB의 가장 중요한 특징은 **밝기 정보(L)와 색상 정보(a, b)가 완전히 분리되어 있다**는 점이다. HSV도 명도(V)를 분리하긴 하지만, HSV의 H는 원형(circular) 값이라 산술 연산(더하기, 빼기, 평균 내기)을 하면 0도와 359도가 서로 가깝다는 사실이 깨지는 등 다루기 까다로운 면이 있다. 반면 LAB의 a, b는 일반적인 직교 좌표이므로 "두 색이 얼마나 다른가"를 유클리드 거리로 비교하는 계산이 사람의 실제 색 인지 차이와 비교적 잘 맞아떨어진다. 이런 특성 때문에 LAB은 다음과 같은 상황에서 특히 유용하다.

- **색 보정(color correction)**: 사진의 밝기(노출)만 바꾸고 색감은 그대로 유지하고 싶을 때, L 채널만 조정하면 a, b는 건드리지 않아도 된다.
- **화이트 밸런스 및 조명 보정**: 조명 색온도가 달라 사진 전체에 색이 번진 경우, a·b 채널에서 편향을 계산해 보정하는 알고리즘(예: Gray World 알고리즘)이 LAB에서 더 직관적으로 동작한다.
- **CLAHE 같은 대비 향상 기법**(8장에서 다룰 예정)을 컬러 사진에 적용할 때, RGB 각 채널에 개별로 적용하면 색이 왜곡되지만 LAB의 L 채널에만 적용하면 색감은 유지한 채 대비만 개선할 수 있다.
- **색차(color difference) 계산**: 두 색이 사람 눈에 얼마나 다르게 보이는지를 정량화해야 하는 품질 검사, 인쇄 색 보정 등에서 LAB 기반 거리 계산이 표준적으로 쓰인다.

```python
import cv2

img = cv2.imread("photo.jpg")
lab = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)

l_channel, a_channel, b_channel = cv2.split(lab)

cv2.imshow("L (lightness)", l_channel)
cv2.imshow("a (green-red)", a_channel)
cv2.imshow("b (blue-yellow)", b_channel)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

### 실전 예제: L 채널만 밝게 보정하기

색감을 유지한 채 사진 전체를 밝게 만드는 간단한 예제를 살펴보자. `cv2.add`로 L 채널에만 값을 더하고, a·b는 그대로 둔 뒤 다시 BGR로 합친다.

```python
import cv2
import numpy as np

img = cv2.imread("dark_photo.jpg")
lab = cv2.cvtColor(img, cv2.COLOR_BGR2LAB)
l, a, b = cv2.split(lab)

# L 채널에만 밝기를 더한다. cv2.add는 255를 넘지 않도록 자동으로 saturate 처리한다.
l_bright = cv2.add(l, 40)

lab_bright = cv2.merge((l_bright, a, b))
result = cv2.cvtColor(lab_bright, cv2.COLOR_LAB2BGR)

cv2.imshow("Original", img)
cv2.imshow("Brightened (LAB)", result)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

만약 같은 작업을 BGR에서 각 채널에 그냥 40을 더하는 방식으로 했다면, 채널마다 원래 값의 분포가 달라 색감이 미묘하게 틀어질 위험이 있다. LAB에서는 밝기 축(L)만 건드리므로 "색은 그대로, 밝기만 변화"라는 의도가 훨씬 정확하게 구현된다.

## 5.8 YCrCb 색공간: 피부색 검출과 비디오 압축

### YCrCb란 무엇인가

YCrCb(또는 YCbCr)는 방송·비디오 압축 분야에서 오랫동안 표준으로 쓰인 색공간이다.

- **Y(Luma, 휘도)**: 밝기 정보. 그레이스케일과 비슷한 역할을 한다.
- **Cr(Chroma Red)**: 빨강 계열의 색차 성분.
- **Cb(Chroma Blue)**: 파랑 계열의 색차 성분.

YCrCb가 만들어진 배경 자체가 "밝기(Y)와 색차(Cr, Cb)를 분리해서, 사람 눈이 색차 변화에는 상대적으로 덜 민감하다는 점을 이용해 색 정보를 압축하기 쉽게 만들자"는 것이었다. JPEG나 MPEG 등 대부분의 이미지·비디오 압축 표준이 내부적으로 YCrCb 계열 색공간을 사용하는 이유도 여기에 있다.

컴퓨터 비전에서 YCrCb가 특히 자주 언급되는 응용은 **피부색(skin color) 검출**이다. 사람의 피부색은 인종이나 조명에 따라 밝기(Y)는 크게 달라지지만, Cr·Cb로 표현되는 색차 성분은 비교적 좁은 범위에 몰려 있는 경향이 있다는 것이 여러 연구를 통해 알려져 있다. 그래서 얼굴 검출의 전처리, 손 동작 인식, 특정 인물의 노출 영역 검출 같은 작업에서 "우선 YCrCb의 Cr·Cb 범위로 피부색 후보 영역을 거칠게 골라내고, 이후 더 정교한 모델(얼굴 검출기 등)로 확인한다"는 2단계 전략이 흔히 쓰인다.

```python
import cv2
import numpy as np

img = cv2.imread("portrait.jpg")
ycrcb = cv2.cvtColor(img, cv2.COLOR_BGR2YCrCb)

# 일반적으로 알려진 피부색의 Cr, Cb 대략적인 범위 (경험적인 값이며 조명·인종에 따라 조정이 필요하다)
lower_skin = np.array([0, 133, 77])
upper_skin = np.array([255, 173, 127])

mask = cv2.inRange(ycrcb, lower_skin, upper_skin)
skin = cv2.bitwise_and(img, img, mask=mask)

cv2.imshow("Original", img)
cv2.imshow("Skin Mask", mask)
cv2.imshow("Skin Only", skin)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

여기서 Y의 범위를 0~255로 넓게 열어둔 것은, 피부색 검출에서는 밝기 변화보다 색차(Cr, Cb)가 훨씬 신뢰할 수 있는 신호이기 때문이다. 다만 이 방식은 배경에 피부색과 비슷한 색(나무 색, 베이지색 옷 등)이 있으면 오탐이 발생하기 쉬운 간단한 방법이므로, 실무에서는 딥러닝 기반 얼굴 검출기(17장에서 다룰 예정)와 함께 보조적으로만 사용하는 것이 일반적이다.

### HSV, LAB, YCrCb 중 무엇을 선택할까

세 색공간의 용도를 표로 정리하면 다음과 같다.

| 색공간 | 핵심 특징 | 대표적인 활용 |
|---|---|---|
| HSV | 색상(H)이 원형 축으로 분리, 직관적 | 특정 색 물체 검출, 색상 기반 필터링, 조명 변화에 강건한 색 분류 |
| LAB | 밝기(L)와 색차(a, b)가 직교 좌표로 분리, 사람의 색 지각과 유사 | 밝기만 조정하는 색 보정, 대비 향상(CLAHE), 색차 정량화 |
| YCrCb | 밝기(Y)와 색차(Cr, Cb) 분리, 압축 친화적 | 피부색 검출, 비디오 코덱 연동, 압축률을 고려한 전처리 |

세 색공간 모두 "밝기와 색을 분리한다"는 공통된 아이디어를 갖고 있지만, HSV는 색상을 사람이 이름 붙이는 방식(빨강, 노랑, 파랑...)과 가장 가깝게 표현하고, LAB은 색의 지각적 차이를 가장 정확하게 반영하며, YCrCb는 압축·전송 표준과 맞닿아 있다는 각자의 강점이 있다. 실무에서는 "지금 풀려는 문제가 색을 이름으로 분류하는 문제인가(HSV), 색 자체의 미세한 차이를 정량화하는 문제인가(LAB), 아니면 비디오 파이프라인과 관련된 문제인가(YCrCb)"를 기준으로 선택하면 된다.

## 5.9 실전 도구: 트랙바로 HSV 범위 실시간 튜닝하기

지금까지의 예제에서는 `lower_red`, `upper_red` 같은 HSV 범위를 이미 "정답"으로 제시했지만, 실무에서는 이런 숫자를 어떻게 찾아낼까? 정답은 대부분 "직접 눈으로 보면서 슬라이더를 조정한다"는 매우 실용적인 방법이다. OpenCV는 `cv2.createTrackbar`로 윈도우에 슬라이더(트랙바)를 붙이는 기능을 제공하는데, 이를 이용해 H/S/V 각각의 최소값과 최대값을 실시간으로 조절하면서 마스크가 어떻게 바뀌는지 즉시 확인할 수 있는 도구를 만들 수 있다.

```python
import cv2
import numpy as np

def nothing(x):
    """트랙바는 값이 바뀔 때마다 콜백 함수를 호출해야 하지만,
    여기서는 값을 읽는 시점을 메인 루프에서 직접 통제하므로 아무 일도 하지 않는다."""
    pass

img = cv2.imread("fruits.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

cv2.namedWindow("Trackbars")

# H는 0~179, S와 V는 0~255 범위이므로 트랙바의 최댓값도 그에 맞춘다.
cv2.createTrackbar("H min", "Trackbars", 0, 179, nothing)
cv2.createTrackbar("H max", "Trackbars", 179, 179, nothing)
cv2.createTrackbar("S min", "Trackbars", 0, 255, nothing)
cv2.createTrackbar("S max", "Trackbars", 255, 255, nothing)
cv2.createTrackbar("V min", "Trackbars", 0, 255, nothing)
cv2.createTrackbar("V max", "Trackbars", 255, 255, nothing)

while True:
    h_min = cv2.getTrackbarPos("H min", "Trackbars")
    h_max = cv2.getTrackbarPos("H max", "Trackbars")
    s_min = cv2.getTrackbarPos("S min", "Trackbars")
    s_max = cv2.getTrackbarPos("S max", "Trackbars")
    v_min = cv2.getTrackbarPos("V min", "Trackbars")
    v_max = cv2.getTrackbarPos("V max", "Trackbars")

    lower = np.array([h_min, s_min, v_min])
    upper = np.array([h_max, s_max, v_max])

    mask = cv2.inRange(hsv, lower, upper)
    result = cv2.bitwise_and(img, img, mask=mask)

    cv2.imshow("Original", img)
    cv2.imshow("Mask", mask)
    cv2.imshow("Result", result)

    # ESC 키(27)를 누르면 종료
    if cv2.waitKey(1) & 0xFF == 27:
        break

cv2.destroyAllWindows()
```

이 도구가 하는 일은 단순하다. 매 프레임(정확히는 `while` 루프가 한 번 돌 때마다)마다 6개의 트랙바 값을 `cv2.getTrackbarPos`로 읽어서 `lower`, `upper` 배열을 새로 만들고, `inRange`로 마스크를 다시 계산해서 화면에 보여준다. 사용자가 슬라이더를 움직이면 다음 루프에서 곧바로 새 값이 반영되므로, 마치 실시간으로 마스크가 반응하는 것처럼 보인다.

`cv2.createTrackbar`의 콜백 함수(`nothing`)에 실질적인 로직을 넣지 않은 것은 의도적인 설계다. OpenCV의 트랙바는 콜백 함수를 반드시 지정해야 하지만, 콜백 안에서 처리하는 대신 메인 루프에서 매번 `getTrackbarPos`로 현재 값을 읽어오는 방식이 훨씬 단순하고 이해하기 쉽다. 이 패턴, 즉 "콜백은 비워두고 루프에서 값을 직접 읽는다"는 방식은 OpenCV로 GUI 도구를 만들 때 매우 흔하게 쓰인다.

실무에서 색상 범위를 찾을 때는 실제로 이런 도구를 즉석에서 만들어, 검출하고 싶은 물체가 화면(마스크)에 하얗게, 나머지는 검게 나올 때까지 슬라이더를 조금씩 움직여 보면서 값을 찾는다. 이렇게 찾은 `(h_min, s_min, v_min)`, `(h_max, s_max, v_max)` 값을 코드에 상수로 박아 넣으면, 이후 그 색을 검출하는 정식 프로그램에 그대로 사용할 수 있다. 조명 조건이 촬영 환경마다 다르므로, 이런 튜닝 과정은 새로운 환경(예: 다른 방, 다른 카메라)에서 프로그램을 돌릴 때마다 다시 거쳐야 하는 경우가 많다는 점도 함께 기억해 두자.

### 웹캠에 적용하기

정지 이미지 대신 웹캠 영상에 대해 같은 도구를 만들고 싶다면, `cv2.imread` 대신 `cv2.VideoCapture`로 매 프레임을 새로 읽어오도록 루프를 바꾸면 된다.

```python
import cv2
import numpy as np

def nothing(x):
    pass

cap = cv2.VideoCapture(0)

cv2.namedWindow("Trackbars")
cv2.createTrackbar("H min", "Trackbars", 0, 179, nothing)
cv2.createTrackbar("H max", "Trackbars", 179, 179, nothing)
cv2.createTrackbar("S min", "Trackbars", 0, 255, nothing)
cv2.createTrackbar("S max", "Trackbars", 255, 255, nothing)
cv2.createTrackbar("V min", "Trackbars", 0, 255, nothing)
cv2.createTrackbar("V max", "Trackbars", 255, 255, nothing)

while True:
    ok, frame = cap.read()
    if not ok:
        break

    hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)

    h_min = cv2.getTrackbarPos("H min", "Trackbars")
    h_max = cv2.getTrackbarPos("H max", "Trackbars")
    s_min = cv2.getTrackbarPos("S min", "Trackbars")
    s_max = cv2.getTrackbarPos("S max", "Trackbars")
    v_min = cv2.getTrackbarPos("V min", "Trackbars")
    v_max = cv2.getTrackbarPos("V max", "Trackbars")

    lower = np.array([h_min, s_min, v_min])
    upper = np.array([h_max, s_max, v_max])
    mask = cv2.inRange(hsv, lower, upper)
    result = cv2.bitwise_and(frame, frame, mask=mask)

    cv2.imshow("Camera", frame)
    cv2.imshow("Mask", mask)
    cv2.imshow("Result", result)

    if cv2.waitKey(1) & 0xFF == 27:
        break

cap.release()
cv2.destroyAllWindows()
```

정지 이미지 버전과 다른 부분은 딱 두 가지, `cv2.VideoCapture(0)`으로 카메라를 열고 루프마다 `cap.read()`로 새 프레임을 받아온다는 것, 그리고 `hsv` 변환을 루프 안에서 매 프레임마다 다시 계산한다는 것뿐이다. 이 구조는 4장에서 다룬 비디오 캡처의 기본 패턴을 그대로 재사용한 것이다.

## 5.10 여러 색상을 동시에 마스킹하기

지금까지는 한 번에 한 가지 색만 찾았지만, 실전에서는 "빨간색 물체와 파란색 물체를 각각 찾아서 서로 다른 방식으로 표시하고 싶다"는 요구가 흔하다. 이럴 때는 색상별로 각각 마스크를 만들고, 그 마스크를 이용해 결과 이미지에 서로 다른 색의 표시를 그려주면 된다.

```python
import cv2
import numpy as np

img = cv2.imread("colorful_objects.jpg")
hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)

# 색상별 HSV 범위 (트랙바 도구로 미리 찾아둔 값이라고 가정한다)
color_ranges = {
    "red": ([0, 100, 100], [10, 255, 255]),
    "blue": ([100, 100, 50], [130, 255, 255]),
    "green": ([40, 70, 70], [80, 255, 255]),
}

# 각 색상을 표시할 때 사용할 BGR 색상 (테두리 색)
display_colors = {
    "red": (0, 0, 255),
    "blue": (255, 0, 0),
    "green": (0, 255, 0),
}

output = img.copy()

for name, (lower, upper) in color_ranges.items():
    lower = np.array(lower)
    upper = np.array(upper)
    mask = cv2.inRange(hsv, lower, upper)

    # 이 색상이 검출된 픽셀의 윤곽선을 찾아 테두리로 표시한다 (12장에서 본격적으로 다룰 내용의 맛보기).
    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for cnt in contours:
        if cv2.contourArea(cnt) < 200:   # 너무 작은 잡티는 무시한다.
            continue
        x, y, w, h = cv2.boundingRect(cnt)
        cv2.rectangle(output, (x, y), (x + w, y + h), display_colors[name], 2)
        cv2.putText(output, name, (x, y - 8),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.6, display_colors[name], 2)

cv2.imshow("Original", img)
cv2.imshow("Detected Colors", output)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

이 예제는 3가지 색상 각각에 대해 독립적으로 `inRange` 마스크를 만든 뒤, `cv2.findContours`(12장에서 자세히 다룰 함수)로 마스크에서 색이 뭉쳐 있는 덩어리(윤곽선)를 찾아내고, `cv2.boundingRect`로 그 덩어리를 감싸는 사각형을 계산해서 그려준다. `cv2.contourArea`로 너무 작은 영역(카메라 노이즈나 조명 반사로 생기는 잡티)은 걸러내는 것도 실전에서 자주 쓰이는 패턴이다. 도형 그리기 함수들(`rectangle`, `putText`)은 6장에서 본격적으로 배우게 되며, 여기서는 색상 마스킹의 결과를 눈으로 확인하기 위한 용도로 미리 살짝 사용해 보았다.

## 5.11 실전 예제: 웹캠으로 색상 기반 객체 추적하기

이제 지금까지 배운 것을 모두 합쳐서, 웹캠 영상에서 특정 색의 물체(예: 파란색 병뚜껑, 초록색 공 등)를 실시간으로 찾아내고 그 중심점에 원을 그려 추적하는 프로그램을 만들어보자. 이 예제는 색상 기반 검출과 컨투어 분석(12장 예고)을 처음으로 연결해보는 자리이기도 하다.

```python
import cv2
import numpy as np

# 추적하고 싶은 색상의 HSV 범위 (트랙바 도구로 미리 찾아둔 값을 사용한다고 가정)
LOWER_COLOR = np.array([100, 120, 70])   # 예: 파란색 계열
UPPER_COLOR = np.array([130, 255, 255])

MIN_AREA = 500  # 이보다 작은 덩어리는 노이즈로 간주하고 무시한다.

cap = cv2.VideoCapture(0)

while True:
    ok, frame = cap.read()
    if not ok:
        break

    frame = cv2.flip(frame, 1)  # 웹캠 영상은 좌우가 반전되어 보이므로 보정한다.
    hsv = cv2.cvtColor(frame, cv2.COLOR_BGR2HSV)

    mask = cv2.inRange(hsv, LOWER_COLOR, UPPER_COLOR)

    # 마스크의 작은 잡티를 줄이기 위한 간단한 모폴로지 연산 (11장에서 자세히 다룰 내용).
    mask = cv2.erode(mask, None, iterations=2)
    mask = cv2.dilate(mask, None, iterations=2)

    contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

    if contours:
        # 가장 넓은 영역을 가진 컨투어를 추적 대상으로 선택한다.
        largest = max(contours, key=cv2.contourArea)
        area = cv2.contourArea(largest)

        if area > MIN_AREA:
            (x, y), radius = cv2.minEnclosingCircle(largest)
            center = (int(x), int(y))

            M = cv2.moments(largest)
            if M["m00"] != 0:
                cx = int(M["m10"] / M["m00"])
                cy = int(M["m01"] / M["m00"])
            else:
                cx, cy = center

            # 물체를 감싸는 원과, 정확한 중심점을 함께 표시한다.
            cv2.circle(frame, center, int(radius), (0, 255, 255), 2)
            cv2.circle(frame, (cx, cy), 5, (0, 0, 255), -1)
            cv2.putText(frame, f"area={int(area)}", (cx - 40, cy - int(radius) - 10),
                        cv2.FONT_HERSHEY_SIMPLEX, 0.5, (0, 255, 255), 1)

    cv2.imshow("Tracking", frame)
    cv2.imshow("Mask", mask)

    if cv2.waitKey(1) & 0xFF == 27:  # ESC로 종료
        break

cap.release()
cv2.destroyAllWindows()
```

이 프로그램의 흐름을 단계별로 정리하면 다음과 같다.

1. **마스킹**: 이번 장에서 배운 대로 HSV로 변환한 뒤 `inRange`로 원하는 색상만 골라낸다.
2. **노이즈 제거**: `cv2.erode`와 `cv2.dilate`로 마스크의 작은 얼룩을 줄인다(11장 모폴로지 연산에서 원리를 자세히 다룬다).
3. **덩어리 찾기**: `cv2.findContours`로 마스크에서 흰색 픽셀이 뭉쳐 있는 윤곽선들을 모두 찾는다.
4. **가장 큰 덩어리 선택**: 여러 개의 후보 중 `cv2.contourArea`가 가장 큰 것을 "추적 대상"으로 선택한다. 이는 노이즈로 생긴 작은 덩어리와 실제 물체를 구별하는 가장 단순하면서도 실용적인 방법이다.
5. **중심점 계산**: `cv2.moments`로 계산한 무게중심(centroid)을 물체의 실제 중심점으로 사용한다. `cv2.minEnclosingCircle`로 얻은 원의 중심과 무게중심은 물체 형태가 완전한 원이 아닌 한 미묘하게 다를 수 있는데, 무게중심이 더 안정적인 추적 기준점이 되는 경우가 많다.
6. **시각화**: 찾아낸 원과 중심점을 프레임 위에 그려서 실시간으로 확인한다.

이 예제에서 사용한 `findContours`, `contourArea`, `boundingRect`, `moments`, `minEnclosingCircle` 같은 함수들은 모두 12장에서 컨투어를 본격적으로 다룰 때 하나씩 원리를 짚어볼 것이다. 지금 단계에서는 "색상 마스크만 있으면, 그 마스크에서 물체의 위치·크기·중심점을 계산해내는 표준적인 도구들이 이미 OpenCV에 준비되어 있다"는 큰 그림을 파악하는 것으로 충분하다. 색상 기반 추적은 구현이 간단하고 실시간 처리가 매우 빠르다는 장점이 있지만, 조명 변화나 비슷한 색의 배경에 취약하다는 한계도 있다. 이런 한계를 보완하기 위한 더 정교한 추적·검출 기법은 이후 장(12장 컨투어 심화, 17장 딥러닝 기반 객체 검출)에서 계속 다룰 것이다.

## 요약

- OpenCV는 컬러 이미지를 BGR 순서로 다루며, RGB를 기대하는 외부 라이브러리(matplotlib 등)와 연동할 때는 `cv2.COLOR_BGR2RGB`로 순서를 바꿔줘야 한다.
- `cv2.cvtColor`는 색공간 변환을 담당하는 공통 함수이며, 변환 코드는 "원본2목표" 이름 규칙(`COLOR_BGR2GRAY`, `COLOR_BGR2HSV`, `COLOR_BGR2LAB`, `COLOR_BGR2YCrCb` 등)을 따른다.
- `COLOR_BGR2GRAY`로 그레이스케일 변환을 하면 채널이 사라진 2차원 배열이 되며, `imshow`는 채널 수에 따라 컬러 또는 흑백으로 자동 표시한다.
- HSV는 색상(H), 채도(S), 명도(V)를 분리해서 표현하며, 조명 변화가 주로 V(와 어느 정도의 S)에만 영향을 주기 때문에 H를 기준으로 하면 색상 기반 필터링이 BGR보다 훨씬 안정적이다.
- LAB은 밝기(L)와 색차(a, b)를 직교 좌표로 분리해 사람의 색 지각과 유사하게 동작하며, 색 보정이나 대비 향상처럼 밝기와 색을 독립적으로 다뤄야 하는 작업에 적합하다.
- YCrCb는 밝기(Y)와 색차(Cr, Cb)를 분리하며 비디오 압축 표준과 맞닿아 있어, 피부색 검출과 같은 응용에 흔히 사용된다.
- `cv2.createTrackbar`/`cv2.getTrackbarPos`로 실시간 슬라이더 도구를 만들면, 원하는 색상의 HSV 범위를 눈으로 보면서 빠르게 찾아낼 수 있다. 이는 실무에서 색상 범위를 정하는 표준적인 작업 방식이다.
- `inRange`로 HSV 범위를 지정해 마스크를 만들고, `bitwise_and`로 원본에 적용하면 특정 색상 영역만 추출할 수 있다. 여러 색상을 동시에 다룰 때는 색상별로 마스크와 컨투어를 각각 처리한다.
- 색상 마스크에 `findContours`, `contourArea`, `moments`, `minEnclosingCircle` 등을 결합하면, 웹캠 영상에서 특정 색 물체를 실시간으로 추적하는 프로그램을 간단하게 구현할 수 있다.

## 연습문제

1. `COLOR_BGR2GRAY` 변환 시 OpenCV가 단순 평균이 아니라 가중합을 사용하는 이유를 사람의 시각 특성과 연관지어 설명해 보라.
2. 5.9절의 트랙바 튜닝 도구를 사용해, 자신이 가진 임의의 사진에서 원하는 색상 하나를 골라 HSV 범위를 직접 찾아보고, 그 값을 이용해 별도의 마스킹 스크립트를 작성해 보라.
3. LAB의 a·b 채널과 YCrCb의 Cr·Cb 채널은 둘 다 "색차"를 표현하지만 서로 다른 목적으로 설계되었다. 두 색공간이 각각 어떤 상황에서 더 유리한지, 이번 장의 내용을 바탕으로 자신의 말로 비교해 설명해 보라.
4. 5.10절의 다중 색상 마스킹 예제를 확장해서, 4번째 색상(예: 노란색)을 추가로 검출하도록 `color_ranges`와 `display_colors` 딕셔너리를 수정해 보라.
5. 5.11절의 객체 추적 예제에서 `MIN_AREA` 값을 너무 작게 설정하면 어떤 문제가 발생할지, 그리고 너무 크게 설정하면 어떤 문제가 발생할지 각각 실험해보고 그 이유를 설명해 보라.
