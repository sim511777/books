## 16.1 프레임 단위 처리 파이프라인 다시 보기

4장에서는 `VideoCapture`로 웹캠이나 동영상 파일을 열어 프레임을 읽어오는 기초적인 방법을 다루었습니다. 이번 장에서는 그 기초 위에서, 읽어온 프레임에 실제로 어떤 처리를 가하고 그 결과를 화면에 보여준 뒤 종료 조건까지 관리하는 실전 파이프라인의 전체 구조를 정리합니다. 이 구조는 이후 어떤 비디오 처리 기능(배경 제거, 옵티컬 플로우, 객체 추적 등)을 추가하든 그대로 재사용할 수 있는 뼈대입니다.

파이프라인은 크게 네 단계로 이루어집니다.

1. **읽기(read)**: `VideoCapture`에서 한 프레임씩 읽어옵니다.
2. **처리(process)**: 읽어온 프레임에 원하는 알고리즘(색공간 변환, 필터링, 배경 제거 등)을 적용합니다.
3. **표시(display)**: 처리된 결과를 `imshow`로 화면에 보여줍니다.
4. **종료 조건(exit condition)**: 사용자가 키를 누르거나 더 이상 읽을 프레임이 없으면 루프를 빠져나옵니다.

```python
import cv2

cap = cv2.VideoCapture(0)  # 0번 웹캠. 파일이면 "video.mp4" 등 경로 전달
if not cap.isOpened():
    raise RuntimeError("비디오 소스를 열 수 없습니다.")

while True:
    # 1. 읽기
    ret, frame = cap.read()
    if not ret:
        break  # 프레임을 더 읽을 수 없으면 종료 (파일의 끝 등)

    # 2. 처리: 예시로 그레이스케일 변환
    processed = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # 3. 표시
    cv2.imshow("Original", frame)
    cv2.imshow("Processed", processed)

    # 4. 종료 조건: 'q' 키를 누르면 종료
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

이 뼈대에서 눈여겨볼 점은, `cap.read()`가 `False`를 반환하는 순간이 곧 종료 조건이라는 것입니다. 웹캠처럼 끝이 없는 스트림에서는 이 조건이 거의 발생하지 않고 대신 키 입력으로 종료하지만, 동영상 파일을 처리할 때는 파일의 마지막 프레임을 지나는 순간 자연스럽게 이 조건으로 루프가 끝납니다. 두 종료 조건(파일의 끝, 사용자 키 입력)을 모두 갖춰두는 것이 실전 코드의 기본입니다.

`cv2.waitKey(1)`의 인자는 한 프레임을 처리한 뒤 키 입력을 몇 밀리초 동안 기다릴지를 결정합니다. 1ms는 실질적으로 "가능한 한 빨리 다음 프레임으로 넘어가되 키 입력만 짧게 확인한다"는 뜻이며, 파일을 특정 배속으로 재생하듯 보여주고 싶다면 이 값을 늘려(예: 30) 프레임 사이의 지연을 의도적으로 늘릴 수 있습니다.

## 16.2 배경 제거로 움직이는 객체 감지하기: MOG2

CCTV 감시 영상에서 사람이 지나가는 것을 감지하거나, 고정된 카메라로 도로의 차량을 세는 것처럼, 카메라가 고정되어 있고 배경은 그대로인데 그 위에서 무언가가 움직이는 상황은 매우 흔합니다. 이런 경우에 쓰는 대표적인 기법이 **배경 제거(background subtraction)**입니다.

배경 제거의 기본 아이디어는 단순합니다. 여러 프레임을 관찰하면서 "이 픽셀은 보통 이런 색이었다"라는 배경 모델을 학습하고, 새로운 프레임이 들어오면 그 모델과 비교해 크게 달라진 픽셀만 "전경(foreground)", 즉 움직이는 객체로 판단하는 것입니다. 단순히 두 프레임을 직접 비교하는 것보다 정교한 이유는, 배경 모델이 나뭇잎의 흔들림이나 조명의 미세한 변화 같은 자잘한 변동까지 통계적으로 학습해서 그런 잡음을 전경으로 오판하지 않기 때문입니다.

OpenCV는 이런 배경 모델을 만들어주는 여러 알고리즘을 제공하며, 그중 가장 널리 쓰이는 것이 **MOG2**(Mixture of Gaussians, 가우시안 혼합 모델의 개선판)입니다. 사용법은 다음과 같은 흐름을 따릅니다.

1. `cv2.createBackgroundSubtractorMOG2()`로 배경 모델 객체를 만듭니다.
2. 각 프레임을 배경 모델의 `apply()` 메서드에 넣습니다. 이 메서드는 전경으로 판단된 영역이 흰색(255), 배경으로 판단된 영역이 검은색(0)인 전경 마스크를 반환합니다. 동시에 내부적으로 배경 모델을 그 프레임 정보로 조금씩 갱신합니다.
3. 필요하면 전경 마스크에 모폴로지 연산(11장 참고)을 적용해 잡음을 제거하고, 컨투어 검출(13장 참고)로 움직이는 객체의 위치와 크기를 얻습니다.

```python
import cv2

cap = cv2.VideoCapture("traffic.mp4")

# MOG2 배경 제거기 생성
# history: 배경 모델을 학습하는 데 참고하는 과거 프레임 수
# varThreshold: 픽셀이 배경/전경으로 갈리는 분산 임계값 (낮을수록 민감)
# detectShadows: 그림자를 별도 회색(127)으로 표시할지 여부
back_sub = cv2.createBackgroundSubtractorMOG2(
    history=500, varThreshold=16, detectShadows=True
)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    # 전경 마스크 계산 (그림자는 127, 전경은 255, 배경은 0)
    fg_mask = back_sub.apply(frame)

    # 그림자(127)를 배경으로 취급하도록 이진화
    _, fg_mask = cv2.threshold(fg_mask, 200, 255, cv2.THRESH_BINARY)

    # 작은 잡음 제거를 위한 모폴로지 열림 연산
    kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    fg_mask = cv2.morphologyEx(fg_mask, cv2.MORPH_OPEN, kernel)

    # 움직이는 객체의 컨투어를 찾아 사각형으로 표시
    contours, _ = cv2.findContours(fg_mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for c in contours:
        if cv2.contourArea(c) < 500:  # 너무 작은 잡음은 무시
            continue
        x, y, w, h = cv2.boundingRect(c)
        cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

    cv2.imshow("Frame", frame)
    cv2.imshow("Foreground Mask", fg_mask)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

`history`가 클수록 배경 모델이 천천히, 안정적으로 적응하고, `varThreshold`가 낮을수록 작은 변화에도 전경으로 민감하게 반응합니다. `detectShadows`를 켜면 그림자 영역이 흰색(255)이 아닌 회색(127)으로 표시되므로, 그림자를 실제 객체와 구분하고 싶다면 위 예제처럼 임계값을 200 정도로 잡아 이진화하면 그림자를 배경 취급으로 걸러낼 수 있습니다.

MOG2는 이름 그대로 각 픽셀의 밝기(또는 색상) 값을 여러 개의 가우시안 분포(정규분포)를 혼합한 모델로 표현합니다. 예를 들어 나뭇잎이 흔들리는 배경이라면, 그 픽셀은 "밝은 하늘색"과 "어두운 잎의 그림자색" 두 가지 상태를 오가므로 하나의 가우시안으로는 표현하기 어렵습니다. MOG2는 이런 픽셀에 여러 개의 가우시안 분포를 할당해 각 상태를 배경의 일부로 인정하고, 그 어느 분포에도 맞지 않는 새로운 값이 나타났을 때만 전경으로 판단합니다. 이 덕분에 반복적으로 변하는 배경 잡음에 강인합니다.

## 16.3 또 다른 선택: KNN 배경 제거기

OpenCV는 MOG2 외에도 **KNN**(K-Nearest Neighbors) 방식의 배경 제거기를 제공합니다. `cv2.createBackgroundSubtractorKNN()`으로 생성하며, 사용법은 MOG2와 거의 동일합니다.

```python
import cv2

cap = cv2.VideoCapture("traffic.mp4")

# KNN 배경 제거기 생성
# history: 배경 모델을 학습하는 데 참고하는 과거 프레임 수
# dist2Threshold: 새 픽셀 값이 배경 샘플들과 얼마나 떨어져야 전경으로 판단할지 결정하는 거리 임계값
# detectShadows: 그림자를 별도 회색(127)으로 표시할지 여부
back_sub = cv2.createBackgroundSubtractorKNN(
    history=500, dist2Threshold=400.0, detectShadows=True
)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    fg_mask = back_sub.apply(frame)
    _, fg_mask = cv2.threshold(fg_mask, 200, 255, cv2.THRESH_BINARY)

    kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    fg_mask = cv2.morphologyEx(fg_mask, cv2.MORPH_OPEN, kernel)

    contours, _ = cv2.findContours(fg_mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for c in contours:
        if cv2.contourArea(c) < 500:
            continue
        x, y, w, h = cv2.boundingRect(c)
        cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

    cv2.imshow("Frame", frame)
    cv2.imshow("Foreground Mask (KNN)", fg_mask)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

MOG2가 각 픽셀을 몇 개의 가우시안 분포로 모델링하는 것과 달리, KNN은 각 픽셀에 대해 과거에 관찰된 샘플 값들을 그대로 모아두고, 새로운 픽셀 값이 그 샘플들 중 가까운 K개 이웃과 얼마나 떨어져 있는지를 계산해 전경 여부를 판단합니다. 즉 분포를 수학적으로 요약하는 대신 실제 샘플 자체를 기준으로 비교하는 방식입니다.

두 알고리즘을 비교하면 다음과 같습니다.

| 항목 | MOG2 | KNN |
|---|---|---|
| 배경 모델링 방식 | 픽셀마다 여러 개의 가우시안 분포를 혼합 | 픽셀마다 과거 샘플 값들의 집합을 유지 |
| 핵심 파라미터 | `varThreshold`(분산 임계값) | `dist2Threshold`(거리 임계값) |
| 복잡한 다중 상태 배경(나뭇잎, 물결 등) | 가우시안 개수가 제한적이라 아주 복잡한 패턴에는 한계가 있을 수 있음 | 샘플 기반이라 더 다양한 패턴을 유연하게 반영하는 경우가 많음 |
| 계산 비용 | 상대적으로 가벼움 | 이웃 탐색 비용이 있어 상대적으로 더 무거울 수 있음 |
| 그림자 검출 | `detectShadows` 지원 | `detectShadows` 지원 |
| 일반적인 선택 기준 | 대부분의 상황에서 기본 선택지로 무난함 | MOG2 결과가 만족스럽지 않은 복잡한 배경에서 대안으로 시도 |

실전에서는 어느 한쪽이 항상 우월하다고 말하기는 어렵고, 같은 영상에 두 방법을 모두 적용해 전경 마스크의 품질(잡음의 양, 객체 윤곽의 선명도)을 직접 비교해 보고 선택하는 것이 가장 확실합니다.

## 16.4 더 단순한 대안: 프레임 차이 계산

MOG2나 KNN 같은 통계적 배경 모델은 정확하지만, 그만큼 여러 프레임에 걸쳐 모델을 학습시켜야 하고 계산 비용도 더 듭니다. 움직임을 감지하기만 하면 되는 간단한 상황이라면, 훨씬 가벼운 방법으로 **프레임 차이(frame differencing)**를 쓸 수 있습니다. 연속한 두 프레임(또는 고정된 기준 프레임과 현재 프레임)의 밝기 차이를 `absdiff`로 계산해서, 차이가 큰 영역을 움직임이 있는 곳으로 판단하는 방식입니다.

```python
import cv2

cap = cv2.VideoCapture("traffic.mp4")

ret, prev_frame = cap.read()
prev_gray = cv2.cvtColor(prev_frame, cv2.COLOR_BGR2GRAY)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # 이전 프레임과 현재 프레임의 차이 계산
    diff = cv2.absdiff(prev_gray, gray)
    _, motion_mask = cv2.threshold(diff, 25, 255, cv2.THRESH_BINARY)

    cv2.imshow("Frame", frame)
    cv2.imshow("Motion Mask", motion_mask)

    prev_gray = gray  # 다음 반복을 위해 현재 프레임을 이전 프레임으로 갱신

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

지금까지 다룬 세 가지 움직임 감지 방법을 정리하면 다음과 같습니다.

| | 프레임 차이 (`absdiff`) | MOG2 | KNN |
|---|---|---|---|
| 원리 | 인접한 두 프레임을 직접 비교 | 가우시안 혼합 모델 | 샘플 기반 최근접 이웃 |
| 계산 비용 | 매우 낮음 | 중간 | 중간~높음 |
| 정지한 객체 | 감지 못함(움직임이 멈추면 차이가 사라짐) | 배경으로 서서히 편입되기 전까지는 계속 전경으로 유지 | 배경으로 서서히 편입되기 전까지는 계속 전경으로 유지 |
| 잡음(나뭇잎 흔들림 등) | 그대로 움직임으로 잡힘 | 반복되는 변동을 어느 정도 학습해 걸러냄 | 다양한 샘플을 유지해 걸러내는 경향이 더 강할 수 있음 |
| 그림자 | 별도 처리 없음 | `detectShadows` 옵션으로 구분 가능 | `detectShadows` 옵션으로 구분 가능 |
| 적합한 상황 | 빠르고 단순한 움직임 감지, 리소스가 제한된 환경 | 대부분의 감시·트래픽 분석 상황에서 기본 선택 | 복잡하고 다양한 배경 패턴이 있는 상황에서의 대안 |

즉 프레임 차이는 구현이 간단하고 빠르지만 정교함이 떨어지고, MOG2와 KNN은 계산 비용이 더 들지만 훨씬 안정적인 전경 마스크를 만들어 줍니다. 실전에서는 요구되는 정확도와 사용 가능한 자원(임베디드 기기인지, 서버인지)에 따라 선택합니다.

## 16.5 옵티컬 플로우로 특징점의 움직임 추적하기

지금까지 살펴본 배경 제거와 프레임 차이는 "어느 픽셀이 변했는가"만 알려줄 뿐, 그 변화가 "어느 방향으로, 얼마나 빠르게" 일어났는지는 알려주지 않습니다. 이런 움직임의 방향과 속도까지 추정하는 기법을 **옵티컬 플로우(optical flow)**라고 부릅니다.

옵티컬 플로우는 한 프레임의 각 픽셀(또는 추적하고자 하는 특정 지점들)이 다음 프레임에서 어디로 이동했는지를 벡터로 추정합니다. 예를 들어 화면 왼쪽에서 오른쪽으로 이동하는 자동차가 있다면, 그 자동차 표면의 픽셀들에 대해 옵티컬 플로우는 오른쪽을 향하는 벡터를 계산해 줍니다. 이렇게 얻은 움직임 벡터는 객체의 이동 궤적을 추적하거나, 카메라 자체의 흔들림을 보정하거나, 영상 압축에서 다음 프레임을 예측하는 등 다양한 곳에 활용됩니다.

옵티컬 플로우는 크게 두 갈래로 나뉩니다.

- **밀집(dense) 옵티컬 플로우**: 이미지의 모든 픽셀에 대해 흐름 벡터를 계산합니다. OpenCV의 `cv2.calcOpticalFlowFarneback()`이 대표적입니다. 정보가 풍부하지만 계산량이 많습니다.
- **희소(sparse) 옵티컬 플로우**: 15장에서 다룬 특징점처럼, 미리 선별한 몇 개의 대표 지점에 대해서만 흐름 벡터를 계산합니다. 계산량이 훨씬 적어 실시간 처리에 적합합니다.

이 절에서는 희소 옵티컬 플로우의 대표 알고리즘인 **Lucas-Kanade 방법**(`cv2.calcOpticalFlowPyrLK`)을 이용해, 첫 프레임에서 뽑은 대표 지점들이 이후 프레임에서 어떻게 이동하는지 실제로 추적하는 예제를 만들어봅니다. 전체 흐름은 다음과 같습니다.

1. 첫 프레임을 그레이스케일로 변환하고, `cv2.goodFeaturesToTrack()`으로 추적할 만한 지점(코너 성격이 강한 지점)들을 뽑습니다.
2. 다음 프레임이 들어올 때마다 `cv2.calcOpticalFlowPyrLK()`에 이전 프레임, 현재 프레임, 그리고 이전 프레임에서 추적하던 점들의 좌표를 넘겨, 각 점이 현재 프레임에서 어디로 이동했는지 계산합니다.
3. 추적에 성공한 점만 남기고, 이동 경로를 선으로 그려 시각화합니다.
4. 추적 중인 점이 너무 적게 남으면 `goodFeaturesToTrack()`을 다시 호출해 새로운 지점을 보충합니다.

```python
import numpy as np
import cv2

cap = cv2.VideoCapture("traffic.mp4")

# goodFeaturesToTrack 파라미터: 추적할 대표 지점을 뽑을 때 사용
feature_params = dict(
    maxCorners=200,     # 최대 추적 지점 개수
    qualityLevel=0.3,   # 코너 응답 강도의 상대적 임계값 (0~1, 높을수록 더 확실한 코너만 채택)
    minDistance=7,       # 추적 지점들 사이의 최소 거리(픽셀)
    blockSize=7,
)

# calcOpticalFlowPyrLK 파라미터: 피라미드 기반 Lucas-Kanade 옵티컬 플로우
lk_params = dict(
    winSize=(15, 15),   # 각 지점 주변에서 이동을 탐색할 윈도우 크기
    maxLevel=2,          # 피라미드 레벨 수 (큰 움직임까지 다룰 수 있게 해줌)
    criteria=(cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 10, 0.03),
)

ret, old_frame = cap.read()
old_gray = cv2.cvtColor(old_frame, cv2.COLOR_BGR2GRAY)

# 추적할 초기 지점들을 검출
p0 = cv2.goodFeaturesToTrack(old_gray, mask=None, **feature_params)

# 이동 궤적을 그릴 캔버스 (원본 프레임 위에 계속 덧그림)
trail_mask = np.zeros_like(old_frame)
colors = np.random.randint(0, 255, (feature_params["maxCorners"], 3))

while True:
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # 이전 프레임의 지점들(p0)이 현재 프레임(gray)에서 어디로 이동했는지 계산
    p1, status, err = cv2.calcOpticalFlowPyrLK(old_gray, gray, p0, None, **lk_params)

    if p1 is not None:
        # status == 1인 지점만 추적에 성공한 것으로 채택
        good_new = p1[status == 1]
        good_old = p0[status == 1]
    else:
        good_new = np.empty((0, 1, 2), dtype=np.float32)
        good_old = np.empty((0, 1, 2), dtype=np.float32)

    # 이동 경로와 현재 위치를 시각화
    for i, (new, old) in enumerate(zip(good_new, good_old)):
        x_new, y_new = new.ravel()
        x_old, y_old = old.ravel()
        color = colors[i % len(colors)].tolist()
        trail_mask = cv2.line(trail_mask, (int(x_new), int(y_new)), (int(x_old), int(y_old)), color, 2)
        frame = cv2.circle(frame, (int(x_new), int(y_new)), 4, color, -1)

    result = cv2.add(frame, trail_mask)
    cv2.imshow("Lucas-Kanade Optical Flow", result)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

    # 다음 반복을 위해 갱신
    old_gray = gray.copy()
    p0 = good_new.reshape(-1, 1, 2)

    # 추적 중인 지점이 너무 적어지면 새로 보충
    if len(p0) < 20:
        new_pts = cv2.goodFeaturesToTrack(old_gray, mask=None, **feature_params)
        if new_pts is not None:
            p0 = new_pts
        trail_mask = np.zeros_like(old_frame)  # 궤적도 새로 시작

cap.release()
cv2.destroyAllWindows()
```

몇 가지 짚어볼 부분이 있습니다.

- `cv2.goodFeaturesToTrack()`은 코너처럼 추적하기 좋은 지점을 찾아주는 함수로, 15장에서 다룬 특징점 검출과 목적은 비슷하지만 디스크립터를 만들지 않고 좌표만 반환한다는 점이 다릅니다. 옵티컬 플로우는 애초에 프레임 사이의 시간 간격이 짧아 위치 변화가 작다고 가정하므로, 디스크립터로 매칭할 필요 없이 "근처에서 비슷한 패턴을 찾는" 방식으로도 충분히 추적할 수 있습니다.
- `cv2.calcOpticalFlowPyrLK()`의 이름에 들어간 "Pyr"는 이미지 피라미드(Pyramid)를 의미합니다. 원본 해상도에서는 큰 움직임을 놓치기 쉬우므로, 이미지를 여러 단계로 축소한 피라미드의 낮은 해상도에서 큰 움직임을 먼저 대략 추정하고, 점차 높은 해상도로 올라가며 정밀하게 보정하는 방식으로 동작합니다. `maxLevel`이 이 피라미드의 단계 수를 결정합니다.
- 반환되는 `status` 배열은 각 지점의 추적 성공 여부(1 또는 0)를 담고 있습니다. 프레임 밖으로 나가거나 가려짐(occlusion)이 생긴 지점은 추적에 실패해 0이 되므로, 이 값으로 걸러내야 합니다.
- 시간이 지나면서 추적하던 지점들이 하나둘 사라지므로(추적 실패, 화면 밖 이탈 등), 남은 지점 수가 일정 이하로 줄어들면 `goodFeaturesToTrack()`을 다시 호출해 새로운 지점을 보충하는 것이 일반적인 실전 패턴입니다.

참고로 밀집 옵티컬 플로우인 `cv2.calcOpticalFlowFarneback()`은 모든 픽셀에 대한 흐름을 (x, y) 두 채널의 벡터 필드로 반환합니다. 이 벡터 필드의 크기(magnitude)와 방향(angle)을 `cv2.cartToPolar()`로 구해 HSV 색상으로 표현하면, 화면 전체의 움직임을 색으로 시각화한 "옵티컬 플로우 지도"를 만들 수 있습니다. 다만 모든 픽셀을 계산하는 만큼 Lucas-Kanade 방식보다 계산 비용이 훨씬 크므로, 실시간성이 중요한 상황에서는 희소 방식을 먼저 고려하는 것이 합리적입니다.

## 16.6 객체 트래킹 API: 지정한 영역을 계속 따라가기

옵티컬 플로우가 낱개의 지점을 추적하는 기법이라면, 사용자가 화면에서 지정한 사각형 영역(바운딩 박스) 하나를 이후 프레임에서 계속 따라가고 싶을 때는 OpenCV의 **객체 트래커(object tracker)** API가 더 적합합니다. 이 API는 첫 프레임에서 "이 영역이 추적 대상이다"라고 한 번만 알려주면, 이후 프레임에서는 그 대상의 새로운 위치를 알고리즘이 스스로 추정해 줍니다.

OpenCV가 제공하는 대표적인 트래커는 다음과 같습니다.

| 트래커 | 특징 |
|---|---|
| `cv2.TrackerCSRT_create()` | Discriminative Correlation Filter 계열로, 정확도가 높고 크기 변화에도 비교적 강인하지만 속도는 상대적으로 느립니다. |
| `cv2.TrackerKCF_create()` | CSRT보다 빠르지만 정확도는 다소 낮습니다. 실시간성이 더 중요한 경우에 적합합니다. |
| `cv2.TrackerMIL_create()` | 비교적 오래된 방식으로, 다른 트래커에 비해 정확도는 낮은 편입니다. |

> **참고**: CSRT와 KCF 트래커는 과거에는 별도 확장 패키지인 `opencv-contrib-python`을 설치해야만 사용할 수 있었지만, OpenCV 4.5.1 이후로는 표준 `opencv-python` 패키지에도 포함되어 바로 사용할 수 있습니다. 만약 사용 중인 환경에서 `cv2.TrackerCSRT_create()`를 찾을 수 없다는 오류가 난다면, OpenCV 버전을 확인하거나 `opencv-contrib-python`을 설치해 보아야 합니다.

사용 흐름은 다음과 같이 단순합니다.

1. 트래커 객체를 생성합니다.
2. 첫 프레임과 추적할 초기 바운딩 박스 `(x, y, w, h)`를 `tracker.init()`에 넘겨 초기화합니다. 초기 바운딩 박스는 `cv2.selectROI()`로 사용자가 마우스로 직접 지정할 수 있습니다.
3. 이후 각 프레임마다 `tracker.update(frame)`을 호출합니다. 이 메서드는 추적 성공 여부와 새로운 바운딩 박스를 반환합니다.

```python
import cv2

cap = cv2.VideoCapture("traffic.mp4")
ret, frame = cap.read()

# 첫 프레임에서 마우스로 추적할 영역을 지정 (엔터 또는 스페이스로 확정)
bbox = cv2.selectROI("Select Object", frame, showCrosshair=True, fromCenter=False)
cv2.destroyWindow("Select Object")

tracker = cv2.TrackerCSRT_create()
tracker.init(frame, bbox)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    success, bbox = tracker.update(frame)

    if success:
        x, y, w, h = [int(v) for v in bbox]
        cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)
        cv2.putText(frame, "Tracking", (x, y - 10),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.6, (0, 255, 0), 2)
    else:
        cv2.putText(frame, "Tracking failure", (20, 40),
                    cv2.FONT_HERSHEY_SIMPLEX, 0.8, (0, 0, 255), 2)

    cv2.imshow("Object Tracking", frame)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

이 API가 배경 제거나 옵티컬 플로우와 다른 점은, 추적 대상을 "무엇인지 몰라도" 다룬다는 것입니다. 배경 제거는 배경과 다른 모든 움직임을 전경으로 잡아내고, 옵티컬 플로우는 코너 같은 일반적인 지점을 추적하지만, 객체 트래커는 사용자가 지정한 특정 대상 하나의 외형(색상 분포, 텍스처 등)을 내부적으로 모델링해서 그 대상만을 계속 따라갑니다. 그래서 "저 사람" 또는 "저 차량 한 대"처럼 특정 개체를 화면에서 놓치지 않고 추적해야 하는 상황(스포츠 중계의 선수 추적, 감시 카메라에서 특정 인물 추적 등)에 적합합니다. 다만 대상이 다른 물체에 완전히 가려지거나 화면 밖으로 나가면 추적이 실패할 수 있으므로, 위 예제의 `success` 값을 항상 확인해 추적 실패 상황을 처리해야 합니다.

## 16.7 처리된 비디오를 파일로 저장하기

지금까지는 처리 결과를 화면에만 보여주었지만, 실전에서는 그 결과(예: 움직임이 표시된 감시 영상, 전경 마스크 영상, 추적 결과 영상)를 파일로 저장해 나중에 다시 볼 수 있어야 하는 경우가 많습니다. 이때 사용하는 것이 `VideoWriter`입니다.

`VideoWriter`를 열 때는 다음 정보가 필요합니다.

- 저장할 파일 경로
- 코덱을 지정하는 4문자 코드(FourCC). 예를 들어 `"mp4v"`는 MP4 컨테이너에서 널리 쓰이는 코덱입니다.
- 초당 프레임 수(FPS)
- 프레임 크기(가로, 세로). 이 크기는 실제로 쓰는 프레임의 크기와 반드시 일치해야 하며, 다르면 저장이 실패하거나 깨진 영상이 만들어집니다.

다음 예제는 웹캠에서 프레임을 읽어 그레이스케일로 변환한 뒤, 그 결과를 `output.mp4` 파일로 저장합니다.

```python
import cv2

cap = cv2.VideoCapture(0)
if not cap.isOpened():
    raise RuntimeError("비디오 소스를 열 수 없습니다.")

# 원본 프레임 크기와 FPS를 소스에서 그대로 가져옴
fps = cap.get(cv2.CAP_PROP_FPS) or 30.0
width = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))
height = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))

fourcc = cv2.VideoWriter_fourcc(*"mp4v")
writer = cv2.VideoWriter("output.mp4", fourcc, fps, (width, height))

while True:
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    # 그레이스케일(1채널)을 그대로 쓰면 컬러 코덱과 맞지 않으므로 3채널로 변환
    gray_bgr = cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)

    writer.write(gray_bgr)
    cv2.imshow("Recording", gray_bgr)

    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
writer.release()
cv2.destroyAllWindows()
```

몇 가지 실수하기 쉬운 부분을 정리하면 다음과 같습니다.

- `VideoWriter`에 넘기는 프레임 크기는 반드시 실제로 `write()`에 넘기는 프레임의 크기와 정확히 일치해야 합니다. 크기가 다르면 대부분의 백엔드에서 저장이 조용히 실패합니다.
- 그레이스케일 처리 결과나 배경 제거의 전경 마스크처럼 1채널 영상을 저장하려면, 코덱이 기대하는 3채널(BGR) 형식으로 다시 변환해 주어야 하는 경우가 많습니다. 위 예제에서 `cv2.COLOR_GRAY2BGR`로 변환한 이유가 바로 이것입니다.
- 작업이 끝나면 `cap`뿐 아니라 `writer`도 반드시 `release()`해야 파일이 온전하게 마무리(finalize)됩니다. 이 과정을 건너뛰면 파일이 생성되었더라도 재생이 되지 않거나 끝부분이 잘리는 경우가 있습니다.
- FourCC 코덱은 운영체제와 설치된 코덱 라이브러리에 따라 지원 여부가 달라질 수 있습니다. `mp4v`가 동작하지 않는 환경에서는 `XVID`(AVI 컨테이너), `MJPG` 등 다른 코덱을 시도해 볼 수 있습니다.
- 웹캠처럼 실제 FPS가 요청한 값과 정확히 일치하지 않는 장치도 있습니다. `cap.get(cv2.CAP_PROP_FPS)`가 0을 반환하는 경우도 있으므로, 위 예제처럼 `or 30.0` 같은 안전한 기본값을 두는 것이 좋습니다.

## 요약

- 비디오 처리의 기본 파이프라인은 "읽기 → 처리 → 표시 → 종료 조건"의 반복이며, `cap.read()`가 실패하는 순간과 사용자 키 입력 두 가지를 모두 종료 조건으로 갖추는 것이 안전합니다.
- 배경 제거(background subtraction)는 정적인 배경 위에서 움직이는 객체를 찾는 기법입니다. `cv2.createBackgroundSubtractorMOG2()`는 픽셀마다 여러 가우시안 분포를 혼합해 배경을 모델링하며, `cv2.createBackgroundSubtractorKNN()`은 픽셀마다 과거 샘플을 유지하며 최근접 이웃 거리로 전경을 판단합니다. 두 방법 모두 매 프레임 `apply()`로 전경 마스크를 얻습니다.
- 프레임 차이(`absdiff`)는 통계적 배경 모델보다 훨씬 단순하고 가볍지만, 정지한 객체를 감지하지 못하고 잡음에 취약하다는 한계가 있습니다. 요구 정확도와 자원 제약에 따라 선택합니다.
- 옵티컬 플로우는 픽셀(또는 대표 지점)의 이동 방향과 속도까지 추정하는 기법입니다. 희소 방식인 `cv2.calcOpticalFlowPyrLK()`(Lucas-Kanade)는 `goodFeaturesToTrack()`으로 뽑은 대표 지점들의 프레임 간 이동을 피라미드 기반으로 추적하며, 밀집 방식인 `cv2.calcOpticalFlowFarneback()`은 모든 픽셀에 대한 흐름 벡터를 계산합니다.
- 사용자가 지정한 특정 바운딩 박스 하나를 계속 추적하고 싶을 때는 `cv2.TrackerCSRT_create()`, `cv2.TrackerKCF_create()` 같은 객체 트래커 API를 사용합니다. 첫 프레임에서 `tracker.init()`으로 초기화한 뒤, 이후 프레임마다 `tracker.update()`를 호출해 새로운 위치를 얻습니다.
- `VideoWriter`로 처리된 프레임을 다시 동영상 파일로 저장할 수 있으며, 코덱(FourCC)·FPS·프레임 크기를 정확히 맞추고 작업 종료 시 반드시 `release()`해야 합니다.

## 연습문제

1. 이번 장의 파이프라인 뼈대를 이용해, 웹캠 영상을 그레이스케일이 아니라 5장에서 배운 HSV로 변환해 화면에 보여주는 프로그램을 작성해 보세요.
2. MOG2와 KNN 배경 제거기를 같은 영상에 각각 적용하고, 전경 마스크의 잡음 정도와 객체 윤곽의 선명도를 비교해 보세요. 또한 MOG2의 `varThreshold`와 KNN의 `dist2Threshold`를 각각 낮음/기본/높음 세 단계로 바꿔가며 결과가 어떻게 달라지는지 확인해 보세요.
3. 정지된 물체(예: 화면 안에 놓인 컵)를 배경 제거와 프레임 차이 두 방법으로 각각 감지해 보고, 16.4절에서 설명한 차이가 실제로 나타나는지 확인해 보세요.
4. 16.5절의 Lucas-Kanade 예제에서 `feature_params`의 `maxCorners`와 `qualityLevel` 값을 바꿔가며 추적되는 지점의 개수와 안정성이 어떻게 달라지는지 관찰하고, 추적 중인 지점이 20개 미만으로 줄어들 때 새 지점을 보충하는 로직이 실제로 어떻게 동작하는지 로그로 확인해 보세요.
5. `cv2.TrackerCSRT_create()`와 `cv2.TrackerKCF_create()`로 같은 영상에서 같은 대상을 추적해 보고, 추적 성공률(`success` 값이 `False`가 되는 빈도)과 처리 속도(프레임당 `time.perf_counter()` 측정)를 비교해 보세요.
