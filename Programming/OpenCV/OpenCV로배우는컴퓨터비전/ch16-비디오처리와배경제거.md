## 16.1 프레임 단위 처리 파이프라인 다시 보기

4장에서는 `VideoCapture`로 웹캠이나 동영상 파일을 열어 프레임을 읽어오는 기초적인 방법을 다루었습니다. 이번 장에서는 그 기초 위에서, 읽어온 프레임에 실제로 어떤 처리를 가하고 그 결과를 화면에 보여준 뒤 종료 조건까지 관리하는 실전 파이프라인의 전체 구조를 정리합니다. 이 구조는 이후 어떤 비디오 처리 기능(배경 제거, 객체 검출, 필터링 등)을 추가하든 그대로 재사용할 수 있는 뼈대입니다.

파이프라인은 크게 네 단계로 이루어집니다.

1. **읽기(read)**: `VideoCapture`에서 한 프레임씩 읽어옵니다.
2. **처리(process)**: 읽어온 프레임에 원하는 알고리즘(색공간 변환, 필터링, 배경 제거 등)을 적용합니다.
3. **표시(display)**: 처리된 결과를 `imshow`로 화면에 보여줍니다.
4. **종료 조건(exit condition)**: 사용자가 키를 누르거나 더 이상 읽을 프레임이 없으면 루프를 빠져나옵니다.

### Python

```python
import cv2

cap = cv2.VideoCapture(0)  # 0번 웹캠. 파일이면 "video.mp4" 등 경로 전달
if not cap.isOpened():
    raise RuntimeError("비디오 소스를 열 수 없습니다.")

while True:
    # 1. 읽기
    ret, frame = cap.read()
    if not ret:
        break  # 프레임을 더 읽을 수 없으면 종료 (파일의 끝 등)

    # 2. 처리: 예시로 그레이스케일 변환
    processed = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # 3. 표시
    cv2.imshow("Original", frame)
    cv2.imshow("Processed", processed)

    # 4. 종료 조건: 'q' 키를 누르면 종료
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>

    cv::VideoCapture cap(0);  // 0번 웹캠. 파일이면 "video.mp4" 등 경로 전달

        cv::cvtColor(frame, processed, cv::COLOR_BGR2GRAY);

        // 3. 표시
        cv::imshow("Original", frame);
        cv::imshow("Processed", processed);

        // 4. 종료 조건: 'q' 키를 누르면 종료
        if (cv::waitKey(1) == 'q') {
            break;
        }
    }

    cap.release();
    cv::destroyAllWindows();
    return 0;
}
```

## 16.2 배경 제거로 움직이는 객체 감지하기

CCTV 감시 영상에서 사람이 지나가는 것을 감지하거나, 고정된 카메라로 도로의 차량을 세는 것처럼, 카메라가 고정되어 있고 배경은 그대로인데 그 위에서 무언가가 움직이는 상황은 매우 흔합니다. 이런 경우에 쓰는 대표적인 기법이 **배경 제거(background subtraction)**입니다.

배경 제거의 기본 아이디어는 단순합니다. 여러 프레임을 관찰하면서 "이 픽셀은 보통 이런 색이었다"라는 배경 모델을 학습하고, 새로운 프레임이 들어오면 그 모델과 비교해 크게 달라진 픽셀만 "전경(foreground)", 즉 움직이는 객체로 판단하는 것입니다. 단순히 두 프레임을 직접 비교하는 것보다 정교한 이유는, 배경 모델이 나뭇잎의 흔들림이나 조명의 미세한 변화 같은 자잘한 변동까지 통계적으로 학습해서 그런 잡음을 전경으로 오판하지 않기 때문입니다.

OpenCV는 이런 배경 모델을 만들어주는 여러 알고리즘을 제공하며, 그중 가장 널리 쓰이는 것이 **MOG2**(Mixture of Gaussians, 가우시안 혼합 모델의 개선판)입니다. 사용법은 다음과 같은 흐름을 따릅니다.

1. `createBackgroundSubtractorMOG2()`로 배경 모델 객체를 만듭니다.
2. 각 프레임을 배경 모델의 `apply()` 메서드에 넣습니다. 이 메서드는 전경으로 판단된 영역이 흰색(255), 배경으로 판단된 영역이 검은색(0)인 전경 마스크를 반환합니다. 동시에 내부적으로 배경 모델을 그 프레임 정보로 조금씩 갱신합니다.
3. 필요하면 전경 마스크에 모폴로지 연산(11장 참고)을 적용해 잡음을 제거하고, 컨투어 검출(13장 참고)로 움직이는 객체의 위치와 크기를 얻습니다.

### Python

```python
import cv2

cap = cv2.VideoCapture("traffic.mp4")

# MOG2 배경 제거기 생성
# history: 배경 모델을 학습하는 데 참고하는 과거 프레임 수
# varThreshold: 픽셀이 배경/전경으로 갈리는 분산 임계값 (낮을수록 민감)
# detectShadows: 그림자를 별도 회색(127)으로 표시할지 여부
back_sub = cv2.createBackgroundSubtractorMOG2(
    history=500, varThreshold=16, detectShadows=True
)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    # 전경 마스크 계산 (그림자는 127, 전경은 255, 배경은 0)
    fg_mask = back_sub.apply(frame)

    # 그림자(127)를 배경으로 취급하도록 이진화
    _, fg_mask = cv2.threshold(fg_mask, 200, 255, cv2.THRESH_BINARY)

    # 작은 잡음 제거를 위한 모폴로지 열림 연산
    kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    fg_mask = cv2.morphologyEx(fg_mask, cv2.MORPH_OPEN, kernel)

    # 움직이는 객체의 컨투어를 찾아 사각형으로 표시
    contours, _ = cv2.findContours(fg_mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
    for c in contours:
        if cv2.contourArea(c) < 500:  # 너무 작은 잡음은 무시
            continue
        x, y, w, h = cv2.boundingRect(c)
        cv2.rectangle(frame, (x, y), (x + w, y + h), (0, 255, 0), 2)

    cv2.imshow("Frame", frame)
    cv2.imshow("Foreground Mask", fg_mask)

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>
#include <opencv2/video.hpp>

int main() {
    cv::VideoCapture cap("traffic.mp4");

    // MOG2 배경 제거기 생성
    cv::Ptr<cv::BackgroundSubtractorMOG2> backSub =
        cv::createBackgroundSubtractorMOG2(500, 16.0, true);

    cv::Mat frame, fgMask, kernel;
    kernel = cv::getStructuringElement(cv::MORPH_ELLIPSE, cv::Size(5, 5));

    while (true) {
        if (!cap.read(frame) || frame.empty()) {
            break;
        }

        // 전경 마스크 계산 (그림자는 127, 전경은 255, 배경은 0)
        backSub->apply(frame, fgMask);

        // 그림자(127)를 배경으로 취급하도록 이진화
        cv::threshold(fgMask, fgMask, 200, 255, cv::THRESH_BINARY);

        // 작은 잡음 제거를 위한 모폴로지 열림 연산

        // 움직이는 객체의 컨투어를 찾아 사각형으로 표시
        std::vector<std::vector<cv::Point>> contours;
        cv::findContours(fgMask, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

        for (const auto& c : contours) {
            if (cv::contourArea(c) < 500) {
                continue;
            }
            cv::Rect box = cv::boundingRect(c);
            cv::rectangle(frame, box, cv::Scalar(0, 255, 0), 2);
        }

        cv::imshow("Frame", frame);
        cv::imshow("Foreground Mask", fgMask);

        if (cv::waitKey(30) == 'q') {
            break;
        }
    }

    cap.release();
    return 0;
```

### C#

```csharp
using System.Collections.Generic;
using OpenCvSharp;

using VideoCapture cap = new VideoCapture("traffic.mp4");

// MOG2 배경 제거기 생성
using var backSub = BackgroundSubtractorMOG2.Create(
    history: 500, varThreshold: 16, detectShadows: true
);

using Mat frame = new Mat();
using Mat fgMask = new Mat();
using Mat kernel = Cv2.GetStructuringElement(MorphShapes.Ellipse, new Size(5, 5));

while (true)
{
    if (!cap.Read(frame) || frame.Empty())
    {
        break;
    }

    backSub.Apply(frame, fgMask);

    Cv2.FindContours(fgMask, out Point[][] contours, out HierarchyIndex[] _,
                      RetrievalModes.External, ContourApproximationModes.ApproxSimple);

    foreach (Point[] c in contours)
    {
        if (Cv2.ContourArea(c) < 500)
        {
            continue;
        }
        Rect box = Cv2.BoundingRect(c);
        Cv2.Rectangle(frame, box, Scalar.FromRgb(0, 255, 0), 2);
    }

    Cv2.ImShow("Frame", frame);
    Cv2.ImShow("Foreground Mask", fgMask);

    {
        break;
    }
}
```

`history`가 클수록 배경 모델이 천천히, 안정적으로 적응하고, `varThreshold`가 낮을수록 작은 변화에도 전경으로 민감하게 반응합니다. `detectShadows`를 켜면 그림자 영역이 흰색(255)이 아닌 회색(127)으로 표시되므로, 그림자를 실제 객체와 구분하고 싶다면 위 예제처럼 임계값을 200 정도로 잡아 이진화하면 그림자를 배경 취급으로 걸러낼 수 있습니다.

## 16.3 더 단순한 대안: 프레임 차이 계산

MOG2 같은 통계적 배경 모델은 정확하지만, 그만큼 여러 프레임에 걸쳐 모델을 학습시켜야 하고 계산 비용도 더 듬니다. 움직임을 감지하기만 하면 되는 간단한 상황이라면, 훨씬 가벼운 방법으로 **프레임 차이(frame differencing)**를 쓸 수 있습니다. 연속한 두 프레임(또는 고정된 기준 프레임과 현재 프레임)의 밝기 차이를 `absdiff`로 계산해서, 차이가 큰 영역을 움직임이 있는 곳으로 판단하는 방식입니다.

### Python

```python
import cv2

cap = cv2.VideoCapture("traffic.mp4")

ret, prev_frame = cap.read()
prev_gray = cv2.cvtColor(prev_frame, cv2.COLOR_BGR2GRAY)

while True:
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

    # 이전 프레임과 현재 프레임의 차이 계산
    diff = cv2.absdiff(prev_gray, gray)
    _, motion_mask = cv2.threshold(diff, 25, 255, cv2.THRESH_BINARY)

    cv2.imshow("Frame", frame)
    cv2.imshow("Motion Mask", motion_mask)

    prev_gray = gray  # 다음 반복을 위해 현재 프레임을 이전 프레임으로 갱신

    if cv2.waitKey(30) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>

int main() {
    cv::VideoCapture cap("traffic.mp4");

    cv::Mat prevFrame, prevGray, frame, gray, diff, motionMask;
    cap.read(prevFrame);
    cv::cvtColor(prevFrame, prevGray, cv::COLOR_BGR2GRAY);

    while (true) {
        if (!cap.read(frame) || frame.empty()) {
            break;
        }

        cv::cvtColor(frame, gray, cv::COLOR_BGR2GRAY);

        // 이전 프레임과 현재 프레임의 차이 계산
        cv::absdiff(prevGray, gray, diff);
        cv::threshold(diff, motionMask, 25, 255, cv::THRESH_BINARY);

        cv::imshow("Frame", frame);
        cv::imshow("Motion Mask", motionMask);

        gray.copyTo(prevGray);  // 다음 반복을 위해 갱신

        if (cv::waitKey(30) == 'q') {
            break;
        }
    }

    return 0;
}
```

### C#

```csharp
using OpenCvSharp;

using VideoCapture cap = new VideoCapture("traffic.mp4");

using Mat prevFrame = new Mat();
using Mat prevGray = new Mat();
cap.Read(prevFrame);
Cv2.CvtColor(prevFrame, prevGray, ColorConversionCodes.BGR2GRAY);

using Mat frame = new Mat();
using Mat gray = new Mat();
using Mat diff = new Mat();
using Mat motionMask = new Mat();

while (true)
{
    if (!cap.Read(frame) || frame.Empty())
    {
        break;
    }

    Cv2.CvtColor(frame, gray, ColorConversionCodes.BGR2GRAY);

    // 이전 프레임과 현재 프레임의 차이 계산
    Cv2.Absdiff(prevGray, gray, diff);
    Cv2.Threshold(diff, motionMask, 25, 255, ThresholdTypes.Binary);

    Cv2.ImShow("Frame", frame);
    Cv2.ImShow("Motion Mask", motionMask);

    gray.CopyTo(prevGray);  // 다음 반복을 위해 갱신

    if (Cv2.WaitKey(30) == 'q')
    {

    }
}
```

두 방법을 비교하면 다음과 같은 차이가 있습니다.

| | 프레임 차이 (`absdiff`) | MOG2 배경 제거 |
|---|---|---|
| 원리 | 인접한 두 프레임을 직접 비교 | 여러 프레임을 통계적으로 학습한 배경 모델과 비교 |
| 계산 비용 | 매우 낮음 | 상대적으로 높음 (모델 유지·갱신 필요) |
| 정지한 객체 | 감지 못함(움직임이 멈추면 차이가 사라짐) | 배경으로 서서히 편입되기 전까지는 계속 전경으로 유지 |
| 잡음(나뭇잎 흔들림 등) | 그대로 움직임으로 잡힘 | 통계 모델이 반복되는 변동을 학습해 어느 정도 걸러냄 |
| 그림자 | 별도 처리 없음 | `detectShadows` 옵션으로 그림자를 구분 가능 |
| 적합한 상황 | 빠르고 단순한 움직임 감지, 리소스가 제한된 환경 | 정교한 전경/배경 분리가 필요한 감시, 트래픽 분석 등 |

즉 프레임 차이는 구현이 간단하고 빠르지만 정교함이 떨어지고, MOG2는 계산 비용이 더 들지만 훨씬 안정적인 전경 마스크를 만들어 줍니다. 실전에서는 요구되는 정확도와 사용 가능한 자원(임베디드 기기인지, 서버인지)에 따라 선택합니다.

## 16.4 옵티컬 플로우 살짝 맛보기

지금까지 살펴본 배경 제거와 프레임 차이는 "어느 픽셀이 변했는가"만 알려줄 뿐, 그 변화가 "어느 방향으로, 얼마나 빠르게" 일어났는지는 알려주지 않습니다. 이런 움직임의 방향과 속도까지 추정하는 기법을 **옵티컬 플로우(optical flow)**라고 부릅니다.

옵티컬 플로우는 한 프레임의 각 픽셀(또는 추적하고자 하는 특정 지점들)이 다음 프레임에서 어디로 이동했는지를 벡터로 추정합니다. 예를 들어 화면 왼쪽에서 오른쪽으로 이동하는 자동차가 있다면, 그 자동차 표면의 픽셀들에 대해 옵티컬 플로우는 오른쪽을 향하는 벡터를 계산해 줍니다. 이렇게 얻은 움직임 벡터는 객체의 이동 궤적을 추적하거나, 카메라 자체의 흔들림을 보정하거나, 영상 압축에서 다음 프레임을 예측하는 등 다양한 곳에 활용됩니다.

OpenCV는 15장에서 다룬 특징점처럼 몇 개의 대표 지점만 추적하는 **희소(sparse) 옵티컬 플로우**(`calcOpticalFlowPyrLK`, Lucas-Kanade 방법)와, 이미지의 모든 픽셀에 대해 흐름을 계산하는 **밀집(dense) 옵티컬 플로우**(`calcOpticalFlowFarneback` 등)를 함수로 제공합니다. 두 방법 모두 이 책의 범위를 넘어서는 구체적인 수학적 원리를 포함하므로, 여기서는 "픽셀의 이동 방향과 속도를 추정하는 기법"이라는 개념만 소개하고 자세한 구현은 다루지 않습니다. 관심이 있다면 이번 장에서 익힌 프레임 단위 처리 파이프라인에 위 함수들을 대입해 보는 것으로 다음 학습을 이어갈 수 있습니다.

## 16.5 처리된 비디오를 파일로 저장하기

지금까지는 처리 결과를 화면에만 보여주었지만, 실전에서는 그 결과(예: 움직임이 표시된 감시 영상, 전경 마스크 영상)를 파일로 저장해 나중에 다시 볼 수 있어야 하는 경우가 많습니다. 이때 사용하는 것이 `VideoWriter`입니다.

`VideoWriter`를 열 때는 다음 정보가 필요합니다.

- 저장할 파일 경로
- 코덱을 지정하는 4문자 코드(FourCC). 예를 들어 `"mp4v"`는 MP4 컨테이너에서 널리 쓰이는 코덱입니다.
- 초당 프레임 수(FPS)
- 프레임 크기(가로, 세로). 이 크기는 실제로 쓰는 프레임의 크기와 반드시 일치해야 하며, 다르면 저장이 실패하거나 깨진 영상이 만들어집니다.

다음 예제는 웹캠에서 프레임을 읽어 그레이스케일로 변환한 뒤, 그 결과를 `output.mp4` 파일로 저장합니다.

### Python

```python
import cv2

cap = cv2.VideoCapture(0)
if not cap.isOpened():
    raise RuntimeError("비디오 소스를 열 수 없습니다.")

# 원본 프레임 크기와 FPS를 소스에서 그대로 가져옴
fps = cap.get(cv2.CAP_PROP_FPS) or 30.0
width = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))
height = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))

fourcc = cv2.VideoWriter_fourcc(*"mp4v")
writer = cv2.VideoWriter("output.mp4", fourcc, fps, (width, height))

while True:
    ret, frame = cap.read()
    if not ret:
        break

    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    # 그레이스케일(1채널)을 그대로 쓰면 컬러 코덱과 맞지 않으므로 3채널로 변환
    gray_bgr = cv2.cvtColor(gray, cv2.COLOR_GRAY2BGR)

    writer.write(gray_bgr)
    cv2.imshow("Recording", gray_bgr)

    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
writer.release()
cv2.destroyAllWindows()
```

### C++

```cpp
#include <opencv2/opencv.hpp>

int main() {
    cv::VideoCapture cap(0);
    if (!cap.isOpened()) {
        return -1;
    }

    double fps = cap.get(cv::CAP_PROP_FPS);
    if (fps <= 0) fps = 30.0;
    int width = static_cast<int>(cap.get(cv::CAP_PROP_FRAME_WIDTH));
    int height = static_cast<int>(cap.get(cv::CAP_PROP_FRAME_HEIGHT));

    int fourcc = cv::VideoWriter::fourcc('m', 'p', '4', 'v');
    cv::VideoWriter writer("output.mp4", fourcc, fps, cv::Size(width, height));

    cv::Mat frame, gray, grayBgr;

    while (true) {
        if (!cap.read(frame) || frame.empty()) {
            break;
        }

        cv::cvtColor(frame, gray, cv::COLOR_BGR2GRAY);
        // 그레이스케일(1채널)을 그대로 쓰면 컬러 코덱과 맞지 않으므로 3채널로 변환
        cv::cvtColor(gray, grayBgr, cv::COLOR_GRAY2BGR);

        writer.write(grayBgr);
        cv::imshow("Recording", grayBgr);

        if (cv::waitKey(1) == 'q') {
            break;
        }
    }

    cap.release();
    writer.release();
    return 0;
}
```

### C#

```csharp
using OpenCvSharp;

using VideoCapture cap = new VideoCapture(0);
if (!cap.IsOpened())
{
    throw new InvalidOperationException("비디오 소스를 열 수 없습니다.");
}

double fps = cap.Fps > 0 ? cap.Fps : 30.0;
int width = (int)cap.Get(VideoCaptureProperties.FrameWidth);
int height = (int)cap.Get(VideoCaptureProperties.FrameHeight);

int fourcc = VideoWriter.FourCC('m', 'p', '4', 'v');
using VideoWriter writer = new VideoWriter("output.mp4", fourcc, fps, new Size(width, height));

using Mat frame = new Mat();
using Mat gray = new Mat();
using Mat grayBgr = new Mat();

while (true)
{
    if (!cap.Read(frame) || frame.Empty())
    {
        break;
    }

    Cv2.CvtColor(frame, gray, ColorConversionCodes.BGR2GRAY);
    // 그레이스케일(1채널)을 그대로 쓰면 컬러 코덱과 맞지 않으므로 3채널로 변환
    Cv2.CvtColor(gray, grayBgr, ColorConversionCodes.GRAY2BGR);

    writer.Write(grayBgr);
    Cv2.ImShow("Recording", grayBgr);

    if (Cv2.WaitKey(1) == 'q')
    {
        break;
    }
}
```

몇 가지 실수하기 쉬운 부분을 정리하면 다음과 같습니다.

- `VideoWriter`에 넘기는 프레임 크기는 반드시 실제로 `write()`에 넘기는 프레임의 크기와 정확히 일치해야 합니다. 크기가 다르면 대부분의 백엔드에서 저장이 조용히 실패합니다.
- 그레이스케일 처리 결과처럼 1채널 영상을 저장하려면, 코덱이 기대하는 3채널(BGR) 형식으로 다시 변환해 주어야 하는 경우가 많습니다. 위 예제에서 `cv2.COLOR_GRAY2BGR`로 변환한 이유가 바로 이것입니다.
- 작업이 끝나면 `cap`뿐 아니라 `writer`도 반드시 `release()`(C#은 `using`으로 자동 처리되거나 `Dispose()`)해야 파일이 온전하게 마무리(finalize)됩니다. 이 과정을 건너뛰면 파일이 생성되었더라도 재생이 되지 않거나 끝부분이 잘리는 경우가 있습니다.
- FourCC 코덱은 운영체제와 설치된 코덱 라이브러리에 따라 지원 여부가 달라질 수 있습니다. `mp4v`가 동작하지 않는 환경에서는 `XVID`(AVI 컨테이너), `MJPG` 등 다른 코덱을 시도해 볼 수 있습니다.

## 요약

- 비디오 처리의 기본 파이프라인은 "읽기 → 처리 → 표시 → 종료 조건"의 반복이며, `cap.read()`가 실패하는 순간과 사용자 키 입력 두 가지를 모두 종료 조건으로 갖추는 것이 안전합니다.
- 배경 제거(background subtraction)는 정적인 배경 위에서 움직이는 객체를 찾는 기법으로, `createBackgroundSubtractorMOG2()`로 배경 모델을 만들고 매 프레임 `apply()`를 호출해 전경 마스크를 얻습니다.
- 프레임 차이(`absdiff`)는 MOG2보다 훨씬 단순하고 가볍지만, 정지한 객체를 감지하지 못하고 잡음에 취약하다는 한계가 있습니다. 요구 정확도와 자원 제약에 따라 선택합니다.
- 옵티컬 플로우는 픽셀의 이동 방향과 속도까지 추정하는 기법으로, OpenCV는 희소 방식(`calcOpticalFlowPyrLK`)과 밀집 방식(`calcOpticalFlowFarneback`)을 제공합니다.
- `VideoWriter`로 처리된 프레임을 다시 동영상 파일로 저장할 수 있으며, 코덱(FourCC)·FPS·프레임 크기를 정확히 맞추고 작업 종료 시 반드시 `release()`해야 합니다.
