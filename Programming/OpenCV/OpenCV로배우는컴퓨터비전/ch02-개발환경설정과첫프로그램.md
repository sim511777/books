# 2장. 개발 환경 설정과 첫 프로그램

[◀ 이전: 1장. OpenCV란 무엇인가](ch01-OpenCV란무엇인가.md) | [📖 목차](00-목차.md) | [다음: 3장. 이미지의 기본 구조(Mat과 NumPy 배열) ▶](ch03-이미지의기본구조.md)


1장에서 OpenCV가 무엇인지, 그리고 이 책이 왜 Python·C++·C# 세 언어를 나란히 다루는지 살펴보았습니다. 이제 실제로 코드를 실행해볼 차례입니다. 이 장에서는 세 언어 각각에서 OpenCV를 설치하는 방법을 알아보고, 이미지 한 장을 읽어서 창에 띄워보는 가장 기본적인 프로그램을 함께 작성합니다. 흔히 "Hello, World"라고 부르는 첫 프로그램의 컴퓨터 비전 버전인 셈이니, 여기서는 "Hello, OpenCV"라고 불러보겠습니다.

세 언어의 설치 과정은 서로 다르지만, 목표는 동일합니다. 각 언어의 프로젝트에서 OpenCV 함수를 호출할 수 있는 상태를 만드는 것입니다. 이미 세 언어 중 하나만 쓸 계획이라면 해당 절만 따라가도 되지만, 나머지 절도 가볍게 훑어보면 "이 언어에서는 라이브러리를 이렇게 가져오는구나"를 비교하는 데 도움이 됩니다.

## 언어별 설치 방법

### Python: pip로 설치하기

Python에서는 패키지 관리자 pip로 OpenCV 바인딩을 설치합니다. 터미널에서 다음 명령을 실행합니다.

```bash
pip install opencv-python
```

이 패키지는 OpenCV의 핵심 기능(이미지 입출력, 필터링, 기하 변환, 컨투어 검출 등)을 담고 있습니다. 그런데 OpenCV에는 특허나 라이선스 문제, 또는 실험적인 성격 때문에 핵심 모듈과 분리되어 관리되는 확장 모듈들도 있습니다. 예를 들어 15장에서 다룰 일부 특징점 검출 알고리즘이나, 추가적인 이미지 처리 기법들이 여기에 포함됩니다. 이런 확장 모듈까지 함께 쓰고 싶다면 `opencv-python` 대신 다음 패키지를 설치합니다.

```bash
pip install opencv-contrib-python
```

`opencv-contrib-python`은 `opencv-python`의 기능을 모두 포함하면서 확장 모듈까지 추가로 제공하는 패키지입니다. 두 패키지를 동시에 설치하면 충돌이 날 수 있으므로, 둘 중 하나만 골라서 설치하는 것이 안전합니다. 이 책의 예제는 대부분 핵심 모듈로 충분하지만, 특정 장에서 확장 모듈이 필요한 경우에는 해당 장에서 별도로 안내합니다.

설치가 끝나면 Python 인터프리터에서 다음과 같이 확인해볼 수 있습니다.

```python
import cv2
print(cv2.__version__)
```

버전 문자열이 출력되면 설치가 정상적으로 완료된 것입니다.

### C++: vcpkg로 설치하고 CMake에 연결하기

C++는 패키지 관리자가 표준화되어 있지 않은 언어라, OpenCV를 설치하는 방법도 여러 가지입니다. 이 책에서는 크로스 플랫폼에서 무난하게 동작하는 vcpkg를 기준으로 설명합니다. vcpkg 자체를 처음 설치하고 부트스트랩하는 과정은 C++ 개발 환경을 다루는 별도의 자료에서 자세히 다루므로, 여기서는 vcpkg가 이미 설치되어 있다고 가정하고 OpenCV를 설치하는 단계부터 시작합니다.

vcpkg를 설치한 디렉터리에서 다음 명령으로 OpenCV를 설치합니다.

```bash
./vcpkg install opencv
```

이 한 줄이 실행되면 vcpkg는 OpenCV의 소스 코드를 내려받아 여러분의 시스템 컴파일러로 직접 빌드하고, 그 결과물(헤더 파일과 라이브러리 파일)을 vcpkg의 `installed/` 디렉터리 아래에 정리해 넣습니다. OpenCV는 다루는 기능이 워낙 많은 라이브러리라 이 빌드 과정이 다른 라이브러리보다 오래 걸릴 수 있으니, 처음 설치할 때는 여유를 두고 기다리는 것이 좋습니다.

설치가 끝나면 CMake 프로젝트에서 OpenCV를 찾아 연결합니다. `CMakeLists.txt`에 다음 두 줄을 추가합니다.

```cmake
find_package(OpenCV REQUIRED)
target_link_libraries(main PRIVATE ${OpenCV_LIBS})
```

`find_package(OpenCV REQUIRED)`는 CMake에게 "OpenCV를 찾아서 그 정보를 변수에 담아두라"고 지시하는 명령이고, 이 명령이 성공하면 `${OpenCV_LIBS}`(연결할 라이브러리 목록)와 `${OpenCV_INCLUDE_DIRS}`(헤더 파일 경로) 같은 변수가 채워집니다. `target_link_libraries`로 이 라이브러리 목록을 실행 파일 타겟에 연결해주면, 코드에서 `#include <opencv2/opencv.hpp>`를 쓸 수 있게 됩니다.

CMake가 vcpkg의 설치 위치를 알 수 있도록, 프로젝트를 구성(configure)할 때 vcpkg가 제공하는 툴체인 파일을 지정해줘야 합니다.

```bash
cmake -B build -DCMAKE_TOOLCHAIN_FILE=<vcpkg 경로>/scripts/buildsystems/vcpkg.cmake
cmake --build build
```

이 툴체인 파일 지정은 vcpkg로 어떤 C++ 라이브러리를 쓰든 공통으로 필요한 과정입니다. 한 번 익혀두면 OpenCV뿐 아니라 앞으로 다른 C++ 라이브러리를 쓸 때도 그대로 재사용할 수 있습니다.

### C#: NuGet으로 OpenCvSharp4 설치하기

C#에서는 NuGet 패키지 관리자로 OpenCvSharp을 설치합니다. Visual Studio를 쓴다면 "NuGet 패키지 관리"에서, `dotnet` CLI를 쓴다면 다음 명령으로 설치합니다.

```bash
dotnet add package OpenCvSharp4
```

여기서 반드시 기억해야 할 점이 하나 있습니다. `OpenCvSharp4` 패키지 자체는 C# 코드로 작성된 API 래퍼만 담고 있고, 실제로 연산을 수행하는 OpenCV 네이티브 바이너리(C++로 컴파일된 DLL 등)는 들어있지 않습니다. 이 네이티브 바이너리는 플랫폼별로 별도의 패키지로 제공되므로, 사용 중인 운영체제에 맞는 런타임 패키지를 함께 설치해야 합니다. Windows라면 다음 패키지가 필요합니다.

```bash
dotnet add package OpenCvSharp4.runtime.win
```

macOS나 Linux를 사용한다면 각 플랫폼에 맞는 런타임 패키지(예: `OpenCvSharp4.runtime.osx` 계열이나 `OpenCvSharp4.runtime.ubuntu` 계열 등, 배포 환경에 따라 이름이 다를 수 있습니다)를 찾아서 설치해야 합니다. `OpenCvSharp4`만 설치하고 런타임 패키지를 빠뜨리면, 코드는 정상적으로 컴파일되지만 실행 시점에 네이티브 라이브러리를 찾지 못했다는 오류가 발생합니다. C#에서 OpenCV 관련 오류를 만났을 때 가장 먼저 확인해볼 지점이 바로 이 런타임 패키지 설치 여부입니다.

## Hello, OpenCV: 이미지를 창에 띄우기

설치가 끝났다면 이제 실제로 코드를 실행해볼 차례입니다. 세 언어 모두 같은 흐름을 따릅니다.

1. 이미지 파일을 읽어 메모리로 불러온다.
2. 창을 하나 만들어 그 이미지를 화면에 띄운다.
3. 사용자가 키를 누를 때까지 기다린다.
4. 열려 있는 창을 모두 닫는다.

아래 예제에서는 `sample.jpg`라는 이미지 파일이 프로그램과 같은 폴더에 있다고 가정합니다. 여러분이 가진 임의의 이미지 파일로 경로만 바꿔서 실행해보세요.

### Python

```python
import cv2

img = cv2.imread("sample.jpg")

cv2.imshow("Hello, OpenCV", img)
cv2.waitKey(0)
cv2.destroyAllWindows()
```

`cv2.imread()`는 이미지 파일을 읽어 NumPy 배열(`np.ndarray`)로 반환합니다. `cv2.imshow()`는 창의 이름과 표시할 이미지를 받아 화면에 띄우고, `cv2.waitKey(0)`는 키 입력이 들어올 때까지 무한히 대기합니다(괄호 안의 숫자는 대기할 밀리초 단위 시간이며, 0은 "무한정 대기"를 의미합니다). 마지막으로 `cv2.destroyAllWindows()`가 열려 있는 모든 창을 닫습니다.

### C++

```cpp
#include <opencv2/opencv.hpp>

int main() {
    cv::Mat img = cv::imread("sample.jpg");

    cv::imshow("Hello, OpenCV", img);
    cv::waitKey(0);
    cv::destroyAllWindows();

    return 0;
}
```

`cv::imread()`는 이미지를 읽어 `cv::Mat` 객체로 반환합니다. 이후 흐름은 Python과 이름만 다를 뿐 완전히 동일합니다. `cv::` 네임스페이스를 앞에 붙인다는 점, 그리고 세미콜론과 `main` 함수 구조가 필요하다는 점이 C++다운 차이입니다.

### C#

```csharp
using OpenCvSharp;

Mat img = Cv2.ImRead("sample.jpg");

Cv2.ImShow("Hello, OpenCV", img);
Cv2.WaitKey(0);
Cv2.DestroyAllWindows();
```

C#에서는 모든 OpenCV 함수가 정적 클래스 `Cv2`의 메서드로 제공되며, 각 함수 이름은 PascalCase로 표기됩니다(`imread` → `ImRead`, `imshow` → `ImShow`처럼 단어의 첫 글자가 대문자가 됩니다). 이미지는 OpenCvSharp의 `Mat` 클래스로 표현되는데, 이름은 C++의 `cv::Mat`과 같지만 실제로는 OpenCvSharp이 그 위에 얹은 별도의 클래스입니다. C#의 `Mat`은 내부적으로 관리되지 않는(unmanaged) 네이티브 메모리를 참조하고 있으므로, 실제 프로젝트에서는 다 쓴 뒤 `img.Dispose()`를 호출하거나 `using` 구문으로 감싸서 리소스를 명확히 해제해주는 것이 좋습니다. 이 짧은 예제에서는 프로그램이 곧바로 종료되므로 생략했지만, 이 관리 방식의 차이는 3장에서 `Mat` 클래스를 자세히 다룰 때 다시 설명합니다.

## 실행 결과 확인과 흔히 만나는 오류

세 코드를 실행하면 모두 "Hello, OpenCV"라는 제목의 창이 뜨고, 그 안에 `sample.jpg` 이미지가 표시됩니다. 아무 키나 누르면 창이 닫히고 프로그램이 종료됩니다.

처음 이 예제를 실행할 때 가장 자주 마주치는 문제는 이미지 파일을 찾지 못하는 경우입니다. 세 언어의 `imread` 계열 함수는 파일을 읽지 못했을 때 예외를 던지는 대신, "비어 있는" 결과를 조용히 반환합니다. Python에서는 `img`가 `None`이 되고, C++에서는 `img.empty()`가 `true`를 반환하는 빈 `Mat`이 되며, C#에서도 마찬가지로 빈 `Mat`이 반환됩니다. 이 상태에서 `imshow`를 호출하면 창이 뜨지 않거나 오류가 나는데, 원인을 파악하기 전에는 "OpenCV가 고장 났다"고 오해하기 쉽습니다. 실제로는 대부분 파일 경로가 잘못되었거나, 실행 파일의 현재 작업 디렉터리가 예상과 다른 경우입니다. 이미지를 불러온 뒤에는 습관적으로 비어 있는지 확인하는 것이 좋으며, 이 점은 4장에서 이미지 입출력을 본격적으로 다룰 때 다시 짚습니다.

또한 C++와 C#에서는 창이 화면에 나타나도록 반드시 `waitKey`(또는 그에 대응하는 대기 함수)를 호출해야 합니다. 이 호출이 없으면 창이 그려지는 짧은 순간에 프로그램이 곧바로 종료되어버려 창을 볼 기회조차 없습니다. Python에서도 마찬가지로 `cv2.waitKey()`를 호출하지 않으면 `imshow`로 그린 내용이 화면에 갱신되지 않는 경우가 있으므로, 이 순서(읽기 → 표시 → 대기 → 닫기)는 세 언어 모두에서 지켜야 하는 기본 패턴으로 기억해두는 것이 좋습니다.

## 요약

- Python은 `pip install opencv-python`으로 설치하며, 특허·실험적 기능을 포함한 확장 모듈이 필요하면 `opencv-contrib-python`을 대신 설치합니다.
- C++는 vcpkg로 `vcpkg install opencv`를 실행해 설치하고, CMake의 `find_package(OpenCV REQUIRED)`와 `target_link_libraries(... ${OpenCV_LIBS})`로 프로젝트에 연결합니다. vcpkg의 툴체인 파일을 CMake 구성 시점에 지정해줘야 합니다.
- C#은 NuGet에서 `OpenCvSharp4`와, 사용 중인 플랫폼에 맞는 네이티브 런타임 패키지(`OpenCvSharp4.runtime.win` 등)를 함께 설치해야 합니다. 런타임 패키지를 빠뜨리면 컴파일은 되지만 실행 시점에 오류가 납니다.
- 이미지를 읽어 창에 띄우는 기본 흐름(읽기 → 표시 → 키 입력 대기 → 창 닫기)은 세 언어 모두 동일하며, 함수 이름의 표기 방식(`cv2.imread`, `cv::imread`, `Cv2.ImRead`)만 각 언어의 관용구를 따라 다릅니다.
- 이미지를 읽지 못했을 때 세 언어 모두 예외 대신 비어 있는 결과를 반환하므로, 사용 전에 비어 있는지 확인하는 습관을 들이는 것이 좋습니다.

3. C#에서 `OpenCvSharp4` 패키지만 설치하고 런타임 패키지를 설치하지 않으면 어떤 증상이 나타나는지, 그리고 그 이유를 설명해보세요.
