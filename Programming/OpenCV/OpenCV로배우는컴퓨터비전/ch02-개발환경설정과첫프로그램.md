## 가상환경 준비하기

OpenCV를 설치하기 전에, 먼저 프로젝트마다 독립된 Python 환경을 만드는 습관을 들이는 것이 좋습니다. 시스템 전역에 패키지를 설치하면 프로젝트 A에서 필요한 라이브러리 버전과 프로젝트 B에서 필요한 버전이 충돌할 수 있고, 실수로 시스템 Python 자체를 망가뜨릴 위험도 있습니다. 가상환경은 프로젝트별로 독립된 패키지 설치 공간을 만들어 이런 문제를 원천적으로 막아줍니다. Python에서 가장 널리 쓰이는 두 가지 방법인 `venv`와 `conda`를 비교해보겠습니다.

### venv로 가상환경 만들기

`venv`는 Python 표준 라이브러리에 포함되어 있어 별도 설치 없이 바로 쓸 수 있는 가장 기본적인 가상환경 도구입니다. 프로젝트 폴더에서 다음 명령으로 가상환경을 만듭니다.

```bash
python -m venv .venv
```

이 명령은 현재 폴더 아래에 `.venv`라는 이름의 디렉터리를 만들고, 그 안에 독립된 Python 인터프리터와 패키지 설치 공간을 구성합니다. 만든 가상환경은 다음과 같이 활성화합니다.

```bash
# Windows(PowerShell)
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate
```

활성화되면 터미널 프롬프트 앞에 `(.venv)`처럼 가상환경 이름이 표시되며, 이 상태에서 `pip install`로 설치하는 모든 패키지는 시스템 전역이 아니라 이 가상환경 안에만 설치됩니다. 프로젝트 작업이 끝나면 `deactivate` 명령으로 가상환경을 빠져나올 수 있습니다. Windows에서 PowerShell의 스크립트 실행 정책 때문에 `Activate.ps1` 실행이 막히는 경우도 있는데, 이때는 관리자 권한 PowerShell에서 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`를 한 번 실행해 정책을 완화해주면 해결됩니다.

### conda로 가상환경 만들기

`conda`는 Anaconda나 Miniconda를 설치하면 함께 제공되는 패키지·환경 관리자입니다. `venv`와 달리 Python 자체의 버전도 환경별로 다르게 지정할 수 있고, OpenCV 실행에 필요한 일부 시스템 라이브러리(예: 특정 코덱 관련 라이브러리)까지 함께 관리해주는 경우가 있어, 특히 Windows에서 복잡한 의존성 문제를 피하고 싶을 때 선호됩니다. 새 환경은 다음과 같이 만듭니다.

```bash
conda create -n cv-study python=3.11
conda activate cv-study
```

`conda create -n cv-study python=3.11`은 `cv-study`라는 이름으로 Python 3.11 버전을 담은 새 환경을 만들고, `conda activate cv-study`로 그 환경을 활성화합니다. 활성화된 환경 안에서는 `conda install`이나 `pip install` 어느 쪽으로도 패키지를 설치할 수 있는데, OpenCV의 경우 conda 채널 패키지보다 PyPI의 `opencv-python`이 더 자주, 더 빠르게 업데이트되므로 이 책에서는 활성화된 conda 환경 안에서도 `pip install`을 사용합니다.

### 두 방법 중 무엇을 고를까

`venv`는 추가 설치가 필요 없고 가볍다는 장점이 있어, 이미 Python이 설치되어 있고 간단한 프로젝트 하나를 격리하고 싶을 때 적합합니다. `conda`는 Python 버전 자체를 환경마다 다르게 지정할 수 있고, 데이터 과학 패키지(NumPy, pandas, scikit-learn 등)의 사전 컴파일된 바이너리를 안정적으로 배포한다는 장점이 있어, 여러 버전의 Python을 넘나들거나 복잡한 의존성을 가진 대규모 프로젝트에 적합합니다. 이 책의 예제는 둘 중 어느 쪽으로 진행해도 무방하며, 아래에서는 가상환경이 활성화된 상태를 가정하고 설명합니다.

## 프로젝트 폴더 구조와 의존성 관리

가상환경까지 준비되었다면, 실습을 진행할 폴더를 간단히 정리해두는 것이 좋습니다. 이 책의 예제는 다음과 같은 최소한의 구조로 충분합니다.

```text
cv-study/
├── .venv/              # 가상환경 (venv로 만든 경우)
├── images/             # 실습에 사용할 이미지 파일들
│   └── sample.jpg
├── requirements.txt    # 설치한 패키지 목록
└── ch02_hello_opencv.py
```

패키지를 설치할 때마다 팀원이나 미래의 자신이 똑같은 환경을 재현할 수 있도록, 설치한 패키지 목록을 `requirements.txt` 파일로 기록해두는 습관을 들이면 좋습니다. 현재 가상환경에 설치된 패키지 목록은 다음 명령으로 파일에 저장할 수 있습니다.

```bash
pip freeze > requirements.txt
```

이렇게 저장된 파일은 다음과 같은 형식으로 각 패키지의 정확한 버전을 담고 있습니다.

```text
opencv-python==4.10.0.84
numpy==1.26.4
matplotlib==3.9.0
```

새 컴퓨터나 새 가상환경에서 같은 환경을 재현하고 싶을 때는 이 파일을 그대로 사용해 한 번에 설치할 수 있습니다.

```bash
pip install -r requirements.txt
```

이렇게 해두면 "내 컴퓨터에서는 되는데 다른 컴퓨터에서는 안 된다"는 흔한 문제의 원인 중 하나(패키지 버전 차이)를 쉽게 배제할 수 있습니다.

## OpenCV 패키지 설치: 세 가지 선택

1장에서 살펴본 것처럼 PyPI에는 이름이 비슷한 OpenCV 패키지가 세 개 있습니다. 실전에서 어떤 것을 선택할지 다시 표로 정리합니다.

| 상황 | 설치 명령 | 이유 |
|---|---|---|
| 데스크톱에서 GUI로 이미지를 직접 보며 개발 | `pip install opencv-python` | 핵심 기능과 `cv2.imshow()` 등 GUI 함수가 모두 필요 |
| 특징점 검출기(SIFT 등 일부), 트래킹 알고리즘 등 확장 모듈이 필요 | `pip install opencv-contrib-python` | 핵심 기능 + 별도 관리되는 확장 모듈까지 포함 |
| 도커 컨테이너, 클라우드 서버, CI/CD 파이프라인처럼 화면 출력이 없는 환경 | `pip install opencv-python-headless` | GUI 의존성(X11, GTK 등)이 전혀 없어 서버 환경에서도 설치·실행 오류가 없음 |

세 패키지는 모두 같은 `cv2` 모듈로 임포트되기 때문에 **한 가상환경에 반드시 하나만** 설치해야 합니다. 이미 하나가 설치된 상태에서 다른 것을 설치하면 파일이 뒤섞여 예측할 수 없는 오류가 날 수 있으므로, 패키지를 바꾸고 싶다면 먼저 기존 패키지를 지우고 새로 설치하는 것이 안전합니다.

```bash
pip uninstall opencv-python opencv-contrib-python opencv-python-headless
pip install opencv-contrib-python
```

이 책의 실습은 기본적으로 `opencv-python`으로 충분하며, 확장 모듈이 필요한 특정 절에서는 그때 `opencv-contrib-python` 설치를 별도로 안내합니다. 이 책에서는 이미지 배열을 다루기 위해 NumPy도 함께 쓰므로, 다음과 같이 한 번에 설치해도 됩니다.

```bash
pip install opencv-python numpy matplotlib
```

`matplotlib`은 뒤에서 Jupyter Notebook 환경에서 이미지를 표시할 때 사용합니다.

## NumPy와 matplotlib을 함께 설치하는 이유

`pip install opencv-python numpy matplotlib`에서 `opencv-python` 외에 두 패키지를 더 설치하는 이유를 짚어두겠습니다.

**NumPy**는 1장에서 설명했듯 OpenCV의 Python 바인딩이 이미지를 표현하는 방식 그 자체입니다. `cv2.imread()`가 반환하는 값도, 이 책의 거의 모든 예제에서 `img`라는 이름으로 다루는 값도 결국 `numpy.ndarray`입니다. `opencv-python`을 설치하면 의존 패키지로 NumPy가 자동으로 함께 설치되므로 따로 신경 쓰지 않아도 되지만, 코드에서 `np.zeros()`나 `np.array()`처럼 NumPy의 함수를 직접 호출하려면 `import numpy as np`로 명시적으로 임포트해줘야 합니다.

**matplotlib**은 OpenCV 자체에는 포함되어 있지 않은 별도의 시각화 라이브러리입니다. 데스크톱에서 `cv2.imshow()`만으로 충분하다면 당장은 필요 없을 수도 있지만, 이 장에서 다룰 Jupyter Notebook·Colab 환경의 이미지 표시, 그리고 이후 장에서 다룰 히스토그램 그래프(14장)를 그리려면 반드시 필요합니다. 미리 설치해두면 나중에 환경을 다시 구성할 필요가 없으므로, 이 책에서는 처음부터 함께 설치하도록 안내합니다.

## 설치 확인

설치가 끝나면 Python 인터프리터나 스크립트에서 다음과 같이 버전을 확인합니다.

```python
import cv2
import numpy as np

print("OpenCV 버전:", cv2.__version__)
print("NumPy 버전:", np.__version__)
```

버전 문자열이 오류 없이 출력되면 설치가 정상적으로 완료된 것입니다. `cv2.__version__`은 설치된 opencv-python 빌드의 버전을 문자열로 알려주는데, 이 값을 확인해두면 나중에 "이 함수가 왜 없지?"라는 문제가 생겼을 때 OpenCV 버전 차이 때문인지 아닌지를 빠르게 판단할 수 있습니다.

## VS Code에서 Python + OpenCV 개발 환경 설정하기

Visual Studio Code(VS Code)는 Python과 OpenCV를 함께 다루기에 무난한 에디터입니다. 원활하게 개발하려면 다음 두 가지를 확인해두는 것이 좋습니다.

**Python 확장 설치.** VS Code의 확장(Extension) 탭에서 Microsoft가 제공하는 "Python" 확장을 설치합니다. 이 확장은 코드 자동완성, 정의로 이동, 디버깅, 린팅 같은 기능을 제공합니다. `import cv2` 뒤에 `cv2.` 까지만 입력해도 사용 가능한 함수 목록이 자동완성으로 나타나는데, 이는 opencv-python 패키지에 포함된 타입 스텁(`.pyi` 파일) 정보를 이 확장이 읽어서 보여주는 것입니다.

**올바른 인터프리터 선택.** 여러 가상환경을 오가며 작업하다 보면, VS Code가 엉뚱한 Python 인터프리터(가령 시스템 전역 Python)를 가리키고 있어서 "cv2를 찾을 수 없다"는 오류가 나는 경우가 흔합니다. 명령 팔레트(`Ctrl+Shift+P` 또는 macOS의 `Cmd+Shift+P`)를 열고 "Python: Select Interpreter"를 검색해, 방금 만든 가상환경(`.venv`나 `cv-study` 등)의 경로를 선택해줘야 합니다. 화면 하단 상태 바에도 현재 선택된 인터프리터가 표시되므로, 코드를 실행하기 전에 이 표시가 원하는 가상환경을 가리키고 있는지 한 번 확인하는 습관을 들이면 좋습니다.

디버깅이 필요할 때는 코드에 중단점(breakpoint)을 찍어두고 `F5`로 디버거를 실행하면, 특정 줄에서 실행을 멈추고 `img.shape`나 `img.dtype` 같은 변수 값을 직접 살펴볼 수 있습니다. 이미지 배열의 형태가 예상과 다를 때 이 디버깅 기능이 특히 유용합니다.

VS Code에서 노트북 형식(`.ipynb`)으로 실습하고 싶다면, Microsoft의 "Jupyter" 확장을 추가로 설치하면 VS Code 안에서도 셀 단위 실행과 인라인 이미지 출력을 그대로 사용할 수 있습니다. 이 경우에도 노트북 우측 상단의 커널 선택 메뉴에서 올바른 가상환경이 선택되어 있는지 확인해야 합니다. 여러 프로젝트를 오가며 매번 인터프리터를 다시 선택하는 것이 번거롭다면, 프로젝트 폴더에 `.vscode/settings.json` 파일을 만들어 다음과 같이 기본 인터프리터 경로를 지정해둘 수도 있습니다.

```json
{
  "python.defaultInterpreterPath": ".venv/Scripts/python.exe"
}
```

macOS나 Linux에서는 경로 구분자가 다르므로 `.venv/bin/python`으로 지정합니다. 이렇게 설정해두면 해당 프로젝트 폴더를 열 때마다 VS Code가 자동으로 이 인터프리터를 기본값으로 선택합니다.

## 흔한 설치 오류와 해결법

OpenCV를 설치하고 실행하는 과정에서 자주 마주치는 오류들을 미리 정리해두면, 실제로 겪었을 때 당황하지 않고 빠르게 해결할 수 있습니다.

**`ImportError: libGL.so.1: cannot open shared object file`.** 우분투 기반 도커 컨테이너나 클라우드 서버에서 `import cv2`를 실행할 때 가장 흔하게 나타나는 오류입니다. `opencv-python`은 GUI 창을 띄우는 기능을 포함하고 있어 그래픽 관련 시스템 라이브러리(`libGL` 등)에 의존하는데, 화면 출력 장치가 없는 서버 환경에는 이 라이브러리가 설치되어 있지 않은 경우가 많습니다. 해결책은 두 가지입니다. 시스템에 해당 라이브러리를 추가로 설치(`apt-get install libgl1` 등)할 수도 있지만, 화면 출력이 애초에 필요 없는 환경이라면 다음처럼 GUI 의존성이 없는 패키지로 바꾸는 것이 훨씬 간단하고 근본적인 해결책입니다.

```bash
pip uninstall opencv-python
pip install opencv-python-headless
```

**`ModuleNotFoundError: No module named 'cv2'`.** `pip install opencv-python`을 실행했는데도 이 오류가 난다면, 대개 설치한 가상환경과 코드를 실행하는 인터프리터가 서로 다른 경우입니다. 터미널에서 `pip show opencv-python`으로 실제로 설치되었는지 확인하고, `python -c "import sys; print(sys.executable)"`로 현재 실행 중인 Python이 어느 경로를 가리키는지 확인해보면 원인을 빠르게 찾을 수 있습니다. VS Code라면 앞서 설명한 인터프리터 선택이 잘못된 경우가 대부분입니다.

**macOS(Apple Silicon)에서의 설치.** M1/M2/M3 등 애플 실리콘 칩을 사용하는 맥에서도 최신 `opencv-python`은 arm64 아키텍처용 사전 빌드된 wheel(설치 파일)을 제공하므로, 별도의 조치 없이 `pip install opencv-python`이 대부분 그대로 동작합니다. 다만 아주 오래된 버전의 pip를 쓰고 있다면 arm64용 wheel을 찾지 못해 소스 코드를 직접 빌드하려다 실패하는 경우가 있으니, 이때는 `pip install --upgrade pip`로 pip 자체를 먼저 최신 버전으로 올려주는 것이 좋습니다.

**최소 설치된 Linux 배포판에서 발생하는 추가 공유 라이브러리 오류.** `libGL.so.1` 외에도 `libSM.so.6`, `libXext.so.6`, `libXrender.so.1` 같은 라이브러리가 없다는 오류가 이어서 나타나는 경우가 있습니다. 이는 최소 설치(minimal install) 옵션으로 구성된 Linux 서버에 GUI 관련 시스템 패키지가 전혀 없기 때문인데, `opencv-python-headless`로 전환하면 이런 라이브러리들에 대한 의존성 자체가 없어져 이 오류들도 함께 사라집니다.

**두 패키지를 동시에 설치해 생기는 충돌.** `opencv-python`과 `opencv-contrib-python`(또는 `headless` 버전)을 둘 다 설치한 상태에서는 `cv2` 임포트 자체는 되지만, 특정 함수가 예상과 다르게 동작하거나 알 수 없는 오류가 나는 경우가 있습니다. `pip list | grep opencv`(Windows PowerShell에서는 `pip list | Select-String opencv`)로 설치된 OpenCV 관련 패키지를 모두 확인하고, 하나만 남기고 나머지는 지우는 것이 안전합니다.

**`cv2.imshow()`를 호출했는데 창이 뜨지 않거나 커널이 멈춘다.** 이는 대부분 Jupyter Notebook이나 Google Colab 같은 환경에서 GUI 창을 띄우려고 했을 때 나타나는 증상입니다. 바로 다음 절에서 이 문제와 해결책을 자세히 다룹니다.

**Windows에서 `ImportError: DLL load failed while importing cv2`.** opencv-python은 내부적으로 컴파일된 네이티브 DLL을 포함하고 있는데, 이 오류는 그 DLL이 필요로 하는 Microsoft Visual C++ 재배포 가능 패키지(Visual C++ Redistributable)가 시스템에 설치되어 있지 않을 때 주로 발생합니다. 마이크로소프트 홈페이지에서 최신 "Visual C++ Redistributable"을 설치하면 대부분 해결됩니다. 드물게는 설치된 Python이 32비트인데 64비트용 패키지가 설치되었거나 그 반대인 경우에도 이 오류가 날 수 있으므로, `python -c "import platform; print(platform.architecture())"`로 Python 아키텍처를 확인해보는 것도 도움이 됩니다.

**웹캠 예제에서 `cap.isOpened()`가 `False`를 반환한다.** 카메라가 다른 애플리케이션(화상 회의 프로그램 등)에서 이미 사용 중이거나, 운영체제의 카메라 권한 설정에서 해당 프로그램(또는 터미널)의 접근이 차단된 경우가 흔한 원인입니다. macOS에서는 "시스템 설정 → 개인정보 보호 및 보안 → 카메라"에서 사용 중인 터미널 앱이나 IDE에 권한이 허용되어 있는지 확인해야 합니다. 여러 대의 카메라가 연결되어 있다면 `cv2.VideoCapture(0)`의 `0` 대신 `1`, `2` 등 다른 번호를 시도해보는 것도 원인 파악에 도움이 됩니다.

## Jupyter Notebook에서 이미지 표시하기

`cv2.imshow()`는 운영체제의 GUI 창 시스템을 직접 제어해 새 창을 띄우는 함수입니다. 그런데 Jupyter Notebook이나 Google Colab은 브라우저 안에서 코드를 실행하는 환경이라, 애초에 독립된 GUI 창을 띄울 수 있는 화면 자체가 존재하지 않습니다. 이런 환경에서 `cv2.imshow()`를 호출하면 플랫폼에 따라 아무 반응이 없거나, 커널이 응답하지 않거나, 심한 경우 커널이 강제로 종료되기도 합니다. 즉 OpenCV나 설치 과정이 잘못된 것이 아니라, "GUI 창을 띄울 수 없는 환경에 GUI 창을 띄우라는 명령을 내렸기 때문"입니다.

이 문제의 해결책은 `cv2.imshow()`를 아예 쓰지 않고, 노트북 셀 안에 이미지를 직접 그려주는 `matplotlib.pyplot.imshow()`로 대체하는 것입니다. matplotlib은 노트북 환경과 잘 통합되어 있어서, 셀을 실행하면 그 셀 바로 아래에 이미지가 인라인으로 표시됩니다.

여기서 반드시 기억해야 할 점이 하나 있습니다. `cv2.imread()`는 이미지를 BGR 순서로 읽어오지만, `matplotlib.pyplot.imshow()`는 RGB 순서를 기대합니다. 이 변환을 빼먹으면 1장에서 살펴본 것처럼 색이 뒤바뀐 이미지가 나타납니다. 다음은 Jupyter Notebook 셀에서 실행할 수 있는 올바른 예제입니다.

```python
import cv2
import matplotlib.pyplot as plt

# 1. 이미지를 읽는다 (BGR 순서로 반환된다)
img_bgr = cv2.imread("sample.jpg")

# 2. matplotlib이 기대하는 RGB 순서로 채널을 바꾼다
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)

# 3. 셀 출력 영역에 이미지를 그린다
plt.imshow(img_rgb)
plt.axis("off")   # 축 눈금과 좌표선을 숨긴다
plt.title("Hello, OpenCV (Jupyter)")
plt.show()
```

각 줄의 역할을 짚어보면, `cv2.imread("sample.jpg")`는 디스크의 이미지 파일을 읽어 NumPy 배열로 반환합니다. `cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)`는 채널의 순서를 B-G-R에서 R-G-B로 재배열해, matplotlib이 올바른 색으로 해석하도록 만들어줍니다. `plt.imshow(img_rgb)`는 이 배열을 이미지로 그리라고 matplotlib에 지시하지만, 이 시점에는 아직 화면에 실제로 표시되지 않고 내부 버퍼에만 그려집니다. `plt.axis("off")`는 이미지 주위에 나타나는 x축·y축의 눈금선을 없애 사진만 깔끔하게 보이도록 합니다. `plt.title(...)`은 이미지 위에 제목을 붙입니다. 마지막으로 `plt.show()`가 호출되어야 지금까지 준비한 내용이 실제로 셀 출력 영역에 렌더링됩니다(주피터 환경에서는 셀의 마지막 표현식이 자동으로 출력되는 경우도 있지만, `plt.show()`를 명시적으로 호출하는 습관을 들이면 스크립트로 옮겨 실행할 때도 동일하게 동작하므로 더 안전합니다).

### Google Colab에서는 cv2_imshow도 대안이 된다

Google Colab은 구글이 제공하는 클라우드 기반 Jupyter Notebook 환경으로, 별도의 설치 없이 브라우저만으로 Python과 OpenCV를 실습할 수 있어 널리 쓰입니다. Colab에는 `opencv-python`이 이미 설치되어 있는 경우가 많지만, 없다면 셀 맨 앞에 `!`를 붙여 셸 명령을 실행할 수 있습니다.

Colab도 Jupyter와 마찬가지로 독립된 GUI 창을 띄울 수 없으므로, `cv2.imshow()`를 그대로 호출하면 오류가 납니다. 앞서 소개한 `matplotlib.pyplot.imshow()` 방식을 그대로 써도 되고, Colab 환경에서는 구글이 제공하는 패치 함수를 사용할 수도 있습니다.


그레이스케일 이미지를 표시할 때는 채널 변환이 필요 없는 대신, 흑백으로 보이도록 컬러맵을 지정해줘야 합니다.

```python
img_gray = cv2.imread("sample.jpg", cv2.IMREAD_GRAYSCALE)

plt.imshow(img_gray, cmap="gray")
plt.axis("off")
plt.show()
```

`cv2.IMREAD_GRAYSCALE` 플래그를 주면 `cv2.imread()`가 이미지를 채널이 하나뿐인 흑백 배열로 읽어옵니다. 이때 `cmap="gray"`를 지정하지 않으면 matplotlib이 기본 컬러맵으로 배열 값을 색상에 매핑해버려, 흑백 사진이 초록·보라 같은 이상한 색으로 보이게 되니 주의해야 합니다.

## 여러 이미지를 한 화면에서 비교하기

이미지 처리 결과를 확인할 때는 원본과 처리 결과를 나란히 놓고 비교해야 하는 경우가 많습니다. matplotlib의 `plt.subplots()`를 쓰면 하나의 창(또는 노트북 셀) 안에 여러 이미지를 격자 형태로 배치할 수 있습니다.

```python
import cv2
import matplotlib.pyplot as plt

img_bgr = cv2.imread("sample.jpg")
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)
img_gray = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2GRAY)

# 1행 2열 격자의 서브플롯(Axes)을 만든다
fig, axes = plt.subplots(1, 2, figsize=(10, 5))

axes[0].imshow(img_rgb)
axes[0].set_title("원본 (RGB)")
axes[0].axis("off")

axes[1].imshow(img_gray, cmap="gray")
axes[1].set_title("그레이스케일")
axes[1].axis("off")

plt.tight_layout()
plt.show()
```

`plt.subplots(1, 2, figsize=(10, 5))`는 1행 2열, 즉 두 개의 그림을 나란히 그릴 수 있는 영역(Axes)을 만들고, 전체 크기를 가로 10인치·세로 5인치로 지정합니다. 반환된 `axes`는 각 그림 영역을 담은 배열이라, `axes[0]`은 왼쪽, `axes[1]`은 오른쪽 영역을 가리킵니다. 각 영역에 `imshow()`로 이미지를 그리고 `set_title()`로 제목을 붙인 뒤, `plt.tight_layout()`으로 영역 사이의 여백을 자동으로 조정하고 `plt.show()`로 전체를 화면에 표시합니다. 이 패턴은 이 책 전체에서 "처리 전/후"를 비교할 때 계속 재사용되므로 지금 익혀두면 이후 장에서도 편리합니다.

## Hello, OpenCV: 창으로 띄우기

일반 `.py` 스크립트를 터미널에서 직접 실행하는 데스크톱 환경이라면, `cv2.imshow()`로 실제 GUI 창을 띄워 결과를 확인할 수 있습니다. 다음은 이미지를 읽어 창에 띄우는 가장 기본적인 스크립트입니다.

```python
import cv2

# 1. 이미지 파일을 읽어 NumPy 배열로 불러온다
img = cv2.imread("sample.jpg")

# 2. 이미지를 제대로 읽었는지 확인한다
if img is None:
    raise FileNotFoundError("sample.jpg 파일을 찾을 수 없습니다. 경로를 확인하세요.")

# 3. "Hello, OpenCV"라는 이름의 창을 만들어 이미지를 띄운다
cv2.imshow("Hello, OpenCV", img)

# 4. 키 입력이 들어올 때까지 무한히 대기한다
cv2.waitKey(0)

# 5. 열려 있는 모든 창을 닫는다
cv2.destroyAllWindows()
```

한 줄씩 살펴보겠습니다. `cv2.imread("sample.jpg")`는 현재 작업 디렉터리를 기준으로 `sample.jpg` 파일을 찾아 읽고, 성공하면 `(높이, 너비, 채널)` 형태의 NumPy 배열을 반환합니다. 파일을 찾지 못하거나 형식을 해석할 수 없으면 예외를 던지는 대신 조용히 `None`을 반환하므로, `if img is None:`으로 반드시 확인하는 습관을 들여야 합니다. 이 확인을 건너뛰면 몇 줄 뒤에서 `img.shape`처럼 `None`에는 없는 속성을 사용하려다 훨씬 알아보기 어려운 오류(`AttributeError: 'NoneType' object has no attribute 'shape'`)를 만나게 됩니다.

`cv2.imshow("Hello, OpenCV", img)`는 첫 번째 인자로 준 문자열을 창의 제목으로 삼아, 두 번째 인자로 준 이미지를 화면에 띄웁니다. 같은 이름으로 다시 `imshow`를 호출하면 새 창을 만드는 대신 기존 창의 내용을 갱신합니다. `cv2.waitKey(0)`은 키보드 입력을 기다리는 함수로, 괄호 안의 숫자는 대기할 시간을 밀리초 단위로 지정합니다. `0`은 "제한 없이 무한정 대기"를 의미하며, 사용자가 어떤 키든 누르면 그 키 코드를 반환하고 즉시 다음 줄로 진행합니다. 이 호출이 없으면 창이 화면에 그려지는 짧은 순간 프로그램이 곧바로 끝나버려서, 창이 뜨는 모습을 볼 기회조차 없습니다. 마지막으로 `cv2.destroyAllWindows()`는 현재 열려 있는 모든 OpenCV 창을 닫습니다.

## Hello, OpenCV 확장하기: 웹캠으로 실시간 영상 띄우기

정지 이미지 한 장을 띄우는 데 성공했다면, 조금만 코드를 바꿔서 웹캠 영상을 실시간으로 띄워볼 수 있습니다. 이 예제는 "이미지 한 장"이 아니라 "연속된 프레임의 흐름"을 다룬다는 점에서, 이후 16장에서 배울 비디오 처리의 가장 단순한 형태이기도 합니다.

```python
import cv2

# 0번 카메라(보통 컴퓨터에 기본으로 연결된 웹캠)를 연다
cap = cv2.VideoCapture(0)

if not cap.isOpened():
    raise RuntimeError("웹캠을 열 수 없습니다. 카메라 연결과 권한을 확인하세요.")

while True:
    # 카메라에서 한 프레임을 읽는다
    ret, frame = cap.read()
    if not ret:
        break

    cv2.imshow("Hello, OpenCV (Webcam)", frame)

    # 1밀리초 대기하며 키 입력을 확인하고, 'q'를 누르면 반복문을 빠져나온다
    if cv2.waitKey(1) & 0xFF == ord("q"):
        break

# 카메라 장치를 반드시 해제한다
cap.release()
cv2.destroyAllWindows()
```

`cv2.VideoCapture(0)`은 시스템에 연결된 카메라 장치 중 0번(보통 내장 웹캠)을 열어 캡처 객체를 만듭니다. `cap.isOpened()`로 카메라가 정상적으로 열렸는지 미리 확인해두면, 카메라가 다른 프로그램에서 이미 사용 중이거나 연결되어 있지 않을 때 원인을 빠르게 파악할 수 있습니다. `cap.read()`는 호출될 때마다 카메라의 현재 프레임을 하나 읽어와, `(성공 여부, 프레임)` 형태의 튜플로 반환합니다. 정지 이미지를 다룰 때의 `cv2.imshow()`·`cv2.waitKey()` 패턴이 이번에는 `while` 반복문 안에서 매 프레임마다 실행된다는 점이 유일한 차이입니다. 이때 `cv2.waitKey(0)`처럼 무한정 대기하면 다음 프레임을 읽지 못하고 멈춰버리므로, `cv2.waitKey(1)`처럼 짧은 시간만 대기하고 다음 프레임으로 계속 넘어가야 합니다. `& 0xFF == ord("q")`는 눌린 키의 코드값 중 하위 8비트만 취해 `q` 키의 코드와 비교하는 관용적인 표현으로, `q`를 누르면 반복문을 빠져나오도록 만듭니다. 반복문을 빠져나온 뒤에는 `cap.release()`로 카메라 장치를 명시적으로 해제해줘야 하는데, 이를 빠뜨리면 카메라가 계속 점유된 상태로 남아 다른 프로그램이나 다음 실행에서 카메라를 열지 못하는 문제가 생길 수 있습니다.

노트북이나 Colab처럼 GUI 창을 띄울 수 없는 환경에서는 이 예제를 그대로 실행할 수 없습니다(카메라 장치 접근 방식 자체가 다르고, `cv2.imshow()`도 쓸 수 없기 때문입니다). 웹캠 실습은 데스크톱 환경에서 `.py` 스크립트로 직접 실행하는 것을 권장합니다.

## 처리 결과를 파일로 저장하기

화면에 띄워 확인하는 것뿐 아니라, 결과를 파일로 저장해야 하는 경우도 많습니다. `cv2.imwrite()`는 NumPy 배열을 다시 이미지 파일로 인코딩해 디스크에 씁니다.

```python
import cv2

img = cv2.imread("sample.jpg")

# 파일 확장자에 따라 자동으로 해당 형식으로 인코딩되어 저장된다
success = cv2.imwrite("output.png", img)

if not success:
    raise IOError("이미지를 저장하지 못했습니다. 경로와 폴더 존재 여부를 확인하세요.")
```

`cv2.imwrite()`의 첫 번째 인자는 저장할 파일 경로이고, 두 번째 인자는 저장할 이미지(NumPy 배열)입니다. 파일 확장자(`.png`, `.jpg`, `.bmp` 등)를 보고 OpenCV가 알맞은 인코더를 자동으로 선택하므로, 별도로 형식을 지정하는 인자는 필요하지 않습니다. 다만 대상 폴더가 존재하지 않거나 쓰기 권한이 없으면 예외를 던지는 대신 `False`를 반환하므로, `cv2.imread()`와 마찬가지로 반환값을 확인하는 습관이 필요합니다.

JPEG처럼 압축률을 조절할 수 있는 형식은 세 번째 인자로 품질을 지정할 수 있습니다.

```python
# JPEG 품질을 0~100 사이에서 지정한다 (기본값은 95, 숫자가 높을수록 용량이 커지고 화질이 좋아진다)
cv2.imwrite("output.jpg", img, [cv2.IMWRITE_JPEG_QUALITY, 90])
```

`[cv2.IMWRITE_JPEG_QUALITY, 90]`처럼 "설정 항목, 값" 쌍을 리스트로 넘기는 방식은 OpenCV의 여러 인코딩·디코딩 함수에서 공통으로 쓰이는 매개변수 패턴이므로, 지금 형태를 눈에 익혀두면 이후 장에서 비슷한 함수를 만났을 때 낯설지 않을 것입니다.

## 실행 결과 확인과 마무리

두 방식(창으로 띄우기, Jupyter에서 matplotlib으로 띄우기) 중 어느 쪽을 쓰든, 기본 흐름은 동일합니다. 이미지를 읽고, 제대로 읽혔는지 확인하고, 화면에 표시하는 것입니다. 데스크톱 스크립트 환경과 노트북 환경의 차이는 오직 "화면에 표시하는 방법"에만 있을 뿐입니다.

앞으로 이 책의 예제 코드는 특별한 언급이 없는 한 창으로 띄우는 방식(`cv2.imshow()`)을 기준으로 작성하지만, 노트북 환경에서 실습하고 있다면 그 부분만 이 장에서 배운 `matplotlib.pyplot.imshow()` 패턴으로 바꿔서 실행하면 됩니다. 두 방식을 오가며 실습해보면, "OpenCV가 이미지를 처리하는 부분"과 "그 결과를 화면에 보여주는 부분"이 서로 독립적인 단계라는 것을 자연스럽게 체감할 수 있습니다.

이 장에서 다룬 실행 환경과 이미지 표시 방법의 대응 관계를 표로 정리하면 다음과 같습니다.

| 실행 환경 | 이미지 표시 방법 | BGR→RGB 변환 필요 여부 |
|---|---|---|
| 데스크톱 `.py` 스크립트 | `cv2.imshow()` + `cv2.waitKey()` | 필요 없음(OpenCV 창은 BGR을 그대로 기대) |
| Jupyter Notebook | `matplotlib.pyplot.imshow()` | 필요함(`cv2.cvtColor(..., cv2.COLOR_BGR2RGB)`) |
| Google Colab | `matplotlib.pyplot.imshow()` 또는 `cv2_imshow()` | matplotlib 사용 시 필요, `cv2_imshow()` 사용 시 불필요 |

이 표를 기준으로 지금 여러분이 실습하는 환경에 맞는 방식을 고르면 됩니다. 어떤 방식을 고르더라도 "이미지를 읽는다 → (필요하면 색공간을 변환한다) → 화면에 그린다"는 흐름 자체는 달라지지 않습니다.

## 요약

- 프로젝트를 시작하기 전 `venv`(표준 라이브러리, 가볍음) 또는 `conda`(Python 버전까지 환경별로 관리, 복잡한 의존성에 강함) 중 하나로 가상환경을 만들어 패키지를 격리하는 것이 좋고, `pip freeze > requirements.txt`로 설치 목록을 기록해두면 환경을 재현하기 쉬워집니다.
- 데스크톱 GUI 개발에는 `opencv-python`, 확장 모듈이 필요하면 `opencv-contrib-python`, 서버나 컨테이너처럼 화면 출력이 없는 환경에는 `opencv-python-headless`를 설치합니다. 한 환경에는 반드시 하나만 설치해야 합니다.
- `cv2.imshow()`는 Jupyter Notebook이나 Colab처럼 GUI 창을 띄울 수 없는 환경에서는 동작하지 않으므로, `matplotlib.pyplot.imshow()`로 대체해야 하며 이때 `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)`로 BGR을 RGB로 변환해줘야 색이 올바르게 보입니다. Colab에서는 `google.colab.patches`의 `cv2_imshow()`를 대신 사용할 수도 있습니다.
- 여러 이미지를 비교할 때는 `plt.subplots()`로 격자 형태의 영역을 만들어 나란히 표시하면 편리하며, 이 패턴은 이후 장에서도 계속 재사용됩니다.
- VS Code에서는 Python 확장을 설치하고, "Python: Select Interpreter"로 올바른 가상환경을 선택해야 `cv2` 임포트와 자동완성이 정상적으로 동작합니다.
- `ImportError: libGL.so.1` 같은 오류는 대부분 GUI 의존성이 없는 서버 환경에 GUI 포함 패키지를 설치했기 때문이며, `opencv-python-headless`로 바꿔 설치하면 해결됩니다. Windows의 `DLL load failed` 오류는 대개 Visual C++ 재배포 패키지 누락이 원인입니다. `cv2.imread()`가 파일을 읽지 못하면 예외 대신 `None`을 반환하므로, 사용 전 `if img is None:`으로 확인하는 습관이 중요합니다.
- `cv2.VideoCapture(0)`, `cap.read()`, `cap.release()`를 이용하면 정지 이미지 예제를 웹캠 실시간 영상으로 손쉽게 확장할 수 있으며, 이때는 `cv2.waitKey(0)`이 아니라 `cv2.waitKey(1)`처럼 짧은 대기 시간을 반복문 안에서 사용해야 합니다.
- `cv2.imwrite()`는 파일 확장자에 따라 자동으로 형식을 인코딩해 저장하며, 실패 시 예외 대신 `False`를 반환하므로 반환값을 확인해야 합니다. JPEG의 경우 `[cv2.IMWRITE_JPEG_QUALITY, 값]`으로 압축 품질을 조절할 수 있습니다.
